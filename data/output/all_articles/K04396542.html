Topic

You should consider using this procedure under the following conditions:

  • You want to use the iControl representation state transfer (REST) API for one or both of the following reasons:
    • You want to verify the proper operation of your BIG-IP system by uploading a QKView file to F5 iHealth.
    • You want to provide a QKView file to F5 Support to aid in troubleshooting an issue with a BIG-IP system.

Description

The qkview utility is a tool that automatically collects configuration and diagnostic information from BIG-IP and BIG-IQ systems. For more information, refer to K12878: Generating diagnostic data using the qkview utility.

Note: The procedures in this article also work for EoL software F5 iWorkflow and Enterprise Manager.

The REST procedure described in this article is an example of a common BIG-IP maintenance task. You can use the iControl REST API to perform most of the BIG-IP system management and configuration tasks that you can perform using the TMOS Shell (tmsh) . For more information about the iControl REST API, refer to the iControl REST User Guide that applies to your BIG-IP version, available on F5 Cloud Docs.

curl and jq utilities

Performing the following procedure requires command-line access to a system with the curl utility and, optionally, the jq (command line JSON processor) utility installed. These utilities are commonly available on Linux systems but you can also install them on Microsoft Windows and Mac OS X systems. Additionally, you can perform this procedure from an alternate BIG-IP system; however, the jq utility is not available on systems running versions earlier than BIG-IP 12.0.0. You can still use the curl portion of commands, but the resulting output is a single string rather than formatted JSON. For more information about the jq utility, refer to https://stedolan.github.io/jq.

Note: This link takes you to a resource outside of AskF5. The third party could remove the document without our knowledge.

Alternatively, you can use the Python json.tool module in place of the jq utility in the examples in this article, to format the JSON output. To do so, replace 'jq .' with 'python -m json.tool' in the commands listed.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • Your BIG-IP system is licensed, provisioned, and configured with a management IP address.
  • You have administrative access to the BIG-IP Configuration utility.
  • You have command-line access to a system with the curl utility and, optionally, the jq utility installed. For more information, refer to curl and jq utilities in this article.
  • You have access to F5 Cloud Docs to review iControl REST API documentation.

Procedures

  • Generating a QKView diagnostic file
  • Listing available QKView diagnostic file
  • Deleting a QKView diagnostic file
  • Downloading a QKView diagnostic file using Python

Generating a QKView diagnostic file

Note: This is an asynchronous endpoint. It exits immediately, allowing for the execution of subsequent tasks to complete. After the file generation it is complete, the status is SUCCEEDED. The output file is saved to /var/tmp/qkviews/<qkview-file-name>.

  1. Enter the following command syntax to start the generation of a new QKView file:

    curl -sku admin:<password> https://<BIG-IP hostname or mgmt IP address>/mgmt/cm/autodeploy/qkview -H "Content-type: application/json" -X POST -d '{"name":"<qkview-file-name>"}' | jq .

    For example, to generate a QKView file using the example configuration described in the previous table, enter the following command:

    curl -sku admin:testing https://LTM1.example.com/mgmt/cm/autodeploy/qkview -H "Content-type: application/json" -X POST -d '{"name":"LTM1.example.com.qkview"}' | jq .

    Output appears similar to the following example:

    {
      "id": "60f9f91f-6fe8-4673-a9bc-e009f77e94a1",
      "name": "LTM1.example.com.qkview",
      "status": "IN_PROGRESS",
      "generation": 1,
      "lastUpdateMicros": 1585240603017868,
      "kind": "cm:autodeploy:qkview:qkviewitemstate",
      "selfLink": "https://localhost/mgmt/cm/autodeploy/qkview/60f9f91f-6fe8-4673-a9bc-e009f77e94a1"
    }
    Note: For subsequent commands, this article refers to this QKView file by the listed id name.

Downloading a QKView diagnostic file using Python

Note: There is a 1M chunk-size limitation to prevent denial of service (DoS) attacks. Additionally, instead of using REST, you can download the QKView file from the /var/tmp directory of the BIG-IP system. For more information about downloading files from the BIG-IP system, refer to K175: Transferring files to or from an F5 system.

Python example

The following Python script example comes from Demystifying iControl REST Part 5: Transferring Files on DevCentral. You can refer to that article for more information.

Note: The following example is provided for demonstration purposes only, without warranty. F5 Support does not support this script. Additionally, the endpoint referenced is /mgmt/cm/autodeploy/qkview-downloads/%s, where %s is the QKView name (LTM1.example.com.qkview in this example) that you want to download.

#!/usr/bin/env python3

import os
import requests

def _download(host, creds, fp):
    chunk_size = 512 * 1024

    headers = {
        'Content-Type': 'application/octet-stream'
    }
    filename = os.path.basename(fp)
    uri = 'https://%s/mgmt/cm/autodeploy/qkview-downloads/%s' % (host, filename)
    requests.packages.urllib3.disable_warnings()

    with open(fp, 'wb') as f:
        start = 0
        end = chunk_size - 1
        size = 0
        current_bytes = 0

        while True:
            content_range = "%s-%s/%s" % (start, end, size)
            headers['Content-Range'] = content_range

            #print headers
            resp = requests.get(uri,
                                auth=creds,
                                headers=headers,
                                verify=False,
                                stream=True)

            if resp.status_code == 200:
                # If the size is zero, then this is the first time through the
                # loop and we don't want to write data because we haven't yet
                # figured out the total size of the file.
                if size > 0:
                    current_bytes += chunk_size
                    for chunk in resp.iter_content(chunk_size):
                        f.write(chunk)

                # Once we've downloaded the entire file, we can break out of
                # the loop
                if end == size:
                    break

            crange = resp.headers['Content-Range']

            # Determine the total number of bytes to read
            if size == 0:
                size = int(crange.split('/')[-1]) - 1

                # If the file is smaller than the chunk size, BIG-IP will
                # return an HTTP 400. So adjust the chunk_size down to the
                # total file size...
                if chunk_size > size:
                    end = size

                # ...and pass on the rest of the code
                continue

            start += chunk_size

            if (current_bytes + chunk_size) > size:
                end = size
            else:
                end = start + chunk_size - 1
