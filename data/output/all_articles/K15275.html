Known Issue

When you create a virtual server using the Traffic Management Shell (tmsh) in a non-default administrative partition, its BIG-IP LTM virtual address may contain an incorrect route domain ID.

This issue occurs when all of the following conditions are met:

  • You have configured at least one non-default administrative partition.
  • You have configured at least one non-zero route domain.
  • Using tmsh (without changing to the desired administrative partition), you have created a new virtual server in a non-default administrative partition object, and the virtual server's default route domain ID is not 0 (zero).

    For example:

    root@(bigip)(cfg-sync Standalone)(Active)(/Common)(tmos)# create /ltm virtual /part1/vip10 destination 10.10.10.10:0

Impact

The affected object's virtual address is configured with the wrong route domain ID.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • When you create the affected virtual server, its virtual address does not have the correct route domain ID.
        
    For example, a virtual server was created with the 10.10.10.10%99 destination address, but the resulting virtual address uses route domain ID 0:

    10.10.10.10%0

    Therefore, the route domain ID trailing at the IP address is mismatched.
  • Client connection to the affected network object may fail because the route domain ID attached to the object is incorrect.
  • If you attempt to correct the route domain ID for the virtual address, you will receive an error message and fail to modify the route domain ID. This error message may appear similar to the following example:

    01070734:3: Configuration error: Invalid virtual address modification. An address change from 10.10.10.10 to 10.10.10.10%99 is not supported.

Workaround

You can work around this issue by deleting the affected virtual server and recreating it using the Configuration utility.

Alternatively, after deleting the affected object, you can recreate it using the tmsh utility by avoiding the issue described in this article. To avoid this issue when using tmsh, you can first change the current partition to the desired administrative partition. You can then create the new virtual server. This step will prevent you from creating a virtual address with an incorrect route domain ID.
