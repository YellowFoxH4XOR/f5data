Description

EDNS query might be dropped by protocol inspection after upgrade from v11.6.x to the known affected versions. The client sends the DNS query which has a client subnet field within the additional records.

Domain Name System (query)
[..snippet..]
    Additional records
        <Root>: type OPT
            Name: <Root>
            Type: OPT (41)
            UDP payload size: 1280
            Higher bits in extended RCODE: 0x00
            EDNS0 version: 0
            Z: 0x8000
                1... .... .... .... = DO bit: Accepts DNSSEC security RRs
                .000 0000 0000 0000 = Reserved: 0x0000
            Data length: 11
            Option: CSUBNET - Client subnet     <<--------!!!
                Option Code: CSUBNET - Client subnet (8)
                Option Length: 7
                Option Data: 00011110b10111
                Family: IPv4 (1)
                Source Netmask: 22
                Scope Netmask: 0
                Client Subnet: 192.168.1.1

In /var/log/ltm or /var/log/pktfilter log file, you would see similar log as below is logged

 info tmm[13855]: 23003139 SECURITYLOG Drop sip:10.10.100.34  sport:35271 dip:10.10.100.230 dport:53 query:test.f5.com qtype:malformed attack:malformed

Environment

  • DNS Query containing CSUBNET option
  • GTM Module
  • AFM Module

Cause
Bug ID 1016049: EDNS query with CSUBNET dropped by protocol inspection

Recommended Actions

Expect the fix will be introduced in v17.x
If you require an EHF, please contact F5 support to acquire the EHF and follow article K13123: Managing BIG-IP product hotfixes (11.x - 16.x) to install it.
