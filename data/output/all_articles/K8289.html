K8289: Disabling blocking for certain object types while allowing blocking for non-existent objects

Topic

In BIG-IP ASM 9.4.1 and earlier, you can disable blocking for certain object types, while allowing the security policy to block requests for non-existent objects. To do so, you need to define an object type with the Check Objects setting disabled, and then enable blocking for non-existent objects.

Beginning in BIG-IP ASM 9.4.2, you can disable blocking for certain object types, while allowing the security policy to block requests for non-existent objects, by performing the following three procedures:
  • Defining an explicit object type
  • Defining a wildcard object with the Check characters on this object setting disabled
  • Enabling blocking for non-existent objects
Defining an explicit object type

To define an explicit object type, for example, a .jpg file, perform the following procedure:
  1. Log in to the Configuration utility.
  2. Click Application Security.
  3. Click the relevant security policy.
  4. Click Object Types.
  5. Click Create.
  6. Enter the .jpg file type in the Object Type box.
  7. Select Explicit from the drop-down menu.

    Note: The .jpg file type is used as an example. You can define other file types based on your web application.
  8. Define the object type properties.
  9. Click Create.
Defining a wildcard object with the check characters on this object setting disabled

Wildcard entities can be used in the security policy to represent object types, web objects, and parameters. When you define a wildcard object in the security policy, you disable blocking for that object, and requests for that object are considered legal. For example, configuring a wildcard expression for the .jpg object specifies that request for a .jpg object is allowed by the security policy.

To define a wildcard object with the Check characters on this object setting disabled, perform the following procedure:
  1. Log in to the Configuration utility.
  2. Click Application Security.
  3. Click the relevant security policy.
  4. Click Objects.
  5. Click Create.
  6. Enter the .jpg file type in the Object Name box.
  7. Select Wildcard from the drop-down menu.

    Note: The .jpg file type is used as an example. You can define other file types based on your web application.
  8. Clear the Check characters on this object check box.
  9. Click Create.
Enabling blocking for non-existent objects

The Non-Existent Objects access violation setting is enabled by default in the security policy. To enable blocking for non-existent objects, perform the following procedure:
  1. Log in to the Configuration utility.
  2. Click Application Security.
  3. Click the security policy from the previous procedure.
  4. Click Policies.
  5. Select Settings from the Blocking menu.
  6. Check the Block column for the Non-existent object access violation setting.
  7. Click Apply Policy.
