K31632053: Open Distro not initialized

Type
Support Solution
Published
2022-11-09
Updated
2025-01-15
Applies to
  • BIG-IQ
  • BIG-IQ Centralized Management: 8.0.0, 8.X.X, 8.3.X, 8.3.0, 8.2.X, 8.2.0, 8.1.X, 8.1.0, 8.0.X
Source
https://my.f5.com/manage/s/article/K31632053

Description

The output of the following command to check the health of Elastic Search in a BIG-IQ environment is Open Distro not initialized.

curl -su admin: -k "https://localhost:9200/_cluster/health?pretty"
Open Distro not initialized

Environment

  • BIG-IQ Centralized Management (CM)
  • BIG-IQ Data Collection Device (DCD) cluster
  • DCD disconnected
  • Unable to query Elastic Search
  • Error: The system returned an unexpected error (500 Server Error). Connection refused.

Cause

Unknown

Recommended Actions

  1. Log in to the BIG-IQ CM using SSH to perform this procedure.
  2. Run the following command to disable Open Distro security (run below command as a whole) in BIG-IQ CM only. You will get a parse error if you perform it on a BIG-IQ DCD:

    ENA=false; URL=$(curl -su admin: localhost:8100/cm/shared/esmgmt/cluster-ssl-task -H 'Content-type: application/json' -d "{\"enable\":\"$ENA\"}" | jq .selfLink -r | egrep -o "/cm.*"); STA=STARTED; while [ $STA == STARTED ]; do STA=$(restcurl $URL | jq .status -r); echo "$(date) - Status is: $STA"; grep cluster-ssl-task /var/log/restjavad.0.log | tail -n1; sleep 10; done

  3. Wait for the command to complete. This can take some time on large systems. Once the process has finished (Status is: FINISHED), confirm that Open Distro was disabled by accessing the cluster endpoint over HTTP using the following command:

    curl -s "http://localhost:9200/_cluster/health?pretty"

  4. Re-enable Open Distro security in the BIG-IQ CM. Run the command below to enable Open Distro security (run below command as a whole):

    ENA=true; URL=$(curl -su admin: localhost:8100/cm/shared/esmgmt/cluster-ssl-task -H 'Content-type: application/json' -d "{\"enable\":\"$ENA\"}" | jq .selfLink -r | egrep -o "/cm.*"); STA=STARTED; while [ $STA == STARTED ]; do STA=$(restcurl $URL | jq .status -r); echo "$(date) - Status is: $STA"; grep cluster-ssl-task /var/log/restjavad.0.log | tail -n1; sleep 10; done

  5. Wait for the command to complete. This can take some time on large systems. Once the process has finished (Status is: FINISHED), confirm that Open Distro was enabled by accessing the same endpoint over HTTPS:

    curl -su admin: -k "https://localhost:9200/_cluster/health?pretty"

It will take some time for the ES cluster to rebuild and for the status to turn green.  If everything worked as expected, Open Distro should have been re-enabled, and the Elastic Search cluster should now work over SSL.

Additional Information

If the disable and re-enable of Open Distro security does not resolve the issue, further troubleshooting will be required.

  1. Re-run step 2 to disable Open Distro security.
  2. Query curl -s "http://localhost:9200/_cluster/health?pretty" until the cluster status is green.
  3. If you get a response, and the cluster is green, then run the following command (run below command as a whole) to collect data for troubleshooting:
    rm -rf /var/tmp/esdebug ;
    mkdir /var/tmp/esdebug  ;
    date > /var/tmp/esdebug/start ;
    curl -k "http://localhost:9200/_cat/shards?bytes=b&s=store:desc&v=true" -so /var/tmp/esdebug/shards ;
    curl -k "http://localhost:9200/_cat/indices?bytes=b&s=store.size:desc&v=true" -so /var/tmp/esdebug/indices ;
    curl -k "http://localhost:9200/_cat/health?v" -so /var/tmp/esdebug/health ;
    curl -k "http://localhost:9200/_cat/nodes?v" -so /var/tmp/esdebug/nodes ;
    curl -k "http://localhost:9200/_cat/allocation?v" -so /var/tmp/esdebug/allocation ;
    curl -k "http://localhost:9200/book*/_search?size=1000" -so /var/tmp/esdebug/book.json ;
    curl -k "http://localhost:9200/meta*/_search?size=1000" -so /var/tmp/esdebug/meta.json ;
    curl -k "http://localhost:9200/_cluster/allocation/explain?pretty" -so /var/tmp/esdebug/allo_explain.json ;
    date > /var/tmp/esdebug/end ;
    tar -czf /var/tmp/esdebug.tgz /var/tmp/esdebug
  4. Generate QKViews on ALL BIG-IQ CM/DCD nodes.
  5. Open a case with F5 support and upload files for further analysis. Refer to K2633: Submit a support case.
