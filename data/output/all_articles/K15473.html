Description

The BIG-IP ASM system checks for HTTP protocol compliance failures based on RFC 2616. The header checks Header name with no header value and Host header contains IP address qualify as RFC-compliant use of the HTTP protocol headers, however, the BIG-IP ASM system can flag these headers as violations.

  • Header name with no header value

    This BIG-IP ASM system checks that presented HTTP headers have an associated value. When the BIG-IP ASM system detects that an HTTP header does not include an associated value, the request is blocked, by default. A legitimate client or application rarely sets an HTTP header without an associated header value. Clients that set headers in this manner are often automated bots or an individual client attempting to craft malicious requests.

    For example, the Authorization header does not include a value declaring the type of authorization and encrypted authorization string.

    Authorization:

    The expected syntax appears similar to the following example:

    Authorization: Basic AWzhZBRpbjovcOVuIHNlc4FtZN==

  • Host header contains IP address

    You can configure the BIG-IP ASM system to check that HTTP Host header values reference fully-qualified domain names (FQDN). When this option is enabled, the BIG-IP ASM system blocks requests that use an address as the host header value. It is rare for legitimate clients to access a public application based on the IP address of the application. Typically, clients accessing a site based on IP addresses are automated and are unlikely legitimate clients for most public-facing applications.

    For example, the Host header value uses an IP address instead of an FQDN for the accessed site.

    Host: 203.0.113.1

    The expected syntax appears similar to the following example:

    Host: www.example.com
