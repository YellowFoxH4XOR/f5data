K33471111: Unable to provision ASM module - Disk limit exceeded

Type
Support Solution
Published
2020-08-05
Updated
2026-04-15
Applies to
  • BIG-IP
  • BIG-IP ASM
Source
https://my.f5.com/manage/s/article/K33471111

Description

  • Unable to provision ASM module
  • An error similar to the following appear on the GUI

    "01071008:3: Provisioning failed with error 1 - warning: tm_install::DosPtable::scan_table -- identification of /dev/sdb1 failed; ID is 7 'Disk limit exceeded. 20338 MB are required to provision these modules, but only 30 MB are available."

  • On /var/log/ltm the following message can be seen

    Jul 21 21:24:08 ltm1.example.com warning mprov:55503:[55503]: 'Disk limit exceeded. 20338 MB are required to provision these modules, but only 24 MB are available.- will mark potential space as free and retry..'
    Jul 21 21:24:08 ltm1.example.com info mprov:55503:[55503]: 'Changing available disk space from 24 to 30'
    Jul 21 21:24:08 ltm1.example.com err mprov:55503:[55503]: 'Disk limit exceeded. 20338 MB are required to provision these modules, but only 30 MB are available.'
    Jul 21 21:24:08 ltm1.example.com info mprov:55503:[55503]: 'Provisioning (validation) failed.'
    Jul 21 21:24:08 ltm1.example.com err mcpd[7390]: 01071008:3: Provisioning failed with error 1 - warning: tm_install::DosPtable::scan_table -- identification of /dev/sdb1 failed; ID is 7

Environment

  • BIG-IP VE
  • /appdata partition with less that 25GB of disk allocation

Cause

The disk allocation for /appdata partition is too small.

Recommended Actions

You will need to extend the /appdata partition. To do so please perform the following steps:

  1. Connect to CLI
  2. Extend /appdata

    tmsh modify sys disk directory /appdata new-size 25000000

  3. Reboot the unit

    reboot
