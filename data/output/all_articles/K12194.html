Known Issue

This is the result of a known issue. A SIP virtual server that references a UDP profile with an immediate timeout may drop packets. This occurs when the virtual server references an iRule that performs session lookup on the SIP traffic.

For example, the following configuration contains a SIP virtual server that references a UDP profile with an immediate timeout, and an iRule that performs session lookup on the SIP traffic:

rule sip_lookup {
when SIP_RESPONSE {
log local0. "?: [session lookup uie [SIP::call_id]]"
}
}
profile udp testudp {
defaults from udp
datagram lb enable
idle timeout immediate
}
virtual testsip {
pool testpool
destination 1.1.1.1:5060
ip protocol udp
rules sip_lookup
profiles {
sip {}
testudp {}
}
}

F5 Product Development tracked this issue as ID 225747 (formerly CR140068), and it was fixed in BIG-IP version 10.2.1. For information about upgrading, refer to the BIG-IP LTM, ASM, PSM, WebAccelerator, APM, WOM, or Edge Gateway release notes.

Additionally, this issue has been fixed in cumulative Hotfix-BIGIP-10.2.0-1789.0-HF2 issued for BIG-IP version 10.2.0. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.
