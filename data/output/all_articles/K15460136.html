Description

After upgrade from v13.x to above, packets outgoing from BIG-IP are duplicated (or replicated) 8 times (or once per tmm).

Tcpdump capture shows that the source packets are duplicated, for example:

[root@bigip:Active:In Sync] ~ # ping 8.8.8.8
PING 8.8.8.8 (8.8.8.8) 56(84) bytes of data.
64 bytes from 8.8.8.8: icmp_seq=1 ttl=118 time=16.4 ms
64 bytes from 8.8.8.8: icmp_seq=1 ttl=118 time=16.4 ms (DUP!)
64 bytes from 8.8.8.8: icmp_seq=1 ttl=118 time=16.7 ms (DUP!)
64 bytes from 8.8.8.8: icmp_seq=1 ttl=118 time=16.7 ms (DUP!)
64 bytes from 8.8.8.8: icmp_seq=1 ttl=118 time=16.8 ms (DUP!)
64 bytes from 8.8.8.8: icmp_seq=1 ttl=118 time=17.0 ms (DUP!)
64 bytes from 8.8.8.8: icmp_seq=1 ttl=118 time=17.2 ms (DUP!)
64 bytes from 8.8.8.8: icmp_seq=1 ttl=118 time=17.7 ms (DUP!)

HTTP monitors are not working and monitor traffic also replicates. See example below for HTTP monitor traffic, where 172.16.15.15 is the pool member on a unit with 8 tmms:

Environment

  • BIG-IP VE, after upgrade
  • HTTP Monitors not working after upgrade
  • Outgoing packets from BIG-IP
  • Third party network devices, using multicast MAC addresses

Cause

Bug ID 946089: BIG-IP might send excessive multicast/broadcast traffic.

Recommended Actions

This issue happens when the destination MAC address is a multicast MAC address, it can be worked around by changing the third party destination devices not to use Multicast MAC addresses, or by changing to in-TMM Monitoring.
