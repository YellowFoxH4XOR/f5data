Topic

Summary

The ARX system uses an aggressive minimum TCP retransmission timeout (RTO Minimum) of 10 milliseconds.

Description

Low latency is critical in a network storage environment. The ARX system, by default, uses a low TCP retransmission timeout (RTO Minimum) of 10 milliseconds. A retransmission timeout (RTO) occurs when the ARX system is missing too many acknowledgments from the filer, and the ARX system takes a timeout and stops sending data altogether.

This is not a problem on a low-latency network. However, on a network where high latency is present, the ARX system may get into an aggressive request cycle when the filer consistently delays its responses beyond the RTO. 

As of ARX 5.2.0, the TCP stack of the ARX NSM has been modified to allow an F5 network support engineer to adjust the minimum TCP retransmit time. The enhancement allows for an increase to the default RTO from 10 milliseconds to 100 milliseconds.

Note: As part of ID 38536, F5 also introduced a workaround option in ARX 5.0.6 HF9 (build 11775), 5.1.5 HF3 (build 11972), and 5.1.7.

Recommendations

  • When encountering a timeout issue, you should consider the following factors:

    • What is the root cause of the timeout?
    • Can you resolve the timeout issue instead of increasing the RTO minimum value on the ARX system?
  • To implement an increase of the RTO Minimum value, contact F5 Technical Support for assistance and reference this article, ID 38536, and ID 339824.
