Topic

NFS access list rules are processed in the order in which they are entered into the configuration, and take effect when you exit gbl-nfs-acl mode.

You may delete or add rules. The additive operation always appends the rule to the list. Therefore, to reorder an NFS access list, you must delete every rule at or below the point of the change in the list, and add rules in the correct order to form the end of the list. You may perform this process manually using the ARX CLI or using the ARX Manager GUI.

In most cases, it is easiest to reorder an NFS access list by modifying it in a text editor, and then using the CLI to delete and re-enter the whole list. To do so, perform the following procedure:

Reordering an NFS access list

  1. Display the NFS access list in question using the following command syntax:

    show nfs-access-list

    The command output appears similar to the following example:

      Access List Name: list1
      Description:
      NIS Domain:                (none)
      Anonymous UID:             65534
      Anonymous GID:             65534
      Number of References:      0

    permit 10.0.20.0 255.255.255.0 read-write root squash
    deny  10.0.30.0 255.255.255.0
    permit 10.0.0.0 255.255.0.0 read-write root squash
  2. Copy and paste the series of lines beginning with permit or deny into a text editor, and insert new rules, rearrange the rules, and prepare the necessary no permit and no deny statements to initially clear the list.

    For example, you may begin with this list of rules from the example in Step 1:

    permit 10.0.20.0 255.255.255.0 read-write root squash
    deny  10.0.30.0 255.255.255.0
    permit 10.0.0.0 255.255.0.0 read-write root squash

    Based on the above example, supposing a malicious client exists at 10.0.20.20, a rule is inserted that adds the following deny statement to the top of the list. The list of rules now appears similar to the following example: 

    deny 10.0.20.20 255.255.255.255
    permit 10.0.20.0 255.255.255.0 read-write root squash
    deny  10.0.30.0 255.255.255.0
    permit 10.0.0.0 255.255.0.0 read-write root squash

    At this point you may also use the text editor to prepare the necessary no permit and no deny statements to remove the existing rules. For example:

    no permit 10.0.20.0 255.255.255.0 read-write root squash
    no deny  10.0.30.0 255.255.255.0
    no permit 10.0.0.0 255.255.0.0 read-write root squash

    Note: The removal statements are a second copy of the original sample with the word no added at the beginning of each line.
  3. Enable privileged mode by typing the following command:

    enable
  4. Enter global mode by typing the following command:

    global
  5. Configure the NFS access list in question using the following command syntax:

    nfs-access-list <list-name>

    Replace <list-name> with the name of the NFS access list you want to configure.

    For example:

    nfs-access-list list1

    You are now in gbl-nfs-acl mode.
  6. From gbl-nfs-acl mode, delete the existing rules from the NFS access list.

    Note: These changes will not take effect until you exit gbl-nfs-acl mode. You may edit them at your leisure and review the results before exiting.

    For each rule that must be deleted, use the no permit or no deny statement with the IP subnet and netmask, using the following command syntax:

    no [permit/deny] [subnet] [mask]

    To delete the rules from the example in Step 2, enter the following commands:

    no permit 10.0.20.0 255.255.255.0 read-write root squash
    no deny 10.0.30.0 255.255.255.0
    no permit 10.0.0.0 255.255.0.0 read-write root squash
  7. Input the new rules in the correct order, either manually or with the list prepared in a text editor.

    Note: For the full syntax of the permit and deny statements, refer to the ARX CLI Reference Guide.

    Following the above example, you would input the following commands:

    deny 10.0.20.20 255.255.255.255
    permit 10.0.20.0 255.255.255.0 read-write root squash
    deny 10.0.30.0 255.255.255.0
    permit 10.0.0.0 255.255.0.0 read-write root squash
  8. Verify the changes to the list with the show nfs-access-list command, using the following command syntax:

    show nfs-access-list [list-name]

    The command output appears similar to the following example:
     
      Access List Name: list1
      Description:
      NIS Domain:                (none)
      Anonymous UID:             65534
      Anonymous GID:             65534
      Number of References:      0

    deny  10.0.20.20 255.255.255.255
    permit 10.0.20.0 255.255.255.0 read-write root squash
    deny  10.0.30.0 255.255.255.0
    permit 10.0.0.0 255.255.0.0 read-write root squash
     
  9. Return to privileged mode by typing the following command:

    end
