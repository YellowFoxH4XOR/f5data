Known Issue

This is the result of a known issue. In BIG-IP ASM 10.0.0 and later, the system does not validate escape sequences within user-defined attack signature rules when you create the rule. An escape sequence that contains invalid syntax causes the BIG-IP ASM Apply Policy function to fail, and the system does not commit changes to the BIG-IP ASM security policy. When this failure occurs, the system displays error messages in the Configuration utility that appears similar to the following example:

Apply Configuration
Could not apply Policy; Error : Failed to set active - Set active failed

User-defined attack signature rules can match special characters if you enter the hexadecimal equivalent values of the ASCII character into an escape sequence in the rule. You must separate multiple hexadecimal pairs by a space character. For example, to match the string X""X in an HTTP request, the rule must appear as follows:

content:"X|22 22|X";

Although there is no space between the double quotes in the string you are matching, you must include a space between the hexadecimal values for the double quotes (22) in the rule.

If you write the escape sequence with no delimiters (|2222|), BIG-IP ASM allows you to create the rule even though the syntax is invalid. The system will not apply a policy containing such a rule and will report the previously-mentioned error message.

F5 Product Development tracked this issue as ID 352243.

Workaround

If you have created a rule that is syntactically invalid and is preventing the system from applying the BIG-IP ASM security policy, you can work around this issue by either deleting the offending rule, or editing the offending rule and modifying the escape sequence to a syntactically valid string

Note: For more information about using escape characters, refer to K8915: Using escape characters in user-defined attack signatures, and the Configuration Guide for BIG-IP Application Security Manager.
