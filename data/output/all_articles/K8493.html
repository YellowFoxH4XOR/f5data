K8493: Installing a version of BIG-IP software prior to 9.3.1 can fail after installing BIG-IP 9.3.1

Known Issue

This is the result of a known issue. If BIG-IP 9.3.1 is installed on a BIG-IP system, and a BIG-IP version prior to 9.3.1 is installed into the last slot on the boot drive, the installation may fail.

For example, if BIG-IP 9.3.1 is installed on slot HD1.1 of a BIG-IP 1500 system, and BIG-IP 9.1.2 is installed on slot HD1.2 on the boot drive of the BIG-IP 1500 system, the 9.1.2 installation may fail. A change in the newer BIG-IP installer script causes the partition table to be incompatible with the installer script from the previous BIG-IP versions.

The last slot on the boot drive varies depending on the BIG-IP platform. The BIG-IP 1500 and 540 platforms use slot HD1.2, and the BIG-IP 3400, 6400, and 6800 platforms use slot CF1.1.

When the installation fails, the installer transfers the installation packages and then fails to create the partition table. The following console output shows the installation error message while installing the BIG-IP 9.1.2 on slot HD1.2:

install.info: 231 of 245 packages transferred...
install.info: 236 of 245 packages transferred...
install.info: 245 of 245 packages transferred.
install.info: BACKUP data ...
install.info: BACKUP HD1.2::otcu.ucs
install.info: BACKUP HD1.2::renamed_otcu.ucs
install.info: Disk update: removing partition (hda.4)
install.info: Creating boot image locations...
install.info: Creating partition: hda4
install.error: An installation error has occurred; code 1

F5 Product Development is tracking this issue as CR87517.

Workaround

You can work around this issue if you have attempted to install a previous version of BIG-IP software after installing BIG-IP 9.3.1 and the installation of the older version failed. To do so, use the bigpipe config save command to back up the current BIG-IP configuration, and then use the wipedisk command to clear the master boot record (MBR). By clearing the MBR, the BIG-IP system's installation script correctly repartitions the drive during the ensuing installation. For more information about using the wipedisk command to clear the MBR, refer to K6346: Recovering from a corrupt drive partition.

Note: Running the wipedisk command clears all BIG-IP configurations on the system.
