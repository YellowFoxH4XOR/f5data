Description

Smtp-server object ("System >> Configuration: Device : SMTP >> [object-name]") is used by the AVR, ASM and APM modules to deliver generated reports.

Note: "smtp-server" object and "outbound-smtp" object are used for different purpose. See K45161233 for more in detail.

On GUI, there is a "Test Connection" button that helps to check connectivity between BIG-IP and Mail Transfer Agent (MTA).

While pressing "Test Connection" button, an error "SMTP Error: Could not connect to SMTP host." may be displayed on GUI despite there should be no TCP connectivity problem.

Figure: GUI sys smtp-server configuration

 

Environment

  • MTA returns STARTTLS against EHLO message from BIG-IP, however, MTA does not fully agree with TLS encryption  (i.e., TLS protocol error / MTA configuration error...etc) .
  • Error persists even after specifying "No encryption" option at "Encrypted Connection" option.

 

Cause

Bug ID868801. "No encryption" option is ignored while using "Test Connection" button.

If you take a packet capture while error is generated, you will see BIG-IP receives STARTTLS message from MTA and after then BIG-IP erroneously tries to do STARTTLS session (despite "No Encryption" option is selected). Here, if MTA disagrees in STARTTLS, then "SMTP Error: Could not connect to SMTP host." generic error is thrown. You will see there is no TCP level connectivity issue presents.

Figure: packet capture of error case (STARTTLS negotiation failure)

 

If, fortunately, MTA supports STARTTLS encryption, error does not happen and SMTP connection will resume with encryption (regardless of "Encrypted Connection" option).

Figure: packet capture of working case

 

Recommended Actions

Consider using local MTA which supports TLS encryption.
