K000157943: [F5OS] Tenant Deployment Failure Due to OS and Service Version Mismatch

Type
Support Solution
Published
2025-11-23
Updated
2026-09-10
Applies to
  • F5OS
  • F5OS-A: 1.8.X, 1.8.3, 1.8.0
Source
https://my.f5.com/manage/s/article/K000157943

Description

This article describes an issue that may occur after upgrading an F5OS-A rSeries host, where tenants fail to deploy successfully. The main symptom is a mismatch between the OS version and the service version on the host, as shown in system version output.

You will get following prompt while logging to the appliance CLI through root credentials:

root@appliance-1(hostname):Waiting for cluster status] ~

Also you can verify the software version using the command after login to appliance using admin credentials:

hostname# show system version 
system version os-version 1.8.0-16036
system version service-version 1.7.0-8741
system version product F5OS-A

Environment

  • F5OS-A platform
  • Upgrade of rSeries host
  • Unable to deploy tenants following upgrade

Cause

Mismatch between OS and service versions after upgrade; service version was not updated to match the new OS version.

Recommended Actions

  • Check current OS and service versions using: show system version
  • If service-version does not match os-version, update it using: system image set-version service-version <version-to-be-upgrade> proceed yes
  • Post reboot verify cluster health and confirm tenant deployment is successful.

Additional Information

  • Aligning the service version with the OS version followed by a reboot restores cluster health and enables tenant deployment.
  • Always verify both OS and service versions post-upgrade.
