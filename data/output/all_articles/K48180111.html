Known Issue

IPsec tunnels may fail to establish.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system is a multiple blade chassis device.
  • You have configured the BIG-IP system with an IPsec policy.
  • You issue the command bigstart restart on a secondary blade of the chassis.

Impact

The IPsec tunnels no longer establish.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • IPsec tunnels are not created as configured in the IPsec policy.
  • When you view the /var/log/racoon.log file of the primary blade, a limited set of log messages similar to the following example are contained in the log file.

    INFO: @(#)ipsec-tools 0.7.3 (http://ipsec-tools.sourceforge.net)
    INFO: @(#)This product linked OpenSSL 1.0.1l-fips 15 Jan 2015 (http://www.openssl.org/)
    INFO: Socket /var/run/rd0.sock created for route domain: 0

    Note: The above racoon service log shows that the racoon service startup is incomplete.

Workaround

To work around this issue, you can restart the tmipsecd service. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) of the primary blade.
  2. To restart the tmipsecd service, type the following command:

    restart /sys service tmipsecd

  3. To exit the tmsh utility, type the following command:

    quit
