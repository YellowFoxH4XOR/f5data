Source

Description

Partition /var/asmdata1 with around 80% space consumed.

Environment

ASM provisioned

Cause

The "/var/asmdata1" partition is where the request log resides, so some growth is expected. Eventually the cleaning mechanism kicks in to keep the size of the request log in check.

Recommended Actions

You can confirm if old logs are being cleared as expected

  1. Connect to CLI
  2. Check for log message that contains "delete_unused_protobuf_files" on /var/log/ts/asmlogd.log

    cat /var/log/ts/asmlogd.log | grep "delete_unused_protobuf_files"

  3. The output should be similar to:
    asmlogd|INFO|Oct 13 06:25:36.826|asm.example.com::RequestLog::delete_unused_protobuf_files,,Dropping protobuf file /var/asmdata1/request_log/0000017806
    asmlogd|INFO|Oct 13 07:20:54.194|asm.example.com::RequestLog::delete_unused_protobuf_files,,Dropping protobuf file /var/asmdata1/request_log/0000017807
    asmlogd|INFO|Oct 13 07:54:21.753|asm.example.com::RequestLog::delete_unused_protobuf_files,,Dropping protobuf file /var/asmdata1/request_log/0000017808
    asmlogd|INFO|Oct 13 08:23:13.010|asm.example.com::RequestLog::delete_unused_protobuf_files,,Dropping protobuf file /var/asmdata1/request_log/0000017809
