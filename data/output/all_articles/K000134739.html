Description

If you need to reset a lost or forgotten root or admin user password on the F5 rSeries system, you need to first restart the F5 rSeries system to single-user mode before performing a series of commands to reset the root or admin user password.

Note: Performing the procedure described in this article only reset the root or admin user password. It does not disable the Appliance mode if enabled on the F5 rSeries hardware product. To enable or disable Appliance mode on the F5 rSeries hardware product, refer to K32730113: Overview of Appliance mode for F5OS on VELOS and rSeries systems.

Environment

  • F5 rSeries hardware products: r2000, r4000, r5000, r10000 series
  • F5OS-A 1.3.x and later
  • Serial console access to the F5 rSeries hardware product

Cause

You need to reset the password for an administrative account, such as the root or admin user on F5OS-A 1.3.x and later.

Recommended Actions

To reset the root or admin user password on the F5 rSeries system, perform the following procedure:

Impact of procedure: This procedure requires that you restart the F5 rSeries system in single-user mode. While in this mode, the F5 rSeries system is unable to run any tenants and does not process any traffic. F5 recommends that you perform this procedure during a maintenance window.

  1. Connect a terminal to the F5 rSeries system serial console port.
  2. Invoke the AOM Command menu from the serial console by entering Esc ( key sequence. The AOM Command menu should look similar to the following example:

    AOM Command Menu:
    A --- Reset AOM
    B --- Set baud rate
    I --- Display platform information
    N --- Configure AOM network
    P --- Power on/off host subsystem
    R --- Reset host subsystem
    S --- Configure SSH server
    U --- Front panel USB port
    Q --- Quit menu and return to console

    Enter Command:

  3. Enter P to invoke the power on/off host subsystem option.
  4. Enter 0 (number zero) to indicate you want to power off the host subsystem. The AOM system prompts for confirmation; enter y to confirm and initiate a power off of the host subsystem. The AOM system will display the AOM Command menu when the host subsystem is powered off.
  5. Enter P to invoke the power on/off host subsystem option again.
  6. To power on the host subsystem, enter 1 (number one). This is followed by a confirmation prompt by the AOM system; enter y to confirm and initiate a power on of the host subsystem. The AOM system will then display the AOM Command menu.
  7. Enter Q to exit the AOM Command menu and return to the host subsystem serial console. You should now see the F5 rSeries system displaying the power on sequence followed by the GRUB menu and counts down before continuing the startup process.
  8. Before the countdown expires, enter e to edit the start options for the first boot image.

          CentOS Linux 7 (Core) (ostree:0)    <---enter e to edit this first boot image
          CentOS Linux 7 (Core) (ostree:1)



          Use the ^ and v keys to change the selection.
          Press 'e' to edit the selected item, or 'c' for a command prompt.

    The system should bring up the GRUB edit screen.

  9. Use the arrow keys to move the prompt to the line that starts with linuxefi. For example,

    linuxefi /ostree/velocity-82a9103adb33ccade74ce581ecb3765ab4dba0f3919e14db851b\
    b533b238415b/vmlinuz-3.10.0-1160.71.1.F5.1.el7_8.x86_64 intel_iommu=on iommu=p\
    t acpi_osi=Linux quiet isolcpus=24,25,26,27,28,29 intel_pstate=disable crashke\
    rnel=auto rd.md.uuid=123310f3:cb28bae2:06f58a53:d7401a86 rd.md.uuid=a662f8ac:4\
    55960f5:6237f918:8c852295 rd.lvm.lv=velocity/root rd.lvm.lv=velocity/swap cons\
    ole=ttyS0 root=/dev/mapper/velocity-root ostree=/ostree/boot.0/velocity/82a910\
    3adb33ccade74ce581ecb3765ab4dba0f3919e14db851bb533b238415b/0

  10. Use the End key or use the right arrow key to go to the end of line.
  11. Enter a space followed by the word rd.break at the end of the linuxefi line. Using the previous example, it should appear similar to the following example:

    linuxefi /ostree/velocity-82a9103adb33ccade74ce581ecb3765ab4dba0f3919e14db851b\
    b533b238415b/vmlinuz-3.10.0-1160.71.1.F5.1.el7_8.x86_64 intel_iommu=on iommu=p\
    t acpi_osi=Linux quiet isolcpus=24,25,26,27,28,29 intel_pstate=disable crashke\
    rnel=auto rd.md.uuid=123310f3:cb28bae2:06f58a53:d7401a86 rd.md.uuid=a662f8ac:4\
    55960f5:6237f918:8c852295 rd.lvm.lv=velocity/root rd.lvm.lv=velocity/swap cons\
    ole=ttyS0 root=/dev/mapper/velocity-root ostree=/ostree/boot.0/velocity/82a910\
    3adb33ccade74ce581ecb3765ab4dba0f3919e14db851bb533b238415b/0 rd.break

  12. Select Ctrl-X to apply the change.
  13. After the single-user mode startup sequence completes, a command-line prompt displays switch_root:/#. The system is now in single-user mode.
  14. Re-mount the /sysroot and /sysroot/sysroot file systems as read-write by entering the following command:

    mount -o remount,rw /sysroot && mount -o remount,rw /sysroot/sysroot

  15. Change the root file system using chroot:

    chroot /sysroot

    The prompt should now display sh-4.2#

  16. Change the root or admin user password using the following command syntax:

    passwd <user>

    For example, you would enter passwd root if you are changing the root user password.

    The system may display errors similar to the following example but it is safe to ignore them:

    /sbin/pam_exec failed: exit code 2
    passwd: Authentication token manipulation error

    Important: Watch out for BAD PASSWORD errors, such as 'it is too simplistic/systematic', 'it is too short', 'is too simple', etc. These errors are not safe to ignore. If you run into them you must redo step 16 with a more complex password.

  17. Load a SELinux policy into the kernel by entering the following command:

    load_policy -i

  18. Restore the default SELinux security context for /etc/shadow file by entering the following command:

    restorecon -v /etc/shadow

  19. Create a shadow.tracker file in the /etc/libnss-udr directory by entering the following command syntax:

    awk -F: '/^<username>:/{print "<username> <username>", $2, $3}' /etc/shadow >> /etc/libnss-udr/shadow.tracker

    For example, you would enter the following command for the root user:

    awk -F: '/^root:/{print "root root", $2, $3}' /etc/shadow >> /etc/libnss-udr/shadow.tracker

    The presence of this file ensures that the system syncs up the passwords in both the /etc/shadow as well as the copy of this file in the controller_userman service and the ConfD database. After completion of the operation, the shadow.tracker file will be removed.

  20. Exit the chroot by entering the following command:

    exit

    The command prompt should now display the single-user mode prompt switch_root:/#.

  21. For F5OS-A 1.x: Exit the single-user mode and start up the system by entering the following command:
    exit
    For F5OS 2.x: You must reboot the system by entering the following command:
    rebootNote: If you have typed "exit" instead of "reboot", the system will be rendered inoperative until you manually reboot, or until the system reboots automatically after various daemons timeout on system startup.
