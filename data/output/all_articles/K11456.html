Known Issue

This is the result of a known issue. When the Selective ACKs option is enabled in a TCP profile, the BIG-IP system performs a retransmission when a lost segment or packet, also referred to as a hole in the data stream, is reported by the client in a TCP Selective Acknowledgment (SACK) message. However, if the client uses a small TCP send window, TMM may panic and core when retransmitting data in response to a TCP SACK message. When this issue occurs, an error message that appears similar to the following example is logged to the /var/log/tmm file:

panic: Request for segment from middle of queue.

Additionally, if the BIG-IP system is configured as a redundant pair with connection mirroring enabled, TMM will also core on the standby unit when this issue occurs.

Selective Acknowledgment is a TCP feature that can improve packet flow over lossy networks. This feature allows the receiver to inform the sender of which segments were successfully received, so that only the lost segments are retransmitted. The Selective Acknowledgment feature is a negotiated option, and is automatically disabled if it is not supported by the TCP peer. By default, the Selective ACKs option is enabled for TCP profiles.

F5 Product Development tracked this issue as CR130310 and CR130313, and it was fixed in BIG-IP 10.1.0. For information about upgrading, refer to the BIG-IP LTM, ASM, PSM, Link Controller, or WebAccelerator release notes.

Additionally, this issue has been fixed in Hotfix-BIGIP-9.4.8-407.0-HF4, which has been issued for BIG-IP 9.4.8. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

For information about installing a hotfix for version 9.x systems, refer to K6845: Managing BIG-IP product hotfixes (9.x).

Workaround

You can work around this issue by disabling the Selective ACKs option in the TCP profile associated with the virtual server. To do so, perform the following procedure:

Note: F5 does not recommend modifying the default TCP profiles. If the virtual server uses a default TCP profile, configure a child TCP profile as described in the following procedure and the associate it with the virtual server.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles.
  3. From the Protocol menu, select TCP.
  4. Select the name of the TCP profile associated with the virtual server.
  5. Clear the Selective ACKs check box.
  6. Click Update.
