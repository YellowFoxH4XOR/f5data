Topic

This article describes how to configure the BIG-IP APM system as an OAuth client with a Microsoft Entra ID OAuth authorization server.

Note: Microsoft Entra ID is formerly known as Azure Active Directory, Azure AD. For more information, refer to Azure Active Directory is now Microsoft Entra ID. You may see instances of both used in this article as the default BIG-IP APM resources continue to use Azure AD. For example, the default Azure AD OAuth provider as seen in the Configuration utility, is named Azure_AD_Provider.

Description

This article guides you through implementing OAuth authentication with the BIG-IP APM system as the OAuth Client/Resource Server with Microsoft Entra ID as the OAuth provider:

Figure: BIG-IP APM system as OAuth Client/Resource Server with Azure AD OAuth provider

The following describes the sequence of exchanges between the systems for OAuth authentication to take place:

  1. The user accesses a resource protected by the BIG-IP APM system.
  2. The BIG-IP APM system redirects the user to an OAuth 2.0 provider, such as Microsoft Entra ID, Facebook, Twitter, Google, or another Enterprise Authorization Server (AS).
  3. The OAuth 2.0 provider authenticates the user.
  4. The OAuth 2.0 provider redirects the user back to the BIG-IP APM system with an authorization code.
  5. The BIG-IP APM system exchanges the authorization code for an access token with the OAuth provider.
  6. The BIG-IP APM system retrieves the user settings from the OAuth provider using the access token.
  7. The system performs the access control decision based on the retrieved user settings.

The following describes the user experience:

  • You connect to an LTM-APM virtual server on the BIG-IP APM system.
  • The BIG-IP APM uses the access policy to authenticate and direct you to the Microsoft Entra ID authentication and authorization server.
  • You provide your Microsoft Entra ID credentials to the Microsoft identity platform v2.0 service.
  • After the server authenticates you, the Microsoft Entra ID authorization server issues an access token and redirects you back to the BIG-IP APM system.
  • The BIG-IP APM system allows you to access the back-end web service configured in a BIG-IP LTM pool.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You have already created a BIG-IP LTM pool on the BIG-IP system with servers providing a web service.
  • There is network connectivity among the client devices, the BIG-IP APM system, and authentication service.
  • There is network connectivity between BIG-IP APM system and authentication service.
  • You have a Microsoft Azure account to configure the authentication services based on Microsoft identify platform v2.0.

Important: With the release of Microsoft identity platform v2.0, the previous version, v1.0, is deprecated. For differences between the two, refer to Why update to Microsoft identity platform (v2.0).

Procedures

The main building blocks of the set up consists of the following:

  • Microsoft service
  • BIG-IP APM as OAuth client and resource server
    • Virtual server
    • Access profile/access policy
      • OAuth Client (Access policy Visual Policy Editor)
      • OAuth Client / Resource Server
        • OAuth Server
        • Provider

Perform the following procedures to build these objects:

  • Configure an application in the Azure portal
  • Configure a BIG-IP APM OAuth client / Resource Server
    • AzureAD provider
    • AzureAD OAuth server
  • Create a new access profile and access policy
  • Create a virtual server for user access
  • Access the service from a client

Configure an application in the Azure portal

In Azure portal, you need to register a new application. Note down the following values as you perform the steps in this procedure for use in subsequent procedures in this article.

ParametersValue
Client IDYou can obtain this value by selecting the top-left menu and selecting Microsoft Entra ID > App registrations > <your app name>.
Client secretRecord this value down when you first create the secret.
Tenant IDYou can obtain this value by selecting the top-left menu and selecting Microsoft Entra ID > App registrations > <your app name>.
Tenant namef5tenant
Application URLhttps://apm.f5tenant.com

Perform the following procedure to create and configure your new application in MS Azure:

Note: Microsoft may update the following procedure without our knowledge. For more information on creating and managing tenanats and Apps in MS Azure, refer to Microsoft Identity platform in the Microsoft documentation.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to Azure portal.
  2. Select Microsoft Entra ID. You can also search with Copilot to display the Microsoft Entra ID option.
  3. Create a new tenant. (This step is optional if you already have an existing tenant)
    1. Select Manage tenants.
    2. Select Create.
    3. For Select a tenant type, select Microsoft Entra ID.
    4. Select Next: Configuration.
    5. For Organization name and Initial domain name, enter f5tenant.

      Note: If you observe the error Already in use by another directory, enter a different name that is not in use.

    6. Select Next: Review + Create.
    7. Select Create.
  4. Switch to the new tenant you created in the previous step.
    1. Select the top-left menu icon and select Microsoft Entra ID.
    2. Select Manage tenants.
    3. Select the new tenant you created in the previous step and select Switch.
  5. Register a new app
    1. Go to All Services > App registrations.
    2. Select New registration.
    3. Enter a name for your app. For example, apm.
    4. For Redirect URI, select Web and enter the following:

      https://apm.f5tenant.com/oauth/client/redirect

    5. Select Register.
    6. Note the Client ID and Tenant ID values.
  6. Configure your new app. Go to All Services > App registrations > <name of your app>, search, and perform the following configurations:
    1. Select Authentication.
      1. Enter a Logout URI. For example:

        https://apm.f5tenant.com/oauth/logout

    2. Select Certificates & secrets.
      1. Select New client secret.
      2. Provide a description, select In 2 years and select Add.
      3. Copy the value of the client secret to clipboard and note it. Note copy the Value not the Secret ID
    3. Select Expose an API. Define custom scopes to restrict access to data and functionality protected by the API. An application that requires access to parts of this API can request that a user or admin consent to one or more of these.
      1. Select the Set link to set a globally unique application ID URI.
      2. Select Save.
      3. Select Add a scope.
      4. Provide a scope name. For example:

        example.resource

      5. Select Admins and users.
      6. Enter values for Admin consent display name, Admin consent description, User consent display name, and User consent description as appropriate for your application.
      7. Select Add scope.
    4. Select API permissions.
      1. Verify that the User.Read (Delegated) (Sign in and read user profile) permission is granted to Microsoft Graph.

        Note: If not granted, you can select Add a permission > Microsoft Graph > Delegated permissions > User > User.Read to grant it.

      2. Select Grant admin consent for f5tenant.
      3. Select Yes.
      4. Select Add a permission.
      5. Select My APIs and the name of your app.
      6. Select the name of the scope you created in the previous step: Expose an API.
      7. Select Add permissions.
    5. Select Manifest.
      1. Locate the line with groupMembershipClaims and replace null with "All". For example:

        "groupMembershipClaims": "All",

      2. Locate the line with accessTokenAcceptedVersion and replace null with "2". For example:

        "accessTokenAcceptedVersion": "2",

      3. Select Save.

Configure a BIG-IP APM OAuth client / Resource Server

AzureAD Provider

In this section, you configure the Microsoft Azure AD OAuth provider, specifying the OpenID URI that the BIG-IP APM system communicates with.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Access > Federation > OAuth Client / Resource Server > Provider.
  3. Select Create.
  4. Enter the values for each of the settings in the following table.
    SettingValue
    NameAzure_AD_Provider
    TypeMS Identity Platform 2.0
    OpenID URIReplace the _tenantid_ string with <Tenant Name>.onmicrosoft.com , where <Tenant Name> is the name you noted in the Configuring an application in the Azure portal procedure.

    For example, if your <Tenant_Name> is f5tenant, enter the following:

    https://login.windows.net/f5tenant.onmicrosoft.com/v2.0/.well-known/openid-configuration

  5. Select Discover.

    Note: After the discovery process completes, observe that the _tenantid_ values in the Authentication URI and Token URI are replaced with the Tenant ID you noted in the Configuring an application in the Azure portal procedure.

  6. Select Finished.

AzureAD OAuth Server

The OAuth Client is the interface on the BIG-IP APM that communicates with the Microsoft Entra ID service. The essential values are the Client Id and Client Secret, which identify the specific MS Azure app you created previously.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Access > Federation > OAuth Client / Resource Server > OAuth Server.
  3. Select Create.
  4. For DNS Resolver, select the appropriate selection or create one by selecting the add icon (+) and performing the following steps:
    1. For Name, enter azureNSResolver.
    2. Select Finished to return to the New OAuth Server Configuration page.
  5. Fill in the remaining settings with the values in the following table.
    SettingValue
    NameAzureAD_Server
    ModeClient
    TypeMS Identity Platform 2.0
    OAuth providerAzureAD_Provider

    Note: This is the name of the provider you created in the previous step.

    Client IDEnter the Client Id you noted in the Configuring an application in the Azure portal procedure. Step 5f
    Client SecretEnter the Client Secret you noted in the Configuring an application in the Azure portal procedure. Step 6b
    Client's ServerSSL Profile Nameserverssl-insecure-compatible

    Note: This value is the SSL profile the BIG-IP APM uses in its SSL handshake with the Microsoft Entra ID service. You should configure your own SSL profile and Trusted Certificate Authorities in production.

  6. Select Finished.

Create a new access profile and access policy

The access profile and access policy determine how the BIG-IP system authenticates and authorizes user logon. The OAuth Client action you configure here selects the OAuth Client configured in the previous step.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Access > Profiles / Policies > Access Profiles (Per-Session Policies).
  3. Select Create.
  4. For Name, enter OAuthClientToAzureAD.
  5. For Profile Type, select All.
  6. Under Languages Settings, for Language, in the Factory BuiltIn Languages, select English and move it to the Accepted Languages list.
  7. Select Finished.
  8. From the list of access policies, for the one you just created, select Edit to open the Visual Policy Editor (VPE).
  9. Create an OAuth Client to authenticate the user using Microsoft Entra ID services.
    1. Select the Add icon (+) on the fallback branch for Start.
    2. Select the Authentication tab, select OAuth Client, and select Add Item.
    3. Fill in the settings with the values in the following table.
      SettingValues
      ServerAzureAD_Server

      Note: The name of the OAuth server you created in the previous step.

      Grant TypeAuthorization Code
      OpenID ConnectEnabled
      OpenID Connect Flow TypeAuthorization Code
      Authentication Redirect Request/Common/MSIdentityPlatform2.0AuthRedirectRequest
      Token Request/Common/MSIdentityPlatform2.0TokenRequestByAuthzCode
      Refresh Token Request/Common/MSIdentityPlatform2.0TokenRefreshRequest
      OpenID Connect UserInfo RequestNone
      Redirection URIUse the default setting.
    4. Select Save.
  10. On the successful branch following the OAuth Client policy item, select the Deny endpoint.
  11. Select Allow and select Save.

Create a virtual server for user access

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Virtual Servers.
  3. Select Create.
  4. For Name, enter ltm-apm-azuread-oauthVS.
  5. For Destination Address/Mask, enter the appropriate IP address. For example, 10.10.10.5.
  6. For Service Port, enter 443.
  7. For SSL Profile (Client), in the Available list, select clientssl and move it to the Selected list.
  8. For SSL Profile (Server), in the Available list, select serverssl and move it to the Selected list.

    Note: The BIG-IP LTM pool member supports HTTPS.

  9. For HTTP Profile, select http.
  10. For Source Address Translation, select AutoMap.
  11. For Access Profile, select OAuthClientToAzureAD.

    Note: This is the access profile you created in the Create a new access profile and access policy procedure.

  12. For Default Pool, select the pool for your back-end web servers.
  13. Select Finished.

Access the service from a client

After completing the configuration, perform the following procedure on a client to test the service:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to your client device.
  2. Using the previous example configuration, add the following example entry to the host file:

    10.10.10.5 apm.f5tenant.com

    Note: This is the IP address you assigned to the virtual server created in step 5 of the Create a virtual server for user access procedure. The apm.f5tenant.com URL is the URL you noted down in the Configure an application in the Azure portal procedure.

  3. Access https://apm.f5tenant.com from a browser.
  4. Enter or select your Microsoft Entra ID account.
  5. Enter your password.
  6. When your login is successful, you are taken to the virtual server's pool to access the back-end service.
