K5033: Web aggregation (OneConnect) processing of certain responses has been made more compliant with standards

Topic

Prior to BIG-IP versions 4.5.13, BIG-IP does not ignore the Content-Length header and body, as required by RFC2616. In addition when the protocol is HTTP 1.0, BIG-IP does not ignore the Content-Length header and the body for HTTP HEAD responses and 304 status messages.

If an HTTP 304 response that contains a Content-length header is processed by a virtual server that uses a delayed binding feature, BIG-IP will wait for further data from the node before continuing with the connection. Since no further data should arrive from the node after it sends an HTTP 304 response, the connection may hang indefinitely.

F5 Networks Product Development tracked this issue as CR46649, CR46650, CR47070 and CR47711 and it was fixed in BIG-IP version 4.5.13 for the 4.5 software branch. For information about upgrading, refer to the BIG-IP Release Notes.

This issue has not been resolved in the BIG-IP version 4.6 branch.

Beginning in versions 4.5.13, BIG-IP is more closely in compliance with standards and will log the following message to /var/log/bigip when it receives a response that incorrectly contains a body:

idle_http_handle_packets_from_server: new data on idle connection: server: <ip_address>:<port>

This behavior change also fixes an issue in which BIG-IP stops passing traffic on a connection while waiting for a body that follows an HTTP 304 message and includes a Content-Length header.
