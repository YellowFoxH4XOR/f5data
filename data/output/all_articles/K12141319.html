Description
Configuration may fail to load when upgrading from 12.1.4 to 12.1.5, or 12.1.X or 13.X.X to 13.1.1.2 onwards if an iRule has a non-existing data-group in it.

After uploading a QKView to iHealth it shows that the configuration failed to load with the following error:

emerg load_config_files: "/usr/bin/tmsh -n -g load sys config partitions all " - failed. -- Loading schema version: 13.0.1 Loading schema version: 13.1.1.2 01070151:3: Rule [/Common/VS_Test] error: Unable to find value_list (in_progress) referenced at line 15: [class match $session eq "in_progress"] Unexpected Error: Loading configuration process failed.

Environment

  • iRule with data-groups
  • Upgrading from 12.1.X - 12.1.4 (fixed in 12.1.5)
  • Upgrading from 12.1.X through 13.1.1.1 or v14 onward (fixed in 13.1.1.2 and v14.0.0.0)

Cause
Due to Bug ID 688629: Deleting data-group in use by iRule does not trigger validation error
The "config validator" didn't trigger any errors while creating an iRule calling a non-existing data-group.

Recommended Actions

  1. Before the upgrade, delete any iRule calling on non-existing data-groups or create the data-groups accordingly.
  2. If you have upgraded the unit already, delete the offending lines from the broken iRule or remove the iRule itself from the configuration file and load the file again using the "tmsh load sys config" command.
Important: During the upgrade process, you can create a new data group with tmsh but cannot save it as mcpd is not fully running. If you cannot edit the config file as above, you must boot back to the prior version and fix the issue there.
Note: Due to the customization and uniqueness of environments, F5 Support is not the best resource for comprehensive assistance in this area. 
However, the implementation, maintenance, and optimization of iRules can be accomplished through F5 Professional Services.

Additional Information
Here's an example of an iRule that would trigger this failure.
Note: The data-group "mydatagroup" wasn't present in the unit configuration, causing the config load issue.

when ACCESS_POLICY_AGENT_EVENT {
         if { [class match $session eq "mydatagroup"] } { <<<<----- Offending line, "mydatagroup" is not a datagroup
            HTTP::redirect "https://test.website.com/"
            }
}
