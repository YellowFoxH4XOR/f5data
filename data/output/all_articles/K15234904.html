K15234904: Basic or Token Auth for a successful F5 REST API call?

Type
Support Solution
Published
2022-07-14
Updated
2026-07-21
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K15234904

Description

You are trying to access the BIG-IP using a REST API call but it fails.

When you try to connect you may see something similar to this when running a curl:

curl -X POST -H "Content-Type: application/json" -d "{\"username\":\"admin\",\"password\":\"xxx \",\"loginProviderName\":\"tmos\"}" https://foo.f5/mgmt/shared/authn/login
{
  "code": 400,
  "message": "loginProviderName is invalid.",
  "referer": "192.168.1.1",
  "restOperationId": 20702660,
  "kind": ":resterrorresponse"
}

Environment

  • Accessing the BIG-IP via F5 REST API
  • TACACS, RADIUS, LDAP, Active Directory, HTTP Basic Authentication

Cause

To access the BIG-IP via REST you must provide authentication to make a successful F5 REST API call. Currently, there are two authentication methods supported: standard HTTP basic authentication and an F5 proprietary token scheme. If both authentication methods are used simultaneously, the token scheme takes precedence.

  • Basic authentication:

    To use basic authentication, include a standard HTTP header as part of the API call. The header looks similar to the following example:

    Authorization: Basic

    When using Base-64 to submit with a username and password the format looks similar to the following example:

    Authorization: Basic YHEtb35Lu01RwqsA

  • Token Based Authentication:

    When using a token, you submit a POST to https://BIG-IP-ADDRESS/mgmt/shared/authn/login. It needs to include a data parameter that triggers the generation of an authentication token. A typical data parameter for the call looks something like the following example:

    {
    "username":"USER",
    "password":"PASSWORD",
    "loginProviderName": "tmos"
    }

    Note: Replace USER and PASSWORD with the actual username and password.

    The response will look similar to the following example, with VUT2YR667OICEHAEKWBGWOJ3HF being the token:

    {"username":"user",
    "loginReference":{"link":"https://localhost/mgmt/cm/system/authn/providers/tmos/1f44a60e-11a7-3c51-a49f-82983026b41b/login"},
    "loginProviderName":"tmos",
    "token":"token":"VUT2YR667OICEHAEKWBGWOJ3HF","name":"VUT2YR667OICEHAEKWBGWOJ3HF",
    "userName":"user",
    "authProviderName":"tmos",
    "user":{"link":"https://localhost/mgmt/cm/system/authn/providers/tmos/1f44a60e-11a7-3c51-a49f-82983026b41b/users/5d9c68c6-c50e-33d0-aa2f-cf54f63993b6"},
    "timeout":1200,
    "startTime":"2017-11-09T14:43:33.101-0800",
    "address":"10.10.2.112",

    Recommended Actions

    The basic authentication method is supported only for local authentication. By default, if you use an external authentication provider, for example, Radius or Active Directory, you cannot use basic authentication but must use token-based authentication. However, you can also configure a local user account to allow remote users to authenticate to iControl using basic authentication. For more information, refer to K84925527: Overview of iControl permissions.
