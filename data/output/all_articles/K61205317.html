Description

AVR DB cannot create tables due to lack of access to create/write changes to files.

The log entries of /var/log/avr look similar to:

DB|ERROR|Jan 13 02:15:39.947|14626|../src/db/MonpdDbAPI.cpp:runStoredProc:0601| Error executing SQL string :
CALL SessionInit(0)
 Because : PROCEDURE AVR.SessionInit does not exist
     DB|ERROR|Jan 13 02:15:39.947|14626|../src/db/MonpdDbAPI.cpp:mysql_query_safe:0208| Error (error number 1) executing SQL string :
SELECT * FROM information_schema.events where event_name LIKE 'InitAvrDB'
 Because : Can't create/write to file '/var/tmp/#sql_4bfc_0.MYI' (Errcode: 13)

Environment

  • AVR module provisioned

Cause

To determine the meaning of "Errcode: 13", use the perror available on any BIG-IP:

  # perror 13
  OS error code  13:  Permission denied


AVR DB has lost permissions to create/edit files in directory /var/tmp

Recommended Actions

Check permisions for directories /var and /shared with following commands, output should look like:

 # ls -Z /var | grep tmp
  lrwxrwxrwx. root  root  system_u:object_r:tmp_t:s0       tmp -> ../shared/tmp
  # ls -Z /shared | grep tmp
  drwxrwxrwt. root root   system_u:object_r:tmp_t:s0       tmp

but the output of command can look similar to:

lrwxrwxrwx. root  root  unconfined_u:object_r:var_t:s0   tmp -> /shared/tmp

This means that directory permission got corrupted and you can try repairing it, e.g.

 # restorecon /shared/tmp

Afterwards, restart services as appropriate, so please restart monpd and mysql.

# bigstart restart monpd mysql

You can also use the following command to fix user and role:

Execute chcon to fix the user and role.

# chcon -h -u system_u -r object_r /var/tmp
