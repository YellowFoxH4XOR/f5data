Description

How to add user/password of Basic Authentication to the request that sends to the upstream servers, in the health_check directive.

Environment

  • NGINX Plus
  • Upstream with Basic Authentication

Recommended Actions

To check the Basic Authentication password-protected URL with active health check, you can use one of the following two methods:

Method 1

Check for 401 status code instead of 2xx or 3xx by doing the following:

Add the match directive in the http context with status 401 and specify the match option with the appropriate status in the health_check directive.

http {
   ...
   match 401_ok {
     status 401;
   }

location / {
   proxy_set_header Host www.example.com;
   proxy_pass http://backend;
   health_check  match=401_ok;
}

Method 2

Move the health check to the dedicated named location and provide credentials so health check can authorize itself.

Specify the proxy_set_header directive Authorization to the base64-encoded value of the appropriate credentials, for example user:password.

Note: To create the base64-encoded value of your credentials, run the following Linux command:

echo "user:password" | base64

The command output appears similar to the following example:

dXNlcjpwYXNzd29yZAo=

location @hc {
   proxy_set_header Host www.example.com;
   proxy_set_header Authorization "Basic dXNlcjpwYXNzd29yZAo=";
   proxy_pass http://backend;
   health_check;
   error_log /var/log/hc_error.log info;
}

The above example contains a separate error_log with info severity to aid in troubleshooting.
