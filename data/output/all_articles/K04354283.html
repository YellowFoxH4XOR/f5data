Description

HTTP Desync Attack mitigation using  tmm.http.rfc.enforcement variable or the "Enforce RFC Compliance" check box is not blocking invalid HTTP traffic for virtual servers using ASM in transparent mode. 

Environment

  • BIG-IP ASM
  • Configured a mitigation of HTTP Desync Attack described in K50375550, ie. set the db value tmm.http.rfc.enforcement to true, or enabled 'Enforce RFC Compliance' checkbox in the HTTP profile.
  • ASM is enabled on the virtual server and its security policy is in transparent mode, or the policy is configured not to block 'HTTP protocol compliance failed' violations.

Cause

This is expected behaviour. When ASM is enabled on a virtual server, its configuration decides what is happening to non-compliant HTTP traffic. LTM-level mitigation is not taking effect in such case.

Recommended Actions

To block non RFC compliant HTTP traffic you can either:
  1. Disable ASM on virtual server by removing or modifying LTM policy assigned to the virtual server while keeping the HTTP Desync Attack mitigation in place.
  2. Put the ASM policy in blocking mode while making sure that 'HTTP protocol compliance failed' violation is set to 'Block'
