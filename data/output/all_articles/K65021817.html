Description

Users could notice intermittent auth failures with iControl REST API and unable to connect to the BIG-IP appliance using REST API calls.

You could notice the following error messages under var/log/secure:

Oct 20 00:52:21 slot3/bigip1 err httpd[12206]: pam_ldap(httpd:auth): error reading from nslcd: Connection reset by peer
Oct 20 00:52:21 slot3/bigip1 notice unix_chkpwd[4042]: password check failed for user (admin)
Oct 20 00:52:21 slot3/bigip1 notice httpd[12206]: pam_unix(httpd:auth): authentication failure; logname= uid=48 euid=48 tty= ruser= rhost=192.168.10.10 user=admin
Oct 20 00:52:23 slot3/bigip1 err httpd[12206]: [auth_pam:error] [pid 12206] [client 192.168.10.10:32287] AUTHCACHE PAM: user 'admin' (fallback: false) - not authenticated: Authentication failure
Oct 20 00:52:23 slot3/bigip1 info httpd(pam_audit)[12206]: User=admin tty=(unknown) host=192.168.10.10 failed to login after 1 attempts (start="Tue Oct 20 00:51:41 2020" end="Tue Oct 20 00:52:23 2020").
Oct 20 00:52:23 slot3/bigip1 info httpd(pam_audit)[12206]: 01070417:6: AUDIT - user admin - RAW: httpd(pam_audit): User=admin tty=(unknown) host=192.168.10.10 failed to login after 1 attempts (start="Tue Oct 20 00:51:41 2020" end="Tue Oct 20 00:52:23 2020").

Environment

  • BIG-IP LTM
  • iControl REST
  • LDAP Authentication

Cause

Issue is due to connection timeout with the LDAP server from the BIG-IP appliance.

Recommended Actions
As a workaround set the auth LDAP idle-timeout to a smaller value on BIG-IP from CLI:

#tmsh modify auth ldap system-auth idle-timeout 175
#save sys config
