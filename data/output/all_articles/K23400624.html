Description

A common practice is to setup and use a script to send emails for specific warnings or system alerts found in the logs. But after an upgrade they no longer work.

Environment

  • Version 12.1.x older and you upgrade to 13.1.x or higher.
  • An email is to be sent on a schedule and a script referencing a cron job is referenced.
  • mailx rpm, SMTP, SNMP, cron

Cause

In versions prior to version 13.1.x it was common to use a script to get daily or weekly emails from the BIG-IP. They used the "mail" command and resembled something like this...

## Mail the output
$result = `/bin/mail -s "$SUBJECT" -c "$CC" "$TO" < $BODY`;

However, after an upgrade that function now fails. The reason for this is the mailx rpm is no longer present on the BIG-IP. Therefore the "mail" command will no longer work.

You can verify if the mailx package is present by running this command:

rpm -qa | grep mailx

The output of the command would be similar to:

mailx-12.4-8.el6_6.i686

Recommended Actions

From 13.1.x and forward the use of SNMP traps and the SMTP protocol functions will need to be used.

K59616664: Configuring email alerts for pool, virtual server, and pool member availability status changes

The ability for the BIG-IP to run scripts is still there but when doing so SMTP will have to be used to mail the output of the commands used.

K14397: Running a command or custom script based on a syslog message
K13180: Configuring the BIG-IP system to deliver locally generated email messages (11.x - 15.x)
