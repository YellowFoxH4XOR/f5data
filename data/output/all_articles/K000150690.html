Description

BIG-IP GTM matches a certificate by x509 Subject orderly from the top.

The following is an example of broken iQuery connection when expired certificate not remove from GTM's server.crt.

Take note of LTM1's device certificate issuer.

[root@LTM1.example.com] # openssl x509 -noout -in /config/httpd/conf/ssl.crt/server.crt -issuer

issuer= /C=US/ST=DE/O=MyCert, Inc./CN=root-ca.example.com

 

Refer to the diagram below, the first and second certificates named 'root-ca.example.com' shares the same x509 Subject.

# openssl x509 -noout -in </path/to/certificate> -subject

subject= /C=US/ST=DE/O=MyCert, Inc./CN=root-ca.example.com

The first certificate has expired. Second certificate is a valid certificate. GTM match certificate orderly from the top. In this example, first certificate will be matched.

 

The result was iQuery connection fails. Similar error message can be found in /var/log/gtm.

GTM1.example.com notice gtmd[18283]: 011ae01c:5: Connection complete to 172.16.20.218. Starting SSL handshake

GTM1.example.com iqmgmt_ssl_connect: IP: 172.16.20.218 SSL error:14090086:SSL routines:ssl3_get_server_certificate:certificate verify failed

 

Environment

  • BIG-IP GTM
  • iQuery

Cause

Duplicate and Expired SSL Certificates can cause iQuery connection to fail

Recommended Actions

  1. Remove expired SSL Certificates from GTM trusted certificate store
  2. Use meaningful and unique entries for the appropriate certificate fields. Avoid using default device certificate with the value of CN=localhost.localdomain

None.
