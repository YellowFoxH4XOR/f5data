Known Issue

This is the result of a known issue. If an HTTP profile is applied to a virtual server deployed in a non-default route domain (a route domain other than 0), the output of the bigpipe conn command fails to show the selected pool member and instead reports any6. This behavior makes it difficult to view or manage connections using the bigpipe conn command.

For example:

Without HTTP profile

192.168.1.5%10:52364 <-> 192.168.1.20%10:http <-> 10.0.0.200%1:http

With HTTP profile

192.168.1.5%10:52364 <-> 192.168.1.20%10:http <-> any6

F5 Product Development is tracking this issue as ID 340469.
