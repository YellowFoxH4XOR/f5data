Known Issue

Modifying an Address type data group may trigger deletion of previously configured objects.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system is configured with an Address type data group that contains multiple IP address objects.
  • You use the Configuration utility to modify the data group by adding an additional IP address object.

Impact

The updated data group may be missing previously configured IP address objects.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • After adding a new IP address object to a data group, some of the previously configured IP address objects are no longer listed as part of the data group.
  • BIG-IP configurations that are dependent on the IP addresses of the data group fail to function as expected.

Workaround

To work around this issue, you can use the Traffic Management Shell (tmsh) to add IP address objects to the data group. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the tmsh utility.
  2. Add a new IP object to an existing data group by using the following command syntax:

    modify /ltm data-group <data-group location> <data-group name> records add { <ip address>/<netmask> }

    For example:

    modify /ltm data-group internal private_networks records add { 10.0.0.0/16 }

  3. To exit the tmsh utility, type the following command:

    quit
