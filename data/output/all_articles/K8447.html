Known Issue

This is the result of a known issue. When you import a digital certificate into the FirePass controller to use as a client root certificate, if the expiration of the certificate (the valid to field of the certificate) is later than January 19, 2038, the expiration date will be displayed incorrectly during the import process. However, the certificate will function correctly with respect to its expiration date.

A client root certificate enables client certificate-based authentication between the FirePass controller and its remote access clients. The client root certificate contains a valid to field which indicates the date and time at which the certificate will expire. When a client root certificate with an expiration date beyond January 19, 2038 is installed by clicking the Client Root Certificate link on the Device Management: Security: Certificates page, the page that is displayed once the certificate is loaded displays a message that appears similar to the following:

Your client root cert issued by ca.siteconfig.com expires 02 2020

Configuration changed.  You must restart the FirePass service for these changes to take effect.

The date listed is incorrect. In the example, the correct expiration year for the certificate is February 2058.

The functionality of the client root certificate is not impaired by this issue, and the certificate will be able to correctly authenticate the client certificates that it issued. However, if you are using the client root certificate to issue client certificates from the FirePass controller using the built-in PKI (as opposed to an external certificate authority), refer to K8451: Self-signed client certificates with expirations past 1/19/2038 corrupt client certificate database.

F5 Product Development is tracking this issue as ID 266973 (formerly CR94775). To monitor the status of this CR, refer to the FirePass release notes.
