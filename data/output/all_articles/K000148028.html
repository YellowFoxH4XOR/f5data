K000148028: Why are Googlebot OR Google crawlers blocked?

Type

Published
2024-11-08
Updated
2024-11-08
Applies to

  • F5 Distributed Cloud
Source
https://my.f5.com/manage/s/article/K000148028

Description

  • Request was blocked as a malicious bot
  • Detailed log states that the "Search Engine Verification Failed".
  • X-Forwarded-For header includes a real IP from Googlebot IP addresses
  • Good Bot set to Report - (default configuration)
  • Why are GoogleBot requests reported as malicious?

Environment

  • F5® Distributed Cloud Console
  • App Firewall

Cause

Good bots usually have predefined IP ranges. App Firewall might report GoogleBot requests as a malicious bot, due to IP address verification failure.

You can easily find that information in security event (req_id: <security-event-id> .

Snippet of bot info:

"bot_info": {
"anomaly": "Search Engine Verification Failed",
"classification": "malicious",
"name": "Google",
"type": "Search Engine"
},

Few more details:

Sometimes, specific request come through the proxy or CDN, because it has "X-Forwarded-For: <goodbot-ip-address>, <proxyORcnd-IP-address>" ; hence, when Trusted Client IP Headers section is not configured, we take source IP address from the TCP socket which is <proxyORcdn-IP-address> in that case. In other words, the combination of GoogleBot user agent with the NON GoogleBot source IP makes us think that this is someone malicious.

Resolution

You can configure Trusted Client IP Headers section under HTTP LB -> Other Settings. By default, we don't retrieve source IP addresses from X-Forwarded-For header. 

Note: When trusted client headers are enabled, system uses real client IP address as the source IP, instead of the proxy's IP address.
