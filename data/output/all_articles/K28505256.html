Known Issue

Secure Sockets Layer (SSL) persisted connections may fail to connect.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system is configured with a virtual server that uses an SSL persistence profile.
  • During the SSL handshake, a connecting user sends a client certificate that exceeds 16,384 bytes.

Impact

The SSL handshake does not complete, and the connection does not establish.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Connections that attempt to complete the SSL handshake time out.
  • When you analyze the network-level traffic between the BIG-IP system and the client, you notice that the system sends the initial packet, as a fragmented packet, to the virtual server that contains the client certificate.
  • When you analyze network-level traffic between the BIG-IP system and the destination server, you notice that the BIG-IP system sends only a single packet to the destination server. The packet contains the client certificate with the first bytes of the next handshake record.

Workaround

To work around this issue, you can use an alternate persistence type such as source address affinity.

Impact of workaround: Performing the suggested workaround will persist connections based on the client IP address. Depending on your environment, this may cause the system to distribute and unevenly persist connections across multiple destination servers.
