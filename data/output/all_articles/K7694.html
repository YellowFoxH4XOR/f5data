Known Issue

This is a result of a known issue. If you use the bigpipe verify [base] load commands to verify a BIG-IP configuration, it will incorrectly re-enable interfaces that you have disabled. For example, if you specifically disabled an interface or several interfaces and later use the bigpipe verify [base] load commands, the interface will be re-enabled and marked up. This behavior may cause the configsync operation to fail for units in a redundant pair.

F5 Product Development tracked this issue as CR82211 and it was fixed in BIG-IP version 9.3.1. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, or Link Controller release notes.
