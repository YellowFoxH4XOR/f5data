K10683: The certificate revocation list may expire before the self-signed client root CA certificate expires

Known Issue

This is the result of a known issue. When you generate and install a self-signed client root CA certificate on the FirePass controller, the corresponding certificate revocation list (CRL) is generated the first time you delete a client certificate. The expiration date of the CRL is set to one year ahead of the current date, and its expiration date is updated each time you delete a client certificate. For example, if you delete a client certificate on 10/28/2008, FirePass sets the expiration date of the CRL to 10/28/2009. 

If you do not delete any client certificates for a year, the CRL expires. This issue causes users with client certificates (including users with valid client certificates) to fail the SSL handshake with the FirePass controller. When this issue occurs, FirePass logs an error message that appears similar to the following example to the Server error log (https) on the Reports: HTTP Logs page:

[error] mod_ssl: Certificate Verification: Error (12): CRL has expired

F5 Networks Product Development tracked this issue as CR72872 and it was fixed in FirePass versions 6.0.2 and 6.1.0. For information about upgrading, refer to the FirePass Release Notes.

This issue was fixed in cumulative hotfix HF-552-11 for FirePass version 5.5.2. You may download this hotfix or later versions of the cumulative hotfix from the F5 Networks Downloads site.

Important: In FirePass versions 6.0.2 and later, and in FirePass version 5.5.2 with cumulative hotfix HF-552-11 or later, the expiration of the CRL is set to the expiration date of the self-signed client root CA certificate.

For instructions about obtaining a hotfix, refer to K167: Downloading software from F5 Networks.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.

To view a list of the latest available hotfixes, refer to K10322: FirePass hotfix matrix.

Workaround

You can work around this issue by creating a test user account, generating a client certificate for the test user, and then deleting the client certificate. Once the client certificate is deleted, the expiration date of the CRL will be set to one year ahead of the current date. For the CRL update to take effect, restart the FirePass services on the Device Management: Maintenance: Restart Services page.
