Description

You are planning to update the ASM attack signatures and you would like to know what effect this has on existing signatures that are going to be updated.

Environment

  • Attack signatures
  • Live Update
  • Security policy

Cause

None

Recommended Actions

When using the default Retain previous rule enforcement and place updated rule in staging, expect the following behaviour:

  • New signatures will be placed into staging, and will need to be enforced after the Enforcement Readiness Period has passed.
  • Updated signatures will be placed into staging. If one of those signatures is already being enforced, then the new version for that signature will be placed into staging, and the old version will still be enforced. When the new version is enforced, it will replace the old version for that signature. In addition, only two versions of any given signature are possible for a policy at one time; the fully enforced signature, and the updated signature in staging. The staged version will always be the most recently loaded version of the signature. If a signature update is performed that includes a signature that is in staging, the new signature will replace the signature in staging, while the enforced signature rule remains unchanged. Both versions will apply to the same signature ID, so it is possible to see instances in the event logs that are triggered by either version.

Additional Information

When you update attack signatures the previous version will still be enforced while the new version is put into staging until the enforcement readiness period has passed and signature is ready to be enforced with the new version.  Yes, signatures will block if your ASM policy is in blocking mode for the signatures that were enforced previously. New signatures are put into staging until you enforce them after the enforcement readiness period has passed which is default 7 days on an ASM policy, or if a lot of traffic is seen with automatic learning mode, the policy may tighten / stabilize sooner.

This is depending on the learning modes for your ASM policies also.

If Automatic learning mode is used then ASM will update the staged signatures for new and enforced.

If Learning mode is Manual or Disabled then the end user has to enforce the attack signatures after the enforcement readiness period has passed to update the signature rule or staged signatures that are new.

Don't get this confused with already enforced signatures that are updated with a new version that is staged because these signatures will still block based on the previous version until the new version is ready to be enforced.  Placing new and updated attack signatures in staging helps to reduce the number of violations triggered by false-positive matches. When signatures match attack patterns during the staging period, the system generates learning suggestions.

Also, if an entity is in staging on your policy and an attack signature is enforced this will not block because the entity is in staging even if policy is in blocking mode.
