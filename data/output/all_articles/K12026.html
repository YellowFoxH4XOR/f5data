Known Issue

This is the result of a known issue. When the BIG-IP WebAccelerator module proxies a request sent on a viable clientside Keep-Alive connection, and the origin web server (OWS) returns a response that uses chunked transfer encoding, the BIG-IP WebAccelerator will send a FIN after sending the response to the client, attempting to close the clientside connection rather than allowing the client to re-use it. Closing viable clientside Keep-Alive connections prematurely forces clients to open new connections, resulting in more clientside connections than necessary.

Note: HTTP clients request Keep-Alive connections by sending the Connection: Keep-Alive header in the HTTP request. HTTP servers indicate they are using chunked transfer encoding by sending the Content-Encoding: chunked header in the response.

F5 Product Development tracked this issue as ID 349754, and it was fixed in BIG-IP WebAccelerator 11.0.0. For information about upgrading, refer to the BIG-IP WebAccelerator release notes.

Note: This issue is masked for virtual servers that are configured with an HTTP profile with LTM RAM Cache enabled, such as the default http-acceleration profile. These connections are closed in a similar fashion for an unrelated reason. For more information, refer to K12025: The number of client-side connections may increase when LTM RAM Cache is used.
