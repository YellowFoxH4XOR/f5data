Description

Unable to establish iQuery connection after updating/changing the device certificates.

  • tmsh show gtm iquery shows that the peers are connected.
  • When trying to use iqdump, it keeps failing with an error similar to the following:

 iqmgmt_ssl_connect: SSL error: error:14090086:SSL routines:ssl3_get_server_certificate:certificate verify failed

Environment

  • iQuery connection between devices were working fine before certificate was changed.
  • BIG-IP GTM/DNS and/or LTM
  • Under DNS ›› GSLB : Servers : Trusted Server Certificates, there were multiple certificates added for the same device

Cause

This can happen if the local device is trying to validate using an old certificate of the remote device. The following log (/var/log/gtm) lines can be used to validate further.
localhost.com gtmd[29182]: 011ae114:3: iqmgmt_ssl_connect: SSL error: error:14090086:SSL routines:ssl3_get_server_certificate:certificate verify failed (123456789) from connection 10.195.98.47

Note: In the above log line, the number in bold is the serial of the certificate.

Recommended Actions

  1. Verify that there is more than one certificate for the same device under DNS ›› GSLB : Servers : Trusted Server Certificates.
  2. From the list of certificates, delete the certificate with serial number shown in the SSL Error in the /var/log/gtm.
    You may need to force to restart big3d and gtmd from the command line of the affected system:

    bigstart restart gtmd big3d

  3. Validate if the iQuery connection is successful using command below:
    iqdump <target/destination IP>

    Example:
    iqdump 10.195.98.47
