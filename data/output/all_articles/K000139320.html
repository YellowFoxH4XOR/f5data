Description

Updating DNS settings list from the GUI, under System ›› Configuration ›› Device ›› DNS, causes any existing 'server' statements in named.conf to be removed

Environment

  • BIG-IP DNS
  • named.conf has been customised to include or more 'server' definitions, to configure bind to use when talking to those DNS servers, for example, a particular DNS server may require a key, or other server-specific settings.

server 192.0.0.1 {};
server 192.0.0.2 { key mykey; edns true; }

 

Cause

 

When the systrem DNS settings page is submitted, named.conf is updated with any forwarders listed on that page, and a server {} section is generated for each of the forwarders.  Any existing server sections are removed. This is a result of bug ID1580157

Recommended Actions

If any existing 'server' entries are present in named.conf,  then avoid the use of the affected page in the BIG-IP GUI for making any changes to the system DNS settings. Instead, use tmsh to change the necessary settings:

If there are no existing server entries, then these workaround steps are not necessary, and the GUI can be used normally.

DNS Lookup List:
tmsh modify sys dns name-servers add {x.x.x.x}

DNS Search Domain List:
tmsh modify sys dns search add { aaaaaaa.xxx }

BIND Forwarder Server List
Make the changes using DNS > GSLB > Zones > Zonerunner > named Configuration

DNS Cache
tmsh modify sys db dns.cache value [enable | disable]

IP Version
tmsh modify sys dns include "options inet6"
