Error Message

notice mcpd[6016]: 01070638:5: Pool <pool_name> member <member_name>:<port> monitor status down. [ /Common/tcp_half_open: down; last error: /Common/tcp_half_open: IPv4 address mismatch @<date> <time>. ]
In this error message, note the following:

  • <PID> is the process ID for the mcpd process
  • <pool_name> is the partition and name of the pool
  • <member_name> is the partition and node name of the pool member
  • <port> is the port number used by the pool member
  • <status> is the availability status of the pool member
  • last error contains the message IPV4 mismatch

For example:
mcpd[6016]: 01070638:5: Pool /Common/pool_http member /Common/10.10.10.10:446 monitor status down. [ /Common/tcp_half_open_monitor: down; last error: /Common/tcp_half_open_monitor: IPv4 address mismatch @2020/12/28 21:54:24.  ] 

Message Location

You may encounter this message in the following location[s]:

  • The /var/log/ltm file
Description

This message occurs when [one|all|subset] of the following conditions [is|are] met:

  • A large number of pools members using a tcp_half_open health monitor
  • The top command shows that the CPU is under heavy load

The IPV4 mismatch error is how the tcp_half_open monitor reports timeouts. This happens during conditions where the CPU is under heavy load due to the nature of how the tcp_half_open monitor works. In the case of a standard tcp monitor, bigd will make a SOCKET binding request to the Linux kernel to process and manage connection tracking for tcp health monitors while bigd waits for confirmation that the health check passed or failed. 
With tcp_half_open health monitors bigd makes a request to the Linux kernel to request a SOCK_RAW for bigd to process and manage connection tracking for the tcp_half_open monitors.  During times of high Tmm Data Plane CPU usage traffic processing is prioritized and takes resources from Control Plane processes. This causes the tcp_half_open monitor to be unable to process and match the SYN/ACK for the health check. 

Impact

Health monitors may  appear to flap and connections may be dropped. 

Recommended Actions

Migrating tcp_half_open monitors to a tcp monitor will mitigate the IPV4 address mismatch errors and decrease CPU resources necessary for bigd to process health checks. F5 recommends testing this change in a staging environment to ensure compatibility with your backend applications.
