K000158893: SMTP traffic is not forwarded to SMTP pool when iRule uses TCP::collect in CLIENT_ACCEPTED

Type
Support Solution
Published
2025-12-24
Updated
2025-12-24
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.2
Source
https://my.f5.com/manage/s/article/K000158893

Description

On BIG-IP LTM, applying an iRule that issues TCP::collect in CLIENT_ACCEPTED to an SMTP virtual server can prevent BIG-IP from establishing the server-side connection to pool members.

 

Environment

  • BIG-IP LTM
  • iRule
  • SMTP virtual server & pool

 

Cause

This behavior is caused by a protocol flow mismatch: SMTP servers typically send a greeting banner immediately after the TCP connection is established, before the client sends any data. When TCP::collect is used in the CLIENT_ACCEPTED event, BIG IP waits for client data before establishing the server-side connection.

 

If the SMTP client is waiting for the server's banner, this can result in a deadlock.

 

Recommended Actions

Remove TCP::collect from iRules attached to SMTP virtual servers or use it in appropriate event

 

Additional Information

Expected SMTP flow: after TCP establishment, the SMTP server sends a 220 greeting banner first.

 

Observed with TCP::collect in CLIENT_ACCEPTED: BIG-IP waits for client payload before creating the server-side connection; if the client is waiting for the server banner, the session stalls and mail delivery fails.
