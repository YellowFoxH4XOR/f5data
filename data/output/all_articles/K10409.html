Known Issue

This is the result of a known issue. Changing provisioning options of a BIG-IP WebAccelerator module while the BIG-IP system is handling traffic may result in the TMM crashing. This behavior will result in a failover on a redundant configured system or a reboot on a non-redundant configured system.

F5 Networks Product Development tracked this issue as CR122271 and it was fixed in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP WebAccelerator Release Notes.

This issue was fixed in Hotfix-BIGIP-10.0.1-342.0-HF1, which has been issued for BIG-IP version 10.0.1, for the BIG-IP 10.0 software branch. You may download this hotfix or later versions of the cumulative hotfix from the F5 Networks Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about the F5 Networks hotfix policy, refer to K4918: Overview of F5 Networks critical issue hotfix policy.

For information about installing 10.x hotfixes on a Logical Volume Management (LVM) disk-formatted system, refer to in K10025: Managing F5 Networks product hotfixes for BIG-IP version 10.x systems.

For information about installing 10.x hotfixes on a partitioned system, refer to K9819: Installing a BIG-IP version 10.x hotfix on a partitioned system.

Workaround

To prevent this behavior, F5 Networks recommends that you perform any changes to provisioning of the BIG-IP WebAccelerator on the standby unit; then you may failover to the partner unit, and perform the change if in a redundant pair configuration. You must make the changes during a maintenance window when traffic can be restricted.
