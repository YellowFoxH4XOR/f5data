K000139075: NGINX failed to validate "fake_ciphers" with command 'nginx -t'

Type
Support Solution
Published
2024-03-28

Status

Applies to

  • NGINX Plus: R31
Source
https://my.f5.com/manage/s/article/K000139075

Description

  • You configured NGINX to offload SSL.
  • In your NGINX configuration, you included an invalid cipher suites like 'FAKE_TLS_ECCPWD_WITH_AES_128_GCM_SHA256:ECDHE-ECDSA-AES128-GCM-SHA256'
  • During NGINX configuration validation using command nginx -t. you whish NGINX to reject this invalid cipher suites

Environment

  • NGINX Plus
  • SSL Protocol
  • openSSL

Cause

  • None

Recommended Actions

  • None

Additional Information

  • NGINX secures communication by relying on openSSL functionalities 
  • openSSL comes with the underlying operating system where NGINX is installed.
  • Upon invoking openSSL, NGINX passes configured ssl_ciphers and other preferred SSL parameters to openSSL
  • openSSL then uses this details to negotiate ssl_ciphers and other SSL spec, during SSL handshake. In other words, NGINX has dependency on openSSL to enforce TLS.
  • This means, "NGINX -t" does NOT validate ssl_ciphers and does NOT have a means to validate such misconfiguration.
