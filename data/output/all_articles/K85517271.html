Description
During the SSL negotiation, the BIGIP system strictly checks the protocol version in the pre-master secret to verify if it matches with the protocol version used in the Client Hello.  

The Version number in PreMasterSecret is the version offered by the client in ClintHello.client_version not the version negotiated for the connection. This feature is designed to prevent rollback attacks. 

If the client implementations use the negotiated version into the PreMasterSecter, SSL Handshake will be failed and if the log.ssl.level is set to debug, an error similar to will be displayed.  

01260009:7: Connection error: hud_ssl_handler:1146: codec alert (20)
01260013:6: SSL Handshake failed for TCP 10.10.10.10:41234 -> 10.10.100.100:443

01260009:7: Connection error: ssl_hs_cn_vfy_fin:2228: corrupt Finished (20)
01260013:6: SSL Handshake failed for TCP 10.10.10.10:44567 -> 10.10.100.100:443

Environment

  • SSL Handshake 
  • Client Hello
  • TLS Rollback Detection

Cause
Bug ID 490936: SSLv2 based handshake causing handshake failures: 
After implementing the ID 490936, BIG-IP strictly checks the protocol version for RSA encrypted premaster secret message. 

Recommended Actions

To disable the TLS rollback check, enabling 'TLS rollback bug workaround' option in the client-ssl profile after BIG-IP 12.1.2 and above.
  1. Login to BIG-IP Configuration Utility
  2. Local Traffic >> Profiles: SSL : Client 
  3. Click on SSL profile 
  4. Select TLS rollback bug workaround from Options List
  5. Click Enable 
  6. Click Save
