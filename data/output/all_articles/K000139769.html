K000139769: LTM configuration got lost post reboot

Type
Support Solution
Published
2024-05-24
Updated
2024-05-24
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000139769

Description

  • Some or all configured LTM objects (virtual servers, pools, profiles, etc) missing after BIG-IP tenant reboot
  • The HA device-group is configured with auto-sync enabled
  • Logs messages similar to the following can be seen on the rebooted BIG-IP tenant on /var/log/ltm

        notice chmand[4548]: 012a0005:5: Hardware/Chassis change detected. Forcing db load from file 
       notice logger[10200]: /usr/bin/mcpd -dbmem 512 -listen 127.0.0.1 -forceload -f  ==> /usr/bin/bigstart disable pgadmind

Environment

  • F5OS tenant (rSeries or VELOS)
  • BIG-IP Tenants on HA
  • Tenant reboot
  • auto-sync enabled

Cause

When auto-sync is enabled on the device-group, the BIG-IP syncs the configuration automatically to the peer, but only saves to the running configuration of the receiving device. It does not save the changes to the configuration files on each device in the device group. 

Due to Bug ID 1105021 the BIG-IP tenant performs an MCPD "forceload" operation after a reboot which means the MCPD loads the configuration from the text config file rather than the binary database. 

If you reboot the BIG-IP peer that received the new configuration, without saving your configuration first, the BIG-IP system reloads your last saved configuration. This may result in configuration loss as a result of operational foul-ups, regardless of which device had a newer configuration before one was rebooted, the newly-rebooted device will claim to have a newer configuration.  

Recommended Actions

As a workaround, you can enable Save on Automatiic Sync to force saving the configuration to file after each aute sync. To do so please refer to K14624

At the time of creation of this article and EngHF with the fix can be provided.
