K000160329: IPV6 in AWS neigh show always FAILED

Type
Support Solution
Published
2026-03-12
Updated
2026-03-12
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000160329

Description

BIG-IP systems may fail to route outbound IPv6 traffic, resulting in "Network is unreachable" errors and neighbor table entries showing "FAILED" status, even when IPv6 addresses, self-IPs, and routes are properly configured. This occurs when the system database variable ipv6.enabled is set to false, preventing the BIG-IP from processing and routing IPv6 packets. Additionally, incorrect IPv6 default route configuration (e.g., using ::/128 instead of ::/0) can prevent proper routing of IPv6 traffic.

Symptoms include:

  • Outbound IPv6 connections (e.g., curl -6, ping6) fail with "Network is unreachable" or "No route to host" errors.
  • The neighbor table (ip -f inet6 neigh show) shows the IPv6 gateway in "FAILED" state.
  • The BIG-IP does not send IPv6 traffic, or traffic is sent but fails to establish connections.
  • Inbound IPv6 traffic may be received (visible via tcpdump), but return traffic is not sent.

Environment

  • BIG-IP LTM (all modules)
  • Any version where IPv6 is supported
  • Particularly relevant for BIG-IP VE deployments in AWS, Azure, Hyper-V, and other cloud/virtualized environments where IPv6 is required

Cause

The system database variable ipv6.enabled is set to false. This setting disables IPv6 processing and routing at the system level, preventing the BIG-IP from sending or handling IPv6 traffic, regardless of configured IPv6 addresses, self-IPs, routes, or VLANs.

Additionally, incorrect configuration of the IPv6 default route (e.g., using ::/128 instead of ::/0 as the network prefix) will prevent the BIG-IP from routing traffic to IPv6 destinations not covered by more specific routes.

Answer/Recommended Actions

  1. Verify the ipv6.enabled database variable setting:

    tmsh list /sys db ipv6.enabled

    If the value is false, IPv6 processing is disabled.

  2. Enable IPv6 processing:

    tmsh modify sys db ipv6.enabled value true

  3. Verify and correct the IPv6 default route:
    • Check the current routing configuration:

      tmsh list /net route

    • Ensure the IPv6 default route uses the correct network prefix (::/0 or default-inet6) and the appropriate gateway address (typically the first usable IPv6 address in your subnet).
    • If the route is incorrect, delete and recreate it:

      tmsh delete /net route <route_name>

      tmsh create /net route <route_name> network default-inet6 gw <IPv6_gateway_address>

    • Ensure a corresponding IPv6 self-IP exists on the same VLAN as the gateway.
  4. Save the configuration:

    tmsh save /sys config

  5. Verify IPv6 connectivity:
    • Test outbound IPv6 connectivity:

      ping6 -c 4 <destination>

      curl -6 -kv <destination_url>

    • Check the neighbor table:

      ip -f inet6 neigh show

      tmsh show /net ndp all

    • Verify the gateway is reachable and neighbor entries are in a valid state (not FAILED).
  6. For cloud deployments (AWS, Azure):
    • Ensure Security Groups and Network ACLs allow ICMPv6 (protocol 58) for proper neighbor discovery.
    • Confirm the VPC route table includes a ::/0 route to the Internet Gateway (if applicable).
    • Verify the subnet has an IPv6 CIDR assigned and the ENI has IPv6 addresses.

Additional Information

  • The ipv6.enabled database variable controls whether the BIG-IP system processes IPv6 traffic at the system level. When set to false, the system will not send or receive IPv6 traffic, even if IPv6 addresses and routes are configured. This setting is independent of having IPv6 addresses or self-IPs configured.
  • The IPv6 default route must use the network prefix ::/0 (or the alias default-inet6). Using ::/128 represents a single specific IPv6 address and does not function as a default route.
  • The BIG-IP system does not support initiating router solicitations for IPv6 and cannot auto-configure its default gateway using Neighbor Discovery Protocol (NDP). Manual configuration of the IPv6 default route is required.
  • If the neighbor entry for the IPv6 gateway remains in a FAILED state after enabling ipv6.enabled and configuring the route, investigate network connectivity issues, such as firewalls blocking ICMPv6 or incorrect gateway addresses.
