Known Issue

The BIG-IP system may fail to copy Secure Sockets Layer (SSL) certificates to secondary blades.

This issue occurs when the following condition is met:

  • You run the tmsh load sys config verify command.

For example, if you create an SSL certificate on the primary blade, and then run the tmsh load sys config verify command, the certificate is not synchronized and the mcpd process restarts on the secondary blades.

Impact

The mcpd process restarts on the secondary blades.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Secondary blades are unavailable for traffic processing while the mcpd process restarts.

Note: BIG-IP 11.x and later versions are not affected by this issue.

Workaround

To work around this issue, you can confirm that SSL certificate files exist across all blades in the chassis before running the verify command.
