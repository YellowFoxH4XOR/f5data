Description

BIG-IP is not able to boot up correctly.
Console output will show the following messages.

Example : 

Checking filesystems
Checking all file systems.
[/sbin/fsck.ext3 (1) -- /] fsck.ext3 -a /dev/md8
set.2./: Superblock last mount time (Sun Sep  1 23:29:23 2019,
        now = Tue Mar 27 00:22:17 2012) is in the future.


set.2./: UNEXPECTED INCONSISTENCY; RUN fsck MANUALLY.
        (i.e., without -a or -p options)
                WelcomGive root password for maintenance
Environment

This issue can happen on any BIG-IP platform on any TMOS software version.

Cause

The current BIG-IP clock has been reset to a much earlier date while the system files shows the current date.
Because of the date difference, fsck is not able to run and the BIG-IP gets stuck at this stage.

Recommended Actions

In general, you will need to ensure that your TMOS software and the hardware BIOS has the current date and time.
After this is done, you will need to reboot the BIG-IP and issue will be resolved.

These are the detailed steps on how to resolve the issue.

  1. Start the device is single user mode. Please follow the GRUB 0.97 or GRUB2 article on how to start to single user mode.
     
  2. Once you have entered GRUB, edit "linux /boot/<boot location>/vmlinuz" and add "single fastboot" at the end of the line. The edited text would look something like this.
    linux /boot/1/vmlinuz ro root=UUID=7237fa64-e347-4bb7-a755-6e2617bd7c0e console=ttyS0 panic=1 platform=D113 quiet single fastboot
     
  3. The "single" is to start the boot in single user mode and "fastboot" is to bypass fsck system check.
     
  4. If the reboot is successful, you should be prompted as below.
    [root@!:!:!] ~ #
     
  5. You can now set the date and time manually. Please check with another BIG-IP in you environment for its current date and time. Use the following command to edit the date and time of the problematic BIG-IP.
    date -s "<day> <month> <year> <time>"
    For example, if you want to set the date to July 30 2019 and time to 03:00:00, type the following command.
    [root@!:!:!] ~ # date -s "30 Jul 2019 03:00:00"
     
  6. Confirm the date and time with the following command.
    [root@!:!:!] ~ # date
     
  7. If the date and time is correct, please save the time to the hardware clock (BIOS) with the following command.
    [root@!:!:!] ~ # hwclock --systohc
     
  8. Please run the following command to ensure that the BIG-IP system time and BIOS clock is the same.
    [root@!:!:!] ~ # date ; hwclock
     
  9. The output should appear similar to the example below.
    Tue Jul 30 03:00:00 UTC 2019
    Tue Jul 30 03:00:00 2019 -0.000328 seconds.
     
  10. Reboot the BIG-IP and the issue should be resolved. The reboot command is as follows.
    [root@!:!:!] ~ # reboot
