Known Issue

The Traffic Management Microkernel (TMM) may produce a core file while processing Security Assertion Markup Language (SAML) messages.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM system is configured with a SAML Identity Provider (IdP) access profile.
  • A service provider (SP) single logout (SLO) message is processed by the IdP access profile.

Impact

The BIG-IP system may temporarily fail to process traffic while TMM restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • A stand-alone device stops processing connections while TMM restarts.
  • The BIG-IP system generates a TMM core file to the /shared/core directory.
  • In the /var/log/apm file, you notice log messages similar to the following examples:

    err tmm1[8247]: 014d0002:3: 56cf7bcb: SSOv2 Error (16) reading slo url from session db
    err tmm1[8247]: 014d0002:3: SSOv2 plugin error(16) in sso/saml.c:4796
    err tmm1[8247]: 014d0002:3: 56cf7bcb: SSOv2 Error (16) ending final logout response

  • In the /var/log/tmm file, you notice log messages similar to the following examples:

Workaround

To work around this issue, you can disable SLO processing by the IdP access profile. To do so, perform the following procedure:

Impact of workaround: SLO will no longer be available.

  1. Log in to the Configuration utility.
  2. Navigate to Access Profiles > SAML > BIG-IP as SP.
  3. Click the IdP External Connectors tab.
  4. Select the check box in front of the Name of the IdP External Connector profile.
  5. Click Edit.
  6. In the Edit SAML IdP Connector menu, click SLO Service Settings.
  7. Remove the configured Single Logout Request URL.
  8. Remove the configured Single Logout Response URL.
  9. Click OK.
