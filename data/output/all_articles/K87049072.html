Description
DNS resolvers sending a query and receiving a response along with a glued C name record. The resolver will  try to resolver the C name record again instead of accepting the glued record received earlier.
 

Environment

  • BIG-IP DNS resolver
  • The DNS response contains a glued C name record.

Cause

The unbound(DNS resolvers) does not trust the glued record on the DNS response, and will make a separate A record query against the CNAME.

CNAMEs are chased by unbound itself, asking the remote server for every name in the indirection chain, to protect the local cache from illegal indirect referenced items.

This is to avoid poisoning of the record as shown below:

# poisoning
Q:
www.attackersite.com. IN A
A:
www.attackersite.com. IN CNAME victimsite.com.
victimsite.com.       IN A     w.x.y.z          ## attacker controlled

# later...
Q:
victimsite.com.       IN A
A:
victimsite.com.       IN A     w.x.y.z           ## cache is poisoned

So in the above case if DNS resolver(unboound) does not verify the A record the cache will remain poisoned.

Recommended Actions

None
