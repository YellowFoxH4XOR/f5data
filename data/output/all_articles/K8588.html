K8588: The BIG-IP ASM sends a RST for blocked requests when the virtual server references a Stream profile

Known Issue

This is the result of a known issue. When the BIG-IP ASM blocks a request, it sends a small 200 OK response to the client containing the support ID for the blocked request. If the BIG-IP ASM-enabled virtual server references a Stream profile, and Response Chunking is set to Selective in the HTTP profile, responses blocked by the BIG-IP ASM are immediately closed with a TCP RST, and the response containing the support ID is not sent to the client.

F5 Product Development tracked this issue as CR97366 and it was fixed in BIG-IP ASM 9.4.5. For information about upgrading, refer to the BIG-IP ASM release notes.

Additionally, this issue was fixed in hotfix BIGIP-9.4.4-HF3 issued for BIG-IP 9.4.4, and in Hotfix BIG-IP-9.4.3-HF4 issued for BIG-IP 9.4.3. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

For information about the F5 hotfix policy, refer to K4918: Overview of F5 critical issue hotfix policy.

For information about how to manage F5 product hotfixes, refer to K6845: Managing F5 product hotfixes.

Workaround

You can work around this issue by setting Response Chunking to Rechunk in the HTTP profile. To do so, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles.
  3. Select HTTP from the Services menu.
  4. Click the relevant HTTP profile.
  5. From the Response Chunking menu, select Rechunk.
  6. Click Update.
