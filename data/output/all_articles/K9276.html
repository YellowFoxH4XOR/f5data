K9276: The 3-DNS system does not allow you to change the virtual server ordering in a Global Availability pool

Published

Known Issue

This is the result of a known issue. When the Global Availability load balancing mode is defined for a pool, the 3-DNS system selects the virtual servers for load-balancing in the order in which they are listed in the pool. If you attempt to update the virtual server ordering for a global availability pool, the 3-DNS system does not make the change, and reverts the ordering to how the virtual servers were originally defined when the pool was created.

F5 Product Development tracked this issue as CR19210.

Workaround

To work around this issue, you can edit the wideip.conf file and change the virtual server ordering. To so so, perform the following procedure:

  1. Log in to the command line.
  2. Use a text editor to edit the /config/3dns/etc/wideip.conf file.
  3. Find the relevant pool, and change the virtual server list to the desired ordering.

    For example, in the following example, the pool name is poolA, and virtual server address 1.1.1.1 is used for load-balancing before address 1.2.2.2:

    wideip {
       address           188.175.112.209
       port              80 // http
       name              "www.server.com"
       ttl               30

       pool {
          name           "poolA"
          preferred      ga

          address        1.1.1.1
          address        1.2.2.2
       }
    }

    Therefore, to change the virtual server ordering so that 1.2.2.2 is used before 1.1.1.1, you would move virtual server address 1.2.2.2 to the top of the list. For example:

    address        1.2.2.2
    address        1.1.1.1
  4. Save the changes and exit the text editor.
  5. Type the following command to restart 3dnsd:

    3ndc restart
