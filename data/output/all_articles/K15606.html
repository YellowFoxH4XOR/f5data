Description

Beginning in BIG-IP 11.5.0, the BIG-IP system aggregates all statistics, including old statistics, every five minutes, even if there are no new statistics written to the database.

This change affects all statistics related to BIG-IP Analytics (AVR), including but not limited to the following:

  • AVR charts (HTTP AND DNS STATISTICS)
  • ASM charts
  • AFM charts
  • SWG charts
  • PEM charts

F5 Product Development tracked this change as ID 435183 and ID 431980.

Environment

  • BIG-IP Analytics

Cause

As a result of the regular aggregation activity performed by the AVR-related processes, such as avrd, monpd, and mysqld, you may notice that system CPU utilization experiences small spikes every 5 minutes, and slightly larger spikes every hour. You can expect similar spikes every 8 hours (aggregating the 1 hour data), 48 hours (aggregating the 8 hour data), 14 days (aggregating the daily data), 8 weeks (aggregating the 4 week data) and 12 months (pruning of old monthly data).

However, this should not affect the performance of Traffic Management Microkernel (TMM) data plane tasks because the AVR-related processes are non-TMM control plane tasks that use separate logical cores and are throttled down when TMM needs the resources. For more information about separate logical cores, refer to K15003: Data plane and control plane tasks use separate logical cores when the BIG-IP system CPU uses Hyper-Threading Technology.

Recommended Actions

None.

Additional Information

Once per 5 mins, analytics data is saved in the 5 minute interval table in the database. Within 1 hour AVR can collect up to 240,000 statistics records (20,000 multiplied by 12 equals 240,000 if avr.stats.internal.maxentitiespertable is set to the default 20,000 amount). When 1 hour passes, to make room for the next hour, the system takes the last hour of data from the 5 minute interval table and aggregates it and places it in the hourly data table. A sum of each metric is created during the aggregation

The next level of aggregation from hourly to the daily table will aggregate metrics further. The data is collapsed more when aggregated into the monthly table.

Storing all data in the 5 min interval table would generate an immense database that would exceed system storage so aggregation is required to avoid this.

You inevitably lose granular metrics when aggregating. So for example certain queries for per virtual server data will not show the exact numbers as these are counted inside the Aggregated values. AVR is not an event logger and therefore does not collect data about all events in the system, the purpose of AVR is to gather data to present a high level view of trends and analytics for your system.

In versions prior to BIG-IP 11.5.0, the BIG-IP system aggregates statistics only when there are new statistics written to the database.

This behavior may not provide accurate report charts, especially if the events are sparse for a module (for example, Secure Web Gateway [SWG]).
