Known Issue

This is the result of a known issue. If an iRule raises two iRule events simultaneously, and in the second event executes a command which temporarily suspends iRule execution, TMM cores. This behavior occurs because the system is unable to suspend iRules processing when two events are simultaneously active on the same flow.

Note: For information about iRule commands that suspend iRules execution, refer to K12962: Some iRules commands may temporarily suspend iRule processing.

For example, the following iRule will evoke this known issue on CMP-enabled systems:

when CLIENT_ACCEPTED {
 set collecting 0
 set renegtried 0
}

when CLIENTSSL_HANDSHAKE {
 if {$collecting == 1}{
  session add ssl [SSL::sessionid] [SSL::cert 0] 300
  set renegtried 1
  HTTP::release
 }
}

when HTTP_REQUEST  {
 if {[matchclass $::cert_urls equals [string tolower [HTTP::uri]]]}{
  set ssl_cert [session lookup ssl [SSL::sessionid]]
  if {$ssl_cert != ""}{
   ...
  } elseif {[SSL::cert count] <= 0}{
   HTTP::collect
   set collecting 1
   SSL::cert mode request
   SSL::renegotiate
  }
 }
}

when HTTP_REQUEST_SEND {
  set ssl_cert [session lookup ssl [SSL::sessionid]]
   ...
  }
 }
}

When the HTTP::release command is called from the CLIENTSSL_HANDSHAKE event, the HTTP_REQUEST_SEND event is raised concurrently with the CLIENTSSL_HANDSHAKE event. When the session lookup command is executed in the HTTP_REQUEST_SEND event, the BIG-IP system attempts to suspend iRules processing for the connection until the TMM holding the session record returns the record. However, since the system is unable to suspend iRules processing when two events are simultaneously active on the same flow, TMM crashes.

F5 Product Development is tracking this issue as ID 327287 and ID 209415 (formerly CR124119) and it was fixed BIG-IP version 10.1.0.

Additionally, Hotfix-BIGIP-10.0.1-342.0-HF1 has been issued for BIG-IP version 10.0.1, for the BIG-IP 10.0.0 software branch. You may download this hotfix or later versions of the cumulative hotfix from the F5  Downloads site.
