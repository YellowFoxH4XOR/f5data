Description

When deploying an HTTP profile from BIG-IQ with mismatch "Response chunking" options against BIG-IP's ones, the following log error is shown in BIG-IP:

ltm	 2021-06-24 09:53:14.000 -04:00 	 Error	 01070281: <myBigIP> mcpd[5319] Invalid "http response chunking" value for profile /common/My-http. Invalid entry, check allowed values.
 

Environment

- BIG-IQ 8.0
- BIG-IP 15.0.0 or newer version


Cause
BIG-IQ 8.0 has the following chunking options:
Response Chunking
Preserve
Select
Rechunk
Sustain
Unchunk



BIG-IP 15.0.0 and newer have the following options:
Unchunk
Rechunk
Sustain   <------ Default


The reason for such mismatch is as follows:
BIG-IP 15.0.0 and later

Specifies that the system preserves request or response chunking unless there is a command to modify the body. If the request or response is chunked, unchunk the HTTP content, process the data, and re-add chunking headers on egress. Chunk extensions will be lost. When the response is chunked, it can be rechunked on egress to the client. Note: The Sustain option is the default, starting with the release of BIG-IP 15.0.0, replacing the earlier release versions' use of Selective.

Preserve and Selective options have been deprecated in BIG-IP running 15.0.0 or newer versions, so a mismatch error is caused when such deprecated options are selected in BIG-IQ for deployment.

 Unchunk and Rechunk remain unchanged.


Recommended Actions

Use with "Sustain" instead or "Preserve" or "Selective" as option in BIG-IQ when deploying an http profile to BIG-IP.
