Known Issue

The BIG-IP system may abort suspended iRules processing for idle User Datagram Protocol (UDP) connection flows.

This issue occurs when all of the following conditions are met:

  • The BIG-IP configuration includes the following:
     
    • A UDP-based virtual server.
    • Client and server UDP profiles with the same idle timeout setting.
    • An iRule configured with a CLIENT_CLOSED or SERVER_CLOSED event that contains suspending commands.

      Note: For information about iRules suspending commands, refer to K12962: Some iRules commands temporarily suspend iRules processing.
  • An existing UDP connection reaches the configured idle timeout and expires while the iRule is suspended.

Impact

The iRule aborts and impacts performance; iRules that are designed to perform operations during the CLIENT_CLOSED or SERVER_CLOSED events may not function as expected.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Messages similar to the following example are written to the /var/log/ltm file:

    info tmm[7564]: 01220009:6: Pending rule /Common/test-rule <SERVER_CLOSED> aborted for 10.0.0.2:500 -> 10.0.0.4:38291

Workaround

None. To mitigate this issue, you can configure different idle timeouts for the client and server UDP profiles assigned to the UDP virtual server. This change causes the described issue behavior to occur much less frequently, although it will not prevent the behavior completely. To do so, perform one of the following procedures:

Changing the idle timeout for an existing UDP profile

This procedure only needs to be performed for one of the UDP profiles assigned to your virtual server; either the client or server. If your virtual server uses the same UDP profile for both the client and server, skip this procedure and perform the Creating a new UDP profile that uses a different timeout value procedure instead.

Impact of procedure: If idle connections are allowed to remain in the BIG-IP connection table for extended periods, the connections continue to consume system memory, which reduces the amount of memory available for new connections. F5 recommends that you increase the idle timeout period gradually, and test.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > Protocol > UDP.
  3. Click the profile to modify.
  4. Type the new Idle Timeout value, in seconds.

    For example, if the client side UDP profile idle timeout is 60 seconds, change the server side UDP profile idle timeout to 65 seconds.

  5. Click Update.

Note: Changing the idle timeout value for an existing protocol profile does not alter the timeout value used for existing virtual server connections; existing connections continue to use the previous idle timeout value.

Creating a new UDP profile that uses a different idle timeout value

If you use a single UDP profile for both the client and server side, you can create a new UDP profile which uses a different idle timeout value, and assign it as either the client profile or server profile (not both).

Impact of procedure: If idle connections are allowed to remain in the BIG-IP connection table for extended periods, the connections continue to consume system memory, which reduces the amount of memory available for new connections. F5 recommends that you increase the idle timeout period gradually, and test.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > Protocol > UDP.
  3. Click Create.
  4. Name the profile.
  5. Select the Custom check box and then type the Idle Timeout value, in seconds.

    For example, if the currently assigned UDP profile idle timeout is 60 seconds, set the new profile idle timeout to 65 seconds.

  6. Modify any other settings, as needed, then click Finished to save your changes.
  7. Navigate to Local Traffic > Virtual Servers.
  8. Click the UDP virtual server to modify.
  9. For Configuration, click Advanced.

    Note: For BIG-IP 11.5.0 and later versions, clicking Advanced is no longer necessary.

  10. Choose either the Protocol Profile (Client) or Protocol Profile (Server) option, and click the new profile you created.
  11. Click Update.
