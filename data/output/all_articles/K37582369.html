Topic

You should consider using this procedure under the following condition:

  • You want to configure your BIG-IP or BIG-IQ system for remote administrative authentication using Terminal Access Controller Access-Control System Plus (TACACS+).

Description

The following procedures show how to configure the BIG-IP system and your TACACS+ server for remote role authentication using TACACS+, based on Shrubbery Networks TACACS+  version F4.0.4.27a.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You currently have a TACACS+ server deployed that is accessible by the BIG-IP system.
  • You have administrative access to the BIG-IP, BIG-IQ, TMOS shell (tmsh), or iControl representation state transfer (REST) application programming interface (API).

Procedures

  • Defining remote roles on the BIG-IP system
  • Modifying the TACACS+ configuration to include F5 groups and users
  • Configuring the BIG-IP system to use TACACS+ for administrative access

Defining remote roles on the BIG-IP or BIG-IQ system

Remote roles are configured on the BIG-IP and BIG-IQ through tmsh or the iControl REST interface. The following procedure demonstrates how to create remote roles:

Impact of procedure:  Performing the following procedure should not have a negative impact on your system.

Creating a remote-role using tmsh

  1. Log in to tmsh.
  2. To list the currently configured remote roles, enter the following command:

    list /auth remote-role role-info

  3. Use the following command syntax to create a remote role:

    modify /auth remote-role role-info add { <role name> { attribute F5-LTM-User-Info-1=<role name> console tmsh line-order <number> role <role numeric value> user-partition <partition> }} 

    Note : Replace <role name> with a unique name for the role. Replace line-order <number> with the next highest number for the configured roles. Replace <role numeric value> with the numeric value for the role as listed in the table that you are creating. Replace <partition> with the allowed partition access for the role, options are Common (the default partition), all for access to all configured partitions, or the name of a partition configured on the BIG-IP system.

    Important: BIG-IQ GUI authentication is case sensitive for the TACACS+ shared secret, as well as all Vendor-Specific Attribute (VSA) names and values. Ensure that the case of all attribute names and values in your TACACS+ server configuration matches exactly with the BIG-IQ configuration. Any mismatch in case may result in authentication or role mapping failures.

    For example:

    modify /auth remote-role role-info add { adm { attribute F5-LTM-User-Info-1=adm console tmsh line-order 1 role 0 user-partition all }}

  4. To save the configuration enter the following command:

    save /sys config partitions all

Creating a remote-role using the iControl REST interface

Important: To execute the following commands you need access to a device that has the curl utility and network access to the BIG-IP management interface.

To list the currently configured remote roles configured on the BIG-IP system use the following command syntax:

curl -sk -u admin:<password> -H "Content-Type: application/json" -X GET https://<ip address>/mgmt/tm/auth/remote-role/role-info | jq -M .

Note: Replace <password> with the password of the admin user. Replace <ip address> with the IP address of the BIG-IP management interface.

Note: The JSON output of the object configuration includes links to view additional nested configuration details. Viewing objects with a REST command can produce verbose JSON output. To format the JSON output to a more user-friendly format, use the jq command line JSON processor command. The jq command -M flag sets the formatted JSON output to use monochrome when displaying the JSON output.  The '.' (period) parameter is optional in jq 1.5 and later.

To create a new remote role on the BIG-IP system, use the following command syntax:

curl -sk -u admin:<password> -H "Content-Type: application/json" -X POST https://<ip address>/mgmt/tm/auth/remote-role/role-info -d '{"name":"<role name>","attribute":"F5-LTM-User-Info-1=<role name>","console":"tmsh","lineOrder":"<number>","role":"<role numeric value>","userPartition":"<partition>"}' 

Note: Replace <password> with the password of the "admin" user. Replace <ip address> with the IP address of the BIG-IP management interface. Replace <role name> with a unique name for the role. Replace lineOrder <number> with the next highest number for the configured roles. Replace <role numeric value> with the numeric value for the role as listed in the table that you are creating. Replace <partition> with the allowed partition access for the role; options are Common (the default partition), all for access to all configured partitions, or the name of a partition configured on the BIG-IP system.

Example command:

curl -sk -u admin:password -H "Content-Type: application/json" -X POST https://192.168.0.100/mgmt/tm/auth/remote-role/role-info -d '{"name":"auditor","attribute":"F5-LTM-User-Info-1=auditor","console":"tmsh","lineOrder":"6","role":"80","userPartition":"all"}' 

Modifying the TACACS+ configuration to include F5 groups and users

To enable the TACACS+ authentication server to assign BIG-IP remote roles to an authenticated user, you need to modify the configuration of the server by adding the F5 remote roles as groups you want and assigning each intended user to the F5 group role. The following example configuration if from a TACACS+ server. 

Important: Configuration syntax may vary between TACACS+ vendors and vendor releases. Consult you TACACS+ vendor specifications prior to modifying the server configuration.

Impact of procedure:  Performing the following procedure should not have a negative impact on your system.

Using the previous remote role example, add the following F5 groups and F5 users to the TACACS+ server configuration file as designated in the configuration file:

Note: For the example configuration, the TACACS server configuration file /etc/tacacs+/tac_plus.conf is configured to use /etc/passwd as the default authentication; therefore, authentication syntax is not required for each user.

## F5 Groups
group = adm {
service = ppp
protocol = ip {
        F5-LTM-User-Info-1 = adm
        F5-LTM-User-Role = 0
    }
  }

## F5 Users
user = user1 {
member = adm
}

Important: The group name used in the TACACS+ server configuration must exactly match the remote role created on the BIG-IP system.

Configuring the BIG-IP or BIG-IQ to use TACACS+ for administrative access

Use the following procedure to configure the BIG-IP system to authenticate users that are not locally configured on the BIG-IP system with TACACS+.

Impact of procedure: Performing the following procedure configures TACACS+ authentication for administrative access for all users not specifically defined on the BIG-IP system.

  1. Log in to the Configuration utility.
  2. Go to System > Users > Authentication.
  3. Select Change.
  4. For User Directory, select Remote - TACACS+.
  5. For Servers, enter the IP address and the port of the TACACS+ server and select Add.
  6. For Secret, enter the TACACS+ shared key.

    Note: The TACACS+ secret key does not support using the pound sign (#) character.

  7. For Confirm Secret, reenter the TACACS+ shared key.
  8. For Encryption, leave the default value (Enabled) or select Disabled.
  9. For Service Name, enter ppp for the name of the service.

    Note: The TACACS+ server must be configured to respond to the appropriate Service Name configured on the BIG-IP system. F5 recommends that you use the ppp service.

  10. Optional: For Protocol Name, enter ip for the name of the protocol.

    Note: The TACACS+ server must be configured to respond to the appropriate protocol name configured on the BIG-IP system. F5 recommends that you use the IP protocol.

  11. Optional: For Configuration, select Advanced. For Authentication, select Authenticate to first server or Authenticate to each server until success.
  12. Optional: For Configuration, select Advanced. For Accounting Information, select Send to first available server or Send to all servers.

    Note: Support for TACACS+ accounting is introduced in BIG-IP 10.2.0.

  13. Optional: For Configuration, select Advanced. For Debug Logging, select Disabled (default) or Enabled.

    This option allows an administrator to troubleshoot communication or authentication problems with the TACACS+ server by logging debug information to the /var/log/secure file.

  14. For Role, select a user role that you want the BIG-IP system to assign as the default role for remote user accounts. This is the role assigned by BIG-IP for a remote user account that is not explicitly assigned a role.
  15. For Partition Access, select the partition, or partitions, to which you want users with remote accounts to have access.
  16. For Terminal Access, select the appropriate access option for your environment.
  17. Select Finished.
