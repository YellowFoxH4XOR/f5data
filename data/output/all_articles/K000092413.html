Description

You may encounter a memory issue with BIG-IP ASM.

  • Log entries indicating a memory issue.

  • ASM will stop the response accumulation, stop enforcing on response, and release the response to the client.

  • You may observe the following log message in /var/log/asm: 
    01310014:4: ASM filtered HTML exceeded limit: event code C190 Filtered Response HTML exceeded max limit

  • You may observe the following log in /var/log/ts/bd.log: 
    clean_resp.c:0188|Filtered HTML is above maximal size ( max size 17476266, is compressed 1) 
    or 
    clean_resp.c:0188|Filtered HTML is above maximal size ( max size 52428800, is compressed 0)

Environment

  • The max_filtered_html_length ASM variable.
  • BIG-IP ASM/Advanced WAF

Cause

This Indicates that ASM is seeing a "single collected response" which is bigger than the value of max_filtered_html_length (default 50MB). At which point ASM will stop the response accumulation, stop enforcing on response and release the response to client.

The behavior which involves ASM response accumulation is most likely the Learn from response feature from the Learning and Blocking Settings page.

Note: When HTTP response compression is in use, the enforced maximum size, as well as the “max size” shown in the error log, is the value of max_filtered_html_length divided by a constant of 3. 

Recommended Actions

Either you can turn off the Learn from response option if you don't need it or you can increase the max_filtered_html_length variable. To do so, perform one of the following procedures:

To disable Learn from response:

  1. Go to Security > Application Security > Policy Building > Learning and Blocking Settings.

  2. In the section labeled Policy Building Process change the dropdown item on the right to Advanced.

  3. At the bottom, in the Option section click on the arrow to expand it.

  4. Uncheck Learn from response.

  5. Save and apply the policy.

Or you can increase the max_filtered_html_length:

  1. Go to Security > Options > Application Security > Advanced Configuration > System Variables.

  2. Locate the variable max_filtered_html_length and select it

  3. Increase the value so responses will not exceed it.
    Note: Increasing this will cause some negative impact on memory. The max_filtered_html_length variable defines the maximum size of responses retained by the system. The default value is 52428800 bytes. Unfortunately we can not advise on what is the right value to increase.
  4. Select Update.
  5. Restart the asm process using the following command from the BIG-IP CLI (restarting ASM will cause a failover since the system will go offline):
    tmsh restart sys service asm
