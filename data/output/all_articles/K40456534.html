Topic

A web application firewall (WAF) is an intermediary system positioned between end-users and the web application and is designed to identify potential threats and protect the web application against layer-7 attacks. Most WAF systems use a combination of techniques to identify threats.

Description

In general, the most common threat detection techniques are the following:

  • Signature-based detection
  • Anomaly-based detection
  • Combination of signature-based and anomaly-based detection

Signature-based detection

Signature-based detection (sometimes referred to as rule-based detection) refers to the process of detecting known attacks by identifying specific patterns in network traffic and blocking the traffic or triggering an alarm when a malicious pattern is detected.

When using signature-based detection, the WAF compares specific values of HTTP request and response elements against a database of attack signature rules. The request/response elements include L7 properties, such as URLs, HTTP headers, parameters, and payload elements. The WAF may also look at L2 - L6 properties, such as ports, and IP addresses. When elements of application traffic match the patterns defined in a signature, the WAF considers the traffic to be malicious and triggers a violation.

ASM attack signatures are organized into sets and are stored in the attack signature database. An attack signature set is a grouping of signatures that represent a specific attack type, such as SQL injection, or cross-site scripting (XSS). If you know the systems that your application is built on (Windows, SQL, IIS, UNIX/Linux, Apache, and so on), you can allow the system to choose the appropriate attack signature sets to include in the security policy.

Signature-based detection relies on patterns defined in rules, so you must update the signature sets as they are released to mitigate the latest attacks. The BIG-IP ASM system allows you to define custom (user-defined) signatures to offer additional flexibility for specific applications and environments. Custom signatures also allow you to proactively mitigate newly discovered vulnerabilities. For example, the following simplistic custom signature triggers a violation when an incoming traffic header contains the keyword backdoor:

<?xml version="1.0" encoding="utf-8"?>
<signatures export_version="15.0.0">
<sig id="300000000">
<rev num="2">
<sig_name>custom-sig-01</sig_name>
<rule>headercontent:"backdoor"; nocase;</rule>
<last_update>2019-08-21 15:18:31</last_update>
<apply_to>Request</apply_to>
<risk>1</risk>
<accuracy>1</accuracy>
<doc>Test of a Custom Signature</doc>
<attack_type>Cross Site Scripting (XSS)</attack_type>
<systems>
<system_name>Microsoft Windows</system_name>
<system_name>Unix/Linux</system_name>
</systems>
</rev>
</sig>
</signatures>

Note: The rule pattern in the signature is usually obfuscated to avoid reverse engineering.

Benefits of signature-based detection

  • Is efficient at detecting known attacks
  • Has lower false positive rates
  • Signature sets can be applied based on the application type
  • New signatures can be evaluated during a staging period
  • User-defined signatures offer additional flexibility

Limitations of signature-based detection

  • Less effective at detecting unknown attacks

Anomaly-based detection

Anomaly-based detection works by monitoring traffic in real time to distinguish normal traffic from anomalous traffic. Instead of inspecting traffic request data against signature rules, anomaly-based detection identifies behavioral patterns in traffic that deviate from the norm. Unusual traffic that is linked with malicious activities is identified as an attack. With this mode, the WAF evaluates traffic for similarity patterns; if the unusual traffic is very similar to previous traffic and does not contain malicious patterns, it is likely not an attack.

Anomaly-based detection considers point-in-time and context. This type of detection observes statistical variation when the behavior changes and considers the context of the application and the environment (including internal and external factors). Anomaly-based detection measures factors like frequency, variation, and volume.

Benefits of anomaly-based detection

  • Is effective at detecting unknown attacks
  • Adapts to the individual application configurations

Limitations of anomaly-based detection

  • More susceptible to false positive violations

Combination of signature-based and anomaly-based techniques   

Signature-based techniques excel at detecting known attacks, and anomaly-based techniques are theoretically better at detecting new attacks. Modern WAF systems like the BIG-IP ASM system use both signature-based and anomaly-based detection to efficiently guard your applications from malicious traffic. For example, you can configure an ASM security policy to use attack signatures sets to guard against attacks on systems that your application is built on, such as SQL, UNIX/Linux, and so on. In addition, you can configure the same policy to use anomaly-based detection features, such as DoS protection, Brute Force attack prevention, and Bot defense.
