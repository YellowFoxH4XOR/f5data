Known Issue

The wamd process may fail to start after you upgrade the BIG-IP WebAccelerator system.

This issue occurs when one of the following conditions is met:

  • You roll the BIG-IP WebAccelerator configuration forward during an upgrade from BIG-IP WebAccelerator 10.x to 11.x.
  • You attempt to load a saved BIG-IP WebAccelerator user configuration set (UCS) archive after an upgrade from BIG-IP WebAccelerator 10.x to 11.x.

After you upgrade BIG-IP WebAccelerator from 10.x to 11.x, a one-time conversion script runs prior to starting the wamd process for the first time. Transactions in the script convert to the new wam-enabled Web Acceleration profiles. If transactions within the script are unable to complete, the script fails.  As a result, the wamd process fails to start even after you reboot the system.

Impact

Virtual servers enabled with BIG-IP WebAccelerator or BIG-IP AAM no longer accept traffic.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The affected virtual servers and newly converted wam-enabled profiles are present in the configuration but the wamd process fails to start.
  • Attempts to start the wamd process using the tmsh restart sys service wamd command fail with an error message similar to the following example:

    wamd down, An error occurred setting up Web Accelerator: The script /var/run/wam_virtual_update8937.tcl failed to update virtuals: /var/run/wam_virtual_update8937.tcl: script     failed to complete

  • Messages appear in the /var/log/ltm file, similar to the following example:

    err WA[14461]: The script /var/run/wam_virtual_update14461.tcl failed to update virtuals: /var/run/wam_virtual_update14461.tcl: script failed to complete: can't eval proc:         "script::run" 01020036:3: The requested Web Acceleration profile (/Common/http-acceleration-wam-enabled-cache) was not found.     while executing "tmsh::commit_transaction"     (procedure "script::run" line 41)     invoked from within "script::run" line:1 script did not successfully complete, status:1

Workaround

To recover from this issue, you can verify all affected virtual servers are configured with wam-enabled Web Acceleration profiles, delete the one-time conversion files, and restart the wamd process. To do so, perform the following procedures:

Impact of workaround: Performing the following procedures should not have a negative impact on your system.

Verifying that affected virtual servers are configured with wam-enabled Web Acceleration profiles

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  3. Click the affected virtual server.
  4. Verify that a wam-enabled profile is selected in the Web Acceleration Profile menu.
  5. Navigate to Local Traffic > Profiles > Services > Web Acceleration.
  6. Click the wam-enabled Web Acceleration profile associated with the virtual server noted in step 4.
  7. Verify that the appropriate Web Application is enabled in the WA Application section.
  8. Repeat steps 2 through 7 for all affected virtual servers.

Deleting the one-time conversion files and restarting the wamd process

  1. Log in to the command line of the BIG-IP system with root privileges.
  2. To remove the one-time conversion files, run the following commands:

    3.     rm -f /config/policyDBDump.cfg

        rm -f /config/wa/.installed_ucs

        rm -f /config/wa/.virtuals.tmp

        rm -f /var/run/wam_virtual_update*.tcl

  3. Restart the wamd process by typing the following command:

    4.     tmsh restart sys service wamd

  4. You can check the status of the wamd process by typing the following command:

    5.     tmsh show sys service wamd

  5. Save the configuration by typing the following command:

        tmsh save sys config partitions all
