Topic

This article applies to BIG-IP 9.x through 10.x. For information about other versions, refer to the following articles:

  • K13558: Allowing asymmetrically routed connections across multiple VLANs (11.x)

You can configure the BIG-IP system to accept asymmetrically routed connections across Virtual Local Area Networks (VLANs) on a per virtual server basis or on a system wide basis, depending on the expected traffic path through the BIG-IP system.  To configure asymmetric routing through the BIG-IP system, perform one of the following procedures:

  • To allow asymmetric routing per virtual server, refer to Using a custom FastL4 profile with Loose Initiation and Loose Close enabled
  • To allow asymmetric routing system wide, refer to Disabling VLAN-keyed connections

Using a custom FastL4 profile with Loose Initiation and Loose Close enabled

Enabling Loose Initiation and Loose Close in a custom FastL4 profile can be useful when an individual virtual server processes asymmetric traffic.  For example, in an nPath configuration, the virtual server only processes the client-side traffic, and responses from the pool member are routed around the BIG-IP system. To allow an individual virtual server to accept asymmetrically routed connections, perform one of the following procedures:

Impact of procedure: Only virtual servers associated with the custom FastL4 profile accept asymmetrically routed connections. For platforms that contain a Packet Velocity ASIC (PVA) chip, you must additionally disable pva-acceleration in the FastL4 profile.

Using the command line to configure a custom FastL4 profile with Loose Initiation and Loose Close enabled

  1. Log in to the command line
  2. Create the profile using the following command syntax:

    bigpipe profile fastl4 <profile_name> [pva-acceleration none] loose close enable loose initiation enable

    For example, to create a FastL4 profile named MyL4Profile, type the following command:

    bigpipe profile fastl4 MyL4Profile loose close enable loose initiation enable

    For example on platforms that contain a PVA chip, to disable pva-acceleration in the FastL4 profile, type the following command:

    bigpipe profile fastl4 MyL4Profile pva acceleration none loose close enable loose initiation enable
  3. Associate the custom FastL4 profile with an existing virtual server using the following syntax:

    bigpipe virtual <virtual server name> {profile <custom profile>}

    For example, to associate the MyL4Profile custom profile created in step 2 with a virtual server named MyVip, type the following command:

    bigpipe virtual MyVip {profile MyL4Profile}
  4. Save the configuration by typing the following command:

    bigpipe save

Using the Configuration utility to configure a custom FastL4 profile with Loose Initiation and Loose Close enabled

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers > Profiles.
  3. From the Protocol box, select FastL4.
  4. Click Create.
  5. In the Name box, type a name for the profile.
  6. Select the Custom PVA Acceleration, Loose Initiation and Loose Close check boxes.
  7. From the PVA Acceleration box, select None.
  8. Select the Loose Initiation check box.
  9. Select the Loose Close check box.
  10. Click Finished.
  11. Navigate to Local Traffic > Virtual Servers.
  12. Click the appropriate virtual server.
  13. From the Protocol Profile box, select the new custom FastL4 profile you just created.
  14. Click Update.

Disabling VLAN-keyed connections

With VLAN-keyed connections enabled, the BIG-IP system manages connections on a per-VLAN basis.  For example, if connection initiation is made to a pool member on VLAN A, the BIG-IP system expects the acknowledgement from the pool member to be received on VLAN A. 

Disabling VLAN-keyed connections allows the BIG-IP system to accept asymmetrically routed connections across multiple VLANs.  For example, this allows connection initiation to a pool member on VLAN A while the pool member's acknowledgement is received on VLAN B. 

To allow the BIG-IP system to accept asymmetrically routed connections across VLANs, disable VLAN-keyed connections using the following procedure:

Impact of procedure: Disabling VLAN-keyed connections affects all VLANs configured on the BIG-IP system globally.  Testing is recommended to account for unintended consequences.

  1. Log in to the command line.
  2. Disable the connection.vlankeyed db key by typing the following command:

    bigpipe db Connection.VlanKeyed disable
