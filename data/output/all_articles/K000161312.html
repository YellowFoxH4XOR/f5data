K000161312: Troubleshooting intermittent TCP connection drops on BIG-IP LTM

Type
Support Solution
Published
2026-05-18
Updated
2026-05-18
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.3
Source
https://my.f5.com/manage/s/article/K000161312

Description

Intermittent TCP connection drops were observed on a BIG-IP LTM virtual server handling TCP traffic. The objective is to determine whether the BIG-IP system is generating TCP resets (RSTs) or dropping packets, affecting traffic between multiple client source IP addresses and backend pool members.

Environment

  • LTM
  • TCP profile

Cause

None

Answer/Recommended Actions

To identify the root cause of the issue, the recommended approach is to capture traffic during the issue occurrence.

1. Enable RST cause logging before starting the capture:

tmsh modify sys db tm.rstcause.pkt value enable
tmsh modify sys db tm.rstcause.log value enable

2. Capture traffic simultaneously on the BIG-IP and the client side:

tcpdump -s0 -vnni 0.0:nnnp host <client_IP> -w /var/tmp/capture.pcap

Or for a client subnet and specific port:

tcpdump -s0 -vnni 0.0:nnnp 'net <subnet/prefix> and port <port>' -w /var/tmp/capture.pcap -C 100 -W 10

3. Disable RST cause logging after completing the capture

tmsh modify sys db tm.rstcause.pkt value disable
tmsh modify sys db tm.rstcause.log value disable

4. Investigate backend server behavior

Review the packet captures and verify whether the backend pool members are sending TCP resets, closing connections unexpectedly, or failing to respond.

Additional Information

If required, collect a fresh QKView after the issue occurs and provide it to the F5 support for further investigation.

CLI:

qkview -s 0

GUI:

System → Support → New QKView (enable unlimited snaplen)
