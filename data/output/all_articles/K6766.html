Known Issue

This is the result of a known issue. When BIG-IP LTM is configured as a Layer 2 forwarding proxy, BIG-IP LTM uses the auto_lasthop global variable destination MAC address, even if the auto_lasthop global variable has been disabled. Therefore, you are unable to disable the auto_lasthop global variable for Layer 2 forwarding traffic.

Using the auto_lasthop global variable destination MAC address for routers configured for Virtual Router Redundancy Protocol (VRRP) will cause traffic to fail in the event of a failover between routers.

The following sequence of events will cause the traffic to fail:

  • The client sends a packet to the VRRP MAC address of the router
  • BIG-IP LTM forwards the packet to the VRRP MAC address of the router
  • The response returns from the non-VRRP MAC address of the router
  • BIG-IP LTM forwards the response packet to the client and records the non-VRRP MAC address as the auto_lasthop global variable MAC address
  • The client sends another packet using the VRRP MAC address of the router
  • BIG-IP LTM uses the auto_lasthop global variable and forwards the response to the non-VRRP MAC address of the router

Under normal conditions, it is not an issue to send packets to the non-VRRP MAC address of the router. However, when the router fails over to the other VRRP router in the middle of a connection, BIG-IP LTM will continue to use the auto_lasthop global variable and send packets to the real non-VRRP MAC address of the now failed router.

F5 Product Development tracked this issue as CR66136 and it was fixed in BIG-IP LTM 9.3 and 9.4. For information about upgrading, refer to the BIG-IP LTM Release Notes.
