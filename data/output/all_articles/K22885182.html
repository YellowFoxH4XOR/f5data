Description

After upgrading BIG-IP version or using the version listed below, BIG-IP administrative users who do not have Advanced shell access cannot make a sftp connection to the BIG-IP system.

In the /var/log/secure file you might find the following log:
err shell[19479]: sftp is disabled in Appliance Mode or TMSH-shell mode

Environment

  • BIG-IP 15.0.0 or higher
  • BIG-IP 14.1.0.2 or higher
  • BIG-IP 13.1.1.5 or higher
  • BIG-IP 12.1.4.1 or higher
  • BIG-IP 11.6.4 or higher
  • BIG-IP 11.5.9 or higher
  • Remote authentication configured for BIG-IP administrative access
  • BIG-IP local user accounts with tmsh-shell access

Cause

SFTP access to the BIG-IP system is now disabled for users with tmsh shell access due to addressing Appliance mode tmsh vulnerability CVE-2019-6616 (Bug ID 703835) , BIG-IP Resource Administrator vulnerability CVE-2019-6618 (Bug ID 745165 ), and CVE-2019-6617 (Bug ID 745387)

Recommended Actions

  • If the user accounts are local BIG-IP accounts authenticated locally (not via Remote Authentication), modify the Terminal Access to Advanced shell
Note: The Default admin account has only TMSH permissions by default
  • If the user accounts are remote user accounts authenticated via remote authentication (Active Directory, LDAP, RADIUS, or TACACS+), use SCP command line program instead of SFTP as SCP is still allowed.
  • If you use WinSCP, you can still use WinSCP GUI by following the steps below;
  1. In WinSCP, either hit New Site to create a new site, or click your existing site (to your BIG-IP) then hit Edit
  2. Under "File protocol" section, change it to "SCP"
  3. Click "Advanced" box
  4. In the Advanced Site Settings, and under "Environment" tree, click "SCP/Shell"
  5. For Shell, type in: bash
  6. Save this configuration or click Login to connect to the BIG-IP
    Note: WinSCP provides Default, /bin/bash, /bin/ksh, sudo su - for Shell in the dropdown list but do NOT select /bin/bash from the dropdown list.  /bin/bash is different from bash, and you would need to type in "bash" at Step 5.
