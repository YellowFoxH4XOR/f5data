Topic

In BIG-IP 9.4.x through 11.3.0, the HTTP Class profile provides a way to classify HTTP traffic and perform an action, such as sending the traffic to a load-balancing pool, rewriting the URI, or forwarding traffic to a selected module, such as ASM.

Starting in BIG-IP 11.4.0, the HTTP Class profile is replaced by the Local Traffic Policies feature. For more information, refer to K14409: The HTTP Class profile is no longer available in BIG-IP 11.4.0 and later.

Description

An HTTP Class profile allows you to sort selected HTTP traffic and perform an action based on the profile configuration. For example, you can send the traffic to a destination, such as a load balancing pool or rewrite the URI.

In addition, you can use the HTTP Class profile to forward traffic to a selected module such as ASM, or WebAccelerator (9.4.x - 10.x).

To configure an HTTP Class profile by using the Configuration utility, navigate to Local Traffic > Profiles > Protocol > HTTP Class.

To classify HTTP traffic, you configure an HTTP Class profile to specify strings that match a list type. The string that you can match to one of these lists can be either a pattern string or a regular expression. The list types are case-sensitive for pattern strings. For example, the system treats the pattern string www.f5.com differently from the pattern string www.F5.com. You can override this case-sensitivity by using the Linux regexp command. The list types that you can use for string matching are listed in the following table:

List typeString exampleRegex example
Hostswww.f5.com - If the hostname in the request matches www.f5.com, route HTTP traffic according to the settings in the profilewww[1-10].f5.com - If the hostname matches www1.f5.com - www10.f5.com, route HTTP traffic according to the settings in the profile
URI paths/path/ - If the URI path matches /path/, route HTTP traffic according to the settings in the profile/path/.* - If the URI path matches /path/ followed by any sequence of characters, route HTTP traffic according to the settings in the profile
HeadersAccept: - If the header matches Accept:, route HTTP traffic according to the settings in the profileAccept* - If the header matches any Accept header type (for example, Accept-Encoding), route HTTP traffic according to the settings in the profile 
Cookiesname1: - If the cookie name matches name1:, route HTTP traffic according to the settings in the profilename? - If the cookie name matches name:, followed by any single character, route HTTP traffic according to the settings in the profile

Once the BIG-IP system matches the string to the corresponding list type, the system can send the traffic to a resource that you specify. Alternatively, you can configure the HTTP Class profile to forward the traffic to a licensed BIG-IP module.

Forwarding traffic through other BIG-IP modules

If the BIG-IP ASM or WebAccelerator modules are licensed on the system, you can configure the HTTP Class profile to direct HTTP traffic to the selected module before sending the traffic to its final destination.

For example, you can use an HTTP Class profile to instruct a virtual server to send traffic matching the hostname www.f5.com through the ASM or WebAccelerator module. To do so, perform the following tasks:

  • Configure the HTTP Class profile
    • Enable the ASM or WebAccelerator module for the profile
    • Configure the matching host entry
  • Associate the HTTP Class profile with the virtual server

You can create an HTTP Class profile from the Local Traffic section of the Configuration utility or from within the BIG-IP ASM or WebAccelerator system. Note that when you classify traffic from within ASM, the HTTP Class profile is known as an application security class. If you create the profile (or application security class) from within a module, the module is already enabled by default. Conversely, if you create an HTTP Class profile using the Local Traffic section of the Configuration utility, you must explicitly enable the Application Security or WebAccelerator setting from within the profile. If you do not explicitly enable this setting, you effectively disable the module for the associated virtual server.

Recommendations

F5 recommends using HTTP Class profiles when it is possible to classify HTTP traffic using simple strings or regex patterns. For more complex operations, you may need to use an iRule.
