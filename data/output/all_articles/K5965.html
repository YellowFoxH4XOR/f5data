K5965: The BIG-IP GTM system is unable to monitor BIG-IP 4.x

Known Issue

When the BIG-IP GTM system attempts to monitor BIG-IP 4.x systems, which have multiple Secure Sockets Layer (SSL) certificates, the BIG-IP GTM bigip_add and big3d_install processes could acquire the incorrect certificate. As a result, the BIG-IP GTM system is unable to communicate with the other system.

Beginning with BIG-IP GTM 9.2.3, the BIG-IP GTM bigip_add and big3d_install processes acquire the correct certificate.

F5 Product Development tracked this issue as CR59299 and it was fixed in BIG-IP GTM 9.2.3. For information about upgrading, refer to the BIG-IP GTM Release Notes.

Resolution

Workaround

If upgrading is not possible, you can work around this issue by manually gathering the correct certificate and copying the certificate into the correct file. To do so, perform the following procedure:

  1. Log in to the BIG-IP GTM command line.
  2. Change directories to the /tmp directory by typing the following command:

    cd /tmp

  3. Type the following openssl command using the IP address of your remote BIG-IP system:

    openssl s_client -tls1 -showcerts -connect <IP address of remote 4.x BIG-IP>:4353 -cert /config/httpd/conf/ssl.crt/server.crt -verify /config/gtm/server.crt -key /config/httpd/conf/ssl.key/server.key > /tmp/outfile

  4. Use a text editor to view the /tmp/outfile file.
  5. Copy the SSL certificate contained in the /tmp/outfile file.

    Important: You must include the BEGIN CERTIFICATE and END CERTIFICATE lines.

  6. Paste the certificate to the top of the /config/gtm/server.crt file. Ensure that there is a blank line between the end of this certificate and the beginning of the next certificate.
  7. Test iQuery by typing the following iqdump command:

    iqdump <IP address of remote 4.x BIG-IP>

    Note: It may take a few minutes for the big3d process to read the new certificate and register the remote BIG-IP 4.x as available.
