K000159929: F5 propagates low window size even if receive window and send buffer size is set with scale factor

Description

The F5 BIG-IP LTM system advertises a lower initial TCP window size than the maximum configured value in the TCP profile, even when the TCP profile is set with a higher window scale factor. This behavior can be observed in packet captures where the initial window size appears smaller than expected, potentially causing concerns about configuration effectiveness.

Environment

  • Product: BIG-IP LTM
  • Version: 17.1.3
  • Standard TCP profile applied to the affected virtual server
  • TCP receive window and send buffer size set to 262140 (scale factor 2)

Cause

The lower initial TCP window size is due to the standard operation of TCP slow start and congestion avoidance algorithms, as implemented by F5 BIG-IP. These algorithms intentionally limit the initial advertised window size to prevent network congestion, regardless of the maximum window size configured in the TCP profile. This behavior is compliant with RFC 5681 and F5 documentation.

Answer/Recommended Actions

  • No changes are required to the F5 configuration; the system is operating as designed.
  • If higher throughput is required, review and adjust TCP profile parameters (e.g., window scaling, buffer sizes) within the limits of network and application requirements. Note that the initial window size will still be governed by TCP slow start.
  • Continue to monitor application performance and packet captures to ensure expected behavior.
  • Refer to RFC 5681 for further details on TCP slow start and congestion avoidance behavior.

Additional Information

  • The initial TCP window size advertised by F5 may be lower than the configured maximum due to TCP slow start and congestion avoidance mechanisms.
  • The calculated window size increases over time during the connection, as expected per TCP standards.
  • This is expected and standards-compliant behavior, not a misconfiguration or bug.
