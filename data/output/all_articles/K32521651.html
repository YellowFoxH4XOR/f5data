Known Issue

When a local traffic policy is configured with a forward action, the configuration may fail to load after you perform an upgrade.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system is configured with a local traffic policy.
  • The local traffic policy uses a traffic match forward to action of member.
  • You upgrade the BIG-IP system to an affected release.
  • The BIG-IP system attempts to load the local traffic policy configuration.

Impact

The configuration load fails and the BIG-IP system cannot process traffic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you view the local traffic policy rule, the actions section contains syntax similar to the following example:

    ltm policy /<partition>/<local traffic policy name> {
            controls { forwarding }
            requires { http }
            rules {
                <rule name> {
                    actions {
                        0 {
                            forward
                            select
                            member <ip address:<port>
                        }
                    }
                    conditions {
                        0 {
                            http-uri
                            contains
                            values { /<uri> }
                        }
                    }
                    ordinal 1
                }
            }

  • After you perform an upgrade, the system displays an error message similar to the following example when loading the configuration:

    emerg load_config_files: "/usr/bin/tmsh -n -g load sys config partitions all " - failed. -- 010716de:3: Policy '/<partition>/<local traffic policy name>', rule '<policy rule name>'; target 'forward' action 'select' does not support parameter of type 'member'. Unexpected Error: Loading configuration process failed.

Workaround

To work around this issue, you can manually modify the /config/bigip.conf configuration file, changing the action use of member to node. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the command line of the affected BIG-IP system.
  2. To create a backup copy of the /config/bigip.conf file, type the following command:

    cp /config/bigip.conf /config/bigip.conf_681757

  3. Using a text editor, open the /config/bigip.conf file.
  4. Locate the BIG-IP local traffic policies.

    The following is an example of the beginning of local traffic policy syntax:

    ltm policy /<partition>/<local traffic policy name>

  5. Replace the word member with the word node in all rule configurations that use the forward selection of member.

    For example:

    Existing syntax:
    rules {
                <local traffic policy rule name> {
                    actions {
                        0 {
                            forward
                            select
                            member <ip address>:<port>
                        }
                    }

    Updated syntax:

    rules {
                <local traffic policy rule name> {
                    actions {
                        0 {
                            forward
                            select
                            node <ip address>:<port>
                        }
                    }

    Note: The actions section forward select "member" is replaced with "node".

  6. Save the configuration changes to the /config/bigip.conf file.
  7. To load the configuration, type the following TMOS Shell (tmsh) command:

    tmsh load /sys config
