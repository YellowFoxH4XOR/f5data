K000161427: Critical TMM memory pressure and stale connection accumulation on Standby unit (Connection Mirroring)

Description

Critical memory pressure and accumulation of stale mirrored connections occur on the Standby unit in a BIG-IP LTM high-availability pair. The Standby unit holds significantly more connections than the Active unit, resulting in repeated activation of aggressive mode sweeper and memory pressure warnings. The Standby unit fails to properly reap mirrored connections after closure or timeout on the Active unit. Log messages include:

Aggressive mode sweeper: /Common/default-eviction-policy (1) (global memory) X Connections killed

TCP: Memory pressure activated

Limiting open port RST response from 501 to 500 packets/sec for traffic-group /Common/traffic-group-1

Environment

  • Product: BIG-IP LTM
  • Version: 17.1.3
  • Configured as an HA pair (Active/Standby)
  • High volume of short-lived TCP/UDP connections
  • Connection Mirroring enabled on several virtual servers
  • FastL4 profile with PVA acceleration initially enabled
  • Asymmetric routing (nPath/DSR) configured on affected virtual servers

Cause

The issue is caused by enabling PVA acceleration in the FastL4 profile on virtual servers configured for nPath routing with connection mirroring. This results in mirrored connections accumulating as stale entries on the Standby unit, leading to memory exhaustion and repeated aggressive sweeper activation.

Answer/Recommended Actions

  1. Disable PVA acceleration in the FastL4 profile for all virtual servers using nPath routing and connection mirroring.
  2. Temporarily enable the tmm.returnmemory database variable to allow the system to sweep and reclaim memory:
    tmsh modify /sys db tmm.returnmemory value enable
    Allow the system to sweep the cache for at least 15 minutes, then disable:
    tmsh modify /sys db tmm.returnmemory value disable
  3. Monitor memory usage and connection table statistics to confirm resolution:
    tmctl -s pages_used,pages_avail -d cluster page_stats | awk 'NR>2 {used += $1; total += $2} END {print (used / total * 100)"%"}'
  4. Ensure that asymmetric routing and connection mirroring are not used together with PVA acceleration.
  5. To view current connection statistics for virtual servers:
    tmctl virtual_server_stat -s name,clientside.cur_conns,clientside.max_conns,tot_pva_assist_conn -K clientside.cur_conns -O -L 5

Additional Information

  • Disabling PVA acceleration and enabling tmm.returnmemory variable significantly reduces memory usage and improves system stability.
  • The issue is most prominent in environments with high-frequency, short-lived connections and connection mirroring enabled for stateful failover.
  • The Standby unit may accumulate more than three times the number of active connections compared to the Active unit if this configuration is present.
  • The aggressive mode sweeper may not clear all stale mirrored entries if the configuration issue is not addressed.
