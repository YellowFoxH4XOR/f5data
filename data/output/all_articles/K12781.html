Known Issue

Description

The httpd process caches the BIG-IP system DNS server configuration for its DNS resolution requests. If you add a new DNS server to the BIG-IP configuration or modify an existing DNS server entry in the BIG-IP configuration, the httpd process does not refresh its cache and continues to forward its DNS resolution requests to the previous DNS server, if configured.

Impact

The issue may result in the httpd process failing to resolve its DNS resolution requests if the previous DNS server is not available.

Symptoms

As a result of this issue, the BIG-IP system may experience the following symptoms:

  • BIG-IP iHealth lists Heuristic H380448 on the Diagnostics > Identified > Low screen.
  • The Configuration utility fails to authenticate users using a remote authentication method (such as Active Directory, LDAP, or Radius) which relies on DNS resolution, the remote authentication fails at the DNS resolution, and denies legitimate users access to the Configuration utility. For example, when the DNS resolution for the radius server fails and subsequently the Configuration utility fails user authentication, the httpd process logs error messages that appear similar to the following example into the /var/log/secure file:

    pam_radius_auth: Failed looking up IP address for RADIUS server <radius server FQDN> (errcode=9)
    pam_radius_auth: All RADIUS servers failed to respond.

Resolution

Status

F5 has confirmed that this issue exists in the products listed in the Applies To box. ID 224966 (formerly CR138207) has been assigned to this issue.

Workaround

To work around this issue, you can restart the httpd process to reload the DNS configuration. To do so, perform the following procedure:

Impact of workaround: The Configuration utility will not be accessible during the httpd process restart, the BIG-IP system traffic processing will continue to function.

  1. Log in to the command line.
  2. To restart the httpd process, type the following command:

    bigstart restart httpd
