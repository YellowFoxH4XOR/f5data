K98410533: Validating a nil element against a schema causes a schema check violation

Type
Support Solution
Published
2022-10-01
Updated
2023-02-21
Applies to
  • BIG-IP ASM: 15.1.6
Source
https://my.f5.com/manage/s/article/K98410533

Description

 

Malformed document - schema validation failed | xsi:nil not allowed in element

example of an xml element:
  <iAmAnElement xmlns=" http://www.path/schema" xmlns:xsi=" http://www.w3.org/2001/XMLSchema-instance" xsi:nil="true"/>

against schema
<?xml version="1.0" encoding="UTF-8"?>
<xsd:schema elementFormDefault="qualified"
        xmlns:xsd=" http://www.w3.org/2001/XMLSchema"
        xmlns:xsi=" http://www.w3.org/2001/XMLSchema-instance"
        xmlns=" http://www.path/schema"
        targetNamespace="http://www.path/schema">

<xsd:element name="iAmAnElement" type="a_type" />                               --- no nillable attribute

<xsd:simpleType name="a_type">
                <xsd:restriction base="xsd:string"/>
        </xsd:simpleType>
</xsd:schema>

Environment

  • Advanced WAF
  • XML schema profile
  • Request containing a nil='true' value
     

Cause
  When using the xmlns:xsi=" http://www.w3.org/2001/XMLSchema-instance" namespace, elements are by default not nillable.  In order to allow a nil="true" value, the element definition must contain nillable="true" explicitly.

Recommended Actions

  1.  change to schema to include nillable = "true" attribute

    <?xml version="1.0" encoding="UTF-8"?>
    <xsd:schema elementFormDefault="qualified"
            xmlns:xsd=" http://www.w3.org/2001/XMLSchema"
            xmlns:xsi=" http://www.w3.org/2001/XMLSchema-instance"
            xmlns=" http://www.path/schema"
            targetNamespace="http://www.path/schema">

    <xsd:element name="iAmAnElement" type="a_type" nillable="true"/>

    <xsd:simpleType name="a_type">
                    <xsd:restriction base="xsd:string"/>
            </xsd:simpleType>
    </xsd:schema>
