Description:

When there are multiple IP addresses in the XFF header, the bot-defense event log takes the last IP address only if they are separated by commas without any whitespace among them. Otherwise, the source IP address will be the address in the IP address packet of the connection. Below are some examples:

1- XFF value without whitespaces: Source IP address is the last IP address in XFF header 30.30.30.30.

curl http://10.10.10.244/holle -H "XFF: 20.20.20.20,30.30.30.30"

2- XFF value with whitespaces: Source IP address is the address of the IP packet.

curl http://10.10.10.244/holle -H "XFF: 20.20.20.20, 30.30.30.30" -v

3- XFF value with whitespaces in quotes: Source IP address is the address of the IP packet.

curl http://10.10.10.244/holle -H 'XFF: "20.20.20.20, 30.30.30.30"' -v

Environment:

  • Bot-defense profile
  • HTTP profile configured to accept XFF header

Cause:

Expected behaviour

Recommended Action:

None

Additional Information:

According to RFC 7230 whitespaces in the header value are optional

https://datatracker.ietf.org/doc/html/rfc7230#section-3.2

header-field = field-name ":" OWS field-value OWS

The section 4 of RFC 7239 shows several examples, one is with whitespaces between IP addresses:
