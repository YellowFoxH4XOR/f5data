Description

The Enforce RFC Compliance feature was introduced in BIG-IP 15.1.0.

The BIG-IP system can now perform basic RFC compliance checks on HTTP traffic as described in the RFC(s) for the HTTP protocol. When you enable the Enforce RFC Compliance setting on an HTTP profile and then assign the profile to a virtual server, the BIG-IP system attempts to reject non-RFC-compliant HTTP traffic and reset the connection. This feature is disabled by default.

The feature is intended to detect a specifically crafted HTTP request that contains non-compliant Content-Length and Transfer-Encoding headers, also known as HTTP Desync Attack. Currently, it does not perform full RFC-compliance checks on all headers (including the Host header).

For more information about HTTP Desync Attack, refer to K50375550: A specifically crafted HTTP request may lead the BIG-IP system to pass malformed HTTP requests to a target pool member web server (HTTP Desync Attack).

Environment

  • HTTP profile
  • Enforce RFC Compliance feature

Cause

None

Recommended Actions

To reject specifically crafted HTTP requests that contain Content-Length and Transfer-Encoding headers, you can enable the Enforce RFC Compliance feature in the HTTP profile.

Note: In BIG-IP 14.1.2.3 and earlier, you can enable this feature with the tmm.http.rfc.enforcement database variable. However, this variable can only be enabled on a global scale.

Additional Information

If the affected BIG-IP system is licensed and provisioned with BIG-IP ASM/Advanced WAF, you can reject this and other non-RFC-compliant HTTP traffic by configuring an appropriate BIG-IP ASM/Advanced WAF security policy to block malformed HTTP requests.
