Topic

You can configure the BIG-IP LTM system to allow internal nodes to make outbound FTP connections. Due to the nature of the FTP protocol, you must perform certain configuration requirements on the BIG-IP system to accomplish this.

For example, you must associate the FTP profile with the virtual server. The FTP profile allows the BIG-IP LTM system to alter the FTP control data so that address translation works correctly. In addition, since it is common for nodes behind the BIG-IP system to have non-routable IP addresses, you may need to configure the BIG-IP LTM system to perform source address translation both in the IP header and in the FTP control channel payload.

The following configuration ensures that, when a node opens a new FTP control connection to an FTP server, the virtual server processes the connection and the system passes it to the pool members, which are the devices directly upstream from the BIG-IP LTM. With address translation disabled for the virtual server, the destination address remains that of the FTP server and the upstream device forwards the packets.

When you configure a secure network address translation (SNAT) object, the system does the following:

  • Replaces the source address with that of the SNAT address
  • Modifies the FTP control data, as necessary, to use the correct new IP address and to detect the FTP mode (passive or active) that is in use
  • Correctly handles any necessary FTP data connections

Note: For File Transfer Protocol Secure (FTPS) load balancing, refer to K9347: Configuring passthrough FTPS load balancing.

To configure the BIG-IP LTM to allow outbound FTP sessions, you must perform the following procedures:

  • Configuring the FTP pool
  • Configuring the FTP virtual server
  • Configuring the FTP iRule (optional)
  • Configuring the Source Address Affinity persistence profile (optional) 

Configuring the FTP pool

The pool member IP address is the IP address of the routers directly upstream from the BIG-IP LTM system.

To configure the FTP pool, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Pools.
  3. Click Create.
  4. Type a name for the FTP pool.
  5. In the Health Monitor section, choose the gateway_icmp monitor from the Available window.
  6. Move the gateway_icmp monitor to the Active window.
  7. In the Address field, enter the IP address of the routers directly upstream from the BIG-IP LTM system.

    Note: This is typically the same IP address that is specified for the gateway address. It can also be separate from the gateway address, or you may define multiple router IP addresses.

  8. From the Service Port menu, select * All Services.
  9. Click Add.

Configuring the FTP virtual server

To configure the FTP virtual server, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers.
  3. Click Create.
  4. Type a name for the FTP virtual server.
  5. In the Destination section, click Network.

    Note: In BIG-IP 11.6.0, there is no radio button selection for virtual server Destination type of Host or Network.

  6. Enter 0.0.0.0 for both the Address and Mask.

    Note: You can use a specific IP address and netmask.

  7. Select FTP from the Service Port menu.
  8. Select Advanced from the Configuration menu.
  9. Select Standard from the Type menu.
  10. Select ftp from the FTP Profile menu.

    Note: F5 recommends that you use the default FTP profile.

  11. Select Enabled on from the VLAN Traffic menu.
  12. Select the VLANs from which nodes will initiate FTP sessions.
  13. Clear the Address Translation and Port Translation check boxes.
  14. If the source IP address must be changed due to the use of non-routable IP addresses, choose a SNAT pool or Auto Map from the SNAT Pool menu.
  15. In the Resources section, select the FTP pool that you created from the Default Pool drop-down menu.
  16. Click Finished.

Configuring the FTP iRule (optional)

Optionally, when the BIG-IP system must translate the node IP addresses to a specific address, you can configure the FTP iRule.

For example, if you want the BIG-IP LTM system to translate the client IP address 10.1.1.100 to 100.100.100.100 before sending the request to the ftp_gateway_pool pool member, or translate the client IP address 10.1.1.101 to 100.100.100.111 before sending the request to the ftp_gateway_pool pool member, you can use the following iRule:

when CLIENT_ACCEPTED {
  if { [IP::addr [IP::client_addr] equals 10.1.1.100]  } {
    snat 100.100.100.100
    pool ftp_gateway_pool
  }
  elseif { [IP::addr [IP::client_addr] equals 10.1.1.101] } {
    snat 100.100.100.111
    pool ftp_gateway_pool
  }
  else {
    discard
  }
}

To configure the FTP iRule, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules.
  3. Click Create.
  4. Type a name for the iRule.
  5. Enter the iRule code in the Definition field.
  6. Click Finished.
  7. Associate the iRule with the FTP virtual server.

Configuring the source address affinity persistence profile (optional)

Optionally, if the BIG-IP system sends connections to multiple upstream routers or firewalls, and if the FTP control and data channels need to take the same path, you can configure the source address affinity persistence profile.

For example, when the upstream devices are firewalls performing FTP connection tracking, you can configure the persistence profile and associate it with the virtual server. In this case, a source address persistence profile ensures that the BIG-IP LTM system sends multiple outgoing connections through the same gateway.

Note: If the BIG-IP system sends connections to one upstream router or firewall, this step is not necessary.

To configure the source address affinity persistence profile, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles.
  3. Select the Persistence menu.
  4. Click Create.
  5. Type a name for the persistence profile.
  6. Select Source Address Affinity from the Persistence Type menu.
  7. Click Finished.
  8. Associate the persistence profile with the FTP virtual server.

Best Practices

When implementing a BIG-IP Link Controller, F5 recommends that you use the configuration defined in this article. The BIG-IP Link Controller configuration usually contains an any:any virtual server configuration with an associated SNAT object. The any:21 virtual server with FTP profile noted in this article ensures that the BIG-IP Link Controller properly translates the FTP control protocol.

When applying SNATs and a forwarding virtual that forwards general purpose traffic, F5 recommends that you create a unique any:21 forwarding virtual server that is associated with an FTP profile. The any:any forwarding virtual configured with SNATs does not properly translate the FTP control protocol.
