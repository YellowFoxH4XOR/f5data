K84508267: Traffic to virtual server fails during TLS handshake after concurrently updating SSL certificates

Type
Support Solution
Published
2022-06-09
Updated
2023-02-21
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.X, 15.1.7, 15.1.6, 15.1.5, 15.1.4, 15.1.3, 15.1.8, 15.1.1, 15.1.0, 15.1.2
Source
https://my.f5.com/manage/s/article/K84508267

Description
After an update to a certificate management tool, all traffic to some TLS virtual servers fail.

Two simultaneous updates from different icrd processes to the same certificate in /var/log/audit
Feb 5 12:34:56 example.bigip.local notice icrd_child[12345]: 01420002:5: AUDIT - pid=12345 user=automation_user folder=/Common module=(tmos)# status=[Command OK] cmd_data=install sys crypto cert my_cerificate { from-local-file /var/local/ucs/:Common:my_certificate }
Feb 5 12:34:56 example.bigip.local notice icrd_child[54321]: 01420002:5: AUDIT - pid=54321 user=automation_user folder=/Common module=(tmos)# status=[Command OK] cmd_data=install sys crypto cert my_cerificate { from-local-file /var/local/ucs/:Common:my_certificate }

You may see the following logs in /var/log/ltm
crit tmm<tmm id>[<pid>]: 01260029:2: Profile <ssl profile> - <path/to/certificate> reading: Unknown error
crit tmm<tmm id>[<pid>]: 01260030:2: Profile <ssl profile> - cannot load key/cert/chain: <path/to/key>/<path/to/certificate>/<path/to/chain cerficate> Unknown error

Example:
crit tmm2[12345]: 01260029:2: Profile /Common/my_ssl_profile - /config/filestore/files_d/Common_d/certificate_d/:Common:my_chain_cerificate reading: Unknown error.
crit tmm4[42865]: 01260030:2: Profile /Common/my_ssl_profile - cannot load key/cert/chain: /config/filestore/files_d/Common_d/certificate_key_d/:Common:my_key//config/filestore/files_d/Common_d/certificate_d/:Common:my_certificate//config/filestore/files_d/Common_d/certificate_d/:Common:my_chain_cerificate: Unknown error.

When a client tries to access the virtual server, the connection will fill fail in the SSL handshake. A packet capture will show the Client Hello but no Server Hello. /var/log/ltm will have messages similar to this:
warning tmm<tmm id>[<pid>]: 01260009:4: <source IP>:<source port> -> <virtual server IP>:<virtual server port>: Connection error: hud_ssl_handler:1208: alert(40) invalid profile unknown on VIP <virtual server name>

Example:
warning tmm4[12345]: 01260009:4: 1.1.1.1:12345 -> 2.2.2.2:443: Connection error: hud_ssl_handler:1208: alert(40) invalid profile unknown on VIP /Common/my_virtual_server

You may see an error message in the GUI when trying to update the SSL profile:
01071ac9:3: Unable to load the certificate file (/Common/my_certificate) - error:0D07803A:asn1 encoding > routines:ASN1_ITEM_EX_D2I:nested asn1 error.

Environment

  • BIG-IP
  • Automated certificate updates

Cause
This can happen when multiple icrd_child pids are updating the same object at the same time. This was observed after a recent update to Venafi certificate manager which allowed concurrent certificate updates. The same intermediate chain certificate was updated multiple times due to being in SSL profile for multiple VIPs and the tool updated the whole certificate chain for each profile.
F5 has filed Bug ID 1110485 for the virtual server and SSL profile behavior

Recommended Actions

Ensure a certificate object isn't updated if it doesn't need any change and/or ensure multiple REST API calls are not read/writing to same filesystem object at the same time
