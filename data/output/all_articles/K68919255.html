K68919255: Creating Istio Object for Aspen Mesh fails with webhook validation error

Type
Support Solution
Published
2021-09-27
Updated
2023-02-21
Applies to
  • Aspen Mesh
Source
https://my.f5.com/manage/s/article/K68919255

Description

When trying to create a service mesh object like Service Entry, it fails with the following error message:

> oc apply -f service-entry.yaml
Error from server (InternalError): error when creating "service-entry.yaml": Internal error occurred: failed calling webhook "validation.istio.io": Post "https://istiod.istio-system.svc:443/validate?timeout=30s": x509: certificate signed by unknown authority (possibly because of "crypto/rsa: verification error" while trying to verify candidate authority certificate "Root CA rsa")
This error can occur while creating any Istio object.

Environment

  • Aspen Mesh: 1.9.x 

Cause

Upon investigation, it was found that the Root Certificate was not matching for the validation webhook “istiod-istio-system" and secret “cacerts”. You can use the following commands to verify the root certificate in both objects. 

> kubectl  get validatingwebhookconfiguration istiod-istio-system –o jsonpath='{.webhooks[0].clientConfig.caBundle}' |  md5sum
f9ebddde0c379d47078ae20745dde5c9

> kubectl  get secrets -n istio-system cacerts -o yaml -o jsonpath='{.data.root-cert\.pem}' | md5sum
F9ebddde0c379d47078ae20745dde5c9

If you want to check the certificate for their issuer and subject, you can use the following command:

> kubectl get secrets -n istio-system cacerts -o yaml -o jsonpath='{.data.root-cert\.pem}' | base64 -d | openssl x509 -noout -text

Recommended Actions

Md5 hash returned the same value for both objects which means that these 2 objects have the same root CA. If it returns different values, we will need to delete the existing secret cacerts from istio-system namespace and Provisioning Existing Certificate Authority (CA) Certificates in Aspen Mesh. 

> kubectl delete secret -n istio-system  cacerts

> kubectl create secret generic cacerts -n istio-system --from-file=<ca-cert.pem> \ --from-file=<ca-key.pem> --from-file=<root-cert.pem> \ --from-file=<cert-chain.pem>

Once the root certificate is the same for both objects, service entry object deploys successfully.

Additional Information

In case of not providing any existing certificate, Aspen Mesh will install a self-signed certificate for the clusters.
