Known Issue

A BIG-IP system in Appliance mode configuration may fail to run certain TMOS Shell (tmsh) commands.

This issue occurs when all of the following conditions are met:

  • You are using one of the following BIG-IP platforms:
    • BIG-IP i2x00 series
    • BIG-IP i4x00 series
    • BIG-IP i5x00 series
    • BIG-IP i7x00 series
    • BIG-IP i10x00 series
    • VIPRION B4450 blade
  • Your BIG-IP system runs in the Appliance mode.
  • You upgrade the BIG-IP software from BIG-IP 10.x or 11.x to the software version in the Applies to (see versions) box, located in the upper-right corner of this article.
  • You boot into the upgraded software volume and attempt to run the unix-ls, unix-rm, or unix-mv utility command from tmsh. The command may appear similar to the following example:

    tmsh run /util unix-ls /var/log

There is no Advanced Shell (bash) access to the file system when the BIG-IP system is in Appliance mode. This is the intended purpose of Appliance mode. However, you should be able to perform certain file operations using the utility commands available in tmsh such as unix-ls, unix-rm, or unix-mv. These utility commands do not work as expected due to this issue.

Impact

You cannot perform certain file operations on a BIG-IP system in Appliance mode.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The BIG-IP system fails to successfully perform certain file operations.

    For example, the command to list the contents in the /var/log directory and the corresponding error messages may appear as follows:

    tmsh run /util unix-ls /var/log

    exception: (Failed to canonicalize "/shared/f5optics/images") (util/RealpathHelper.cpp, line 49), continuing...
    Data Input Error: /var/log is not an accessible directory for the current mode.

Resolution

Status

F5 Product Development has assigned ID 669288 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies to (see versions) box, located in the upper-right corner of this article. For information about releases, point releases, or hotfixes that resolve this issue, refer to the following table.

Workaround

To work around this issue, you can boot the BIG-IP system into single-user mode and manually create the missing directory named /shared/f5optics/images. To do so, perform the following procedure:

Impact of workaround: If the BIG-IP system is the active member of a redundant pair, booting the system into single-user mode causes a failover. If the system is a standalone unit, booting the system into single-user mode interrupts traffic processing. F5 recommends that you perform this procedure during a maintenance window.

  1. Boot the BIG-IP system into single-user mode using one of the procedures described in the following articles:
    • K14662: Restarting the BIG-IP system in single-user mode (GRUB2)
    • K4178: Restarting the BIG-IP system in single-user mode (GRUB 0.97)

      Note: To determine the GRUB version of your BIG-IP system, refer to K14658: Determining the GRUB bootloader version on the BIG-IP, BIG-IQ, or Enterprise Manager system.

  2. Create the /shared/f5optics/images directory by typing the following command:

    mkdir -m 777 -p /shared/f5optics/images

  3. Restart the BIG-IP system by typing the following command:

    reboot
