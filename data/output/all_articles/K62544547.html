Known Issue

The Internet Content Adaptation Protocol (ICAP) ADAPT::result bypass command may cause a bad state transition after the server returns a 100-continue response.

This issue occurs when the following conditions are met:

  • There is an ICAP adapt profile associated with an internal virtual server.
  • The internal virtual server has an iRule that uses one of the following events:
    • when ADAPT_REQUEST_RESULT {
      ADAPT::result bypass
      }
    • when ADAPT_RESPONSE_RESULT {
      ADAPT::result bypass
      }

Impact

The BIG-IP system resets the connection to the affected virtual server and logs an unexpected state transition.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • You observe that the ADAPT::result bypass command does not work as expected in the ADAPT_REQUEST_RESULT event when the ICAP server returns a 100-continue response.

Workaround

To work around this issue, avoid using the ADAPT::result bypass iRules command when Message Preview is not configured on the ICAP server.

Impact of workaround: The impact of the suggested workaround depends on the specific environment. F5 recommends that you test any such changes during a maintenance window and consider the possible impact on your specific environment.
