What Happened?

When a Site is deployed and runs Virtual Kubernetes (vK8s), the resources like CPU and memory are not showing up less even when there are lot more available. Also, in the same vK8s dashboard, the information shown in resource widgets vs the Sites tile is different, and this could be confusing.

Resources can be viewed in one of the following ways:

  • Use Site dashboard in Console. Log in to Console and go to Sites > Site List in Cloud and Edge Sites service. Click on a Site to open its dashboard view and switch to Nodes tab to see the resource widgets.
  • Use vK8s dashboard. Go to Applications > Virtual K8s in Distributed Applications service. Click on the vK8s object to open its dashboard to see the resource widgets. In the same view beneath the widgets, the Sites tiles is present which also shows CPU, memory, and storage columns. 
  • Use kubectl with the vK8s kubeconfig from CLI. The commands kubectl describe nodes and kubectl get nodes return the resource information.

Environment

The following services in F5® Distributed Cloud Console:

  • Cloud and Edge Sites
  • Distributed Apps

Resolution/Answer

The vK8s are per namespace, meaning, if a Site is selected as part of vK8s, then the vK8s cluster running on the Site will run only that namespace. Also, out of the total available Site resources, only a specific portion is allocated for vK8s on that Site. This is required because Site needs to run other infrastructure related services and resource allocation for vK8s will be limited to specific portion of total available Site resources. Therefore, the associated vK8s dashboard reports are only to be understood within that scope.

The following apply when using kubectl with the vK8s:

  • The kubectl get nodes command  against vK8s will not return any nodes unless something is deployed to the Site(s).
  • Deploying a Site with certified hardware image such as  xxxxxx-regular-nic-voltmesh/combo/  will allocate a percentage of RAM, CPU, and storage to system processes. This means only a specific percentage of resources will be available for compute workloads. Recommendation is to use xxxxx-regular-nic-voltstack-combo for compute use-cases because of this behavior.
  • The kubectl describe node output uses kubectl get node and kubectl get pods to display. Hence the output is different on Site vs vK8s since on vK8s only the pods in the namespace are present. This is as per design and therefore, check the PodStatusconditions which indicate the reason why the pod cannot be scheduled (such as insufficient CPU or memory).
