Topic



When booting a FirePass controller equipped with a Cavium CN1005 SSL accelerator card, you may receive the following error message on the Reports: System Logs page:

kernel   DDR discovery failure. err: 1

This error message does not indicate an error. Instead, the error message indicates that the boot-time hardware probe did not find double-data rate (DDR) memory on this model of SSL accelerator card. This is the expected behavior from a FirePass controller equipped with a Cavium CN1005 SSL accelerator card.

Note: This is not expected behavior for a FirePass controller equipped with a Cavium CN1120 SSL accelerator card with FIPS processing.

The full sequence of the syslog error messages appears similar to the following example:

kernel: 2 Nitrox/Nitro
-Lite cores enabled.   
kernel   Registeration is a success The major device number is 125   
kernel   dma mask = ffffffff   
kernel   Interrupt line = 1d   
kernel   Allocating resources to manage 2 MB of Context Memory.   
kernel   Resorting to Context memory on Host.   
kernel   DDR discovery failure. err: 1   
kernel   bar 1: 9400   
kernel   bar 0: 9800   
kernel   PCI device 177d:0003   
kernel   Trying Nitrox-Lite only...   
kernel   Nitrox/Nitrox-Lite device not found.   
kernel   Nitrox/Nitrox-Lite driver ver 2.8

The error messages are from the Nitrox Linux kernel driver. The driver supports different SSL accelerator cards. Some cards use DDR synchronous dynamic random access memory (SDRAM); others use different memory types or use the host system memory. The driver performs a probe at boot time to determine whether a card is present. If the card is present, the driver determines the hardware configuration of the card, including the memory configuration.
