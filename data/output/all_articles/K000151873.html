Description

When using source address persistence with the "match-across-services" or "match-across-virtuals" feature enabled on multiple virtual servers, some virtual servers may not create their own persistence records even though they are actively processing traffic. This can cause confusion when reviewing the persistence table, as not all virtual servers will display separate entries for each client connection.

Environment

  • Persistence profile
  • match-across-services/match-across-virtuals

Cause

This behavior is by design and does not indicate an issue with BIG-IP LTM’s operation.

Recommended Actions

This is expected behavior due to how the "match across" features operate:

  • match-across-services: Shares a single persistence record among all virtual servers with the same destination IP but different ports.
  • match-across-virtuals: Shares a single persistence record among all virtual servers using the same persistence profile, regardless of destination IP.

When a client initiates a connection, only the first relevant virtual server creates a new persistence record. Other virtual servers that match the criteria will reference this existing record instead of creating their own. As a result, some VS will not show unique entries in the persistence table for every client—they are correctly referencing shared records.
