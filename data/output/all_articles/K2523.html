BIG-IP is a very secure device in its default configuration. To provide additional protection against DoS and syn flood attacks, you can make the following changes to BIG-IP:

  • Upgrade BIG-IP
  • Lower the service timeout settings
  • Lower simple service monitor settings

Upgrade BIG-IP

To provide additional protection against attacks, upgrade to the most current version of BIG-IP. As the attacks change, so do the protection levels of BIG-IP. The most current version of BIG-IP will protect you against the most current attacks. For example, versions 4.5 and higher include a feature that is specifically designed to help BIG-IP stop DoS attacks like a syn flood. This feature is called adaptive reaping, and is used as a global attribute in relation to the amount of free memory on the BIG-IP. If the memory used reaches a certain percentage (known as the reaper lowater setting), service timeouts become more aggressive, and when the memory used reaches an even higher percentage (known as the reaper hiwater), no further connections are allowed through the BIG-IP until the memory usage falls back below the hiwater threshold. The default percentages for these thresholds are 95 for reaper hiwater and 85 for reaper lowater.

Lower service timeout settings

Unacknowledged syn packets can cause the kernel memory to rise, which, along with the speed of the Internet connection, is directly related to how fast idle connections need to be reaped to sustain a DoS attack. Lowering the service timeout for port 80 to 30 seconds (or less, in extreme circumstances) will remove unacknowledged syn packets from the connection table.

To set the service timeout to 30 seconds for TCP port 80, type the following command:

bigpipe service 80 timeout tcp 30

Lower simple service monitor settings

Under a heavy DoS attack, all nodes may be marked down, come back up and bounce a few times before stabilizing again. To determine if this is happening, view the /var/log/bigd file and see if there are messages stating all configured nodes are down.

To avoid this issue, change simple service monitor settings so monitoring happens more frequently. If the general check is 5 seconds with a timeout of 16 seconds (5/16), you may want to change it to a 3/21 or 3/31 ratio so that there are 7 or 10 chances for the ping to come back instead of just 3 chances.

If the problem is still occurring after you make this change, the service monitor settings may need further adjustment. For more information about these settings, refer to the Monitors chapter in the BIG-IP Reference Guide.

Enable Syn cookies

If you are running BIG-IP version 4.5 PTF-04 or later, you can enable syn cookies to protect against syn flood attacks. For more information, refer to the Preventing SYN Flood Attacks section of the BIG-IP Reference Guide.
