Known Issue

This is the result of a known issue. Dynamic routes are injected into the kernel routing table with a metric of 0 (zero), while management routes are injected with a metric of 245. Since routes with lower metrics are preferred, if the BIG-IP learns a dynamic route which conflicts with a statically configured management route, the BIG-IP will prefer the dynamic route over the matching static management route. As a result, management traffic originating from the BIG-IP system may use a dynamically learned route rather than the intended static management route. Inbound connections to the management address and their responses will use the existing static management routes as expected.

F5 Networks Product Development tracked this issue as CR118034 for the 9.4.x software branch, and it was fixed in BIG-IP version 9.4.7. For information about upgrading, refer to the BIG-IP LTM Release Notes.

F5 Networks Product Development is tracking this issue as CR118034-1 for the 10.x software branch.

Workaround

You can work around this issue by creating a route map on remote routers, which prevents the remote routers from advertising routes that conflict with static management routes configured on the BIG-IP system.
