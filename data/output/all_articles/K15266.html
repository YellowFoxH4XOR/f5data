Description

You want to create a local user database on the BIG-IP APM system from a comma separated values (CSV) file import.

Environment

  • APM
  • localdb authentication

Cause

None


Recommended Actions

In BIG-IP APM 11.4.0 and later, you can create and query a local user database for access policy authentication. This feature allows you to create multiple local user databases and provide on-box user access authentication, segment users, and maintain individual user information.

The BIG-IP APM system can import an existing user database from a properly formatted CSV file. The following information explains the appropriate formatting of the CSV file, required (minimum) fields of the file, and the steps to create a new local user database and import data from the CSV file.

CSV field formats

The 18 fields listed in the following table must be stated in the first line of the CSV file, even if a specific field is not used for the local user database:

FieldDescriptionImportedMinimum
uidA unique, positive numeric value for the userYesYes
unameThe user name (logon name)YesYes
instance/<partition>/<db_instance> The BIG-IP APM administrative partition and dB instance nameYesYes
passwordThe user's encrypted password. Refer to the Password encryption considerations section.YesYes
user_groupsA comma separated list of group names enclosed in quotation marks that the user will be associated withYesNo
login_failuresThe number of login failure attempts for the unameNoNo
passwd_expireThe date and time the user's password expiresNoNo
lockout_startThe date (epoch) and time that a user account is placed in the locked out stateNoNo
ttlAccount creation time in seconds since epochNoNo
dynamic_userA user created by a BIG-IP APM access policy configurationNoNo
deletedThe user account is in the deleted state and no longer active in the local user databaseNoNo
suspendedThe user account is suspended and the user is prohibited from authenticatingNoNo
locked_outThe user's access locked out status 0 or 1 default 0 not locked outNoNo
change_passwdForce the user to change their password 0 or 1 default 0 no password change requiredNoNo
last_modifiedThe date and time the user configuration was modifiedNoNo
first_nameFirst name of the userYesNo
last_nameLast name of the userYesNo
emailEmail address of the userYesNo

Important: The uid for each user must be a unique, positive integer; otherwise, multiple users with the same uid may corrupt the CSV file import.

Minimum fields required to import a user from a CSV file

To import users to the BIG-IP APM system from a CSV file, you must populate the following fields with data:

  • uid
  • uname
  • instance
  • password

The first two lines of the CSV file should include "LocalDB Schema Version=1.0" and all comma separated fields and appear similar to the following example:

Note: In the first line of the following example, the text wraps for display purposes; however, this should be one continuous line in the CSV file.

LocalDB Schema Version=1.0
"uid","uname","instance","password","user_groups","login_failures","passwd_expire","lockout_start","ttl","dynamic_user","deleted","suspended",
"locked_out","change_passwd","last_modified","first_name","last_name","email"

The third line of the CSV file should state the first user configuration of the CSV and appear similar to the following example:

"6953","test01","/Common/test1","{SSHA}5iujcoOj/oYl0201s6a0Jcsf2j1GPDU=","","0","","0","","0","0","0","0","0","","","",""

Note: In this example, only the first four of the 18 fields are populated with data, and the other 14 fields are represented with commas and quotation marks.

Important: To maintain the continuity of the CSV file, each field must be represented whether populated or not. Fields that do not contain data must be represented with a comma and quotation marks.

Password encryption considerations

When you import a user database CSV file, the password field can use MD5, SMD5, SHA or SSHA style encryption. Additionally, when placing the encrypted user password in the CSV file, the encrypted password must be prefixed with {MD5}, {SMD5}, {SHA}, or {SSHA} respectively.

For example, the encrypted password hash using the SHA and MD5 algorithms would appear as follows:

  • {SHA}f72qWouzjoc6vqk8vf5NBIVHFXs=
  • {MD5}UNG4f7RAlP50hb3SspL4PA==

You can generate a user's password hash with the one of the above algorithms by using the openssl command from the BIG-IP command line.

For example, to generate a password hash for a password secret using the SHA algorithm, type the following command from the BIG-IP command line:

echo -n secret | openssl sha -binary | base64

The command output appears similar to the following example:

f72qWouzjoc6vqk8vf5NBIVHFXs=
 

Important: In versions v13.1.x and above you can no longer use SHA - please use SSHA instead.

#!/bin/bash
INSTANCE=/Common/test1
USER="test01"
PASSWD=my_secret_password
ROW=1
PREFIX='"","0","","0","","0","0","0","0","0","","","",""'

echo "LocalDB Schema Version=1.0"
echo '"uid","uname","instance","password","user_groups","login_failures","passwd_expire","lockout_start","ttl","dynamic_user","deleted","suspended","locked_out","change_passwd","last_modified","first_name","last_name","email"'

SALT="$(openssl rand 3)"
SHA1="$(printf "%s" "$PASSWD" "$SALT" | openssl dgst -binary -sha1)"
HASH="$(printf "%s%s" "$SHA1" "$SALT" | base64)"
echo -e "\"6953\",\"$USER\",\"$INSTANCE\",\"{SSHA}$HASH\",$PREFIX"
ROW=$((ROW+1))
echo "FOUND_ROWS()=\"$ROW\""

 

Procedures

Creating a CSV file for the BIG-IP APM local user database import feature

Before you import a new local user database, you must use the tmsh utility to initiate the instance of the database.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh).
  2. Use the following command syntax, replacing <partition> and <db_instance> with the specific partition and db_instance names defined in the CSV import file:

    create /apm aaa localdb /<partition>/<db_instance>

    For example:

    create /apm aaa localdb /Common/my_local_user_db

  3. Save your change by typing the following command:

    save /sys config

  4. Exit the tmsh utility by typing one of the following commands:
    • q
    • quit

Importing the Local User DB CSV file

After the CSV file has been created, you can import the file into the BIG-IP APM system to populate the newly created local user database instance.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Access Policy > Local User DB.
  3. Click Import from CSV.
  4. On your local device, locate the CSV file and then click Open.
  5. A warning window appears. Click Yes to continue importing the CSV file.

    The file will be imported at completion, and the screen reverts back to the local user database screen that displays imported users.

    The new local user database is now ready for reference within a BIG-IP APM access policy for AAA.

Note: Importing a CSV file with the same local user database containing an existing user account will overwrite the configured user information, excluding the user's password.
