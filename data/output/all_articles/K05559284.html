Description
HA errors can be seen in the output of the show cm failover-status command for cluster IP addresses, while some IPs using the same physical connections show as Ok.

Output similar to the one below may be seen on one, or both, members of the HA pair:

(example)(cfg-sync In Sync)(/S1-green-P::Active)(/Common)(tmos)# show cm failover-status

---------------------------------------------------------------------------------------------------------------------
CM::Failover Connections
Local Failover Address  Remote Device                            Packets    Transitions  Received Last Packet  Status
---------------------------------------------------------------------------------------------------------------------
10.10.10.187:1026       example.f5.com                          12329603   3            2022-Apr-21 21:31:07  Ok
10.10.10.188:1026       example.f5.com                          12329628   3            2022-Apr-21 21:31:08  Ok
10.10.10.186:1026       example.f5.com                          0          1            -                     Error
10.10.10.189:1026       example.f5.com                          161700034  3            2022-Apr-21 21:31:08  Ok

Environment

  • BIG-IP
  • Viprion with multiple blades 
  • Cluster IP address configured in Failover Unicast Configuration

Cause
Configuring the cluster IP address in the Failover Unicast Configuration is a misconfiguration and can cause unexpected behavior.

Recommended Actions
Use only the cluster member IP addresses in the Failover Unicast Configuration, do not add the cluster IP address to the entries.
