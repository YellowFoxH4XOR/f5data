K8980: Defining a network virtual server as subnet of a directly connected network may cause TMM to crash

Known Issue

This is the result of a known issue. The BIG-IP Configuration utility allows creation of an invalid configuration that may cause TMM to crash.

The invalid configuration consists of a network virtual server that is a subnet of a directly connected network, which transparently forwards traffic to a pool member on the same directly connected network. This configuration causes an internal forwarding loop that eventually causes TMM to crash.

For example, if the 10.10.0.0/16 network is directly connected to a BIG-IP VLAN, and you want to route traffic specific for the 10.10.0.0/17 subnet through the router at 10.10.30.1, it is possible to create a network virtual server with the virtual address 10.10.0.0/17, address and port translation disabled, and define a pool containing 10.10.30.1:0. Traffic bound for the 1010.0.0/17 network is intended to be forwarded by BIG-IP to the router's address, but instead loops internally.

F5 Networks Product Development tracked this issue as CR100691 and it was fixed in BIG-IP version 9.4.6. You can no longer create a virtual server that is a subnet of a directly connected network. The attempted operation now fails with a message that appears similar to the following example: 

BIGpipe unknown operation error: 01070358:3: Route 10.10.0.0 pool http_pool member 10.10.10.20 must be directly connected to this machine.

Additionally, this issue was fixed in Hotfix-BIG-IP-9.4.5-HF2, issued for BIG-IP version 9.4.5. You may download this hotfix or a later version of the hotfix from the F5 Downloads site.
