K000162091: Interface Remains Down After Disable/Enable on F5OS-A r2000 Series

Type
Support Solution
Published
2026-07-06
Updated
2026-07-06
Applies to
  • F5OS Products
  • F5OS-A: 1.8.X, 1.8.4, 1.8.3, 1.8.0
Source
https://my.f5.com/manage/s/article/K000162091

Description

On F5OS-A running on r2000 series platforms, disabling and re-enabling a physical interface may result in the interface remaining in a DOWN state and not recovering until a system reboot or specific container restart. Kernel log messages such as "page allocation failure" indicate memory allocation problems in the nic-manager process.

Environment

  • Product: F5OS-A
  • Hardware: r2000 series (R2600, R2800)
  • Operations: Frequent interface disable/enable (e.g., for network changes or failover automation)
  • Kernel log messages: "page allocation failure" involving nic-manager
  • Not observed on r5k, r10k, or VELOS platforms

Cause

When a physical interface is disabled and re-enabled, the OS may be unable to allocate sufficient contiguous memory, resulting in the interface remaining down until a reboot or container restart. This is tracked as Bug ID 2331113. 

Answer/Recommended Actions

To recover the affected interface without a full system reboot, restart the relevant containers:

  1. Stop the containers:

    docker stop system_L2
    docker stop nic-manager

  2. Verify both containers are stopped:

    docker ps -a --filter "name=system_L2"
    docker ps -a --filter "name=nic-manager"

  3. Start the containers:

    docker start nic-manager
    docker start system_L2

  4. Confirm both containers are running:

    docker ps -a --filter "name=system_L2"
    docker ps -a --filter "name=nic-manager"

Alternatively, a full system reboot will also restore the interface.

Additional Information

  • The issue is confirmed to affect only r2k (R2600/R2800).
  • No engineering hotfix or permanent fix is available at the time of publication.
  • The issue may occur sporadically and is dependent on the system's memory state.
