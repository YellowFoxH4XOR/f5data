Known Issue

This is the result of a known issue. When you run the bigpipe load command on a BIG-IP LTM with a large configuration of 2000 or more objects, Linux swapping can impact the system load time.

F5 Product Development is tracking this issue as CR70075.

Workaround

Note: F5 does not recommend changing the setting of the bigdb database variable Provision.ExtraMB on BIG-IP LTM systems with 768 megabytes or less of memory.

You can work around this issue by modifying the bigdb database variable Provision.ExtraMB. To do so, perform the following procedure:

  1. Log in to the BIG-IP LTM command line interface.
  2. At the system prompt, type the following command to log on to the bigpipe shell:

    bigpipe shell

  3. At the bigpipe shell prompt, type the following command to set the bigdb database variable Provision.extraMB to 128:

    bp> db provision.extramb 128

    Note: Setting Provision.extraMB to 128 enables the system to boot as quickly as possible.

  4. Reboot the system.

Warning: Incorrectly modifying the bigdb database variable Provision.ExtraMB can cause the system to become inoperable. For more information about using bigpipe commands to configure a system, refer to Appendix A of the BIG-IP Command Line Interface Guide.
