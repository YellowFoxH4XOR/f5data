Known Issue

The Traffic Management Microkernel (TMM) may produce a core file and restart when the Woodside congestion control is used.

This issue occurs when all of the following conditions are met:

  • You configure a TCP profile to use the Woodside congestion control algorithm.
  • You associate the TCP profile with a virtual server.
  • The virtual server processes a TCP packet where the congestion window is set to 0 (zero).

Impact

If the BIG-IP system is a member of a redundant configuration, traffic fails over to the standby BIG-IP system. If the BIG-IP system is not part of a redundant pair, traffic is interrupted until the TMM restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system temporarily fails to process traffic.
  • The BIG-IP system generates a TMM core file to the /shared/core directory.
  • The BIG-IP system fails over to another host in the device group.

Workaround

To work around this issue, you can configure the affected TCP profile to use a congestion control algorithm other than the Woodside congestion control algorithm.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
