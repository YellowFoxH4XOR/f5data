Insufficient logging and monitoring failures

Insufficient logging and monitoring failures are frequently a factor in major security incidents. The BIG-IP system provides security features to protect against attacks that can result from insufficient system and application logging and monitoring.

Failure to sufficiently log, monitor, or report security events, such as login attempts, makes suspicious behavior difficult to detect and significantly raises the likelihood that an attacker can successfully exploit your API. For example, an attacker may probe your API for known vulnerabilities over a period of time. Allowing such probes to continue undetected increases the likelihood that the attacker ultimately finds a vulnerability and successfully exploits the flaw.

Insufficient logging and monitoring common weakness enumeration (CWE)

The following common weaknesses may increase the likelihood of attacks against your APIs:

  • CWE-223: Omission of Security-relevant Information
  • CWE-778: Insufficient Logging
  • CWE-532: Insertion of Sensitive Information into Log File
  • CWE-117: Improper Output Neutralization for Logs

Insufficient logging and monitoring failures attack scenario

In the following scenario, an attacker exploits an organization that does not use adequate logging and monitoring.

  1. An attacker gains access to an organization's network and runs a scanning tool to locate APIs with known vulnerabilities.
  2. Since the organization does not follow adequate logging and monitoring practices, they are unable to detect active attacks.
  3. The data breach continues undetected.

Secure your APIs against insufficient logging and monitoring failures with F5 products

To protect your APIs, best practices recommend that you appropriately log security messages and implement actions and processes to monitor, alert, and audit based on these security messages. Use the F5 product features listed in the following tables to do so.

For NGINX App Protect WAF:

Use the app_protect_security_log directive to define what, where, when, and the format in which you want NGINX App Protect to log. You can log per-request, based on type of violation, violation ratings, or log specific attributes, such as support_id, violation details, vs_name, and outcome_reason.

Use the three logging profiles (All, Illegal, and Blocked) to configure logging verbosity. Using a combination of Alarm and Block settings together with Enforcement Mode (Blocking and Transparent settings), NGINX App Protect WAF provides you granular control of when and what to log.

The Security Logs and Policy Enforcement Modes sections of the NGINX App Protect WAF Configuration Guide

For NGINX App Protect DoS:

Enable sufficient logging in NGINX App Protect DoS by enabling the appropriate variables for the access log.

During a denial-of-service (DoS) attack, there is a large number of incoming requests, which can flood the access log. Configure rate limiting.
  • The Logs Overview section of the NGINX App Protect DoS manual.
  • The Logging Rate Limit section of the NGINX App Protect DoS manual.
Remote loggingFor NGINX App Protect WAF:

Use the app_protect_security_log command to configure remote logging. For example: app_protect_security_log “config.json” syslog:server=FQDN:514;
