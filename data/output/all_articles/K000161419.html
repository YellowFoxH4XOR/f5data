K000161419: NGINX returns a "404 File not found" response and does not redirect HTTP requests to HTTPS because the specific configuration is not loaded

Description

NGINX returns a 404 File not found response and does not redirect HTTP requests to HTTPS because the specific configuration is not loaded.

The expected HTTP and HTTPS server blocks and their listen directives are absent from the active configuration.

Environment

  • NGINX Plus
  • Specific application deployment
  • Specific configuration files stored in /etc/nginx/conf.d/Specific/
  • HTTP-to-HTTPS redirection configured for the Specific application
  • Main configuration file: /etc/nginx/nginx.conf

Cause

The configuration directory is not included within the http block of nginx.conf. Consequently, the specific server blocks are not loaded, and their listen directives are not active.

Answer/Recommended Actions

  1. Open the NGINX main configuration file:
    /etc/nginx/nginx.conf
  2. Add the following directive inside the http block:
    include /etc/nginx/conf.d/specific/*.conf;
  3. Validate the NGINX configuration:
    nginx -t
    Confirm that the syntax check is successful.
  4. Reload or restart NGINX according to your operational procedures.
  5. Verify that the specific configuration has been loaded and that the expected HTTP and HTTPS listeners are active:
    nginx -T
  6. Test the application and confirm that HTTP requests are redirected to HTTPS and that the application no longer returns the default NGINX 404 response.

Additional Information

  • The following directive does not load configuration files from nested directories such as /etc/nginx/conf.d/specific/:

 

include /etc/nginx/conf.d/*.conf;
  • Each configuration directory containing application-specific server blocks must be explicitly included.
  • A redirection server block can use the following form: 
    server {
listen <IP-address>:80;
server_name <domain-name>;
return 301 https://$host$request_uri;
}
  • The redirection configuration cannot take effect until its containing configuration is loaded by NGINX.
