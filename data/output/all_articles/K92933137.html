K92933137: DNS configuration load fails when a virtual server name contains a colon

Type
Support Solution
Published
2020-10-06
Updated
2023-02-21
Applies to

  • BIG-IP DNS: 15.X.X, 15.1.X, 15.0.X, 14.1.X, 14.0.X, 12.1.X, 15.1.8, 15.1.7, 15.1.6, 15.1.5, 15.1.4, 15.1.3, 15.1.2, 15.1.1, 15.1.0, 15.0.1, 15.0.0, 14.1.5, 14.X.X, 14.1.3, 14.1.2, 14.1.0, 14.0.1, 14.0.0, 13.1.3, 13.1.1, 12.1.6, 12.1.5, 12.1.4, 12.1.3, 12.1.2, 12.1.1, 12.1.0, 14.1.4

Source

Description

DNS configuration load fails when the virtual server name contains a colon.
  • DNS service is not available
  • In the DNS/GTM configuration file double backslash was added to the affected GTM pool member

    gtm pool a /Common/my_gtm_pool {
        members {
            /Common/my_gtm_server\\:my_vip:443 {
               member-order 0
     <...snip...>  

  • In /var/log/ltm following error is recorded
    01070226:3: Pool Member <pool_member_name> references a nonexistent Virtual Server Unexpected Error: Loading configuration process failed.

Environment

  • DNS/GTM has been upgraded to a version with fix for ID722682 from a version that does not have the fix for the bug.
    Please follow the ID722682  to get more details.
  • A GTM server has a name with no colon
    gtm server /Common/my_gtm_server
  • The GTM server has a virtual server with colon in the name
    <...snip...>
    my_vip:443 {
      destination 10.10.10.:443
    <...snip...>
  • That virtual server is added to a pool
    gtm pool a /Common/my_gtm_pool {
        members {
            /Common/my_gtm_server:my_vip:443 {
               member-order 0
     <...snip...>  

Cause

The issue is caused by a Bug ID947217 which is a side effect of the Bug ID722682 fix for GTM server objects containing colon ":" in the name

Recommended Actions

Edit bigip_gtm.conf manually to delete "\\" or replace colon ":" with other non-reserved char. such as "-".
