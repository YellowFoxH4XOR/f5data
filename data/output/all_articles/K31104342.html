Known Issue

The BIG-IP system may fail to persist connections after a pool member is marked down.

This issue occurs when all of the following conditions are met:

  • The virtual server is configured to use a pool with multiple pool members.
  • Your virtual server configured with a persistence profile.
  • The BIG-IP system has multiple Traffic Management Microkernels (TMM).
  • The pool member for an existing persistence entry is marked down or forced down administratively.
When the pool member with existing persistence entries is marked down, each TMM may persist subsequent connections to different remaining available pool members.

Impact

Multiple TMMs may not persist connections to the same pool member.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • New connections may not be persisted to the same pool member.
  • The tmsh show ltm persistence persist-records command will show inconsistent persistence entries across TMMs.

    For example:

    Sys::Persistent Connections
    source-address  10.10.1.0  10.10.2.1:80  10.10.3.11:80  (tmm: 3)
    source-address  10.10.1.0  10.10.2.1:80  10.10.3.12:80  (tmm: 2)
    source-address  10.10.1.0  10.10.2.1:80  10.10.3.11:80  (tmm: 0)
    source-address  10.10.1.0  10.10.2.1:80  10.10.3.12:80  (tmm: 1)
    Total records returned: 4
