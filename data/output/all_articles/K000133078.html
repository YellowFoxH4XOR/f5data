Description

BIG-IP may fail to pass HTTP chunked and compressed response from server to client with the following TCP RST cause in /var/log/ltm:

01230140:3: RST sent from <client_IP or SNAT_IP>:<client_Port> to <server_IP>:<server_Port>, [0xXXXXXXXX:YYY] Compression error 



Environment


  • BIG-IP
  • Virtual Server with HTTP profile
  • HTTP response is chunked and compressed


Cause


BIG-IP inflates the compressed response if the size of the response exceeds the configured value for tmm.deflate.memory.threshold the reset is sent.
 


Recommended Actions


  1. Using tmsh modify the  tmm.deflate.memory.threshold value to a larger value to enable inflation of full response payload. This is the value of the chunk payload and not the full file size.
  2. This has some direct impact on memory since the chunks will be need to be unchunked and viewed by whatever profiles need to inspect that data, such as ASM.


Example:

Change the value of tmm.deflate.memory.threshold to 2000000 bytes:


tmsh modify sys db tmm.deflate.memory.threshold value 2000000
tmsh save sys config



To revert back to default settings:


tmsh modify sys db tmm.deflate.memory.threshold value 1572864
tmsh save sys config



 


To show the current value :


tmsh list sys db tmm.deflate.memory.threshold all-properties



sys db tmm.deflate.memory.threshold {
   default-value "1572864"
   scf-config "true"
   value "1572864"
   value-range "unsigned integer min:393216 max:4718592"
}
