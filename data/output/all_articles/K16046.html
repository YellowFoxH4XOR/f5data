Known Issue

Protocol mismatches may cause the Traffic Management Microkernel (TMM) to restart.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system is configured with a virtual server that uses an iRule.
  • The iRule uses the virtual command to select a destination virtual server to process traffic.
  • The destination virtual server, selected by the iRule, uses a different Layer 4 (L4) protocol than the virtual server that initially received the traffic.

    For example, this condition can occur when a TCP virtual server uses an iRule that selects a destination virtual server configured for User Datagram Protocol (UDP) to handle the traffic.
  • Traffic is processed through the virtual server and the associated iRule.

Impact

Traffic is interrupted while the TMM restarts.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The TMM process restarts and produces a core file in the /var/core directory.
  • The BIG-IP system's /var/log/tmm file indicates that TMM is restarting with a SIGFPE.
  • You notice that the TMM core file contains an error message similar to the following example:

    tmm_panic (format=0x1b4cbf8 "../modules/hudfilter/tcp4/tcp4.c:4469: %sMust be syncookie%s") at ../lib/stdio.c:1245

Workaround

To work around this issue, you can ensure that the iRule virtual command references the same protocol destination virtual server resources as the virtual server that initially received the traffic.
