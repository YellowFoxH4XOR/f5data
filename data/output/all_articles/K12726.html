Known Issue

This is the result of a known issue. If you install Microsoft patches KB2478960 or KB2478971 onto Windows filers, the ARX system marks the filer's shares offline. When you restart the filer to apply the patches, the ARX marks the filer's shares offline, as expected, but when the filer has finished restarting, the filer's shares remain offline. The show health command indicates the shares are offline and displays a message that appears similar to the following:

System Health Information
Date                     ID      Event                       Description
---------------------------------------------------------------------------------------
Wed Mar 14 10:09:18 2011 (670) - shareOffline                10.20.30.50:cifs:/share1

Additionally, the procdat log file contains log messages that appear similar to the following:

:BESPD-0-INFO-CIFS_UNSUPPORTED:: The CIFS connection to 10.20.30.50 reported an unsupported protocol option. Check 'LAN Manager authentication level' and 'Minimum session security for NTLMSSP-based servers' at filer.
:BESPD-0-INFO-SHARE_CONN:: Connection to filer at 10.20.30.50:Share [59]: STATUS_NOT_SUPPORTED (Duration: 0.004s)

Note: The procdat log file is located in the /acopia/var/log directory of the ARX system diagnostic information file. For information about creating an ARX system diagnostic information file, refer to K8294: Providing an ARX diagnostic information file to F5 Networks Support.

The STATUS_NOT_SUPPORTED error message is not unique to the issue that the patches caused, and may occur for other issues. To verify that the Microsoft patches are the cause of offline shares, you must increase the logging level of the LIBCIFSAUTH component to the debug level and query the affected filer. To do so, perform the following procedure:

  1. Log in to the ARX CLI.
  2. Enable privileged mode by typing the following command:

    enable

  3. Enable configuration mode by typing the following command:

    config

  4. Set the logging level for LIBCIFSAUTH to debug by typing the following command:

    logging level LIBCIFSAUTH debug

  5. Query the filer for the affected shares using the show exports command. For information about the show exports command, refer to the ARX CLI Reference Guide.

    Once you have increased the logging and have run the show exports query, syslog reports log entries that appear similar to the following.

    :LIBCIFSAUTH-0-DBG-MSG7:: parsing spnegonegprot response
    :LIBCIFSAUTH-0-DBG-MSG7:: mech OID[0] is 1 2840 48018 1 2 2, kerberos
    :LIBCIFSAUTH-0-DBG-MSG7:: mech OID[1] is 1 2840 113554 1 2 2, kerberos
    :LIBCIFSAUTH-0-DBG-MSG7:: mech OID[2] is 1 2840 113554 1 2 2 3, kerberos u-to-u
    :LIBCIFSAUTH-0-DBG-MSG7:: mech OID[3] is 1 36 1 4 1 311 2 2 10, ntlmssp
    :LIBCIFSAUTH-0-DBG-MSG7:: failed to process CONTEXT[3] for negHints; status 5


    The message that corresponds to this issue is the "failed to process CONTEXT" message. If the system reports that message, then the Microsoft patches most likely caused the offline share issue.
  6. Set the logging level for LIBCIFSAUTH back to defaults by typing the following command:

    no logging level LIBCIFSAUTH

F5 Product Development tracked this issue as ID 352085 and it was fixed in ARX versions 5.2.2, 6.0.0, and ARX VE version 5.3.1. For information about upgrading, refer to the ARX release notes.

Additionally, this issue has been fixed in hotfix release 5.1.9 HF2 (build 12107). For information about the hotfix, refer to K12595: Overview of ARX version 5.1.9 hotfixes. Customers affected by this issue should request the hotfix from F5 Technical Support, referencing this Solution number and ID 352085.

For information about Microsoft patches KB2478960 and KB2478971, refer to the following documents:

Workaround

To recover from this issue, you must uninstall the Microsoft patches KB2478960 and KB2478971 and reboot the Windows filer. For information about uninstalling the Microsoft patches, refer to the Microsoft knowledge base documentation.

To prevent this issue, do not install Microsoft patches KB2478960 or KB2478971 until F5 provides an appropriate fix and you have applied the fix to your ARX system.
