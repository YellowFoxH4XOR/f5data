Description

The article describes the signature syntax for the Protocol Inspection signature files.

Environment

  • Upload Signature file
  • Correct Syntax

Cause

None.

Recommended Actions

The signature syntax used for creating the signature file is snort syntax that is used for content matching.

An example of the syntax is ( excluding the double-quotes ):

"content: "SOME_1"; content: "SOME_2"; metadata: service http; msg:"Test signature description 1";"

After uploading the file, the configuration will appear as such:

# tmsh list security protocol-inspection signature http_test_test_signature_description_1 all-properties

security protocol-inspection signature http_test_test_signature_description_1 {

  accuracy low

  action accept

  app-service none

  attack-type none

  deprecated no

  description "Test signature description 1"

  direction any

  documentation none

  id 100000

  last-updated 2023-04-18:02:45:21

  log yes

  partition Common

  performance-impact low

  protocol "any"

  reference-links none

  references none

  revision 1

  risk low

  service http

  sig "content: \"SOME_1\"; content: \"SOME_2\"; metadata: service http; msg:\"Test signature description 1\";"

  subscription no

  systems none

  user-defined yes

}

Additional Information

The signature from the file is generated using the metadata ( for e.g. msg + service ) to create it name and other attributes.
When viewing the signature from tmos/GUI, the signature field will include the metadata, however, it is not part of the inspection.
The traffic is matched to the content part for inspection.
