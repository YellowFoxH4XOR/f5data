Topic

This article outlines the recommended steps that you should take when cloning BIG-IP Virtual Edition (VE) instances.

Description

The convenience and ease of cloning virtual machines has made managing and duplicating BIG-IP VE systems a commonplace practice. The following recommendations are intended to help minimize possible conflicts with BIG-IP VE cloned instances.

Note: When you clone a BIG-IP VE to a new host, the virtual hardware is altered significantly, and can cause the license to stop functioning. This behavior occurs because the existing license no longer recognizes the hardware with which it was authorized. For more information, refer to K13570: Moving BIG-IP Virtual Edition to a new VMware host may require authorization for license moves.

Resolution

BIG-IP VE is automatically configured during the first system boot with a unique REST device ID and secure shell (SSH) keys. When BIG-IP VE is cloned, these values become part of the cloned instance. In environments where multiple BIG-IP clone instances are run, the duplicate REST ID and SSH keys can cause access and management conflicts.

The cloned BIG-IP VE instance will have an identical /config/f5-rest-device-id key value of the original instance. BIG-IP VEs that are managed by a BIG-IQ system that shares the same f5-rest-device-id key value can cause a conflict regarding the BIG-IQ system's ability to discover or manage the BIG-IP VE clone instances.

The cloned BIG-IP VE instance will have identical SSH keys as the original instance, and may be presented as a security risk in some environments.

Avoiding potential conflicts between BIG-IP VE clone instances

You can easily avoid BIG-IP VE clone instance conflicts by completing the following procedure on a BIG-IP VE clone template.

Note: If you create a new BIG-IP VE from the clone template without completing the following procedure, the clone instance will have a duplicate REST ID and duplicate SSH keys as the BIG-IP system clone template instance.

Create a BIG-IP VE clone template based on the original BIG-IP VE instance.

  1. Create the BIG-IP VE clone template based on the original BIG-IP VE instance.
  2. Power on the new clone template instance.
  3. Log in to the command line of the running BIG-IP VE clone template instance.
  4. To delete f5-rest-device-id directory files, type the following command.

    rm -f /config/f5-rest-device-id

    This forces the REST device ID files to be uniquely generated the next time you start the clone.

  5. To delete the BIG-IP VE clone instance-generated SSH keys, type the following command:

    rm -f /config/ssh/ssh_host_* 
    rm -f /shared/ssh/ssh_host_*

    This forces the SSH keys to be uniquely generated the next time you start the clone.

  6. To delete the bigip.license file, type the following command:

    lrm -f /config/bigip.license

  7. (BIG-IP 14.1.0 and later only) To reset the device administrative account passwords to their default values, type the following command:

    echo "root:default" | chpasswd
    echo "admin:admin" | chpasswd

  8. To power off the BIG-IP VE clone template instance, type the following command:

    shutdown -h now

You can now use the BIG-IP VE clone template instance to create additional BIG-IP VE clone instances.

Important: F5 recommends that you leave the clone template powered off. Run these steps on the clone template instance each time you start the instance, before shutting down the instance.

 

If you have cloned devices that did not follow this procedure, it is still possible to change the f5-rest-device-id

  1. Remove restid from affected BIG-IP

    rm -f /config/f5-rest-device-id

  2. Restart restjavad 

    bigstart restart restjavad

  3. Verify now different restIDs:

    cat /config/f5-rest-device-id

  4. License device once again
