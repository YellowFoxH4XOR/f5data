Description

An iRule for Network Access, similar to one in K27804015 to log the Session/Client information, is no longer working after APM Client upgrade to APM Clients 7.2.4 or above. No logs are visible in /var/log/ltm for new Network Access sessions.

Environment

  • APM with Network Access
  • APM Clients 7.2.4 or later
  • iRules

Cause

Due to a change in how the GET requests are being sent from the client, the condition that the IF statement previously used (as per K27804015) no longer works. It is because the requests no longer include

/myvpn?sess=

In fact, "sess" is now sent in the session cookie header.

Recommended Actions

To account for this, we need to change the IF statement part. There are two choices; If we only want it for APM Clients 7.2.4 and above (this syntax is valid for all 7.2.4.X versions, up to the newest 7.2.4.7, as of the time of updating this article), we can use

if { [HTTP::uri] starts_with "/myvpn?ipv4="}

If we want this to work both for APM Clients 7.2.4 and earlier versions, we can use

if { [HTTP::uri] starts_with "/myvpn?" and [HTTP::uri] contains "ipv4=" }

For reference, here's how an example GET URI looks on 7.2.4.X versions of APM client:

     /myvpn?ipv4=yes&ipv6=yes&hostname=<hostname>=&hdlc_framing=no&Z=<NA_Name>

And here is an example iRule to log requests:

     when HTTP_REQUEST {
         if { ([HTTP::uri] starts_with "/myvpn?") && ([HTTP::uri] contains "ipv4=") } {
             log local0. "VPN was established: [HTTP::URI]"
         }
     }
