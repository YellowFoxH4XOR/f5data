Topic

This article applies to BIG-IP 9.x through 10.x. For information about other versions, refer to the following article:

  • K13426: Monitoring login attempts (11.x - 12.x)

Monitoring login attempts is an important part of network security. If an unauthorized user were to gain access to one system in the network with a compromised username and password, they could gain access to other devices as well.

BIG-IP 10.x

You can view BIG-IP 10.x login attempts from either the Configuration utility or the command line.

Configuration utility

To view login attempts from within the Configuration utility, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to System > Logs.
  3. Select Audit.

Command line

You can view the /var/log/audit log from the command line.

Valid CLI login attempts will appear similar to the following example:

Mon Jul 6 10:17:38 BST 2009    root    0-0    sshd(pam_audit): user=root(root) partition=All level=Administrator tty=/dev/pts/1 host=192.168.10.10 attempts=1 start="Mon Jul 6 10:17:38 2009".

When the user logs out, information that appears similar to the following example is reported:

Mon Jul 6 10:18:30 BST 2009    root    0-0    sshd(pam_audit): user=root(root) partition=All level=Administrator tty=/dev/pts/1 host=192.168.10.10 attempts=1 start="Mon Jul 6 10:17:38 2009" end="Mon Jul 6 10:18:30 2009".:

Invalid CLI login attempts will simultaneously generate two messages, as follows:

  • Logged to the /var/log/audit file:

    root    0-0    sshd(pam_audit): User=root tty=ssh host=192.168.10.10 failed to login after 1 attempts (start="Mon Jul 6 10:19:10 2009" end="Mon Jul 6 10:19:14 2009").:

  • Logged to the /var/log/secure file:

    Jul  6 10:19:14 local/abasm err sshd[24600]: error: PAM: Authentication failure for root from 192.168.10.10

Valid Configuration utility login attempts will appear similar to the following example:

Mon Jul 6 10:23:23 BST 2009    admin    0-0    httpd(mod_auth_pam): user=admin(admin) partition=[All] level=Administrator tty=1 host=192.168.10.10 attempts=1 start="Mon Jul 6 10:23:23 2009".

Invalid Configuration utility login attempts will appear similar to the following example:

Mon Jul 6 10:21:03 BST 2009    bob    0-0    httpd(pam_audit): User=bob tty=(unknown) host=192.168.10.10 failed to login after 1 attempts (start="Mon Jul 6 10:21:01 2009" end="Mon Jul 6 10:21:03 2009").:

To determine the cause of a failed Configuration utility login attempt, you must log in to the CLI and examine the /var/log/secure file where you will find a corresponding log entry that appears similar to the following example:

Jul  6 10:21:03 local/abasm err httpd[4133]: [error] [client 192.168.10.10] AUTHCACHE PAM: user 'bob' - not authenticated: Authentication failure, referer: https://172.16.10.10/tmui/login.jsp

BIG-IP 9.4.2 through 9.6.1

In BIG-IP 9.4.2 through 9.6.1, the system logs only command line transactions, and all messages are logged to the /var/log/secure file.

Valid login attempts appear similar to the following example:

sshd[29206]: Accepted keyboard-interactive/pam for root from 192.168.10.10 port 49303 ssh2
sshd(pam_unix)[29209]: session opened for user root by root(uid=0)

Invalid login attempts appear similar to the following example:

sshd(pam_unix)[29285]: authentication failure; logname= uid=0 euid=0 tty=ssh ruser= rhost=192.168.10.10  user=root
sshd[29283]: error: PAM: Authentication failure for root from 192.168.10.10

Note: For additional authentication information that can be logged using syslog_ng, refer to K5523: Configuring the syslog-ng utility to log authentication messages.

BIG-IP 9.4.1 and earlier

By default, BIG-IP 9.4.1 and earlier do not record login information from the command line or Configuration utility.

Note: To configure BIG-IP log authentication information in versions 9.4.1 and earlier, refer to K5523: Configuring the syslog-ng utility to log authentication messages.
