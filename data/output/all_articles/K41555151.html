Description

Knative runs serverless containers on Kubernetes. It can use multiple network layers. Use the one that will accommodate your needs.

In this article we will focus on Aspen Mesh/Istio as a network layer.

Environment

  • Kubernetes 1.20.x  
  • Aspen Mesh 1.9.x  

Cause

N/A

Recommended Actions

Before continuing with the configuration process, we are assuming you are following the guide for installing Knative in Install Serving with YAML. You should take note of the requirements and prerequisites listed in the guide. Perform the following procedures:
  1. Install Knative serving component
  2. Install Aspen Mesh as a network layer
  3. Verify the installation
Install Knative serving component

Complete step 1 in the installation guide here:

The manifest will create all the objects needed, namespace, deployments, services etc.

Install Aspen Mesh as a network Layer

At this point, if you are following this guide, we are assuming you have already Aspen Mesh installed. If not, refer to K74423478: Customizing Aspen Mesh installations.

Once you have Aspen Mesh installed, you need to perform the following steps:
  1. Install knative istio controller by running this command:

    kubectl apply -f https://github.com/knative/net-istio/releases/download/knative-v1.1.0/net-istio.yaml

  2. Fetch the External IP address or CNAME by running the command and save it for later:

    kubectl --namespace istio-system get service istio-ingressgateway

  3. If the command above does not return anything maybe you don’t have an ingress-gateway, you need to install it following K50557252: Install Istio Ingress Gateway using the Aspen Mesh Ingress Helm Chart
  4. With Aspen Mesh we do auto-injection and mTLS enabled, so you will need to inject sidecar in the knative-serving namespace by running this command:

    kubectl label namespace knative-serving istio-injection=enabled

  5. Restart the pods in the knative-serving namespace
  6. Verify all the pods are running and the logs are not showing any errors.

    Note: Verify that the manifest for the knative istio controller match the version of the knative serving component you installed.

kubectl get pods -n knative-serving

Verify the installation

After verifying all the pods are running in step 6, verify the installation.

  1. Create a Knative service. The following shows an example:

    apiVersion: serving.knative.dev/v1
    kind: Service
    metadata:
      name: httpbin-shell
      namespace: default
    spec:
      template:
        spec:
          containers:
            - image: docker.io/kennethreitz/httpbin
              imagePullPolicy: Always
              ports:
              - containerPort: 80
              env:
                - name: TARGET
                  value: "httpbin Sample v1"

  2. Verify the Knative service is running until you see service is ready

    kubectl get ksvc
    NAME            URL                                        LATESTCREATED         LATESTREADY           READY   REASON
    httpbin-shell   http://httpbin-shell.default.example.com   httpbin-shell-00001   httpbin-shell-00001   True

  3. If your Knative service never gets to ready status=True and the reason is failed to resolve image to digest, then you should need to do an extra step. Edit the config-deployment with the following command

    kubectl edit cm config-deployment –n knative-serving

    Add the following line:

    registriesSkippingTagResolving: kind.local,ko.local,dev.local,docker.io,index.docker.io

    Items will be separated by ‘,’ and you should add your public or private registry in the case is not secured.
    You can find more information about Tag Resolution.
    Save it and restart the controller pod in the knative-serving namespace.

  4. Verify routes have been created in the namespace your serverless container was deployed

    kubectl get virtualservices

    NAME                                  GATEWAYS                                                                              HOSTS
                                                                                                        AGE
    httpbin-shell-ingress                 ["knative-serving/knative-ingress-gateway","knative-serving/knative-local-gateway"]   ["httpbin-shell.default","httpbin-shell.default.example.com","httpbin-shell.default.svc","httpbin-shell.default.svc.cluster.local"]   25m

    httpbin-shell-mesh                    ["mesh"]                                                                              ["httpbin-shell.default","httpbin-shell.default.svc","httpbin-shell.default.svc.cluster.local"]                                       25m

  5. Test application connectivity if you do not have a DNS that can be resolved, refer to the guide in Configure DNS in the Knative documentation
    You will use temporary DNS.
