Description

Noticed inconsistent data between selected Time Period while generating Avg. Source Translation.
For example (the graph taken from Security > Reporting > NAT > Source > Translation).
- When "Hours" selected, the graph is showing the overall avg active translation between 60-80k.
- When switched to "Last Day", the graph showing Y axis value between 1000-2500
- When switched to "Last Week", the graph showing Y axis value up to 150 (a lower value).

Environment

  • CGNAT
  • AVR Graphs

Cause

 

In graphs lines are composed by points with specific interval depends which time period you select (last hour, day, week and month). And the points presents the average value of that interval.

  • last hour: The lines on the graph are composed of points spaced 10 seconds apart.
    Example jan 26 00:01:00 then jan 26 00:01:10, each point presents average value 10s interval
  • last day: The lines on the graph are composed of points spaced 4 minutes apart.
    Example jan 26 00:24:00 then jan 26 00:28:00, each point presents average value 4mins interval
  • last week: The lines on the graph are composed of points spaced 1 hour apart.
    Example jan 26 01:00:00 then jan 26 02:00:00, each point presents average value 1hour interval
  • last month: The lines on the graph are composed of points spaced 4 hour apart.
    Example jan 26 00:00:00 then jan 26 04:00:00, each point presents average value 4hour interval

When traffic volume never changes, let's say always 1000 requests per second. You will see all graph have save range, because the average of 10s, 4minus, 1hour and 4hours are always same --- 1000 requests/s

Since this is a real traffic which means traffic volume are dynamically changed, 10s interval's average value could not be equal to 4 hours average value. And the bigger chance is the range is getting smaller when you choose bigger time period.

For example:

With 1 hour interval: 01:00 1000/s, 02:00 2000/s, 03:00 2000/s, 04:00 1000/s. The highest value in the range is 2000, but after we merge these data to 4 hours interval. (1000+2000+2000+1000)/4 = 1500 --- highest value of 4 hour interval is 1500.

 

Recommended Actions

This is expected behaviour, no action required

Additional Information

There could be some corner cases.
For example: Usually from 01:00 to 04:00, there are 20k ~30k connections/s, but one day, there is a ddos attack happened at 02:00 and caused 02:00 average requests reached 130M.
Then last week graph with 1 hour interval, you will see 130M at 02:00 as the max value, but when you select last month, 01:00 to 04:00 4 points will be recalculated to one point, (130M + 30k*4)/4 is about 30+M
