Known Issue

This is the result of a known issue. When viewing a schedule using the GUI or using the show policy schedule command, if the schedule uses an hourly interval starting at midnight (00:00) the ARX system will reboot three times and dump core.

The show policy schedule command will fail with an error message that appears similar to the following example:

-cli_daemon: TimeUtils.cc:636: time_t getNthTimeFromList(time_t, hourList_t&, int): Assertion `loopCount < 2' failed

When the ARX system reboots, a warm start SNMP trap will report the following:

Message: mib2 warmStart: software reboot: Resource 'Policy Decision Point' has failed/exited

F5 Product Development tracked this issue as ID 37588 and it was fixed in ARX 5.1.5. For information about upgrading, refer to the ARX Release Notes.

Workaround

When creating a schedule, configure the schedule to start one minute after midnight (00:01).
