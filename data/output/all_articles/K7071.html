Known Issue

Note: This article only applies to F5 platforms that have SCCP.

This is the result of a known issue. A timer wrap within the SCCP kernel occurs after 497 days, and resets the timer to 0 (zero). The timer wrap causes I2C (Inter-Integrated Circuit bus) driver read/write failures because the I2C is unable to correctly handle the kernel timer wrapping. The SMBus then enters a lockup condition, which causes all subsequent I2C read/write communications to fail until the SCCP is rebooted. As a result, the SCCP cannot gather data from the host system on chassis fan speeds and link status until the SCCP is rebooted.

Important: This behavior can cause SFP fiber ports to become disabled and then re-enabled by the system. This triggered response occurs due to a fix that was introduced in BIG-IP version 9.1 as CR47185 for the Broadcom chipset. This behavior can cause disruption to network traffic when the ports are reset by the system.

F5 Product Development tracked this issue as CR73960 and it was fixed in BIG-IP 9.1.3, 9.3, and 9.4.1. For information about upgrading, refer to the BIG-IP LTM, GTM, ASM, Link Controller, or WebAccelerator Release Notes.

Note: CR73960 does not fix the Linux Kernel 497 day issue detailed in K7036: The Linux uptime counter wraps after 497 days; it only fixes the behavior of the I2C drive and allows the I2C driver to recover when an F5 Networks product encounters the Linux kernel 497 day issue.

Workaround

You can work around this issue when it is encountered on a system with an uptime of 497 days or more by rebooting the system. Alternatively, you can avoid this issue by rebooting the system prior to the 497 day counter wrap.

Note: Reboot the system using the full_box_reboot command.

To determine how long the system has been up, use the Linux uptime command. The uptime command produces output that appears similar to the following example:

19:52:48 up 20 days, 9:24, 1 user, load average: 0.09, 0.05, 0.11

Note: Execute the uptime command while logged into the SCCP.
