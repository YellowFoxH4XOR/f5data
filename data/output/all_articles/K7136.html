Known Issue

This is the result of a known issue. The BIG-IP LTM system can be configured to proxy the Secure Sockets Layer (SSL) Virtual Private Network (VPN) connection to one or more FirePass controllers through the use of an iRule. The VPN client uses SSL to connect to the BIG-IP LTM client SSL virtual server, and the BIG-IP LTM system then proxies the unencrypted connection to the FirePass controller. This behavior offloads SSL decryption from the FirePass controller, preserving CPU resources and other resources.

When BIG-IP LTM is configured to perform load balancing and SSL offloading for one or more FirePass controllers, upgrading BIG-IP LTM to version 9.4 will cause some FirePass functionality to fail. This issue occurs as a result of an issue in BIG-IP LTM 9.4, in which the HTTP::disable iRule command only disables client side of the connection, and not the server side. As a result, the server side of the connection appears to hang.

F5 Product Development tracked this issue as CR75545 and it was fixed in BIG-IP 9.4.1. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Workaround

To work around this issue, you can change the following HTTP::disable iRule syntax:

when HTTP_REQUEST_SEND {if { $http_disable != 0 } {HTTP::disable}}

When you change the HTTP::disable iRule syntax, it will appear similar to the following example:

when HTTP_REQUEST_SEND {if { $http_disable != 0 } {clientside {HTTP::disable}}}

For example, the following iRule can be used on the BIG-IP system to offload FirePass SSL transactions in BIG-IP LTM 9.4:

when RULE_INIT { set ssl_handshake 0 }when CLIENTSSL_HANDSHAKE {set ssl_handshake 1}when CLIENTSSL_CLIENTCERT {set ssl_handshake 1}when HTTP_REQUEST {set http_disable 0if { $ssl_handshake == 1 } { HTTP::header replace "BIGIP" "on"HTTP::header replace "BIGIP_SSL_CIPHER" "[SSL::cipher name]"HTTP::header replace "BIGIP_SSL_CIPHER_USEKEYSIZE" "[SSL::cipher bits]"HTTP::header replace "BIGIP_SSL_PROTOCOL" "[SSL::cipher version]"set ssl_handshake 0}if { [HTTP::uri] starts_with "/myvpn" } {HTTP::class disableset http_disable 1}if { [HTTP::uri] starts_with "/tunnel" } {HTTP::class disableset http_disable 1}}when HTTP_REQUEST_SEND {if { $http_disable != 0 } {clientside {HTTP::disable}}}

For more information about configuring the BIG-IP system to load balance and offload SSL transactions for FirePass controllers, refer to the Configuring the BIG-IP system for FirePass controllers Deployment Guide.
