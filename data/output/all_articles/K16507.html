Issue

This article applies to BIG-IP 11.5.0 and later. For information about other versions, refer to the following article:

  • K12647: The device certificate is generated using the SHA-1 hash algorithm (10.1.x - 11.4.x)

Old Behavior

In versions prior to BIG-IP 11.5.0, and BIG-IQ 4.4.0, the device certificate was generated using the SHA-1 hash algorithm.

New Behavior

Beginning in BIG-IP 11.5.0 and BIG-IQ 4.4.0, the device certificate is generated using the SHA-2 hash algorithm.

The SHA-2 hash family includes multiple hash function sizes; SHA-256 (32-bit) and SHA-512 (64-bit). There are also truncated versions; SHA-224, SHA-384, SHA-512/224 and SHA-512/256.

The BIG-IP system's device certificate is a self-signed SSL certificate that is automatically generated when the software is first installed on the system. However, when you upgrade the system to a new software version and roll forward an existing configuration, the system will continue to use the device certificate from the existing configuration. The device certificate is used for a number of features. For example, this is the certificate presented to your browser when you connect to the Configuration utility. For more information about its additional uses, refer to K15664: Overview of BIG-IP device certificates (11.x).

Impact

None

Recommended Actions

Although this is not required from a functional standpoint, if a BIG-IP system or BIG-IQ system is currently using an SHA-1 device certificate, either because the system is running an old software version or the device certificate was rolled forward, you can replace it with a SHA-2 device certificate by performing the following procedure:

  1. Connect to the BIG-IP, BIG-IQ, or Enterprise Manager command line.
  2. Change directories to the /config/httpd/conf/ssl.crt/ directory by typing the following command:

    cd /config/httpd/conf/ssl.crt/
  3. Back up the server.crt file by typing the following command:

    cp server.crt server.crt.sol16507
  4. Generate a new SHA-256 device certificate by typing the following command:

    openssl req -new -key ../ssl.key/server.key -x509 -out server.crt -sha256
  5. For BIG-IP or Enterprise Manager system, restart the httpd process by typing the following command:

    tmsh restart sys service httpd

    For the BIG-IQ system, restart the webd process by typing the following command:

    tmsh restart sys service webd

Alternatively, if the device in question is running on BIG-IP 11.5.0 or later, you can renew the device certificate using the Configuration utility (System > Device Certificates > Device Certificate).

Note: Additional considerations should be taken into account when renewing the device certificate of a BIG-IP GTM or BIG-IP Link Controller system. For more information, refer to K6353: Updating an SSL certificate on a BIG-IP GTM or Link Controller system.

If you are unsure about the hash algorithm used by a device certificate, type the following command from the command line of the device in question:

openssl x509 -noout -text -in /config/httpd/conf/ssl.crt/server.crt | grep Signature -m 1

For example, the following output shows that the device certificate was generated using the SHA-2 hash algorithm:

Signature Algorithm: sha256WithRSAEncryption
