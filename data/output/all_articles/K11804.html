Known Issue

This is the result of a known issue. When a backup ARX system reboots and rejoins a redundant pair, a rare race condition may allow the active ARX system to enable remote metalog writes and/or resilvering before the backup ARX system is ready. As a result, the ARX system's kernel.log file will contain remote metalog timeout and resilvering error messages that appears similar to the following example:

sm-3-2 mtlDoPacketDMulticast error bit set in qstats:a01 qtimer:0
sm-3-2 mtlDoPacketDMulticast error descp(f7e84000): 4001906b 37e84000 27a50c01 24fdd0 5ffffff 0
sm-3-2 mtlBlock_transfer_multicast multicast failed
sm-3-2 mtlDoPacketD error bit set in qstats:801
sm-3-2 mtlDoPacketD done descp(f7e84000): 19045 37e84000 27a50c00 24fdd0 5006860 0
sm-3-2 mtlDoPacketD error bit set in qstats:801
sm-3-2 mtlDoPacketD done descp(f7e84000): 190c5 37e84000 27a50c00 24fdd0 5006860 0
sm-3-2 mtlDoPacketD error bit set in qstats:801
sm-3-2 mtlDoPacketD done descp(f7e84000): 190c5 37e84000 27a50c00 24fdd0 5006860 0
sm-3-2 mtlDoPacketD error bit set in qstats:801
sm-3-2 mtlDoPacketD done descp(f7e84000): 190c5 37e84000 27a50c00 24fdd0 5006860 0
sm-3-2 mtlDoPacketD error bit set in qstats:801
sm-3-2 mtlDoPacketD done descp(f7e84000): 190c5 37e84000 27a50c00 24fdd0 5006860 0
sm-3-2 MTLDISK multicast error retry local 4 at block 93f7400

sm-3-2 mtlBlockResilverFunc: phase 1 error resilvering region 0
sm-3-1 mtlBlockResilverFunc: phase 1 error resilvering region 1

However, this issue is self-correcting. The failure causes a new membership declaration in which the backup switch will be ready.

F5 Product Development tracked this issue as ID 28839 and it was fixed in ARX version 5.2.0. For information about upgrading, refer to the ARX release notes.
