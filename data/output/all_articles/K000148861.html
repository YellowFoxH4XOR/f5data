K000148861: After moving to a new VE instance, high CPU is observed

Description

  • Migrated existing VE to new VE instance and observed high CPU usage
  • When running tmctl proc_pid_stat -s proc_name,cpu_usage_recent --sortby=cpu_usage_recent -O -L 5 you observe tmm consistently using the most CPU
  • When running tmctl crypto_cpu  you observe a high sw_crypto percentage
  • Same volume/type of traffic being processed as before the migration
  • No changes in configuration on the BIG-IP

Environment

  • VE migration
  • HyperV hypervisor
  • Configuration restored to a different VM, or VM migrated to new hypervisor system

Cause

In the hypervisor settings, CPU compatibility mode may be enabled on the new VM instance. Compatibility mode may limit the instruction sets that are passed to the VM.

The BIG-IP leverages modern CPU instruction sets to process traffic. If these features are not offered to the BIG-IP by the hypervisor, the system will not be able to process traffic as efficiently and high CPU usage and latency may be observed. 

To check the instruction sets that are available to the BIG-IP, you can review cat /proc/cpuinfo | grep flags:

Example of VM with compatibility mode enabled:

flags           : fpu vme de pse tsc msr pae mce cx8 apic sep mtrr pge mca cmov pat pse36 clflush mmx fxsr sse sse2 ss ht syscall nx lm constant_tsc rep_good nopl xtopology eagerfpu pni cx16 hypervisor lahf_lm ssbd ibrs ibpb spec_ctrl flush_l1d arch_capabilities 

Example of VM with compatibility mode disabled:

flags           : fpu vme de pse tsc msr pae mce cx8 apic sep mtrr pge mca cmov pat pse36 clflush mmx fxsr sse sse2 ss ht syscall nx pdpe1gb rdtscp lm constant_tsc rep_good nopl xtopology eagerfpu pni pclmulqdq ssse3 fma cx16 sse4_1 sse4_2 movbe popcnt aes xsave avx f16c rdrand hypervisor lahf_lm abm 3dnowprefetch ssbd ibrs ibpb stibp fsgsbase bmi1 hle avx2 smep bmi2 erms invpcid rtm mpx avx512f avx512dq rdseed adx smap clflushopt clwb avx512cd avx512bw avx512vl xsaveopt xsavec xgetbv1 spec_ctrl intel_stibp flush_l1d arch_capabilities

Recommended Actions

Do not enable any compatibility mode as this limits CPU features to bare minimum to ensure backwards compatibility. When doing an inline upgrade, hypervisor settings are retained, but when doing a migration to a new VE, ensure 1 to 1 parity between all hypervisor settings.

If compatibility mode is enabled, the VM will need to be rebooted after the mode is disabled.

Additional Information

Review hypervisor settings to ensure understanding of what compatibility modes do and consider its implications to performance before enabling.
