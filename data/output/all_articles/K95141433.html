Description

F5 SSL Orchestrator (SSLO) can’t intercept traffic using the QUIC transport layer protocol. Typically, this will be from Chrome browsers with the QUIC protocol enabled to Google properties and some other websites. Here are some example websites:
  • https://www.youtube.com
  • https://www.google.com
  • https://www.facebook.com
By default, traffic using QUIC will bypass SSLO.

Environment

  • SSLO
  • Chrome browser with the QUIC protocol enabled
  • Web server that supports the QUIC protocol
Cause

SSLO does not yet support the QUIC protocol.

Recommended Actions

Modify the SSLO Security Policy to include a rule to reject detected QUIC traffic (forcing all browsers to switch to TLS/TCP) by doing the following:

  1. Login to the Configuration utility.
  2. Navigate to SSL Orchestrator > Configuration. The Configuration utility displays the Configure page with the Topologies tab selected by default.
  3. Click the Security Policies tab.
  4. Click the name of the existing deployed security policy.
  5. Click Add to add a security policy rule.
  6. Enter a name for the Name setting.
  7. Select L7 Protocol Lookup (UDP) for the Conditions setting. This gives the options QUIC and DNS in the L7 protocol list.
  8. Select QUIC.
  9. Select Reject for the Action setting.
  10. Click OK to save the change.
  11. Move the new rule to the top of the list by dragging it above the Pinners_Rule.
  12. Click Deploy to deploy the change.

Clients will drop back to TCP+TLS and SSLO will be able to decrypt and pass traffic along its service chain.
