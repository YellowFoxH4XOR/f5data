K000149351: APM App Tunnel always connects to the first port in port range Virtual Server

Type
Support Solution
Published
2025-01-17
Updated
2025-01-17
Applies to
  • BIG-IP
  • BIG-IP APM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000149351

Description

When using App Tunnel to connect to an application behind a Virtual Server configured with a port range, connections always target the first port in the range, regardless of the port specified in the App Tunnel resource.


Environment

  • One VS with an APM policy that assigns App Tunnel resources spanning a port range (e.g., 7000-7099).
  • Another VS acting as the App Tunnel gateway with the same port range which receives the traffic from the VS mentioned above.

Cause

This issue is being tracked as Bug ID 1786421.


Recommended Actions

While this issue has been acknowledged with Bug ID 1786421, a workaround is available to address the problem until a permanent fix is implemented:


1. Workaround:


Instead of using a single Virtual Server with a port range, create individual Virtual Servers for each required port. While this approach increases configuration complexity, it resolves the immediate issue by directing connections to the correct port.


2. Monitor for Updates:


Keep track of the Bug ID 1786421 in the F5 Bug Tracker at https://cdn.f5.com/product/bugtracker/ID1786421.html or through F5 support channels for updates on a permanent fix or hotfix release.
