Description

Dialup Entry/Windows Logon Integration deployments that use some sort of MFA (i.e., OTP/passcode/client or machine cert check) are failing the access policy checks

While logging in, users do not see the MFA window/prompt. Instead, they will get an error message similar to the following:

Connecting
Error 702: Device response received when none expected
Reconnect        Cancel

Environment

  • BIG-IP APM
  • Dialup Entry/Windows Logon Integration deployment
  • Windows clients (domain-joined)

Cause
MFA is supported for Dialup Entry/Winlogon Integration deployments.

The most likely cause why it doesn't work is that the Windows dialer's settings were not correctly configured, when it was first deployed.

Recommended Actions

When customizing the Windows Client Package for use with Dialup Entry/Winlogon Integration, under Dialup Settings:

 - select the Enforce Access Policy in Custom Dialer check box
 - clear the Prompt Username and Password check box

 
With these settings, username and password fields are prefilled and the access policy runs.
