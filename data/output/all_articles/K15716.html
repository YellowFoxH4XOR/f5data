Known Issue

The Open Shortest Path First version 3 (OSPFv3) default-information originate option may not respond to a default route addition.

This issue occurs when all of the following conditions are met:

  • You configured the BIG-IP system with OSPFv3 using the default-information originate option to redistribute default route information.
  • You then add a default route.

Impact

The default IPv6 route is not advertised using OSPFv3.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The Link State Advertisement (LSA) is not created when the default route is added after configuring the default-information originate option on OSPFv3.
  • When reviewing a tcpdump capture from a neighbor device to verify the IPv6 route, you observe that the affected default route is not advertised.

Workaround

To work around this issue (assuming you have already added the default route), you can disable OSPFv3 with the default-information originate option and then re-enable OSPFv3 with the default-information originate option.

To avoid this issue, you can create the default route first, and then enable OSPFv3 with the default-information originate option.
