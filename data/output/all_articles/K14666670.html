Description

Configuring a network failover self IP address port lockdown setting to Allow None will block HA communications, causing the systems to report their peer as offline and go active-active despite the self IP address responding to pings.

Note: If you change the port lockdown configuration on a network failover self IP to Allow None, the change does not take affect until after an event such as a reboot or when connections are deleted from the connection table. At that time the systems will attempt to reconnect, but fail as connectivity will be blocked.

Environment

  • BIG-IP
  • network failover
  • self IP address
  • port lockdown

Cause

Allow None means no traffic apart from port lockdown exceptions will be processed by the self IP address. For network failover to work, port 1026 must be accessible between peer devices.
For more information and to review port lockdown exceptions, refer to K17333: Overview of port lockdown behavior (12.x - 17.x).

Recommended Actions

Ensure that all self IP addresses used for network failover are set with Allow Default (or configure Allow Custom including port 1026 in the allowed ports list).
