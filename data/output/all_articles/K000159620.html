Description

When configuring SAML authentication with BIG-IP APM, users are successfully redirected to the Identity Provider (Azure AD) and authenticate correctly. However, after the SAML response is received, users are redirected back to the initial login page instead of being granted access.

Environment

  • BIG-IP

Cause

The Access Profile contains the below configuration:

[...]
samesite-cookie true
samesite-cookie-attr-value lax

The SameSite=Lax cookie attribute, prevents cookies from being sent with cross-site POST requests. While this setting allows cookies to be sent with top-level navigations (such as clicking a link), it blocks cookies on cross-site POST requests unless the navigation is considered "safe" (GET, HEAD, etc.).

SAML, OAuth, OIDC, and Multi-domain SSO authentication flows rely on POST requests to transmit authentication assertions.

Therefore, the initial SAML request and the SAML response from the Identity Provider creates two different session IDs, even though the InResponseTo ID correctly matches the initial SAML request.

Recommended Actions

Modify the Access Profile configuration (SSO/Auth Domains tab) to use,

samesite-cookie true
samesite-cookie-attr-value none
secure-cookie true

The last one is added because when you put "SameSite=None", you must have the "Secure" attribute set to the cookie.
