Topic

This article applies to BIG-IP 10.x. For information about other versions, refer to the following article:

  • K15067: The Auto Failback setting should be disabled when HA group is configured

If you have configured a high availability (HA) group to control the redundancy state of your BIG-IP system, you must set the Redundancy State Preference setting to None. Since both the HA group configuration and the Redundancy State Preference setting attempt to independently manage the redundancy state of the system, the HA group option is not compatible with the Redundancy State Preference setting. Configuring both can have unpredictable results.

The Redundancy State Preference setting has been available since BIG-IP 9.0.0. In a BIG-IP redundant system, the Redundancy State Preference setting controls which unit should become active when both units are online and capable of assuming the active role. If you configure one unit with a Redundancy State Preference setting of Active, and the other with a Redundancy State Preference setting of Standby, each will prefer their respectively configured state. As a result, the unit with the Redundancy State Preference setting of Standby will never assume the Active role unless the the unit with the Redundancy State Preference setting of Active is incapable of assuming that role.

The HA group feature was introduced in BIG-IP 10.1.0. An HA group defines a set of objects, which may include trunks, pools, or clusters. The system uses the status of each HA group object to calculate a health score for each unit in a redundant system configuration. This score controls which unit becomes active when both units are online and capable of assuming the active role.

Note: For more information, refer to K8184: Overview of the Redundancy State Preference setting.

Note: For more information, refer to the Configuring HA Groups section of the TMOS Management Guide for BIG-IP Systems.
