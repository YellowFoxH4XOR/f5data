Description

After modifying or deleting management firewall rules following K46122561, the old rules are still enforced.

Traffic is blocked or allowed unexpectedly.

Environment

  • Management firewall
  • mgmt_acld
  • BIG-IP 14.1.x

Cause

The MCP and iptables rules are inconsistent, as a result of bug ID 812481.

When this issue is encountered, you will see an iptables -xvL f5acl command, when running:

ps aux | grep -E '[/]mgmt_acld|[i]ptables'

For example:

USER         PID   PPID  %CPU  %MEM     VSZ     RSS TTY      STAT START   TIME        COMMAND
root       10728   6612   0.0   0.2    2.2G   25.1M ?        S    Feb22   00:21:16.75 /usr/bin/mgmt_acld
root       15097  10728   0.0   0.0   51.2M    1.7M ?        S    15:17   00:00:00.00 /sbin/iptables -xvL f5acl  <---

The PPID (parent process ID) of this process will correspond to the PID of the mgmt_acld process, which is responsible for maintaining statistics relating to the management firewall rules.

Additionally, running the iptables -xvL f5acl command manually from the command line will result in the following:

Another app is currently holding the xtables lock. Perhaps you want to use the -w option?

The iptables -xvL f5acl command runs every 10 seconds to gather stats about the various firewall rules for mgmt_acld.

By default, when using the -L option, iptables attempts a reverse DNS lookup of any IP addresses present, in order to display hostnames rather than IP addresses.

These reverse lookups can take a long time (especially if they fail), and since the process runs every 10 seconds, the system will be continually attempting those lookups. The result is that any other command that requires the xtables lock (like those that would add or delete rules) is likely to not work, resulting in the rule changes not being properly propagated to iptables (iptables-save is an exception to this and does not require the lock).

Recommended Actions

Upgrade to 15.1.x or later, which includes the fix for bug ID 812481. The iptables command spawned from mgmt_acld in the fixed versions includes the -n option, which causes iptables to displays IP addresses in numerical format, rather than attempt to resolve them to hostnames using a reverse DNS lookup.

Alternatively, to work around the issue, do one of the following:

  • Reboot the system:

    touch /service/mcpd/forceload && reboot

  • Stop mgmt_acld, clear the /run/xtables.lock file, delete the old rule(s) in question from iptables, then start mgmt_acld.

    Note: This option is not recommended, unless you are an advanced user of iptables.

  • Stop mgmt_acld, clear the /run/xtables.lock file, create a new firewall rule which does not contain an IP address, then start mgmt_acld:

    • tmsh stop sys service mgmt_acld && rm -f /run/xtables.lock
    • <create new management firewall rule>
    • tmsh start sys service mgmt_acld

Note: There is an element of timing with the workarounds, since mgmt_acld runs the iptables command every 10 seconds.

Additional Information

You can review the current rules in the f5acl chain with the following command:

command iptables -nL f5acl
(including command, which is a bash builtin)

Note: This command will not work if the system is still affected by bug ID 812481.
