K000161604: Configuration BIG-IP device to send audit log using TLS over TCP protocol

Description

This article describes how to configure BIG-IP LTM to securely forward authentication logs (such as user login/logout events) to a remote syslog server (e.g., Graylog) using TLS encryption over TCP. This is accomplished by leveraging syslog-ng for log selection and forwarding, and a BIG-IP virtual server with a serverside-ssl profile to provide TLS encryption.

By default, BIG-IP LTM uses two separate logging mechanisms:

  • HSL (High-Speed Logging): Handles logs from BIG-IP daemons (e.g., mcpd, tmm) but does not support authentication logs.
  • syslog-ng: Handles Linux native daemon logs (e.g., sshd, httpd, pam) including authentication events.

HSL cannot forward authentication logs. To send these logs securely over TLS, syslog-ng must be configured to forward them to a local virtual server, which then encrypts and forwards the logs to the remote syslog server.

Environment

  • BIG-IP LTM (all supported versions)
  • Remote syslog server (e.g., Graylog) capable of receiving TLS-encrypted syslog
  • syslog-ng enabled on BIG-IP

Cause

By default, authentication logs are not forwarded securely via HSL. syslog-ng must be used to select and forward these logs, and a virtual server is required to provide TLS encryption.

Answer/Recommended Actions

  1. Create a Pool for the Remote Syslog Server

    ltm pool pool_remote_secure_syslog {
    members {
    syslog_server:syslog-tls {
    address <REMOTE_SYSLOG_SERVER_IP>
    }
    }
    monitor tcp_half_open
    }

  2. Create a Virtual Server for TLS Encryption

    This virtual server receives plain TCP syslog from syslog-ng and encrypts it using a serverside-ssl profile.

    ltm virtual vs_secure_syslog_target {
    destination <VS_IP_ADDRESS>:<PORT>
    ip-protocol tcp
    mask <MASK>
    pool pool_remote_secure_syslog
    profiles {
    serverssl-insecure-compatible { context serverside }
    tcp { }
    }
    serverssl-use-sni disabled
    source <SOURCE_IP>/0
    source-address-translation { type automap }
    translate-address enabled
    translate-port enabled
    vlans { internal }
    vlans-enabled
    }

    Note: Replace <VS_IP_ADDRESS>, <PORT>, <MASK>, <SOURCE_IP>, and <REMOTE_SYSLOG_SERVER_IP> with your actual values. Specify the correct ingress VLAN (e.g., internal) to ensure syslog-ng can reach the virtual server.
  3. Configure syslog-ng to Forward Authentication Logs
    1. Access tmsh:
      tmsh
    2. Edit the syslog configuration:
      edit sys syslog all-properties
    3. In the editor, add the following to the include field (use :set paste and press i to enter insert mode):

      include "
      destination d_remote_auth {
      tcp(\"<VS_IP_ADDRESS>\" port(<PORT>));
      };
      filter f_auth_events {
      facility(auth, authpriv)
      or (facility(local6) and match(\"pam_audit|auth_pam|mod_auth_pam|AUDIT\"))
      or (facility(local0) and match(\"AUDIT\"));
      };
      log {
      source(s_syslog_pipe);
      filter(f_auth_events);
      destination(d_remote_auth);
      };
      "

      Note: Replace <VS_IP_ADDRESS> and <PORT> with the virtual server’s IP and port.
    4. Save and exit:
      :wq!
      Then press y to confirm.
    5. Save the configuration:
      tmsh save sys config
  4. (Optional) Use a Custom Certificate in the Server SSL Profile
    • Import your certificate and key to BIG-IP.
    • Create a custom server-ssl profile and assign the certificate and key.
    • Apply this profile to the virtual server instead of serverssl-insecure-compatible.

Additional Information

  • syslog-ng includes the hostname in log messages by default.
  • HSL configuration can remain for BIG-IP daemon logs if needed.
  • syslog-ng uses the management plane to forward logs to the local virtual server, which then uses the data plane to encrypt and forward logs to the backend server.
  • Authentication logs are typically found in /var/log/secure on BIG-IP.
