K84200202: Connection Table entries for a blade are deleted when the blade fails

Type
Support Solution
Published
2020-09-24
Updated
2026-07-16
Status
Legacy Content
Applies to
  • VIPRION Platforms
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K84200202

Description
When a blade in a VIPRION chassis transitions from Active/running state to another state (due to admin down, failure, unseat), connection table entries utilizing that blade are deleted.

Environment

  • VIPRION
  • Connection Mirroring configured "Between Clusters"

Cause
This is functioning as designed when Connection Mirroring is configured for "Between Clusters". Alternatively, Connection Mirroring can be configured within a single cluster as "Within Cluster" with another Active/running state blade receiving the connections from the unavailable blade.

Recommended Actions

When "Between Cluster" Connection Mirroring is enabled, a peer chassis is also configured and traffic is intended to transition to that peer when the currently active BIG-IP experiences problems. If traffic remains on the BIG-IP which experienced blade failure and does not transition to the peer the architecture should be reviewed for potential reconfiguration.
