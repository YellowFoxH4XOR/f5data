Description

The Traffic Management Microkernel (TMM) may restart when a DNS cache resolver's max-concurrent-queries setting value is significantly larger than the default.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP configuration contains a cache resolver that resolves DNS queries.
  • You have modified the max-concurrent-queries setting to a value significantly larger than the default value
  • The BIG-IP system receives a large amount of DNS traffic.
  • TMM CPU usage on TMM spiked to 100% with no traffic increase. TMM becomes unresponsive, then restarts.
  • no core file generated.
  • On the logs under /var/log/ltm a high number of clock advance messages were observed.

  • For example:

    01010029:5: Clock advanced by 518 ticks
    01010029:5: Clock advanced by 505 ticks
    01010029:5: Clock advanced by 590 ticks

 

Environment

  •  TMM
  •  The max-concurrent-queries value (This value defines how many concurrent queries our platform can execute to the DNSs to feed the cache.)
  • Big-IP LTM
 

Cause

The max-concurrent-queries value larger than the default (1,204) makes TMM stuck in inbound handling communications between BIG-IP and backend DNS servers. This leads to breaking MCPD connections, making TMM exit. 

Recommended Actions

F5 recommends to adjust DNS cache tuning. Start with those concurrent connection settings, lowering the parameters.
 
  1.               Log in to the GUI
  2.               Go to DNS >> Cache >> Cache List >> Select your cache profile >> modify the following settings:

            Adjust max-concurrent-queries from XXXX to default value of 1024
            Adjust max-concurrent-tcp from XXX to default value of 20
            Adjust max-concurrent-udp from XXXX to default value 8192
