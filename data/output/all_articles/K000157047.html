Description

After upgrading to a new BIG-IP version the device failed to start properly. The system reported configuration load errors referencing missing EPSEC files and cache paths, resulting in an inability to load the full configuration and bring the device online. You will see log messages similar to this

load_config_files[9169]: "/usr/bin/tmsh -n -g -a load sys config partitions all " - failed. -- 01070712:3: Failed: name (/Common/epsec-1.0.0-1303.0.iso) Cache path (/config/filestore/files_d/Common_d/epsec_package_d/:Common:epsec-1.0.0-1303.0.iso_65289_1) does not exist and there is no copy in trash-bin to restore from.

You may also find that you are unable to revert back to the previous version. 

Environment

  • BIG-IP APM
  • After Upgrade

Cause

The root cause is due to manual deletion of EPSEC package files from the files system ,  without removing corresponding BIG-IP configuration, resulting in broken references that prevented proper configuration loading after upgrade.

Recommended Actions

Reboot back to the previous version.

When you see the below error:

load_config_files[1234]: "/usr/bin/tmsh -n -g -a load sys config partitions all " - failed. -- 01070712:3: Failed: name (/Common/epsec-1.0.0-ABCD.0.iso) Cache path (/config/filestore/files_d/Common_d/epsec_package_d/:Common:epsec-1.0.0-ABCD.0.iso_abcde_1) does not exist and there is no copy in trash-bin to restore from.

 

  1. Copy the highlighted filename from your log message
  2. Enter the command below, pasting the filename after the `touch` command:
    touch /config/filestore/files_d/Common_d/epsec_package_d/:Common:epsec-1.0.0-ABCD.0.iso_abcde_1
    Note: If you are unable to copy/paste the filename, you will need to replace the values ABCD and abcde with the actual numbers you see while typing the command into the CLI.
  3. Reboot the system again
  4. If you see another EPSEC related error message, return to step 1 and repeat the process with the next epsec filename that the log message refers to
  5. When you see no more errors like this, you can continue to the next step
  6. Validate the configuration with the following commands:
    tmsh save sys config partitions all
    tmsh load sys config verify
  7. You should not see any errors, but maybe a few warnings, (warnings are ok)
  8. Log into the Web UI Navigate to System > Software management > Boot locations
  9. Click on the boot location for the version you are upgrading to.
  10. For Install configuration, set this to YES
  11. Select the source volume and set it to the (current) partition you have just repaired
  12. Click Activate to reboot. 

When the BIG-IP has finished rebooting into the new upgraded version, follow the steps in article K21175584  to remove the unwanted EPSEC files using the correct method.
