Known Issue

The BIG-IP system does not present the root Certificate Authority (CA) certificate when configured in a Secure Sockets Layer (SSL) profile.

This issue occurs when all of the following conditions are met:

  • You configure an SSL profile with a root CA certificate and apply the profile to a virtual server.
  • The virtual server performs an SSL/Transport Layer Security (TLS) handshake.

If you include the root CA certificate in a certificate bundle and add it to the certificate key chain configuration of an SSL profile, the BIG-IP system will not present the root CA certificate during the SSL/TLS handshake.

Important: Putting the root CA certificate in the certificate bundle is optional and will not cause the client to trust the root CA unless the client is specifically configured to do so. In typical deployments, clients do not trust the root CA because it defeats the purpose of third-party validation. Trusted CAs should be predetermined and their certificates intentionally installed on the client.

Impact

Certificate validation will fail with custom client configurations that require the root CA from the server.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Packet captures show the root CA certificate is not provided by the BIG-IP system during an SSL/TLS handshake.
  • Client systems display a certificate error that indicates the server certificate is not trusted.
