Topic

As of BIG-IP 4.5.0, BIG-IP verifies that the literal (quoted string) is the appropriate length. If the length is over 63 characters per literal, it is considered too long for the BIG-IP to properly handle and BIG-IP will return an error.

To work around this issue, the BIG-IP rules and pool engines have been changed so that the argument to redirect and log functions is now an expression, rather than a string.

This change allows you to connect literals and variables to form the resulting redirect URL or log message and allows you to enter information related to the current request into redirect URLs and log messages using variables (for example, server_addr, and http_uri).

Note: Format strings (%h, %u, %p) are still supported within the first text literal in the expression for backward compatibility.

Long redirect URL rules

Following is an example of a redirect rule:

redirect to "http://mysite.mydomain.com/asp/myasppage" + "?userinfocheck+iteminfo"

The redirect statement, redirect to "http://%h/backup/%u", is still supported, but only for single strings. A better solution is to combine literal strings and variables.

The following is an example of the strings and variable combination that will result in the same redirect as http://%h/backup/%u:

redirect to "http://" + http_host + "/backup/" + http_uri

Log function rule

Following is an example of a log function rule:

log "information" + "more information"
