Known Issue

Users experience increased latency when the BIG-IP system is using a FastL4 profile and connection mirroring.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system is part of a high availability (HA) group.
  • You configured the BIG-IP system with a virtual server using a FastL4 profile and enabled connection mirroring.

Enabling Nagle's algorithm (default behavior) in the internal TCP profile for the HA connection between BIG-IP systems causes increased latency for initial connection setup for FastL4 virtual servers when connection mirroring is enabled.

Impact

Users experience a light traffic delay during connection setup.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Increased latency during connection setup.

Workaround

To work around this issue, you can either:

  • Disable the tm.fastl4_ack_mirror sys db setting and, optionally, enable the tm.fastl4_mirroring_taciturn sys db setting.

    or

  • Disable Nagle's algorithm for the internal high availability (HA) TCP profile.

To do so, perform one of the following procedures:

  • Disabling the tm.fastl4_ack_mirror sys db setting and, optionally, enabling the tm.fastl4_mirroring_taciturn sys db setting
  • Disabling Nagle's algorithm for the internal HA TCP profile (11.4.x - 11.6.x)
  • Disabling Nagle's algorithm for the internal HA TCP profile (12.x - 13.x)
  • Disabling Nagle's algorithm for the internal HA TCP profile (14.x)

Disabling the tm.fastl4_ack_mirror sys db setting and, optionally, enabling the tm.fastl4_mirroring_taciturn sys db setting

When you disable the tm.fastl4_ack_mirror sys db setting, the active BIG-IP system no longer waits for the peer to acknowledge a mirrored connection before completing the connection. As a result, the active system may establish connections that are not mirrored on the standby system.

When you enable the tm.fastl4_mirroring_taciturn sys db setting, the system reduces the number of mirroring messages per flow, resulting in a slightly higher risk that flows at certain stages encounter a longer delay while they are establishing the connection, or they drop. The risk is very slight, and it is only a risk during the initial setup. Instead of a full state mirror, the system advances the state on the standby, at an earlier time.

Additionally, the system retains modifications to sys db settings through system upgrades.

Impact of workaround: This procedure requires you to restart the Traffic Management Microkernel (TMM), which interrupts traffic processing, so perform this procedure during a maintenance window.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. Disable the tm.fastl4_ack_mirror sys db setting by typing the following command:

    modify /sys db tm.fastl4_ack_mirror value disable

  3. Optional: Enable the tm.fastl4_mirroring_taciturn sys db setting by typing the following command:

    modify /sys db tm.fastl4_mirroring_taciturn value enable

  4. Save your changes by typing the following command:

    save /sys config

  5. Restart TMM by typing the following command:

    restart /sys service tmm

    Important: When you restart TMM on the active system, it causes a failover.

Disabling Nagle's algorithm for the internal HA TCP profile (11.4.x - 11.6.x)

Impact of workaround: This procedure requires that you:

  • Restart TMM, which interrupts traffic processing.
  • Temporarily remount the /usr file system in read-write mode.
  • Perform this procedure on each BIG-IP system in your HA group.

Additionally, when you perform a software upgrade, you lose the modifications you made to the tmm_base.tcl file.

  1. Log in to the BIG-IP command line.
  2. Remount the /usr file system in read-write mode by typing the following command:

    mount -o remount,rw /usr

  3. Change to the /usr/lib/tmm directory by typing the following command:

    cd /usr/lib/tmm

  4. Back up the original tmm_base.tcl file by typing the following command:

    cp tmm_base.tcl tmm_base.tcl.sol16601

  5. Edit the tmm_base.tcl file using either the Pico or vi text editor.
  6. Locate the following section:

    # High Availability TCP server
    # TCP-> <ha server> <- TCP:
    proxy HA {
        clientside TCP4
        serverside TCP4
    }

    Add the profile tcp _tcp4_ha_defaults stanza, similar to the following example:

    Important: In BIG-IP 11.5.1 and later, the profile tcp _tcp4_ha_defaults profile configuration already exists; simply modify the nagle setting from enabled to disabled.

    # High Availability TCP server
    # TCP-> <ha server> <- TCP:

    profile tcp _tcp4_ha_defaults {
        idle_timeout 30
        keep_alive_interval 1
        maxrtx 4
        syn_maxrtx 3
        rcvwnd 4194304
        sndbuf 4194304
        delayed_acks enabled
        time_wait_recycle enabled
        deferred_accept disabled
        selective_acks enabled
        dsack disabled
        ecn disabled
        limited_transmit enabled
        timestamps enabled
        slow_start disabled
        nagle disabled
        ack_on_push disabled
    }

  7. Add the profile _tcp4_ha_defaults reference to the proxy HA stanza, similar to the following:

    proxy HA {
        clientside TCP4
        serverside TCP4
        profile _tcp4_ha_defaults
    }

  8. Save the /usr/lib/tmm/tmm_base.tcl file.
  9. Remount the /usr file system in Read-Only mode by typing the following command:

    mount -o remount,ro /usr

  10. Restart TMM by typing the following command:

    tmsh restart /sys service tmm

    Important: When you restart TMM on the active system, it causes a failover.

    11. Disabling Nagle's algorithm for the internal HA TCP profile (12.x - 13.x)

    Impact of workaround: This procedure requires that you:

    • Restart TMM, which interrupts traffic processing.
    • Temporarily remount the /usr file system in read-write mode.
    • Perform this procedure on each BIG-IP system in your HA group.

    Additionally, when you perform a software upgrade, you lose the modifications you made to the tmm_base.tcl file.

    1. Log in to the BIG-IP command line.
    2. Remount the /usr file system in read-write mode by typing the following command:

      mount -o remount,rw /usr

    3. Change to the /usr/lib/tmm directory by typing the following command:

      cd /usr/lib/tmm

    4. Back up the original tmm_base.tcl file by typing the following command:

      cp tmm_base.tcl tmm_base.tcl.sol16601

    5. Edit the tmm_base.tcl file using either the Pico or vi text editor.
    6. Locate the following section:

      # High Availability state mirroring server and client
      #     :TCP4 -> SSL -> <ha server>:
      #     :<ha client> -> SSL -> TCP4:
      # HA TCP4 defaults

      Modify the profile tcp _tcp4_ha_defaults stanza and change auto_nagle enabled to auto_nagle disabled, similar to the following example:

      profile tcp _tcp4_ha_defaults {
          idle_timeout 30
          keep_alive_interval 1
          maxrtx 4
          syn_maxrtx 3
          rcvwnd 4194304
          sndbuf 4194304
          delayed_acks enabled
          time_wait_recycle enabled
          deferred_accept disabled
          selective_acks enabled
          dsack disabled
          ecn disabled
          limited_transmit enabled
          timestamps enabled
          slow_start disabled
          auto_nagle disabled
          ack_on_push disabled
          abc enabled
          cmetrics_cache enabled
          congestion_ctrl 3
          delay_window_control disabled
          mptcp_mode disabled
          mss 0
      }

    7. Save the /usr/lib/tmm/tmm_base.tcl file.
    8. Remount the /usr file system in read-only mode by typing the following command:

      mount -o remount,ro /usr

    9. Restart TMM by typing the following command:

      tmsh restart /sys service tmm

      Important: When you restart TMM on the active system, it causes a failover.
