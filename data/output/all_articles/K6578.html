Topic

The Traffic Management Microkernel (TMM) may stop responding if an iRule attempts to store too much data in a variable

Description

The Traffic Management Microkernel (TMM) may stop responding if an iRule attempts to save more than 4 MB of data to a variable for BIG-IP 9.x and 10.x, or various limits as detailed below in subsequent BIG-IP releases. TMM restricts the maximum contiguous allocation for iRule variables and if the amount of data to be saved exceeds the limit, TMM stops responding.

Note: The limit has been increased to 32 MB beginning in BIG-IP 11.0.0, and increased further in subsequent releases.
          For more information, refer to: K13387: TMM now allocates memory in larger blocks

However, strings that undergo manipulations, which convert text from UTF-8 to Unicode, double in size. As a result, iRules requiring such string manipulations are artificially restricted to act on variables less than half of the maximum size (2 MB for BIG-IP 9.x and 10.x, and 16 MB for BIG-IP 11.x and later).

This condition typically manifests under any of the following conditions:

  • You use the HTTP::collect or TCP::collect iRules commands to collect data, then save the payload to a variable.
  • You use the append iRules command to append data to a variable.
Recommended Action

You can mitigate this condition by limiting the data your iRule saves to a single variable to 4 MB or 32 MB or less (2 MB/16 MB if regular expression replacements are performed against the data).

When collecting data using the HTTP::collect iRule command, you can use the optional length parameter to limit the amount of data collected. To do so, use a command similar to one of the following examples:

  • HTTP::collect 4000000

    This command limits the amount of data collected to just below the 4-MB limit for BIG-IP 9.x and 10.x

  • HTTP::collect 16000000

    This command limits the amount of data collected to just below the 16-MB limit for BIG-IP 11.x when using regular expression replacements.

Note: For an example iRule demonstrating the recommended implementation of the HTTP::collect limitation described previously, refer to the HTTP Payload Collection article on DevCentral.

Note: Character set conversions and regular expression operations can quadruple the payload size in memory; therefore, the functional maximum collection limit for payload manipulation is 1 MB.

When collecting data using the TCP::collect iRule command, you can use the optional minimum amount parameter to specify the amount of data which must be collected in order to fire the event. To do so, use a command similar to the following example:

  • TCP::collect 1000

    This command triggers the iRule event after 1000 bytes of data and then releases the data.

    Note: If the TCP payload is less than 1000 bytes, the event is not triggered.

Note: For an example iRule demonstrating the recommended implementation of the TCP::collect command, refer to the TCP::collect command description on F5 Cloud Docs.

For iRules that use the append iRule command to append data to a variable, make sure to unset the appended variable at the end of the iRule event. To do so, use a command similar to the following example:

unset <appended_variable>

For example:
{
set variable [HTTP::uri]
append new_variable "?" $variable
....
.....
....
unset new_variable
}
