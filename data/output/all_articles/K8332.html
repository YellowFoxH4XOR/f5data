Known Issue

This is the result of a known issue. The FastL4 profile TCP Handshake Timeout setting specifies the acceptable duration for establishing a TCP handshake for the FastL4 virtual server connection. If the TCP handshake takes longer than the timeout, the BIG-IP system automatically closes the connection. The default is five seconds.

When the PVA Acceleration level for the virtual server is set to either full or assist, and a TCP handshake takes longer than five seconds to complete, the BIG-IP system does not honor the TCP Handshake Timeout setting. As a result, the incomplete TCP connection remains in the BIG-IP connection table until it is timed out by the FastL4 profile idle timeout value.

F5 Product Development is tracking this issue as ID 248064 (formerly CR44256).

Workaround

You can work around this issue by creating a new FastL4 profile with the PVA Acceleration setting set to none. To do so, perform the following procedure:

Note: Setting the PVA Acceleration setting to none means that no traffic for the virtual server is accelerated by the PVA chip.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles.
  3. Select FastL4 from the Protocol drop-down menu.
  4. Click Create.
  5. Type a name for the profile.
  6. In the PVA Acceleration menu, select None.
  7. Click Finished.
You must now associate the new FastL4 profile with the virtual server.
