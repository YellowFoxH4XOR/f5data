K53139549: After removing the NTLM Configuration you still see traffic towards the Domain Controller for NTLM Authentication Server

Description
After removing the NTLM machine account and NTLM auth configuration from an Active device., then, syncing the configuration to the standby unit, you still see traffic from the BIG-IPs being directed towards the Domain Controller for NTLM Authentication.

You may see these logs under /var/log/apm
err nlad[14882]: 01620000:3: <0x57800b70> nlclnt[66586000a] init: Error [0xc0000001,NT_STATUS_UNSUCCESSFUL] connecting to DC <IP Address>
err nlad[14882]: 01620000:3: <0x56c00b70> nlclnt[66486000a] init: Error [0xc0000011,NT_STATUS_END_OF_FILE] connecting to DC <IP Address>
err nlad[14882]: 01620000:3: <0x56f00b70> nlclnt[66486000a] init: Error [0xc0000011,NT_STATUS_END_OF_FILE] connecting to DC <IP Address>
err nlad[14882]: 01620000:3: <0x57200b70> nlclnt[66486000a] init: Error [0xc0000011,NT_STATUS_END_OF_FILE] connecting to DC <IP Address>

Environment

  • Remove NTLM Authentication
  • nlad and eca communication channels.

Cause
This occurs because the channel is maintained until the eca and nlad services are restarted.

Recommended Actions

Restart the eca and nlad services in the BIG-IP device that is still sending traffic towards the Domain Controller
tmsh restart /sys service eca nlad
IMPORTANT: restarting the eca and nlad services will effectively interrupt all communication channels towards the Domain Controller and all NTLM transactions will stop. Please, plan accordingly.
