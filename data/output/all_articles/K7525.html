Known Issue

This is the result of a known issue. The following password authentication module (PAM) error messages are reported in the /var/log/cron file:

crond[28855]: PAM unable to dlopen(/lib/security/pam_krb5.so)
crond[28855]: PAM [dlerror: /lib/security/pam_krb5.so: cannot open
shared object file: No such file or directory]
crond[28855]: PAM adding faulty module:
/lib/security/pam_krb5.so

These error messages occur because the PAM is unable to locate the pam_krb5.so module. The BIG-IP system does not install or use this module.

F5 Product Development tracked this issue as ID234505 (formerly CR62196) and it was fixed in BIG-IP 9.4.0. For information about upgrading, refer to the BIG-IP LTM, GTM, ASM, or Link Controller release notes.

Note: The option that causes the error message to be reported has been removed in BIG-IP 9.4.0 and later. However, if a system is upgraded from a previous version to BIG-IP 9.4.0 or later and the configuration file is rolled forward, the error message will be reported, as the option is contained within the configuration file. To prevent the error message from being reported after upgrading to BIG-IP 9.4.0 or later, refer to the following workaround.

This issue still exists in the BIG-IP 9.3 software branch.

Workaround

You can work around this issue by preventing the error messages from being logged each time the crond process runs. To do so, perform the following procedure:

  1. Log in to the BIG-IP command line.
  2. Using a text editor, edit the /config/bigip/auth/pam.d/crond file.
  3. Remove or comment out the following line:

    session optional pam_krb5.so

  4. Save the changes to the file.

Note: You do not need to restart the BIG-IP system or any daemons; the change will occur automatically the next time the crond process runs.
