Known Issue

This is the result of a known issue. When you configure a Web Application Tunnel and select the Locked Browser check box, users can bypass the Locked Browser feature in Microsoft Internet Explorer by pressing the keyboard shortcut CTRL+N to open a new browser window after launching the Web Application Tunnel. The new browser window will be a standard browser window, containing an Address bar in which the user can enter alternate URLs.

Important: FirePass correctly applies the Web Application Tunnel Allow List to the new browser window, and so users can only access sites permitted by the Allow List in the new browser window.

F5 Networks Product Development tracked this issue as CR83959 and it was fixed in FirePass version 6.0.2. For information about upgrading, refer to the FirePass Release Notes.

Additionally, cumulative hotfix HF-601-9 has been issued for FirePass version 6.0.1. You may download this hotfix or later versions of the cumulative hotfix from the F5 Networks Downloads site.

For instructions about obtaining a hotfix, refer to K167: Downloading software from F5 Networks.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.

Workaround

To minimize the impact of this issue, ensure that the Allow List configured for each Web Application Tunnel is as restrictive as possible. Additionally, avoid using wildcard characters in Allow Lists when possible. For example:

http://*.siterequest.com/*

Rather than use the wildcard character, you could use the following:

http://sales.siterequest.com/database/dbquery.php

Note: Web Application Tunnels are configured on the Application Access: App Tunnels: Resources page under the Web Application Tunnels tab.
