Topic

You should consider using this procedure under the following conditions:

  • You have a BIG-IP system with the BIG-IP APM module licensed and provisioned.
  • You have client-side checks enabled in your access policy configuration.
  • You are unable to connect to the BIG-IP APM system or fail to pass or complete the antivirus or firewall checks.
  • Failing antivirus or firewall checks allow you to connect to the BIG-IP APM system when you should not be able to.

Description

This article provides steps for data collection that are required in order to troubleshoot issues with BIG-IP APM client-side antivirus or firewall checks.

Note: To open support cases with F5 Support, you must have an active support contract and be authorized to open cases. If you use an F5 product or client application, such as F5 Access for IOS or F5 Access for Android, and you require support, contact your system administrator or IT department for assistance.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have administrative access to the BIG-IP APM Configuration utility.
  • You have administrative access to the BIG-IP APM command line.
  • You have access to a test system that fails client-side antivirus or firewall checks.

Procedures

When experiencing trouble with client-side antivirus or firewall checks, use the following procedures to gather data for troubleshooting:

  • Determining the active OPSWAT version
  • Reviewing the OPSWAT support chart to verify support for your antivirus or firewall software
  • Obtaining and installing the latest OPSWAT software
  • Enabling debug logging for the BIG-IP APM system.
  • Running the Client Troubleshooting Utility (CTU)
  • Generating OESIS diagnostic logs

Determining the active OPSWAT version

BIG-IP APM antivirus and firewall client-side checks use software libraries from a software development kit (SDK) created by OPSWAT, Inc. You can upload several OPSWAT image files to the BIG-IP APM; however, you can only install and use one version. Be sure you know which version of OPSWAT software is installed on the system. In some cases, upgrading the OPSWAT software may resolve client-side check issues. For more information about determining the active version of OPSWAT software installed on the BIG-IP APM system, refer to K14207: Determining the active OPSWAT version.

Reviewing the OPSWAT support chart to verify support for your antivirus or firewall software

You can find support charts for antivirus, firewall, and other applications in the online help menus. The charts are automatically updated when you install OPSWAT hotfixes. You should review the support charts to verify that the antivirus or firewall check is supported for your software version. For information about locating the OPSWAT support chart for the BIG-IP APM system and the FirePass controller, refer to K12385: OPSWAT support chart.

Obtaining and installing the latest OPSWAT software

OPSWAT periodically issues new versions of SDK libraries to include new and updated security products and software enhancements. If you experience a problem detecting a Windows-based third-party security product, you should download and install the latest OPSWAT software on your BIG-IP APM system to ensure the latest products are included.

Downloading the latest OPSWAT hotfix
If you have valid F5 Support contract, you can obtain the latest OPSWAT software by performing the following procedure:

  1. Use a browser, to log in to the F5 Downloads site.
  2. On the Downloads Overview page, select Find a Download.
  3. On the Select a Product Line page, select the appropriate product line for the version of software currently installed on your BIG-IP APM system.
  4. On the Select a Product Version and Container for page, select the appropriate BIG-IP APM version number in the version list.
  5. Select the name of the OPSWAT file. For example, espec-<version>-<build>.
  6. Read the End User Software License Agreement and select I Accept to accept the agreement terms.
  7. On the Select a Download page, select the name of the OPSWAT ISO file. For example, epsec-<version>.<build>.iso.
  8. On the Download Locations page, select the location closest to you, and then save the file to a location on your computer.

Installing OPSWAT hotfixes on the BIG-IP APM system

To use the updated OPSWAT software, you need to upload and install the OPSWAT hotfix on the BIG-IP APM system. For more information about installing OPSWAT hotfixes, refer to K10942: Installing OPSWAT hotfixes on BIG-IP APM systems.

Enabling and disabling debug logging for the BIG-IP APM system

You can obtain more information about antivirus and firewall check failures by enabling debug logging for the BIG-IP APM system. After you enable debug logging, you can try to reproduce the problem. Note the user session ID to refer to later when reviewing logs for troubleshooting.

Beginning in BIG-IP APM 12.x, you can create separate logging settings for each access profile. To enable debug logging for the affected access profile, perform the following procedure:

Impact of procedure: F5 recommends that you return the log level to the default value after you complete the troubleshooting steps. Leaving debug logging enabled when the system is in normal production mode may generate excessive logging and cause poor system performance.

Enabling debug logging for BIG-IP APM 13.x

  1. Log in to the BIG-IP Configuration utility and go to Access > Overview > Event Logs > Settings.
  2. Select Create.
  3. Under General Information enter a name and select the Enable Access System Logs check box.
  4. Under Access System Logs, for Access Policy, select Debug.
  5. Under Access Profiles move the access profile you want to log from Available to Selected.
  6. Select OK.

Disabling debug logging for BIG-IP APM 13.x

Impact of procedure: Performing the following procedure should not have a negative impact on your system.
  1. Log in to the BIG-IP Configuration utility and go to Access > Overview > Event Logs > Settings.
  2. Select the check box for the log settings you created in the previous procedure.
  3. Select Delete and then select Yes to confirm deletion of the debug log settings and to remove the settings from the access profile.

Enabling debug logging for BIG-IP APM 12.x

  1. Log in to the BIG-IP Configuration utility and go to Access Policy > Event Logs > Log Settings.
  2. Select Create.
  3. Under General Information enter a name and select the Enable Access System Logs check box.
  4. Under Access System Logs, for Access Policy, select Debug.
  5. Under Access Profiles move the access profile you want to log from Available to Selected.
  6. Select OK.

Disabling debug logging for BIG-IP APM 12.x

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP Configuration utility and go to Access Policy > Event Logs > Log Settings.
  2. Select the check box for the log settings you created in the previous procedure..
  3. Select Delete and then select Yes to confirm deletion of the debug log settings and to remove the settings from the access profile.

Enabling and disabling debug logging for BIG-IP APM 11.x

In BIG-IP APM 11.x, you can enable and disable access policy debug logging using the Configuration utility or by setting the log.accesscontrol.level database variable. To do so, perform one of the following procedures:

Using the Configuration utility

Impact of procedure: F5 recommends that you return the log level to the default value after you complete the troubleshooting steps. Leaving debug logging enabled when the system is in normal production mode may generate excessive logging and cause poor system performance.

  1. Log in to the BIG-IP Configuration utility and go to System > Logs > Configuration > Options.
  2. Under Access Policy Logging, select Debug in the Access Policy list.
  3. Select Update.
After you've finished troubleshooting, you can disable debug logging by repeating step 1 in the previous procedure and selecting Notice in the Access Policy list in step 2.

Setting the log.accesscontrol.level database variable

Impact of procedure: F5 recommends that you return the log level to the default value after you complete the troubleshooting steps. Leaving debug logging enabled when the system is in normal production mode may generate excessive logging and cause poor system performance.

  1. Log in to the Traffic Management Shell (tmsh) by entering the following command:

    tmsh

  2. Enable access policy debug logging by entering the following command:

    modify /sys db log.accesscontrol.level value debug

  3. After you've finished troubleshooting, you can disable debug logging and reset access policy logging to the default setting by entering the following command:

    modify /sys db log.accesscontrol.level reset-to-default

Running the Client Troubleshooting Utility (CTU)

The CTU is a Windows-based client application you can use to collect diagnostic data when troubleshooting client issues. You can download the file for distribution from the Configuration utility by selecting Client troubleshooting Utility for Windows on the Welcome page under Downloads. For information about running the CTU, refer to K12444: Overview of the Client Troubleshooting Utility for Windows.

Beginning in APM Clients 7.2.1.4, the CTU also includes a OPSWAT Endpoint Inspection report of the client device by default. This includes reports on firewall, antivirus, peer-to-peer software, patch management, hard disk encryption, antispyware, and Windows health agent.

Generating OESIS diagnostic logs

The OESIS Diagnose utility allows you to collect diagnostic data that you can use to troubleshoot client-side security checks. In BIG-IP APM 11.4.1 HF6 and later, the tool is located in the OPSWAT ISO file (epsec-<version>.<build>.iso) in the .Tools folder. For information about generating the OESIS diagnostic log, refer to K11643: Troubleshooting with the OPSWAT OESIS Diagnostic tool.
