K000137128: BIG-IP Next Central Manager fails to create VMWare instance with Invalid escape sequence error

Source

Description

When you attempt to create a new instance on the VMWare vSphere provider through the BIG-IP Next Central Manager, the instance creation fails and the BIG-IP Next Central Manager logs the following alert in the Alerts & Notifications page:

BIG-IP Next Central Manager 20.3.0

Summary - Failed to create instance <instance management IP>
Description - Failed to create vSphere instance "<instance management IP>" due to an internal error. Check the log and try creating instance again.

BIG-IP Next Central Manager 20.2.1

Summary - Failed to create instance <instance management IP>
Description - unable to instantiate vSphere BIG-IP Next instance. Check the log for more details

BIG-IP Next Central Manager 20.1.0 through 20.2.0

Summary - Instance Creation Alert
Description - unable to instantiate vSphere BIG-IP Next instance. Check the log for more details

BIG-IP Next Central Manager 20.0.1 through 20.0.2

Summary - Instance Creation Alert
Description - Invalid escape sequence

Environment

  • BIG-IP Next Central Manager 20.0.1 and later
  • VMWare vSphere provider 7.x

Cause

When you add the VMWare vSphere provider, you used a username that contains a backslash (\). For example, mydomain\user1.

Recommended Actions

If your VMWare vSphere environment supports using usernames without the domain name, for example, user1 instead of mydomain\user1, you should delete the provider from BIG-IP Next Central Manager and recreate a new one using the username without the domain name.

Additional Information

Starting from BIG-IP Next Central Manager 20.1.0, if you perform a Log Search on the BIG-IP Next Central Manager's qkview in iHealth and search for instantiate, you should observe detailed error message similar to the following example:

Failed to create workspace vsphereserver1-mydomain\\\\user1-192.168.61.135: exit status 1\\n\\nThe workspace name \\\"vsphereserver1-mydomain\\\\\\\\user1-192.168.61.135\\\" is not allowed. The name must contain only URL safe\\ncharacters, and no path separators.
