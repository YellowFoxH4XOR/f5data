Description

After upgrade, rule for Source Address Translation in NAT policy changed from None to Automap.

Environment

  • After upgrade, both GUI and output from tmsh list Automap
  • Before upgrade, GUI showed it as None while tmsh listed Automap.
  • bigip_base.conf shows Automap

Cause

A bug ID has been opened; 928653.

At the time this article is published, available information is: "When we change in UI from automap to none then configuration is applied to TMM but change is not applied to config file bigip_base.conf."

Note: This is a new bug ID and being investigated. Information regarding it will soon be published.


Recommended Actions

Impact of procedure: Procedure includes editing bigip_base.conf and loading the configuration. Performing the steps during maintenance window is recommended.
  1. Connect to the BIG-IP via SSH
  2. Using a preferred editor tool, open bigip_base.conf
  3. Search for the rule and change the configuration to None.

    It should then look as below:

                translation {
                    source none
                }
     
  4. Save the bigip_base.conf
  5. Load the configuration using the command: 

    tmsh load sys config
     
  6. The same steps must be performed on the peer device.
Note: Please do not save the configuration from the CLI as the configuration in the bigip_base.conf reverts to Automap.

Additional Information

In the investigation, it was determined, prior the upgrade, at some point NAT policy had NAT automap in source translation. It was changed to None in GUI. The configuration did not update the configuration file due to the bug ID928653.

The issue can be reproduced without the upgrade by loading the configuation ( tmsh load sys config ) and the config change to Automap will be seen.
