Topic

The security policy comprises several important security policy elements specific to the BIG-IP ASM system. Understanding these elements is critical to creating and maintaining the security policy.

The following HTTP POST header illustrates a typical request to the web application that the BIG-IP ASM security policy would process:

POST /main/login.jsp HTTP/1.1
Accept: image/gif, image/x-xbitmap, image/jpeg,
image/pjpeg, application/x-shockwave-flash,
application/vnd.ms-excel, */*
Accept-Language: en-us
Accept-Encoding: gzip, deflate
User-Agent: Mozilla/4.0 (compatible; MSIE 6.0; Windows NT 5.1; SV1)
Host: www.example.com:80
Connection: Keep-Alive
Cookie: pref=style1; window=nav2

user=mike&pass=1234

Key elements in the HTTP request, and how these elements are defined in the security policy are as follows:

  • File Types

    The file type or file extension contained in the request. File types are case sensitive and can be allowed or disallowed in the policy. The file type in the example request is as follows:

    .jsp

  • URLs

    The URL defines the path to the file that you are protecting, including the file and file extension. The URL in the example request is as follows:

    /main/login.jsp

  • Flows

    The application flow is the logical access path leading from one URL to another URL within the web application. A flow is comprised of the start point, request method, protocol, and requested object. The flow in the example request is as follows:

    Entry Point -> POST via HTTP -> /main/login.jsp

  • Parameters

    Parameters are located in the HTTP POST data or query string. The parameters could be associated globally, with the URL, or with the flow. The parameters in the example request are as follows:

    user
    pass

  • Parameter values

    A parameter value is a value for a given parameter. The parameter values in the example request are as follows:

    mike
    1234

  • Methods

    The security policy accepts standard HTTP methods by default. The default allowed methods are GET, HEAD, and POST. The method in the example request is a POST.

  • Headers

    Headers allow you to classify traffic to specify one or more headers whose associated requests you want to direct through the security policy. The cookie header is described below:

    Cookies

    Cookies are located in the HTTP Cookie header. Cookies are listed in the following format:

    <cookie name>: <cookie value>; <cookie name>: <cookie value>

    The cookies in the example request are as follows:

    pref
    window

    Cookie values

    Cookie values define the value for the cookies in a request. The Cookie values in the example request are as follows:

    style1
    nav2
