Topic

The files that are included in a user configuration set (UCS) archive are configured by the keys in the /usr/libdata/configsync/cs.dat data file.

The /usr/libdata/configsync/cs.dat data file contains three types of keys to control the files that are included in a UCS archive:

  • Keys that specify what files to include
  • Keys that specify what directories to include
  • Keys that specify what files to exclude

The keys appear similar to the following example:

save.1250.file = /var/tmp/ts_db.save_dir_location.cstmp
save.1251.file = /var/tmp/ts_db.save_dir_*.cstmp/*
save.1251.save_post = (rm -rf /var/tmp/ts_db.*.cstmp)

The first column contains a unique key name, which is a dot-delimited value consisting of three fields. The first field in the key name indicates the type of operation to which the key applies. The value of save indicates that the key applies to archive operations. The second field contains an index number which controls the order in which the specified operations are performed. The index number is typically unique to a given file or fileset. The third field contains a string indicating the action to be taken, which for UCS operations may be one of the following:

save.<index>.file      The file(s) will be saved in UCS file.
save.<index>.save_pre  The action before saving file(s).
save.<index>.save_post The action after saving file(s).
save.<index>.ignore    The file(s) will not be saved in UCS file.
save.<index>.dir       The files under the directory will be saved in UCS file.
save.<index>.dir_opt   The files under the directory are optional to be saved in UCS file.

Multiple keys may use the same index to specify actions against the same file or fileset, but each three-field key name must be unique. For example, in the output above, two entries exist for the index value 1251, which refers to the *.cstmp fileset. The save.1251.file key specifies that the fileset indicated are saved in UCS archive files. The save.1251.save_post key specifies that the fileset indicated are deleted from the disk after the UCS archive file has been created. The keys are unique since they vary on the action field.

Important: If the BIG-IP system is upgraded to a new version, the cs.dat file is replaced and any customizations to this file will be lost. F5 does not recommend adding the cs.dat file into a UCS archive because you may encounter errors when saving or installing a UCS archive after you upgrade.

Important: If this procedure is being used on a multi-blade BIG-IP VIPRION system, the same operation must be performed on each blade (and reapplied to any new or replacement blades that are inserted into the system). 

 

Viewing the files and directories that are configured to be included in a UCS archive

You can view what is configured to be included in or excluded from a UCS archive.

  • To view the files that are configured to be included in a UCS archive, type the following command:

    grep 'save\.[0-9]\+\.file' /usr/libdata/configsync/cs.dat

  • To view the directories that are configured to be included in a UCS archive, type the following command:

    grep 'save\.[0-9]\+\.dir' /usr/libdata/configsync/cs.dat

  • To view the files that are configured to be excluded from a UCS archive, type the following command:

    grep 'save\.[0-9]\+\.ignore' /usr/libdata/configsync/cs.dat

The cs.dat file also contains keys that specify other tasks to be performed within the context of backing up and restoring a UCS archive.

  • To view all of the keys in the cs.dat file which are relevant to archive operations, type the following command:

    grep 'save\.[0-9]\+\.' /usr/libdata/configsync/cs.dat

Adding a UCS archive entry

  1. Log in to the BIG-IP command line.
  2. To back up the existing cs.dat file, type the following command:

    cp /usr/libdata/configsync/cs.dat /usr/libdata/configsync/cs.dat.SOL4422

  3. Using a text editor, edit the /usr/libdata/configsync/cs.dat file.

    Note: The /usr file system is mounted in read only mode. In order to edit the /usr/libdata/configsync/cs.dat file, you must first remount the /usr file system in read-write mode. For more information, refer to K11302: The /usr file system is mounted in read-only mode.

  4. At the end of the file, create a new section for custom entries by adding the following new line:

    # custom UCS keys

  5. Under this section heading, add a new key representing the new file to be included in UCS archive files using the following syntax:

    save.<number>.file = <filename>

    Replace <number> with a higher number than the last key listed in the preceding section, and replace <filename> with the full path to the file you want to include.

    For example, if you want to include the /var/tmp/myfile.txt file and the highest existing key number in the database is 8990, you would add the following key:

    save.9000.file = /var/tmp/myfile.txt

  6. Save the file and exit the editor.

    The file you specified is now included each time a UCS archive is created.

Removing a UCS archive entry

Important: F5 recommends that you only delete keys for files that you have created. If you delete a default key, it results in an incomplete backup.

  1. Log in to the BIG-IP command line.
  2. To back up the existing cs.dat file, type the following command:

    cp /usr/libdata/configsync/cs.dat /usr/libdata/configsync/cs.dat.SOL4422

  3. Using a text editor, edit the /usr/libdata/configsync/cs.dat file.

    Note: The /usr file system is mounted in read only mode. In order to edit the /usr/libdata/configsync/cs.dat file, you must first remount the /usr file system in read-write mode. For more information, refer to K11302: The /usr file system is mounted in read only mode.

  4. Locate the line that matches the key that you want to delete.
  5. Delete the line.
  6. Save the file and exit the editor.

Modifying a UCS archive entry

Important: F5 recommends that you only modify keys for files that you have created. If you modify a default key, it results in an incomplete backup.

  1. Log in to the BIG-IP command line
  2. To back up the existing cs.dat file, type the following command:

    cp /usr/libdata/configsync/cs.dat /usr/libdata/configsync/cs.dat.SOL4422

  3. Using a text editor, edit the /usr/libdata/configsync/cs.dat file.

    Note: The /usr file system is mounted in read only mode. In order to edit the /usr/libdata/configsync/cs.dat file, you must first remount the /usr file system in read-write mode. For more information, refer to K11302: The /usr file system is mounted in read-only mode.

  4. Locate the line that matches the key that you want to modify.
  5. Edit the value of the key, which begins after the equal sign (=).
  6. Save the file and exit the editor.
