Description

When creating a SSH public key for a specific user via K13454 the key is being created with the 'root' user instead of the specified user, see:
  
[test@my-bigip:Active:Standalone] ~ # ssh-keygen
Generating public/private rsa key pair.
Enter file in which to save the key (/root/.ssh/id_rsa): /home/test/mykyes
Enter passphrase (empty for no passphrase):
Enter same passphrase again:
Your identification has been saved in /home/test/mykyes.
Your public key has been saved in /home/test/mykyes.pub.
The key fingerprint is:
SHA256:1jgd... root@my.hostname.com <-----[!]
 

Environment

  • BIGIP all versions
  • Public Key

Cause

If you create an admin user the id is 0, that's the root id, this is working as design.

Recommended Actions

You can modify or delete the user@hostname comment from the certificate and set a different comment during creation by using the -C option. E.g:

[pepe@certis-bigiq-cm:Active:Standalone] ~ # ssh-keygen -C pepe@lalala
Generating public/private rsa key pair.
Enter file in which to save the key (/root/.ssh/id_rsa): /home/pepe/.ssh/id_rsa2
Enter passphrase (empty for no passphrase):
Enter same passphrase again:
Your identification has been saved in /home/pepe/.ssh/id_rsa2.
Your public key has been saved in /home/pepe/.ssh/id_rsa2.pub.
The key fingerprint is:
SHA256:PvCJy5WW3yw4uE6jFYQD4o0nU7kaLxVa5IrRFFpa3ic pepe@lalala
The key's randomart image is:
+---[RSA 2048]----+
|. B+.      |
|.X=* .      |
|+==+E o     |
|.+=o =      |
|..=  o S    |
| o .  * +    |
| .  =.X.    |
|   =.=oo.o   |
|  ..=. ...o  |
+----[SHA256]-----+
[pepe@certis-bigiq-cm:Active:Standalone] ~ # cat /home/pepe/.ssh/id_rsa2.pub
ssh-rsa AAAAB3NzaC1yc2EAAAADAQABAAABAQCoWTmHvfn6sMaQ6i9si20Tyq2bl0aRDWGet9j... pepe@lalala


In this way you have the cert/key to have the specified name that you want.

Additional Information

See https://www.man7.org/linux/man-pages/man1/ssh-keygen.1.html for more details:

ssh-keygen will by default write keys in an OpenSSH-specific format.
This format is preferred as it offers better protection for keys at rest as well as allowing storage of key comments within the private key file itself.
The key comment may be useful to help identify the key.
The comment is initialized to “user@host” when the key is created, but can be changed using the -C option.
