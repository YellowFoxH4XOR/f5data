Topic

You should consider using these procedures under the following condition:

  • You want to configure antivirus protection for the BIG-IP ASM system.

Description

You can configure the BIG-IP ASM system to check requests for viruses by configuring the system to connect with an Internet Content Adaptation Protocol (ICAP) server. When you configure antivirus protection, the system connects to an external ICAP server and prompts the server to inspect file uploads and attachments for viruses before releasing the content to the pool member. You can configure the BIG-IP system to perform content inspection on binary data for the following types of data:

Note: The system performs content inspection on binary data only; the BIG-IP ASM attack signature engine protects non-binary data.

  • HTTP file uploads: The system checks content types for multipart file uploads in which no content profile is associated. For example, the requested URL of the multipart post is not associated with XML or JSON profiles.
  • SOAP attachments: You must configure the XML profile to allow and inspect Simple Object Access Protocol (SOAP) attachments
  • SMTP email attachments: The SMTP profile must have the antivirus options selected.

Prerequisites

You must meet the following prerequisite to use these procedures:

  • You have access to the BIG-IP ASM Configuration utility.

Configure the ICAP server

To configure the external ICAP server to which the BIG-IP system will connect, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Security > Options > Application Security > Integrated Services > Anti-Virus Protection.
  3. For Server Host Name/IP Address, enter the ICAP server hostname or IP address.
  4. For Server Port Number, enter the ICAP server port in or leave the default value of 1344.
  5. Select the Guarantee Enforcement check box if you want the system to perform virus checking even if performing checking may slow your web application.
  6. Select Save.
  7. To activate the security policy changes immediately, select Apply Policy.

Configure antivirus blocking settings

You can configure the blocking policy for antivirus protection for each security policy as needed. To do so, perform the following procedure for your BIG-IP version:
Note: For more information on configuring antivirus software detection and blocking refer to the About Antivirus chapter of the BIG-IP Access Policy Manager: Visual Policy Editor Per-Request Policy Item Reference About per-request policy subroutine items guide.
Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Configure antivirus blocking settings (BIG-IP 13.x and later)

  1. Log in to the Configuration utility.
  2. Go to Security > Application Security > Policy Building > Learning and Blocking Settings.
  3. Expand Antivirus (expand Antivirus Protection in versions prior to 14.x) and select either or both of the Alarm and Block check boxes for the Virus Detected violation.
  4. Select Save.
  5. To activate the security policy changes immediately, select Apply Policy.

Configure the internal system variables

You can configure the ICAP URI and the virus header name settings on the System Variables page in the Configuration utility. To do so, perform the following procedure.

Antivirus vendorValue of virus_header_name
McAfee VirusScan Enterprise    X-Infection-Found, X-Virus-Name
Trend Micro ProductsX-Infection-Found, X-Virus-ID
Symantec Protection EngineX-Violations-Found
Kaspersky Anti-VirusX-Virus-ID

Note: The listed antivirus vendors and vendor specific virus header names are applicable for BIG-IP ASM 11.6.0 and later (If this still fails, verify that the vendor did not change the headers.)

Note: When you configure the headers above in the System Variables page, the BIG-IP will check for the configured headers, and if they exist, will block the request. Hence, make sure to configure ONLY the required headers.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Configure the internal system variables (BIG-IP 13.1.x and later)

  1. Log in to the Configuration utility.
  2. Go to Security > Options > Application Security > Advanced Configuration > System Variables.
  3. Select the icap_uri parameter name, enter the URI for the ICAP service in the Parameter Value setting, which checks requests for viruses by connecting to ICAP server.
  4. Select the virus_header_name parameter name, enter the header name used by an antivirus program on an ICAP server in the Parameter Value setting. By default, the system supports an ICAP server with McAfee antivirus protection (X-Virus-Name, X-Infection-Found). If you are using different ICAP servers, change this to the appropriate header value, or specify multiple header values separated by commas.
  5. Select Update.
  6. Restart the asm process by entering the following command:

    tmsh restart /sys service asm

    To restart multi-slot devices, use the following command:

    clsh tmsh restart /sys service asm

    Important: This step causes a brief traffic disruption.

Configure the internal system variables (BIG-IP 11.x - 13.0.x)

  1. Log in to the Configuration utility.
  2. Go to Security > Options > Application Security > Advanced Configuration > System Variables.
  3. For the icap_uri setting, enter the URI for the ICAP service, which checks requests for viruses by connecting to ICAP server.
  4. For the virus_header_name setting, enter the header name used by an antivirus program on an ICAP server. By default, the system supports an ICAP server with McAfee antivirus protection (X-Virus-Name, X-Infection-Found). If you are using different ICAP servers, change this to the appropriate header value, or specify multiple header values separated by commas.
  5. Select Save.
  6. Restart the asm process by entering the following command:

    tmsh restart /sys service asm

    To restart multi-slot devices, use the following command:

    clsh tmsh restart /sys service asm

    Important: This step causes a brief traffic disruption.

Configure antivirus scanning for HTTP file uploads and SOAP attachments (BIG-IP 16.1.0 and later)

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Security > Application Security > Security Policies > Policies List.
  3. Select the name of the security policy
  4. Select General Settings.
  5. Under Integrated Services select  Scan HTTP Uploads.
  6. To perform antivirus scanning on SOAP attachments, select the relevant XML profiles from the Scan SOAP Attachments on the following XML Profiles list.
  7. Select Save.
  8. To activate the security policy changes immediately, select Apply Policy.

Configure antivirus scanning for HTTP file uploads and SOAP attachments (BIG-IP 11.x - 16.0.x)

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Security > Application Security > Integrated Services > Anti-Virus Protection.
  3. Select the Inspect file uploads within HTTP requests check box.
  4. To perform antivirus scanning on SOAP attachments, move the relevant XML profiles from the Antivirus Protection Disabled list to the Antivirus Protection Enabled list.

    Note: You can also create an XML profile by selecting Create.

  5. Select Save.
  6. To activate the security policy changes immediately, select Apply Policy.

Configure antivirus scanning for email attachments

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Security > Options > Application Security > Advanced Configuration > System Variables.
  3. Under System Variables, make sure that the values for the icap_uri (URI for the ICAP service), and virus_header_name (header name used) parameters correspond to your ICAP server's settings.
  4. If you change the values, select Save.
  5. Go to Security > Protocol Security > Security Profiles > SMTP.
  6. Select Create to create a new SMTP security profile.
  7. Define the appropriate settings for the profile.
  8. For the Virus Detection setting, select the Alarm or Block check boxes as required.
  9. Select Create to create the new profile.
  10. To activate the security policy changes immediately, select Apply Policy.

Configure antivirus scanning for base64-encoded XML elements

  1. Log in to the Configuration utility.
  2. Go to Security > Application Security > Content Profiles > XML Profiles.
  3. Select the appropriate XML profile.
  4. Select the Value Masking tab (select the Sensitive Data Configuration tab in versions prior to 14.x).
  5. In the Name list, select Element and enter the element name used to store the base64 encoded file, and select Add.
  6. Select Update.
  7. To configure antivirus scanning for the XML element, refer to one of the following procedures:
    • Configuring antivirus scanning for HTTP file uploads and SOAP attachments (16.1.0 and later)
    • Configuring antivirus scanning for HTTP file uploads and SOAP attachments (11.x - 16.0.x)
  8. Select Save.
  9. To activate the security policy changes immediately, select Apply Policy.

Note: Enabling element masking in the XML Profile is a required configuration step to forward the XML payload to the ICAP server. This does not imply the masked values will be decoded prior to transmission; instead, the entire payload, including masked elements, is sent as-is.

View reports for antivirus detection

To view reports of virus transactions detected by the ASM system, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Security > Reporting > Application > Charts.
  3. Select Top Viruses Detected in the charts list.
  4. The system displays the detected viruses over time.
