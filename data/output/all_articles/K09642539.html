Known Issue

The bigd process does not rotate DNS servers when the system does not receive the Internet Control Message Protocol (ICMP) packet.

This issue occurs when all of the following conditions are met:

  • Multiple DNS servers are configured for fully-qualified domain name (FQDN) resolution for bigd monitors.
  • The first DNS server becomes unavailable.
  • ICMP messages are not received by the bigd process.

Impact

The bigd process continues to send FQDN node resolutions to the (now-unavailable) DNS server, which fails to resolve (that is, the bigd process does not rotate to the next configured DNS server).  Existing resolved FQDN nodes and all associated monitors continue to function normally.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • When the first DNS server becomes unavailable for FQDN node resolution, and no ICMP message is received, the bigd process does not rotate to the next DNS server. In the common case where a DNS server becomes unavailable, an ICMP message notifies the bigd process that the server is unavailable, and the bigd process rotates to the next available DNS server. However, if network configuration fails to route this ICMP message back to the bigd process, the system acts as though the DNS server remains in an available state, and all subsequent DNS resolve operations fail, as the DNS server is unavailable.

Resolution

Status

F5 Product Development has assigned ID 659596 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies to (see versions) box, located in the upper-right corner of this article. Workaround

Ensure that the network routes the ICMP messages to the bigd process when the DNS server becomes unavailable.
