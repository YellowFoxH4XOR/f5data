Known Issue

The BIG-IP system fails to ensure that the protocol profile assigned to a virtual server includes both client-side and server-side contexts.

For example, the following Traffic Management Shell (tmsh) command syntax creates a virtual server named vs_foo that includes a client-side context, but no server-side context for the tcp-lan-optimized protocol profile:

tmsh create /ltm virtual vs_foo ip-protocol tcp destination 1.1.1.3:8080 profiles replace-all-with { tcp-lan-optimized { context clientside } http }

Impact

Affected virtual servers fail to pass traffic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The virtual server fails to pass traffic, and may respond to client requests with a TCP RST packet.
  • The tmsh list /ltm virtual command output displays either a client-side or server-side context for the protocol profile.

    For example, the following output shows a virtual server with a client-side context only, and no server-side context for the protocol profile:

    ltm virtual vs_foo {
    destination 1.1.1.3:8080
    ip-protocol tcp
    mask 255.255.255.255
    profiles {
    http { }
    tcp-lan-optimized {
    context clientside
    }
    }
    source 0.0.0.0/0
    vs-index 12
    }
  • The BIG-IP system logs an error message to the /var/log/ltm file that appears similar to the following example:

    err tmm1[17712]: 01010008:3: Proxy initialization failed for /Common/vs_foo
  • The BIG-IP system logs an error message to the /var/log/tmm file that appears similar to the following example:

    /var/log/tmm: notice hudfilter_init: 'HTTP' is not a bottom-level filter.
  • The virtual address does not respond to Address Resolution Protocol (ARP) requests if there are no other functional virtual servers on the same virtual address.

Workaround

To work around this issue, you can modify the virtual server to include the missing protocol profile context. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh
  2. Display the affected virtual server configuration and confirm the missing protocol profile context by using the following command syntax:

    list /ltm virtual <virtual_server_name>

    For example, the following tmsh command displays a virtual server named vs_foo that is missing the protocol profile server-side context:

    list /ltm virtual vs_foo

    ltm virtual vs_foo {
    destination 1.1.1.3:8080
    ip-protocol tcp
    mask 255.255.255.255
    profiles {
    http { }
    tcp-lan-optimized {
    context clientside
    }
    }
    source 0.0.0.0/0
    vs-index 12
    }
  3. Modify the virtual server to include the missing protocol profile context by using the following command syntax:

    modify /ltm virtual <virtual_server_name> profiles modify { <protocol_profile> { context all } }

    For example, the following tmsh command modifies the virtual server named vs_foo to include the missing tcp-lan-optimized protocol profile context:

    modify /ltm virtual vs_foo profiles modify { tcp-lan-optimized { context all } }
  4. Save the configuration by typing the following command:

    save /sys config
