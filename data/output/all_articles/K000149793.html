Description

Nginx allows to share the data in shared memory zones between nginx nodes in the cluster and keep it almost runtime (updated with zone sync interval). Currently the functionality works for: HTTP sticky sessions (sticky learn), information about excessive HTTP requests (limit_req_zone), and key-value pairs (keyval_zone) both in http and stream.

Error: 

[error] 1111#1111: *2222 connection timed out (110: Connection timed out) while connecting to node, node: <nginx_node_IP>


Consequences: nginx shared zones configured via "sync" parameter are not synchronized between nginx zones and thus the values stored there can not be used in all nodes 

Environment

Nginx configuration for cluster wit 3 nginx nodes:

stream {
      
   resolver DNS_IP1 DNS_IP2 DNS_IP3  ipv6=off valid=360s;
   server {
            
      listen 8081;
            
      #…;
            
      zone_sync_server www.nginxcluster.com:8081 resolve;

   }
}

 

stream {
      
   resolver DNS_IP1 DNS_IP2 DNS_IP3  ipv6=off valid=360s;
   server {
            
      listen 8081;
            
      #…;
            
      zone_sync_server <node1_ip>:8081;
      zone_sync_server <node2_ip>:8081;
      zone_sync_server <node3_ip>:8081;

   }
}

Cause

  1. Issues with DNS records that nginx receives while performing the DNS requests, for the configuration with the cluster defined by general domain name "www.nginxcluster.com"

  2. The network communication between nodes is blocked on FW/network level

 

Recommended Actions

  1. For the cluster configured with external DNS resolving, the following command executed on nginx nodes, will help to understand what nginx will use as a node IPs
    - host www.nginxcluster.com <DNS_IP1>
- host www.nginxcluster.com <DNS_IP2>
- host www.nginxcluster.com <DNS_IP3>

    All DNS servers should provide the same 3 nginx IP's in one query.  It allows each nginx node in cluster to sync the records in the zones with all other instances at the same time.

  2. "nc" or "telnet" command outputs will display if nginx nodes are able to connect each other, for example the following command displays the reason of "Connection timed out) while connecting to node" error:    
nc -v <node1_ip> 8081
