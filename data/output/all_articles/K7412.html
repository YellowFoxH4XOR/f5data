Known Issue

This is a result of a known issue. The output from the bigpipe conn show all command does not correctly display the idle time for PVA-assisted connections.

PVA-assisted connections, which are connections that use the FastL4 profile, appear to exceed the idle timeout value in the bigpipe conn show all output. The PVA determines if a PVA-assisted connection should be handled by the PVA or by TMM. If the connection is handled by the PVA, TMM retains an entry in connection table, and the PVA periodically updates the connection to keep it in the TMM connection table. When the connection is torn down by the PVA, the PVA notifies TMM, and TMM removes the connection table entry.

Note: Additionally, in BIG-IP versions prior to 9.4, the BIG-IP system may incorrectly display the idle timeout value as eight times the FastL4 idle timeout value. For more information, refer to K11186: BIG-IP systems may display the wrong idle timeout value for virtual servers using PVA-enabled FastL4 profiles.

F5 Product Development tracked this issue as CR78006, and it was fixed in BIG-IP 9.4.2. For information about upgrading, refer to the BIG-IP release notes.
