K000148357: After upgrade the configuration is not loading. Error message: "The key exchange is already in use by SSH Security Configuration"

Type
Support Solution
Published
2024-11-08
Updated
2024-11-20
Applies to
  • BIG-IP
  • BIG-IP APM: 17.1.1, 17.1.0, 16.1.5, 16.1.4
Source
https://my.f5.com/manage/s/article/K000148357

Description

You performed upgrade and can't load configuration on your BIG-IP system. After performing "tmsh load sys config" you see below message:

01b70088:3: The key exchange (%Cipher_name) is already in use by SSH Security Configuration (/%Location).
Unexpected Error: Loading configuration process failed. 

Environment

  • APM provisioned
  • Software upgrade to BIG-IP 16.1.4 or 17.1.0 later
  • Key Exchange Methods configuration parameter in APM Ephemeral Authentication using LDAP/LDAPS Proxy with WebSSH includes Diffie-Hellman key method

Cause

All Diffie-Hellman key method is deprecated in BIG-IP 16.1.4 and 17.1.0 later.
This change is made by a fix of CVE-2002-20001 & CVE-2022-40735.

Deprecated key method is following.

  diffie-hellman-group-exchange-sha1
  diffie-hellman-group-exchange-sha256
  diffie-hellman-group1-sha1
  diffie-hellman-group14-sha1

After upgraded to BIG-IP 16.1.4 and 17.1.0 later, All Diffie-Hellman key method is replaced with ecdh-sha2-nistp256.

If multiple Diffie-Hellman key method is configured, or 

a Diffie-Hellman key method with ecdh-sha2-nistp256 key method is configured together,

The configuration cannot load because BIG-IP tries to use the same cipher name “%Cipher_name” twice. This is due to deprecated ciphers that have been changed to the same new ones in a later version.

Example:

diffie-hellman-group-exchange-sha256 not supported. Replacing with default "ECDH_SHA2_NISTP25
diffie-hellman-group14-sha1 not supported. Replacing with default "ECDH_SHA2_NISTP256"
01b70088:3: The key exchange (ecdh-sha2-nistp256) is already in use by SSH Security Configuran (/Common/custom_ssh_config).
Unexpected Error: Loading configuration process failed.

Recommended Actions

  1. Boot to previous (old) version.
  2. Remove deprecated Diffie-Hellman key method - one or more, depends on the error, always keep at least one to make sure it will be changed to a new one after the upgrade. If there is already ecdh-sha2-nistp256 is defined, Remove all Diffie-Hellman key method.
  3. Upgrade your device.
  4. Perform following command:
tmsh load sys config verify

       5. If you didn't observe any issues, execute:

tmsh load sys config
