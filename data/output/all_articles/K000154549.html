K000154549: After an upgrade, secondaries and DNSSEC SOA serial number are out of sync.

Type
Support Solution
Published
2025-09-16
Updated
2025-09-16
Applies to
  • BIG-IP
  • BIG-IP DNS: 17.5.X, 17.5.1, 17.5.0
Source
https://my.f5.com/manage/s/article/K000154549

Description

After upgrading BIG-IP DNS to version 17.5.1, DNSSEC-enabled zones may serve empty data with an unexpectedly high SOA serial number, causing secondary DNS servers to receive empty zones and fail to update correctly after rollback to version 17.1.2.1. Symptoms include empty zone transfers, mismatched SOA serial numbers between primary and secondary servers, and persistent SERVFAIL or empty responses from secondaries. The issue is specific to environments using DNSSEC with zone transfers. Logs such as the following may appear:

err zxfrd[4867]: 0153102a:3: Failed connect callback to 127.0.0.1 for transfer of zone <zone>.
err zxfrd[4867]: 01531018:3: Failed to transfer zone <zone> from 127.0.0.1, will attempt IXFR (Refresh).

Environment

  • BIG-IP DNS
  • Software versions: upgrade from 17.1.2.1 to 17.5.1
  • DNSSEC-enabled zones with SOA serial synchronization to secondary servers
  • Configuration objects: ltm dns dnssec zone, xfr-soa-serial, xfr-primary-soa-serial
  • ZoneRunner and DNS Express modules provisioned
  • Manual edits to configuration files required for recovery

Cause

After upgrade, the BIG-IP DNSSEC zone's SOA serial number (xfr-soa-serial) became desynchronized from secondary servers due to internal handling of xfr-soa-serial, resulting in empty zone transfers and secondaries failing to update after rollback.

Recommended Actions

  1. Compare SOA serial numbers between BIG-IP DNS and secondary servers to identify affected zones.
  2. Manually update the xfr-soa-serial value for each affected zone in the configuration file to match the expected serial number.
  3. Reload the GTM configuration using the command:
  4. tmsh load sys config gtm-only
  5. Verify that the SOA serial number is synchronized and that secondary servers receive correct zone data.
  6. Create backups before making any changes to configuration files.

If there is a DNSX zone which is dynamically signed by DNSSEC and there are DNS transfer clients configured, the BIG-IP creates its own SOA serial number. The BIG-IP will use the xfr-soa-serial serial number in the SOA response.

It cannot be modified directly:

# tmsh modify ltm dns dnssec <zone> xfr-soa-serial <newSerial>
Syntax Error: "xfr-soa-serial" is a read-only property

However, it should be possible to modify bigip_gtm.conf and update 'xfr-soa-serial' for all zones. Then the gtm config can be loaded with:

# tmsh load sys config gtm-only

 At this point SOA will contain the new serial number which will increment by one for every zone change including for a new DNSSEC key generation. 

Additional Information

  • This issue is specific to DNSSEC-enabled zones and does not affect standard zone transfers.
  • Ensure all devices participating in the IQuery mesh are upgraded together to avoid further synchronization issues.
