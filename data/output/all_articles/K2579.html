Standard SNATs

Previous releases of the BIG-IP system included only one type of SNAT, known as a standard SNAT. A standard SNAT has three main characteristics:

  • Selection of a translation address is always based on a specific piece of packet data — the original client IP address.
  • The BIG-IP system can select from a limited number of translation addresses to map to an original client IP address. The BIG-IP system can use either a translation address that you specify, or, if the SNAT automap feature is enabled, a set of self IP addresses.

    For example:

    snat map <originating_IP_addr> to <snat_translation_addr>

    b snat map <originating_IP_addr> to auto

  • Self IP addresses, which are used as translation addresses for SNAT automapping, cannot be virtual IP addresses.

All three of the above characteristics limit your ability to configure SNATs. The new SNAT types offered with BIG-IP version 4.5 PTF-04, selective SNATs, and intelligent SNATs (iSNATs), remove these limitations.

Selective and Intelligent SNATs

In BIG-IP version 4.5 PTF-04, you can use the iSNAT feature, which offers two new kinds of SNATs: selective SNATs and intelligent SNATs.

Overview

Using the standard SNAT feature available in previous releases of the BIG-IP system, you could only map an original client IP address to an individual translation address (or in the case of the SNAT automap feature, to a set of self IP addresses).

With the advent of selective and iSNATs, however, you can now map an original client IP address to an entire pool of translation addresses. This pool of translation addresses is known as a SNAT pool. Instead of mapping one or more originating addresses to a specific translation address, you map the originating address or addresses to a SNAT pool. The BIG-IP system then chooses a translation address from the SNAT pool.

For example, the standard method for creating a SNAT appears similar to the following:

b snat map <originating_IP_address> to <snat_translation_address>

Instead of using the standard method for creating a SNAT, you can now create a SNAT as follows:

b snat map <originating_IP_address> to snatpool <snat_pool>

There are two types of SNATs that make use of SNAT pools — selective SNATs and intelligent SNATs (iSNATS). A selective SNAT is similar to a standard SNAT because it causes the BIG-IP system to select a translation address to map to an original client IP address based on the original client IP address; however, a selective SNAT maps an original client IP address to a SNAT pool, unlike a standard SNAT that maps an original client IP address to an individual translation address.

An intelligent SNAT, or iSNAT, is a type of SNAT that causes the BIG-IP system to select a translation address to map to an original client IP address based on any piece of packet data that you specify. This piece of data can be an original client IP address, but this is not required. Similar to a selective SNAT, an iSNAT maps an original client IP address to a SNAT pool, rather than to an individual translation address.

Using selective SNATs or iSNATs instead of standard SNATs has distinct advantages:

  • iSNATs give the BIG-IP system the ability to use packet data other than original client IP addresses as a basis for selecting translation addresses.
  • The translation addresses are not self IP addresses, and therefore can be virtual IP addresses.
  • Additional attributes are available for translation addresses.
  • Statistics for intelligent and selective SNATs show all translation addresses. This is contrary to statistics for standard automapped SNATs, which do not show the translation addresses because they are self IP addresses.
  • The translation addresses support connection limits, whereas self IP addresses do not.

The BIG-IP system uses an algorithm to choose a translation IP address from a SNAT pool that is similar to the algorithm used in standard SNAT automapping. The BIG-IP chooses a translation address from a network or a VLAN that matches the next hop network or outgoing VLAN. If more than one translation address in the SNAT pool matches the next hop network or outgoing VLAN, the BIG-IP selects from the matching translation addresses at random.

Note: The Configuration utility does not support the ability to create a selective SNAT or iSNAT.

Understanding selective SNATs

Similar to a standard SNAT that has automapping enabled, a selective SNAT causes the BIG-IP system to base its selection of a translation address on two specific criteria:

  • The original client IP address being translated.
  • The address of the next hop network or outgoing VLAN.

Also, similar to a standard automapped SNAT, a selective SNAT allows the BIG-IP system to select a translation address from multiple translation addresses. Unlike a standard automapped SNAT, the translation addresses for selective SNATs are not self IP addresses. Therefore, a selective SNAT is necessary when you not only want the BIG-IP system to be able to choose from multiple translation addresses, but also want those translation addresses to be virtual IP addresses.

You create a selective SNAT by using the same bigpipe snat map command that you use for standard SNATs; however, instead of supplying a specific translation address or the auto option, you supply a new <snatpool_name> argument.

To configure a selective SNAT, you must:

  • Create a SNAT pool that contains IP addresses as its members. When you create this SNAT pool, the BIG-IP system automatically designates those IP addresses as translation addresses and assigns a set of default attributes to them. To create a SNAT pool, use the bigpipe snatpool command or edit the bigip.conf file directly.
  • Map one or more original client IP addresses to the SNAT pool, using the bigpipe snat map command or editing the bigip.conf file directly.

For detailed information about how to perform these tasks, refer to Creating selective SNATs and intelligent SNATs.

Understanding intelligent SNATs (iSNATs)

Unlike a selective SNAT, an iSNAT allows the BIG-IP system to base its selection of a translation address on any piece of packet data that you specify. This piece of data could be the original client IP address, or it could be another piece of data in the packet, such as a server port or an HTTP cookie.

Some of the reasons that you would implement an iSNAT are as follows:

  • The BIG-IP system can select a translation address on criteria other than the original client IP address, such as a destination server port.
  • The BIG-IP system has multiple translation addresses to select from, due to the use of a SNAT pool.
  • The translation addresses in the SNAT pool can be virtual IP addresses.

To configure an iSNAT, create an iRule specifying the following information:

  • The type of packet data the BIG-IP system will use as a basis for selecting a translation address, such as the server port.
  • The SNAT pools the BIG-IP will use to select a translation address.

The following example shows an iRule that uses the server_port variable to specify the type of packet data to be used as a basis for selecting translation addresses, and the use snatpool statement to specify the SNAT pools from which the BIG-IP is to select the translation addresses:

rule my_rule {
if (server_port equals 80) {
use snatpool http_trans_addr
}
else {
use snatpool smtp_trans_addr
}
use pool out_pool
}

Similar to the use pool statement, the use snatpool statement directs the virtual server to a specific SNAT pool for selection of a translation address. In this example, the virtual server is directed to use one of two different SNAT pools:http_trans_addr or smtp_trans_addr.

To configure an iSNAT, you must:

  • Create a SNAT pool that contains IP addresses as its members. When you create this SNAT pool, the BIG-IP system automatically designates those IP addresses as translation addresses and assigns a set of default attributes to them. To create a SNAT pool, you can use the bigpipe snatpool command or edit the bigip.conf file directly.
  • Create an iRule that selects a SNAT pool and a load balancing pool using either the bigpipe rule command or editing the bigip.conf file directly.
  • Create a virtual server that references the iRule.

Creating selective SNATs and intelligent SNATs

To create a selective SNAT or an iSNAT, you must first create one or more SNAT pools. Then, depending on whether you are implementing a selective SNAT or an iSNAT, you either map your original client IP addresses to the newly-created SNAT pool (selective SNAT), or you create a rule that references the SNAT pool and the virtual server (iSNAT).

Creating a SNAT pool

The first step in configuring a selective SNAT or an iSNAT is to create the SNAT pool. You create a SNAT pool by specifying the IP addresses that you want to use as translation addresses in the SNAT pool. Once you have created the SNAT pool, you can optionally modify the attributes that the BIG-IP system automatically assigns to each translation address in the SNAT pool.

With selective SNATs and iSNATs, you do not need to designate IP addresses as translation addresses before you create the SNAT pool. You simply create the SNAT pool and the BIG-IP system behaves as follows:

 

  • The BIG-IP system automatically designates IP addresses, which were not previously designated as translation addresses, as translation addresses.
  • For any IP addresses previously designated as translation addresses, the BIG-IP recognizes those addresses as being translation addresses.

To create a SNAT pool:

Use the following bigpipe snatpool command syntax to create a SNAT pool and define its members.

b snatpool <snatpool_name> { member <snat_translation_address> member <snat_translation_address> <...> }

After you have run the bigpipe snatpool command, the syntax of entries will appear similar to the following in the bigip.conf file:

snatpool snatpool_name {
member snat_translation_address
member snat_translation_address
member snat_translation_address
}

To modify SNAT translation attributes:

Every translation address has attributes with which it is associated, such as a VLAN on which the translation address is enabled or disabled, and a unit ID to which the translation address applies.

When the BIG-IP system designates IP addresses, which were not previously designated as a translation address, as a translation address, it automatically assigns these attributes with default values.You can use the default values or change them to suit your needs.

SNAT translation addresses have three attributes, known as SNAT global attributes, in addition to the attributes that you can modify for each individual translation address. If you have not previously configured these global attributes, the BIG-IP system assigns default values to these attributes when it designates the IP addresses as translation addresses. Unlike the non-global attributes, the global attributes allow you to define the default value.

For non-global attributes, use the bigpipe snat <snat_translation_address> [attributes] command.

After you have created one or more SNAT pools, you can create either a selective SNAT or an iSNAT. Use one of the following two sections to create either a selective SNAT or an iSNAT.

Creating a selective SNAT

After you have created a SNAT pool, you can create either a selective SNAT or an iSNAT. Note that for information on creating a standard SNAT, refer to the BIG-IP Reference Guide.

Creating a selective SNAT is similar to creating a standard SNAT, because you map the original client IP addresses to translation addresses using the bigpipe snat map command; however, instead of specifying a specific translation address or the auto keyword, you specify the name of a SNAT pool. The following example shows how to create a selective SNAT:

b snat map <orig_addr> <...> to snatpool <snatpool_name>

Note: You can modify the original client IP addresses that you mapped to the SNAT pool. You can do this by using the same bigpipe command syntax as above, but specifying different original IP addresses with the same SNAT pool name.

Creating an intelligent SNAT (iSNAT)

Instead of using the bigpipe snat map command to map your original client IP addresses to a SNAT pool, you can create an iRule. The if statement in the iRule tells the BIG-IP system to test the value of various elements in the header or content of a client request. Based on the results, the BIG-IP system selects both a SNAT pool and a load balancing pool.

The easiest way to create an iRule for an iSNAT is to edit the bigip.conf file directly. In addition to the if statement, the iRule must also include a use snatpool statement and a use pool statement. For an example of an iRule created for an iSNAT, see Example 2: An intelligent SNAT.

Examples

This section contains two examples showing how you can use selective and intelligent SNATs to provide a business solution.

    Example 1: A selective SNAT

    An example of the selective SNAT feature is an Internet Service Provider (ISP) that needs to provide two customers (customer 1 and customer 2) with two routable IP addresses each, for links to the internet.

    The issue:

    The customers need to use these routable IP addresses as virtual IP addresses for inbound traffic to their own servers, and as translation addresses for outbound traffic from their servers.

    The solution:

    Note: In this example, all translation address attributes use the default values.

    In this case, a selective SNAT provides the solution. To create the selective SNAT, the ISP created the SNAT pools and load balancing pool, just as with the iSNAT. The SNAT pools in this example are customer1_snatpool, customer2_snatpool, and other_snatpool. Again, the BIG-IP system automatically designated the SNAT pool members as translation addresses, as shown in the first six entries of the example.

    Unlike the iSNAT example, instead of writing an iRule that selects the SNAT pools, the ISP simply mapped each original address directly to the appropriate SNAT pool.

    The following example shows a partial bigip.conf file after the ISP has configured a selective SNAT:

    snat translation 199.5.6.10 snat translation 207.8.9.10 
snat translation 199.5.6.20 Translation address definitions
snat translation 207.8.9.20 snat translation 199.5.6.30
snat translation 207.8.9.30
snatpool customer1_snatpool { SNAT pool definition
member 199.5.6.10
member 207.8.9.10
}
snatpool customer2_snatpool { SNAT pool definition
member 199.5.6.20
member 207.8.9.20
}
snatpool other_snatpool { SNAT pool definition
member 199.5.6.30
member 207.8.9.30
}
pool isp_pool { Load balancing pool definition
lb_method rr
member 199.5.6.254:0
member 207.8.9.254:0
}
snat map {
192.1.1.10 192.1.1.11 to snatpool customer1_snatpool
} Mapping of original addresses to SNAT pool
snat map {
192.1.1.20 192.1.1.21 to snatpool customer2_snatpool
} Mapping of original addresses to SNAT pool
snat map default to snatpool other_snatpool Default SNAT mapping to SNAT pool
virtual 0.0.0.0:0 use pool isp_pool Referencing a pool

    Once the selective SNAT is configured as shown in the previous example, a number of actions occur, as in the following process:

    • A request from original client address 192.1.1.30 arrives at the BIG-IP system and matches the wildcard virtual server.
    • The wildcard virtual server selects load balancing pool isp_pool.
    • The request matches the default SNAT and therefore the BIG-IP system selects the SNAT pool other_snatpool.
    • Using the round robin load balancing mode, the BIG-IP system selects 207.8.9.254 from the load balancing pool.
    • The next hop network, 207.8.9.254/24, matches the network of the translation address 207.8.9.30 in the SNAT pool other_snatpool.
    • The BIG-IP translates the original client IP address to address 207.8.9.30, and forwards the packet to 207.8.9.254.

      Example 2: An intelligent SNAT

      A good example of the iSNAT feature is an Internet Service Provider (ISP) that wants to translate the initiating source address to a SNAT address, based on the server port to which the packet is being directed.

      The issue:

      The ISP has two redundant connections to the Internet. In addition, the ISP handles many simultaneous CHAT connections (using port 531), and wants to avoid exhausting the supply of server-side client ports. Finally, the ISP would like to collect statistics separately for CHAT, SMTP, and all other traffic.

      The solution:

      In this case, configuring an iSNAT is the best way to choose the address translation. The following figure shows an example of a partial bigip.conf file that contains entries for an iSNAT.

      As shown in the example, the ISP:

      • Created the SNAT pool chat_snatpool, with four IP addresses, shown by the entry snatpool chat_snatpool and the subsequent IP addresses. Notice that the first four entries in the example show that the BIG-IP system automatically designated these IP addresses as translation addresses during creation of the SNAT pool. These translation addresses are: 199.5.6.10, 199.5.6.11, 207.8.9.10, and 207.8.9.11. These addresses correspond to each of the two next hop networks that are to be used for CHAT traffic.
      • For each translation address, changed the timeout value for TCP connections to 600, using the bigpipe snat timeout tcp <tcp_connection_timeout> command.
      • Created a second SNAT pool, smtp_snatpool, and made two IP addresses members of that SNAT pool. These IP addresses are 199.5.6.20 and 207.8.9.20, where each IP address corresponds to one of the two next hop networks that are to be used for SMTP traffic. Again, the BIG-IP system automatically designated these IP addresses as translation addresses, as shown in the fifth and sixth entries of the example.
      • Created the SNAT pool other_snatpool for all other traffic (that is, non-CHAT and non-SMTP traffic), where each IP address corresponds to one of the two next hop networks that are to be used by all other traffic. Again, the BIG-IP system automatically designated these IP addresses as translation addresses, as shown in the seventh and eighth entries of the example.
      • Created an iRule that selects a SNAT pool based on the server port of the initiating packet, and a node pool (out_pool).

      Once the iSNAT is configured as shown in the previous example, a number of actions occur, as in the following process:

      • An HTTP request arrives at the BIG-IP system and matches the wildcard virtual server.
      • The iRule is evaluated and the BIG-IP system selects the SNAT pool chat_snatpool and the load balancing pool isp_pool.
      • The BIG-IP system selects the next hop network, 199.5.6.254, from the load balancing pool isp_pool, using the round robin load balancing method.
      • The next hop network, 199.5.6.254/24, matches the network of two translation addresses in the SNAT pool chat_snatpool: 199.5.6.10 and 199.5.6.11.
      • From these two translation addresses, the BIG-IP system selects the address 199.5.6.11 at random.
      • The BIG-IP translates the original client IP address to address 199.5.6.11, and forwards the packet to 199.5.6.254.

      Modifying and deleting SNAT pools

      You can modify existing SNAT pools or you can delete them entirely.

      Modifying a SNAT pool

      Modifying a SNAT pool means either adding new members to an existing SNAT pool, replacing the members of a SNAT pool with different members, or deleting members from a SNAT pool. The following shows the syntax for modifying a SNAT pool using the bigpipe snatpool command.

      b snatpool <snatpool_name> [ add | delete ] [{] member
      <snat_translation_address> [ member <snat_translation_address> ... ] [}]

      Thus, to add members to an existing SNAT pool, you would use the following syntax:

      b snatpool <snatpool_name> add { member <snat_translation_address> [
      member <snat_translation_address> ... ] }

      To replace members of an existing SNAT pool, you would use the following syntax:

      b snatpool <snatpool_name> { member <snat_translation_address> [ member
      <snat_translation_address> ... ] }

      To delete members of an existing SNAT pool, you would use the following syntax:

      b snatpool <snatpool_name> delete { member <snat_translation_address> [
      member <snat_translation_address> ... ] }

      Deleting one or more SNAT pools

      You can delete one or more SNAT pools, using the bigpipe snatpool command as follows:

      b snatpool <snatpool_name> <...> delete
