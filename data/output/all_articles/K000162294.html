Description

  • F5OS-A upgrade causes BIG-IP tenants to enter configuration error state.
  • Issue observed immediately post-upgrade.
  • All tenants failed to load configuration post-upgrade, causing service disruption.
  • Manual recovery required for each tenant.

Environment

  • Platforms:  rSeries/VELOS tenants
  • BIG IP Tenants - not upgraded
  • All tenants failed to load configuration post-upgrade, causing service disruption.

Cause

  • F5OS platform upgrade forces text-based config reload
  • New BugID opened: BugID2390853

Recommended Actions

Since the upgrade of the F5OS caused the configuration to reload with this user: f5hubblelcdadmin

We have 2 options to overcome this situation:

Option 1: Remove the username from the bigip_user.conf file:

  1. Verify the user is removed — On each BIG IP tenant, confirm that f5hubblelcdadmin does not appear in /config/bigip_user.conf.
    1. If present, remove the stanza and run tmsh save sys config.
  2. Check both HA peers that f5hubblelcdadmin does not appear in /config/bigip_user.conf. — The user must be removed from all devices in the sync group to prevent it from being re-introduced via config sync.
  3. Upgrade again.

Option 2: Use a UCS file to recover

  1. UCS restore
  2. Force Full Load from the active peer, followed by save sys config

Important note: In case you will use the second option, you will need to remove the user from bigip_user.conf to avoid it will happen again.
