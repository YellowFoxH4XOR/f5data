K53411521: Reboot-Guard service will prevent user from rebooting appliance from the CLI

Type
Support Solution
Published
2022-09-06
Updated
2023-02-21
Applies to
  • VELOS Platforms
  • F5OS
  • rSeries Platforms
Source
https://my.f5.com/manage/s/article/K53411521

Description

When the reboot-guard service is enabled on an F5OS appliance, a user will not be able to reboot the appliance from the CLI.
A reboot attempt will result in logs similar to this:

[root@appliance-1 system]# reboot

Failed to start reboot.target: Transaction contains conflicting jobs 'stop' and 'start' for reboot.target. Probably contradicting requirement dependencies configured.
See system logs and 'systemctl status reboot.target' for details.

If the user is attempting to reboot from the config shell as an admin user, they may see logs similar to this:

r10900_nti_lab_2(config)# system reboot 
The reboot of the system results in data plane and management connectivity to be disrupted. Proceed? [no,yes] yes Error: application communication failure

Environment

  • F5OS Appliance

Cause

This behavior will occur when the reboot-guard service is enabled on the appliance.
 

Recommended Actions

  1. View the status of the reboot guard service with the command: 

           # systemctl status reboot-guard.service

       reboot-guard.service - Reboot Guard
    Loaded: loaded (/usr/lib/systemd/system/reboot-guard.service; enabled; vendor preset: disabled)


       2. To disable the reboot guard service, run the command:

           # systemctl disable --now reboot-guard.service

       Removed symlink /etc/systemd/system/shutdown.target.requires/reboot-guard.service.
