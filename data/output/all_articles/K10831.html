Known Issue

This article applies to BIG-IP WebAccelerator 9.x and 10.x. For information about other versions, refer to the following article:

  • K13153: Crystal Reports file extensions are not included in the Compression Exceptions object type list (11.x)

This is the result of a known issue. The BIG-IP WebAccelerator associates the Compression Exceptions object type with the MIME types used by Crystal Reports, but not with their related file extensions.

The following files are used by Crystal Reports:

FileExtensionMIME type
encapsulated page file.epfapplication/x-epf
encapsulated totaller file.etfapplication/x-etf
report file.rtpapplication/x-rpt
encapsulated message file.emfapplication/x-emf

If responses containing these objects do not include the appropriate MIME type in the Content-Type or Content-Disposition header, the extension cannot be classified, and the object will typically match a policy's Unclassified node. This node is usually set to Always proxy in the Proxying tab.

Note: Beginning in 9.4.5-HF2, a no-cache directive was added to the Cache-Control header as a result of this issue.

F5 Product Development is tracking this issue as ID 223819 (formerly CR132077).

Workaround

You can work around this issue by adding the extensions for the affected objects. To do so, perform one of the following procedures:

Versions 10.2.0 - 10.2.4:

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to WebAccelerator > Policies > Object Types.
  3. Select the Compression Exceptions predefined object type.
  4. Add the epf, etf, rpt, and emf extensions to the Extensions list.
  5. To save the modified configuration, click Save.

Versions 10.0.0 - 10.1.0:

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to WebAccelerator > Policies.

    Note: A separate window will open for WebAccelerator configuration.

  3. Navigate to Object Types.
  4. Select the Compression Exceptions predefined object type.
  5. Add the epf, etf, rpt, and emf extensions to the Extensions list.
  6. To save the modified configuration, click Save.

Version 9.4.x

  1. Log in to the BIG-IP WebAccelerator command line.
  2. Change directories to the /config/wa directory by typing the following command:

    cd /config/wa

  3. Back up the original globalfragment.xml file by typing the following command:

    cp globalfragment.xml globalfragment.xml.sol0831

  4. Open the globalfragment.xml file in a text editor.
  5. Locate the compression-exceptions objType entry.
  6. Edit the ext="" portion of the media objType object.

    For example:

    ext="epf,etf,rpt,emf"

  7. Save the globalfragment.xml file.
  8. Restart the pvac process by typing the following command:

    bigstart restart pvac
