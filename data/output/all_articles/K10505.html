Known Issue

Note: This issue only affects those platforms that include a Packet Velocity ASIC (PVA) chip. For more information about the PVA chip, refer to K4832: Overview of Packet Velocity ASIC (PVA) Acceleration features and sub features.

This is the result of a known issue. If a FastL4 profile with PVA acceleration enabled is associated to a virtual server, and the virtual server receives an ICMP error message in response to a previously sent ICMP echo request, the BIG-IP system may log an error message in the /var/log/ltm file that appears similar to the following example:

local/tmm err tmm[2445]: 012f0001:3: ERR at ../modules/hudproxy/bigproto/pva/pva_frames.c:644:key is not TCP or UDP!

The BIG-IP system assumes that the ICMP echo request that generated the ICMP error was accelerated by the PVA chip. However, the ICMP echo request was not sent by the PVA chip because it can only handle L4 traffic (TCP/UDP). This error message is logged because the ICMP error packet is incorrectly sent towards the PVA chip.

This behavior and error message are benign. ICMP error packets sent to the PVA chip are ultimately discarded.

F5 Product Development tracked this issue as CR127430 and it was fixed in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP LTM release notes.
