Description

  • I want to know the steps needed to configure F5 Distributed Cloud in a SaaS deployment to only terminate TLS in specific F5 Distributed Cloud Regional Edge locations (REs).
  • I would like to only decrypt application services within an specific region.
  • I need a quick how-to on limiting the LB on selected REs
  • How do I control the advertising of applications

Environment

  • F5® Distributed Cloud (SaaS)
  • Dedicated VIP
  • F5 Load Balancer

Answer/Recommended Actions

After you follow this article, the src_site you saw in the logs will be changed and all traffic from clients will be routed to these REs.

To support this configuration, we have a prerequisite of the customer tenant purchasing an additional IP/VIP for their Tenant. This IP is the IP we utilize to route traffic to specific REs as configured for specific regional TLS termination. If a customer wants to have multiple regional topologies for TLS termination, each topology will need its own additional IP/VIP.

Example US-Only REs, AUS-Only REs and EU-Only REs – this would require three additional IP/VIPs, totally four IP/VIPs for the tenant. All REs advertise a prefix or set of prefixes to the internet. Per internet standards, the smallest subnet space or prefix that can be advertised is a /24. 

 

Requirement: additional IP in the tenant.

  1. In the shared namespace, create a virtual site. Type: RE and with the desired REs. Here for instance all the ones in the Iberia region.
     

  2. In the shared namespace, public ip addresses, change the Virtual Site for the selected public IP address. From all-res to the virtual site created in Step 1.
     

  3. In the LB configuration, advertise the public IP address with the modified virtual site.

From a networking perspective the anycast block will still be announced on all the POPs because that’s the way anycast is working. So a customer from the US will still enter the network in the US. We will not limit the IP advertisement with this method.

But from a TCP/IP connection termination point of view regarding the reverse proxies, the termination will be done only on the REs part of the virtual host. This can be easily demonstrated with some curl, you will see that the x-volterra-location will always be the one from the REs part of the virtual site.

So, this is not to do geofencing, geo-fencing is in service policies, this is how you can limit TLS termination in some countries / locations.

Verification:

Be sure to update DNS so that your LB FQDN resolves to your new IP address. Verify that this is updated by running nslookup or dig on your local machine. 

 

Additional Information

  • Since we have restricted our traffic to specific RE's, the Health Checks will be timed out for other RE's and this will be reflected in the Health of the HTTP Load Balancer (Distributed Apps > HTTP Load Balancer)
