Description

vCMP guest fails to load config after host reboot into a new volume or upgrade.

Environment

  • Multislot vCMP guest with seperate cluster management IP addresses

Cause

Volume change on the host will cause the guest to detect hardware change thereby causes the guest to remove cluster config and replace it with backup cluster config which will named as "/shared/db/cluster.conf.<chassis serial>

Recommended Actions

If a UCS backup is available with correct cluster management IP address

  1. Use clsh to stop the secondary blades
    Note: You MUST exclude the primary slot ID from the command option else you will stop your primary instance as well.
    Example with two slots and slot 1 is the primary
    clsh --slot=2 bigstart stop
    Example with three slots and slot 1 is the primary
    clsh --slot=2,3 bigstart stop

  2. Stop clusterd
    bigstart stop clusterd
  3. Extract chassis cluster config file from UCS
    cd /var/tmp/ && tar -zxvf <UCS file> shared/db/cluster.conf shared/db/cluster.conf

  4. Overwrite /shared/db/cluster.conf
    cp /var/tmp/shared/db/cluster.conf /shared/db/cluster.conf && cp /shared/db/cluster.conf /shared/db/cluster.conf.<chassis serial>

  5. Restart clusterd
    bigstart start clusterd

  6. Load config
    tmsh load sys config

  7. Use clsh to restart the slot(s) stopped blades once the primary blade is in a state where the configuration is running properly
    Example with two slots and slot 1 is the primary 
    clsh --slot=2 bigstart start

If UCS backup is not available

  1. Use clsh to stop the secondary blades
    Note: You MUST exclude the primary slot ID from the command option else you will stop your primary instance as well.
    Example with two slots and slot 1 is the primary
    clsh --slot=2 bigstart stop

    Example with three slots and slot 1 is the primary
    clsh --slot=2,3 bigstart stop

  2. Stop clusterd
    bigstart stop clusterd

  3. Edit chassis cluster config file.
    vim /shared/db/cluster.conf.<chassis serial>

  4. Enter the correct cluster management IP and mask 
        cluster default {
            min_up_members="1"
            min_up_members_enable="disable"
            min_up_members_action="failover"
            addr 10.200.68.101/24
            members {
                1
                2
                3
                4
            }

  5. Overwrite /shared/db/cluster.conf
    cp /shared/db/cluster.conf.<chassis serial> /shared/db/cluster.conf

  6. Restart clusterd
    bigstart start clusterd

  7. Load config
    tmsh load sys config

  8. Use clsh to restart the slot(s) stopped blades once the primary blade is in a state where the configuration is running properly
    Example with two slots and slot 1 is the primary 
    clsh --slot=2 bigstart start
