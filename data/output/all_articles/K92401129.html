Known Issue

The Traffic Management Microkernel (TMM) process may leak memory.

This issue occurs when all of the following conditions are met:

  • One of the following network objects has five or more VLANs enabled or disabled:
    • virtual server
    • network address translation (NAT)
    • secure network address translation (SNAT)
    • large-scale NAT (LSN) pool
  • The affected network object has its configuration modified, for example a VLAN is added or removed.

Impact

TMM memory may eventually become exhausted and may result in a system core. The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting. If the system is configured as part of a high-availability pair, the device may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H556585 on the Diagnostics > Identified > Medium screen.
  • TMM memory consumption steadily increases over time. You can monitor TMM memory usage using the tmstat command, or the following Traffic Management Shell (tmsh) command:

    tmsh show sys memory

  • If configured as a high-availability pair, the BIG-IP system fails over to the standby system.
  • The BIG-IP system generates a TMM core file to the /shared/core directory.

Workaround

There is no work around for this issue. However, you can mitigate this issue by minimizing the number of configuration changes to the affected network objects. Additionally, you can reduce the number of Virtual Local Area Networks (VLAN) enabled or disabled on the affected network objects if this is feasible in your application environment.

Impact of workaround: Performing the mitigation should not have a negative impact on your system.
