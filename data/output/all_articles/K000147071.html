Description

This article discusses high-level steps on how to integrate BIG-IP DNS with F5® Distributed Cloud DNS (XC DNS), and it provides information on how to transfer the zone file using the ZoneRunner utility from the Primary BIG-IP device. 

The BIG-IP DNS ZoneRunner utility allows you to manage the local BIND server configuration. Enabling zone transfers on the BIG-IP device allows XC DNS to transfer existing zones from the remote BIG-IP DNS server. 

In order to generate a valid TSIG key, you can follow the explanations provided in this article.

Environment

You should consider using these procedures under the following conditions:

  • You want to transfer DNS zone files using the ZoneRunner utility in BIG-IP DNS.
  • You want to use the F5® Distributed Cloud DNS as a Secondary DNS service to provide additional redundancy and resiliency to your DNS infrastructure.

Answer/Recommended Actions

In BIG-IP DNS, ensure each of the following:

1. Adjust named.conf file to Allow Transfer as follows:

allow-transfer {
     localhost;
     F5-Cloud;
};

2. The <F5-Cloud> is an ACL for the following IP addresses:

acl "F5-Cloud" {
     52.14.213.208/32;
     3.140.118.214/32;
};

3. If there is a zone label < . > - this should be removed:

zone "." {
     type master;
     file "db.external.example.com";
     allow-update {
     127.0.0.1;
     localhost;
};

4. Verify the file named tsig.key in the /var/named/config directory exists, and the configuration syntax is correct: 

key "<key_name>" {
     algorithm <hash_alg>;
     secret "<secret>";
};

5. Include <key_name>, and remember to use the same name as it is case sensitive: 

zone "example.com." {
        type master;
        file "db.external.example.";
        allow-update {
            localhost;
        };
        allow-transfer {
            key <key_name>;
            localhost;
        };
    };

6. Make sure that the zone transfer works correctly, by performing a local AXFR from the BIG-IP, with the below command:

dig +norecurse AXFR @localhost <zone-name> -y <tsig-algorithm>:tsig-key:<secret>
  • <zone-name>: must be replaced by the DNS zone you want to transfer (e.g. example.com)
  • <tsig-algorithm> and <secret> must be replaced by the values you have defined in the above steps.

7. Once you have confirmed that the local AXFR works, you can then proceed to create and deploy the secondary DNS zone()s on F5 Distributed Cloud, by following the explanations in that article. 

Troubleshooting

Here are some additional troubleshooting steps to check whether zone transfer succeed or not:

  1. Log into the BIG-DNS/ GTM and use dig against the GTM/DNS listener IP address to validate what the BIG-IP DNS resolving. Then, dig against the Cloud Services' name servers.
    $ dig @8.8.8.8 example.com
    $ dig @ns1.f5clouddns.com example.com
    $ dig @ns2.f5clouddns.com example.com
  2. Check the /var/log/ltm for any zone transfer errors. 
    $ tailf /var/log/ltm | grep -i "zone example.com"
