Description

When all pool members are down due to being forced offline or a monitor failure the virtual server itself will continue to respond to a telnet request or other 3WHS which can potentially cause problems with external monitoring solutions. 

Environment

Standard virtual server with all pool members marked down either by monitor or manually forced down

Cause

This is by design since the virtual server could still have iRules or other functionality that doesn't rely on pool members.  

Recommended Actions

If there is a requirement that this behavior be changed so that the virtual will not respond to telnet/3WHS when pool members are down it can be changed by:

  1. Go to the virtual server properties
  2. Change Configuration from Basic to Advanced
  3. Find "Immediate Action On Service Down" 
  4. By default it's set to None, change it to either Drop or Reject depending on the behavior you prefer.
