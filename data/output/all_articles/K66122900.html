Description

One BIG-IP is experiencing unexpectedly high CPU compared to other BIG-IP's with the same configuration.

Environment

  • BIG-IP
  • High CPU on one BIG-IP in same sync group
  • Traffic load is equal between devices

Cause

The BIG-IP experiencing high CPU is performing more work and this can be caused by a variety of reasons.

Recommended Actions

Upload the QKViews to iHealth for comparison and review the following:
  1. Look for differences in the Heuristics on the iHealth Diagnostics page such as:
    Log levels are not set to the default value
    Debug logging keys in the BigDB database are not set to their default values
    Out of Memory Killer was invoked. Possible memory issues present
  2. Review the audit logs to see if BIG-IP is being queried by external commands or REST API:
    /var/log/audit
    /var/log/restjavad-audit.0.log

Additional Information

DB variables do not synchronise to the sync group.
Debug logging should only be enabled for troubleshooting purposes.  Disable when not in use.

For further CPU troubleshooting steps see K40472403: Collecting relevant data to troubleshoot high CPU utilization
