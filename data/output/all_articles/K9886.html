Known Issue

This is the result of a known issue. For BIG-IP versions prior to 9.4.0, if you specify the name of a non-existent file as a parameter to the bigpipe load command, the command will load a blank configuration and overwrite the running configuration in memory without warning.

F5 Product Development is tracking this issue as CR62817, and it was fixed in BIG-IP version 9.4.0. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Workaround

To work around this issue, reload the default configuration from disk by typing the bigpipe load command without a filename parameter:

bigpipe load

This command automatically loads the correct files from their default locations, including the /config/bigip.conf file. If you must temporarily load a configuration file other than the default, make sure to specify the full path to a valid configuration file that exists on the BIG-IP filesystem.
