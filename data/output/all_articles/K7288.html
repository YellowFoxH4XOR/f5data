Known Issue

This is the result of a known issue. If you belong to a master group that uses an Intranet webtop, and you use a Landing URI to access the FirePass controller, the standard logon page will load if you log out of FirePass and attempt to log back in. Because you cannot load the customized logon page that corresponds to the Landing URI, you typically cannot log in to the FirePass controller. Clicking the To open a new session, please click here link of the logout page, or typing in the Landing URI will display the default login page, rather than the customized login page for that Landing URI.

You can configure the FirePass controller to display customized login pages that are accessed by unique Landing URIs, on the URI-based Customization tab of the Device Management: Customization page. When you access the FirePass controller using the Landing URI under normal conditions, you will see the customized login page instead of the default login page, and will see a customized webtop instead of the default webtop when you log in.

F5 Networks Product Development tracked this issue as CR77242 and it was fixed in FirePass versions 6.0.2 and 6.1.0. For information about upgrading, refer to the FirePass Release Notes.

Additionally, cumulative hotfix HF-600-13 has been issued for FirePass version 6.0.0 and cumulative hotfix HF-601-2 has been issued for FirePass version 6.0.1. You may download these hotfixes or later versions of the cumulative hotfixes from the F5 Networks Downloads site.

For instructions about obtaining a hotfix, refer to K167: Downloading software from F5 Networks.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.

Workaround

You can work around this issue by closing the browser, opening a new browser, and accessing the Landing URI logon page. If you are still unable to access the Landing URI logon page, clear the cookies from the browser after restarting and then attempt to load the Landing URI logon page.
