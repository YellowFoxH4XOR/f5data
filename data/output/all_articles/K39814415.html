Description

SSH public key authentication is configured in BIG-IP systems as described in article K13454. However, when attempting to log in to the remote system, authentication is still requesting the remote device's password.

In addition, when you run ssh command specifying the private key (-i <file name>) associated with the public key previously shared and with  highest debug (-vvv)  parameter specified  for this connection, you are encountering an  error similar to:

Example of the command used: ssh -i /root/.ssh/id_rsa user_1@10.10.10.10 -vvv

Error:debug3: sign_and_send_pubkey: RSA 1a:2b:3c:3f:4a:5b:6f:7e:8a:9b:00:a1:b2:c3:d4:f5:a6:b7:00:a1

@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
@         WARNING: UNPROTECTED PRIVATE KEY FILE!          @
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@

It is required that your private key files are NOT accessible by others.
This private key will be ignored.
bad permissions: ignore key: /home/user1/id_rsa

Environment

  • BIG-IP High Availability pair with SSH public key shared.
  • BIG-IP and server with Linux server running SSHD process with SSH public key shared.

Cause

The device may be skipping that private key.
 

Recommended Actions

Use chmod command to edit file permissions for the private key to allow only the file owner to be able to read and write the private key .

#chmod 700 /home/user1/id_rsa

Additional Information

K13454: Configuring SSH public key authentication on BIG-IP systems (11.x - 16.x)
K17318: Public key SSH authentication may fail after installing a UCS
