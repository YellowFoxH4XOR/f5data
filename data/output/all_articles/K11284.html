Known Issue

This is the result of a known issue. Disabling the Enable Content Assembly on Proxies option but leaving normalization enabled for all document types results in the following behavior:

  • The BIG-IP WebAccelerator will not normalize documents sent in the response. This is expected behavior when disabling the Enable Content Assembly on Proxies option.
     
  • The BIG-IP WebAccelerator will proxy the initial request for an object and insert an S10201 code in the response. The BIG-IP WebAccelerator inserts Cache-Control headers max-age and s-maxage with the expected values. This is also expected behavior.

    Note: The S10201 code is defined as follows:

    Request was sent to the origin web server, because it was for new content. The WebAccelerator system caches the response from the origin web server for future requests, before responding to the request. The WebAccelerator system will respond to future request for this content, from cache.

    The S10201 code implies that the response will be cached by the BIG-IP WebAccelerator; however, the request will be proxied according to the policy configuration, and the response will not be cached.

  • When a second request for an object is made, the BIG-IP WebAccelerator proxies the request and inserts an S10232 code in the response. However, the BIG-IP WebAccelerator inserts a Cache-Control header into the response that does not have the max-age directive and contains an s-maxage directive with an incorrect value of 17280000. This instructs all intermediate caches that they can keep a copy of the document for 200 days. The value of 17280000 is not configurable in either the Configuration utility or from the command line.

F5 Product Development tracked this issue as ID 243290 (formerly CR136200) and it was fixed in BIG-IP version 10.2.0. For information about upgrading, refer to the BIG-IP WebAccelerator Release Notes.

Workaround

You can prevent the BIG-IP WebAccelerator from instructing intermediate caches to hold the object for 200 days. If you want to have normalization, F5 recommends that you also enable the Enable Content Assembly on Proxies option.

If you do not want to have normalization enabled for the node or specific content, you can disable normalization under WebAccelerator >> Policies >> URL Normalization.

Note: For more information regarding URL Normalization, refer to the Policy Management Guide for the BIG-IP WebAccelerator system.
