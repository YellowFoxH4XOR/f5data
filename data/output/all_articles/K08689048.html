Known Issue

The Traffic Management Microkernel (TMM) service may produce a core file and restart when you execute the tmsh mv command.

This issue occurs when all of the following conditions are met:

  • The BIG-IP mcpd.mvenabled variable is configured to the non-default setting of true (the default setting is false).
  • Your BIG-IP system is configured with a pool.
  • Using the TMOS Shell (tmsh), you move a pool name to a different pool name.

For example:

tmsh mv /ltm pool <original pool name> <new pool name>

Note: The tmsh mv command is deprecated and is not supported.

The mcpd.mvenabled database variable must be set to true to allow moving and renaming objects using the tmsh mv command. To do so, type the following command:

Important: Currently, the ability to move certain BIG-IP objects to other folders and to rename those objects is an experimental feature. F5 recommends that you disable this feature after you have moved or renamed any BIG-IP objects. Also, use of this feature could result in a loss of statistics and a disruption in BIG-IP DNS (formerly known as BIG-IP GTM) service. If you plan to move or rename a virtual server, please contact your BIG-IP DNS administrator before doing so.

modify /sys db mcpd.mvenabled value true

To disable the feature, type the following command:

modify /sys db mcpd.mvenabled value false

Impact

The BIG-IP system may temporarily stop processing traffic while the TMM service restarts. Systems configured as part of a high availability (HA) pair may fail over to a peer device.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Your BIG-IP system temporarily stops processing traffic when configured to fail over to a peer device.
  • Your BIG-IP system generates a TMM core file in the /shared/core/ directory.
  • Your BIG-IP system logs a message to the /var/log/tmm file that appears similar to the following example:

    notice failed to find pool /<partition>/<old pool name>
    notice ** SIGSEGV **

Resolution

Status

F5 Product Development has assigned ID 562808 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies to (see versions) box, located in the upper-right corner of this article. Workaround

To work around this issue, you can duplicate the pool configuration under a new pool name. To do so, assign the new pool to the appropriate virtual servers and then delete the unused pool.

Impact of workaround: F5 recommends performing the suggested workaround during a scheduled maintenance window.
