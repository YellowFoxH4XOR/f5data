Description

After the upgrade reboot, the device is unable to load the configuration.

  • The device keeps INOPERATIVE and multiple daemons such mcpd keep restarting and the device is not able to load the configuration.
  • You can identify these logs into the /var/log/ltm
Sep 28 08:29:49 Big-IP.local err mcpd[18609]: 01070734:3: Configuration error: MCPProcessor::initializeDB: can't chmod for directory (/config/filestore/files_d/anydir_d/certificate_key_d) err (Permission denied).
Sep 28 08:29:49 Big-IP.local err mcpd[18609]: 01070596:3: An unexpected failure has occurred, can't chmod for directory (/config/filestore/files_d/anydir_d/certificate_key_d) err (Permission denied). - sys/validation/FileObject.cpp, line 628, exiting...
Sep 28 08:29:51 Big-IP.local notice mcpd[18937]: 01071539:5: Mcpd is starting. The BIG-IP version is 16.0.0.1.
Sep 28 08:29:51 Big-IP.local notice mcpd[18937]: 01390002:5: User requested database size set to 512MB

Environment

  • BIG-IP upgrade from v14.x - 16.0.1.x
  • Reboot from v14.x - 16.0.1.x installed location with copy config enabled.
  • Lost GUI and SSH access

Cause

  • Bug ID 862937
     

Recommended Actions

Follow workaround in Bug ID 862937
