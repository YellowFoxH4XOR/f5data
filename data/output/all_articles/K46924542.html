Description

BIG-IP Proxy SSL feature

The BIG-IP system supports the Proxy SSL feature to optimize SSL traffic between the client and the destination server, without terminating the SSL connection on the BIG-IP system. For more information, refer to K13385: Overview of the Proxy SSL feature.

When you configure this, it is important to consider the memory requirements and allocation of the cache. The memory used by the Proxy SSL cache is determined by the size of the DB variable tmm.proxyssl.cachesize as follows:

Total amount of memory used by the Proxy SSL cache = (Size of tmm.proxyssl.cachesize) x (Number of TMM instances on the system)

The default value of tmm.proxyssl.cachesize is 2,621,440 sessions. For example, for a system with 8 TMM instances, the cache size is 20,971,520 sessions.

Issue

When using the Proxy SSL feature, even during low traffic throughput periods, you observe the BIG-IP system under memory pressure with the following logs in the /var/log/ltm file:

mode sweeper: /Common/default-eviction-policy (200000000016c) (global memory) 20 Connections killed
err tmm4[18841]: 011e0003:3: Aggressive mode sweeper: /Common/default-eviction-policy (400000000016c) (global memory) 10 Connections killed

Environment

  • BIG-IP LTM
  • Proxy SSL virtual server

Cause

It is important to note that cache entries in the Proxy SSL cache do not expire or timeout and will accumulate over time. So as traffic passes through a Proxy SSL enabled virtual server, cache allocations are made until the total amount of memory of the Proxy SSL cache is reached. At this point, cache allocations will be reused, starting with the earliest allocated entries.

Due to this process, even at low levels of Proxy SSL traffic, you may observe TMM memory utilization increasing, until the maximum Proxy SSL cache allocation is reached.

This issue may be compounded in BIG-IP systems where HTSplit is disabled where the number of TMM instances is doubled, leading to a large amount of memory allocated to the Proxy SSL cache. For more information on HTSplit and the number of TMM instances, refer to K23505424: Overview of the HTSplit feature.

For example, on an 8-vCPU BIG-IP VE, using the default tmm.proxyssl.cachesize of 20,971,520 sessions, with each allocation consuming 144 bytes, this can result in the maximum ProxySSL cache reaching around 3GB. The level of Proxy SSL traffic connections will determine how quickly this limit is reached. This could create a situation where allocated TMM memory is over the defined limits for aggressive reaping, and traffic could be impacted.

Recommended Actions

When configuring the Proxy SSL feature, you should configure the value of the tmm.proxyssl.cachesize DB variable as appropriate for your environment taking the following into consideration:

  • monitor the (dht_entry, ssl_dht_data, ssl_dht_key) entries memory allocations in the Proxy SSL cache. You can do so my navigating to the tmsh show sys memory command on your QKview on iHealth as follows: Commands > Standard > tmsh > sys > show /sys memory

You may observe an output similar to the following with other entries removed:
------------------------------------------------------------------------------------------------
Sys::SubSystem Memory
SubSystem                     Alloc (bytes)  Max Alloc (bytes)  Object Size  Current Allocations
------------------------------------------------------------------------------------------------
dht_entry                              1.2G               1.2G           64              20527934
ssl_dht_data                         939.7M             939.7M           48              20527934
ssl_dht_key                          626.5M             626.5M           32              20527934

  • Performing a system reboot clears the cache and releases the memory allocated.
  • Depending on the traffic throughput through the virtual server(s) together with the rate of increase of memory usage of the Proxy SSL cache, you may decrease the size of the tmm.proxyssl.cachesize DB variable step by step as appropriate.

    Note: The throughput level of Proxy SSL traffic connections will determine how quickly the maximum memory allocation is reached.

    For example, if you are running a BIG-IP VE with HTSplit disabled, you may consider reducing the cache size by half as a first step. And then proceed to decrement the size further, when you observe the total active connections of the Proxy SSL virtual server lower than the total number of cache entries.

  • Display and modify the tmm.proxyssl.cachesize DB variable:

    • To list this value on your system, enter the following tmsh (tmos) command:
      list sys db tmm.proxyssl.cachesize

    • To modify this value on your system, enter the following tmsh (tmos) command:
      modify sys db tmm.proxyssl.cachesize value <new value>
