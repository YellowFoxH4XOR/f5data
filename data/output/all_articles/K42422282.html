Topic

Multifactor authentication (MFA) is a best practice that enhances authentication by requesting two or more verifiable authentication factors. Common authentication factors are: Something You Know, Something You Have, and Something You Are.

  • Something You Know is typically a password or a PIN, but it may include questions that only you can answer or a touch pad gesture.
  • Something You Have is typically either a physical or software token, but it may include a certificate or some combination of certificate and token.
  • Something You Are is typically a biometric input, such as fingerprint, retina scan, or facial or voice recognition.

You should consider using this procedure under the following condition:

  • You want to configure a second factor authentication on top of AD Authentication and AD Query to authenticate users using a one-time password (OTP).

Description

In addition to native MFA-like RSA SecurID, the BIG-IP APM system offers the flexibility to combine multiple authentication mechanisms in an arbitrary manner for a single access policy.

You can enforce MFA by configuring two or more distinct authentication factors in the BIG-IP APM access policy. For the authentication methods available in BIG-IP APM and how to configure them, refer to the BIG-IP Access Policy Manager: Authentication Methods manual.

Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching MyF5 and finding product documentation.

The following diagram shows an example of an MFA configuration on the BIG-IP APM system. In this scenario, you provide a password (Something You Know) that the system evaluates against MS Active Directory (AD). Then, you provide an OTP (Something You Have) that the system automatically generates and transmits to you through external SMS. Moving through the Successful branches, the policy includes the following policy items in the order in which authentication is processed: Logon Page, AD Auth, AD Query, OTP Generated, OTP delivery by HTTP, Logon Page OTP, OTP Verify, and Full Resource Assign. Each fallback branch from the policy items leads to access Failure. For detailed information on how to configure this policy, refer to the Overview: Providing a one-time password using an external SMS section of the BIG-IP APM: One-Time Password Authentication manual. 

Figure: BIG-IP APM access policy for MFA AD Auth + OTP

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have an existing backend HTTP AAA server connected to the BIG-IP APM to send OTPs using SMS.
  • You already have a AAA Active Directory Server configuration on the BIG-IP APM system.

Create an HTTP AAA server

To send the password in a text message, you can use a form-based HTTP authentication policy item. You pass the OTP in hidden parameters to a form action. You must create a form action that sends the OTP using an external SMS. 

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Access > Authentication > HTTP.
  3. Select Create.
  4. Enter a name for your server.

  5. Fill in the remaining settings with the values in the following table.

    Note: The following settings are dependent on the HTTP AAA server. You need to modify the settings to meet the specific requirements of your HTTP AAA server.

    SettingsValues
    Authentication TypeForm Based
    Form MethodPOST
    Form ActionEnter the complete destination URL to process the form. For example:
    http://example.com/http-api.php
    Hidden Form Parameters/Values

    otp_http_mobile "%{session.ad.last.attr.mobile}"
    otp_http_email "%{session.ad.last.attr.mail}"
    otp_http_body "One Time Passcode: %{session.otp.assigned.val} Expires after use or in %{session.otp.assigned.ttl} seconds"

    Successful Logon Detection Match TypeSelect the method that your authenticating server uses.
    Successful Logon Detection Match Value Enter a cookie name, a URL, or a string, depending on the successful logon detection match type you selected.

  6. Select Finished

Create the access policy for MFA AD Auth + OTP using a built-in macro

In this section, you will create the access policy as shown in the Figure: BIG-IP APM access policy for MFA AD Auth + OTP.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Create the access profile
    1. Go to Access > Profiles / Policies.
    2. Select Create.
    3. Enter a name for your access profile.
    4. For Profile Type, select All.
    5. Under Languages Settings, for Language, in the Factory Builtin Languages, select English and move it to the Accepted Languages list.
    6. Select Finished.
  3. Create the AD auth query OTP by HTTP and resources macro.
    1. Select Edit for the access profile that you just created.
    2. Select Add New Macro.
    3. For Select Macro template: select AD auth query OTP by HTTP and resources macro.
    4. Select Save.
    5. Under Add New Macro, select the add icon (+) to expand the macro you created.
  4. Configure the AD Auth, AD Query, OTP delivery by HTTP and Full Resource Assign policy items.
    1. Select the AD Auth policy item.
    2. For Server, select your existing AAA AD Server.
    3. Select the AD Query policy item.
    4. For Server, select your existing AAA AD Server.
    5. Select Add new entry.
    6. For Required Attributes (optional), enter mobile.
    7. Make any further configuration you require in AD Query and select Save.
    8. Select the OTP delivery by HTTP policy item.
    9. Select the AAA Server you created in the Creating a HTTP AAA server procedure.
    10. Select Save.
    11. Select Full Resource Assign.
    12. Select Add new entry and select Add/Delete.
    13. Add the resources to assign to your users and select Update.
    14. Select Save.
  5. Adding the macro to the access policy user login flow.
    1. Between Start and the Deny end points, select the add icon (+).
    2. On the Macros tab, select the macro you created in the previous procedure.
    3. On the Successful branch, change the Deny endpoint to Allow, and select Save.
    4. Select Add Item.
  6. Select Apply Access Policy.

Create a virtual server

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Virtual Servers > Virtual Server List.
  3. Select Create, and enter a name for the profile.
  4. For Destination Address/Mask, enter the virtual server IP address.
  5. For Service Port, enter 443 or https.
  6. For the SSL Profile (Client) and SSL Profile (Server), select the appropriate profiles. For example, clientssl and serverssl.
  7. For HTTP Profile, select an appropriate HTTP profile. For example, http.
  8. For Source Address Translation, select Auto Map if your environment requires it.
  9. For Rewrite Profile, select rewrite.
  10. Under Access Policy, for Access Profile, select the access profile you created in the Creating the BIG-IP APM access policy for MFA AD Auth + OTP access policy procedure.
  11. For Connectivity Profile, select an appropriate profile. If you do not have one, select the add icon (+) to create a new one.
  12. Select Finished.
