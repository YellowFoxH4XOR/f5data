K000160061: BIG-IP APM – Access Profiles not applying after Microsoft key rollover

Type
Knowledge
Published
2026-02-24
Updated

Applies to

  • BIG-IP APM: 17.X.X, 17.5.X, 17.5.1, 17.5.0, 17.1.X, 17.1.3, 17.1.2, 17.1.1, 17.1.0, 17.0.X, 17.0.0
Source

Description

On BIG-IP with APM provisioned, Access Profiles may remain in a "not applied" state after a Microsoft public key/JWKS rollover event. Configuration changes to Access Profiles do not take effect, and certificate verification errors such as "certificate has expired" in /var/log/ltm, and SSL handshake failures like "alert(40) renegotiation disallowed" are observed. 

Environment

  • Multiple Access Profiles

  • Microsoft JWKS/public key rollover event

Cause

Stale JWKS cache in the APM daemon after a Microsoft public key rollover event prevents Access Profiles from being applied and causes certificate verification errors and SSL handshake failures.

Recommended Actions

  1. Restart the APM daemon using the following command:
    bigstart restart apmd

  2. This refreshes the JWKS cache and applies the Access Profiles. This will terminate active APM sessions but is generally non-disruptive to new connections.

  3. After remediation, verify:

    • In the GUI: Access > Profiles/Policies > Access Profiles (Per-Session Policies) — confirm Access Profiles show "applied" status and configuration changes are reflected.

    • In the CLI: Run tmsh show apm access-profile to confirm Access Profiles are properly applied.

    • In logs: Check /var/log/apm and /var/log/ltm for absence of new certificate verification errors or SSL handshake failures.
