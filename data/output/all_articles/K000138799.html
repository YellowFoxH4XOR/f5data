K000138799: BIG-IP VE (KVM Hypervisor) TMM restarts continuously after upgrade.

Description

After upgrading to v17.1.1.1 the BIG-IP VE (KVM Hypervisor) with machine type q35 tmm constantly restarts.

Below given logs are observed in /var/log/tmm:

notice EAL: probe driver: 1af4:1041 net_virtio
notice dpdk[0000:05:00.0]: DPDK internal port_id 0
notice xnet_lib [pci:0000:05:00.0]: Device attach complete (MAC: fa:16:3f:9a:80:91 Queues: 1/1)
notice xnet_lib [pci:0000:05:00.0]: Queue configuration complete (rx: 1/256 tx: 1/256)
notice virtio_mtu_set(): MTU should be between 68 and 8750             <=====
notice dpdk[0000:05:00.0]: Error: rte_eth_dev_set_mtu failed: err=-22  <=====
notice xnet[05:00.0]: Error: Command 0 failed: 5

Environment

  • TMM enters a restart loop
  • BIG-IP VE on KVM Hypervisor with machine type q35
  • Upgrade to version 17.1.1.1

Cause

This issue is observed when device model 'Virtio' is selected for Network Driver on the Hypervisor and xnet-driver is unable to attach after booting, the device becomes unstable and data traffic is impacted.

Recommended Actions

  • Configuring the BIG-IP VE system to use the SOCK network driver instead of the default network driver. Refer:
    • K10142141: Configure the BIG-IP VE system to use the SOCK network driver

Important: The following procedure requires you to edit the /config/tmm_init.tcl file and restart the VE instance. Network traffic is disrupted while the system restarts.
