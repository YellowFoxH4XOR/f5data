K000161882: Session Persistence Issues When Using F5 Distributed Cloud (XC) with BIG-IP Source IP Persistence

  • F5 Distributed Cloud WAF
Source

Description

When integrating F5 Distributed Cloud (XC) as a reverse proxy in front of an application load balanced by BIG-IP, users may experience repeated session invalidation, unexpected redirects, or the application issuing new JSESSIONID cookies on nearly every request. Typical symptoms include, but not limited to,  broken user sessions and workflow interruptions.

Environment

  • F5 Distributed Cloud (XC) acting as a reverse proxy/load balancer
  • Downstream BIG-IP load balancer in front of application servers
  • BIG-IP virtual servers configured with Source IP persistence
  • Application expects session continuity via JSESSIONID cookie
  • XC uses SNAT, resulting in variable source IP addresses as seen by the origin

Cause

The root cause is the use of Source IP persistence on the BIG-IP load balancer. When traffic passes through XC, the origin server sees the SNAT IP addresses from XC, which can change between requests. Since the application or BIG-IP ties session validity to the L3 source IP, this results in session invalidation and the issuance of new JSESSIONID cookies for each request.

Answer/Recommended Actions

  • Update the persistence method on the BIG-IP virtual server from Source IP to a Layer 7 method:
    • Change persistence profile on the BIG-IP virtual server to:
      • Cookie Persistence (recommended for HTTP/HTTPS applications)
      • Universal Persistence based on the JSESSIONID cookie (if custom logic is required)
  • Ensure the application does not rely on the L3 source IP for session tracking. Instead, use application-layer identifiers such as cookies or the X-Forwarded-For (XFF) header.
  • Review and update application logic to avoid tying session validity to the client’s source IP address.

Additional Information

  • Using Source IP persistence is not compatible with reverse proxy architectures where the client’s source IP is not preserved (e.g., when SNAT is used).
  • Session persistence should be based on application-layer data (such as cookies) to ensure reliable user experience through proxies and load balancers.
