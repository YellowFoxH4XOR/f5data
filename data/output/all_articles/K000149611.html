K000149611: How to unblock ASM when multiple conditions are met using iRule

Description

You want to override the security policy that blocks certain actions for a specific violation, such as Attack Signatures, by using iRules that fulfill multiple conditions and redirecting the request to the origin server.
To do this, you can use the ASM::unblock iRules command.

Note: The following applies to using the ASM::unblock iRules command:

  • Violations from an unblocked request will not be learned for policy modification, neither manually nor automatically.
  • The command applies to requests only. It is not possible to unblock a response in which violations were found.
  • An unblocked request will not be sent to Antivirus scanner.
  • The command takes effect even if it is followed by ASM::raise command with a blocking violation.
  • The command takes effect even if it is followed by ASM::deception command.
  • The command takes effect even if it is followed by ASM::captcha command.

Environment

BIG-IP ASM
iRule with the below conditions:

  • When the HTTP request Content-Type contains "text/xml".
  • When the HTTP request URI contains "index.php".
  • When the HTTP request user-agent contains "Agilitbot".
  • When the ASM violation details contain attack signature IDs such as "200002883" and "200000098".

Cause

None.

Recommended Actions

Enable BIG-IP ASM iRules events

Before configuring the iRule to unblock ASM, ensure you enable ASM iRules events for the relevant security policy.
To do so, perform the following procedures.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Security > Application Security > Security Policies > Policies List.
  3. Select the name of the policy that you want to edit.
  4. Select the General Settings tab.
  5. For Trigger ASM iRule Events Mode, select Normal.
  6. Select Save.
  7. Select Apply Policy.

Create the iRule to unblock ASM when multiple conditions are met

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > iRules > iRule list.
  3. Select Create.
  4. Enter the iRule code (update the code according to your requirements).
when ASM_REQUEST_DONE {
    log local0. "ASM request done"
    if {[HTTP::header "Content-Type"] contains "text/xml"} {
        if {[string tolower [HTTP::uri]] contains "/index.php"} {
            if {[HTTP::header "User-Agent"] contains "Agilitybot"} {
                if {([ASM::violation details] contains "200002883" or 
                     [ASM::violation details] contains "200000098")} {
                    ASM::unblock
                    log local0. "ASM unblocking [HTTP::uri]"
                }
            }
        }
    }
}

    5. Select Create.
    6. Associate the iRule with the virtual server.

When iRule is functioning correctly, you should see the following logs in the CLI and WebUI (details in ASM event logs).

CLI (/var/log/ltm):

info tmm2[22744]: Rule /Common/<iRule_Name> <ASM_REQUEST_DONE>: ASM request done
info tmm2[22744]: Rule /Common/<iRule_Name> <ASM_REQUEST_DONE>: ASM unblocking <[HTTP::uri]>

WebUI (ASM Event Logs):
-- Request Status = Unblocked
-- Blocking Exception Reason = Unblocked from iRule
