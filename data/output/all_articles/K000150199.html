Description

When passing a file through a BIG-IP LTM Virtual Server, the application may hang or fail to receive the complete response. A network packet capture typically shows TCP retransmissions and the BIG-IP sending “[TLS segment of a reassembled PDU]” to the client, but it does not receive an acknowledgment (ACK). As a result, we see “[TCP Retransmission]” on the BIG-IP. However, on the client side, no packets are received, and after a few seconds, the client terminates the session with a FIN/ACK.

Environment

  • Product BIG-IP LTM VE on Microsoft Azure

Cause

This problem is caused by a known bug (ID 1320889) present in certain BIG-IP VE versions where TCP Segmentation Offload (TSO) is enabled by default. With TSO enabled, BIG-IP may fail to properly segment and transmit large TCP payloads, especially in virtualized environments such as Azure, resulting in some segments not being sent from the VM to the underlying host. This leads to incomplete responses and application hangs when handling large payloads.

Recommended Actions

Take a packet capture simultaneously on both the BIG-IP side and the host (Microsoft Azure) to verify whether the packets are reaching their destination.

If not receiving the packets on the Host, apply one of the following workarounds:

Option 1: Disable TCP Segmentation Offload (TSO)

1. Log in to the CLI.

2. Disable the database key for TSO:

tmsh modify sys db tm.tcpsegmentationoffload value disable

3. Save the system configuration:

tmsh save sys config

4. Restart the Traffic Management Microkernel (TMM) process:

bigstart restart tmm

Important: Restarting the TMM process will temporarily disrupt traffic. Perform this change during a maintenance window.

Note:  In an HA pair, making the change and syncing will push the update to the peer.

Option 2: Upgrade BIG-IP

Upgrade to one of the following versions or later:

  • v17.5.0
  • v17.1.1
  • v16.1.5
