Description

Enabling the Bot Defense profile on a BIG-IP ASM (Advanced WAF) virtual server results in Set-Cookie headers being added to every HTTP response. This causes downstream caching solutions, such as Cloudflare, to bypass caching for these responses, as indicated by the CF-cache-status header set to "bypass." Disabling the Bot Defense profile restores normal caching behavior. 

Environment

  • Product: BIG-IP ASM (Advanced WAF)
  • Version: 17.1.3
  • Virtual server with multiple WAF policies and a Bot Defense profile
  • Cloudflare used as a reverse proxy and cache in front of BIG-IP
  • Two websites served from the same virtual server, both using the same Bot Defense profile

Cause

Set-Cookie headers are generated by the ASM module as part of the Bot Defense profile's normal operation. These cookies are required for session security and bot verification. Their presence in every response is expected and necessary for Advanced WAF/Bot Defense functionality. The difference in caching behavior is due to how Cloudflare handles responses with Set-Cookie headers, not a change or abnormality in BIG-IP ASM operation.

Answer/Recommended Actions

  • Set-Cookie headers generated by the Bot Defense profile are required for security and cannot be disabled without impacting WAF/Bot Defense functionality.
  • To allow caching for specific endpoints, consider whitelisting cacheable URLs in the Bot Defense profile and disabling mitigation/challenges for those URLs.
  • Further investigation or adjustments may be needed on the Cloudflare side to handle responses with Set-Cookie headers if caching is required.

Additional Information

  • Advanced WAF cookies act as a security seal for the session, tracking the state of the security policy and ensuring that application cookies have not been tampered with by the client.
  • Bot Defense cookies are used to store the results of proactive challenges that prove a browser is real and capable of processing complex web content.
