Description

The F5 Journeys migration utility is a tool for migrating legacy BIG-IP configurations to BIG-IP tenants running on F5OS-managed platforms such as VELOS and rSeries.

To improve code security, governance, and release control, F5 moved the F5 Journeys tool from GitHub to the MyF5 Downloads portal.

This article provides awareness of that change, explains supported releases and limitations, and outlines the future migration strategy, including the transition toward platform-migrate and upcoming migration capabilities.

For guidance around how to deploy the tool, refer to K000161936: Quick deployment guide for F5 Journeys tool

F5 Journeys Repository Move

What Changed

The F5 Journeys migration utility was previously hosted on GitHub. As of Journeys version 4.2.0, the tool is now distributed exclusively through the MyF5 Downloads portal:

  1. Go to MyF5 Downloads.
  2. For Group select BIG-IP.
  3. For Product Line select F5 Journeys App.
  4. For Product Version select the latest version.
  5. Complete the remaining steps to download a file to your workstation.

Rationale

The decision to move F5 Journeys from GitHub to MyF5 Downloads was made to:

  • Increase code security and integrity.
  • Ensure controlled distribution.
  • Align with F5’s software delivery and security policies.
  • Reduce ambiguity around supported and validated builds.

No functional regression was introduced because of this move

What Is F5 Journeys Used For?

F5 Journeys is a configuration migration utility designed to assist with moving legacy source BIG-IP configurations including systems such as:

  • BIG-IP iSeries
  • VIPRION
  • vCMP

To BIG-IP tenants running on modern F5OS-managed platforms, including:

  • VELOS
  • rSeries

The tool prepares configurations for compatibility with F5OS-managed tenants by analyzing and modifying unsupported elements rather than performing a full end-to-end migration.
For a detailed solution overview refer to F5 Journeys App – Solution Overview (PDF).

F5 Journeys is supported for customers running the following BIG-IP versions:

  • BIG-IP 21.0.x
  • BIG-IP 17.5.x
  • BIG-IP 17.1.x
  • BIG-IP 16.x

These releases represent the primary target audience for the Journeys utility when migrating toward F5OS-managed environments.

Key Limitations of F5 Journeys

While F5 Journeys remains useful, it has important architectural limitations that customers should understand:

  1. External to BIG-IP
    • Journeys is not natively integrated into BIG-IP.
    • It runs externally and processes configuration files rather than operating directly on the system.
    • Requires Docker, which may be problematic to some customers with environment restrictions.
  2. Not an End-to-End Migration Tool
    • Journeys does not automatically complete the migration.
    • It focuses on:
      • Removing Layer 2 (L2) configuration elements.
      • Removing high availability (HA) constructs.
      • Modifying or flagging/removing unsupported objects for F5OS-managed platforms.
    • Additional steps are required to complete the migration and deploy the tenant.

Because of these limitations, F5 Journeys should be viewed as a migration preparation and remediation tool, not a fully automated migration solution.

Future Direction

F5 is transitioning away from external utilities like Journeys in favor of native migration capabilities built directly into BIG-IP using the platform-migrate workflow. F5 will publish more details upon release of the new migration features.

Sunsetting of F5 Journeys

F5 Journeys will be eventually sunset as BIG-IP versions 16.x and 17.x reach End of Software Support. At that point migration capabilities built directly into BIG-IP will become the standard migration mechanism.

Key points about the planned retirement of Journeys:

  • F5 Journeys remains supported and recommended for current use cases.
    • To receive support open a MyF5 case, mention F5-Journeys in the description and select the BIG-IP LTM module. 
  • No immediate end-of-support date has been announced.
  • New migration features will be delivered through BIG-IP native tooling, not F5 Journeys.
  • Alternative migration options include:
    • The tmsh load sys ucs platform-migrate command. For more information refer to K82540512: Overview of the UCS archive 'platform-migrate' option.
    • ConfigSync for some migrations. For more information refer to K15496: Migrate a device group member to a new BIG-IP platform.
    • Ansible collection for migrations. For more information refer to Modernizing F5 Platforms with Ansible.
