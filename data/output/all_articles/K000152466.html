Description

When processing JSON API requests through BIG-IP LTM with ASM (Application Security Manager) enabled, requests may be blocked with a "Malformed JSON data" violation. This occurs even if the JSON payload appears correctly formatted. The issue is triggered by the presence of non-breaking space (U+202F), narrow no-break space, or other special Unicode space characters within JSON fields, especially in message strings.

Environment

  • Configuration: ASM policy enforcing JSON validation on API endpoints
  • Payload: JSON requests containing non-breaking space (U+202F) or similar special characters in string fields

Cause

The ASM JSON validation engine enforces strict compliance with the JSON specification and rejects payloads that contain non-breaking space (U+202F), narrow no-break space, or similar special Unicode characters within JSON fields. These characters are not recognized as valid whitespace in standard JSON, resulting in a "Malformed JSON data" violation and blocking of the request.

Recommended Actions

Remove all non-breaking spaces (U+202F), narrow no-break spaces, or other special Unicode whitespace from all string values in the client-side JSON payload before sending to BIG-IP ASM-protected endpoints.

If it is not possible to remove these characters at the source application, relax the ASM JSON validation engine as described in F5 article K58055038. This change requires an ASM restart and should be scheduled during a maintenance window due to its impact.
