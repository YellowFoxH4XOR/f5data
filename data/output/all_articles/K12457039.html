K12457039: Port Upgrade is not working for Service Entry with resolution NONE

Type
Support Solution
Published
2022-10-26
Updated
2023-02-21
Applies to
  • Aspen Mesh
Source
https://my.f5.com/manage/s/article/K12457039

Description

When creating a Service Entry (SE) in a cluster, it allows the application pods in a mesh to talk to external clients. While doing so, there are 3 parameters for resolution that can be set: NONE, DNS, STATIC. Here is an example of one of the service entry:

kubectl apply -n ns1 -f - <<EOF
apiVersion: networking.istio.io/v1alpha3
kind: ServiceEntry
metadata:
  name: nginx-se1
spec:
  hosts:
  - diameter-tcp-upgrade.all
  location: MESH_EXTERNAL
  ports:
  - number: 3868
    name: tcp-3868
    protocol: TCP
  - number: 4433
    name: tcp-5868
    protocol: TCP
  resolution: NONE
EOF

Once the Service Entry is created, it is propagated to all the pods where SE is applied. When looking at one of the pods, you can see the clusters it created:

> istioctl pc cluster nettools-797c4cc775-6lb6k.ns1 --fqdn "outbound|4433||diameter-tcp-upgrade.all"
SERVICE FQDN                 PORT     SUBSET     DIRECTION     TYPE             DESTINATION RULE
diameter-tcp-upgrade.all     4433     -          outbound      ORIGINAL_DST     nginx-dr1.ns

Port upgrade is used when you want envoy to route the traffic to another port based on virtual service. Here is an example which shows when traffic is received on one port but is forwarded to another:

Istio Documentation: Virtual Service - TCPRoute

Environment

  • Aspen Mesh: 1.11.x

Cause

Setting resolution: NONE on the ServiceEntry will create ORIGINAL_DST cluster type assigned to the listener on the specified port. This means that Envoy istio-sidecar proxy is a pass-through proxy. It does not modify the Destination IP (and port) sent by the application to open a TCP connection. In this scenario the Application is responsible for resolving the external IP address. this is just a passthrough/ORIGINAL_DST cluster which means that it does not rewrite the destination Port.

Recommended Actions

To fix that you would have to use resolution: DNS or specify the Endpoints. In Endpoints you must specify the address (required field):

Istio Documentation: WorkloadEntry

You can use DNS name in the address field but then you will end up with the similar behavior as when ServiceEntry has the resolution set to DNS.

Additional Information

According to Envoy's documentation, you cannot bind to address without setting how it is to be resolved (either STRICT or LOGICAL). Without being able to set the portValue, a rewrite cannot occur. For more information, refer to the following article:

Envoy Documentation: config.core.v3.SocketAddress

DNS_ROUND_ROBIN isn't included in AM 1.11, it was added with 1.12 release of Istio as an option for resolution in Service Entry. For more information, refer to the following article:

Istio 1.12 Change Notes
