Windows Media 9 connections contain a unique Client ID field. You can configure a BIG-IP iRule to use this value to load balance and persist Window Media 9 connections.

The following iRule example searches for the client-id= keyword in the first 200 bytes of a packet and selects a pool based on that value. The client-id= keyword is a unique alphanumeric value at least 36 characters in length.

Example iRule

rule WinMedia9_rule {
if (findstr(tcp_content, <0x63,0x6c,0x69,0x65,0x6e,0x74,0x2d,0x69,0x64,0x3d>, 10, 200)) {
log "client_addr,${client_addr} passed "
use pool Content_pool
}
else {
log "client_addr ${client_addr} failed "
use pool Bouncer_pool
}
}

The pool is configured to use the same iRule parse method for persistence, as in the following example:

pool xpmedia_pool {
persist findstr(tcp_content, <0x63,0x6c,0x69,0x65,0x6e,0x74,0x2d,0x69,0x64,0x3d>, 10, 200)
persist_timeout 300
member 172.16.33.20:1755
member 172.16.43.20:1755
}

Example persistence table

For the client-id= keyword values on a system configured with the previous example rule, the b pool Content_pool persist dump command produces the following output:

Windows Media 9 port

After you create the iRule and pool, you must associate them with a virtual server using the Windows Media port (by default, TCP 1755.)

 

For example:

virtual 172.16.101.51:1755 unit 1 {
use rule WinMedia9_rule
}
