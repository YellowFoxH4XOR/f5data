Environment

  • BIG-IQ
  • Stats Collection
  • BIG-IP not sending stats to AVR

Cause

Functioning as designed.
 

Recommended Actions

Depending on the application, the 0.0 results may be ignored, otherwise use "By Entities" metric query to check for valid results.

Additional Information
 

Detailed explanation of why we get multiple entries with value set to 0 on the response:


BIG-IQ analytics system keeps track of when data of a specific module of statistics was first received and when the latest data received.  This information is kept in a bookkeeper index and used to validate query time ranges before sending a query to the elasticsearch database.
When we send a request with a very old timeframe, appiq first checks the bookkeeper index to find out if there are any stats available for that period of time. If there aren't then it returns an empty response, without even trying to query the statistics indices.

In the case where we have a valid timeframe, but a BIG-IP that hasn't sent any stats, or that doesn't exist:

An elasticsearch query is created with the hostname filter in order to get only data relevant to the specific BIG-IP device and sent to elasticsearch.

A by-time query is set to return the requested data, aggregated in specified time buckets filtered by the given filter. The by-time query is configured to return empty buckets if there is no data that fits the query filter in those parts of the time range. such buckets have a 'count' value of 0, which means that the number of documents that were aggregated in the bucket was 0

A more convenient way to see if a BIG-IP is reporting statistics is to use the "by-entites" metric query - Metrics Query

"by-entites" metric queries return requested aggregations, grouped by values of a requested dimension. the number of returned values can be also limited. A query can be created in which the group-by dimension is set to 'hostname' and a dimension filter is added for a specific BIG-IP hostname. With such query either a single result will be returned or no results at all.

Example:

- If data exists for the specific BIG-IP hostname in the requested time range, an aggregated value will be returned in the result.
query:
{
    "kind": "ap:query:stats:byEntities",
    "module": "bigip-cpu",
    "dimension": "hostname",
    "limit": 1,
    "timeRange": {
            "from": "-1h",
            "to": "now"
    },
    "aggregations": {
            "cpu-usage$avg-value-per-event": {
                    "metricSet": "cpu-usage",
                    "metric": "avg-value-per-event"
            }
    },
    "dimensionFilter": {
            "type": "eq",
            "dimension": "hostname",
            "value": "example.com"
    }
}
