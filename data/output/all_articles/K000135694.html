Description

After installing Aspen Mesh in an OpenShift cluster, new pods fail to come up.  The init container (istio-validation) logs the below errors:

[am-test@k8s-1 ~]$ kubectl logs sleep-pod -c istio-validation
2023-07-10T06:43:56.483439Z    info   in new validator: 10.233.67.214

2023-07-10T06:43:56.483782Z    error  Error connecting to 127.0.0.6:15002: dial tcp 127.0.0.1:0->127.0.0.6:15002: connect: connection refused
2023-07-10T06:43:57.484145Z    error  Error connecting to 127.0.0.6:15002: dial tcp 127.0.0.1:0->127.0.0.6:15002: connect: connection refused
2023-07-10T06:43:58.484498Z    error  Error connecting to 127.0.0.6:15002: dial tcp 127.0.0.1:0->127.0.0.6:15002: connect: connection refused

Environment

Aspen Mesh 1.14.x
Aspen Mesh 1.11.x
Red Hat OpenShift
Istio CNI Plugin

Cause

The Istio CNI plugin is malfunctioning and has not been installed correctly.

Recommended Actions

Reinstall the Istio cni-plugin.
Make sure the Istio cni-plugin has been installed along with required prerequisites (e.g. NetworkAttachmentDefinition, adm policy)
Follow Install the CNI plugin instructions from the Aspen Mesh documentation.

Additional Information

The istio-validation init container is added as part of sidecar injection, which detects if traffic redirection is set up correctly, and blocks the pod from starting up if not. The Istio CNI DaemonSet will detect and evict any pod stuck in such state.
After reinstalling the cni-plugin the init container istio-validation should finish and allow pod creation.
