Known Issue

Domain Name System Security Extension (DNSSEC) keys do not automatically generate after the configured rollover period.

This issue occurs when all of the following conditions are met:

  • You configure your BIG-IP DNS system (formerly known as BIG-IP GTM) to use DNSSEC to sign DNS responses.
  • You configure your BIG-IP DNS system to use the automatic key rollover process.
  • The rollover period expires.

Impact

New DNSSEC keys do not generate after the key rollover period, and DNS responses are not signed after the key expiration period.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • DNSSEC validation is not working for remote DNS clients.
  • Your system logs an error message to the /var/log/ltm file that appears similar to the following example:

    01010228:3: DNSSEC: Could not initialize cipher context for key /Common/example-zsk.
    01010231:4: DNSSEC: Did not add RRSIGs to response RR set (owner: www.example.com).

Workaround

There is no workaround. To recover from this issue, you can restart the Traffic Management Microkernel (TMM). To do so, perform the following procedure:

Impact of action: Performing the following procedure stops all traffic processing while TMM restarts. You should only perform this procedure during a scheduled maintenance period.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. To restart TMM, type the following command:

    restart sys service tmm
