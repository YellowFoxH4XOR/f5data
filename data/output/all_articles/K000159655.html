Description

Some of the HTTP POST requests sent to virtual server are closed by BIG-IP with [F5RST: Compression error] sent to the client.

Environment

  • BIG-IP LTM
  • Virtual server with HTTP compression profile
  • iRule configured to enable decompression for gzip-encoded requests

Cause

The request in question is gzip-encoded POST. The iRule applied to virtual server uses `DECOMPRESS::enable request` to decompress client requests, but the size after decompression exceeds the memory threshold controlled by tmm.deflate.memory.threshold.

Recommended Actions

1.Verify the decompressed size of failing HTTP request by checking value for "File Data:" in packet capture.

Example:

    Content-encoded entity body (gzip): 54272 bytes -> 1828247 bytes
   File Data: 1828247 bytes

2. Verify current settings for sys db tmm.deflate.memory.threshold

tmsh list sys db tmm.deflate.memory.threshold

Example output:

sys db tmm.deflate.memory.threshold {
    default-value "1572864"
    scf-config "true"
    value "1572864"
    value-range "unsigned_integer min:0 max:9437184"
}

3. Increase the value for sys db tmm.deflate.memory.threshold by running:

tmsh modify sys db tmm.deflate.memory.threshold value <your value>

For the given example we can use:

tmsh modify sys db tmm.deflate.memory.threshold value 3000000
