Known Issue

An HTTP monitor response code may contain extraneous trailing characters when the server does not include a carriage return/line feed (CR/LF) after the response status line.

This issue occurs when all of the following conditions are met:

  • An HTTP monitor is configured with a receive string.
  • The server does not include a CR/LF in the TCP segments that match the receive string.

Impact

The monitor status code displays the correct server response code, but appends extraneous trailing characters. The monitor continues to function and respond to status changes as expected.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • An HTTP, HTTPS, or TCP monitor response code contains extraneous trailing characters, similar to the following example:

    Response Code: 200 (OKOKDate: 2017-10-24 11:54:17)

Workaround

To work around this issue, configure your servers to respond with a CR/LF after the response status line and before the receive string.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
