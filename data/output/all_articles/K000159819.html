K000159819: F5OS Tenant cannot start/boot up, stuck in Pending state.

Type
Support Solution
Published
2026-01-29
Updated
2026-01-29
Applies to

Source
https://my.f5.com/manage/s/article/K000159819

Description

After redeploying tenants on F5OS-A rSeries platforms, tenants may remain stuck in the pending state. The tenant status does not progress to running, and the following log messages are observed in the host appliance logs:

qat-confd-service[123]: priority="Info" version=1.0 msgid=0x6e04000000000002 msg="." func="find" infostr="no matches for vcpu_count(4) qat_device_count(6)         m_unbound.size(1) floor_time(1769673569) ceiling_time(1769673689) variation(60)".
qat-confd-service[123]: priority="Info" version=1.0 msgid=0x6e04000000000002 msg="." func="runPartitionUpdateHandler" infostr="Terminating search since device mapping not found for tenant <tenant-name>".

Environment

  • F5OS-A version 1.5.2
  • rSeries platforms

Cause

This issue is caused by Bug ID 1567945. When tenants are moved to the config state and redeployed, the qat-devs.json file may become corrupted or contain stale entries. This prevents the QAT device from being properly allocated to the tenant, resulting in the tenant being stuck in the pending state.

Answer/Recommended Actions

  1. Immediate Workaround: Reboot the host appliance to clear the stale QAT device allocation and allow tenants to start successfully.
  2. Permanent Resolution: Upgrade to F5OS-A version 1.8.0 or later, where this issue is resolved.

Impact of workaround: Rebooting the host appliance will cause all tenants to be temporarily unavailable during the reboot process.
