Known Issue

This is the result of a known issue. Performing the config sync command between redundant BIG-IP WebAccelerator module systems can appear to fail and display the following error message:
 

Wed Mar 14 12:00:00 EDT 2007

Saving active configuration...

Configsync Mode: Push

Transferring UCS to peer...

Installing UCS on peer...

SOAPException: 'Unexpected return Content-Type: text/html; charset=iso-8859-1'

Transport and install failed

Error running config sync all.

BIGpipe unknown query error:

01110001:3: Error running config sync all

Wed Mar 14 12:05:00 EDT 2007

This error is received because the config sync process on the system sending the configuration has timed out waiting for the system receiving the configuration to respond within the 300 second timeout value defined in the httpd configuration. The system receiving the configuration fails to respond in time because it is busy re-importing the pre-defined acceleration policies into the WebAccelerator database.

Important: The config sync process eventually finishes on the system receiving the configuration.

F5 Networks Product Development tracked this issue as CR72614 and it was fixed in BIG-IP WebAccelerator module  version 9.4.2.  For information about upgrading, refer to the BIG-IP WebAccelerator Release Notes.

Workaround

Note: When you use this workaround, the pre-defined acceleration policies will properly synchronize between the redundant systems because the pre-defined policies are identical on both systems.

To work around this issue by preventing the pre-defined acceleration policies from being synchronized and re-imported into the database, move the pre-defined acceleration policies to an alternate location, by performing following procedure:

  1. Log in to the WebAccelerator command line.

  2. Change directories to the default WebAccelerator policy directory, by typing the following command:

    cd /usr/local/wa/config/policies/predefined

  3. Create an alternate location to which the pre-defined acceleration policies can be moved, by typing the following command:

    mkdir tmp

  4. Move the pre-defined acceleration policies to the alternate location, by typing the following command:

    mv *.xml tmp
