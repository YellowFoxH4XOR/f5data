Topic

The Receive Message too short message occurs when the big3d agent receives something other than an ICMP ECHOREPLY in response to its ICMP ECHO.

Because one message is logged for every packet, 3-DNS may log a high volume of these messages. For example, if the big3d agent sends 20 packets for QoS measuring on a particular path, you will see 20 packets for that path. This message indicates that an intermediate device cannot reach the specified destination.

In 3-DNS Controller version 3.0, these messages are more verbose and are logged at the crit and emerg log levels.

Note: In 3-DNS Controller version 4.0.1, there are fewer messages logged at the crit and emerg levels. As such, you would have to lower the log level for syslog to see these messages.

In general, these messages are harmless. If 3-DNS, BIG-IP, and the hosts are probed properly, they can be ignored. For more information about changing the log level, refer to K1035: Configuring the level of information that syslog sends to log files.
