K12614: Overview of the 'Allow session to continue without client certificate for tunnel connections' feature

Topic

Starting in FirePass versions 6.1.0, 7.0.0, and 6.0.3 with HF-603-2.1 installed, the Allow session to continue without client certificate for tunnel connections feature has been added to the Device Management: Security: User Access Security page.

By enabling this option, users will not be repeatedly prompted to present their client certificates when attempting to establish a Dynamic or Static AppTunnel, or a Network Access Favoritel. Without this option enabled, the user's browser is responsible for handing the client certificate. Each browser handles client certificates differently. For example, Internet Explorer 6 (IE6) users are only prompted to present their certificate during the initial authentication process; however, Internet Explorer 7 (IE7) users are prompted at logon, as the tunnel starts and when a connection is established to a backend server.

After enabling the Allow session to continue without client certificate for tunnel connections option, IE7 and later users will be prompted in the same manner as IE6 users. FirePass uses the existing client certificate session, rather than attempting to establish new sessions at each point during the process of establishing a tunnel session. As a result, the number of prompts are reduced.

F5 Product Development tracked this Request for Enhancement as ID 296565 (formerly CR70987), and it was introduced in FirePass versions 6.1.0 and 7.0.0. For information about upgrading, refer to the FirePass release notes.

Additionally, this enhancement has been added in cumulative hotfix HF-603-2.1, which has been issued for FirePass version 6.0.3. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.
