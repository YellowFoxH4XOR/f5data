What Happened?

  • What are the NTP servers configured on Customer Edge (CE) and how does NTP flow work on Distributed Cloud?

Environment

  • F5® Distributed Cloud Customer Edge

Resolution/Answer

  • After registration CE is using our REs (Regional Edge) as NTPs. If users define their custom NTP servers, the default Volterra NTP will be ignored. The default NTP server used are: volterraNtp = []string{"169.254.0.10", "169.254.0.11"}

  • Before registration, we use NTP servers in pool.ntp.org.

More details

Before CE gets registered, there are several ways that CE will sync with time server:

    1. Sync with the NTP server configured by user. NTP server can be configured by VPM admin shell "configure" command, VM property prompt during OVA creation, etc...
    2. If NTP is not configured on OS, OS tries to fetch time with the underlay BIOS. For example the time configured on ESXi, iDrac or iLO.
    3. As last resource, OS tries to sync time with the NTP server below:
  • pool 2.rhel.pool.ntp.org iburst <- for RHEL
server 0.centos.pool.ntp.org iburst <- for CentOS same as below.
server 1.centos.pool.ntp.org iburst
server 2.centos.pool.ntp.org iburst
server 3.centos.pool.ntp.org iburst
  • Thus, you must ensure, Customer Edge time can be synced by any of the three options mentioned above.
  • Allowlist, open above domains for NTP port (UDP 123).

Additional Information

  • It is not a valid option to wildcard all *.pool.ntp.org as it is thousands of IP addresses (see https://www.pool.ntp.org/zone/@).
