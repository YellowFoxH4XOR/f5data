Topic

You should consider using this procedure under either of the following conditions:

  • You want to increase the size of requests that the BIG-IP PSM security policy is allowed to process.
  • You want to allow large requests to bypass the BIG-IP PSM security policy.

Description

By default, the BIG-IP PSM system does not process requests larger than 10 megabytes. The system terminates requests that exceed this size. If your environment requires a larger request limit, for example, to accommodate large file uploads, the BIG-IP PSM processing limit can be increased to 20 megabytes. This limit is defined by the long_request_buffer_size internal parameter.

Note: Beginning in BIG-IP PSM 11.x, the processing limit can be increased to 30 megabytes.

In the case of still larger requests, you can configure the BIG-IP PSM system to bypass the security policy when a request exceeds the limit defined by the long_request_buffer_size internal parameter. You can modify the default behavior (to terminate the connection with a TCP RST) by configuring the EnableASMByPass internal parameter.

Note: If a request exceeds the limit defined by the long_request_buffer_size internal parameter, the PSM system will protect no part of the request. The request will be terminated or else bypass the security policy if bypass is enabled.

For example:

You can configure the internal parameters with the values shown in the following example:

long_request_buffer_size 15000000

EnableASMByPass 0

With the previous configuration, the BIG-IP PSM system behaves in the following manner:

  • The BIG-IP PSM security policy processes requests that are smaller than 15MB, as normal.
  • The system blocks requests that are larger than 15MB and resets the connection.

You can configure these internal parameters with the values shown in the following example:

long_request_buffer_size 15000000

EnableASMByPass 1

With the previous configuration, the BIG-IP PSM system behaves in the following manner:

  • The BIG-IP PSM security policy processes requests smaller than 15MB, as normal.
  • The system passes requests larger than 15MB to the origin web server and bypasses the BIG-IP PSM security policy.

Beginning in BIG-IP PSM 10.3.0 HF6 and 10.4.0 HF3, the enforce_rfc_in_long_request internal parameter is added, which allows enforcement of RFC compliance, geolocation, and IP reputation violations for requests that exceed the long_request_buffer_size limit. By default, the enforce_rfc_in_long_request internal parameter is disabled and has a value of 0. You can enable the parameter by setting its value to 1.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have administrative command line access.
  • In the case of BIG-IP PSM 10.2.2, to use this procedure, you have installed Hotfix-BIGIP-10.2.2-852.0-HF1 or later.

Procedures

Configuring the long request limit

To modify the long request limit from the default value, perform the following steps:

Impact of procedure: You must restart the BIG-IP PSM service, resulting in a brief service interruption.

  1. Log in to the command line.
  2. Configure the long request limit using the following command syntax:

    /usr/share/ts/bin/add_del_internal add long_request_buffer_size <value in bytes>

    For example, to configure the long request limit to the maximum value (20mb), enter the following command:

    /usr/share/ts/bin/add_del_internal add long_request_buffer_size 20000000

  3. Commit the change by restarting the BIG-IP PSM service by entering the following command:

    bigstart restart asm

    Important: This step causes a brief interruption of BIG-IP PSM services.

    Note: Although this procedure affects the BIG-IP PSM system, as noted in this step, you restart the ASM process to restart the BIG-IP PSM system.

Configuring the EnableASMByPass internal parameter

To modify the behavior when long_request_buffer_size is exceeded, perform the following procedure:

Impact of procedure: If you configure the system so large requests bypass the BIG-IP PSM system, the BIG-IP PSM security policy does not evaluate connections. F5 recommends that you thoroughly evaluate and test such a change to ensure that the configuration is appropriate for the security needs of your specific environment.

  1. Log in to the command line.
  2. To enable large requests to bypass the BIG-IP PSM security policy, enter the following command:

    /usr/share/ts/bin/add_del_internal add EnableASMByPass 1

  3. Commit the change by restarting the BIG-IP PSM service with the following command:

    bigstart restart asm

    Important: This step causes a brief interruption of BIG-IP PSM services.

    Note: Although this procedure affects the BIG-IP PSM system, as noted in this step, you restart the ASM process to restart the BIG-IP PSM system.

To return the BIG-IP PSM system to the default configuration and block all requests that exceed the long_request_buffer_size value, repeat the previous steps, except enter the following command in step 2, instead of the command shown in step 2:

/usr/share/ts/bin/add_del_internal add EnableASMByPass 0

Configuring system behavior when the long request limit is exceeded and EnableASMByPass is enabled

To enforce RFC compliance, geolocation, and IP reputation violations for bypassed requests that exceed the long_request_buffer_size when EnableASMByPass is enabled, perform the following procedure:

Impact of procedure: If you configure the system so that large requests bypass the BIG-IP PSM system, the BIG-IP PSM security policy does not enforce all violations. F5 recommends that you thoroughly evaluate and test such a change to ensure that the configuration is appropriate for the security needs of your specific environment.

  1. Log in to the command line.
  2. To enable enforcement of RFC compliance, geolocation, and IP reputation for large requests that exceed the long_request_buffer_size when EnableASMByPass is enabled, enter the following command:

    /usr/share/ts/bin/add_del_internal add enforce_rfc_in_long_request 1

  3. Commit the change by restarting the BIG-IP PSM service with the following command:

    bigstart restart asm

    Important: This step results in a brief interruption of BIG-IP PSM services.

    Note: Although this procedure affects the BIG-IP PSM system, as noted in this step, you restart the ASM process to restart the BIG-IP PSM system.

To return the enforce_rfc_in_long_request internal parameter to the default configuration and bypass all requests that exceed the long_request_buffer_size value without any enforcement, repeat the previous steps, except enter the following command in step 2, instead of the command shown in step 2:

/usr/share/ts/bin/add_del_internal add enforce_rfc_in_long_request 0
