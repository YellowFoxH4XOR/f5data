Description

You have configured multiple destionations in the syslog include configuration which looks like below:

sys syslog {
    ---snipped---
    include "
    destination d_ltm {
         file(/var/log/ltm create_dirs(yes));
    };
    destination d_dns {
         file(/var/log/gtm create_dirs(yes));
    };
    destination d_waf {
         file(/var/log/asm create_dirs(yes));
    };
    destination d_mgmt {
         file(/var/log/secure create_dirs(yes));
    };
    destination remote_server {
         udp(\"192.168.11.111\" port (514));
         udp(\"192.168.11.112\" port (514));
    };
    ---snipped---
    "
}

After you perform an upgrade for the BIG-IP version, there are scrolling following logs when you execute command journalctl -fu syslog-ng in the BIG-IP CLI which indicates the syslog-ng service is in restart loop.

<hostname> syslog-ng[<PID>]: [<timestamp>] WARNING: Default value changed for the prefix() option of systemd-journal source in syslog-ng 3.8; old_value='', new_value='.journald.'
<hostname> syslog-ng[<PID>]: [<timestamp>] Error checking the uniqueness of the persist names, please override it with persist-name option. Shutting down.; persist_name='affile_dd_writers(/var/log/ltm)', location='/etc/syslog-ng/syslog-ng.conf:1549:10'
<hostname> syslog-ng[<PID>]: [<timestamp>] Error checking the uniqueness of the persist names, please override it with persist-name option. Shutting down.; persist_name='affile_dd_writers(/var/log/gtm)', location='/etc/syslog-ng/syslog-ng.conf:1552:10'
<hostname> syslog-ng[<PID>]: [<timestamp>] Error checking the uniqueness of the persist names, please override it with persist-name option. Shutting down.; persist_name='affile_dd_writers(/var/log/asm)', location='/etc/syslog-ng/syslog-ng.conf:1555:10'
<hostname> syslog-ng[<PID>]: [<timestamp>] Error checking the uniqueness of the persist names, please override it with persist-name option. Shutting down.; persist_name='affile_dd_writers(/var/log/secure)', location='/etc/syslog-ng/syslog-ng.conf:1558:10'
<hostname> systemd[<PID>]: syslog-ng.service: main process exited, code=exited, status=2/INVALIDARGUMENT
<hostname> systemd[<PID>]: Failed to start System Logger Daemon.
<hostname> systemd[<PID>]: Unit syslog-ng.service entered failed state.
<hostname> systemd[<PID>]: syslog-ng.service failed.
<hostname> systemd[<PID>]: syslog-ng.service holdoff time over, scheduling restart.

Environment

  • Upgrade BIG-IP version to 13.1.0 or later

  • Multiple destionations in the syslog include configuration

  • Command journalctl -fu syslog-ng in the BIG-IP CLI

Cause

A missing persist-name() for the destination in the syslog include configuration that was accepted in earlier versions is rejected in the new version which prevents syslog-ng from starting.

The improper configuration passes validation and can be loaded successfully during the BIG-IP version upgrade, this is ID1074841.

Recommended Actions

You can follow procedures below to resolve this issue.

  1. Add unique persist-name() to each destination

sys syslog {
    ---snipped---
    include "
    destination d_ltm {
         file(/var/log/ltm create_dirs(yes) persist-name(ltm));
    };
    destination d_dns {
         file(/var/log/gtm create_dirs(yes) persist-name(dns));
    };
    destination d_waf {
         file(/var/log/asm create_dirs(yes) persist-name(waf));
    };
    destination d_mgmt {
         file(/var/log/secure create_dirs(yes) persist-name(mgmt));
    };
    destination remote_server {
         udp(\"192.168.11.111\" port (514));
         udp(\"192.168.11.112\" port (514));
    };
    ---snipped---
    "
}

  1. Then restart syslog-ng service with command tmsh restart sys service syslog-ng
