K000163571: BIG-IP Edge Client automatic upgrade leaves some installed components at older versions

Type
Support Solution
Published
2026-10-06
Updated
2026-10-06
Applies to
  • BIG-IP
  • BIG-IP APM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000163571

Description

After BIG-IP Edge Client automatically upgrades during a connection to BIG-IP APM, some installed files may still show older version numbers. A direct installation of the newer client package may update more files than the automatic upgrade. For example, after an Edge Client upgrade, an administrator may see older versions of:


  • urSuperHost.dll
  • f5vpn.exe

Environment

  • BIG-IP APM
  • BIG-IP Edge Client
  • Component update enabled in the Connectivity Profile applied to the APM Virtual Server

Cause

A customized client installation package can include various components. The Edge Client’s automatic update checks the client application version and updates components required for the current connection, based on the agents in the Access Policy applied to the Virtual Server. Browser-based access follows a different client-component workflow. For BIG-IP APM 13.0.0 and later, browser connections use F5 helper applications rather than the standalone Edge Client update workflow.


Answer/Recommended Actions

  1. Identify which files remain at older versions. Use the Client Troubleshooting Utility (CTU) to review installed services and components.
  2. Check the workflow in which those components are used. If the affected component is used by a browser-based APM connection, test that workflow and compare the file versions again.
  3. Investigate a component that remains outdated when required. If a component required for the tested connection does not update, collect the CTU report and the connection details and contact F5 Support.
  4. Use a customized installation package when deploying a selected set of components together.


Additional Information

The connectivity profile’s Component Update setting governs Edge Client update behavior, but No does not prevent every component update.
