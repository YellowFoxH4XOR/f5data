K11023: Importing shares from Data Domain filers fails when NFSv3 UDP is enabled in the namespace

Topic

Starting in ARX version 5.0.5, ARX supports Data Domain for use as an NFS file server. However, current versions of Data Domain do not support NFSv3 UDP. When importing NFS shares from a filer running Data Domain, NFSv3 UDP must be disabled in the namespace. If NFSv3 UDP is enabled, the import will fail. Additionally, ARX will log an error message to the syslog that appears similar to the following example:

Oct 21 05:35:58 localhost 2009-10-21T05:35:58.583+0000:arx1:1-1-ACM-6101:SMGMT-0-ERR-MSG3:: [SMGMT-UDP] Failed NFSv3 FSINFO for share share SID 137, (192.168.1.185:/public/home1)
Oct 21 05:35:58 localhost 2009-10-21T05:35:58.591+0000:arx1:1-1-ACM-28856:SMGMT-0-ERR-MSG3:: [SMGMT-UDP] Failed NFSv3 FSINFO for share share SID 142, (192.168.1.184:/public/home2)

Important: Additional limitations exist for Data Domain filers. For more information, refer to K10909: F5 Networks Data Solutions Compatibility Matrix.

To prevent this issue from occurring, disable NFSv3 UDP on the namespace where <namespace-name> is the name of the namespace:

For example:

ARX01# global
ARX01(gbl)# namespace <namespace-name>
ARX01(gbl-ns[<namespace-name>])# no protocol nfs3

Important: Changing a protocol setting on a namespace may require disabling or destaging all volumes in the namespace. For information about disabling or destaging volumes, refer to the ARX CLI Maintenance Guide.
