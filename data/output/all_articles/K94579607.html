Description
If you do not wish to receive all known BIG-IP traps, and you cannot filter traps from your SNMP management console / SNMP trap receiver and would like to disable the traps, follow the below procedure.

Environment

  • SNMP Trap
  • Logging 

Cause
None

Recommended Actions

To disable SNMP traps on BIG-IP you must have Advanced Shell (bash) access with root read/write permissions to perform this procedure

Impact of procedure: This procedure backs up the default alert.conf into /config, and creates a symbolic link for alertd to load it, and restarts alertd

  1. Modify the default alert.conf configuration in the /config directory
    # cp /etc/alertd/alert.conf /config/alert_modified.conf

  2. Edit /config/alert_modified.conf and comment out all the snmptrap directives that you do not want.
    # vi /config/alert_modified.conf

  3. Move / backup the original alert.conf into the /config directory
    # mv /etc/alertd/alert.conf /config/alert.conf

  4. Create a symbolic link from /etc/alertd/alert.conf to your modified configuration:
    # ln -s /config/alert_modified.conf /etc/alertd/alert.conf

  5. Check that the link exists:
    # ls -la /etc/alertd/alert.conf
    lrwxrwxrwx. 1 root root 18 Jul 28 02:47 /etc/alertd/alert.conf -> /config/alert_modified.conf

  6. Restart alertd
    # bigstart restart alertd
     

To revert the changes to original configuration follow below steps. 

Impact of procedure: This restores the default configuration after the above procedure has been applied

  1. Ensure the original file exists
    # ls -la /config/alert.conf
    -r--r--r--. 1 root root 37999 Jun 23 10:59 /config/alert.conf

  2. Verify that the default location for alert.conf is a symbolic link:
    # ls -la /etc/alertd/alert.conf
    lrwxrwxrwx. 1 root root 18 Jul 28 02:47 /etc/alertd/alert.conf -> /config/alert_modified.conf

  3. Remove the symlink
    # rm /etc/alertd/alert.conf

  4. Restore the original file
    # cp /config/alert.conf /etc/alertd/alert.conf

  5. Restart alertd
    # bigstart restart alertd

  Note: These procedures will not survive an upgrade.  This procedure will need to be repeated if the BIG-IP is upgraded or another new boot location is started up.
