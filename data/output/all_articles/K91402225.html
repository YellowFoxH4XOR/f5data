Description

You have configured one or more NTP servers on your BIG-IP.
And at the time of running "ntpq" command to check the daemon status is stuck on "INIT". Below you can see an example of how it looks:
 

[device1@bigip1:Peer Time Out of Sync:Changes Pending] ~ # ntpq -np
remote           refid      st t when poll reach   delay   offset  jitter
==============================================================================
 X.X.X.X         .INIT.     16 u    - 1024    0    0.000    0.000   0.000
 X.X.X.X         .INIT.     16 u    - 1024    0    0.000    0.000   0.000
 X.X.X.X         .INIT.     16 u    - 1024    0    0.000    0.000   0.000

NOTE: X.X.X.X represents your NTP server addresses.
NOTE: refid .STEP. means ntp has needed to perform an instantaneous change to your system clock. No action required and will be changed to NTP server IP.

Environment

  • BIG-IP / BIG-IQ
  • NTP

Cause

The restriction option is enabled in the NTP configuration:

tmsh list sys ntp all-properties
sys ntp {
    restrict {
        /Common/x.x.x.x { }
        /Common/y.y.y.y { }
        /Common/ntp-generic {
            default-entry enabled
            ignore enabled
        }
        /Common/ntp-specific { }
    }
    servers { x.x.x.x, y.y.y.y, z.z.z.z }
    timezone America/Chicago
}

Recommended Actions

  1. Verify the configuration by running this command:
    tmsh list sys ntp all-properties
     
  2. If enabled, remove the restriction setting by running this command:
    tmsh modify sys ntp restrict none
     
  3. Verify the configuration running this command:
    tmsh list sys ntp all-properties

    Now, it should be set to none:
    sys ntp {
    ...
        restrict none                
    ...
     
  4.  Save the configuration:
    save sys config
     
  5.  Restart the ntp process:
    restart /sys service ntpd
