Description

You can configure your BIG-IP APM system to log BIG-IP APM network access (VPN) users connecting to a web service.

After users connect to BIG-IP network access, VPN, they can connect to different web services in the corporate network. You may want to log usage data such as which user is accessing a web service through VPN; this data can be useful when scaling your servers or troubleshooting.

Environment

  • BIG-IP APM network access, VPN traffic
  • You want to understand and log the usage data of a web service (pool of web servers) due to your VPN users

Cause

None

Recommended Actions

The following procedures assume you already configured a BIG-IP APM network access virtual server where users are connected. To log usage data to your web servers, you must configure the following resources on the same BIG-IP system:

  • Create an iRule to log usage data
  • Create a layered LTM virtual server with the iRule
    Note: This is a BIG-IP LTM virtual server listening on the connectivity profile of the BIG-IP APM network access virtual server, with the web server pool and iRule associated.

The following describes the traffic flow:

Client device ---(VPN traffic) -→ BIG-IP APM network access virtual server → BIG-IP LTM layered virtual server → Web servers

Create an iRule to log usage data

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > iRules.
  3. Select Create.
  4. Depending on the data that you want to log, enter your iRule. The following example logs the APM session ID, username, and IP addresses:

    when CLIENT_ACCEPTED {
       set current_user [ACCESS::session data get session.logon.last.username]
       set apmsessionid [ACCESS::session sid]
       log local0. "APM sessionID: $apmsessionid : USER $current_user connected to [IP::local_addr]:[TCP::local_port] from NA leasepoolIP [IP::remote_addr] through layeredVS [virtual]"
    }
    With this iRule, when a user accesses the web service, you may observe an output in the /var/log/ltm file similar to the following example:

    info tmm4[12236]: Rule /Common/iRuleName <CLIENT_ACCEPTED>: APM sessionID: 5ac89[...]744182c0: USER ann connected to 10.5.4.2:443 from NA leasepoolIP 10.5.1.4 through layeredVS /Common/layeredVSName

  5. To get more information about the user's APM session, run the grep command on the APM session ID that is logged. For this example, you would enter the following command on bash:

    grep 744182c0 /var/log/apm

Note that you can modify the iRule as appropriate for your logging requirements. For example, you can modify the event for which the iRule will be triggered to HTTP_REQUEST. For more logging iRule examples, refer to the following articles:

  • K82485132: How to match subnet of the client IP in iRule
  • K86071030: iRule to log connection on SSL/TLS versions with client IP address
  • K42210592: iRule to log HTTP Request and Response headers for specific client IPs
  • The ACCESS namespace on F5 Cloud Docs

Create a layered LTM virtual server with the iRule

For more information about layered virtual servers, refer to K03113285: Overview of BIG-IP APM layered virtual servers.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Virtual Servers.
  3. Select Create.
  4. Use the following information to enter the required parameters.
     
    ParameterValue
    NameEnter an appropriate name.
    Destination Address/MaskEnter the IP address that VPN users use to access the web service.
    Service PortEnter the port number of the web service. Note: This is typically 443.
    HTTP Profile (Client)http
    SSL Profile (Client)clientssl (for HTTPS web service)
    SSL Profile (Server)serverssl (if your servers are HTTPS web servers)
    VLAN and Tunnel TrafficSelect Enabled on... 
    Select the Connectivity profile of your BIG-IP APM network access virtual server.
    Source Address TranslationAuto Map (if required in your environment)
    iRules    Select the iRule created in the previous procedure.
    Default PoolSelect + to create a pool of your web servers.
    Or select the name of your pool if one is already created.
  5. Select Finished.
