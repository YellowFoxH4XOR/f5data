Description
In situation of sync failure, when looking at config between the two units in an HA pair and finding there is a huge discrepancy, for example the standby is missing 100 virtual servers, you may want to take a more aggressive approach to fixing the sync.

The reason is that fixing one issue of sync conflict, in such a huge discrepancy situation, can lead to the 2nd error or point of failure to load, and fixing the 2nd point of failure will lead to the 3rd error, the 4th and so on. In situation like that, a more appropriate approach will be to clear the synced config from the standby, then sync from active.

Note: In the example mentioned previously, the active BIG-IP would be the the BIG-IP that has the up-to-date/complete configuration. 

When syncing on the WebUI, you may see a similar error to the below:
Sync error on host.mydomian.com: Load failed from 01.mydomian.com 01070734:3: Configuration error: Modify of node attribute is not permitted.
 
On /var/log/ltm logs you may see  a similar error to the below:
01020066:3: The requested Pool Member (/Common/pool /Common/pooMember-192.168.1.1 443) already exists in partition Common.

Environment
BIG-IP HA Pair

Cause
Not keeping good practice of sync after each update.

Recommended Actions
Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Note: If you have not already created UCS on both BIG-IPs, please do now.

Note: Make sure you have the root/admin passwords.

  1. On the standby BIG-IP, perform the following steps.
    1. Create a backup of current bigip.conf. For example, mv /config/bigip.conf /config/bigip.conf-Jan132021, replacing "Jan132021" with the current date.
    2. Create an empty bigip.conf file using the following command: touch /config/bigip.conf.
    3. Load the empty config file to memory using the following command: tmsh load sys config.
       
  2. On the active BIG-IP, perform the following steps.
    1. Push a full sync configuration from the active BIG-IP to the Standby BIG-IP, by navigating to the Device Management > Overview page in the WebUI.
