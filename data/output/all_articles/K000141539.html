K000141539: VXLAN tunnels may continue to send traffic after db entires deleted

Type
Support Solution
Published
2024-10-21
Updated
2024-10-21
Source
https://my.f5.com/manage/s/article/K000141539

Description

VXLAN tunnels may continue to send traffic after FDB entries are deleted. These may be static FDB entries configured for tunnels in multipoint mode or dynamic FDB entries for tunnels in multicast mode.

Environment

Relevant environmental factors specific to the topic

  • BIG-IP Classic
  • VXLAN tunnel

Cause

TMM maintains an internal cache of VXLAN tunnel endpoints (VTEPs) which is separate from the FDB. This can result in what appears to be FDB entries continuing to function after they are deleted.

There is currently no way to inspect or clear the VTEP cache.

Recommended Actions

None

Additional Information

The VTEP cache timeout is configurable using the sys DB key iptunnel.vxlan.vtepidletimeout which defaults to 300 (seconds).

You can view the cache timeout in tmsh using the command:

list /sys db iptunnel.vxlan.vtepidletimeout

And edit it using the "modify" verb. For example, to set to 180 seconds:

modify /sys db iptunnel.vxlan.vtepidletimeout value 180
