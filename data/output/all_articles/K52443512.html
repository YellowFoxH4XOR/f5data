Known Issue

The system does not set the error message on the user-supplied variable when you use the catch command on the TCL_ERROR.

This issue occurs when the following condition is met:

  • You have configured an iRule using the catch command on the TCL_ERROR, which sets an error message on a user-supplied variable.

For example, the following example demonstrates the issue with the catch command, resulting in a missing error message:

ltm rule rule_node_test {
    when CLIENT_ACCEPTED {
        set n "test"
        set cr [catch {pool $n} message]
        log local0. "cr: '$cr', message: '$message'"
    }
}

Notice that the message is empty in the /var/log/ltm output:

local/tmm info tmm[4902]: Rule rule_node_test <CLIENT_ACCEPTED>: cr: '1', message: ' '

Impact

The error message is missing from the log entry.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The system receives a Tool Command Language (Tcl) exception on a variable, but does not post an error message.

Workaround

To work around this issue, you can use the ::errorInfo variable instead of the catch command, as follows.

Impact of workaround: Performing the following workaround should not have a negative impact on your system.

For example:

set static::errorInfo {$::errorInfo}
<Custom iRule logic>
log local0. "error: [subst $static::errorInfo]"

If you use the static::errorInfo variable, the system can capture error messages for user-supplied variables; declaring the variable as static prevents it from interfering with Clustered Multiprocessing (CMP), as the variable is declared locally and not globally.
