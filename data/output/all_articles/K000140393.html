Description

Changing or updating the mode of Port Groups under Network Settings may pop up an error similar to:

State optic-state: QUALIFIED_MODE_MISMATCH

Environment

  • F5OS-A
  • F5OS-C
  • Port Groups

Cause

It's common to have a qualified optic inserted but the incorrect mode configured for the kind of optic it is. This happens when, for example, you have a 40G QSFP+ inserted, but the blade still has the portgroup mode set to the 'MODE_100GB'. The mode and the optic kind are mismatched.

Recommended Actions

Check the port-group configuration:

# show running-config portgroups

--snip--
portgroups portgroup 2/1
config mode MODE_100GB    <-- This portgroup is currently configured for 100G.
config ddm ddm-poll-frequency 30
!

Check what's inserted in the port:

# show portgroups

--snip--
portgroups portgroup 2/1
state vendor-name   "F5 NETWORKS INC."
state vendor-oui    009065
state vendor-partnum  "OPT-0036    "
state vendor-revision A2
state vendor-serialnum "X2FA2LE     "
state transmitter-technology "850 nm VCSEL"
state media      40GBASE-SR4          <-- But a 40G QSFP+ is inserted.
state optic-state   QUALIFIED_MODE_MISMATCH    <-- There's a mismatch between this transceiver and the portgroup mode.

--snip--    

In the F5OS user interface, you can set the port-group mode to the appropriate setting for the inserted optic.

Additional Information

Since F5OS-A 1.8.0, ID1583813 is fixed, which results in QUALIFIED_MODE_MISMATCH.  https://my.f5.com/manage/s/article/K000138830 states a mismatch *can* prevent a link from coming up, but in F5OS-A 1.8.0 on r5k/r10k it's a *will* prevent.
