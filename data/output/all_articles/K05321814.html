Topic

The vCMP feature allows you to provision and manage multiple instances of the BIG-IP software on a single hardware platform. The vCMP host is the system-wide hypervisor that runs BIG-IP instances, known as guests. vCMP guests are instances of the BIG-IP software that you create on the vCMP host for the purpose of processing application traffic. The guest instances contain the local traffic objects, such as virtual servers, pools, and monitors. As the BIG-IP administrator, you need to know which administrative tasks to perform on the vCMP host system and which tasks to perform on the vCMP guests.

Description

The following table lists common administrative tasks and whether to perform the tasks on the vCMP host, the vCMP guest(s), or on both.

Task categoryAdministrative taskHost or Guest(s)Details
System managementLicensingHostPerform license activation on the vCMP host; each guest inherits the license of the host.

Note: Reactivating the vCMP host license results in a temporary traffic interruption on guest systems.

ProvisioningHost and Guest(s)
  • Host: Provision the vCMP module on the host.
  • Guest(s): Provision BIG-IP modules, such as BIG-IP LTM, BIG-IP DNS, BIG-IP ASM, on the individual guests.
Disk allocationHostManage and allocate disk space on the vCMP host.
UpgradingHost and Guest(s)
  • Host: Perform upgrades for the host by downloading the ISO image to the host and running the upgrade from the host.
  • Guest(s): Perform upgrades for the guest(s) by downloading the ISO image to the host and running the upgrade from the individual guest.
Upgrade orderHost and Guest(s)Plan the order for host/guest upgrades according to the following guidance:
  • To determine vCMP host/guest compatibility for your platform, refer to K14088: vCMP host and compatible guest version matrix.
  • If you are upgrading the vCMP system to a version that would temporarily result in the vCMP host and guest running incompatible versions, F5 recommends that you upgrade the guest instance first and then activate the boot location for the newly upgraded guest. Next, on the vCMP host, set the upgraded guest to the Provisioned state. You can then safely upgrade the vCMP host to the new, compatible version. Once you have rebooted the host to the new version, set the vCMP guest to Deployed.
  • For other cases, F5 recommends that you upgrade the host first.
Installation imagesHostDownload and retain BIG-IP installation image (ISO) files to the host system; the images are available when upgrading and installing software on the host and guest(s).
RebootingHost and Guest(s)
  • Host: Perform host restarts by logging in to the host system. Before restarting a host, you should perform a graceful shutdown of all guest systems running on the host.
  • Guest(s): Perform guest restarts by logging in to the individual guest system.
Backing upHost and Guest(s)
  • Host: Perform backups for the host by logging in to the host system and creating a UCS archive.
  • Guest(s): Perform backups for the guest(s) by logging in to each guest system and creating a UCS archive.
NetworkVLANsHostConfigure VLANs on the host; the VLANs are then available for selection on the vCMP guest system(s) as needed.
TrunksHostConfigure trunks on the host.
InterfacesHostConfigure interfaces on the host.
Self IPsGuest(s)Configure self IP addresses on the guest(s) and associate them with VLANs.
Module configurationLocal TrafficGuest(s)Configure local traffic features, such as virtual servers, pools, monitors, and iRules, on the guest(s).
Application SecurityGuest(s)Configure application security features, such as security policies, DoS protection, and Bot defense, on the guest(s).
Global TrafficGuest(s)Configure DNS features, such as wide IPs, data centers, DNSSEC zones, on the guest(s).
Access PolicyGuest(s)Configure access policy features, such as portal and application access on the guest(s).
Advanced FirewallGuest(s)Configure advanced firewall features, such as network firewall policies on the guest(s).
High availability (HA)Device groupsGuest(s)Configure device groups on vCMP guest(s); you should not configure high availability features on the host.
FailoverGuest(s)Configure failover on vCMP guest(s); you should not configure high availability features on the host.
ConfigSyncGuest(s)Configure ConfigSync on the vCMP guest(s).
MirroringGuest(s)Configure traffic mirroring on the vCMP guest(s).
SecurityCertificate managementHost and Guest(s)
  • Host: Perform host device certificate management tasks on the host.
  • Guest(s): Perform traffic certificate management tasks for virtual servers on the individual guest. Perform guest device certificate management tasks on the guest(s).
Access controlsHost and Guest(s)
  • Host: Configure access control to the host by other host administrators, by defining user accounts, roles, and partition access on the host.
  • Guest(s): Configure access control to the guest(s) by other guest administrators, by defining user accounts, roles, and partition access on the guest(s).
