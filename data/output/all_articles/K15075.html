Known Issue

A self IP name may be incorrectly interpreted as an IP address.

This issue occurs when the following condition is met:

  • A self IP name resembles an IP address (n.n.n.n) but does not match the actual IP address of the self IP.

    For example, the following name/IP address combinations encounter this issue:

    Self IP name /Common/1.1.1.1 and a self IP address of 1.1.1.1%3 (route domain 3)
    Self IP name /Common/1.1.1.0 and a self IP address of 1.1.1.1

Impact

Attempts to create a self IP may fail if the name is interpreted as a non-matching IP address, and the system configuration may not load after an upgrade to an affected version.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H451359 on the Diagnostics > Identified > Medium screen.
  • You are unable to create the self IP, and you receive an error message similar to the following example:

    0107162c:3: Name (/Common/1.1.1.1) encodes address (1.1.1.1) which does not match address (1.1.1.1%3)
  • After upgrading from an earlier unaffected version, if you attempt to roll a configuration forward that contains an affected self IP name, the configuration fails to load and displays an error message similar to the following example:

    0107162c:3: Name (/Common/1.1.1.1) encodes address (1.1.1.1) which does not match address (1.1.1.1%3) Unexpected Error: Loading configuration process failed.

Workaround

There is no workaround for this issue. However, to prevent this issue, you can ensure self IP names do not resemble IP addresses. If a self IP name must resemble an IP address, ensure that the self IP name exactly matches the self IP address.

For example, a self IP name of 1.1.1.1%4 functions correctly for a self IP address of 1.1.1.1%4.
