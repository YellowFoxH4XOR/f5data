Known Issue

TCP stream corruption may occur when a VLAN is configured with 802.1QnQ (double tagging).

This issue occurs when the following condition is met:

  • Double tagging is configured on the VLAN processing traffic.

Impact

TCP connections fail.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Packet traces of the connection show TCP acknowledgements using incorrect ACK numbers based on the amount of received data.
  • Applications that rely on the affected connections malfunction or experience degraded functionality.

Workaround

To work around this issue, you can set the tm.tcplargereceiveoffload database variable to disable. To do so, perform the following procedure:

Impact of workaround: You must restart the Traffic Management Microkernel (TMM) after modifying the tm.tcplargereceiveoffload database variable, which temporarily interrupts traffic processing. F5 recommends that you perform this procedure only during a maintenance window.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. To set the tm.tcplargereceiveoffload variable to disable, type the following command:

    modify /sys db tm.tcplargereceiveoffload value disable

  3. Restart TMM by typing the following command:

    restart /sys service tmm
