Known Issue

The BIG-IP ASM Configuration utility becomes unresponsive when accessing extractions.

This issue occurs when all of the following conditions are met:

  • An extraction is configured with thousands of URLs to extract from.
  • You attempt to display the Extraction List (Application Security > Parameters > Extractions) or to display the properties of an extraction. 

Impact

Administrators are unable to display the Extraction List or the properties of an extraction.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Administrators are unable to display the Extraction List or the properties of an extraction.
  • The system logs error messages in the /var/log/httpd/httpd_errors file that display similar to the following example:

    err httpd[<pid>]: [error] [client <client_ip>] PHP Fatal error: Maximum execution time of 30 seconds exceeded in /var/ts/dms/common/classes/thrift/transport/TTransport.php on line 87, referer: https://192.168.20.197/dms/policy/pl_param_extracts.php">https://<vip_ip>/dms/policy/pl_param_extracts.php

Workaround

If the extraction can apply to all URLs, you can work around this issue by manually configuring the security policy to extract from all items. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. From the Configuration utility, export the security policy in XML format.
  2. Find the start of the extractions.

    For example:

    <extraction name="__<extraction_name>">

  3. Find the following XML file setting:

    <extract_globally>false</extract_globally>

    Change the setting to appear as follows:

    <extract_globally>true</extract_globally>

  4. Remove all extract_from_url lines in the XML file.

    For example:

    <extraction_from_url name="/<url_previously_configured_for_extraction>" protocol="HTTP" type="explicit"/>

  5. Import the modified XML policy into the Configuration utility
