Known Issue

A BIG-IP APM access policy configured with the Active Directory query action may cause TMM to panic when the attribute is replicated to the standby unit.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system is configured with high availability
  • The Active Directory query returns an attribute larger than 64 KB

Impact

A failover event occurs.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The user login appears to stop responding until the failover completes. The user then receives the following message:

    Session Expired/Timeout
    Due to user inactivity, your session expired. Click the following link to start a new session.

  • A TMM core file exists in the /var/core directory.
  • The /var/log/tmm file has an entry that appears similar to the following example:

    notice panic: ../modules/hudproxy/ha/ha_proxy.c:1870: Assertion "ha pkt is within size limit" failed.

Workaround

To work around this issue, you can define the attributes to import in the AD Query action. To do so, perform the following procedure:

Impact of workaround: You must define each Active Directory attribute that you want to use in the Required Attributes list.

  1. Log in to the Configuration utility.
  2. Click Access Policy.
  3. Click Access Profiles.
  4. Click Edit in the row of the access policy you want to edit.
  5. Click AD Query.
  6. Click Add new entry.
  7. Enter the name of the AD attribute to import.

    For example:

    distinguishedName

  8. Repeat steps 6 through 7 for each attribute to import.
  9. Click Save.
  10. Click Apply Access Policy.
  11. Click Close.
