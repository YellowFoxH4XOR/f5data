K10945: The BIG-IP WebAccelerator may corrupt origin web server responses that use single line feed separators

Known Issue

This is the result of a known issue. When an origin web server (OWS) uses a single line feed (LF) character instead of a carriage return/line feed (CRLF) sequence to separate HTTP headers, the BIG-IP WebAccelerator may corrupt the response. For example, the BIG-IP WebAccelerator may add extra characters to the message body. In some cases, the the pvac process may also crash.

Although the missing CR character makes the OWS response non-RFC compliant, RFC2616 section 19.3: Tolerant Applications, notes the following:

The line terminator for message-header fields is the sequence CRLF. However, we recommend that applications, when parsing such headers, recognize a single LF as a line terminator and ignore the leading CR.

F5 Product Development tracked this issue as CR128042 and it was fixed in BIG-IP 10.1.0. For information about upgrading, refer to the BIG-IP LTM release notes.

Workaround

You can work around this issue by configuring your OWS to use the expected CRLF sequence to separate HTTP headers according to RFC2616.
