Known Issue

The BIG-IP system may reset TCP connections prematurely when you use embedded Packet Velocity Acceleration (ePVA) full acceleration.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system has an ePVA chip.
  • Your BIG-IP system processes traffic with a TCP virtual server that has an associated FastL4 profile.
  • The FastL4 profile's Packet Velocity ASIC (PVA) acceleration value is set to Full.

Impact

The BIG-IP system prematurely resets a large number of TCP connections. The BIG-IP system may experience potential performance impact due to longer than expected idle TCP connections.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The system terminates a large number of TCP connections in a short period of time.
  • The TCP Handshake Timeout setting is not updated to the Idle Timeout setting after the system completes the handshake.

Workaround

To work around this issue, you can disable PVA acceleration on the FastL4 profile. To do so, perform the following procedure:

Impact of workaround: Disabling PVA acceleration may impact system performance and increase CPU utilization.

Note: F5 does not recommend that you modify a default profile. If an affected virtual server uses the default FastL4 profile, you should create a new custom FastL4 profile with PVA acceleration disabled and configure the affected virtual server to use the new custom FastL4 profile.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles > Protocol.
  3. To view the list of FastL4 profiles, click FastL4.
  4. Select the affected FastL4 profile.
  5. From the PVA Acceleration menu, select None.
  6. Click Update.
