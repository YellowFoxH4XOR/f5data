K8352: An iRule containing an HTTP::payload rechunk will not load

Known Issue
Published
2008-02-19
Updated

Source

Known Issue

This is the result of a known issue. An iRule containing the HTTP::payload rechunk iRule command will not load. The iRule reports the following error message:

[< procedure: rechunk] [HTTP::payload rechunk]

For example:

rule testing {
when HTTP_RESPONSE {
HTTP::payload rechunk
}
}

When the example iRule is loaded from the command line with the bigpipe load command, the following message displays:

config # bigpipe load
Reading configuration from /config/bigip_base.conf.
Reading configuration from /usr/bin/monitors/builtins/base_monitors.conf.
Reading configuration from /config/profile_base.conf.
Reading configuration from /config/daemon.conf.
Reading configuration from /config/bigip.conf.
Reading configuration from /config/bigip_local.conf.
Loading the configuration ...
BIGpipe rule creation error: <==
01070151:3: Rule [testing] error: <==
line 2: [< procedure: rechunk] [HTTP::payload rechunk] <==

F5 Networks Product Development tracked this issue as CR85181 and it was fixed in BIG-IP LTM version 9.4.4. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Additionally, this issue was fixed in hotfix BIGIP-9.4.3-14.3-HF3 issued for BIG-IP version 9.4.3. You may download this hotfix or a later version of this hotfix from the F5 Networks Downloads site.
