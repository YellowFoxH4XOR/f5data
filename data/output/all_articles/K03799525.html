Topic

The embedded Packet Velocity Acceleration chip (ePVA) is a powerful but limited resource that provides an alternate, faster packet path for network traffic. This update provides a means to prioritize traffic to specific virtual servers, giving you the ability to select which traffic gets access to the limited resource. 

Description

In some use cases, for example service providers, virtual servers have traffic flows that range from very high bandwidth (such as backups) to high bandwidth (such as video) to medium (such as audio) and so on. When managing the ePVA flow accelerator utilization, in such cases, you may need to ensure that very high bandwidth applications get the priority ahead of other applications.

Introduced in BIG-IP 15.x, this feature allows you to add priority to the ePVA offload entries instead of all the ePVA entries having the same priority. You can also configure the BIG-IP system to observe, learn the traffic flow rate, and dynamically adjust the priority. This allows higher byte-rate flows to achieve higher priority and lower byte-rate flows to get lower priority in ePVA offload. This enables connections to better utilize the ePVA flow cache instead of using it equally for all flows, regardless of the byte rate of the flows that are offloaded, thus maximizing the efficient use of hardware acceleration.

Note: A flow differs from a connection. There are typically two flows per-connection (client side and server side).

New fastL4 configuration settings

This feature adds the following new configuration parameters to the FastL4 profile:

  • PVA TCP Offload Direction specifies the direction that the ePVA can offload TCP traffic. Options include Bidirectional, Client to Server Only, and Server to Client Only. For example, when Client to Server Only is selected, the ePVA does not offload traffic from server to client, even if the traffic threshold is exceeded.
  • PVA Offload Initial Priority specifies the initial priority level for traffic flows that you want to the system to insert into the flow accelerator and the flow priority to use when PVA Offload Dynamic Priority is set to Disabled. Options are Low, Medium, and High. The default is Medium.
  • PVA Offload Dynamic Priority specifies whether flows have their ePVA priority adjusted dynamically. When set to Enabled, the system automatically adjusts flow priority based on throughput, flow table occupancy and collision rate . This provides a prioritization mechanism that supports application-level control of which flows utilize the limited FPGA resources. If this option is set to Disabled, the system does not dynamically adjust ePVA priority on flows. Instead, the system uses the PVA Offload Initial Priority value. The default is Disabled.

    Note: This applies only to UDP and TCP traffic only and the ePVA platforms only. For the list of ePVA platforms, refer to K12837: Overview of the ePVA feature.

New database variables

Along with the configuration parameters, the feature introduces the following database variables:

  • pva.priorityratethresholdkb.low is the ePVA low bitrate threshold and defaults to 1 Kbps.
  • pva.priorityratethresholdkb.medium is the ePVA medium bitrate threshold and defaults to 50 Kbps.
  • pva.priorityratethresholdkb.high is ePVA high bitrate threshold and defaults to 5 Mbps.

When PVA Offload Dynamic Priority is enabled and the ePVA thrash rate exceeds the ePVA thrash threshold, the previously listed database variables set the boundaries at which the priority of flows are determined in the following scenarios.

Note: The ePVA thrash rate is calculated every second and is the number of ePVA evictions due to collisions divided by the number of successful ePVA inserts. The ePVA thrash threshold defaults to 0.3..

Important: F5 carefully tunes the default database variable settings. You should use extreme care when you modify the settings. Configuring threshold values that are too low or high may lead to thrashing and inefficient use of the ePVA hardware.

Initial insertion priority

When a flow is offloaded to hardware and initially inserted, the BIG-IP system calculates the initial value of Per-Flow Exponential Moving Average bit-rate and uses the boundary set by the database variables to determine the priority of the flow. For example, if the Per-Flow Exponential Moving Average bit-rate value is lower than the pva.priorityratethresholdkb.low threshold, the flow is not offloaded to hardware. If the value is between the low and medium threshold values as defined by the database variables, the flow inserted has low priority, and so on.

Subsequent insertion priority

With offload dynamic priority enabled, the BIG-IP system continues to calculate the Per-Flow Exponential Moving Average bit-rate value every second. Just like the initial insertion scenario, this value is used to determine the priority of subsequent insertions the same way.

Dynamic priority adjustments

For flows that is in hardware, the BIG-IP system continues to calculate the Per-Flow Exponential Moving Average bit-rate value every three seconds. If the value is lower than the low or medium thresholds as defined by the database variables, the priority is set to low. If the value is between the medium and high threshold, the priority is set to medium, and so on.

Recommendations

You can observe the priority of the client-side and server-side flows of your virtual server using the tmsh command. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the TMOS Shell (tmsh )by typing the following command:

    tmsh

  2. To display the connections for your virtual server use the following command syntax:

    show sys connection virtual-server <VS-name> all-properties

    For example:

    show sys connection virtual-server exampleFastL4VS all-properties

In the following settings example, a FastL4 profile with the following setting is associated to the virtual server:

  • PVA TCP Offload Direction: set to Bidirectional
  • PVA Offload Initial Priority: set to High
  • PVA Offload Dynamic Priority: set to Enabled
