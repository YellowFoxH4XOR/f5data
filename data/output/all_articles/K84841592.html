K84841592: How to verify SAML signature and encryption with 'xmlsec1'

Published

Applies to

  • BIG-IP APM: 16.X.X, 16.1.X, 16.0.X, 16.1.3, 16.1.2, 16.1.1, 16.1.0, 16.0.1, 16.0.0
Source
https://my.f5.com/manage/s/article/K84841592

Description

With 'xmlsec1' you can decrypt the SAML assertion and verify its signature.
BIGIP v16 and later allows you to use 'xmlsec1' from CLI.

Environment

  • APM is configured as SAML SP.
  • SAML IdP is sending;
    •   An encrypted assertion that you need to decrypt
    •   A signed assertion that you need to verify.

Cause

You hit a SAML signature validation error on APM SAML SP

Recommended Actions

1. You need to obtain the private key from bigip.conf configuration file to decrypt the assertion
apm aaa saml /Common/OC_SP {
    idp-connectors {
        /Common/OAS_IdP { }
    sp-signkey /Common/saml-lab
    
sys file ssl-key /Common/saml-lab {
    cache-path /config/filestore/files_d/Common_d/certificate_key_d/:Common:saml-lab_432587_1

2. You need to obtain the public key from bigip.conf configuration file to verify the signature

apm aaa saml-idp-connector /Common/OAS_IdP {
    idp-certificate /Common/OAS_IdP__saml_idp_metadata_cert.crt
 
sys file ssl-cert /Common/OAS_IdP__saml_idp_metadata_cert.crt {
    cache-path /config/filestore/files_d/Common_d/certificate_d/:Common:OAS_IdP__saml_idp_metadata_cert.crt_432565_1

3. Run these tasks from CLI once APM SAML SP receives the SAML Auth Response

4. URL decode and base64 decode the SAML Auth Response from the tcpdump and copy it to input.xml
5. Run the 'xmlsec1' command with private key 'sp-signkey'. There will be errors like "unable to get local issuer certificate" but assertion will be decrypted. These errors can be ignored 

xmlsec1 --decrypt --output output.xml --privkey-pem /config/filestore/files_d/Common_d/certificate_key_d/:Common:saml-lab_432587_1 input.xml

6. If the assertion is signed, you can verify the signature with this 'xmlsec1' command. This time you need to use public certificate "idp-certificate". If SAML Auth Response was encrypted you can use the output.xml file as input

xmlsec1 --verify --pubkey-cert-pem /config/filestore/files_d/Common_d/certificate_d/:Common:OAS_IdP__saml_idp_metadata_cert.crt_432565_1 --id-attr:ID urn:oasis:names:tc:SAML:2.0:assertion:Assertion --store-references --store-signatures output.xml

Besides verifying the signature,' xmlsec1' will dump "PreDigest data" and "PreSigned data".
This information is useful in case there is an issue matching digest or verifying the signature.

"PreDigest data" should match "Canonicalized Assertion" in access logs.
"PreSigned data" should match match "Canonicalized SingedInfo" in access logs
