K000163011: Characters, emojis and other items are not rendering when a DoSL7 profile is assigned to the virtual server.

Type
Support Solution
Published
2026-08-20
Updated
2026-08-20
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000163011

Description

Emoji and other wide or multibyte UTF-8 characters may display as invalid characters, gibberish, or replacement symbols in an application when a BIG-IP L7 DoS profile is attached to a virtual server.

The issue can occur even when the DoS profile is configured in Transparent mode. This is due to the Javascript (JS) that happens whether it is in Blocking or Transparent mode. Removing the DoS profile allows the characters to display correctly.

Environment

  • UTF-8 characters in the HTML
  • Chinese or other language characters, emojis
  • The character set is defined by an HTML <meta> tag rather than the HTTP Content-Type header
  • The application contains more than one <meta> tag
  • L7 DoS Application Security profile

Cause

ID795497 covers an issue where character sets are not displaying correctly. However, there can be other issues where symptoms similar to this ID can occur.;

For example Chrome and Firefox require that the Charset declaration is present within the first 1024 bytes. But, after the injection, the Charset declaration UTF-8 is moved after 4435 bytes.

The ID solution works when the Charset declaration is located in the first meta tag in the HTTP response (most cases), but in this case it's included in the second meta tag. <head>
<meta name="GENERATOR" content="Microsoft SharePoint" />
<meta http-equiv="Content-type" content="text/html; charset=utf-8" />
...

The standard solution for ID795497 is after,meta,before,script,before,/head,before,body. The JS injection can be injected in 4 different places: 

  • Priority 1: after, meta
  • Priority 2: before, script
  • Priority 3: before, /head
  • Priority 4: before, body <head>
    <meta name="GENERATOR" content="Microsoft SharePoint" />
    <APM_DO_NOT_TOUCH> <--------------- Script was injected AFTER FIRST META TAG
    <meta http-equiv="Content-type" content="text/html; charset=utf-8" />
    ...

Answer/Recommended Actions

When the application has multiple <meta> tags and the charset declaration is not the first one, change the injection order so BIG-IP does not use the after,meta anchor.

Run the following command on the BIG-IP device:tmsh modify sys db dosl7.parse_html_inject_tags value before,/head,before,/body

This changes the available injection locations to:

  1.     Before the closing </head> tag
  2.     Before the closing </body> tag if </head> is unavailable

The JavaScript is therefore inserted after the existing <meta charset="utf-8"> declaration, leaving the charset declaration in its original position.

Considerations:

1) This is a global sys db variable — it will change injection anchor behavior for all VIPs on the box using DoS/SPA/Bot Defense JS injection, not just dosl7_http_Spus. Confirm whether other applications behind other DoS/Bot Defense profiles could be affected by this anchor-order change (in practice, injecting after meta instead of after head should be a safe, non-breaking reordering, but review is still warranted since this is production).

2) No restart is required for sys db variables in general, but confirm this specific one takes effect immediately by testing right after the change (some like this dosl7-related setting apply to newly established connections/responses immediately since it's read by tmm at injection time, not just at daemon startup).
