Known Issue

Configuration synchronization (ConfigSync) may fail when an SSL profile has different certificate key chain names on each of the BIG-IP systems in a high-availability (HA) configuration.

This issue occurs when all of the following conditions are met:

  • The BIG-IP systems in the HA configuration are performing a full ConfigSync operation.
  • An SSL profile is attached to a virtual server.
  • The SSL profile's certificate key chain name is different on the HA devices.

Impact

Configurations updated using ConfigSync may not load properly on the standby host, and HA may be compromised.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You notice error messages in the /var/log/ltm file that appear similar to the following example:

    0107149e:3: Virtual server /Common/example_vip has more than one clientssl/serverssl profile with same server name.
    010717e1:3: Client SSL profile cannot contain more than one set of same certificate/key type.

  • ConfigSync may fail, or if ConfigSync succeeds, the SSL profile has two certificate key chain objects on the receiving device.

Workaround

To work around this issue, log in to each device in the HA device group to compare the SSL profile certificate key chain name for the virtual server object that fails to load to determine the correct one. Then, you can edit the appropriate /config/bigip.conf file so all devices have the same correct cert-key-chain name for the affected SSL profile. You can then synchronize the configuration.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.

  1. Log in to the Advanced Shell (bash) on each device in the HA device group.
  2. Create a backup copy of the /config/bigip.conf file by typing the following command:

    cp /config/bigip.conf /config/bigip.conf.K16218

  3. Using a text editor, open the /config/bigip.conf file and locate the virtual name from the error message.
  4. Under profiles, determine the SSL profile name. In the following example, the SSL profile is named example_ssl:

    ltm virtual /Common/example_vip {
        destination /Common/192.168.10.100:80
        ip-protocol tcp
        mask 255.255.255.255
        pool /Common/example_pool
        profiles {
            /Common/tcp { }
            /Common/example_ssl {
                context clientside
            }
        }
    }

  5. Locate the SSL profile determined from step 4 in the bigip.conf file.
  6. Under cert-key-chain, determine the cert-key-chain name. In the following example, the cert-key-chain is named my_key_chain.

    ltm profile client-ssl /Common/example_ssl {
        app-service none
        cert-key-chain {
            my_key_chain {
                cert /Common/example.crt
                key /Common/example.key
            }
        }
     }

  7. After determining the correct name for the cert-key-chain, edit the cert-key-chain name and save the bigip.conf file.
  8. Validate that there are no configuration load errors by typing the following command:

    tmsh load sys config verify

    Note: If there are no errors, proceed to the next step; otherwise, go back to step 3.

  9. Load the system configuration by typing the following command:

    tmsh load sys config

    The BIG-IP systems should now successfully synchronize.
