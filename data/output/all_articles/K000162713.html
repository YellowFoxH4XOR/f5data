Description

  1. Configure the DNS lookup servers
    Configure DNS before enabling SSRF enforcement.
    1. Log in to the BIG-IP Configuration utility.
    2. Go to System > Configuration > Device > DNS.
    3. Under DNS Lookup Server List, add one or more trusted recursive DNS server addresses.
    4. Place the preferred DNS server at the top of the list.
    5. Click Update.

    The configured DNS servers must be reachable from the BIG-IP and able to resolve the hostnames used by the application.

    When multiple servers are configured, BIG-IP normally queries the first server in the list. It uses a subsequent server if the previous server returns an error or times out. For more information, see K66202843: How the DNS Server Order Works when using multiple servers.

    • DNS traffic is permitted from the BIG-IP to the configured servers.
    • The appropriate route domain and routing path are available.
    • The DNS servers can resolve approved external and internal application domains.
    • DNS responses are not being blocked by an upstream firewall.

     

  2. Enable SSRF protection in the security policy
    1. Go to Security > Application Security > Security Policies > Policy List.
    2. Select the required security policy.
    3. Open Advanced Protection > SSRF Protection.
    4. Enable SSRF protection.
    5. Configure the SSRF Hosts list.

    The SSRF Hosts list should contain only approved hostnames, IP addresses, or CIDR ranges.

    For example:

    example.com

    Use the hostname only. Do not include:

    • URL scheme
    • Port
    • URL path
    • Filename
    • Query string
    • Fragment

    For example, configure:

    example.com

    Do not configure:

    example.com/path/file.jpg

    Use the narrowest possible allowlist. Add wildcard domains only when the application legitimately requires access to multiple subdomains.

     

  3. Configure the parameter value type
    When configuring the relevant application parameter, Parameter Value Type can be set to Auto detect.
    1. Go to Security > Application Security > Parameters > Parameter List.
    2. Create or edit the applicable parameter.
    3. Set Parameter Value Type to Auto detect.
    4. Save the configuration and apply the security policy.

    With Auto detect, ASM examines parameter values and can identify URL-like values as URI values. This allows SSRF processing to inspect URI parameters without requiring every parameter to be manually configured as a URI.

    Auto detection is useful when:

    • The application has many URL parameters.
    • The exact URI parameters are not known.
    • URLs may occur in query strings, JSON, or multipart form-data.
    • Broad SSRF inspection is required.

    However, Auto detect can also classify application data that resembles a URL. This may cause ASM to perform DNS processing for values that were not explicitly configured as URI parameters.

    When the URI parameter is known, it may be configured explicitly as a URI to limit SSRF inspection to the intended parameter. Auto detect remains valid when broad automatic URI detection is required.

     

  4. Configure the SSRF host action
    Configure an appropriate action for each SSRF host entry.
    • Allow — permits access to an approved hostname or address.
    • Deny — blocks access to the specified host or address.
    • Resolve — resolves a hostname and evaluates the resulting address according to the SSRF policy.

    For a trusted destination, use an explicit host-only allow entry:

    example.com Allow

    Maintain deny entries for destinations that should never be accessed through URI parameters, including:

    • Loopback addresses
    • Private network ranges
    • Link-local addresses
    • Cloud metadata endpoints
    • Other internal or reserved address ranges

    Do not broadly allow private address space unless the application specifically requires it and the security impact has been reviewed.

     

  5. Configure the SSRF violation
    1. Go to Security > Application Security > Policy Building > Learning and Blocking Settings.
    2. Expand the parameter-related settings.
    3. Locate Server-side access to disallowed host.
    4. Enable Alarm and Block according to the deployment stage.
    5. Save and apply the policy.

    Use Alarm while validating legitimate application destinations. After the approved hosts have been confirmed, enable Block to enforce SSRF protection.

Additional Information

Troubleshooting No DNS Record Found

If ASM generates No DNS Record Found for an approved host:

  1. Confirm that the host-only entry is present in the SSRF Hosts list.
  2. Confirm that the DNS servers are configured under System > Configuration > Device > DNS > DNS Lookup Server List.
  3. Verify that the hostname resolves successfully from the BIG-IP console: dig <hostname> @<DNS IP address> for example, dig www.f5.com @8.8.8.8 

Recommended configuration summary

  1. Configure trusted DNS servers under System > Configuration > Device > DNS > DNS Lookup Server List.
  2. Confirm DNS reachability and hostname resolution.
  3. Enable SSRF protection in the ASM security policy.
  4. Add approved hostnames to the SSRF Hosts list using host-only entries.
  5. Configure the relevant parameter with Parameter Value Type = Auto detect when automatic URI detection is required.
  6. Use an explicit URI parameter when the URL-bearing parameter is known and inspection should be narrowly scoped.
  7. Enable Server-side access to disallowed host with Alarm and Block.
  8. Test encoded, multipart, JSON, and path-based URL values.
