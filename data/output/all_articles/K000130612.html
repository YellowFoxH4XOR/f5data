Description

If the device has HT-split enabled (most appliance platforms), you may observe high CPU usage in odd-numbered CPU cores.

Environment
  • BIG-IP AFM
  • Logging AFM messages to /Common/local-syslog
  • Large amount of messages written to /var/log/ltm constantly (hundreds or thousands messages per second)
Cause
Large amount of local logging will drive up CPU usage of alertd and syslog-ng. BIG-IP is not intended as a logging device. If there are many log messages, send them to remote logging server instead.
Recommended Actions
  1. Verify that alertd and syslog-ng are having high CPU usage by running either one of the following commands.

    # top

    # tmctl proc_pid_stat -s proc_name,cpu_usage_5mins -OK cpu_usage_5mins -L 10
     
  2. Verify that there are many messages being written to /var/log/ltm by running the following command:

    # tail -f /var/log/ltm

    You may see new messages being written constantly (hundreds or thousands of messages per second).
     
  3. Verify that you have configured to log AFM messages locally. You may have configurations similar to the following in /config/bigip.conf:

    sys log-config publisher /Common/my_log_publisher {
        destinations {
            /Common/remote_splunk { }
            /Common/local-db { }
            /Common/local-syslog { }   <===
        }
    }

    security log profile /Common/global-network {
        built-in enabled
        description "Default logging profile for network events"
        dos-network-publisher /Common/my_log_publisher   <===
        ip-intelligence {
            log-geo enabled
            log-publisher /Common/my_log_publisher   <===
            log-rtbh enabled
            log-scrubber enabled
            log-shun enabled
            log-translation-fields enabled
        }
        network {
            global-network {
                filter {
                    log-acl-match-drop enabled
                }
                publisher /Common/my_log_publisher
            }
        }
        protocol-dns {
            global-dns { }
        }
        protocol-dns-dos-publisher /Common/my_log_publisher   <===
        protocol-sip-dos-publisher /Common/my_log_publisher   <===
        traffic-statistics {
            log-publisher /Common/my_log_publisher   <===
            syncookies enabled
        }
    }
     
  4. To reduce CPU usage, send AFM logs to remote logging servers instead of logging locally. Remove /Common/local-syslog from the log publisher and add remote logging server if necessary.
