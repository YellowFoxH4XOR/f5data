Known Issue

This is the result of a known issue. When you configure a BIG-IP WebAccelerator parameter value substitution for a leaf node, you must define a Target type. The Target type determines which parameters in the links embedded in the origin web server (OWS) response that the BIG-IP WebAccelerator system will re-write with alternate values. When the Target type is defined as Query Parameter and the request is proxied (S code S10201, S10202, S10232, etc.), the BIG-IP WebAccelerator system does not substitute the intended values in the matching query parameter targets that are embedded in the response. As a result, links embedded in the response page may not function as expected.

Note: This issue does not occur if the BIG-IP WebAccelerator returns responses from its Smart Cache (S code S10101, S10102, etc.).

Note: Other target types, such as Unnamed Query Parameter and Path Segment, are not affected, and the BIG-IP WebAccelerator system performs the expected substitutions on proxied responses.

Note: Parameter value substitution is configured in the BIG-IP WebAccelerator Configuration utility on the Assembly Policy tab of the leaf node. For more information, refer to the Configuring Assembly Rules chapter of the Policy Management Guide for the BIG-IP WebAccelerator.

For example, note the following sequence of events:

  • The following configuration instructs the BIG-IP WebAccelerator to parse each OWS response for any embedded link that contains a parameter named url, then replace its value with the encoded request URI:

    Source Type:             Request URL
    Target Type:                 Query Parameter    
    Parameter name:        url
  • The BIG-IP WebAccelerator virtual server receives a request for the following URI and proxies the request to the OWS:

    http://www.site.com/mypage.jsp?entity=orange

  • The OWS response contains the target parameter url within an embedded link:

    <a href="http://www.site.com/page2.jsp?url=&ID=123456">

  • After substitution, the embedded URL, as served by the BIG-IP WebAccelerator system, is expected to appear as follows:

    <a href="http://www.site.com/page2.jsp?url=http%3A%2F%2Fwww.site.com%2Fpage1.jsp%3Fentity%26orange&ID=123456">

  • Due to the known issue described, the BIG-IP WebAccelerator does not substitute the value of the request parameter for the target parameter, and the following unmodified link is returned:

    <a href="http://www.site.com/page2.jsp?url=&ID=123456">

F5 Product Development tracked this issue as ID 338520, and it was fixed in BIG-IP version 11.0.0. For information about upgrading, refer to the BIG-IP WebAccelerator release notes.
