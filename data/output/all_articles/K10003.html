Known Issue

This is the result of a known issue. If you configure a protected configuration custom check that contains a logical operator (AND, OR, or NOT) in addition to a greater than ( > ), a greater than or equal to ( >= ), a less than ( < ), or a less than or equal to ( <= ) operator, users fail the custom check even if they meet the defined criteria.

Important: This issue only occurs after installing cumulative HF-603-2 or HF-603-2.1 on the FirePass controller.

For example, users would fail the following custom check even if they met the defined criteria:

session.fw.summary.count>=1 AND session.av.McAfeeAV.database_age<5

This issue does not affect the relational operators equal to ( == ) and not equal to ( != ). For example, the following custom check expression would work correctly:

session.fw.summary.count!=0 AND session.av.McAfeeAV.database_age==5

A protected configuration is a collection of safety measures or checks that guard the connection and client system against various kinds of attacks or threats. A protected configuration custom check allows FirePass administrators to define a customized check based on information collected by a pre-logon sequence. Protected configurations are configured on the Users: Endpoint Security: Protected Configurations page.

Note: For more information about protected configurations, refer to the FirePass Controller Administrator Guide.

F5 Networks Product Development tracked this issue as CR120102 and it was fixed in FirePass version 6.1.0. For information about upgrading, refer to the FirePass Release Notes.

Additionally, this issue was fixed in cumulative HF-603-3, which was issued for FirePass version 6.0.3. You may download this hotfix or a later version of the cumulative hotfix from the F5 Networks Downloads site.
