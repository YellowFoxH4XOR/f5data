Topic

The BIG-IP ASM logs requests in the /var/log/asm file.

Description

The log requests appear similar to the following example:

asm dcc[2895]: 01310038:2: [SECEV] Request violations: Illegal object length,Illegal request length,Illegal object type,Non-existent object. support id: 211251080305049616, source ip: 172.16.63.94, xff ip: 0.0.0.0, HTTP classifier: MyASMClass, scheme HTTP, request: <GET /register.php? HTTP/1.1\r\nHost: 172.16.63.66\r\nUser-Agent: Mozilla/5.0 (X11; U; Linux i686; en-US; rv:1.9.0.14) Gecko/200>

The requests are formatted using the following syntax:

Note: Beginning in BIG-IP ASM 11.6.0, security events are no longer logged to the /var/log/asm file by default. This behavior is now controlled by the send_content_events internal parameter. F5 recommends enabling the send_content_events parameter only for troubleshooting purposes due to a potential decrease in performance.

BIG-IP ASM 11.6.0 and later

<Rejection Description> <Request Violation> <Support ID> <Source IP> <XFF IP> <Source Port> <Destination IP> <Destination Port> <Route Domain> <HTTP Classifier> <Scheme> <Geographic Location> <Request> <Username> <Session ID> <Violation Rating>

BIG-IP ASM 11.1.0 through 11.5.1

<Rejection Description> <Request Violation> <Support ID> <Source IP> <XFF IP> <Source Port> <Destination IP> <Destination Port> <Route Domain> <HTTP Classifier> <Scheme> <Geographic Location> <Request> <Username> <Session ID>

BIG-IP ASM 10.1.0 through 11.0.0

<Rejection Description> <Request Violation> <Support ID> <Source IP> <XFF IP> <Source Port> <Destination IP> <Destination Port> <HTTP Classifier> <Scheme> <Geographic Location> <Request>

BIG-IP ASM 9.4.0 through 10.0.1

<Rejection Description> <Request Violation> <Support ID> <Source IP> <XFF IP> <HTTP Classifier> <Scheme> <Request>

Each section of the request is defined in the following table.

SectionDescription
Rejection DescriptionEmpty unless the request is blocked by the policy
Request Violation(s)A comma separated list of the violation(s) that occurred during enforcement of the request/response
Support IDSupport ID assigned to violation by the system to allow the system administrator to track
Source IPThe source IP where the request originated
XFF IPThe X-Forwarded-For (XFF) IP address. This is the IP address located in the XFF header.
Source PortThe source port from which the request originated
Destination IPThe destination IP of the request
Destination PortThe destination port of the request
Route DomainRoute Domain where request originated
HTTP ClassifierSpecifies the name of the HTTP Class or Security Policy
SchemeSpecifies whether the request was made using HTTP or HTTPS
Geographic LocationThe two letter country code of origin based on source IP
RequestThe actual request made including headers up to 128 bytes
UsernameUsername associated with the request
Session IDSession ID assigned to the request to allow the system administrator to track requests by session
Violation RatingRating between 1 and 5.  1 is most likely a false positive and 5 is most likely an attack.
