Known Issue

BIG-IP ASM may report legitimate request traffic as a violation (false positive).

This issue occurs when all of the following conditions are met:

  • Your BIG-IP ASM configuration uses an active security policy.
  • The BIG-IP ASM bd process loses synchronization with the security policy configuration files.
  • You upgrade the BIG-IP ASM device or fail over to a peer BIG-IP ASM device where the bd process is not synchronized.

Impact

BIG-IP ASM may report some legitimate requests as security policy violations.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When reviewing the BIG-IP ASM request log, you notice that legitimate traffic is logged as a violation.
  • When the access security policy is configured to block, the policy blocks legitimate traffic.
  • In the /var/log/bd directory, you notice log messages similar to the following example:

    ECARD|ERR   |<date and time>|<pid>|table.h:0287|KEY_REMOVE: Failed to REMOVE data

  • In the /var/log/asm directory, you notice log messages similar to the following example:

    info perl[24196]: 01310053:6: ASMConfig change: Allowed Method HEAD [delete] { audit: policy = /<partition>/<security policy name>, username = admin, client IP = 172.18.184.222 }
    notice g_server_rpc_handler.pl[<pid>]: 01310019:5: [USER_ACTIVITY] User admin performed Apply Policy operation on policy: /<partition>/<security policy name>. 2008.
    notice g_server_rpc_handler.pl[<pid>]: 01310019:5: [USER_ACTIVITY] User admin created history version for policy: /<partition>/<security policy name>. 2070.
    info perl[<pid>]: 01310053:6: ASMConfig change: Apply Policy /<partition>/<security policy name> [update] { audit: policy = /<partition>/<security policy name>, username = admin, client IP = <ip address> }
    err perl[<pid>]: 01310011:3: ASM configuration error: event code T1499 Failed to update configuration table CONFIG_TYPE_DYNAMIC_TABLES

Workaround

To work around this issue, you can restart the asm process of the affected BIG-IP ASM device. To do so, perform the following procedure:

Impact of workaround: While the asm process restarts, BIG-IP ASM does not process traffic.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Restart the asm process by typing the following command:

    restart /sys service asm

  3. Exit tmsh by typing the following command:

    quit
