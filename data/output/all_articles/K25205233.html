Description

  • After FIPS 140-2 license is installed on BIG-IP FIPS-certified hardware devices, the system halts while booting upon performing the FIPS integrity check
  • Console will show similar to:
           Starting System Logger Daemon...
      [ OK ] Started System Logger Daemon.
      [  14.943495] System halted.
     
  • BIG-IP software versions 14.1.0 and above where Bug ID 934941 is not fixed will not log to the console the specific FIPS integrity check failure.

Environment

The BIG-IP device has a license that includes the FIPS 140-2 option (FIPS full-box license)

  • System element monitored by FIPS 140-2 integrity check has changed
  • The device is rebooted

Cause

System halted while booting due to a FIPS integrity check failure. 
Potential causes of system halt:

  • Critical file modification which would be reported by running the utility /usr/libexec/sys-eicheck.py and also logged in /config/f5_public/fipserr 
  • Upgraded big3d installed in /shared/bin/big3d.

Recommended Actions

If on BIG-IP software version that contains a fix for Bug ID 739507, follow the below procedure to boot the device with FIPS integrity checking disabled:

  1. Connect a terminal to the BIG-IP serial console port
     
  2. From the serial console, enter the GRUB menu
     
  3. Before the countdown expires, use the Up Arrow and Down Arrow keys to stop the countdown, and select the appropriate boot image
     
  4. Press the key 'E' to start the edit options. A new GRUB menu displays
     
  5. Use the Up Arrow and Down Arrow keys to navigate to the line that starts with 'linux' , or the first line that starts with 'module' or the first line which contains 'vmlinuz'
     

  6. Enter the word NO_FIPS_INTEGRITY=1 at the end of the line, depending on the platform, the boot command may appear similar to the following example:

    linux /boot/1/vmlinuz ro root=UUID=7237fa64-e347-4bb7-a755-6e2617bd7c0e console=ttyS0 panic=1 platform=D113 NO_FIPS_INTEGRITY=1

    Then press ENTER  
     
  7. If a new line in the mini Editor appears and you're not sent to the GRUB menu, means the device has an old version of the GRUB and you need to cancel these changes (by pressing ESC key), then repeat steps 3 to 6 but instead of pressing ENTER you should press the Ctrl-X sequence or the F10 key to reboot with the modified options.
     
  8. If no a new line appears in the mini Editor, the edited line has been saved and you're sent back to the GRUB menu, here press 'b' to restart the system using the modified options
     
  9. The machine will boot into the partition containing FIPS 140-2-enabled license
     
  10. Examine the content of file /config/f5_public/fipserr to ascertain the cause of the FIPS module startup error
     
  11. Fix the problem reported in the aforementioned error file
     
  12. Run the test tool /usr/libexec/sys-eicheck.py to ensure that no fatal error is reported, such as:

    Integrity Check Result: [ FAIL ]

    If fatal error persists, do not reboot (otherwise the system will go into the halt state, and the steps starting from Step 1 will need to be repeated).
    Fix the problematic files reported.
    Re-run the /usr/libexec/sys-eicheck.py test tool until no error is seen.
    # /usr/libexec/sys-eicheck.py
     
  13. Remove the contents of the file /config/f5_public/fipserr
    # cat /dev/null > /config/f5_public/fipserr


If on BIG-IP software version that does not contain a fix for Bug ID 739507, follow the below procedure to boot the device into an alternate boot volume:

  1. The device needs to have serial console access.
     
  2. From the serial console, enter the GRUB menu and boot into a different boot location not having a FIPS 140-2 enabled license, or boot into TMOS Maintenance.
     
  3. On a VIPRION or chassis-based vCMP guest, stop mcpd to prevent the system from automatically rebooting back to the previous install location that has the FIPS 140-2 license:
    # bigstart stop mcpd
     
  4. Mount the disk volumes from the inactive boot location that has the FIPS 140-2 license (example below, but see K51222154 for details)
    Example from a non-raid platform:
      # lvdisplay | grep config
      LV Path                /dev/vg-db-sda/set.1._config
      LV Name                set.1._config
      LV Path                /dev/vg-db-sda/set.2._config
      LV Name                set.2._config
      LV Path                /dev/vg-db-sda/set.3._config
      LV Name                set.3._config

    # mkdir /mnt/test

    # mount /dev/vg-db-sda/set.3._config /mnt/test
     
  5. In the mounted volumes from the inactive boot location that has the FIPS 140-2 license, examine the contents of the file [mount location]/f5_public/fipserr to identify the files that were changed, leading to failure of the FIPS 140-2 license-enabled partition.
     
  6. In the mounted volumes from the inactive boot location, restore the identified files to their original ones (may need to mount additional volumes)
     
  7. In the mounted volumes from the inactive boot location, remove the contents of the file [mount location]/f5_public/fipserr
    # cat /dev/null > /mnt/test/f5_public/fipserr
     
  8. Reboot

    If system still halts, repeat from Step 1 above, until this no longer happens.
