K000139586: Certificate/key load errors after auto update of Cert Bundle

Type
Support Solution
Published
2024-05-13
Updated
2024-05-13
Applies to
  • BIG-IP
  • BIG-IP LTM: 16.1.4
Source
https://my.f5.com/manage/s/article/K000139586

Description

You can use the ca-bundle-manager component to automatically update and install CA-bundles on the system from two sources - local certificate file objects and remote URL resources.

Certificate and key loading problems arise from a race condition related to HA auto-sync and the automatic update of the CA Bundle Manager. This inconsistency occurs when the CA-bundle file is briefly deleted and then re-created.

The entry in the /var/log/ltm log might display one or several of the subsequent errors.

Apr 1 17:03:30 <HOSTNAME> crit tmm2[24040]: 01260027:2: Profile /Common/<Profile-Name> - cannot load Certificate Authority /config/filestore/files_d/Common_d/certificate_d/:Common:<CUSTOM_CA_BUNDLE.crt_66089_5>: Unknown error.

Apr 1 17:03:30 <HOSTNAME> crit tmm2[24040]: 01260027:2: Profile /Common/<Profile-Name> - cannot load Certificate Authority 

Connection error: hud_ssl_handler:1312: alert(40) invalid profile unknown on VIP /Common/<VS-Name> 

Environment

  • CA-bundle manager set up with configuration that includes a remote URL and is scheduled to update at regular intervals.
  • A Virtual Server configured with a client/server SSL profile referencing the CA-bundle file.
  • High Availability (HA) configured with auto-sync enabled.

Cause

ID 1585153 - CA bundle manager with auto-sync enabled leads to cannot load key/cert/chain

Note: The symptoms observed here closely resemble those of defect ID 1110485, with the distinction being the involvement of High Availability (HA).

Recommended Actions

To avoid the recurrence of defect ID1585153, disable one of the following features:

  • HA auto-sync
  • Automatic update of the Certificate Bundle Manager

Additional Information

To restore back functionality to the affected Virtual server(s), perform either of the procedures outlined below:

  • Remove the client/server SSL profile association from the virtual server, which is linked to the CA-bundle file. Reattach the client/server SSL profile to the virtual server.
  • Access the virtual server in the GUI and proceed to update it, with or without making any minor modifications.
