K6518: A zone cannot be created if a zone file of the same name already exists

Published

Known Issue

This is the result of a known issue. When a zone is deleted using ZoneRunner, the associated zone file is not deleted. Therefore, attempts to create a zone using the same zone name as the deleted zone will fail because the associated zone file still exists.

Attempts to create a new zone (with the same name) fail, and the system generates an error message to the /var/log/gtm file that appears similar to the following example:

zrd: 01150331:3: Error creating zone www.test.com, zone file /var/named/config/namedb/db.external.www.test.com. already exists

F5 Product Development tracked this issue as CR62605, CR62610, and CR68208 and it was fixed in BIG-IP GTM 9.2.4, 9.3.0, and 9.4.0. For information about upgrading, refer to the BIG-IP GTM release notes.

Note: CR65032 was created to track this issue for two or more synchronized BIG-IP GTM devices.

Workaround

You can work around this issue by manually deleting the applicable zone files from the /var/named/config/namedb/ directory. To do so, perform the following procedure:

  1. Log in to the BIG-IP GTM command line.
  2. Delete the undesired zone file by typing the following command:

    rm /var/named/config/namedb/<zone_file_name>

    For example, to delete a zone file for an external zone named www.test.com, you would type the following command:

    rm /var/named/config/namedb/db.external.www.test.com
