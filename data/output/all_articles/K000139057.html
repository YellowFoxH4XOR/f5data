K000139057: TMM memory leak is observed with FTP VS.

Type
Support Solution
Published
2024-03-27
Updated
2024-03-28
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.10
Source
https://my.f5.com/manage/s/article/K000139057

Description

TMM memory gradually increases on the active device, a memory leak behaviour is observed.

The output of tmsh show /sys memory will have 'traffic managment interface' as one of the highest memory consuming process. This is related to request-logging which is enabled.

Environment

  • BIG-IP LTM.
  • FTP virtual server with request-logging enabled.

Cause

The issue is related to Bug ID1550869, where TMM memory leak behaviour is observed due to specific type of virtual server which has FTP profile and response logging which uses ephemeral connections and the ratio matches. 

Recommended Actions

  1. To review the top 5 processes which has consumed the most memory in the last 24 hours, use the below given command through BASH.
    If the output shows 'traffic managment interface', refer point 2 for workaround.

    ls /shared/tmstat/snapshots/blade0/public/3600/* | while read file; do echo $file; tmctl -f $file memory_usage_stat -s name,allocated,cur_allocs -OK cur_allocs -L 5;done

  1. The two workaround to migitgate the issue are as follows
  • Remove request/response logging profile from the FTP virtual server and observed the behaviour.
  • Request an EHF for Bug ID1550869.

Note: EHF can only be request on latest release of every branch, refer K9502: BIG-IP hotfix and point release matrix

Additional Information

  • The issue with memory leak, only happens when you have a request-logging profile is associated with an FTP virtual-server. Request-logging profiles are ideally meant to be used for HTTP virtual server to log request/responses. 

  • When request-logging profile is enabled with FTP VS it will not be logging http response codes since this it is not an HTTP virtual server.
