Description

Loading UCS from platform/VE BIG-IP  to Tenant with platform-migrate option is failing. /var/log/ltm has logs similar to shared below

load_config_files[17729]: "/usr/bin/tmsh -n -g -a load sys config partitions all  platform-migrate" - failed. -- 01070674:3: Trouble allocating a trunk ID for trunk (trunk_object_name).
Unexpected Error: Loading configuration process failed.
 
2025 Jul  2 10:23:30 localhost.localdomain load_config_files[17729]: "/usr/bin/tmsh -n -g -a load sys config partitions all  platform-migrate" - failed. -- 01070674:3: Trouble allocating a trunk ID for trunk (trunk_object_name).

Environment

  • F5OS-A Tenant
  • UCS from Platform
  • platform-migrate

Cause

  • Bug ID 658943
  • The trunk (called LAG) is created in F5OS-A, not in Tenant, thus Tenant can not allocate ID for the Trunk object.

Recommended Actions

  • Log in to CLI of the Tenant (or original BIG-IP)
  • Run the below commands to extract the ucs file to a temporary directory
    mkdir /tmp/<foldername>
    tar xzvf <full path to your UCS archive> -C /tmp/<foldername>
  • Edit the bigip_base.conf file to remove the trunk object and any reference to it    vi /tmp/<foldername>/bigip_base.conf
  • Then pack up ucs file with the following commands:
    cd /tmp/<foldername>
    tar czvf /shared/<new_backup.ucs> *
  • Load the new ucs file
    tmsh load sys ucs /shared/<new_backup.ucs> no-license platform-migrate
