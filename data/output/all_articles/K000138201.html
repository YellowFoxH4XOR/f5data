Description

APM as a SAML SP can automate the creation of an IdP connector used to send SAML messages to the federated party. This procedure will create the idp connector on the bigip system and link it to an existing SAML Service Provider. The aim of this guide is to help explain how to get the IdP Automation working.

 

Environment

APM as a SAML SP

External IdP

 

Note

  1. It's difficult in most metadata files to get sensible information to use when configuring IdP Automation. If you're able to download the file, add tags to it, and host it internally or add tags to the file at the vendors site, this would be helpful. In the example below I added some tags for demonstration purposes and hosted the file internally
  2. When configuring the Connector Automation, the tags used can be child tags. If there's multiple tags with the same name, only the first one (top most tag) is used

Preparing For Automation

This information and configuration you'll need to get IdP Automation configured and working properly

  1. On the Bigip, you'll need:
    1. An existing SP configured under Access -> Federation -> SAML Service Provider -> Local SP Services
      1. This will be the service provider the automated IdP will connect to
    2. A Preconfigured DNS Resolver on the bigip that resolves the name of the server hosting the metadata. DNS Resolvers are out of the scope of this article. For more information on configuring a dns resolver see K31539643
  2. The IdP's metadata URL
    1. You should be able to paste this url into your browser and see the resulting IdP's metadata xml file
    2. For the above example I paste in http://md.islands.gelane/md/idp.xml and I can see or download the metadata
  3. Explore the metadata and note 2 tags that contain a tag value (a value between the opening and closing tag)
    1. Metadata Tag Match Value
      1. This will be used when a user connects to the VIP of APM as the SP and the selected matching source will match this value in order to use this idp connector
    2. Metadata Tag For IdP Connector Name
      1. The value of this tag will be used to name the idp connector (as will be seen in Access -> Federation -> SAML Service Provider -> External IdP Connectors)
    3. XML structure we are concerned with is:
      1. <tag attribute1="attribute value" attribute2="attribute value">TAG VALUE</tag>
    4. This type of xml tag will not work
      1. <tag attribute1="attribute value" attribute2="attribute value" />

 

Configuring IdP Automation

  1. Navigate to Access -> Federation -> SAML Service Provider -> Local SP Services -> Connector Automation and Click Create
  2. General Settings
    1. Name* - This is the name of the automation configuration (not the name of the resulting IdP Connector)
    2. SP Service*: - This is the service the resulting IdP connector will be connected to
    3. IdP Matching Source*:
      1. This is either a predefined session variable or you can type a custom session variable here
      2. Because APM as an SP can have multiple attached idp connectors, this setting will be used to determine when to use this automated IdP
      3. Example %{session.server.landinguri}
    4. Metadata Tag Match Value*:
      1. Works with the IdP Matching Source
      2. The Matching Source's value should match this tags Value
      3. Example, above example metadata contains a <Path> tag who's value is /auto. You would put Path here
    5. Metadata Tag For IdP Connector Name*:
      1. used for the name of the connector that is attached to the specified SP
      2. Example, above example metadata contains a <saml:Attribute ...> tag who's value is idp_auto. You would put saml:Attribute here
    6. Frequency* - This is in minutes. It tells the samlidp service how often to check the url for updates
  3. Metadata URLs
    1. Click the add button to specify 1 or more Metadata URLs to read
  4. Connection Properties
    1. DNS Resolver* - Specify your pre-configured DNS Resolver
    2. SSL Profile (Server)
      1. The only optional configuration
      2. Specify an SSL profile to use for your https metadata server or none at all if the server is accessed over http
  5. Click OK to save the configuration

Confirming It Worked

  1. You can navigate to Access -> Federation -> SAML Service Provider -> Local SP Services and check that the idp connector is attached to the SP. If it is not, then something may have happened.
  2. APM reaches out to the server to pull down the xml file, parse it and create the idp connector. APM gets an MD5 of the xml file so if there are any changes, the MD5 will be different and, if those changes affects tags that are being used or a new certificate, APM knows it needs to update the idp connector. You can view this happening by watching /var/log/saml_automation.log

Changes to Metadata

if a change to a tag being used or a certificate inside the metadata changes, APM will update the configuration automatically. The certificate file will be updated in the bigip's certificate store. However, the admin will need to Apply the access profile

 

Troubleshooting

  • No logs printing
    • restart the samlidpd service (tmsh restart /sys service samlidpd)
  • IdP Connector not created
    • Make sure you can resolve the hostname of the metadata url and ensure there's connectivity from the bigip to that server
    • ip route get <ip of metadata server> may help to ensure routing is not an issue
    • Check to make sure there's no strangeness with the xml formatting
  • Create a ticket with F5 Support if there's still an issue and provide problem details and a qkview.
