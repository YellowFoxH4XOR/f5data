Known Issue

The Traffic Management Microkernel (TMM) process may restart and produce a core file following a configuration update or a ConfigSync operation.

This issue occurs when all of the following conditions are met:

  • The configuration has virtual servers that target another virtual server directly or as a result of an iRule, acceleration prefetch function, or other internal conditions.
  • The virtual servers are under load when you perform a configuration update (or a high-availability peer receives a ConfigSync).

A rare race condition when performing a configuration update (including a ConfigSync operation from a high-availability peer) on a heavily loaded system may allow the system to create a connection flow using an invalid or non-existent listener. As a result, the TMM process may restart and produce a core file when attempting to use or remove the affected flow.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from the TMM restart, and devices configured as a high-availability pair may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system unexpectedly fails over to another system in the device group.
  • You observe a TMM core file in the /shared/core directory.
