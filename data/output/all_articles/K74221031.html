Known Issue

Modifying the default SSL profile may cause upgrades to fail.

This issue occurs when all of the following conditions are met:

  • Your system is running BIG-IP 12.x or BIG-IP 13.x.
  • You modify the cipher string for a default Client SSL or Server SSL profile to contain the invalid keyword SSLv2, COMPAT, or RC2.
  • The SSL profile(s) whose ciphers settings are inherited from the default profile are not present in bigip.conf file.
  • You attempt to upgrade system to BIG-IP 14.x or BIG-IP 15.x.

Impact

The configurations fails to load after you upgrade the BIG-IP system.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The BIG-IP configuration fails to load and the system displays an error message similar to the following example, here indicating the invalid keyword sslv2 in the default Client SSL profile:

    err mcpd[7916]: 01070312:3: Invalid keyword 'sslv2' in ciphers list for profile /Common/splitsession-default-clientssl
    Unexpected Error: Loading configuration process failed

Workaround

To work around this issue, you can manually modify the /config/bigip.conf file to remove invalid keyword sslv2 by using a text editor and running tmsh load /sys config command. Alternatively, you can use the sed command to remove the entries. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the BIG-IP system command line interface.
  2. Make a backup of your bipgip.conf file by typing the following command:

    cp /config/bigip.conf /config/bigip.conf.K74221031

  3. Modify the /config/bigip.conf file by using the following sed command syntax:

    sed -i "s/\<invalid_keyword>//g" /config/bigip.conf

    For example,

    sed -i "s/\(\!SSLv2:\|:\!SSLv2\)//g" /config/bigip.conf

  4. Reload the configuration using tmsh, by typing the following command:

    tmsh load /sys config
