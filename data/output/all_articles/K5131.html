K5131: HTTP POSTs that use an Expect header do not work when cookie persistence is enabled

Known Issue

This may be the result of a known issue.

HTTP POSTS can be performed two ways:

  • The client can send the HTTP headers and the POST data in the same request.

    BIG-IP has no problems handling this type of POST.

  • The client can send the HTTP headers in a discrete request and include an Expect header. The server should then respond with an HTTP 100 (continue) message, based on the Expect header. When the client receives the server's response, the client sends the POST data.

    BIG-IP does not handle this type of POST properly.

When a node responds to a client with an HTTP 100 (continue) message and cookie persistence is enabled, BIG-IP does not forward the HTTP 100 (continue) message to the client. As a result, the client must wait for the connection to time out before it sends the POST data, which results in a significant delay.

F5 Networks Product Development tracked this issue as CR24772.
