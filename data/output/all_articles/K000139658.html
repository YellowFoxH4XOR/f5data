Description

BIG-IP device, attempting to create objects with diacritics (accented characters). New object creation is failing.

Environment

  • BIG-IP device
  • Creating a new load balancing object

Cause

Creating BIG-IP objects with accented characters (diacritics) in the object name is not supported. BIGIP supports ASCII only, not extended ASCII.

ASCII uses 7 binary digits (bits) to represent characters.

ASCII does not have diacritics (marks that are added to a letter, like the dots (umlauts) above vowels in German, or the tilde (~) above the 'n' for the 'ñ' used in Spanish). It was only meant for English and doesn't work well for most other languages.

7-bit ASCII characters are accepted. However, extended ASCII (8-bits), which would support ó characters, is not.

This can be seen when attempting to paste the ó character in the tmsh and bash shell respectively. Notice how it translates to more than 7-bits, which means it is not supported by BIG-IP, in tmos shell.

ó is understood by bash, but since BIG-IP is not compatible with extended ASCII, the character ó causes an error.

As an example, attempting to create a new object with the name "Alarcón", for the city in Spain.

# pasted ó character into tmsh

[root@localhost1:Active:Changes Pending] config # tmsh

root@(localhost1)(cfg-sync Changes Pending)(Active)(/Common)(tmos)# create ltm node Alarc\U+FFC3\U+FFB3 address 101.10.10.2

root@(localhost1)(cfg-sync Changes Pending)(Active)(/Common)(tmos)# list ltm node Alarc

ltm node Alarc {

address 101.10.10.2

}

 

# pasted ó character into bash

root@(localhost1)(cfg-sync Changes Pending)(Active)(/Common)(tmos)# q

[root@localhost1:Active:Changes Pending] config # tmsh create ltm node Alarcó address 101.10.10.3

-bash: �tmsh: command not found

Recommended Actions

Create objects without diacritics. Non-English characters are not supported by BIG-IP.
