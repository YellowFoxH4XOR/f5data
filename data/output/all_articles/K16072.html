Known Issue

The Traffic Management Microkernel (TMM) may produce a core file that includes an 'Assertion "valid node" failed' error message.

This issue occurs when all of the following conditions are met:

  • An Internet Content Adaptation Protocol (ICAP) profile and either a Request Adapt or Response Adapt profile are assigned to a virtual server.
  • An ICAP internal virtual server has an iRule that contains a suspending command, such as session or table.
  • The ICAP internal virtual server receives a protocol error or unexpected status code from the ICAP server, causing the internal virtual server connection to stop and close the connection during the iRule processing.

If an ICAP internal virtual server connection is closed while ICAP is processing an iRule that completes asynchronously, the iRule still attempts to process the connection upon resumption of the asynchronous iRule command, resulting in an Assertion "valid node" failed error.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting. If the BIG-IP system is configured as part of a high-availability (HA) group, a device failover may occur.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system fails over to the standby system if the system is configured for HA.
  • The BIG-IP system generates TMM core files to the /shared/core directory.
  • In the /var/log/ltm log file, you may observe messages similar to the following example:

    notice sod[7056]: 01140045:5: HA reports tmm NOT ready.

  • In the /var/log/tmm* files, the BIG-IP system logs a message similar to the following example:

    panic: ../modules/hudfilter/hudfilter.c:827: Assertion "valid node" failed.

Workaround

There is no workaround for this issue. To mitigate this issue, F5 recommends that you avoid iRules commands that could complete asynchronously (such as the session or table commands) in ICAP iRules events.
