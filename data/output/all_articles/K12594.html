Known Issue

Note: The ARX will fail the import of a share if a subdirectory contains the .acopia directory.

This is the result of a known issue. When the ARX system import finds the .acopia directory, the import report will state that the .acopia directory was found at the root (/) of the share. However, the message logged to the syslog file will contain the actual full path to the .acopia directory.

For example, the following import report indicates the ARX system found the .acopia directory in the root (/) directory.

Import Scan:
================================================================================

----------------------------------------------------------
Import Scan Start Time: Fri Jan 14 09:54:18 2011
----------------------------------------------------------

Type Path
-------- ----------------------------------------------------------------------
[ D MG] /.acopia

However, the error message logged to the syslog file correctly states that the .acopia directory was found in the /vol/test/001 directory.

2011-01-14T14:54:18.988+0000:SupARX2k1b:1-1-ACM-1602:DNAS_PGRP-2-ERR-MSG3:: Found .acopia
directory in /vol/test/001, on share 71

F5 Product Development tracked this issue as ID 348651 and it was fixed in ARX 5.2.2 and 6.0.0. For information about upgrading, refer to the ARX release notes.

Additionally, this issue was fixed in ARX 5.2.0 HF5 (build-12643). You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
