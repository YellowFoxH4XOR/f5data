Known Issue

The iRule LSN::pool event will not work for inbound connections if the Large Scale Nat (LSN) pool is not selected using the virtual server LSN pool option.

This issue occurs when all of the following conditions are met:

  • You have a carrier-grade network address translation (CGNAT) virtual server configured.
  • You have an LSN pool configured with either inbound connections or hairpinning enabled.
  • The virtual server references only the LSN using the iRule.

Impact

Inbound connections and hairpinning remain disabled for subscribers.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Inbound connections, hairpinning, or both, are enabled on the LSN pool, but remain disabled for subscribers.

Workaround

None. You must associate the LSN pool using the virtual server LSN pool option, which requires a new virtual server for each LSN pool in use.
