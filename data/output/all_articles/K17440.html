Known Issue

The Traffic Management Microkernel (TMM) may restart and produce a core file with a valid proxy assertion.

This issue occurs when all of the following conditions are met:

  • Active flows exist on an internal virtual server.
  • A configuration update or synchronization affecting the internal virtual server is in progress.
  • The client initiates a new connection to the internal virtual server during the update.

When a configuration update or synchronization takes place while there are active connections on an internal virtual server, and the client initiates a new connection to the internal virtual server during the update, the TMM can assert valid proxy, restart, and produce a core file.

If there are no pre-existing active connections, the assertion will not occur. However, even if an assertion and restart do not occur, connections initiated during the configuration update may still be in an unstable state and exhibit unpredictable behavior.

Note: This issue is intermittent and rarely encountered.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from the TMM restart, and devices configured as a high availability (HA) pair may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Your BIG-IP system temporarily fails to process traffic as it recovers from the TMM restart.
  • Devices configured as a (HA) pair fail over.

Workaround

There is no workaround for this issue. However, you can reduce the risk of encountering this issue by avoiding configuration changes that affect the internal virtual server while connections are active.
