Description

IP Intelligence doesn't work after upgrade to BIG-IP version 15.1.4 or later. You may observe an error message in the /var/log/iprepd/iprepd.log that appears similar to the following example:

iprepd|WARNING|Oct 15 10:00:01.004|28072|Failed to auto-detect
    Internet Protocol for TCP connections
iprepd|ERR|Oct 15 10:00:02.004|28072|Cannot determine Internet
    Protocol for host api.bcti.brightcloud.com

Environment

  • IP Intelligence is licensed (note this is a periodic subscription license).
  • After upgrade to BIG-IP version 15.1.4 or later.

Cause

Starting in BIG-IP version 15.1.4, F5 upgraded the third party SDK that is used for IP intelligence. This has a number of significant changes:

  • The previous version was limited to downloading over a IPv4 network. This current version can download over a dual stack network. The network protocol can be set using a db variable to use auto-detect, IPv4 only or IPv6 only. It now defaults to auto-detect.
  • The previous version used a text based API and server FQDN "vector2.brightcloud.com" The new version uses a json based API and different servers starting at api.bcti.brightcloud.com. While vector2.brightcloud.com originally used a fixed static IP address, it moved to a dynamic address early in 2021 (see K08155398 below).
    The new servers need to have the dynamic addresses *.bcti.brightcloud.com FQDN's allowed through any firewalls (or Proxies) to the Internet.


Recommended Actions

  1. Check connectivity to *.brightcloud.com and port 443. Update any firewalls in the Internet path.
     
  2. Ensure that the db key is configured for "auto-detect", as shown in the example below:

    tmsh list sys db iprep.protocol all-properties

    sys db iprep.protocol {
        default-value "auto-detect"
        scf-config "false"
        value "auto-detect" 
        value-range "auto-detect ipv4 ipv6"
    }

  3. To isolate any issues with IPv6 connectivity, change this value to "ipv4" to force the protocol:

    tmsh modify sys db iprep.protocol value ipv4

  4. Save the changes:

    tmsh save sys config
     

Additional Information

You may also see logs for TCL iRule failure, related to the IP Intelligence iRule on /var/log/ltm:

01220001:3: TCL error: /Common/intelligence_irule <HTTP_REQUEST> - IP Reputation database (/var/IpRep/F5IpRep.dat) not loaded (line 45) invoked from within "IP::reputation [IP::client_addr]"

These are a result of the IP intelligence database not being able to be downloaded.
