Description
When a FQDN node receives only a CNAME record in response to its periodic DNS query it does not recursively query for the Canonical Name and consequently does not receive the desired A/AAAA record.

Environment

  • BIG-IP LTM
  • 11.6.0 and later
  • FQDN node configured
  • LDNS provides only CNAME as response to FQDN node name resolution

Cause
By design the BIG-IP only parses A and AAAA record types for FQDN node functionality and intentionally ignore all other record types, including CNAME and DNAME records. This means that the BIG-IP will not recursively resolve CNAME records to their Canonical Names because those records are ignored. If any A/AAAA records are included in the response from the LDNS along with the CNAME record, the A/AAAA records will be processed and can result in changes to the ephemeral nodes. If the LDNS response only contains a CNAME record it is the equivalent of no record being returned to the BIG-IP.

Recommended Actions

Configure the LDNS so that the BIG-IP is never expected to receive and process CNAME records for FQDN node functionality and always receives A and/or AAAA records.

This is standard behavior for resolving DNS servers.
