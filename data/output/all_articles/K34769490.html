Topic

You should consider using this procedure under the following conditions:

  • Your origin web server (OWS) is configured to respond to HTTP OPTIONS method per RFC 7231: Hypertext Transfer Protocol (HTTP/1.1): Semantics and Content.
  • You want to configure your BIG-IP system to block HTTP requests that contain this method from reaching your OWS.

Note: This link takes you to a resource outside of AskF5, and it is possible that the document may be removed without our knowledge.

Description

The HTTP OPTIONS method represents a request for information about the communication options (For example, OPTIONS, GET, HEAD, POST, and TRACE methods listed in the Allow header of a HTTP response) available on the target URI as well as the capabilities of the OWS. Due to the type of information it may be able to expose, it is possible that some vulnerability assessment scanning tools may flag HTTP OPTIONS method as an insecure HTTP method.

You can configure a virtual server to reject HTTP requests using this HTTP method by modifying its associated HTTP profile and exclude it. By default, the HTTP profile Known Methods setting contains a list of the most common HTTP request methods, including OPTIONS, and the Unknown Method setting is set to Allow, which allows all methods regardless of whether they are known. Alternatively, you can configure an iRule to either reject or return an appropriate response of your choice when the virtual server receives such HTTP requests.

If your BIG-IP system is provisioned with the BIG-IP ASM module, you can block HTTP requests using the HTTP OPTIONS method by configuring a security policy for the affected virtual server. By default, the BIG-IP ASM security policy does not allow the HTTP OPTIONS method, it allows only the HTTP GET, POST and HEAD methods. You must ensure that the HTTP OPTIONS method is not configured in the Allowed Methods setting on the Security > Application Security > Headers > Methods page. The BIG-IP ASM system will log an Illegal Method violation when it detects HTTP methods that are not listed in the Allowed Methods setting. For more information, refer to K12312: Overview of BIG-IP ASM Illegal Method violations.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • Administrative access to the Configuration utility

Procedures

  • Configuring the HTTP profile to reject HTTP requests that uses the HTTP OPTIONS method
  • Configuring an iRule to block HTTP requests that uses the HTTP OPTIONS method

Configuring the HTTP profile to reject HTTP requests that uses the HTTP OPTIONS method

You can configure the HTTP profile to reject HTTP requests that use the HTTP OPTIONS method. When you have completed the procedure, the BIG-IP system rejects any HTTP request that uses the HTTP OPTIONS method. To do so, perform the following procedure:

Impact of procedure: When you set the Unknown Method setting to Reject, all unknown methods are rejected; this is not limited to HTTP requests using the HTTP OPTIONS method.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > Services > HTTP.
  3. Select the name of the affected HTTP profile.
  4. Select the Custom check box.
  5. Under Enforcement for Unknown Method, select Reject.
  6. For Known Methods, select OPTIONS, then select Delete.
  7. Select Update.

Configuring an iRule to block HTTP requests that uses the HTTP OPTIONS method

You can configure an iRule to either reject a HTTP request that uses the OPTIONS method by using the reject iRule command. Alternatively, you can configure the iRule to return an appropriate response of your choice using the HTTP::respond iRule command when the virtual server receives such HTTP requests.

Impact of procedure: The following example iRule may not apply to all environments. F5 recommends that you create an iRule that works best for your application environment. Adding an iRule increases the resources that the associated virtual server uses. Depending on the type and volume of the connections, this processing may introduce noticeable latency. F5 recommends that you test any such changes in an appropriate environment.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > iRules.
  3. Select Create.
  4. Enter a name for the iRule.
  5. For Definition, enter the following iRules syntax to reject HTTP requests using the HTTP OPTIONS method:
    when HTTP_REQUEST {
         if { [HTTP::method] equals "OPTIONS" } {
              log local0. "Forbidden HTTP method ([HTTP::method]) attempted by [IP::client_addr]"
              reject
         } 
    }
    The previous iRule rejects HTTP requests using the OPTIONS method and logs a message similar to the following example in the /var/log/ltm file:

    Rule /Common/blockHTTPOptions <HTTP_REQUEST>: Forbidden HTTP method (OPTIONS) attempted by 192.168.50.199

    Alternatively, you can configure the iRule to return an HTTP 501 response code to the client by replacing the reject iRules command with the HTTP::respond iRules command. For example:
    when HTTP_REQUEST {
         if { [HTTP::method] equals "OPTIONS" } {
              log local0. "Forbidden HTTP method ([HTTP::method]) attempted by [IP::client_addr]"
              HTTP::respond 501 -version 1.1 content "HTTP OPTIONS method is not supported!\n\n" noserver
         } 
    }

    Note: For more information about the HTTP::respond iRules command, refer to the HTTP::respond iRules wiki.

    The client would see a HTTP response from the BIG-IP system similar to the following example:

    HTTP/1.1 501 Not Implemented
    Connection: Keep-Alive
    Content-Length: 39

    HTTP OPTIONS method is not supported!

  6. Select Finished to save the iRule.
  7. Assign this iRule to your virtual server.
