Known Issue

This is the result of a known issue. If the MTU is changed after a connection has been established with a virtual server utilizing a FastL4 profile, the connection will stall. This issue occurs due to the FastL4 profile not passing the ICMP Need to Fragment message to the back-end server. Since the server does not receive this message specifying it must send smaller packets, it will continue to send packets using the original MTU when the connection was established. As a result, the connection will stall.

This behavior typically occurs when the FastL4 profile is used with a virtual server that is configured to handle tunneling, such as GRE or IPSEC. Once the tunnel is established, the MTU changes due to the overhead of the encapsulation used.

F5 Product Development tracked this issue as CR44165 and it was fixed in BIG-IP LTM versions 9.3.0 and 9.4.0. For information about upgrading, refer to the BIG-IP LTM release notes.

Workaround

You can work around this issue by specifying the Maximum Segment Size Override option with the FastL4 profile. To do so, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Select Local Traffic.
  3. Select Profiles.
  4. Select Protocol.
  5. Select FastL4.
  6. Select the FastL4 profile you are using.
  7. Select Specify from the drop-down menu for Maximum Segment Size Override.
  8. Specify a size, in bytes, for the maximum segment size to use.

    For example, a typical GRE tunnel is 1436 bytes in size, which is 1476 total bytes minus 40 bytes for GRE overhead.

  9. Select Update.
