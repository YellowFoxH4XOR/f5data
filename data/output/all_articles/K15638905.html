Topic

You should consider using this procedure under the following conditions:

  • Legitimate requests trigger attack signature violations for XML payloads.
  • You want to prevent false positives by disabling an attack signature in an XML profile.

Description

You can prevent attack signature false positives for XML payloads by disabling the triggered attack signatures in an XML profile. You can then associate the XML profile with a URL or parameter known to contain the XML content. When you disable an attack signature in an XML profile, the attack signature is not applied to the content defined in the XML profile, but it remains enabled for the security policy.

To prevent false positives for an attack signature by disabling it in an XML profile, perform one of the following procedures:

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You have administrative access to the Configuration utility.
  • You have created and associated an XML profile with a security policy.

Procedures

  • Disabling an attack signature when using a parameter (BIG-IP 11.3.0 and later)
  • Disabling an attack signature when using a URL (BIG-IP 11.3.0 and later)
  • Disabling an attack signature when using a parameter (BIG-IP 11.0.0 - 11.2.1)
  • Disabling an attack signature when using a URL (BIG-IP 11.0.0 - 11.2.1)

Disabling an attack signature when using a parameter (BIG-IP 11.3.0 and later)

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Configuring a parameter with an XML profile

  1. Log in to the Configuration utility.
  2. Navigate to Security > Application Security > Parameters.
  3. Select the name of the security policy you want to update in Current edited security policy.
  4. In the Parameters List section, click Create.
  5. For Parameter Name, select Explicit and type a parameter name.
  6. For Parameter Level, select Global, URL, or Flow and complete the information for the setting.
  7. For Parameter Value Type, select XML value.
  8. For XML Profile, select the appropriate XML profile.
  9. Click Create to save the parameter.

Disabling an attack signature in an XML profile

  1. Log in to the Configuration utility.
  2. Navigate to Security > Application Security > Content Profiles > XML Profiles.
  3. Select the name of the security policy you want to update in Current edited security policy.
  4. Click the name of the XML profile for which you want to disable an attack signature.
  5. Click the Attack Signatures tab.
  6. Ensure that the Check attack signatures check box is selected.
  7. In the Global Security Policy Settings box, select the attack signature that is causing the false positive and click << to move it to the Overridden Security Policy Settings box.
  8. For the attack signature State, select Disabled.
  9. Click Update.
  10. Click Apply Policy to apply the changes.

Disabling an attack signature when using a URL (BIG-IP 11.3.0 and later)

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Configuring a URL with an XML profile

  1. Log in to the Configuration utility.
  2. Navigate to Security > Application Security > URLs > Allowed URLs.
  3. Select the name of the security policy you want to update in Current edited security policy.
  4. In the Allowed URLs List section, click Create.
  5. For Create New Allowed URL, select Advanced.
  6. For URL, select Explicit, select either HTTP or HTTPS, and then type a name for the URL.
  7. Click the Header-Based Content Profiles tab.
  8. For Request Header Name, type a header name that must appear in requests for this URL.
  9. For Request Header Value, type a pattern string to match the header value that must appear in requests in order to be processed as XML data. You can use the following special characters: asterisk (*), question mark (?), and square brackets ([abc]).
  10. For Request Body Handling, select XML.
  11. For Profile Name, select the appropriate XML profile.
  12. Click Add and move the entry up in the list order if necessary to ensure proper matching.
  13. Click Create.

Disabling an attack signature in an XML profile

  1. Log in to the Configuration utility.
  2. Navigate to Security > Application Security > Content Profiles > XML Profiles.
  3. Select the name of the security policy you want to update in Current edited security policy.
  4. Click the name of the XML profile for which you want to disable an attack signature.
  5. Click the Attack Signatures tab.
  6. Ensure that the Check attack signatures check box is selected.
  7. In the Global Security Policy Settings box, select the attack signature that is causing the false positive and click << to move it to the Overridden Security Policy Settings box.
  8. For the attack signature State, select Disabled.
  9. Click Update.
  10. Click Apply Policy to apply the changes.
