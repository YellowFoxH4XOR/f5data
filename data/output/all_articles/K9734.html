Topic

By default, the Lightweight Directory Access Protocol (LDAP) application health monitor performs a single level scope search. A single level scope search is used when there are immediate subordinates of the entry specified as the search base DN. When an LDAP monitor has the Mandatory Attributes feature enabled, the resulting LDAP request will perform a full subtree search. As the scope of the subtree search cannot be limited, this may result in lengthy LDAP searches that utilize resources on the LDAP server. It may also result in LDAP monitor timing out if the search and subsequent response take longer than the LDAP monitor's timeout value. It is advisable to only use the Mandatory Attribute feature when an attribute that isn't returned from a single level scope search is necessary. In the event that it is necessary, specifying the location in the LDAP tree from which the monitor starts the health check by configuring the Base field in the LDAP monitor will mitigate the amount of time used to complete the search.

Workaround

To work around the LDAP monitor timing out, you can increase the number of seconds that the BIG-IP system will allow the LDAP search to continue before timing out. To do so, perform the following procedure:

Impact of workaround: Increasing the time out value will increase the amount of time it takes for the BIG-IP system to mark a resource down in the event of failure.

Increasing the timeout value for the LDAP monitor

  1. From the Configuration utility, expand the Local Traffic tree.
  2. Click Monitors.
  3. Click the LDAP monitor's name.
  4. Increase the value of the Timeout field to the approximate number of seconds it takes to successfully complete the necessary search.

    Note: This value is dependent on your environment and should be kept to the lowest value possible

  5. Click Update.
