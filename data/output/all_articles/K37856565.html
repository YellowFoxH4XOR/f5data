Description

A Local Traffic Policy is configured to reset the connection with the shutdown action on matching HTTP requests, for example:

ltm policy /Common/block_hosts {
    requires { http }
    rules {
        block_1 {
            actions {
                0 {
                    shutdown
                    connection
                }
            }
            conditions {
                0 {
                    http-header
                    name Host
                    not
                    values { www.example.com }
                }
            }
        }
    }
    strategy /Common/first-match
}

This policy intends to reset the TCP connection when a HTTP request is received with a Host header that is not www.example.com.

An iRule is also configured to take action during the same event, for example:

when HTTP_REQUEST {
    HTTP::redirect https://[getfield [HTTP::host] ":" 1][HTTP::uri]
}

The iRule is executing and returning a 302 response, even for requests that meet the policy actions with a non-matching Host header.

Result shown in a packet trace:

172.16.10.5 → 10.10.10.80  TCP IN   s1/tmm0 : 49542 → 80 [SYN]
10.10.10.80 → 172.16.10.5  TCP OUT  s1/tmm0 : 80 → 49542 [SYN, ACK]
172.16.10.5 → 10.10.10.80  TCP IN   s1/tmm0 : 49542 → 80 [ACK]
172.16.10.5 → 10.10.10.80  HTTP IN  s1/tmm0 : GET / HTTP/1.1
10.10.10.80 → 172.16.10.5  HTTP OUT s1/tmm0 : HTTP/1.0 302 Moved Temporarily
10.10.10.80 → 172.16.10.5  TCP OUT  s1/tmm0 : 80 → 49542 [RST, ACK] [F5RST: reset by policy]
172.16.10.5 → 10.10.10.80  TCP IN   s1/tmm0 : 49542 → 80 [ACK]
10.10.10.80 → 172.16.10.5  TCP OUT  s1/tmm0 : 80 → 49542 [RST, ACK] [F5RST: No flow found for ACK]

Expected behaviour is for the connection to be reset before the iRule's execution of the HTTP_REQUEST event.

Environment

  • Traffic Policy
  • iRule

Cause

Bug ID 867985: LTM policy with a 'shutdown' action incorrectly allows iRule execution

Recommended Actions

There is no fix for bug ID 867985 at the time of this article's publication.

A workaround is to set a TCL variable in the policy actions to [event disable all]. This prevents all iRule events from running in that connection.

For example:

ltm policy /Common/block_hosts_fixed {
    requires { http }
    rules {
        block_1 {
            actions {
                0 {
                    shutdown
                    connection
                }
                1 {                                     <---
                    tcl                                 <---
                    set-variable                        <---
                    expression "[event disable all]"    <---
                    name ID867985                       <---
                }                                       <---
            }   
            conditions {
                0 {
                    http-header
                    name Host
                    not
                    values { www.example.com }
                }
            }
        }
    }
    strategy /Common/first-match
}
