Description

When in-TMM monitoring is enabled on BIG-IP LTM, health monitors may not probe at the expected frequency. In some configurations, probes are spaced based on the timeout value rather than the configured interval or up-interval (if configured) when pool members are UP.

Environment

  • BIG-IP LTM
  • In-TMM monitoring enabled (sys db bigd.tmm set to enable)
  • Monitor interval is not a multiple of the timeout value

Cause

Bug ID 2185541: In-tmm monitors don't always probe on the interval value

Due to architectural limitations, in-TMM monitoring may not handle probe timing correctly when interval, timeout, and up-interval values are not aligned. When the monitor interval or up-interval is not a multiple of the timeout, the system uses the timeout value for probe spacing instead of the configured interval/up-interval while the pool member is UP.

Recommended Actions

Option 1: Disable in-TMM monitoring to restore correct interval behavior:

tmsh modify sys db bigd.tmm value disable
tmsh save sys config
bigstart restart bigd

Verify status:

tmsh list sys db bigd.tmm
bigstart status bigd

Note: Disabling in-TMM monitoring reverts health monitoring to the legacy bigd process, which may increase CPU usage on the host system but provides more precise and stable timing behavior.

Option 2. If in-TMM monitoring must remain enabled for performance reasons, consider adjusting monitor timing values so that the timeout is a multiple of the interval/up-interval.

For example:

ltm monitor tcp in_tmm_tcp {
    adaptive disabled
    defaults-from tcp
    interval 4
    ip-dscp 0
    recv none
    recv-disable none
    send none
    time-until-up 0
    timeout 16
    up-interval 8    # optional  
}

The interval or up-interval must divide evenly into the timeout value (1, 2, 4, 8, or 16 seconds for a 16-second timeout).
