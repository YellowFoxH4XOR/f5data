Description

Traffic may appear to be blackholed and not forwarded to pool members when DOSL7::disable or BOTDEFENSE::disable iRule commands are used together with HTTP::disable command.

 

Example 1:

ltm rule rule_bot_disable {
    when CLIENT_ACCEPTED {
        HTTP::disable
        BOTDEFENSE::disable
    }
}

Example 2:

ltm rule rule_dosl7_disable {
    when CLIENT_ACCEPTED {
        HTTP::disable
        DOSL7::disable
    }
}

Environment

  • BIG-IP ASM / Advanced WAF
  • DoSL7 or Bot Defense Profiles attached to Virtual Server
  • iRule using commands to disable DOSL7 (DOSL7::disable) or Bot Defense (BOTDEFENSE::disable)
  • iRule using command to disable HTTP (HTTP::disable)

 

Cause

Bug ID 1110281 and Bug ID 974985

 

Recommended Actions

Follow the workaround described in Bug ID 1110281 and Bug ID 974985.
