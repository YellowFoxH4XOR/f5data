Description

After importing cert and key combo(PFX), customer is not able to convert a normal key test to FIPS by seeing below error messages:

err mcpd[7082]: 010713e4:3: FIPS subsystem reported error while attempting file object operation: convert_key: Could not convert key /Common/test to FIPS.. 
err mcpd[7082]: 01070712:3: Caught configuration exception (0), unable to convert key /Common/test to a FIPS 140 key. 
err tmsh[16432]: 01420006:3: 01070712:3: unable to convert key /Common/test to a FIPS 140 key

sys crypto key /Common/test {
    key-size 2048
    key-type rsa-private
    security-type normal
}

Environment

  • BIG-IP FIPS HSM
  • v15.x

Cause

FIPS module already contains a RSA key with same modulus value as the one you are attempting to convert, so it can't be converted to FIPS again.
 

Recommended Actions

1. Run below command to check the modulus for the cert

openssl x509 -in test.crt -noout -modulus 
Output:
Modulus=DE1EACA266622F1771D523376CA0C93B3B99F44B7EF31AC711F2F777547760E648D061FBFBFF8139F566B684BF6BA695......


2.  Run below command to check if there is a existing FIPS key having the same Modulus value 
Find the name of existing key, for example, ras1 is the name of the existing FIPS key. 

# show sys crypto fips key all-properties
-------------------------------------------
FIPS 140 Hardware Device
-------------------------------------------
=== private keys (2)
        id: de1eaca266622f1771d523376ca0c93b
        name: /Common/rsa1.key
        modulus (2048 bits):
                de:1e:ac:a2:66:62:2f:17:71:d5:23:37:6c:a0:c9:3b
                3b:99:f4:4b:7e:f3:1a:c7:11:f2:f7:77:54:77:60:e6
                48:d0:61:fb:fb:ff:81:39:f5:66:b6:84:bf:6b:a6:95

...

3. After making sure this old key and its cert are not being used by any profile, delete them on HA pair.  
4. System should be able to to convert new key test to FIPS.
