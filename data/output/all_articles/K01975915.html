Description

  • A remote syslog server is configured for your BIG-IP DNS system

  • You may find the remote syslog server receives the following log messages from BIG-IP DNS
syslog-ng[PID]: Error processing log message: </probe object>

For example: 
syslog-ng[2387]: Error processing log message: </getconfig_element>
syslog-ng[2387]: Error processing log message: </monitor>
syslog-ng[2387]: Error processing log message: </vip>
syslog-ng[2387]: Error processing log message: </getconfig>
syslog-ng[2387]: Error processing log message: </pool>

Environment

  • BIG-IP DNS
  • Remote Syslog Server
  • gtm.debugprobelogging is enabled

Cause

This issue is caused by system db key gtm.debugprobelogging is enabled and make it hits Bug ID 842669.  The big3d probe debug logs include messages with embedded newlines which systemd-journald cannot handle.

For example:

big3d[7381]: 012b600d:5: Probe from ::ffff:192.168.11.11:34972: len 211/buffer = <getconfig>
                    <ip>::ffff:192.168.11.11</ip>
                    <target_ip>::</target_ip>
                    <autoconf_enabled>0</autoconf_enabled>
                    <timestamp>none</timestamp>
                    <expose_route_domains>0</expose_route_domains>
                 </getconfig>

The logging subsystem then accepts syslog messages with embedded newlines and writes the first line to /var/log/gtm and remaining lines to /var/log/user.log and /var/log/messages.

The last line of message, namely </getconfig> in this example, causes remote syslog server receives the log message in the beginning.

Recommended Actions

You can use command "tmsh modify sys db gtm.debugprobelogging value disable" to resolve this issue or refer to K32513441: Logs are full of closed parenthesis ")" lines for workaround.
