Description

Some ipv6 clients fail to connect to a virtual server which is referencing ipv4 virtual server by use of virtual irule command

Example config:

ltm virtual /Common/ipv6_virtual_http {
    destination /Common/1111:111:1111:1111::1.80
    ip-protocol tcp
        profiles {
        /Common/fastL4 { }
    }
    rules {
        /Common/redirect_irule
    }
    serverssl-use-sni disabled
    source ::/0
    source-address-translation {
        pool /Common/example_snatpool
        type snat
    }
    translate-address enabled
    translate-port enabled
}

ltm rule /Common/redirect_irule {
when CLIENT_ACCEPTED { virtual ipv4_virtual_http }
}

ltm snatpool example_snatpool {
    members {
        bbbb:bbbb:bbbb:bbbb::1
    }
}

Environment

  • BIG-IP
  • IPv6 virtual server has an irule with "virtual" command referencing IPv4 virtual server
  • IPv6 virtual server has no SNAT applied or has IPv6 SNAT
  • IPv6 virtual has "translate address" enabled

Cause

TMM has to convert IPv6 address to IPv4 address when connection is passed between both virtual servers which can produce an unexpected address that is sometimes rejected by TMM
 

Recommended Actions
 

Follow F5 best practice:
  1.  Apply IPv4 snat on the front IPv6 virtual server and enable "translate address"
    or
  2. Disable IPv4 snat and "translate address" on the front IPv6 virtual server (this will work due to fix of ID1002945)
