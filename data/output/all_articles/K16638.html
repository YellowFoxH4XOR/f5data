Known Issue

The Traffic Management Microkernel (TMM) may produce a core file when applying an access policy.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM configuration contains an access policy that references an unused custom macro.
  • You apply the access policy.

Impact

TMM temporarily stops processing traffic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system fails over to a peer system if configured for high availability (HA).
  • The BIG-IP system generates a TMM core file to the /shared/core directory, with a time stamp that correlates with when the access policy was applied.
  • Log messages similar to the following example are logged to /var/log/ltm file, with a time stamp that correlates with when the access policy was applied:

    notice ** SIGSEGV **

Resolution

Status

Workaround

To work around this issue, you can delete all unused macros from the access policies prior to applying an access policy.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
