Description
After an upgrade to BIG-IP v15.1.5, v15.1.5.1, v16.1.2.1, v16.1.2.2, or v17.0.0, iRules using the event CLIENTSSL_CLIENTCERT may not get triggered. If there are variables being initialized in CLIENTSSL_CLIENTCERT, this issue may lead to TCL error when the uninitialized variable gets called in other events and the connection being reset with "F5RST: iRule execution error".

For example, you have the following iRule attached to a virtual server, with client SSL profile configured with peer-cert-mode set to either request, or require.

ltm rule iRule1 {
  when CLIENTSSL_CLIENTCERT {
    set $myvar "none"
  }

  when HTTP_REQUEST {
    log local0. "My variable is: $myvar"
  }
}


When a client sends an empty certificate, or if no certificate is sent, the CLIENTSSLCLIENTCERT event in the iRule will not trigger. This means $myvar will never be initialized. When an HTTP request arrives, this results in an error similar to the following when the variable is called:

err tmm[17523]: 01220001:3: TCL error: /Common/iRule1 <HTTP_REQUEST> - can't read "myvar": no such variable while executing "log local0. "My variable is: $myvar""

Environment

  • BIG-IP v15.1.5, v15.1.5.1, v16.1.2.1, v16.1.2.2, or v17.0.0
  • iRule using CLIENTSSL_CLIENTCERT event

Cause

  • ID1087469 iRules are not triggered when an SSL client connects to a BIG-IP system using an empty certificate.

Recommended Actions

Workaround:
  • Modify the iRule so that the affected variables are initialized elsewhere (ie. CLIENTSSL_CLIENTHELLO), or for the iRule to gracefully handle uninitialized variables.
