Known Issue

This is the result of a known issue. When a connection traverses an iRule that executes the substr command using the optional third parameter that defines the termination character for the substring, the gtmd process produces a core file and restarts. For example, the following iRule will cause the gtmd to produce a core file when you execute the substr command:

rule substr_test {
when LB_SELECTED {
set pool [substr "pool12" 0 "2"]
}
}

Note: For more information about the substr command, refer to the following DevCentral wiki page:

https://devcentral.f5.com/Wiki/iRules.substr.ashx

A separate DevCentral login is required to access this content; you will be redirected to authenticate or register (if necessary).

Workaround

You may be able to work around this issue by using alternative string manipulation commands, such as the Tcl string command.
