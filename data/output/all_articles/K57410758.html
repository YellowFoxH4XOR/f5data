Issue

Error Message

Error message: <irule_name>: warning: [use curly braces to avoid double substitution][<Part_of_irule_in_question>]

In this error message, note the following:

  • <irule_name> is the name of the iRule.
  • <Part_of_irule_in_question> is the part of the iRule that is subject to double substitution.

For example:

/Common/irule_PROXY:26: warning: [use curly braces to avoid double substitution][[string length ${servername}]]

Message Location

You may encounter this message in the following locations:

  • The /var/log/ltm file
  • The command line, when you load or validate the configuration

Description

This message occurs when the following condition is met:

  • You load a configuration that has an incorrectly braced iRules expression. 
  • You use the tmsh load sys config verify command to validate an affected configuration. 

Some Tool Command Language (Tcl) commands, such as expr, if, and while, parse their arguments according to the grammar of expr, resulting in another round of variable and command substitution. Double substitution refers to the substitution that happens during these additional rounds of interpretation. Double substitution can be useful but is more often the result of inadvertently neglecting to brace the arguments to expr or to the expr arguments of if and while.

For example, the following iRules expression returns the double substitution error message, because the expr argument is not correctly braced:

Important: This code deliberately exposes code injection and is unsafe.

when HTTP_REQUEST {
    set double [HTTP::header value Double]
    set val [expr ${double} * 2]
    HTTP::respond 200 content $val
}

The following example is the same iRules expression with the correct curly braces:

when HTTP_REQUEST {
    set double [HTTP::header value Double]
    set val [expr {${double} * 2}]
    HTTP::respond 200 content $val
}

Impact

This error message is informational and does not prevent the system from loading the configuration.

Recommended Actions

The log message describes the warning that the BIG-IP system encountered when you loaded the configuration. To correct the problematic code, consider the following:

  • You can inspect your iRules expressions to ensure that Tcl expressions are correctly braced ({ and }).
  • You should properly brace your iRules Tcl code to avoid the possibility of an Injection attack. Injection attacks often allow users to run arbitrary code in a privileged context.
  • Ensure that you properly brace the arguments to the expr to avoid the first layer of substitution by the Tcl interpreter. The same applies for the first argument to if and while.
  • If your iRule depends on double substitution, ensure that, in all instances, the system enters trusted data in the iRule, not data that users submit.
