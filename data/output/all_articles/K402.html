Topic

The bigtop utility reports the number of new connections in the last four seconds.

                     |  bits  since       |  bits  in prior    |  current
                     |  Mar 28 17:39:12   |  4 seconds         |  time
BIG-IP      ACTIVE   |---In----Out---Conn-|---In----Out---Conn-|  10:41:32
192.168.18.249            0      0      0      0      0      0
 
VIP ip:port          |---In----Out---Conn-|---In----Out---Conn-|-Nodes Up--
192.168.18.208:80         0      0      0      0      0      0       1
 
NODE ip:port         |---In----Out---Conn-|---In----Out---Conn-|--State----
10.1.1.128:1645           0      0      0      0      0      0    UNCKD

Once the connection is moved to the bits since (accumulator) column, you may continue to see new bytes transferred to the columns on the right as the connection continues. Therefore, it is possible to have zero in the bits in prior 4 seconds (new connections) column and still see bytes accumulating.

Browsers can open several connections for each web page: one for text, another for a graphics, and so on. For this reason, a single web page can be balanced over several servers. For example, the text for the web page may come from node 1, the graphics from node 2, and another graphic from node 3. This can account for a discrepancy in the number of connections.

To test this, set up a virtual server (VIP) that points to only one web server node and access that VIP with a web browser. Since there is only one node, no load balancing is occurring and you should be able to see more clear and accurate statistics. Perform the following tasks to determine if the discrepancies are caused by load balancing a single page across several nodes:

  • Count the connections displayed by the bigtop utility.
  • Compare the connection information to that of the server.
  • Count the graphics on the page and see if the web server is counting the hit on the page as one, or if it includes all the graphic elements in the count.

Another reason for the discrepancies could be HTTP keep-alives, where multiple requests for data from a browser are sent during a single connection. BIG-IP is only counting the connection to the server, while the server is counting the actual data requests; therefore, if during a single connection a web browser received three graphics from the web server, BIG-IP would only increment the total connections by one, while the web server would log three connections.

The connection statistics displayed in the Configuration utility are different that those displayed by the bigtop utility, because the Configuration utility displays all open connections, while the bigtop utility displays newly-initiated connections over a sample period.
