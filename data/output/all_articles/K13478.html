Topic

This article applies to BIG-IP 11.x through 12.x. For information about other versions, refer to the following articles:

  • K84303332: Overview of connection and persistence mirroring (13.x - 15.x)
  • K7222: Overview of connection and persistence mirroring (9.x - 10.x)

The connection and persistence mirroring feature allows you to configure a BIG-IP system to duplicate connection and persistence information to the standby unit of a redundant pair. This setting provides higher reliability but may affect system performance.

  • The Redundant System Configuration chapter of the VIPRION Systems: Configuration manual (12.x)
  • The Configuring Mirroring for VIPRION Systems chapter of the Configuration Guide for the VIPRION System (11.x)

Note: For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

Description

The BIG-IP device service clustering (DSC) architecture allows you to create a redundant system configuration for multiple BIG-IP devices on a network. System redundancy includes the ability to mirror connection and persistence information to a peer device to prevent service interruptions during failover. The Traffic Management Microkernel (TMM) manages the state mirroring mechanism, and connection and persistence data is synchronized to the standby unit with every packet or flow state update. The standby unit decapsulates the packets and adds them to the connection table.

BIG-IP 11.3.0 and earlier versions maintain only a single global connection and persistence mirroring channel. The active BIG-IP system in a high availability (HA) device group can only mirror to one specific standby BIG-IP system using the global mirror channel. The mirroring channel is created on TCP port 1028.

Beginning with version 11.4.0, the BIG-IP system maintains a separate mirroring channel for each traffic group. The active BIG-IP system in an HA device group dynamically establishes a mirroring connection to the standby with a status of Next Active for a given traffic group. The port range for each connection channel begins at TCP 1029 and increments by one for each new traffic group and channel created. For more information, refer to K14894: The BIG-IP system establishes a separate mirroring channel for each traffic group.

In BIG-IP 12.0.0 and later, you can configure the system to mirror Secure Sockets Layer (SSL) connections that are terminated by the BIG-IP system to peer device group members. For more information, refer to K17391: Configuring SSL connection mirroring.

You can use the Configuration utility or Traffic Management Shell (tmsh) to configure mirroring addresses, configure connection mirroring for virtual servers and Secure Network Address Translations (SNATs), and configure persistence mirroring. You can also view mirroring data on the active and standby BIG-IP systems using tmsh. To do so, refer to the following procedures:

  • Choosing a VLAN for mirroring traffic
  • Configuring mirroring IP addresses
  • Configuring connection mirroring for a virtual server
  • Configuring connection mirroring for a SNAT
  • Configuring mirroring for a persistence profile
  • Viewing mirrored connection data from either the active or standby unit
  • Viewing mirrored persistence data from either the active or standby unit

Choosing a VLAN for mirroring traffic

If the BIG-IP system is required to mirror a high volume of connection and persistence information, F5 recommends using a dedicated Virtual Local Area Network (VLAN) and dedicated interfaces to process mirroring traffic.

Configuring mirroring IP addresses

Mirroring addresses are the IP addresses that you want the BIG-IP system to use for connection and persistence mirroring. You should specify a primary mirroring address as well as a secondary address for the system to use if the primary address is unavailable. To configure mirroring addresses, perform one of the following procedures:

Configuration utility

  1. Log in to the Configuration utility.
  2. Go to Device Management > Devices.
  3. In the Device List, select the name of the local device indicated with (Self).
  4. Hover on the Device Connectivity tab and select Mirroring.
  5. For Primary Local Mirroring Address and Secondary Local Mirroring Address, select the appropriate addresses.
  6. Select Update.

tmsh

  1. Log in to tmsh by entering the following command:

    tmsh

  2. Configure the primary mirroring address by using the following command syntax:

    modify /cm device <device_name> mirror-ip <IP address> mirror-secondary-ip <IP address>

    For example, to configure mirroring for a device named example.com using primary mirroring IP address 10.11.23.100 and secondary mirroring IP address 10.11.23.101, enter the following command:

    modify /cm device example.com mirror-ip 10.11.23.100 mirror-secondary-ip 10.11.23.101

  3. Save the change by entering the following command:

    save /sys config

Configuring connection mirroring for a virtual server

The BIG-IP system can mirror TCP or User Datagram Protocol (UDP) connections for a virtual server. To configure connection mirroring for a virtual server, perform one of the following procedures:

Configuration utility

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Virtual Servers.
  3. Select the virtual server for which you want to enable connection mirroring.
  4. For Configuration, select Advanced.
  5. For Connection Mirroring, select the check box.
  6. Select Update.

tmsh

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To configure connection mirroring for the virtual server, use the following command syntax:

    modify /ltm virtual <virtual_server> mirror enabled

  3. Save the change by entering the following command:

    save /sys config

Configuring connection mirroring for a SNAT

The BIG-IP LTM system can mirror TCP or UDP connections for a SNAT. To configure connection mirroring for a SNAT, perform one of the following procedures:

Note: For information about File Transfer Protocol (FTP), refer to the Recommendations section.

Configuration utility (BIG-IP 11.3.0 and later)

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Address Translation > SNAT List.
  3. Select the SNAT for which you want to enable connection mirroring.
  4. Select the Stateful Failover Mirror check box.
  5. Select Update.

Configuration utility (BIG-IP 11.0.0 through 11.3.0)

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > SNATs.
  3. Select the SNAT for which you want to enable connection mirroring.
  4. Select the Stateful Failover Mirror check box.
  5. Select Update.

tmsh

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To configure connection mirroring for the SNAT, use the following command syntax:

    modify /ltm snat <snat> mirror enabled

  3. Save the change by entering the following command:

    save /sys config

Configuring mirroring for a persistence profile

The BIG-IP system can mirror persistence information between peers for the following persistence profiles:

  • Destination address affinity
  • Hash
  • Microsoft Remote Desktop
  • SIP
  • Source address affinity
  • SSL
  • Universal

To configure mirroring for a persistence profile, perform one of the following procedures:

Configuration utility

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles.
  3. Select the appropriate persistence profile (or select Create to create a new profile).
  4. Select the Mirror Persistence check box.
  5. Select Update.

tmsh

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To configure the profile to mirror persistence information, use the following command syntax:

    modify /ltm persistence <profile_name> mirror enabled

  3. Save the change by entering the following command:

    save /sys config

Viewing mirrored connection data from either the active or standby unit

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To view mirrored connection data, enter the following command:

    show /sys connection type mirror

Viewing mirrored persistence data from either the active or standby unit

  1. Log in to tmsh by entering the following command:

    tmsh

  2. To view mirrored connection data, enter the following command:

    show /ltm persistence persist-records

Recommendations

When configuring mirroring on the BIG-IP system, F5 recommends that you consider the following suggestions:

Note: After a failback event, the BIG-IP system re-mirrors only FastL4 and SNAT connections.

  • Use configuration mirroring only between identical systems

    Connection mirroring is designed to be used between identical BIG-IP platforms with identical configurations.

  • Enable connection and persistence mirroring when a BIG-IP failover would cause the user's session to be lost or significantly disrupted

    For example, where long-term connections, such as FTP and Telnet, are good candidates for mirroring, mirroring short-term connections, such as HTTP and UDP, is not recommended as this causes a decrease in system performance. In addition, mirroring HTTP and UDP connections is typically unnecessary, as those protocols allow for failure of individual requests without loss of the entire session.

  • Configure a dedicated VLAN and dedicated interfaces to process mirroring traffic

    The TMM process manages the BIG-IP LTM state mirroring mechanism, and connection data is synchronized to the standby unit with every packet or flow state update. In some mirroring configurations, this behavior may generate a significant amount of traffic. Using a shared VLAN and shared interfaces for both mirroring and production traffic reduces the overall link capacity for either type of traffic. Due to high traffic volumes, production traffic and mirroring traffic may interfere, potentially causing latency in mirrored connections or interrupting the network mirror connection between the two BIG-IP devices. If the network mirror connection is interrupted, it can cause loss of mirror information and interfere with the ability of the peer device to take over connections in the event of a failover.

  • Use direct cables for network mirroring interfaces

    You can use direct cables for network mirroring interfaces on the BIG-IP systems in the failover pair, and F5 highly recommends that you do this when configuring a dedicated VLAN for mirroring. Configuring the pair in this way removes the need to allocate additional ports on surrounding switches and removes the possibility of switch failure and switch-induced latency. Interfaces used for mirroring should be dedicated to the mirroring VLAN. Tagged interfaces shared with other VLANs could become saturated by traffic on other VLANs.

  • Configure both primary and secondary mirroring addresses

    This allows an alternate mirroring path and ensures reliable mirroring in the event of equipment or cable failure.

  • Use a virtual server to process FTP traffic

    When using SNATs to process FTP connections, the BIG-IP system may modify the FTP control channel's TCP payload, for example, when rewriting the IP address in the FTP PORT command request packet sent from the client to the FTP server. The modification to the TCP payload size in the FTP PORT command packet may cause a difference between the TCP sequence and TCP acknowledgment numbers on both the client- and server-side connection flows. During an HA failover event, FTP control connections can fail because SNAT mirroring does not synchronize TCP sequence and TCP acknowledgement numbers between all of the BIG-IP systems in the HA configuration. To avoid this, process FTP connections using a standard virtual server with an associated FTP profile and mirroring enabled. For more information, refer to K93017176: Overview of the Standard virtual server.

  • Note that the standby system's connection table may contain entries that have been cleared from the active system's connection table

    When a connection is closed and cleared from the connection table of the active BIG-IP system, that connection is not cleared from the standby BIG-IP system's connection table at the same time. By default, the connection remains in the standby system's connection table until the system reaches the connection's idle timeout value. If you require the standby system's connection table to be synchronized with the active system, you can enable the statemirror.verify database variable (disabled by default) on the active and standby systems. Enabling the statemirror.verify database variable causes the system to mirror connections from the active system to the standby system, and back to the active system before they are processed. Enabling the statemirror.verify database variable may significantly decrease performance. The amount of performance loss depends on the specific environment. F5 recommends that you test any such changes during a maintenance window and consider the possible impact on your specific environment.
