K000137329: iHealth Automation with Ansible does not upload qkviews correctly

Description

If you try to use the Ansible URI function to upload a qkview, iHealth responds that "Input is not in the .gz format".

Cause

Ansible config: 
    - name: Upload qkview
      uri:
        url: https://ihealth2-api.f5.com/qkview-analyzer/api/qkviews
        method: POST
        http_agent: "MyGreatiHealthClient"
        body_format: form-multipart
        headers:
          Authorization: "Bearer {{ ihealth_token }}"
          Accept: application/vnd.f5.ihealth.api
        body:
          qkview:
            filename: /var/tmp/my-bigip-qkview.qkview
            mime_type: application/octet-stream
        return_content: yes
      register: result

So the qkview is being sent as a form attachment as expected, but Ansible is encoding it with Base64, which iHealth does not currently support, so we see that the iHealth API responds with:

<?xml version="1.0" encoding="UTF-8" standalone="yes"?><qkview_upload><result>Input is not in the .gz format</result></qkview_upload>

 

Workaround

To workaround this issue, you need to use the curl via the shell command:
 

 - name: Upload qkview via curl

   shell: 'curl -X POST "https://ihealth2-api.f5.com/qkview-analyzer/api/qkviews" \
   -H "Content-Type: multipart/form-data" \
   -H "Authorization: Bearer {{ihealth_token }}" \
   -H "Accept: application/vnd.f5.ihealth.api" \
   --user-agent "MyGreatiHealthClient" \
   --form "qkview=@/var/tmp/my-bigip-qkview.qkview"'

   register: result
