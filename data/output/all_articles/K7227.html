Topic

You can use the tcpdump utility to capture (to a file) or view (to the console) packets for a tagged VLAN on the BIG-IP system. The syntax, flags, and options specified when performing a packet capture using the tcpdump utility determine what information is included in the packet capture file and displayed to the console.

This article applies to tagged VLAN specific traffic when using the tcpdump utility. For a general overview of the tcpdump utility, refer to K411: Overview of packet tracing with the tcpdump utility.

When performing a packet capture, you can use a syntax option to specify the interface on which to perform the packet capture. When specifying the interface, you can capture on a specific VLAN name or on a specific interface number using one of the following syntax methods:

  • tcpdump -ni <vlan name>
  • tcpdump -ni x.x

While these methods are similar, you should consider the following differences and limitations:

Capture on a specific VLAN name

When you specify the VLAN name in the tcpdump syntax (tcpdump -ni <vlan name>), the utility filters the packet capture so that it captures only packets on the specified VLAN.

However, a limitation of this method is that the tcpdump utility does not receive these packets until after the system copies them on switch ingress, processes them through the Traffic Management Microkernel (TMM), and sends them to the host. By this point the VLAN header has been removed and the packet capture file does not contain any VLAN tag ID information. As a result, you can't see or filter on any VLAN tag ID information when viewing or processing the packet capture file in a packet analyzer, such as Wireshark.

Additionally, the VLAN tag ID information does not display when the utility sends the output directly to the console, even if you specify the -e flag.

Note: If the <vlan name> you specify is actually a VLAN group, tcpdump receives the packet before the system removes the VLAN header for VLAN processing.

Capture on a specific interface number (x.x)

When you specify the interface number in the tcpdump syntax (tcpdump -ni x.x), the utility does not filter the packet capture but instead captures all packets on the specified x.x interface.

When capturing on the x.x interface, the tcpdump utility receives the packet when the system copies it on switch ingress from the switch fabric to the host. Therefore, the VLAN header, including the VLAN tag ID information, is still present. As a result, you can view and filter on the VLAN tag ID information when viewing or processing the packet capture file in a packet analyzer, such as Wireshark. You can also display the VLAN tag ID information when the utility sends the output directly to the console if you specify the -e flag.

Note: For tagged VLANs, the administratively specified VLAN tag ID will be displayed with the packets. For untagged VLANs, the BIG-IP will assign a default ID to each VLAN (incrementing down from 4094) and this VLAN tag ID will be displayed with the packets.

In addition, because the VLAN tag ID information is present, you can filter for a specific VLAN using the additional vlan <tag> syntax option.

For example, to capture packets on interface 1.1, but only if they have a VLAN tag ID of 603, type the following command:

tcpdump -ni 1.1 vlan 603

Note: Running tcpdump on a specific interface is rate-limited to 200 packets per second. For more information, refer to K6546: Recommended methods and limitations for running tcpdump on a BIG-IP system.

Note: The vlan <tag> syntax does not work on BIG-IP Virtual Edition due to a limitation in the platform.
