K7331: The FirePass Webtop fails to display Webifyer icons if the default master group limits access to Favorites

Known Issue

This is the result of a known issue. The FirePass webtop will not display a Webifyer icon for users in any master groups other than the Default master group if the administrator has configured the same Webifyer in the Default master group to limit access to administrator-defined Favorites.

When a user logs in to the FirePass controller, the webtop typically displays the Webifyer types that the administrator has configured for the user's master group. However, if the administrator has configured the Default master group to display only administrator-defined Favorites for a Webifyer, that Webifyer will not appear on the webtop for users in other master groups.

For example, an administrator may configure the webtop to display Web Applications, Windows Files, Mobile E-Mail, Terminal Servers and Network Access Webifyers for all master groups. If the administrator then configures the Default master group by selecting the Show administrator-defined favorites only check box on the Portal Access: Web Applications: Master Group Settings page, and the Limit Terminal Servers Access to Favorites only check box on the Portal Access: Terminal Servers: Master Group Settings page, the Web Applications and Terminal Servers Webifyers will not appear on the webtops of users in master groups other than the Default master group.

F5 Networks Product Development tracked this issue as CR76796 and it was fixed in FirePass version 6.0.2.  For information about upgrading, refer to the FirePass Release Notes.

Workaround

Select the appropriate check box under the Master Group Settings page of your Webifyer for the Default master group. This configuration will allow users in other master groups to see the Webifyers on the webtop, but will prevent users from creating and accessing user-defined Favorites of that Webifyer type.
