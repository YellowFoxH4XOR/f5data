Known Issue

This is the result of a known issue. iRules using the after command may cause a TMM connection flow memory leak. When this issue occurs, the bigpipe memory command shows that the connflow subsystem consumes an excessive amount of memory and continues using the excessive amount of memory when the number of connections decreases.

F5 Product Development tracked this issue as ID 344159 and it was fixed in BIG-IP version 10.2.2. For information about upgrading, refer to the BIG-IP LTM, ASM, PSM, WebAccelerator, APM, WOM, or Edge Gateway release notes.

Additionally, this issue has been fixed in cumulative hotfix Hotfix-BIGIP-10.2.1-473.0-HF1, which has been issued for BIG-IP version 10.2.1. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

For information about installing a hotfix for version 10.x systems, refer to K10025: Managing F5 product hotfixes for BIG-IP version 10.x systems.
