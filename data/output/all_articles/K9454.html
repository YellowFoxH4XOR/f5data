Known Issue

This is the result of a known issue. Creating a new HTTP class on a BIG-IP ASM system in which one or more security policies is configured with a complex XML profile, causes a temporary spike in CPU use. This issue occurs because the BIG-IP ASM system creates a new XML configuration container for each new Web Application, even if that particular Web Application does not reference an XML profile.

The CPU spike is a transient condition and should clear in approximately 30 seconds. In addition, the CPU spike only affects CPU(s) servicing host processes, and not CPUs dedicated to TMM processing (in non-CMP systems).

If these operations take a long enough period of time, you may see error messages that appear similar to the following examples logged to the var/log/ts/dcc file:

Note: You can safely ignore the following error messages; the system recovers correctly once the load drops back to a normal level.

COMMAND_MAN::check_command, ]   Command UPDATE_CORE(2) - unique id: (194) failed.
dcc[3252]: 01310020:5: ASM Update Config command failed: No acknowledge received from unit: 00:E0:81:4C:D3:3B

Note: If your BIG-IP ASM system contains complex XML profiles, F5 recommends that you create new HTTP classes or Web Applications during low traffic periods.

F5 Product Development is tracking this issue as CR112203.
