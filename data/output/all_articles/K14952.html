Topic

You should consider using these procedures under the following condition:

  • You want to increase the disk space on a BIG-IP Virtual Edition (VE) that does not have sufficient disk space for any of the following tasks:
    • Upgrading software, or installing hotfix or point releases
    • Provisioning multiple modules
    • Preparing for increased logging that requires additional disk space

    Important: The maximum supported disk space is set at 1.9 TB. Only the primary disk (HD1) supports software volume installations. You should extend the primary disk size, rather than adding additional virtual disks, when you need more room for additional software volumes.

Note: For information about increasing the disk space of a BIG-IP tenant running on F5 VELOS or F5 rSeries hardware products, refer to K000137433: Extending disk space for BIG-IP tenants running on F5 VELOS and rSeries. For information about increasing the disk space of a vCMP guest, refer to K24156414: Increasing the disk space for a BIG-IP vCMP guest.

Description

When installing a new boot location or provisioning some modules, BIG-IP creates new volumes using unused space in the LVM physical volume (PV).  BIG-IP automatically detects any additional space added at the hypervisor to the primary disk during boot, and automatically adds it to the LVM physical volume.  In most cases, increasing the disk size at the hypervisor level and rebooting is all that is required to create space for a new boot location or provision an additional module that requires disk space.

The BIG-IP VE image is available in three different sizes for supported hypervisors, in order to keep the consumed disk space to a minimum, for example the 1SLOT (micro) variant  can not be upgraded by default because there is insufficient space for a second boot location. The intention for that image type is that if a software upgrade or hotfix is required, a new virtual machine would be deployed with the new software, rather than upgrading to that version in-place.

Howver, if you have deployed a BIG-IP VE using one of the smaller images, and find the disk size inadequate for upgrading or for storage of logs or data (including hotfix and point release installation) or for provisioning additional feature modules, you can increase the BIG-IP VE disk size, and the volume sizes as needed.

Additionally, even with the 'ALL' image size, which typically has sufficient space to provision all modules, and has space for a second boot location, there are use cases, for example configurations with extensive local logging, where specific volumes may still need additional space allocated to prevent those volumes becoming full. 

If, before or after provisioning a new module, ihe individual volumes/mounts mentioned below are not full (or near full), then there is no need to increase their size.

Before increasing the disk size of individual directories in the BIG-IP VE, you must first increase the disk size in the hosting hypervisor configuration using the steps appropriate for the given hypervisor system. After this is complete, if necessary, you can increase the size of the directories on the BIG-IP VE by using the tmsh modify /sys disk directory /<target directory> new-size <new size in KB> command syntax. Additionally, you can confirm the usable free space available on the disk by using the tmsh list /sys disk command. The BIG-IP VE disk size increase does not take effect until after a reboot. You can use the tmsh show /sys disk directory command to verify if the changes have taken effect. A value in the New Size column in the command output indicates disk size increases that have not taken effect.

Note: In most cases you will find /var to be about 4.4G. For ASM that may not be sufficient. K000157081: Adv WAF and ASM Upgrade Best Practices

For example, the following output from the tmsh show /sys disk directory command indicates that the extension of the /shared directory to 10 GB has not taken effect:

Directory Name                  Current Size    New Size
--------------                  ------------    --------
/config                         503808          -
/shared                         512000          10485760
/var                            503808          -
/var/log                        512000          -
 

The following output indicates that the extension of the /shared directory to 10 GB has taken effect after the reboot:

Directory Name                  Current Size    New Size
--------------                  ------------    --------
/config                         503808          -
/shared                         10485760        -
/var                            503808          -
/var/log                        512000          -

 

The BIG-IP VE supports growing the following directories:

  • /var
  • /var/log
  • /config
  • /shared
  • /appdata

Notes: The shrinking of the disk size is not supported because most hypervisors do not support disk shrinking.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • The BIG-IP VE is deployed using a BIG-IP VE image.
  • You have sufficient access rights to modify the BIG-IP VE guest settings on the hypervisor that is hosting the BIG-IP VE.
  • You have administrative access to the BIG-IP VE.

Procedures

  • Extending disk space for upgrading software, or installing hotfix or point releases on an additional slot
  • Extending disk space for provisioning multiple modules
  • Extending disk space for increased logging

Extending disk space for upgrading software, or installing hotfix or point releases on an additional slot

This procedure is most applicable to BIG-IP VE systems that use the micro instance image with a disk size between 7 GB and 10 GB, depending on version. You can also use this procedure on BIG-IP VE systems that already had a larger disk capacity to allow additional slots if needed. To extend disk space for upgrading software, or installing hotfix or point releases on an additional slot, perform the following procedure.

Important Note: You must shut down the BIG-IP VE during the disk provisioning steps, and the system will not be available for traffic processing. You should perform this procedure during a suitable maintenance window. Increasing the disk size on the BIG-IP VE is irreversible because F5 does not support disk shrinking. Increasing the disk size beyond 1.9 TB may render the system unbootable. F5 recommends the extended disk space should not exceed 1.9 TB.

  1. Log in to the BIG-IP VE Advanced Shell (bash).
  2. To shut down the system, enter the following command:

    shutdown -h now

  3. Provision the desired disk space for the BIG-IP VE on the hypervisor. For example, if you need only one additional slot for an upgrade, or hotfix or point release installation on a BIG-IP VE that is using the micro instance image, you may want to modify the BIG-IP VE guest disk space setting from 7 GB to 31 GB on the hypervisor. For information about disk provisioning on the hypervisor, refer to the documentation from your hypervisor vendor.
  4. Start up the BIG-IP VE guest instance on your hypervisor. For information about starting a guest instance on the hypervisor, refer to the documentation from your hypervisor vendor.
  5. When the BIG-IP VE is up, log in to bash.
  6. Confirm the hypervisor expanded the disk by using the following command:

    tmsh list /sys disk

  7. To extend the /shared directory, use the following command syntax:

    Note: Do not commit all of the disk resource that you have just added to the BIG-IP VE into extending the /shared directory, as the remaining added disk resource may be needed for other purposes, for example space to perform a software installation into a new software slot.

    tmsh modify /sys disk directory /shared new-size <desired value in KB>

    For example, you would enter the following command to extend the /shared directory to 10 GB:

    tmsh modify /sys disk directory /shared new-size 10485760

  8. Save the configuration by entering the following command:

    tmsh save /sys config

  9. Reboot the BIG-IP VE by entering the following command:

    reboot

  10. When the BIG-IP VE is up, log in to bash.
  11. To verify that the /shared directory is successfully extended to the size you have specified in step 7, enter the following command:

    tmsh show /sys disk directory

  12. Upload the ISO images/hotfixes/point releases using the Configuration utility, and install to the next available slot.

Note:  Repeat this procedure to expand the /var/log, /shared, and /appdata directories to the sizes you want. 
           For /config and /var, please refer to the following Important Note.

Important Note:

Do not extend /config and /var unless you meet the following criteria:
   - The BIG-IP VE disk was under 45 GB and has been extended beyond 45 GB
   - /config has a size of about 500000 KB
   - /var has a size of about 900000 KB

Never extend /config and /var beyond the following size.
   /config: 2271424
   /var: 3145728

If /config has already been extended beyond the value, please remove any custom files that are not related to the BIG-IP configration. And make sure the used amount for /config is less than 2GB if the size of the vDisk is higher than 45GB or less than 500MB if the size of the vDisk is lower than 45GB. Otherwise, the upgrade will fail with the following error message in the /var/log/liveinstall.log

info: /var/local/ucs/config.ucs: Not enough free disk space to install! 

Extending disk space for provisioning multiple modules

This procedure is most applicable to a BIG-IP VE using an image with a disk size that is 31 GB or less. You can also perform this procedure on BIG-IP VE that already has a larger disk capacity if additional disk space is required. To extend disk space for provisioning multiple modules, perform the following procedure.

Note: You cannot combine multiple hard drives into one logical volume to extend disk space.

Impact of procedure: You must shut down the BIG-IP VE during the disk provisioning steps, and the system will not be available for traffic processing. You should perform this procedure during a suitable maintenance window. Increasing the disk size on the BIG-IP VE is irreversible because F5 does not support disk shrinking. Increasing the disk size beyond 1.9 TB may render the system unbootable. F5 recommends the extended disk space should not exceed 1.9TB.

  1. Log in to the BIG-IP VE bash.
  2. To shut down the system, enter the following command:

    shutdown -h now

  3. Provision the desired disk space for the BIG-IP VE on the hypervisor. For example, if you need to provision BIG-IP LTM, ASM, and AFM on a BIG-IP VE that is using a 31 GB image, you may want to modify the BIG-IP VE guest disk space setting from 31 GB to 100 GB on the hypervisor. You may also need to increase the number of CPU cores and guest memory on the hypervisor to accommodate provisioning more modules. For information about disk provisioning on the hypervisor, refer to the documentation from your hypervisor vendor.
  4. Start up the BIG-IP VE guest instance on your hypervisor. For information about starting a guest instance on the hypervisor, refer to the documentation from your hypervisor vendor.
  5. When the BIG-IP VE is up, log in to bash.
  6. Confirm the hypervisor expanded the disk by using the following command syntax:

    tmsh list /sys disk

  7. Extend the /var, /var/log, /config, /shared, and /appdata directories as needed to accommodate the module provisioning. For the /var, /var/log, and /config directories, sizes can range from 2 GB to 3 GB or more. The /shared and /appdata directories are larger and can range from 10 GB  to 15 GB or more. For example, to increase the /config directory, use the following command syntax:

    Note: Do not commit all of the disk resource that you have just added to the BIG-IP VE into extending the directories, as the remaining added disk resource may be required to perform the software installation into a new software slot.

    tmsh modify /sys disk directory /config new-size <desired value in KB>

    For example, you would enter the following command to extend the /config directory to 2.1 GB:

    tmsh modify /sys disk directory /config new-size 2171984

    Note: Run the command for each of the other directories to increase their size as needed.

  8. Save the configuration by entering the following command:

    tmsh save /sys config

    Note: df -h output will not show changes until after a reboot of BIG-IP VE

  9. Reboot the BIG-IP VE by entering the following command:

    reboot

  10. When the BIG-IP VE is up, log in to bash.
  11. To verify that the /shared directory is successfully extended to the size you have specified in step 7, enter the following command:

    tmsh show /sys disk directory

  12. Log in to the BIG-IP VE Configuration utility.
  13. Go to System > Resource Provisioning.
  14. Provision the modules as desired.
  15. Select Submit and wait for the system to complete the resource provisioning.

Extending disk space for increased logging

If the BIG-IP VE runs out of disk space due to increased logging, you can extend the disk space for logs by performing the following procedure.

Impact of procedure: You must shut down the BIG-IP VE during the disk provisioning steps, and the system will not be available for traffic processing. You should perform this procedure during a suitable maintenance window. Increasing the disk size on the BIG-IP VE is irreversible because F5 does not support disk shrinking. Increasing the disk size beyond 1.9TB may render the system unbootable. F5 recommends the extended disk space should not exceed 1.9TB.

  1. Log in to the BIG-IP VE bash.
  2. To shut down the system, enter the following command:

    shutdown -h now

  3. Provision the desired disk space for the BIG-IP VE on the hypervisor. For information about disk provisioning on the hypervisor, refer to the documentation from your hypervisor vendor.
  4. Start up the BIG-IP VE guest instance on your hypervisor. For information about starting a guest instance on the hypervisor, refer to the documentation from your hypervisor vendor.
  5. When the BIG-IP VE is up, log in to the command line.
  6. To extend the /var/log directory, use the following command syntax:

    tmsh modify /sys disk directory /var/log new-size <desired value in KB>

    For example, enter the following command to extend the /var/log directory to 10 GB:

    tmsh modify /sys disk directory /var/log new-size 10485760

  7. Save the configuration by entering the following command:

    tmsh save /sys config

  8. Reboot the BIG-IP VE by entering the following command:

    reboot

  9. When the BIG-IP VE is up, log in to bash.
  10. To verify that the /var/log directory is successfully extended to the size you have specified in step 6, enter the following command:

    tmsh show /sys disk directory
