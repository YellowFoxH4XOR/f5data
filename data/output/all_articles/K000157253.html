K000157253: SSLO version isn't upgraded after upgrading BIGIP version from 17.1.x to 17.1.3

Type
Support Solution
Published
2025-10-31
Updated
2025-10-31
Applies to
  • BIG-IP
  • F5 App Protect
  • BIG-IP LTM: 17.1.3
  • BIG-IP SSL Orchestrator: 17.1.3
Source
https://my.f5.com/manage/s/article/K000157253

Description

After upgrading BIG-IP from version 17.1.x to 17.1.3, the SSL Orchestrator (SSLO) package may not automatically update to the expected newer version. When accessing SSL Orchestrator >> Configuration, the upgrade process does not initiate.


Although the new SSLO RPM — f5-iappslx-ssl-orchestrator-17.1.0-11.2.3.noarch.rpm — appears in the directory /usr/share/packages/f5-iappslx-ssl-orchestrator/ after the upgrade, the system continues operating with the previously installed SSLO package.


Environment

BIG-IP software upgrade: From 17.1.x to 17.1.3

SSLO RPM


Cause

An incorrect SSLO RPM package was included in the BIG-IP 17.1.3 release. The version shipped — f5-iappslx-ssl-orchestrator-17.1.0-11.2.3.noarch.rpm — was built with the wrong patch number. The correct version should be f5-iappslx-ssl-orchestrator-17.1.3-11.3.3.noarch.rpm.


As a result, when upgrading from BIG-IP 17.1.x to 17.1.3, the system may detect the SSLO RPM as an older version and skip the upgrade automatically.


F5 has created ID 2141269 to track and address this issue.


Recommended Actions

To work around the issue, you can download the SSL Orchestrator RPM from the F5 downloads site under product version 17.1.3. Then manually import and install it using the SSL Orchestrator GUI.
