Known Issue

The standby BIG-IP system leaks memory when connection mirroring is enabled on a standard virtual server.

When connection mirroring is enabled on a standard virtual server, the standby BIG-IP system leaks 192 bytes of memory for every connection mirrored to it.

Impact

The standby BIG-IP system may eventually run out of memory causing the TMM process to stop responding and restart.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The standby BIG-IP system memory usage grows over time depending on the amount of traffic mirrored to it.
  • The amount of cur_allocs memory for the connflow object continually increases over time.

    The following example shows the tmctl command used to display the memory allocation information and the resulting output:

    # tmctl memory_usage_stat name=connflow

    name allocated max_allocated held size tot_allocs cur_allocs
    -------- --------- ------------- ---- ---- ---------- ----------
    connflow 23552 23808 127 256 366 92

Workaround

To work around this issue, you can disable connection mirroring on the standard virtual server. To do so, perform the following procedure:

Impact of workaround: In the event of a failover, the connections will need to re-establish on the affected virtual server.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers > Virtual Server List.
  3. Click the name of the affected standard virtual server.
  4. Clear the Connection Mirroring check box.
  5. Click Update.
