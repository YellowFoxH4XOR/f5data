Description
The /root/.bash_history file consists of entries including commands run from Bash by user root or any remotely authenticated user who has Advanced Shell privilege.

When it comes to any remotely authenticated user who has Advanced Shell privilege, the timestamp is not logged and we simply observe the command entry being added to the /root/.bash_history file, after the user's session has been terminated. 

Environment

  • BIG-IP: 11.6.0 - 11.6.5, 12.0.0 - 12.1.3.5, 13.0.0, 13.0.1
  • Remote Auth user with Advanced Shell privilege
Cause

Bug ID 624484: Timestamps not available in bash history on non-login interactive shells
Remote user with Advanced Shell access has root privilege, so the commands run from bash will result in them being added to /root/.bash_history file. However, we will only see the commands issued by remote users being added to this file. The timestamp entry in epoch format is not recorded.

Recommended Actions

Refer to Bug ID 624484 for possible workaround and fixed versions

Additional Information

For user root, the timestamp for each issued command will be specified above the command in epoch time format. For example,

#1600297542
uname -n
#1600374471
top -cbn1

The timestamp entry inclusion is controlled by HISTTIMEFORMAT environment variable part of root's bash profile and, in affected versions, remotely authenticated users do not have one. A query for this environment variable's value returns null value when issued by a remote user 'johnsmith':

[johnsmith@bigip1:Active:Standalone] config # echo $HISTTIMEFORMAT

[johnsmith@bigip1:Active:Standalone] config #

The same query, when initiated by user root, results in the variable's value set within it's bash profile:

[root@bigip1:Active:Standalone] config # echo $HISTTIMEFORMAT
%Y-%m-%d %T
[root@bigip1:Active:Standalone] config #
