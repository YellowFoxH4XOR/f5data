Description

NGINX Controller does not start correctly.

You cannot login.

On Startup the controller-postgres-0 pod enters Crashloop.

The log on the pod will report

LOG: invalid resource manager ID in primary checkpoint record
PANIC: could not locate a valid checkpoint record

 

Environment

NGINX Controller with an internal database.

Cause

In some cases the PostgreSQL pod does not shutdown cleanly. Normally it will replay the WAL, but that can be corrupted.

This may be more likely if the database is using a NFS mount

 

Recommended Actions

If you have current backups, reinstall.

See K000134998: Upgrade nginx controller - problem with consistency postgres DB

 

However if the backups, which are located

/opt/nginx-controller/cluster-backup/cluster-config-backup-<data>.tgz

/opt/nginx-controller/postgres_data/backup_<timestamp>UTC.tar

 

are old, you may wish to recover the existing database.

If you are using a nfs mount, mount the share manually.

  1. Check that there is plenty of disk space.
  2. Stop the Controller. This releases the postgres server lock on the db.
    /opt/nginx-controller$ ./helper.sh controller stop
  3. Start the postgresql container, mounting the correct PGDATA location. This gives a bash shell.
    docker run -v /opt/nginx-controller/postgres_data/pgdata:/var/lib/postgresql/data/pgdata -it postgres:12.5-alpine bash
  4. Inside the container, reset the WAL and exit
    su postgres
    pg_resetwal -f -D /var/lib/postgresql/data/pgdata
    exit
    exit
  5. umount nfs if you mounted it manually.
  6. Start Controller. wait 60 mins for a scheduled backup to run.
    /opt/nginx-controller$ ./helper.sh controller start
  7. It should be possible to login to the GUI, or it may be in a failure state.
  8. You can  perform an upgrade using the existing version to update system certificates which may resolve it.

If that does not resolve it, proceed to  K000134998: Upgrade nginx controller - problem with consistency postgres DB

Additional Information

The Controller has a backup and restore function.

This requires that postgreSQL be operational so that psql and pg_restore can work.

Other than the procedure given, the only other option is to reinstall to a new cluster and thus a blank database. Then to perform the restore operation.
