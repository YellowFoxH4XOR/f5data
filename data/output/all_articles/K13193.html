Known Issue

If the Automatic Sync process fails due to a problem with a configuration object, removing the object from the configuration and attempting to manually synchronize the configurations may also fail.

This issue occurs when all of the following conditions are met:

  • Automatic Sync has failed due to a problem with a specific configuration object
  • The problematic object has been manually removed from the configuration and the configuration has been successfully reloaded
  • A manual synchronization is attempted

Under certain circumstances, the Automatic Sync process may fail due to a problem with a given configuration object, such as a SNAT. In general a common workaround would be to manually remove the object from the configuration, reload the configuration, and then attempt to manually synchronize the modified configurations. However this issue may prevent the BIG-IP system from correctly recovering from the failed Automatic Sync event, and the manual synchronization may continue to fail, even with the offending object removed from the BIG-IP configuration.

Impact

System configuration can become unrecoverable, requiring re-installation of the configuration.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • A manual synchronization operation such as Synchronize TO Group or Synchronize FROM Group will complete without generating errors.
  • Configuration changes will not propagate to or from the group, as appropriate to the attempted manual synchronization operation.
  • The affected device will show a sync-failed status, as displayed in the output of the tmsh command show cm device-group in the following example:

    CM::Device-Group
    Group Name Member Name Status
    device-group-failover-18017e0dd6d0 D84BBB.TEST sync-failed
    device-group-failover-18017e0dd6d0 D84TTT.test in-sync

Workaround

While there is no work around available to prevent this issue from occurring, you may be able to recover a system in this state by restoring the system configuration.

For additional information on restoring a configuration, refer to K13132: Backing up and restoring BIG-IP configuration files (11.x).
