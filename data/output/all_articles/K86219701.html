Introduction

When you need to upgrade your BIG-IP instance on Amazon Web Services (AWS), you can use the f5-aws-migrate.py script. The script maintains your AWS BIG-IP instance's network interfaces, IP addresses, security groups, and other resources.

Update or upgrade considerations

Important: The f5-aws-migrate.py script is a F5 DevCentral community-driven project in GitHub. F5 Support does not provide support for the script itself. However, the various underlying products and components used, such as BIG-IP Virtual Edition and UCS restoration, are supported. You should test your update or upgrade thoroughly in a staging environment first and have a backup and restoration plan before performing the procedures in this article.

Before you implement the steps in this article to upgrade your BIG-IP system, you should first consider the following:

  • You should consider first using one of the traditional ISO upgrade methods described in chapters 5 through 8 of this guide. You can use the upgrade method described in this article under the following conditions:
    • Your BIG-IP VE has only a single boot location.
    • You require a completely new BIG-IP VE. For example, you suspect a security compromise on your BIG-IP system. For more information, refer to K11438344: Considerations and guidance when you suspect a security compromise on a BIG-IP system
  • This article does not apply when your BIG-IP virtual machine is an instance in an AWS autoscaling group.
  • If you previously used a continuous integration/continuous delivery (CI/CD) orchestration or automation tool such as Ansible or Terraform to deploy your BIG-IP AWS instance, you should continue using the same tool to perform the upgrade.

The script performs the following tasks to upgrade your BIG-IP AWS instance:

  1. Logs in to the BIG-IP system using SSH, iControl to create a user configuration set (UCS) archive.
  2. Polls AWS to gather the network interfaces of your BIG-IP instance.
  3. Sets the DeleteOnTermination value of the elastic network interfaces (ENIs) in your BIG-IP instance to False, so they can be re-used.
  4. Terminates your original BIG-IP instance, detaching its ENIs for re-use.
  5. Opens a new BIG-IP instance from an Amazon Machine Image (AMI) of your choice. This is your new, upgraded BIG-IP AWS instance.
  6. Installs the license for bring-your-own-license (BYOL) from the RegKey in the source AMI instance or option.
  7. For BIG-IP BYOL systems, uses the RegKey from the source AMI image or from the command line option you specified to install the license on the system.
  8. Restores the UCS archive on the new upgraded BIG-IP instance (with the no-license flag so as not to overwrite the new license).

Upgrade vs. update

This chapter may use the word upgrade to refer to either a software upgrade or update. For a definition that explains the difference between the two terms, refer to Upgrading vs. updating in the Introduction.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • AWS environment requirements:
    • This procedure applies only to updating or upgrading your BIG-IP instance. It restores a UCS archive generated from the original BIG-IP instance on the new BIG-IP instance. Downgrading fails.
    • Your BIG-IP instance must have a name. Verify you have one at AWS Console > EC2 > Instances.
    • The management IP address for your BIG-IP instance is an Elastic IP address. Without an Elastic IP address, AWS allocates a different management IP address to the new BIG-IP instance, which prevents the script from logging in to restore the UCS archive. In this case, you must perform the UCS restoration manually. For more information on public IP address persistence in AWS, refer to Public IPv4 addresses in the Amazon VPC User Guide.
  • Client system requirements:
    • You have a Linux remote client machine that has SSH and Secure Copy (SCP) protocol access to the management interface of the BIG-IP instance.
    • You have the SSH PEM file and administrative credentials to log in to the BIG-IP instance.
    • You have the aws_access_key_id and aws_secret_access_key credentials to log in to the AWS portal.
    • For BIG-IP BYOL systems, the script uses the registration key from the source AMI image or from the command line option you specified to install the license on the system automatically. This means your BIG-IP instance must have internet connectivity to the F5 license server (https://secure.f5.com/Infopage/index.jsp). When this is not possible, you must manually perform the licensing and UCS archive restore on the BIG-IP system after the script launches the new BIG-IP instance. For more information, refer to K7752: Licensing the BIG-IP system.
    • Your remote Linux client machine has the following software installed:

      Note: You can install each software application by navigating to its website or use your Linux client software management tool to install on your client directly. For example, apt-get install <software> or yum install <software> depending on your Linux distribution.

      Note: These links take you to resources outside of AskF5, and it is possible that the documents may be removed without our knowledge.

      • Python 2.7 environment: python.org
      • AWS command line interface (for testing and troubleshooting): AWS
      • BOTO3 (required to run the script): Boto3
      • Pexpect (required to run the script in CVE mode using -C or --CVE flags): Pexpect

Prepare

Implement your backup plan

Perform the following backup steps:

  • Back up your BIG-IP AWS instance. For example, you can use AWS Backup. For more information, refer to AWS Backup.

    Note: This link takes you to resources outside of AskF5, and it is possible that the document may be removed without our knowledge.

  • On the BIG-IP system, generate a UCS archive. Although the f5-aws-migrate.py script generates a backup file and saves it in your local remote directory, generate one and save it locally as well. For more information, refer to K4423: Overview of UCS archives.

With these two backups in place, you can easily recover your BIG-IP instance if necessary.

Determine the AMI ID of the image you want to update or upgrade to

The f5-aws-migrate.py script requires you to provide the AMI ID to launch the new BIG-IP instance.

Important: Providing an invalid or incompatible AMI image to the script results in failure to upgrade and you may have to perform the upgrade by launching the correct instance and associating AWS resources all manually.

  1. Log in to the AWS Management Console.
  2. Search for marketplace and select AWS Marketplace Subscriptions.
  3. Do one of the following:
    • In your subscription, in the list of AMI images, if you can find an image you want to upgrade to, select the image, and then skip to the next step.
    • If you cannot find an image you want to upgrade to, perform the steps in the Add an AMI image to your subscription section, and then continue to the next step.
  4. Select Launch new instance for the AMI image you want to use.
  5. Software Version lists the latest version available. If you require a different version, select full AWS Marketplace website.
  6. Select the Software Version.
  7. Select your Region
  8. Note the AMI ID number at the bottom of the form.

    You must provide the AMI ID when you run the f5-aws-migrate.py script.

    For example, you note the following AMI ID:

    AMI ID: ami-034ae61881d640103

Install the f5-aws-migrate.py script and required files on your remote client

Install the f5-aws-migrate.py, restore-clean-ucs, and save-clean-ucs files on your remote Linux client machine.

For example, to install f5-aws-migrate.py, perform the following procedure:

  1. Go to f5-aws-migrate on GitHub.
  2. Select f5-aws-migrate.py.
  3. Select Raw.
  4. To select all and then paste the contents of the script using your favorite editor on your client machine, select Ctrl+a.
  5. Save the file.
  6. Repeat steps 1-5 for restore-clean-ucs and save-clean-ucs.

When you finish, you have three files in the same directory.

Install your AWS access credentials on your remote client

To manage resources on your AWS account, you must provide your AWS credentials on your remote client. To do so, performing the following procedure:

  1. Go to the hidden AWS directory in your user home directory by entering the following command:

    cd ~/.aws

  2. Create a file named credentials by entering the following command:

    touch credentials

  3. Use a text editor to paste your AWS credentials to the file.

    For example, you type the following code syntax:

    [default]
    aws_access_key_id = APOPJOYHFXYCWHKZDJ3Q
    aws_secret_access_key = MYsVrwik4ArWSvhgitcqUu6CIDG+Fvg2D5jp9aJ5

  4. Create a file named config by entering the following command:

    touch config

  5. Use a text editor to paste the following text into the file:

    [default]

Update or upgrade

Revoke your BYOL license for reuse on a new BIG-IP instance

Perform the following procedure when you are upgrading from a BYOL instance to a BYOL instance. If your new (target) BIG-IP instance is pay-as-you-go (PAYG) and does not require a registration key, skip this procedure.

In BIG-IP VE 12.1.3.3 and later, and in BIG-IP 13.1.0.2 and later, you can revoke a BYOL license from a BIG-IP VE system and re-use the license on a different BIG-IP VE system. For more information, refer to K41458656: Reusing a BIG-IP VE license on a different BIG-IP VE system.

Impact of procedure: Revoking the license results in a disruption of services. F5 recommends performing this procedure during a scheduled maintenance window.

  1. Record your BIG-IP license key.
  2. Log in to the TMOS Shell (tmsh) by entering the following command:

    tmsh

  3. To revoke the license, enter the following command:

    revoke /sys license

  4. You can now install the license on the new BIG-IP VE system.

Run the script to perform the update or upgrade

To start the upgrade process, run the f5-aws-migrate.py script by performing the following procedure:

Impact of procedure: Running the script begins the upgrade process, resulting in a disruption in services. F5 recommends performing this procedure during a scheduled maintenance window.

  1. To display the Help menu for a list of options you can include in the command, enter the following:

    python f5-aws-migrate.py -h

  2. Verify the following checks before entering the command to start the upgrade process:
    • Your BIG-IP instance must have a name. Verify you have one at AWS Console > EC2 > Instances.
    • The key you provide with the -k switch in the next step must be readable on the filesystem and exist in your AWS account. Verify the key at AWS Console > EC2 > Network & Security > Key Pairs.
  3. To run the script and start the upgrade process, use the script example in the following table that is appropriate for your upgrade and licensing case.
    If you are updating or upgrading from and to these types of instances:Use this 'f5-aws-migrate.py' script example:
    From PAYG utility instance to a PAYG utility instancepython f5-aws-migrate.py -k /home/john/.ssh/keypair.pem -i i-155b46d2 -m 10.0.0.245 -u admin -p ‘strongpassword’ -d ami-d9ee1ab9 -R us-west-2 --debug-level 1
    From BYOL instance to a BYOL instancepython f5-aws-migrate.py -k /home/john/.ssh/keypair.pem -i i-f75d4030 -m 10.0.0.245 -u admin -p ‘strongpassword’ -d ami-5fe81c3f -r ZJQWC-EXJMJ-HEKVX-KNJTB-LGUCGVZ  -R us-west-2 --debug-level 1
    From PAYG utility instance to a new BYOL instancepython f5-aws-migrate.py -k /home/john/.ssh/keypair.pem -i i-155b46d2 -m 10.0.0.245 -u admin -p ‘strongpassword’ -d ami-5fe81c3f -r ZJQWC-EXJMJ-HEKVX-KNJTB-LGUCGVZ -R us-west-2 --debug-level 1
    Note: You need to use the -r switch to specify your license registration key for the new (upgraded) BIG-IP instance.
    BYOL instance to a new PAYG utility instancepython f5-aws-migrate.py -k /home/john/.ssh/keypair.pem -i i-f75d4030 -m 10.0.0.245 -u admin -p ‘strongpassword’ -d ami-d9ee1ab9 -R us-west-2 --debug-level 1

You upgraded your BIG-IP AWS instance.

Troubleshoot

The Introduction section lists the tasks that the script performs. Follow the output that the system displays to ensure that the command completes all of the tasks.

When the script finishes running, the system displays output similar to the following example:

Note: It is possible for the system to log errors and then run the script completely.

/var/local/ucs/f5-i-0bd6843b0d3629e1a.ucs is loaded.

_____BIG-IP Migration Completed_____

When the script finishes running, it saves the following files in the local directory for verification, backup, and restoration purposes:

  • f5-i-<instanceID>-cached-bigip-license: the original BIG-IP license file
  • f5-i-<instanceID>-cached-instance.json: json file with information about your BIG-IP AWS instance
  • f5-i-<instanceID>-cached-new-instance.json: json file with information of the new (upgraded) BIG-IP AWS instance
  • f5-i-0bd6843b0d3629e1a.ucs: UCS archive generated at the beginning of the script run
