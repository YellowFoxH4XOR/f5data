Description
Static NAT translation uses a one to one IP mapping (1:1), port remains unchanged. This means that it requires the same number of origin addresses than translated addresses. If we use the same translated IP in different NAT policies of different NAT rules in the same policy for different origin IPs,  the static NAT will not properly, and you may find RST from AFM.
 

Environment

  • BIG-IP AFM
  • Configure the same source or destination translated IP in multiple NAT policies or NAT rules mapped to different origin IPs.

For example, for destination static NAT:
In this example, 10.0.0.0 is used in multiple policies(NAT-policy-1 and NAT-policy-2) as translation destination.

security nat policy NAT-policy-1 { 
    rules {
        nat-rule-1 {
            destination {
                addresses {
                    10.0.0.1{ }
                }
            }
            log-profile global-network
            source {
                address-lists {
                    list-1
                }
            }
            translation {
                destination 10.0.0.0   <------!!!
                source SNAT1
            }
        }
    }
    traffic-group /Common/traffic-group-1
}


security nat policy NAT-policy-2 {
    rules {
        nat-rule-2 {
            destination {
                addresses {
                    10.0.0.3 { }
                }
            }
            log-profile global-network
            translation {
                destination 10.0.0.0   <------!!!
            }
        }
    }
    traffic-group /Common/traffic-group-1
}


Then, you will find that NAT won't work properly.
From the client;

# curl http://10.0.0.2/
curl: (56) Failure when receiving data from the peer


You will see the the error message in /var/log/ltm

test err tmm7[14668]: 01230140:3: RST sent from 10.0.0.2:80 to 10.0.0.132:14815, [0x2b03774:4583] (FW NAT) dst_trans failed.
 

In case of this configuration error when using source static NAT you will get an error including:

[...] "src_addr_trans error"

Cause
It is our AFM design. Static NAT is 1:1 mapping, the same IP cannot be assigned to more than one origin IP.

Recommended Actions

Remove the duplicated static NAT translation from the policy or add more translated IPs.
