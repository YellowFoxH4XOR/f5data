Known Issue

This is the result of a known issue. When the BIG-IP system is licensed for hardware compression, if compression is enabled for any virtual server, the Linux top utility, SNMP, and the BIG-IP performance graphs report CPU 0 usage at 100 percent, and continue to do so even after compression is disabled on all virtual servers.

When the BIG-IP system is configured to use compression, the system starts the tmzd process. Once started, the tmzd process appears to use 100 percent of CPU 0. As a result, the tmzd process is running, and incorrect usage metrics are displayed in the statistics section of the BIG-IP LTM Configuration utility, in SNMP, and in the top utility.

Important: Although CPU 0 appears to be fully consumed, the tmzd process yields the CPU to other processes, as needed.

Note: This issue is also present in BIG-IP LTM versions prior to 9.4, when you use the tm_comp process. For more information, refer to K6775: BIG-IP performance graphs report the CPU 0 usage at 100 percent if the BIG-IP system is licensed for hardware compression.

F5 Product Development tracked this issue as CR71202, and it was fixed in BIG-IP LTM 9.4.2. For information about upgrading, refer to the BIG-IP LTM release notes.

Workaround

You can work around this issue by re-booting the affected BIG-IP system.
