K000137023: Using wildcard SNAT may lead to stale connections piling up

Type
Support Solution
Published
2023-09-28
Updated
2025-02-07
Applies to
  • BIG-IP
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K000137023

Description

If wildcard SNAT is configured:

ltm snat /Common/wildcard-snat {
    ...
    origins {
         0.0.0.0%1/0 

In specific conditions:

- There is a spike in active connections
- Increased CPU/Memory resource utilization on the device
- The aggressive mode sweeper might be triggered
 

Environment

  • Wildcard SNAT

Cause

If traffic does not hit any virtual server and the BIG-IP system is unable to reach the destination, while the connection was already SNAT-ed, connections will be stuck, due to SNAT timeout being indefinite by default. It will lead to resource exhaustion as the connection can be only closed gracefully, which is not possible in such a case.

Recommended Actions

If wildcard SNAT needs to be applied, consider changing the TCP Idle timeout for this SNAT to a reasonable value.
 

Additional Information

None.
