Topic

The bigd process manages health checking for pool members, nodes, and services on the BIG-IP LTM system. This process collects health checking status and communicates the status information to the Master Control Program Daemon (MCPD), which stores the data in shared memory so that the Traffic Management Microkernel (TMM) can read it.

In the event that the bigd process stops or is manually shut down, the mcpd process continues to store (in memory) the last known status of pool members, nodes, and services that it received from the bigd process. Therefore, it is possible for the bigd process to stop or be shut down, but for the BIG-IP LTM system to mark up the pool members, nodes, and services.

For example, a pool named HTTP_POOL currently has five members marked up and three members marked down by an HTTP monitor. The bigd process collects the pool member status and passes the status to the mcpd process. The mcpd process stores the pool member status for HTTP_POOL in shared memory so the TMM can read the status. If the bigd process then stops or is manually shut down, the mcpd process continues to report the last known status for the pool. In this case, the last known status for HTTP_POOL is five members marked up and three members marked down.
