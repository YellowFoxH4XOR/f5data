Topic

You should consider using this procedure under the following conditions:

  • You want to configure Lightweight Directory Access Protocol Secure (LDAPS) when using the BIG-IP system as a passthrough device.
  • You want to configure LDAPS when offloading SSL processing to a BIG-IP device.

Description

This article provides guidance to configure BIG-IP system to load balance LDAPS traffic to the back-end servers pool. In an SSL passthrough configuration, the BIG-IP system forwards encrypted LDAPS traffic to the back-end LDAPS servers without decryption. This type of configuration is preferable when you do not want the BIG-IP system to do anything with encrypted traffic but simply load balance it to a pool of destination LDAPS servers for processing.

When you configure Client SSL or Server SSL profiles and assign them to a virtual server, the BIG-IP system offloads SSL processing from the destination server. The most common way to configure the BIG-IP system is to create a Client SSL profile, which makes it possible for the BIG-IP system to decrypt client LDAPS traffic before sending them to the back-end server, and encrypt server responses before sending them back to the client. You can optionally configure a Server SSL profile for enhanced security on your internal network. When you configure Server SSL profile, the BIG-IP system re-encrypts the LDAPS traffic before sending it to the LDAPS server.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You can access the BIG-IP Configuration utility.
  • You must import a valid certificate and key onto the BIG-IP system if configuring the system for SSL offload.

Configure LDAPS when using the BIG-IP system as a passthrough device

When configuring BIG-IP system for passthrough, you are not required to configure Client SSL or Server SSL profile since your virtual server does not decrypt or encrypt the LADPS traffic. To load balance LDAPS traffic on a BIG-IP system, perform the following procedures:

Note: Ensure that you include the fully qualified domain name (FQDN) of the virtual server in the server SSL certificate installed on each LDAPS server in your pool.

Impact of procedure: Performing the following procedures should not have a negative impact on your system

Configure the Persistence profile

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > Persistence > Create.
  3. Specify a name for the new Persistence profile.

    For example:

    ldaps_sourceaddress

  4. For Persistence Type, select appropriate type from the list.

    For example, you can create Persistence profile using the Source Address Affinity parent.

  5. Configure any remaining settings as needed.
  6. Select Finished.

Create an LDAPS health monitor

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Monitors.
  3. Select Create.
  4. Specify a Name for the new monitor.

    For example:

    ldaps_monitor

  5. Optional: For Description, enter a description for the monitor.
  6. For Type, select LDAP.
  7. For Security , select either TLS or SSL, as appropriate for your configuration.

    Note: There is currently no option within the LDAP monitor to specify an SSL profile or define client or server certificate authentication.

  8. Configure any remaining settings that apply to the LDAP service you want to monitor.
  9. Select Finished.

Create an LDAPS server pool

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Pools > Pool List.
  3. Select Create.
  4. For Name, enter the name of the pool.
  5. For Health Monitors, in the Available list, select the monitor you created in the previous procedure and move it to the Active list.
  6. For Node Name, enter a name for the new node.
  7. For Address, enter the IP address of the new node.
  8. For Service Port, enter port 636 (LDAPS port).

    Note: Port 389 is the virtual port used for LDAP, and port 636 is used for LDAPS.

  9. Select Add.
  10. Configure any remaining settings as needed.
  11. Select Finished.

Create a virtual server for LDAPS

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Virtual Servers > Virtual Server List.
  3. Select Create.
  4. For Name, enter a name for the new virtual server.

    Optional: For Description, enter a description for the virtual server.

  5. For Source Address, enter the IP address.

    For example,

    0.0.0.0/0

  6. For Destination Address/Mask, enter the virtual server IP address.
  7. For Service Port, enter port number 636 for the LDAPS server.
  8. Under Resources, for Default Pool, select the LDAP server pool you created earlier.
  9. Under Resources, for Default Persistence Profile, select the Persistence profile you created earlier.
  10. Configure any remaining settings as needed.
  11. Select Finished.

Configure LDAPS when offloading SSL processing to a BIG-IP system

You configure a Client SSL profile when you want the BIG-IP system to terminate client-side SSL traffic for the purpose of decrypting client-side ingress traffic and encrypting client-side egress traffic. By terminating client-side SSL traffic, the BIG-IP system offloads these decryption/encryption functions from the destination LDAPS servers.

Impact of procedure: Performing the following procedures should not have a negative impact on your system

Configure the Client SSL profile

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > SSL > Client.
  3. Select Create to create a new profile.
  4. For Name, enter the name for your profile.
  5. Select the Custom check box for Certificate Key Chain if it is not already selected.
  6. For Certificate Key Chain, select the associated certificate and key you imported earlier.
  7. Select Add.
  8. Configure any remaining settings as needed.
  9. Select Finished. Assign this profile to the virtual server you create in the final procedure.

Configure the Server SSL profile

You can optionally configure a Server SSL profile if you want the BIG-IP system to perform re-encryption for server-side LDAPS traffic.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > SSL > Server.
  3. Select Create to create a new profile.
  4. For Name, enter the name for your profile.
  5. Perform the following optional steps to configure server authentication or configure other settings as needed and select Finished.
  6. Import the trusted CA certificate or CA certificate bundle by following the steps of the Import an SSL certificate procedure in K14620: Manage SSL certificates for BIG-IP systems using the Configuration utility.
  7. Select Custom for the Server Authentication section.
  8. For Server Certificate select require.
  9. For Authenticate Name enter the common name (CN) of the server certificate which must be a fully qualified domain name (FQDN).
  10. For Trusted Certificate Authorities select the certificate or certificate bundle you imported previously.
  11. Configure other settings as needed and select Finished. Assign this profile to the virtual server you create in the final procedure.

Configure the Persistence profile

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Profiles > Persistence > Create.
  3. Specify a name for the new Persistence profile.

    For example:

    ldaps_sourceaddress

  4. For Persistence Type, select appropriate type from the list.

    For example, you can create persistence profile using the Source Address Affinity parent.

  5. Configure any remaining settings as needed.
  6. Select Finished.

Create an LDAPS health monitor

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Monitors.
  3. Select Create.
  4. Specify a Name for the new monitor.

    For example:

    ldaps_monitor

  5. Optional: For Description, enter a description for the monitor.
  6. For Type, select LDAP.
  7. Optional: For Security, select either TLS or SSL as appropriate for your configuration.

    Note: Use this option if you are configuring the BIG-IP system to re-encrypt traffic to the LDAP servers. There is currently no option within the LDAP monitor to specify an SSL profile or define client or server certificate authentication.

  8. Configure any remaining settings that apply to the LDAP service you want to monitor.
  9. Select Finished.

Create an LDAP server pool

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Pools > Pool List.
  3. Select Create.
  4. For Name, enter the name of the pool.
  5. For Health Monitors, in the Available list, select the monitor you created in the previous procedure and move it to the Active list.
  6. For Node Name, enter a name for the new node.
  7. For Address, enter the IP address of the new node.
  8. For Service Port, enter 389, or 636 if you are configuring the virtual server to re-encrypt the LDAP traffic.
  9. Select Add.
  10. Configure any remaining settings as needed.
  11. Select Finished.

Create an LDAPS virtual server

  1. Log in to the Configuration utility.
  2. Go to Local Traffic > Virtual Servers > Virtual Server List.
  3. Select Create.
  4. For Name, enter a name for the new virtual server.

    Optional: For Description, enter a description for the virtual server.

  5. For Source Address, enter the IP address.

    For example,

    0.0.0.0/0

  6. For Destination Address/Mask, enter the virtual server IP address.
  7. For Service Port, enter port number 636 for the LDAPS server.
  8. For SSL Profile (Client), in the Available list, select the client SSL profile you created and move it to the Selected list.

    Optional: For SSL Profile (Server), in the Available list, select the server SSL profile you created and move it to the Selected list.

    Note: Use this option if you are configuring the BIG-IP system to re-encrypt traffic to the LDAP servers.

  9. Under Resources, for Default Pool, select the LDAP server pool you created earlier.
  10. For Default Persistence Profile, select the Persistence profile you created earlier.
  11. Configure any remaining settings as needed.
  12. Select Finished.
