K000163102: Venafi rejected CSRs generated by the F5OS appliance with the error “The CSR you have entered could not be decoded.”

Type
Support Solution
Published
2026-08-26
Updated
2026-08-26
Applies to

  • F5OS: 2.0.0
Source
https://my.f5.com/manage/s/article/K000163102

Description

Venafi rejected CSRs generated by the F5OS appliance with the error “The CSR you have entered could not be decoded", because the generated CSR contained an incorrect PKCS#10 version encoding.

 

Environment

  • F5 rSeries R5000-series appliance.
  • F5OS 2.0.
  • Venafi was upgraded to version 25.3, after which stricter CSR validation exposed the issue.
  • CSR generation was performed through the F5OS CLI or GUI and submitted to Venafi for certificate issuance.

 

Cause

F5OS CSR generation produced a non-compliant PKCS#10 version encoding of "INTEGER:01 (0x1)", instead of the expected "INTEGER:00 (0x0)". Venafi 25.3 applied stricter CSR parsing and rejected the resulting CSR as undecodable. This behavior was reproduced on F5OS 2.0 and tracked under Bug ID2452829. The issue was resolved by generating the CSR and private key externally with OpenSSL, obtaining the signed certificate from Venafi, and importing the signed certificate and the respective private key into F5OS.

NOTE: Bug ID2452829 has no public facing article while this article was published.

Answer/Recommended Actions

- Until Bug ID2452829 is fixed, use a Linux system or another host with OpenSSL to generate the CSR and private key for the F5OS appliance.

- After Venafi signs the CSR, install the signed leaf certificate and its matching private key on F5OS.

- Install root and intermediate certificates separately in the F5OS CA bundle; do not paste the complete certificate chain into the leaf certificate field.

- Verify the installed certificate.

 

Additional Information

If you don't have another Linux machine, use the F5OS bash CLI.

(1) Login the F5OS by using the "root" account, and backup your current device certificate and key.
# cp -p /var/system/httpd/ssl/f5os.crt /var/tmp/f5os.crt.backup
# cp -p /var/system/httpd/ssl/f5os.key /var/tmp/f5os.key.backup


(2) Create the OpenSSL config. (Modify the details as required)

cat > /var/tmp/f5os-csr.cnf <<'EOF'
[req]
prompt = no
distinguished_name = req_distinguished_name
req_extensions = req_ext

[req_distinguished_name]
C = US
ST = New York
L = New York
O = Example Corporation
OU = Network Security
CN = adc01.example.com

[req_ext]
subjectAltName = DNS:adc01.example.com,IP:192.0.2.10
EOF


(3) Use the OpenSSL command to generate the CSR and private key.

openssl req -new \
  -newkey rsa:4096 \
  -nodes \
  -sha256 \
  -keyout /var/tmp/f5os-device.key \
  -out /var/tmp/f5os-device.csr \
  -config /var/tmp/f5os-csr.cnf
  
NOTE: Make sure there is no empty line between each line.

(4) The CSR and private key will output in the CLI.

  • Copy the CSR and submit for certificate issuance.
  • Keep the private key with you.

(5) Once the certificate gets signed, import the certificate, key, and CA bundle via the GUI.
Authentication & Access > TLS configuration.

  • Add the signed certificate to the TLS certificate, and the private key to the TLS key. (Leave the "TLS key passphrase" empty.)
  • Add the Root and Intermediate certificate to the CA bundle.

(6) Log out the web GUI, refresh the web browser to re-connect to the GUI with the correct FQDN.

  • Check if the browser shows "this is a secured connection" and check the certificate chain.
