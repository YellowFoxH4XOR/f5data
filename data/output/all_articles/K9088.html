Known Issue

This is the result of a known issue. If a client requests a compressed document, the response contains a Vary value that replaces a previously cached entry of the same document that does not contain a Vary header. The compressed document overwrites the cache entry with an empty Vary value. As a result, subsequent client requests that do not request compression will receive the compressed content.

F5 Product Development tracked this issue as CR102693 and it was fixed in BIG-IP LTM 9.4.6. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Additionally, this issue was fixed in Hotfix-BIGIP-9.4.4-94.0-HF3, issued for BIG-IP 9.4.4, and in Hotfix-BIG-IP-9.4.5-HF2, issued for BIG-IP 9.4.5. You may download this hotfix or a later version of the hotfix from the F5 Downloads site.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

For information about how to manage F5 product hotfixes, refer to K6845: Managing BIG-IP product hotfixes (9.x).
