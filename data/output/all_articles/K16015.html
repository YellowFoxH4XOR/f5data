Known Issue

The BIG-IP system may truncate log files, and fail to store log messages for longer than 24 hours.

This issue occurs when the following condition is met:

  • Your BIG-IP system experiences heavy logging; this is more likely to occur on a multi-blade system in a high availability (HA) configuration.

The max-file-size log-rotate variable is set to 1024. This may cause BIG-IP systems to truncate log files, and prevent log files from storing messages for the expected period of time.

Impact

Diagnosing and troubleshooting issues using the log files may be difficult.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H501962 on the Diagnostics > Identified > Medium screen.
  • The system log files are truncated; some log messages are not available on the system.

Workaround

To work around this issue, you can change the max-file-size log-rotate variable to a higher value. 102400 (1GB) is recommended. Setting it to zero (0) disables the setting. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To set the max-file-size log-rotate variable to 102400, type the following command:

    modify /sys log-rotate max-file-size 102400

  3. Save the change by typing the following command:

    save /sys config
