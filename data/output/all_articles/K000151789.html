Description

In rare circumstances, with specific configurations where both asymmetric routing and L2 proxying is configured, a tenant may respond with a RST packet with a src MAC of the upstream hop. F5OS will learn a duplicate FDB entry from the RST packet, which may cause BIGIP to send the traffic from an unexpected vlan .

Environment

  •  F5OS
  • Asymmetric routing (Fastl4 forwarding virtual)
  • VLAN groups or L2 forwarding virtual

Cause

  • Based on the below capture on tenant, as the there is no existing connection, BIGIP sends the RST with source MAC 00:50:56:9d:08:04 - which is the dst MAC of the upstream device the client was sending to:

Ethernet II, Src: 00:50:56:9d:08:03, Dst: 00:50:56:9d:08:04
    
2.  1.322397 0.000000 4093 10.6.1.201→ 10.6.1.55 40 443 51000 TCP OUT s1/tmm7 : 443 → 51000 [RST, ACK] Seq=1 Ack=32 Win=0 Len=0 [F5RST: No flow found for ACK
Ethernet II, Src:00:50:56:9d:08:04 , Dst: Src: 00:50:56:9d:08:03

  • When F5OS receives the RST packet, it will add a new FDB entry, the value F for ifh.did means this entry is learned from the tenant. You may see duplicate entries as below learned from different vlans, the first entry is learned from normal traffic.

 

mac        nti l2_tag tag_type entry_type owner fpga nse_unit table address age ifh.nti ifh.nti_en ifh.did

00:50:56:9d:08:04 4095  4092    1     1   1  1    0 Hash   245C 30    0     0   15

00:50:56:9d:08:04 4095  4093    1     1   1  0    0 Hash   196C 300    0     0    F

  • When the first FDB entry times out, a tenant egresses traffic to a static mac address, and there have been no ingress packets from that mac address, there will be no l2 nse entry for that destination,So traffic will be flooded out all ports. You may see the traffic is sent out from an unexpected vlan and cause an outage.

Recommended Actions

  • Check the asymmetric routing issue, block this traffic if it's unexpected.
  • This is expected behavior based on F5OS design. In cases such as this you can add a static FDB entry on F5OS
