K9540: Appropriate use of wildcards when configuring the Requested Host definitions for a BIG-IP WebAccelerator application

Topic

Only hostnames that are optimized by the BIG-IP WebAccelerator should be configured in the Requested Hosts section of the WebAccelerator application. In particular, F5 recommends against using an asterisk ( * ) character as a wildcard to represent all hostnames within a domain unless all of the hostnames in the domain are optimized by the BIG-IP WebAccelerator system. 

The BIG-IP WebAccelerator system applies Intelligent Browser Referencing (IBR), multiconnect, and other URI modifications to all URIs embedded in the response whose hostnames match those in the Requested Hosts list. As a result, requests for the modified URIs are intended to be processed by the WebAccelerator system. However, if the hostname in the modified URI refers to an application that is not not optimized by the BIG-IP WebAccelerator, the BIG-IP system will respond with HTTP 404 errors any request for the modified URI.

For example, if you configure a single entry as *.domain.com, and the page returned in response to a request for www.domain.com includes URIs for hostnames host1.domain.com through host99.domain.com, but only host1.domain.com, host2.domain.com, and host99.domain.com are optimized by the BIG-IP WebAccelerator, the client will receive HTTP 404 errors for any subsequent requests for the modified URIs that reference host3.domain.com through host98.domain.com.

Note: Similar issues will be encountered if any hostname that is not managed by the BIG-IP WebAccelerator is configured in the Requested Hosts section.
