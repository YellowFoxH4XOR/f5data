K45308356: Want to upgrade standby unit, then upgrade active unit several days later

Type
Support Solution
Published
2020-06-08
Updated

Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.X, 15.1.8, 15.1.7, 15.1.6, 15.1.5, 15.1.4, 15.1.3, 15.1.2, 15.1.1, 13.1.X, 13.1.5, 13.1.4, 13.1.3, 13.1.1, 13.1.0, 15.1.0
Source

Description

You want to upgrade your standby unit to a different major version, then upgrade your active unit several days later. For example, you have two units running 13.1.x, and you would like to upgrade one to 15.1.x, while the remaining unit will still run 13.1.x for several days.

You would like to know if sync and failover functions will work during this time, and if the cluster will be stable.

Environment

  • Upgrade
  • ConfigSync
  • Failover

Cause

None

Recommended Actions

Failover will likely work as expected in this scenario, as this is a simple UDP heartbeat between peers. ConfigSync will not work, so no changes should be made during the interim period.

Furthermore, this is far from an ideal scenario, so this should be avoided if possible, and both units should be upgraded at the same time.

Ensure that the failover configuration includes both a management and TMM channel, as per the following article:

  • K14135: Defining network resources for BIG-IP HA features (11.x - 15.x)

Additional Information

You may review the current status of the HA channel with the following command:

tmsh show /cm failover

The below example output indicates that both failover channels are established and receiving packets from the peer. One system is running 15.1.0.3 and one is running 13.1.1.2.

[root@bigip1:Active:Disconnected] images # tmsh show cm failover | tail -5

-----------------------------------------------------------------------------------------------------
10.0.115.243:1026       bigip1.com                 331280   5            2020-Jun-03 13:34:42  Ok

Note: The sync status in the prompt indicates Disconnected. This means that sync will not work.
