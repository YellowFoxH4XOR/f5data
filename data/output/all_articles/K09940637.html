Security Advisory Description

Network Time Protocol (NTP), as specified in RFC 5905, uses port 123 even for modes where a fixed port number is not required, which makes it easier for remote attackers to conduct off-path attacks. (CVE-2019-11331)

Impact

Using an off-path attack (not a man-in-the-middle attack), a remote attacker may more easily exploit unpatched NTP vulnerabilities, which could potentially allow an an attacker to access resources, modify files, or cause a denial of service (DoS) attack.

This vulnerability is inherent in RFC 5905, and thus F5 cannot affect a fix without breaking compatibility. IETF has drafted a port randomization RFC for future publication and adoption. For further information, refer see the Supplemental Information section in this article.

Mitigation

To mitigate this vulnerability, the NTP source port can be randomized by iptables masquerading rules.

Notes:

  • iptables and ip6tables command changes do not persist after BIG-IP software upgrades. These commands needs to be re-run after an upgrade.
  • iptables and ip6tables command changes do not sync to peer device in HA. These commands need to be executed on individual BIG-IP devices in the HA/sync device groups.
  • Ensure to run the service iptables save and service ip6tables save commands. iptables and ip6tables changes when saved, persist after a BIG-IP system reboot.

To do so, use one of the following as appropriate:

  • BIG-IP systems with IPv4 IP addresses
  • Multi blade tenant or vcmp guest or BIG-IP with IPv4 IP addresses
  • BIG-IP systems with IPv6 IP addresses
  • Multi blade tenant or vcmp guest or BIG-IP with IPv6 IP addresses

BIG-IP systems with IPv4 IP addresses

  1. Login as root on the BIG-IP command line.
  2. Randomize the NTP source port by entering the following command:
    /sbin/iptables -t nat -I POSTROUTING -p udp -m udp --sport 123 -j MASQUERADE --to-ports 60000-61000
  3. List the change in the NAT table:
    /sbin/iptables -t nat -L
  4. Save the change:
    service iptables save

Multi blade tenant or vcmp guest or BIG-IP with IPv4 IP addresses

  1. Login as root on the BIG-IP command line.
  2. Randomize the NTP source port by entering the following command:
    clsh /sbin/iptables -t nat -I POSTROUTING -p udp -m udp --sport 123 -j MASQUERADE --to-ports 60000-61000
  3. List the change in the NAT table:
    clsh /sbin/iptables -t nat -L
  4. Save the change:
    clsh service iptables save

BIG-IP systems with IPv6 IP addresses

  1. Login as root on the BIG-IP command line.
  2. Randomize the NTP source port by entering the following command:
