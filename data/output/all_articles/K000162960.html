K000162960: BIG-IQ Fails to Back Up UCS Files and Re-add BIG-IP Due to an Invalid Certificate Error

Type
Support Solution
Published
2026-08-18
Updated
2026-08-18
Applies to
  • BIG-IQ
  • BIG-IQ Centralized Management: 8.0.0
Source
https://my.f5.com/manage/s/article/K000162960

Description

BIG-IQ fails to take a BIG-IP UCS backup, and re-adding the BIG-IP also fails. You find an error similar to the following in /var/log/secure.


Got exception while handling EM auth token request: Invalid Certificate: Certificate has expired.

Environment

  • BIG-IQ
  • Managed BIG-IP devices
  • The certificates are located under /shared/em/ssl.crt/ on the BIG-IP, but they have expired.


Cause

The certificates located under /shared/em/ssl.crt/ on the BIG-IP, but are expired.


Answer/Recommended Actions

1. Take a UCS backup on the BIG-IP from the BIG-IP GUI or tmsh.


2. If the BIG-IP is still managed by the BIG-IQ, remove it from the BIG-IQ.

 

3. Check if you still have *.crt files under /shared/em/ssl.crt on the BIG-IP, but they have expired.


# cd /shared/em/ssl.crt

# ls -l

# for f in ./*.crt; do echo "=== $f ==="; openssl x509 -in "$f" -noout -dates; done

=== ./xxx.xxx.xxx.xxx.crt ===

notBefore=Aug 3 18:09:25 2016 PDT

notAfter=Aug 3 18:09:25 2026 PDT

<snip>


4. Run clear-rest-storage on the BIG-IP in question.

 

K78734243: Clearing or restoring REST framework from BIG-IP after being managed by BIG-IQ


5. After creating a backup, remove the *.crt files under /shared/em/ssl.crt on the BIG-IP in question.

 

# cp -r /shared/em /var/tmp/em_backup

# cd /shared/em/ssl.crt/

# rm -f *.crt

# ls -l

 

6. Try to re-add the BIG-IP from the BIG-IQ.
