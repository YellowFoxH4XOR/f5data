Description

When scanning the management IP, able to connect using TLS 1.0 or TLS 1.1 on port 4353.

Tried this:

tmsh modify /sys httpd ssl-protocol "TLSv1.2"
save /sys config
tmsh restart sys service httpd

But still able to connect with versions other than TLS 1.2, confirmed by testing with:

openssl s_client -connect <management ip>:4353 -tls1

Environment

  • Vulnerability scan
  • Management IP

Cause

When connecting to port 4353 on the management or self IPs, we are connecting to big3d, not httpd.

ss -panotux
Netid  State      Recv-Q Send-Q Local Address:Port               Peer Address:Port
tcp    LISTEN     0      5        :::4353                        :::*                   users:(("big3d",pid=6491,fd=8))
tcp    LISTEN     0      128      :::443                         :::*                   users:(("httpd",pid=12656,fd=5))

big3d does allow TLS 1.0 and above by default. This is defined by:

sys db big3d.minimum.tls.version {
    default-value "TLSv1"
    scf-config "true"
    value "TLSv1"
    value-range "string"
}

Recommended Actions

To restrict big3d connections to a minimum of TLS 1.2, change the value of big3d.minimum.tls.version, then restart big3d:

tmsh modify sys db big3d.minimum.tls.version value TLSv1.2

tmsh restart sys service big3d

Note: iQuery connections will be re-established when big3d completes its restart. If your BIG-IP devices is in a high availability (HA) configuration, restarting the big3d should not result in a failover.

For more information, refer to:

  • K71057100: Configuring the minimum TLS version for iQuery
  • K31434426: Configuring the cipher strength for iQuery

Additional Information

There are multiple ways to verify a connection for a particular TLS version, the syntax is:

openssl s_client -connect <management ip>:4353 [-tls1 | -tls1_1 | -tls1_2 | -tls1_3]
