Topic

The Machine Cert Auth verification consists of actions to check whether the machine certificate from the Windows client system meets a set of criteria and/or whether a valid private key is present. When troubleshooting, you should have a good understanding of these two checks.

Machine Cert Auth verification criteria

The BIG-IP APM system can check for a valid machine certificate on a Windows client system as part of an access policy sequence. Inserting the Machine Cert Auth action in an access policy will allow BIG-IP APM to validate the client certificate using the following criteria:

  • The common name (CN) of the machine certificate must exactly match the full computer name configured on the Windows client system.
  • The machine certificate parameters must be valid. For example, the certificate cannot be expired.
  • The machine certificate cannot appear on a Certificate Revocation List (CRL) configured on the BIG-IP APM system.
  • The machine certificate must be stored in the Local Computer certificate store on the Windows client system.
  • The BIG-IP APM client-side components must be able to sign a character string sent by the BIG-IP APM system using the machine certificate private key.
  • The public root or intermediate Certificate Authority (CA) that issued the machine certificate must be installed and trusted on the BIG-IP APM virtual server. For a CA to be trusted, a chain of trust must be established between the CA that signed the machine certificate and the CA that is already trusted by the virtual server. To verify whether the chain certificate creates a chain of trust to the SSL certificate, use the following command syntax:

    openssl verify -purpose [sslserver|sslclient] -CAfile /var/tmp/<chain cert name> /config/filestore/files_d/<partition>_d/certificate_d/<cert name>

    For example, to verify the server SSL certificate MyCert.crt in the Common partition using the chain certificate mychain.crt, type the following command:

    openssl verify -purpose sslserver -CAfile /var/tmp/mychain.crt /config/filestore/files_d/Common_d/certificate_d/:Common:MyCert.crt_1

    If the chain of trust can be established for the certificate using the specified chain, the command returns output that appears similar to the following example:

    MyCert.crt: OK

    For more information on SSL chain certificates, refer to K13302: Configuring the BIG-IP system to use an SSL chain certificate (11.x - 15.x).

Machine Cert Auth private key verification

Private keys located in the Local Computer certificate store are only accessible by the user who installed the private key, and by users with administrator privileges. If a user did not install the machine certificate and does not have administrator privileges on the Windows client system, the BIG-IP APM client components that run with the user's privileges cannot access the private key to sign the character string sent by BIG-IP APM. When the Machine Cert Auth action can verify the machine certificate, but not the private key, it will trigger the found rule. The default behavior for the found rule is to redirect the user to the Logon Denied page. To verify the machine certificate, but not the private key, refer to the Configure the Machine Cert Auth action procedure.

Note: For enhanced security, do not mark the private key as exportable when you import a machine certificate onto a client system. For more information about certificate security, refer to your Windows documentation.

You can work around this limitation by performing one of the following five procedures:

  • Grant the user account administrator privileges on the Windows client system. For more information, refer to Microsoft Windows documentation.
  • Import the machine certificate private key into the user's personal certificate store on the Windows client system. For more information, refer to Windows documentation.

    Important: Do not remove the machine certificate from the Local Computer certificate store. The Machine Cert Auth action requires that the machine certificate reside in the Local Computer certificate store.

  • Customize the BIG-IP APM Windows Client Package to include the Machine Certificate Checker Service. Once the service is installed on the client endpoint, the Machine Cert Auth action can check the endpoint machine certificate even when the user does not have admin privilege. For more information about the Machine Certificate Checker Service, refer to the BIG-IP Access Policy Manager: Edge Client and Application Configuration guide.

    Note: For information about how to locate F5 product guides, refer to K98133564: Tips for searching AskF5 and finding product documentation.

  • Use the Microsoft Windows HTTP Services Certificate Configuration Tool (WinHttpCertCfg.exe) on the Windows client machine to grant the user access to the machine certificate private key in the Local Computer certificate store. For more information, refer to Windows documentation.

    Note: For more information, refer to K9017: Using WinHttpCertCfg.exe to grant non-administrator users access to machine certificate private keys.

  • Configure the Machine Cert Auth action to verify the machine certificate, but not the private key. To do so, perform the following procedure.

Configure the Machine Cert Auth action to verify the machine certificate, but not the private key

Note: This example assumes you already have an access policy configured with a Machine Cert Auth action. For more information about using the Machine Cert Auth action, refer to the Configuration Guide for BIG-IP Access Policy Manager.

For information about how to locate F5 product guides, refer to K98133564: Tips for searching AskF5 and finding product documentation.

Important: Applying an access policy will take effect immediately.

  1. Log in to the BIG-IP Configuration utility.
  2. Select Access Policy.
  3. Select Access Profiles.
  4. Select Edit next to the access policy you want to configure.
  5. Locate the Machine Cert Auth action.
  6. To the right of the Found branch, change the ending from Logon Denied Page to Logon Allowed Page or to the next action in your access policy.

    Note: The session variable for Machine Cert Auth action is session.cert_check.last_check.result and will have a value of 2 for a found certificate, but no private key.

  7. Select Close.
  8. Select the check box next to the name of the access policy you just edited.
  9. Select Apply Access Policy.
