Security Advisory Description

Multiple desync attacks have been discovered. For more information refer to the following related articles:

  • K27144609: Overview of HTTP/2 desync attacks
  • K30341203: BIG-IP LTM and NGINX are not exposed to certain desync attacks
  • K63312282: BIG-IP LTM HTTP/2 desync attacks: request line injection

An HTTP/2 request with an HTTP/2 header which contains an \r\n sequence in a header value may be used to maliciously insert an additional HTTP/1.1 header. If the affected BIG-IP translates requests from HTTP/2 to HTTP/1.1 without adequate sanitisation, this may lead to unexpected HTTP requests reaching the target pool member web server.

This issue occurs when all of the following conditions are met:

  • The BIG-IP LTM system has one or more virtual servers configured to proxy HTTP/2 requests from the client side to HTTP/1 requests on the server side.
  • An HTTP/2 client sends a request with one of the following issues and the BIG-IP passes it to the server-side pool members:
    • Carriage return and line feed (CRLF) header splitting
    • H2.TE header Injection
    • H2.X via request splitting
    • Newlines in headers
Important: NGINX is not affected by this security exposure.

Impact

Malicious HTTP/2 requests may be translated into HTTP/1 requests and sent to the pool member web server. Depending on the behavior of the pool member web server, this may lead to an HTTP Request Smuggling attack. When the affected virtual server is configured with the OneConnect profile, an attacker may be able to impact the responses sent to a different client.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Malicious requests may be passed to server-side pool members.

Security Advisory Recommended Actions

Workaround

BIG-IP ASM and Advanced WAF workaround

If you are using the BIG-IP ASM or F5 Advanced Web Application Firewall (WAF) module to protect an affected virtual server, you can completely mitigate this security exposure by using the following BIG-IP ASM/Advanced WAF signatures enabled in blocking mode:

Note: You must perform a signature file update to ASM-AttackSignatures_20210803_080323.im or later for these signatures to be available on your system.

The following signatures will block the corresponding attack types:

  • HTTP Desync Attack Attempt, ID 200018061
  • HTTP/2 Desync Attack Attempt, ID 200018134
  • HTTP Response Splitting (1)(Parameter), ID 200023001
  • HTTP Response Splitting (2)(Parameter), ID 200023002
  • HTTP Response Splitting (3)(Parameter), ID 200023003
  • HTTP Response Splitting (4)(Parameter), ID 200023004
  • Non-standard Transfer-Encoding header value, ID 200200002

For information about working with attack signatures, refer to K12885: Working with BIG-IP ASM attack signatures.

Note:  After you configure these ASM signatures, no further mitigation is necessary.

OneConnect profile workaround

Note: Performing these actions on the OneConnect profile prevents the HTTP requests aggregation, thus mitigating the risk of an attacker interacting with a legitimate client; however, it does not prevent the target pool member web server from being subjected to potential HTTP Request Smuggling attacks.

If the BIG-IP ASM system is not available and the affected virtual server is configured with the OneConnect profile, you should consider adjusting the Source Prefix Length (BIG-IP 12.x and later) or Source Mask (11.x) setting of the OneConnect profile to prevent aggregation of HTTP requests from separate client-side TCP streams into the same server-side connection. Alternatively, you may consider disabling OneConnect for specific connections using an iRule or removing it entirely from the affected virtual server if your application environment permits. For information about modifying an iRule to disable OneConnect reuse, refer to the ONECONNECT::reuse iRule command

Impact of workaround: Depending on your application environment, adjusting the value of the Source Prefix Length or Source Mask setting of the OneConnect profile may impact optimal connection re-use, while disabling OneConnect may impact performance. For additional information, refer to K7208: Overview of the OneConnect profile.
