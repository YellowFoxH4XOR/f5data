Description

When configuring custom log files on BIG-IP systems with size-based rotation parameters (such as max-file-size or maxsize), administrators may observe that log files do not rotate automatically when they reach the specified size limit. Instead, rotation only occurs when:

  • The logrotate utility is manually executed using logrotate -f /etc/logrotate.conf`
  • The scheduled cron job runs logrotate at its configured interval

This behavior can result in log files growing significantly larger than the configured size limit before rotation occurs, particularly when log generation is unpredictable or occurs in bursts.

Environment

  • Product: BIG-IP LTM
  • Version: 11.x - 17.x (including 17.5.1)
  • Configuration objects:
    • sys log-rotate (max-file-size parameter)
    • sys syslog (custom filters and destinations)
    • Custom log files in directory
    • Cron jobs scheduling logrotate execution
  • Recent actions:
    • Configuration of custom syslog-ng filters and destinations
    • Attempts to configure size-based log rotation parameters

Cause

The logrotate utility operates on a schedule-based execution model via cron jobs, not through real-time file size monitoring. When logrotate runs, it checks configured log files and performs rotation actions based on the criteria defined (size, age, etc.). However, logrotate does not continuously monitor file sizes in the background. Therefore, log files are only evaluated and rotated when the cron job invokes logrotate, regardless of whether the file has exceeded the configured size limit between scheduled executions.

Answer/Recommended Actions

To ensure timely rotation of custom log files based on size:

  1. Verify logrotate configuration for custom log files:
    • Log in to tmsh: tmsh
    • Edit log-rotate configuration: edit /sys log-rotate all-properties
    • Ensure the include parameter contains your custom log file with appropriate rotation settings (maxsize, rotate count, etc.)
    • Save changes: Press Esc, type :wq, then press Enter
    • Save system configuration: tmsh save sys config
  2. Review current cron schedule:
    • Access the command line as root
    • View current cron jobs: crontab -l
    • Identify the frequency at which logrotate is executed (default is typically daily)
  3. Adjust cron frequency for more frequent rotation:
    • Edit the crontab: crontab -e
    • Add or modify the logrotate execution frequency based on your log growth patterns
    • Example for every 5 minutes (testing purposes): */5 * * * * /etc/cron.daily/logrotate`
    • Example for hourly execution: 0 * * * * /etc/cron.daily/logrotate`
    • Save and exit the editor
  4. Test the configuration manually:
    • Execute logrotate manually to verify configuration: logrotate -f /etc/logrotate.conf`
    • Verify that log files rotate as expected
  5. Monitor log rotation after implementation:
    • Check log files after the next scheduled cron execution
    • Verify rotation occurs within acceptable timeframes

Additional Information

  • Logrotate is a scheduled utility that does not provide real-time file size monitoring. It only evaluates and rotates files when executed by cron.
  • Increasing the frequency of logrotate execution via cron can help ensure more timely rotation for rapidly growing log files, but may increase system overhead slightly.
  • The frequency of cron execution should be balanced against system performance considerations and log growth patterns.
  • For log files with highly variable growth rates, consider setting the cron frequency to match the fastest expected growth scenario.
  • After rotation, logrotate creates a 0-byte placeholder file with the original filename, which is overwritten by new log entries.
