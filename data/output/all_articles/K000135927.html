Description

Recommended Actions

The ideal workaround for this situation is to go into maintenance operating system (MOS) and run the fsck/resize2fs manually on the partition.
 

Impact of procedure: While system booted in MOS, the system will not pass traffic and the Configuration utility will be unavailable; therefore, F5 recommends that you perform this procedure during a scheduled maintenance window.

 

1. Booting the BIG-IP system into MOS and correcting file system issues from TMOS maintenance mode:

For more information on MOS, please refer to K14245.

 

2. Unmount the logical directory in question (e.g: /var) :

# umount /var

 

3. Run this to correct any file system issue on /var:

# e2fsck -yf /dev/mapper/vg--db--sda-set.2._var

 

4. Run this command to enlarge the /var volume:

# resize2fs /dev/mapper/vg--db--sda-set.2._var

 

5. Mount back /var volume, type the following command:

# mount /dev/mapper/vg--db--sda-set.2._var /var

 

6. Confirm the amount of free space in the volume group is increased

# df -h
# vgs
# lvs

7. After everything is complete, restart the system using the following command:

# reboot
