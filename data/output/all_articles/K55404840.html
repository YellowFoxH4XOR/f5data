K55404840: pkcs11d is down after CloudHSM client installation

Published
2026-06-17

  • BIG-IP
Source

Description

After successfully installing the AWS CloudHSM client on BIG-IP, pkcs11d fails to start.

Environment

  • BIG-IP (all platforms) TMOS v14-v17
  • AWS CloudHSM integration
  • CloudHSM client installed

Symptoms

  • pkcs11d does not come up; tmsh show sys service pkcs11d shows: 
    pkcs11d      down, initializing ..
  • cloudhsm-client service shows active (running), but detailed logs contain a "No preferred server found" error: 
    [admin@<device-hostname>:Active:Standalone] ~ # service cloudhsm-client status -l
Redirecting to /bin/systemctl status -l cloudhsm-client.service
* cloudhsm-client.service - AWS CloudHsm Client daemon
   Loaded: loaded (/usr/lib/systemd/system/cloudhsm-client.service; enabled; vendor preset: disabled)
   Active: active (running) since Thu 2020-05-28 08:58:34 UTC; 1 weeks 0 days ago
...
Jun 04 12:53:49 <hostname> cloudhsm_client[665]: time: <time> liquidSecurity ERR: daemon_app_readcb: No preferred server found
Jun 04 12:53:49 <hostname> cloudhsm_client[665]: time: <time> liquidSecurity ERR: daemon_app_readcb: No preferred server found
  • A tcpdump capture on port 2223 shows a successful TLS handshake followed by an Encrypted Alert sent from BIG-IP to the HSM IP address.
  • /var/log/ltm log is populated with repeated errors: 
    May 22 04:16:58 hostname err pkcs11d_test_suite[22607]: 01680048:3: C_Initialize: pkcs11_rv=0x00000005, CKR_GENERAL_ERROR

Cause

A required step in the AWS CloudHSM client configuration was missed: the issuing certificate customerCA.crt was not copied to the /opt/cloudhsm/etc/ directory on the BIG-IP system.

Without this certificate, the CloudHSM client cannot complete mutual TLS authentication with the HSM cluster, causing the TLS alert and preventing pkcs11d from initializing.

Recommended Actions

  1. Verify network connectivity between BIG-IP and the HSM — confirm routing, ARP, and reachability on port 2223.
  2. Follow the CloudHSM installation guide closely, ensuring no steps are skipped.
  3. Verify required certificates are present in /opt/cloudhsm/etc/: 
    ls /opt/cloudhsm/etc/
    Confirm both of the following files exist:
    • client.crt
    • customerCA.crt
  4. If customerCA.crt is missing, copy the issuing certificate to /opt/cloudhsm/etc/ as per the AWS CloudHSM Edit Client Configuration guide, then restart the CloudHSM client and verify pkcs11d comes up: 
    tmsh show sys service pkcs11d
Note: After copying customerCA.crt to /opt/cloudhsm/etc/, pkcs11d should start successfully and HSM key generation and use in SSL profiles should function normally.

Additional Information

  • BIG-IP System and Net HSM Implementation (16.1.0)
  • AWS CloudHSM — Edit Client Configuration
