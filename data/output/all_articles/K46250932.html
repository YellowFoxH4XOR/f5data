Issue

You should consider using this procedure under either of the following conditions:

  • You have an IPv4 or IPv6 wildcard forwarding virtual server with the address resolution protocol (ARP) option enabled.
  • You have an IPv4 or IPv6 subnet-addressed virtual server with the address resolution protocol (ARP) option enabled.

Symptoms

As a result of having a wildcard/subnet Forwarding virtual server with ARP advertisement enabled, you may encounter any of the following symptoms:

  • You are unable to reach any pool members from the BIG-IP system.
  • ARP or NDP on the BIG-IP system returns as incomplete.
  • Your system experiences IP address conflicts with log entries such as:

01190004:4: address conflict detected for 10.10.10.1 (00:1c:00:00:00:01) on vlan 1234

A wildcard forwarding virtual server is defined as a virtual address of destination 0.0.0.0 with a subnet mask of 0.0.0.0 in the case of IPv4 or with destination :: and a subnet mask of /0 in the case of IPv6.  If the ARP advertisement option is also enabled on this virtual address, the BIG-IP system responds to all ARP or NDP requests, even for IP addresses that are not configured on the device.  This may disrupt connectivity on the network.

Recommended Actions

To resolve this issue, you should disable the ARP option on the wildcard/subnet virtual address by performing one of the following procedures:

  • Using the Configuration utility to disable ARP for a virtual address
  • Using tmsh to disable ARP for a virtual address

Note: The ARP option in tmsh and in the Configuration utility control the virtual-address behaviour for both ARP and NDP. The following procedures therefore also apply to IPv6 virtual servers even though the neighbour discovery protocol (NDP) is used by these virtual servers rather than address resolution protocol (ARP).

Using the Configuration utility to disable ARP for a virtual address

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Navigate to Local Traffic > Virtual Servers > Virtual Address List.
  2. Click the virtual address you want to modify.
  3. Clear the ARP check box.
  4. Click Update.

Using tmsh to disable ARP for a virtual address

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. Disable ARP for the virtual address by using the following command syntax:

    modify ltm virtual-address <virtual_address> arp disabled

    Note: Replace <virtual_address>  with the IP address of the virtual address.

  3. Save the change by typing the following command:

    save sys config
