Known Issue

Changing the Parameter Level setting of a wildcard parameter may prevent the BIG-IP ASM security policy from being activated.

This issue occurs when all of the following conditions are met:

  • At least two wildcard parameters exist in a policy.
  • The parameter level of a wildcard parameter is changed, and at least one other wildcard parameter already exists at the target parameter level.
  • The policy is applied.

For example, a security policy may have the following three wildcard parameters with the parameter level as shown:

ParameterParameter Level
MyParam1* Global Parameter
MyParam2* URL Parameter

MyParam1* already exists as a Global Parameter, so if MyParam2* is changed from a URL Parameter to a Global Parameter, this issue will occur.

If MyParam2* were changed to a Flow Parameter, this issue would not occur because no other wildcard parameter exists with the Parameter Level of Flow Parameter.

Impact

You cannot apply the BIG-IP ASM Policy.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • When you click the Apply Policy button, log messages similar to the following example will be written to the /var/log/asm file:

    01310027:2: ASM subsystem error (asm_config_server_rpc_handler.pl,F5::ASMConfig::Handler::log_error_and_rollback): Set active failed

  • When you click the Apply Policy button, a message will be displayed in the Configuration utility similar to the following example:

    Could not apply configuration; Set active failed

Workaround

To work around this issue, you can delete the old parameter and create a new parameter of the desired type. To do so, perform the following procedure:

Impact of workaround: None.

Delete the old parameter

  1. Log in to the Configuration utility.
  2. Navigate to Application Security > Parameters.
  3. In the Parameters List, select the Parameter Name you want to modify.
  4. Click Delete to remove the parameter.
  5. Confirm the delete operation by clicking OK.

Re-create the parameter

  1. Log in to the Configuration utility.
  2. Navigate to Application Security > Parameters.
  3. On the Parameters List screen, click Create.
  4. On the Create New Parameter screen, enter the appropriate details for the wildcard parameter you want to create, including the new Parameter Level setting.
  5. Click Create.
  6. Click Apply Policy.
