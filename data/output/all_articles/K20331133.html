Description

The sod (switch over daemon) process will kill the TMM process that has become unresponsive.

  • Messages in ltm logs similar to the following precede a TMM core file being generated:
    /var/log/ltm
    notice sod[7261]: 01140041:5: Killing tmm.0 pid 10617.
    warning sod[7261]: 01140029:4: HA daemon_heartbeat tmm fails action is go offline down links and restart.
  • Messages within tmm logs similar to the following which indicates sod triggered the SIGABRT:
    /var/log/tmm
    notice ** SIGABRT **
    notice sender pid: 7261 (/usr/bin/sod)

Environment

  • LTM Traffic Policy applied to a Virtual server

Cause

A virtual server is mis-configured with a local traffic policy that is configured to forward traffic to itself causing a loop that tmm cannot exist from. 
sod can kill TMM due to a self-referencing virtual server configuration in the form of a LTM policy.  This can also result in sod to not respond to the daemon_heartbeat and create a failover.

For example:

Within the bigip.conf file you may something similar to this version 13.x configuration and after sending traffic to this Virtual Server and LTM Traffic Policy.

ltm policy /Common/<LTM_POLICY> {
    controls { forwarding }
    requires { http }
    rules {
        <RULE_NAME> {
            actions {
                0 {
                    forward
                    select
                    virtual /Common/<VIRTUAL_SERVER>           <--Traffic Policy applied to virtual server targets itself creating a loop and causing TMM to abort.
                }
            }
        }
    }
    strategy /Common/first-match
}

Recommended Actions

Remove any traffic-directing reference to the same virtual server of which the LTM Traffic Policy is applied.
There are a couple of different way's this can be done. 

  • If you have not lost access to the GUI, you can remove the Traffic Policy from the Virtual Server.
  • If you have lost access to the GUI, modifying bigip.conf directly and commenting out the Traffic Policy that is referenced on the Virtual Server would be your alternative.  Also make sure that the Virtual Server is not referencing the Traffic Policy and comment it out as well. 
    Note: Modifying the configuration file manually does need a high level of familiarity with editing configuration files and also includes some risks doing so.  If you need comprehensive assistance optimize your configuration file via a text editor, F5 Professional Services is equipped to assist.
     
    • After saving the change, reload the config
      #tmsh load sys config
