K54222629: Configuring SNMPv3 traps on HA Pair

Type
Support Solution
Published
2021-06-03
Updated
2023-02-21
Applies to
  • BIG-IP Platforms
  • BIG-IP
  • BIG-IP LTM: 13.1.1
Source
https://my.f5.com/manage/s/article/K54222629

Description

SNMPv3 traps need to be created on via TMOS individually to include unique engineID.
SNMPv3 traps create via GUI is synchronize from active to standby unit without unique engineID.

Environment

  • BIG-IP HA
  • SNMPv3 traps configured on GUI
  • Config Sync from GUI

Cause

Due to Bug ID 837481: SNMPv3 pass phrases should not be synced between high availability (HA) devices as that are based on each devices unique engineID

Recommended Actions

The actions or steps required to address the topic covered in the description.

  1. On each F5, login via cli.
  2. cat /config/net-snmp/snmpd.conf 
    • obtain "oldEngineID 0x80001f8880ff0cbf5c53227960"
  3. Create trap via tmsh
    # tmsh modify sys snmp traps add { iasd {auth-protocol md5 auth-password letmein12345asd  host 192.168.1.1 security-name mee port 166  security-level auth-no-privacy  version 3 engine-id 0x80001f8880ff0cbf5c53227960  } }

  4. Save the configuration
    # tmsh save sys config
