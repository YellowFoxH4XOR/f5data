Known Issue

Description

When you attempt to remove an ARX share, it may appear to stall and subsequently fail.

This issue occurs when the following condition is met:

  • A share was previously removed from the same volume.

When you remove a subsequent share, the ARX system might encounter a stale storage id, which causes the ARX system to attempt to remove a share that is no longer there. As a result, the share removal appears to stall and eventually times out and fails.

Impact

You cannot successfully remove a share.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The system appears to be removing the share.
  • The share removal fails.
  • Error messages that appear similar to the following example show up in the ARX syslog:

From version 5.x:

DTFS_ERROR: "Volume not found" [0]: dnastranfs.c:dtfs_mcast_rndir():[2424]

DTFS_ERROR: "Storage not found" [71]: dnastranfs.c:dtfs_syncdir():[3209]

DNAS_PGRP-3-NOTE-MSG5:: setattr recovery: Unable to synchronize directory attributes for path '/pa24mv1/PA24V1FM_NJROS1F10/DEL/prerstst/' on share (ID 71): Failed to find storage in table

DTFS_ERROR: "Storage not found" [71]: dnastranfs.c:dtfs_syncdir():[3209]

DNAS_PGRP-3-NOTE-MSG5:: setattr recovery: Unable to synchronize directory attributes for path '/vol/vol1/Example' on share (ID 71): Failed to find storage in table

MGT_DNAS_CONFIG-3-WARN-STORAGE_REMOVE_ERROR:: An error occurred removing the filer 'Filer1' path '/vol/vol1/Example' bound to share 'example_share' in volume '/vol1', namespace 'NS_example': Unable to flush pending directory operations on share [-475].

From version 6.x:

DNAS_PGRP-1-ERR-MSG3:: DTFS_ERROR: "Volume not found" [0]: dnastranfs.c:dtfs_mcast_setattr():[2702]

DNAS_PGRP-1-ERR-MSG3:: DTFS_ERROR: "Volume not found" [0]: dnastranfs.c:dtfs_mcast_setattr():[2702]

Workaround

To recover from this issue, you can rebuild the affected volume. To do so, perform the following procedure:

Impact of workaround: The volume will be unavailable during the initial rebuild process; CIFS clients need to refresh their connection, and NFS clients need to re-mount.

  1. Log in to the ARX CLI.
  2. Enter privileged mode by typing the following command:

    enable

  3. Rebuild the volume using the following command syntax:

    nsck <namespace> rebuild volume <volume>

    For example:

    nsck ns1 rebuild volume /vol1

Supplemental Information

  • For information about the nsck command, refer to the ARX CLI Reference Guide.
