Known Issue

The BIG-IP Configuration utility fails to apply the new state to all pool member instances.

This issue occurs when all of the following conditions are met:

  • Two or more pools share the same pool member.
  • You attempt to change the state of the shared pool member.
  • You apply the Apply new state to all pool member instances option on the shared pool member.

The Apply new state to all pool member instances State Options is only available if more than one pool is configured with a shared pool member and you attempt to change its state. This option is not available in the tmsh utility.

Impact

You are unable to disable or force offline all instances of the affected pool member.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The BIG-IP Configuration utility fails to apply the new state and reports an error message that appears similar to the following example:

    An error has occurred while trying to process your request

  • The pool member's state remains unchanged after you attempt to apply the new state. You can view the pool member's state by refreshing the Local Traffic > Pools > Pool List > <pool name> > Members > <pool member> page.

Workaround

If you want to disable or force offline all instances of the same pool member, you have to go to each and every pool to which the affected pool member is assigned, set that pool member to the desired new state and save the change. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Pools > Pool List.
  3. Click the name of the pool to which the affected pool member is assigned.
  4. Click the Members tab.
  5. Click the affected pool member.
  6. Select either Disabled or Forced Offline, as desired.
  7. Click Update to save the change.

Repeat this procedure for every pool to which the affected pool member is assigned.
