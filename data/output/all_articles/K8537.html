Topic

This article applies to BIG-IP 9.x through 10.x. For information about other versions, refer to the following articles:

  • K13454: Configuring SSH host-based authentication on BIG-IP systems (11.x - 12.x)

Host-based user authentication uses the public key of a specified user on the secure shell (SSH) client system to authenticate that user to the remote server's SSH daemon instead of requiring password input. This provides a non-interactive form of authentication best used in scripts and automated processes, such as application health monitors, cron jobs, automated backups and file transfers, or in other situations where a user will not be present to input authentication information.

You can configure host-based authentication involving a BIG-IP system using the following three methods:

  • Authenticate one way from a remote system to the BIG-IP system
  • Authenticate one way from the BIG-IP system to a remote system
  • Authenticate bi-directionally between the BIG-IP system and a remote system

Important: You should configure the least permissive option that meets your requirements. Any non-interactive login is inherently insecure, since it permits authentication without user challenge. Host-based authentication is more secure than the .rhosts method used by the Berkeley r commands; however, it cannot resolve the inherent insecurity of non-interactive logins, and public-key authentication is preferred whenever feasible. In any case, you should take aggressive measures to ensure that any system configured for host-based authentication is adequately secured.

Authenticate one way from a remote system to the BIG-IP system

To authenticate from a remote system to the BIG-IP system only, perform the following procedures:

  • Creating user authentication DSA key pair on the remote host
  • Configuring the BIG-IP SSH server to accept host-based authentication
  • Configuring the remote SSH client to authenticate to the BIG-IP system using host-based authentication

Authenticate one way from the BIG-IP system to a remote system

To authenticate from the BIG-IP system to a remote system only, first verify that the SSH server is installed and functional on the remote host system, then perform the following procedures:

  • Creating user authentication DSA key pair on the BIG-IP system
  • Configuring the BIG-IP SSH client to authenticate to a remote host using host-based authentication
  • Configuring the remote SSH server to accept host-based authentication

Authenticate bi-directionally between the BIG-IP system and a remote system

To authenticate bi-directionally between the BIG-IP system and a remote system, first verify that the SSH server is installed and functional on the remote host system, then perform the following procedures:

  • Creating user authentication DSA key pair on the BIG-IP system
  • Creating user authentication DSA key pair on the remote host
  • Configuring the BIG-IP SSH server to accept host-based authentication
  • Configuring the remote SSH server to accept host-based authentication
  • Configuring the BIG-IP SSH client to authenticate to a remote host using host-based authentication
  • Configuring the remote SSH client to authenticate to the BIG-IP system using host-based authentication

Creating a user authentication DSA key pair on the BIG-IP system

Note: This procedure is only required if you are configuring a BIG-IP user to authenticate to a remote host.

You must generate an authentication key pair on the BIG-IP system for each user that wants to use SSH with digital signature algorithm (DSA) authentication from BIG-IP to a remote host. You can create an authentication DSA key pair for the user on the BIG-IP system by performing the following procedure:

  1. Log in to the BIG-IP command line.
  2. Type the following command:

    ssh-keygen -t dsa

  3. If you are generating an authentication key pair for a user other than root, skip to step 4.

    If you are generating an authentication key pair for the root user, accept the default values, using an empty passphrase.

    The following key files are generated and placed in the /root/.ssh/ directory:

    • The id_dsa private key file.
    • Note: The private key file contains the protocol version 2 DSA authentication identity of the user.
    • The id_dsa.pub public key file.

      Note: The public key file contains the protocol version 2 DSA public key for authentication. The SSH daemon will read this file when a login attempt is made by this user.

  4. If you are generating an authentication key pair for a user other than root:

    Specify the path to the appropriate user's .ssh directory, and use an empty passphrase. For example for the user notroot, you would specify:

    /home/notroot/.ssh/

    Note: If the user does not already have a /home/<user>/.ssh directory, you will need to create it.

    The following key files are generated and placed in the /home/<user>/.ssh/ file:

    • The id_dsa private key file.
    • Note: The private key file contains the protocol version 2 DSA authentication identity of the user.
    • The id_dsa.pub public key file.

      Note: The public key file contains the protocol version 2 DSA public key for authentication. The SSH daemon will read this file when a login attempt is made by this user.

Creating a user authentication DSA key pair on the remote host

Note: This procedure is only required if you are configuring a user on a remote host to authenticate to BIG-IP.

You must generate an authentication key pair on the remote host for each user that wants to use SSH with DSA authentication from the remote host to BIG-IP.

You can create an authentication DSA key pair for the user on the remote host by performing a similar procedure on the remote host as that detailed above for BIG-IP.

Configuring the BIG-IP SSH server to accept host-based authentication

Note: This procedure is only required if you are configuring a user on a remote host to authenticate to BIG-IP.

For an SSH server to accept host-based authentication, the SSH server configuration must be modified to allow this authentication method globally. The SSH server must also be pre-configured with information about the remote users who are allowed to authenticate using this method: The remote user's public key must be added to the authorized_keys file (the list of hosts that are authorized for host-based authentication).

To configure the BIG-IP SSH server to accept host-based authentication for a specific user on a remote host, perform the following procedure:

  1. Log in to the BIG-IP command line.
  2. Add the remote user's public key to the list of keys that the BIG-IP system will accept for host-based authentication by typing the following command:

    ssh <RemoteUser>@<Remote Host> 'cat .ssh/id_dsa.pub' >> ~/.ssh/authorized_keys

    Note: The <RemoteUser> field is the login name of the user on the remote host who is to be allowed to use host-based authentication. The <RemoteHost> field is the IP address or DNS name of the remote host from which host-based authentication for this user will be allowed.

    Note: This command retrieves the remote user's public key from the remote server and appends it to the authorized_keys file in the BIG-IP home directory of the BIG-IP user by whom the command was executed.

To globally enable host-based authentication on the BIG-IP system, perform one of the following two procedures, depending on which version of BIG-IP you are running:

BIG-IP versions 9.4.2 and later

  1. Log in to the BIG-IP command line.
  2. Enter the bigpipe shell by typing the following command:

    bpsh
  3. At the bigpipe prompt, paste the following text:

    sshd include "
    IgnoreRhosts no
    HostbasedAuthentication yes
    AuthorizedKeysFile %h/.ssh/authorized_keys"
  4. Press the Enter key.
  5. To save the configuration, type the following command:

    bigpipe save all
  6. To exit the bigpipe shell, type the following command:

    exit

Configuring the remote SSH server to accept host-based authentication

Note: This procedure is only required if you are configuring a BIG-IP user to authenticate to a remote host.

For an SSH server to accept host-based authentication, the SSH server configuration must be modified to allow this authentication method globally. The SSH server must also be pre-configured with information about the remote users who are allowed to authenticate using this method: The remote user's public key must be added to the authorized_keys file (the list of hosts that are authorized for host-based authentication).

To configure the remote SSH server to accept host-based authentication for a specific user on a remote host, perform the following procedure:

  1. Log in to the remote host command line using the remote host account to which you want to allow host-based authentication.
  2. Add the BIG-IP user's public key to the list of keys that the remote host will accept for host-based authentication by typing the following command:

    ssh <BIGIPUser>@<BIGIPHost> 'cat .ssh/id_dsa.pub' >> .ssh/authorized_keys

    Note: The <BIGIPUser> field is the login name of the user on the BIG-IP who is to be allowed to use host-based authentication. The <BIGIPHost> field is the IP address or DNS name of the BIG-IP from which host-based authentication for this user will be allowed.

    Note: This command retrieves the BIG-IP user's public key from the BIG-IP and appends it to the authorized_keys file in the remote host home directory of the remote user by whom the command was executed.

To globally enable host-based authentication on the remote system, perform the following procedure:

  1. Log in to the remote host command line using an administrative account.
  2. Using a text editor, edit the sshd_config file.
  3. Add the following lines to the configuration file:

    IgnoreRhosts no
    HostbasedAuthentication yes
    AuthorizedKeysFile %h/.ssh    /authorized_keys
  4. Save and close the configuration file.

Configuring the BIG-IP SSH client to authenticate to a remote host using host-based authentication

Note: This step is only required if you are configuring a BIG-IP user to authenticate to a remote host.

The SSH client must be made aware that host-based authentication is desired whenever possible, and of the public host key for the remote system to which the BIG-IP client will connect.

To configure the BIG-IP SSH client, perform the following procedure:

  1. Log in to the BIG-IP system.
  2. To seed the BIG-IP user's known_hosts file with the public host key of the remote host, type the following two commands:

    echo -n '<RemoteHost> ' >> ~/.ssh/known_hosts
    ssh <RemoteUser>@<RemoteHost> 'cat /config/ssh/ssh_host_dsa_key.pub' >> ~/.ssh/known_hosts

    Note: These commands retrieve the remote system's public host key and append it, along with its IP or hostname, to the known_hosts file of the BIG-IP user by whom the above command was executed.
  3. To configure the BIG-IP SSH client so that it attempts host-based authentication, type the following three commands:

    echo 'HostbasedAuthentication yes' >> /config/ssh/ssh_config
    echo '<RemoteUser> <RemoteHost>' >> ~/.shosts
    chmod 400 .shosts

    Note: The <RemoteUser> field is the login name of the user on the remote host who is to be allowed to use host-based authentication. The <RemoteHost> field is the IP address or DNS name of the remote host from which host-based authentication for this user will be allowed.
  4. If you have configured host-based authentication for a BIG-IP user other than root, skip to step 5.

    If you have configured host-based authentication for the BIG-IP root user, you can now login directly to the remote system without entering a password.
  5. If you have configured host-based authentication for a BIG-IP user other than root, you can now login to the remote system without entering a password, however you must specify the correct username and identity file, using the following syntax:

    ssh <username>@<remote-host> -o IdentityFile=<path-to-identity-file>

    Where <path-to-identity-file> is the path to the private key file you created in step 4 of the section Creating a user authentication DSA key pair on the BIG-IP system, above.

    For example:

    ssh notroot@10.10.10.1 -o IdentityFile=/home/notroot/.ssh/id_dsa

Configuring the remote SSH client to authenticate to the BIG-IP system using host-based authentication

Note: This step is only required if you are configuring a user on a remote host to authenticate to BIG-IP.

The SSH client must be made aware that host-based authentication is desired whenever possible, and of the public host key for the BIG-IP system to which the remote host user will connect.

To configure the remote host SSH client, perform the following procedure:

  1. Log in to the remote host.
  2. To seed the remote user's known_hosts file with the public host key of the BIG-IP system, type the following two commands:

    echo -n '<BIGIPHost> ' >> ~/.ssh/known_hosts
    ssh <BIGIPUser>@<BIGIPHost> 'cat /config/ssh/ssh_host_dsa_key.pub' >> ~/.ssh/known_hosts
  3. To configure the remote SSH client so that it attempts host-based authentication, type the following three commands:

    echo 'HostbasedAuthentication yes' >> /config/ssh/ssh_config
    echo '<BIGIPUser> <BIGIPHost>' >> .shosts
    chmod 400 .shosts

    Note: The <BIGIPUser> field is the login name of the user on the BIG-IP who is to be allowed to use host-based authentication. The <BIGIPHost> field is the IP address or DNS name of the BIG-IP from which host-based authentication for this user will be allowed.
