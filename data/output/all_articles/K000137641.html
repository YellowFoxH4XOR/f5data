Topic

You should consider using this procedure under the following conditions:

  • You want to review the non-default settings for your security policy.

Description

There may be occasions when you want to evaluate your BIG-IP ASM / Advanced WAF security policy and review the non-default settings in the policy. Or you might want to determine whether multiple security policies are configured with a particular non-default setting.

For example, if you are troubleshooting an issue on your BIG-IP ASM / Advanced WAF system and find a Support article that mentions a particular non-default setting, you may want to determine whether a policy is configured with the setting. You can use the Configuration utility and check if the setting is enabled, but doing so may be time-consuming if you have numerous security policies or are not sure how to locate the setting.

Note: Since BIG-IP ASM / Advanced WAF security policy settings are stored in the MySQL database and not a flat file, using the command line or iControl REST API to locate a policy setting may not be practical.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have access to the BIG-IP ASM / Advanced WAF Configuration utility.

Procedures

Review the non-default settings for your security policy

To review the non-default settings for your policy, create a blank security policy using the same policy template as the existing policy and compare the policies using the Configuration utility. To do so, perform the following procedures:

Impact of procedures: Performing the following procedures should not have a negative impact on your system.

Verify the security policy template type for the existing policy

To verify the security policy template type for the existing policy, perform the following steps:

  1. Log into the Configuration utility.
  2. Go to Security > Application Security > Security Policies > Policies List.
  3. Select the existing policy which contains the non-default settings.
  4. Select General Settings.
  5. Under Policy Template, note the security policy template type. For example, Rapid Deployment Policy.

Create a blank security policy

Next, create a new blank security policy using the same template type as the existing policy from the previous procedure. To do so, perform the following steps:

  1. Go to Security > Application Security > Security Policies > Policies List.
  2. Select Create.
  3. Enter a name for the new policy. For example, MyTestPolicy.
  4. Select the template type from Policy Template that matches the existing policy. For example, Rapid Deployment Policy.
  5. Do not configure any other settings for the policy.
  6. Select Save.

Compare the security policies

To compare the blank policy you created in the previous procedure with the existing policy, perform the following steps:

  1. Go to Security > Application Security > Security Policies > Policy Diff.
  2. From First Policy select the existing security policy.
  3. From Second Policy select the blank policy that you created in the previous procedure.
  4. From Working Mode select Work on Original.
  5. Select Calculate Differences.
  6. Under Policy Differences Summary select the listed policy entities to view differences between the policies.
