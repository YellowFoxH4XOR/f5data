K000137649: Modify ecdsa key size

Type

Published
2023-12-11
Updated
2025-02-07
Applies to
  • BIG-IP
  • BIG-IQ
Source

Description

This article provides the steps to modify the keyswap.sh file to change size of ecdsa key for the BIG-IP system. 

Environment
BIG-IP and BIG-IQ ssh access.

Cause
You should consider using these procedures to increase the ecdsa keys on the BIG-IP system from 256 bits to 384 or 521 bits.

Recommended Actions

Verify the current private key strength.

By default it's 256 bits, to verify follow procedure:

  1. Log in to the BIG-IP command line.
  2. To verify the current private key size enter the following command:

openssl ec -noout -text -in /var/ssh/ssh_host_rsa_key | grep -i key

 

For a BIG-IP system using the default key size the output of the command appears similar to the following example:

Private-Key: (256 bit)

 

3. To view the current ssh-keygen data, enter the following command:

grep keygen /usr/bin/keyswap.sh |grep ecdsa

 

output by default should be:

ssh-keygen -q -f ${tmpdir}/ssh_host_ecdsa_key -t ecdsa -N "" -C "$hostname"

ssh-keygen -q -f ${tmpdir}/ssh_host_ecdsa_key -t ecdsa -N "" -C "$hostname"

 

To increase key size you need to provide the desired size using -b option. To do that follow next steps:

  1. To remount the /usr file system in read-write mode, enter the following command: mount -o remount,rw /usr
  2. To create a backup of your current keyswap.sh file, enter the following command: cp /usr/bin/keyswap.sh /usr/bin/keyswap.sh_bkp
  3. Using a text editor, open the /usr/bin/keyswap.sh file and edit the ssh-keygen commands to generate 384 or 521 bits ecdsa keys. To do so, locate the following lines: ssh-keygen -q -f ${tmpdir}/ssh_host_ecdsa_key -t ecdsa -N "" -C "$hostname"
  4. add the -b option with the desired size for every found line: ssh-keygen -q -f ${tmpdir}/ssh_host_ecdsa_key -t ecdsa -b 384 -N "" -C "$hostname" (Note: Only update the ssh-keygen command for the ecdsa keys.)
  5. Save the /usr/bin/keyswap.sh file.
  6. To remount the /usr file system in read-only mode, enter the following command: mount -o remount,ro /usr

Regenerate the SSH keys

To regenerate and apply the new key size, perform the following procedure:

Impact of procedure: The sshd service restarts. Depending on your BIG-IP version, your SSH session may be terminated. If your session is terminated, when you reconnect, the BIG-IP system may display a Warning - POTENTIAL SECURITY BREACH! message. This is an expected warning because the SSH private keys have changed.

  1. To regenerate the SSH keys, enter the following command:
  2. /usr/bin/keyswap.sh -genkeys
  3. The command causes the sshd service to stop and restart. Output of the command appears similar to the following example:
  4. Stopping sshd: [ OK ]
  5. Starting sshd: [ OK ]
  6. If required, re-establish your SSH session.
  7. Note: When you reconnect, the BIG-IP system may display a Warning - POTENTIAL SECURITY BREACH! message. This is an expected warning because the SSH private key has changed.
  8. To verify the new current private key is being used, enter the following command: openssl ec -noout -text -in /var/ssh/ssh_host_ecdsa_key | grep -i key
  9. The output of the command appears similar to the following example: Private-Key: (384 bit)

Additional Information
You need to have command-line access to the BIG-IP system as a root user.
