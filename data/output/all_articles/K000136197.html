K000136197: SSH Permission denied (publickey) with public key authentication

Published
2023-09-14
Updated

Source

Description 

When using public key authentication to connect via SSH to an F5 device (or a remote server), login may fail with:

Permission denied (publickey)

Environment

  • SSH
  • Public Key
  • Authentication

Cause

The error occurs because the "publickey" authentication method requires the client to authenticate using a corresponding private key rather than a password. When this process fails, there can be several underlying reasons:

 

Common Problems

  1. Private Key Not Used by the Client:
    The client is not configured to use a private key file during authentication, or the private key file is missing.

  2. Public Key Not Provided to the Server:
    The remote server does not have the associated public key registered in the appropriate user’s authorized_keys file.

  3. Key Pair Mismatch:
    The public key stored on the server does not match the private key being used by the client.

  4. Invalid or Incompatible Private Key Format:
    The private key file is in a corrupted, outdated, or unparseable format, preventing the SSH client from using it. For example, newer SSH tools may require keys in a specific format (such as OpenSSH or a PEM format).
