K000159056: CLI method for removing BIG-IQ standby

Type
Support Solution
Published
2026-01-12
Updated
2026-01-12
Applies to
  • BIG-IQ
  • BIG-IQ Centralized Management: 8.3.0
Source
https://my.f5.com/manage/s/article/K000159056

1. Description

When attempting to remove a BIG-IQ from a High Availability (HA) pair and reset it to standalone mode using the REST API method documented for BIG-IQ 7.0.0, the operation fails with a JSON deserialization error.

Symptoms:

  • POST request to /mgmt/shared/ha/reset-task with an empty body returns HTTP 400 error
  • Error message: "JSON posted couldn't be deserialized to class com.f5.rest.workers.shared.ha.ResetTaskItemState"
  • The REST API method does not successfully reset the BIG-IQ to standalone mode

2. Environment

  • BIG-IQ version 8.3.0
  • BIG-IQ configured in High Availability (HA) pair
  • Active or Standby BIG-IQ node requiring reset to standalone mode
  • Management interface configured with IP address

3. Cause

The REST API endpoint /mgmt/shared/ha/reset-task with an empty body, as documented for BIG-IQ 7.0.0, does not function properly in BIG-IQ 8.3.0 and returns a JSON deserialization error.

4. Recommended Actions

Primary Method - GUI (Officially Supported):

  1. Navigate to System at the top of the screen
  2. Select BIG-IQ HA on the left
  3. Click Remove Standby
  4. Confirm the removal in the dialog box
  5. The system will log you out while it removes the standby BIG-IQ
  6. Log back in to the active BIG-IQ
  7. After a few minutes, the screen will update to show a single standalone BIG-IQ

Alternative Method - CLI:

  1. Extract the management IP address and run the ha_reset command:
  2. read _ _ _ addr _ <<<$(ip -4 -o address show dev mgmt)
  3. ha_reset -f ${addr/\/*}
  4. bigstart restart webd restjavad
  5. Alternatively, manually determine the management IP address and execute:
  6. ha_reset -f <local_device_IP>
  7. bigstart restart webd restjavad
  8. Verify the system state after reset:
  9. restcurl /mgmt/shared/ha-state
  10. Expected output should show:
  • "systemMode": "STANDALONE"
  • "nodeRole": "STANDALONE"

5. Additional Information

  • The ha_reset CLI script method is documented in KB K25071552 for scenarios when the GUI is unavailable
  • The CLI method using ha_reset -f <discovery_address> has been successfully used in previous BIG-IQ cases for resetting HA configurations to standalone mode
  • After running ha_reset, restarting the webd and restjavad services is necessary to complete the transition and restore UI/REST functionality
  • The GUI method remains the officially recommended approach for standard operations
