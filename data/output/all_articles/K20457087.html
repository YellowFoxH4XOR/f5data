Description

You want to create a custom attack signature set for latest Log4j2 vulnerability mitigation.

Environment

Relevant environmental factors specific to the topic

  • BIG-IP ASM
  • Security policy
  • Attack Signatures

Cause

You have new attack signatures to add to a new user-defined(custom) attack signature set for Apache Log4j2 Remote Code Execution vulnerability.
Note: When applying Apache Log4j2 Remote Code Execution vulnerability signatures, it can be useful to manually create a user-defined Attack Signature Set to avoid certain False Positive that may be in the Server Side Code Injection signature set. One way to avoid to possibility is to create a specific signature set with only the attack signatures needed.

Recommended Actions

Creating a set of attack signatures

When you create an attack signature set, you can include the attack signatures that are relevant to your specific systems and applications.

  1. Log on to the Configuration utility.
  2. Go to Security > Options > Application Security > Attack Signatures > Attack Signature Sets.
  3. Click Create.
  4. Enter a name and change Type drop down to Manual.
  5. In Signatures enter each of the following 9 signature ID's and move them to the Assigned signatures section (to the left).

    Java Naming and Directory Interface (JNDI) Injection:
    200104768
    200104769

    Generic JNDI Injection signatures:
    200004450
    200004451
    200004474
    200104770
    200104771
    200104772
    200104773
     
  6. Click Create.


If you are using this for latest vulnerability mitigation.

  1. Go to Security > Application Security > Policy Building > Learning and Blocking Settings.
  2. Select the security policy name from the drop-down menu.
  3. Expand Attack Signatures.
  4. Click Change.
  5. Remove the checkbox for Server Side Code Injection Signatures, if applicable.
  6. Click the checkbox for the new Attack Signature Set you created.
  7. Click Save.
  8. Click Apply Policy.
