K000138417: TMOS software installation gets stuck in the middle on BIG-IP VE in Amazon AWS

Type
Support Solution
Published
2024-01-31
Updated
2024-07-24
Applies to
  • Public Cloud
  • Amazon Web Services
Source
https://my.f5.com/manage/s/article/K000138417

Description

TMOS software installation gets stuck in the middle. The progress percentage of software installation when it gets stuck varies from time to time, and wait (I/O wait) for a CPU core shows a high percentage when running the top command. Depending on which CPU core handles SSH and HTTPD, the issue makes SSH connections and GUI unresponsive.

# tmsh show sys software status
 
----------------------------------------------------------------
Sys::Software Status
Volume  Product   Version   Build  Active                 Status
----------------------------------------------------------------
HD1.1    BIG-IP  14.1.5.6  0.12.6     yes               complete
HD1.2    BIG-IP  14.1.5.6   0.0.6      no  installing 66.000 pct
 

Environment

  • BIG-IP VE on AWS
  • AWS instance type m3.xxx, m4.xxx or c4.xxx is in use

    Note: The list of AWS instance types is not exhaustive. These are the ones which F5 Support received reports on experiencing the issue.

Cause

Unknown. We suspect the disk write during TMOS software installation exhausted the available I/O on underlying hardware.

Recommended Actions

  • Hard reboot of the virtual machine may be required.
  • We also received a report that using m5.xxx instance type instead of affected instance type list in the Environment section resolved the issue. We recommend using m5 or equivalent instance types when your BIG-IP instance experiences the issue.

Additional Information

When looking at iostat command result, it shows one or more devices keep showing 100% util. When the util goes up and down, it is not this issue.
