Topic

Note: F5 Support does not provide assistance in writing BIG-IP packet filter rules but provides their best effort to assist customers in troubleshooting these rules.

You should consider using this procedure under the following condition:

  • You need to configure packet filtering to block Classless Inter Domain Routing (CIDR) network block addresses.

Description

You can use the BIG-IP packet filter functionality to enhance network security by enforcing an access policy on traffic ingressing or egressing a VLAN on the BIG-IP system. You must configure packet filter functionality to block CIDR network addresses from the TMOS Shell (tmsh).

The BIG-IP packet filter functionality is based on the Berkeley Software Design Packet Filter architecture (BPF). The packet filter rules are composed of four mandatory attributes and three optional attributes. The mandatory attributes are name, order, action, and rule while the optional attributes are vlan, logging, and rate-class.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have command line access to the BIG-IP system.
  • You are familiar with packet filter syntax.

    For example:

    • src = source
    • dst = destination
    • host = a specific IP address
    • net = a network address
    • proto = an IP protocol
    • port = a port

Procedures

Configure packet filtering to block CIDR network addresses using tmsh

To configure packet filtering using tmsh, perform the following procedure:

To watch a video demo of this procedure, go to  Configure packet filtering to regulate specified traffic to the BIG-IP system.

Impact of procedure: Configuring packet filter rules that are inappropriate for your environment may result in traffic disruption.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. If packet filtering is not enabled, enter the following command:

    modify /sys db packetfilter value enable

  3. Set the values you want for each of the following packet filter general properties that apply to your environment by entering the respective command shown in the following table.
     
    General propertiesDB keyAvailable valuesDefault valueCommand
    Unhandled Packet Actionpacketfilter.defaultactionAccept
    Discard
    Reject    		Acceptmodify /sys db packetfilter.defaultaction value <action>
    Filter established connectionspacketfilter.establishedEnable
    Disable    		Disablemodify /sys db packetfilter.established value <enable/disable>
    Send ICMP error on packet rejectpacketfilter.sendicmperrorsEnable
    Disable    		Disablemodify /sys db packetfilter.sendicmperrors value <enable/disable>
    Always accept ARPpacketfilter.allow.arpEnable
    Disable    		Enablemodify /sys db packetfilter.allow.arp value <enable/disable>

    Packet filter loggingpacketfilter.defaultlogEnable
    Disable    		Disablemodify /sys db packetfilter.defaultlog value <enable/disable>
  4. If you want packet filter exemptions, add the exemptions using the appropriate command syntax from the following table.
     
    Exemption forCommand
    MAC Addressesmodify /net packet-filter-trusted mac-addresses add { <mac address 1> <mac address 2> ...}
    IP Addressesmodify /net packet-filter-trusted ip-addresses add { <ip address 1> <ip address 2> ...}
    VLANsmodify /net packet-filter-trusted vlans add { <vlan 1> <vlan 2> ...}
  5. To create the packet filter rule, enter the following command:

    create /net packet-filter <name> order <integer> action <action> logging <enable/disable> vlan <vlan name> rule <filter rule>

    For example, to create a packet filter rule with the name icmpdrop that drops ICMP packets from hosts belonging to subnet 10.10.0.1 - 10.10.15.254 (CIDR format: 10.10.0.0/20),  enter the following command:

    create /net packet-filter icmpdrop order 5 action discard rule "( proto ICMP ) and ( src net 10.10.0.0/20 )"

  6. Save the change by entering the following command:

    save sys config
