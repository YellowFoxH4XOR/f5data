Topic

Summary

Windows filers may experience a resource utilization limitation that may cause an importing share to fail when there are in excess of 1.5 million files and subdirectories within a single directory.

Description

During the import of large directory structures, the filer utilizes a high amount of system resources to provide data to the ARX system. This behavior may cause extremely slow response times that may lead to the filer failing to respond to the ARX system. When importing a share, ARX relies crucially on the ability to enumerate the content of the directory using CIFS (using find-first/find-next requests) because the CIFS protocol does not contain a way to continue a directory enumeration across a connection failure; the enumeration has to restart from the beginning. As a result, the ARX system will cancel the import to prevent a loop from occurring.

As a result of this issue, you may encounter the following symptoms:

  • You may see the following log messages on your ARX system:

    • traplog

      shareImportFail (650) shr 'ns-01:/vol-fileserv-x:s-fileserv-x-arx', name 'fileserv', ip 'x.x.x.x': Error: Network communications failure during import scan. Check the import report for more details.
    • syslog

      DNAS_IMPORT-7-ERR-MSG3:: failed to enumerate directory, "/Root/RAW/29/2/LED/01/Extract/fi.lp" -308,share inshr-001 (\\x.x.x.x\X-arx$ [36]) 

      DNAS_IMPORT-7-ERR-IMPORT_FIND_FILES_CIFS_ERROR:: CIFS find-files failed for directory '/Root/RAW/29/2/LED/01/Extract/fi.lp' on share inshr-001 (\\x.x.x.x\X-arx$ [36]), Error: 'STATUS_UNEXPECTED_NETWORK_ERROR'.
  • By running the performance monitor on the Windows filer during import, you can observe the following resource saturation symptoms that will persist until import failure and disconnection of ARX:

    •  A CPU will be at 100 percent use
    • The cache fault rate would exceed 100K faults per second

Recommendations

To work around the Windows filer resource limitation, you can sufficiently reduce the imports resource requirements by splitting up the contents of all directories that exceed 1 million files or directories to either separate subdirectories or separate shares.

If you are unable to move the files or directories, F5 recommends opening a customer service case with Microsoft Support to investigate the Windows file server resource limitations, and for recommendations on how to work around the exhaustion of the filer resources.
