K000089261: NGINX App Protect: Requests blocked due to attack signature detected when signature set block equals "false"

Type
Support Solution
Published
2021-12-21
Updated
2026-07-30
Source
https://my.f5.com/manage/s/article/K000089261

Description

Requests may still get blocked even though the signature set is set to Alarm:True and Block:False.

Environment

  • NGINX App Protect

Cause

NAP is by default configured to block traffic primarily through "Violation Rating" assessment.

( See: https://docs.nginx.com/nginx-app-protect/configuration/#basic-configuration-and-the-default-policy )

This means that all violations that are in alarm mode contribute to the evaluated risk of the request.

If the request is assessed as likely to be malicious then it will be blocked even if no other specific violation was in blocking mode.

Recommended Actions

You can set the Alarm field to False as well to prevent this.

If it is just one signature that is triggering you can disable that one signature in the set.
