K000160839: How to Restrict NGINX Plus OIDC Authentication to IPv4 Only When IPv6 Is Disabled

Type
Support Solution
Published
2026-04-16
Updated
2026-04-16
Applies to
  • NGINX Products
  • NGINX Plus: R35, R36, R33, R34
Source
https://my.f5.com/manage/s/article/K000160839

Description

When using NGINX Plus with the OpenID Connect (OIDC) module for Azure AD authentication, DNS resolution for login.microsoftonline.com returns both IPv4 and IPv6 addresses. In environments where IPv6 is disabled (such as AWS Cloud VPCs), NGINX attempts to connect to IPv6 addresses first, resulting in errors like:

[error] connect() to [2603:1036:3000:e8::3]:443 failed (101: Network is unreachable) while connecting to upstream

Although NGINX eventually connects via IPv4, this causes degraded performance and unnecessary error logs.

Environment

  • NGINX Plus
  • OIDC module configured for Azure AD authentication
  • AWS Cloud VPC with IPv6 disabled
  • DNS resolution for login.microsoftonline.com returns both IPv4 and IPv6 addresses

Cause

NGINX attempts to connect to IPv6 addresses returned by DNS, but IPv6 is disabled in the AWS VPC. This results in failed connection attempts and error logs before falling back to IPv4.

Answer/Recommended Actions

To restrict OIDC authentication to IPv4 only for Azure AD, use the ipv6=off parameter in the NGINX resolver directive for relevant locations or upstreams. This ensures only IPv4 addresses are used for OIDC authentication, while IPv6 remains available elsewhere.

Method 1: Using proxy_location Directive within oidc_provider Context

  1. Configure the OIDC provider and location block as follows:

    oidc_provider entra_id {

    issuer https://login.microsoftonline.com/....;

    ssl_trusted_certificate ca.crt;

    ...

    proxy_location /entra;

    }


    location /entra {

    internal;

    resolver 1.1.1.1 valid=60s ipv6=off;

    subrequest_output_buffer_size 64k;

    proxy_ssl_trusted_certificate ca.crt;

    proxy_ssl_server_name on;

    proxy_ssl_verify on;

    proxy_ssl_verify_depth 5;

    proxy_pass $oidc_idp_request_uri;

    }

  2. Ensure all proxy_ssl_* directives are properly configured for TLS security.

Method 2: Upstream Override

  1. Define an upstream block for login.microsoftonline.com:

    upstream login.microsoftonline.com {

    resolver 8.8.8.8 valid=60s ipv6=off;

    zone login_microsoft 64k;

    server login.microsoftonline.com:443 resolve;

    }

  2. Use this upstream in your OIDC authentication flow.

Additional Information

  • The ipv6=off parameter in the resolver directive disables IPv6 address resolution for the specified context, preventing connection attempts to IPv6 addresses.
  • These changes can be applied only to OIDC authentication flows, allowing IPv6 support elsewhere in your configuration as needed.
