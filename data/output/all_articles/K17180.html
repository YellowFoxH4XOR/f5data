Known Issue

The BIG-IP APM system may not properly delete a dynamic user for the local user database.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM access policy uses a local user database for authentication.
  • The BIG-IP APM access policy uses the Allow User Creation option of the local database action.
  • Users attempting to authenticate are dynamically created in the local user database.

    A dynamically created user record is, by default, removed from the cache after 20 minutes and marked for deletion in the local user database. The record is later removed from the local user database by an internal housekeeping process (localdbmgr). However, if the record has been removed from the cache, and a dynamic user reauthenticates before localdbmgr removes the record from the local user database, the system will clear the record for deletion and create stale records.   

Impact

Due to the stale records, the local user database gets larger, causing performance issues.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • In the /var/log/ltm file, you observe an error message similar to the following example:

    err mcpd[<pid>]: 01071392:3: Background command '/usr/libexec/localdb_mysql_restore.sh' failed. The command exited with status 1.
    err mcpd[<pid>]: 01071703:3: Postprocess action (/usr/libexec/localdb_mysql_restore.sh) failed with exit code (256).
