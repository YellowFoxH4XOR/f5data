K000132474: [F5OS-C] Tenant does not start after upgrade F5OS.

Type
Support Solution
Published
2023-02-09
Updated
2024-08-16
Applies to
  • F5OS
  • F5OS-C
Source
https://my.f5.com/manage/s/article/K000132474

Description

After upgrade, F5OS GUI is working normal, can not observe any alerts/events.

Tenant status on GUI:

Configured : Running

Then try to change Deployed status then status becomes Fail.

The below commands run on CLI (log in as root)

kubectl get -n kubevert pods
oc get pods --all-namespaces

then get the bellow message:

The connection to the server controller-ha.chassis.local:8443 was refused - did you specify the right host or port?

/var/log/Openshift log contains similar to the below message:

Cluster Status: Inited:T,Ready:F,CCslot:2,haActive:F,etcd3Launched:F,etcdDelay:0 <<---- This F means fail.

/var/log/message log contains the below messages repeatedly:

journal: grep: /etc/etcd/etcd.conf: No such file or directory
omd_container.sh: grep: /etc/etcd/etcd.conf: No such file or directory

 

Environment

  • F5OS-C
  • Velos
  • upgraded
  • Tenant does not come back to deployed.

Cause

  • /etc/etcd/etcd.conf has been missing before upgraded.

Recommended Actions

Re-install Openshift by running this command on CLI of Active Controller (log in as root)

touch /var/omd/CLUSTER_REINSTALL

IMPORTANT: once this command executed, it will take about 1.5 hours to complete. Do not change or turn off anything.

IMPORTANT: Do this in maintenance window as this will affect all partitions/tenants.
