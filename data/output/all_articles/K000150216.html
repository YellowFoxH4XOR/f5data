Unbounded consumption

The inference process in LLMs, which generates responses based on prompts, is computationally intensive. Unrestricted prompt submission can lead to resource depletion, impacting model performance and potentially enabling denial-of-service attacks or model replication, thus compromising intellectual property.

Unbounded consumption attack scenario

An example of an unbounded consumption attack is when an attacker manipulates input data, by increasing the amount of text that exceeds the model's context window. By sending a stream of such requests, the attacker can cause service degradation in the model's performance.

Security best practices to protect against unbounded consumption attacks

To mitigate this vulnerability, best practice recommends that you do the following:

  • Implement data validation to examine and restrict what prompts users can send the model.
  • Limit the rate in which an entity can send the model prompts.
  • Manage and monitor resource usage so that attacks can be detected early and halted early. Resources should also be able to scale dynamically to meet demand.

Mitigate unbounded consumption attacks using F5 products

This section discusses the following F5 products that can provide protection/mitigation for unbounded consumption attacks.

Rate limiting

To mitigate against unbounded consumption attacks, one of the most important things to do is to implement rate limiting to all interactions with your LLM. One of the most common ways users, administrators and other components interact with LLMs is through API requests and responses. You can use the following F5 products to implement API access rate limiting:

  • Configure BIG-IP APM to implement and enforce rate-limiting restrictions by setting Request Quotas, Spike Arrest values, request weight, and direct requests to different server resources.
  • Configure rate limiting and DoS protection in BIG-IP ASM/Advanced WAF, NGINX and F5 Distributed Cloud Services products.

For more information, refer to the chapter K000135849: Unrestricted Resource Consumption | APIs and the OWASP Top 10 guide (2023) to understand how F5 products can rate limit API requests and manage resource consumption on your models.

Use a defense-in-depth strategy to protect your AI workloads

This section discusses the defense-in-depth strategies involving multiple layers of security controls and measures using F5's range of products and services that can assist in mitigating the threat at different layers:

Figure: Defense-in-depth with F5 products

Using F5 products and a defense-in-depth security strategy for your LLM applications can help reduce the likelihood of OWASP LLM vulnerabilities. This approach involves using multiple layers of security to protect your accounts, workloads, data, and assets. By doing so, you can ensure that if one security measure is compromised, additional layers can effectively help isolate threats and manage security events. You can enhance security and resilience by integrating various strategies, including F5 services and solutions, at each layer.

Data validation and sanitization

BIG-IP ASM/Advanced WAF

Data validation and sanitization refers to checking input data to ensure it meets specific criteria or constraints, and modifying or blocking the input data to prevent harmful or unexpected characters. Use the following features available in BIG-IP ASM/Advanced WAF to ensure that inputs to your LLM conform to strict security policies to mitigate resource abuse attacks.

Integration with OAuth providers

Implement IAM security for API access to your LLMs. BIG-IP APM integrates with your OAuth provider to implement secure authentication. Depending on your application logic, configure the following agents in a per-request policy:

  • An OAuth Client agent in a per-request policy with OpenID Connect to authenticate API requests with your OAuth provider.
  • An OAuth Scope agent in a per-request policy to validate tokens issued by your OAuth provider.

You can configure the BIG-IP APM to validate JWT tokens either internally or externally. In both configurations, implement the following to add a layer of protection:

  • Access token expiry
  • Access token deny list
  • Validate that the access token is signed with a secure signing algorithm

Summary

Similar to the other vulnerabilities in the LLM OWASP top ten, addressing unbounded consumption attacks requires implementing security measures at different layers, from examining and managing the content of requests or prompts to your LLM to limiting their numbers from each user or entity. It also requires implementing strict identity management and rule-based access control of users and devices.
