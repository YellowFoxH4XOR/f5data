K000132520: Endpoints not getting created in sidecar configuration for Kubernetes services

Description

After creating a test pod (httpbin) no endpoints are listed in the istioctl proxy-config endpoint command output for the httpbin service

$ oc get po,svc,endpoints -n default
NAME             READY  STATUS  RESTARTS  AGE
pod/httpbin-59488cdb78-lg8bg  2/2   Running  0     43m

NAME         TYPE      CLUSTER-IP    EXTERNAL-IP              PORT(S)  AGE
service/httpbin   ClusterIP   192.168.179.88  <none>                 8000/TCP  3h49m

NAME          ENDPOINTS                     AGE
endpoints/httpbin   192.168.0.137:8000                3h49m

$ istioctl pc endpoints -n default httpbin-59488cdb78-lg8bg --port=8000
ENDPOINT   STATUS   OUTLIER CHECK   CLUSTER

$ istioctl pc endpoints -n default httpbin-59488cdb78-lg8bg 
ENDPOINT                        STATUS   OUTLIER CHECK   CLUSTER
127.0.0.1:15000                     HEALTHY   OK        prometheus_stats
127.0.0.1:15020                     HEALTHY   OK        agent
unix://./etc/istio/proxy/XDS              HEALTHY   OK        xds-grpc


Environment

Aspen Mesh 1.11.*, 1.14.*
 

Cause

discoverySelectors is enabled preventing istiod from adding the endpoint configuration.
 

Discovery selectors allow us to control which namespaces Aspen Mesh/Istio control plane watches and sends configuration updates for. By default, the Aspen Mesh/Istio control plane watches and processes updates for all Kubernetes resources in a cluster. Aspen Mesh/Istio configures Envoy proxies in the mesh to reach every workload in the mesh and accept traffic on all ports associated with the workloads.
 

Recommended Actions

The discoverySelectors configuration declares what Aspen Mesh/Istio control plane watches and processes. Without discoverySelectors configuration, the Aspen Mesh/Istio control plane watches and processes all namespaces/services/endpoints/pods in the cluster.
 

Therefore disable discoverySelectors if you need Aspen Mesh/Istio control plane to watch and process all namespaces/services/endpoints/pods in the cluster or make sure the selection criteria target only the required resources.
