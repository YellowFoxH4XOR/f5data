Known Issue

This is the result of a known issue. The pvad process may assign the incorrect acceleration mode to virtual servers when more than 16 VLANs are configured. As a result, pvad places some virtual servers into wired mode when they should be in assist mode, or in assist mode when they should be in wired mode.

F5 Product Development tracked this issue as CR58266 and it was fixed in version 9.4 for the BIG-IP LTM software branch. For information about upgrading, refer to the BIG-IP LTM Release Notes.

This issue has been fixed in Hotfix-BIGIP-9.3.1-HF5, which has been issued for BIG-IP 9.3.1, for the BIG-IP 9.3 software branch. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

For information about how to manage F5 product hotfixes, refer to K6845: Managing F5 product hotfixes.

Note: For more information about the PVA modes, refer to K4832: Overview of PVA Acceleration features and sub features.

Note: This article applies only to platforms using PVA1 or PVA2, which supports hardware assist acceleration for a maximum of 16 VLAN MAC addresses. If more than 16 VLANs are configured on the system and the vlan.macassignment bigpipe db variable is set to first-member, the BIG-IP system disables hardware acceleration for all virtual servers.

Workaround

If you cannot upgrade or install the hotfix, you can work around this issue by performing the following procedure:

1. Log in to the command line.

2. Set the vlan.macassignment db variable from first-member to global, by typing the following command:

   bigpipe db vlan.macassignment global

The following example illustrates that first-member uses unique MAC address for each VLAN. Note the use of a unique MAC address on the first VLAN line for both VLANs:
