K16503435: With BIGIP APM, the MSRDP persistence profile may fail when the RDP object is set up with SSO.

Type
Support Solution
Published
2025-04-09

2025-04-09
Applies to

  • BIG-IP Platforms

  • VIPRION Platforms
Source

Description
BIGIP APM can be used to proxy Microsoft RDP connections.
If the connections to the RDP hosts can be made from the APM unit, other deployments rely on any BIGIP LTM load-balancer [LB] unit.
Those later can use "MSRDP" persistence profile, to ensure new connections will be connected to the same hosts, as it is for the existing ones.

The MSRDP persistence profile may fail when the APM is configured to perform SSO to the RDP hosts.

Environment

  • You're using BIGIP APM;
  • The Remote Desktop connections are using the Microsoft RDP protocol;
  • The RDP object is configured with SSO being enabled;
  • You're having an LTM LB unit, sitting between the BIGIP APM and the RDP hosts;
  • The LTM unit Virtual Server is configured with a MSRDP persistence profile.

Cause
When APM is to perform the SSO, it first establishes an SSL session to the RDP hosts.
As such, the credentials - and any other parameters related to the RDP session, such as cookies - are unknown to the MSRDP persistence profile.

Recommended Actions

We would need to choose to use any other persistence profile (such as address IP based profiles).
