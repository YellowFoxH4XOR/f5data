Known Issue

The BIG-IP system fails to load a configuration that has a proxy exclude IP address assigned to a non-default route domain. This issue occurs when all of the following conditions are met:

  • The configuration consists of a vlangroup object assigned to a non-default route domain.
  • The vlangroup object has an IP address defined in its Proxy Exclusion List.
  • The IP address is assigned to the non-default route domain.

For example, the following configuration snippet has the IP address 10.1.10.100%10 assigned to non-default route domain 10 and included in the Proxy Exclusion List for vlangroup vg_4858:

vlangroup all {
proxy excludes 10.1.10.100%10
}
vlangroup vg_4858 {
bridge in standby disable
members {
vlan1148
vlan1158
}
}
route domain 10 {
vlans {
vg_4858
vlan1148
vlan1158
}
}

This issue occurs because the BIG-IP system places the route domain configuration stanza below the vlangroup configuration stanza in the /config/bigip_base.conf file. When this configuration is loaded on a BIG-IP system after a software upgrade, hotfix installation, or a UCS archive restore on a RMA replacement unit, the configuration fails to load and the BIG-IP system reports an error.

Impact

The BIG-IP system fails to load the configuration and is unable to process traffic.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The BIG-IP system fails to load the configuration and reports an error message to both the command line and the /var/log/ltm file, which appears similar to the following examples:

    01070973:3: The specified route domain (10) does not exist for address (10.1.10.100%10).

    or

    ERROR, recvMCPreply: Got bad result: 01070973:3: The specified route domain (10) does not exist for address (10.1.10.100%10).

Workaround

To work around this issue, you can move the affected route domain stanza before the vlangroup stanza by modifying the /config/bigip_base.conf file. To do so, perform the following procedure:

Impact of workaround: None

  1. Log in to the command line.
  2. Make a copy of /config/bigip_base.conf file as a backup by typing the following command:

    cp -p /config/bigip_base.conf /var/tmp/bigip_base.conf.sol13183

  3. Edit the /config/bigip_base.conf file using a text editor of your choice.
  4. Locate the affected route domain stanza. A non-default route domain stanza may appear similar to the following example:

    vlangroup all {
    proxy excludes 10.1.10.100%10
    }
    vlangroup vg_4858 {
    bridge in standby disable
    members {
    vlan1148
    vlan1158
    }
    }
    route domain 10 {
    vlans {
    vg_4858
    vlan1148
    vlan1158
    }
    }

  5. Move the affected route domain stanza to a location before the vlangroup proxy exclusion stanza. The following example shows the affected route domain 10 placed before the vlangroup proxy exclusion stanza:

    route domain 10 {
    vlans {
    vg_4858
    vlan1148
    vlan1158
    }
    }
    vlangroup all {
    proxy excludes 10.1.10.100%10
    }
    vlangroup vg_4858 {
    bridge in standby disable
    members {
    vlan1148
    vlan1158
    }
    }

  6. Save the modifications and exit the text editor.
  7. Load the configuration by typing one of the following commands:
    • tmsh command

      tmsh load /sys config

    • bigpipe command

      bigpipe load
