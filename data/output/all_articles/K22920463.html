K22920463: BIG-IQ setup wizard fails with tokuToPgUpgrade.sh errors after upgrade to 8.x

Type
Support Solution
Published
2022-08-23
Updated
2025-02-06
Applies to
  • BIG-IQ
Source
https://my.f5.com/manage/s/article/K22920463

Description

While trying to finish the setup wizard on BIG-IQ CM on the last stage we may observe the following error:

Errors on Launch
Traceback (most recent call last):
  File "/usr/local/lib/python2.7/site-packages/bigiq_setup/configuration/bootstrap.py", line 239, in main
    _do_bootstrap(out)
  File "/usr/local/lib/python2.7/site-packages/bigiq_setup/configuration/bootstrap.py", line 196, in _do_bootstrap
    commander.run_pgupgrade()
  File "/usr/local/lib/python2.7/site-packages/bigiq_setup/configuration/commands.py", line 82, in run_pgupgrade
    stdout=self.outfile, stderr=STDOUT, env=env, close_fds=True)
  File "/usr/local/lib/python2.7/subprocess.py", line 186, in check_call
    raise CalledProcessError(retcode, cmd)
CalledProcessError: Command '['bash', '/usr/bin/tokuToPgUpgrade.sh']' returned non-zero exit status 1

 

Environment

  • BIG-IQ CM
  • Upgrade to version 8.x from pre-7.1.0 version of BIG-IQ
  • BIG-IQ CM setup

Cause

The database is corrupted.
Pre-7.1.0 BIG-IQ used tokumx database while PostgreSQL was introduced in 7.1.0.

The migration between the two different DB could lead to issue.

Recommended Actions

1. Remove the existing volume with 8.x version "tmsh delete sys software volume HD1.X" (replace X with the actual volume number).
2. Modify the self-allow list to include the port used by postgres for HA:

tmsh modify net self-allow defaults add {tcp:5432}

3. Save the updated configuration:  tmsh save sys config
4. Make file /config/startup writeable:

chmod +w /config/startup

5. Edit the /config/startup file using an editor of choice and add the following lines to the end:

   if [ -d "/var/config/rest/toku/data" ]
     then
      chcon -Rt mongod_var_lib_t /var/config/rest/toku/data
   fi

6. Return file /config/startup to read-only:  chmod -w /config/startup
7. Install the 8.x image onto a new partition.
8. Boot into the new partition.
9. On GUI check the upgrade progress - it may take up to 3-4 hours to complete.
