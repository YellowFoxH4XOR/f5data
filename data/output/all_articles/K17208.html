Known Issue

The BIG-IP Edge Client may contain duplicate entries in the Select server: list.

This issue occurs when all of the following conditions are met:

  • Multiple BIG-IP APM Connectivity Profiles are configured to use the same alias names for different resources.
  • A BIG-IP Edge Client user establishes a session to each of the different virtual servers that are configured with duplicate Connectivity Profile alias names.

    Following is an example of conflicting Connectivity Profiles:

    client-policy {
            conn_profile1_clientPolicy {
                servers {
                    {
                        alias LondonLab
                        host https://apm.london1.example.com
                    }
                    {
                        alias SeattleLab
                        host https://apm.seattle1.example.com
                    }
                }
            }
        }


    client-policy {
            conn_profile2_clientPolicy {
                servers {
                    {
                        alias LondonLab
                        host http://apm.london2.examplesite.com
                    }
                    {
                        alias SeattleLab
                        host http://apm.seattle2.examplesite.com
                    }
                }
            }
        }

    Note: The alias names of LondonLab and SeattleLab are the displayed server names in the BIG-IP Edge Client server list.

Impact

The BIG-IP Edge Client user's Select server: list will contain duplicate server names (aliases) that reference different resources.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When a BIG-IP Edge Client user selects a server from their server list based on the server name/alias, the user may not be selecting the intended resource.

Workaround

To work around this issue, avoid duplicate alias names across Connectivity Profiles, when possible.
