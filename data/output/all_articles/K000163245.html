K000163245: F5OS-A r5800 Reports Different NVMe Disk Sizes 700.00GB on F5OS 1.5.0 and 652.00GB on F5OS 1.8.4

Description

F5OS can display the same NVMe namespace as approximately 700.00GB on F5OS 1.5.x and approximately 652.00GB on later F5OS 1.8.x releases. This is an expected capacity-unit reporting difference and does not indicate physical disk capacity loss.

Environment

  • F5OS-A
  • rSeries platforms
  • NVMe storage
  • Storage information displayed by:
    show components component storage

Cause

In F5OS 1.5.x, platform-mgr used the physicalSizeGB field, which reports capacity using decimal/SI units:

1 GB = 1,000,000,000 bytes

Beginning with later F5OS 1.8.x releases and F5OS 2.0, platform-mgr uses the sizeGB field, which reports capacity using binary units:

1 GiB = 1,073,741,824 bytes

Consequently, approximately 700,000,000,000 bytes is displayed as approximately 652 GiB when the binary-unit calculation is used:

700,000,000,000 / 1,073,741,824 ≈ 652 GiB

The underlying NVMe capacity has not decreased. Only the unit convention used for the SIZE value has changed.

Recommended Actions

  1. Interpret the approximately 700.00GB value from F5OS 1.5.x as a decimal/SI capacity.
  2. Interpret the approximately 652.00GB value from later F5OS releases as approximately 652 GiB.
  3. Treat the two values as equivalent representations of the same storage capacity.
  4. Do not replace the NVMe drive or classify the difference as hardware capacity loss based solely on the SIZE field.
  5. Collect additional RAID, namespace, partition, or filesystem information only if there is evidence of degraded storage, reduced usable capacity, or an operational impact.

Additional Information

The displayed storage value may also be lower than the physical drive datasheet capacity because F5OS presents storage after platform reservations and over-provisioning.
