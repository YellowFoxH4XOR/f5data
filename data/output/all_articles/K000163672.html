K000163672: How to selectively disable client-side HTTP/2 by SNI on BIG-IP LTM

Type
Support Solution
Published
2026-10-12
Updated
2026-10-12
Applies to
  • BIG-IP
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K000163672

Description

When an iRule on BIG-IP LTM is configured to selectively disable client-side HTTP/2 using HTTP2::disable or HTTP2::disable clientside in the HTTP_REQUEST event, a TCL error (e.g., 01220001:3: TCL error ... invoked from within "HTTP2::disable") occurs and clients may receive ERR_HTTP2_PROTOCOL_ERROR. This happens because the HTTP_REQUEST event occurs after ALPN negotiation and the client-side HTTP/2 session is already established, making it too late to disable HTTP/2 at that stage.

Environment

  • BIG-IP LTM 17.1.3 with HTTP/2 profile enabled on a virtual server
  • Client-side TLS/SSL termination
  • iRule logic for selective HTTP/2 disablement based on hostname
  • Hostname matching via data group
  • Use case involving slow upload/POST performance with client-side HTTP/2

Cause

HTTP2::disable or HTTP2::disable clientside is invoked in HTTP_REQUEST, which is after ALPN negotiation and client-side HTTP/2 session establishment. Disabling HTTP/2 at this point triggers protocol errors.

Answer/Recommended Actions

  • Perform selective client-side HTTP/2 disablement before ALPN negotiation by inspecting SNI in the CLIENTSSL_CLIENTHELLO event.
  • Example iRule:

when CLIENTSSL_CLIENTHELLO {
    if {[SSL::extensions exists -type 0]} {
        binary scan [SSL::extensions -type 0] @9a* SNI
    }
    if {[info exists SNI] && [class match $SNI equals dq-p09.awaf.abraxas-tools.ch_Host_HTTP2_disable]} {
        HTTP2::disable clientside
    }
}

  • Use SNI in CLIENTSSL_CLIENTHELLO for hostname-based HTTP/2 control, not HTTP::host in HTTP_REQUEST.
  • Test the iRule to ensure only intended hostnames fall back to HTTP/1.1.

Additional Information

  • Disabling HTTP/2 on the server side in HTTP_REQUEST may not cause the same error, but does not affect client-side HTTP/2.
  • For mitigating slow upload performance with client-side HTTP/2, disable HTTP/2 before ALPN negotiation.
