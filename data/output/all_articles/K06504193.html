Known Issue

The BIG-IP system allows you to configure multiple remote roles for a user, where each role uses the same partition access.

This issue occurs when all of the following conditions are met:

  • You have configured multiple groups with the same Attribute String.
  • These groups have a different Assigned Role and the same Partition Access.

    This can frequently occur when the values of Assigned Role and Partition Access in a group are configured with variable substitution, as denoted by a %. For example:

    %F5-LTM-User-Role

    In this case, the authentication server sets the value, thus, the invalid configuration would not be apparent in the bigip.conf file.

Impact

Affected users will match multiple roles; therefore, the BIG-IP system may assign remote users an unexpected role.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • When a remote user logs in, the BIG system may assign the user an unexpected role.

Resolution

Status

F5 Product Development has assigned ID 464289 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies To box, located in the upper-right corner of this article. For information about releases or hotfixes that resolve this issue, refer to the following table:

*Note: In fixed versions, the BIG-IP system prevents the invalid configuration, or in the case of variable substitution, logs an error in /var/log/ltm file, similar to the following example, when a user attempts to log in and matches multiple remote roles.

notice mcpd[7349]: 01070829:5: Input error: Duplicate remote user exampleuser in partition Common

Workaround

To work around this issue, you can reconfigure Remote Role Groups to eliminate conflicting remote roles for a single user. 

Impact of workaround: The impact of the suggested workaround depends on the specific environment. F5 recommends that you test any such changes during a maintenance window with consideration to the possible impact on your environment.
