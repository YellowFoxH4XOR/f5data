Known Issue

The BIG-IP system will experience a memory leak when you use SIP in TCP/Client SSL configurations.

This issue occurs when all of the following conditions are met:

  • You have a virtual server with a Client SSL profile configured.
  • You have the SIP profile configured on this virtual server.
  • You are using the SIP protocol over this virtual server.
  • The client-side flow is torn down in response to the SSL handshake not completing.

Impact

TMM may become unstable and possibly produce a core file as a result of exhausted memory.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H504308 on the Diagnostics > Identified > Medium screen.
  • In the /var/log/ltm file, you may observe error messages similar to the following example:

    warning tmm[12345]: 011e0003:4: Aggressive mode sweeper: 100 Connections killed

  • TMM memory consumption steadily increases over time.

    You can monitor TMM memory usage by using the tmstat command, or by typing the following tmsh command:

    tmsh show sys memory

  • The BIG-IP system fails to process traffic for a brief period of time.
  • The BIG-IP system fails over to another host in the device group.
  • TMM generates a core file in the /var/core directory.
