K000160359: Starting from version 17.5.x, the base64 identification logic may incorrectly identify some inputs, resulting in false positives.

Type
Support Solution
Published
2026-04-15
Updated
2026-04-28
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.5.X, 17.5.1, 17.5.0, 21.X.X, 21.0.X, 21.0.0
Source
https://my.f5.com/manage/s/article/K000160359

Description

After upgrading BIG-IP ASM to version 17.5.x, the base64 decoding option for parameters was automatically set to "Enabled" (auto-detect) for all parameters, resulting in false positives where non-base64 parameter values were incorrectly detected as base64. This led to decoded values triggering attack signature violations and blocking legitimate requests in production.

Environment

  • BIG-IP ASM/advanced WAF
  • Base64 decoding of parameter values

Cause

The root cause is a behaviour change in BIG-IP ASM 17.5 where the base64 decoding option for parameters defaults to "Enabled" (auto-detect). The detection algorithm incorrectly identifies some non-base64 values as base64, resulting in unnecessary decoding and attack signature violations and is documented as defect bug 2131797.

Answer/Recommended Actions

  • As a workaround, export the security policy in XML format, modify the <decode_value_as_base64> flag for affected parameters to "Disabled," and re-import the policy.
  • Alternatively, use the REST API to update parameters with the following command:

curl -sk https://${BIGIP_USER}:${BIGIP_PASSWORD}@${BIGIP_MGMT}/mgmt/tm/asm/policies/${POLICY_ID}/parameters?\$filter=decodeValueAsBase64+eq+"enabled"+and+dataType+eq+"alpha-numeric" -XPATCH -d'{"decodeValueAsBase64": "disabled"}'

In order to find the POLICY_ID, we can use below command.

curl -sk https://${BIGIP_USER}:${BIGIP_PASSWORD}@${BIGIP_MGMT}/mgmt/tm/asm/policies?\$filter=name+eq+"POLICY_NAME" | jq . | egrep -i "\"name\"|\"id\""

Additional Information

In versions prior to BIG-IP v17.5.x, there were only two options. Enabled and Disabled,  the default is disabled.

  • Enabled means input parameter value must be base64 and if decoding fails then Violation will be triggered.
  • Disabled means there will be no decoding attempted to the input parameter value.

In BIG-IP v17.5.x, a behavioural change for this feature is introduced. Now, there are three values, Enabled/Disabled/Required, the default is now changed to enabled.

  • Enabled means it will run the input parameter value through the internal algorithm to find out if provided value is base64 encoded or not. If it turns out to be legal base64 then only base64 decoding will proceed. If the decoded value has violations (such as AS triggers, illegal meta char), they will get triggered. There will be no violation triggered if it turn out to be non base64. 
  • Required the input parameter value must be valid base64, if decoding fails then Violation will be triggered.
  • Disabled means there will be no decoding attempted to the input parameter value.

There is no global option or DB variable exists to revert the default Base64 Decoding setting in ASM 17.5.x

OpenAPI YAML import does not support disabling Base64 Decoding for all parameters
