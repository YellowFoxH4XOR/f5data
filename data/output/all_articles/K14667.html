Known Issue

VIPRION systems may use the incorrect hash algorithm for TCP/User Datagram Protocol (UDP) packets.

This issue occurs when the following conditions are met:

  • The VIPRION cluster UDP or TCP hash algorithm was changed from the default setting of port to ipport.

    For example:

    tmsh list /sys db udp.hash
    sys db udp.hash {
        value "ipport"
    }


  • UDP or TCP virtual servers are configured on the system.
  • A new blade is inserted into the chassis.

Impact

The BIG-IP system may experience uneven traffic distribution across Traffic Management Microkernel (TMM) instances, which may disrupt traffic flows or reduce traffic throughput.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The system experiences uneven traffic distribution across TMM instances.

    For example, you may observe that traffic arriving on the newly installed blade is being hashed to one TMM instance.
  • The system experiences higher than normal CPU utilization.

Workaround

To work around this issue, you can reboot the newly installed blade after adding it to the cluster. To do so, perform the following procedure:

Impact of workaround: The VIPRION blade will be unavailable during the reboot.

  1. Log in to the newly installed VIPRION blade using the blade's Cluster Member IP Address.
  2. Navigate to System > Clusters > Properties.
  3. Select the check box next to the slot number for the newly installed blade, and then click Disable/Yield.
  4. Navigate to System > Configuration > Device.
  5. Click Reboot Blade.
