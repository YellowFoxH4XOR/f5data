Known Issue

BIG-IP APM may incorrectly handle HTTP server responses that contain the HTTP Refresh header.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM system is configured for portal access.
  • The APM virtual server is configured with a rewrite profile.
  • The destination server of the portal access configuration responds with an HTTP Refresh header to a user request for a non-text (binary) object.

Impact

Content that depends on the HTTP Refresh header may not function as expected.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The portal user's web page content does not display correctly.
  • Log messages that appear similar to the following example are written to the /var/log/apm file:

    notice <timestamp> rewrite - RewritePlugin.cpp:225 : Rewrite Log Level Set to:5
    notice <timestamp> rewrite - RewritePlugin.cpp:194 : Rewrite Invalid SID (<null>) Length:6 should be 1 or 8
    notice <timestamp> rewrite - RewritePlugin.cpp:225 : Rewrite Log Level Set to:5
    notice <timestamp> rewrite - RewritePlugin.cpp:194 : Rewrite Invalid SID (<null>) Length:6 should be 1 or 8
    notice <timestamp> rewrite - RewritePlugin.cpp:225 : Rewrite Log Level Set to:5
    notice <timestamp> rewrite - RewritePlugin.cpp:194 : Rewrite Invalid SID (<null>) Length:6 should be 1 or 8
    notice <timestamp> rewrite - RewritePlugin.cpp:225 : Rewrite Log Level Set to:5
    notice <timestamp> rewrite - RewritePlugin.cpp:194 : Rewrite Invalid SID (<null>) Length:6 should be 1 or 8
  • The BIG-IP system generates a rewrite core file to the /shared/core directory, which appears similar to the following example:

    /shared/core/rewrite.2.bld608.0.core.gz
