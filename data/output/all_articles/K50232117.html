Description

When performing a ConfigSync, it results in a Sync Failed state. The following error can be seen in the GUI and /var/log/ltm:

01020036:3: The requested profile (/Common/bot-defense-device-id-generate-before-access) was not found.

Environment

  • ConfigSync

Cause

One or more default Bot Defense profiles were manually deleted from the /config/bigip.conf file.

Bug ID 772165

Note: This issue might occur even if ASM is not provisioned.

Recommended Actions

First, attempt the workaround listed in Bug ID 772165.

If that doesn't work, proceed with the alternative workaround below:

Alternative workaround

Determine which device in the device group is missing the profiles, then re-add the profiles to the /config/bigip.conf file, reload the configuration, and sync once more.

  1. From the command line of each device in the group, grep for the bot-defense profiles in /config/bigip.conf:

    grep 'profile /Common/bot-defense' /config/bigip.conf

    There may be no output returned, or shorter output, on the affected device.

    The default profiles that should always be present are:

    security bot-defense profile /Common/bot-defense
    security bot-defense profile /Common/bot-defense-device-id-generate-after-access
    security bot-defense profile /Common/bot-defense-device-id-generate-before-access
    security bot-defense profile /Common/bot-defense-device-id-none

  2. Once you have determined which device is affected, copy the bot-defense profiles from the non-affected unit's /config/bigip.conf file into a text editor.

  3. Edit the /config/bigip.conf file on the affected unit and paste in the missing bot defense profiles.

    Note: It does not matter which location they are inserted at. For convenience you may place them at the end of the file.

  4. Reload the configuration:

    tmsh load sys config

    Note: When reloading the configuration, all device groups will enter a changes pending state and the device with the reloaded config will have the newest commit ID.

  5. Verify the profiles are in the running and text configuration:

    grep 'profile /Common/bot-defense' /config/bigip.conf

    tmsh list security bot-defense profile | grep profile

  6. Sync the sync-failover and datasync-global-dg device groups to the group:

    tmsh run cm config-sync to-group <sync-failover-group>

    tmsh run cm config-sync to-group datasync-global-dg

  7. (Optional) Save the running configuration on all devices:

    tmsh save sys config

The issue should not return unless the profiles are manually removed from the /config/bigip.conf file once more.

You may also run into a scenario where this configuration is missing from each HA peer causing sync failure. If the expected default profiles have been removed entirely from both devices, you must then extract these entries from a .UCS that still contains the relevant bot-defense configuration or by restoring one of the peers to the system default configuration and proceeding with the workaround above.

Additional Information

Default profiles are typically loaded into the running configuration from /config/profile_base.conf and associated files when the system boots or when issuing a load sys config command. In the situation where defaults are missing in /config/bigip.conf and the config is reloaded, they won't be re-added to /config/bigip.conf but they will exist in memory.
