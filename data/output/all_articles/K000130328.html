K000130328: SNMP is not working on vCMP guest after vCMP host was rebooted without disabling vCMP guest(s)

Type
Support Solution
Published
2022-12-22
Updated
2022-12-22
Applies to
  • BIG-IP
  • BIG-IP LTM: 16.1.3
Source
https://my.f5.com/manage/s/article/K000130328

Description

When a vCMP host is rebooted, intentionally or unintentionally, without putting vCMP guests into configured state first, upon the next boot-up of the vCMP guest, it would fail to 1) parse/load SNMPv3 usmUser, 2) create an oldEngineID in /config/net-snmp/snmpd.conf.

The resulting configuration appears as follows:

[root@guest1:Active:Standalone] config # cat net-snmp/snmpd.conf | egrep "^[a-z]"
usmUser 1 3 0x80001f88808481a27ed8be5063 "user2" "user2" NULL .1.3.6.1.6.3.10.1.1.3 0x86745fb6ba630de483ba9cbc4ef5a7a9d2879bdc .1.3.6.1.6.3.10.1.2.4 0x103700ae1c7d0f73d8f04a45fd4f377f 0x 0x2f436f6d6d6f6e2f6975736572325f3100
setserialno 1745462443
engineBoots 94
[root@guest1:Active:Standalone] config #

Note the "0x" on second-to-the-last column of usmUser token, and the absence of oldEngineID.

The symptoms would normally be:

1. Failure to query the BIG-IP using SNMPv3, which returns an Engine ID error.

[root@guest1:Active:Standalone] config # snmpget -v 3 -u user2 -a SHA -A "123456789" -x AES -X "123456789" -l authPriv localhost sysSystemUptime.0
snmpget: Unknown engine ID (Sub-id not found: (top) -> sysSystemUptime)

2. An error in /var/log/snmpd.log that says:

<snip>
snmpd[PID]: Starting snmpd
snmpd[PID]: buffer too small to read octet string (13 < 13)
</snip>

The issue appears to affect vCMP guests that use NET-SNMP v5.8 via (ID858769). It doesn't affect vCMP guests running NET-SNMP v5.7.2 such as BIG-IP v13.1.5.1.

Re-starting snmpd with 'bigstart restart snmpd' only resolves the oldEngineID issue, but never fixes the usmUser issue.
 

Environment

BIG-IP vCMP guest
NET-SNMP v5.8


Cause

ID1209465


Recommended Actions

The workaround is to reboot the vCMP guest. After which you'll see the "fixed" config, with the correctly formatted usmUser token together with the presence of oldEngineID token.

[root@guest1:Active:Standalone] config # cat net-snmp/snmpd.conf | egrep "^[a-z]"
usmUser 1 3 0x80001f888097ff1b0318c25063 "user2" "user2" NULL .1.3.6.1.6.3.10.1.1.3 0x12ad9432678f4946ccb98e4543b660606c87b061 .1.3.6.1.6.3.10.1.2.4 0x5e7573ce43e2d2d3ff1b6d939df10ea1 "" 0x2f436f6d6d6f6e2f6975736572325f3100
setserialno 1745462444
engineBoots 95
oldEngineID 0x80001f888097ff1b0318c25063

Mitigation is to ensure that vCMP guest is set to configured prior to rebooting the vCMP host.
