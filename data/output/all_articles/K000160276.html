K000160276: TLS Handshake Failure with "unexpected_message(10)" when using TLS Session Tickets feature

Type
Support Solution
Published
2026-03-09
Updated
2026-03-09
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.3
Source
https://my.f5.com/manage/s/article/K000160276

Description

Intermittent server-side SSL/TLS connections fail with the error "unexpected_message(10)" during the handshake process. The failure occurs when session resumption via TLS Session Tickets is enabled. Affected connections will be highlighted in the logs with a message such as the following:

warning tmm1[18299]: 01260009:4: 10.70.5.170:443 -> 10.70.5.37:44544: Connection error: ssl_hs_rx:5756: alert(10) unexpected msg

Environment

Product: BIG-IP LTM
Version: 15.x, 16.1.x, 17.1.x & 17.5.x releases
Configuration:

  • Server SSL profile with Session Ticket enabled (session-ticket enabled)
  • Backend server also supports Session Ticket
  • SNI and peer certificate validation may be enabled
  • Issue occurs when the backend server rejects the Session Ticket sent by BIG-IP (e.g., after server-side session ticket cache is cleared or server is restarted)

Cause

Bug ID2230705.

The issue is triggered when BIG-IP attempts to resume a session by presenting a non-zero length session ticket in the TLS ClientHello, but the backend server responds with a zero-length session ticket extension in the ServerHello (indicating it cannot resume the session and will issue a new ticket). According to RFC5077 Section 3.2, this is a valid scenario and BIG-IP should proceed with a full handshake and accept a new session ticket. However, affected BIG-IP versions instead terminate the handshake with a fatal alert before the server can send the NewSessionTicket message.

Answer/Recommended Actions

As a workaround, disable the Session Ticket feature in the Server SSL profile:

 

  • Navigate to the Server SSL profile applied to the virtual server
  • Set session-ticket to disabled
  • Save and apply the configuration

This will prevent BIG-IP from attempting session resumption using session tickets, avoiding the handshake failure

If session ticket functionality is required, contact F5 Support to request an Engineering Hotfix (EHF) referencing Bug ID2230705.

The issue only occurs when BIG-IP presents a non-zero length session ticket and the backend server rejects it (e.g., after a server restart or session ticket cache loss).
