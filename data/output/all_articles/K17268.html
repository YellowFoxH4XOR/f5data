Known Issue

In certain circumstances, TMM may exit and restart when processing Secure Sockets Layer (SSL) traffic.

This issue occurs when all of the following conditions are met:

  • The affected virtual server is configured with a Client SSL profile.
  • Specific conditions such as a null event context or aborted flow are encountered while processing SSL traffic, which cause a SIGSEGV signal to be sent to TMM.

While not all conditions are currently known, this issue has been observed when using the SSL::handshake resume iRule command to resume SSL processing, and when performing URL categorization using the BIG-IP APM SWG system.

Impact

The BIG-IP system temporarily fails to process traffic as it recovers from the TMM restart, and devices configured as a high-availability pair may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system generates a TMM core file to the /shared/core directory.
  • The BIG-IP system temporarily fails to process traffic or fails over to the Standby system.
  • A SIGSEGV message and stack trace are logged to the /var/log/ltm file.
