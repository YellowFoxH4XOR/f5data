Known Issue

The BIG-IP APM apd and logd processes may experience high CPU utilization under load.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM system is processing a large number of authentication requests per second.
  • When processing authentication requests, the BIG-IP APM system either receives TCP resets or no response at all, or is bound by logging events. As a result, this behavior increases the number of unprocessed authentication requests in the queue.

Impact

The apd process becomes unresponsive, causing user authentication to fail.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Utilities, such as top or ps, show high CPU utilization for the apd and logd processes.

    For example:

    PID USER PR NI VIRT RES SHR S %CPU %MEM TIME+ COMMAND

    12659 root 20 0 164m 67m 26m S 94.6 1.0 5:18.81 /usr/bin/apd -d 5 -f -n 40 -u 4
    12510 root 20 0 75616 31m 22m R 89.0 0.5 3:50.97 /usr/bin/logd
  • Users are unable to authenticate to the BIG-IP APM system.
  • The BIG-IP APM system experiences performance degradation.
  • The BIG-IP APM system exhausts available file descriptors.

Workaround

There is no workaround for this issue, but you may be able to recover from the issue by restarting the apd process. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure will prevent the BIG-IP APM system from processing traffic while the apd process restarts.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Restart the apd process using the following command syntax:

    restart /sys service <service>

    For example:

    restart /sys service apd

  3. Exit tmsh by typing the following command:

    q
