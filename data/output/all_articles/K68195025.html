Description
Route to a subnet defined on APM is not being patched in client's routing table when connecting to VPN.

For example, if a client connects and has a private address of 10.10.10.123/24 and there is an APM defined route 10.0.0.0/24 on the Network Access resource, this route will not be added to client's routing table. So VPN connected clients with the IP 10.x.x.x/24 as a source private addresses are unable to access corporate resources on the 10.0.0.0 LAN.

Environment

  • BIG-IP APM
  • BIG-IP Edge Client

Cause
Route to same subnet existent on client before connecting to VPN.

Recommended Actions

If using Split tunneling, disable "Allow Local Subnet" in the Network access resource.
This object can be found in the GUI here:
Access ›› Connectivity / VPN : Network Access (VPN) : Network Access Lists ›› <network_access_resource_name> : "Allow Local Subnet"
