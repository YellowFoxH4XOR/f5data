Known Issue

This is the result of a known issue. An HTTP response with a chunked header and no data results in a buffer memory leak.

In the following HTTP response example, the Transfer-Encoding Header is set to chunked, but the response contains no data:

HTTP/1.1 200 OK
Date: Mon, 30 Oct 2006 21:08:26 GMT
Server: Apache/2.0.50 (Linux/SUSE)
Transfer-Encoding: chunked <===
Content-Type: text/plain; charset=ISO-8859-1
<no data in packet, HTTP header only>

The BIG-IP LTM system creates a buffer each time it receives an HTTP response with the Transfer-Encoding Header set to chunked. If the HTTP response does not contain any data, the buffer is not freed and remains in memory.

Note: The amount of memory allocated for 0-byte buffers is minimal. Therefore, the memory leak is slow and may not affect your system immediately.

F5 Product Development tracked this issue as CR70761 and it was fixed in BIG-IP LTM 9.1.3, 9.2.5, 9.3, and 9.4. For information about upgrading, refer to the BIG-IP LTM Release Notes.
