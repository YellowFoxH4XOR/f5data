K12708: The BIG-IP WebAccelerator rewrites Pragma with Xragma under certain conditions

Topic

If an HTML page contains the Pragma meta tag with the value set to no-cache, some client browsers may re-validate the content the next time this page is requested. If you configure the BIG-IP WebAccelerator with the Use HTTP lifetime headers if present and Ignore no-cache HTTP headers in the response settings enabled, the BIG-IP WebAccelerator rewrites the Pragma to Xragma.

For example:

<META HTTP-EQUIV="Xragma" content="no-cache">.

As a result, the client browser will ignore this meta tag. The reason for this rewrite is to prevent the Pragma meta tag from over-riding the caching behavior configured in Lifetime > Client Cache Settings. In addition, this rewrite may also occur if the Use HTTP lifetime headers if present setting is cleared.

F5 Product Development tracked a Request for Enhancement (RFE) as ID 351523 to provide an option to disable the rewrite. This RFE no longer applies to BIG-IP WebAccelerator 11.0.0 and later due to architectural changes.

Workaround

You can prevent the rewrite by configuring the Use HTTP lifetime headers if present setting. To do so, perform the following procedure:

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to WebAccelerator > Policies > Policy List.
  3. Click on the Policy that you want to configure.
  4. Navigate to the leaf node that you want to modify.

    For example, to modify the Pages leaf node, you would navigate to Site > Application Generated > Pages.
  5. Click on the Matching Rules drop-down box.
  6. Select Acceleration Rules.
  7. Click the Lifetime tab.
  8. Under the Header Lifetime Options section, select the Use HTTP lifetime headers if present check box.
  9. Clear the Ignore no-cache HTTP headers in the response check box.
  10. To save the modifications, click Save.
  11. To publish the modifications, click Publish.
  12. (Optional) Add comments in the Comment box.
  13. Click Publish Now.
