Description

When configuring the waf_exclusion_policy block within the volterra_http_loadbalancer resource using the Volterra (F5 Distributed Cloud/XC) Terraform provider, users may encounter errors such as:

  • Error: Insufficient waf_exclusion_policy blocks
  • Terraform plan always reports changes: + waf_exclusion_policy {} even when no configuration changes were made.

This article clarifies whether waf_exclusion_policy is optional or required at the route level, explains observed Terraform plan drift, and outlines correct configuration patterns.

Environment

  • Product: F5 Distributed Cloud HTTP Load Balancer
  • Terraform Provider: volterraedge/volterra (tested with v0.11.48)
  • Resource: volterra_http_loadbalancer
  • Configuration objects:
    • waf_exclusion_policy
    • waf_exclusion_inline_rules
    • routes.simple_route.advanced_options

Cause

Wrong syntax used.

Answer/Recommended Actions

Key Configuration Rules

  • At the load balancer level (waf_exclusion {} block), configure either waf_exclusion_policy {} or waf_exclusion_inline_rules {}—not both. These are mutually exclusive. The provider will only use the first one found and ignore the other.
  • At the route level (routes.simple_route.advanced_options), the waf_exclusion_policy {} block is independent of the LB-level exclusion. It is not required unless you want to override the LB-level policy for a specific route.

When is waf_exclusion_policy {} Required at the Route Level?

  • Required if you want to override the LB-level WAF exclusion with a route-specific policy.
  • Not required if:
    • You set inherited_waf_exclusion = true (the route inherits the LB-level exclusion).
    • You set disable_waf = true (WAF is disabled for the route).
    • Neither inherited_waf_exclusion nor waf_exclusion_policy is set (the route uses the LB-level exclusion by default).

Example Patterns

1. LB-level policy, route-level override:

resource "volterra_http_loadbalancer" "example" {
waf_exclusion {
waf_exclusion_policy {
name = "global-policy"
namespace = "production"
}
}
routes {
simple_route {
advanced_options {
# Option A: inherit LB-level exclusion
inherited_waf_exclusion = true
# Option B: override with a different policy
# waf_exclusion_policy {
# name = "route-specific-policy"
# namespace = "production"
# }
}
}
}
}

2. LB-level inline rules, route-level override:

resource "volterra_http_loadbalancer" "example" {
waf_exclusion {
waf_exclusion_inline_rules {
rules {
metadata {
name = "my-rule"
}
any_domain = true
any_path = true
waf_skip_processing = true
}
}
}
routes {
simple_route {
advanced_options {
waf_exclusion_policy {
name = "route-specific-policy"
namespace = "production"
}
}
}
}
}

Additional Information

  • The route-level waf_exclusion_policy {} is always available and independent of the LB-level configuration.
  • There is no dependency or expectation between LB-level and route-level WAF exclusion configuration.
  • If both waf_exclusion_policy {} and waf_exclusion_inline_rules {} are present at the LB level, only the first is used; the other is ignored.
  • To avoid errors, ensure only one of waf_exclusion_policy {} or waf_exclusion_inline_rules {} is present at the LB level.
