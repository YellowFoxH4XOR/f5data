Known Issue

Certain global iRules commands may reset virtual server connections that use a FastL4 profile.

This issue occurs when all of the following conditions are met:

  • The iRule uses the peer, clientside, or serverside global commands.
  • The virtual server associates with the iRule and a FastL4 profile.

Impact

Connections processed by the iRule may reset.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • F5 iHealth lists Heuristic H427511 on the Diagnostics > Identified > High screen.
  • You find an error message in the /var/log/ltm file that appears similar to the following example:

    err tmm[8781]: 01220001:3: TCL error: /Common/rule <iRule_EVENT> - no peer connection established LINK::vlan_id needs an established peer connection!

  • Connections processed by the iRule are unexpectedly reset.

Resolution

Status

F5 Product Development has assigned ID 414849 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies To box, located in the upper-right corner of this article. For information about releases, point releases, or hotfixes that resolve this issue, refer to the following table.

Release11.4.0K2200: Most recent versions of F5 software
Point release/hotfix11.3.0 HF8K9502: BIG-IP hotfix matrix

Note: BIG-IP WebAccelerator and BIG-IP WOM were combined to create BIG-IP AAM in 11.4.0.

Workaround

You may be able to work around this issue by rewriting the affected iRule to communicate the information between connection sides using shared variables. For more information about iRules commands, refer to iRules Home on F5 Cloud Docs.

Impact of workaround: Changing the design of an iRule may have additional effects on traffic processing. Ensure modifications are compatible with your environment.
