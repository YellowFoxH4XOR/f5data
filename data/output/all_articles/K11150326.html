Description

Users in APM local user database do not get synchronized to the standby device.

Issue happened on a new device being added to a cluster after an RMA.

Customer was not using a UCS backup, basic network and device group configuration were manually added, configuration sync executed, and the devices were showing to be in Sync. However customer had missed out on provisioning APM on the Standby device, hence it was done later.

After APM was provisioned the users in local user database present on the Active device were not present on the new standby device , however other APM related configuration seemed to be in place.

Environment

  • New device being added to a cluster after RMA, however configuration sync was done prior to provisioning APM on the new device.

Cause

Unknown at time of publication

Recommended Actions

  1. Do an mcpd reload on standby device following K13030.
  2. Do a force sync from the current active unit to the device-group following K13920

Additional Information

For local user database data to be synchronized across devices, the devices must be included in a Sync-Failover device group. In a Sync-Failover device group, the active node provides the local user database data to the other nodes initially, and then provides updated data every five minutes.
