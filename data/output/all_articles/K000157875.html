Description

This article explains how to resolve an issue where DHCPv6 relay packets forwarded by BIG-IP LTM have a hop limit (hlim) of 0, causing them to be dropped by downstream DHCPv6 servers. The problem occurs when client solicit messages arrive at BIG-IP with a hop limit of 1, and the system decrements this value during relay. Unlike DHCPv4, there is no GUI option for "Max Hops" in DHCPv6 profiles; however, starting with BIG-IP v15.x, you can override this behavior using the internal database variable tmm.dhcp.dhcpv6.ttl_client_overwrite.

Environment

  • DHCPv6 relay virtual server
  • DHCPv6 profile applied to the virtual server
  • Relayed packets from clients with initial hop limit of 1
  • DB variable: tmm.dhcp.dhcpv6.ttl_client_overwrite

Cause

None

Recommended Actions

To override the hop limit for relayed DHCPv6 packets on BIG-IP LTM:

  1. Check the current value of the DB variable:
    tmsh list sys db tmm.dhcp.dhcpv6.ttl_client_overwrite
  2. If set to 0, change it to a value greater than 0 (e.g., 5):
    tmsh modify sys db tmm.dhcp.dhcpv6.ttl_client_overwrite value 5
  3. Ensure that the correct DHCPv6 profile is applied to your virtual server.
  4. Clear any existing DHCPv6 connections:
    tmsh delete sys conn cs-server-port <port>
  5. Retest relay functionality and verify outgoing packet hop limits.

Additional Information

  • The DB variable tmm.dhcp.dhcpv6.ttl_client_overwrite allows administrators to set a custom hop limit for relayed DHCPv6 packets.
  • This workaround is available starting from BIG-IP v15.x.
