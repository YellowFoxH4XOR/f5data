Description

iRule with SNAT command fails with an "F5RST: Address in use" in HTTP_REQUEST

 

Environment

  • BIG-IP LTM
  • irule with snat
  • TCP profile with Verified-Accept

 

Cause

When the TCP profile enables Verified-Accept, the server-side TCP 3-way handshake is established as the client-side TCP 3-way handshake is proceeding.

Other operations (such as TLS handshake) also proceed. This means that when the client sends a TCP request, there is already an established server-side connection.

Attempting to change server-side connection settings (such as changing the SNAT address) will cause an error.

 

ltm profile tcp /Common/tcp-verified-accept {

  app-service none

  defaults-from /Common/tcp

  verified-accept enabled            <===

}

We can see the effect of Verified-Accept in the following packet capture:

If the TCP profile does not enable Verified-Accept, the server-side TCP connection will not be established until an HTTP request is received from the client.

In that case, the SNAT address can be changed in HTTP_REQUEST in the irule without error.

 

Recommended Actions

remove TCP profile Verified-Accept option

or

use LB::detach in the irule prior to changing a server-side connection option, along with a OneConnect profile.

Note: This option may be inefficient if SSL profiles are in use on the server-side connection.
