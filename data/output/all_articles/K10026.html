Note: Beginning in ARX 5.2.0, the ARX Secure Agent software is no longer bundled with the ARX software. For more information, refer to K12394: The ARX Secure Agent software is no longer bundled with the ARX software.

Note: For information about obtaining the ARX Secure Agent software, refer to K8784: Obtaining the ARX Secure Agent software.

Note: For information about installing, upgrading, and configuring the ARX Secure Agent software after successfully retrieving it from the ARX software directory, refer to the Secure Agent Installation Guide for your specific ARX software version.

The ARX Secure Agent software, formerly named the Acopia Secure Agent software, is a lightweight service that runs on a Microsoft Windows domain controller to assist the ARX system when performing NTLM authentication of clients that access ARX front-end Common Internet File System (CIFS) services, and NTLM authentication of the back-end ARX session to the filer.

The Secure Agent software runs on the following Microsoft Windows domain controller versions:

  • Windows 2012 - 32-bit and 64-bit
    • Requires Secure Agent 5.1.7 HF4 (build 12065). Previous versions of Secure Agent are not compatible with Windows 2012.
  • Windows 2008 (all editions) - 32-bit and 64-bit
    • Requires Secure Agent 5.1.0 or later. Previous versions of Secure Agent are not compatible with Windows 2008.
  • Windows 2003 SP2 - 32-bit and 64-bit
  • Windows 2003 R2 - 32-bit and 64-bit
  • Windows 2003 SP1 - 32-bit and 64-bit
  • Windows 2003
  • Windows 2000 Server, SP4

The Secure Agent software is required when an ARX deployment is configured to use the NTLM authentication protocol. Secure Agent is not required when the deployment supports Kerberos only. Additionally, NTLMv2 support was introduced in Secure Agent 5.1.0. If you require NTLMv2 authentication, both Secure Agent and the ARX system must run version 5.1.0 or later.

Note: For information about displaying the version information for ARX Secure Agent, refer to K11713: Displaying the software version for the ARX Secure Agent.

NTLM authentication is required when clients that access ARX-hosted CIFS services are not capable of negotiating Kerberos in a manner supported by the ARX system. All ARX-supported Microsoft clients, such as Microsoft Windows 2000 and newer, support Kerberos. However, Windows NT 4.0 and Mac OS clients do not support Kerberos.

Installing or upgrading the Secure Agent software

You can find detailed instructions to install or upgrade the Secure Agent software in the ARX Secure Agent Installation Guide. When you upgrade, the Windows domain controller must be rebooted to complete the upgrade process. The Secure Agent software requires domain administrator privileges to install and run. Additionally, when User Account Control (UAC) is enabled in Windows 2008, you must enter the administrator account password if you use a different domain administrator account to install or run the software.

Programs included with ARX Secure Agent to access the Microsoft Windows password database

ARX Secure Agent uses various programs to access the Microsoft Windows password database that consists of user names and MD4 password hashes. To determine the program for your specific ARX Secure Agent version, refer to the following table:

ARX Secure Agent versionProgram
5.1.5 HF1 (build 11966) and latermd4dump.exe and md4service.exe
5.1.0 to 5.1.5fgdump.exe
5.0.6 and earlierpwdump.exe

Important: Passwords are never dumped, accessed, or obtainable in clear-text.

Using the md4dump, fgdump or pwdump utility within Secure Agent does not compromise or weaken network security. The MD4 password hashes are never exchanged between Secure Agent and the ARX system. Only usernames, random challenges, and 24-byte responses are shared between Secure Agent and the ARX system. This behavior is not different from the normal information exchange between a client and server in a native CIFS authentication exchange, except the connection between Secure Agent and the ARX system is an encrypted and authenticated session, and requires knowledge of a shared secret.

Note: The source code for md4dump.exe, fgdump.exe and pwdump.exe is available under GPL. The procedure to build the executable is included in Secure Agent's build procedure. 

Anti-virus software running on the Microsoft Windows domain controller

Some anti-virus software may erroneously interpret components of ARX Secure Agent as malware, and may prevent ARX Secure Agent from installing or functioning properly. If the domain controller that runs ARX Secure Agent has AV software installed, you may need to configure the anti-virus software to allow or exclude ARX Secure Agent components.
