Topic

The BIG-IP APM base and maximum license counts are platform and module specific.

This article applies to non-iSeries platforms. For information about iSeries, VIPRION, and Virtual Edition (VE), refer to the following articles:

  • K95135311: BIG-IP APM licensing for Virtual Edition instances
  • K41332981: BIG-IP APM licensing for VIPRION
  • K01151630: BIG-IP APM licensing for BIG-IP iSeries appliances

Description

The BIG-IP APM system uses different types of licenses, depending on the type of resource you access.

For example, note the following:

  • The system uses an access session license when you start any new session.
  • The system uses a User Connectivity License (CCU) when you assigned one or more BIG-IP APM resources with tunnel-type access.
  • The system uses a Secure Web Gateway (SWG) license when you employ a URL filtering service or an SWG service.

For more information about license types, refer to K13267: BIG-IP APM connectivity license use.

Beginning September 2019, for a BIG-IP APM standalone, GBB (Best) or BIG-IP APM add-on license, after you reactivate the license on your BIG-IP system, you may observe that the value of the total access sessions and total swg limited sessions increases to a large value (10M, 20M, and greater).

For example:

# tmsh show apm license
--------------------------------------------
Global Access License Details:
--------------------------------------------
 total access sessions: 10.0M
 [...]
 total swg limited sessions: 10.0M

This behavior occurs so that the number of total access sessions and total swg limited sessions are not restricted based on licensing. However, the values (10M, 20M) do not indicate your BIG-IP APM system's capacity to handle the number of sessions. You must continue performing capacity and sizing tests before you deploy your BIG-IP system in production. This licensing change does not affect the current CCU and SWG license enforcement.

PUA (license version 18 or later)

Privileged User Access (PUA) allows ephemeral authentication for smart cards or allows you to use federated authentication credentials to gain access to traditional password-only systems (for example, SSH and Telnet). PUA allows browser-based access and authentication to systems that traditionally do not include passwordless authentication options, such as federated or smart cards.

You can configure Ephemeral Authentication to behave as an LDAP or Radius authentication server, or to proxy authentication to an LDAP or Radius authentication server.

Note: Ephemeral Authentication is available starting in BIG-IP APM 16.0.0.
