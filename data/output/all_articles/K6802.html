Issue

The BIG-IP 4.x implementation of Windows Terminal Services (WTS) and Microsoft Remote Desktop (MSRDP) persistence uses incoming tokens exchanged between the WTS/MSRDP client and WTS/MSRDP server. This token stays with the client until the client logs out of the WTS/MSRDP server. The token is stored on the client and behaves similarly to cookie persistence. There is no way to configure a timeout value for the token in BIG-IP 4.x—the timeout value must be configured on the WTS client or server.

The BIG-IP 9.x implementation of Windows Terminal Services (WTS) and Microsoft Remote Desktop (MSRDP) persistence uses a Microsoft Remote Desktop persistence profile on the BIG-IP LTM for WTS/MSRDP persistence. You can configure the timeout value as desired using the Microsoft Remote Desktop persistence profile.

In BIG-IP 4.x, since there is no way to configure the BIG-IP to time out the client's token, the BIG-IP would continue to persist to a server that has gone down. Changing from token-based persistence to a BIG-IP persistence profile with configurable timeout value helps to avoid situations where the client connection is persisted to a server that is down.

Specifying the timeout value used in the Microsoft Remote Desktop persistence profile

To specify the timeout value used for the Microsoft Remote Desktop persistence profile, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles.
  3. Click Persistence.

    The Persistence Profiles screen opens.

  4. Click the desired Microsoft Remote Desktop profile.
  5. From the Timeout menu, select Specify...
  6. Type the desired timeout value, in seconds, in the Seconds box.
  7. Click the Update button.

For information about configuring the BIG-IP LTM with WTS and Microsoft Remote Desktop, refer to the following deployment guide:

Deploying the BIG-IP LTM System and Microsoft Windows Server 2003 Terminal Services
