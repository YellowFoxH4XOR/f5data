Topic

It is possible to route requests through multiple BIG-IP ASM policies in sequence using the virtual iRule command. For example, you can use this approach to test a new security policy to ensure it does not generate false positives without removing the protection offered by the existing security policy.

To route traffic through two security policies, you must create two virtual servers and apply one policy to each virtual server. The first virtual server will also use a simple iRule to direct all traffic to the second virtual server using the virtual iRule command.

Building the configuration

To build this example configuration, perform the following three procedures:

  • Configuring the iRule for the first virtual server
  • Configuring the first virtual server
  • Configuring the second virtual server

Note: Each of the two BIG-IP ASM security policies must already be built and applied to an HTTP class profile before you can build the remainder of the configuration.

Configuring the iRule for the first virtual server

To create the iRule in the Configuration utility, perform the following procedure:

  1. From the Configuration utility, click Local Traffic Manager.
  2. Click the iRules menu option.
  3. On the iRules screen, click Create.
  4. In the Name field, type a name for the iRule.

    For example:

    forward_to_VS2
  5. In the Definition field, paste the following iRule:

    when HTTP_CLASS_SELECTED {
    virtual VS2
    }
  6. To save the iRule, click Finished.

Configuring the first virtual server

To create the first virtual server, perform the following procedure:

  1. From the Configuration utility, click Local Traffic Manager.
  2. Click the Virtual Server menu option.
  3. On the Virtual Server screen, click Create.
  4. In the Name field, type a name for the virtual server.

    For example:

    First_VS
  5. In the Address field, type an IP address for the virtual server.

    Note: Clients will connect to this address, so it must be a publicly routable address.
  6. In the Service Port field, type the port number to which clients will connect for this application.
  7. In the HTTP Profile field, select an HTTP profile.
  8. In the iRules dialog box, select from the Available list the iRule that you created in the Configuring the iRule for the first virtual server procedure.
  9. Click << to move the iRule to the Enabled list.
  10. In the HTTP Class dialog box, select the appropriate Application Security enabled HTTP class profile from the Available list.

    Note: Select the policy that should process requests first.
  11. Click << to move the profile to the Enabled list.
  12. The Default Pool value should be left at None.
  13. To save the virtual server, click Finished.

Note: Modify other virtual server settings as necessary to support your application.

Configuring the second virtual server

To create the second BIG-IP ASM virtual server, perform the following procedure:

  1. From the Configuration utility, click Local Traffic Manager.
  2. Click the Virtual Server menu option.
  3. On the Virtual Server screen, click Create.
  4. In the Name field, type a name for the virtual server.

    For example:

    Second_VS
  5. In the Address field, type the IP address to which clients will connect for this application.

    Note: Clients will not connect to this address; it can be a loopback or private address.
  6. In the Service Port field, type the port number on which this virtual server will accept connections.
  7. In the HTTP Profile field, select an HTTP profile.
  8. In the HTTP Class dialog box, select the appropriate Application Security enabled HTTP class profile from the Available list.

    Note: Select the policy that should process requests second.
  9. Click << to move the profile to the Enabled list.
  10. In the Default Pool drop-down menu, select the appropriate server pool
  11. To save the virtual server, click Finished.

Note: Modify other virtual server settings as necessary to support your application.

Request Processing

The high-level sequence of events for request processing through both virtual servers is as follows:

  • The client sends a request to the first virtual server that has the first security policy applied.
  • The security policy applied to the first virtual server processes the request.
  • If the first policy does not block the request, the iRule applied to the first virtual server forwards the request to the second virtual server.
  • The second security policy applied to the second virtual server processes the request.
  • If the second policy does not block the request, the second virtual server forwards the request to the origin server.

Note: Depending on the security policy configuration, each request may be processed and logged twice. As a result, performance may be negatively impacted.
