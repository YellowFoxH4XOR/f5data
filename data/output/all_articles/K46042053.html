Known Issue

The BIG-IP SSL profile response to a client certificate request causes the TLS handshake to fail.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system attempts to connect to a destination server using Transport Layer Security (TLS) and a BIG-IP Server SSL profile.
  • The destination server is configured with TLS 1.2.
  • The destination server sends a client authentication certificate request with the Signature Hash Algorithms set to SHA256.
  • The BIG-IP Server SSL profile advanced configuration setting for SSL sign hash is set to ANY or SHA256.

Impact

The TLS handshake to the destination server fails.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • If the BIG-IP server SSL profile advanced configuration setting SSL sign hash is set to ANY, the BIG-IP system responds to the destination server Certificate Request with a Certificate Verify message containing the signature signed with SHA1.
  • If the BIG-IP server SSL profile advanced configuration setting SSL sign hash is set to SHA256, the follow occurs:
    • The BIG-IP system stops the session without sending the Certificate Verify message.
    • The BIG-IP system logs a message similar to the following example to the /var/log/ltm file:

      warning tmm1[]: 01260009:4: Connection error: ssl_hs_rsaprivenc:8428: no shared hash algorithm (40)
