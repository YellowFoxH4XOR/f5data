Known Issue

BIG-IP AAM Web Application policy modifications may not persist after you save them.

This issue occurs when all of the following conditions are met:

  • You create a copy of a pre-defined acceleration policy.
  • You make one of the following changes to the created policy:

    • You modify the Path matching rule for the Site node.
    • You modify the Description field of an invalidation trigger for a policy leaf node after creating a Request Header Matching Criteria or Cached Content to Invalidate parameter.

Impact

Administrators are unable to make changes to certain parts of the Web Application policy.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP AAM Configuration utility appears to have successfully saved changes to the Web Application policy, but the changes do not appear.
  • In the /var/log/ltm file, you may observe messages that the BIG-IP AAM system generates, similar to the following example:

    err mcpd[<PID>]: 01070734:3: Configuration error: Policy "/Common/Drafts/<policy_name>", node "Site", matching rule "path:Path": Must have at most one value.
