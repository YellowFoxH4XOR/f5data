K000135112: ssh-keygen for non-root user requires -f parameter

Type
Support Solution
Published
2023-06-23
Updated
2023-06-23
Source
https://my.f5.com/manage/s/article/K000135112

Description

Using ssh-keygen by non-root user might not create private and public key in his home directory.
 

Environment

Big-IP CLI
 

Cause

ssh-keygen is using getuid() system call to identify user's UID and corresponding home directory. If non-root user executes it private and public key is going to be created in /root directory.

john@hostname:Active:Standalone] ~ # echo $USER && echo $HOME && id && ssh-keygen
john
/home/john
uid=0(root) gid=500(webusers) groups=500(webusers),996(sdm) context=unconfined_u:unconfined_r:unconfined_t:s0-s0:c0.c1023
Generating public/private rsa key pair.
Enter file in which to save the key (/root/.ssh/id_rsa

Recommended Actions

In order to create private and public key in correct directory you need to specify exact path with -f

[john@hostname:Active:Standalone] ~ # mkdir /home/john/.ssh
[john@hostname:Active:Standalone] ~ # ssh-keygen -f /home/john/.ssh/id_rsa
Generating public/private rsa key pair.
Enter passphrase (empty for no passphrase): 
Enter same passphrase again: 
Your identification has been saved in /home/john/.ssh/id_rsa.

[john@hostname:Active:Standalone] ~ # chmod -R 600 /home/john/.ssh/
