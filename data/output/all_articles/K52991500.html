Description

You observe a strange java process executing each 5 minutes under the datasyncd main process.

This process keeps doing the same each 5 minutes and seems to repeat indefinitely.

This happened shortly after an upgrade.

Environment

  • BIG-IP ASM or BIG-IP FPS
  • High CPU
  • After upgrade

Cause

The observed behavior is expected and an overview is provided in:

  • K02827102: BIG-IP ASM and BIG-IP FPS systems experience higher CPU usage for several hours per day

This java process is spawned by datasyncd through a bash script. It's expected that it runs multiple times during the obfuscation period.

It requires a set number of cycles so it doesn't always take two to four hours. It depends on the platform and the overall CPU utilization.

If you observe that this process is not obeying the configured obfuscation hours immediately after an upgrade, this is also expected.

datasyncd has a set number of rows (versions of obfuscation) that it will generate, with the max being 1001. After an upgrade, versions must be generated anew and the obfuscator runs continually until one of the following conditions occurs:

  1. 30 minutes prior to the scheduled daily start time.

  2. X versions/rows of obfuscated JavaScript have been generated, where X is the minimum between 1001 and the value of:

    tmsh list security datasync local-profile cs-asm-dosl7 max-gen-rows

  3. Provisioned memory dedicated for obfuscation (based on memory available on the system) has been exhausted - at this point the max-gen-rows from 2. is automatically updated so that we don't attempt to create more versions. Note that this value likely won't be anywhere near 1001.

The max of 1001 rows is derived from:

tmsh list security datasync global-profile /Common/datasync-global/datasync-global-profile-cs-asm-dosl7-initial max-rows

So after an upgrade, until the system encounters condition 1 or 3, above, the obfuscator will run constantly.

Recommended Actions

There is no action needed, since this is expected behavior.

The java process is niced at a low priority so impact to other control plane processes, or data plane activities, is not generally expected.

If the datasyncd obfuscator is still behaving unusually after waiting 48 hours or more, open a service request with F5 Support.

Additional Information

You can monitor the datasyncd activity in the log file if desired:

tailf /var/log/datasync/datasyncd.log

Note: This process is quite chatty so don't be alarmed if you see many messages there.

You can also increase the value of security datasync local-profile cs-asm-dosl7 min-cpu-percent if desired, to give the obfuscator fewer opportunities to run. Similarly, you can reduce security datasync local-profile cs-asm-dosl7 max-gen-rows, which reduces the amount of work the obfuscator needs to do, because fewer versions need to be generated. However, for most environments these changes are not recommended as it may make it easier to reverse-engineer the obfuscated JavaScript.
