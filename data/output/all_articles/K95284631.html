K95284631: You May Fail to Change the Max-duration Password Policy for the Secondary Unit

Type
Support Solution
Published
2022-04-14
Updated
2023-06-26
Applies to
  • BIG-IQ
  • BIG-IQ Centralized Management: 8.0.X
Source
https://my.f5.com/manage/s/article/K95284631

Description

Whenever you tried to change the max-duration policy following the K49507549: Configuring a secure password policy for the BIG-IQ system and change the password for your account to make it take effect, you see that it will be reverted back to the default value like the below on the Secondary Unit:
# chage -l <username>
Last password change                                    : Apr 14, 2022
Password expires                                        : never
Password inactive                                       : never
Account expires                                         : never
Minimum number of days between password change          : 0
Maximum number of days between password change          : 99999
Number of days of warning before password expires       : 7

Environment

  • BIG-IQ HA
  • Max Duration Password Policy
  • Remote Auth Provider (RADIUS, TACACS, etc) is configured

Cause

The underlying TMOS module in the BIG-IQ HA system has a bug: Bug ID 1091989: The local password policy max-duration does not work for local users when external auth in use.

Recommended Actions

As the max duration policy application on Primary is working well and the change on the password can be synced to the Secondary unit, it only has a limited impact on your system and file sync. If you want to keep track of the bug ID fix status, please refer to the bug ID page: Bug ID 1091989: The local password policy max-duration does not work for local users when external auth in use.
