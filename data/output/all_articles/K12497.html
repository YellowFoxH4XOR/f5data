Known Issue

This is the result of a known issue. The High Speed Logging feature may be disrupted and fail to resume if all of the log server pool members go down.

Note: For information about the High Speed Logging feature and how to configure its use within an iRule, refer to the following DevCentral article. A separate DevCentral login is required to access this content; you will be redirected to authenticate or register (if necessary):

https://devcentral.f5.com/wiki/iRules.HSL.ashx

This issue only affects the High Speed Logging feature if TCP is used for communication. If all the members of a configured log server pool go down and the High Speed Logging feature is configured to use TCP, the feature may be disrupted and fail to resume sending TCP log data when any of the members of the log server pool return to an active and up status.

F5 Product Development is tracking this issue as ID 344675.

Workaround

To prevent this behavior from occurring, F5 recommends using UDP instead of TCP as the communication protocol.
