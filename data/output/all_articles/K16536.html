Known Issue

Deleting a Federal Information Processing Standards (FIPS) protected Secure Socket Layer (SSL) key is not prevented when the key name is longer than 32 characters.

Note: Beginning in BIG-IP 11.4.0, deleting a FIPS-protected SSL Key should be prevented when the SSL key exists in the BIG-IP configuration.

This issue occurs when all of the following conditions are met:

  • You have a BIG-IP system that has a FIPS device installed to protect SSL keys.
  • You have created a FIPS-protected SSL key with a name longer than 32 characters.
  • The FIPS-protected SSL Key exists in the BIG-IP configuration. For example, a client SSL profile references the SSL key.
  • You delete the FIPS-protected SSL Key by handle using the Traffic Management Shell (tmsh).

    For example:

    tmsh delete sys crypto fips by-handle <key_handle_number>

Impact

The FIPS-protected key is deleted from the FIPS device, but remains in the BIG-IP configuration. This causes connection failures if the key is mistakenly selected for use.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • SSL connections to the BIG-IP system are failing.

Workaround

There is no workaround for this issue. To avoid this issue, avoid creating FIPS keys with names longer than 32 characters.
