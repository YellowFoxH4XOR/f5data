Topic

This article applies to BIG-IP 11.x - 17.x. For information about other versions, refer to the following article:

  • K11723: Filtering log messages sent to remote syslog servers (9.4.x - 10.x)

You should consider using this procedure under the following condition:

  • You want to filter the log messages sent to remote syslog servers.

Description

The default syslog levels defined for the BIG-IP system logs apply to only local logs; the syslog levels do not apply to remote syslog servers that were defined using the TMOS Shell (tmsh)  modify /sys syslog remote-servers command. For example, if your syslog configuration contains a remote-servers statement, the system sends all syslog logging to the remote server; this will be done before filters are applied, so remote-servers in a filter will not be used. A remote-servers statement appears similar to the following example:

tmsh list /sys syslog remote-servers

sys syslog {
    remote-servers {
        server {
            host 10.11.16.253
        }
    }
}

 

The following table provides a list of the available facilities and their default values.

FacilityDescription
auth-priv-fromSpecifies the lowest level of security/authorization messages to include in the log.
The default value is notice.
auth-priv-toSpecifies the highest level of security/authorization messages to include in the log.
The default value is emerg.
cron-fromSpecifies the lowest level of messages about time-based scheduling to include in the system log.
The default value is warning.
cron-toSpecifies the highest level of messages about time-based scheduling to include in the system log.
The default value is emerg.

The default value is notice.
daemon-toSpecifies the highest level of messages about daemon performance to include in the system log.
The default value is emerg.
kern-fromSpecifies the lowest level of kernel messages to include in the system log.
The default value is debug.
kern-toSpecifies the highest level of kernel messages to include in the system log.
The default value is emerg.
local6-fromSpecifies the lowest error level for messages from the local6 facility to include in the log.
The default value is notice.
local6-toSpecifies the highest error level for messages from the local6 facility to include in the log.
The default value is emerg.
mail-fromSpecifies the lowest level of maillog messages to include in the system log.
The default value is notice.

The following table describes the levels available for each facility. The levels are listed in order of the severity of the messages they handle. Generally, higher levels contain all the messages for lower levels. For example, the alert level generally also reports all messages from the emerg level, and the debug level generally reports all messages for all levels.

LevelDescriptionVerbosity
emergEmergency system panic messagesMinimum
alertSerious errors that require administrator interventionLow
critCritical errors, including hardware and filesystem failuresLow
errNon-critical, but possibly very important, error messagesLow
warningWarning messages that should at least be logged for reviewMedium
noticeMessages that contain useful information, but may be ignoredMedium
infoMessages that contain useful information, but may be ignoredHigh
debugMessages that are only necessary for troubleshootingMaximum

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have administrator access to tmsh.
  • You have some knowledge of syslog filtering rules.
  • You are able to use the vi text editor.

Procedures

If you want to filter the log messages that the system sent to remote syslog servers, you must first remove the remote-servers statement and then configure a syslog include statement that defines a filter rule and the remote server. To do so, perform the following tasks:

Removing the remote-servers syslog statement (if defined)

If you previously defined a remote syslog server using the tmsh modify /sys syslog remote-servers command, you must remove the remote-servers statement before you define the filter rule. To remove the remote-servers statement, perform the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the TMOS Shell (tmsh) by entering the following command: 
    tmsh
  2. To remove the currently defined remote syslog servers, enter the following command: 
    modify /sys syslog remote-servers none
  3. Save the change by entering the following command: 
    save sys config

Defining a syslog filter rule that references the remote server

To define the desired syslog filter that references the remote server, perform the following procedure:

Note: Modifications to the syslog configuration properties that are made by using this procedure may not be reflected in the Configuration utility.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command: 
    tmsh
  2. To define the desired syslog filter that references the remote server, enter the following command: 
    edit /sys syslog all-properties

    The syslog configuration opens in the vi text editor and appears similar to the following example:

    modify syslog {
    auth-priv-from notice
    auth-priv-to emerg
    cron-from warning
    cron-to emerg
    daemon-from notice
    daemon-to emerg
    description none
    include none
    iso-date disabled
    kern-from notice
    kern-to emerg
    mail-from notice
    mail-to emerg
    messages-from notice
    messages-to warning
    remote-servers none
    user-log-from notice
    user-log-to emerg
}

    Refer to the table in the Description section on the function of each facility, as well as its default value. If you require advanced syslog filter, refer to the next step.
     

  3. Replace the include none line with the desired syslog filter.

    For example, to configure syslog-ng to log a warning through emergency log level messages to TCP port 1468 on 10.11.16.253 and to UDP port 514 on 10.11.16.252, use the following syntax:

    include "
filter f_remote_loghost {
level(warning..emerg);
};

destination d_remote_loghost {
tcp(\"10.11.16.253\" port(1468));
udp(\"10.11.16.252\" port(514));
};

log {
source(s_syslog_pipe);
filter(f_remote_loghost);
destination(d_remote_loghost);
};
"

    After adding the previous filter rule, the syslog configuration appears similar to the following example:

    modify syslog {
    auth-priv-from notice
    auth-priv-to emerg
    cron-from warning
    cron-to emerg
    daemon-from notice
    daemon-to emerg
    description none
    include "
    filter f_remote_loghost {
        level(warning..emerg);
    };

    destination d_remote_loghost {
        tcp(\"10.11.16.253\" port(1468));
        udp(\"10.11.16.252\" port(514));
    };

    log {
        source(s_syslog_pipe);
        filter(f_remote_loghost);
        destination(d_remote_loghost);
    };
    "
    iso-date disabled
    kern-from notice
    kern-to emerg
    mail-from notice
    mail-to emerg
    messages-from notice
    messages-to warning
    remote-servers none
    user-log-from notice
    user-log-to emerg
}

    Important: You should use this parameter with caution. The system does not validate the configuration used with the include parameter. If you use this parameter incorrectly, the BIG-IP syslog may fail to function. F5 recommends that you test this in an appropriate environment before implementing in a production environment.

  4. Exit the text editor by entering the following key sequence: 
    :wq!
  5. At the following prompt, press y to save the changes to the file: 
    Save changes? (y/n/e)

    The tmsh prompt returns.

    Note: If the syslog filter contained syntax errors, tmsh returns the following prompt:

    There were errors. Continue editing (y) or discard changes (n) (y/n)

    The BIG-IP system now sends syslog traffic to the remote server using the defined syslog filter.
     

  6. Save the configuration by entering the following command: 
    save /sys config

     

Note: It may be necessary to restart the syslog-ng service, run the following command from bash:

bigstart restart syslog-ng


Note: To remove the remote syslog server and filter configuration, run the following command from tmsh:

modify /sys syslog include none
