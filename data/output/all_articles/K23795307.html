Description

You want to add a new blade or replace an existing blade in a VIPRION system that has multiple blades installed.

Environment

  • Viprion chassis with multiple blades
  • Adding a new additional blade
  • RMA an existing blade.

Cause

  • Adding a new additional blade
  • RMA an existing blade

Recommended Actions

  1. When adding a new blade: Insert the new blade in an open slot and wait for the new blade to come up properly.
  2. When replacing a blade because of an RMA:
    • Insert the RMA blade in the same slot and wait for the new blade to come up properly.
    • If you have vCMP guests associated to multiple blades, the working blade will copy the vCMP guest configuration to the RMA blade in the same slot.

For both scenarios above, if you have upgraded from a previous version. Ensure you have the previous version ISO(s) files on the good blade so the new blade can be upgraded if needed.

  • When inserting the RMA or new blade, the existing working blade will automatically try installing the original .iso(s) for the equipment referred to as "initial-image" with some initial configuration to the new blade.
    • *Important: the initial-image required .iso(s) may be old and no longer used by the previously installed blade, but the system will require their presence because it defaults to the "initial-image" state on bring-up.
  • For example, if the guest was once loaded with version 12.x but upgraded to 13.x you will need to have the 12.x ISO on the working blade so it can try to upgrade the RMA or new blade from 12.x to 13.x.
  • You can run the command below on the host system to find out which .iso(s) are needed to bring up the guest.
    • tmsh list /vcmp guest all-properties | grep "initial-image"
  • After the iso(s) are installed and the blade is able to boot up, if it does not match the expected configuration (Big-IP version or settings, refer to the procedures below for installing the correct Big-IP version to the guest and using the .ucs archive to reload the last saved settings)
    • Update or upgrade BIG-IP VIPRION systems (vCMP) | BIG-IP update and upgrade guide (f5.com)
    • Backing up and restoring BIG-IP configuration files with a UCS archive (f5.com)

Note the Following:

  • The newly inserted blade may take 20 minutes or more to become fully functional because it needs to copy the software and configuration.
  • The BIG-IP system may reboot the newly added blade multiple times to install required software and/or firmware.
  • Ensure that the blades in the system are all the same model (see K03544041: Support for mixing blade types within a VIPRION chassis for more information).
  • If the current primary blade only has one volume created, you may need to create a second volume and install software onto the volume so that the new blade can upgrade properly. The new blade may need to boot into a different partition while it performs upgrades to the primary boot slot of the new blade.
  • If the newly inserted blade was inserted into an administratively disabled slot, the configuration copied from the primary blade will continue to indicate the slot as down. The Traffic Management Microkernel (TMM) will not enable interfaces or process traffic on the newly inserted blade until the slot is enabled.
  • BIG-IP 11.5.0 and later supports direct upgrades to point release software. (K13845: Overview of supported BIG-IP upgrade paths and an upgrade planning reference)

You can monitor the newly added blade status using the following command: 

watch -n 1 "tmsh show sys cluster"

This watch command will run "tmsh show sys cluster" every 1 second to monitor the status of the new blade and should be ran from the bash shell. Please give the new blade time to complete loading properly which can take over 20 mins to complete. (K07557518: VIPRION cluster shell utility(clsh) commands)

 

Additional Information

While there should be no traffic disruption when inserting new blade, it is expected this is performed during a maintenance window to avoid running into any race condition that could impact traffic.
