Known Issue

This is the result of a known issue. If you create a protected configuration custom check that contains a greater than (>), greater than or equal to (>=), less than (<), or less than or equal to (<=) operator, users fail the custom check even if they meet the defined criteria.

For example, users will fail the following protected configuration custom checks even if they meet the defined criteria:

session.av.McAfeeAV.database_age<5
session.av.McAfeeAV.database_age<=5
session.fw.summary.count>0
session.fw.summary.count>=1

A protected configuration is a collection of safety measures or checks that guard the connection and client system against various kinds of attacks or threats. A protected configuration custom check allows FirePass administrators to define a customized check based on information collected by a pre-logon sequence. Protected configurations are configured on the Users: Endpoint Security: Protected Configurations page. For more information about protected configurations, refer to the FirePass Controller Administrator Guide.

F5 Product Development tracked this issue as CR86859 and it was fixed in FirePass version 6.0.3. For information about upgrading, refer to the FirePass release notes.

This issue still exists in the FirePass version 5.x branch.

Additionally, cumulative hotfix HF-601-9 has been issued for FirePass version 6.0.1 and cumulative hotfix HF-602-1 has been issued for FirePass version 6.0.2. You may download these hotfixes or later versions of the cumulative hotfixes from the F5 Downloads site.

For instructions about obtaining a hotfix, refer to K167: Downloading software from F5.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.

Workaround

You can work around this issue by replacing the greater than (>, >=) or less than (<, <=) operators with the equal to (==) or not equal to (!=) operators in your protected configuration custom checks. If the custom check expression cannot be rewritten with the equal to (==) or not equal to (!=) operators, you can work around this issue by deleting the custom check.

Editing a protected configuration custom check

  1. Log on to the FirePass Administrative Console.
  2. Navigate to the Users: Endpoint Security: Protected Configurations page.
  3. Click the name of the protected configuration you want to configure.
  4. Click the Protection Criteria tab.
  5. Click the tab under which your custom check is defined. For example:

    Unauthorized Access

  6. Next to custom check, click the I icon to open the edit pane.
  7. In the custom check expression text field, enter the new expression.
  8. Click the Save button.

    This action returns you to the Protected Endpoint Configuration page.

  9. At the bottom of the Protected Endpoint Configuration page, click the Save button to save the change.


Deleting a protected configuration custom check

  1. Log on to the FirePass Administrative Console.
  2. Navigate to the Users: Endpoint Security: Protected Configurations page.
  3. Click the name of the Protected Configuration you want to configure.
  4. Click the Protection Criteria tab.
  5. Click the tab under which your custom check is defined. For example:

    Unauthorized Access

  6. Next to Custom Check, click the X icon to delete the custom check.
  7. At the bottom of the page, click the Save button to save the change.
