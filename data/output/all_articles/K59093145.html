Description

When discovering a BIG-IP ASM system, the BIG-IQ returns an error message:

Error while transforming objects in bulk: ASM Policy - Url in <affected_policy_ID>, message 'cannot convert contentProfile: https://localhost/mgmt/tm/asm/policies/<policy_ID>/json-profiles/<profile_ID>?ver=16.1.0' was returned

Environment

  • BIG-IQ
  • an attempt to discover ASM configuration on the BIG-IQ
  • BIG-IP ASM

Cause

When an Application Security Policy was created based on the other Application Security Policy (or cloned), the URL content profile incorrectly references the URL's content profile from the parent/template policy.

Recommended Actions

Find the affected policy, and re-create the problematic content profile.
 
1. Let's assume you get the following error message:
 
Error while transforming objects in bulk: ASM Policy - Url in cFGNG08sgwxdOGXCYSlGA8g, message 'cannot convert contentProfile: https://localhost/mgmt/tm/asm/policies/aFSGSAtmdOGXCGSAWXsarg/json-profiles/X284F8VWJ5Tohv82YHDa?ver=16.1.0' was returned

where "cFGNG08sgwxdOGXCYSlGA8g" is <affected_policy_ID>
 
2. Identity which Application Policy is affected. Run the following command in the BIG-IP ASM system you want to discover:
 
restcurl -u admin:admin /mgmt/tm/asm/policies\?\$select=name,selfLink | grep <affected_policy_ID> -C 2
 
Example:
 
restcurl -u admin:admin /mgmt/tm/asm/policies\?\$select=name,selfLink | grep cFGNG08sgwxdOGXCYSlGA8g -C 2

    {
      "kind": "tm:asm:policies:policystate",
      "selfLink": "https://localhost/mgmt/tm/asm/policies/cFGNG08sgwxdOGXCYSlGA8g?ver\u003d16.1.2",
      "name": "name_of_the_policy" <-------- !!!! name of the affected policy
    },
 
3. The error message informs that the affected content profile belongs to "json-profiles" family. Run the following command to find the affected URL, to which the problematic content profile is attached:

restcurl -u admin:admin /mgmt/tm/asm/policies/<affected_policy_ID>/urls/ | grep 'json-profiles' | grep -v "<affected_policy_ID>"

Example:
 
restcurl -u admin:admin /mgmt/tm/asm/policies/cFGNG08sgwxdOGXCYSlGA8g/urls/ | grep 'json-profiles' | grep -v "cFGNG08sgwxdOGXCYSlGA8g"
 
  NOTE: The output shows a completely different reference to the Application Policy ID. This is the problematic Application Policy ID:

            "link": "https://localhost/mgmt/tm/asm/policies/aFSGSAtmdOGXCGSAWXsarg/json-profiles/X284F8VWJ5Tohv82YHDa?ver\u003d16.1.2", <
            
where "aFSGSAtmdOGXCGSAWXsarg" is <erroneous_policy_id_reference>

If no output is shown, you are probably not experiencing the behavior explained in this article. 
 
4.  Identify the name of URL associated with erroeus 
 
restcurl -u admin:admin /mgmt/tm/asm/policies/<affected_policy_id>/urls/ | grep -E 'link|name' | grep <erroneous_policy_id_reference> -C2

Example:
 
restcurl -u admin:admin /mgmt/tm/asm/policies/cFGNG08sgwxdOGXCYSlGA8g/urls/ | grep -E 'link|name' | grep aFSGSAtmdOGXCGSAWXsarg -C2
 
  "name": "<AFFECTED_URL_NAME>",
        "link": "https://localhost/mgmt/tm/asm/policies/aFSGSAtmdOGXCGSAWXsarg/urls/A2_1VXNSMsst976IesTz1g/parameters?ver\u003d16.1.2",
            "link": "https://localhost/mgmt/tm/asm/policies/aFSGSAtmdOGXCGSAWXsarg/json-profiles/X8FbXF48VWJ5Tecp5ATd4A?ver\u003d16.1.2",
            "name": "Default"
            "link": "https://localhost/mgmt/tm/asm/policies/aFSGSAtmdOGXCGSAWXsarg/xml-profiles/jwQd_XYZPfNGYnc3l7P4Pg?ver\u003d16.1.2",
 
5. Once the name of affected URL has been identified, you can now just re-add the affected content profiles in the URL configuration.
 
Note: In the above scenario, only json-profiles have been reported by the error message, but other content profiles like xml-profiles might be affected as well.
 
  • Go to the allowed URLs of the policy identified in step 2, and locate the affected URL (identified in step 4).
  • Select "advanced" from the list and go to "Header-Based Content Profiles".
  • Delete XML (or | and) JSON profiles from the list.
  • Recreate the profiles using the same values as earlier :
Example:
 
"Content-Type": "*xml*" >> XML
"Content-Type": "*json*" >> JSON
 

Alternatively, you can use the following iControl REST command syntax to fix the affected URLs from the CLI of the ASM.

curl -sku <username>:<password> -H "Content-Type:application/json" https://localhost/mgmt/tm/asm/policies/<affected policy ID>/urls/<URL ID>?\$select=urlContentProfiles | sed 's/<erroneous policy ID>/<affected policy ID>/g' | curl -sku admin:admin -H "Content-Type:application/json" -X PATCH https://localhost/mgmt/tm/asm/policies/<affected policy ID>/urls/<URL ID> -d @-  

In the previous syntax, note the following:

  • curl -sku <username>:<password> -H "Content-Type:application/json" https://localhost/mgmt/tm/asm/policies/<affected policy ID>/urls/<URL ID>?\$select=urlContentProfiles
    This is an iControl REST command that outputs only the content profiles section of the URL configuration object.
  • | sed 's/<erroneous policy ID>/<affected policy ID>/g'
    A pipe operator directs the content profile output to a sed command where all instances of the erroneous policy ID are replaced with the correct policy ID.
  • | curl -sku admin:admin -H "Content-Type:application/json" -X PATCH https://localhost/mgmt/tm/asm/policies/<affected policy ID>/urls/<URL ID> -d @-
    The pipe operator directs the edited content profile output to an iControl REST PATCH command to update the URL content policy configuration. The -d @- reads the content profile output and uses it as the PATCH data for the command. PATCH overwrites the content policy configuration with the new correct configuration so no other changes need to be made to the URL.

For example:

curl -sku admin:admin -H "Content-Type:application/json" https://localhost/mgmt/tm/asm/policies/R5ygGoer8BWZQnMW7PCcXA/urls/N_a3D1S7OKDehYEPb-mgCg?\$select=urlContentProfiles | sed 's/8NL-KHdDxEZqmIW9w2aNUA/R5ygGoer8BWZQnMW7PCcXA/g' | curl -sku admin:admin -H "Content-Type:application/json" -X PATCH https://localhost/mgmt/tm/asm/policies/R5ygGoer8BWZQnMW7PCcXA/urls/N_a3D1S7OKDehYEPb-mgCg -d @-  

Once you have completed fixing all the URLs, apply the policy with the following command syntax:

curl -sku <username:password> https://localhost/mgmt/tm/asm/tasks/apply-policy | jq '.'

For more information about configuring the ASM with iControl REST, refer to K18432457: Display and configure BIG-IP ASM security policy configuration using iControl Rest API.

6. When the above steps are done, apply policy and try to re-discover and re-import configuration on the BIG-IQ.
