K000133299: Clickhouse pod's container is not coming up and corrupt nfs data is suspected

Description

Upon startup, the container for the clickhouse pod does not come up

Environment

NGINX Controller

Cause

This could be a result of corrupt nfs data

Recommended Actions

Backup and remove nfs data

1. Scale down clickhouse

kubectl scale sts clickhouse --replicas=0

2. Remove data from nfs shared folder

  • Confirm path of nfs data share directory
  • Backup nfs data share folder
  • Remove all data from nfs data shared folder
  • Example 
    • From controller
    $ kubectl get pv clickhouse -oyaml | grep "nfs:" -A1
  nfs:
    path: /mnt/nfs_share/nfs_tsdb
    • From nfs
    [/mnt/nfs_share]$ sudo tar cvzf /tmp/nfs_tsdb_2.tar.gz nfs_tsdb
[/mnt/nfs_share]$ sudo rm -rf nfs_tsdb/*

3. Scale up clickhouse

kubectl scale sts clickhouse --replicas=1

Note: The Clickhouse pod will create the necessary folder and data structure within the empty nfs share folder

4. If Clickhouse and other pod/services come up healthy, recreate the Clickhouse database and tables with these two commands:

kubectl set env sts clickhouse CH_PASS=$(kubectl get $(kubectl get secret -oname | grep clickhouse-secret) -o json | jq -r .data.CLICKHOUSE_PASS_writer | base64 -d) CH_USER=writer CH_HOST=$(kubectl get $(kubectl get svc -oname clickhouse) -o json | jq -r .spec.clusterIP) CH_PORT=9000 CH_DB=controller SKIP_DEFAULT_OPS=false
kubectl exec -it clickhouse-0 -- sh -c '/clickhouse-init/migrate.sh'
