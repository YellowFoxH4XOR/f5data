K000161161: Understanding BIG-IP LTM Behavior: Advertised MSS increased by 12 bytes when TCP timestamps are enabled on serverside

Type
Support Solution
Published
2026-05-07
Updated
2026-05-07
Applies to
  • BIG-IP
  • BIG-IP SSL Orchestrator: 17.1.3
Source
https://my.f5.com/manage/s/article/K000161161

Description

When using BIG-IP LTM, the Maximum Segment Size (MSS) advertised from BIG-IP to the backend server may be 12 bytes higher than the MSS advertised by the client to BIG-IP. This occurs when the client does not use the TCP timestamp option, but the server-side TCP profile on BIG-IP has TCP timestamps enabled. For example, if a client sends a SYN with an MSS of 1098 and no TCP timestamp, BIG-IP may send a SYN to the server with an MSS of 1110 and include the TCP timestamp option. This behavior is by design and aligns with how BIG-IP manages TCP options and payload alignment between client and server connections.

Environment

  • Product: BIG-IP LTM
  • Version: 17.1.3
  • TCP Profiles:
    • proxy-mss enabled on both client and server TCP profiles
    • proxy-options disabled
    • TCP timestamps enabled on server-side TCP profile
    • Client-side connection does not use TCP timestamps

Cause

When TCP timestamps are enabled on the server-side but not present on the client-side, BIG-IP increases the advertised MSS by 12 bytes on the server-side SYN. This is to align the maximum TCP payload size between client and server connections, accounting for the 12-byte TCP timestamp option that will be present in the server-side packets.

Answer/Recommended Actions

  • This behavior is expected and by design. The backend server, upon seeing TCP timestamps in use, will reduce the maximum payload size by 12 bytes (the size of the TCP timestamp option) when sending data, ensuring that the actual payload matches the client-side MSS.
  • No action is required if this behavior is acceptable for your deployment.
  • If you want to prevent the MSS from being increased by 12 bytes on the server-side, disable the TCP timestamp option in the server-side TCP profile on BIG-IP.

Additional Information

  • According to RFC 6691, the MSS value in the TCP option should be calculated by subtracting only the size of the fixed IP and TCP headers from the MTU, not accounting for TCP options like timestamps. The sender must reduce the TCP data length to account for any options it includes. From RFC6691:
    "2.  The Short Statement
     
       When calculating the value to put in the TCP MSS option, the MTU
       value SHOULD be decreased by only the size of the fixed IP and TCP
       headers and SHOULD NOT be decreased to account for any possible IP or
       TCP options; conversely, the sender MUST reduce the TCP data length
       to account for any IP or TCP options that it is including in the
       packets that it sends."
  • Even if the server-side MSS is higher, the server will send payloads matching the client-side MSS when TCP timestamps are in use.
  • This behavior helps avoid fragmentation and ensures consistent payload sizes across asymmetric TCP connections.
