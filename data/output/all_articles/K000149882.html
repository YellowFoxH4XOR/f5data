K000149882: Snmpd may crash and generate core file while frequently modifying auth|privacy-password of SNMPv3 trap configuration.

Type
Support Solution
Published
2025-02-20
Updated
2025-02-20
Applies to

  • BIG-IP LTM: 16.0.0, 16.0.X, 16.0.1, 17.X.X, 16.X.X, 17.1.X, 17.1.2, 17.1.1, 17.1.0, 17.0.X, 17.0.0, 16.1.X, 16.1.5, 16.1.4, 16.1.3, 16.1.2, 16.1.1, 16.1.0
Source
https://my.f5.com/manage/s/article/K000149882

Description

Snmpd may suddenly crash and generate core file. The /var/log/daemon.log log file will have similar messages as shown below.

Feb 20 10:35:21 bigip.local err snmpd[9689]: Can't register new trap destination: max limit reached: 1024
Feb 20 10:35:22 bigip.local err sflow_agent[5614]: unknown snmp version 193
Feb 20 10:35:23 bigip.local emerg logger[29278]: Re-starting snmpd
Feb 20 10:35:37 bigip.local err sflow_agent[5614]: unknown snmp version 193

 

Environment

  • SNMPv3 auth|privacy-password was updated many times.

Note: In one example, the problem locally reproduced when there were four SNMPv3 trap destinations configured and auth|privacy-password of each trap destination was updated by more than 250 times without manually restarting snmpd.

Cause

Bug ID 954433.

 

Recommended Actions

No fix code available at the time of article publication. Snmpd will automatically get back to online after crash, and snmpd crash should not impact TMM traffic processing. Therefore, user will not have to take any additional actions urgently.

 

Additional Information

None.
