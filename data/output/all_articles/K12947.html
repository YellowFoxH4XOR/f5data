Known Issue

The rate class feature does not honor a Burst Size setting other than the default of 0 (zero).

When using a non-default Burst Size setting for a single rate class, the setting does not have the intended effect of allowing traffic to burst beyond the base rate configured for the rate class. When using a non-default Burst Size setting for a rate class referencing a hierarchical rate class (a child class referencing a parent class), traffic processed by the rate class may cause the Traffic Management Microkernel (TMM) to panic and generate a core file.

The Burst Size setting is intended to specify the maximum number of bytes that traffic is allowed to burst beyond the base rate configured for the rate class. When the burst rate is set to zero, no bursting is allowed.

Impact

Traffic does not burst beyond the base rate configured for the rate class. In the case of hierarchical rate classes, the BIG-IP system may temporarily fail to process traffic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • F5 iHealth lists Heuristic H581873 on the Diagnostic > Identified > Medium page. 
  • Your BIG-IP system does not allow traffic to burst beyond the base rate for the rate class.
  • Your BIG-IP system sends a SIGFPE signal to TMM, resulting in a core file.
  • The system generates an assertion failure panic string in the /var/log/tmm file that appears similar to the following example:

    notice panic: ../net/rate_shaper.c:601: Assertion "bursted <= plen" failed

Workaround

To work around this issue, you can disable the Burst Size setting by changing the value to 0 (zero). To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to Network > Rate Shaping.
  3. Click the appropriate rate class.
  4. Change the Burst Size to 0 (zero).
  5. Click Update.
