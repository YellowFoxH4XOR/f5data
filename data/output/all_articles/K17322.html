Known Issue

The Traffic Management Microkernel (TMM) may restart when the BIG-IP system is configured to use high-speed logging (HSL), and a high availability (HA) failover event occurs.

This issue occurs when all of the following conditions are met:

  • You have configured the BIG-IP system to use remote HSL.
  • The BIG-IP system is unable to connect to the remote logging server.
  • The Primary HA member experiences a failover event, and the subsequent TMM restarts.

Impact

TMM may restart and produce a core file.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system fails over to another host in the device group.
  • TMM generates a core file in the /var/core directory.

Workaround

To work around this issue, you can create a log filter specifically for message-id 1010235. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Navigate to System > Logs > Configuration > Log Filters.
  3. Click Create.
  4. In the Name box, type a unique name for this filter.
  5. From the Severity list, select Critical.
  6. From the Source list, select tmm.
  7. In the Message ID box, type 1010235.
  8. From the Log Publisher list, select None, or a custom publisher that logs to local-syslog.
  9. Click Finished.
