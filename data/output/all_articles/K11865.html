Known Issue

This is the result of a known issue. When an NFS client creates a hard link on an ARX direct volume that references a share that is a managed volume, the ARX system will respond with the an incorrect file ID. As a result, the client system may generate a dmesg entry that appears similar to the following example:

NFS: server hostname error: fileid changed fsid 0:1d: expected fileid 0x10190dd, got 0x190dd

Client access to the hard link is not affected and will function as expected.

F5 Product Development tracked this issue as ID 35763 and it was fixed in ARX 5.1.7. For information about upgrading, refer to the ARX release notes.
