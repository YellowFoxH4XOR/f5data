K000161696: GTM–LTM iQuery SSL Handshake Failure Caused by Incompatible Cipher Configuration

Type
Support Solution
Published
2026-08-26
Updated
2026-08-26
Applies to
  • BIG-IP
  • BIG-IP DNS: 17.5.1
Source
https://my.f5.com/manage/s/article/K000161696

Description

BIG-IP DNS may fail to establish iQuery trust and connectivity with BIG-IP LTM when custom TLS settings exclude cipher suites required by iQuery. GSLB health checks may fail, and Wide IPs may become unavailable.

Common errors include:

  • SSL routines:SSL23_GET_SERVER_HELLO:sslv3 alert handshake failure

  • SSL_ERROR_SYSCALL

  • ssl3_get_client_hello:no shared cipher

  • Cipher is (NONE)

The bigip_add utility may appear to complete successfully while iqdump continues to report an SSL handshake failure or an untrusted device certificate.

Environment

  • BIG-IP DNS and BIG-IP LTM
  • iQuery communication through Self IP addresses
  • Custom TLS and cipher settings configured on BIG-IP DNS and BIG-IP LTM
  • Relevant settings may include:
    • big3d.minimum.tls.version
    • gtm global-settings general iquery-minimum-tls-version
    • big3d.ssl.cipherlist
    • gtm global-settings general ssl-cipher-list

Cause

The custom cipher configuration excluded all RSA-based cipher suites by using !RSA. iQuery SSL communication between the gtmd and big3d processes requires compatible RSA-based cipher suites. Because no common cipher was available, the TLS handshake failed with a no shared cipher error.

This behavior is tracked under Bug ID 936417. A supported cipher configuration that includes compatible RSA-based cipher suites can resolve the issue.

Answer/Recommended Actions

Perform the following actions on the applicable BIG-IP DNS and BIG-IP LTM systems.

  1. Verify that port 22 is permitted on the Self IPs used for iQuery communication and that SSH allow lists permit communication between the systems.
  2. Review the current iQuery and big3d TLS settings:
    tmsh list gtm global-settings general
    tmsh list sys db big3d.minimum.tls.version
    tmsh list sys db big3d.ssl.cipherlist
  3. Revert the iQuery cipher and TLS settings to the supported defaults:
    tmsh modify gtm global-settings general iquery-minimum-tls-version tls1
    tmsh modify gtm global-settings general ssl-cipher-list DEFAULT
    tmsh modify sys db big3d.minimum.tls.version value tls1
    tmsh modify sys db big3d.ssl.cipherlist value DEFAULT
  4. Restart the iQuery services:
    bigstart restart gtmd big3d
  5. Re-establish trust from BIG-IP DNS to the BIG-IP LTM system:
    bigip_add <LTM_Self_IP>
  6. Save the configuration:
    tmsh save sys config
  7. Verify iQuery connectivity:
    iqdump <LTM_Self_IP>
    tmsh show gtm iquery
  8. If security hardening requires a custom cipher list, ensure that it includes cipher suites compatible with iQuery and does not exclude all RSA-based suites. The following cipher list can be used as a starting point:

    AESGCM:AES:!ADH:!AECDH:!PSK:!aECDH:!DSS:!ECDSA:!AES128:-SHA1:AES256-SHA

    Validate custom cipher settings with the security team and test iQuery connectivity after applying them.

Additional Information

  • A valid and unique device certificate does not resolve this condition when the TLS peers cannot negotiate a common cipher.
  • Successful TCP or SSH connectivity does not confirm successful iQuery connectivity. iQuery must complete its SSL/TLS handshake separately.
  • The bigip_add utility uses SSH during certificate exchange; therefore, port 22 and SSH allow-list settings must be correct before trust can be established.
  • Reverting to supported default cipher settings can restore BIG-IP DNS–BIG-IP LTM trust and iQuery connectivity.
  • Security-hardening changes affecting big3d, gtmd, TLS versions, or cipher suites should be tested against iQuery before deployment.
