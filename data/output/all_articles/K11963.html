Issue

When the ARX system is configured to use a Windows 2003 domain controller for authentication, authentication fails for clients who use a read-only domain controller (RODC) and Kerberos authentication. When the ARX system is unable to authenticate, an error message similar to the following example is logged to the syslog file:

:VCIFS-1-ERR-TKTFAIL:: Failed to obtain authentication credentials for host 'host@domain.net' on behalf of principal 'user@domain.net' at IP address 172.10.10.1 to CIFS service 'vip.domain.net'. The Kerberos error message is 'Decrypt integrity check failed' (KRB5KRB_AP_ERR_BAD_INTEGRITY, -1765328353).

This issue occurs because the Windows 2003 domain controller used by the ARX system is unable to authenticate a client presenting a forwardable ticket-granting-ticket (TGT) issued by the RODC. This behavior is an issue on the domain controller, not on the ARX system. For additional information about this issue, refer to the following Microsoft KB article:

http://support.microsoft.com/kb/2360265

Note: This link takes you to a resource outside of AskF5, and it is possible that the information may be removed without our knowledge.

To allow the affected clients to authenticate, you must configure the ARX system to use a Windows 2008 domain controller for authentication. For information about configuring the ARX system to use a Windows 2008 domain controller for authentication, refer to the Preparing for CIFS Authentication section of the ARX Storage Management Guide.
