Topic

You should consider using this procedure under the following condition:

  • Your want your BIG-IP device to advertise the route to a configured SNAT address through dynamic routing.

Description

It can be beneficial to advertise the route to a configured SNAT IP address in deployments in which you use dynamic routing. When you configure a SNAT, the ability to include the SNAT IP address in route advertisements is not available, but you can add the IP address of the SNAT to route advertisements using the underlying virtual address functionality of the BIG-IP system. The following procedures demonstrate how to add, modify or delete a SNAT IP address to the virtual address list.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • Your BIG-IP system is licensed and configured for dynamic routing.
  • You have administrative access to the BIG-IP using the following methods
    • Configuration utility
    • TMOS Shell (tmsh)
    • iControl REST interface

Procedures

  • Enabling SNAT route advertisement using tmsh and the Configuration utility
  • Enabling SNAT route advertisement using tmsh
  • Enabling SNAT route advertisement using the iControl REST interface

Enabling SNAT route advertisement using tmsh and the Configuration utility

The following procedures demonstrate how to create, modify or delete an existing virtual address that shares the same IP address of a configured SNAT.

Impact of procedure: Performing the following procedure adds the selected SNAT IP address to the device route advertisements.

  1. To configure route advertisement for a SNAT you must first create a virtual address that shares the same IP address of the SNAT. You can only create a new virtual address using tmsh. Log in to tmsh by typing the following command:
    tmsh
  2. Enter the following syntax:
    create ltm virtual-address <snat address>
    Note: Replace <snat ip address> with the IP address of the configured SNAT that you want to include in dynamic routing advertisements.
  3. Save the configuration with the following command:
    save sys config
  4. Go to the Configuration utility and navigate to Local Traffic > Virtual Servers > Virtual Address List.
  5. Click the name of the virtual address you created in the previous steps.
  6. Under Configuration, for Availability Calculation or Advertise Route, select Always from the drop down list.
  7. For Route Advertisement, click Always or the setting appropriate for your environment.
  8. Click Update.

Delete an existing virtual address that is shared with a SNAT IP address

If no longer needed, you can delete an existing virtual address that is shared with a SNAT IP address by performing the following steps:

  1. Navigate to Local Traffic > Virtual Servers > Virtual Address List.
  2. Select the check box for the virtual address name.
  3. Click Delete.
  4. Click Delete to confirm.

    Note: When the IP address is in use by a virtual server object the system issues a warning that the virtual address cannot be deleted.

Enabling SNAT route advertisement using tmsh

The following tmsh procedures demonstrate how to create, modify, or delete a virtual address that shares the same IP address of a configured SNAT IP address.

Impact of procedure: Performing the following procedure adds the selected SNAT IP address to the device route advertisements.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. Use the following command syntax to create a new virtual address with route advertisement set to always or replace always with the setting appropriate for your environment:

    create /ltm virtual-address <snat ip address> route-advertisement always server-scope none

    Note: Replace <snat ip address> with the IP address of the configured SNAT that you want to include in dynamic routing advertisements.
    Note: server-scope none sets the Availability Calculation/Advertise Route to always which is necessary to always advertise this IP. server-scope none means that no virtual servers that use this virtual address need to be up for the system to advertise this IP. The system will always advertise it regardless.

    Use the following command syntax to modify an existing virtual address:

    modify /ltm virtual-address <snat ip address> route-advertisement <new setting> server-scope <new setting>

    Note: Replace <snat ip address> with the IP address of the configured SNAT that you want to include in dynamic routing advertisements.

    If no longer needed, use the following command syntax to delete the virtual address:

    delete /ltm virtual-address <snat ip address>

    Note: Replace <snat ip address> with the IP address of the configured SNAT that you want to include in dynamic routing advertisements.

  3. Type the following command to save the changes:

    save /sys config

Enabling SNAT route advertisement using the iControl REST interface

The following iControl REST interface procedures demonstrate how to create, modify, or delete a virtual address that shares the same IP address of a configured SNAT IP address.

Impact of procedure: Performing the following procedure adds the selected SNAT IP address to the device route advertisements.

Note: For the following syntax commands:

  • Replace <username>:<password> with the administrative access username and password.
  • Replace <big-ip ip address> with the management IP address of the intended BIG-IP device.
  • Replace <snat ip address> with the IP address of the SNAT for which you want to enable route advertisements.
  • Replace <partition name> with the name of the partition of the modified configuration.
  1. Use the following iControl REST interface syntax to create a new virtual address (using the SNAT IP address) with route advertisement set to selective.

    curl -sk -u <username>:<password> -H "Content-Type: application/json" -X POST https://<big-ip ip address>/mgmt/tm/ltm/virtual-address/<snat ip address> -d '{"routeAdvertisement":"selective","serverScope":"none"}' | jq -M .

    Use the following iControl REST interface syntax to modify an existing virtual address that shares the same IP address with a configured SNAT with route advertisement set to selective:

    curl -sk -u <username>:<password> -H "Content-Type: application/json" -X PUT https://<big-ip ip address>/mgmt/tm/ltm/virtual-address/<snat ip address> -d '{"routeAdvertisement":"selective","serverScope":"none"}' | jq -M .

    If no longer needed, use the following iControl REST interface syntax to delete an existing virtual address:

    curl -sk -u <username>:<password> -H "Content-Type: application/json" -X DELETE https://<big-ip ip address>/mgmt/tm/ltm/virtual-address/<snat ip address>

    Use the following iControl REST interface command syntax to save the configuration changes to the default partition (Common)

    curl -sk -u <username>:<password> -H "Content-Type: application/json" -X POST https://<big-ip ip address>/mgmt/tm/sys/config -d '{"command":"save"}'

  2. Use the following iControl REST interface syntax to save the configuration for BIG-IP systems configured with multiple partitions (BIG-IP version 13.1.0 and later):

    curl -sk -u <username>:<password> -H "Content-Type: application/json" -X POST https://<big-ip ip address>/mgmt/tm/sys/config -d '{"command":"save","partition":"all"}'

    For versions prior to BIG-IP 13.1.0, you must use the following iControl REST interface syntax to declare the specific partition if the partition is not the default partition (Common):

    curl -sk -u <username>:<password> -H "Content-Type: application/json" -X POST https://<big-ip ip address>/mgmt/tm/sys/config -d '{"command":"save","partition":"<partition name>"}'

    Note: Viewing and creating objects with a REST command can produce verbose JSON output. To format the JSON output to a more user-friendly format, use the jq command line JSON processor command. The jq command -M flag sets the formatted JSON output to use monochrome when displaying the JSON output. The '.' (period) parameter is optional in jq versions 1.5 and later.
