Topic

You should consider using this procedure under the following condition:

  • You are replacing an ARX system.

Description

When F5 dispatches an ARX device as a replacement for a suspected failed device, you need to perform the following tasks and procedures to complete the replacement:

  • Preparing for switch replacement
  • Initial interview
  • Importing and installing an ARX archived configuration
  • Transferring the ARX configuration using the ARX system terminal
  • License activation (ARX 6.0.0 and later)

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have established power and physical connectivity, as appropriate for the environment.
  • You have console access through the the serial port.
  • You have a copy of the running-config.
  • You have a copy of the global-config.

Procedures

Preparing for Switch Replacement

Prior to replacing the failed switch, you must determine the failed ARX system's private subnet, UUID, and master key and associated passwords.

Impact of procedure: None.

  • Determine the private subnet

    Two of the questions in the initial-boot process ask for the switch’s private subnet IP and mask. The private subnet of the replacement switch will need to match those of the switch that failed. Each ARX uses its private subnet for communication with other ARX systems in the same Resilient Overlay Network (RON). The private-subnet and VLAN information appears at the top of the output of the show running-config command for a failed switch.

    The following example shows the top of a running-config file from a failed switch:

    ; ARX-2000
    ; Version 6.00.000.12538 (Feb 16 2011 20:14:13) [nbuilds]
    ; Database version: 600000.25
    ; Generated running-config Tue Feb 22 03:03:19 2011
    ; System UUID 05d5a0fa-f2fb-11df-8daf-af50d57e388e
    ; ip private vlan internal 1008 metalog 1009 subnet 169.254.100.0 255.255.255.0
    ;
    terminal character-set unicode-utf-8
  • Determine the UUID of the failed switch

    When a switch imports storage from file servers, it marks each share with its Universally Unique ID (UUID). A replacement switch must use the same UUID or it rejects all of the shares imported by its predecessor. Also, you must set the UUID if the switch is brought back to its factory defaults. A manufacturing installation by F5 personnel resets the switch and its UUID. The UUID appears at the top of the output of the show running-config command.

    The following example shows the top of a running-config file:

    ; ARX-2000
    ; Version 6.00.000.12538 (Feb 16 2011 20:14:13) [nbuilds]
    ; Database version: 600000.21
    ; Generated running-config Tue Feb 22 03:03:19 2011
    ; System UUID 05d5a0fa-f2fb-11df-8daf-af50d57e388e
    ; ip private vlan internal 1008 metalog 1009 subnet 169.254.100.0 255.255.255.0
    ;
    terminal character-set unicode-utf-8
      
  • Determine the master key

    The ARX generates a master key during the switch’s initial interview process. The ARX master key is used to encrypt and decrypt all of its CSPs (such as passwords). The master key must be the same as the failed device for the configuration to function properly. Use the show master-key command to get an encrypted copy of the master key.

    To gather the ARX master key, you will need to have the system password and wrapping password. The system password is a password entered at initial boot and is 12 to 32 characters long. The wrapping password is entered at initial boot and may be edited later. The wrapping password is 12 to 32 characters, and at least one character in this password must be a number.

    The following example shows the show master-key command:

    ARX1# show master-key
    Master Key System Password: *************
    Wrapping Password: *************
    Validate Wrapping Password: *************

    Encrypted master key:
    2oftVCwAAAAgAAAApwazSRFd2ww/H1pi7R7JMDZ9SoIg4WGA/XsZP+HcXjsIAAAADDRbMCxE/bc=

Initial startup and configuration

The initial startup of the replacement device will set the stage for the rest of the ARX system replacement. An ARX system with no boot configuration present will run the initial interview automatically. The initial interview prompts you for basic configuration and security information required to access the ARX management interface.

Impact of procedure: None.

  1. Connect to the ARX console interface.

    Note: For information about connecting a serial (console) interface, refer to the Connecting the Console Interface section of the Hardware Installation Guide.
  2. Power on the ARX system.
  3. The initial interview, which runs automatically at switch start-up, will begin by displaying the following prompt:

    F5 ARX Startup
    This F5 ARX switch does not currently have critical system information programmed. The following wizard prompts you for this information. You can connect to the switch through the out-of-band management interface when you finish.
    To restart the configuration program, enter 'r' at any prompt.
  4. You will be prompted to enter the following information:

    • The desired management port IP address
    • The desired management port subnet mask
  5. At the Are you doing a switch replacement? prompt, type the following:

    yes
  6. You will be prompted to enter the following information:

    • The switch private IP address

      Note: This information should have been gathered when performing the Preparing for Switch Replacement procedure.
    • The switch private subnet mask

      Note: This information should have been gathered when performing the Preparing for Switch Replacement procedure.
    • The switch UUID

      Note: This information should have been gathered when performing the Preparing for Switch Replacement procedure.
    • The switch base registration key
    • The crypto-officer user name
    • The crypto-officer password
    • The crypto-officer password
    • The system password
    • The previously used master key

      Note: This information should have been gathered when performing the Preparing for Switch Replacement procedure.
    • The wrapping password
  7. The ARX will prompt you with a configuration summary. Verify that all of the information is correct.
  8. To load the configuration, type the following:

    yes

    Alternatively, to perform the interview again, type the following:

    r

Importing and installing an archived ARX configuration

The following are simplified steps necessary to complete the loading of a stored ARX system configuration. Detailed steps are outlined in the Restoring the Configuration section of the ARX CLI Maintenance Guide. If the configuration is in a collect archive or .txt document, use the Transferring the ARX configuration using the ARX system terminal procedure.

Impact of procedure: None.

  1. Establish an ARX terminal session.
  2. Log in to the ARX CLI using the recently configured crypto-officer.
  3. Enable privileged mode by typing the following command:

    enable
  4. In order to install an archived configuration on a replacement ARX system, you first need to transfer the saved information to the newly booted device. Transfer a copy of the archived configuration using the copy command using scripts as the target location for the configuration files.

    Note: For assistance on using the copy command, refer to the ARX CLI Reference guide.
  5. To replay a configuration that has been copied to the ARX, use the following command syntax:

    run scripts <running-config-name>
  6. If the unit is part of a high availability pair, the pair should re-establish and the global config should be synchronized between the two units. If this unit is standalone, you must configure the Global configuration. You may run the copied global config by typing the following command syntax:

    run scripts <global-config-name>

Transferring the ARX configuration using the ARX system terminal

If the saved information is in a collect archive or .txt document, these sections may be copied out of the document and directly pasted into the ARX terminal session to replay the configuration.

Impact of procedure: None.

  1. Establish an ARX terminal session.
  2. Log in to the ARX CLI using the recently configured crypto-officer.
  3. Enable privileged mode by typing the following command:

    enable
  4. To paste the commands into the ARX, you must configure the CLI environment to accept the commands without requiring a confirmation for each configuration item. To do so, type the following commands:

    no terminal length
    no terminal confirmation
    terminal debug

    Note: The terminal debug command is required to allow certain configuration items that have been recommended by F5 Technical Support to be accepted.
  5. Paste the running configuration.
  6. To verify that the configuration is correct, type the following command:

    show running-config
  7. If the unit is part of a high availability pair, the pair should re-establish and the global config should be synchronized between the two units. Alternatively, if this unit is a standalone unit, you must configure the global configuration. You may paste the global-config information into the CLI.
  8. To verify all items have been correctly configured, type the following command:

    show global-config

License activation (ARX 6.0.0 and later)

To install, run, and upgrade the software, you will need to activate the license on the unit. To do so, refer to K12800: Overview of ARX licensing for instructions on how to license an ARX system.
