K676: File locking is not performed when running the 3dns_add and sync_zones scripts

Known Issue

This is most likely the result of a known issue. Normally, when you perform synchronization the system locks the configuration files so that you cannot make changes while the synchronization is in progress.

When you run the 3dns_add script or the sync_zones script, the system does not lock the configuration files. This makes it possible for you to change files while the synchronization is occurring, which can result in corrupted configuration files or files that are out of sync.

F5 Networks Product Development tracked this issue as CR37919 and CR41854.

Workaround

To avoid a file corruption issue, ensure that there are no configuration changes in progress before you run the 3dns_add or sync_zones scripts.
