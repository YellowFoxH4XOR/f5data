Topic

In pass-through mode, the BIG-IP system by default blocks non-compliant HTTP traffic, including unknown HTTP extension methods. However, you can configure the HTTP profile so that the BIG-IP system acts as an HTTP transparent proxy and passes non-compliant traffic from non-browser clients to back-end servers. For example, when configured as a transparent proxy, the BIG-IP system can forward rather than block invalid HTTP headers or unknown HTTP extension methods and send the traffic to servers.

Description

In BIG-IP 11.4.1, F5 adds the database variables (also called database keys) listed in the following table to control how the BIG-IP system manages non-compliant HTTP traffic. When enabled, these database variables switch the HTTP profile to pass-through mode and the BIG-IP system passes through non-compliant HTTP traffic.

Note: These database variables are not available in BIG-IP 11.5.0 and later, but you can use the Configuration utility to set the HTTP profile to pass-through mode.

Important: Enable the first three listed database variables only if you want your BIG-IP system to operate in pass-through mode. In pass-through mode, the BIG-IP system does not validate HTTP traffic and may forward invalid traffic to back-end servers.

Database variableDefinitionDefault setting
tmm.http.passthru.invalid_headerWhen enabled, allows traffic with invalid HTTP headers to pass through. Possible values are enable and disable.Disabled
tmm.http.passthru.pipelineWhen enabled, switches the HTTP profile to pass-through mode when the BIG-IP system receives pipeline data. Possible values are enable and disable.Disabled
tmm.http.passthru.unknown_method When enabled in combination with tmm.http.passthru.invalid_header, allows traffic with unknown HTTP extension methods to pass through. Possible values are enable and disable.Disabled
tmm.http.passthru.truncated_redirectWhen enabled, forwards invalid HTTP redirects with missing trailing carriage returns to the client. Possible values are enable and disable.Disabled

To view or change database variable default values, perform the following procedures:

  • Viewing default database variables
  • Changing default database variables

Viewing default database variables

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To list the current settings, use the following command syntax:

    list /sys db <db key name> all-properties

    For example, to list the default DB setting for the tmm.http.passthru.unknown_method variable, type the following command:

    list /sys db tmm.http.passthru.unknown_method all-properties

    The command output appears similar to the following example:

    sys db tmm.http.passthru.unknown_method {
        default-value "disable"
        scf-config "true"
        value "disable"
        value-range "disable enable"
    }

Changing default database variables

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. To change a database variable default value, use following command syntax:

    modify /sys db <db key name> value <enable|disable>

    For example, to change the default setting for the tmm.http.passthru.unknown_method variable, type the following command:

    modify /sys db tmm.http.passthru.unknown_method value enable

Recommendations

For security purposes, F5 recommends that you only enable tmm.http.passthru.invalid_header, tmm.http.passthru.pipeline, or tmm.http.passthru.unknown_method database variables when you want the BIG-IP system to operate in pass-through mode. In pass-through mode, the BIG-IP system does not validate HTTP traffic and non-compliant traffic may be forwarded to the servers.
