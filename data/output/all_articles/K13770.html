Known Issue

The BIG-IP system fails to include the Subject Alternative Name (SAN) extension when generating a Certificate Signing Request (CSR).

This issue occurs when the following conditions are met:

  • You attempt to include the SAN extension when generating a CSR using the Traffic Management Shell (tmsh).

    For example, the following tmsh command fails to include the SAN extension in the resulting CSR:

    tmsh create sys crypto key ID376995 gen-csr common-name AskF5.com country US subject-alternative-name "DNS:www.askf5.com DNS:solutions.askf5.com"
  • You attempt to include the SAN extension when generating a CSR using the Configuration utility.

A SAN Secure Sockets Layer (SSL) certificate allows you to associate multiple name values with a single SSL certificate, avoiding the costs of purchasing multiple similarly named certificates. Starting in BIG-IP 11.1.0, the Configuration utility and tmsh utility support the SAN extension.

Impact

The CSR generated does not include the SAN extension.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The CSR generated does not include the SAN extension.

Workaround

You can work around this issue by using OpenSSL to create a CSR that contains the SAN extension. To do so, perform the procedure documented in K11438: Creating SSL SAN certificates and CSRs using OpenSSL.
