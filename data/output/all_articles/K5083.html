K5083: Connection rebinding fails if another node is not available when the connected node fails

Known Issue

This is the result of a known issue. When connection rebinding is enabled and the following sequence of events occurs, BIG-IP is unable to rebind the connection to an available node:
  • A connection is established to an available node.
  • The node becomes unavailable.
  • There are no other nodes available to handle the connection.
  • The client continues to send requests more frequently than the timeout for the connection.
  • A node becomes available.

When connection rebinding is enabled and there are no nodes available, BIG-IP maintains a connection entry to a non-existent node. Because the client continues to send requests, preventing the connection from timing out, BIG-IP maintains the connection entry to the non-existent node and cannot select a new node when one becomes available.

F5 Product Development tracked this issue as CR49773 and CR49774 and it was fixed in BIG-IP version 4.5.13 for the 4.5 software branch. For information about upgrading, refer to the BIG-IP Release Notes.

This issue still exists in the version 4.6 branch.
