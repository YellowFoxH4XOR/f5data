Description

After logging into the BIG-IP GUI with a local user account there is a yellow banner with the following error message at the top of the page:

Your Password is going to expire in <x> days

Environment

  • BIG-IP
  • Password policy configuration

Cause

Changes to the default settings of the BIG-IP Password policy have been made to an individual local user.

Recommended Actions

Password policy configuration changes should only be made at the global level using tmsh modify auth password-policy or in the Password Policy section on the System > Users > Authentication page. Follow the procedure below to match the user to the global settings.

  1. Log into the BIG-IP CLI using root.
  2. Make sure you are logged in to bash.
  3. Run the following command to view the global password policy max-duration setting:
    tmsh list auth password-policy all-properties
  4. Run the following to view the local user's account information:
    chage -l <username>

    Example output:
    [root@apm4:Active:Standalone] config # chage -l testuser
    Last password change                                    : Nov 01, 2021
    Password expires                                        : never
    Password inactive                                       : never
    Account expires                                         : never
    Minimum number of days between password change          : 0
    Maximum number of days between password change          : 30   <<<<<--------------------
    Number of days of warning before password expires       : 7
     
  5. The Maximum number of days between a password change can be updated by adding the appropriate option to the chage command.
    To view all chage options enter the following at the command prompt:
    chage
    Example output:
    Usage: chage [options] <username>

    Options:
      -d, --lastday LAST_DAY        set date of last password change to LAST_DAY
      -E, --expiredate EXPIRE_DATE  set account expiration date to EXPIRE_DATE
      -h, --help                    display this help message and exit
      -I, --inactive INACTIVE       set password inactive after expiration
                                    to INACTIVE
      -l, --list                    show account aging information
      -m, --mindays MIN_DAYS        set minimum number of days before password
                                    change to MIN_DAYS
      -M, --maxdays MAX_DAYS        set maximim number of days before password
                                    change to MAX_DAYS
      -R, --root CHROOT_DIR         directory to chroot into
      -W, --warndays WARN_DAYS      set expiration warning days to WARN_DAYS
     
  6. Enter the following to update the Maximum number of days between password change:

    chage -M <global value from step 3>  <username>

    For example: 
    chage -M 99999 testuser
      Note: This change is not synchronized in a device group so you will need repeat it on the other HA members.
  7. Confirm changes with the following syntax:
    chage -l <username> 

    Example of output:
    [root@apm4:Active:Standalone] config #
    chage -l testuser
    Last password change                                    : Nov 01, 2021
    Password expires                                        : never
    Password inactive                                       : never
    Account expires                                         : never
    Minimum number of days between password change          : 0
    Maximum number of days between password change          :99999   <<<<<-------------------- updated with new value password will now expire in 99999 days
    Number of days of warning before password expires       : 7
     

Additional Information

Default local users settings:

Last password change                                   : <Date of last password change>
Password expires                                       : never
Password inactive                                      : never
Account expires                                        : never
Minimum number of days between password change         : 0
Maximum number of days between password change         : 99999
Number of days of warning before password expires      : 7

Note: When you change the secure password policy, the new configuration values, such as password expiration, do not apply to passwords that were created prior to the policy change. The new policy takes effect when the user changes passwords. Refer to K15497 for more details.
