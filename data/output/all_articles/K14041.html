Known Issue

AAA (Authentication, Authorization, and Accounting) server authentication through the BIG-IP APM system fails with the error invalid credentials.

This issue occurs when the following condition is met:

  • An AAA server password is longer than 29 characters.

The maximum password length is 32 characters. However, only 29 of the 32 characters are available for a user to set their password. The three additional characters are reserved for use by the encryption algorithm. This will affect the following AAA server types: RADIUS, LDAP, AD, and Oracle OAM.

Impact

Users will be unable to log in to any BIG-IP APM virtual server that relies on authentication through the RADIUS, LDAP, AD, or Oracle OAM AAA server.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The user is unable to log in.
  • AAA server authentication fails with an error.

    For example, an Active Directory AAA server generates the following error:

    err apd[3948]: 01490107:3: b9e86dc2: AD module: query with '(sAMAccountName=<user>)' failed in krb5_get_init_creds_password():
    Preauthentication failed, principal name: <adminstrator UPN>. Invalid user credentials. (-1765328360)

    In the previous example, note the following:

    - <user> is the user logon ID
    - <administrator UPN> is the administrator name configured on the AAA server
  • The AAA server error logs may display authentication failures.

Workaround

To work around this issue, you can create a password or shared secret that is 29 characters or fewer in length.

Impact of workaround: This workaround may not be feasible depending on your security policies or AAA server configurations.
