Topic

You should consider using these procedures under the following condition:

  • You want to use Remote Authentication Dial-in User Service (RADIUS) authentication to access the BIG-IQ TMOS Shell (tmsh).

Description

You can configure the BIG-IQ system to use RADIUS authentication when accessing tmsh. It is important to understand these important points prior to configuring RADIUS authentication:

BIG-IQ TMOS Shell

You should only use tmsh for diagnostic purposes, such as viewing memory usage, disk usage, log files, or restarting certain system processes. You must perform BIG-IQ tasks, such as remote device discovery and management using the BIG-IQ user interface.
 
Local authentication

When you enable RADIUS authentication for tmsh access, the BIG-IQ system no longer uses local authentication for user accounts other than the administrator. To access the BIG-IQ user interface, you must also configure a RADIUS authentication provider using the user interface. For more information about configuring RADIUS authentication for the BIG-IQ user interface, refer to: K51458353: Configuring the BIG-IQ system to use RADIUS authentication.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You have administrative access to the BIG-IQ system.
  • You have administrative access to the RADIUS server.

Procedures

To enable RADIUS authentication for tmsh, perform the following procedures:

  • Adding the F5 dictionary file to the RADIUS server
  • Configuring the RADIUS server
  • Configuring the remote role group

Configuring the RADIUS server

You must configure a RADIUS authentication server object and change the BIG-IQ system's authentication source from local to radius. Obtained the RADIUS authentication server IP address, service port, and radius secret prior to performing the following procedure.

Important: All user accounts except the administrator (admin) and root will authenticate using RADIUS regardless of whether they are configured for or choose local authentication from the BIG-IQ user interface. Users created locally that do not have radius accounts will not be able to log in to the BIG-IQ system.

Impact of procedure: All user accounts other than the default admin and root user accounts will authenticate using RADIUS. F5 recommends performing this procedure during a scheduled maintenance period.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To configure a RADIUS server, use the following command syntax:

    create auth radius-server <server_name> { server <IP_address> port <service_port> secret <radius_secret> }

    For example, to create a RADIUS server named example_server, using IP address 192.168.10.100, service port 1812 (default radius) and a secret passphrase of ExampleSecret, type the following command:

    create auth radius-server example_server { server 192.168.10.100 port 1812 secret ExampleSecret }

    Note: You can repeat this step to add a secondary server to use if the primary server fails.

  3. To add the RADIUS server as an authentication provider, use the following command syntax:

    create auth radius system-auth servers add { <primary_server> <optional_secondary_server>}

    For example, to add a RADIUS server named example_server as an authentication provider, type the following command:

    create auth radius system-auth servers add { example_server }

    Note: If you created primary and secondary RADIUS servers, add them in order of priority.

  4. To modify the BIG-IQ system to use RADIUS authentication for tmsh access, type the following command:

    modify auth source { type radius }

    Note: You can return the BIG-IQ system back to the default local authentication by typing modify auth source { type local }.

  5. To save the configuration, type the following command:

    save sys config
     

Configuring the remote role group

You must configure one or more ordered remote role groups on the BIG-IQ system to allow authorization of users based on their group membership. When the BIG-IQ system requests user authorization, the remote RADIUS server will respond with the F5 VSA associated with the user account. BIG-IQ then matches the VSA to the locally configured remote role group and applies the appropriate role to the user.

Note: This article is based on the FreeRADIUS application using the following RADIUS user configuration for user john with password of password and the F5 VSA F5-LTM-User-Info-1 = exampleadmin.

john Cleartext-Password :="password"
     F5-LTM-User-Info-1 = exampleadmin,

Impact of procedure: The following procedure should not have a negative impact on your system.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. To create a remote role, use the following command syntax:

    modify auth remote-role role-info add { <object_name> { attribute <F5 VSA attribute>=<remote role name> console <type> line-order <number> role <VSA defined role> user-partition <partition> } }

    For example, to create a remote role object named exampleadmin using the F5-LTM-User-Info-1 VSA attribute to allow administrative user role 0 with tmsh access to All partitions, type the following command:

    modify auth remote-role role-info add { exampleadmin { attribute F5-LTM-User-Info-1=exampleadmin console tmsh line-order 1 role 0 user-partition All } }

  3. To set the auth remote-user configuration to no access and to disable remote console access, type the following command:

    Important: When your RADIUS server returns VSA attributes that do not match what is defined in any remote role objects, the BIG-IQ system will assign the role defined in auth remote-user configuration.

    Note: You can set auth remote-user to any user, F5 recommends no-access for security purposes.

    modify auth remote-user default-role no-access remote-console-access disabled

  4. To save the configuration, type the following command:

    save sys config
