Description

When you create or modify an iRule using tmsh or the iControl REST API, the operation fails with a Tcl parser error similar to the following in the /var/log/audit file:

 

01070151:3: Rule [/Common/<rule_name>] error: /Common/<rule_name>:<line>: error: [braces are required around the expression][<iRule content>]

 

When using REST API, you may get a response body like this:

 

{"code":400,"message":"HTML Tag-like Content in the Request URL/Body","errorStack":[]}

 

The same iRule text saves successfully when entered through the BIG-IP Configuration utility (GUI)

 

Environment

BIG-IP

 

Cause

The underlying cause is a raw, non-ASCII Unicode/UTF-8 character embedded in the iRule text which is not correctly parsed

 

Answer/Recommended Actions

Choose one of the following solutions:

 

1. Create/edit the iRule via the GUI instead. The Configuration Utility encodes non-ASCII characters as HTML entities before submission, which avoids the parser error.

 

2. Remove or replace the offending non-ASCII character(s) in the iRule text before submitting via tmsh or iControl REST.

 

3. Escape the unicode characters. For example, you can replace an em dash `—` with escape sequence \u2014

 

Additional Information

A common example is an em dash (`—`, Unicode U+2014), frequently used by AI tools
