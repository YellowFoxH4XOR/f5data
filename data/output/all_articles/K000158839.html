K000158839: F5OS static Link Aggregation Group (LAG) not forward the packet even the interface is UP

Description

After upgrading F5OS and BIG-IP LTM tenants to the latest versions, Rseries device configured with a static Link Aggregation Group (LAG) may experience intermittent connectivity failures to other devices. Symptoms include failed ICMP (ping) and intermittent TCP connections, even though ARP resolution is successful and all interfaces appear UP. The issue is isolated to environments where static LAG mode is used for link aggregation between F5OS and the connected switch, and is resolved by disabling either member interface. This behavior is due to the lack of link failure detection in static LAG mode.

Environment

  • F5OS platform with BIG-IP LTM tenant
  • Link Aggregation Group (LAG) configured as STATIC across two interfaces
  • VLANs: untagged and tagged VLANs on the trunk
  • No LACP (Link Aggregation Control Protocol) enabled; static LAG mode used
  • Devices connected to a switch with a matching static LAG configuration

Cause

The root cause is the use of static LAG mode for link aggregation. Static LAG does not provide link failure detection or negotiation, so if one link is not passing traffic correctly, the system continues to use it, resulting in intermittent connectivity failures. LACP is required to enable proper link health monitoring and automatic failover.

Recommended Actions

  • Reconfigure the LAG on both F5OS and the connected switch to use LACP instead of static mode.
  • Ensure both ends of the LAG are set to LACP active or passive as appropriate.
  • Use LACP for all link aggregation configurations to ensure proper link health detection and failover.
