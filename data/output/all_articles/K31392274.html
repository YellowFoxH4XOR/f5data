Issue

You should consider using this procedure under the following conditions:

  • You have your BIG-IP APM system configured for Network Access VPN.
  • You have the timeout settings for the access profile configured.
  • Clients connect to the BIG-IP APM system using BIG-IP Edge Client for Windows or macOS or using the BIG-IP Edge Client Browser Plugins for Windows or macOS.
  • The BIG-IP Edge Client VPN sessions abruptly disconnects and/or reconnects.

Symptoms

As a result of the configured timeout values in the access profile, you may encounter the following symptoms:

  • VPN connections to the BIG-IP APM system abruptly disconnect and/or time out.
  • Those using Windows or macOS systems see pop-up messages indicating that the session will soon timeout.

Recommended Actions

There are two timeout scenarios for a BIG-IP APM access profile that may result in a VPN disconnection or re-connection. End users may not be aware of the timeout settings configured by the administrator. Contact the BIG-IP APM administrator to learn about your organization’s VPN policies.

You can locate the Access Profile Timeout Settings (Per-Session) by navigating to Access > Profiles / Policies > Access Profiles (Per-Session Policies) in the Configuration utility.

Note: Access policy timeout is only used during the initiation of a user session. If a user does not complete the BIG-IP access policy negotiation from session initiation through policy completion, this timer applies. This occurs before a VPN tunnel is initiated.

Session inactivity timeout

The session Inactivity Timeout setting specifies the inactivity timeout for the connection in seconds. If there is no activity between the client and server within the specified threshold time, the system closes the current session. The threshold time is defined by the Session Update Threshold and Session Update Window settings in the Network Access configuration.

Session Update Threshold defines the average byte rate where either ingress or egress tunnel traffic must exceed in order for the tunnel to update session. If the average byte rate falls below the threshold, session times out according to the inactivity timeout defined in the access profile. Session Update Windows defines the delta to calculate the exponential moving average (EMA) byte rate of ingress and egress tunnel traffic.

When the session is deleted the BIG-IP APM system logs messages with a syntax similar to the following example to the /var/log/apm file:

<date><time> <hostname> notice tmm[14716]: 01490502:5: /Common/NA_full_tunnel:Common:<sessionID>: Session deleted due to user inactivity.
<date><time> <hostname> notice tmm[8856]: 01490502:5: /Common/NA_full_tunnel:Common:<sessionID>: Session deleted due to user inactivity.

On the client machine, a pop-up message displays, indicating that your session is idle and that you will be logged out soon. See the following figure for an example:

Figure: Example of a session idle message (BIG-IP Edge Client for Windows shown)

For Windows systems, messages with a syntax similar to the following appear in the %temp%/logterminal.txt file:

<date> <time> APPCTRL CAppTunnelEx::OnCheckingSessionComplete, Session terminated by the server. Redirected: 0, status: 404, content length: 0)
<date> <time> APPCTRL \ubindstatuscallback.h, UBindStatusCallback::OnStopBinding, Http status code:404

For macOS systems, messages with a syntax similar to the following are logged to the /Users/<username>/Library/Logs/F5Networks/edge.log file:

<date> <time> , <pid>,<tid>edge, 2, /TunnelController.mm, 185, TunnelController, tunnelError(), Error code, Session Expired

Maximum Session Timeout

The Maximum Session Timeout setting determines the maximum time a session is valid, starting from session creation. This setting is commonly used to limit the amount of time a user can be connected to the VPN before forcing users to re-authenticate. This timeout is not data sensitive and will force a re-connection even if users are passing traffic.

When the tunnel was disconnected because the maximum session timeout was met, the BIG-IP APM system logs a message with syntax similar to the following to the /var/log/apm file:

<date><time> <hostname> notice tmm[18473]: 01490567:5: /Common/NA_full_tunnel:Common:<sessionid>: Session deleted (expired).

On the client machine, a pop-up message displays, indicating that your session is about to reach maximum session timeout and that you will be logged out soon. See the following figure for an example:

Figure: Example of a maximum session timeout message (BIG-IP Edge Client for Windows shown)

For Windows systems, messages with a syntax similar to the following appear in the %temp%/logterminal.txt and f5TunnelServer.txt files:

<date> <time> \USocketChannel.cpp, USocketChannel::Read(), connection shut down

<date> <time> APPCTRL Session <sessionid> closed. Status 0x0

For macOS systems, messages with a syntax similar to the following are logged to the /Users/<username>/Library/Logs/F5Networks/svpn.log file:

<date> <time> , <pid>,<tid>,edge, 2, /TunnelController.mm, 172, TunnelController, Disconnected state, Error code, Session Expired
