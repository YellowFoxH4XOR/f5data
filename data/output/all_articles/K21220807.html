Known Issue

The BIG-IP system may erroneously detect a stuck crypto queue on Nitrox-based systems.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system uses the Nitrox PX or Nitrox 3 encryption hardware.
  • You use hardware-based Secure Sockets Layer (SSL) encryption.
  • Your system experiences a high SSL traffic load.

During high SSL traffic load, the Cavium Nitrox SSL hardware requires more time to complete encryption and decryption. This issue may occur due to a low default Nitrox request timeout value and the request timeout logic.

Impact

The system reports device errors and takes crypto high availability (HA) action, which can cause failover.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you examine the tmm/crypto stats, you observe no queued requests. The output of the tmctl -d blade tmm/crypto command appears similar to the following example:
name                  done      queued cancelled
cn0                   65881553  0      0
cn-crypto-0           65845487  0      0
cn-crypto-0-bulk      65805639  0      0
cn0-00:09.00-cipher   16451410  0      0
cn0-00:09.01-cipher   16451410  0      0
cn0-00:09.02-cipher   16451410  0      0
cn0-00:09.03-cipher   16451409  0      0
cn-crypto-0-pk-verify 15118     0      0
cn-crypto-0-ka-comp   7980      0      0
cn-crypto-0-pk-sign   7980      0      0
  • In the /var/log/ltm file, you observe error messages similar to the following example:
crit tmm2[12074]: 01010260:2: Hardware Error(Co-Processor): cn2 request queue stuck
warning sod[6249]: 01140029:4: HA crypto_failsafe_t cn-crypto-2 fails action is failover.
  • The BIG-IP system fails over to another system in the HA pair.
