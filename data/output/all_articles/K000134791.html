K000134791: SSH key authentication fail for local users due to SELinux

Type
Support Solution
Published
2023-06-07
Updated
2025-04-02
Applies to
  • BIG-IP
Source

Description

Public key authentication uses the public key of a specified user on the SSH client system to authenticate that user to the remote server's SSH daemon instead of requiring password input.
For an SSH server to accept public key authentication, the SSH server configuration must allow this authentication method globally.  The SSH server must also be pre-configured with information about the remote users who are allowed to authenticate using this method by adding the remote user's public key to the local user's authorized_keys file.

On linux level, SELinux is the security mechanism for Linux. 
If local user's authorized_keys file does not have the correct secure context to match SELinux policy, Public key authentication will not work.

 

Symptoms

SSH using Public key authentication failed.

In /var/log/auditd/audit.log, we can see
avc: denied { read } for pid=xxxx comm="sshd" name="authorized_keys" dev="dm-5" ino=xxxx scontext=system_u:system_r:sshd_t:s0-s0:c0.c1023 tcontext=unconfined_u:object_r:home_root_t:s0 tclass=file

 

Environment

  • SSH
  • Public key authentication for local admin user

 

Cause

The authorized_keys file does not have the correct security context to match SELinux Policy.
Process sshd reads file, but access is denied by target because of SELinux.

 

Recommended Actions

Restorecon restores the default context of a file or directory by reading the default rules set in the SELinux policy. If the wrong context is applied, restorecon automatically corrects it from the policy of the filesystem.

restorecon -FRv /home/****/.ssh
Note: Please use your user name to replace ****
