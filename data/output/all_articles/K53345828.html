Known Issue

When you use a custom search engine, the BIG-IP ASM system may go offline or show a sync status of Changes Pending.

This issue occurs when any of the following conditions are met:

  • You configure multiple devices in a Sync-Failover device group with BIG-IP ASM synchronization enabled, and you create a custom search engine which has a new bot name but uses an existing search engine name.

    Note: In BIG-IP 12.1.3.6, the default Bing search engines have different bot names, which causes this issue when you configure multiple devices in a Sync-Failover device group with BIG-IP ASM synchronization enabled. You can work around this issue by deleting one of the Bing search engines and re-creating it with a unique search engine name.

  • You create a custom search engine with a bot name and domain name that are identical to an existing search engine.
  • You create a custom search engine and upgrade to a release that already includes a search engine with the same bot name and domain name but a different search engine name.

Impact

The custom search engine may not be bypassed for JavaScript challenges that are sent when using the Web Scraping or Device-ID features. If you encounter either the second or third of the conditions previously listed and the BIG-IP ASM system subsequently restarts, the system may fail to start successfully and enter a restart loop. As a result, the BIG-IP ASM system remains offline and fails to process traffic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The sync status for the device shows Changes Pending, even after you have the system perform a configuration synchronization (Config Sync).
  • The BIG-IP ASM system device status changes to Offline.
  • The system fails to start and enters a restart loop. The system repeatedly logs messages similar to the following in the /var/log/asm file:

    01310053:6: ASM starting

  • A message similar to the following example appears in the Configuration utility and the /var/log/asm file when you attempt to create a custom search engine:

    010719b1:3: Cannot add the same Domain '<domain_name>' more than once to the Signature's Domains list.

Workaround

To work around this issue when the custom search engine uses an existing search engine name but a new bot name, you can delete the custom search engine and re-create it using a unique search engine name. To work around this issue when performing an upgrade, you can boot back into the previous version, delete the conflicting search engine, then perform the upgrade again. To delete or re-create a custom search engine, perform the following procedures as needed:

Impact of workaround: Performing the following procedures should not have a negative impact on your system.

Deleting a search engine

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Navigate to Security > Options > Application Security > Advanced Configuration > Search Engines.
  3. Select the check box next to the custom search engine.
  4. Click Delete.

Re-creating a search engine

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Navigate to Security > Options > Application Security > Advanced Configuration > Search Engines.
  3. Click Create.
  4. Type a name in the Search Engine box.
  5. Use the information from the search engine you're re-creating to fill in the Bot Name and Domain Name boxes.
  6. Click Create.
