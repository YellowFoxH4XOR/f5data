Description

BIG-IP APM Network Access remains stuck in an initializing state. The user is intermittently connected, delayed, and/or never get connected. The client sends a HTTP request in the following format in order to signal the BIG-IP system to start the control channel but the request fails:

/isession?sess=<sessionid>&ipv4=<yes|no>&ipv6=<yes|no>

The %temp%/logterminal.txt file on the Windows computer contains errors similar to the following examples:

  • <date>,<time>, \UOverlappedIOSocket.cpp, UOverlappedIOSocket::isAvailable(), WSAGetOverlappedResult() error, 10054, An existing connection was forcibly closed by the remote host.
  • <date>,<time>,  \UHTTPChannel.cpp, UHTTPChannel::beginConnection(), EXCEPTION - m_iTransport->Read() error
  • <date>,<time>,  \UHTTPChannel.cpp, UHTTPChannel::beginConnection, EXCEPTION caught: UHTTPChannel::beginConnection() - EXCEPTION

Environment

  • BIG-IP APM Network Access 
  • BIG-IP Edge Client for Windows 10
  • BIG-IP APM Browser Network Access Client

Cause

If there are connectivity issues between the Windows client and the BIG-IP APM system, BIG-IP Edge Client or the web browser plug-in may get stuck in an "Initializing" state. This can be caused by a variety of reasons, from an unplugged network cable to a faulty network switch, or an SSL issue to a layer 7 (L7) application error.

Recommended Actions

  • Enable TCP Reset Cause Logging on the BIG-IP system to determine if the network failure is being initiated by the BIG-IP system.

    Refer to K13223: Configuring the BIG-IP system to log TCP RST packets.

  • Perform a network packet capture on the BIG-IP system and Windows Client to determine the cause of the network reset.

    Refer to K411: Overview of packet tracing with the tcpdump utility.

  • Review the following logs on the client and the BIG-IP system: 
    • Windows Log Files

      Refer to K00819308: Gathering F5 VPN Client Logs.

    • The /var/log/apm logs on the BIG-IP system
  • Gather data to troubleshoot the issue.

    Refer to K22373944: Gathering data to investigate BIG-IP Edge Client connection issues.
