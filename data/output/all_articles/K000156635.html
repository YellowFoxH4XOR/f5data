Description

After upgrading BIG-IQ to version 8.4.0, the system may fail to find a database backup file. The following messages are observed in the bootstrap logs:

Setting system personality in /config/biq_provision.cfg to big_iq

No DNS specified

No DNS search specified

No NTP servers specified

No timezone specified

No hostname specified

No management IP specified

No management route IP specified

Saving Changes

Testing existence of /usr/bin/update-rest-storage

Running pgupdate

A database backup file is missing.

Errors on Launch Traceback (most recent call last):

File "/usr/local/lib/python2.7/site-packages/bigiq_setup/configuration/bootstrap.py",", line 239, in main _do_bootstrap(out) File", "/usr/local/lib/python2.7/site-packages/bigiq_setup/configuration/bootstrap.py",", line 188, in _do_bootstrap commander.run_pgupdate() File", "/usr/local/lib/python2.7/site-packages/bigiq_setup/configuration/commands.py",", line 76, in run_pgupdate stdout=self.outfile, stderr=STDOUT, close_fds=True) File", "/usr/local/lib/python2.7/subprocess.py",", line 186, in check_call raise CalledProcessError(retcode, cmd) CalledProcessError: Command '['",/usr/bin/update-rest-storage']'']' returned non-zero exit status 1

 

Environment

  • BIG-IQ
  • Upgrade from 8.x to 8.4.0
  • Insufficient /var partition sizing for newly created volume
  • Large database files present

 

Cause

ID 1162401 

 

Recommended Actions 

1.      Ensure new /var Partition is the correct size

Reference:  K14532110

a.     Boot into your previous BIG-IQ version using switchboot

b.     Remove any failed upgrade volume to free up space:
tmsh delete sys software volume HD1.x

c.      # Replace x with appropriate volume number

d.     Add a new volume for upgrade and resize /var to match current size: 
addvol HD1.x <path_to_iso>

resizevol /var <size_in_kilobytes>

Example for a desired size of 90GB (KB size will be 90 x 10242)

           resizevol /var 94371840

2.      Perform Upgrade

a.      Preserve the existing /config/startup file

 cp -p /config/startup /config/startup.<date>

b.     Modify the /config/startup file to allow modification

chmod +w /config/startup

c.      Add the following line to the end of the file

restorecon -Fiv /var/config/rest/bigiq_db.bin

d.     Save the file and exit

e.      Perform the upgrade normally

3.      Post Upgrade Actions

a.      Restore the /config/startup file to the preserved version: 

 mv /config/startup.<date> /config/startup

 

 

If the space in /var was sufficient and the Big-IQ is still booted to V8.4, the following steps can be used to resolve this issue:

1. Check whether the following files are available at /var/config/rest/ 
bigiq_db.bin
bigiq_db_globals.sql

2. If these files are available and encounter the error "A database backup file is missing.", then execute the following commands to update the SELinux Permissions

restorecon -Fv /var/config/rest/bigiq_db.bin
restorecon -Fv /var/config/rest/bigiq_db_globals.sql
reboot
