K000140454: After each device reboot / tenant reboot / mcpd restart, the VLAN interface on a tenant will be lost / restored, or management IP / hostname will be restored.

Description

When create / edit the tenant, we can configure the hostname, management IP and gateway, and the VLANs.

In the tenant, we also can edit the management IP, gateway, hostname and VLAN / interface (for R2000 and R4000).

When the hardware device is power rebooted, when reboot the tenant, when mcpd restart in the tenant, we notice VLAN configuration restored, management IP / gateway / hostname on the BIG-IP tenant are restored or removed.

Changes on the interface/LAG configuration will trigger a reconciliation with the Tenant's vlan(s) configuration. Even adding a new VLAN to a LAG, even if not used on the Tenant will reconcile the configured vlan(s) on every Tenant.

Environment

  • F5OS
  • rSeries / VELOS
  • VLAN / interface
  • Management IP / hostname of the tenant

Cause

These setting are supposed to be managed by the F5OS.

Recommended Actions

Configure the VLAN / management IP / hostname in the F5OS, do not change it in the tenant.

VLANs shouldn't be modified inside the tenant, unless you want to move them to a different partition than Common.

This would also apply if we are using trunk/LAG config, tag VLAN in F5OS.

These setting are supposed to be done in the hypervisor. When mcpd starts up, it will read the config from the hypervisor and update the tenant config to match what's on the hypervisor.
