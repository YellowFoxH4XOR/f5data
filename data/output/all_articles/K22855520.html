Description

After a period of inactivity, a client is disconnected from the application when connecting through the BIG-IP.

Environment

  • Idle Timeout value
    • Persistence profile
    • TCP profile
    • FastL4 profile

Cause

The application requires a persistent connection to a single pool member over a long period of time.  The connection experiences a period of inactivity (Idle connection) longer than a configured idle timeout

If the connection is idle long enough, the connection may be closed due to various idle timeout values:
BIG-IP timeout values:

  • Persistence profile idle timeout
    • Persistence entry removed so subsequent requests may be load balanced to a different pool member that is unaware of client session.
  • TCP Idle Timeout
    • Connection is reset which interrupts long lived connection (such as SSH, FTP, etc).
Non-BIG-IP timeout closures:
  • The client
    • The client may be configured with an idle timeout and close the connection after a period of time.
  • Inline devices
    • Devices between the client and BIG-IP may be closing the connection (such as a Firewall).

Recommended Actions

Determine which idle timeout value is closing the connection: BIG-IP or Non-BIG-IP. If it's a BIG-IP timeout, modify the idle timeout value in the affected profile. Increase the timeout value to what that is appropriate for the application. Do one of the following depending on the the profile type:

Protocol Profile
To modify the idle timeout of a protocol profile refer to the following article:

  • K7166: Changing the idle timeout for a protocol profile

Persistence Profile
To modify the idle timeout of a persistence profile perform the following procedure:
Impact of procedure: Lengthy timeouts can increase the memory usage of the BIG-IP because persistence entries will stay in the persistence table longer. Increase the value to a timeout that is only long enough to allow the application to work properly.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Profiles.
  3. Select the Persistence tab.
  4. Select the relevant persistence profile (not a cookie type persistence profile).
  5. Select the Custom box next to the Timeout setting.
  6. Specify a new value in seconds for the Timeout setting.
  7. Select Update.


Alternatively, for HTTP traffic, consider the use of Cookie persistence, which does not use a persistence timeout on the BIG-IP, as the client stores the persistence data in a cookie. For more information refer to the following article:

  • K83419154: Overview of cookie persistence


Additional Information

Timeout example
In this example, a connection is already established and the pool member 10.10.20.40:8443 sends some data which is proxied by the BIG-IP to the client.

10.10.20.40 → 10.10.20.100 1396 8443 50821 TLSv1.2 IN  s1/tmm0 : Application Data
10.10.10.80 → 10.10.10.1 1396 8443 50821 TLSv1.2 OUT s1/tmm0 : Application Data

The connection is then idle for a period of time. The client 10.10.10.1 then closes the connection, and immediately opens a new connection.

10.10.10.1 → 10.10.10.80 40 50821 8443 TCP IN s1/tmm0 : 50821 → 8443 [FIN, ACK] Seq=1139 Ack=17313 Win=64240 Len=0

The BIG-IP load balances this new connection to a different pool member, 10.10.20.50:8443.

10.10.10.100 → 10.10.20.50 48 51188 8443 TCP OUT s1/tmm0 : 51188 → 8443 [SYN] Seq=0 Win=4380 Len=0 MSS=1460 SACK_PERM=1
10.10.20.50 → 10.10.10.100 48 8443 51188 TCP IN s1/tmm0 : 8443 → 51188 [SYN, ACK] Seq=0 Ack=1 Win=8192 Len=0 MSS=1460 SACK_PERM=1
10.10.10.100 → 10.10.20.50 40 51188 8443 TCP OUT s1/tmm0 : 51188 → 8443 [ACK] Seq=1 Ack=1 Win=4380 Len=0
