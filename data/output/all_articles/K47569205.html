Description

When creating a virtual server that has identical traffic matching criteria with another virtual server, but uses a source address defined from an address list, it fails, with an error similar to the following:

01b90011:3: Virtual Server /Common/http-vs-2's Traffic Matching Criteria /Common/http-vs-2_VS_TMC_OBJ illegally shares destination address, source address, service port, and ip-protocol with Virtual Server /Common/http-vs-1 destination address, source address, service port.

Environment

  • Address list
  • First virtual server uses wildcard source, for example, 0.0.0.0/0
  • Second virtual uses identical destination, protocol, and port, with source address defined from an address list

Cause

The system cannot compare an address list to a traditional CIDR block.

Recommended Actions

To achieve this configuration, use the traditional method of creating multiple virtual servers that listen for specific source addresses.

Additional Information

CIDR blocks are hierarchical and one CIDR block can be in another, wider CIDR block. In this case it's easy to find which CIDR block is within another CIDR block.

Address lists are not hierarchical and support 'dynamic' ranges which can span across many CIDR blocks. There can be a CIDR block in a list, but also ranges of IP addresses, which don't need to be aligned to a full CIDR block. It's impossible to define what address is more specific if two overlapping ranges are used, since the system cannot compare an address list to a CIDR block.
