K000135498: "Unexpected protocol options redefined" warning message when running nginx -t command

Applies to

Source

Description

  • You recently upgraded your configuration to version nginx/1.23.4 (R29)
  • when confirming Nginx syntax using command nginx -t, you observe warning messages similar to "protocol options redefined for 0.0.0.0:443 in /etc/nginx/conf.d". 
  • You want to know why you are receiving a protocol warning message 
        nginx: [warn] protocol options redefined for 0.0.0.0:443 in /etc/nginx/conf.d/example_ssl.conf:5
        nginx: the configuration file /etc/nginx/nginx.conf syntax is ok
        nginx: configuration file /etc/nginx/nginx.conf test is successful
        nginx version: nginx/1.23.4 (nginx-plus-r29)

Environment

  • Nginx Plus
  • HTTP2
  • SSL
  • Listen

Cause

  • Cause of the warning message relates to "listen" directive associated with SSL and http2 parameters.

Recommended Actions

The warning message usually relates to how one defined port 443 as well as http2 parameter with "listen" directive
ssl parameter

  • When defining well know port 443, you would also need to include ssl parameter
          server {
               listen *:443;                #  < -- here we have missing ssl parameter 
               server_name  my.example.com;

http2 parameter

  • Going forward, in Nginx, HTTP/2 is becoming a standalone directive in its own right.
          server {
              listen 443 ssl http2;         #  < -- here we have additional parameter http2
              server_name  my.example.com;
  • As for now and given http2 directive appeared in version 1.25.1 OSS and we do not have equivalent directive in Nginx Plus for the next couple of release
  • This means, If we have to work with http/2 protocol, we would still need to associate listen directive with http2 parameter.
  • This means, we may have to accept on the presence of the warning message till HTTP2 directive becomes a directive on its own right in the coming releases.
