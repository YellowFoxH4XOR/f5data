Known Issue

Duplicate routes may randomly exist in the management route table on the BIG-IQ system.

A BIG-IQ system with duplicate management routes may appear similar to the following example:

[root@bigiq1:Active] config # ip route show | cat -n
     1    127.1.1.0/24 dev tmm0  proto kernel  scope link  src 127.1.1.1
     2    127.3.0.0/24 dev mgmt_bp  scope link
     3    10.20.10.0/24 dev eth0  proto kernel  scope link  src 10.20.10.225
     4    10.20.10.0/24 dev eth0  scope link  src 10.20.10.225  metric 9
     5    default via 10.20.10.254 dev eth0  metric 9

Impact

None

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The affected BIG-IP system displays duplicate routes in the management route table.

    For example:

    10.20.10.0/24 dev eth0  proto kernel  scope link  src 10.20.10.225
    10.20.10.0/24 dev eth0  scope link  src 10.20.10.225  metric 9

  • When you perform a Simple Network Management Protocol (SNMP) query on the ipCidrRouteTable object, you may encounter an error reporting Error: OID not increasing.

    For example:

    [root@bigiq1:Active] config # snmpwalk -v 2c -c public localhost ipCidrRouteTable
    IP-FORWARD-MIB::ipCidrRouteDest.0.0.0.0.0.0.0.0.0.10.20.10.254 = IpAddress: 0.0.0.0
    IP-FORWARD-MIB::ipCidrRouteDest.10.20.10.0.255.255.255.0.0.0.0.0.0 = IpAddress: 10.20.10.0
    IP-FORWARD-MIB::ipCidrRouteDest.10.20.10.0.255.255.255.0.0.0.0.0.0 = IpAddress: 10.20.10.0
    Error: OID not increasing: IP-FORWARD-MIB::ipCidrRouteDest.10.20.10.0.255.255.255.0.0.0.0.0.0
     >= IP-FORWARD-MIB::ipCidrRouteDest.10.20.10.0.255.255.255.0.0.0.0.0.0

    For more information on the error generated from the SNMP query, refer to K16207: An SNMP query on the ipCidrRoute table may result in an error message.

Workaround

To work around this issue, you can manually remove the second entry of the duplicate management routes. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system. After you perform this procedure, the duplicate management routes may reappear when the BIG-IQ system reboots. You need to repeat this procedure to remove the duplicate routes.

  1. Log in to the BIG-IQ system Advance Shell (bash) as administrator.
  2. Display the current management route table by typing the following command:

    ip route show

  3. Take note of the duplicated management route entries.

    For example, the command output from step 2 on a BIG-IQ system with duplicate management routes may appear similar to the following example:

    ink  src 10.20.10.22510.20.10.0/24 dev eth0  proto kernel  scope l

    10.20.10.0/24 dev eth0  scope link  src 10.20.10.225  metric 9

  4. Delete the second entry of the duplicate routes.

    For example, referencing the output example from step 3, the second entry would be as follows:

    10.20.10.0/24 dev eth0  scope link  src 10.20.10.225  metric 9

    To delete this entry, you would type the following command:

    ip route del 10.20.10.0/24 dev eth0  scope link  src 10.20.10.225  metric 9

    Note: This duplicate management route reappears when the BIG-IQ system is rebooting.
