K000136949: ASM out of memory error: event code P297

Type
Support Solution
Published
2023-09-22
Updated
2023-09-22
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.8
Source
https://my.f5.com/manage/s/article/K000136949

Description

  • ASM device reports out of memory errors.
  • Messages similar to the following are logged on /var/log/asm:

    emerg perl[15535]: 01310003:0: ASM out of memory error: event code P297

  • Error simialr to the following are logged on /var/log/ts/bd.log:

    IO_PLUGIN|ERR |Sep 12 14:27:43.600|15644|io_plugin.c:4324|TMEVT_REQUEST: Request has no HTTP selector, empty web-security, action is bypass

Environment

  • BIG-IP ASM.
  • ASM security policy.
  • ASM out of memory error.

Cause

Seen behaviour is the result of a configuration issue that is explained here ID521713. The amount of websecurity profiles is not equal to the policies amount overall, meaning that some VS's are missing a policy configuration while websecurity is configured which triggers the error seen below:

IO_PLUGIN|ERR |Sep 12 14:28:01.875|15642|io_plugin.c:4324|TMEVT_REQUEST: Request has no HTTP selector, empty web-security, action is bypass
IO_PLUGIN|ERR |Sep 12 14:28:15.236|15643|plugin_common.c:0298|trans_open: Not enough UMU memory to start a new trans.

Recommended Actions

Make sure all virtual servers are configured correctly.

1. Connect to CLI
2. Run the following command:

for vs in `tmsh list ltm virtual one-line | cut -f3 -d' '`; do tmsh modify ltm virtual ${vs} profiles delete { websecurity }; done

Note: Above bash command will fail, with a visible error, for any VS that actually needs to have the websecurity profile assigned (which is OK) and it will remove the websecurity profile from any VS where it is not really required.
