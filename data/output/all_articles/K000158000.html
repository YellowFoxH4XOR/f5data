K000158000: BIG-IP APM: "Max Sessions Per User" Setting Enforces Limit Globally Instead of Per User

Type
Support Solution
Published
2025-11-27
Updated
2025-12-23
Applies to
  • BIG-IP
  • BIG-IP APM: 17.1.2
Source
https://my.f5.com/manage/s/article/K000158000

Description

When configuring the "Max Sessions Per User" setting in a BIG-IP APM access profile to any value other than 0, only one active session is allowed across all users. This causes issues such as VDI applications disconnecting multiple users and becoming unusable for concurrent access. The expected behavior is for the session limit to apply per individual user.

Environment

  • Product: BIG-IP Access Policy Manager (APM)
  • Version: 17.1.2
  • Platform: F5-BIG-VE-BT-3G-V18, BIG-IP
  • Feature: Access Profiles with "Max Sessions Per User" setting
  • Configuration: VDI application protected by APM access policy
  • Condition: "Max Sessions Per User" set to any value other than 0

Cause

The access policy does not populate the required session variable session.logon.last.logonname. When this variable is not set, the "Max Sessions Per User" restriction is enforced globally for all users rather than individually per user.

Recommended Actions

To enforce session limits per user:

  1. Edit your APM access policy.
  2. Add a Variable Assign action after your authentication step (Logon Page, SAML, or Client Certificate).
  3. In the Variable Assign action:

    1. Add a new entry.
    2. Set variable name to session.logon.last.logonname
    3. Set expression according to your authentication method:
      1. Username/Password Authentication:
        1. expr { [mcget {session.logon.last.username}] }
      2. SAML Authentication:
        1. expr { [mcget {session.saml.last.identity}] }
      3. Client Certificate Authentication (example):
        1. expr { [mcget {session.cert.subject.cn}] }
    4. (or extract UPN as needed)

  4. Save and apply the updated access policy.
  5. Set "Max Sessions Per User" in your access profile to the desired value (e.g., 1).
  6. Test with multiple users to confirm each can have one session; additional sessions by the same user are denied while other users remain unaffected.

Additional Information

  • If session.logon.last.logonname is not set, only one active session is allowed globally for all users.
  • The default value for "Max Sessions Per User" is 0 (unlimited).
  • Only superAdmins and application editors can modify this field.
