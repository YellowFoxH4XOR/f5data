Description

Many circumstances may lead to the need of saving or streaming a tcpdump packet capture to a remote device, some of the reasons could be:

  • Security policies preventing from saving files in the BIG-IP.
  • The BIG-IP might be isolated with restricted access and SCP/FTP are no options to download the packet capture from the device.
  • Company policies preventing from taking files out of the BIG-IP.
  • Lack of disk space in the BIG-IP.


Environment

The following environment requirements are mandatory in order to accomplish saving/streaming tcpdump data to a remote location.

  • BIG-IP. 
  • Remote Linux device.

Note. The Linux device must be capable to reach the BIG-IP and have ufw and tshark preinstalled.

Cause

None

Recommended Actions

Perform the following steps to start a packet capture and send the data to the remote Linux device:
       
Note. This example will use a remote Linux device running a Debian based OS

        1. Log in to the remote Linux device using CLI (SSH)
        2. Open a TCP port in the Linux device so it is able to "listen" and receive the data from the BIG-IP. We will use TCP port 12345.
     
          sudo ufw allow 12345

        3. Run the following command to start listening for the tcpdump stream.
     
          sudo nc -l -p 12345 | sudo tshark -i -

           You can use this other command to listen to the stream and save it to a pcap file:

           nc -l -p 12345 > /var/tmp/remote.pcap

      user@debian:~$ sudo nc -l -p 12345 | sudo tshark -i -
      Running as user "root" and group "root". This could be dangerous.
      Capturing on 'Standard input'

        4. Log in to the BIG-IP using CLI (SSH).
        5. Run the following command in the BIG-IP to start the capture and stream the content to the Linux device.
             You can use any tcpdump parameter and filters as you would do in a normal packet capture

           tcpdump -s0 -nnvi 0.0:nnn host 10.10.1.68 -w - | nc 10.154.172.72 12345

Note: 10.10.1.68 is traffic we are capturing. 10.154.172.72 is the IP address of the remote Linux device and 12345 is the remote Linux device port

      [root@BIGIP-A:Active:Standalone] ~ # tcpdump -s0 -nnvi 0.0:nnn host 10.10.1.68 -w - | nc 10.154.172.72 12345                                                 tcpdump: listening on 0.0:nnn, link-type EN10MB (Ethernet), capture size 65535 bytes
      Got 27

           At this time you should receive data at the remote Linux device, to stop the packet capture just Ctrl+C in the BIG-IP CLI, this will also stop the process in the remote Linux device.
