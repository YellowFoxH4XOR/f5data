Known Issue

This is the result of a known issue. A large number of VLAN failsafe or gateway failsafe entries in the high availability table may cause network failover to fail. In BIG-IP version 9.4.x, when network failover is configured, the BIG-IP system attempts to construct a single UDP network failover heartbeat packet containing all of the high availability table entries. If all the high availability table entries do not fit into a single packet, the BIG-IP system cannot construct and send the packet to the peer system, and logs the following message in the /var/log/ltm file:

sod[1810]: 010c0031:4: Packet create error.

When the peer unit does not receive the network failover heartbeat packet, it asserts itself as the active unit, which may result in an unintended active-active condition and disruption of traffic. Loss of heartbeat may also prevent a compromised unit from failing over to the apparently unavailable peer.

The number of high availability table entries may grow too large to fit in the failover packet when either of the following is true:

  • VLAN failsafe is enabled on a large number of VLANs

    When you enable VLAN failsafe, the BIG-IP system adds a VLAN failsafe entry to the high availability table with a corresponding failover action.
  • The gateway failsafe configuration includes a large number of pools with the Threshold setting configured to a value other than 0 (zero)

    When you define the Threshold setting for a gateway failsafe pool, the BIG-IP system adds a pool min up member entry to the high availability table with a corresponding failover action.

The number of high availability table entries that can be included in a failover packet depends on the platform, version of software, and the length of the names of the VLANs and gateway failsafe pools. For example, on a BIG-IP 3400 platform running BIG-IP version 9.4.8, you can configure up to 63 VLANs with 10-character names. If you configure 64 VLANs, network failover fails.

F5 Product Development is tracking this issue as CR133461 for the BIG-IP version 9.4.x software branch. The version 9.6.x and 10.x branches do not send the entire high availability table in each network failover heartbeat packet, and are unaffected by this issue.

Workaround

You can work around this issue by performing one or more of the following procedures:

  • Verify the contents of the high availability table and remove any invalid entries. Old high availability table entries may still exist if a gateway pool has been deleted without the members having been deleted first.

    Note: For more information, refer to K9876: Gateway failsafe pool entry is not removed from the high availability table after the pool is deleted.
  • Configure serial failover rather than network failover.

    Note: For more information, refer to K2397: Comparison of serial failover and network failover features.
  • Reduce the number of VLANs that have VLAN failsafe enabled.

    Note: For more information, refer to the BIG-IP Network and System Management Guide and to K7066: Overview of VLAN failsafe.

  • Reduce the number of gateway failsafe entries that have a Threshold setting configured to a value other than zero.

    Note: For more information, refer to the BIG-IP Network and System Management Guide and K5308: Configuring gateway fail-safe from the command line.
