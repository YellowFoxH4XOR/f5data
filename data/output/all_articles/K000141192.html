K000141192: TMM memory usage increases over time

Type
Support Solution
Published
2024-09-26
Updated
2024-10-26
Applies to
  • BIG-IP
  • BIG-IP APM: 17.1.X, 17.1.1, 17.1.0
Source
https://my.f5.com/manage/s/article/K000141192

Description

  • TMM memory usage increases over time
  • LTM logs reports "Aggressive mode sweeper" triggered
  • Application traffic is slow or impacted
  • Error similar to the following can be seen on /var/log/ltm

    err tmm2[15221]: 011e0003:3: Aggressive mode sweeper: /Common/default-eviction-policy (2000000000000) (global memory) 736 Connections killed
    err tmm1[15221]: 011e0003:3: Aggressive mode sweeper: /Common/default-eviction-policy (1000000000000) (global memory) 776 Connections killed
    err tmm[15221]: 011e0003:3: Aggressive mode sweeper: /Common/default-eviction-policy (0) (global memory) 1211 Connections killed

  • On the output from the following command, you can see process sso::sso_saml memory usage increasing over time

    ls /shared/tmstat/snapshots/blade*/public/3600/* | xargs -I {} sh -c 'echo "\n"{}; tmctl -f {} memory_usage_stat -s memory_usage_stat -s name,max_allocated -OK max_allocated| head -n 15;'

Cause

Recommended Actions

At the time of creation of this article, there is no fix available on a public releases. If required, and Engineering Hotfix (EngHF) with the fix can be provided.
