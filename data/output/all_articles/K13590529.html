Description
iRule change reflects in running config but old iRule still executes on new connections.

The correct, changed, iRule code is shown through the Configuration utility and tmsh, however testing shows that the iRule executes old code on new connections. Review K13253: Configuration changes to local traffic objects do not affect existing connections for help determining this.

Environment

  • BigDB variable mcpd.mvenabled set to true 
  • virtual server with an iRule attached, where the following changes are made:
    1. virtual server renamed using mv in tmsh
    2. iRule edited using any method
  • configuration synced to a peer device using incremental sync
  • workaround for Bug ID 550739 applied if necessary

Cause
The mv command is experimental and can have unintended consequences. This specific sequence of changes can cause an issue on devices which receive a configuration sync where TMM uses an old version of the iRule code, even for new connections.

The workaround for Bug ID 550739, a similar issue which causes TMM to fail to execute iRules after a virtual server is renamed, does not resolve this issue.

Recommended Actions
Do not use the mv command.

If this issue is encountered, use the following steps to workaround it:
Impact of workaround: The system will not be available while restarting TMM.

  1. On each impacted system, restart TMM:
    tmsh restart sys service tmm
