Known Issue

The BIG-IP system may fail to install a 12.x hotfix with an RPM transaction failure error message.

This issue occurs when all of the following conditions are met:

  • You are running BIG-IP 11.x software listed in the Applies to (see versions) box, located in the upper-right corner of this article.
  • You install 12.x software without a hotfix to an alternate software volume and boot into it.
  • You then boot your BIG-IP system back to the 11.x software volume to install a hotfix on the 12.x software volume.

During the initial boot process on the 12.x software volume, the BIG-IP system applies the relevant SELinux policy to the file system; it has a more restrictive SELinux policy compared to 11.x software. As a result, the subsequent hotfix installation from the 11.x software volume fails to update all the necessary files on the 12.x software volume.

The BIG-IP hotfix installation requires you to import both the base software (for example, 12.0.0) and hotfix (for example, 12.0.0 HF3) installation files into the BIG-IP system. By default, BIG-IP proceeds to install the base software version, before applying the hotfix to the target software volume. If the required base software is present on the target software volume, BIG-IP proceeds to perform only the hotfix installation. For more information, refer to K13123: Managing BIG-IP product hotfixes (11.x - 13.x).

Impact

The BIG-IP 12.x hotfix installation fails.

Symptoms

As a result of this issue, you may encounter the following symptoms:

Note: F5 offers platforms that contain single hard drive configurations and mirrored hard drive configurations. The hard drive designator for single hard drive systems is HD, and the hard drive designator for mirrored hard drives is MD.

  • You observe the following tmsh show /sys software status command output, which displays that the installation failed:

    --------------------------------------------------------------------------------------------------------------
    Sys::Software Status
    Volume  Product  Version   Build  Active                                                 Status
    --------------------------------------------------------------------------------------------------------------
    HD1.1    BIG-IP   12.0.0  3.0.654      no  failed (RPM transaction failure.)
    HD1.2    BIG-IP   11.6.0   0.0.401     yes                                                complete
     

  • The software installation fails with an error messages in the /var/log/liveinstall.log file that appears similar to the following example:

    RPM: can't create /service/snmpd/run at usr/share/perl5/vendor_perl/daemon.pm line 99.

    Note: In this example, the installation failure is related to the snmpd service. However, you may observe failure in other services (for example, eventd or websso).

Workaround

To work around this issue, you can reinstall the hotfix by first deleting the failed software volume and performing the hotfix installation to a new software volume using the Traffic Management Shell (tmsh) or Configuration utility. To do so, perform one of the following procedures:

Note: F5 offers platforms that contain single hard drive configurations and mirrored hard drive configurations. The hard drive designator for single hard drive systems is HD, and the hard drive designator for mirrored hard drives is MD.

Using the tmsh utility

Impact of workaround: Performing the software volume delete operation will remove the site/environment-specific data (for example BIG-IP configuration) residing on that volume.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command.

    tmsh

  2. To delete the failed software volume, use the following command syntax:

    delete /sys software volume <failed_software_slot>

    For example, if the tmsh show /sys software command output shows that HD1.1 has failed, type the following command:

    delete /sys software volume HD1.1

  3. To perform the hotfix installation, use the following command syntax:

    install /sys software hotfix <hotfix_version> create-volume volume <new_software_slot>

    For example, to perform the 12.0.0 HF3 hotfix installation on a new software volume named HD1.1, type the following command:

    install /sys software hotfix Hotfix-12.0.0.3.0.654.iso create-volume volume HD1.1

Using the BIG-IP Configuration utility

Impact of workaround: Performing the software volume delete operation will remove the site/environment-specific data (for example BIG-IP configuration) residing on that volume.

  1. Log in to the Configuration utility.
  2. Navigate to System > Disk Management > Logical View.
  3. Click the disk label.

    For example:

    HD1

  4. In the Contained Software Volumes, select the check box for the software volume with the failed status.

    For example:

    HD1.1

  5. Delete the failed software volume by clicking Delete.
  6. Click Delete again on the delete confirmation page.
  7. To perform the hotfix installation, navigate to System > Software Management > Hotfix List.
  8. From the Available Images section, select the check box of the desired hotfix you want to install.
  9. Click Install.

    The Install Software Hotfix screen opens.

  10. For the Select Disk setting, select the disk on which to install the hotfix.

    For example:

    HD1

  11. For the Volume set name setting, type a unique volume name to install the hotfix on a new software volume.

    For example, to perform the hotfix installation on a new software volume named HD1.1, type 1 as the volume set name.

    Note: The format for a volume set name is lowercase only, alphanumeric with hyphenation, and limited to 32 characters.

    Important: If the volume name exists on the BIG-IP system, proceed to the next step to perform the hotfix installation on the specified volume. As a result, all site/environment-specific data residing on that volume will be removed.

  12. To start the hotfix installation, click Install.
