Description

When logging in the tmsh, a warning pops-out like:
warning, can't fully initialize ternimal, TERM is set to "XXX", status (0).
In the warning message, XXX represents client terminal type.
For example:

Warning, can't fully initialize ternimal, TERM is set to "vt320", status (0)
No entry for terminal type "vt320";

Environment

  • BIG-IP LTM
  • Terminal type

Cause

This warning message appears when your client terminal type isn't included in the BIG-IP terminal database.
This is due to the mismatch between client-claimed TERM and the system-supported terminals. This check happens only when you use TMSH.

Recommended Actions

This warning has no impact to your system, but it is suggestted to use the supported terminal types.

You can find all the BIG-IP system-supported terminals through /usr/share/terminfo/.
For example, in the Linux system:
env | grep TERM

You may be able to verify the client terimanl type to see if it's included in BIG-IP terminfo dababase.
ls /usr/share/terminfo

Additional Information

The client passed its supported terminal type by variable TERM when log in using SSH. The BIG-IP TMOS system checks the client-claimed terminal type by comparing it with the system-supported terminals.
