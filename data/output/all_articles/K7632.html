Known Issue

This is the result of a known issue. If you specify a list of ciphers within a Secure Sockets Layer (SSL) profile, and the cipher string is not adorned with characters to specify placement of the ciphers, the string is automatically moved to the end of the cipher list. OpenSSL specifications state that if cipher strings in a cipher list are preceded by an exclamation point (!), a plus sign (+), or a minus sign (-), the cipher strings should be interpreted as a list of ciphers to be appended to the current list.

Note: For information about the OpenSSL ciphers and cipher list, refer to the man pages for ciphers from the command line.

According to the OpenSSL standard, if you are using the ALL:RC4 cipher list string, the string should be added to the list of specified ciphers if it is not already loaded. The SSL profiles for BIG-IP LTM incorrectly move the RC4 ciphers to the end of the list, rather than ignoring them if they are already loaded, or appending them to the list of available loaded ciphers.

F5 Product Development tracked this issue as CR65841, CR65851, and CR68151, and it was fixed in BIG-IP LTM 9.1.3, 9.2.4, 9.3, and 9.4. For information about upgrading, refer to the BIG-IP LTM release notes.
