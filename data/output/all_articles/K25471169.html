Known Issue

The Windows 10 Anniversary software update may cause access session failures.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM system is configured with an access profile to access an HTTP or HTTPS resource.
  • The user device used to establish an access session is running the Windows 10 operating system and Internet Explorer version 11.
  • The user's device was updated tothe Windows 10 Anniversary update release.
  • The user establishes an access session and attempts to access the destination resource.
  • Content returned from the the destination resource references a shortcut icon link.

    For example:

    <link rel="shortcut icon" href="fav_resource.ico" type="image/x-icon">

    Note: This is a known issue with Internet Explorer: Microsoft Issue #8748123. This link takes you to a resource outside of AskF5. The third party could remove the document without our knowledge.

Impact

Access sessions may fail.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When attempting to access content from the destination resource, the access session terminates with an error message that appears similar to one of the following examples:

    • Your Session is finished

    • Access Policy evaluation is already in progress for your current session

  • When viewing the HTTP communication between the user device and your BIG-IP APM system, requests sent from the Internet Explorer browser do not contain the access session cookies when requesting the shortcut icon content.

Workaround

To work around this issue, you can create and assign an iRule to the affected virtual server that will send an HTTP 404 to the shortcut icon request that matches the specific affected Internet Explorer version. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility of the affected BIG-IP APM system.
  2. Navigate to Local Traffic > iRules.
  3. Click Create.
  4. In the new iRule Name text box, type a name for the iRule.
  5. In the Definition text box, enter the following text:

    when ACCESS_SESSION_STARTED {
    if { [HTTP::method] equals "GET" and ( [HTTP::path] ends_with ".ico" or [HTTP::path] ends_with ".ico?F5CH=I" ) and [HTTP::header "User-Agent"] contains "Trident/7.0; rv:11.0" } {
       ACCESS::session remove
       HTTP::respond 404 
     }
    }

  6. Click Finished.
  7. Navigate to Local Traffic > Virtual Servers.
  8. Select the affected BIG-IP APM virtual server.
  9. Click Resources.
  10. In the iRules section, click Manage.
  11. From the Available column, select the new iRule.
  12. Click << to move the iRule to the Enabled column.
  13. Click Finished.
