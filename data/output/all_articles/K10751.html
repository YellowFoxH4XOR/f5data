K10751: HTTP authentication fails if a Portal Access resource does not use NTLM for authentication

Known Issue

This is the result of a known issue. Users may fail to authenticate when accessing a Portal Access web application if the Proxy Basic and NTLM auth using FirePass user logon form option has been enabled and the Portal Access resource advertises Negotiate authentication, but is not using NTLM authentication. The Portal Access reverse proxy attempts to handle the authentication request only using NTLM, regardless of which Negotiate type is needed. If the Portal Access resource is using a different type of Negotiate authentication, such as Kerberos, FirePass will continually try NTLM and fail to authenticate. The users will receive an authentication failure notice.

F5 Product Development is tracking this issue as ID 238277 (formerly CR125293).

Workaround

You can work around this issue by configuring FirePass to try basic authentication instead of NTLM. To do so, perform the following procedure:

Note: In order for this workaround to function, the web service accessed through FirePass also needs to use basic authentication.

  1. Log in to the FirePass Administrative Console.
  2. Navigate to Portal Access : Web Applications : Master Group Settings.
  3. Confirm that the Proxy Basic and NTLM auth using FirePass user logon form option is selected.
  4. From the Preference drop-down menu, select Basic Authentication.
  5. Navigate to Device Management : Maintenance : Restart Services.
  6. Click on Restart Services.
