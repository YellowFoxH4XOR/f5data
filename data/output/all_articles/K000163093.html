K000163093: F5 Distributed Cloud Customer Edge: Service Account Usage During SMSv2 GCP Deployment

Description

During an SMSv2 ClickOps deployment of a F5 Distributed Cloud Customer Edge (CE) node on Google Cloud Platform (GCP), the service account selected for deployment is not attached to the CE VM. The VM instead displays the Compute Engine default service account.

This is expected behavior. The selected service account is used for provisioning GCP resources, while the service account displayed on the VM is its separate runtime identity.

Environment

  • F5 Distributed Cloud Customer Edge deployed on GCP.
  • SMSv2 GCP ClickOps deployment procedure.
  • Deployment service account roles:
    • roles/config.agent
    • roles/compute.admin
    • roles/iam.serviceAccountUser
  • Deployment user roles:
    • Editor
    • ComputeInstanceAdmin(v1)

Cause

The service account selected during deployment is a provisioning identity used to create the CE VM and associated GCP resources. It is not assigned as the VM's runtime service account.

Because the SMSv2 deployment path does not explicitly override the VM instance service account, GCP assigns the Compute Engine default service account to the VM.

Recommended Actions

The Compute Engine default service account displayed in the CE VM configuration is expected for this deployment model.

  1. Create or select a service account with the required provisioning roles:
    • roles/config.agent
    • roles/compute.admin
    • roles/iam.serviceAccountUser
  2. Ensure the user performing the deployment has:
    • Editor
    • ComputeInstanceAdmin(v1)
  3. Specify the provisioning service account during the SMSv2 GCP CE deployment.
  4. After deployment, treat the service account shown in the VM configuration as the VM runtime identity. When no different instance service account is assigned, this is the Compute Engine default service account.
  5. Do not interpret the VM's Compute Engine default service account as evidence that the provisioning service account was ignored or incorrectly configured.

No corrective change is required for CE operation based solely on this behavior. The CE node does not require GCP API access during runtime. Its control-plane communication with F5 Distributed Cloud Regional Edges uses IPsec/TLS tunnels.

Additional Information

  • The provisioning service account and the VM runtime service account have different purposes.
  • The provisioning service account is used to create GCP resources during deployment.
  • The Compute Engine default service account is used as the VM runtime identity when no other instance service account is assigned.
  • The CE node does not use GCP APIs during normal runtime operation, so this service account distinction does not affect CE functionality.
  • SMSv2 deployment documentation should clearly distinguish between the provisioning service account and the VM runtime service account.
