Description

When passing from BIG-IP to the web server you can encounter 502 error, but when you are bypassing BIG-IP there is no error encountered.

You can also notice error below in /var/log/ltm:

Nov 19 14:00:06 BIG-IP.com err tmm[17942]: 01230140:3: RST sent from 1.1.1.1:443 (Virtual Server) to 1.1.1.2:53489 (Pool Member), [0x3060e81:14513] {peer} TCP zero window timeout.

Environment

  • BIG-IP
  • Pool Member

Cause

The reason of that is the pool member processing the traffic and clearing to window to accept the new data. As a result of that BIG-IP is sending reset because it is not getting the information regarding the window advertisement from the pool member in the define timeout value which is 20 seconds by default. 

Recommended Actions

F5 strongly encourage verify on the pool members end for any high resource utilisation or something else due to which it is taking more time to process the traffic.

This might be a workaround however this is a not permanent solution since the issue is not on the BIG-IP. You can try changing the Zero Window Timeout setting if you want to give more time to application and do not want the BIG-IP to send reset but it will surely add latency in accessing the application . Currently it is configured as 20000 milliseconds i.e. 20 seconds under tcp profile.
