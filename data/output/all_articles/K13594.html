Known Issue

Due to a known issue with the ARX Kerberos cache directory, the ARX system may experience slow authentication and poor CIFS performance.

This issue occurs when all of the following conditions are met:

  • Clients are authenticating through Kerberos
  • The Kerberos cache directory fills to 100 percent

Impact

Clients may experience slow authentication and poor CIFS performance.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • Slow Kerberos authentication 
  • Poor CIFS performance
  • The system may generate an SNMP trap that appears similar to the following example:

    • "kerberosCacheRaise (232) :
    resource:Kerberos cache threshold:95 slot:1 proc:1"

Workaround

To work around this issue, you will need to reload the primary ARX device and fail over to the peer unit. To do so, perform the following procedure:

Impact of workaround: Clients will not be able to connect to the shares as the devices complete failover.

Reloading the switch software

  1. Log in to the ARX CLI.
  2. Enable privileged mode by typing the following command:

    enable
  3. Reload the ARX system by typing the following command:

    reload
  4. When prompted, confirm the reload of the chassis by typing the following command:

    5. yes
