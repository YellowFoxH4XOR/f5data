Description

When the ASM (Application Security Manager) policy is removed from a BIG-IP virtual server, applications may become unreachable. This occurs when backend server HTTP responses lack a Content-Length header and do not use chunked transfer encoding. Clients receiving such responses may fail to process them correctly, resulting in failed transactions. With the ASM policy enabled, ASM adds a Transfer-Encoding: chunked header to these responses, allowing clients to process them successfully.

Environment

  • Virtual server with/without ASM policy attached
  • HTTP profile applied to the virtual server
  • Backend server sends HTTP responses without Content-Length header

Cause

When the ASM policy is enabled, it processes HTTP responses and adds a Transfer-Encoding: chunked header if the response lacks a Content-Length header. This allows clients to interpret and process the response correctly.If the ASM policy is removed, the original backend response—lacking both Content-Length and chunked encoding—is sent directly to the client. Many clients cannot handle such responses, leading to application failures.This behavior is associated with known Bug ID 1302689, where ASM requests rechunking of HTTP responses that lack a Content-Length header.

Recommended Actions

You can refer following step to resolve the issue:

  1. Apply an HTTP profile to your virtual server.
  2. Set the Response Chunking  option within the HTTP profile to Rechunk.  This ensures that any backend response lacking a Content-Length header will be properly chunked before being sent to clients.
  3. If using ASM: Be aware that enabling an ASM policy automatically triggers this behavior for affected responses.
  4. If not using ASM: The correct configuration of your HTTP profile’s chunking settings becomes critical for client compatibility.
  5. For more information on available chunking options (Sustain, Rechunk, and Unchunk) in BIG-IP HTTP profiles, refer to official article K40243113.
