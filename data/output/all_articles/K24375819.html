K24375819: TCP connections via a FastL4 or Forwarding virtual server may hang when reused after server or network failure

Type

Published
2021-08-06
Updated
2025-02-06
Applies to
  • BIG-IP
  • BIG-IP LTM: 13.1.X, 13.1.4, 13.1.3, 13.1.1, 13.1.5, 12.1.3, 13.1.0
Source
https://my.f5.com/manage/s/article/K24375819

Issue

Starting in v12.1.3 and v13.0.0, under certain conditions, FastL4 virtual servers (including Forwarding virtual servers) stop forwarding SYN packets for established connections. This applies to all FastL4 virtual servers.

Symptoms

As a result of this behavior, you may encounter the following symptoms:

  • TCP clients fail to reuse client ports when using FastL4 virtual servers when:
    • The client attempts to reuse the connection within the FastL4 idle timeout, AND
    • The first three attempts (the first three SYNs) do not successfully resume the connection
  • TCP connection reuse may indefinitely fail when:
    • clients continually try to reuse the connection within the FastL4 idle timeout, AND
    • the server does not actively shut down the connection
  • Certain applications which use fixed or persistent client ports may fail
    • this is known to occur with the Linux kernel NFS client, which uses a persistent source port across connection failure with NFS over TCP. Specifically, NFS mounts may hang indefinitely.

Recommended Actions

These issues typically only occur as a result of extended network interruptions or critical server failure such as power loss. F5 recommends troubleshooting to determine the source of these failures as well as addressing this condition on BIG-IP.

Procedures

When experiencing the above issues, you can use the following procedure to work around the issue:

  • Recovering affected connections

Recovering affected connections

This procedure functions as an immediate, low-impact "break-fix" to recover any connections in a failed state.

Impact of procedure: This procedure affects only the connections selected to terminate, which can be limited to failed connections.

  1. Identify as many of the following details as possible about the affected client-side connection:
    • client port
    • client address
    • server port
    • server address
  2. In tmsh, use "delete sys connection" to terminate the connection, filling in as many details as possible:
    delete sys connection cs-client-addr [client address] cs-client-port [client address] cs-server-addr [server address] cs-server-port [server port]
    For example, if you are able to determine a client address of 192.0.2.42, a server address of 198.51.100.53, with a server port of 2049, but are unable to determine the client port, run:
    delete sys connection cs-client-addr 192.0.2.42 cs-server-addr 198.51.100.53 cs-server-port 2049

Procedure back out: None.

Contact F5 Support if needed for further assistance with this issue. 

In versions where Bug ID 742078 is fixed, you may disable this SYN limiting. 

  1. In tmsh, run:
    modify sys db tm.dupsynenforce value disable
