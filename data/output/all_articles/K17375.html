Known Issue

The source IP address used for SNMP traps may be inconsistent.

This issue occurs when all of the following conditions are met:

  • The SNMP trap destination is on a Traffic Management Microkernel (TMM) interface network.
  • The configuration does not include a specific management route to forward traffic destined for the trap destination via the management IP address.

Traps that are generated from the alertd process (such as traps regarding monitor up/down statuses) are sent with a TMM self IP address as the source IP address. Traps generated from the snmpd agent (such as configuration changes or the restart of the SNMP agent) are sent with the management IP address as the source IP address.

Impact

The SNMP trap destination (management system) may not accept an SNMP trap from an unregistered IP address or multiple source IP addresses.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The source IP address used for SNMP traps is inconsistent.

    For example, traps sent regarding monitor up/down statuses are sent with the TMM self IP address as the source IP address. However, traps regarding configuration changes or the restart of the snmpd agent are sent with the management IP address as the source IP address.

  • The SNMP trap destination (management system) discards SNMP traps received from the BIG-IP system.

Workaround

To work around this issue, you can configure a specific management route to make the SNMP traps consistently source from the management IP address. For information about configuring a management route, refer to K13833: Managing static routes (11.x) or K13284: Overview of management interface routing (11.x - 12.x).

Impact of workaround: The impact of the suggested workaround depends on the specific environment. F5 recommends testing any such changes during a maintenance window with consideration to the possible impact on your specific environment.

Alternatively, you can configure an Address Resolution Protocol (ARP) disabled FastL4 forwarding virtual server, by using the destination IP address of the SNMP trap destination IP address, and then associating an iRule that translates the source IP address to a TMM self IP address.

Impact of workaround: The impact of the suggested workaround depends on the specific environment. F5 recommends testing any such changes during a maintenance window with consideration to the possible impact on your specific environment.

For example, to make SNMP traps destined for the 10.10.10.200 trap host consistently sourced from a 10.10.10.101 TMM self IP address, you can use configuration objects similar to the following:

sys snmp {
traps {
my_trap {
community public
host 10.10.10.200
}
}
}

ltm rule trap_translate {
when CLIENT_ACCEPTED {
log local0. "original src-ip is [IP::client_addr], going to translate"
snat 10.10.10.101
}
}

ltm virtual-address 10.10.10.200
address 10.10.10.200
arp disabled
mask 255.255.255.255
traffic-group traffic-group-1
}

ltm virtual trap_translate_vip {
destination 10.10.10.200:snmptrap
ip-forward
ip-protocol udp
mask 255.255.255.255
profiles {
fastL4 { }
}
rules {
trap_translate
}
translate-address disabled
translate-port disabled
vlans-disabled
}
