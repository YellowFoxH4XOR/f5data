K000141407: JWT Keys will not automatic updated, and Access Session failes with "error: Signature verification failed for all the provided JWK keys"

Type
Support Solution
Published
2024-10-10
Updated
2024-11-20
Applies to
  • BIG-IP
  • BIG-IP APM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000141407

Description

Access session fails and /var/log/apm shows

OAuth Client: failed for server '/<partition>/<Oauth Server>' using 'authorization_code' grant type (client_id=<The Oauth server's Client ID>), error: Signature verification failed for all the provided JWK keys

recent /var/log/restjavad.*.log does NOT have

Applying access policies [/<partition>/<access_policy_name>] after doing discover for /<partition>/<Oauth_provider_name>

 

Environment

  • BIG-IP APM
  • Oauth Discovery
  • non-default partition

Cause

  • Bug ID 1473701 : We can provide EngHF
  • Bug ID 1293805 : We can provide EngHF

 

Recommended Actions

There is no official workaround for Bug ID 1293805, however below may be a good workaround.

For Access session policy in non-default partition

Using Crontab, schedule a task to restart restjavad, and then save access policy in the non-default profile.

tmsh restart sys service restjavad && tmsh modify apm profile access /<partition_name>/<access_profile_name> generation-action increment

 

For Access per request policy in non-default partition

Using Crontab, schedule a task to restart restjavad, and then save sys conf if the access policy is per-request may work.

tmsh restart sys service restjavad && tmsh restart sys service restjavad && tmsh save sys config
