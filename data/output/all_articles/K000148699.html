Description

You have seen a scenario that a device is continuously sending DNS queries to a specific IP address. Through analysis of packet captures (pcap), the DNS queries were directed to this IP address without any apparent configuration found in device that can cause this behavior.

Environment

  • BIG-IP DNS
  • DNS Cache Resolver

Cause

The root cause of the issue was traced back to the DNS cache resolver settings. The BIG-IP system had cached the NS record for the domain query, which resulted in it sending recursive DNS queries to the NS server at the specified IP address. This behavior is attributed to the DNS cache resolver profile associated with the listener on the BIG-IP system.

Recommended Actions

Checking if there is the DNS cache resolver profile associated with the listener.

If there is DNS cache resolver configured on the listener, then collect and review the output of the following commands to understand the cached NS records:

# tmsh show ltm dns cache records nameserver cache dns_cache zone-name [domain]

Note: [domain] refers to the records you found from the packet capture.

The output above should contain the IP which you observer from the packet capture.

Additional Information

The query path involves:

  • The client sending a DNS query to the BIG-IP listener.
  • If the record isn't in GSLB, the query will go to cache.
  • If record is not in the BIG-IP cache and there is a DNS cache profile with resolver type, the BIG-IP performs a recursive query and caches the NS records.
  • When the following query for records in the same domain comes into listener, the BIG-IP would send the query to NS server directly.
