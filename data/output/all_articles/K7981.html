K7981: Microsoft Internet Explorer uses the wrong character set when displaying Portal Access Web Application favorites

Source

Topic

If Microsoft Internet Explorer 6 or 7 uses the correct character set when a user accesses a web page directly, but uses the wrong character set when a user accesses the same web page through a Portal Access Web Application favorite, the issue may be due to the placement of the META HTTP-EQUIV HTML tag after FirePass rewrites the web page content. Microsoft Internet Explorer 6 and 7 may not parse the META HTTP-EQUIV tag if it appears after a SCRIPT tag in the HTML source code of the web page. The reverse proxy on the FirePass controller adds a SCRIPT tag directly after the HEAD tag when it rewrites the content of a Portal Access Web Application page, which may cause Internet Explorer to ignore the META HTTP-EQUIV tag.

F5 Product Development is tracking this issue as CR84223.

Workaround

You can work around this issue by creating a sed script that inserts the META HTTP-EQUIV tag directly below the opening HEAD tag after FirePass rewrites the web page content. For example, the following sed script inserts the META HTTP-EQUIV tag directly below the opening HEAD tag for all web pages at http://www.siterequest.com:

  • Processing script name:  AddMetaTag

  • URL match patterns:  http://www.siterequest.com/

  • Content Type:  text/html

  • Sed processing script:  s/<HEAD>/<HEAD><META HTTP-EQUIV="Content-Type" CONTENT="text\/html; CHARSET=UTF-8">/gi

  • Processing:  Post-process response data (after content patching)

You can configure sed scripts on the Portal Access: Content Processing page in the Web Applications Content Processing Scripts section.

Important: Set the CHARSET variable in the META HTTP-EQUIV tag to the character set appropriate for your web page. In the previous example, CHARSET is set to UTF-8.
