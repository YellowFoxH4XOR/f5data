Topic

BIG-IP APM access control lists (ACL) are not supported for connections between VPN tunnel clients. As long as IP addresses assigned to clients are not in an excluded address space, a client can send traffic to another client that is connected to a network access tunnel. The same is true for servers to client traffic, where a server could initiate a connection to a client.

Description

BIG-IP APM ACLs have no effect on communication between users who have established network access sessions (tunnels). Access policies that incorporate ACLs with network access profiles apply the ACLs to only the specific configured destination resources and do not apply to individual user network access sessions. The system applies the ACLs to user network access sessions that access defined destination resources.

For each client tunnel connection, an internal forwarding virtual server using the client's IP address is created and process all traffic to the client. This internal virtual server is not accessible by administrators and BIG-IP APM ACL cannot be applied on it.

Recommendations

To prevent established user network access sessions from cross communicating between lease pool network ranges, use one of the following as appropriate for your environment:

  • Use network Packet Filters. To do so, refer to the following resources:
    • K14998: BIG-IP APM access policy ACLs and network access tunnels
    • The Packet Filters chapter of the BIG-IP TMOS: Routing Administration manual for your BIG-IP version.

  • Use the network access Split-Tunneling with the IPV4 Exclude Address Space feature. You can achieve this state if you configure the network access network settings to use Split-Tunneling and specifically configure the IPV4 Exclude Address Space to exclude the network address ranges of lease pools that are configured to be used with other network access profiles. When you configure the network access Split-Tunneling IPV4 Exclude Address Space feature to exclude the network ranges of other lease pools, you must consider excluding all network access profile address ranges, and exclude the address range of the lease pool that the specific network access profile uses.

For example:

    • Two users establish network access sessions (tunnels) to the BIG-IP APM system, using different network access profiles and lease pool configurations.
    • User A receives an IP address from the Alpha lease pool with the network address range of 172.16.101.0/24.
    • User B receives an IP address from the Beta lease pool with the network address range of 172.16.202.0/24.
    • The IPV4 Exclude Address Space for the network access profile used by user A referencing the lease pool Alpha would exclude the network range of 172.16.202.0/24 (the Beta lease pool range).
    • The IPV4 Exclude Address Space for the network access profile used by user B referencing the lease pool Beta would exclude the network range of 172.16.101.0/24 (the Alpha lease pool range).
    • If you configure the IPV4 Exclude Address Space configuration for either network access profile without excluding the other lease pool's network range, the two users will still be able to communicate with one another.
