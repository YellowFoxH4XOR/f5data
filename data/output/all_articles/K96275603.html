Known Issue

The mcpd process may not start due to a syslog configuration parsing error after you upgrade to BIG-IP 13.1.0.

This issue occurs when the all of the following conditions are met:

  • The syslog configuration contains a filter that matches a string with a left bracket character ( [ ) and a right bracket character ( ] ).
  • Only the right bracket character is escaped with two backslash characters ( \ ).

    For example:

    filter f_ssl_acc_req {
            not (facility(local6) and level(info) and match('[ssl_acc\\]')) or
            not (facility(local6) and level(info) and match('[ssl_req\\]'));
        };

Prior to BIG-IP 13.1.0, the left bracket is not treated as a special character and you do not have to escape the character. A newer version of syslog-ng is included with BIG-IP 13.1.0, which requires you to escape the left bracket.

You can prevent the issue from occurring altogether by defining filters using the guidelines outlined in the following documents:

  • K16932: Configuring the BIG-IP system to suppress sending SSL access and request messages to remote syslog servers
  • Syslog-ng FAQ

    Note: This link takes you to a resource outside of AskF5. The third party could remove the document without our knowledge.

Impact

The BIG-IP system fails to start in BIG-IP 13.1.0 or later.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • The system logs messages to the /var/log/ltm file that appear similar to the following example:

    err mcpd[<PID>]: 01070920:3: Application error for confpp: Error parsing filter expression, error compiling search pattern, error=Error while compiling PCRE expression, error=missing terminating ] for character class, error_at=10 in /etc/syslog-ng/syslog-ng.conf at line 1522, column 57: not (facility(local6) and level(info) and match('[ssl_acc\\]'))

Workaround

To work around this issue, prior to upgrading to BIG-IP 13.1.0, you can edit the syslog configuration and escape the left square bracket. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the TMOS shell (tmsh) by typing the following command:

    tmsh

  2. Edit the syslog configuration by typing the following command:

    edit /sys syslog all-properties

    The syslog configuration opens in the vi text editor.

  3. To enter insert mode, type i.
  4. Within the include section of the configuration, locate the left bracket character and enter four backslash characters immediately before the bracket. For example, your configuration contains a line similar to the following:

    not (facility(local6) and level(info) and match('[ssl_req\\]'));

    If your BIG-IP system is running 12.1.5 or later, add two backslash characters immediately in front of [ssl_req\\]:

    not (facility(local6) and level(info) and match('\\[ssl_req\\]'));

    If your BIG-IP is running a version earlier than 12.1.5, add four backslash characters immediately in front of [ssl_req\\]:

    not (facility(local6) and level(info) and match('\\\\[ssl_req\\]'));

  5. To leave insert mode and return to command mode, press Esc.
  6. Exit the text editor by typing the following:

    :wq

  7. At the following prompt, to save the changes to the syslog configuration, type y:

    Save changes? (y/n/e)

    Note: If there are any syntax errors, the following message displays: There were errors. Continue editing(y) or discard changes(n) (y/n)

  8. When you are back at the tmsh prompt, save the configuration changes by typing the following command:

    save /sys config
