Description

  • While attempting to deploy container ingress services (CIS) for Kubernetes using values.yaml manifest for Helm charts specified in github  documentation: https://github.com/F5Networks/charts/blob/master/src/stable/f5-bigip-ctlr/README.md the container may return status of ImagePullBackOff. You may see errors below returned from kubectl while describing the pod:
Warning  Failed     6m4s (x4 over 7m29s)    kubelet            Failed to pull image "f5networks/k8s-bigip-ctlr:latest": failed to pull and unpack image "docker.io/f5networks/k8s-bigip-ctlr:latest": failed to resolve reference "docker.io/f5networks/k8s-bigip-ctlr:latest": failed to do request: Head "https://registry-1.docker.io/v2/f5networks/k8s-bigip-ctlr/manifests/latest": tls: failed to verify certificate: x509: certificate is valid for api.twitter.com, api.x.com, not registry-1.docker.io
  • While executing the command to view errors relating to the pod "kubectl describe pod <controller_pod_name> -n kube-system"
  • Errors similar to below may be observed
Warning  Failed     6m4s (x4 over 7m29s)    kubelet            Error: ErrImagePull
Warning  Failed     5m37s (x6 over 7m28s)   kubelet            Error: ImagePullBackOff
Normal   BackOff    2m28s (x19 over 7m28s)  kubelet            Back-off pulling image "f5networks/k8s-bigip-ctlr:latest"

Environment

  • BIG-IP LTM/DNS
  • Helm chart manifest to deploy CIS

Cause

  • Controller image repo referenced in values.yaml manifest maybe inaccessible

Recommended Actions

  • Edit values.yaml manifest and within the image section
  • Replace the image user and version parameter values below:
image:
  # Use the tag to target a specific version of the Controller
  user: f5networks
  repo: k8s-bigip-ctlr
  pullPolicy: Always
version: latest
  • With the following repo user and version
image:
  # Use the tag to target a specific version of the Controller
  user: quay.io/f5networks
  repo: k8s-bigip-ctlr
  pullPolicy: Always
version: 2.18.0
