Known Issue

The BIG-IP system may fail to load the configuration after an upgrade. This issue occurs when all of the following conditions are met:

  • You upgrade the BIG-IP system from 10.x to 11.x.
  • During the conversion process, the Persist.WellKnownProxyClass db variable is assigned the /Common/aol value.

When upgrading from 10.x to 11.x, the conversion utility converts 10.x file formats to 11.x formats. During the conversion, the db variables and their configured values in the /config/BigDB.dat file are also converted. When this issue occurs, the conversion process assigns the Persist.WellKnownProxyClass db variable a value of /Common/aol, which does not exist in the /config/bigip.conf file. This behavior causes configuration load failures in certain upgrades, but no configuration load failures in others, except for a log message in the /var/log/ltm file.

In some cases involving an upgrade of a VIPRION system, the issue prevents the affected blade from rejoining the cluster after the upgrade and the affected blade remains offline until manual intervention occurs.

Impact

The affected BIG-IP system may be unable to process traffic.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The affected BIG-IP system may be unable to process traffic.
  • An affected VIPRION blade remains offline and fails to rejoin the cluster after an upgrade.
  • The BIG-IP system may fail to load the configuration and logs an error message that appears similar to the following example in the /var/log/ltm file:

    01070265:3: The class (/Common/aol) cannot be deleted because it is in use by a DB variable (persist.wellknownproxyclass).
    err load_config_files: "/usr/libexec/bigpipe base daol" - failed. -- BIGpipe unknown operation error:    01070265:3: The class (/Common/aol) cannot be deleted because it is in use by a DB variable (persist.wellknownproxyclass).

  • Displaying the value of the Persist.WellKnownProxyClass db variable using the tmsh list sys db persist.wellknownproxyclass command returns the incorrect /Common/aol value:

    sys db persist.wellknownproxyclass {
        value "/Common/aol"
    }

Workaround

If you encountered this issue after an upgrade to 11.0.0, you can reboot to the previous 10.x slot and reset the db variable before performing the upgrade again. If you encountered this issue after an upgrade to 11.1.0, you can reset the value of the Persist.WellKnownProxyClass db key on the affected BIG-IP system. To do so, perform the procedure appropriate for your version:

  • Reboot to the previous 10.x slot, reset the db key value, and perform the upgrade (11.0.0 only)
  • Reset the db key value (11.1.0 and later)

Reboot to the previous 10.x slot, reset the db key value, and perform the upgrade (11.0.0 only)

Impact of workaround: None.

  1. Log in to the Configuration utility.
  2. Click System.
  3. Click Software Management.
  4. Click Boot Locations.
  5. Choose the appropriate slot from the Boot Partition for which you want to revert.
  6. To reboot the device and activate the selected boot partition, click Activate.
  7. When the reboot is complete, log in to the command line.
  8. Reset the db key value and save the changes by entering the following two commands:

    tmsh modify sys db persist.wellknownproxyclass value \"\"
    tmsh save sys config

  9. Perform the upgrade to your desired 11.x version by following the steps detailed in the release notes for your version.

Reset the db key (11.1.0 and later)

Impact of workaround: None.

  1. Log in to the Traffic Management Shell (tmsh) by entering the following command:

    tmsh

    Note: If you are currently logged in to the tmsh shell, you can skip this step.

  2. Reset the Persist.WellKnownProxyClass db key value to its default by entering the following command:

    modify sys db persist.wellknownproxyclass reset-to-default

  3. Reload the configuration by entering the following command:

    load sys config
