Known Issue

The configuration of an unbundled 40 Gigabit Ethernet (GbE) 2.x interface is unexpectedly inherited by the first 10 GbE 1.x interface of the bundle.

This issue occurs when all of the following conditions are met:

  • The platform supports 40 GbE interface bundles, which includes one of the following configurations:
    • B2250 blade installed in a VIPRION 2200 or 2400 Chassis
    • B4300 blade installed in a VIPRION 4400 or 4800 Chassis
    • BIG-IP 10000 series platforms
    • BIG-IP 12000 series platforms
  • The bundle state for the 2.x interface is disabled.
  • The state for the 2.x interface is disabled or the SFP Requested Media setting is set to a fixed value (changed from auto).

On platforms that support 40 GbE interface bundles, each interface bundle is represented as a 2.x interface (2.1, 2.2, 2.3, 2.4). Each 2.x interface is associated with a group of four 10 GbE 1.x interfaces. For example, interface 2.1 is associated with interfaces 1.1, 1.2, 1.3 and 1.4, interface 2.2 is associated with interfaces 1.5, 1.6, 1.7 and 1.8. Depending on the platform, the 2.x interface may be four individual 1/10 GbE interfaces or a single 40 GbE QSFP+ interface. The bundle state for a 2.x interface bundle of four individual 1/10 GbE interfaces will be disabled by default (unbundled). The bundle state for a 2.x interface of a single 40 GbE QSFP+ interface will be enabled by default (bundled).

When a 2.x interface's bundle state is disabled (unbundled), the system will unexpectedly apply the 2.x interface attributes (including the enabled/disabled state and the SFP Requested Media setting) to the first 10 GbE 1.x interface of the associated bundle.

For example:

If the bundle state for interface 2.1 is disabled and you also disable the actual 2.1 interface (state), the disabled state will be unexpectedly inherited by the 1.1 interface. As a result, the 1.1 interface will report a status of DOWN even if the 1.1 interface state is specifically configured as enabled.

In addition, if the bundle state for interface 2.1 is disabled and you have hard set the SFP Requested Media setting to a state other than auto for the actual 2.1 interface, that SFP Requested Media setting will be unexpectedly inherited by the 1.1 interface. As a result, the 1.1 interface will fail to establish a link successfully.

Impact

The first 1.x 10 GbE interfaces for the associated unbundled 2.x 40 GbE interface bundle may not behave as expected.

  • Disabling an unbundled 40 GbE 2.x interface will also disable the first 10 GbE 1.x interface of the associated bundle.
  • Setting the SFP Requested Media setting for a 2.x interface will cause the first associated 10 GbE 1.x interface to fail to establish a link successfully.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • After disabling a 2.x interface for an unbundled interface bundle, the first associated 1.x interface reports a status of DOWN, even though the 1.x interface state is enabled.
  • After hard setting the SFP Requested Media setting of a 2.x interface for an unbundled interface bundle, the first associated 1.x interface is unable to establish a successful link.

Workaround

To mitigate this issue, you can disable and then re-enable the affected 1.x interface.

Impact of mitigation: This mitigation will not persist a reboot and the issue will return if the interface configuration is reloaded.

To work around this issue, you should ensure unbundled 2.x interfaces are configured as enabled and the SFP Requested Media setting is configured to auto.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
