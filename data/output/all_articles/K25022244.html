Known Issue

The tmm process may produce a core file when a large number of Secure Sockets Layer (SSL) keys are loaded.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP configuration uses a large number of SSL keys.
  • Your BIG-IP system is heavily loaded.

When the configuration is loaded, all associated SSL keys are read. Reading configurations with a large number of configured SSL keys can take long enough to cause the Traffic Management Microkernel (TMM) watchdog timer to expire. The exact number of SSL keys required to cause this issue varies depending on the number of keys configured and the load on your BIG-IP system.

Impact

The BIG-IP system may temporarily fail to process traffic and fail over if configured as part of a high-availability system.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system temporarily fails to process traffic, and fails over to the peer device.
  • The tmm process restarts and produces a core file in the /shared/core directory.

Workaround

There is no workaround for this issue; however, you may be able to mitigate this issue by limiting the number of SSL keys in your configuration.
