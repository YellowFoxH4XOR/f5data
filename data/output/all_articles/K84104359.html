Description

You have multiple Virtual Servers configured with Source Address Affinity Persistence Profile. One Persistence Profile has the option match-across-virtuals disabled but another has been enabled.

- Virtual Server A (Service Port 80): persistence source-addr
- Virtual Server B (Service Port 81): persistence source-addr (match-across-virtuals enabled)
- Virtual Server C (Service Port 82): persistence source-addr (match-across-virtuals enabled)

When a client makes a connection to the Virtual Server B, a persistent record will be created. (Persistent Record B)
Then, the same client makes a subsequent connection to the Virtual Server C, the Persistent Record B will be used to load balanced.
When the same client makes a subsequent connection to the Virtual Server A, another persistent record will be created. (Persistent Record A)
However, the same client makes a subsequent connection to the Virtual Server C, the Persistent Record to be used is not only Persistent Record B but also Persistent Record A.

Environment

  • BIG-IP LTM
  • Your virtual servers have a Source Address Affinity persistence profile configured.
  • Some virtual servers have the option match-across-services enabled.
  • One virtual server does not have the option match-across-services.

Cause

This is by design. 
When Match Across Virtual Servers option is enabled, the BIG-IP system searches the persistence record table but doesn't require the virtual server information to be consistent between the current connection and the persistence records searched.

Recommended Actions

On 14.1 or later, Virtual Server has Service Port field, which can accommodate multiple ports.
It may help to avoid the issue.
