This article provides an overview of several large, bundled engineering hotfixes (EHF), released on top of BIG-IP versions 21.1.0.2, 17.5.1.9 and 17.1.3.5. This article covers where to find a list of fixes, installation prerequisites, and references to upgrade guidelines and documentation to assist you.

The following is a list of the bundled EHFs F5 released:

  • Hotfix-BIGIP-21.1.0.2.0.30.22-ENG (Also includes a fix for CVE-2026-94127)
  • Hotfix-BIGIP-17.5.1.9.0.160.12-ENG (Also includes a fix for CVE-2026-94127)
  • Hotfix-BIGIP-17.5.1.9.0.46.12-ENG
  • Hotfix-BIGIP 17.1.3.5.0.41.14-ENG (Also includes a fix for CVE-2026-94127)
  • Hotfix-BIGIP-17.1.3.5.0.1.14-ENG

For a list of issues that the EHFs resolve, refer to the accompanying EHF_Release_Notes PDF files for each release on the MyF5 Downloads page.

Note: When planning for an upgrade to BIG-IP version 21.1.0.2, 17.5.1.9 or 17.1.3.5, consider the following factors:

  • If you are not currently running an engineering hotfix, you should review the IDs listed in the applicable EHF release notes. Once that review is done, you can then determine whether it is applicable and apply it as needed or proactively.
  • If you are currently running an engineering hotfix:
    • Review the EHF release notes for 21.1.0.2, 17.5.1.9 or 17.1.3.5 to ascertain the status of the IDs in your current EHF. If you find all the IDs in your current EHF are fixed, then you can use just the base image. You should also review the release notes for the EHF on the MyF5 Downloads page and determine whether to install the EHF as needed or proactively.
    • If you find that not all IDs are fixed in 21.1.0.2, 17.5.1.9 or 17.1.3.5, then review the release notes for the applicable EHF. If you find that the IDs you have are found there, then install the EHF.
    • After your review of the IDs in your current EHF, if it is shown that an ID from the current EHF is not fixed or is not listed in the release notes, open a case with F5 Support. Please provide a clear statement of what you discovered and why you are requesting an engineering hotfix for BIG-IP version 21.1.0.2, 17.5.1.9 or 17.1.3.5. Please include the IDs in question.
      • Review K4918: Overview of the F5 critical issue hotfix policy prior to installing a hotfix.

Description

The EHFs are delivered as part of F5's commitment to addressing critical customer needs and resolve a wide range of known issues across multiple components. The bundled EHFs are designed to build on the 21.1.0.2 base version, 17.5.1.9 base version, and 17.1.3.5 base version.

Recommendations

You must upload the base BIG-IP version 21.1.0.2, 17.5.1.9, or 17.1.3.5 to the system before applying the corresponding EHF for each of those releases. The base image and the engineering hotfix must reside on the BIG-IP system and are stored in the default image location, /shared/images, so the BIG-IP system can automatically install the image if needed when you perform a hotfix installation. They can be seen in the GUI at System >> Software :: Image or System >> Software :: Hotfix.

For more information about installing EHFs refer to the following resources:

  • K55025573: BIG-IP engineering hotfix installation overview
  • K13123: Managing BIG-IP product hotfixes (15.x - 21.x)

For more information about upgrading refer to: K02693745: Prepare to update or upgrade the BIG-IP system | BIG-IP update and upgrade guide.

Additional Information

Important: An earlier version of the v17.5.1.9.0.46.12-ENG engineering hotfix release notes incorrectly listed Bug IDs 2172041 and 2221585 as fixed in this release. These fixes are not included in the EHF package. The release notes were updated on September 11, 2026 to correct this information. Customers who accessed the release notes prior to the update should review the latest version.

For additional details, refer to the following Bug Tracker articles:

  • Bug ID 2172041: Zone transfer fails for dnsx when the zone file contains TLSA records
  • Bug ID 2221585: When tenant renews DHCP lease on eth2, the interface IP address on mgmt also gets modified
