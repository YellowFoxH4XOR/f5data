Description

The F5 persistence cookie profile does not have an option to add the SameSite attribute to the HTTP set-cookie response header, but the SameSite attribute can be configured using an iRule.

Environment

  • BIG-IP
  • Cookie persistence
  • iRule

Cause

The SameSite attribute is not currently supported using the persistence profile.

Recommended Actions

The following example iRule can be used to insert the SameSite attribute within the F5 persistence cookie.

Note: The following iRule is provided as an example and should be tested to determine impact to your specific environment. F5 also recommends that you review your current global iRule configuration, if any, to ensure that there are no conflicts or redundant configuration.

when HTTP_RESPONSE_RELEASE priority 500 {
   if {[set pos [lsearch -glob [HTTP::cookie names] {BIGip*}]] ne {-1}} {
     set cookie_name [lindex [HTTP::cookie names] $pos]     
# ignores incompatible clients and always sets SameSite to None
     HTTP::cookie attribute $cookie_name remove {samesite}
     HTTP::cookie attribute $cookie_name insert {SameSite} {None}
   }
}

Additional Information

The SameSite attribute of the Set-Cookie HTTP response header allows you to declare if your cookie should be restricted to a first-party or same-site context.

For security compliance some site requires this site to be set as Strict so cookies will only be sent in a first-party context and not be sent along with requests initiated by third party websites.

Note: This iRule ignores the fact that not all clients are compatible with the SameSite attribute. There is the full iRule in DevCentral:
iRule to set SameSite for compatible clients and remove it for incompatible clients (LTM|ASM|APM).
