Topic

This article applies to BIG-IP 9.x through 10.x. For information about other versions, refer to the following article:

  • K14912: Adding and removing encryption from private SSL keys (11.x - 12.x)

Prior to BIG-IP 9.0, the BIG-IP system did not support the use of passphrase-encrypted private Secure Socket Layer (SSL) keys. Beginning in BIG-IP 9.0, the BIG-IP system allows the use of encrypted private SSL keys by enabling the administrator to specify the passphrase used to encrypt the private SSL keys.

Beginning in BIG-IP 9.4.5, a security feature was introduced to encrypt the passphrase used to encrypt the private SSL key. The following description of this new feature is an excerpt from the BIG-IP 9.4.5 release notes:

SSL key passphrase encryption

This release includes a new security feature designed to protect passphrases for SSL keys. This new security feature is an internal mechanism within the BIG-IP system that automatically creates a master key for the purpose of encrypting, and therefore protecting, key passphrases.

For increased security, the master key is also protected. When stored on the system, the master key is always encrypted with a hardware key, and never in the form of plain text.

Note: Passphrases are an optional feature that you specify within a Client or Server SSL profile. Therefore, the passphrase encryption feature applies only to configurations in which you are using the Client or Server SSL profile Pass Phrase feature.

Important: UCS archives and configuration files that contain passphrase-protected SSL keys can only be restored or loaded on the standalone or redundant system on which they were created. You cannot load a configuration containing encrypted passphrases from one BIG-IP system onto a system with a different master key. If you are unsuccessful in restoring a configuration that contains encrypted passphrases, edit the /config/bigip.conf file, replacing each encrypted passphrase string with its clear text equivalent, then reload the configuration. The system re-encrypts the passphrases with the new system's master key.

Secure configuration synchronization

The BIG-IP system can securely exchange the encrypted master key between the units of a redundant pair during the configuration synchronization process, with no intervention by the BIG-IP system administrator.

Upgrade considerations

As an internal process, this feature is primarily hidden from users. However, whenever you upgrade the BIG-IP system to versions 9.4.5 and later, you should consider the following information:

  • Encrypted passphrase strings

    After an upgrade, passphrases appear as encrypted strings, such as MDEyMzQ1Njc4OWFiY2RlZmdoaWprbG1ub3BxcnN0dXZ3eHl6.
  • Management of user configuration set (UCS) files

    Because master keys are specific to a single unit or pair of peer units, encrypted passphrases cannot be used on systems other than the units for which the master key was generated. Thus, you cannot successfully create a UCS file, copy the file to another (non-peer) system, and then use the file.

Adding a passphrase to encrypt a private SSL key/Changing an existing passphrase for an encrypted private SSL key

If you are currently running BIG-IP 9.4.5, or later, and want to use this feature, you can specify a passphrase to be used to encrypt the private SSL keys. To do so, perform the following procedure:

Important: If you change or add a passphrase to a key currently in use by a virtual server, SSL connections to the virtual server fail until the related SSL profile configuration is updated with the newly-added passphrase and the changes have been loaded into memory. To avoid service disruption, perform this procedure during a scheduled outage.

  1. Log in to the command line.
  2. Change directories to the /config/ssl/ssl.key/ directory.

    For example:

    cd /config/ssl/ssl.key/

    To check if the SSL key is already encrypted with a passphrase, use the following command:

    openssl rsa -text -noout -in <name of key>.key

    Command output of an SSL key that is not encrypted with a passphrase appears similar to the following example:

       # openssl rsa -text -noout -in testkey1.key
       Private-Key: (1024 bit)
       modulus:
           00:b0:fd:c2:81:60:3f:d2:dc:fe:2d:34:c6:46:1e:
           08:72:c3:78:f3:4d:12:16:b9:39:3e:0b:d3:8b:e7:
           ...

    Command output of an SSL key encrypted with a passphrase appears similar to the following example:  

      # openssl rsa -text -noout -in testkey2.key
       Enter pass phrase for t3.key:
       Private-Key: (1024 bit)
       modulus:
           00:b0:fd:c2:81:60:3f:d2:dc:fe:2d:34:c6:46:1e:
           08:72:c3:78:f3:4d:12:16:b9:39:3e:0b:d3:8b:e7:
           ...

  3. To add a passphrase and encrypt the SSL key, use the following syntax:

    openssl rsa -des -in <unencrypted name>.key -out <encrypted name>.key

    Note: F5 recommends that you specify a different name or use a distinguishing number when encrypting a private SSL key to prevent any service interruption. If you use the same name for the encrypted name, it overwrites the private SSL key file with the encrypted key and may interrupt traffic until the SSL profile has been updated with the passphrase to allow it to read the private SSL key.

    For example:

       # openssl rsa -des -in testkey1.key -out testkey2.key
         writing RSA key
         Enter PEM pass phrase:
         Verifying - Enter PEM pass phrase:

    Important: Store the passphrase in a secure place. If the passphrase is lost or forgotten, there is no way to retrieve the passphrase and a new private SSL key must be generated.

  4. To change a passphrase on an encrypted SSL key, use the following syntax:

    openssl rsa -des -in <encrypted name>.key -out <updated encrypted name>.key

    Note: F5 recommends that you specify a different name or use a distinguishing number when changing the passphrase of an encrypted private SSL key to prevent any service interruption. If you use the same name for the updated encrypted name, it overwrites the private SSL key file with the updated passphrase and may interrupt traffic until the SSL profile has been updated with the new passphrase to allow it to read the private SSL key.

    For example:

       # openssl rsa -des -in testkey3.key -out testkey4.key
       Enter pass phrase for t3.key:
       writing RSA key
       Enter PEM pass phrase:
       Verifying - Enter PEM pass phrase:

    The testkey3.key key is the original encrypted SSL key. The testkey4.key key has the new passphrase.

    Important: Store the new passphrase in a secure place. If the passphrase is lost or forgotten, there is no way to retrieve the passphrase and a new private SSL key must be generated.

  5. Update the corresponding SSL profiles with the correct passphrase and key file name, if changed.

Removing a passphrase from an encrypted private SSL key

If you do not want to have your private SSL key encrypted, perform the following procedure:

  1. Log in to the command line.
  2. Change directories to the /config/ssl/ssl.key/ directory.
       
    For example:

    cd /config/ssl/ssl.key/

  3. Locate the private SSL key that you want to remove a passphrase from, and run the following command:

    openssl rsa -in <encrypted name>.key -out <unencrypted name>.key

    For example:

    # openssl rsa -in <encrypted name>.key -out <unencrypted name>.key
    writing RSA key
    Enter PEM pass phrase:
    Verifying - Enter PEM pass phrase:

    Note: If you do not know the passphrase to the private SSL key, there is no way to retrieve it. A new private SSL key must be generated.

  4. Update corresponding SSL profiles and remove the passphrase for those SSL keys that are no longer encrypted.
