K30023210: The BIG-IP ASM cookies are no longer passed to origin web servers

Type
Knowledge
Published
2018-10-02
Updated
2025-04-02
Applies to
  • BIG-IP
  • BIG-IP ASM: 14.1.0, 14.0.0
Source
https://my.f5.com/manage/s/article/K30023210

Issue

Old Behavior

In versions prior to 14.0.0, the BIG-IP system forwards ASM cookies to origin web servers (OWS) as part of client requests. All ASM cookies including Main, Frame, and Feature cookies are not removed and left intact from HTTP requests set by the BIG-IP ASM system. These cookies are not usable by the OWS and in some cases may present an issue for protected applications.

New Behavior

Beginning in 14.0.0, a new system database variable asm.strip_asm_cookies was introduced to control whether the BIG-IP system forwards ASM cookies to the OWS. The default value of asm.strip_asm_cookies is set to true, which indicates all ASM cookies will be removed from HTTP requests prior to forwarding to the OWS.

Note: The BIG-IP system does not remove the ASM persistent storage server-side cookie (TSXXXXXXXX027) unless the requests return to the same policy which generated the cookie.

F5 Product Development tracked this change as ID 382511.

Impact

The new default BIG-IP ASM behavior prevents ASM cookies being passed to OWS which may improve the compatibility between the BIG-IP ASM system and certain protected applications.

Recommended Actions

If desired, you can modify the asm.strip_asm_cookies database variable and revert the ASM cookie behavior as prior to version 14.0.0 so the ASM cookies are left intact and passed to OWS. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. To modify the system database variable and allow ASM cookies to pass to OWS, type the following command:

    modify /sys db asm.strip_asm_cookies value false

  3. To verify the modified system database variable, type the following command:

    list /sys db asm.strip_asm_cookies
