Known Issue

The BIG-IP system may append extra carriage return/line feed (CR/LF) characters to the end of an HTTP monitor POST or PUT request.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system is configured to monitor resource pool members with an HTTP monitor.
  • The HTTP monitor is configured to send an HTTP POST or PUT request that contains HTTP body text, similar to the following example:

    ltm monitor http example_monitor {
    defaults-from http
    destination *:*
    interval 5
    ip-dscp 0
    send "POST /index.html HTTP/1.1\r\nHost: host.postcrlf.com\r\n\r\nsome_data_to_send_over_to_the_server"
    time-until-up 0
    timeout 16
    }

Monitored resources may interpret the HTTP POST or PUT requests sent for an affected HTTP monitor as malformed.

Note: Internet Engineering Task Force (RFC2616) specifically prohibits a POST request from including extra CR/LF characters, as described in the "...an HTTP/1.1 client MUST NOT preface or follow a request with an extra CRLF" text. This link takes you to a resource outside of AskF5, and the third party could remove the document without our knowledge.

Impact

The BIG-IP system may erroneously mark down resource objects that are associated with the affected monitor, and may not direct traffic to the expected resources.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Resource objects associated with the affected HTTP monitor fail to respond to requests, and the monitor marks the resource object down.
  • The system logs messages to the /var/log/ltm file that appear similar to the following examples:

    01070638:5: Pool member <ServerIP_port> monitor status down
    01070640:5: Node <ServerIP> monitor status down

Workaround

To work around this issue, you can use an alternate monitor type or an HTTP monitor that does not send an HTTP request containing data in the body of the HTTP request.

Impact of workaround: The impact of the suggested workaround depends on the specific environment. F5 recommends testing any such changes during a maintenance window with consideration to the possible impact on your specific environment.
