Known Issue

The big3d agent may restart after you set the security.commoncriteria db variable to true.

This issue occurs when the following conditions are met:

  • You are running BIG-IP 11.4.0 or earlier, and have set the security.commoncriteria db variable to true.
  • You install a newer version of the big3d agent.

Impact

The big3d process restarts, and the BIG-IP system fails to collect and synchronize metrics information for device group members.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • In the /var/log/daemon.log file, you observe error messages that appear similar to the following example:

    emerg logger: Re-starting big3d

  • The BIG-IP system fails to collect and synchronize metrics information for device group members.

Workaround

To work around this issue, you can set the security.commoncriteria db variable to false. Alternatively, you can re-install the older version of the big3d process on the affected system. To do so, perform the following procedure:

Impact of workaround: If you set the security.commoncriteria db variable to false, the system will not run the ccmode script or set the default configuration for a Common Criteria evaluated configuration.

Setting the security.commoncriteria db variable to false

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To set the security.commoncriteria db variable to false, type the following command:

    modify /sys db security.commoncriteria value false
