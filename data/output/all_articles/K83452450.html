Description:

You would like to launch native remote desktop resource from BIG-IP APM portal but failed. While the same remote desktop resource is able to be connected directly.

Environment:
  • BIG-IP system with APM provisioned
  • Native RDP with Server Side SSL enabled
  • Remote Desktop Resource is running on Windows 7
  • Virtual Server is using default server-ssl profile

Cause:

Windows 7 remote desktop resources are allowed to be securely connected by using SSLv3. While BIG-IP system will use TLS1.2 to encrypt server-side RDP connection.
If the peer does not support TLS protocol, SSL layer handshake will fail. So launching Native RDP via APM portal will get failure.

Recommended Actions:

Install Microsoft official patch and enable TLS1.1 and TLS1.2 on the remote desktop resource which is running on Windows 7:
Update to add RDS support for TLS 1.1 and TLS 1.2 in Windows 7 or Windows Server 2008 R2
