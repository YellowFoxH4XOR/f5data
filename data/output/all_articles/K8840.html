Known Issue

This is the result of a known issue. TMM sends gratuitous ARP requests for non-local SNAT, NAT, and SNAT pool member addresses when a gateway route exists on the same non-local address range and the system fails over.

The gratuitous ARP requests are sent on the VLAN on which the gateway route is assigned.

The device must request an update and send ARP requests in order to receive the correct MAC address from the correct device. In the meantime, ARP tables may be overwritten with the incorrect MAC address. This behavior can result in disruption on the network.

F5 Product Development is tracking this issue as CR98039.

Note: This behavior does not occur in the 9.4 branch due to network changes.

Additionally, this issue was fixed in Hotfix-BIG-IP-9.3.1-HF3 issued for BIG-IP version 9.3.1, for the BIG-IP 9.3 software branch. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
