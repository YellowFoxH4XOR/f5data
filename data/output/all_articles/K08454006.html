Known Issue

The bigd process produces a core file when a user deletes a route domain associated with a pool that is using a gateway_ICMP monitor.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system is configured with a non-default route domain, for example, route-domain 9.
  • The non-default route domain is associated with a pool that uses gateway_ICMP as its health monitor.
  • A user deletes the non-default route domain from the configuration.

Impact

The BIG-IP system does not perform health monitoring when the bigd process is restarting. As a result, the BIG-IP system may not collect information used for load balancing decisions.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • In the /var/log/ltm file, you observe an error message that appears similar to the following example: 

    emerg logger: Re-starting bigd

  • The BIG-IP system writes a bigd core file to the /shared/core directory.
