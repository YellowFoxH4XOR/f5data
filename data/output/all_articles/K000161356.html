Description

This page explains how to do the following on the XC console:

  • How to configure new firewall rules
  • How to edit existing firewall rules

Environment

  • Distributed Cloud

  • Routed DDoS

Cause

Firewall Rules are key for improving defensive postures efficiency. With them, you can have your traffic cleared for defined unexpected types of traffic even before any alert is generated and alert based mitigations are triggered, protecting you from huge short lived attacks and reducing the time to mitigate

Answer/Recommended Actions

To create or edit firewall rules navigate to Home > Routed DDoS > Manage > Firewall Rules

 

To Add a new firewall rule:

  1.  Click "Add Firewall Rule".
  2. Fill in the information for the new firewall rule (descriptions of fields below).

     

    Metadata
    NameUnique name value for the object to be created.
    Labels (Optional)Can be used to organize and categorize as chosen by the user.
    DescriptionHuman readable description for the object.
    Prefix Configuration
    Version

    IP Version

    Source Prefix

    Enter an IP prefix in the format of 1.2.3.0/24 (or relevant mask).

    Select "All Prefixes" to apply the rule to all source prefixes.

    Destination Prefix 

    Enter an IP prefix in the format of 1.2.3.0/24 (or relevant mask). This is the destination prefix(es) inside of the range of addresses being advertised by Distributed Cloud.

    Select "All Prefixes" to apply the rule to all destination prefixes.

    Protocol

    Select either All Protocols, or select a protocol such as TCP or UDP.

    Note: The Port Configuration section only appears when a relevant Protocol is selected. i.e. it appears with TCP but not with ICMP.

    Port Configuration

    Source Port / RangeEnter a port / ports range value. Ports are located between 1 and 65534. You can also select "All ports".
    Destination Port / RangeAs above, but for the destination port.
    DescriptionOptional internal notes on firewall rule.
     Options
    Action Choose whether the firewall rule will Allow or Deny incoming traffic.
    StateChoose whether the firewall rule is On or Off.

    The firewall rule must be On to start allowing or blocking the matched traffic.

    FragmentsChoose whether the firewall rule will Allow or Deny fragments (for applicable protocols).
  3.  Click Add Firewall Rule at the right bottom to save.
    Note: Firewall rules must be added to a firewall ruleset. The commonest scenario is to use the default firewall rulesets.
  4. Navigate to Home > Routed DDoS > Manage > Firewall Rules > Firewall Rulesets.

     

  5. Click the 3-dot Actions menu next to the desired firewall ruleset.
  6. Click Manage Configuration (A preview of the rule will be displayed).

     

  7. Click Edit Configuration at the right top.

     

  8. Click Edit Configuration at the Firewall Rules section.

     

  9. Click Add Item.

     

  10. Select the desired rule from available options in the box (there is also an option available to create a new rule from there).
    Note: Ensure your rules have the desired order. Drag items to change their order in the list.  
  11. Click Apply.

Note: Firewall Rulesets are contained into Firewall Rule Groups. While the commonest scenario is to use the Default Firewall Rule Group in general, you can always create new groups. Creating a group will automatically create new rulesets. You can apply different firewall rule group to specific tunnels from the corresponding tunnel configuration if needed.

 

To Edit firewall rules:

  1. Click the 3-dot Actions menu next to the desired firewall rule.
  2. Click Manage Configuration (A preview of the rule will be displayed).

     

  3. Click Edit Configuration at the right top.



  4. Once you have completed editing, click Save Firewall Rule. 

 

To Delete firewall rules you can either:

  1. Click the checkbox of the desired rule(s), then Delete selected.

     


  2. Click the 3-dot Actions menu next to the desired firewall rule, then Delete.

      


Additional Information

Firewall Rules configure what traffic is allowed or denied prior to returning to the customer's data center. Note: Customers can only make firewall rules for IP space that they own as part of their account.

The firewall filters are evaluated based on context of connections resulting in either permitting or denying traffic based on:

  • Source / Destination prefixes
  • Destination and source Ports including ranges 
  • Protocol types (UDP/TCP etc)

For TCP traffic, the context established via the first packet of a TCP session must match all subsequent packets in order for the session to remain active.

Note: This Firewall functionality is for Routed DDoS services only.
