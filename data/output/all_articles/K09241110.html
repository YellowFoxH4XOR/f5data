Description

After upgrading the vCMP guest, at a deployed state is ok but there is no network access to the vCMP guest including management IP.

You are able to vconsole the vCMP guest and it showed that configuration was not loaded including the management IP address. This caused the vCMP guest not having network accesss.

tmsh load sys config verify show the following error message:
Unexpected Error: Saving and loading configuration is only allowed on the primary slot

Environment

  • BIG-IP Viprion
  • After upgrading vCMP guest
  • vCMP host would show that the vCMP was successfully deployed (green)
  • vCMP guest does not have network access including management IP
  • vconsole the vCMP showed that configuration was not loaded
  • Following error message when ran tmsh load sys config verify:
    Unexpected Error: Saving and loading configuration is only allowed on the primary slot

Cause

Unknown at time of publication.

Recommended Actions

To resolve the issue, you would need to rebuild the binary configuration by running a MCPD reboot.

  1. SSH to the vCMP host.
  2. vconsole to the vCMP guest (K15372) with the following command:
    vconsole <guest_name> <slot_number>
    Example if the guest name is guest_example on slot 1 the command would be:
    vconsole guest_example 1
  3. Log in to the Advanced Shell (bash).
  4. Create a null file with the file name forceload in the /service/mcpd directory, enter the following command:
    touch /service/mcpd/forceload
  5. Restart the BIG-IP system, enter the following command:
    reboot
  6. After the vCMP guest has rebooted, you will have will have access to it.
    Note: Since the vCMP guest has just started on the new software upgrade, it will take several minutes for it to load
