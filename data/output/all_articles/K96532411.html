Known Issue

The TCP::option iRules command fails after you upgrade to BIG-IP 11.x.

This issue occurs when all of the following conditions are met:

  • You use an iRule that contains the TCP::option command to gather TCP option information from the TCP header.
  • You set the Rules.Tcpoption.settings database variable to specify a TCP option to collect.

Impact

When you upgrade from BIG-IP 10.2.x to BIG-IP 11.x, iRules that use the TCP::option command and depend on the Rules.Tcpoption.settings database variable do not work as expected.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • F5 iHealth lists Heuristic H539210 on the Diagnostics > Identified > Medium page.
  • You upgrade from BIG-IP 10.2.x to BIG-IP 11.x and see that iRules causes an error and triggers the following event:

    CLIENT_ACCEPTED - Illegal argument. TCP::option get on profile without tcp option setting (line 1) invoked from within 'TCP::option get 8'.

Resolution

Status

F5 Product Development has assigned ID 530011 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies to (see versions) box, located in the upper-right corner of this article. Workaround

To work around this issue, after the upgrade, configure the TCP profile that collects the appropriate TCP option for the iRule.

Impact of workaround: Configuring a TCP profile affects production traffic of the virtual server, and you should make this change during a scheduled maintenance window.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Create a TCP profile using the following command syntax:

    create ltm profile tcp <example_profile_name> tcp-options "{8 last}"

    For example, type the following command to create a TCP profile:

    create ltm profile tcp new_profile1 tcp-options "{8 last}"

    Note: This example command creates a new TCP profile, new_profile1, that inherits settings from the parent TCP profile. If the existing TCP profile you are using was customized previously, configure the new TCP profile appropriately.

  3. Associate the TCP profile to the affected virtual server.

Note: For information about changes to the TCP::option command in BIG-IP 11.x, refer to TCP on F5 Cloud Docs.
