Description

You noticed that the MSSQL health monitor is no longer sending monitor probes to Pool Members.

  • Packet capture doesn't show any monitor probes to the backend servers
  • Health monitor marked the pool members as down
     

Environment

  • BIG-IP LTM
  • MSSQL health monitor
     

Cause

Configured monitor interval and timeout settings are shorter than the period required for the MSSQL health monitor time to log in, run the database query, and report the status to the bigd process.

Login times to Microsoft SQL Server-based databases can be slow, the MSSQL health monitor has relatively high default values for the interval and timeout settings: 30 and 91 seconds respectively.

The MSSQL health monitor requires enough time to perform this process, F5 recommends that you do not change the default values for the interval and timeout settings. 
 

Recommended Actions

  1. Configure MSSQL monitors for a minimum Interval of 30 second and Timeout of 91 seconds.
    Example: 
    ltm monitor mssql test-mssql-monitor {
        count 0
        database TestDB
        debug no
        defaults-from mssql
        destination *:*
        interval 30       <<---
        password ***scrubbed***
        recv none
        send none
        time-until-up 0
        timeout 91        <<---
        username Admin
    }
     
  2. Optional: Restart the bigd (The bigd monitor daemon provides system health checks)
    bigstart restart bigd
