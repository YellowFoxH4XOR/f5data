Known Issue

Processing Siebel content with the BIG-IP APM reverse-proxy engine does not rewrite the Siebel content for portal use.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM system has been configured with a portal to access Siebel resources.
  • The BIG-IP APM portal for Siebel access has an associated rewrite profile.

Impact

Access through the BIG-IP APM portal configured for Siebel access does not function and the resource is unavailable.

Symptoms

As a result of this issue, you may encounter the following symptom:

  • Clients attempting to use a BIG-IP APM portal to access a Siebel resource cannot access the resource.

Workaround

To work around this issue, you can create a pair of iRules to process Siebel content for the BIG-IP APM portal. To do so, perform the following procedures:

Impact of workaround: Performing the following procedures should not have a negative impact on your system.

  • Configuring the BIG-IP APM portal for Siebel processing
  • Modifying custom settings for the existing BIG-IP APM portal
  • Creating a BIG-IP LTM pool that contains the Siebel resource and port
  • Creating an iRule to disable compression for the virtual server associated with the BIG-IP APM Siebel portal
  • Creating the iRule for processing Siebel content for the BIG-IP APM portal
  • Associating the new iRules to the BIG-IP LTM virtual server used by the BIG-IP APM portal

Configuring the BIG-IP APM portal for Siebel processing

Prior to performing the following procedures, you must perform the following steps:

  • Customize the settings for an existing Siebel BIG-IP APM portal
  • Create a BIG-IP LTM pool containing the Siebel destination resource
  • Create an iRule to remove the HTTP "Accept-Encoding" header
  • Create the iRule to rewrite the Siebel content
  • Associate iRules to the BIG-IP APM portal BIG-IP LTM virtual server

Note: For instructions about creating BIG-IP APM portals, refer to the BIG-IP Access Policy Manager Portal Access guide (11.0.0 - 11.3.0) or the Configuring Resources for Portal Access chapter of the BIG-IP Access Policy Manager: Portal Access guide (11.4.0). For information about how to locate F5 product guides, refer to K12453464: Finding product documentation on AskF5.

Modifying custom settings for the existing BIG-IP APM portal

  1. Log in to the Configuration utility.
  2. Navigate to Access Policy > Portal Access.
  3. Select the existing BIG-IP APM portal created for Siebel access.
  4. Set Type to Minimal Patching.
  5. Select the Scheme Patching and Host Patching check boxes.
  6. Set Host Search Strings and Host Replace String to "*" (asterisk = any).
  7. Click Update.

Creating a BIG-IP LTM pool that contains the Siebel resource and port

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Pools.
  3. Select Create.
  4. Name the pool.
  5. Select TCP for the health monitor.
  6. Enter the address of the servers and enter the TCP port.
  7. Add the members to the pool.
  8. Click Finished.

Note: To create an advanced Siebel monitor, refer to the Deploying F5 with Siebel Business Applications 8.0 deployment guide. For information about how to locate F5 product guides, refer to K12453464: Finding product documentation on AskF5.

Creating an iRule to disable compression for the virtual server associated with the BIG-IP APM Siebel portal

Note: This iRule is an optional step depending on the Siebel environment.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules.
  3. Click Create.
  4. Name the iRule as follows:

    disable_compression_irule

  5. In the Definition field, copy the following iRule syntax:

    when ACCESS_ACL_ALLOWED {
    HTTP::header remove "Accept-Encoding"
    }

  6. Click Finished.

Creating the iRule for processing Siebel content for BIG-IP APM portal

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules.
  3. Click Create.
  4. Name the iRule as follows:

    scm_rewrite_irule

  5. In the Definition field, copy the following iRule syntax:

    Note: The pool name of the Siebel resource in this example is Siebel.

    when RULE_INIT {
    global scm_proto
    global scm_host
    global scm_subst_re
    set scm_proto "https"
    set scm_host "scm.org.com"
    set scm_subst_re [string map { . {\.} } "$scm_proto://$scm_host/"]
    }

    when HTTP_REQUEST {
    global scm_host
    set need_fix false
    set is_first_req false
    if { ! ( [HTTP::header value "Cookie"] contains "MRHSCMHint=1" ) } {
    log local0.debug "There is no MRHSCMHint=1"
    return
    }
    set vs_host [HTTP::host]
    set vs_host_re [string map { . {\.} } $vs_host]
    set vs_subst "https://$vs_host/"
    set http_uri [HTTP::uri]
    if { ($http_uri starts_with "/service_adsi/") || ($http_uri starts_with "/analytics/") } {
    if { [HTTP::header exists "Host"] } {
    pool Siebel
    log local0.debug "Fixing Host $http_uri ..."
    HTTP::header replace "Host" $scm_host
    }
    if { [HTTP::header exists "Referer"] } {
    log local0.debug "Fixing Referer $http_uri ..."
    HTTP::header replace "Referer" [regsub "SWEHo=$vs_host_re" [HTTP::header value "Referer"] "SWEHo=$scm_host"]
    }
    if { $http_uri starts_with "/service_adsi/start.swe?SWECmd=Login&" } {
    log local0.debug "Fixing URI $http_uri ..."
    regsub "SWEHo=$vs_host_re" $http_uri "SWEHo=$scm_host" http_uri
    HTTP::uri $http_uri
    }
    if { ($http_uri starts_with "/service_adsi/start.swe") || ($http_uri starts_with "/analytics/saw.dll") } {
    log local0.debug $http_uri
    set need_fix true
    }
    }
    }

    when REWRITE_REQUEST_DONE {
    global scm_host
    set http_path [HTTP::path]
    if { ( [HTTP::host] == $scm_host ) && ( ($http_path starts_with "/service_adsi/start.swe") || ($http_path starts_with "/analytics/saw.dll") ) } {
    REWRITE::disable
    set is_first_req true
    }
    }

    when HTTP_RESPONSE {
    if { $is_first_req } {
    log local0.debug "Setting MRHSCMHint cookie ..."
    HTTP::header insert "Set-Cookie" "MRHSCMHint=1; path=/"
    }
    if { $need_fix && ( [HTTP::status] == 200 ) } {
    log local0.debug "Fixing $http_uri ..."
    set clen [HTTP::header value "Content-Length"]
    log local0.debug "CL: $clen"
    if { $clen > 0 } {
    HTTP::collect $clen
    }
    }
    }

    when HTTP_RESPONSE_DATA {
    global scm_subst_re
    set payload [HTTP::payload]
    log local0.debug "Fixing body of $http_uri ..."
    regsub -all $scm_subst_re $payload $vs_subst payload
    HTTP::payload replace 0 [HTTP::payload length] $payload
    log local0.debug "Releasing body of $http_uri ..."
    HTTP::release
    }
  6. Select Finished.

Associating the new iRules to the BIG-IP LTM virtual server used by the BIG-IP APM portal

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > Virtual Servers.
  3. Select the virtual server that is referenced by the BIG-IP APM portal for Siebel resources.
  4. Select the virtual server's Resources tab.
  5. In the iRules section, click Manage.
  6. Select the disable_compression_irule if required for the Siebel environment and move to the Enabled box.
  7. Select the scm_rewrite_irule iRules and move to the Enabled box.

    Important: When using both the disable_compression_irule and the scm_rewrite_irule, ensure that the disable_compression_irule is the first iRule preceded by the scm_rewrite_irule.

  8. Click Finished.
