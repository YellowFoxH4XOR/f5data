Known Issue

The BIG-IP system may fail to resume a connection that is suspended by an iRule command during a CLIENT_DATA event.

This issue occurs when all of the following conditions are met:

  • The affected iRule is associated with a User Datagram Protocol (UDP) virtual server.
  • The affected virtual server is not configured with a pool resource.

For more information about iRule suspending commands, refer to K12962: Some iRules commands temporarily suspend iRule processing.

Impact

The BIG-IP system drops connection packets.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H425757 on the Diagnostics > Identified > High page.
  • When the iRule suspends the connection, it does not return from suspension and the BIG-IP system drops the connection packets.
  • When reviewing the /var/log/ltm file, you observe an error message that appears similar to the following example:

    01220009:6: Pending rule /Common/MyRule <CLIENT_DATA> aborted for 10.10.10.104:40371 -> 10.10.10.203:69

Resolution

Status

F5 Product Development has assigned ID 424228 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies to (see versions) box, located in the upper-right corner of this article. Workaround

There is no workaround. However, you may avoid the issue by using the CLIENT_ACCEPTED event for UDP data or assigning a default pool to the affected virtual server.
