Known Issue

The BIG-IP ASM bd process may produce a core file on VIPRION systems.

This issue occurs when all of the following conditions are met:

  • You are running a VIPRION system with more than one blade installed.
  • You have a high availability (HA) device group configured.
  • Your system is upgraded from version 11.3.0 and later.
This is a rare race condition, where the system configuration is being read during a synchronization event, which results in a temporarily inconsistent state.

Impact

The initial synchronization state for BIG-IP ASM in a device group fails to resolve successfully, and the standby BIG-IP ASM system is unable to become active.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The bd process produces a core file in the /var/core directory of the standby device.
  • Messages similar to the following example are logged in the /ts/log/bd.log file:

    BD_MISC|NOTICE|<timestamp>|12345|temp_func.c:0688|-- EMPTY TABLE: CONFIG_TYPE_DB_SECURITY_SERVER ack num 123
    DATA_PROTECT|ERR |<timestamp>|29378|src/data_protect_conf.c:0390|context_init: Error opening file '/ts/var/account/data_protection/data_protection_1d71cdd6c19765a8298828aacdc01d82': No such file or directory
    DATA_PROTECT|ERR |<timestamp>|12345|src/data_protect_api.c:0020|data_protect_context_init: failed to initialize security context.

Workaround

To work around this issue, you can restart the asm service on the standby system. If restarting the asm service fails to resolve the issue, you can push the full configuration from the active BIG-IP ASM system. To do so, perform the following procedures:

Restarting the asm service on the standby system

Impact of workaround: Performing the following procedure should not have a negative impact on your system because the standby BIG-IP ASM system is not handling traffic.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh
  2. Restart the asm service by typing the following command:

    restart /sys service asm
  3. Exit the tmsh utility by typing the following command:

    quit

Pushing the full configuration from the active BIG-IP ASM system

Impact of workaround: BIG-IP system performance may be impacted when the ConfigSync operation performs a full configuration synchronization of a large configuration.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh
  2. Disable incremental synchronization by using the following command syntax:

    modify cm device-group <device_group_name> full-load-on-sync true

    For example:

    modify cm device-group my_devicegroup full-load-on-sync true
  3. Save the change by typing the following command:

    save /sys config
  4. Perform a ConfigSync operation by using the following command syntax:

    run /cm config-sync to-group <sync_group>

    For example, the following command pushes the local device's configuration to remote devices in the SyncFailover device group:

    run /cm config-sync to-group SyncFailover
  5. Optional: After successful device synchronization, you can re-enable incremental synchronization by using the following command syntax:

    modify /cm device-group <device_group_name> full-load-on-sync false

    For example:

    modify /cm device-group my_devicegroup full-load-on-sync false
