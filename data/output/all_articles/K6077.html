Known Issue

This may be the result of a known issue. A validation error in the big3d agent can cause the big3d_install script to erroneously report that the remote big3d agent was updated.

F5 Product Development tracked this issue as CR60888 and CR67986 and it was fixed in BIG-IP GTM 9.2.4. For Information about upgrading, refer to BIG-IP GTM Release Notes.

Workaround

Important: The following workaround procedure should be performed any time you are updating a remote systems' big3d agent from a BIG-IP GTM 9.2.2 or 9.2.3 system.

To work around this issue, you must ensure that the big3d agent is updated properly by stopping the big3d agent on the remote BIG-IP system on which you intend to install the new big3d. To stop the big3d agent on the remote system and then install the new big3d agent, perform the following procedure:

  1. Log in to the BIG-IP GTM system command line as root.
  2. Shut down the big3d agent on the remote BIG-IP system, by typing the following command:

    ssh root@<BIG-IP addr> "bigstart shutdown big3d"

  3. Enter the root password when prompted.
  4. Run the big3d_install command against the remote BIG-IP system, by typing the following command:

    big3d_install <BIG-IP addr>

    Note: This step requires you to enter the root password of the remote BIG-IP system several times as the script executes and the updated big3d file is copied to the remote BIG-IP system.

    The following example represents output from the big3d_install command:

        # big3d_install 192.168.1.1

(Will wait up to 5 seconds for each IP address)

      Getting BIG-IP version ...Connection to ::ffff: 192.168.1.1:4353 failed: Connection refused

      BIG-IP 192.168.1.1  9.2.2
Will need to install a new version of big3d

big3dshim                                     100%  153KB 153.0KB/s   00:00
Restarting big3d on 192.168.1.1 ...
Password:
    Done.
  5. Repeat steps 2, 3 and 4 for each remote BIG-IP system that requires an updated big3d agent.
