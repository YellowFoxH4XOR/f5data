Description

TCP RST being sent when a browser requests a fictive URL that starts with either of the following strings:

  •  /TSPD/xxx...xxx?type=x
  •  /TSbd/xxx...xxx?type=x
CSRF/Web Scraping/Single Page Application/AJAX Blocking page features might not work. This happens intermittently when the back-end server's HTML page (the one where the fictive URL is injected) is cached in the browser for more than two days.

Environment

This occurs in either of the following scenarios:

  • ASM policy is attached to a virtual server, and any of the following is enabled: Cross-Site Request Forgery (CSRF), Web Scraping/Single Page Application/AJAX Blocking internal.
  • DoS profile with Single Page Application enabled is attached to a virtual server.

Cause

Browser caches the fictive URLs, so when client accesses them hours or a few days later, they are invalid and result in a reset of the connection.
Bug ID 701792
 

Recommended Actions

Issue has been fixed in software version 13.1.1.5 and higher. A parameter has been added that will instruct ASM to remove cache headers for pages where fictive URLs are injected.
To enable the parameter, run the following from the CLI:
    # /usr/share/ts/bin/add_del_internal add disable_cache_upon_injection 1

ASM will then need to be restarted for the changes to take effect.
Note that restarting ASM will cause the unit to go offline and failover (if active).
    # bigstart restart asm

Additional Information

If you wish to disable the parameter at some time in the future, it can be disabled by running:
    # /usr/share/ts/bin/add_del_internal add disable_cache_upon_injection 0

ASM will then need to be restarted for the changes to take effect.
    # bigstart restart asm
