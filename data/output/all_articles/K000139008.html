K000139008: Managing the list of ciphers and MAC and Key Exchange algorithms used by the SSH service on the VELOS or rSeries systems

Topic

You should consider using this procedure under the following condition:

  • You want to list the encryption ciphers, the key exchange (KEX) algorithms, or the Message Authentication Code (MAC) algorithms used by the secure shell (SSH) service on the VELOS or rSeries system.
  • You want to change the encryption ciphers, the KEX algorithms, or the MAC algorithms used by the SSH service on the VELOS or rSeries system.

Note: For systems that are not licensed for FIPS 140-3, SSH Host Key Algorithms are not configurable until ID1636261 is resolved. Even when ssh-rsa is configurable, RFC 8332: Use of RSA Keys with SHA-256 and SHA-512 in the Secure Shell (SSH) Protocol has disallowed the use of ssh-rsa as it is considered deficient nowadays.

Description

Starting in F5OS-C 1.6.0 and F5OS-A 1.4.0, you can display and configure the list of encryption ciphers, MAC and KEX algorithms used by the SSH service on the VELOS or rSeries system. This affects only the control plane traffic via the SSH service and does not apply to data plane traffic. You can list the encryption ciphers, the KEX algorithms, or the MAC algorithms configured and change them to meet your requirements if needed.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You must have administrative access to the management interface (webUI/CLI/REST API) of the VELOS or rSeries system.
  • If you intend to use the REST API procedures, you should have a workstation with the curl utility installed. If you do not have one, you can login to the VELOS chassis or the rSeries command line as the root user to use the curl utility as needed.

Procedures

  • Using the webUI
  • Using the CLI
  • Using the REST API

Using the webUI

You can use the webUI to perform the following procedure to display and configure the encryption ciphers, the KEX algorithms, or the MAC algorithms used for the SSH service on the VELOS chassis and partition as well as the rSeries system.

Impact of procedure: Performing the following procedures will result in the restart of the SSH service; as a result, the SSH service will be momentarily unavailable.

  1. Log in to the webUI as the admin user.
  2. Navigate to SYSTEM SETTINGS > System Security.
  3. The list of supported ciphers, MAC and Key Exchange algorithms currently in used by the SSH service is presented in the sshd Ciphers, sshd MAC Algorithms and sshd KEX Algorithms settings under Services section respectively. Add or remove the ciphers, MAC and/or KEX algorithms; be sure to separate each algorithm in the list with a space and enclose the list with square brackets. For example, [ kex1 kex2 kex3... ]
  4. Select Save to save the changes.
  5. The system then prompts you to confirm if you want to make the change. Select OK to confirm. The process will restart the SSH service and the SSH service will be momentarily unavailable.

Using the CLI

You can use the CLI to perform the following procedure to display and configure the encryption ciphers, the KEX algorithms, or the MAC algorithms used for the SSH service on the VELOS chassis and partition as well as the rSeries system.

Impact of procedure: Performing the following procedures will result in the restart of the SSH service; as a result, the SSH service will be momentarily unavailable.

  1. Log in to the CLI as the admin user.
  2. To display the list of ciphers, MAC and Key Exchange algorithms currently in used by the SSH service, enter the following command:

    show system security services service sshd

    The command returns an output similar to the following example:

    system security services service sshd
     state ciphers [ aes128-cbc aes128-ctr aes128-gcm@openssh.com aes256-cbc aes256-ctr aes256-gcm@openssh.com ]
     state kexalgorithms [ diffie-hellman-group14-sha1 diffie-hellman-group14-sha256 diffie-hellman-group16-sha512 ecdh-sha2-nistp256 ecdh-sha2-nistp384 ecdh-sha2-nistp521 ]

    Note: Although "show system security services service sshd" displays MAC algorithms, they will only appear in the CLI output if they have been explicitly configured. If the state macs line is missing, the system is utilizing internal factory defaults.
  3. To modify the list of ciphers, MAC and Key Exchange algorithms currently in used by the SSH service, you must first enter into the configuration mode by entering this command:

    config

    Then enter the following command syntax:

    system security services service sshd config < ciphers | kexalgorithms | macs > [ <replacement list of ciphers/key exchange/MACs> ]

    For example, to remove the use of Diffie Hellman key exchange, enter
    system security services service sshd config kexalgorithms [ curve25519-sha256 curve25519-sha256@libssh.org ecdh-sha2-nistp256 ecdh-sha2-nistp384 ecdh-sha2-nistp521 ]

    For example, to configure MAC to use hmac, enter
    system security services service sshd config macs [ hmac-sha1 hmac-ripemd160 hmac-ripemd160@openssh.com ]

  4. To save the change, enter the following command:

    commit and-quit

    The system then prompts you to confirm if you want to proceed with committing the change as the process will restart the SSH service and the SSH service will be momentarily unavailable:

    The following warnings were generated:
      'system security services service sshd': Changing SSH configuration will restart the SSHD service.
    Proceed? [yes,no]

    To proceed, enter yes.

  5. To verify the change, enter the following command:

    show system security services service sshd

Using the REST API

You can use the REST API to perform the following procedure to display and configure the encryption ciphers, the KEX algorithms, or the MAC algorithms used for the SSH service on the VELOS chassis and partition as well as the rSeries system.

Impact of procedure: Performing the following procedures will result in the restart of the SSH service; as a result, the SSH service will be momentarily unavailable.

  1. Login to a workstation with curl utility installed. Alternatively, you can login to the VELOS chassis or the rSeries command line as the root user.
  2. To display the list of ciphers, MAC and Key Exchange algorithms currently in used by the SSH service, enter the following command syntax:

    curl -sku <admin user>:<admin password> -H "Content-Type: application/yang-data+json" -X GET "https://<management IP address of the VELOS chassis/partition or rSeries system>/api/data/openconfig-system:system/f5-security-ciphers:security/services/service=sshd"

    For example,

    curl -sku admin:admin -H "Content-Type: application/yang-data+json" -X GET "https://192.168.78.7/api/data/openconfig-system:system/f5-security-ciphers:security/services/service=sshd"

    You should observe the command returning an output similar to the following example:

    {
      "f5-security-ciphers:service": [
        {
          "name": "sshd",
          "config": {
            "name": "sshd",
            "ciphers": ["aes128-cbc", "aes128-ctr", "aes128-gcm@openssh.com", "aes256-cbc", "aes256-ctr", "aes256-gcm@openssh.com"],
            "kexalgorithms": ["diffie-hellman-group14-sha1", "diffie-hellman-group14-sha256", "diffie-hellman-group16-sha512", "ecdh-sha2-nistp256", "ecdh-sha2-nistp384", "ecdh-sha2-nistp521"]
          },
          "state": {
            "name": "sshd",
            "ciphers": ["aes128-cbc", "aes128-ctr", "aes128-gcm@openssh.com", "aes256-cbc", "aes256-ctr", "aes256-gcm@openssh.com"],
            "kexalgorithms": ["diffie-hellman-group14-sha1", "diffie-hellman-group14-sha256", "diffie-hellman-group16-sha512", "ecdh-sha2-nistp256", "ecdh-sha2-nistp384", "ecdh-sha2-nistp521"]
          }
        }
      ]
    }

  3. To modify the cipher, MAC and Key Exchange algorithms currently in used by the SSH service, enter the following command syntax:

    curl -sku <admin user>:<admin password> -H "Content-Type: application/yang-data+json" -X PUT "https://<management IP address of the VELOS chassis/partition or rSeries system>/api/data/opencofig-system:system/f5-security-ciphers:security/services/service=sshd/config" -d '{ "config": { "name": "sshd", "ciphers": [<replacement list of ssh ciphers you want>], "macs": [<replacement list of ssh MACs you want>], "kexalgorithms": [<replacement list of ssh kex you want>] } }'

    For example,

    curl -sku admin:admin -H "Content-Type: application/yang-data+json" -X PUT "https://192.168.78.7/api/data/openconfig-system:system/f5-security-ciphers:security/services/service=sshd/config" -d '{ "config": { "name": "sshd", "ciphers": ["aes256-cbc", "aes256-ctr", "aes256-gcm@openssh.com"], "macs": ["hmac-sha1", "hmac-ripemd160", "hmac-ripemd160@openssh.com"] } }'

    The command does not return an output. Note that the process will restart the SSH service and the SSH service will be momentarily unavailable. To verify if the command is processed successfully, enter the following command syntax:

    curl -sku <admin user>:<admin password> -H "Content-Type: application/yang-data+json" -X GET "https://<management IP address of the VELOS chassis/partition or rSeries system>/api/data/openconfig-system:system/f5-security-ciphers:security/services/service=sshd"

    You should observe the command returning an output similar to the following example:

    {
      "f5-security-ciphers:service": [
        {
          "name": "sshd",
          "config": {
            "name": "sshd",
            "ciphers": ["aes256-cbc", "aes256-ctr", "aes256-gcm@openssh.com"],
            "macs": ["hmac-ripemd160", "hmac-ripemd160@openssh.com", "hmac-sha1"],
            "kexalgorithms": ["diffie-hellman-group14-sha1", "diffie-hellman-group14-sha256", "diffie-hellman-group16-sha512", "ecdh-sha2-nistp256", "ecdh-sha2-nistp384", "ecdh-sha2-nistp521"]
          },
          "state": {
            "name": "sshd",
            "ciphers": ["aes256-cbc", "aes256-ctr", "aes256-gcm@openssh.com"],
            "macs": ["hmac-ripemd160", "hmac-ripemd160@openssh.com", "hmac-sha1"],
            "kexalgorithms": ["diffie-hellman-group14-sha1", "diffie-hellman-group14-sha256", "diffie-hellman-group16-sha512", "ecdh-sha2-nistp256", "ecdh-sha2-nistp384", "ecdh-sha2-nistp521"]
          }
        }
      ]
    }

    The previous curl command uses the HTTP command PUT which performs a direct replacement of the values for each of the settings (ciphers, macs, kexalgorithms). If you are looking to add new ciphers/macs/kexalgorithms to the currently in used list, you can use the HTTP command PATCH.

    For example,

    curl -sku admin:admin -H "Content-Type: application/yang-data+json" -X PATCH "https://192.168.78.7/api/data/openconfig-system:system/f5-security-ciphers:security/services/service=sshd/config" -d '{ "config": { "name": "sshd", "macs": [ "hmac-sha2-256" ] } }'

    Similar to the HTTP command PUT, the HTTP command PATCH does not return an output. Additionally, the process will restart the SSH service and the SSH service will be momentarily unavailable. To verify if the command is processed successfully, enter the following command syntax:

    curl -sku <admin user>:<admin password> -H "Content-Type: application/yang-data+json" -X GET "https://<management IP address of the VELOS chassis/partition or rSeries system>/api/data/openconfig-system:system/f5-security-ciphers:security/services/service=sshd"

    You should observe the command returning an output similar to the following example:

    {
      "f5-security-ciphers:service": [
        {
          "name": "sshd",
          "config": {
            "name": "sshd",
            "ciphers": ["aes256-cbc", "aes256-ctr", "aes256-gcm@openssh.com"],
            "macs": ["hmac-ripemd160", "hmac-ripemd160@openssh.com", "hmac-sha1", "hmac-sha2-256"],
            "kexalgorithms": ["diffie-hellman-group14-sha1", "diffie-hellman-group14-sha256", "diffie-hellman-group16-sha512", "ecdh-sha2-nistp256", "ecdh-sha2-nistp384", "ecdh-sha2-nistp521"]
          },
          "state": {
            "name": "sshd",
            "ciphers": ["aes256-cbc", "aes256-ctr", "aes256-gcm@openssh.com"],
            "macs": ["hmac-ripemd160", "hmac-ripemd160@openssh.com", "hmac-sha1", "hmac-sha2-256"],
            "kexalgorithms": ["diffie-hellman-group14-sha1", "diffie-hellman-group14-sha256", "diffie-hellman-group16-sha512", "ecdh-sha2-nistp256", "ecdh-sha2-nistp384", "ecdh-sha2-nistp521"]

Important: The default ciphers, macs and key exchange algorithms (for non-FIPS licensed platforms) might not match your security requirements, this list should be reviewed in a per case basis and modified to match your compatibility and security requirements. IETF has deprecated some of the less secure algorithms in RFC 9142: Key Exchange (KEX) Method Updates and Recommendations for Secure Shell (SSH), this document should provide guidelines on the current and recommended algorithms to use.
