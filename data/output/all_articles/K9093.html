Topic

Summary

Microsoft Remote Desktop (MSRDP) persistence relies on a routing token generated by the Windows RDP client to maintain persistent sessions between Windows clients and servers that are running the Microsoft Remote Desktop Protocol (RDP) service.

When you associate an MSRDP persistence profile with a BIG-IP virtual server, the BIG-IP system reads the mstshash routing token and persists the connection to the correct Windows server.

When multiple Windows RDP clients employ usernames where the first nine characters are the same, the sessions may be persisted to the incorrect RDP server.

Important: This behavior is the result of the mstshash routing token nine-character limitation, not a BIG-IP system defect.

Description

By default, the Windows RDP client generates a nine-character routing token in the following format:

Cookie: mstshash=UserName

The routing token uses the RDP client's User Name field, or the username:s: field in the *.rdp configuration file.

When multiple Windows RDP clients employ usernames where the first nine characters are the same, the routing tokens for the three clients are identical, and the sessions may be persisted to the incorrect RDP server.

For example, Windows RDP clients with the usernames msrdpuser1, msrdpuser2, and msrdpuser3 will generate the following routing token:

Cookie: mstshash=msrdpuser

The username character limitation is greatly increased if clients include the Windows domain name when logging in to the RDP server.

For example, Windows RDP clients with the usernames Rachael, Richard, and Rick also include the Windows domain name when logging in will generate the following routing token:

Cookie: mstshash=wdomain/r

Since the routing token is identical for all three clients, the BIG-IP system may persist the RDP sessions to the incorrect RDP server.

Recommendations

Viewing the MSRDP persistence table

To view the current mstshash routing token used by the BIG-IP system to persist a client's connection, type the following command:

# tmsh show /ltm persistence persist-records mode msrdp
Sys::Persistent Connections
msrdp fredrick 192.168.10.1:3389 192.168.10.5:3389 (tmm: 1)
msrdp msrdpuser 192.168.10.10:3389 192.168.10.50:3389 (tmm: 1)
msrdp wdomain/r 192.168.10.100:3389 192.168.10.150:3389 (tmm: 1)

Conserving characters

To conserve characters in the mstshash routing token passed to the BIG-IP LTM system, verify that the Windows domain name exists in the domain:s: field in the *.rdp configuration file.
