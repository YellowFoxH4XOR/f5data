Issue

Note: BIG-IP WebAccelerator and BIG-IP WOM were combined to create BIG-IP AAM in 11.4.0.

By default, the BIG-IP WebAccelerator system checks the hit logs every hour to identify if any of the log files exceed 10 megabytes in size. If a hit log file exceeds 10 megabytes, the system rotates the log(s), and restarts the pvac process, if necessary.

If the hit logs are not rotating properly, the log files may grow indefinitely until they consume all available partition space allocated to the log file system. When this issue occurs, BIG-IP WebAccelerator performance degrades considerably. In addition, the system logs an error message to the /var/log/messages file that appears similar to the following example:

local/RNTF5-0 notice logrotate: wa_logrotate exited abnormally with [1]

To troubleshoot issues related to hit log rotation and to remove oversized hit log files from the system, perform the following procedures:

  • Testing the validity of the log rotation instructions
  • Removing logrotate customizations
  • Removing oversized hit log files in the /var/log/wa/access directory

Testing the validity of the log rotation instructions

You may be able to determine why the hit log rotation failed by using the logrotate command. The following command tests the validity of the log rotation instructions, and may provide an indication as to why log rotation failed:

logrotate -d /var/run/config/logrotate.d/wa

Note: The logrotate -d switch implies the -v switch.

For example, the following command output indicates a duplicate log entry for a hit log file:

# logrotate -d /var/run/config/logrotate.d/wa
reading config file /var/run/config/logrotate.d/wa
reading config info for /var/log/wa/access/*.log /var/log/wa/pvacLog_8081
reading config info for /var/log/wa/stats/*.log /var/log/wa/stats/system/*.log
reading config info for /var/log/wa/stats/perfmonitor/*.log
error: /var/run/config/logrotate.d/wa:26 duplicate log entry for /var/log/wa/access/test_hit_log_file.log

Removing logrotate customizations

BIG-IP WebAccelerator log rotation may fail due to invalid logrotate customizations that were made on the system, for example, using the tmsh or bigpipe commands. You can remove the customizations by performing the following procedure:

  1. Log in to the BIG-IP command line.
  2. To determine if logrotate customizations were made, enter the following command that applies to your BIG-IP WebAccelerator version:
    • Version 11.x and later:

      tmsh list /sys log-rotate wa-include
    • Versions 9.x - 10.x:

      bigpipe logrotate wa include
  3. If the logrotate configuration includes customization, you can remove the configuration by entering the following command that applies to your BIG-IP WebAccelerator version:
    • Version 11.x and later:

      tmsh modify /sys log-rotate wa-include none

    • Versions 9.x - 10.x:

      bigpipe logrotate wa include none

Removing oversized hit log files in the /var/log/wa/access directory

After you determine why logrotation was failing, you should delete any oversized hit log files in the /var/log/wa/access directory. You should also start the pvac process so it no longer references the large files. To do so, perform the following procedure:

  1. Log in to the BIG-IP command line.
  2. List the files in the /var/log/wa/access directory by file size.

    For example, the following output lists a hit log that is greater than 700 megabytes in size:

    ls -lS /var/log/wa/access/
    total 811592
    -rw-r--r-- 1 root root 830211072 Jan 26 14:45 test_hit_log_file.log
    -rw-r--r-- 1 root root 19929 Jan 26 12:42 test_hit_log_file.log.1.gz
    -rw-r--r-- 1 root root 19929 Jan 26 12:41 test_hit_log_file.log.2.gz

  3. Remove any large hit log files.

    For example:

    rm -rf /var/log/wa/access/test_hit_log_file.log*

  4. Restart the pvac process by entering the following command:

    bigstart restart pvac

    On versions 11.4.0 and later restart the wamd process by entering the following command:

    tmsh restart sys service wamd

    Note:  Restarting the pvac or wamd process may temporarily interrupt web accelerated traffic.

Note: In BIG-IP WebAccelerator versions 9.4.2 through 9.4.3, the hit logs are not rotated properly. For more information, refer to K8320: BIG-IP WebAccelerator hit logs are not rotated.
