Description

Is it possible to add Allowed / Disallowed URLs to a Security Policy using the REST API?

Environment

  • Security Policy
  • REST API

Cause

None

Recommended Actions

It is possible to create, modify and delete Allowed or Disallowed URLs using the REST API.

Refer to the steps below, along with examples given using curl:

  • Retrieving a Security Policy MD5 hash identifier (id)
  • Retrieving all URLs in a policy
  • Creating an Allowed URL
  • Creating a Disallowed URL
  • Enforcing a URL
  • Applying a Security Policy
  • Deleting a URL

Retrieving a Security Policy MD5 hash identifier (id)

Retrieve the policy ID by sending a GET request to /mgmt/tm/asm/policies:

curl -sku username:password 'https://localhost/mgmt/tm/asm/policies?$select=name,id&$filter=name%20eq%20<policy name>' | jq .

Example, retrieve the id of a policy named K03519157_policy:

root@v15:Active:Standalone] config # curl -sku admin:password'https://localhost/mgmt/tm/asm/policies?$select=name,id&$filter=name%20eq%20K03519157_policy' | jq .
{
  "kind": "tm:asm:policies:policycollectionstate",
  "selfLink": "https://localhost/mgmt/tm/asm/policies?$select=name%2Cid&ver=15.1.1&$filter=name%20eq%20K03519157_policy",
  "totalItems": 1,
  "items": [
    {
      "kind": "tm:asm:policies:policystate",
      "selfLink": "https://localhost/mgmt/tm/asm/policies/mC-RUkDx14XTLHADQ_3XUg?ver=15.1.1",
      "name": "K03519157_policy",
      "id": "mC-RUkDx14XTLHADQ_3XUg"
    }
  ]
}


Retrieving all URLs in a policy

Retrieve the current URLs in a policy by sending a GET request to /mgmt/tm/asm/policies/{policy id}/urls.

curl -sku username:password 'https://localhost/mgmt/tm/asm/policies/{policy id}/urls' | jq .

Note: Both the Allowed and Disallowed URLs are returned.

Example:

[root@v15:Active:Standalone] config # curl -sku admin:password'https://localhost/mgmt/tm/asm/policies/mC-RUkDx14XTLHADQ_3XUg/urls?$select=protocol,name,type,id' | jq .
{
  "kind": "tm:asm:policies:urls:urlcollectionstate",
  "selfLink": "https://localhost/mgmt/tm/asm/policies/mC-RUkDx14XTLHADQ_3XUg/urls?$select=protocol%2Cname%2Ctype%2Cid&ver=15.1.1",
  "totalItems": 1,
  "items": [
    {
      "protocol": "http",
      "kind": "tm:asm:policies:urls:urlstate",
      "selfLink": "https://localhost/mgmt/tm/asm/policies/mC-RUkDx14XTLHADQ_3XUg/urls/VU9a-pJIEUAJ68P4h-3YvA?ver=15.1.1",
      "name": "/main.php",
      "id": "VU9a-pJIEUAJ68P4h-3YvA",
      "type": "explicit"
    }
  ]
}
  ]
}


Creating an Allowed URL

Create a new Allowed URL by sending a POST to /mgmt/tm/asm/policies/{policy id}/urls. The body must include the URL configuration details.

curl -sku username:password -X POST https://localhostmgmt/tm/asm/policies/{policy id}/urls --data '
{
    "name": "<url name>",
    "protocol": "<protocol>",
    "description": "<description>",
    "performStaging": "<true/false>"
}' | jq .
 

Note: Only name is required. Other properties may optionally be specified.

Example:

[root@v15:Active:Standalone] config # curl -sku admin:password -X POST https://localhost/mgmt/tm/asm/policies/mC-RUkDx14XTLHADQ_3XUg/urls --data '
> {
>   "name": "/main.php",
>   "protocol": "http",
>   "description": "This is a new URL",
>   "performStaging": "true"
> }' | jq .

(response not shown)


Creating a Disallowed URL

To create a disallowed URL add the isAllowed element with value false.

Example:

[root@v15:Active:Standalone] config # curl -sku admin:password -X POST https://localhost/mgmt/tm/asm/policies/mC-RUkDx14XTLHADQ_3XUg/urls --data '
> {
>   "name": "/info.php",
>   "protocol": "http",
>   "description": "This is a disallowed URL",
>   "performStaging": "false"
>   "isAllowed": "false"
> }' | jq .
 


Verifying successful creation

To confirm a URL has been added successfully, repeat the GET to /mgmt/tm/asm/policies/{policy id}/urls.


Enforcing a URL

To Enforce a Staged URL, send a PATCH to /mgmt/tm/asm/policies/{policy id}/urls/{url id}. The body should include the performStaging element with value false.

curl -sku admin:password -X PATCH https://localhost/mgmt/tm/asm/policies/{policy id}/urls/{url id} --data '
{
   "performStaging": "false"
}' | jq .

Example:

[root@v15:Active:Standalone] config # curl -sku admin:password -X PATCH https://localhost/mgmt/tm/asm/policies/mC-RUkDx14XTLHADQ_3XUg/urls/VU9a-pJIEUAJ68P4h-3YvA --data '
> {
>    "performStaging": "false"
> }' | jq .

(Response not shown)


Applying a Security Policy

At this point you may want to apply the policy. This can be done by sending a POST to /mgmt/tm/asm/tasks/apply-policy, with the id of the policy in the body:

curl -sku username:password -X POST https://localhost/mgmt/tm/asm/tasks/apply-policy --data '
{
    "policyReference": {
        "link": "https://localhost/mgmt/tm/asm/policies/{policy id}"
        }
}' | jq .

Example:

[root@v15:Active:Standalone] config # curl -sku admin:password -X POST https://localhost/mgmt/tm/asm/tasks/apply-policy --data '
> {
> "policyReference": {
>  "link": "https://localhost/mgmt/tm/asm/policies/mC-RUkDx14XTLHADQ_3XUg"
> }
> }' | jq .

(Response not shown)


Deleting a URL

To delete a URL, send a DELETE request to /mgmt/tm/asm/policies/{policy id}/urls/{url id}:

curl -sku username:password -X DELETE https://localhost/mgmt/tm/asm/policies/{policy id}/urls/{url id}| jq .

Example:

[root@v15:Active:Standalone] config # curl -sku admin:password -X DELETE https://localhost/mgmt/tm/asm/policies/mC-RUkDx14XTLHADQ_3XUg/urls/VU9a-pJIEUAJ68P4h-3YvA | jq .

(Response not shown)

Additional Information

Similar procedures may be used to manage other Security Policy configuration items.
