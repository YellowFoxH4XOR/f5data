Known Issue

The BIG-IP WebAccelerator may not process PDF files properly. This issue occurs when the linearization engine encounters a PDF construct introduced in a later version than the version of the file being processed. For example, if a PDF 1.4 feature appears in a PDF 1.3 document, the BIG-IP WebAccelerator does not process the PDF properly and returns a stack error to the client. When this occurs, the BIG-IP WebAccelerator logs an error message that appears similar to the following example:

GPL Ghostscript 8.63: Unrecoverable error, exit code 1

In BIG-IP WebAccelerator versions 9.4.7 and 9.4.8, the error message is reported in the /var/log/wa/pvac.log file; in BIG-IP WebAccelerator versions 10.0.0 and 10.0.1, the error message is reported in the /var/log/user.log file.

Note: The stack error content that is returned to the client is not displayed by the PDF reader, but can be observed using an HTTP header viewer, such as Live HTTP Headers.

In addition, the PDF reader may report an error message that appears similar to the following example:

File does not begin with '%PDF-'.

F5 Product Development tracked this issue as ID 208448 (formerly CR122353) and it was fixed in BIG-IP version 10.1.0. For information about upgrading, refer to the BIG-IP WebAccelerator release notes.

Additionally, this issue was fixed in BIGIP-10.0.1-378.0-HF3 issued for BIG-IP version 10.0.1, and Hotfix-BIGIP-9.4.8-407.0-HF4 for BIG-IP version 9.4.8. You may download these hotfixes or later versions of the cumulative hotfixes from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about the F5 hotfix policy, refer to K4918: Overview of F5 critical issue hotfix policy.

For information about installing 10.x hotfixes on a Logical Volume Management (LVM) disk-formatted system, refer to in K10025: Managing F5 product hotfixes for BIG-IP version 10.x systems.

For information about installing 10.x hotfixes on a partitioned system, refer to K9819: Installing a BIG-IP version 10.x hotfix on a partitioned system.

Workaround

You can use one of the following three workarounds:

Disable PDF linearization on the BIG-IP WebAccelerator

To disable PDF linearization on the BIG-IP WebAccelerator, following the procedure in K9408: Enabling and disabling PDF linearization on the BIG-IP WebAccelerator.

Use an iRule to bypass the WebAccelerator module when the URI contains a request for a PDF document

In addition, you can create an iRule to bypass the WebAccelerator module when the URI contains a request for a PDF document.

Note: Disabling content based identity as outlined in SOL8379 does not work in this instance.

For example, in BIG-IP WebAccelerator version 9.4.7, the following iRule bypasses the WebAccelerator module when the URI contains a request for a PDF document:

when HTTP_REQUEST {
  if { [HTTP::uri] contains ".pdf" } {
    HTTP::class disable
    CACHE::disable
  }
}

In BIG-IP WebAccelerator version 10.0.1, the following iRule bypasses the WebAccelerator module when the URI contains a request for a PDF document:

when HTTP_REQUEST {
  if { [HTTP::uri] contains ".pdf" } {
    WAM::disable
  }
}

Modify the linearization script

This more advanced workaround allows linearization to occur for all PDF files that do not cause the linearization engine to fail. For more information and assistance with implementing this workaround, contact F5 Technical Support and mention this article number.
