K000133696: BIG-IP does not send out GARPs if static routes exist for local self-ip subnets

Type
Support Solution
Published
2023-04-28
Updated
2025-10-25
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.6
Source
https://my.f5.com/manage/s/article/K000133696

Description

After a failover event, the newly active BIG-IP device may not send Gratuitous ARP (GARP) packets out for the failover objects.

Environment

The following conditions are required:

  • BIG-IP in an HA pair (device-group)
  • Failover objects are configured (VIP, Floating Self-IP, etc..)
  • Floating self-IP object(s) are associated with the traffic-group, for example 192.168.0.0/24
  • Static routes are configured for the same subnet with a longer subnet mask than is defined for the self-ip for example 192.168.0.0/25, 192.168.0.128/25

Cause

The presence of a static route for part of a subnet within the range of the self-ip means that from TMM's point of view, the failover objects that fall within the static route range are not directly-connected, and therefore not local.

For example, with a self-ip with a /24 mask, and a static route inside that range with a /25, or /26, or /27 etc,  the IP addresses covered by the static route will be seen as remote addresses, and GARP packets for those addresses will not be sent out.

 

Recommended Actions

Do not configure static routes for destination ranges that exist within a configured self-ip's subnet.
