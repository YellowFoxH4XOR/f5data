Known Issue

The BIG-IP system may erroneously mark a virtual server as available when the associated default pool status is offline. This issue occurs when all of the following conditions are met:

  • The virtual server is associated with an iRule that uses the HSL::open command.
  • The HSL::open command references a high-speed logging (HSL) pool directly using the -pool option.
  • The status of the HSL pool that is referenced by the iRule is available.

This issue occurs because the affected virtual server incorrectly considers the status of the HSL pool that is referenced by the iRule instead of considering only the associated default pool status when determining its own status.

Impact

The affected virtual server incorrectly continues to send traffic to the offline default pool.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The affected virtual server status is reported as available when its associated pool status is reported as offline.
  • The client establishes connectivity but observes failure when requesting for content.

Resolution

Status

F5 has confirmed that this issue exists in the products listed in the Applies to (see versions) box, located in the upper-right corner of this article. Workaround

To work around this issue, you can modify the iRule associated with the affected virtual server by substituting the HSL pool name with a variable for the -pool option of the HSL::open command. This allows the HSL::open command to indirectly reference the HSL pool. To do so, perform the following procedure:

Impact of workaround: The following iRule may not apply to all environments. F5 recommends that you create an iRule that works best for your application environment. Additionally, adding an iRule increases the resources that the associated virtual server uses. Depending on the type and volume of the connections, this processing may introduce noticeable latency. F5 recommends that you test any such changes in an appropriate environment.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules > iRule List.
  3. Click the name of the iRule associated with the affected virtual server.
  4. Locate the HSL::open iRules command.

    For example:

    set hsl [HSL::open -proto UDP -pool myexamplehslpool]

  5. Set a variable to reference the HSL pool and substitute the pool name with the variable for the HSL::open command. Using the previous example, the modified statement should look similar to the following example:

    set mypool myexamplehslpool
    set hsl [HSL::open -proto UDP -pool $mypool]

  6. Click Update.
