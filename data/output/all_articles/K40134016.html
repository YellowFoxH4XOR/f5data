Description

When remote user (Administrator Role) generate the qkview via Configuration Utility, get the error below, stuck at this page:

Internal server error while authorizing request

The same remote user is able to generate the qkview via Advanced shell (bash).
The local user (like admin) is able to generate the qkview via Configuration Utility.
When the issue happened, you can find the log in the log file /var/log/restjavad-audit.0.log:

[I][<PID>][<Date time> UTC][ForwarderPassThroughWorker] {"user":"local/null","method":"POST","uri":"http://localhost:8100/mgmt/shared/authn/login","status":200,"from":"<Client IP>"}
[I][<PID>][<Date time> UTC][ForwarderPassThroughWorker] {"user":"tmos/<remote username>","method":"GET","uri":"http://localhost:8100/mgmt/tm/sys/diags/ihealth-result","status":500,"from":"<Client IP>"}
[I][<PID>][<Date time> UTC][ForwarderPassThroughWorker] {"user":"tmos/<remote username>","method":"GET","uri":"http://localhost:8100/mgmt/tm/sys/diags/ihealth-request","status":500,"from":"<Client IP>"}
[I][<PID>][<Date time> UTC][ForwarderPassThroughWorker] {"user":"tmos/<remote username>","method":"GET","uri":"http://localhost:8100/mgmt/tm/sys/db/setup.run","status":500,"from":"<Client IP>"}

Environment

  • BIG-IP
  • Configuration Utility
  • Remote user
  • qkview

Cause

It is caused by the corrupted mcpd database.

Recommended Actions

The solution is, rebuild the mcpd database, for the details, please refer to the article K13030:  Forcing the mcpd process to reload the BIG-IP configuration.
Note: Please perform the operation in a maintenance window.

Additional Information

None.
