Description

Sending a tls request to a NIC service where ip address issue used in the request then the connection may fail with an ssl error, unrecognized name. For example:

$ curl https://<nic_ip>/coffee -H "Host: cafe.example.com" -v
* Trying <nic_ip>:443...
* Connected to <nic_ip> (<nic_ip>) port 443
* ALPN: curl offers h2,http/1.1
* (304) (OUT), TLS handshake, Client hello (1):
* CAfile: /etc/ssl/cert.pem
* CApath: none
* LibreSSL/3.3.6: error:1404B458:SSL routines:ST_CONNECT:tlsv1 unrecognized name
* Closing connection
curl: (35) LibreSSL/3.3.6: error:1404B458:SSL routines:ST_CONNECT:tlsv1 unrecognized name

Environment

NGINX Ingress Controller

Cause

When the tls sni name (in tls handshake) does not match the common name in the tls server certificate configured for the requested NGINX Ingress Controller service then that certificate will not be used. If a default certificate is not specified (command line argument -default-server-tls-secret <string>) then the request will fail with ssl error unrecognized name (see error in example above).

Recommended Actions

If installing NGINX Ingress Controller using manifests then set the following command line argument:

 default-server-tls-secret <string>

If installing NGINX Ingress Controller using helm then set the following values attribute:

 controller.defaultTLS.secret: <namespace>/<name>
