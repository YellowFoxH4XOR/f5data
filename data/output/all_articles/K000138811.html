Description

SYN/ACK that has traversed a fastl4 virtual server on rSeries (r5000 or above) or VELOS BIG-IP tenant is dropped by client, or client issues a TCP reset.

Environment

  • fastl4 traffic
  • Tenant on VELOS or rSeries platform with FPGA hardware (r5000 or above)
  • PVA accelerated traffic (e.g. via IP forwarding virtual server)
  • AFM provisioned

Cause

Bug ID 1391525: Timestamp Cookies and ePVA acceleration are incompatible on VELOS and rSeries platforms

The traffic is PVA accelerated and TS cookies are enabled in the AFM device DoS configuration.

security dos device-config /Common/dos-device-config {
    <...>
    dos-device-vector {
        tcp-ack-ts {
        <...>
        tscookie enabled
    }
    <...>
}

In the below example, the SYN/ACK is returned to the client with an invalid timestamp echo reply value, triggering a reset.

Frame  SRC IP       DST IP       TCP Flags      TSVal        TSEchoReply
1      10.10.10.1   172.16.10.1  ··········S·   527014845    0          <-- SYN towards BIG-IP/rSeries      [Client-side]
2      10.10.10.1   172.16.10.1  ··········S·   1771813915   0          <-- SYN towards server              [Server-side]
3      172.16.10.1  10.10.10.1   ·······A··S·   1099898348   1771813915 <-- SYN/ACK towards BIG-IP/rSeries  [Server-side]
4      172.16.10.1  10.10.10.1   ·······A··S·   1099898348   1771813915 <-- SYN/ACK towards client          [Client-side]
5      10.10.10.1   172.16.10.1  ·········R··  <------------------------<-- Reset from client               [Client-side]

A timestamp value of 527014845 is provided in the client SYN in frame 1. This is the value that should be used for the timestamp echo reply value in the server SYN/ACK towards the client in frame 4. Note the incorrect value of 1771813915 from the server-side flow is used.

Recommended Actions

ID1391525 doesn't yet have a fix at the time of this article's publication, but there are a couple of workarounds.

Either disable TS cookies in the AFM device DoS configuration, or disable PVA acceleration in the relevant fastl4 profile.

Additional Information

This issue only affects PVA accelerated traffic.
