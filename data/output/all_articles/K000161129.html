K000161129: RST_STREAM with error code: PROTOCOL_ERROR in Nginx agent log

Type
Support Solution
Published
2026-05-05
Updated
2026-05-05
Applies to
  • NGINX Products
  • NGINX Instance Manager: 2.21.0
Source
https://my.f5.com/manage/s/article/K000161129

Description

RST_STREAM PROTOCOL_ERROR errors appear in the NGINX Agent log when streaming metrics to NGINX Instance Manager through an NGINX OSS proxy. Metrics reporting fails, and HTTP connection/request metrics are not visible in NGINX Instance Manager. The issue does not occur when the Agent connects directly to NGINX Instance Manager, bypassing the proxy.

Environment

  • NGINX Agent v2.45.2
  • NGINX Instance Manager v2.21.0
  • NGINX OSS proxy between Agent and Instance Manager
  • Agent configuration: ssl_verify true
  • Proxy configuration using HTTP/2 and gRPC pass-through for metrics channel

Cause

NGINX Agent does not support proxy functionality for metrics streaming via HTTP/2/gRPC. Proxying gRPC traffic through NGINX OSS using HTTP/2 breaks the protocol, resulting in RST_STREAM PROTOCOL_ERROR. The Agent requires direct L4 TCP passthrough to NGINX Instance Manager for gRPC communication.

Answer/Recommended Actions

To resolve the issue:

  1. Switch Proxy Configuration to Stream Context (L4 TCP Passthrough):
    • Use the NGINX stream module to proxy TCP connections directly to NGINX Instance Manager.
    • Remove unsupported directives (e.g., status_zone) from stream context if using NGINX OSS.
  2. Example NGINX OSS Stream Configuration:

    stream {
    upstream stream_backend {
    zone tcp_servers 64k;
    server instance-manager-1.example.com:443;
    }
    log_format basic '$remote_addr [$time_local] '
    '$protocol $status $bytes_sent $bytes_received '
    '$session_time "$upstream_addr" '
    '"$upstream_bytes_sent" "$upstream_bytes_received" "$upstream_connect_time"';
    access_log /var/log/nginx/nginx1_access.log basic;
    error_log /var/log/nginx/nginx1_error.log debug;
    server {
    listen 5000;
    proxy_pass stream_backend;
    proxy_next_upstream on;
    }
    }

  3. Agent Configuration:
    • Set command: and metrics: parameters to your NGINX Instance Manager server's hostname.
  4. Restart Services:
    • Restart NGINX OSS proxy, NGINX Instance Manager, and NGINX Agent after making configuration changes.
  5. Monitor Metrics Reporting:
    • Confirm that metrics are successfully reported in NGINX Instance Manager.

Additional Information

  • The issue is not specific to NGINX OSS; NGINX Plus as a proxy does not resolve the problem, as the Agent does not support proxying for metrics streaming.
  • Direct connection from Agent to NGINX Instance Manager (without proxy) works as expected.
  • For NGINX One Console proxy configuration, refer to the official documentation.
