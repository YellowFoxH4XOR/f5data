Known Issue

The mcpd process may enter a restart loop after you disable the default admin account on a VIPRION system.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system runs on a VIPRION platform configured with one or more secondary blades.
  • You attempt to configure a new user account with the 'admin' role to replace the default admin account by using the Traffic Management Shell (tmsh) or the Configuration utility.

    Note: The 'admin' role specified in the tmsh utility is also known as the 'Administrator' role in the Configuration utility.

Beginning in BIG-IP 11.6.0, you can replace the default admin account with another administrative account by modifying the value of the systemauth.primaryadminuser database key with the desired administrative account. This database key has a default value of 'admin' and replacing this value will cause the default admin account to be disabled. For more information, refer to K15632: Disabling the admin and root accounts using the BIG-IP Configuration utility or the Traffic Management Shell.

Impact

Network traffic may be interrupted when the mcpd process on secondary blades enter into the restart loop. If the affected system is configured with a high-availability redundancy, the system may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The mcpd process restarts continuously on the secondary blades.
  • The secondary blades log error messages to the /var/log/ltm file that appear similar to the following example:

    err mcpd[26012]: 010718e7:3: The requested primary admin user (admin-primary1) must have a password set.
    err mcpd[26012]: 01070734:3: Configuration error: Configuration from primary failed validation: 010718e7:3: The requested primary admin user (admin-primary1) must have a password set.... failed validation with error 17242343.

Workaround

There is no workaround for this issue. To recover the secondary blades from the mcpd restart loop, you can re-enable the default admin account. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Advanced Shell (bash) of the BIG-IP system.
  2. Access the tmsh utility by typing the following command:

    tmsh

  3. Re-enable the default admin user account by typing the following command:

    modify /sys db systemauth.primaryadminuser value admin

  4. Save the changes by typing the following command:

    save /sys config
