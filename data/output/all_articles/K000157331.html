Description

When you are setting up F5 WAF for NGINX an issue occurs and it fails to load.

  • Load failure due to a manifest failing to open.
  • You may see something similar to these log entries...
BD_MISC|CRIT  |Oct 29 08:32:30.169|0013|/builds/t1_j2fGn9/7/waf/waf-general/secore/bd/bd/manifest_listener.cpp:0203|failed to get manifest last modification time, err: No such file or directory
Timeout detected while waiting for configuration. time since last config: 40 BD aborting
BD_MISC|WARN  |Oct 29 08:32:30.170|0013|/builds/t1_j2fGn9/7/waf/waf-general/secore/bd/bd/manifest_listener.cpp:0204|Timeout detected while waiting for configuration. time since last config: 40 BD aborting
BD_MISC|ERR   |Oct 29 08:32:30.170|0013|/builds/t1_j2fGn9/7/waf/waf-general/secore/bd/bd/manifest_listener.cpp:0116|failed opening manifest out file. path=/opt/app_protect/bd_config/tables/bd_cfg_manifest_load_state.json
2025/10/29 08:32:30 /usr/share/ts/bin/bd-socket-plugin failed: exit status 1
2025/10/29 08:32:30 Command exited with code: 1

Environment

  • NGINX App Protect WAF
  • All version 5.x

Cause

The cause can be a missing or incorrectly mounted volumes, missing compiled policy bundles, or when the waf-enforcer container starts with all app_protect_enable directives set to OFF and no policy bundle present. 

This error sequence indicates that the NAP "bd" (Big Daemon) process is unable to find or access its manifest state file (commonly bd_cfg_manifest_load_state.json). The process waits for a configuration update, times out after 40 seconds, and then aborts. The final error is a failure to open the manifest output file, which causes the process to exit with a non-zero status.

The most common causes are:

  1. Missing or Unmounted Directory/Volume
    1. The directory where the manifest file should be written does not exist, is not mounted, or is not writable. This is especially common in Kubernetes or Docker environments if the required volume is not mounted or is ephemeral.
  2. Permissions Issues
    1. The directory exists but is not writable by the NGINX user.
  3. Incorrect or Missing Policy/Bundle Files
    1. For NAP v5+, you must use compiled policy bundles (.tgz files). If these are missing or not referenced correctly, the manifest cannot be generated.
    2. See NGINX App Protect WAF Compiler Guide.
  4. Startup/Deployment Race Condition
    1. In containerized environments, if the config manager or policy files are not ready when the enforcer starts, this error can occur.

In some rare case it can also happen when the waf-enforcer container starts with all app_protect_enable directives set to OFF and no policy bundle present, it waits for a policy configuration for 40 seconds by default. If none arrives, the process times out and exits as designed unless ENFORCER_CONFIG_TIMEOUT is set to allow indefinite waiting.

Recommended Actions

1. Check Volume Mounts and Directory Existence

  • Ensure the directory (e.g., /opt/app_protect/bd_config/tables/) exists and is mounted in all relevant containers (waf-enforcer, waf-config-mgr).
  • In Kubernetes, verify your volumeMounts and volumes sections in the deployment YAML.

2. Check Permissions

  • The directory and files should be owned by the nginx user and group, and be writable.
  • Example commands:
chown -R nginx:nginx /opt/app_protect/bd_config
chmod -R 755 /opt/app_protect/bd_config

3. Ensure Compiled Policy Bundles Are Present

  • For NAP v5+, use the waf-compiler to generate .tgz bundles and place them in the correct volume.
  • Reference the bundle in your NGINX config as per official documentation.

4. Restart the Affected Pods/Services

  • After correcting the above, restart the NGINX App Protect services or pods to trigger a new configuration load.

5. If all the app_protect_enable directives are set to OFF set the waf-enforcer to wait indefinitely by setting the ENFORCER_CONFIG_TIMEOUT env variable to 0 in the yaml deployment file.

env:
  - name: ENFORCER_CONFIG_TIMEOUT
    value: "0"

Additional Information

  • By default, waf-enforcer waits up to 40 seconds for a policy before exiting if none is provided, or iit cannot be accessed.
  • Setting ENFORCER_CONFIG_TIMEOUT to "0" allows indefinite waiting—useful when starting containers with no initial policy.
  • This behavior may not be fully documented in all NGINX App Protect guides but is referenced in some related documentation.
