Topic

This article applies to BIG-IP Link Controller version 9.x through 10.x. For information about other versions, refer to the following articles:

  • K13466: Configuring the BIG-IP Link Controller to shorten the time taken to detect a status change in a virtual server (11.x)

The BIG-IP Link Controller monitors the availability and performance of multiple ISP connections to intelligently manage incoming and outgoing traffic flows. To do so, the BIG-IP Link Controller includes selected LTM system and GTM system features. Within the same BIG-IP Link Controller, the LTM system and GTM system components communicate with each other using the iQuery architecture.

To establish an iQuery connection between the two components, the BIG-IP Link Controller automatically assigns a special monitor named bigip to itself.  The bigip monitor tells the gtmd process to connect to a BIG-IP device and periodically poll its configuration, including the current availability of objects, such as virtual servers. Because the BIG-IP Link Controller assigns the bigip monitor to itself, the gtmd process learns and monitors the LTM configuration running on the local host.

For example, shortly after configuring a new virtual server, the GTM system side of the Link Controller will learn of the virtual server's existence and it will be possible to assign the new virtual server to a wide IP; the bigip monitor is responsible for this process.

By default, the bigip monitor has an interval of 30 seconds. Depending on when the next configuration update is due, the gtmd process may take up to 30 seconds to detect a status change in a virtual server. During this time, a wide IP may direct traffic to a virtual server that is currently marked as down under Local Traffic >> Virtual Servers.

The Configuration utility allows you to create a custom bigip monitor with a shorter interval; however, it does not allow you to assign this monitor to the BIG-IP Link Controller.

If you want the gtmd process to receive more frequent updates from the LTM side of the BIG-IP Link Controller, perform the following two procedures:

Configuring a custom bigip monitor

This procedure uses the Configuration utility to create a custom bigip monitor with a shorter interval:

  1. Log in to the Configuration utility of the BIG-IP Link Controller.
  2. Navigate to Link Controller >> Monitors.
  3. Click the Create button.
  4. From the Type drop-down menu, select BIG-IP.
  5. From the Import Settings drop-down menu, select bigip.
  6. Enter a name for the new monitor; for example, my_bigip_monitor.
  7. Ensure that all configuration options are visible by selecting Advanced from the Configuration drop-down menu.
  8. Enter custom Interval and Timeout values, for example, 3 and 9 seconds. An interval of 3 seconds means that the gtmd process will receive an LTM configuration update every 3 seconds.

    Important: F5 recommends that you set an interval of at least 3 seconds. Additionally, the timeout value should be three times the interval value.

  9. Click the Finish button.

Assigning a custom bigip monitor to the BIG-IP Link Controller

This procedure uses the command line to manually assign a custom bigip monitor to the BIG-IP Link Controller:

  1. Log in to the command line of the BIG-IP Link Controller.
  2. Change directories to the /config/gtm/ directory by typing the following command:

    cd /config/gtm/

  3. Make a backup of the wideip.conf file by typing the following command:

    cp wideip.conf wideip.conf.SOL12087

  4. Using the text editor of your choice, open the wideip.conf file.
  5. Locate a section that appears similar to the following example:

    Note: A standalone BIG-IP Link Controller system should include only one server definition; redundant BIG-IP Link Controller systems should include two server definitions.

    // *** Server Definitions (1) ***

    server { // datacenter=Default DC, #VS=0
       name            "LinkController.example.com"
       type            bigip
       box { // gtm
          address 10.0.0.1
          unit_id 1
       }
       autoconf        enable
       monitor "bigip"
    }

  6. Edit the monitor statement, as required. For example, replace monitor "bigip" with monitor "my_bigip_monitor" to use the custom monitor created in the previous procedure.

    Note: If two server definitions are present (indicating that the unit is part of a high-availability pair), you can edit both server definitions.

  7. Save the changes and exit the editor.
  8. Reload the GTM configuration by typing the following command:

    gtmload -l
