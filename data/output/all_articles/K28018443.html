K28018443: After upgrade to 16.1.x, CPU usage remain high.

Type
Support Solution
Published
2021-10-13
Updated
2023-06-20
Applies to
  • BIG-IP
  • BIG-IP FPS: 16.1.X, 16.1.3, 16.1.2, 16.1.1, 16.1.0
  • BIG-IP ASM: 16.1.X, 16.1.3, 16.1.2, 16.1.1, 16.1.0
Source
https://my.f5.com/manage/s/article/K28018443

Description

After upgrade/booting up from 16.1.x, odd number CPU usage went high, and remain high for over 1 day.
 

Environment

  • BIG-IP ASM/FPS provisioned
  • v16.1.x
  • Upgraded
     

Cause

This is due to the BUG ID1060393 which causes the obfuscator to take more time generating rows resulting in extended high CPU by datasyncd.

Recommended Actions

To check if you hit this known issue, 
  1. determine if java is the cause of high CPU, using ps/top command
  2. determine if the java process has datasyncd as parent process.
  3. check log /var/log/datasync/datasyncd.log has similar to below logs:  
    DATASYNCD|NOTICE|Oct 12 10:11:41.312|14248|datasyncd_main.c:5399|obfuscator_prepare_config: This will obfuscate 5 rows, with 164 remaining to be obfuscated.
...
DATASYNCD|NOTICE|Oct 12 10:13:10.815|14248|datasyncd_main.c:4294|count_generated_rows: counted 1 more generated rows on table CS_ASM_DOSL7, reaching 833 / 1001 rows.
            If this is the case, please generate fresh qkview and raise a case to F5 Support.
            NOTE: there should not have any performance degradation as the java which has datasyncd as parent process is running nice 19, means lowest priority.
  1. Run the following command to check the time between row generations: 
    $ grep -e 'count_generated_rows' /var/log/datasync/datasyncd.log | sed -r 's/\s{2,}/ /g'
