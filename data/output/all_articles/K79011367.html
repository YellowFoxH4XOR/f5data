K79011367: Using the 'Auto detect' option for a parameter to reduce false positive violations

Topic

You should consider using this procedure under the following condition:

  • You want to reduce false positive violations caused by attack signatures.

Description

A false positive violation occurs when the BIG-IP ASM security policy detects a security violation for a valid request to the web application. In some cases, a legitimate request to your web application causes the system to report a false positive for an attack signature.

Starting in BIG-IP ASM 15.1.0, you can use the Auto detect parameter value type for identifying certain parameter values. Using this option may reduce the frequency of false positive violations for some types of traffic. For example, you can select Auto detect for the parameter value type if XML/JSON might be part of the parameter payload. If the security policy detects XML or JSON parameter values in the request, the system indicates that the violation is most likely a false positive. If the policy discovers that the JSON or XML is non-compliant or malformed, the content is handled as alphanumeric and the system generates a violation. You can specify the Auto detect parameter value type for any kind of parameter, including wildcard or explicit.

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You have access to the Configuration utility.

Procedures

Configuring the Auto detect option for a parameter

To configure the Auto detect option for a parameter, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Security > Application Security > Parameters > Parameters List.
  3. Select Create.
  4. Enter a name for the parameter in the Parameter Name field, and select one of the following parameter types:
    • Explicit: Specifies that this parameter is a regular named parameter.
    • No Name: Specifies that this parameter does not have a name.
    • Wildcard: Specifies that any parameter name that matches the wildcard expression is permitted by the security policy.
  5. Select one of the following options from the Parameter Level field:
    • Global Parameter: Specifies that this is a global parameter and so it has no association with flows or URLs.
    • URL Parameter: Specifies that this is a URL parameter and is associated with a specific URL.
    • Flow Parameter: Specifies that this is a flow parameter and is associated with a specific flow.
  6. Select the appropriate option from the Location field.
  7. Select Auto detect from the Parameter Value Type field.
  8. Select Create.
  9. Select Apply Policy to apply the changes.

Viewing Event log details for violations marked as likely false positives

To view Event log details for violations marked as likely false positives, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to Security > Event Logs > Application > Requests.
  3. Select the Open Filter icon.
  4. For BIG-IP Advanced WAF/ASM 17.x, select the Advanced tab. For BIG-IP Advanced WAF/ASM 16.x and earlier, select the IP / Username / URL tab.
  5. For BIG-IP Advanced WAF/ASM 17.x, select Detected for the Potential False-Positive setting. For BIG-IP Advanced WAF/ASM 16.x and earlier, select Potential False-Positive Attack Signature Detected or Likely False-Positive Attack Signature Detected.
  6. Select Apply Filter.
  7. Select a Request record to examine the details of the request marked as a likely false positive violation.
