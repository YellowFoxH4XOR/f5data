Description

On BIG-IP APM systems, the /config partition may become full, resulting in degraded performance or system issues. This is typically identified by running disk usage commands (such as df -h) and observing that the /config partition has reached 100% utilization. Common symptoms include inability to save configuration changes or perform normal operations due to lack of available space. Investigation often reveals that large files, particularly OPSWAT EPSEC package files, are consuming significant space within the /config directory.

# df -h
Filesystem                             Size  Used Avail Use% Mounted on
/dev/mapper/vg--db--sda-set.3._config  3.2G  3.0G     0 100% /config

Environment

  • BIG-IP APM
  • /config partition at or near 100% usage
  • Multiple large epsec_package files present in the filestore under /config

Cause

Excessive accumulation of large, obsolete OPSWAT EPSEC package files in the /config partition, specifically under the filestore directory for epsec_package objects, resulting in storage exhaustion.

Recommended Actions

  • Identify large files in the /config partition using the following command:
    find /config/ -xdev -type f -exec du -h {} \; | sort -rh | head -20
  • Remove unnecessary OPSWAT EPSEC package files by following the procedure outlined in F5 article K21175584: Removing unnecessary OPSWAT EPSEC packages from the BIG-IP APM system.
    Important: Do not delete these files directly using Linux commands; always use the documented process to ensure system integrity.
  • Monitor /config partition usage regularly to prevent recurrence.
  • Consider implementing a maintenance routine to periodically review and remove obsolete package files.

Additional Information

Deleting EPSEC package files directly from the file system is not supported and may cause configuration or system issues. Always use the recommended procedure for removal.
