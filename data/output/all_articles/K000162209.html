Title

Printing Fails with BIG-IP APM: Connection Reset When URI Contains Special Characters (Caret ^, etc.)

 

1. Description

When using BIG-IP APM (Access Policy Manager) on a virtual server, attempts to print files from a web application may fail. Symptoms include blank screens, broken PDF report popups, and browser errors such as net::ERR_CONNECTION_RESET. The backend server does not receive the print job requests. This occurs when the print job URL contains special characters (such as the caret ^) in query parameters, e.g., ?PrintType=TAXINVandINRSHARE&RefNo=lkyafafaOmMrX2352532ffKA==,^lkyvnk245lknmdswfvPZZ4ffKA==,. Packet captures show TCP RST packets from the BIG-IP with the cause "Access encountered an error (Operation not supported)".

2. Environment

  • BIG-IP APM module, version 17.5.1.6
  • Virtual server with LTM pool and APM access policy for authentication
  • Application print job URLs containing special characters (e.g., ^, {, }, |) in query parameters

3. Cause

Bug ID2298245

 

4. Answer/Recommended Actions

To resolve the issue, apply an iRule to the affected virtual server to URL-encode problematic characters (^, {, }, |) before APM processes the URI:

 

when HTTP_REQUEST priority 100 {

  set my_uri [HTTP::uri]

  if { ($my_uri contains "^") or ($my_uri contains "{") or ($my_uri contains "}") or ($my_uri contains "|") } {

    HTTP::uri [string map {"^" "%5E" "{" "%7B" "}" "%7D" "|" "%7C"} $my_uri]

  }

}

 

Alternatively, upgrade BIG-IP to version 17.5.1.7 or later, which contains the permanent fix for this bug.

Ensure testing is performed with a new client connection and cleared access session to verify resolution.

 

5. Additional Information

  • The APM HUD filter in BIG-IP 17.5.1.6+ enforces strict RFC 3986 URI compliance and rejects HTTP requests containing non-compliant characters, resulting in immediate connection resets.
  • Printing works as expected when only LTM is enabled (no APM access policy).
