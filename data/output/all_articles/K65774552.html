Description

Some connections can not be completed and in /var/log/ltm logs as the following are seen:
Error Message: 011e0003:4: Aggressive mode sweeper: <policy> (<context>) <#> Connections killed

Environment

  • vCMP Guest with limited resources.
  • High memory usage
  • Aggressive mode sweeper activated.
     

Cause

This happens in a high memory usage environment. The device has reached the threshold so protection is activated and according to the sweeper function settings, some connections are killed.
The adaptive connection reaper continues to reap connections while memory utilization or connection flows exceed activation thresholds.

Recommended Actions

  1. Change profiles to lower resources 
If you have connections that are kept for a longer time than needed, consider releasing connections as the default protocol profile indicates. Maintaining idle connections longer time consumes additional memory. 
 
K7606: Overview of BIG-IP idle session timeouts
K7166: Changing the idle timeout for a protocol profile
  1. Change low-water hi-water thresholds 
The system comes with a default eviction policy named default-eviction-policy. The default eviction policy uses values of 85% for low-water and 95% for high-water levels and has the Bias Idle and Bias Oldest algorithms selected. You should not modify the values of a default policy. If you want non-default values, you should create a customer eviction policy. For information about configuring an eviction policy with custom values, refer to
 
K15822: Configuring custom eviction policies

 
If you have determined that the issue is capacity related...
  1. Add more cores and assign more memory to the vCMP guest
K64791553: Increasing CPU and memory resources on a deployed vCMP Guest
