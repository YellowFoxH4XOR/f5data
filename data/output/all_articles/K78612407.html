Known Issue

The BIG-IP system fails to process traffic when creating a FIPS hardware security module (HSM) certificate.

This issue occurs when the following condition is met:

  • You attempt to create a FIPS certificate signing request (CSR) when the BIG-IP system processes heavy FIPS traffic.

Impact

The BIG-IP system temporarily fails to process production traffic if certificate creation takes longer than expected.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The FIPS certificate creation times out under heavy FIPS traffic.
  • The BIG-IP system fails over to the standby system.
  • The BIG-IP system reports a message to the /var/log/tmm file that appears similar to the following example:

    crit tmm7[12345]: 01010025:2: Device error: crypto codec fips-crypto0-7 queue is stuck

  • The BIG-IP system reports messages to the /var/log/ltm file that appears similar to the following example:

    sod[8147]: 01140029:4: HA crypto_failsafe_t fips-crypto0-1 fails action is failover
    sod[8147]: 010c0018:5: Standby

Workaround

To work around this issue, you can increase the crypto.queue.timeout database variable from the default value of 100 to 2000 milliseconds on the affected HA systems. To do so, perform the following procedure:

Impact of workaround: The impact of the suggested workaround depends on the specific environment. F5 recommends that you test any such changes during a maintenance window and consider the possible impact to your specific environment.

  1. Log in to the TMOS Shell (tmsh) by typing the following command:

    tmsh

  2. To increase the crypto queue timeout value to 2000, type the following command:

    modify /sys db crypto.queue.timeout value 2000

  3. Repeat the previous steps on the HA peer system.
