Known Issue

The BIG-IP WebAccelerator or BIG-IP AAM system may fail to load a configuration after an upgrade to BIG-IP 11.x.

Note: BIG-IP WebAccelerator and BIG-IP WOM were combined to create BIG-IP AAM in BIG-IP 11.4.0.

This issue occurs when either of the following conditions is met:

  • You attempt to upgrade a BIG-IP WebAccelerator or BIG-IP AAM system with a configuration that contains a published policy with no nodes.
  • You attempt to install a BIG-IP 10.x user configuration set (UCS) that contains a configuration with a published policy with no nodes.

While it is possible to configure a policy that has no nodes, the policy does not accelerate content and may incur unnecessary processing.

Impact

  • The BIG-IP WebAccelerator or BIG-IP AAM system fails to function.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H385950 on the Diagnostics > Identified > High screen.
  • The BIG-IP WebAccelerator or BIG-IP AAM configuration does not load after migration.
  • BIG-IP WebAccelerator or BIG-IP AAM processes do not start.
  • The bigstart status command output displays an error message for the wamd process, that appears similar to the following example:

    wamd   down, An error occurred setting up Web Accelerator: Tmsh load failed: 01071419:3: Published policy (/Common/<name of policy>) must have at least one node.

  • The /var/log/audit file includes an error message that appears similar to the following example:

    May  9 14:53:05 hostname notice tmsh[14771]: 01420002:5: AUDIT - pid=14771 user=rroot folder=/Common module=(tmos)# status=[01071419:3: Published policy (/Common//
    <name of policy>) must have at least one node.] cmd_data=load sys configg merge file /config/policyDBDump.cfg

  • If you upgrade by manually loading a legacy UCS backup on a newly installed version 11.x system, you see an error message that appears similar to the following example:

    Tmsh load failed: 01071419:3: Published policy (/Common/empty_policy) must have at least one node.  Unexpected Error: Loading configuration process failed.

Workaround

Before upgrading, you must first either delete the policy that contains no nodes or add at least one node to this policy.

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

If the BIG-IP system is upgraded to 11.x, you must revert to or reinstall a 10.x partition, delete or modify the offending policy, and perform the upgrade again.

Impact of workaround: Additional downtime is required to repeat the upgrade procedure.
