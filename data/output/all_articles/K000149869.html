Description

When using APM API protection and for example you set max-spike-requests to 3 and spike-interval to 1, sometimes you can see inconsistent behavior with these settings.  Sometimes the client receives a 429 http response with only 2 requests (not expected) or sometimes the client receives a 429 response with 3 requests (expected)

Environment

BIG-IP APM

API Protection

Cause

This issue can be caused by threading/concurrency on the client using the API

Recommended Actions

Do not use threading/concurrency on the client sending the API requests
