Description

Cloud failover extension no longer works or does not fail over properly after an upgrade


You may observe logs similar to the following:


/var/log/ltm

/var/log/restjavad.0.log


[WARNING][245871][17 Jun 2023 08:27:27 UTC][8100/shared/iapp/build-package BuildRpmTaskCollectionWorker] Failed to execute the build command 'rpmbuild -bb --define '_tmppath /shared/tmp' --define 'main /var/config/rest/iapps/f5-cloud-failover' --define '_topdir /var/config/rest/node/tmp' '/var/config/rest/node/tmp/0eeec6f8-5793-435a-ae2c-977f16a48371.spec'', Threw:com.f5.rest.workers.shell.CommandExecuteException: Command execution process killed



Environment

BIG-IP VE

Cause

There can be numerous causes for this issue, some possible existing bugs


Bug ID 929213: iAppLX packages not rolled forward after BIG-IP upgrade

Bug ID 1079817: Java null pointer exception when saving UCS with iAppsLX installed


In addition to these bugs there may be an uknown cause that can be fixed by uninstalling the cloud failover extension, clearing the rest storage and re-installing the latest cloud failover extension

Recommended Actions

Perform the following steps on EACH unit in the failover group


1. Take a backup archive of the unit if you do not have a current one under System -> Archives -> Create button


2. From the Configuration Utility, Navigate to 'iApps > Package Management LX


3. Find the package named "f5-cloud-failover" and checkmark it and click the Uninstall button below. If the package name does not show up on this page proceed with step 4


4. From the command line run the following command (no disruption to traffic is expected when running this command):


# clear-rest-storage -l


5. Download the latest version of f5-cloud-failover-x-x-x-x.noarch.rpm at https://github.com/f5networks/f5-cloud-failover-extension/releases


6. From the Configuration Utility, Navigate to 'iApps > Package Management LX


7. Choose the file downloaded in step 5 and click the Upload button


8. From the command line run the following command to restart restjavad and restnoded (no disruption to traffic is expected when running this command):


# bigstart restart restjavad restnoded
