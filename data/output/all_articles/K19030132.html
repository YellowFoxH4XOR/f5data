K19030132: TMM memory utilization peak could be seen during sync when there are many incremental sync cache on data-group

Type
Support Solution
Published
2025-06-18
Updated
2025-07-07
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.0.0, 17.1.0, 17.0.X, 17.X.X, 17.5.X, 17.5.1, 17.5.0, 17.1.X, 17.1.2, 17.1.1
Source
https://my.f5.com/manage/s/article/K19030132

Description

By default, a device-group is using 'incrementcal' configuration sync to sync configurations to HA peer.
When there are a lot of changes on a data-group before performing sync operation, TMM process memory peak could been on HA peer during the configuration sync. 

Environment

  • Device-group with 'full-load-on-sync' set to false
  • Data-group 

To trigger this issue, the data-group should be large and has been changed many times before sync operation.

 

Cause

None

Recommended Actions 

Workaround:

Option 1:
Please perform full load sync to workaround this issue.


Option 2:
Enable auto-sync so that there are not so many incrementcal sync caches.


Additional Information

None
