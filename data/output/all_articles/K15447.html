Known Issue

The BIG-IP APM system may not pass the HTTP username header to destination resources.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP device is licensed and provisioned with the BIG-IP APM and BIG-IP ASM modules.
  • The BIG-IP APM access profile is associated with a virtual server.
  • An application on the destination resource uses the HTTP username (case insensitive) header.

Impact

Attempts to access the destination resource content may fail.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • When examining HTTP headers, the username header is visible for traffic between the user and the BIG-IP APM associated virtual server, but it is not visible for traffic between the BIG-IP APM system and the destination resource.
  • Users cannot access the HTTP content of the destination resource, and may receive errors similar to the following example:

    500 Internal Server Error

Workaround

To work around this issue, you can create an iRule to ensure the username header is sent to destination resources. To do so, perform the following procedure:

Impact of workaround: F5 recommends that you perform this procedure during a scheduled maintenance window.

Creating the HTTP username header iRule

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules.
  3. Click Create.
  4. In the new iRule text Name box, type a name for the iRule.

    For example:

    username_insert
  5. In the Definition box, enter the following text:

    when ACCESS_ACL_ALLOWED {
    set myusername [HTTP::header username]
    }
    when HTTP_REQUEST_RELEASE {
    if { [info exists myusername] } {
    HTTP::header replace username $myusername
    }
    }
  6. Click Finished.
  7. Navigate to Local Traffic > Virtual Servers.
  8. Click the name of the virtual server that is affected by this issue.
  9. Click the Resources tab.
  10. In the iRules section, click Manage.
  11. From the Available column, select the iRule you previously created.
  12. Click << to move the iRule to the Enabled column.
  13. Click Finished.
