Description

BIG-IP VE failing to start after problem with host that was recovered.

Filesystem errors present, cannot run df or mount successfully.  Error could be shown as below:

[root@!:!:!]  ~] df -h
df: '/var/log' : No such file or directory
df: '/shared/rrd.1.2' : No such file or directory.

Booting to older volumes works fine.

Environment

  • BIG-IP VE
  • VM Host
  • File System
  • Maintenance Mode

Cause

System has booted to maintenance mode due to filesystem issues. This can happen after storage changes / disruption on the host while the BIG-IP VE is running.

Recommended Actions

From within maintenance mode, run the following command:

fsck -y /dev/mapper/vg--*

or

fsck -Ay

Note: fsck is a frontend for all the filesystem-specific fsck commands. Invoking fsck automatically invokes the correct filesystem-specific fsck. -A option will walk through the /etc/fstab file and try to check all file systems in one run.  the -y option will cause the fs-specific fsck to always attempt to fix any detected filesystem corruption automatically.

Then reboot the system.

Additional Information

This issue can affect multiple BIG-IP VEs if they are running on the same host.
