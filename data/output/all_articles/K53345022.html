Description

When BIG-IP initiates a HA failover to the peer BIG-IP, the nodes or backend pool members goes down (the health monitor is failing) on both BIG-IPs. Then, it will go up again after a few mins.

Environment

  • BIG-IP HA Pair
  • BIG-IP pairs are connected to Cisco ACI fabric
  • Health Monitor is failing upon failover (no ICMP response from nodes)

Cause

The default behavior of an ACI fabric is to do all learning via UDP unicast lookups in the endpoint database located in the spines and as such there is no need to broadcast or flood an ARP.  However in order for failover to work in a BIG-IP system, it will send out gratuitous ARPs (GARPs) for floating self IP addresses and virtual server addresses in order to update the Address Resolution Protocol (ARP) cache of devices on the network. The large amount of GARP sent will overwhelm the Cisco ACI (Cisco APIC)'s default settings. 

Details on the cause can be read below:
K7332: GARPs may be lost after a BIG-IP failover event
 

Recommended Actions

In order for the ACI fabric to be able to learn endpoint moves via GARP, you need to enable some non-default features on the Bridge Domain (BD) associated with the End Point Group (EPG) on Cisco ACI. Those are “ARP Flooding” and "EP Move Detection Mode” (GARP Detection Mode).

Important: Please consult with the Cisco certified engineer before making changes to the Cisco ACI configuration. F5 will not take responsibility for any unexpected outcome.
