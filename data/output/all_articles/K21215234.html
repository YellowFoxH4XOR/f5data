Issue

Description

Three wizards are provided to assist users to configure new resources on the BIG-IP APM. After getting the BIG-IP Edge Gateway or BIG-IP LTM with Access Policy Manager (APM) licensed and provisioned, and basic network settings configured, one of the three different Access Policy Manager Device Wizards can be used to configure the following resources:

  • Network Access Setup Wizard for Remote Access
  • Portal Access Setup Wizard
  • Web Application Access Management for Local Traffic Virtual Servers

Environment

The following prerequisites should be met in order to use any of the following wizards.

  • The BIG-IP system must be licensed and provisioned for Access Policy Manager (APM).
  • The user must have administrative access to the BIG-IP.
  • Basic network settings for the system have previously been configured.
  • DNS server must be configured to resolve internal addresses.

Cause

None

Recommended Actions

Network Access Setup Wizard for Remote Access

Configure a network access VPN connection for remote access. Creates an access policy and local traffic virtual server so that end users can establish a full network access VPN connection to internal resources.

Running the Network Access Wizard:

  1. Log in to the BIG-IP APM Configuration utility. 
  2. Navigate to Wizards > Device Wizards. 
  3. Under the Wizard Section in the detail pane, select the Network Access Setup Wizard for Remote Access.
  4. Click Next.
  5. In the Policy Name box, type a name for your policy.
  6. Select the Default Language to be displayed to the users.
  7. Select the Full Webtop check box if a webtop landing page is desired.
  8. Clear the Enable Antivirus Check in the Access Policy check box if it is not required on the client side.
  9. Configure the IPv4 Default Gateway.
  10. Click Next.
  11. Create or use an existing AAA server. If Create new was selected, the next screen will allow the user to configure the authentication details for the selected authentication type.
  12. Click Next.
  13. You will need to create a Lease Pool. Lease pools are collections of IP addresses that the system assigns to users who make network access connections (client PPP addresses). A lease pool IP address is assigned to each client when the network access connection is established.
  14. Click Next
  15. Configure the network access resources. Options include force all traffic across the tunnel, Split tunneling, Allow Local Subnet, Client side Security, and DTLS.
  16. Specify DNS name servers, WINS servers, and a DNS default domain suffix. These servers and settings are assigned to end user client machines as part of the network access connection process, and are used by the client when performing name resolution for internal network resources.
  17. Specify an IP address to create a local traffic virtual server that is correctly configured for network access. Your end users connect to a DNS name representing this destination address to start a network access connection.
  18. Check the option Create Redirect Virtual Server (HTTP to HTTPS) to create a local traffic virtual server that automatically redirects users who connect using http:// instead of https:// with their web browser.
  19. Review your configuration to ensure all is correct. To change a setting, use the Previous button to go back to the page you want to edit.
  20. Click Next to complete the configuration and apply the settings.

Portal Access Setup Wizard

Configure a remote access connection to one or more internal web applications. Creates an access policy and local traffic virtual server so that end users can access internal web applications through a single external virtual server. Use this if you need to provide secure extranet access to internal web applications without creating a full VPN connection.

Running the Portal Access Wizard:

  1. Log in to the BIG-IP APM Configuration utility. 
  2. Navigate to Wizards > Device Wizards. 
  3. Under the Wizard Section in the detail pane, select the Portal Access Setup Wizard option.
  4. Click Next.
  5. In the Policy Name box, type a name for your policy.
  6. Select the Default Language of the portal to be displayed to the end users.
  7. Select the Full Webtop check box if a webtop landing page is desired.
  8. Clear the Enable Antivirus Check in the Access Policy check box.
  9. Configure the IPv4 Gateway address.
  10. Click Next.
  11. You will need to create or use an existing AAA server. If you select create new, the next screen will allow you to configure the authentication details for the selected authentication type.
  12. Click Next.
  13. Specify the Portal Access Start URI and SSO method if desired.
  14. Specify an IP address to create a local traffic virtual server that is correctly configured for web applications. Your end users connect to a DNS name representing this destination address to start a web applications connection.
  15. Check the option Create Redirect Virtual Server (HTTP to HTTPS) to create a local traffic virtual server that automatically redirects users who connect using http:// instead of https:// with their web browser.
  16. Review your configuration to ensure all is correct. To change a setting, use the Previous button to go back to the page you want to edit.
  17. Click Next to complete the configuration and apply the settings.

Web Application Access Management for Local Traffic Virtual Servers

Configure authentication and access control for a web application behind a local traffic virtual server. This creates an access policy for a new or existing local traffic virtual server to provide authentication, access control, and endpoint security for a web application.

Running the Web Application Access wizard:

  1. Log in to the BIG-IP APM Configuration utility. 
  2. Navigate to Wizards > Device Wizards. 
  3. Under the Wizard Section in the detail pane, select the Web Application Wizard option.
  4. Click Next.
  5. To enable authentication and access control for a web application behind a standard local traffic virtual server, you can either use an existing local traffic virtual server or create a new local traffic virtual server as part of this wizard. If you would prefer to manually create a virtual server, with an http profile, Client SSL profile, and pool, with no assigned access profile, and then return to the wizard, click Cancel now. You can then return to the wizard and use the virtual server you created manually. If you would like the wizard to create the virtual server with appropriate profiles click Next.
  6. In the Policy Name box, type a name for your policy.
  7. Select the Default Language displayed to the end users.
  8. Clear the Enable Antivirus Check in the Access Policy check box if not required.
  9. Configure the IPv4 Gateway Address.
  10. Click Next.
  11. You will need to create or use an existing AAA server. If you select create new, the next screen will allow you to configure the authentication details for the selected authentication type.
  12. Click Next.
  13. Specify the SSO method if desired.
  14. Click Next.
  15. Create a new HTTPS local traffic virtual server, or select an existing virtual server. You can only select an existing virtual server if it is correctly configured for HTTPS on port 443, with both a Client SSL profile and the HTTP profile assigned, and no access profile assigned. If you create a new virtual server, you must also configure the IP address of a pool member.
  16. Check the option Create Redirect Virtual Server (HTTP to HTTPS) to create a local traffic virtual server that automatically redirects users who connect using http:// instead of https:// with their web browser.
  17. Review your configuration to ensure all is correct. To change a setting, use the Previous button to go back to the page you want to edit.
  18. Click Next to complete the configuration and apply the settings.
