Topic

F5 Access for Android version 3.0.8 incorporates Android's new password complexity criteria. This change is applicable to devices running Android 10 or later.

Description

Beginning in August 2021, new or updated Android applications can target Android 10 (API level 29) or later. Google now requires all partners to migrate to work profiles or fully managed devices. New restrictions have been added to the device administration policies that now require enforcing device password complexity on devices running Android 10 or later.

The device password complexity is divided into four categories: None, Low, Medium, and High. For more information about Android's new password complexity categories, refer to the following documentation:

Behavior with the BIG-IP APM system

BIG-IP APM 17.0.0 and later

In BIG-IP APM 17.0.0 and later, the desired device password complexity can be configured in the Device Lock Complexity setting in the Connectivity profile. Administrators can choose between these device password complexity options: None, Low, Medium, or High.

Users who upgrade to F5 Access for Android 3.0.8 and connect to a BIG-IP APM system running 17.0.0 or later must comply with the Device Lock Complexity setting or be redirected the device's lock change screen to update the device password. 

BIG-IP APM versions prior to 17.0.0

Users who upgrade to F5 Access for Android 3.0.8 or later and connect to the BIG-IP APM system will default to the Medium setting. Therefore, users who have a device lock password that does not meet Medium complexity criteria will be redirected to Android's device lock change screen and asked to update their device password. Additionally, you cannot enforce device lock complexity that is higher than Medium. For example, if your existing device lock complexity criteria is more complex than Medium, users are still able to set passwords with Medium complexity and see no change.

In addition, there is no way for administrators to enforce the presence of alphabetic characters in device locks. This behavior is a limitation from Android, as none of the device complexity categories (None, Low, Medium, or High) enforce the use of alphabetic characters in device locks.

Note: The behavior described above is applicable for devices running Android 10 or later. There are no deviations from the current behavior for the devices running on Android 9 or earlier.

For more information, refer to the compatibility matrix of F5 Access for Android 3.0.8 or later with the BIG-IP APM system.
