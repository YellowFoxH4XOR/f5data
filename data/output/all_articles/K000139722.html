Description

 

Impact of apm session settings on storefront ica sessions.

 

Environment

 

  • BIG-IP APM
  • VDI Citrix Integration mode

Cause

Storefront has their own sessions states, independent from APM

Recommended Actions

From the big-ip perspective we can set Inactivity Timeout, Access Policy Timeout and Maximum Session Timeout, which basically did not impact only on ICA connection.

Inactivity Timeout - specifies the inactivity timeout for the connection, in seconds. If there is no activity between the client and server within the specified threshold time, the system closes the current session.

Access Policy Timeout - The timeout requires that a user, who has executed a per-session policy, must complete the policy before the timeout expires.

Maximum Session Timeout - Specifies the maximum lifetime of one session, in seconds. The maximum lifetime is between the time a session is created, to when the session terminates. By default, it is set to 604800 seconds (one week). If you set this to 0 (zero), it means no limit.

Here are the Storefront sessions states that are independent from APM:

  1. Active : The active state is maintained as long as there is a communication between the client machine and the XenApp server.
  2. Idle: If we leave our machine for a few minutes, the session state changes to idle. While a session is in an idle state, communication channels are kept open, but the communication between the client machine and the XenApp server is stopped. When a session is open and idle on the server, the applications still use resources and a license on the XenApp servers. To avoid wastage of the server's resources, it is best practice to establish an idle timeout value. If a session has remained idle longer than the allowed threshold, the session will change states.

  3. Disconnected: When the XenApp server retains an open session but the user is no longer actively connected this is a disconnected session. For example, instead of logging off from the application, if user simply close the window, his session will go into disconnected state.

    Also, disconnected sessions can happen for other reasons like network issues or loss of network connectivity. Similar to an idle session, a disconnected session remains running on the XenApp server consuming resources, until the disconnected session is terminated, using the disconnected timeout value.
