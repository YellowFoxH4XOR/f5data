Description

In rare circumstances, BIG-IP platforms with a High Speed Bridge (HSB) could experience Frame Check Sequence (FCS) errors on an internal ports between the HSB and internal switch. On systems with multiple HSBs, only a portion of traffic is affected, causing what seems random unexplained traffic failures or monitor flapping.  Small amounts of FCS errors on any interfaces, including internal interfaces, is normal. However, large amount of FCS errors in a very short period of time, E.g. 10 seconds, on an interface indicates some failure.

 

Environment

  • BIG-IP Platforms with an HSB
  • i5000 Series
  • i7000 Series
  • i10000 Series
  • i11000 Series
  • B2250 Blades
  • B4450 Blades
  • B4460 Blades

Cause

F5 is tracking this as Bug ID 1052057.

Note: VIPRION B2250 blades do not support the HGM‑based FCS monitoring and auto‑mitigation features (ID 1239905). This platform may still experience FCS errors on HSB internal interfaces, but the automatic detection and reboot mitigation mechanism is not available.

Recommended Actions

Internal interfaces can only be reviewed from the command line interface of the device. Using the command "tmsh show net interface all-properties -hidden" will show something similar to the below.  Review "Errs In" column internal interfaces for your platform. Re-run the command several times overly equally spaced small intervals. If "Errs In" is growing at a large rate, please contact F5 support.

BIG-IP has support that improves detection and mitigation of FCS errors on internal interfaces.

  • This functionality is available in BIG-IP v15.1.8, BIG-IP v16.1.4, and BIG-IP v17.1.0 for B4450 and B4460 blades (Bug ID 1048709)
  • This functionality is available in BIG-IP v17.1.2 and BIG-IP v17.5.0 for iSeries appliances (Bug ID 1239905)
  • This functionality is NOT available for B2250 blade. Recommend manual FCS monitoring, SNMP alerting, reboots when errors spike, and consider a hardware upgrade. 

When FCS errors are detected on an internal link, the bcm56xxd daemon will generate a log message:

info bcm56xxd[1234]: 012c0012:6: HGM FCS detected on 10.1: delta 2001 threshold 0

This improvement is controlled by the following three db variables:

sys db bcm56xxd.hgmfcsthreshold {
    value "0"
}

The default value = 0, which means it is disabled.  The system will monitor for FCS errors and log them, but will take no further action. If this is a non-zero value, then it specifies the number of FCS errors that need to occur within a poll loop (1s) before the HA action is triggered. It is used with bcm56xxd.hgmfcsnumpolls before deciding to trigger the HA action.

 

sys db bcm56xxd.hgmfcsnumpolls {
    value "5"
}

The number of consecutive poll loops that exceed the FCS threshold before the HA action is triggered. Each poll loop is 1s, with the default at 5s. For example, the threshold value specified in bcm56xxd.hgmfcsthreshold needs to be exceeded in each poll loop for 5s before the HA action is triggered.

 

sys db bcm56xxd.hgmfcsrebootaction {
    value "enable"
}

Specifies the HA action to take when the FCS threshold is exceeded. There are two options:
bcm56xxd.hgmfcsrebootaction = enable: triggers a nic_failsafe reboot
bcm56xxd.hgmfcsrebootaction = disable: triggers a nic_failsafe go-offline-downlinks
