Topic

You should consider using this procedure under the following conditions:

  • Your BIG-IP system has limited hard drive space.
  • You want to acquire a packet capture from the device.

Description

In some BIG-IP deployment scenarios, the available hard drive space of the BIG-IP system may be limited. This issue may occur when the device is a BIG-IP Virtual Edition (VE) device or a physical device that holds a large amount of log files, software images, or various files, such as previous tcpdump files, UCS archives and qkview files. This scenario may cause issues if you need to acquire a packet capture from the affected device. You can work around a hard drive space limitation by creating a temporary file store using the device memory, or executing tcpdump to save the capture file to a remote device.

Note: Creating a tcpdump file with the Configuration utility requires more hard drive space than creating one from the command line. The Configuration utility creates the tcpdump file and a TAR file that contains tcpdump. These files are located in the /shared/support directory.

Important: Before performing the following procedures, ensure that the BIG-IP system has ample CPU and memory resources.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You must have administrative access to the BIG-IP command line.
  • You must have the ability to SCP or FTP the packet capture file to an alternate device.

Procedures

Creating a RAM file system and writing the tcpdump file directly to memory

To create and use a memory file system and write the tcpdump file directly to memory, perform the following procedure:

Impact of procedure: The size of the capture files stored in RAM will directly reduce the amount of available memory for the BIG-IP system.

  1. Log in to the BIG-IP command line.
  2. To create the temporary file system directory mount point, type the following command:

    mkdir /var/tmpfs
  3. To  mount the temporary file system, type the following command:

    mount -t tmpfs none /var/tmpfs

  4. To write the packet capture file to the temporary file system, use the following command syntax:

    tcpdump -ni <vlan_name> -c <packet_count> -s0 -w /var/tmpfs/mytcpdump.bin

    In this command, note the following:
    • <vlan_name> is the name of the VLAN.
    • <packet_count> is the packet count value.
    Note: Make sure to use the tcpdump -c <packet count> command. The -c option forces tcpdump to exit after receiving the designated number of packets. For example, tcpdump exits after receiving 500 packets when you run the following command:

    tcpdump -c 500

Performing the tcpdump remotely through SSH and writing the output to the client system

To save the tcpdump file to a remote device, you can use an SSH command by performing the following procedure:

Impact of procedure: The capture processing and transfer will require additional system resources and network bandwidth.

  1. Connect to the remote device using SSH.
  2. Write the remote capture file to the local device using the following command syntax:

    ssh <username>@<remote_device> 'eval $(which tcpdump) -c<packets>-s0 -w- -i interface' > <filename>

    In this command, note the following:

    • <username> is the user on the remote system.
    • <remote_device> is the hostname or IP address of the BIG-IP system.
    • <packets> is the number of packets you want to capture.
    • <filename> is the name you want for the tcpdump binary capture file.
    Note: Ensure that the tcpdump syntax flag -w- includes the prefix dash ( - ) and the suffix dash ( - ).

    For example:

    ssh root@remote_device 'eval $(which tcpdump) -c10000 -s0 -w- -i internal' > mytcpdump.bin

    The tcpdump command executes on the BIG-IP system and writes the mytcpdump.bin capture file to the local device.

Important: The tcpdump output is buffered. If you issue CTRL-C on the system from which you are running the commands, it may terminate the SSH session instead of the remote tcpdump, resulting in an incomplete or unusable tcpdump capture. Therefore, it is important to wait for the tcpdump process to complete collecting the specified number of packets.
