Topic

When FirePass performs Active Directory authentication or dynamic group mapping, the returned Active Directory attributes are stored as session variables. Active Directory variables can be used in numerous places on the FirePass controller for customization purposes. The following table provides a list of Active Directory attributes and their corresponding FirePass session variable that the FirePass controller can store and use.

Active Directory attributes are stored every time a user authenticates through Active Directory or when Active Directory Mapping Method is used for either Master Group or Dynamic Group assignment. If Active Directory authentication was the event that is being used, the asterisk (*) in the FirePass Variable field will be replaced with session.ad.auth. If Active Directory Mapping Method was the event that is being used, the asterisk will be replaced with session.ad.groupmapping. For example, for Active Directory authentication, the first name will be stored in %session.ad.auth.givenname%; for Active Directory Mapping Method, the first name will be stored in %session.ad.groupmapping.givenname% in FirePass versions 6.0.1 and earlier and as %session.ad.groupresourcemapping.givenname% in FirePass version 6.0.2 and later.

OtherAdditional Active Directory attributes not listed here are also imported to FirePass session variables. You can access these variables using the syntax of %*<name of attribute>% where name of attribute is the name of the attribute as it is defined in Active Directory.

To view these session variables, perform the following procedure:

  1. Log on to the FirePass Administrative Console.
  2. Navigate to Device Management : Maintenance : Troubleshooting Tools.
  3. Under the Session Variable Dump section, select the Save user's session variables to Logon Reports check box.

    Note: Enabling this feature can cause a significant increase in the amount of information that is being logged. F5 Networks recommends this feature be disabled when not in use
  4. Have an Active Directory user log into FirePass to generate logs.
  5. Navigate to Reports : Logons to view the logs.

    Note: Logon details will not appear if the user was denied during the pre-login sequence. Starting in version 6.0.3, under the Logon column, [logon denied] represents users who are denied during the pre-login sequence.
  6. When you have the data you are looking for, navigate back to Management : Maintenance : Troubleshooting Tools and clear the Save user's session variables to Logon Reports check box.
