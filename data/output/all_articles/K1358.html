Note: The following information describes the dynamic rebinding function and provides a sample configuration. This information was written with the assumption that the reader is familiar with configuring a BIG-IP firewall sandwich. If you require additional information about how to configure a firewall sandwich, refer to the BIG-IP manual specific to the version you are running.

Dynamic rebinding is a virtual server attribute that was introduced in BIG-IP version 4.1.1. It is used primarily for firewall sandwich installations, like the one shown in the Figure 1.

When dynamic rebinding is enabled and a node address (or service) in a virtual server's pool transitions to a down state, all virtual server connections to that node move to another designated node in the virtual server pool. This new node is selected using the virtual server pool's load balancing algorithm.

In order for dynamic rebinding to work properly, all BIG-IPs must perform transparent service checks (ECV) through the firewalls and the firewalls must share state information. Sample ECV configurations are provided in the following examples. In these examples, Firewalls 1, 2, and 3 all share connection information. If one of the firewalls fails, the BIG-IP transitions the connection to the next available firewall. This feature is most useful with long-lived connections, such as FTP or Telnet.

Dynamic rebinding is disabled by default. You can enabled dynamic rebinding from the command line using the following bigpipe commands, or by checking the Enable Connection Rebind option in the Virtual Server properties section of the Configuration utility.

Note: Dynamic rebinding will not work when the auto lasthop feature is enabled; therefore, to use dynamic rebinding, you must define the lasthop pools. You can, however, keep auto lasthop enabled for processes that are not related to dynamic rebinding. Also, in order for dynamic rebinding to occur, both BIG-IPs must show the node/firewall in a down state.

To enable, disable, and show dynamic rebinding through bigpipe, use the following commands:

b virtual <ip>:<service> conn rebind enable
b virtual <ip>:<service> conn rebind disable
b virtual <ip>:<service> conn rebind show

ECV Example: BIG-IP 1

In the following example, ECV is performing a transparent service check through the firewalls on the VIP of BIGIP 2. Dynamic rebinding is enabled on the 10.10.0.0 VIP on the Internet facing BIG-IP 1 (see Figure 1). If a connection is going through Firewall 1 and that firewall is marked down by this ECV, BIG-IP would move that connection to the next available firewall.

# monitors
monitor FW_test {
    # type tcp
    use 'tcp'
    interval 1
    timeout 3
    dest 10.10.30.x:ssh
    send 'SSH-1.99-2.0.12 F-SECURE SSH'
    recv '
    transparent
}
node 10.10.20.4:any 10.10.20.5:any 10.10.20.6:any monitor use FW_test

Note: For 10.10.30.x:ssh, x is defined as the shared self IP address of the BIG-IP.

ECV Example: BIG-IP 2

In the following example, ECV is performing a transparent service check through the firewall and checking port 22 on the floating IP address of BIGIP 1. Dynamic rebinding is enabled on the 0.0.0.0:0 VIP on the "User Cloud" facing BIG-IP 2 (see Figure 1). If a connection is going through Firewall 1 and that firewall is marked down by this ECV, BIG-IP would move that connection to the next available firewall.

monitor FW_test {
    # type tcp
    use 'tcp'
    interval 1
    timeout 3
    dest 10.10.20.x:ssh
    send 'SSH-1.99-2.0.12 F-SECURE SSH'
    recv '
    transparent
}
node 10.10.30.4:any 10.10.30.5:any 10.10.30.6:any monitor use FW_test

Note: For 10.10.30.x:ssh, x is defined as the shared self IP address of the BIG-IP.
