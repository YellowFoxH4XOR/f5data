Known Issue

ADAPT iRule events may fail to inspect HTTP headers after adaptation.

This issue occurs when all of the following conditions are met:

  • You associate the Request Adapt or Response Adapt profiles with a virtual server for adaptation.
  • You use iRule ADAPT_REQUEST_RESULT or ADAPT_RESPONSE_RESULT events to inspect an HTTP request or response after adaptation.

Impact

HTTP headers after adaptation are not visible in iRule ADAPT_REQUEST_RESULT or ADAPT_RESPONSE_RESULT events.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • HTTP headers after adaptation are not visible in iRule ADAPT_REQUEST_RESULT or ADAPT_RESPONSE_RESULT events.
  • Inspecting an HTTP header in ADAPT_REQUEST_RESULT or ADAPT_RESPONSE_RESULT event reveals the original headers before the request was adapted.

Resolution

Status

F5 Product Development has assigned ID 504348 to this issue. F5 has confirmed that this issue exists in the products listed in the Applies To box, located in the upper-right corner of this article. For information about releases or hotfixes that resolve this issue, refer to the following table:

Workaround

There is no workaround for this issue. However, versions in which the fix was introduced include the new ADAPT_REQUEST_HEADERS and ADAPT_RESPONSE_HEADERS events, which trigger after ADAPT receives the modified HTTP headers.
