Description

The action values for signatures and compliances in Protocol Inspection profiles change when a configuration is loaded.

In other words, when loading a configuration, the action value for some signatures and compliance checks changes from accept to reject or drop. The "configuration load" includes restoring configuration from UCS, loading a config using load sys config from-terminal merge tmsh command, and software upgrades.

Environment

  • BIG-IP AFM Protocol Inspection is licensed
  • Loading configuration
  • BIG-IP software upgrade

Cause

The issue is due to a known issue ID 1122205 .

Configuration files that contain user configurations (like bigip_base.conf and bigip.conf) generally do not contain default parameters. When the system loads configuration, it merges the user configuration files with default configuration files to retrieve full configuration parameters.

The issue occurs because signatures and compliances hide action accept parameter in the configuration file although some of them has the default action either reject or drop.

For example, the compliance /Common/diameter_disallowed_apn has the default action reject, but the configuration file does not have action accept line in it. Therefore, when BIG-IP loads configuration from file, it loads the default action parameter, which is reject.

security protocol-inspection profile /Common/ips_profile1 {
    ...snip...
    services {
        /Common/diameter {
            compliance {
                /Common/diameter_disallowed_apn { }   <-- Empty curly bracket indicates default values.
            }
            ports {
                3868 { }
            }
        }
    }
    ...snip...

When using all-properties argument when running tmsh list command, it shows action accept.

# tmsh list security protocol-inspection profile ips_profile1 all-properties
    services {
        diameter {
            compliance {
                diameter_disallowed_apn {
                    action accept          <-- This is the actual configuration in memory.
                    log yes
                    value ""
                }
            }
            config none
            ports {
                diameter { }
            }
            signature none
            status enabled
        }
    }

Recommended Actions

List the affected signatures and compliances (with non-accept default action) using the commands below and check if you have those defined in your protocol inspection profiles. If you do, you may follow the workaround mentioned in ID 1122205 .

Signarures

tmsh list sec protocol-inspection signature all-properties | egrep "protocol-inspection|^\s*action" | awk '{ if($2 == "drop" || $2 == "reject") { print prev"\n"$0 } } { prev = $0 }'

Compliances

tmsh list sec protocol-inspection compliance all-properties | egrep "protocol-inspection|^\s*action" | awk '{ if($2 == "drop" || $2 == "reject") { print prev"\n"$0 } } { prev = $0 }'
