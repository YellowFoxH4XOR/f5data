Description

During NGINX Controller installation, the process consistently fails at step 16 "Running Database Initialization". The container-backend/initialization logs display the following error:

Postgres is unavailable - sleeping

psql: error: could not translate host name "controller-host" to address: Try again

This error occurs for both internal and external PostgreSQL implementations.

Environment

  • Red Hat Enterprise Linux 7
  • NGINX Controller (version not specified in original issue)

Cause

The firewall running on the NGINX Controller host blocks internal Kubernetes communication required for PostgreSQL hostname resolution and database initialization. Specifically, the firewall prevents NAT (masquerade) traffic and blocks ports used for internal Kubernetes operations.

Recommended Actions

  1. Enable NAT (masquerade) on the NGINX Controller host firewall:

    sudo firewall-cmd --add-masquerade --permanent

  2. Reload the firewall configuration:

    sudo firewall-cmd --reload

  3. Verify the following ports are open for internal traffic (these ports are used for internal traffic only and do not need to be open to external networks):
    • 6443 TCP - Kubernetes API server
    • 2379 TCP - etcd
    • 2380 TCP - etcd
    • 10250 TCP - Kubelet API
  4. Retry the NGINX Controller installation.

Additional Information

For complete firewall and IP configuration requirements, refer to the NGINX Controller Technical Specifications documentation:
https://docs.nginx.com/nginx-controller/admin-guides/install/nginx-controller-tech-specs/#firewall-ip-settings
