K07393698: Accessing the Big-IP webUI may not work correctly through a proxy

Type
Support Solution
Published
2022-10-07
Updated
2025-02-06
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K07393698

Description

If you access the Big-IP administrative interface (webUI) through a proxy - or "jump box" you may experience issues with certain features.

  • Guided Configuration status seemingly stuck on "Initializing"
  • Config sync status not updating
  • Current HA state not reflecting the true state (online/standby, etc.)
  • Software installation status not updating

Environment

This can be caused by a proxy between the administrative user and the Big-IP.

Cause

The webUI periodically queries the big-IP using REST calls.  If those queries are for some reason blocked or modified by a proxy server, the webUI will not be able to get those updates.

Recommended Actions

Adjust the settings on the proxy or bypass that proxy server.  It is also possible to create a tunnel using ssh that may still go through that proxy but the proxy will be unable to block/inspect/modify the REST queries.  An example way to create this tunnel is:

(From your Windows or Mac desktop/laptop)
ssh -L 127.100.0.1:443:<BigIP_Mgmt_IP>:443 <adminstrative_user>@<BigIP_Mgmt_IP>

This can also be done using PuTTY

In this example, replace <BigIP_Mgmt_IP> with the Big-IP's management IP address and <adminstrative_user> with the username you would normally use to log into the Big-IP command-line.
This ssh command creates a tunnel over the ssh connection, in this case listen locally on loopback address 127.100.0.1, port 443 and with the destination of that tunnel on the Big-IP being the management IP address.
