Description

SNMP trap for Kubernetes cluster health

Environment

  • Kubernetes / opeshift cluster
  • Cluster health state
  • SNMP trap

Cause

SNMP traps are not generated when the cluster health status changes.

Currently there are no inbuilt traps for the cluster health changes.

RFE already in place, RFE ID2008541 - Generate SNMP traps when Kubernetes cluster is not healthy

Recommended Actions

You could chose to regularly monitor using the API of the controller instead:

curl -ku admin:admin https://<IP-Address>:8888/restconf/data/f5-chassis-cluster:cluster

(or)

curl -ku admin:admin https://<IP-Address>:8888/restconf/data/f5-chassis-cluster:cluster/cluster-status/summary-status

<summary-status xmlns="http://f5.com/yang/chassis-cluster"  xmlns:f5-chassis-cluster="http://f5.com/yang/chassis-cluster">
Openshift cluster is healthy, and all controllers and blades are ready.
</summary-status>
