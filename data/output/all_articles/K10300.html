Known Issue

Note: The threshold rule option allows configuring a BIG-IP ASM attack signature to only generate an alarm once in a given time interval, rather than generating an alarm each time the signature is triggered. For example, you can configure an attack signature to generate only one alarm per second, even if the unit is processing 20 requests per second which would normally generate this alarm. For more information about configuring the threshold rule option, refer to the Using the threshold rule option section of the BIG-IP Application Security Manager Configuration Guide.

Note: For information about how to locate F5 product guides, refer to K12453464: Finding product documentation on AskF5.

The attack signature threshold rule option does not function as designed under all circumstances. In low traffic situations, when all requests are processed by a single BIG-IP ASM application thread, the threshold option may appear to operate as designed. However, when the level of requests is such that requests are processed by multiple BIG-IP ASM application threads, the threshold option does not operate as designed.

As a result of this issue, if you create a custom attack signature featuring the threshold rule option, the attack signature may generate an alarm on each invocation rather than in accordance with your desired threshold.

This issue should not be a cause for concern since it is not possible to overwhelm a unit with the number of alarms being generated. The BIG-IP ASM rate limits logging in other ways to ensure that the unit continues to pass traffic even under heavy load; therefore, this is an extremely low-impact issue, which has no visible symptoms.

F5 Product Development is tracking this issue as ID 327995.
