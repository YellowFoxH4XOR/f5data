Known Issue

This is the result of a known issue. When more than eight different MAC masquerade addresses are defined on a BIG-IP system, the Address Resolution Logic (ARL) hash algorithm may prevent some of the MAC masquerade addresses from being stored in the forwarding database (FDB). Only the 14 least significant bits of the MAC address are used to determine the ARL hash. Only eight MAC masquerade addresses that result in the same hash are stored in the FDB. TMM will drop packets that are destined for a MAC masquerade address that is not in the FDB.

Note: This issue does not occur within VLAN groups defined on the BIG-IP system.

Note: A media access control (MAC) masquerade address is a locally administered MAC address that is shared between the BIG-IP units to allow more seamless failover. To ensure uniqueness, the address is generally defined by modifying the MAC address that is pre-assigned to the physical interface. The result is a unique MAC masquerade address whose 14 least significant bits match the original MAC address. For more information, refer to K3523: Configuring a unique Media Access Control (MAC) address for MAC masquerade.

For example, a customer defines the following MAC masquerade addresses on eight VLANs on the same system:

VLAN1001     02:10:01:f5:f5:f5
VLAN1002     02:10:02:f5:f5:f5
VLAN1003     02:10:03:f5:f5:f5
VLAN1004     02:10:04:f5:f5:f5
VLAN1005     02:10:05:f5:f5:f5
VLAN1006     02:10:06:f5:f5:f5
VLAN1007     02:10:07:f5:f5:f5
VLAN1008     02:10:08:f5:f5:f5

The MAC addresses are intended to reflect a locally administered address (02), the VLAN ID (10:0x), and that the address is assigned to an F5 Networks system (f5:f5:f5).

Since the addresses are identical in the least significant 14 bits, the hashes collide and all available FDB table entries are consumed.

If the following MAC masquerade address is also defined, only eight of the nine addresses will be saved in the FDB, and traffic bound for the missing MAC address will be dropped:

VLAN1009     02:10:09:f5:f5:f5

F5 Product Development tracked this issue as CR109346, and it was fixed in BIG-IP version 10.0.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, or WebAccelerator release notes.

Workaround

You can work around this issue by varying any of the least significant 14 bits in the MAC masquerade addresses. For example, the example MAC masquerade addresses above could be modified to reflect the same details (a locally administered address, the VLAN ID, and that the address is assigned to an F5 Networks system) by flipping the locally administered bit as in the original example, but using the F5 Networks vendor code and varying on VLAN ID in the significant portion of the address:

VLAN1001     02:01:d7:f5:10:01
VLAN1002     02:01:d7:f5:10:02
VLAN1003     02:01:d7:f5:10:03
VLAN1004     02:01:d7:f5:10:04
VLAN1005     02:01:d7:f5:10:05
VLAN1006     02:01:d7:f5:10:06
VLAN1007     02:01:d7:f5:10:07
VLAN1008     02:01:d7:f5:10:08
VLAN1009     02:01:d7:f5:10:09

Alternatively, you can also work around this issue by configuring the BIG-IP system to use the same MAC masquerade address on all VLANs.
