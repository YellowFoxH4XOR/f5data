Topic

Beginning in BIG-IP 10.1.0, support for RAID (redundant array of independent disks) was introduced. The current RAID implementation is managed by the operating system (software RAID), and supports RAID 1 exclusively. RAID 1 mirrors the contents of the disks participating in the array, performing a type of real-time backup. Also known as hard drive mirroring, RAID 1 provides fault tolerance from disk errors and failure of all but one of the drives. This behavior allows a BIG-IP system to continue to operate as long as at least one drive is functioning.

This feature is available on platforms containing multiple hard drives and require the drives to be formatted with the volumes disk-formatting scheme.

Note: RAID is automatically configured for BIG-IP 11.x and later multi-drive systems.

The BIG-IP 8950 and 11050 platforms are only supported beginning with BIG-IP 10.2.0. Because every BIG-IP 8950 or 11050 system shipped by F5 is formatted with the volumes disk-formatting scheme and performs hard drive mirroring by default, the rest of this article does not apply to these platforms.

Whether and how a BIG-IP 6900 or 8900 system will perform hard drive mirroring depends on how BIG-IP 10.1.0 or later is installed. Refer to the following installation scenarios:

  • Manufacturing and clean installations of BIG-IP 10.1.0 or later
  • Upgrading to BIG-IP 10.1.0 or later volumes from 10.0.x partitions or 9.4.x
  • Upgrading to BIG-IP 10.1.0 or later volumes from 10.0.x volumes using the image2disk utility

Manufacturing and clean installations of BIG-IP 10.1.0 or later

BIG-IP 6900 and 8900 systems that ship with 10.1.0 or later feature mirrored volume sets exclusively.

Similarly, if you perform a clean installation of BIG-IP 10.1.0 or later on a 6900 or 8900 system, and you choose the volumes disk-formatting scheme, the BIG-IP system will feature mirrored volume sets exclusively.

In either case, when featuring mirrored volume sets exclusively, the installation process creates the following three mirrored volume sets by default:

  • MD1.1
  • MD1.2
  • MD1.3

Upgrading to BIG-IP 10.1.0 or later volumes from 10.0.x partitions or 9.4.x

To upgrade a BIG-IP 6900 or 8900 system which is formatted with the partitions disk-formatting scheme to BIG-IP 10.1.0 or later volumes, you must use the image2disk utility. When performing the upgrade, make sure you pass the --format=volumes option to the image2disk utility. During the installation the image2disk utility will re-format all the drives and create mirrored volume sets exclusively. This means that at the end of the installation the BIG-IP system will be running mirrored volume sets only. By default, the image2disk utility will create three mirrored volume sets: MD1.1, MD1.2 and MD1.3.

Note: When upgrading to BIG-IP 10.1.0 or later volumes using the image2disk utility and the --format=volumes option, specify any of the existing HD1.<name> boot locations for the installation slot. The actual choice will be irrelevant as the installation will re-format all the drives and create mirrored volume sets exclusively (MD1.<name>).

Note: For more information about the image2disk utility, refer to the Using the image2disk and diskinit Utilities section in the BIG-IP Systems: Getting Started Guide.

Upgrading to BIG-IP 10.1.0 or later volumes from 10.0.x volumes using the image2disk utility

If you upgrade a BIG-IP 6900 or 8900 system to 10.1.0 or later volumes from 10.0.x volumes using the image2disk utility, you must use the --format=volumes option. During the installation the image2disk utility will re-format all the drives and create mirrored volume sets exclusively. This means that at the end of the installation the BIG-IP system will be running mirrored volume sets only. By default, the image2disk utility will create three mirrored volume sets: MD1.1, MD1.2 and MD1.3.

Note: Upgrading a BIG-IP system to 10.1.0 or later volumes from 10.0.x volumes using the image2disk utility, but without supplying the --format=volumes option, is not a permitted operation. The installation will be cancelled and the following error message will be returned:

Terminal error: SVM (Software Volume Management) is available, and this is not a format request.
Please use SVM.
