Description

A reboot was experienced with the following error in   /var/log/kern.log: 

err kernel: ena 0000:00:05.0 eth0: Keep alive watchdog timeout.
err kernel: ena 0000:00:05.0 eth0: ena_admin_q_no_completion: 0
err kernel: ena: reading reg failed for timeout. expected: req id[10] offset[88] actual: req id[57015] offset[88]
err kernel: ena: reading reg failed for timeout. expected: req id[11] offset[8] actual: req id[57016] offset[88]
err kernel: ena: Reg read32 timeout occurred
err kernel: ena 0000:00:05.0: Device reset failed
err kernel: ena: reading reg failed for timeout. expected: req id[1] offset[88] actual: req id[57006] offset[0]
err kernel: ena: reading reg failed for timeout. expected: req id[2] offset[8] actual: req id[57007] offset[0]
err kernel: ena: Reg read32 timeout occurred
err kernel: ena 0000:00:05.0: Can not reset device
err kernel: ena 0000:00:05.0: Can not initialize device
err kernel: ena 0000:00:05.0: Reset attempt failed. Can not reset the device
info kernel: mgmt: port 1(eth0) entered disabled state


Environment

BIG-IP VEs
AWS Cloud BIG-IP VEs
 

Cause

Not the BIG-IP,  the problem is in the AWS infrastructure.

The Watchdog timeout occurred on a port not from the CPU. The system tried to reset the device (eth0) and not the entire system, but after the attempt fail a reboot is triggered. The reason why some ports can fail to the watchdog is explained In the following AWS article is:

NOTE: External links are being provided as a convenience and for informational purposes only. F5 bears no responsibility for the content of the external site or for that of subsequent links.

https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/troubleshooting-ena.html 

As we can see there:

Register read timeout

The ENA architecture suggests a limited usage of memory mapped I/O (MMIO) read operations. MMIO registers are accessed by the ENA device driver only during its initialization procedure.

If the driver logs (available in dmesg output) indicate failures of read operations, this may be caused by an incompatible or incorrectly compiled driver, a busy hardware device, or hardware failure.

Recommended Actions

Review the driver is the recommended one (K10142141 ), if the port was working before means the driver selection was appropriate and the only possibilities are a Busy hardware device or a hardware failure. 


In any cloud environment, we rely on the cloud provider to provide stable computing resources. We do not have access to the underlying hardware to troubleshoot further.

If additional indications suggest busy hardware, for example "Clock advance", we can discard hardware failure, in any case consider moving the BIG-IP instance to another host.
