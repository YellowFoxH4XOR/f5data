K000162368: APM Access IPsec VPN fails with error "PPP not allowed - IPsec connectivity profile"

Type
Support Solution
Published
2026-07-22
Updated
2026-08-20
Applies to
  • BIG-IP
  • BIG-IP APM: 21.1.0
Source
https://my.f5.com/manage/s/article/K000162368

Description

An Access IPsec VPN tunnel on BIG-IP APM fails after the Edge Client establishes the HTTPS/TLS connection. The APM log displays:

MYVPN Error: PPP not allowed - IPsec connectivity profile

No IKE or IPsec Security Associations (SAs) are created, and UDP/500 or UDP/4500 traffic is not observed.

Environment

  • BIG-IP APM 21.1.0
  • Windows 11 client
  • BIG-IP APM Edge Client
  • Access IPsec VPN tunnel configuration
  • An IPsec Connectivity Profile assigned to the virtual server
  • Machine Certificate Authentication configured in the Access Policy

Cause

An Edge Client issue can prevent the connection from progressing from the HTTPS/TLS phase to IPsec negotiation. An updated Edge Client build containing the fix resolves the behavior.

The server certificate must also include the BIG-IP virtual server IP address in the Subject Alternative Name (SAN).

Answer/Recommended Actions

  1. Upgrade the BIG-IP APM Clients package to version 7.2.7 (or later). Please note that the default APM Clients package (v7.2.6) bundled with BIG-IP 21.1.0 is affected by this behavior and will continue to produce this error.
  2. Confirm that the IPsec Connectivity Profile is configured and assigned to the intended virtual server.
  3. Confirm that Machine Certificate Authentication is configured in the Access Policy.
  4. Verify that the server certificate includes the virtual server IP address in the Subject Alternative Name (SAN). The certificate should include an entry similar to:

    subject-alternative-name DNS:<server-name>, IP Address:<virtual-server-IP>

  5. Reconnect using the updated Edge Client.
  6. Verify that the IPsec tunnel is established by checking for IKE and IPsec SAs:
    tmsh show net ipsec ike-sa
    tmsh show net ipsec ipsec-sa
  7. Confirm that the BIG-IP log reports the tunnel as active. A successful connection includes entries similar to:

    tmm IPsec: Tunnel up <client-IP> - <virtual-server-IP>

    The IKE state should progress to:

    state ESTABLISHED

Additional Information

  • The initial HTTPS/TLS connection can succeed even when subsequent IPsec tunnel negotiation fails.
  • A lack of IKE or IPsec SAs and the absence of UDP/500 or UDP/4500 traffic indicate that IPsec negotiation has not completed.
  • The PPP not allowed - IPsec connectivity profile message does not necessarily indicate that the Access Policy is attempting to use a standard PPP-based Network Access VPN.
  • The server certificate’s IP SAN is required for this configuration.
