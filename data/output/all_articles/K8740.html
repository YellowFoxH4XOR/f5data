Known Issue

This is the result of a known issue. Disabled node(s) may cause the pvad process to crash during runtime, or when the BIG-IP system is initializing after system boot up. For example, this issue can occur when adding a new (disabled or downed) node to the BIG-IP configuration using the following bigpipe command:

bigpipe node <addr> { session disable }

When this issue occurs, a pvad core file will be generated and saved to the /var/core/ directory. In addition, the following error messages are logged to the /var/log/ltm file:

pvad[980]: 01130005:3: ../main.cpp:62 - obj id=165293256 key=<node_ip_address>: object wasn't found!
pvad[980]: 01130005:3: Expression 'cfgObj != cfg.end()' failed in '../CfgEvents.cpp', line: 594

In addition, creating new node(s) in the down state may cause the pvad process to crash and generate error messages in the /var/log/tmm file.

Note: Nodes may only be created in the down state from the CLI.

For example:

b node 10.0.0.10 {'
screen examplenode
limit 150
down
}'

If you run the example command to create the node 10.0.0.10 in the down state, the following error messages are logged to the /var/log/tmm file:

Jan 1 00:00:00 - MCP Message:
Jan 1 00:00:00 BIG-IP modify {
Jan 1 00:00:00 BIG-IP node_address {
Jan 1 00:00:00 BIG-IP node_address_addr 10.0.0.10
Jan 1 00:00:00 BIG-IP node_address_monitor_status 7
Jan 1 00:00:00 BIG-IP node_address_session_status 1
Jan 1 00:00:00 BIG-IP }
Jan 1 00:00:00 BIG-IP }
Jan 1 00:00:00 BIG-IP root: Re-starting pvad

F5 Product Development is tracking this issue as CR87183.

This issue was fixed in Hotfix-BIG-IP-9.3.1-HF4, issued for BIG-IP version 9.3.1. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about the F5 hotfix policy, refer to K4918: Overview of F5 critical issue hotfix policy.

For information about how to manage F5 product hotfixes, refer to K6845: Managing F5 product hotfixes.

Workaround

To work around this issue at startup, re-enable any disabled nodes prior to restarting the system. For example, the following command syntax enables the node:

bigpipe node <addr> { session enable }

To work around this issue at runtime, create the node first, then mark it down.

Note: You may perform both actions in either in the GUI or the CLI.
