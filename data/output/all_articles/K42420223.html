Topic

You should consider using this procedure under the following condition:

  • You want to create HTTP and HTTPS virtual servers with different profiles within a single F5 Modules for Ansible task.

Description

When deploying an application, you will often create HTTP and HTTPS virtual servers in tandem. You can use a loop with the bigip_virtual_server F5 module to create both an HTTP and HTTPS virtual server on a BIG-IP system in a single task.

Note: To learn how to run tasks only on the active BIG-IP in a device group, refer to K10531487: Running Ansible tasks on the active BIG-IP in a device group.

Example playbook

The following is an example of a playbook that creates two virtual servers: one HTTP virtual server on port 80 and one HTTPS virtual server on port 443 with a client side SSL profile.

---
- name: Create local traffic objects on a BIG-IP
  hosts: bigip14-1.askf5team.local
  gather_facts: False
  connection: local
  vars:
    provider:
      password: "{{ bigip_password }}"
      server: "{{ ansible_host }}"
      user: "{{ bigip_username }}"
      validate_certs: False
    profiles: "tcp-wan-optimized,http,wan-optimized-compression"

  tasks:
    - name: Create HTTP and HTTPS virtual servers
      bigip_virtual_server:
        provider: "{{ provider }}"
        name: "{{ item.name }}"
        destination: 198.51.100.1
        port: "{{ item.port }}"
        snat: "Automap"
        all_profiles: "{{ item.profiles }}"
        pool: "example_pool"
      loop:
        - { name: "server_port_80",
            port: 80,
            profiles: "{{ profiles }}"
          }
        - { name: "server_port_443",
            port: 443,
            profiles: "{{ profiles + ',example_client_ssl' }}"
           }
      notify:
        - Save the running configuration to disk
 
  handlers:
    - name: Save the running configuration to disk
      bigip_config:
        save: yes
        provider: "{{ provider }}"

Prerequisites

You must meet the following prerequisites to use the procedures in this article:

  • You are familiar with using Ansible.
  • You have Ansible 2.7 or later installed on the control machine.
  • You have BIG-IP 12.x or later installed on the devices in the environment.
  • You read the User's Guide section of F5 Modules for Ansible Documentation.
  • The Python packages required for each module or filter you want to use on the control machine are installed. For example, the F5 Modules require the f5-sdk package. For more information, refer to Module Index in the Ansible User Guide.

Procedures

  • Defining initial play settings
  • Creating a task that deploys the HTTP and HTTPS virtual servers and creating a handler to save the configuration
  • Running the playbook

Defining initial play settings

In this procedure you create your playbook, define play settings, and create a variable that lists the profiles you want both your virtual servers to have. In the subsequent procedure you add a client SSL profile to this list for only the HTTPS virtual server.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to your control machine.
  2. Create a playbook file called add_vip_80_443.yml in your playbooks directory.
  3. Create a play and define the name and hosts. Include the connection: local directive if all tasks are F5 Modules for Ansible, as shown in the example playbook. You can set gather_facts to false.
  4. In the vars parameter, create a playbook variable called provider. Add the BIG-IP connection details as the values to the provider variable. In the example, group variables from the group the host belongs to are used. You can reference the provider variable in the provider parameter of the F5 Module. You can encrypt BIG-IP passwords for the playbook by placing them in the vault. For more information, refer to K64450989: Using the 'ansible-vault' command to encrypt BIG-IP passwords used in a playbook.
  5. Also in vars, create a variable called profiles with the profiles that you want both virtual servers to have. The profiles must already exist in the configuration.

    For example:

    profiles: "tcp-wan-optimized,http,wan-optimized-compression"

    Refer to the example playbook at the beginning of the article for a complete view of the initial play settings.

Creating a task that deploys the HTTP and HTTPS virtual servers and creating a handler to save the configuration

In this procedure you create a task and handler in your play. You add a loop in the task to run the bigip_virtual_server module twice using the parameters you define in the loop. You take advantage of string concatenation to add the client SSL profile to only the HTTPS virtual server.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Create a task with the bigip_virtual_server module. Give the task a name and use the provider variable as the value for the provider parameter
  2. For the name, port, all_profiles parameters, and any other parameters you want to define with a list in the loop, reference each with item.* syntax.

    For example:

          loop:
            - { name: "server_port_80",
                port: 80,
                profiles: "{{ profiles }}"
              }
            - { name: "server_port_443",
                port: 443,
                profiles: "{{ profiles + ',example_client_ssl' }}"
               }

  3. Include a notify statement in this task to signal the handler you create in the next step to run.
  4. Create a handler that runs the bigip_config module to save the configuration changes you made to disk.

    Refer to the example playbook at the beginning of the article for a complete view of the bigip_virtual_server module task and bigip_config handler.

Running the playbook

After you've performed the previous procedures in this article, you can run the playbook from your control machine to make configuration changes to the BIG-IP devices in the play.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to your control machine.
  2. Change the working directory to the one with your playbooks.
  3. To run the playbook from the command line of your control machine, enter the following command:

    ansible-playbook add_vip_80_443.yml

    The output from the command appears similar to the following:

    PLAY [Create local traffic objects on a BIG-IP] ****************************************

    TASK [Create HTTP and HTTPS virtual servers] ****************************************
    changed: [bigip14-1.askf5team.local] => (item={u'name': u'server_port_80', u'profiles': u'tcp-wan-optimized,http,wan-optimized-compression', u'port': 80})
    changed: [bigip14-1.askf5team.local] => (item={u'name': u'server_port_443', u'profiles': u'tcp-wan-optimized,http,wan-optimized-compression,example_client_ssl', u'port': 443})

    RUNNING HANDLER [Save the running configuration to disk] ****************************************
    changed: [bigip14-1.askf5team.local]

    PLAY RECAP ****************************************
    bigip14-1.askf5team.local : ok=2 changed=2 unreachable=0 failed=0 skipped=0 rescued=0 ignored=0

  4. If you get an error when running the handler similar to FAILED! => {"changed": false, "msg": "No JSON object could be decoded"}, this is most likely cosmetic. You can verify if the configuration changes were written to disk by using the following syntax from the control machine:

    ssh <BIG-IP Advanced shell user>@<IP address of BIG-IP> 'grep "ltm virtual " /config/bigip.conf'

    For example:

    ssh root@10.1.1.9 'grep "ltm virtual " /config/bigip.conf'
