Description

Sensitive data, including Social Security Numbers (SSNs) and authorization headers, remain unmasked in response logs even after being added to the Sensitive Parameters list or enabling the Mask Value in Logs option in the header configuration.

Environment

  • Adv.WAF
  • Response Logging

Cause

This functionality is not currently supported. However, an open Request for Enhancement (RFE) — ID865953 — has been logged to address this in a future update.

Recommended Actions

The workaround applies only to masking sensitive data within the response body; it does not affect masking within response headers:

  1.  Ensure that Data Guard is enabled in the ASM policy.
  2. In Data Guard Configuration, add a regex pattern to detect the sensitive data.
  3. Disable the blocking flag for the violation Data Guard: Information leakage detected. This ensures that sensitive data is masked both in responses sent to clients and in response logs without blocking legitimate traffic.
