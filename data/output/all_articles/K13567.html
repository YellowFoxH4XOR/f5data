Topic

You should consider using this procedure under the following condition:

  • You want to synchronize DNS Express zones using a Sync-Only device group.

Description

The DNS Express feature allows a BIG-IP system to act as an authoritative secondary DNS server by performing zone transfers and serving DNS records faster than the primary DNS servers and local BIND servers.

You can configure a DNS Express zone on a BIG-IP system, and then synchronize the zones to a Sync-Only device group. This configuration helps to ensure that the zones will always be served by the active device group member.

Note: When you synchronize DNS Express zones to a Sync-Only device group, the BIG-IP system only synchronizes the zone configuration information. The system does not synchronize the actual DNS records for the zones; each DNS Express instance is responsible for transferring and maintaining its own DNS records.

To synchronize DNS Express zones using a Sync-Only device group, perform the following procedures:

  • Assigning ConfigSync and failover IP addresses to device group members
  • Creating a Sync-Only device group
  • Creating a folder (partition) that is linked to the device group
  • Adding DNS Express Zones to the folder
  • Running ConfigSync manually and verifying sync status

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have access to the TMOS Shell (tmsh).
  • Network connectivity is established between device group members.
  • NTP is configured on device group members.
  • DNS zones are configured on a BIG-IP GTM system or remote BIND server. If the zones reside on a remote BIND server, it must be configured to allow BIG-IP GTM systems to perform zone transfers.

Procedures

Assigning ConfigSync and failover IP addresses to device group members

Before you create the device group, you must assign ConfigSync and failover IP addresses to each device group member. The ConfigSync address is the self IP address that the system uses when synchronizing the configuration with peer devices. The failover address is the self IP address that the system uses for network failover. To assign a ConfigSync address, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Note: You should perform this procedure on each BIG-IP system that you add to the device group.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. Configure the self IP address that will be used for ConfigSync operations for each device. To configure the ConfigSync address, use the following syntax:

    modify /cm device <hostname> configsync-ip <ip_address>

    For example, the following command modifies the ConfigSync IP address for BIGIP.local.net to be the self IP address 10.10.10.100:

    modify /cm device BIGIP.local.net configsync-ip 10.10.10.100

  3. Configure the self IP address that will be used for failover. To configure the failover address, use the following syntax:

    modify /cm device <hostname> unicast-address {{ ip <ip_address> }}

    For example, the following command modifies the failover IP address for BIGIP.local.net to be the self IP address 10.10.10.100:

    modify /cm device BIGIP.local.net unicast-address {{ ip 10.10.10.100 }}

  4. Save the configuration by typing the following command:

    save /sys config

Creating a Sync-Only device group

Creating a device group also involves joining any BIG-IP devices that you intend to add to the device group to the same local trust domain. To add devices to the same local trust domain and create the Sync-Only device group, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. Add the peer devices to the local trust domain using the following syntax:
    • BIG-IP 13.x and later

      modify /cm trust-domain /Common/Root add-device { device-ip <mgmt_ip_address> device-name <device name> username <admin_username> password <admin_password> ca-device true }

      For example, the following command adds the remote device called BIGIP.remote.net (with the management IP address of 172.24.10.100, and the administrator user name and password of admin/admin) to the local system's trust domain:

      modify /cm trust-domain /Common/Root add-device { device-ip 172.24.10.100 device-name BIGIP.remote.net username admin password admin ca-device true }

    • BIG-IP 11.x - 12.x

      modify /cm trust-domain /Common/Root ca-devices add { <mgmt_ip_address> } name <device name> username <admin_username> password <admin_password>

      For example, the following command adds the remote device called BIGIP.remote.net (with management IP address of 172.24.10.100, and administrator username and password of admin/admin) to the local system's trust domain:

      modify /cm trust-domain /Common/Root ca-devices add { 172.24.10.100 } name BIGIP.remote.net username admin password admin

  3. Verify that the trust domain contains the correct devices, by typing the following command:

    list /cm trust-domain

  4. Save the configuration by typing the following command:

    save /sys config

  5. Repeat steps 2 through 4 for each BIG-IP system that you want to add to the local trust domain.
  6. Create a device group and add the peer devices to the device group using the following syntax:

    create /cm device-group <device_group_name> devices add { <local_device_name> <remote_device_name> } type sync-only auto-sync enabled

    For example, the following command creates a Sync-Only device group named My-Dev-Group, containing the local device called BIGIP.local.net and remote devices BIGIP.remote1.net and BIGIP.remote2.net:

    create /cm device-group My-Dev-Group devices add { BIGIP.local.net BIGIP.remote1.net BIGIP.remote2.net } type sync-only auto-sync enabled

  7. Save the configuration by typing the following command:

    save /sys config

Creating a folder (partition) that is linked to the device group

Create a folder (partition) that is linked to the device group. The folder will be used to synchronize the DNS Express zones to device group members. To create the folder object, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by tying the following command:

    tmsh

  2. Create a folder object that is linked to the device group using the following syntax:

    create /sys folder /<folder_name> device-group <device_group_name> traffic-group none

    For example, the following command creates a folder named My-Folder, which is linked to the Sync-Only device group named My-Dev-Group:

    create /sys folder /My-Folder device-group My-Dev-Group traffic-group none

  3. Save the configuration by typing the following command:

    save /sys config

Adding DNS Express zones to the folder

To add the DNS Express zones to the newly created folder, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. Change to the newly-created folder using the following syntax:

    cd /<folder_name>

    For example, the following command changes to the /My-Folder folder:

    cd /My-Folder

  3. Create the DNS Express zone using the following syntax as appropriate for your BIG-IP version:
    • BIG-IP 11.5.0 and later

      create /ltm dns nameserver <GTM_or_BIND_server_name> address <GTM_or_BIND_server_IP> port <DNS_port>
      create /ltm dns zone <zone_name> dns-express-enabled yes dns-express-server <GTM_or_BIND_server_name>

      For example, to create a DNS express zone named My-Zone that performs a zone transfer from the BIG-IP GTM localhost, you would type the following commands:

      create /ltm dns nameserver GTM_NS address 127.0.0.1 port 53
      create /ltm dns zone My-Zone dns-express-enabled yes dns-express-server GTM_NS

    • BIG-IP 11.0.0 through 11.4.1

      create /ltm dns dns-express zone <zone_name> transfer-target <GTM_or_BIND_server_IP> enabled

      For example, to create a DNS Express zone named My-Zone that performs a zone transfer from the BIG-IP GTM localhost, you would type the following command:

      create /ltm dns dns-express zone My-Zone transfer-target 127.0.0.1 enabled

  4. Save the configuration by typing the following command:

    save /sys config

Running ConfigSync manually and verifying sync status

After you have completed the previous procedures, you can synchronize the DNS Express zones by running ConfigSync manually. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by typing the following command:

    tmsh

  2. Run the ConfigSync process using the following syntax:

    run /cm config-sync <sync_direction> <sync_group>

    For example, the following command pushes the local device's configuration to remote devices in the My-Dev-Group device group:

    run /cm config-sync to-group My-Dev-Group

  3. After running the ConfigSync process, you can check the sync status by typing the following command:

    show /cm sync-status

    The following output shows a successful sync status between a device group containing two members:

    ----------------------------------------------------------------------------
    CM::Sync Status
    ----------------------------------------------------------------------------
    Color    green
    Status   In Sync
    Summary
    Details
             /Common/BIGIP.local.net: connected (for 2548 seconds)
             /Common/My-Dev-Group (In Sync):
              - all 2 devices consistent
             /Common/device_trust_group (In Sync):
              - all 2 devices consistent
