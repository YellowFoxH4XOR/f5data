K000158935: An F5OS host on R5000/R10000 platforms is unable to use the :nnn interface flag to capture extended f5ethtrailer info in the pcap

Type
Support Solution
Published
2025-12-29
Updated
2025-12-29
Applies to
  • F5OS
  • rSeries Platforms
  • F5OS-A: 1.8.X, 1.8.3, 1.8.0
  • rSeries 5000
  • rSeries 10000
Source
https://my.f5.com/manage/s/article/K000158935

Description

On R5000/R10000 platforms, an F5OS host pcap is unable to use the :nnn interface flags to capture extended F5-specific capture headers (f5ethtrailer info) in the pcap.

 

Environment

F5OS on R5000/R10000 platforms

 

Cause

This is by design and unfortunately the F5OS host is currently unable to capture extended f5ethtrailer info in the pcap.

 

Recommended Actions

None.


Additional Information

Sample capture output for a successful capture start with cmdline:

 

[root@appliance-1(R10900-R9-S42):Active] ~ # tcpdump -s0 -i 19 -w /var/tmp/test.pcap

tcpdump: listening on veth8d9049e, link-type EN10MB (Ethernet), capture size 262144 bytes

<...>

 

Sample capture output for an unsuccessful capture with cmdline including :nnn after the interface name, as an attempt to capture including extended f5ethtrailer info:

 

[root@appliance-1(R10900-R9-S42):Active] ~ # tcpdump -s0 -i 19:nnn -w /var/tmp/test.pcap

tcpdump: 19:nnn: No such device exists

(SIOCGIFHWADDR: No such device)

 

[root@appliance-1(R10900-R9-S42):Active] ~ # tcpdump -s0 -i 19:n -w /var/tmp/test.pcap

tcpdump: 19:n: No such device exists

(SIOCGIFHWADDR: No such device)
