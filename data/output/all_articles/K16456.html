Known Issue

The Traffic Management Microkernal (TMM) may restart or disabled server-side connections may be reused when a OneConnect profile is configured and OneConnect reuse is disabled by an iRule.

This issue occurs when all of the following conditions are met:

  • You have configured a virtual server to use a OneConnect profile.
  • The virtual server references an iRule that disables OneConnect reuse on server-side connections.

    For example:

    when SERVER_CONNECTED {
      if { [clientside ONECONNECT::reuse] } {
      ONECONNECT::reuse disable
      }
    }

Impact

In BIG-IP 11.3.0 and earlier, TMM may restart. In 11.4.0 and later, disabled connections may be unexpectedly reused.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP system fails to process traffic for a brief period of time.
  • The BIG-IP system fails over to another host in the device group.
  • TMM generates a core file in the /var/core directory.

Workaround

To work around this issue, you can ensure that iRules apply to both the client and server side of the connection and have the necessary commands applied:

11.4.0 and later

Client side

In the client-side iRule event, replace the following command:

ONECONNECT::reuse disable

With the following command:

set oc_reuse_ss_disable 1

An example client-side iRule:

when HTTP_REQUEST {
  set oc_reuse_ss_disable 1
  CACHE::disable
  COMPRESS::disable
  HTTP::disable
}

Server side

The server-side command should contain the following commands:

info exists oc_reuse_ss_disable
ONECONNECT::reuse disable

An example server-side iRule:

when SERVER_CONNECTED {
  if { [info exists oc_reuse_ss_disable] } {
  ONECONNECT::reuse disable
  }
}

11.3.0 and earlier

Client side

The client-side iRule event should contain the following commands:

ONECONNECT::reuse disable
CACHE::disable
COMPRESS::disable
HTTP::disable

An example client-side iRule:

when HTTP_REQUEST {
  set oc_reuse_ss_disable 1
  ONECONNECT::reuse disable
  CACHE::disable
  COMPRESS::disable
  HTTP::disable
}

Server side

The server-side iRule event should contain the following commands:

ONECONNECT::reuse disable
ONECONNECT::detach disable

An example server-side iRule:

when SERVER_CONNECTED {
  if { [info exists oc_reuse_ss_disable] } {
  ONECONNECT::reuse disable
  ONECONNECT::detach disable
  }
}
