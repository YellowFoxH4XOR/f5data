K12152714: New connection attempts intermittently result in reset cause ''TCP Closed'' from BIG-IP after upgrade to 14.1.0

Type
Support Solution
Published
2023-03-22
Updated
2025-02-06
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K12152714

Description

New connections that attempt to use the port already in use by an orphaned connection are reset with [0x2830261:5357] TCP closed
 

Environment

  • Upgraded BIG-IP 14.1.0
  • Users complain of intermittent failed connections when accessing a virtual server.
  • TCP Capture shows Immediate reset

Cause

Known Bug ID754143

Recommended Actions

In order to verify this bug is the cause of TCP resets, you can do the following steps:
  1.  Enable TCP Reset cause (packet)
    1. K13223 - Enable TCP reset cause logging and packet trailer
  2. Verify you are seeing "TCP Closed" (hex: 0x2830261:<port>) intermittently on a given Virtual server.
If these are occurring, Please see the Detailed explanation and actions in the following article: 

K45456231: TCP connections may become orphaned when the server-side connection times out
 

Additional Information
 

This issue can be resolved by rebooting the BIG-IP system

  1. Log in to the Advanced Shell (bash).
  2. To restart the system, type the following command:

reboot



This issue was resolved in 14.1.0.2 and is fixed in 15.0.0
