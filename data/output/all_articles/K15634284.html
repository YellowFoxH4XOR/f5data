Source

Description

Intermittently SSL traffic fails on a virtual server.

Environment

The BIG-IP uses Safenet HSM

  • LTM logs show "FIPS acceleration device failure: cannot locate key" messages
  • Daemon logs show "Nethsm: pkcs11_op_enqueue queue full qhead 1151 qtail 639"

Cause

The error "Nethsm: pkcs11_op_enqueue queue full qhead 1151 qtail 639" indicates HSM is not fast enough processing handshakes. It could be slow pkcs11d, slow network or slow HSM. 

Recommended Actions

The actions or steps required to address the topic covered in the description.

  1. Collect concurrent tcpdumps on the BIG-IP & HSM.
    • Check for connectivity issues.
    • Note any impacted tmms.
       
  2. Enable HSM debug & logging
    • tmsh modify sys db log.pkcs11d.level value debug
       
  3. Make a copy of the Safenet client library under a different name
    • cp /usr/lunasa/lib/libCryptoki2_64.so /usr/lunasa/lib/libCryptoki2_64.so.orig
       
  4. Edit /etc/Chrystoki.conf and add this section:
     
    • CkLog2 = {
         LibUNIX64=/usr/lunasa/lib/libCryptoki2_64.so.real;
         Enabled=1;
         File=/var/log/cklog.log;
         Error=/var/log/cklog-error.log;
         NewFormat=1;
         LoggingMask=ALL_FUNC;
      }
  5. Replace /usr/lunasa/lib/libCryptoki2_64.so with a symlink to libcklog2.so, as pkcs11d is hardcoded to try to open "/usr/lunasa/lib/libCryptoki2_64.so".
    • ln -sf /usr/lunasa/lib/libcklog2.so /usr/lunasa/lib/libCryptoki2_64.so
       
  6. Restart pkcs11d
    • tmsh restart sys service pkcs11d
    • Note: This requires restarting pkcs11d so it could resolve the issue. It is also traffic impacting so perform during a maintenance window.
  7. If the problem persists, collect another set of simultaneous packet captures on the BIG-IP and HSM.
     
  8. Generate a diagnostic core of tmm.
    • killall -v -s 6 tmm
    • Note: This is traffic impacting so perform during a maintenance window.
       
  9. Undo HSM debug & logging.
    • Replace /usr/lunasa/lib/libCryptoki2_64.so with the original (actual) library:
      • rm -f /usr/lunasa/lib/libCryptoki2_64.so
      • cp /usr/lunasa/lib/libCryptoki2_64.so.orig /usr/lunasa/lib/libCryptoki2_64.so
    • Restart pkcs11d
      • bigstart restart pkcs11d
    • Remove the CkLog2 section from /etc/Chrystoki.conf (Optional)
    • Disable debug on HSM
      • tmsh modify sys db log.pkcs11d.level value error

Additional Information

Enable Policy 16 on the HSM to test if this resolves the issue. Policy 16 removes RSA blinding and improves performance, but reduces security.

Policy 16 = ON
If this is allowed, the partition may run in a mode that does not use RSA blinding.

Policy 16 = OFF
If feature is disallowed, the partition will always run in RSA blinding mode; performance will be lower than SafeNet published performance.
