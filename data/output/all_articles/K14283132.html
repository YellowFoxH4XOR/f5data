Description

  • You reboot a Cloud Ve and the Management IP is pingable for a few seconds then does not respond.
  • The Management IP continues to be pingable from another device in that subnet, typically another BIG-IP.

Environment

  •  Not a 1 Nic image
Cause

When the device boots it starts with the prior settings. Its pingable from another subnet.
After a few seconds dhcp runs to set the Management IP and also the Management Routes.
If any of the routes in dhcp are already statically defined, then dhcp will not set any Management Routes.
For example the default and metadata-route are normally set by dhcp. If metadata-route is statically set we see this in /var/log/ltm:

Configuration error: invalid Management Route, the dest/netmask pair 169.254.169.254/255.255.255.255 already exists for /Common/metadata-route
dhcp will not set the default management route and any working route set by dhcp will be removed.

Recommended Actions

Remove the conflicting Management Route.  At the CLI:
  1. tmsh list sys management-route     ## we need the Management Route's name
  2. tmsh delete sys management-route <name>     ## metadata-route in this example
  3. tmsh save sys config
  4. bigstart restart dhclient
  5. tmsh list sys management-route       ## the correct routes should be visible
Additional Information

If you can't get access to the Management IP by using a peer device in the same subnet, try the self Ip. The "default" port lockdown allows https and ssh.
Self Ip's do not use the Management Routes.
