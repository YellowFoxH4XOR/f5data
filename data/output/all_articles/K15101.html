Topic

When a Windows client system establishes a Network Access tunnel with a BIG-IP APM system, any pre-existing connections to target systems with IP addresses defined in the split tunnel configuration remain connected through the existing route after the tunnel is created. As a result, these connections are not routed through the Network Access tunnel.

Note: To ensure the Windows OS you are using is supported, refer to the BIG-IP APM Client Compatibility matrix for your version. For information about how to locate F5 product manuals, refer to K98133564: Tips for searching AskF5 and finding product documentation.

Description

When split tunneling is enabled in the BIG-IP APM Network Access configuration, you can define target IP addresses for which traffic is routed over the Network Access tunnel. Clients route traffic through the tunnel based on entries added to their routing table by the BIG-IP APM system. Client traffic destined for other IP addresses bypass the tunnel using existing routes on the client.

Beginning in Windows Vista, Windows systems implement the strong host model by default. For multi-homed systems, the strong host model ensures traffic can only be sent and received on the network interface configured with the associated source or destination IP address in the packet. This provides security against multi-homed attacks since a network interface will not accept traffic with a destination IP address configured on another interface.

When the strong host model is enabled on Windows clients and long lived connections, such as SSH, exist to target IP addresses defined in the split tunneling configuration prior to Network Access tunnel creation, subsequent tunnel creation does not close the connections. The existing connections remain intact through the existing routes and are not routed through the tunnel even though matching routes have been added to the client. This occurs when the BIG-IP APM system is configured for split tunneling and Integrated IP filtering engine is cleared. This is an expected behavior and does not occur in Linux or Mac OS X systems since they do not implement the strong host model by default.

Recommendations

If you want to force the closure of these existing connections after a Network Access tunnel is established, you can choose one of the following options:

  • Disable split tunneling by selecting the Force all traffic through the tunnel check box in the Network Settings section of the Network Access configuration.
  • Enable client side IP filtering by selecting the Integrated IP filtering engine check box in the Network Settings section of the Network Access configuration.
  • Disable strong host functionality on the client.
