K000160746: Identifying Stalled SAML Single Logout (SLO) connections when the BIG-IP is the Service Provider (SP)

Support Solution

Applies to

Source

Description

When using SAML with the BIG-IP as a Service Provider, during logout the sessions can often stall if misconfigured incorrectly on the IdP.

Environment

  • SAML Single Logout
  • BIG-IP APM as SAML Service Provider
  • Third Party IdP such as Okta

Cause

Generally this is due to one of 2 things:

  1. Manually configured SAML Configuration on the IdP including the SP connector with a misconfigured SAML SLO URL.
  2. Modified SLO URL in the IdP connector.
  3. Custom iRule configuration that causes unexpected logout routes and apm session removal

You can identify this by reviewing an HTTPWatch/Decrypted Fiddler of the Logout.

The HTTPWatch will show the user send the SAML SLO Request to the IdP and then there will be no redirect back to the IdP.

Recommended Actions

This is not an issue with the BIG-IP, the recommendation is to review the SLO documentation and ensure the correct SLOs are on the IdP. (see below)
