Known Issue

An Internet Key Exchange (IKE) Peer Remote Address and IPsec Policy Tunnel Remote Address mismatch may cause the Traffic Management Microkernel (TMM) process to restart and produce a core file.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP system uses an IPsec tunnel configuration that includes IKE peers, an IPsec policy, and an IPsec traffic selector.
  • The IP address for the IKE Peer Remote Address does not match the IP address for the IPsec Policy Tunnel Remote Address.
  • Your BIG-IP system attempts to process IPsec tunnel traffic for the affected tunnel.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from the TMM restart, and devices configured as a high availability (HA) pair may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Your BIG-IP system temporarily fails to process traffic as it recovers from TMM restarting.
  • Devices configured as an HA pair fail over.
  • TMM produces a core file in the /shared/core directory.

Workaround

To work around this issue, ensure that you have configured the IKE Peer Remote Address and the IPsec Policy Tunnel Remote Address to use the same IP address.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
