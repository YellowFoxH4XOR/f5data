Overview of the pool of available MAC addresses

Each BIG-IP system has a pool of available MAC addresses that can be assigned to interfaces, trunks, and VLANs. The pool consists of 64 addresses on all platforms, with the exception of the VIPRION platform where 512 addresses are available on each blade. The address range of the pool can be determined by adding 63 or 511 (depending on the platform) to the base MAC address of the BIG-IP system. However, because MAC addresses are represented as hexadecimal values, you would actually have to perform one of the following hexadecimal additions, where the hexadecimal numbers 3F and 1FF are the equivalent of the decimal numbers 63 and 511:

<base MAC address> + 3F

<base MAC address> + 1FF

To determine the base MAC address of the BIG-IP system, use either of the following two commands:

bigpipe platform | grep 'base MAC'

tmsh show sys hardware | grep 'Base MAC'

For example, supposing a BIG-IP 6900 system has a base MAC address of 00:01:D7:A1:9D:80, the range of available MAC addresses would be 00:01:D7:A1:9D:80 - 00:01:D7:A1:9D:BF (80+3F = BF).

MAC address assignment for interfaces

The BIG-IP system assigns a MAC address from the pool to each interface, including the management interface and hidden interfaces. However, switch interfaces only use their assigned MAC address for L2 protocols (STP, LACP, etc.). The BIG-IP system uses the MAC address of the VLAN to pass L3 or above traffic.

BIG-IP 9.4.0 and later

In BIG-IP 9.4.0 and later, each platform has a fixed order of interfaces that are independent of the order of PCI device probing. This fixed order specifies that a MAC address is fixed for each interface and will not change.

Note: BIG-IP versions prior to 9.4.0 do not behave the same, and this is discussed in the next section. If you upgrade to BIG-IP 9.4.0 or later, the MAC address assignment for each interface will change. This change can affect secure environments in which the MAC address is used to determine which devices are allowed to communicate within the network.

BIG-IP versions prior to 9.4.0

In BIG-IP versions prior to 9.4.0, the MAC address assignment for each interface is performed though a PCI probe on startup. The order of the interfaces depends on the sequence of the PCI device probed. MAC addresses are assigned to each interface, starting from the base MAC address, based on their sequence when the PCI probe found each interface.

Note: The order of the probed PCI devices is typically fixed, but there is no guarantee this order will remain fixed.

Displaying the MAC address assigned to each interface

You can display the MAC address assigned to each interface by running either of the following two commands:

bigpipe interface show all | grep INTERFACE

tmsh show sys mac-address | grep interface

MAC address assignment for trunks

When a trunk is configured through the Configuration utility or from the command line, a MAC address from the pool is assigned to the trunk. However, like switch interfaces, trunks only use their assigned MAC address for L2 protocols. The BIG-IP system uses the MAC address of the VLAN to pass L3 or above traffic.

Displaying the MAC address assigned to each trunk

You can display the MAC address assigned to each trunk by running either of the following two commands:

bigpipe trunk show all | grep TRUNK

tmsh show sys mac-address | grep trunk

MAC address assignment for VLANs

When a VLAN is created, a MAC address from the pool is assigned to the VLAN. The BIG-IP system may re-use one of the interface MAC addresses for a VLAN. The BIG-IP system uses this MAC address to pass L3 or above traffic

BIG-IP 10.x

The following bigpipe database variable controls how MAC addresses are assigned to VLANs:

Vlan.MacAssignment

The possible values for the variable are unique and global. The default value is unique.

When the variable is set to unique, each VLAN is assigned a unique MAC address from the pool. However, this is only true as long as there are available MAC addresses to assign. If you create many VLANs, the BIG-IP system will start assigning the same MAC address to multiple VLANs.

When the variable is set to global, all VLANs are assigned the same MAC address.

In either case, multiple VLANs can safely share the same MAC address as long as your other network devices support a per-VLAN MAC address table. This allows those devices to learn the same MAC address on multiple VLANs without issue. This is a very common feature.

To view the current value of the bigpipe database variable, type the following command:

bigpipe db Vlan.MacAssignment

To change the value of the bigpipe database variable, type one of the following two commands:

bigpipe db Vlan.MacAssignment unique

bigpipe db Vlan.MacAssignment global

This variable can also be modified through the Configuration utility by checking or unchecking the Share Single MAC Address option, which can be found under System >> Configuration >> Local Traffic >> General. When the option is checked, the variable is set to global; when the option is unchecked, the variable is set to unique.

Important: If you modify this variable in BIG-IP versions prior to 10.1.0 (either through the Configuration utility or from the command line), you must restart the services by running the bigstart restart command. This is no longer necessary in later versions.

BIG-IP 9.x

The following bigpipe database variable controls how MAC addresses are assigned to VLANs:

Vlan.MacAssignment

The possible values for the variable are first-member and global. The default value is first-member.

When the variable is set to first-member, each VLAN is assigned the MAC address of its first member interface.

Note: Because of the architecture of the BIG-IP system, a VLAN will also include some hidden interfaces, and these hidden interfaces are also considered for the selection. For example, if you create a VLAN on a BIG-IP 6900 system, the 0.1, 0.2, 0.3, 0.4 and 4.1 hidden interfaces will also be assigned to the VLAN along with the regular interface you selected.

Note: If the MAC address of the first member interface is already in use by another VLAN, then the VLAN will use the MAC address of the next available member interface. If none of the MAC addresses of the member interfaces are available, then the VLAN will use a MAC address that is already being used by a different VLAN.

For example:

  • A BIG-IP 6900 system running version 9.x is not currently configured with any VLAN.
  • Ten different VLANs are configured on this system, and they are all assigned interface 1.1.
  • As discussed above, each of these VLANs will also be assigned the 0.1, 0.2, 0.3, 0.4 and 4.1 hidden interfaces.
  • The BIG-IP system will assign the following MAC addresses to the VLANs:

    vlan1: the MAC address of interface 0.1
    vlan2: the MAC address of interface 0.2
    vlan3: the MAC address of interface 0.3
    vlan4: the MAC address of interface 0.4
    vlan5: the MAC address of interface 1.1
    vlan6: the MAC address of interface 4.1

    /* the MAC addresses of all member interfaces have now been used */

    vlan7: the MAC address of interface 4.1
    vlan8: the MAC address of interface 4.1
    vlan9: the MAC address of interface 4.1
    vlan10: the MAC address of interface 4.1

When the variable is set to global, all VLANs are assigned the same MAC address.

In either case, multiple VLANs can safely share the same MAC address as long as your other network devices support a per-VLAN MAC address table. This allows those devices to learn the same MAC address on multiple VLANs without issue. This is a common feature.

To view the current value of the bigpipe database variable, type the following command:

bigpipe db Vlan.MacAssignment

To change the value of the bigpipe database variable, type one of the following two commands:

bigpipe db Vlan.MacAssignment first-member

bigpipe db Vlan.MacAssignment global

You can modify this variable through the Configuration utility by selecting or clearing the Share Single MAC Address option, which can be found under System > Configuration > Local Traffic > General. When the option is selected, the variable is set to global; when the option is cleared, the variable is set to first-member.

Important: If you modify this variable (either through the Configuration utility or from the command line), you must restart the services by running the bigstart restart command.

Displaying the MAC address assigned to each VLAN

You can display the MAC address assigned to each VLAN by running either of the following two commands:

bigpipe vlan

tmsh show net vlan

Invalid MAC address assignment for VLANs

Under certain conditions, the BIG-IP system may not initialize a VLAN properly and assign an invalid MAC address, such as 00:00:00:00:00:00 or null, to the VLAN. As a result, traffic fails to traverse the affected VLAN. You can identify the affected VLAN by typing the following command from the BIG-IP command line:

ifconfig -a | grep HWaddr

If the output displays an all-zero MAC address (00:00:00:00:00:00) or null for a VLAN, traffic will fail to traverse that VLAN. For example, traffic is unable to traverse external VLAN because the MAC address assigned to it is all-zero:

external Link encap:Ethernet HWaddr 00:00:00:00:00:00

The following two known issues cause the BIG-IP system to assign an invalid MAC address to a VLAN:

  • K11200: BIG-IP assigns MAC address of 00:00:00:00:00:00 for 62nd configured VLAN
  • K12362: VIPRION systems may assign an all-zero MAC address to a VLAN when the vlan.assignment DB variable is set to global

If your BIG-IP system assigns a VLAN with an all-zero MAC address or null, but is not affected by the issues described in SOL11200 or SOL12362, contact F5 Technical Support for further assistance.
