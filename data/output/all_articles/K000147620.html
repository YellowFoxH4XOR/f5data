K000147620: How to move traffic between origin servers without interruption

Description

You want to find a way to move traffic between origin servers without interruptions nor HTTP 504s or HTTP 408s

Environment

  • F5® Distributed Cloud HTTP Load Balancers

Answer/Recommended Actions

To ensure a smoother transition for your end users, we recommend creating a new Origin Pool for the new server.

  • Create a new Origin Pool, or clone the Origin Pool currently assigned to the LB.
  • Add the new Origin Pool to the Load Balancer with a Priority of 0.  The effect is that traffic would be sent to the new pool only if all endpoints of the legacy pool are unavailable.
    • NOTE: Depending on LB configuration, the pool assignment may need to be done at the LB level or on a Route, or both.

  • Go to the Performance Dashboard, select the LB and go to the "Origin Servers" tab.  Ensure that all endpoints of the new Origin Pool are healthy.
  • When ready to switch to the new origin, go back to the HTTP LB and invert the Priority settings on the Origin Pools, i.e. set the new pool to Priority: 1 and the old pool to Priority: 0
    • NOTE: Depending on LB configuration, the pool assignment may need to be done at the LB level or on a Route, or both.

  • User traffic should switch to the new Origin Pool.  Existing sessions may remain on the old pool depending on timeout settings.  You can monitor which pool is taking the traffic in the Requests tab (either Security or Performance dashboard) using the 'dst' or 'dst_ip' filters.
  • Once confirmed that all existing sessions to the old Origin Pool have been completed, remove the old Origin Pool from the Load Balancer.
  • This approach ensures a seamless switch while minimizing any disruptions for your users.
    • Some users may have to refresh a page or re-authenticate, but the application should remain continuously available through the process.

 

Additional Information

  • Endpoints in a newly-created Origin Pool do not typically become available immediately upon creation.  Endpoint discovery (for DNS-defined origin servers) and healthcheck must first be processed with success before the endpoints become available.  Attaching the new Origin Pool to the LB in 'standby' priority mode facilitates status monitoring of those discovery/healthcheck operations across all global PoPs within the LB object in XC console dashboard,
