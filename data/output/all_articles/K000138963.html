K000138963: Unable to switch to TMSH mode

Type
Support Solution
Published
2024-03-22
Updated
2024-04-02
Applies to
  • BIG-IP
  • BIG-IP Platforms
Source
https://my.f5.com/manage/s/article/K000138963

Description

After the upgrade, you are unable to enter TMSH mode on CLI. A similar output can be found:

bash-4.2# tmsh exception: (Can't open command history file (/root/.tmsh-history-root), No such file or directory) (framework/CmdHistoryFile.cpp, line 92), exiting...

You also confirmed that user's home directory and the .bashrc file exist, as mentioned in the following article:  K000130016: BIG-IP CLI prompt shows only bash-4.2#, can't switch to tmsh

Environment

  • CLI
  • Bash
  • TMSH
  • After upgrading the BIG-IP

Cause

The file system in Linux may become corrupted after an upgrade due to various reasons.

Recommended Actions

You may choose one of the below options to fix the problem.

  1. Force filesystem check:
    K73827442: Forcing a file system check on the next system restart (12.x - 16.x)

  2. If the above does not resolve the problem then you may perform rollback to the previous boot location and install software again to the new one.

  3. OR perform a clean install and restore the configuration from UCS file.
    K13117: Performing a clean installation of BIG-IP 11.x - 17.x
    K13132: Backing up and restoring BIG-IP configuration files with a UCS archive
