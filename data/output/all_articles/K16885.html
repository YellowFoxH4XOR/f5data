Topic

You should consider using this procedure under any of the following conditions:

  • You want to disable Address Resolution Protocol (ARP) for a virtual address.
  • You want to disable Internet Control Message Protocol (ICMP) echo response for a virtual address.

Description

You can control whether the virtual address sends responses to Internet Control Message Protocol (ICMP) and Address Resolution Protocol (ARP) requests. Disabling a virtual server prevents the virtual server from accepting new connections, but the virtual address may still advertise through Address Resolution Protocol (ARP) and respond to Internet Control Message Protocol (ICMP) echo packets. A disabled virtual server, even a deleted virtual server, continues to process existing connections.

The following Configuration utility settings are used to control the behavior for a virtual address:

ICMP Echo

This setting specifies how the BIG-IP system sends responses to ICMP requests on a per-virtual address basis. By default, the BIG-IP system intercepts ICMP echo request packets and responds to them directly, regardless of the state of any virtual servers associated with the virtual address. When this setting is disabled, the BIG-IP system drops any ICMP echo request packets sent to virtual addresses, including standard statistics and logging. By default, the BIG-IP system always respond to ICMP echo requests when a request sends to this virtual address.

Note: Enabling ICMP Echo on a virtual address causes the BIG-IP system to use original destination's IP address when sourcing ICMP Echo and other ICMP error messages, such as time to live (TTL) expired in transit messages.

ARP

You can use this settings to enable or disable ARP requests for a virtual address. By default, the BIG-IP system responds to ARP requests for a virtual address, regardless of the state of any virtual servers associated with the virtual address. When this setting is disabled, the BIG-IP system ignores ARP requests that other routers send for this virtual address. By default, the BIG-IP system respond to a ARP requests when a request sends to this virtual address.

Note: Disabling all virtual servers does not stop the virtual address from replying to ICMP requests. The Selective option stops replying to ICMP requests only when all virtual servers (same IP address) are put into an offline state by a monitor or when all pool members are forced offline. For more information, K13310: Disabling nodes or pool members for maintenance (11.x - 15.x).

Prerequisites

You must meet the following prerequisite to use this procedure:

  • You must have administrative access to the system.

Procedures

To disable ARP and ICMP echo for a virtual address, perform one of the following procedures:

  • Using the Configuration utility to disable ARP for a virtual address
  • Using tmsh to disable ARP for a virtual address
  • Using the Configuration utility to disable ICMP Echo for a virtual address
  • Using tmsh to disable ICMP Echo for a virtual address

If you prefer the behavior of the BIG-IP response to ICMP echo packets to be based on the state of the virtual servers associated with the virtual address, you must configure the virtual address ICMP Echo setting with Selective, and choose the virtual address Advertise Route setting most appropriate for your environment. To do so, perform one of the following procedures:

  • Using the Configuration utility to selectively respond to ICMP echo for a virtual address
  • Using tmsh to selectively respond to ICMP echo for a virtual address

Using the Configuration utility to disable ARP for a virtual address

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Go to Local Traffic > Virtual Servers > Virtual Address List.
  2. Select the Virtual Address to be modified.
  3. Clear the ARP check box.
  4. Select Update.

Using tmsh to disable ARP for a virtual address

You can disable ARP for a virtual address using the TMOS Shell (tmsh) by performing the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. Disable ARP for the virtual address by using the following command syntax:

    modify /ltm virtual-address <virtual_address> arp disabled

    In the previous syntax, note the following:

    • <virtual_address> is the IP address of the virtual address in question.

  3. Save the change by entering the following command:

    save /sys config

Using the Configuration utility to disable ICMP Echo for a virtual address

You can disable ICMP Echo for a virtual address using the Configuration utility, by performing the following steps:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Go to Local Traffic > Virtual Servers > Virtual Address List.
  2. Select the Virtual Address you want to modify.
  3. For ICMP Echo, select the Disabled option:

    BIG-IP 13.1.0 and later

    • Disabled: The system does not send ICMP responses.
    • Always: The system always sends ICMP responses, regardless of availability status. This requires an enabled virtual address.
    • Selective: The system internally enables or disables responses based on virtual server state: any virtual server, all virtual servers, or always, regardless of the state of any virtual server.

      Note: For Selective, you must configure each relevant virtual server to notify the virtual address of its status.

    • Any: The system responds when any virtual server is available.
    • All: The system responds only when all virtual servers are available.

    BIG-IP 11.5.2 through BIG-IP 13.0.0

    • Enabled: The system always sends an ICMP echo response for an ICMP request packet sent to the virtual address, regardless of the state of any virtual servers associated with the virtual address.
    • Disabled: The system does not send ICMP responses.
    • Selective: The system internally enables or disables ICMP responses for the virtual address based on associated virtual server status.
  4. Select Update.

Using tmsh to disable ICMP Echo for a virtual address

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to tmsh by entering the following command:

    tmsh

  2. Disable ICMP echo for the desired virtual address by using the following command syntax:

    modify /ltm virtual-address <virtual_address> icmp-echo disabled

    In the previous syntax, note the following:

    • <virtual_address> is the IP address of the virtual address in question.

  3. Save the change by entering the following command:

    save /sys config

Using the Configuration utility to selectively respond to ICMP echo for a virtual address

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Go to Local > Virtual Servers > Virtual Address List.
  2. Select the Virtual Address you want to modify.
  3. For the ICMP Echo setting, select Selective.
  4. Select Update.

Using tmsh to selectively respond to ICMP echo for a virtual address

Impact of procedure: Performing the following procedure should not have a negative impact on your system. 

  1. Log in to tmsh by entering the following command:

    tmsh

  2. Configure selective ICMP echo response behavior for the virtual address by using the following command syntax:

    modify /ltm virtual-address <virtual_address> icmp-echo selective server-scope [none | any | all]

    Note: When configuring the ICMP echo response behavior, use the any server-stop command when any virtual server node is available, and ICMP responses generate when at least one node in the pool attached to a virtual server is available. Use all if all virtual server nodes are available and ICMP responses are generated only when all nodes in the pool attached to the virtual server are available.

    In the previous syntax, note the following:

    • <virtual_address> is the IP address of the virtual address in question.
  3. Save the change by entering the following command:

    save /sys config
