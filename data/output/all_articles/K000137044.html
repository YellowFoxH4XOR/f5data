K000137044: What is Remote Code Execution?

Published

Description

Remote Code Execution (RCE) vulnerabilities are a specific type of Arbitrary Code Execution vulnerability.

Environment

Any computer system.

Cause

  • Software or hardware bugs may allow arbitrary code execution, for example:
    • Buffer overflows or over-reads
    • Deserialization vulnerabilities
    • Type confusion vulnerabilities

Recommended Actions

Static or Dynamic Code Analysis tools can assist developers in discovering the code problems (above) which may lead to arbitrary or remote code execution vulnerabilities during the development process, while fuzzing tools may be able to help a developer or security researcher discover these code problems within compiled executables.

In general, following a rigorous Secure Development Lifecycle should help developers avoid these problems from the outset as well as considering adopting memory-safe languages (such as Python, Java, Go or Rust) where appropriate to eliminate the possibility of buffer overflows or other vulnerabilities caused by unsafe memory operations.

Additional Information

Arbitrary Code Execution is usually achieved either through manipulation of the instruction pointer (e.g., by exploiting a buffer overflow flaw) or through the direct injection of code by exploiting a deserialization vulnerability.

Remote Code Execution (or RCE) occurs when an attacker is able to inject arbitrary code or execute specific code through the manipulation of the instruction pointer via the network stack, rather than locally on the target device. For example, a buffer overflow in a web server might allow an attacker to inject both arbitrary code and manipulate the instruction pointer, thereby executing their injected code.

In its most basic form, Arbitrary Code Execution or RCE vulnerabilities only allow the attacker to execute code with the same privileges as the target vulnerable application or system, which often limits what the attacker can attempt to do. For this reason these attackers are commonly chained with Privilege Escalation; to take our earlier example, if the attacker exploits a web server they may find their exploit code running with the limited privileges of the ‘www-data’ user, restricting what modifications they can make to the system. If the attacker can have their injected code elevate privileges via kernel calls or to a secondary vulnerability (perhaps a binary with the setuid bit) they may be able to elevate their privileges to that of the root user or kernel and thereby gain complete control of a target system.

Affected Environments

As we have seen above, almost all applications, web servers, and environments are potentially susceptible to arbitrary code execution, however in order for this to be a possibility the attacker must find a defect in the target system or application which will allow them to inject their malicious code.
