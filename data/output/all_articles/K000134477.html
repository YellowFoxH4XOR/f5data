Description

25Gb optic SFP on rSeries platform may not change to an UP state.

Environment

  • F5OS-A
  • rSeries

Cause

Missing configuration on upstream switch may prevent expected operation.

Recommended Actions

  1. Ensure upstream switch ports are configured to enable Forward Error Correction (FEC) CL108 or compatible FEC for CL108 ( also known as: RS_IEEE_FEC or RS_FEC_IEEE).  Note, some customers report that you must make sure to first shutdown the port before you change the FEC setting.
  2. Disable speed auto-negotiation and manually configure interface speed to 25G.

Additional Information

FEC CL108 for 25G interface is default and F5OS-A has no configurable option to change FEC.

If your device is a r2000 or r4000 series, you may be able to turn off the FEC mode by logging into the CLI of your device as the root user and use the ethtool utility. To do so, perform the following procedure:

Switches that doesn't support RS_IEEE_FEC or RS_FEC_IEEE will cause the interfaces to stay down.  The alternative is to turn off the encoding but this is not saved in the configuration.  

Important: This procedure does not allow the change to be saved to the F5OS-A configuration. As a result, the change is lost whenever the system reboots or the interfaces are reset or reinitialized. You must perform the procedure again whenever any of these situations occur.

  1. Login as the root user to the CLI of your r2000 or r4000 series device.
  2. Run and capture the current port configuration by typing the following command:

    ethtool <sfp_X>

    Where <sfp_X> corresponds to the interface.

    For example, type ethtool sfp_5 for interface 5.0.

  3. Set the FEC mode to off by typing the following command:

    ethtool --set-fec <sfp_X> encoding off

    Using the previous example,

    ethtool --set-fec sfp_5 encoding off

  4. Run and capture the new port configuration by typing the following command:

    ethtool <sfp_X>

  5. Check if the port is up.
