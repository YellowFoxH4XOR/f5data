Description

Customer has an irule that changes the HTTP2::header :authority pseudoheader in HTTP_REQUEST. This could be required for pool member security requirements or SSL certificate selection. The existing value of HTTP::host does not change when HTTP2::header :authority is modified, and events after HTTP_REQUEST (such as ASM) will evaluate the client-supplied HTTP host header value.

Environment

  • BIG-IP LTM and ASM
  • HTTP and HTTP2 profile
  • irule that modifies HTTP2:header :authority in HTTP_REQUEST

Cause

HTTP/2 requests are converted to HTTP/1.1 before being passed to ASM.

HTTP::host will be populated from the HTTP2::header :authority prior to any TCL HTTP_ event.

After this point, modifying HTTP2::header :authority does not automatically update HTTP::host

Answer/Recommended Actions

Modify HTTP::host as well as HTTP2::header :authority in irules.

A better solution is to not modify HTTP::host/HTTP2::header :authority in HTTP_REQUEST prior to ASM evaluation.

If the headers need to be changed before sending to pool members,  they can be modified in HTTP_REQUEST_RELEASE, after ASM evaluation is complete.
