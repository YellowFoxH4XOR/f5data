K000163899: Portal Access Connections Reset with "Fetching cookie failed"

Support Solution
Published
2026-10-26
Updated
2026-10-26
Applies to

Source
https://my.f5.com/manage/s/article/K000163899

Applies To

  • BIG-IP APM with Portal Access (webtop and rewrite resources)
  • Affected branches and fixed releases (per the public bug tracker entry for ID2359001):
    • 17.1.3.6 and later
    • 17.5.1.10 and later
    • 21.1.0.3 and later

Symptoms

  • After several Portal Access applications are opened in one session, the browser shows one of the following:
    • Chrome: ERR_EMPTY_RESPONSE or ERR_CONNECTION_RESET
    • Firefox: PR_END_OF_FILE_ERROR
  • A packet capture shows the BIG-IP sending a TCP RST with this message: Internal error (APM::REWRITE requested abort (ERROR Fetching cookie failed.))
  • The /var/log/ltm file contains entries like: err tmm1[...]: 01230140:3: RST sent from ... Internal error (APM::REWRITE requested abort (ERROR Fetching cookie failed.))
  • The rewrite log contains entries like: rewrite - RewritePlugin.cpp:3290 ...: ERROR: Fetching cookie failed.
  • The APM session stays active. Access Reports show no session end or timeout.
  • The failure can worsen over time. Affected users can fail on the first application, not only after the Nth one.

Cause

Cookie data accumulates in the APM session as more applications are opened. Backend and security modules (such as ASM and Bot Defense) can set large cookies, which increases the cookie data the rewrite engine must process.

Resolution

1. Upgrade to a fixed release

Install one of the fixed releases listed above, or a later release on the same branch. The fix is in a release with ID2359001, so an engineering hotfix may be needed on some builds. Follow K4918: Overview of the F5 critical issue hotfix policy for hotfix guidance.

2. Confirm the system database variable exists

After the upgrade, verify that the variable is defined:
tmsh list sys db access.http.buffersize

If the command returns 01020036:3: The requested database variable (access.http.buffersize) was not found., do not change the value. Contact F5 Support.

3. Increase the rewrite buffer size

The default value is 16 (KB). The valid range is 4 to 128.
tmsh modify sys db access.http.buffersize value 32

If the issue persists at 32, increase the value in steps, up to 128. Test each change before moving to a higher value.

4. Validate the fix

  1. Start a new Portal Access session.
  2. Open the same number of applications that previously failed.
  3. Check /var/log/ltm for Internal error (APM::REWRITE requested abort (ERROR Fetching cookie failed.)). The message should not appear.
  4. Confirm that the browser loads all applications without resets.

Interim Workaround (Not a Fix)

Disabling AVR (Application Visibility and Reporting) on the affected virtual server reduced the cookie size in one customer environment and resolved the symptoms. This is a temporary measure. It does not remove the underlying cookie size limit, and it removes AVR reporting for that virtual server. Re-test after the upgrade before you re-enable HTTP Analytics or AVR.

Notes

  • Do not apply the workaround and the buffer size change at the same time. Change one item at a time so that you can see which one has an effect.
  • If you open a support case, include the following:
    • The output of tmsh show sys version
    • The output of tmsh list sys db access.http.buffersize
    • A packet capture or rewrite log that shows the RST message
