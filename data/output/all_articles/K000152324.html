Description

The following error may be observed in BIG-IP logs:

CMI peer <IP_ADDRESS> certificate rejected, error 19: self signed certificate in certificate chain

You do not observe any issue with the status of HA cluster.

Environment

  • BIG-IP LTM
  • High Availability (HA) cluster with device trust/config-sync enabled
  • Default SSL certificates used for device trust

Cause

The default SSL certificate located at /config/ssl/ssl.crt/default.crt on one or more BIG-IP devices has expired. When this occurs, the peer device rejects the expired certificate, resulting in the "self signed certificate in certificate chain" error.

Recommended Actions

  1. Verify Certificate Expiry:
    Check the expiration date of the default certificate using CLI (the GUI may show outdated information):
    openssl x509 -in /config/ssl/ssl.crt/default.crt  -text -noout
    Review the "Not After" field to confirm if the certificate is expired.
  2. Renew the Default Certificate:
    Note: You will not able to renew the certificate via GUI, as it does not take affect. This needs to be done via CLI.
    If expired, generate a new default certificate and key pair using CLI commands. Refer K13579: Generating new default certificate and key pairs for BIG-IP SSL profiles

Additional Information

Update CA Bundle if needed. If /config/ssl/ssl.crt/ca-bundle.crt is also nearing expiration, update it according to K60612439: Manually updating the BIG-IP default CA certificate bundle file
