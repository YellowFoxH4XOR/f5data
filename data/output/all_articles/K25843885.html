Known Issue

HTTP POST requests fail when the body is larger than 64 KB.

This issue occurs when all of the following conditions are met:

  • The BIG-IP APM system is configured for clientless mode.
  • The client sending the request currently has no active sessions with the BIG-IP APM system.
  • The client sends an HTTP POST request with a body larger than 64 KB.
BIG-IP APM clientless mode provides access to clients, such as Citrix receivers, ActiveSync, Outlook Anywhere, or other customized web applications, that may not support HTTP cookies or redirects. When processing HTTP requests in clientless mode, the BIG-IP APM system limits the size of the request body to 64 KB by default. If the request body exceeds 64 KB, the BIG-IP APM system will reset the connection. This action may prevent clients, such as email clients, from sending messages larger than 64 KB.

Impact

The BIG-IP APM system rejects the client's HTTP request.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The BIG-IP APM system resets client requests.
  • Users are unable to upload files or send emails with attachments larger than 64 KB.
  • Clientless email clients fail to send and receive emails.
  • Messages log to the /var/log/ltm file that appears similar to the following example: 
    tmm err tmm[11519]: 01230140:3: RST sent from <virtual_server_IP>:443 to <client_IP>:51653, [0x13df544:2095] APM HTTP body too big
  • Messages log to the /var/log/apm file that appear similar to the following example: 
    tmm1 err tmm1[11520]: 01490514:3: 00000000: Access encountered error: ERR_NOT_SUPPORTED. File: ../modules/hudfilter/access/access.c, Function: hud_access_process_ingress, Line: 2097

Workaround

There is no workaround for this issue. When you need large HTTP requests to execute an APM access policy, you may be able to mitigate this issue by configuring the client to first send a smaller request to set a valid MRHSession cookie and establish an active session with BIG-IP APM. You can then subsequently send the larger request, including the previously established MRHSession cookie.

In fixed versions, you can allow body sizes larger than 64 KB in HTTP requests using the new tmm.access.maxrequestbodysize database key. To do so, perform the following procedure:

Impact of workaround: In clientless mode, the BIG-IP APM system buffers the initial HTTP GET or POST request into memory if it lacks a valid MRHSession cookie. Increasing the value of the tmm.access.maxrequestbodysize database key may increase system memory usage if many large incoming requests are processed simultaneously. You should thoroughly test modifications during a maintenance window.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh
  2. To view the current setting, type the following command:

    list /sys db tmm.access.maxrequestbodysize

    Output will appear similar to the following example:

    sys db tmm.access.maxrequestbodysize {
    value "64000"
    }
  3. To increase the value of the tmm.access.maxrequestbodysize database key, use the following syntax:

    modify /sys db tmm.access.maxrequestbodysize value <new_value>

    For example, to increase the value to 100 KB, you would type the following command:

    modify /sys db tmm.access.maxrequestbodysize value 100000
  4. To exit the tmsh utility, type q and press Enter.
