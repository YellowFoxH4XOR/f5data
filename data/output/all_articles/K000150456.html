K000150456: The pool selection might be overwritten when the HTTP Request match two or more conditions in the iRule logic

Type
Support Solution
Published
2025-03-19
Updated
2025-03-19
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.0
Source
https://my.f5.com/manage/s/article/K000150456

Description

If you have configured one or more iRules to redirect the HTTP Requests to a different pools and the HTTP Request match two or more conditions specified in the iRule, the BIG-IP will forward the requests to the pool that was matched as the last one.  

 

Environment

  • BIG-IP LTM
  • Pool selection based on the specific conditions from the iRule

Cause

The HTTP Request match two or more conditions specified in the iRule. 

 

Recommended Actions

To resolve this issue and prevent similar problems:

 

  1. Avoid overlapping logic across iRules: Ensure there are no conflicting logics for the same event (e.g., HTTP_REQUEST). Consolidate related logic into a single iRule if possible.
  2. Review and adjust iRule execution order: If multiple iRules must be used, carefully review their order of execution on the virtual server to ensure proper processing flow.
