Known Issue

Users may be locked out of the BIG-IP APM access session.

This issue occurs when one of the following conditions are met:

  • Scenario one:

    • The first user logs in and establishes an access session.

      For example, "Bob"

    • A second user logs on and establishes an access session with a variation of the username of the first user, which includes one or more spaces in front of or after the username.

      For example:

      " Bob "

    • Either user session reaches the Maximum Session Timeout setting of the access profile, and the BIG-IP APM system logs out the user.
  • Scenario two:

    • The first user attempts to establish an access session after failing authentication numerous times and exhausting the allowed number of log in attempts for the access profile.

      For example, "Bob "

    • The second user attempts to log on using a variation of the username.

      For example, "Bob" (with no trailing space)

Impact

The users are locked out of the BIG-IP APM access session.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Users attempting to log in to the BIG-IP APM access profile are denied access.
  • When you view the BIG-IP APM memstats apm.localdb file, the username is listed.
  • When you view the BIG-IP APM MySQL username entries, the username is not listed.
