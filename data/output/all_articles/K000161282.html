K000161282: Disparity in Available Load Balancing Methods Across Platforms with APM Standalone License

Type
Support Solution
Published
2026-05-14
Updated
2026-05-14
Applies to
  • BIG-IP
  • BIG-IP APM: 17.1.3
Source
https://my.f5.com/manage/s/article/K000161282

Description

When configuring a pool on BIG-IP systems licensed with an APM Standalone license, the available Load Balancing Methods in the GUI differ depending on the hardware platform:

  • Lower-end platforms (i2000/r2000) and Virtual Edition (VE): Display multiple load balancing methods, including Round Robin, Ratio (member), and Ratio (node)
  • Higher-end platforms (i4000, i7000, i11800, r4000, r5000): Display only Round Robin

This discrepancy is observed even when all devices are confirmed to be running the same APM Standalone license type.

Environment

  • Product: BIG-IP APM
  • Behavior is license-SKU-driven and not version-specific
  • Platforms affected:
    • Lower-end (more LB methods available): iSeries i2000 series (i2600, i2800), rSeries r2000, Virtual Edition (VE)
    • Higher-end (Round Robin only): iSeries i4000, i7000, i11800; rSeries r4000, r5000
  • License type: APM Standalone license on all platforms
  • Feature in question: Pool Load Balancing Method selection (Ratio member / Ratio node)
  • License flag involved: ltm_lb_ratio in /config/bigip.license

Cause

This behavior is caused by a licensing policy decision at the SKU level. The ltm_lb_ratio license flag is intentionally included in APM Standalone license SKUs for lower-end platforms (e.g., F5-BIG-APM-I2600-B, F5-BIG-APM-I2800-B) and VE, but is intentionally omitted from APM Standalone SKUs for higher-end platforms.

  • Bug ID 1015661: Documents the addition of the ltm_lb_ratio flag to APM Standalone licenses for lower-end platforms and VE only (via licensing change). Higher-end platform SKUs were not included.

The lower-end platform inclusion of ltm_lb_ratio is designed to provide exposure to additional load balancing methods during initial deployments. When migrating to higher-end platforms, a full LTM license is required to access these features.

Answer/Recommended Actions

To verify the license flags on your devices, run the following command:

  1. Log in to the BIG-IP command line.
  2. Check for the presence of the ltm_lb_ratio flag in the license file:
    grep ltm_ /config/bigip.license
  3. Compare the output across platforms:
    • Lower-end platforms and VE will show ltm_lb_ratio : enabled
    • Higher-end platforms with APM Standalone will not show ltm_lb_ratio

To rule out an expired time-limited add-on license as a contributing factor:

  1. Run the following and check the timelimited_module section for any expired entries:
    tmsh show sys license detail
  2. If an expired time-limited module is found, re-activate the base license:
    • Navigate to System > License > Re-activate
    • Remove the expired add-on key and re-activate

If Ratio load balancing methods are required on higher-end platforms:

  • Obtain a full BIG-IP LTM license or a Good/Better/Best bundle with APM as an add-on module.
  • Contact your F5 Sales or Account team to discuss licensing options, as this restriction is a strategic licensing decision and not a product defect.
  • No software workaround is available. The limitation is enforced at the license SKU level.

Additional Information

  • The available load balancing methods in the BIG-IP GUI are dynamically rendered based on LTM feature flags present in the installed license, not the hardware platform itself or the underlying OS (TMOS vs. F5OS).
  • Running an rSeries tenant on F5OS does not inherently grant additional LTM features; the license SKU is the determining factor.
  • The full set of LTM load balancing methods (Least Connections, Fastest, Observed, Predictive, etc.) is only available with a full BIG-IP LTM base license.
  • APM Standalone licenses also cap the pool member limit (ltm_lb_pool_member_limit) at 3 members, compared to unlimited with a full LTM license.
  • A similar licensing behavior applies to other standalone module licenses. For example, a BIG-IP system with an ASM-only license also supports only a subset of load balancing features (Round Robin, Ratio member, Ratio node), as documented in KB K62450265.
