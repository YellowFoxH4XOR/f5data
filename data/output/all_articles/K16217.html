Known Issue

The TMM daemon may produce a core file with a SIGFPE on the standby BIG-IP system.

This issue occurs when the following conditions are met:

  • Connection mirroring is enabled for the virtual server.
  • The virtual server references a OneConnect profile.

Impact

TMM may produce a core file and temporarily fail to process traffic.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H509367on the Diagnostics > Identified > Low|High screen.
  • The BIG-IP system sends a SIGFPE signal to TMM, resulting in a stack trace and core file.
  • The BIG-IP system generates a panic string in the /var/log/tmm file that appears similar to the following example:

    'panic: TCP4: HUDEVT_EXPIRED (Connection expired) bad pcb magic (0x00585858)'

Workaround

To work around this issue, you can disable connection mirroring for the virtual server, or remove the OneConnect profile from the virtual server.
