K6325: The big3d daemon may leak memory when VLANs are disabled from virtual servers or SSL proxies

Known Issue

When you disable one or more VLANs for a virtual server or SSL proxy, the big3d daemon may leak memory. When this occurs, BIG-IP user space memory usage will slowly increase until the system becomes unresponsive or, if you have enabled the kernel deadman timer, until the kernel deadman timer triggers and reboots the system. The rate at which the big3d daemon leaks memory depends on the number of virtual servers and SSL proxies with disabled VLANs in the configuration.

F5 Networks Product Development tracked this issue as CR62315.

Workaround

You can work around this issue by configuring BIG-IP to periodically restart the big3d daemon. Use the following steps to schedule a cron job that will restart the big3d daemon:

  1. Log in to the command line.

  2. Edit the /etc/crontab file.

  3. At the end of the file, add the following line:

    0 0 * * <days> root /sbin/bigstart restart big3d

    Replace <days> with the interval, in days, at which you would like BIG-IP to restart the big3d daemon. Seven days should generally be a safe value.

  4. Save the file and exit the editor.

  5. Restart the cron daemon by typing the following command:

    kill -HUP `pidof cron`

BIG-IP will now restart the big3d daemon after the interval you specified.
