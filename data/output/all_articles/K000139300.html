Description

When you attempt to add a VELOS or rSeries hardware product as a provider on the BIG-IP Next Central Manager, the BIG-IP Next Central Manager fails to add the VELOS or rSeries hardware product and returns an error similar to the following example:

DEVICE-00060: Internal error testing authentication

Environment

  • BIG-IP Next Central Manager 20.2.0 and later
  • You can ping the VELOS partition IP or the rSeries management IP from Central Manager (being unable to reach the VELOS/rSeries results in the same error message)

Cause

The BIG-IP Next Central Manager 20.2.0 and later requires that the F5OS type provider (F5 VELOS/rSeries) uses a TLS certificate with well formed Subject Alternative Names (SAN). This is being tracked as ID 1505589. ID 1505589 is fixed beginning in the following F5OS versions:

  • F5OS-A 1.8.0

Recommended Actions

You should ensure the F5 VELOS/rSeries hardware product uses a TLS certificate with well formed SAN. The current F5OS-C/A releases of F5 VELOS/rSeries hardware products do not support generating a CSR to include SAN, you have to use an external system (such as a CentOS-based system) with OpenSSL utility to generate a CSR with SAN. For information about how to generate a CSR with SAN using a CentOS-based system, refer to K11438: Creating SSL SAN certificates and CSRs using OpenSSL. Note that you should append the following minimum information to the custom openssl.cnf per described in step 5 of K11438: Creating SSL SAN certificates and CSRs using OpenSSL:

[ req_ext ]
subjectAltName = @alt_names

[ alt_names ]
DNS.1 = <localhost | FQDN>
IP.1 = <Management IP address of the VELOS/rSeries hardware product>

For example,

[ req_ext ]
subjectAltName = @alt_names

[ alt_names ]
DNS.1 = myf5r5900.myf5.com
IP.1 = 192.168.80.15

When you have generated the appropriate CSR, you can either self-sign the CSR per K11438: Creating SSL SAN certificates and CSRs using OpenSSL or submit to your trusted Certificate Authority (CA) to sign.

After signing, you would need to configure the F5 VELOS/rSeries hardware product to use the signed certificate and its key. To do so, perform the following procedure:

Impact of procedure: The webUI of the F5 VELOS/rSeries hardware product will be momentarily unavailable when it is configured to use a new TLS certificate and key.

  1. Log in to the F5 VELOS partition webUI as the partition admin user or the F5 rSeries webUI as the admin user.
  2. Go to AUTHENTICATION & ACCESS > TLS Configuration.
  3. Select Show located to the right of TLS Certificate & Key. This will display any previously installed TLS certificate and key or two blank text areas for TLS certificate and key if there is none.
  4. Copy the text of the new TLS certificate with SAN which you have either self-signed or signed by a CA. The TLS certificate file should contain encrypted text between the two text delimiters -----BEGIN CERTIFICATE----- and -----END CERTIFICATE-----. Paste the text of the new TLS certificate in the text area of the TLS Certificate setting.
  5. Similarly, copy the text of the key file of the new TLS certificate. The TLS key file should contain encrypted text between the two text delimiters -----BEGIN PRIVATE KEY----- and -----END PRIVATE KEY-----. Paste the text of the key file in the text area of the TLS Key setting.
  6. If you have encrypted the TLS key with a passphrase, enter the passphrase in the TLS Key Passphrase setting.
  7. Select Save to save the changes.
  8. The webUI will prompt you for confirmation to update the TLS Configuration, select OK to proceed. During this time, the webUI may be unavailable momentarily. When the webUI is back online, you should refresh your browser to obtain the new TLS certificate you have just configured for the webUI in previous steps.
  9. [Optional] If your new TLS certificate is signed by a CA, you should add the CA certificate to the webUI by going to AUTHENTICATION & ACCESS > TLS Configuration. Then select Add under the CA Bundles section. The webUI pops up the Add CA Bundle screen; enter a name for the CA certificate in the Name setting and copy/paste the CA certificate text in the TLS CA Certificate setting. Select Save & Close to save the change.

Now that you have configured the webUI with a TLS certificate that includes SAN, you can proceed to add the F5 VELOS/rSeries hardware product as a provider in BIG-IP Next Central Manager.
