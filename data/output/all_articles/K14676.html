Known Issue

Layer 4 (L4) mirroring and session state data may not mirror to the standby device in the traffic group.

This issue occurs when the following conditions are met:

  • The Traffic Management Microkernel (TMM) restarts on the standby device.
  • The active device in the traffic group detects that the high availability (HA) connection to the peer device is unavailable.

Once the active device determines that the HA connection is unavailable, it will not attempt to to re-establish the HA connection. As a result, L4 connection mirroring and session data will not mirror to the standby device.

Impact

A failover to the standby peer device will require previously established connections to re-establish their sessions.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • After a failover, previously established connections are not available.
  • The tmctl ha_stat command output returns all zero values on the standby peer device.

    For example:

    name accepts connects connfails expires overflows buffered rxpkts rxctx
    ---------- ------- -------- --------- ------- --------- -------- ------ -----
    default HA 0 0 0 0 0 0 0 0

    txpkts txctx droppkts dropctx
    ------ ----- -------- -------
    0 0 0 0

  • The bigstart status tmm command output from the standby unit shows that TMM has been restarted since the initial boot of the device.

    When TMM has not restarted since the device was initially booted, output appears similar to the following example:

    tmm run (pid 5795) 11 days

    When TMM has restarted since the device was initially booted, output appears similar to the following example:

    tmm run (pid 5292) 45 minutes, 1 start

  • When TMM restarts, log messages in the /var/log/ltm file appear similar to the following example:

    tmm notice tmm[5449]: 01010001:5: default x86_64 vadc TMM Version 11.3.0.2806.0 starting

Workaround

To temporarily work around this issue, you can reinitialize the HA connection by temporarily removing and then re-adding any of the mirroring IP address on any device in the traffic group. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure will interrupt mirroring on the device.

  1. Log in to the BIG-IP Configuration utility.
  2. Click Device Management.
  3. Click Devices.
  4. Select the device name.
  5. Click Device Connectivity.
  6. Click Mirroring.
  7. From the Primary Local Mirror Address or Secondary Local Mirror Address menu, modify the existing address to None.
  8. Click Update.
  9. From the same Primary Local Mirror Address or Secondary Local Mirror Address menu, change None to the previously selected ip address.
  10. Click Update.
