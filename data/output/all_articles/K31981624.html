Known Issue

The alertd process does not run the logrotate utility when the /var/log file has less than ten percent free space.

Note: The logrotate utility rotates and compresses the logs in the /var/log file, and by default, the BIG-IP system runs it daily regardless of disk usage. For more information, refer to K13367: Managing log files on the BIG-IP system (11.x - 13.x).

This issue occurs when the following condition is met:

  • The /var/log file has less than ten percent free space.

The diskmonitor utility will log a disk space alert message when the /var/log file has less than ten percent free space; however, in BIG-IP versions affected by this known issue, the log message does not trigger the alertd process to run the logrotate utility as expected. For more information about the diskmonitor utility, refer to K8865: Overview of the diskmonitor utility.

Impact

The /var/log file may become completely full, preventing new log messages from being written.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • No new log messages are written to log files in the /var/log directory.
  • When you attempt to create a file in the /var/log directory, you observe an error message similar to the following example:

    write error: No space left on device

  • In the /var/log/ltm file, you observe an error message similar to the following example:

    011d0004:3: Disk partition /var/log has only 4% free
