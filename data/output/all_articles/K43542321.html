Description

Configurations that use IPPORT cmp-hash  may result in 20% CPU utilization increase.
This is expected behavior.


Environment

  • Uncommon IP protocols
  • Configuring net vlan <VLAN_NAME> cmp-hash ipport

 

Cause

    Processing cmp hashing is done in software or hardware depending on platform:
    If  tmsh modify net vlan <VLAN_NAME> cmp-hash ipport configured on  platform that does not support hardware acceleration of IPPORT hash (e.g. B4430) , The DAG is performed in software and may result in 20% CPU utilization increase.

    Note that this only applies to platforms that support hardware accelerated DAG but lack hardware acceleration for IPPORT. The list of platforms that support this is documented in KB article K14435.

    It does not apply to Virtual Editions (VE) instances where all DAG modes are software-based. Leveraging IPPORT CMP hash on BIG-IP VE instance shouldn't introduce any additional penalty beyond the marginal cost of hashing over more fields, as also noted earlier above.

    Recommended Actions

    Currently,  B4450 and i15000 platforms support hardware acceleration of IPPORT hash and are recommended  in order to avoid potential CPU increase when processing uncommon IP protocols using IPPORT DAG.

    Additional Information

    Traffic disaggregation (DAG) using the default cmp-hash algorithms is dependent on L4 port values of TCP/UDP traffic. 
    Disaggregating uncommon IP protocols not containing L4 ports (e.g. ICMP, GRE, ESP etc.)  as well protocols with low entropy L4 ports (e.g. SIP)   IPPORT DAG may be used in order to avoid pinning traffic to single TMM.
    The IPPORT hash dis-aggregates ingress traffic based on 4-tuples {local IP, remote IP, local Port, remote Port}

    IPPORT hash should hash over destination and source IP address for all protocols as well as:

    • Local port and remote port are set to 0 for uncommon protocols by default
    • For TCP, UDP and SCTP over destination and source port number;
    • For ICMP echo and echo replies – ICMP type and ICMP sequence id;
    • For ESP over the SPI field.
    • For tunneled traffic, over the inner IP header.
