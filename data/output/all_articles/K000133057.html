Description

CGNAT Log format is changed after upgrading from v14 to v15.1 or later. 

For example, NAT 44 PBA log

v14 format:

"LSN_PB_ALLOCATED""1.1.1.1%10""2.2.2.2:18625-19024""1675168367158""No-lookup"

 

v15.1 format

"LSN_PB_ALLOCATED""1.1.1.1%10""""2.2.2.2:18625-19024""1675168367158""No-lookup"
Each fields means
"LSN Event""LSN Client""LSN IPv6 subscriber prefix length""LSN PBA""Start time""Subscriber ID"

In v15.1 format, a new field for 'IPv6 subscriber prefix length' has been added.

 

 

Environment

CGNAT upgrade from v14 to v15.1 or later

Example lsn log profile:

ltm lsn-log-profile /Common/lsn_log_custom {

app-service none

csv-format disabled

defaults-from /Common/lsn_log_profile

description none

end-inbound-session {

action enabled

}

end-outbound-session {

action enabled

elements none

}

subscriber-id enabled

}

 

ltm lsn-pool /Common/lsn_pba_pool {

egress-interfaces {

/Common/Internal

}

egress-interfaces-enabled

log-profile /Common/lsn_log_custom

log-publisher /Common/lsn_log_pub

members {

2.2.2.2/32

}

mode pba

port-block-allocation {

block-idle-timeout 100

block-size 32

client-block-limit 2

}

}

 

Recommended Actions

That is the new format, and generally, the 'LSN IPv6 subscriber prefix length' and 'Subscriber ID' fields will be empty(or 'No-lookup' respectively) for IPv4 and LTM use cases. One example where you may see these fields is 

1. IPv6 client and VIP environment.

2. PEM SessionDB exists for the client(subscriber).

3. Subscriber-id enabled on the log profile.
