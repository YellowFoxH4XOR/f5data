Topic

F5 has released Hotfix-BIGIP-10.2.2-852.0-HF1. BIG-IP version 10.2.2 HF1 corrects several issues that affect customers running version 10.2.2.

Important: If you are currently running 10.2.2 and have installed Engineering hotfixes, check with F5 Technical Support to confirm whether the Engineering hotfixes are included in 10.2.2 HF1 before installing the hotfix.

223470, 362541NoneWith this version, you can now configure whether web application traffic should bypass the ASM and PSM or not, and if yes, under which circumstances.

Note: For PSM, bypass is only for HTTP traffic, and not for FTP and SMTP traffic.

Warning: When you enable bypass, you enable users to continue accessing the web application. However, web application traffic is directed to the web server without passing the ASM or PSM. As a result, your ASM security policies and PSM security profiles will not protect your web application. This puts your web application at risk of security threats and false positives.

There are three new internal parameters used to configure bypassing the ASM/PSM; two are available from the Configuration utility, and one from the command line only.

The following parameters are available in the Configuration utility:
  • bypass_upon_asm_down - Specifies whether traffic bypasses the ASM/PSM when the ASM/PSM is stopped. The possible values are 1 (bypass enabled) or 0 (bypass disabled). The default value is 0 (bypass disabled). If you set this parameter value to 1, web traffic bypasses the ASM/PSM if any of the following occur:
    • You stop running ASM/PSM.
    • You restart the ASM/PSM. Traffic bypasses the ASM/PSM from the time the ASM/PSM is stopped until the Security Enforcer reloads.
    • The Security Enforcer performs a core dump, until the Security Enforcer reloads.
  • bypass_upon_load - Specifies whether traffic bypasses the ASM/PSM, when there are not enough system resources for the Security Enforcer. The possible values are 1 (bypass enabled), and 0 (bypass disabled). The default value is 0 (bypass disabled). If you set this parameter value to 1, web traffic bypasses the ASM/PSM if there is not enough memory for the Security Enforcer, or not enough system resources.


To change these parameters' default values, from the Configuration utility, navigate to Application Security > Options > Advanced Configuration or Protocol Security > Options > Advanced Configuration.

The internal parameter that is available from the command line but not from the Configuration utility is bypass_upon_high_cpu. This parameter's value specifies whether traffic bypasses the ASM/PSM when your system is consuming a large amount of CPU, indicated by the small amount of idle CPU available. The default is 90 percent, meaning that if the system's idle CPU is 10 percent, traffic bypasses the ASM/PSM.

To add and change the default value of this parameter, open the command line, and use the add_del_internal script, in the following format:
/usr/share/ts/bin/add_del_internal add <param_name> <param_value>

To delete an internal parameter from your configuration, from the command line, enter the following command:
/usr/share/ts/bin/add_del_internal del <param_name>

After adding or deleting an internal parameter, you must enter and run the command bigstart restart asm in order for the changes to take effect.
