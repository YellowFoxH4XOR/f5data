Known Issue

The Cavium Octeon II compression card may hang on VIPRION platforms.

This issue occurs when the following conditions are met:

  • The VIPRION chassis contains one of the following blades:
    • B4300 (A108)
    • B2100 (A109)
  • HTTP compression is enabled for the virtual server.
  • The HTTP or HTTP compression profile is configured to use the gzip compression method.

Impact

The virtual server may fail to return the desired content.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H390240 on the Diagnostics > Identified > High screen.
  • The virtual server may fail to return the desired content.
  • TMM instances may indicate increased CPU utilization.
  • The BIG-IP system logs error messages to the /var/log/ltm file on the host blade. The messages appear similar to the following:

    slot2/tmm err tmm[9684]: 01240013:3: Octeon chip sync error was detected

  • The BIG-IP system logs error messages to the /var/log/tmm file on a guest blade. The messages appear similar to the following:

    slot1/bigip-1 notice oct0 (vcmp-0x84-tmm0): wlite provider not responding - consumer cancelling pending reqs and unregistering
    slot1/bigip-1 notice wlite OCTEON (c|f): Registration tx success for vcmp-shm

  • The tmctl command may indicate a high number of queue stalls.

    For example:

    # tmctl -d blade tmm/octeon

    name queue_stalls queue_full queued done callbacks queue_writes
    ------------------- ------------ ---------- ------ ---- --------- ------------
    tmm0 300140 0 0 355790 355932 355790
    tmm7 29774 0 0 355711 355850 355711
    tmm3 35811 0 0 358716 358855 358716

Workaround

To work around this issue, you can temporarily disable the Octeon compression card until you can obtain a permanent software fix. To do so, perform the following procedure:

Disabling the Octeon compression card

Impact of workaround: Running the bigstart restart command temporarily interrupts traffic processing. In addition, disabling the Octeon compression card results in the system using a software compression provider to compress data. Using software compression will increase the BIG-IP system CPU utilization. You must re-enable the Octeon compression card after installing a fixed software version or hotfix.

  1. Log in to the command line.
  2. Type the following command:

    echo "device exclude 08:00.0" >> /config/tmm_init.tcl

  3. Restart the system services by typing the following command:

    bigstart restart

Re-enabling the Octeon compression card

After installing a fixed software version or hotfix, you must re-enable the Octeon compression card.

Impact of workaround: Running the bigstart restart command temporarily interrupts traffic processing.

  1. Log in to the command line.
  2. Use a text editor to edit the /config/tmm_init.tcl file.
  3. Remove the following line:

    device exclude 08:00.0

  4. Restart the system services by typing the following command:

    bigstart restart
