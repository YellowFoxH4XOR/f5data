Known Issue

This is the result of a known issue. If a new resource group is created by copying a setting from an existing resource group, any Network Access IP Group Filters will fail to take effect until the next Services restart or reboot. Failure of a resource group's IP Group Filters can cause applications to fail due to absence of filter rules allowing communication to the needed IP addresses and ports.

F5 Networks Product Development tracked this issue as CR88510, and it was fixed in FirePass version 6.0.3. For information about upgrading, refer to the FirePass Release Notes.

Note: Version 5.4.2 of FirePass software will experience this issue when hotfix HF-47044-47312-47374-48056-54631-1 is installed. This hotfix cannot be uninstalled. Customers using version 5.4.2 who are affected by this issue must upgrade to a supported version of FirePass in order to resolve the issue.

Additionally, this issue was fixed in Cumulative Hotfix HF-602-5 issued for FirePass version 6.0.2. You may download this hotfix or later versions of the Cumulative Hotfix from the F5 Downloads page.

For instructions about obtaining a hotfix, refer to K167: Downloading software from F5.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.


Workaround

You can work around this issue by performing the following procedure after creating the new resource group:

  1. Log on to the FirePass Administrative Console.
  2. Navigate to the Network Access : Global Settings page.
  3. In the Packet Filter Rules section, click the I icon to the right of an existing rule.
  4. Without making any changes to the rule, click the Save button.
  5. Click the Apply these rules now button.
  6. Navigate to the Network Access : Resources page.
  7. Click the IP Group Filters tab.
  8. In the Group Packet Filter section, click the I icon to the right of an existing rule.
  9. Without making any changes to the rule, click the Save button.
  10. Click the Apply these rules now button.

Note: This workaround is not required for all systems in a failover pair or cluster. The workaround is only required on the active member of a failover pair or the cluster master.
