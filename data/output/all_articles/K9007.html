Known Issue

This is the result of a known issue. BIG-IP interfaces with fixed media settings transition to a down state and then up state during a configuration load. For example, if you change the media speed for trunk members from auto to 100baseTX, and then load the configuration by typing the bigpipe load command, the trunk status changes to down and then back to up.

Note: The bigpipe config sync command also loads the system configuration and causes the interface status to transition to down and then up.

F5 Product Development is tracking this issue as CR82694.

This issue has been fixed in Hotfix-BIG-IP-9.3.1-HF5 issued for BIG-IP version 9.3.1. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

To view a list of the latest available hotfixes, refer to K9502: BIG-IP hotfix matrix.

For information about installing a hotfix, refer to K6845: Managing F5 product hotfixes.

For information about F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

Workaround

You can work around this issue by re-enabling the trunk. To do so, type the following command from the command line:

bigstart restart lacpd

Note: The bigstart restart lacpd command temporarily re-enables the trunk until the next time the configuration is loaded. To permanently work around this issue, set the media speed for the trunk members to autonegotiate.
