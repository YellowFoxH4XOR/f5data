Topic

Beginning in BIG-IP 14.1.0, F5 provides full proxy (client-side and server-side) support for the HTTP/2 protocol. In the HTTP/2 protocol, the h2 string identifies the protocol in which HTTP/2 uses Transport Layer Security (TLS), and the h2c string identifies the protocol in which HTTP/2 runs without TLS over cleartext TCP.

Description

The h2c protocol identifier describes HTTP/2 in plain-text that does not use TLS. h2c starts in the following two ways:

Upgrade from HTTP/1.1

When a client does not have prior knowledge about server h2c support, it makes a request to an HTTP URI in HTTP/1.1 by including an Upgrade header field with the h2c token. For example:

     GET / HTTP/1.1
     Host: server.example.com
     Connection: Upgrade, HTTP2-Settings
     Upgrade: h2c

A server that supports HTTP/2 responds with an HTTP/1.1 101 (Switching Protocols) response and the exchange proceeds in HTTP/2.

Direct HTTP/2

Some clients already have prior knowledge that a server supports h2c, having learned it through a mechanism such as ALT-SVC, or you may be using an HTTP/2 tool such as nghttp. In such cases, the client initiates HTTP/2 messages directly after the TCP handshake without an initial HTTP/1.1 exchange.

BIG-IP support for h2c only includes the direct method, in which clients have prior knowledge of the server's support for h2c. h2c through upgrade from HTTP/1.1 is not supported.

Recommendations

Although the HTTP/2 standard does not require the use of encryption, all major browsers (Firefox, Chrome, Edge, Safari, and so on) only support HTTP/2 over TLS. When configuring HTTP/2 without TLS h2c, you should consider the following factors:

  • BIG-IP monitors do not currently support h2c, but you can configure an external monitor to do so. For more information, refer Using an EAV external monitor to monitor HTTP/2 h2c servers on DevCentral.
  • To configure h2c on the BIG-IP virtual server, you should ensure the following:
    • Your back-end server is configured to support the direct method when negotiating h2c.
    • Your server-side configuration uses the following parameters:
      • SSL Profile (Server): None
      • HTTP/2 Profile (Server): A HTTP/2 profile with the Activation Modes parameter set to Always
      • HTTP MRF Router: Enabled
    • Your client-side configuration uses the following parameters:
      • Service Port: 80 HTTP
      • SSL Profile (Client): None
      • HTTP/2 Profile (Client): A HTTP/2 profile with the Activation Modes parameter set to Always
      • HTTP MRF Router: Enabled
  • Without a mechanism such as ALT-SVC, browsers do not by default have prior knowledge of server h2c support and use the Upgrade header method in HTTP/1.1 to establish HTTP/2. This is not supported by the BIG-IP system.
  • Beginning in BIG-IP 14.1.0, you can use the nghttp tool to troubleshoot HTTP/2. nghttp makes direct HTTP/2 requests without using the Upgrade header method in HTTP/1.1. To do so, use the following command syntax:

    nghttp -nv http://<server_IP_address>

    When a server does not support HTTP/2, you may observe the following at the end of the output:

    [...]
    [  0.007] [ERROR] Remote peer returned unexpected data while we expected SETTINGS frame.  Perhaps, peer does not support HTTP/2 properly.
    Some requests were not processed. total=1, processed=0

    When a server supports HTTP/2, you may observe the following at the end of the output:

    [...]
    [  0.012] send GOAWAY frame <length=8, flags=0x00, stream_id=0>
              (last_stream_id=0, error_code=NO_ERROR(0x00), opaque_data(0)=[])
