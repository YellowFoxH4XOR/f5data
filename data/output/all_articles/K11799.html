Known Issue

This is the result of a known issue. A virtual server that uses the Packet Velocity ASIC (PVA) may report more current connections than it is actually processing.

Note: The PVA is included in the BIG-IP 2400, 3400, 6400, 6800, 8400, and 8800 platforms. For more information about the PVA, refer to K4832: Overview of Packet Velocity ASIC (PVA) Acceleration features and sub features.

This issue occurs because the BIG-IP system incorrectly tracks connections that cannot be accelerated by a PVA-enabled virtual server. Such connections remain in the connection table until their idle timeout has expired, even if one of the endpoints has already closed or reset the connection. This behavior causes the affected virtual server to report inflated current connection figures.

Note: This issue does not affect BIG-IP versions 9.x; therefore, PVA-enabled virtual servers are likely to report an increase in the number of current connections after a BIG-IP system is upgraded to versions 10.x.

Note: This issue may be exacerbated by performance testing. Certain performance benchmarks, for example, ApacheBench, are known to cause the PVA to refuse to accelerate connections, further inflating the connection count.

F5 Product Development tracked this issue as ID 225434, ID 329800, and ID 328298 (formerly CR139371) and it was fixed in BIG-IP version 10.2.2. For information about upgrading, refer to the BIG-IP LTM or Link Controller release notes.

Additionally, this issue has been fixed in Hotfix-BIGIP-10.1.0-3402.0-HF2, issued for BIG-IP version 10.1.0. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
