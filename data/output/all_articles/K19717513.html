Description

After upgrading to 15.1.0, the LTM configuration was failing to load.

  • The Configuration Utility displays the following error:  
    "The configuration has not yet loaded. If this message persists, it may indicate a configuration problem."

  • 'tmsh load sys config' produces an error message, similar to:

    01070597:3: Monitor /Common/http2 is read only.
Unexpected Error: Loading configuration process failed.

Environment

  • BIG-IP LTM, version 15.1.0 or newer.
  • Configuration contains a user-created health monitor, named 'http2'

Cause

In version 15.1.0, we introduced a new HTTP/2 health monitor. If your configuration contained an HTTP health monitor named 'http2', prior to 15.1.0, a conflict will encountered.

Recommended Actions

To resolve the conflict, the custom user-created 'http2' health monitor must be removed from the configuration. 

Use the Configuration Utility, to boot back into the previously-working boot location.

  1. Locate the user-created HTTP monitor, named 'http2' and delete it.
  2. Reinstall the TMOS upgrade. (This is important. Simply booting the system back into the upgraded boot location may not clear the error).
  3. Boot into the re-upgraded boot location.

Alternatively, if you are comfortable working in the GNU/Linux command line, you can use a command-line text editor, such as 'vi', to remove the problematic monitor from the /config/bigip.conf configuration file. After editing the configuration file, run 'tmsh load sys config'.
The offending health monitor object will appear like: ltm monitor http /Common/http2 { adaptive disabled defaults-from /Common/http destination *:* interval 5 ip-dscp 0 recv none recv-disable none send "GET /\r\n" time-until-up 0 timeout 16 } Note: Prior to making these changes, review your configuration, to ensure that the offending health monitor is not in use by any pool.
