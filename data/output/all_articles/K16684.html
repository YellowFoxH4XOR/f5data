Known Issue

Under rare circumstances, the mcpd process may erroneously fail to validate the configuration and report an unrelated error message. This issue occurs when one of the following conditions is met:

  • You perform a configuration load on an affected system.
  • You perform a configuration synchronization (ConfigSync) between members of a device group.
  • You perform an initial configuration load on a secondary blade in a VIPRION system.

Impact

The affected system is unable to load the configuration or sync the configuration, and the mcpd process may restart.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H524813 on the Diagnostics > Identified > High screen.
  • The mcpd process fails to load the configuration, and in the /var/log/ltm file, reports an error message similar to the following example:

    01070911:3: The requested integer (0) is invalid for egress_high in profile_mblb (/Common/mblb)

    Note: The configuration on the affected system does not need to reference MBLB profiles for this issue to occur.

  • The ConfigSync fails to complete and reports an error message similar to the following example:

    Sync error on example.f5.com: Load failed from example.f5.com 01070911:3: The requested integer (0) is invalid for egress_high in profile_mblb (mblb)

    Note: The configuration on the affected system does not need to reference MBLB profiles for this issue to occur.

  • When the configuration is initially loaded on a secondary blade in a VIPRION system, the mcpd process restarts, and in the /var/log/ltm file, the system logs error messages similar to the following examples:

    01070911:3: The requested integer (0) is invalid for egress_high in profile_mblb (/Common/mblb)
    01070734:3: Configuration error: Configuration from primary failed validation: 01070911:3: The requested integer (0) is invalid for egress_high in profile_mblb (/Common/mblb)... failed validation with error 17238289.

    Note: The configuration on the affected system does not need to reference MBLB profiles for this issue to occur.

Workaround

To work around this issue, you can force the mcpd process to reload the BIG-IP configuration. To do so, perform the steps described in K13030: Forcing the mcpd process to reload the BIG-IP configuration.

Impact of workaround: Rebooting the BIG-IP system disrupts traffic processing until the system is back up.
