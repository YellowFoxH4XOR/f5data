Description

When configuring a Global Log Receiver (GLR) in F5 Distributed Cloud (XC) to forward logs to an external HTTP endpoint (such as SentinelOne Data Lake), test connections may fail with a 401 Unauthorized error. The following error messages and logs may be observed:

  • Http failure response: 500 Server Error
  • connection test status: FAIL unable to send test message

Environment

  • Product:  F5® Distributed Cloud (XC)
  • Feature: Global Log Receiver (GLR), HTTP Receiver
  • Target endpoint: External HTTP log ingestion service (e.g., SentinelOne Data Lake)
  • Note: GLR always sends logs with Content-Type: application/x-ndjson (not configurable).

Cause

The 401 Unauthorized error occurs when the Authorization header is not correctly formatted or the token is not accepted by the target endpoint. Specifically, including the word "Bearer" under Authentication, Token Authentication value (e.g., setting the token as "Bearer <token>") results in the header being sent as Authorization: Bearer Bearer <token>, which is invalid. The correct format is Authorization: Bearer <token>, where only the token value is provided in the configuration, and the system prepends "Bearer" automatically.

Additionally, note that GLR always sends logs using Content-Type: application/x-ndjson.

Answer/Recommended Actions

  • When configuring Authentication for a GLR HTTP receiver, do not include "Bearer" in the token value—enter only the raw token string; "Bearer" will be prepended automatically.

  • If your endpoint expects a different Content-Type, be aware that GLR will always use application/x-ndjson and this cannot be changed.
  • If you receive a 401 Unauthorized error:
    • Double-check that your token is valid and has not expired.
    • Ensure you are not duplicating "Bearer" in your configuration.
    • Confirm with your endpoint provider what format they expect for authorization headers.

Additional Information

The Authorization header is used in HTTP requests to provide credentials for authenticating with a remote server. When using Bearer token authentication, the header should be formatted as Authorization: Bearer <token>, where <token> is the actual access token provided by the authentication system. The word "Bearer" is a prefix that tells the server the type of authentication being used, and it should not be included in the token value itself—only the raw token is needed. The system or application will automatically prepend "Bearer" to the token when constructing the header, ensuring the correct format for the server to validate the request. If "Bearer" is mistakenly included in the token value, the header will be malformed (e.g., Authorization: Bearer Bearer <token>), leading to authentication failures such as 401 Unauthorized errors.
