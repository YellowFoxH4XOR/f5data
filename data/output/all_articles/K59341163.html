Description

The following error messages are logged on the destination BIG-IP when attempting to synchronise a newly created FIPS key from the source BIG-IP:

/var/log/ltm
err mcpd[9225]: 01071a43:3: FIPS manager failed to synchronize FIPS key.
err mcpd[9225]: 01070712:3: Caught configuration exception (0), unable to synchronize FIPS key

The following error message may be logged when attempting to install a manually transferring .exp file to another BIG-IP:

For example:

tmsh install sys crypto key /Common/testkey.key from-local-file /shared/tmp/testkey.exp security-type fips
Key management library returned bad status: -18, A vendor error has occurred.
OR
Key management library returned bad status: -18, ERR_ARGUMENTS_BAD

Environment

  • BIG-IP FIPS (HSM)
  • HA pair
  • New deployment

Cause

This is caused by a Key Encryption Key (KEK) mismatch between the the FIPS cards.

Recommended Actions

The following pre-requisites must be met before you can synchronise FIPS (HSM) Keys between HA peers.

Before you can synchronize the FIPS hardware security modules (HSMs), you must ensure that the target HSM:
  • Is already initialized
  • Has an identical security domain name
  • Does not contain existing keys
  • Is the same hardware model
  • Contains the same firmware version
Before you run the fips-card-sync command, ensure that you have this information:
  • The SO password for the source F5 device
  • The SO password for the target F5 device
  • The root password for the target F5 device
The target device must also be reachable using SSH from the source device.


Additional Information

Refer to Manual Chapter : Hardware HSM Setup and Administration for further instructions for configuring FIPS (HSM) on your platform
