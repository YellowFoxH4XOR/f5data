K43573347: AD and LDAP System Authentication fails when /etc/nslcd.conf file not linked to /config/bigip/auth/pam.d/ldap/system-auth.conf

Description

After upgrade to BIG-IP appliance from software versions 14.1.2.x, 14.1.3.x, 15.1.x, 17.1.x, or 17.5.x, Active Directory and LDAP system authentication may fail with the following error(s) in /var/log/secure log file:

err httpd[XXXXX]: pam_ldap(httpd:auth): error opening connection to nslcd: No such file or directory

The systemctl command may produce the following message:

# systemctl status nslcd

* nslcd.service - Naming services LDAP client daemon.
  Loaded: loaded (/usr/lib/systemd/system/nslcd.service; disabled; vendor preset: disabled)
  Active: active (running) since Tue 2020-05-26 06:57:47 AEST; 1min 55s ago
  Main PID: 29907 (nslcd)
     CGroup: /system.slice/nslcd.service
             `-29907 /usr/sbin/nslcd -n
May 26 06:58:13 example.local nslcd[29907]: [8b4567] <authc="example-admin"> failed to bind to LDAP server ldap://127.0.0.1/: Can't contact LDAP server: Transport endpoint is not connected
May 26 06:58:13 example.local nslcd[29907]: [8b4567] <authc="example-admin"> no available LDAP server found, sleeping 1 seconds

Environment

  • BIG-IP LTM
  • Active directory
  • LDAP server
  • nslcd service

Cause

/etc/nslcd.conf is not linked to /config/bigip/auth/pam.d/ldap/system-auth.conf

Recommended Actions
Impact of procedure: Performing this procedure should not have a negative impact on your BIG-IP system.

Solution 1 

  1. Log in to the Active BIG-IP CLI as root.
  2. Remove /etc/nslcd.conf file.
    # rm /etc/nslcd.conf

  3. Manually create a symbol link.
    # ln -s /config/bigip/auth/pam.d/ldap/system-auth.conf /etc/nslcd.conf -f

  4. Restart the nslcd daemon using systemctl.
     # systemctl restart nslcd

  5. Log in to the Standby BIG-IP CLI as root. Remove /etc/nslcd.conf file.
    # rm /etc/nslcd.conf

  6. Push the config from Active to Standby.

Note: If you are using an Standalone BIG-IP, just complete steps 1 to 4.

Solution 2

  1. Log in to the BIG-IP CLI as root.
  2. Remove /etc/nslcd.conf file.
    # rm /etc/nslcd.conf

  3. Reload the config.
    # tmsh load sys config partitions all

Additional Information

Solution 1 should not cause an outage, but Solution 2 may cause traffic to be interrupted. If you have the ASM module provisioned, Solution 2 will cause a failover, as the ASM Module can take over 60 seconds to load.
