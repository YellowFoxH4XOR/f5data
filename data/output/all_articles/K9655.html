Topic

This article applies to BIG-IP GTM 9.x - 10.x. For information about other versions, refer to the following article:

  • K13994: Configuring virtual server and link auto-discovery (11.x)

Virtual server discovery and link discovery (auto-discovery) are features in which the BIG-IP GTM system automatically discovers virtual servers and links that are associated with defined BIG-IP systems. When you enable virtual server or link discovery, the BIG-IP GTM system searches for the resources on the BIG-IP system, and adds them to the BIG-IP GTM configuration. By default, the BIG-IP GTM system polls the BIG-IP LTM big3d agent based on the Auto-Discovery Request Interval setting of 30 seconds. If the BIG-IP GTM systems are members of a sync group, one of the BIG-IP GTM members becomes the device responsible for virtual server and link discovery. That BIG-IP GTM system then distributes the list of objects to the relevant sync group members.

Auto-discovery best practices

Refer to the following best practices before enabling auto-discovery for your BIG-IP system:

  • Configure auto-discovery for BIG-IP systems that have a large number of virtual servers and/or links

    F5 recommends that you configure auto-discovery for a large network that consists of hundreds of virtual servers, as managing these virtual servers can be a time-consuming process.

  • Auto-discovery is unavailable for BIG-IP virtual servers that employ address translation

    If the BIG-IP virtual servers use network address translation, do not attempt to configure virtual server auto-discovery.

    Note: Address translation in this context refers to when the BIG-IP virtual server IP addresses reside in a private network space, as defined by RFC1918, and are mapped to public IP addresses that are defined on a firewall.

Configuring auto-discovery

Enabling auto-discovery is a two-step process. You must first ensure that auto-discovery is enabled globally on the BIG-IP GTM system, and then enable virtual server and/or link auto-discovery for the appropriate BIG-IP LTM server definitions.

Enabling auto-discovery globally

Before you configure virtual server or link auto-discovery, you must verify that auto-discovery is enabled globally on the BIG-IP GTM system. To enable auto-discovery globally on the BIG-IP GTM system, perform one of the following two procedures, depending on which version you are running:

BIG-IP 10.x

  1. Log in to the Configuration utility.
  2. Navigate to System > Configuration.
  3. From the Global Traffic menu, select General.
  4. Click Auto-Discovery.
  5. Click Update.

BIG-IP 9.x

  1. Log in to the Configuration utility.
  2. Navigate to System > General Properties.
  3. From the Global Traffic menu, select General Properties.
  4. Click Auto-Discovery.
  5. Click Update.
Note: Starting with the release of 9.4.2 when the bigip_link monitor is attached to a link object, global auto-discovery cannot be disabled. Though the auto-discovery global setting can be toggled it will be automatically revert to the enabled state. In order to global auto-discovery to disabled all objects configured with the bigip_link monitor will need to have the monitor setting use a different monitor type prior to changing the global setting.

Configuring virtual server auto-discovery

When you configure virtual server auto-discovery, the BIG-IP GTM system automatically discovers the virtual server objects associated with the BIG-IP LTM server definition and adds them to the BIG-IP GTM configuration. To configure virtual server auto-discovery for a BIG-IP LTM server definition, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to Global Traffic > Servers.
  3. Click the BIG-IP LTM server definition for which you want to enable virtual server auto-discovery.
  4. Click the Virtual Servers menu.
  5. From the Virtual Server Discovery menu, select Enabled or Enabled (No Delete).

    Note: If you select the Enabled (No Delete) setting, the BIG-IP GTM system automatically adds and modifies virtual server settings in the configuration, but does not delete them. Using this setting prevents inadvertent deletion of valid network objects during network outages.

  6. Click Update.

Configuring link auto-discovery

When you configure link auto-discovery, the BIG-IP GTM system automatically discovers the link objects associated with the BIG-IP LTM server definition and adds them to the BIG-IP GTM configuration. To configure link auto-discovery for a BIG-IP LTM server definition, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to Global Traffic > Servers.
  3. Click the BIG-IP LTM server definition for which you want to enable link auto-discovery.
  4. Click the Links menu.
  5. From the Link Discovery menu, select Enabled or Enabled (No Delete).

    Note: If you select the Enabled (No Delete) setting, the BIG-IP GTM system automatically adds and modifies Link settings in the configuration, but does not delete them.

  6. Click Update.

Auto-discovery of virtual servers in other route domains

When a BIG-IP GTM system performs auto-discovery, only virtual servers within the route domain being queried will be discovered.

Beginning in BIG-IP GTM 10.2.3, you can configure auto discovery to discover virtual servers for all route domains on the BIG-IP LTM system by enabling the expose-route-domains option. Enable the expose-route-domains option for a BIG-IP GTM server using the following procedure:

Note: When setting the expose-route-domains option to yes, BIG-IP GTM discovers all virtual servers, including those in non-default route domains. However, BIG-IP GTM does not include route domain notation in its configuration. For this reason, all virtual servers must have unique names.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Enable the expose-route-domains option for a BIG-IP GTM server by typing the following syntax:

    modify gtm server <server_name> expose-route-domains yes

    In this syntax, replace <server_name> with the name of the BIG-IP GTM server.

Troubleshooting auto-discovery

If you have configured auto-discovery and the BIG-IP GTM system does not automatically identify the virtual servers and links, you should verify the following:

  • Confirm that the BIG-IP virtual servers do not employ address translation.
  • Verify that NTP is configured on the BIG-IP GTM and LTM systems, and that the system times are in sync.
  • Confirm that iQuery communication is functioning between devices.
  • Verify that the big3d process is broadcasting the virtual server and link data.
  • Confirm sync group functionality (BIG-IP GTM sync group members).

Confirm that the BIG-IP virtual servers do not employ address translation

Auto-discovery is unavailable for virtual servers using translated IP addresses. Before troubleshooting auto-discovery issues, confirm that the BIG-IP virtual servers do not use address translation.

Note: For more information, refer to K9138: The BIG-IP GTM disables virtual server auto-discovery for BIG-IP systems which utilize translated virtual server addresses.

Verify that NTP is configured on the BIG-IP GTM and LTM systems, and that the system times are in sync

BIG-IP GTM sync group members synchronize their configurations by comparing the timestamps of their own configuration files with the timestamps of configuration files on other BIG-IP GTM systems. As a result, sync group members must be configured to use NTP.

Note: For more information about configuring NTP, refer to K3122: Using the BIG-IP Configuration utility to add an NTP server.

After verifying that NTP is configured for F5 systems, run the date command on the devices, and confirm that the dates and times are synchronized.

Confirm that iQuery communication is functioning between devices

When your network topology consists of multiple BIG-IP GTM systems load-balancing BIG-IP LTM systems, the systems must be able to communicate using the iQuery protocol. Upon starting, the gtmd process running on each BIG-IP GTM system reads the wideip.conf file and attempts to establish an SSL connection on port 4353 with the big3d process running on BIG-IP LTM systems. The BIG-IP GTM system performs this action for all self IP addresses that are configured for the BIG-IP LTM server objects, creating a mesh of iQuery connections running between all gtmd and big3d processes.

Note: For more information about troubleshooting iQuery connections on the BIG-IP GTM system, please refer to the following article:

K14227: Troubleshooting BIG-IP GTM synchronization and iQuery connections (10.x)

If there is a failure in the iQuery communication channel, gtmd will fail to automatically discover objects defined on the target BIG-IP LTM. One way to confirm that iQuery communication is functioning is to check the BIG-IP LTM server status on all BIG-IP GTM devices. The BIG-IP LTM server objects should appear green. If the BIG-IP LTM server objects are red or blue, you should verify the following:

  • Verify that the self IP addresses and iQuery port are reachable between F5 devices

    To verify that the self IP addresses and iQuery port are accessible between F5 devices, use the telnet command to open a connection on port 4353 from one F5 device to another. For example, to Telnet on port 4353 from the BIG-IP GTM system to the remote BIG-IP LTM device, type the following command:

    telnet <remote_ltm_ip> 4353

  • Verify that the SSL device certificates are valid

    F5 devices use SSL certificates for iQuery communication. If device certificates are missing or expired on an F5 device, iQuery communication will fail, and error messages that appear similar to the following example are logged to the /var/log/gtm file of the BIG-IP GTM system initiating the iQuery session:

    gtmd[8472]: 011ae020:5: Connection in progress to <iquery_peer>
    gtmd[8472]: 011ae01c:5: Connection complete to <iquery_peer>. Starting SSL handshake
    iqmgmt_ssl_connect: SSL error:14090086:SSL routines:SSL3_GET_SERVER_CERTIFICATE:certificate verify failed

    Note: If iQuery communication fails due to missing or expired SSL device certificates, refer to K8187: Troubleshooting BIG-IP device certificates.

Verify that the big3d process is broadcasting the virtual server and link data

Once the iQuery mesh is established, the gtmd process sends probes to the big3d process in the form of Zlib compressed XML data, which are XML blocks sent to a big3d. Multiple block types are used. The big3d process then compiles a list and broadcasts the response by sending the XML block to multiple BIG-IP GTM systems that have an established iQuery connection with the big3d.

If the remote BIG-IP LTM devices are marked green by the BIG-IP GTM systems, but the BIG-IP GTM systems fail to automatically discover the virtual server and link objects, you can use the iqdump utility to verify that the BIG-IP LTM is properly broadcasting the virtual server and link objects.

For example, when you create a new virtual server configuration on the BIG-IP LTM, the mcpd process notifies big3d of the new configuration, and the big3d agent then broadcasts the virtual server information along with the complete list of virtual servers to all gtmds in the same sync group in a <getconfig> element block. You can verify that the big3d process is broadcasting the virtual server information by running the iqdump command from the BIG-IP GTM system, as follows:

iqdump <bigip_ltm_ip>

The command output appears similar to the following example:

<getconfig_element>
<type>2</type>
<ip>::ffff:172.16.65.73</ip>
<netmask>::</netmask>
<port>8085</port>
<flags>0</flags>
<pool>vip6</pool>
</getconfig_element>
<getconfig_element>
<type>2</type>
<ip>::ffff:172.16.65.73</ip>
<netmask>::</netmask>
<port>8090</port>
<flags>0</flags>
<pool>vip10</pool>
</getconfig_element>

The <getconfig> element blocks display the virtual server IP address, service port, and name. If you verify that the big3d process is properly broadcasting the virtual server information, but the virtual servers do not appear in the BIG-IP GTM configuration, you may need to restart the big3d process by typing the following command on the BIG-IP LTM system:

bigstart restart big3d

Confirm sync group functionality (BIG-IP GTM sync group members)

A BIG-IP GTM synchronization group is a collection of multiple BIG-IP GTM systems that synchronize BIG-IP GTM configuration settings and metrics information. You must meet several minimum requirements for BIG-IP GTM synchronization group members to communicate and synchronize properly. For information, refer to K13734: BIG-IP GTM synchronization group requirements.
