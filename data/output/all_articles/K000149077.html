Description

K66202843 outlines how BIG-IP sends DNS query to name servers when there are multiple name servers configured under "[System] >> Configuration : Device : DNS".


On the following example configuration, 2 DNS name servers "10.1.1.203" and "10.1.1.204" are configured, and "10.1.1.203" has higher precedence than "10.1.1.204". 

Figure: DNS Lookup Server List example

 

Given ordered list of multiple name servers as shown above, BIG-IP normally sends DNS query to "10.1.1.203" first. If "10.1.1.203" is unavailable or returns "SERVFAIL" response, BIG-IP sends DNS query to next server "10.1.1.204". Expected behavior here is that every time when BIG-IP needs to resolve each hostname ("mail", "mail.localhost", or "mail.f5ss.local"), "10.1.1.203" is first choice, as shown on following example.

Figure: packet capture example (order of nameservers is honored)

 

However, under specific condition, ordered name server list may be ignored and BIG-IP may send DNS query to name server which has lower priority than other name server. Specifically, BIG-IP (dnscached, which is APM related DNS service) selects name server based on internally cached srtt value.


On the following example, BIG-IP first sends DNS query for host "mail" to "10.1.1.204" and after then sends same query to "10.1.1.203". After then, to resolve another name "mail.localhost" (search domain "localhost" is appended), BIG-IP sends DNS query for "mail.localhost" to "10.1.1.204" first. And then, BIG-IP tries to resolve another hostname "mail.f5ss.local" (another search domain "f5ss.local" is appended) but BIG-IP again sends DNS query to "10.1.1.204" first. Here, higher priority server "10.1.1.203" is merely used. This is because 10.1.1.204 had been responding to DNS query faster than 10.1.1.203 did. In other words, 10.1.1.204 was 'preferred', as it has been 'faster' than 10.1.1.203.

Figure: packet capture example (order of nameservers is ignored)

 

There is no configuration option to have dnscached send DNS query to name server in a strict order.

 

Environment

All of following conditions need to be met.

 

  • BIG-IP S/W version with ID876937 fix (14.1.4.3 or later / 15.1.4 or later / 16.x / 17.x).
  • APM access policy uses OTP generator (One Time Password generator). Access policy uses Device SMTP server (sys smtp-server) configuration to send one-time password email to mail server.
  • "SMTP Server Host Name" (smtp-server-host-name) is configured with hostname, not with an IP address. If "SMTP Server Host Name" is configured with an IP address, no DNS name resolution happens.
sys smtp-server otp-generate-smtp-server {
    from-address bigipadmin@f5ss.local
    local-host-name VEAPM.f5ss.local
    smtp-server-host-name mail
}
  • System DNS configuration is configured with multiple name-servers.
sys dns {
    name-servers { 10.1.1.203 10.1.1.204 }
    search { localhost f5ss.local }
}

 

Cause

ID876937 introduced this behavior change.

 

Recommended Actions

None. Even though order of name server is not strictly honored, name resolution for SMTP server would succeed as long as any name server provides proper A record.
