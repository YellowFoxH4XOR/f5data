Known Issue

This is the result of a known issue. The snmpd daemon may begin restarting and producing a core dump repeatedly. This issue occurs after the snmpd process attempts to perform a division by 0 (zero), which is an illegal arithmetic operation. This issue is known to occur after upgrading the BIG-IP system to a new release or hotfix.

You may observe the following symptoms when this issue occurs:

  • Messages that appear similar to the following example are logged to /var/log/daemon.log file:

    rmonsnmpd[18220]: Lost connection to master agent.
    subsnmpd[18214]: Lost connection to master agent.
    LOGIN: Re-starting snmpd
    subsnmpd[18441]: Connect to master agent successfully.
    rmonsnmpd[18444]: Connect to master agent successfully.
  • The following message is displayed on the BIG-IP console:

    ‘LOGIN: Re-starting snmpd
  • The bigstart status command shows that the snmpd, rmonsnmpd, and subsnmpd daemons have restarted multiple times since system boot up:
     
    For example:

    rmonsnmpd    run (pid 27074) 1 minutes, 28630 starts
    snmpd        run (pid 27047) 1 minutes, 28570 starts
    subsnmpd     run (pid 27067) 1 minutes, 28629 starts

When this issue occurs, the BIG-IP system works correctly, except for snmp related functions. Restarting the BIG-IP system does not resolve the issue.

F5 Product Development tracked this issue as CR118315 and it was fixed in BIG-IP versions 9.4.7 and 10.1.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, Link Controller, WebAccelerator, PSM, or WAN Optimization release notes.

Additionally, this issue was fixed in Hotfix-BIG-IP-9.3.1-81.1-HF8 issued for BIG-IP version 9.3.1, Hotfix-BIGIP-9.4.5-1091.0-HF3 issued for BIG-IP version 9.4.5, Hotfix-BIGIP-9.4.6-423.0-HF2 issued for BIG-IP version 9.4.6, and Hotfix-BIGIP-10.0.1-342.0-HF1 issued for BIG-IP version 10.0.1.
