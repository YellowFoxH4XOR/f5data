Known Issue

The BIG-IP system may not correctly parse URLs that contain multiple question marks ( ? ).

This issue occurs when all of the following conditions are met:

  • You are using the Intelligent Browser Referencing (IBR) feature.
  • The requested URL contains two or more question marks.
  • One or more question marks are located within the query data of the request.

For example, the following URL includes a question mark in the query data, which is the second question mark in the URI:

http://f5test.com/path?query=bar?&data=baz

As a result, the system sends a malformed request to the origin web server (OWS):

http://f5test.com/path;waf8fa815e263741ce??query=bar

Impact

Affected queries to the OWS will fail.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The OWS may respond with an HTTP 404 - Not Found response code or other application error message, indicating the request cannot be processed.

Workaround

To work around this issue, you can use an iRule to strip out IBR tags from requests to the OWS. To do so, perform the following procedure:

Impact of workaround: iRules may increase processing overhead and require more system resources per connection.

Associate the following iRule to your BIG-IP AAM-enabled virtual server:

when HTTP_REQUEST_RELEASE {
  set ibrpoint [string first ";wa" [HTTP::uri]]
  if {$ibrpoint != -1} then {
    set ibrend [expr {$ibrpoint + 18 } ]
    HTTP::uri [string replace [HTTP::uri] $ibrpoint $ibrend]
  }
}

Note: You may need to change the ;wa string in the previous iRule if the default IBR prefix has been modified.
