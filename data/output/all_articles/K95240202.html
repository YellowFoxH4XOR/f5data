Description

You want to understand how BIG-IP iRule variables are scoped.

Three types of variables are available in iRules: local, static, and global (deprecated). iRule variables are accessible from all iRules in the scope where they are set. More information is available below and in the related content.

Environment

  • BIG-IP
  • iRules
Cause

None

Recommended Actions

None

Additional Information

Variables are scoped according to a prefix. If a variable has a :: tag in its name it is either static or global, depending on the prefix. Otherwise :: cannot be used in a variable name.

Local variables
These variables have no prefix - for example, a variable named foo. Local variables are scoped to the connection, and are deleted when the connection is cleared. In most cases, this is the most appropriate variable type to use.
Note: With certain configurations, iRule commands can be used to share local variables between connections that otherwise could not share iRule data. These include sharedvar, MR::store, and MR::restore. 

Static variables
These variables have a prefix of static:: - for example, a variable named static::bar. These variables are scoped to the local TMM (some documentation refers to CMP node). Most often, static variables are set in RULE_INIT to configure iRules. They can also be set during connection processing, but you must consider the implications of setting a variable which will only change on the local TMM.

Global variables
Important: Global variables are considered deprecated and should be avoided in new configurations.
These variables have a prefix of :: - for example, a variable named ::baz. Global variables are globally scoped, but to accomplish this they demote any virtual server the iRule is attached to from CMP. For this reason, F5 recommends storing information generated at runtime using the table command if it must be accessed by all connections. Review K13033: Constructing CMP-compatible iRules for more information.

Local vs Static Example

In the following example the local variable in CLIENT_ACCEPTED is accessible to SERVER_CONNECTED, HTTP_REQUEST, and HTTP_RESPONSE. All those events occur in the same connection and each time CLIENT_ACCEPTED occurs it will assign a new value to the variable. Typically static variables are set in RULE_INIT and then can be accessed by any connection and will contain the same static value that is assigned when RULE_INIT fires. The following example iRule and log output illustrates how local and static variables work:

when RULE_INIT {
    set static::statcurtime [clock seconds]
    set static::statformattedtime [clock format $static::statcurtime -format {%H:%M:%S} ]
    log "RULE_INIT time: $static::statformattedtime"
}

when CLIENT_ACCEPTED {
    set curtime [clock seconds]
    set formattedtime [clock format $curtime -format {%H:%M:%S} ]
    log "CLIENT_ACCEPTED time: $formattedtime"
}

when SERVER_CONNECTED {
    log "CLIENT_ACCEPTED time: $formattedtime and RULE_INIT time: $static::statformattedtime"
}

when HTTP_REQUEST {
    log "CLIENT_ACCEPTED time: $formattedtime and RULE_INIT time: $static::statformattedtime"
}

when HTTP_RESPONSE {
    log "CLIENT_ACCEPTED time: $formattedtime and RULE_INIT time: $static::statformattedtime"
}

The time stays the same in the static variable created during RULE_INIT while it updates to the current time in the local variable each time CLIENT_ACCEPTED fires:

Rule /Common/var_test <CLIENT_ACCEPTED>: CLIENT_ACCEPTED time: 10:24:20
