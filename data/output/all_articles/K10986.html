K10986: Configuring static web content to bypass BIG-IP ASM versions 10.0.1 and later

Topic

You can configure the BIG-IP ASM system to allow static web content requests, such as images, to bypass the BIG-IP ASM security policy and travel directly to the web server. To do so in BIG-IP ASM 10.0.1 or higher, perform the following three procedures:

  • Ensure that the images Data Group contains the correct file types
  • Create a static web content pool
  • Create an iRule to cause static content to bypass the BIG-IP ASM

Note: A known issue in BIG-IP ASM 10.0.0 requires the additional configuration of a second virtual server to which bypass traffic will be directed. For more information and a workaround, refer to K10128: The PLUGIN iRule commands do not function in BIG-IP version 10.0.0.

Note: For information about configuring BIG-IP ASM 9.x to allow static web content requests to bypass the BIG-IP ASM system, refer to K7616: Configuring static web content to bypass the BIG-IP ASM in BIG-IP version 9.x.

Ensure that the images Data Group contains the correct file types

To ensure that the images Data Group contains the correct file types, perform the following procedure:

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Click Local Traffic.
  3. Click iRules.
  4. Click Data Group List from the menu bar.
  5. Click the images Data Group.
  6. Verify that the file types listed represent the static image files on the web server. Entries must be in lower case.
  7. Click the Update button.
Create a static web content pool

To create a static web content pool, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Click Local Traffic.
  3. Click Pools.
  4. Click Create.
  5. Type a name for the pool.

    Note: The iRule example below uses the pool named static_pool.

  6. Choose an appropriate monitor to check the status of the pool members.
  7. Select a load balancing method from the Load Balancing Method drop-down menu.
  8. Add the pool members that serve static web content.
  9. Click Finished.
Create an iRule to cause static content to bypass the BIG-IP ASM (version 10.0.1 and later)

To create an iRule to cause static content to bypass BIG-IP ASM versions 10.0.1 and later, perform the following procedure:

  1. Log in to the BIG-IP ASM Configuration utility.
  2. Click Local Traffic.
  3. Click iRules.
  4. Click Create.
  5. Type a name for the iRule.
  6. Enter the following iRule in the Definition box:

    Note: Replace host.domain.com with the name of the Host header you want to insert; if necessary, also replace static_pool with the name of the pool you created in the previous procedure.

    when RULE_INIT {
    set static::mypool "static_pool"
    set static::myhost "host.domain.com"
    set static::maxurilength "100"
    }
    when HTTP_CLASS_SELECTED {
    ASM::enable
    if {[matchclass [string tolower [HTTP::uri]] ends_with images]}{
    # Verify request is an HTTP GET, starts with a / and is of required length
    if {([HTTP::method] eq "GET") and ([HTTP::uri] starts_with "/")and([string length [HTTP::uri]] < $static::maxurilength)}{
    set test_uri [string range [HTTP::uri] 1 [expr {[string last . [HTTP::uri]]-1}]]
    # verify request only contains allowable characters
    if {[string is alnum [string map {%20 {} / {} $ {} _ {} - {}} $test_uri ] ]} {
    # Remove all HTTP headers
    foreach header_name [HTTP::header names] {
    while { [HTTP::header exists $header_name] } {
    HTTP::header remove $header_name
    }
    }
    HTTP::header insert Host static::myhost
    # Set the HTTP version
    HTTP::version "1.0"
    HTTP::header insert Connection close
    ASM::disable
    pool $static::mypool
    }
    }
    }
    }

  7. Click Finished.

You must now associate the iRule and Pool with the virtual server that manages traffic for the security policy.
