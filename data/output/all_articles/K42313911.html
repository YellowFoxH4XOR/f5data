Description

Upon upgrade from a version lower than 13.0 to a version higher than 13.0, configuration may fail to load with an error such as the one example below:

010716e2:3: Policy '<policy_name>', rule '<rule_name>'; an action precedes its conditions.
Unexpected Error: Validating configuration process failed.

Environment

  • After upgrade to 13.0 or above
  • LTM policy
  • Config not loading

Cause

For "first-match" strategy, the system uses an ordinal number. It starts the verification from lower to higher. For more info on this, please see K15085.

In 13.0, a stricter verification of LTM policies was introduced via ID758101. Before, one could configure (for example) an HTTP response time check event with ordinal number 1 and an HTTP request time check event with ordinal number 2.  Since an HTTP response happens after an HTTP request event (and not before) this is now not allowed due to the stricter verification introduced.

This means that, any older systems (<13.0) running with such configurations which perform an upgrade to >13.0 will have their configuration failing to load.

The error message will give away the name of the LTM policy and the rule number for which the problem was found. Typically, one has to look for the ordinal number of the rule being presented as problematic and look for a rule with ordinal number before the one being presented. In the example provided above (HTTP response with ordinal 1 and HTTP request with ordinal 2), the system would present ordinal 2 as being problematic but the one to focus is the one before (in this case, ordinal 1). This rule should have an ordinal number higher than others, so it runs after all other rules. The idea is that, all HTTP response rules should run after the HTTP request ones (so the ordinal number of HTTP response rules should be higher than all ordinal numbers from HTTP request rules).

Recommended Actions

Remove the policy mentioned on the error from bigip.conf file, this can be done before or after upgrade, on the command line, by editing the bigip.conf file and then loading the config again with tmsh load sys config.
