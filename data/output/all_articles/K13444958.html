K13444958: Extending Prometheus storage without deleting data for Aspen Mesh Metrics Collector

Type
Support Solution
Published
2021-07-27
Updated
2023-02-21
Applies to
  • Aspen Mesh
Source
https://my.f5.com/manage/s/article/K13444958

Description

Prometheus instance running in Aspen Mesh Metrics Collector is using Persistent Volume Claim (PVC) to store metrics collected from the mesh. The PVC filesystem is mounted to /metrics-collector/tsdb directory in metrics-collector container:

$ kubectl get pods -n istio-system aspen-mesh-metrics-collector-85f7866d77-wjww8 -o yaml  
…
  containers:
    name: metrics-collector
    - mountPath: /metrics-collector/tsdb
      name: datastore
…
- name: datastore
    persistentVolumeClaim:
      claimName: aspen-mesh-metrics-collector

By default, PVC is deployed by helm chart with 10Gi of storage requirements.

Here is the part of the default configuration for aspenmesh-metrics-ccollector chart extracted from Helm values yaml file:

aspen-mesh-metrics-collector:
  server:
  persistentVolume:
    enabled: true
    accessModes:
      - ReadWriteOnce
    annotations: {}
    existingClaim: ""
    size: 10Gi
    # storageClass: "-"

Metrics collector collects data from all PODs in the mesh. The number of metrics exposed by every POD depends on multiple factors like the size of the mesh and the traffic patterns. One Envoy proxy may create hundreds or even thousands of metrics. In time 10 Gi storage might be not enough for the large mesh.

Int this article we show how to increase Persistent Volume Claim size without deleting data stored by Prometheus.

Environment

  • Kubernetes: 1.17x,1.18.x,1.19.x,1.20.x  
  • Aspen Mesh:  1.6.x, 1.9.x, 1.11.x, 1.14.x

Cause

N/A

Recommended Actions

Persistent volume expansion was implemented in Kubernetes in early versions and was promoted to beta since version 1.11. Using this feature users do not have to manually modify storage backend or filesystem to extend the size of the volume. Shrinking the volume is not supported. Not all kubernetes volume plugins allow PVC expansion. For more information, please refer too Kubernetes documentation. Examples are also shown here.

To increase PVC size assigned to aspenmesh-metrics-collector, perform the following procedure:

  1. Verify the actual size of the Persistent Volume Claim provisioned to Aspen Mesh Metrics Collector using the following command:

    kubectl get pvc -n istio-system aspen-mesh-metrics-collector

    The output appears similar to the following example:

    NAME                           STATUS   VOLUME                                     CAPACITY   ACCESS MODES   STORAGECLASS    AGE
    aspen-mesh-metrics-collector   Bound    pvc-34dce652-4005-4275-abcb-765130dc4df8   1Gi        RWO            kops-ssd-1-17   164m

  2. Verify that StorageClass used by the PVC allows storage capacity expansion using the following command:

    kubectl get storageclass kops-ssd-1-17

    The output appears similar to the following example:

    NAME                      PROVISIONER             RECLAIMPOLICY   VOLUMEBINDINGMODE      ALLOWVOLUMEEXPANSION   AGE
    kops-ssd-1-17 (default)   kubernetes.io/aws-ebs   Delete          WaitForFirstConsumer   true                   35d

  3. Check current disk usage on Prometheus metrics-collector container by opening a shell and running df -kh command:

    /metrics-collector/tsdb $ df -kh

    The output appears similar to the following example:

    Filesystem                Size      Used Available Use% Mounted on
    …
    /dev/nvme1n1            975.9M    939.7M     20.2M  98% /metrics-collector/tsdb

  4. Modify override global values yaml file for Istiod Helm chart and configure the storage size you want to use. For example:

    aspen-mesh-metrics-collector:
      server:
        persistentVolume:
          size: 10Gi

  5. Upgrade Istiod Helm deployment with the following command:

    helm upgrade istiod manifests/charts/istio-control/istio-discovery --namespace istio-system --values values.yaml

  6. Verify that the PVC was extended and the filesystem inside container shows a new size. For detail, refer to the following commands and example outputs:

    kubectl get pvc -n istio-system aspen-mesh-metrics-collector
    NAME                           STATUS   VOLUME                                     CAPACITY   ACCESS MODES   STORAGECLASS    AGE
    aspen-mesh-metrics-collector   Bound    pvc-34dce652-4005-4275-abcb-765130dc4df8   1Gi        RWO            kops-ssd-1-17   164m

    kubectl get storageclass kops-ssd-1-17
    NAME                      PROVISIONER             RECLAIMPOLICY   VOLUMEBINDINGMODE      ALLOWVOLUMEEXPANSION   AGE
    kops-ssd-1-17 (default)   kubernetes.io/aws-ebs   Delete          WaitForFirstConsumer   true                   35d

    kubctl get pvc -n istio-system aspen-mesh-metrics-collector
    NAME                           STATUS   VOLUME                                     CAPACITY   ACCESS MODES   STORAGECLASS    AGE
    aspen-mesh-metrics-collector   Bound    pvc-34dce652-4005-4275-abcb-765130dc4df8   10Gi       RWO            kops-ssd-1-17   166m

    kubectl exec -n istio-system aspen-mesh-metrics-collector-85f7866d77-l64sw -c metrics-collector-- sh
    /metrics-collector/tsdb $ df -kh
    Filesystem                Size      Used Available Use% Mounted on
    …
    /dev/nvme1n1              9.8G    944.1M      8.9G   9% /metrics-collector/tsdb
