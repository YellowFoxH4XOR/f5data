Known Issue

This is the result of a known issue. In BIG-IP versions 9.3.x, 9.4.x, and 10.x, the BIG-IP system may incorrectly report the ConfigSync state as synchronized when the running configurations on the devices in the high-availability pair are not synchronized. This state may occur when the member of the high availability pair that has been synchronized to fails to load the new configuration after it has been transferred from its peer.

This issue can occur any time the configuration fails to load on the remote host after a ConfigSync. For example, the issue can occur for the following reasons:

  • The configuration contains features that are not licensed on the destination device
  • Object conflicts (a floating self IP is declared on a network for which no non-floating self IP is already extant)
  • Syntax errors in iRules

Error messages returned by the ConfigSync process indicate that the configuration has failed to load. These error message appear similar to the following example:

OperationFailed exception:
Primary error : 16908289
Secondary error: 0
Error text : Error installing configuration

Loading the configuration ...
WARNING: There were one or more errors detected during installation.
Check the error messages and take the proper actions if needed.
ERROR: UCS installation failed.
Operation aborted.
/tmp/configsync.spec: Error installing package
Config install aborted.
BIGpipe parsing error:
01110001:3: Error running config install

However, following such a failure, the system will report the sync status in the Configuration utility as ConfigSync: OK.

When you check the sync status from the command line by typing the following command:

bigpipe db Configsync.State

The command output will return the following value:

Configsync.State = 0 - Synchronized

Determining the reason for the ConfigSync failure

If the above UCS installation error message displays while running a ConfigSync, you can determine the reason for the failure by performing the following procedure:

  1. Log in to the master BIG-IP host command line as the root user.
  2. Manually create a UCS backup by typing the following command:

    bigpipe config save /var/tmp/config.ucs
  3. Copy the config.ucs file to the peer host by typing the following command:

    scp /var/tmp/config.ucs peer://var/tmp/config.ucs
  4. Enter your root password if requested.
  5. Log in to the peer BIG-IP host as the root user.
  6. Restore the ucs file you copied from the master host by typing the following command:

    bigpipe config install /var/tmp/config.ucs

Any errors you see during the UCS installation should help you determine the reason for the UCS install failure.

F5 Product Development tracked this issue as ID 249234 and it was fixed in BIG-IP version 11.0.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, or WOM release notes.
