Known Issue

Custom external monitors using the curl command may fail to establish Secure Sockets Layer (SSL) connections.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system is running any of the following versions:
    • 11.5.4 HF2 through 11.5.6
    • 11.6.1 HF1 through 11.6.3
  • You use the curl command on the BIG-IP system to connect to a SSL server.
  • The curl command uses the --tlsv1.0 or --tlsv1.1 flag to force the SSL connection to establish a connection at that version level.

Impact

The SSL connection establishes at a different Transport Layer Security (TLS) version or the connection fails to establish.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When you analyze SSL connection information, the connection establishes using a different TLS version.
  • When you analyze the SSL connection information, the connection fails with an SSL handshake failure.

Workaround

To work around this issue, you can utilize the curl-apd command when requiring TLSv1.0 connections.

Impact of workaround: The curl-apd command does not implement TLSv1.1 or TLSv1.2; curl-apd will not function when connecting to SSL servers that require these versions.
