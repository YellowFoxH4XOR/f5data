K9251: Failover behavior in Active Directory group mapping

Topic

You can use the Active Directory (AD) dynamic group mapping method, which is located on the Users : Groups : Dynamic Group Mapping : Group mapping methods page, to use a primary and secondary server for authentication. When the primary server is not available, FirePass will send requests to the secondary server. However the FirePass does not send requests back to the primary server once the primary server returns to an active state until the administrator manually pushes the traffic back to that server. This is expected behavior based on the implementation of CR92934 (K8680:Active Directory servers that are unresponsive for group mapping cause delayed logins). Requiring manual intervention will ensure that authentication is not bouncing back and forth in the event that the primary server is intermittently available but the root problem has not been resolved.

To force FirePass to send requests back to the primary server, the administrator can click on the Update button on the Users : Groups : Dynamic Group Mapping : Group mapping methods : AD page. The administrator can test the setting of a user on the Users : Groups : Dynamic Group Mapping : master group mapping table/resource group mapping table : Test page. The results should show the FirePass controller query the primary server first.
