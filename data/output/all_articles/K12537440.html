Description

SYN is not forwarded by a fastl4 virtual server with source-port preserve-strict. It is silently dropped, causing the client to retransmit, and the connection to fail.

7.520557  10.10.30.114 → 10.10.30.135 TCP 185 IN  s1/tmm0 : 5060 → 80 [SYN]

22.820084 10.10.30.114 → 10.10.30.135 TCP 185 IN  s1/tmm0 : [TCP Retransmission] 5060 → 80 [SYN]
38.948851 10.10.30.114 → 10.10.30.135 TCP 185 IN  s1/tmm0 : [TCP Retransmission] 5060 → 80 [SYN]

Environment

  • FastL4 profile
  • Source Port Preserve Strict
  • SNAT

Cause

This is expected behaviour with source-port preserve-strict when there is already a server-side connection using the expected connection tuple. In this case, a collision occurs and the ingress SYNs are silently dropped.

This behaviour is covered in ID 678450.

Recommended Actions

Examine the connection table output to determine if a server-side connection already exists. Further troubleshooting may be needed to locate the source of the connection in question.

  • K53851362: Displaying and deleting BIG-IP connection table entries from the command line
Note: There are numerous reasons why a SYN might be dropped. If source-port preserve-strict is not in use, the issue described in this article is unlikely to be the root cause.

Additional Information

This issue only occurs with a fastl4 profile in use. With a standard virtual server, a TCP reset would be issued on the client side.
