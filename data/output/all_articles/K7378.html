K7378: FP_DO_NOT_TOUCH tags are disabled after an upgrade to FirePass 6.0.1 or 5.5.2

Issue

Web content requested by a client using Portal Access is sent from the server through the FirePass controller's reverse proxy engine. The reverse proxy engine processes the content using rewriting mechanisms, such as obscuring the server hostname in the URL, and also performs security checking. However, you may insert into a web page the following FirePass-specific markup language:

<FP_DO_NOT_TOUCH>

Standard web content...

</FP_DO_NOT_TOUCH>

Web content between the FP_DO_NOT_TOUCH tags is not processed in the standard way by the reverse proxy engine. This is useful if standard processing has been shown to break the web application.

In FirePass 6.0.1 and 5.5.2, a check box setting has been added to the Administration UI that allows you to choose whether the content within the FP_DO_NOT_TOUCH tags is processed normally by the reverse proxy engine.

When you upgrade to feature release 6.0.1 or later, or maintenance release 5.5.2 or later, the check box is selected by default. When the check box is selected, the FP_DO_NOT_TOUCH tag functionality is disabled, and web content within the tags is processed normally by the reverse proxy engine. This setting produces the opposite behavior of the version of FirePass software from which you upgraded. Web applications that required the FP_DO_NOT_TOUCH tags will not function as they did prior to the upgrade. To restore the previous behavior, clear the Process content of the FP_DO_NOT_TOUCH element check box on the Global Settings tab of the Portal Access > Web Applications > Content Processing page.
