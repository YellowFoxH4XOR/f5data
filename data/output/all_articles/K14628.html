Known Issue

A connection may hang or the BIG-IP system may direct the connection to an incorrect pool member.

This issue occurs when all of the following conditions are met:

  • The affected virtual server does not have a default pool configured.
  • The affected virtual server is configured to use a fallback persistence profile.
  • The affected virtual server uses an iRule that accomplishes one of the following:

    • The virtual server performs the destination pool selection using the pool command.
    • The virtual server runs the persist command multiple times within the same Client_Accepted or Layer 7 request event.

When an iRule pool command performs the pool selection, the BIG-IP system may not forward the connection to the selected pool member and the connection will stop responding.

When the iRule runs the persist command multiple times within the same event, the BIG-IP system may fail to persist and load balance the connection to an incorrect pool member.

Impact

Connections may stop responding or the BIG-IP system directs these connections to an incorrect pool member.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H427305 on the Diagnostics > Identified > Medium screen.
  • Connections may stop responding.
  • Connections may not be persisted as expected.

Workaround

To work around this issue, you can configure the virtual server to use a default pool, and/or modify the affected iRule to ensure the persist command runs only once.
