Description

If you are accessing an application, the client machine initiates a handshake with the server machine. If the handshake is not successful, the connection is dropped. 

To view the handshake is successful, you may capture the traffic from the client or server machine and inspect the Wireshark capture to identify the status of the handshake. 

Environment

  • BIG-IP passing TLS Traffic
  • Client SSL Profile (optional)
  • Server SSL Profile (optional)

Cause

None

Recommended Actions

  • Review TCP 3-Way-Handshake
  • Review TLS Negotiation

TCP Handshake

TCP handshake is also known as a 3-Way-Handshake. When a connection is initiated from the client machine to the server machine, the client and server exchange SYN and ACK packets before the data is transmitted.

TLS Negotiation

SSL or TLS handshake happens after the 3-Way handshake. SSL and TLS names are used interchangeably, SSL communication consists of a series of messages exchanged between two parties (client and server). The TLS negotiation between a client and server consists of steps, and appears as follows.

Note: Depending on the options presented in the Client Hello and Server Hello, there may be additional steps required to complete the TLS Negotiation.

The SSL messages determine the parameters of the encrypted communication channel that the two parties will use. It is important that the client and server agree on the message details, such as the protocol version, cipher suites, secure renegotiation, or client certificate requests. Otherwise the handshake will fail. The SSL handshake has the following messaging components:

  • Client Hello
  • Server Hello
  • Certificate
  • ServerHelloDone
  • ClientKeyExchange
  • ChangeCipherSpec
  • Finished
  • Resumed SSL sessions

For detailed description of each component, refer K15292
