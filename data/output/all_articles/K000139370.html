Description

CLIENTSSL_SERVERHELLO_SEND event does not fire even though an iRule is attached to client-ssl virtual server. Here is sample iRule.

ltm rule ssl-test-rule {
   when CLIENTSSL_SERVERHELLO_SEND {
      log local0. "MYDEBUG: CONNECTION: [IP::client_addr]:[TCP::client_port] to [IP::local_addr]:[TCP::local_port]"
      log local0. "MYDEBUG: TMM: TMM is [TMM::cmp_unit]"
   }
}

 

Environment

  • SSL virtual server.
  • An iRule with CLIENTSSL_SERVERHELLO_SEND event.

 

    Cause

    As explained on clouddocs iRule document, SSL Forward Proxy Bypass configuration is required for CLIENTSSL_SERVERHELLO_SEND event to fire. 

      > Triggered when the system is about to send its SSL ServerHello message on the clientside connection. This event is triggered only when in Forward Proxy Bypass mode and the bypass decision is still unknown

    Here is sample configuration with which CLIENTSSL_SERVERHELLO_SEND event can fire.

    ltm virtual fwdp_vs {
    destination 0.0.0.0:https
    ip-protocol tcp
    mask any
    pool nexthop_pool
    profiles {
        my_clientssl_fwdp {
            context clientside
        }
        my_serverssl_fwdp {
            context serverside
        }
        tcp { }
    }
    rules {
        ssl-test-rule
    }
    serverssl-use-sni disabled
    source 0.0.0.0/0
    source-address-translation {
        pool my_snatpool2
        type snat
    }
    translate-address enabled
    translate-port enabled
}
ltm profile client-ssl my_clientssl_fwdp {
    app-service none
    cert-key-chain {
        default {
            cert default.crt
            key default.key
        }
        ubuntu2004server1ca.f5ss_1 {
            cert ubuntu2004server1ca.f5ss.local
            key ubuntu2004server1ca.f5ss.local
            usage CA
        }
    }
    defaults-from clientssl
    inherit-ca-certkeychain false
    inherit-certkeychain true
    ssl-forward-proxy enabled
    ssl-forward-proxy-bypass enabled
}
ltm profile server-ssl my_serverssl_fwdp {
    app-service none
    defaults-from serverssl
    revoked-cert-status-response-control ignore
    ssl-forward-proxy enabled
    ssl-forward-proxy-bypass enabled
}
ltm rule ssl-test-rule {
   when CLIENTSSL_SERVERHELLO_SEND {
      log local0. "MYDEBUG: CONNECTION: [IP::client_addr]:[TCP::client_port] to [IP::local_addr]:[TCP::local_port]"
      log local0. "MYDEBUG: TMM: TMM is [TMM::cmp_unit]"
   }
}

    Recommended Actions

    Make sure SSL Forward Proxy Bypass is enabled on client-ssl profile and server-ssl profile.
