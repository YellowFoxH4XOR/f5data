Known Issue

Windows 10 users may be unable to establish a remote desktop.

This issue occurs when all of the following conditions are met:

  • Your BIG-IP APM system is configured for Microsoft Remote Desktop Gateway Services.
  • The Windows user is running Windows 1703 (Creators Update).
  • The Windows user attempts to establish a remote desktop.

Impact

The user is unable to establish an access session to the BIG-IP APM access profile.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When the system attempts to establish a remote desktop access session, authentication fails.
  • When you analyze the network-level communication between the user client and the BIG-IP APM remote desktop virtual server, you observe that the user's authentication request is sent as a Negotiate HTTP authentication scheme.

Workaround

To work around this issue, you can add a custom iRule to the affected BIG-IP APM virtual server to ensure that the connecting user device uses NTLM authentication. To implement the iRule, perform the following procedure:

Impact of workaround:  F5 recommends that you perform the following procedure during a scheduled maintenance window.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules > Create.
  3. In the Name box, type a name for the iRule.

    For example:

    rdg_ntlm_required

  4. In the Definition box, enter the following text:

    when HTTP_REQUEST {
        set is_rdg_request [expr { [HTTP::method] starts_with "RDG_" }]
        if {!$is_rdg_request} { return; }
        set auth [HTTP::header Authorization]
        set is_nego_auth [expr { $auth contains "Negotiate" }]
        if { $is_nego_auth } {
            set auth [string map {"Negotiate" "NTLM"} $auth]
            HTTP::header replace Authorization $auth
        }
    }
    when HTTP_RESPONSE_RELEASE {
        if {!$is_rdg_request || !$is_nego_auth} { return; }
        catch {
            set auth [HTTP::header WWW-Authenticate]
            if { $auth contains "NTLM" } {
                set auth [string map {"NTLM" "Negotiate"} $auth]
                HTTP::header replace WWW-Authenticate $auth
            }
        }
    }

  5. Click Finished.
  6. Click Virtual Servers.
  7. Click the name of the virtual server that is affected by this issue.
  8. Click Resources.
  9. Under iRules, click Manage.
  10. In the Available list, click the iRule you previously created and move it to the Enabled list.
  11. Click Finished.
