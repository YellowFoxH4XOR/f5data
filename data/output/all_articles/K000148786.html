K000148786: Latest cache-fm-Modern.js file for Portal Access

Type
Support Solution
Published
2024-12-04
Updated
2026-10-29
Applies to
  • BIG-IP
  • BIG-IP APM: 17.X.X, 17.1.X, 17.1.1, 17.1.0, 17.0.X, 17.0.0
Source
https://my.f5.com/manage/s/article/K000148786

Description

When an application is rewritten in Modern mode (configured with the Rewrite Control List, K000130439), the BIG-IP system sends the browser-side rewriter file cache-fm-Modern.js to the browser. F5 Support sometimes provides an updated version of this file with fixes for rewrite issues, before those fixes are included in a BIG-IP release.

This article provides the most recent version of the file. You can use it with an iFile and an iRule on the Portal Access virtual server.

Important: F5 recommends that you first upgrade to the latest maintenance release of a supported BIG-IP version, which may already include the fix. Use this file if the issue remains.

Environment

  • BIG-IP APM 17.1.x, 17.5.x, or 21.1.x

  • Portal Access resource

  • The application is configured for Modern mode in the Rewrite Control List of the rewrite profile, and still does not work as expected

Cause

The application may be affected by a known rewrite issue in the cache-fm-Modern.js file of the installed BIG-IP version. The latest version of the file may resolve it.

Answer/Recommended Actions

Impact of procedure: The iRule replaces cache-fm-Modern.js for every Portal Access application on the virtual server. Test with the application before you use it in production.

Note: The file in this article is derived from BIG-IP 21.1.x and is backward compatible with earlier versions.

  1. Download the following file: Latest-cache-fm-Modern.txt

  2. Import the file to the BIG-IP system:

    1. Go to System > File Management > iFile List, and click Import.

    2. For File Name, browse to the downloaded Latest-cache-fm-Modern.txt file.

    3. For Name, enter file-cachefm.

    4. Click Import.

  3. Create the iRule iFile object:

    1. Go to Local Traffic > iRules > iFile List, and click Create.

    2. For Name, enter LatestModernCachefm.

    3. For File Name, select file-cachefm.

    4. Click Finished.

  4. Create the following iRule, and add it to the Portal Access virtual server:

    # This iRule is from MyF5 article K000148786
    when CLIENT_ACCEPTED {
        ACCESS::restrict_irule_events disable
    }
    when HTTP_REQUEST {
        if { [HTTP::has_responded] } { return }
        if { [HTTP::path] ends_with "cache-fm-Modern.js" } {
            HTTP::respond 200 content [ifile get LatestModernCachefm] "Content-Type" "application/javascript" "Cache-Control" "max-age=3600"
            return
        }
    }

  5. Clear the browser cache, and test the application.

To back out of this procedure, remove the iRule from the virtual server.

If the issue persists, open a support case and provide the data listed in the Collect HTTPWatch or HAR files for support section of K14184: Troubleshooting BIG-IP APM Portal Access applications. Keep the iRule on the virtual server while you collect the data.
