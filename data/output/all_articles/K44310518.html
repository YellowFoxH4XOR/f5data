Description

BIG-IP resets traffic that matches a disabled virtual server instead of continuing to a less specific virtual server. The reset may occur before completion of the client-side TCP handshake and can appear in a packet capture as:

F5RST: VIP disabled (administrative)

This behavior can affect BIG-IP APM Portal Access and VPN traffic when rewritten application requests match a disabled HTTPS SSO virtual server with a broad destination mask.

Environment

  • BIG-IP virtual servers with overlapping destination ranges or addresses

  • Virtual servers configured with different matching precedence

  • BIG-IP APM Portal Access or VPN traffic using rewritten application requests

  • A disabled virtual server with a broad destination mask

Cause

When tm.continuematching is set to false, BIG-IP does not continue matching less specific virtual servers after traffic matches a more specific virtual server that is disabled. The connection is reset with VIP disabled (administrative) instead of being processed by another matching virtual server.

Recommended Actions

  • If less specific virtual servers must process traffic when a more specific virtual server is disabled or unavailable, set tm.continuematching to true


    • tmsh modify sys db tm.continuematching value true

  • Save the configuration:

    tmsh save /sys config

Retest the affected traffic and verify that it is handled by the intended virtual server and that VIP disabled (administrative) resets no longer occur.

  • To restore the default behavior:

    • tmsh modify sys db tm.continuematching value false

  • To verify the current setting:

    • tmsh list sys db tm.continuematching 

Additional Information

  • Changing tm.continuematching can produce unintended traffic patterns and is not generally recommended. Test the change during a maintenance window.

    When virtual servers use overlapping IP addresses, ports, or destination ranges, compare the relevant system database variable values between BIG-IP environments.
