K000139083: F5OS-A Error starting VirtualMachine - Flannel upgrade check failed repeatedly - kube-flannel pod not running

Type
Support Solution
Published
2024-03-28
Updated
2024-05-09
Applies to
  • F5OS
  • F5OS-A: 1.7.X, 1.7.0
Source
https://my.f5.com/manage/s/article/K000139083

Description

Unable to deploy a tenant on rSeries r5k or above:

Error starting VirtualMachine the server is currently unable to handle the request

Entries in /var/F5/system/log/platform.log indicate that appliance-orchestration-manager is repeatedly attempting to install Flannel, and failing:

appliance-1 appliance-orchestration-manager[8]: priority="Err" version=1.0 msgid=0x6705000000000001 msg="ERROR: Failed to install CNI plugin." CNI="Flannel upgrade check failed:" ERROR=256 REF_LOG="/var/log/flannel-install.log".
appliance-1 appliance-orchestration-manager[8]: priority="Err" version=1.0 msgid=0x6705000000000004 msg="Error: Failure during CNI installation process." STEP="Flannel install" ERROR=256.

These messages will be repeating continuously.

In addition, the /var/log/flannel-uninstall.log file indicates that an Ansible playbook is being repeatedly run to uninstall Flannel. The /var/log/flannel-install.log file contains no recent or useful entries.

The kube-flannel pod is not listed in the output of kubectl get pods -A.

Re-installing k3s does not resolve this issue.

Environment

  • F5OS-A
  • Flannel install
  • After upgrade or reboot

Cause

This problem occurs if Appliance Orchestration Manager's Flannel upgrade check fails. This will fail if /var/log/appliance.log is a directory, not a regular file.

When this issue happens, messages similar to the following will repeat in /var/log/messages:

appliance-1 omd_container.sh: /tmp/appliance-flannel-image.env
appliance-1 omd_container.sh: /usr/share/omd/check-for-update-module.sh: line 18: /var/log/appliance.log: Is a directory
appliance-1 omd_container.sh: return value is localhost:2001/appliance-flannel:0.13.1
appliance-1 omd_container.sh: /usr/share/omd/check-for-update-module.sh: line 45: /var/log/appliance.log: Is a directory
appliance-1 omd_container.sh: /usr/share/omd/cni/check-cni-upgrade.sh: line 31: /var/log/appliance.log: Is a directory
appliance-1 omd_container.sh: export appliance_flannel_image=localhost:2001/appliance-flannel:0.13.1
appliance-1 omd_container.sh: /usr/share/omd/cni/check-cni-upgrade.sh: line 37: /var/log/appliance.log: Is a directory
appliance-1 omd_container.sh: /usr/share/omd/cni/check-cni-upgrade.sh: line 42: /var/log/appliance.log: Is a directory

Appliance Orchestration Manager will then attempt to uninstall Flannel.

/var/log/appliance.log should be a regular file.

Recommended Actions

You can check if /var/log/appliance.log is a regular file or directory with the stat command:

stat /var/log/appliance.log

To recover from this issue, delete the /var/log/appliance.log directory:

rm -rfv /var/log/appliance.log

Then re-install k3s:

1. Set tenants to Configured state

2. Stop Appliance Orchestration Manager

    systemctl stop appliance_orchestration_manager_container

3. Uninstall k3s

    k3s-uninstall.sh
    rm /var/omd/* /tmp/omd/tokens/* /tmp/omd/appliance-ansible-host

4. Start Appliance Orchestration Manager again to trigger the k3s install

    (touch /tmp/omd/skip; sleep 1m; rm -f /tmp/omd/skip)&
    systemctl start appliance_orchestration_manager_container

5. Wait ~15 minutes for the install to complete.

   You can monitor the status with:

    tail -F /var/log/*-install.log

6. Check that the pods are running:

    kubectl get pods -A

There should be ~16 pods, including a flannel pod.

Additional Information

There may be other conditions that cause a Flannel install to fail. If your rSeries system is exhibiting these symptoms and /var/log/appliance.log is not a directory, further investigation is required.
