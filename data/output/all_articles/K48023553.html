Description

Troubleshooting FQDN dynamic updates for auto-populating pool members and nodes by enabling dynconfd debug level logging.

Environment

The FQDN (fully-qualified domain name) pool members and nodes in use

Cause

In situations where there is a need to troubleshoot dynamic DNS resolution updates for auto-populating FQDN pool members and nodes, one may enable dynconfd debug level logging. 

Recommended ActionsEnable dynconfd daemon debug level logging

Impact of procedure: Depending on the debug level set, a BIG-IP system may experience disk space issues or a performance degradation if the BIG-IP system is overloaded and processes a huge amount of debug data to the /var/log/dyconfd.log file.

Note: When dynconfd debugging is enabled a new log file is created and written to /var/log/dynconfd.log. FQDN dynamic debug level updates are no longer logged and written to /var/log/dynconfd.log when disabling dynconfd debug level logging. General status of nodes, pools, and pool members can still be found in the /var/log/ltm file.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command: 
    tmsh
  2. To configure the BIG-IP system to log FQDN debug dynamic updates, one must set a debug level for the dynconfd.loglevel BigDB database key by typing the following command:modify sys db dynconfd.loglevel value debug_msgvalue-range: "debug, debug_msg, deep_debug, error, info, none"

Disable dynconfd daemon debug level logging

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:
    tmsh
  2. To configure the BIG-IP system to restore back the default logging value of error for the dynconfd daemon, one must set the dynconfd.loglevel BigDB database key by typing the following command:
    modify sys db dynconfd.loglevel reset-to-default

Additional Information

  • In versions prior to to BIG-IP 13.1.0 the DNS Resolution of FQDN Nodes and Pool Members are handled by the bigd process (FQDNv1). In release v13.1.0 the FQDNv2 implementation was first introduced adding a new dynconfd daemon for managing DNS resolution for FQDN Nodes and Pool Members. The dynconfd daemon FQDNv2 implementation was also "back-ported" and released in BIG-IP v12.1.3.3. 
  • The dynconfd daemon (to perform DNS resolution) manages a list of DNS servers (resolvers) as part of the FQDNv2 implementation of the BIG-IP LTM monitors. The implementation permits users to configure node and pool-member instances using a fully qualified domain name (FQDN), in which IP addresses are resolved through a lookup to a DNS server.
