Topic

Summary

The BIG-IP ASM system may prevent object caching by a Web Acceleration profile.

Description

To cache commonly requested objects and decrease response time for clients, you can apply a Web Acceleration profile to a virtual server that has BIG-IP ASM enabled. To prevent caching malicious content, you should cache only content that complies with the BIG-IP ASM security policy and is considered safe.

When both Web Acceleration and Application Security are enabled for a particular web application, the BIG-IP ASM system may need to prevent the system from caching certain content. For example, the BIG-IP ASM system prevents caching if any of the following traffic conditions are present:

  • Policy Builder is running and the policy is unstable.
  • A violation or learning suggestion is generated.
  • Frame cookies are either created or removed due to, for instance, dynamic parameter extraction.
  • The system processes a request that triggers tightening suggestions (file types, URLs, or parameters).
  • The system processes requests for pages that have extractions configured (including pages with dynamic sessions).
  • The system processes requests for pages that are within a Flow Access (including URLs imbedded in the cookie and logout URLs).

Note: Even if the learning mode is disabled, make sure Learn New Objects isn't set to compact, as this will cause the enforcer to generate a tightening suggestion, which causes ASM to prevent object caching. 

If any of these conditions are present, the BIG-IP ASM system inserts a cache directive into the traffic to prevent caching for that response. Depending on the caching mechanism in use, you may see a different cache directive.

If the system is using either a BIG-IP Web Acceleration profile with no enabled Web Acceleration application for caching, the BIG-IP ASM system inserts the following Tcl command to signal no caching:

CACHE::disable

If the system is using either the BIG-IP WebAccelerator system or the BIG-IP AAM system for caching, the BIG-IP ASM system inserts the following HTTP header to prevent caching:

Surrogate-Control: content="ESI/1.0",no-store

Recommendations

When enabling caching on the BIG-IP ASM system, you should apply the Web Acceleration profile to the BIG-IP ASM-enabled virtual server only after the BIG-IP ASM security policy is stable. Note: Subsequent modifications to the BIG-IP ASM security policy will clear the cached objects.
