Known Issue

If you apply a fallback persistence profile with a custom timeout other than the default 180 seconds, modify the timeout of an existing fallback persistence profile, or replace a fallback persistence profile with one configured to use a different timeout, the new timeout may not be honored until TMM is restarted.

In addition, if you have applied different fallback persistence profiles to multiple virtual servers, all associated persistence records will honor the same timeout, which includes either the default 180-second timeout, or the timeout value configured in the first-loaded fallback persistence profile. This condition persists even if TMM is restarted.

Note: A fallback persistence profile is a persistence profile that has been selected as the Fallback Persistence Profile in the properties of at least one virtual server.

F5 Product Development tracked this issue as ID 227308 (formerly CR90975) and it was fixed in BIG-IP 11.4.0. For information about upgrading, refer to the BIG-IP release notes.

Workaround

If you have configured only one fallback persistence profile and you want to change its timeout value, you can do so by restarting TMM after modifying the fallback persistence profile. Type the following command at the BIG-IP command line:

bigstart restart tmm

Note: Multiple fallback persistence timeouts will still not be honored after restarting TMM.
