Description

When a user attempts to log on to a virtual server with an access policy using an external logon page, they cannot log in successfully.

  • User accesses the virtual server, and the logon page is displayed. After entering the credentials, the logon page is displayed again.
  • APM log message shows the session is deleted:

    Sep 22 11:58:20 BIGIP notice tmm[12282]: 01490567:5: /Common/ACCESS_PROFILE_NAME:Common:1234abcd: Session deleted (restarted).

Environment

  • External Logon Page agent specified in the Access Policy

Cause

When using an External Logon Page Agent, the server hosting the external logon page must be configured so that the user credentials are POSTed to /my.policy.

If the user credentials are POSTed to /, the session will be invalidated and the user agent will be redirected to /my.policy with a new session id.

Recommended Actions

Ensure the server hosting the external logon page is configured to post the user's credentials to Virtual server using the URI /my.policy.
