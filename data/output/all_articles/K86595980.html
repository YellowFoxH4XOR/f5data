Description

When performing SNMP polling, the BIG-IP system is very slow to respond.

In some cases, logs similar to the following may be observed:

warning snmpd[9108]: 010e0004:4: MCPD query response exceeding 120 seconds.

Environment

  • SNMP
  • Large configuration

Cause

The system is being polled very aggressively from multiple SNMP managers, with many requests per second.

Recommended Actions

Adjust the polling interval and polling patterns of your SNMP management software. There are different schools of thought on how often you need to poll for status. For example, a five minute polling interval for status (e.g. up/down/warning) is considered standard, while some products use a default of two minutes. Refer to your SNMP vendor documentation for information about recommended SNMP polling patterns.

Additional Information

When the snmpd process receives a poll, it has to ask mcpd for data before it can send a response, and mcpd has to retrieve this data from its databases, which can sometimes be very large. If mcpd cannot process a huge amount of queries, it won't be able to send a timely response to snmpd, there will be a significant delay in responses to the SNMP manager, and in some cases snmpd or even mcpd can core (which would cause a failover).
