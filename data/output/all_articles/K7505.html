Issue

The Configuration utility reports an error message when all of the following conditions are met:
  • LB_ events are used in conjunction with HTTP::methods within an iRule
  • The iRule is associated with a virtual server using both a TCP profile and an HTTP profile
  • The iRule is assigned to a virtual server or the iRule is modified after it has been assigned to the virtual server

    The error message appears similar to the following example:

    01070394:3: HTTP::<method name>in rule xxxx requires an associated FastHTTP profile on the virtual server yyyy

    Note: The xxxx and yyyy place holders represent the names of the iRule and the virtual server, respectively. The <method name> is the name of the HTTP method you specified, such as uri or header.

    This error message is a result of the system incorrectly validating the HTTP events and LB methods with the HTTP profile.

    For example, the following iRule produces an error message:

    when LB_FAILED { HTTP::fallback "http://www.f5.com[HTTP::uri]" }

    However, when the following iRule is used instead, the system correctly validates, loads, and allows the virtual server to use the iRule:

    when HTTP_REQUEST { set uri [HTTP::uri] } when LB_FAILED { HTTP::fallback "http://www.f5.com$uri" }

    F5 Product Development tracked this issue as CR49352 and it was fixed in BIG-IP LTM version 9.2.0. For information about upgrading, refer to the BIG-IP LTM release notes.
