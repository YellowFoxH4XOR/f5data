Known Issue

This is the result of a known issue. When browsing web pages on a Microsoft Internet Information Server (IIS) using either Dynamic Application Tunnels or Web Application Tunnels, the server returns a 401 status code (401.2 extended code) and a message that appears similar to the following example appears in the browser:

You are not authorized to view this page

Typically, an authentication pop-up box would appear for the user to enter logon credentials.

This issue occurs when the IIS server is configured to perform both Kerberos-based authentication and NTLM-based authentication over HTTP, and you then request a page that is protected by authentication. In a packet trace of the HTTP connection, such a configuration can be seen in the HTTP header of the 401 response, which contains the following fields:

WWW-Authenticate: Negotiate
WWW-Authenticate: NTLM

Instead of presenting the authentication pop-up box and then resending the web page request with credentials, the browser displays the aforementioned error message and does not resend the request for the web page.

F5 Product Development tracked this issue as CR67651 and it was fixed in FirePass version 6.0.1. For information about upgrading, refer to the FirePass release notes.

Workaround

To work around this issue, you can configure a Static Application Tunnel instead of a Dynamic Application Tunnel or Web Application Tunnel.
