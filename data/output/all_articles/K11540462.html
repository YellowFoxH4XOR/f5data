Description

Incorrect syslog-ng syntax prevents the BIG-IP configuration from loading after an upgrade.

  • After an upgrade, the Configuration utility displays a message that appears similar to the following example:
    The configuration has not yet loaded. If this message persists, it may indicate a configuration problem.
  • The system logs messages to the /var/log/ltm file similar to the following example:
    01070920:3: Application error for confpp: Error parsing filter expression, Unknown priority level"critical" in /etc/syslog-ng/syslog-ng.conf at line 1440, column 19:

Environment

  • The syslog-ng configuration use the include field
  • The system is upgraded
  • Configuration load errors after upgrade

Cause
The BIG-IP system has a syslog-ng configuration with invalid syntax.
Important: In the following example, note that the level "critical" is not a valid configuration value. The correct value should be "crit".

For example:
The following syslog-ng configuration has a bad syntax in the include statement:

sys syslog {
    include "
        filter f_remote_loghost {
            level(critical..emerg);       <————————————
        };
        destination d_remote_loghost {
            udp(\"10.10.10.2\" port(514));
            udp(\"10.40.0.254\" port(514));
        };
        log {
            source(s_syslog_pipe);
            filter(f_remote_loghost);
            destination(d_remote_loghost);
        };"
    remote-servers {
        /Common/remotesyslog1 {
            host 10.1.2.3
        }
    }
}

Recommended Actions
To fix this you should follow the procedures listed below:

  • Boot the system to the previous software image
  • Modify the Syslog configuration
  • Delete the boot location where you attempt to upgrade
  • Perform the upgrade

Boot the system to the previous software image
  1. Log in to the Configuration utility with administrative privileges.
  2. Go to System > Software Management > Boot Locations.
  3. Select the Boot Location for the previous software version.
  4. Select Activate.
  5. To close the confirmation message, select OK.
Modify the Syslog configuration
  1. Log in to the TMOS Shell (tmsh).
  2. To modify the syslog filter configuration, enter the following command:

    edit /sys syslog all-properties

    The syslog configuration opens in the vi text editor and appears similar to the following example:

    modify syslog {
        auth-priv-from notice
        auth-priv-to emerg
        clustered-host-slot enabled
        clustered-message-slot disabled
        console-log enabled
        cron-from warning
        cron-to emerg
        daemon-from notice
        daemon-to emerg
        description none
        include "
            filter f_remote_loghost {
                level(critical..emerg);
            };
            destination d_remote_loghost {
                udp(\"10.254.0.249\" port(514));
                udp(\"10.40.0.254\" port(514));
            };
            log {
                source(s_syslog_pipe);
                filter(f_remote_loghost);
                destination(d_remote_loghost);
            };"
        iso-date disabled
        kern-from debug
        kern-to emerg
        local6-from notice
        local6-to emerg
        mail-from notice
        mail-to emerg
        messages-from notice
        messages-to warning
        remote-servers replace-all-with {
            remotesyslog1 {
                description none
                host 108.179.255.232
                local-ip none
                remote-port 514
            }
        }
        user-log-from notice
        user-log-to emerg
    }

  3. Locate and correct the syntax error
  4. Exit the text editor by entering the following key sequence:
    :wq!
  5. At the following prompt, press y to save the changes to the file:

    Save changes? (y/n/e)

    The tmsh prompt returns.

    Note: If the syslog filter contained syntax errors, tmsh returns the following prompt:
    There were errors. Continue editing (y) or discard changes (n) (y/n)

  6. Save the change by entering the following command:
    save sys config

Delete the boot location where you attempt to upgrade

  1. Log in to the Configuration utility.
  2. Go to System > Software Management > Image List.
  3. In the Installed Images section, select the logical disk name listed in the Disk column of the failed upgrade to delete.
    For example, HD1
  4. In the Contained Software Volumes section, select the check box for the volume that you want to delete.
    Note: If the selected volume also has an associated application volume, such as a MySQL database, the associated application volume will also be deleted automatically so you do not have to select it.
  5. Click Delete.
  6. Confirm deletion by clicking Delete.
    After the system finishes deleting the selected volume, the Configuration utility displays the following banner message:
    The system must be rebooted for some changes to take effect.
  7. Go to System > Configuration > Device > General.
  8. Select Reboot.
  9. To confirm you want to reboot the device, select OK.

Perform the upgrade
For more information on performing a BIG-IP system upgrade refer to:  K84554955: Overview of BIG-IP system software upgrades
