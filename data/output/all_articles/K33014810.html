Known Issue

An HTTP 302 redirect response may trigger cross-site request forgery (CSRF) attack detection.

This issue occurs when all of the following conditions are met:

  • The BIG-IP ASM application security policy is configured with CSRF detection enabled.
  • The HTTP 302 redirect response includes a Location field that does not contain a full URL path specified in the CSRF URL List configuration.

Impact

Access to the redirect destination triggers CSRF detection.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When analyzing the HTTP protocol communication of the request, the Location field references a URL that does not include the server path.

    For example:

    Accept-Encoding    gzip, deflate
    Accept-Language    en-US
    Cache-Control    no-cache
    Connection    Keep-Alive
    Content-Length    58
    Content-Type    application/x-www-form-urlencoded
    Cookie    <server cookie>=<cookie value>; 
    TS01f1169d=<asm cookie value>; 
    TS0188cadd=<asm cookie value>; 
    TS0177adbe=<asm cookie value>; 
    TS01b9b94e=<asm cookie value>; 
    TS01c0650e=<asm cookie value>; 
    TS01c0650e_28=<asm cookie value>
    Host    www.example.com
    Referer    https://www.example.com/<path>/application.asp
    User-Agent    Mozilla/5.0 (Windows NT 6.1; WOW64; Trident/7.0; rv:11.0) like Gecko


    BIG-IP ASM virtual server response to the user

    HTTP/1.1 302 Object moved
    Cache-Control    private
    Content-Length    182

    Note: The user request to the referenced redirect location includes the server path. However, the request does not include the BIG-IP ASM CSRF token, which triggers the CSRF attack detection.
     
  • The system logs a message to the /var/log/asm file that appears similar to the following example:
