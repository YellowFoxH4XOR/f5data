Known Issue

This is the result of a known issue. A qkview or tcpdump output file created using the Configuration utility is not automatically removed.

When a qkview or tcpdump is generated via the System >> Support section of the Configuration utility, a file is created on the memory file system for the user to download. This file should be automatically removed after 30 minutes. However, in some cases the process responsible for removing the file does not operate correctly and the qkview or tcpdump output file may remain on the memory file system until manually removed.

When this situation occurs, error messages that appear similar to the following example are logged to the /var/log/tomcat/catalina.out file:

com.f5.tmui.util.Syscall$CallException: No Access
at com.f5.tmui.util.Syscall.call(Unknown Source)
at com.f5.tmui.util.Syscall.call(Unknown Source)
at com.f5.tmui.system.handler.support.timers.CleanupTimer$CleanupTask.run(Unknown Source)
at java.util.TimerThread.mainLoop(Unknown Source)
at java.util.TimerThread.run(Unknown Source)

The previous error messages may be logged at 30 minute intervals until the qkview or tcpdump output file is removed from the System > Support section of the Configuration utility.

This issue is benign.

F5 Product Development tracked this issue as ID 225265 (formerly CR138924) and it was fixed in BIG-IP 11.0.0. For information about upgrading, refer to the BIG-IP LTM, ASM, GTM, PSM, Link Controller, WebAccelerator, APM, WOM, or Edge Gateway release notes.

In addition, BIG-IP iHealth may list Heuristic H757803 on the Diagnostics > Identified > Low screen.

Workaround

To manually remove an old qkview or tcpdump output file, navigate to System > Support and click Delete.

Note: If you require submitting a qkview or tcpdump output file to F5 Technical Support, ensure that the file you are about to download from the Configuration utility is not an old file. Submitting an old file to F5 Technical Support can cause delays in the resolution of an issue.
