Description

The HTTP::proxy chain iRule command sends a CONNECT method to a downstream outgoing internet proxy.

However, this command can only be used in the context of a HTTP profile and HTTP events.

 

It is sometimes useful to be able to forward a (non-HTTP) TCP or non-terminated TLS connection via the outgoing internet proxy using a CONNECT method.

 

Environment

  • BIG-IP LTM
  • HTTP Proxy
  • iRules

 

Cause

iRule validation prevents the use of "HTTP::proxy chain" for non-HTTP use cases

 

Recommended Actions

Use the TCL eval command to bypass HTTP::proxy chain context validation.

The following allows the TCP connection to be forwarded by the downstream proxy to destination.server.net:443

 

when CLIENT_ACCEPTED {
  set target_proxy {HTTP::proxy chain host destination.server.net 443}
  eval $target_proxy
  HTTP::disable
}

 

Additional Information

Other iRule events where this technique may be applied include:

  • CLIENTSSL_CLIENTHELLO
  • CLIENT_DATA

In both these events it may be possible to extract a connection destination that can be used in the HTTP::proxy chain command.
