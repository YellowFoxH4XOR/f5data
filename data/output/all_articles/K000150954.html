Description

Implementing security hardening on F5 BIG-IP systems may involve disabling the root account and using an administrative account with advanced shell (bash) access for critical administrative tasks.

This article explains about whether such an admin account can serve as a secure "break-glass" (emergency access) account and what best practices should be followed to ensure compliance and operational readiness. 

 

Environment

  • F5 BIG-IP LTM
  • Configuration Details: 
  • Root account disabled
  • Admin account with advanced shell (bash) access enabled
  • Security hardening measures applied

 

Cause

Security compliance requirements and hardening policies often require disabling direct root access. Organizations therefore need an alternative secure method for emergency administrative access—commonly referred to as a "break-glass" account.

 

Recommended Actions

Break-Glass Account Configuration

  • An admin account with advanced shell (bash) access can function as a break-glass account if managed securely.
  • Restrict access strictly to authorized personnel.
  • Store credentials in a secure password vault or hardware security module, ensuring monitoring and audit trails are in place.
  • Enable detailed logging and monitoring of all activities performed by this account.
  • Periodically test the break-glass process to ensure functionality, and document procedures for authorized users.

F5 Best Practices

  • Limit or disable root usage; use administrative accounts with controlled permissions instead.
  • Assign advanced shell (bash) rights only where necessary for critical recovery or troubleshooting tasks.
  • Enforce strong password policies (complexity, rotation schedules, minimum length).
  • Apply role-based access controls (RBAC) so the admin/break-glass account has only essential privileges.
  • Centralize logs using syslog or SIEM solutions for auditing and compliance tracking.
  • Implement multi-factor authentication (MFA) for additional protection of privileged accounts.
  • Reserve the break-glass/admin account exclusively for emergencies—not routine administration.
  • Regularly back up configurations and verify that emergency accounts function during failover scenarios in HA/clustered environments.

Documentation & Testing

  • Maintain clear documentation of emergency procedures; store securely but make accessible to authorized staff when needed.
  • Test break-glass/emergency processes regularly (e.g., quarterly or during maintenance windows).
  • Confirm operability across all devices in clustered/high availability deployments.
