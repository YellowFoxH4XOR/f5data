K33521110: Azure-hosted BIG-IP crashed and lost its configuration

Type
Support Solution
Published
2021-09-17
Updated
2025-02-06
Applies to
  • Public Cloud
  • BIG-IP
  • Microsoft Azure
Source
https://my.f5.com/manage/s/article/K33521110

Description

The Azure-hosted BIG-IP system crashed and came back up without any configuration files.

  • /var/log/kern.log:
    Aug 19 10:02:42 bigiphostname.com debug kernel: mlx4_en: f5slave1: Close port called
    Aug 19 10:02:42 bigiphostname.com info kernel: hv_netvsc 0022481c-93ce-0022-481c-93ce0022481c eth1: Data path switched from VF: f5slave1
    Aug 19 10:02:42 bigiphostname.com info kernel: hv_netvsc 0022481c-93ce-0022-481c-93ce0022481c eth1: VF unregistering: f5slave1
    Aug 19 10:02:43 bigiphostname.com warning kernel: mlx4_core 0002:00:02.0: Failed to release qp range base:0 cnt:0
    2021-08-19T10:05:18+00:00 bigiphostname notice boot_marker : ---===[ HD1.1 - BIG-IP 15.1.2.1 Build 0.0.10 ]===---
    Aug 19 10:05:06 bigiphostname info kernel: Command line: ro root=UUID=4btf4545-ccdr-1234-4321-h6f2t832cba1 console=ttyS0 console=tty0 panic=1 platform=Z100 default_cpu_order quiet
  • Configuration files may be missing, after the system attempts to boot, following the crash.
  • Azure logs indicate "GuestOSCrash"

Environment

  • BIG-IP Virtual Edition, running in Microsoft Azure Cloud environment
  • Accelerated Networking is enabled on the virtual interfaces

Cause

Bug ID 948417: Network Management Agent (Azure NMAgent) updates causes Kernel Panic

Recommended Actions

  1. Workaround: Disable Accelerated Networking on BIG-IP network interfaces (Reversed settings from Azure documentation)
  2. Upgrade to a Fixed Version.
