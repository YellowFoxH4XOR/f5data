K99462468: BIG-IP with highest number assigned management IP address get to be active in a HA cluster

Type
Support Solution
Published
2023-02-01
Updated
2023-02-01
Applies to
  • BIG-IP Platforms
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K99462468

Description

Failover occurs in a High Availability cluster

  • Device which may have been active becomes standby
  • Device which may have been standby but has highest dotted decimal value of IP address becomes active

Environment

High Availability cluster with following possible configurations

  • HA failover traffic configured on management interfaces only
  • HA failover traffic configured on tmm interfaces only
  • HA failover traffic configured on both management and tmm interfaces

Cause

  • Failover traffic interrupted over 3 seconds for devices with HA traffic only defined over the management interface.
  • Failover traffic interrupted over 3 seconds for devices with HA traffic only defined over a tmm interface.
  • Failover traffic is interrupted over 3 seconds for both management and tmm.
  • Both devices have been rebooted at the same time.


Note: This is is expected behaviour.
This occurs when devices in a cluster fail to see each other over 3 seconds. Both or all devices become active such that when the network is restored  both or all have the same "Load Aware" or "Group Score". To break the tie a static score calculated using the value of the management IP address is used. This results in the device with the highest last octet of management IP address becoming active.

Recommended Actions

Ensure to configure network failover redundancy by adding both the management IP address(es) and tmm IP addresses. Follow article K14135 for all platforms including BIGIP VE or Cloud or K37361453 for Vipirion systems.
