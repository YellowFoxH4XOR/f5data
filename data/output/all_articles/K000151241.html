Description

A NAP WAF Policy/APPolicy, that implements a user-defined web browser exception, results in requests, that contain said defined web browser, being rejected/blocked by said policy.

Example use case:

  - A policy with a browser definition, matchString: ExampleBrowser
  - That browser definition is configured to be detected (not blocked)
  - A request with a User-Agent that contains ExampleBrowser is blocked.

Example NAP WAF policy (YAML format for implementation in NIC):

Environment

NGINX App Protect (NAP) WAF

Cause

You can see from the above event message that the bot signature DBrowse was detected for the request, bot_signature_name=DBrowse, and as a result a blocking violation was raised. The browser-definition only takes effect after bot signatures are evaluated. I.e., if a bot signature is detected and a blocking violation is raised then that request will be blocked. Refer to NGINX App Protect WAF Configuration Guide.

If the received request has no bot signatures or the bot signature is ignored, then the following enforcement occurs:
  1. Parse the User-Agent header. If a known browser is identified, then enforce based on the action set in the browser subsection of the classes section.
  2. If no factory or user-defined browser is identified, then enforce based on the action set in the unknown subsection of the classes section.
  3. If both factory and user-defined browser were detected, then the user-defined one takes precedence and its action is executed according to point 1.
  4. If more than one user-defined browser was detected, then the most severe action of the detected browsers is taken. 



Recommended Actions


To mitigate the blocked request, disable/ignore the detected bot signature (DBrowse in this example). Refer to NGINX App Protect WAF Configuration Guide. Below is the example policy with the unblocking mitigation (see comment at spec.policy.bot-defense.mitigations.signatures).


apiVersion: appprotect.f5.com/v1beta1
kind: APPolicy
metadata:
  name: dataguard-alarm
spec:
  policy:
    applicationLanguage: utf-8
    enforcementMode: blocking
    name: dataguard-alarm
    template:
      name: POLICY_TEMPLATE_NGINX_BASE
    browser-definitions:
      - name: example
        matchString: ExampleBrowser
    bot-defense:
      settings:
        isEnabled: true
      mitigations:
        classes:
          - name: browser
            action: detect
          - name: unknown
            action: alarm
        browsers:
          - name: example
            action: detect
        signatures:          <--- mitigation to unblock (REMOVE THIS COMMENT)
        - action: ignore

    blocking-settings:
