Known Issue

This is the result of a known issue. The big3dshim process does not drop path probes if the big3dshim process has not received any gateway probes within the last five minutes.

BIG-IP and 3-DNS 4.x versions are capable of sending two types of probes:

  • Gateway path probe
    This type of path probe determines the health of the gateway path.

  • Gateway probe
    This type of path probe determines whether the gateway is up or down.

This issue occurs when BIG-IP or 3-DNS version 4.x system is used with a BIG-IP version 9.x Link Controller, GTM, or LTM system, and the BIG-IP or 3-DNS version 4.x system is talking to a BIG-IP version 9.x Link Controller, GTM, or LTM system. When using a transparent monitor on a BIG-IP LTM gateway pool, the gateway path probe could report a successful status, while the gateway probe reports the gateway as down. The BIG-IP or 3-DNS version 4.x unit will report the link as up (green) even though the gateway itself is down (red).

The big3dshim process should drop the gateway path probe results if the big3dshim process has not received an update for the gateway probe to prevent this situation from occuring.

F5 Product Development tracked this issue as CR74194 and it was fixed in BIG-IP GTM 9.3 and 9.4.2. For information about upgrading, refer to the BIG-IP LTM, GTM, or Link Controller Release Notes.
