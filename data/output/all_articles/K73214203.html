K73214203: BIG-IQ not showing graphs due to max shards

Description

BIG-IQ is not showing graphs.

Further check shows that it has max shards. Running the following command shows the shards for each disk.
# curl -s localhost:9200/_cat/allocation?v
shards disk.indices disk.used disk.avail disk.total disk.percent host          ip            node
 19000        4.2gb     8.8gb     20.2gb     29.1gb           30 10.100.100.11 10.100.100.22 77777777-6666-qqqq-bbbb-aaaaaaaaaaaa
 17000        3.7gb     9.5gb     19.5gb     29.1gb           32 10.100.100.22 10.100.100.22 55555555-aaaa-3333-0000-bbbbbbbbbbbb
 13000        2.7gb     9.3gb     19.7gb     29.1gb           32 10.100.100.33 10.100.100.33 aaaaaaaa-cccc-4444-9999-cccccccccccc

A good rule-of-thumb is to ensure you keep the number of shards per node below 20 per GB heap it has configured. A node with a 30GB heap should therefore have a maximum of 600 shards, but the further below this limit you can keep it the better. This will generally help the cluster stay in good health.

As per the above example, 13,000 - 19,000 shards are too high as compared to the expected 600 shards.

Another way to view the shards is to run the following command:

Environment
  • BIG-IQ
  • No graphs on BIG-IQ
  • Max shards showing "over-sharding"

Cause

This is a common issue called “over-sharding”: too many shards were created in ElasticSearch for storing stats data which eventually lead to JAVA heap memory exhaustion.

Recommended Actions

You can use the following steps to remove the existing stats to recover the BIG-IQ cluster to a working status, then configure the stats retention settings to prevent "over-sharding" from happening again.

  1. To recover the cluster run the following commands on any of the 3 BIG-IQ DCDs (this will remove all real time stats indices in ElasticSearch)
    On BIG-IQ DCD:
    curl localhost:9200/stat*tl0* -X DELETE
    curl localhost:9200/events*tl0* -X DELETE
     
  2. You may need to run that command a couple of times until you get "acknowledge: true".
    Check the status of the cluster to confirm that the number of allocations was reduced.
    As per the example above, it currently have 13,000 to 19,000 shards per node. This number needs to be reduced.
    Run the following command to check the shards value (on BIG-IQ DCD):
    curl -s localhost:9200/_cat/allocation?v
     
  3. Restart ElasticSearch on BIG-IQ CM
    bigstart restart elasticsearch
     
  4. Run the command on both BIG-IQ CM and BIG-IQ DCD to confirm BIG-IQ CM has joined the cluster.
    curl -s localhost:9200/_cat/nodes?v
     
  5. Clear the appiq data to remove remaining stats.
    On BIG-IQ CM:
    clear-appiq-data
     
  6. While the above is running, you'll be ask to stop appiqagent on each BIG-IQ DCD
    bigstart stop appiqagent
     
  7. Once the process finishes, go back to the BIG-IQ WebGUI.
     
  8. Confirm that statistics collection is enabled and that the "last collected date" gets updated for some managed devices.
