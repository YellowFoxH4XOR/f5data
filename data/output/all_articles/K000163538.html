K000163538: Configuring zone-level forwarders to prevent global forwarding of local master-zone queries

Type
Support Solution
Published
2026-10-05
Updated
2026-10-05
Applies to
  • BIG-IP
  • BIG-IP DNS: 17.5.1
Source
https://my.f5.com/manage/s/article/K000163538

Description

With recursion enabled and global BIND forwarders configured on BIG-IP DNS, recursive queries for records in local master zones may be sent to remote nameservers instead of being resolved from local zone data. If the remote forwarder lacks the record or is unreachable, the client may receive NXDOMAIN, a timeout, or no response. Equivalent non-recursive queries may return the local record successfully.

Environment

  • BIG-IP DNS
  • BIND configured with recursion yes;
  • Global BIND forwarders configured
  • Local master zones containing the queried records

Cause

Global forwarding can apply to recursive queries when BIG-IP DNS does not consider itself authoritative for the exact queried name. The resolver then forwards the query to the configured remote nameserver instead of using or iterating through the local master-zone data.

Answer/Recommended Actions

Configure an empty forwarder list in each affected local master zone to prevent queries for that zone from using global forwarders:

zone "<affected-local-zone>" {

    type master;

    file "<local-zone-file>";

    forwarders {};

    allow-update { localhost; };

};

Use this zone-level setting when records must be resolved locally and must not be sent to global forwarders.

Apply the configuration to all affected master zones. Then:

  1. Verify resolution from an external client using both recursive and non-recursive DNS queries.
  2. Use packet capture or equivalent monitoring to confirm that queries for local records are no longer sent to remote forwarders.
  3. Review the global forwarder configuration before adding local zones, because recursive queries may otherwise be forwarded when the resolver is not authoritative for the queried name.

Additional Information

The empty forwarders {}; setting disables forwarder use for the affected zone, allowing the resolver to resolve locally or iterate. A non-recursive NS query may return NOERROR with the locally configured NS record, while the equivalent recursive NS query returns NXDOMAIN when global forwarding is applied.
