Known Issue

This is most likely the result of a known issue, which was introduced in BIG-IP 9.1.2 of the 9.1 branch, and version 9.2.2 of the 9.2 branch, as a result of a behavior change. After upgrading the BIG-IP system from version 9.0.x or version 9.1.x to version 9.1.2 of the BIG-IP 9.1 branch, or to version 9.2.2 of the BIG-IP 9.2 branch, traffic may not pass through the BIG-IP system, and the non-management interfaces may be non-responsive. Under these circumstances, the command line prompt indicates the status as INOPERATIVE, as displayed in the following example:

[root@bigip:INOPERATIVE] config #

Additionally, the following symptoms are exhibited:

  • The bigpipe load command does not report any errors when reloading the configuration.
  • The bigstart status tmm command indicates the TMM daemon status is running; however, a process list does not show the /bin/tmm process running, only the runsv tmm process, as shown in the following example output:
    [root@bigip:INOPERATIVE] config # bigpipe loadReading configuration from /config/bigip_base.conf.Reading configuration from /usr/bin/monitors/base_monitors.conf.Reading configuration from /config/profile_base.conf.Reading configuration from /config/bigip.conf.Loading the configuration ...[root@bigip:INOPERATIVE] config # bigstart status tmmtmm          run (pid 740) 2 minutes[root@bigip:INOPERATIVE] config # ps |grep tmm709  ttyS0 0:00 runsv tmm

Note: A similar behavior change was introduced in version 9.1.1 and version 9.2.2 that affected the bcm56xxd daemon. For more information on this issue, refer to K5872: BIG-IP does not pass traffic and non-management interfaces are non-responsive after upgrading BIG-IP to versions 9.1.1 or 9.2.2.

This issue can occur if the /etc/syslog-ng/syslog-ng.conf file was customized prior to the upgrade. If the file was customized, the upgrade process may not have updated the /etc/syslog-ng/syslog-ng.conf file with the following entries:

# capture output from tmm and put it in /var/log/tmmsource s_tmm {pipe("/var/run/tmm.pipe");};destination d_tmm {file("/var/log/tmm" create_dirs(yes));};log {source(s_tmm);destination(d_tmm);};

In BIG-IP 9.1.2 and 9.2.2, the tmm daemon writes to a named pipe; therefore, these entries are required. If the syslog-ng daemon does not use the named pipe, the tmm daemon will not start.

F5 Product Development tracked this issue for the BIG-IP 9.2 branch as CR58625 and it was fixed in BIG-IP 9.2.3. For information about upgrading, refer to the LTM, GTM, ASM, Link Controller, or WebAccelerator Release Notes.

F5 Product Development is tracking the syslog-ng dependency for the tmm daemon issue for the 9.1 software branch as CR65653.

For additional information about these CRs, refer to K5879: The BIG-IP system does not pass traffic and non-management interfaces are non-responsive if syslog-ng fails to start.

Workaround

Important: This procedure requires that you reboot the BIG-IP system. This procedure must be performed from the command line, through the console (accessed through the serial terminal), or using SSH connected through the management interface.

To work around this issue, perform the following steps:

  1. Log in to the command line.
  2. Change directories to the /etc/syslog-ng directory, by typing the following command:

    cd /etc/syslog-ng

  3. Using a text editor, such as vi or nano, edit the syslog-ng.conf file.
  4. Add the following lines at the end of the file:
    # capture output from tmm and put it in /var/log/tmmsource s_tmm {pipe("/var/run/tmm.pipe");};destination d_tmm {file("/var/log/tmm" create_dirs(yes));};log {source(s_tmm);destination(d_tmm);};
  5. Save the file and exit the editor.
  6. Reboot the BIG-IP system, by typing the following command:

    reboot
