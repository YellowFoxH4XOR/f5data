K000163767: OSPF Adjacencies Fail When Message-Digest Authentication Is Incompletely Configured

Type
Support Solution
Published
2026-10-18
Updated
2026-10-18
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000163767

Description

OSPF adjacencies and dynamic route exchange can be disrupted when message-digest authentication is configured inconsistently across participating interfaces. A message-digest key alone does not enable authentication; the authentication command must also be configured.

Environment

  • BIG-IP LTM
  • OSPF process
  • OSPF configured on multiple interfaces
  • Interfaces use OSPF message-digest authentication

Cause

The OSPF authentication configuration was incomplete:

  • One interface had no OSPF authentication or message-digest key.
  • Another interface had a message-digest key configured, but message-digest authentication was not enabled.

This configuration mismatch prevented OSPF authentication from being applied consistently. The issue was not caused by the BIG-IP software upgrade.

Resolution

Enable message-digest authentication and configure the same key ID and matching key on every participating OSPF interface:

ip ospf authentication message-digest

ip ospf message-digest-key 1 md5 <matching-key>

For example:

interface f5_dmz

ip ospf authentication message-digest

ip ospf message-digest-key 1 md5 <matching-key>

ip ospf cost 1000

ip ospf priority 0


interface transit_dmz

ip ospf authentication message-digest

ip ospf message-digest-key 1 md5 <matching-key>

ip ospf cost 100

ip ospf priority 0

The authentication command and message-digest key must match on both OSPF peers.

Verification

Verify the OSPF neighbor state:

show ip ospf neighbor

Verify detailed adjacency information:

show ip ospf neighbor detail

A healthy broadcast OSPF network may show:

  • The DR or BDR neighbor in the Full state.
  • Priority-0 neighbors in the 2-Way/DROther state.
  • No neighbors in Down, Init, ExStart, Exchange, or Loading.
  • Empty Database Summary, Link State Request, and Link State Retransmission lists.

A priority-0 neighbor in the 2-Way/DROther state is expected when the neighbor is neither the DR nor the BDR.

Verify dynamically learned routes:

show ip route

tmsh show /net route

Recommended Actions

  1. Review the OSPF authentication configuration on every participating interface.
  2. Confirm that ip ospf authentication message-digest is enabled wherever a message-digest key is configured.
  3. Confirm that the key ID and key match on all OSPF peers.
  4. Verify OSPF neighbor states after making configuration changes.
  5. Confirm that expected dynamic routes are present.
