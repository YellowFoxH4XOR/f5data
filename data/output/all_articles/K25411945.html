Description

On the LCD screen, the following message shows:

Updating FW, can take up to 10min , do not interrupt!
Host inaccessible or in diagnostic mode
  • This persists through a power cycle.
  • The Appliance is not accessible.

Environment

  • BIG-IP
  • LCD Screen

Cause

This issue may arise due to the following causes in descending order of probability:
  • If the unit is running EUD it will be in this state. This is completely normal and expected.  It does not indicate a hardware concern outside of why the EUD was run initially..

    Recommendation: In this case, wait for the EUD to complete.

  • The BIG-IP system is in an inactive state. In this situation the console interface is expected to be accessible and the command prompt for TMOS to report the inactive state. This message on the LCD indicates that the BIG-IP system was unable to fully start all of the background processes responsible for updating the LCD. 

    Recommendation: Review the log files beginning with /var/log/ltm to determine the root cause.

    K73827442: Forcing a file system check on the next system restart (12.x - 16.x)
    K95002127: Troubleshooting BIG-IP failover events
    K10062: Overview of managing BIG-IP core files

    The following lists some (but not limited to) common causes:

    • One or more directory on the system (e.g. /var) is out of storage. This could be due to a lack of maintenance, excessive log files (this may be caused by a poor configuration causing excessive logging) or misconfiguration that blocks complete load of the system.

      • K000132482: Recover /var disk partition free space that is filling or full

      • K14403: Maintaining disk space on the BIG-IP system

    • Software processes, daemons unable to start correctly or software file corruption.

  • If this message exists and the console interface is not accessible it could be one of the rare hardware related issues causing the unit to not function properly. For example, a hardware chip is unable to communicate with the CPU.

    Recommendation: Run a EUD test and use the console to gather AOM information for more information refer to the following:

    • K7172: Overview of the End User Diagnostics software
    • K14594: Accessing the AOM Command Menu
    • K9403: Overview of the AOM subsystem

Recommended Actions

After performing the recommended steps described in the Cause section above, and if you are unable to determine the root cause, you can open a case with F5 Support after obtaining the AOM diagnostic information.
