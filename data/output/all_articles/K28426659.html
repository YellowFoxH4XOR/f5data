Topic

What is a WAF?

A web application firewall (WAF) is an intermediary system positioned between the web application and the end-users which is designed to protect the web application against layer-7 attacks. Attackers exploit vulnerabilities in web application with the aim of disrupting services and stealing and manipulating data. Therefore, you typically deploy a WAF as a reverse proxy and place it in front of web applications to ward off illicit, malicious traffic before it reaches your web application. A WAF inspects and monitors ingress and egress web application traffic for malicious patterns or anomaly behavior. After harmful traffic is detected, the WAF triggers a violation and the system enforces mitigating actions, such as adding challenges, blocking, and monitoring.

Figure: WAF overview

As web application traffic transit through it, a WAF inspects traffic components, including the application payload, and identifies bad traffic using signature-based and/or anomaly detection techniques. Thus, the WAF allows detection and protection against OWASP Top 10 attacks, such as SQLi and XSS. In addition, some WAFs also secure the availability web applications and services by mitigating against layer-7 DoS, DDoS, and bots attacks.

Description

WAF evolution

You can think of the evolution of WAF as how the system progresses in detecting threats.

WAFs have come a long way to become the key component of web application infrastructure that they are today. WAFs originate from network firewalls, which started to appear commercially in the early 1990s. At that time, application firewalls were not separate system but instead were part of a Network Intrusion Defense System (NIDS), with limited layer-7 application capabilities and few specific protocols, such as FTP and remote shell (rsh). With the proliferation of Internet, the need to protect web application such as e-commerce became imperative, thus came the inception of dedicated web application firewalls, separated from the network firewall functions and specific to web application and web services protection. From that point, WAFs have evolved by using different techniques to improve threat detection rate (the percentage of attacks detected) and threat detection accuracy (the percentage of false positives). The enhancement of signature-based and anomaly-based detection is one notable evolution since then. Adaptive learning (sometime called application learning) has set a precedent, leading to the contemporary artificial intelligence and machine learning capabilities in today's WAFs.

WAF deployment modes

Whether you use WAFs as a hardware appliance or a virtual machine, on-premises or in the cloud, behind a load balancer or on the web server, inline or out-of-line, the specific web traffic for the application you are protecting should transit through your WAF. This enables the WAF to inspect in real time, detect, and mitigate malicious traffic before it reaches the application.

A WAF ASM is typically deployed in routed mode or in one-arm mode deployment, as shown in the following figures.

Routed mode

In routed mode, ingress and egress web application traffic routes through the WAF. The WAF is physically inline with web application traffic and executes security controls to protect your applications.

Figure: WAF in routed mode

One-arm mode

In one-arm mode, the WAF is logically in line with the web application traffic flow but not physically in line with all ingress and egress traffic. In this topology, client-side web traffic that needs to be protected must be redirected to the WAF, and SNAT is used when retransmitting traffic to web application servers.

Figure: WAF in routed mode

BIG-IP ASM is not just a WAF

BIG-IP ASM is a WAF and protects web applications against layer-7 attacks, such as buffer overflows, SQL injection, cross-site scripting, parameter tampering, brute force attacks, cookie poisoning, web scraping, and many others.

BIG-IP ASM also helps ensure compliance with key regulatory mandates, such as HIPAA and PCI DSS, and provides an OWASP Compliance Dashboard, which displays a list of BIG-IP ASM security policies and their respective OWASP Top 10 compliance scores. BIG-IP ASM is equipped with a learning engine that examines ingress and egress web traffic and intelligently learns the intended behavior of the application. That learning feeds Policy Builder, which can automatically configure the security controls required to protect your application. When using automatic learning, the system continuously learns as traffic is processed and can suggest new security controls as the application's design or usage evolves, thus, significantly reducing the complexity and number of signatures that you have to manually configure.

In addition to protecting web applications, web services, and WebSocket, BIG-IP ASM also secures other protocols such as FTP and STMP, providing protection for requests sent to your SMTP and FTP servers.

Among other additions to a standard WAF, BIG-IP ASM provides flexion and extension through programmability; notably through custom signatures, iRules, and AS3. With custom signatures (also referred as user-defined signatures), you can create simple or, using RegEx, complex rules to identify application patterns specific to your application. You can also apply a script using the iRules language that inspect, modify, reroute, discard, reject, or take any other protective actions on ingress and egress application traffic. In addition, you can also use AS3 to provide a declarative API and abstract away the complexity of the BIG-IP ASM configuration.
