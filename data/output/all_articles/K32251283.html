Description

You want to modify the key exchange (KEX) algorithms used by the secure shell (SSH) service on the BIG-IP system, for example:

  • To disable weak key exchange algorithms like diffie-hellman-group1-sha1 and diffie-hellman-group-exchange-sha1.
  • To enable strong key exchange algorithms like ecdh-sha2-nistp256 and ecdh-sha2-nistp384.

Environment

  • BIG-IP
  • SSH

Cause

Controlling which KEX algorithms are available will allow you to balance compatibility and security in your specific environment.

Recommended Actions

Important: On VIPRION systems, at least one cipher, one KEX algorithm, and one MAC from the ciphers list used by the SSH client must be included for blade-to-blade communication, to allow SSH between slots and qkview collection. For the list of ciphers, refer to the /config/ssh/ssh_config file.

Impact of procedure: Incorrectly configured ciphers can prevent SSH access to the BIG-IP system. Currently connected SSH sessions will not be interrupted, however, it is recommended to test changes by opening a second SSH session to the BIG-IP system and ensuring that you are able to connect before closing the first SSH session.

You can configure the SSH service (sshd) to use a desired set of KEX algorithms to meet the security policy enforced in your environment.

  1. Log in to the command line of the BIG-IP system using the Advanced shell (bash)
  2. Check the available KEX algorithms by entering the following command:

    sshd -T | grep -i kexalgorithms

  3. Log in to the TMOS Shell (tmsh) by entering the following command:

    tmsh

  4. Display the current sshd configuration by entering the following command, observing the value for include:

    list /sys sshd all-properties

    The output appears similar to the following example:

    sys sshd {
      allow { ALL }
      banner disabled
      banner-text none
      description none
      fips-cipher-version 0
      inactivity-timeout 0
      include none
      log-level info
      login enabled
      port 22
    }

    Note: If no custom configuration has previously been applied to sshd, the default value for the include statement will be none. In the next step, you will modify the include statement, which will then override the default sshd configuration.

  5. Edit the sshd configuration by entering the following command:

    edit /sys sshd all-properties

  6. To enter insert mode, select the i key.
  7. Replace the include none line with your preferred KEX algorithms.

    For example, if you want to limit the system to only ecdh-sha2-nistp256, ecdh-sha2-nistp384, and ecdh-sha2-nistp521 KEX algorithms, use the following include statement:

    include "KexAlgorithms ecdh-sha2-nistp256,ecdh-sha2-nistp384,ecdh-sha2-nistp521"

    Note: If the include statement already contains other configuration, such as Ciphers and MAC, you can append a new line with the keyword KexAlgorithms within the same include statement. For more information, refer to K80425458: Modifying the list of ciphers and MAC and key exchange algorithms used by the SSH service on the BIG-IP or BIG-IQ systems.

  8. Select the ESC key to exit from insert mode.
  9. Save the modifications and exit the editor by enter the following command and selecting the Enter key:

    :wq

  10. A prompt similar to the following example gives you the option to save your modifications:

    Save changes? (y/n/e)

    Select the y key.

  11. Verify the change was made to the running configuration by entering the following command:

    list /sys sshd all-properties

    The output should appear similar to the following example:

    sys sshd {
      allow { ALL }
      banner disabled
      banner-text none
      description none
      fips-cipher-version 0
      inactivity-timeout 0
      include "KexAlgorithms ecdh-sha2-nistp256,ecdh-sha2-nistp384,ecdh-sha2-nistp521"
      log-level info
      login enabled
      port 22
    }

  12. Save the updated running configuration to disk by entering the following command:

    save /sys config

Additional Information

The 'ssh -Q' switch is only available for ssh versions 6.3 or later. You may check the ssh version using the command 'ssh -V'.
