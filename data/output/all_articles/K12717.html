Known Issue

This is the result of a known issue. If a client sends an unconditional POST request for objects that are cached on the BIG-IP WebAccelerator system, and the object is due for content revalidation, the BIG-IP WebAccelerator system inserts the If-None-Match header with the object Etag before sending it to the origin web server (OWS) as a conditional POST request. The OWS may respond with an HTTP 412 Precondition Failed status, instead of an HTTP 304 Not Modified status, for objects that have not changed. If the OWS returns an HTTP 412 Precondition Failed status response, the BIG-IP WebAccelerator system forwards this status to the client. As a result, the client may display the HTTP 412 Precondition Failed error message.

Note: The system can use the If-None-Match header with any HTTP request method to make the request conditional. The purpose of a conditional method is to allow the system to update cached objects without having to send multiple requests or having to transfer data that is already on the client. This method reduces unnecessary network traffic.  As described in RFC2616 Section 14.26, it is expected behavior for the OWS to respond to the system with an HTTP 412 Precondition Failed status for objects that have not been modified, when the OWS receives a request with an If-None-Match header. For more information, refer to RFC2616: Hypertext Transfer Protocol -- HTTP/1.1.

F5 Product Development is tracking this issue as ID 350853 and has been fixed in BIG-IP 11.0.0. For information about upgrading, refer to the BIG-IP WebAccelerator release notes.

Workaround

You can work around this issue by configuring a new node that matches the POST method to always proxy instead of caching the object in the BIG-IP WebAccelerator system. To do so, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Click WebAccelerator.
  3. Click Policies.
  4. Click Policy List.
  5. Click the name of the policy you would like to configure.
  6. Navigate to the leaf node you would like to configure.
  7. Click the leaf node you would like to configure.
  8. Click Copy.
  9. In the Name box, type a name you would like to give this new leaf node.
  10. To make a copy, click Copy.
  11. Click the new leaf node.
  12. In the Add Parameter menu, select Method.
  13. Click Add.
  14. Under the Value section, select POST.
  15. Click Save.
  16. In the Matching Rules menu, select Acceleration Rules.
  17. Click the Proxying tab.
  18. Select the Always proxy requests for this node option.
  19. Click Save.
  20. Click Publish.
  21. Optional: Add any comments in the Comment box.
  22. Click Publish Now.
