Known Issue

The Traffic Management Microkernel (TMM) may restart and produce a core file when Message Routing Framework (MRF) messages cross from one TMM to another.

This issue occurs when all of the following conditions are met:

  • MRF messages travel from one TMM to another
  • An asynchronous operation occurs at the same time. For example, this issue can occur when persistence is configured on the BIG-IP system.

Impact

The BIG-IP system temporarily fails to process traffic as it recovers from the TMM restart, and devices configured as a high availability (HA) group may fail over.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • You observe segmentation fault messages similar to the following example in the /var/log/tmm* log files:

    notice ** SIGSEGV **
    notice fault addr: 0x18
    notice fault code: 0x1
    notice version: pgo_use x86_64 padc TMM Version 11.6.0.6.301.442

  • Your BIG-IP system generates a TMM core file to the /shared/core directory.
