K000140356: Error: ''REST framework is not available'' is displayed on GUI for ASM configurations when accessing via non-primary cluster IP in VIPRION/VCMP.

Type
Support Solution
Published
2024-07-25
Updated
2024-07-25
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.1.0
Source
https://my.f5.com/manage/s/article/K000140356

Description

When managing ASM configurations on a VIPRION/vCMP environment through a non-primary cluster IP address, administrators may encounter the message "REST framework is not available". This message appears exclusively when attempting to access ASM configurations; however, LTM configurations remain unaffected and are accessible as usual.

Environment

  • VIPRION/vCMP
  • Configuration Utility

Cause

The appearance of the "REST framework is not available" message when accessing ASM configurations from non-primary cluster IP addresses is not indicative of an error or malfunction. This behavior is by design, officially known as FAD (Functioning As Designed), and is an expected outcome of the system's operation.

Recommended Actions

To verify that ASM configuration changes have been successfully synchronized across cluster member IP addresses or different slots, administrators should utilize the grep command to filter for the term "tsconfd" in the ASM logs. Below is an illustrative example showcasing the logs generated when a new ASM policy named "test_asm_policy3" was created. In this instance, the primary slot in use was slot 2. 

  • CLI command to initiate the log search:
    grep tsconfd /var/log/asm
  • Log excerpt below demonstrates the type of entry that may be encountered following the creation of a new ASM policy. This log entry indicates a successful addition of the ASM policy "test_asm_policy3," and synchronization of the change with non-primary slot member (in this case slot 1).
    slot1/localhost.localdomain info perl[18033]: 01310053:6: ASMConfig change:  Security Policy /Common/test_asm_policy3 [add]: Parent Policy was set to empty value. Type was set to Security. Encoding Selected was set to false. Active was set to false. Policy Name was set to /Common/test_asm_policy3. { audit: policy = /Common/test_asm_policy3, component = tsconfd }

Additional Information

The "tsconfd" process is responsible for dispatching policy updates to the bd process via the bd_agent and for managing events received from the bd_agent.
