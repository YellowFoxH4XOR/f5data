Description

You have configured SNI (Server Name Indication) in a BIG-IP Server SSL profile and used it on a HTTPS health monitor. For more information about this configuration, refer to K65219243: SNI support for HTTPS monitors. However, packet captures show that SNI is not being sent to the pool or node. For example, refer to the following Client Hello packet capture:

Environment

  • BIG-IP 13.1 and later
  • SNI has been configured on a Server SSL profile
  • HTTPS health monitor is using the SNI configured Server SSL profile
  • In-TMM for health monitoring is disabled

Cause

The monitoring traffic is being processed by bigd. It is expected behavior for bigd to not send the SNI in HTTPS health monitoring. Use of SNI in HTTPS health monitors is officially supported through the use of in-TMM monitoring only.

Recommended Actions

To workaround the issue, follow one of the following solutions:

  • Enable In-TMM monitoring instead of bigd. For more information, refer K11323537: Configuring In-TMM monitoring.
  • Use an external monitor. Refer to HTTPS SNI Monitoring How-to.
  • If In-TMM has been enabled and you are using a non-default route domain, refer to K83500821: HTTPs monitor does not send SNI field in Client Hello.
