Known Issue

The Traffic Management Microkernel (TMM) process may produce a core file under heavy load when you use the logging profile with packet classification.

This issue occurs when all of the following conditions are met:

  • Packet classification is enabled.
  • The security logging profile is enabled for a network firewall with the Log Translation Fields option enabled.
  • The Fast Flow Forwarding feature is enabled, which is the default setting.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from TMM restarting, and a failover may occur if you have configured the system as part of a high availability (HA) group.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Your BIG-IP system generates a TMM core file to the /shared/core directory with a time stamp that correlates to the traffic interruption.
  • Your BIG-IP system unexpectedly fails over to another system in the device group.

Workaround

To work around this issue, you can disable the Fast Flow Forwarding feature. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure requires that you reboot the BIG-IP system. The tmm.ffwd.enable database variable allows a TMM at 100 percent capacity to forward connections to a TMM under less intensive CPU load.

  1. Log in to the BIG-IP command line.
  2. To disable the Fast Flow Forwarding feature, type the following command:

    tmsh modify sys db tmm.ffwd.enable value false

  3. To reboot the BIG-IP system, type the following command:

    reboot
