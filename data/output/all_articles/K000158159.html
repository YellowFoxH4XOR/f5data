K000158159: Login Failure for Specific User Accounts on Standby Unit After Password Change

Type
Support Solution
Published
2025-12-11
Updated
2025-12-11
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.1.1
Source
https://my.f5.com/manage/s/article/K000158159

Description

  • After changing passwords for several local user accounts on the Primary Device (Active) in a high-availability (HA) pair, specific user accounts are unable to log in to the Secondary Device (Standby).
  • Audit logs on the standby device show repeated authentication failures and account lockout messages for these users, despite successful password change and login on the active device.
  • Audit logs on the standby unit show repeated authentication failures and account lockout messages, such as:

     pam_tally2(httpd:auth): user myuser1 tally 6, deny 5
     not authenticated: Authentication failure

Environment

  • BIG-IP LTM module
  • HA configuration: Primary Device (Active) and Secondary Device (Standby)
  • Local user accounts managed via GUI
  • Device group synchronization status: "In Sync"

Cause

The affected user accounts on the standby device were locked out due to exceeding the allowed number of failed login attempts, as enforced by the password-policy. This lockout persists even after password changes and configuration synchronization until manually cleared.

Recommended Actions

Clear the account lockout for affected users on the standby device using the following command

tmsh reset-stats /auth login-failures <User1> <User2> ...

For example, to reset the user account name myuser1, type the following command:

reset-stats /auth login-failures myuser1
