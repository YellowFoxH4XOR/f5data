Known Issue

Provisioning more than eight processing units for a BIG-IP Virtual Edition (VE) system may cause the Traffic Management Microkernel (TMM) process to produce a core file and restart.

This issue occurs when all of the following conditions are met:

  • You install a VE version of the BIG-IP system.
  • You configure more than eight CPUs on the virtual machine.

The default installation of the datastor libraries and process is limited to support no more than eight processing units.

Impact

The BIG-IP system may temporarily fail to process traffic as it recovers from the TMM restart, and devices configured as a high-availability (HA) pair may fail over.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The TMM process restarts continuously.
  • A message similar to the following example appears in the datastor log file:

    ipc_endpt_limit: Assertion `cpus > 0 && cpus <= MPI_NADDR'
  • The BIG-IP system unexpectedly fails over to another system in the device group.
  • You observe a TMM core file in the /shared/core directory.

Workaround

To work around this issue, you can reconfigure the virtual machine to use eight or fewer CPUs.

Impact of workaround: Performing the suggested workaround should not have a negative impact on your system.
