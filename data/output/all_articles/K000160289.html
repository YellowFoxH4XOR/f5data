K000160289: F5 APM session clears immediately after the access policy completes

  • BIG-IP APM: 17.0.0, 17.1.0, 17.0.X, 17.X.X, 17.5.X, 17.5.1, 17.5.0, 17.1.X, 17.1.3, 17.1.2, 17.1.1
Source
https://my.f5.com/manage/s/article/K000160289

Description

SAML authentication fails with error "Decryption of assertion key failed" when assertion encryption is enabled. APM session is not removed when users log out of Citrix StoreFront. Error messages include "Response/assertion is not signed" and "Session deleted due to user logout request." Session may terminate immediately after SAML authentication completes.

Environment

  • F5 BIG-IP APM
  • Citrix StoreFront servers
  • SAML authentication enabled with assertion encryption
  • F5 in FIPS mode
  • SAML IdP: RSA SecurID
  • Access Policy with SAML authentication agent
  • iRules for browser prefetch mitigation and session handling

Cause

The SAML assertion decryption failure was caused by a mismatch in the key transport algorithm. RSA-OAEP was not supported for assertion encryption in the F5 FIPS setup. Changing the IdP to use RSA v1.5 resolved the issue.

Session logout issues occur because Citrix StoreFront does not send a unique, detectable HTTP request on logout, making iRule-based session removal unreliable. SAML Single Logout (SLO) or a unique logout URI is required for reliable session termination.

Answer/Recommended Actions

SAML Assertion Decryption Failure

  1. Confirm the SAML IdP is using RSA v1.5 for key transport algorithm when assertion encryption is enabled and F5 is in FIPS mode.
  2. Ensure the IdP encrypts assertions using the public certificate that matches the private key configured on the F5 SAML SP object.
  3. Verify certificate/key pair match on F5:
    openssl x509 -noout -modulus -in <certificate.crt> | openssl md5
    openssl rsa -noout -modulus -in <private.key> | openssl md5
    NOTE: The output hashes must match.
  4. Re-exchange metadata between F5 and IdP if certificate/key changes are made.
  5. Test SAML authentication after making these changes.

Session Logout Issues

Option 1: SAML Single Logout (SLO) - Recommended

  1. F5 BIG-IP APM Configuration:
    • Navigate to Access > Federation > SAML Service Provider > Local SP Services
    • Configure SLO Settings:
      • Single Logout URI: /saml/sp/profile/post/slo
      • Binding: POST
      • Certificate/Key: Use the same certificate/key pair as for SAML Authentication
    • Export Metadata
  2. Citrix StoreFront Configuration:
    • Import the F5 metadata XML file
    • Enable Single Logout
    • Set the SLO endpoint to the F5 SLO URI
    • Set the binding to POST

Option 2: Logout Redirect URI

  1. Citrix StoreFront Configuration:
    • Set Post-Logout Redirect URL to a unique path (e.g., /my.logout.php3)
  2. F5 BIG-IP APM Configuration:
    • Navigate to Access > Profiles / Policies > Access Profiles
    • Edit the profile used for Citrix
    • Add /my.logout.php3 to the Logout URI Include field
    • Save and Apply Access Policy

Additional Troubleshooting

  • Ensure "Close session after redirect" is unchecked in Access Policy Redirect Endings unless immediate session deletion is desired.
  • Remove any iRules attempting to handle Citrix logout unless StoreFront is customized to send a unique logout request.
  • Apply browser prefetch mitigation iRule if needed.

Additional Information

  • Assertion encryption and decryption require exact certificate/key matching between IdP and SP.
  • Citrix StoreFront's default logout flow does not trigger a unique HTTP request; SAML SLO or logout URI configuration is required.
  • Browser prefetch requests can cause unexpected session terminations and should be mitigated with an iRule.
  • SAML authentication is supported only for browser-based access, not Citrix Workspace App.
