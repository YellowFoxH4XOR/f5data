Known Issue

This is the result of a known issue. If you configure a proxy auto-configuration (PAC) script for a Network Access connection, Windows clients are unable to establish a Network Access connection from the FirePass webtop. When this issue occurs, FirePass displays an error message that appears similar to the following example in the Network Access status window:

Error initializing proxy

This issue does not occur if the Windows client connects to the FirePass controller using the standalone VPN client.

Note: PAC scripts are configured on the Network Access: Resources page in the Autoconfig script field, under the Client Settings tab. The Autoconfig script field appears only if the Client proxy settings check box is selected.

F5 Product Development tracked this issue as ID 296162 (formerly CR108535) and it has been fixed in FirePass version 6.1.0. Additionally, this issue has been fixed in cumulative hotfix HF-603-1, which has been issued for FirePass version 6.0.3. You may download this hotfix or later versions of the cumulative hotfix from the F5 Downloads site.

For instructions about obtaining a hotfix, refer to K167: Downloading software and firmware from F5.

For instructions about installing a hotfix, refer to K3430: Installing FirePass hotfixes.

Workaround

You can work around this issue by entering a port number in the Port field and an asterisk (*) character in the Proxy exclusion list field under the Client proxy settings check box. To do so, perform the following procedure:

  1. Log in to the FirePass Administrative Console.
  2. Navigate to the Network Access: Resources page.
  3. In the Resource Group menu, select the name of the resource group you want to configure.
  4. Select the Client proxy settings check box.
  5. Under Client Settings, in the Port field, enter the number 0 (zero).
  6. Enter the asterisk (*) character in the Proxy exclusion list field.
  7. Click Update.
