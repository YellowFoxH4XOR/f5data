Known Issue

Attempting to edit an access policy containing an incorrect topology can trigger the apmd process to produce a core file and restart.

This issue occurs when all of the following conditions are met:

  • You import an access profile into the BIG-IP APM configuration.
  • The access policy of the access profile contains multiple references to the same macro call.
  • You attempt to edit the imported access policy using the visual policy editor.

Impact

The access policy does not render in the visual policy editor. In some cases, the apmd process will produce a core file and restart temporarily, disrupting the ability to establish access sessions.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When attempting to edit the access policy using the visual policy editor, the system displays an error message that appears similar to the following example:

    Unable to load accessPolicy '/<partition>/<access policy name>' from source. Access Policy Item /<partition>/<access policy name>-<resource assign agent name> addPrevWire: Unable to add prev wire - current object could have only one prev link, and it's already linked

    loading stopped, please refresh
     
  • When attempting to edit the access policy using the visual policy editor, the system logs a message to the /var/log/apm file that appears similar to the following example:

    notice apmd[<pid>]: 01490000:5: ** SIGSEGV **
     
  • The apmd/apd process produces a core file in the /shared/core/ directory, similar to the following example:

    apd.bld690.0.core.gz

Workaround

To work around this issue, you can manually edit the affected access policy duplicate link reference. To do so, perform the following procedure:

Impact of workaround:  F5 recommends performing the following procedure during a scheduled maintenance window. 

  1. Log in to the BIG-IP APM command line.
  2. Create a backup of the configuration file by typing the following command:

    cp /config/bigip.conf /var/tmp/bigip.conf.original

  3. Open the /config/bigip.conf file in a text editor.
  4. Locate the affected access policy.
  5. Review the access policy configuration for duplicate next-item objects.
  6. Replace the next-item action with end_deny.

    For example, an access policy contains the following duplicate next-item objects:

    next-item /Common/example_advanced_resource_assign_default
    next-item /Common/example_advanced_resource_assign_default

    Note: Replace the action after the first underscore character ( _ ) of the next-item /<partition>/<name>_<action>.

    For the example, replace _advanced_resource_assign_default with _end_deny.

  7. Modify the duplicate next-item and replace the action of the object with end_deny. 

    For example:

    next-item /Common/example_end_deny

  8. Save the file changes and exit the text editor.
  9. Reload the BIG-IP configuration by typing the following command:

    tmsh load /sys config
