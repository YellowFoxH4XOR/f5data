Known Issue

This is the result of a known issue. A monitor that operates in transparent mode can monitor nodes or pool members through transparent network devices, such as firewalls. When you define a transparent TCP monitor without a send string and receive string, the BIG-IP system does not properly close the monitor connection.

When a transparent TCP monitor without send and receive strings runs, the BIG-IP system does not close the monitor connection with a TCP RST packet, and it does not respond to the pool member's TCP FIN packet with an ACK.

F5 Product Development tracked this issue as CR92875 and it was fixed in BIG-IP 9.4.4. For information about upgrading, refer to the BIG-IP LTM Release Notes.

Additionally, Hotfix-BIG-IP-9.3.1-HF2 has been issued for BIG-IP 9.3.1. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.

For information about the F5 hotfix policy, refer to K4918: Overview of the F5 critical issue hotfix policy.

For information about managing F5 product hotfixes, refer to K6845: Managing BIG-IP product hotfixes (9.x).

Workaround

You can work around this issue by enabling the Bigd.ResetTransparent BigDB variable. To do so, type the following command:

bigpipe db Bigd.ResetTransparent true
