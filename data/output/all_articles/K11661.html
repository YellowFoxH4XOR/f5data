Known Issue

The BIG-IP system may fail to load configurations containing iRules with double-byte characters.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system is upgraded from a version prior to 10.1.0.
  • The BIG-IP system is configured with custom HTTP response iRules.
  • The custom iRule HTTP response contains double-byte characters as found in the following languages.
    • Chinese
    • Japanese
    • Korean

Impact

The system configuration fails to load after upgrading.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • BIG-IP iHealth lists Heuristic H4372378 on the Diagnostics > Identified > Medium screen.
  • After upgrading from a version prior to 10.1.0 to 10.1.0 - 10.2.4, the system configuration fails to load.
  • Error messages similar to the following example are logged to /var/log/ltm:

    err mcpd[11425]: 01070151:3: Rule [japanese_irule_respond] error: line 1: [braces are required around the expression] [when HTTP_REQUEST { if { [active_members test_pool] < 1 }{ HTTP::respond 200 Content "<HTML><BODY>ç¾å¨ãµã¼ãåæ­¢ä¸­ã§ãã</H1><HR><H1 ALIGN=center> ãããã°ãããå¾ã¡ãã ããã</BODY></HTML>" "Content-Type" "text/html" } }]

Workaround

To work around this issue, you can convert the iRule HTTP response to base64 encoding. To do so, perform the following procedure:

Impact of workaround: F5 recommends that you test such changes during a maintenance window, and consider the possible impact on your specific environment.

Converting the HTTP response characters to base64 encoded.Procedure 1 Title

  1. Log in to the command line of the BIG-IP system, or most Linux-based operating systems.
  2. Using the following command syntax, modify the HTTP response to a response containing the double-byte characters.

    For example:

    echo "?????" | base64

    5a2X56ym55qE5rWL6K+VCg==

  3. Copy the output text of the previous command.

Updating the affected iRule to use the base64 encoded text.

  1. Log in to the Configuration utility.
  2. Navigate to Local Traffic > iRules.
  3. Select the Name of the affected iRule.
  4. Replace the iRule HTTP response text with the base64 encoded output.

    Following is some example iRule syntax containing double-byte characters:

    when HTTP_REQUEST {
    HTTP::respond 200 content "?????" "Content-Type" "text/html; charset=UTF-8"
    }

    Following is some example iRule syntax using the base64 encoded characters:

    when HTTP_REQUEST {
    HTTP::respond 200 content [b64decode "5a2X56ym55qE5rWL6K+VCg=="] "Content-Type" "text/html; charset=UTF-8"
    }

    Note: Ensure that the base64 encode statement is enclosed with the brackets [ and ], and that the base64 encoded text is enclosed in quotation marks (").

  5. To save the iRule changes, click Update.
