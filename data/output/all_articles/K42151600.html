Issue

Error Message

011f0016:3: http_process_state_prepend - Invalid action:<code> Server sends too much data. serverside (<ss_connection>) clientside (<cs_connection>) (Server side: vip=<vs_name> profile=<profile_name> pool=<pool_name> server_ip=<pool_member_IP>)

In this error message, note the following:

  • <code> is an internal hexadecimal code.
  • <ss_connection> is the IP address and port number information for the serverside connection.
  • <cs_connection> is the IP address and port number information for the clientside connection.
  • <vs_name> is the affected virtual server object name.
  • <profile_name> is the name of the affected HTTP profile.
  • <pool_name> is the name of the affected pool.
  • <pool_member_IP> is the IP address of the affected pool member.

For example:

011f0016:3: http_process_state_prepend - Invalid action:0x109010 Server sends too much data. serverside (10.10.10.100:80 -> 10.10.10.10:69872) clientside (10.8.20.240:69872 -> 10.20.20.70:80) (Server side: vip=/Common/vs_http profile=http pool=/Common/pool_http server_ip=10.10.10.100)

Message Location

You may encounter this message in the following location:

  • The /var/log/ltm file

Description

This message occurs when any of the following conditions are met:

  • The virtual server is configured with an HTTP profile, and the BIG-IP system receives a response from the pool member that either contains more data than indicated in the Content-Length header or has additional data following the ending chunk of a chunked response.
  • A Performance L4 virtual server configured with an HTTP profile processes SSL traffic. 

Note: This error message may occur more frequently in BIG-IP 12.1.0 and later. Beginning in BIG-IP 12.1.0, this error message is triggered if the excess data is included in either the same packet or an additional packet. For previous versions, the error message would only be triggered if the excess data was received in an additional packet.

Impact

The BIG-IP system stops processing the response, terminates the connection, and sends a reset to the affected pool member server.

Recommended Actions

If the error message occurs as a result of a Performance (Layer 4) virtual server being configured with an HTTP profile and processing SSL traffic, you should remove the HTTP profile from the affected virtual server. For more information, refer to K01155812: Overview of the Performance (Layer 4) virtual server, and K4707: Choosing appropriate profiles for HTTP traffic.

If the error message occurs as a result of processing HTTP traffic, the message indicates that the response received from the back-end server is not RFC-compliant. You should first and foremost modify and correct the back-end server behavior. If this is not possible and you must perform a temporary workaround until the back-end server behavior is corrected, in BIG-IP 12.1.0 and later, you can configure the BIG-IP system to allow the invalid HTTP content length to be processed. To do so, perform the following procedure:

Note: The database key in this action only works when the additional segment data is present in the same packet.

Impact of workaround: The impact of the suggested workaround depends on the specific environment. F5 recommends testing any such changes during a maintenance window with consideration to the possible impact on your specific environment.

  1. Log in to the TMOS Shell (tmsh) by entering the following command:

    tmsh

  2. To enable the tmm.http.passthru.invalid_content_length database key, enter the following command:

    modify /sys db tmm.http.passthru.invalid_content_length value enable

Note: The newly configured behavior is applied to new connections. Existing connections are not affected.
