K000135004: multi-domain access policy appears to not be functioning for sub-hosts

Description

APM VS was sending RST upon re-entry to another virtual with same APM policy.

 

Environment

BIG-IP APM v16.1.3.4

multidomain sso

VS sending RST

 

Cause

When applying the below iRule, to include "ACCESS::restrict_irule_events disable", this iRule allows events to access internal access to control URIs.

ltm rule /Common/ir_allowed_hosts_2 {

when CLIENT_ACCEPTED {

ACCESS::restrict_irule_events disable

}

 

Then any subsequent irule, like below, will be allowed to change the internal access control URIs to lower case which potentially causes issues if it was coded to be case specific.

 

ltm rule /Common/ir_URI_to_lower_case {

when HTTP_REQUEST {

HTTP::path [string tolower [HTTP::path]]

}

Recommended Actions

Remove iRule and have a more targeted approach within the APM VPE, see: K20811234: How to change Session variables to lower case - APM  

Additional Information

Connection may see RST, and will have a log entry in the APM log similar to below:

ERR_ARG. File: ../modules/hudfilter/access/access.c, Function: access_multidomain_sso_redirect_to_slave_auth_virtual, Line: 16111
