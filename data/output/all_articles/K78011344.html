Description

GRE (Generic Routing Encapsulation) is a tunneling protocol that can encapsulate a wide variety of network layer protocols inside virtual point-to-point links over an IP network. Due to its nature, which allows huge payloads to be encapsulated and sent and which adds processing overhead of IP defragmentation to impact a target, attackers can abuse GRE and use it in GRE flood attacks.

You can use the BIG-IP AFM DoS Device Protection Feature to mitigate a GRE flood attack using the IP Unknown/IP Uncommon Protocol Attack vectors from the Other Attack type list.

Environment

  • BIG-IP AFM module is provisioned

Cause

GRE flood traffic is suspected to be hitting the BIG-IP system.

Recommended Actions

To mitigate GRE flood attack, you can configure the detection and rate limit/mitigation thresholds for the IP Unknown Protocol attack type. To do so, perform the following procedure:

Impact of procedure: Depending on your application environment, you would need to determine the threshold values acceptable for your application environment.

  1. Log in to the Configuration utility
  2. Navigate to page appropriate for your BIG-IP version:

    BIG-IP AFM 14.x

    Security  >  DoS Protection > Device Protection

    BIG-IP AFM 13.x

    Security  >  DoS Protection > Device Configuration > Network Security

    BIG-IP AFM 12.x

    Security  >  DoS Protection > Device Configuration

  3. Click IP Unknown Protocol attack type to expose its properties
    • BIG-IP AFM 14.x

      Click Network to expose this attack type.

    • BIG-IP AFM 12.x through 13.x

      Click the Add icon (+) next to the Other category to expose this attack type. 

  4. Modify the values for the following settings acceptable to your application environment:
    • BIG-IP 13.x and later
      • Detection Threshold EPS*
      • Detection Threshold %
      • Mitigation Threshold EPS
    • BIG-IP 12.x
      • Detection Threshold PPS*
      • Detection Threshold Percent
      • Rate Limit
  5. To save the changes, 
    • BIG-IP AFM 14.x

      Click Commit Changes to System.

    • BIG-IP AFM 12.x through 13.x

      Click Update.

For BIG-IP AFM DoS Protection Device Configuration, the thresholds and rate limit values are applied per Traffic Management Microkernel (TMM). For more information, refer to K15023: The BIG-IP AFM system enforces configured thresholds and limits for each TMM. 

* For Detection Threshold EPS/PPS value, as a sample possible value, allow an acceptable value to accommodate expected increase of this type of traffic. For example, if the stats rate value has an average value of 5000 packets per second, and there are four TMMs in the BIG-IP AFM being configured, and the Detection Threshold EPS/PPS value is set to 8000, this allows the BIG-IP AFM to potentially handle a total of 31996 GRE flood packets before BIG-IP AFM detects the IP Unknown Protocol attack vector. However, if one of the TMM exceeds the Detection Threshold EPS/PPS value of 8000, for example 8100, the BIG-IP AFM detects the GRE flood attack and generates a log similar to the following example in the /var/log/ltm file:

err tmm1[21964]: 01010252:3: A Enforced DOS attack start was detected for vector IP uncommon proto, Attack ID 480207285.

When the GRE flood attack traffic falls below the Detection Threshold EPS/PPS value, a log similar to the following example is generated in the /var/log/ltm file noting that the attack stopped and referencing the corresponding IP uncommon proto Attack ID:

notice tmm1[21964]: 01010253:5: A Enforced DOS attack has stopped for vector IP uncommon proto, Attack ID 480207285.

Additional Information

  • All protocols except TCP/UDP/ICMPv4/ICMPv6/SCTP - bits 1/6/17/58/132 - are uncommon. For example in Wireshark, filter ip.proto == 6 to filter IP traffic that has a TCP Payload.
  • GRE Protocol number is 47.
