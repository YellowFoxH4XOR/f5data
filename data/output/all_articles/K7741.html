Topic

This article applies to BIG-IP GTM and Link Controller 9.x through 10.x. For information about other versions, refer to the following article:

  • K13827: Associating virtual servers with link objects (11.x - 12.x)

A BIG-IP GTM and BIG-IP Link Controller server object contains one or more virtual servers that are used in wide IP load-balancing pools. When the virtual server is created on the BIG-IP GTM or BIG-IP Link Controller, it is automatically associated with a link. The link represents the physical connection to the internet.

The BIG-IP GTM and BIG-IP Link Controller use the following logic to automatically associate a virtual server and a link:

  • The BIG-IP GTM and BIG-IP Link Controller associates the virtual server with the link by matching the subnet addresses of the virtual server, link, and self IP address. Most of the time, the virtual server is associated with the link that is on the same subnet as the self IP address.
  • In some cases, the BIG-IP GTM and BIG-IP Link Controller cannot associate the virtual server and link because the subnet addresses do not match. When this issue occurs, the BIG-IP GTM associates the virtual server with the default link, which is assigned to the datacenter. This association may cause issues if the link that is associated with the virtual server does not provide network connectivity to the virtual server.

If the virtual server is associated with a link that does not provide network connectivity to that virtual server, the BIG-IP GTM and BIG-IP Link Controller may incorrectly return the virtual server IP address in the DNS response to a wide IP query, even if the link is disabled or marked as down.

The following example BIG-IP GTM configuration provides answers for queries to the www.example.com wide IP:

// *** Link Definitions (2) ***link { // datacenter=examplename "example1"address 172.16.1.1isp "example1"monitor "bigip_link"}link { // datacenter=examplename "example2"address 172.16.2.1isp "example2"monitor "bigip_link"}//***Server Definitions****server { // datacenter=example, #VS=2name "nucleus.example.com"type genericbox {address 172.16.41.2address 172.16.42.2unit_id 1}monitor "gateway_icmp"vs {name "example_www1"address 172.16.41.2:80 // httplink "example1"}vs {name "example_www2"address 172.16.42.2:80 // httplink "example2"}}// *** Pool Definitions (1) ***pool {   name           "http_pool"   ttl            30   monitor all "http"   preferred      rr   alternate      null   member         172.16.1.2:80   member         172.16.2.2:80}// *** Wide IP Definitions (1) ***wideip {   name         "www.example.com"   pool_lbmode  ga   pool         "http_pool"}

The following table details the effects on the example configuration if certain links are marked as down or are disabled:

LinkResult
example2The virtual server IP address 172.16.42.2 will no longer be returned as an A record response for DNS queries matching www.example.com.
example1The virtual server IP address 172.16.41.2 will no longer be returned as an A record response for DNS queries matching www.example.com.
example1 and example2The BIG-IP GTM will return any A records for www.example.com from BIND using the Return to DNS load-balancing method.

Note: To change a virtual server / link association, you must manually edit the wideip.conf file. After manually editing the wideip.conf file, you must load the configuration by using the gtmload command, and then restart the BIG-IP GTM by using the bigstart restart gtmd command. For assistance in manually editing the wideip.conf file, contact F5 Technical Support.
