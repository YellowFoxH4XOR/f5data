Description

On TMSH, it is possible to specify snatpool (LTM) without "type snat" option. But when missing "type snat" option, specified snatpool object (LTM) is not applied on the virtual server and as a result no source-address-translation will happen.

 

root@(bigip1)(cfg-sync Standalone)(Active)(/Common)(tmos)# list ltm virtual http_vs source-address-translation { type pool }
ltm virtual http_vs {
    source-address-translation {
        pool none
        type none
    }
}
root@(bigip1)(cfg-sync Standalone)(Active)(/Common)(tmos)# list ltm snatpool my_snatpool
ltm snatpool my_snatpool {
    members {
        192.168.20.175
    }
}
root@(bigip1)(cfg-sync Standalone)(Active)(/Common)(tmos)# modify ltm virtual http_vs source-address-translation { type none pool my_snatpool }		<=== !!! no error is thrown on TMSH
root@(bigip1)(cfg-sync Standalone)(Active)(/Common)(tmos)# list ltm virtual http_vs source-address-translation { type pool }
ltm virtual http_vs {
    source-address-translation {
        pool none			<=== !!! pool "my_snatpool" is not set, as previous command did not have "type snat".
        type none
    }
}
root@(bigip1)(cfg-sync Standalone)(Active)(/Common)(tmos)#

 

On TMSH, it is possible to specify lsn-pool (CGNAT) without "type lsn" option. But when missing "type lsn" option, specified lsn-pool object (CGNAT) is not applied. No source-address-translation will happen, either.

 

root@(bigip1)(cfg-sync Standalone)(Active)(/Common)(tmos)# list ltm lsn-pool my_lsnpool
ltm lsn-pool my_lsnpool {
    egress-interfaces {
        internal
    }
    egress-interfaces-enabled
    members {
        192.168.20.129/32
    }
}
root@(bigip1)(cfg-sync Standalone)(Active)(/Common)(tmos)# list ltm virtual http_vs2 source-address-translation { type pool }
ltm virtual http_vs2 {
    source-address-translation {
        pool none
        type none
    }
}
root@(bigip1)(cfg-sync Standalone)(Active)(/Common)(tmos)# modify ltm virtual http_vs2 source-address-translation { type none pool my_lsnpool }		<=== !!! no error is thrown on TMSH
root@(bigip1)(cfg-sync Standalone)(Active)(/Common)(tmos)# list ltm virtual http_vs2 source-address-translation { type pool }
ltm virtual http_vs2 {
    source-address-translation {
        pool none			<=== !!! pool "my_lsnpool" automatically changes to "none", as "type lsn" was not specified on previous modify command.
        type none
    }
}
root@(bigip1)(cfg-sync Standalone)(Active)(/Common)(tmos)#

 

In each cases, error log is recorded on "/var/log/ltm" while running TMSH modify command. But no warning message is shown on TMSH while running modify command.

Apr 27 10:44:39 bigip1.local err mcpd[6470]: 01071753:3: The source address translation type (none) cannot support pool attribute (/Common/my_snatpool).
Apr 27 10:48:33 bigip1.local err mcpd[6470]: 01071753:3: The source address translation type (none) cannot support pool attribute (/Common/my_lsnpool).

 

Environment

  • Configure virtual server source-address-translation property on CLI (TMSH) without specifying "type" option.

 

Cause

Bug ID2288617.

 

Answer/Recommended Actions

While configuring source-address-translation on TMSH, make sure to set appropriate "type" value ("automap", "lsn", or "snat").
GUI does not have this problem, as it is necessary to select "Type" option before trying to specify SNAT/LSN pool object.

 

Additional Information
