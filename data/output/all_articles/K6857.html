Known Issue

This is the result of a known issue. Secure Sockets Layer (SSL) clients with a small maximum segment size (MSS) during the initial SSL handshake can cause the Cavium Accelerator to stall.

This issue occurs when a small MSS is used by the client during the initial handshake and the client is sending multiple records (responsible for ensuring data security and integrity), in which each record is filtered by the system. If a new record is received before the current record can be cleared from the filter, a bad request is then queued to the Nitrox driver—the driver responsible for operating the Cavium accelerator.

This causes the Nitrox queue to stall, effectively stopping all traffic on a single Cavium system.

F5 Product Development tracked this issue as CR70819 and CR70682, and the issue was fixed in BIG-IP LTM 9.2.5, 9.3, and 9.4. For information about upgrading, refer to the BIG-IP LTM Release Notes.
