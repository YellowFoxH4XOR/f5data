Topic

You should consider using this procedure under the following condition:

  • You want to configure the BIG-IP system to send audit data to either Terminal Access Controller Access-Control System Plus (TACACS+) or RADIUS accounting server(s).

Description

When you make changes to the BIG-IP system configuration using the TMOS Shell (tmsh) or the Configuration utility, the BIG-IP system logs the changes in audit event messages to /var/log/audit. The follow are examples of logged audit events:

  • When you create, modify, delete or change the configuration of objects, such as virtual servers and load balancing pools
  • When users log in or out of the BIG-IP command line or the Configuration utility

The system can transmit these messages to a remote accounting server following the accounting protocol specifications. This can result in truncation or segmenting of the message to the accounting server. The system continues to writes complete messages to the /var/log/audit file. When the connection to the remote auditing server is lost, the system does not transmit messages however it continues to write them to /var/log/audit.

For RADIUS up to the first 255 UTF-8 formatted characters (each one byte/octet) of each message are included with the string "TRUNCATED" postpended if truncation occurs. This is transmitted as the value for the attribute "F5-LTM-Audit-Msg" and results in a total length of no more than 253 octets as required by the protocol. For example see below:

Wed Aug  5 14:20:44 2020
        NAS-IP-Address = 1.2.3.4
        Acct-Status-Type = Interim-Update
        Acct-Session-Id = "F5-BIGIP-AUDIT-FORWARDER"
        F5-LTM-Audit-Msg = "Aug  5 07:20:44 bigip1 notice mcpd[5183]: 01070417:5: AUDIT - client tmui, user steve - transaction #1127530-4 - object 0 - create { pool_member { pool_member_pool_name \"/Common/example_pool\" pool_member_node_name \"/Common/1.1.1.1\" poTRUNCATED"
        Event-Timestamp = "Aug  5 2020 14:20:44 UTC"
        Tmp-String-9 = "ai:"
        Acct-Unique-Session-Id = "3816b155ef596fdf8744e274ed421e8a"
        Timestamp = 1596637244

For TACACS+ the entire message is sent as the reason attribute value in conjunction with the cmd_acct event. If the message length is greater than 255 characters/bytes, it is segmented into multiple attribute/value pairs with the first labeled "reason=", the next "reason1=" and so on until the entire message has been segmented. For example see below:

Aug  5 14:49:24 2.3.4.5      root    unknown unknown update  service=system protocol=ip      task_id=3       start_time=1596638964   event=cmd_acct  reason=Aug  5 07:49:24 bigip1 notice tmsh[31366]: 01420002:5: AUDIT - pid=31366 user=root folder=/Common module=(tmos)# status=[Command OK] cmd_data=save / sys config partitions all
ool" pool_update_status 1 } } [Status=Command OK]
tart="Wed Au    reason1=g  5 07:49:02 2020".

By default, the system sends audit messages to only one destination. Starting in BIG-IP 11.6.0, you can control audit message destinations using the config.auditing.forward.multiple database variable. This database variable has three options: broadcast, failover and none (default value).

If you want the BIG-IP system to send audit data to multiple destination addresses, you must modify the config.auditing.forward.multiple database variable to either broadcast or failover.

When you set the database variable to broadcast, the BIG-IP system sends audit messages to all destinations.

When you set it to failover, the BIG-IP system sends the message to the first destination. If that fails, the system then tries the next destination until it finds a successful destination, or fails all destinations. Note that RADIUS servers do not support setting the database variable to failover, because RADIUS typically uses User Datagram Protoco (UDP) as its underlying transport layer. As a result, for RADIUS servers, the BIG-IP system treats the database variable as none when it is set to failover.

When the BIG-IP system fails to send the audit message, the system logs errors similar to the following example in the /var/log/ltm file:

err audit_forwarder: ConnFailed: conn to 192.168.100.100 timed out
err audit_forwarder: SendFailed: sending to 192.168.100.100 failed

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You configured either a TACACS+ or RADIUS remote accounting server.
  • The connection between the BIG-IP system and the remote server uses the following ports:
    • TACACS+ accounting server must use TCP port 49.
    • RADIUS accounting server must use UDP port 1813.

Procedures

  • Enabling remote audit logging for single destination
  • Enabling remote audit logging for multiple destinations
  • Disabling remote audit logging

Enabling remote audit logging for single destination

To enable remote audit logging on the BIG-IP system for single destination, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to System > Logs > Configuration > Options.
  3. Under Audit Logging, on the tmsh list, select Enable.
  4. Select Update.
  5. Log in to tmsh by entering the following command from the BIG-IP command line:

    tmsh

  6. To set the destination IP address of your accounting server, enter the following command syntax:

    modify sys db config.auditing.forward.destination value <IP address>

    Note: This address can be either an IPv4 or IPv6 address.

    In the following example, the command sets the destination to 192.168.100.100:

    modify sys db config.auditing.forward.destination value 192.168.100.100

  7. To set the secret string for your accounting server, enter the following command syntax:

    modify sys db config.auditing.forward.sharedsecret value <secret string>

    In the following example, the command sets the secret to mysecret:

    modify sys db config.auditing.forward.sharedsecret value mysecret

  8. To set the auditing server type, enter the following command syntax:

    modify sys db config.auditing.forward.type value <radius | tacacs+ | none>

    In the following example, the command sets the auditing servers to tacacs+:

    modify sys db config.auditing.forward.type value tacacs+

  9. To permanently save these options, enter the following command:

    save /sys config

Enabling remote audit logging for multiple destinations

To enable remote audit logging on the BIG-IP system for multiple destinations, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to System > Logs > Configuration > Options.
  3. Under Audit Logging, on the tmsh list, select Enable.
  4. Select Update.
  5. Log in to tmsh by entering the following command from the BIG-IP command line:

    tmsh

  6. To configure the system to send audit messages to multiple destinations, enter the following command syntax:

    modify sys db config.auditing.forward.multiple value <broadcast | failover | none>

    Note: Setting the value to none restricts the system to sending to only one destination. This is the default behavior.

    In the following example, the command configures the system to broadcast to all configured destinations:

    modify sys db config.auditing.forward.multiple value broadcast

  7. To set the destination IP address of your accounting servers, enter the following command syntax:

    modify sys db config.auditing.forward.destination value <IP address 1,IP address 2,...>

    In the following example, the command configures the system to send audit messages to 192.168.100.100 and 192.168.100.101:

    modify sys db config.auditing.forward.destination value 192.168.100.100,192.168.100.101

    Note: This address can be either an IPv4 or IPv6 address.

  8. To set the secret string for your accounting servers, enter the following command syntax:

    modify sys db config.auditing.forward.sharedsecret value <secret string>

    In the following example, the command sets the secret to mysecret:

    modify sys db config.auditing.forward.sharedsecret value mysecret

  9. To set the auditing servers type, enter the following command syntax:

    modify sys db config.auditing.forward.type value <radius | tacacs+ | none>

    In the following example, the command sets the auditing servers to tacacs+:

    modify sys db config.auditing.forward.type value tacacs+

  10. To permanently save these options, enter the following command:

    save /sys config

Disabling remote audit logging

To disable auditing on the BIG-IP system, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Configuration utility.
  2. Go to System > Logs > Configuration > Options.
  3. Under Audit Logging, in the tmsh list, select Disable.
  4. Select Update.
  5. Log in to tmsh by entering the following command from the BIG-IP command line:

    tmsh

  6. Enter the following command:

    modify sys db config.auditing.forward.type value none

  7. To permanently save this option, enter the following command:

    save /sys config
