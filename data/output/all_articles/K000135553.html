K000135553: Change the log level of DNS Controller without restarting the pod

Type
Support Solution
Published
2023-07-21
Updated
2023-07-21
Applies to
  • Aspen Mesh: 1.14
Source
https://my.f5.com/manage/s/article/K000135553

Description

Logging level for DNS Controller can be set when installing the feature by defining the level in the values file however if you need to increase or reduce the logging level for troubleshooting purposes you can do it on the fly i.e. without restarting the DNS controller pod after a helm upgrade.

# This section can be modified while installing the DNS controller to
# set the logging level. It controls the amount of logging emitted by the
# dns-controller. Valid values are debug, info, warn, and error.
loggingLevel: info

 

Environment

  • Aspen Mesh 1.14.6-am4
  • DNS Controller


Cause

Logging level may need to be changed without restarting the DNS Controller pod for troubleshooting purposes.


Recommended Actions

Identify the current DNS-controller pod leader

In order to identify the current leader we need to get the lease name first and then we can get the name of the pod that is working as leader. In this example the DNS Controller was installed on the dns-controller namespace. 
❯ kubectl get lease -n dns-controller
NAME                                 HOLDER                                                                 AGE
dnscontrollerinstance.aspenmesh.io   dns-controller-65b66d485c-rdpft_a7b47cee-ea85-4ee5-aac1-abf29a4da56e   51m

##dnscontrollerinstance.aspenmesh.io is the lease name and it's used in the next command

❯ kubectl get lease -n dns-controller dnscontrollerinstance.aspenmesh.io -o json | jq -r '.spec.holderIdentity' | gawk 'match($0, /^(.*)_.*$/, a) { print a[1] }'
dns-controller-65b66d485c-rdpft

##dns-controller-65b66d485c-rdpft is the name of the pod that is currently working as a leader​​​​​

 

Forward a local port to the DNS Controller leader pod

We need to forward a local port to the DNS Controller leader pod to be able to change the logging level. Using the pod name identified in the previous step, we need to do the following in a new terminal window: 
❯ kubectl port-forward dns-controller-65b66d485c-rdpft -n dns-controller 8080
Forwarding from 127.0.0.1:8080 -> 8080
Forwarding from [::1]:8080 -> 8080

 

Send a request using cURL to the /log/level endpoint to review and/or change the logging level

We can send a GET request to view the current logging level and a PUT request to change the logging level 
❯ curl http://localhost:8080/log/level ##curl defaults to GET method if none is specified with -X
{"level":"info"} ## current level = info

❯ curl -X PUT http://localhost:8080/log/level -d level="debug"
{"level":"debug"} ## level changed to debug

❯ curl http://localhost:8080/log/level
{"level":"debug"} ## confirm level was changed to debug

❯ curl -X PUT http://localhost:8080/log/level -d level="info"
{"level":"info"} ## changing the level back to info

❯ curl http://localhost:8080/log/level
{"level":"info"} ## level changed back to info
In the other terminal window where the port-forwarding is running you will see a new line for each submitted request 
❯ kubectl port-forward dns-controller-65b66d485c-rdpft -n dns-controller 8080
Forwarding from 127.0.0.1:8080 -> 8080
Forwarding from [::1]:8080 -> 8080
Handling connection for 8080
Handling connection for 8080
Handling connection for 8080
Handling connection for 8080
Handling connection for 8080
