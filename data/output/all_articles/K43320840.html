Known Issue

The system fails to load the configuration when the cluster management IP is not defined, and instead uses the address list.

This issue occurs when all of the following conditions are met:

  • You have set up the cluster with multiple blades.
  • You have assigned no management IP to individual blades.
  • You have assigned the cluster management IP address list to the cluster of blades.

Impact

After you reboot the system, the configuration fails to load on the secondary blades.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • In a cluster setup with multiple blades, if you do not assign management IP addresses to individual blades, but instead assign a cluster management IP address list to the cluster of blades, the configuration load fails.
  • The system posts an error message similar to the following example:

    err mcpd[24235]: 01071824:3: The address list is referenced by one of the rules of the admin IP either directly or in a nested manner, and the entry is of a different address family from that of the Admin IP.

Resolution

Status

F5 has confirmed that this issue exists in the products listed in the Applies to (see versions) box, located in the upper-right corner of this article. Workaround

To work around this issue, you can define the cluster management IP address as the destination (in rule) without using an address list.
