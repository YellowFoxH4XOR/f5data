Issue

Beginning in BIG-IP 10.2.1 and Enterprise Manager 2.1.0, the image2disk utility --instslot and --format options are mutually exclusive. If you attempt to invoke the image2disk utility specifying both options, the system returns an error message that appears similar to the following example:

Terminal error: You cannot specify the target location when using the format option.

If you want the disks to be formatted before the installation is performed, specify only the --format option. Because the format operation destroys all current boot locations, and a standard set of boot locations (suitable for your platform) are created by the install process, the utility installs the software to the first available location after formatting.

For example, if you run the following command on a single-drive BIG-IP system, the software installs on HD1.1:

image2disk --format=volumes BIGIP-10.2.1.297.0.iso

Note: This change in behavior was introduced because the image2disk utility erroneously validates the target location when invoked with the --format option. For more information, refer to: K10380: The image2disk utility erroneously validates the target location when the --format option is specified.

Note: In all versions prior to BIG-IP 10.2.1 and Enterprise Manager 2.1.0, the --instslot option is mandatory, and must be specified whenever the image2disk utility is invoked.

Note: You do not need to run BIG-IP 10.2.1 or Enterprise Manager 2.1.0 for the new behavior to apply. If you upgrade to one of these versions, the new behavior applies; the image2disk utility upgrades itself to a newer version if one is found in the installation repository.
