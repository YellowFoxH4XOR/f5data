K000151125: Services with 'LoadBalancer' Type Used To Expose NGINX Ingress Controller May Fail to Receive External IP Addresses

Type
Support Solution
Published
2025-05-01
Updated
2025-06-02
Applies to
  • NGINX Products
  • NGINX Ingress Controller: 5.0.X, 5.0.0
Source
https://my.f5.com/manage/s/article/K000151125

Description

You created a service with 'LoadBalancer' type to expose the NGINX Ingress Controller's pods, but you noticed no External IP address was assigned:

# kubectl get svc example-svc
NAME          TYPE           CLUSTER-IP      EXTERNAL-IP   PORT(S)                      AGE
example-svc   LoadBalancer   10.0.0.1        <pending>     80:31146/TCP,443:32150/TCP   1d

 

Environment

  • NGINX Ingress Controller  
  • A service with 'LoadBalancer' type created to expose the NGINX Ingress Controller's pods

Cause

  • Kubernetes services of type `LoadBalancer` rely on the underlying infrastructure (typically a cloud provider) to automatically provision and assign an external IP address. In environments without such integration (e.g. on-premises clusters) external IP addresses are not assigned automatically.

Recommended Actions

  • If the 'LoadBalancer' service type is not supported in your environment, you can create a service of type NodePort.  (See related documentation)
  • If you want to assign external IP addresses manually to the 'LoadBalancer' service, you can try any of the following:
    • For Helm deployments, use the parameter 'controller.service.externalIPs' to specify external IP address(es) manually.   (see related documentation) 
    • You may also use the below command to add the external IP address(es) manually: 
      kubectl patch svc <SERVICE_NAME> -p '{"spec": {"type": "LoadBalancer", "externalIPs":["10.0.0.1"]}}'

NOTE: Replace '10.0.0.1' with an IP address in your environment (e.g. IP address of your K8S Master Node)
