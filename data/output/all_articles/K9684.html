K9684: Users cannot save user-defined favorites

Topic

Two types of FirePass users exist: local and external. Account information for local users is stored in the FirePass user database. Account information for external users is stored on an external server, such as an Active Directory server. When you create a master group that uses an external authentication server, you can still set the user type to Local. The primary purpose of this functionality is to enable users to create their own FirePass favorites for use in subsequent sessions. 

Important: External users cannot create custom favorites.
 
When a local user logs on to the FirePass website for the first time, the user may be unable to save user-defined favorites. This behavior occurs when the following conditions are met:
 
  • The master group uses an external authentication server
  • The Bypass signup by template form and enter user information later check box is selected for the user’s master group

    Note: The Bypass signup by template form and enter user information later check box is located on the Users: Groups: Master Groups page under the Signup Templates tab.
 
Workaround
 
Users can work around this behavior by logging out of their current FirePass session and opening a new FirePass session.
 
Additionally, you can prevent this behavior by clearing the Bypass signup by template form and enter user information later check box in the master group configuration. Users who do not already exist in the FirePass user database will be prompted to enter their account details, such as name and email address, the first time they successfully authenticate. Once the user enters their account information, the user can define and save custom favorites.
