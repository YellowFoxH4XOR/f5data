Description
TMM logs clock advanced messages and tmm core files are found in /var/core

You may see messages similar to the following in /var/log/ltm

  • Jan 5 06:29:18 ltm1.example.com notice tmm[6779]: 01010029:5: Clock advanced by 271 ticks
  • Jan 5 23:10:05 ltm1.example.com warning sod[6427]: 01140029:4: HA daemon_heartbeat tmm fails action is go offline down links and restart.
  • Jan 6 18:10:59 ltm1.example.com notice tmm[20262]: 01010338:5: Virtual /Common/http_respond iRule /Common/responder <HTTP_REQUEST> execution ran for 631 ticks (192.0.2.5:38169 -> 198.51.100.8:80 TCP)

Environment

  • iRule performing expensive processing, for example:

    • a large number of if and/or elseif expressions

    • a large switch expression

    • using expensive operations such as regular expressions

    • a loop over a large list or nested loops

Cause
While processing an iRule, unless interrupted by certain commands that pause iRule execution, TMM is unable to update its heartbeat. This can cause the heartbeat to fail, which causes sod to kill TMM using a signal which causes TMM to dump core. 

Recommended Actions

  1. Avoid regular expressions when glob matches or less expensive operators such as starts_with, ends_with, or contains would suffice.
  2. If you are matching against a large number of values, consider using data groups and the class iRule command, which is faster than matching values individually.
  3. Use the IP::addr iRule command to match IP addresses or subnets.
