K000140774: Resolving APM Policy Sync Loop and Configuration Load Errors

Type
Support Solution
Published
2025-03-10
Updated
2025-03-10
Applies to
  • BIG-IP
  • BIG-IP APM: 15.1.10
Source
https://my.f5.com/manage/s/article/K000140774

Description

A policy sync operation on BIG-IP APM VE devices may get stuck in a "Sync Initiate" status loop. Attempts to reload the configuration can fail with the following error message:

01070712:3: failed in syscall link(/config/filestore/files_d/SSL_VPN_d/policy_sync_d/:SSL_VPN:<policy_name>:<file_name>, /config/filestore/.trash_bin_d/.current_d/SSL_VPN_d/policy_sync_d/:SSL_VPN:<policy_name>:<file_name>) errno=(No such file or directory)  
Unexpected Error: Loading configuration process failed.

Additionally, disk space-related errors such as the following may appear:

01070734:3 Configuration error: Total disk space occupied by sandbox files cannot exceed 536870912 bytes

These issues prevent successful synchronization of APM policies between devices.

Environment

  • BIG-IP APM 
  • 15.1.10 
  • Sync-Only Device Group

Cause

The issue occurs due to stale or incomplete references to apm policy psync-* objects in the /config/bigip.conf file. These references point to missing files that no longer exist on the system, causing errors during configuration reloads and preventing successful synchronization. 

Recommended Actions

  1. Create a UCS backup of your BIG-IP system and store it externally: tmsh save /sys ucs <backup_filename>.ucs
  2. Make a local backup of the /config/bigip.conf file: cp /config/bigip.conf /config/bigip.conf.<current_date>
  3. Search for all apm policy psync-* entries in the /config/bigip.conf file: cat /config/bigip.conf | grep "apm policy psync-*"
  4. Open the /config/bigip.conf file using a text editor (e.g., vi, nano) or an external editor like Sublime Text or Notepad++ via an FTP client (e.g., WinSCP). Avoid using basic Notepad as it may introduce formatting issues.
  5. Delete all lines referencing apm policy psync-*.
  6. If you encounter errors related to missing files during configuration reload, create dummy files for each missing reference using the following command format: touch <path_to_missing_file>. For example: touch /config/filestore/files_d/SSL_VPN_d/policy_sync_d/:SSL_VPN:<policy_name>:<file_name>
  7. Reload the system configuration after making changes: tmsh load sys config
  8. Check if the sync status is resolved and ensure there are no further errors: show cm sync-status
