Description

  • Unable to load configuration
  • A message similar to the following  can be seen on /var/log/ltm

    Self-device config sync address cannot reference the non-existent Self IP (10.0.0.1); Create it in the /Common folder first.

Environment

  • LTM
  • HA pair

Cause

The config sync self-ip address is not defined/configured on bigip_base.conf

Recommended Actions

Add self-ip address in question to bigip_base.conf

  1. Connect to CLI
  2. Edit bigip_base.conf and add the following

    net self self_1nic {
        address 10.0.0.1/24
        allow-service {
           default
        }
       traffic-group traffic-group-local-only
       vlan internal
    }

    Note: replace 10.0.0.1 with the IP indicated in the error message

  3. Save the changes
  4. Load the configuration

    tmsh load sys config



Additional Information
*It may be possible to add the missing selfip from the webui.

Alternatively, you can resolve this issue with the following workaround:

  1. Backup /config/bigip_base.conf: cp /config/bigip_base.conf /config/bigip_base.conf-ORIG
  2. Edit the /config/bigip_base.conf, and remove the following line:  configsync-ip 10.0.0.1
  3. Verify bigip_base.conf loads: tmsh load sys config verify
  4. Reload configuration: tmsh load sys config

Please note that if you are migrating a ucs onto another appliance with an existing device trust configuration you may have to remove the configsync-ip a couple of times.

*You will also need to set a proper configsync ip from the device trust menu if you wish to restore configsync functionality after restoring your configuration.
