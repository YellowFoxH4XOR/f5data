Known Issue

This is the result of a known issue. Use of the HTTP::redirect/respond event in an iRule on a request that is split among multiple packets may erroneously forward the request to the server.

In order for this issue to occur, an iRule with the HTTP::redirect/respond event must be associated with a virtual server with an SSL profile. With this configuration, requests can be broken up among multiple packets when encryption is used.

The issue occurs when the iRule attempts to access the header information within the packet after the BIG-IP LTM has already passed the packet to the server.

For example, the following list illustrates the sequence of events in a connection flow that would trigger this issue:

  • A virtual server receives a connection
  • The virtual server is using an SSL profile with an HTTP POST whose headers and body are contained in separate records
  • The SSL profile receives the end of the header record and entire body record in a single packet
  • The SSL profile decrypts the record packets and passes them to the iRule engine
  • The iRule engine receives the first packet that does not contain all of the headers, and passes the packet to the server
  • The second packet, which contains the end of the headers as well as the body content, is passed to the iRule engine
  • The iRule HTTP::redirect/respond event is fired to read the headers

Since the system already passed the first packet, which contained most of the headers, the known issue occurs.

Note: The issue is further compounded in some versions, such as BIG-IP LTM 9.3 and 9.3.1, if cookie persistence is used. This will cause the system to access the headers during the connection, if the packet is erroneously forwarded to the server before the system can review the headers. As a result, TMM may crash.

F5 Product Development tracked this issue as CR99895 and it was fixed in BIG-IP version 10.0.0. For information about upgrading, refer to the BIG-IP LTM release notes.

Additionally, this issue was fixed in Hotfix-BIG-IP-9.3.1-HF3 issued for BIG-IP version 9.3.1. You may download this hotfix or later versions of the hotfix from the F5 Downloads site.
