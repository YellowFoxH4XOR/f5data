Topic

You should consider using this procedure under the following condition:

  • You want to mitigate User Datagram Protocol (UDP) flood traffic through the BIG-IP system.

Description

UDP is a standard protocol for communication across IP networks, but, as UDP packets are stateless, they have less error checking and validation compared to TCP. A UDP flood attack attempts to overload a server with requests by saturating the connection tables on every accessible port on a server.

Filling the connection table with these requests prevents valid requests from being served, and the server can become inaccessible to valid clients.

The BIG-IP system has a packet filter feature to prevent UDP floods from reaching a virtual server, virtual address, or a self-IP at the VLAN level.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have administrator access to the BIG-IP Configuration utility.
  • You have access to the Advanced Shell (bash).

Procedures

To achieve this mitigation, perform the procedures:

  • Determining the source of UDP flood traffic using a packet capture
  • Creating a packet filter rule
  • Reviewing packet filter files

Determining the source of UDP flood traffic

You can determine the source of the UDP flood traffic using several methods. For example, you can determine the source externally using a report from an external monitoring tool or a packet capture. You may also be able to determine this using the BIG-IP system during an actual UDP flood traffic event in which a packet capture may be beneficial to understand the type of payload and datagram size of the UCP traffic being flooded to the BIG-IP system.

  1. Log in to bash.
  2. Run a packet capture using tcpdump utility by typing the following command.

    tcpdump -nni 0.0:nnn udp -s0 -w /var/tmp/udp_flood.pcap -C 5 -W 2 -vv

    The following notes from tcpdump man page may help explain the previous command options:

    -n, nn, or nnn: Capture with increasing amounts of internal debugging information, appended to the end of each packet. This requires the use of -s0 to actually acquire and display the information.

    -C: Before writing a raw packet to a savefile, check whether the file is currently larger than file_size and, if so, close the current savefile and open a new one. Savefiles after the first savefile have the name specified with the -w flag, with a number after it, starting at 1 and continuing upward. The units of file_size are millions of bytes (1,000,000 bytes, not 1,048,576 bytes).

    -W: Used in conjunction with the -C option, this limits the number of files created to the specified number and begins overwriting files from the beginning, thus creating a rotating buffer. In addition, it names the files with enough leading 0s to support the maximum number of files, allowing them to sort correctly.

    -s Snarf snaplen bytes of data from each packet rather than the default of 65535 bytes. Setting snaplen to 0 sets it to the default of 65535 for backwards compatibility with recent older versions of tcpdump.

  3. Use the tshark command to determine the top source IP addresses sending the UDP traffic and which VLAN is sending the traffic. Type the following command:

    tshark -nnnr /var/tmp/udp_flood.pcap1 -T fields -e ip.src -e vlan.id | sort -rn | uniq -c | sort -rnk 1

    Note: You can also use Wireshark to review the packet capture and determine the top source IP addresses and VLAN.

    Output appears similar to the following:

Creating a packet filter rule

Impact of procedure: Configuring packet filter rules that are inappropriate for your environment may result in traffic disruption.

Note: Changing the default value of the Unhandled Packet Action property can produce unwanted consequences. Before changing this value to Discard or Reject, make sure that any traffic that you want the BIG-IP system to accept meets the criteria specified in your packet filter rules.

Packet filters enhance network security by specifying whether a BIG-IP system interface should accept or reject certain packets based on criteria that you specify. Packet filters enforce an access policy on incoming traffic. They apply to incoming traffic only. This complements the BIG-IP default deny, in which an additional layer of protection to is available to BIG-IP listeners.

Packet filter rules require the protocols, source hosts and networks, destination hosts and networks and destination port information in order to create the rule.

Creating a packet filter using the Configuration utility

  1. Log in to the Configuration utility.
  2. Navigate to Network > Packet Filters > General.
  3. Set Packet Filtering to Enabled.
  4. Click Update.
  5. Navigate to Network > Packet Filters > Rules.
  6. Click Create.
  7. Provide the following information on the rule creation page:
    • Under Configuration, provide a descriptive name for the packet filter rule. For example, block_source_UDP.
    • For Order, click the order in which the system applies the packet filter if you configure more than one packet filter rule. For example, First.
    • For Action, set to Discard. This setting specifies how the system should process a packet that matches the criteria specified in the packet filter rule.
    • For VLAN / Tunnel, click the appropriate VLAN name. This is the VLAN on which the UDP flood traffic is arriving.
    • For Logging, click Enabled for troubleshooting and verifying the action taken by the packet filter.
    • Under Filter Expression , for Filter Expression Method, click Build Expression.
    • For Protocols, click UDP.
    • For Source Hosts and Networks from the previous procedure, Determining the source of UDP flood traffic, add the IP addresses or networks of UDP flood traffic source. For example, 192.0.2.231.
    • For Destination Hosts and Networks, if you want to deny access to certain destination or any destination, set the appropriate IP address or network address. For example, Any.
    • For Destination Port, set the destination port. For example, Any.

Creating a packet filter using tmsh

To use the TMOS Shell (tmsh) to create the same example configuration as described in the Configuration utility version, perform the following procedure:

  1. Log in to tmsh.
  2. Type the following command:

    create /net packet-filter block_source_UDP order 1 action discard rule "( proto UDP ) and ( src net 192.0.2.231 )"

  3. Type the following command:

    save sys config

    You can modify the previous example can to block UDP traffic form an entire network using the following command:

    create net packet-filter block_udp_UDP_Subnet order 1 action discard rule "( proto UDP ) and ( src net 192.0.2.0/24)"

Reviewing packet filter files

If logging is enabled, you can review the packet filter generated logs from the following locations:

Configuration utility

  1. Log in to the Configuration utility.
  2. Navigate to System > Logs > Packet Filter.

bash

  • The /var/log/pktfilter log file.

Note: It is important to disable logging after you confirm the packet filter rule is blocking the UPD flood traffic as expected because this log file can grow rapidly.
