K57044833: Declarative Onboarding fails to apply management route

Type
Support Solution
Published
2021-12-02
Updated
2023-02-21
Applies to
  • Virtual Editions
  • BIG-IP Platforms
  • F5 Automation and Orchestration
  • F5 Declarative Onboarding
Source
https://my.f5.com/manage/s/article/K57044833

Description

Declarative Onboarding fails to apply the management route specified in the declaration with the following error in /var/log/restnode.log:

finer: [f5-declarative-onboarding: restWorker.js] tryUntil error: 01070734:3: Configuration error: invalid Management Route, the dest/netmask pair 0.0.0.0/0.0.0.0 already exists for /Common/default tries left: 30

Environment

  • BIG-IP with TMOS version that is compatible and supported for Declarative Onboarding
  • A ' default' management route is configured on the BIG-IP:
sys management-route /Common/Default {
    gateway 10.192.18.1
    network default
}
  • Declarative Onboarding declaration being applied unsuccessfully has an identical management-route:
"mgmtRoute": {
    "class":"ManagementRoute",
    "gw":"10.192.18.1",
    "network":"default"
}

Cause

  • When adding a management route to the declaration the name has to match what exists on the device
  • In this case, there is an existing route named 'default' with the gateway address of 10.192.18.1 while trying to add another route named 'mgmtRoute' with the same address
  • Declarative onboarding does not support renaming a route, hence failing the declaration
  • Similar failures may be noted when the declaration has the identical name for the management route but has a different case i.e. 'default' is different to 'Default' 

Recommended Actions

Reapply the declaration with the following modification to the management route declaration:

"Default": {
"class":"ManagementRoute",
  "gw":"10.192.18.1",
  "network":"default"
}
