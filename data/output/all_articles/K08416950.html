Description
Silent boot on BIG-IP VE causes a failover. Following logs could be found on /var/log/kern.log before the reboot:

debug kernel: mlx4_en: f5slave4: Close port called
debug kernel: : [9175698.982208] mlx4_en: f5slave4: Close port called
info kernel: : [9175699.010456] hv_netvsc 000d3a8a-c51d-000d-3a8a-c51d000d3a8a eth4: Data path switched from VF: f5slave4
info kernel: : [9175699.010863] hv_netvsc 000d3a8a-c51d-000d-3a8a-c51d000d3a8a eth4: VF unregistering: f5slave4
info kernel: hv_netvsc 000d3a8a-c51d-000d-3a8a-c51d000d3a8a eth4: Data path switched from VF: f5slave4
info kernel: hv_netvsc 000d3a8a-c51d-000d-3a8a-c51d000d3a8a eth4: VF unregistering: f5slave4
notice boot_marker : ---===[ HD1.1 - BIG-IP 15.0.1 Build 0.0.11 ]===---
 

Environment

  • BIG-IP Azure Virtual Edition 
  • LTM hosted in Azure
  • Cloud Failover Extension unexpected behavior (where applicable)
  • BIG-IP VE using Accelerated Networking

Cause
Bug ID 948417: Network Management Agent (Azure NMAgent) updates causes Kernel Panic
 

Recommended Actions

  1. - Workaround: Disable Accelerated Networking on BIG-IP network interfaces (Reversed settings from Azure documentation)
  2. - Upgrade to a Fixed Version (v16.1.0)

Additional Information
None.
