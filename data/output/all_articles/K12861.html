Known Issue

The BIG-IP system does not send ARP request for the next hop network device whose ARP entry on the BIG-IP system is about to expire. This issue occurs when all of the following conditions are met:

  • The Auto Last Hop feature (Connection.AutoLasthop) is disabled
  • The affected network device does not advertise its ARP actively
  • The BIG-IP system does not have a static ARP configured for the remote network device
  • There is no new connection egressing from the BIG-IP system to the next hop network device

When this issue occurs, the BIG-IP system drops all packets except the last received packet in its buffer and forwards that packet to the next hop network device after receiving the ARP reply.

Impact

The BIG-IP system drops incoming packets.

Symptoms

As a result of this issue, you may encounter the following symptoms:

  • The BIG-IP system drops packets from existing connections
  • Packets appear to be out-of-order on the egressing end of the BIG-IP system

Workaround

To work around this issue, you can configure a static ARP entry for the affected next hop network device. To do so, perform the following procedure:

Impact of workaround: Configuring a static ARP for network devices that share an IP address for high availability gateway failover (such as HSRP) may affect their failover operation if those devices do not share a single MAC address.

  1. Log in to the BIG-IP Configuration utility.
  2. Navigate to Network > ARP > Static List.
  3. Click Create.
  4. In the IP Address box, type the IP address of the affected next hop network device.
  5. In the MAC Address box, type the MAC address of the affected next hop network device.
  6. To save the configuration, click Finished.
