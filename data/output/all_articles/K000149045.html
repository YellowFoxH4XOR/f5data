Description

When the "Sync Type" is "Manual with Full Sync" for the "Sync-Failover" device group, it's not able to sync the config after performing below actions:

  • Disassociate the security log profile from virtual server
  • Delete the security log profile
  • Perform config sync to device group

And you can see below err log in the /var/log/ltm:

err mcpd[PID]: 01070635:3: The security log profile (<log profile name>) is referenced by one or more virtual servers or Nat policy rule.

err mcpd[PID]: 01071488:3: Remote transaction for device group /Common/<Device Group> to commit id <ID> <Commit ID> /Common/<Host Name> 0 failed with error 01070635:3: The security log profile (<log profile name>) is referenced by one or more virtual servers or Nat policy rule..

Environment

  • ASM
  • Security log profile
  • Config sync

Cause

It is normal as logging profile is being removed from VS and without syncing it to the peer

Logging profile is being deleted and then synced which makes peer think that logging profile is deleted.

It is a kind of sequencing that which object is being proceed by MCPD first in the peer when config sync is received.

Recommended Actions

  • Change the "Sync Type" of the "Sync-Failover" device group to "Manual with Incremental Sync" or "Automatic with Incremental Sync" if you want to avoid this problem.

Or

  • Make a config sync before you delete the log profile if you want to keep the "Sync Type" of the "Sync-Failover" device group as "Manual with Full Sync".
