K000159905: BIG IP IP Intelligence does not work with empty feedlist

Type
Support Solution
Published
2026-02-05
Updated
2026-08-19
Status
Final
Applies to
  • BIG-IP
  • BIG-IP AFM
Source
https://my.f5.com/manage/s/article/K000159905

Description

IP Intelligence feed lists configured with HTTPS URLs fail to download. The IP Intelligence policy remains empty (0 IPs), and traffic from blacklisted IP addresses is not blocked. System logs show certificate authentication errors indicating the BIG-IP system cannot validate the feed list server's SSL certificate.

Environment

  • BIG-IP AFM (all versions)
  • IP Intelligence with external feed lists configured
  • Feed list URL using HTTPS protocol
  • Feed list server using SSL certificate signed by a CA not present in BIG-IP's default trust bundle

Cause

The dwbld daemon responsible for downloading IP Intelligence feed lists uses the system trust bundle at /etc/pki/tls/certs/ca-bundle.crt`` to validate the SSL certificate presented by the feed list server during HTTPS connections. When the server's CA certificate (root or intermediate) is not present in this trust bundle, the TLS handshake fails and the feed list cannot be downloaded, leaving the IP Intelligence policy empty and not function.

Recommended Actions

  1. Verify the issue by checking /var/log/dwbl/dwbld.log`` for errors similar to for errors similar to:

    dwbld| err|<timestamp>|<pid>|CURLER|curler|(null)|CURL failed with error Peer certificate cannot be authenticated with given CA certificates

  2. Obtain the feed list server's CA certificate chain:
    • Contact your feed list provider for the root and any intermediate CA certificates
    • Alternatively, use OpenSSL to retrieve the certificate chain:

      openssl s_client -connect <feed_list_server_hostname>:443 -showcerts

    • Save the CA certificates (not the server certificate itself) to a file
  3. Add the CA certificate(s) to the BIG-IP trust bundle:
    • Log in to the BIG-IP Advanced shell (bash) as root
    • Back up the existing ca-bundle.crt:

      cp /etc/pki/tls/certs/ca-bundle.crt /etc/pki/tls/certs/ca-bundle.crt.backup

    • Append the CA certificate(s) to ca-bundle.crt:

      cat /path/to/your_ca_certificate.crt >> /etc/pki/tls/certs/ca-bundle.crt

    • If multiple certificates are needed (root + intermediates), append each one
  4. Restart the dwbld service to apply the changes:

    tmsh restart sys service dwbld

    Note: This command does not impact traffic processing
  5. Verify the resolution:
    • Monitor /var/log/dwbl/dwbld.log`` for successful feed list download messages (errors should cease for successful)
    • Confirm the feed list file is cached in /var/dwbl/.cache/``
    • Verify the IP Intelligence policy is populated:

      tmsh show security ip-intelligence info address <known_blacklisted_ip>

    • Test that traffic from a blacklisted IP is now blocked as expected
  6. Save the configuration to preserve changes across reboots:

    tmsh save sys config

Additional Information

  • The /etc/pki/tls/certs/ca-bundle.crt`` file is used by the BIG-IP system for outbound HTTPS client connections, including those made by the dwbld daemon for IP Intelligence feed list downloads file.
  • This procedure is specific to external feed list servers and is different from configuring SSL certificates for Virtual Server SSL profiles.
  • If your feed list server's certificate changes in the future (e.g., certificate renewal with a different CA), you will need to repeat this procedure.
  • The ca-bundle.crt is overwritten during upgrades. This procedure must be re-applied after BIG-IP software upgrades.
  • For general information about updating the default CA bundle file, refer to K60612439: Manually updating the BIG-IP default CA certificate bundle file
  • For information about configuring IP Intelligence feed lists, refer to the BIG-IP AFM documentation.
