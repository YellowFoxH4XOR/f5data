Description

Virtual Server with no default pool is in an Offline/Unavailable state, but it has a traffic policy applied which forwards to a pool, and that pool is Available.

Why is the Virtual Server Offline/Unavailable?

Environment

  • Local Traffic Policy
  • Virtual Server with no default pool

Cause

Virtual Server in question has an iRule attached which references a pool, and that pool is Offline/Unavailable.

A Virtual Server's availability is not derived from the status of any pools referenced in attached traffic policies. However, it can be determined from the status of any pools referenced in attached iRules:

  • K73440174: How referenced pools in iRules affect VIP status

For example, if the following iRule is attached, and the pool my-hsl-pool is Offline/Unavailable, the Virtual Server will be unavailable as well:

ltm rule /Common/logging-irule {
    when CLIENT_ACCEPTED {
        set hsl [HSL::open -proto UDP -pool my-hsl-pool]
    }
...
}

Recommended Actions

There are several solutions to this issue.

It is recommended to investigate why the pool is being marked down and fix that, if possible.

Alternatively, use an iRule instead of a policy to forward traffic. As long as an iRule references an available pool, the virtual server will be available, even if another iRule-referenced pool is down.
