Known Issue

If the default RADIUS user role is set to something other than none, the peer system will revert to using none after running the configsync command.

F5 Networks Product Development tracked this problem as CR27477 and CR41937.

Workaround

Within the directory server, the default role entry is associated to the hostname; therefore, separate entries exist for each system.

To correct this issue, you must correct the entry for the peer BIG-IP on the primary system, but you cannot do that from the Configuration utility on the primary system.

To work around this issue, perform the following steps.

  1. Configure the default role on the primary BIG-IP.
  2. Synchronize the configuration to the peer BIG-IP.
  3. Configure the correct default role on the peer BIG-IP.
  4. Synchronize the configuration from the peer BIG-IP to the primary BIG-IP.
