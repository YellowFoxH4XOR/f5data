Known Issue

Certain health monitors may report the pool member with an incorrect status.

This issue occurs when all of the following conditions are met:

  • The BIG-IP system is configured with a pool member that is associated with at least one health monitor.
  • One of the health monitors associated with the affected pool member reports the pool member as down.

The triggering condition of this issue may vary based on the monitor type. For example, when using a TCP monitor, the TCP handshake between the pool member and the monitor succeeds, but the monitor times out. Additionally, the UDP monitor will not mark the pool member up after it was marked down from a last state check.

Impact

The affected pool member may flap or report an incorrect status.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The affected UDP monitor fails to mark a pool member up, even when the pool member is up after it legitimately marks the pool member down from the previous state check.
  • The affected TCP monitor successfully completes the TCP handshake with the pool member, but the monitor times out.
  • When the bigd process is enabled in debug mode, you view an error message in the /var/log/bigdlog file that appears similar to the following example:

    ID global:(_main_loop): Error: select: Bad file descriptor
