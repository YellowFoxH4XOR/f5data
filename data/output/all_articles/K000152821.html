Description

When configuring a BIG-IP LTM virtual server for HTTP/HTTPS traffic using round robin load balancing via the CIS controller and AS3 declarations, traffic may be consistently directed to a single pool member. This behavior mimics session persistence, even when no explicit persistence profile is configured. The issue can be observed as uneven load distribution, with repeated requests being served by the same backend server.

 

Environment

  • BIG-IP
  • AS3

 

Cause

1. Default Persistence Profile:
When no persistence profile is specified in the AS3 declaration, BIG-IP automatically applies a default persistence profile. For HTTP/HTTPS virtual servers, this is typically a cookie-based persistence profile. This results in all requests from the same client being directed to the same pool member.

2. HTTP Keep-Alive:
If the client uses HTTP keep-alive, multiple requests are sent over the same TCP connection. BIG-IP will continue to use the same pool member for the duration of the connection, further contributing to the appearance of persistence and uneven load balancing.

 

Recommended Actions

1. Explicitly Disable Persistence:

In your configuration, explicitly set the persistence profile to "none" to prevent automatic assignment of a default persistence profile.

For CIS CRD:

persistenceProfile: "none"

For AS3:

"persistenceMethods": []

Use syntax appropriate for your deployment method.

2. Client Connection Handling:

Ensure that clients or test tools use the "Connection: close" header instead of "keep-alive". This forces each request onto a new TCP connection and allows round robin load balancing to function correctly.

3. Clear Persistence Table and Statistics:

After making changes to persistence settings, clear any existing entries in the persistence table and reset statistics on BIG-IP before retesting.

4. Verify Configuration:

Confirm that no unwanted persistence profiles are attached and that round robin distribution is occurring as expected after changes are applied.
