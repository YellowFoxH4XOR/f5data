Known Issue

The BIG-IP Virtual Edition (VE) system may have minimal disk space for the /var software partition when you deploy from the OVA file for the Better or Best license bundle.

This issue occurs when all of the following conditions are met:

  • You have deployed a BIG-IP VE system using one of the following affected OVA files for 11.5.3 or 11.6.0:
    • For BIG-IP VE 11.5.3, the affected OVA files' file name prefix is BIGIP-11.5.3.0.0.163.
    • For BIG-IP VE 11.6.0, the affected OVA files' file name prefix is BIGIP-11.6.0.0.0.401.
  • The system is licensed with a Better or Best license bundle.

Impact

BIG-IP VE systems deployed with an affected OVA file will have a /var file system with insufficient space to provision licensed module options. Performing a software upgrade to an alternate software slot may also fail.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • The size of /var software partition is 500 MB instead of 3 GB when using the Better or Best license bundle.
  • The /var software partition runs out of space.
  • Attempting to provision licensed modules fails with a message similar to the following example:

    The resources required for the selected modules is likely greater than those available.

  • Attempting to perform a software upgrade fails with a message similar to the following example in the /var/log/liveinstall.log file:

    info: /var/local/ucs/config.ucs: Not enough free disk space to install!

Workaround

To work around this issue, you can resize the /var volume on the existing software slot or the target software slot when performing a software upgrade operation. To do so, perform one of the following procedures:

Impact of workaround: This procedure involves rebooting the BIG-IP system, and F5 recommends that you perform the procedure during a scheduled maintenance period.

Resizing /var volume on the existing software slot

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. Resize the software partition /var to 3 GB by typing the following command:

    modify /sys disk directory /var new-size 3145728

  3. Reboot the BIG-IP system by typing the following command:

    reboot

Resizing /var volume on the target software slot when performing a software upgrade operation

Note: Depending on the available disk space on your BIG-IP VE system, you may need to extend the disk space on the BIG-IP VE system to have additional software slot created. For more information, refer to K14952: Extending disk space on BIG-IP VE.

  1. Log in to the BIG-IP command line.
  2. Use a text editor to edit the /shared/.tmi_config/global_attributes file.
  3. Set the TMI_VOLUME_FIX_VAR_MIB value to 3000. The content of the file should look similar to the following example:

    {"TMI_VOLUME_FIX_VAR_MIB":"3000","TMI_VOLUME_FIX_CONFIG_MIB":"500"}

  4. Log in to the tmsh utility by typing the following command:

    tmsh

  5. Perform the software upgrade to a new software slot using the following command syntax:

    install sys software image <software_version> create-volume volume <new_software_slot>

  6. Reboot the BIG-IP system into the new software slot after installation has completed successfully by typing the following command syntax:

    reboot volume <new_software_slot>

  7. After the system boots up, verify the size of the /var volume in the new software slot by typing the following command:

    tmsh show /sys disk directory

    The following example shows the size of the /var volume set to 3GB:

    [root@bigip:Active:Standalone] config # tmsh show /sys disk directory
    Directory Name Current Size New Size
    -------------- ------------ --------
    /config 3321856 -
    /shared 31457280 -
    /var 3145728 -
    /var/log 7340032 -
