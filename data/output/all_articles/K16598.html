Known Issue

The BIG-IP GTM configuration may fail to load after you add virtual server dependencies.

This issue occurs when all of the following conditions are met:

  • You have configured the BIG-IP GTM system with multiple virtual servers.
  • You have configured one of the BIG-IP GTM virtual servers with a dependency list that includes virtual servers from the same BIG-IP GTM system.

When configuring the dependency list, the configuration saved by the BIG-IP GTM system will no longer include the virtual servers that you specified in the dependency list.

For example, the BIG-IP GTM configuration has BIG-IP GTM virtual servers GTM_vs1, GTM_vs2, and GTM_vs3 configured. The bigip_gtm.conf file will include virtual server definitions for all three virtual servers. If you then configure GTM_vs1 with a dependency list that includes GTM_vs2 and GTM_vs3, the bigip_gtm.conf file will be saved with only the GTM_vs1 virtual server definition. A subsequent attempt to load the configuration file will fail, indicating the dependent BIG-IP GTM virtual server does not exist. In addition, if you attempt to re-new the license or perform a software installation to an alternate slot, the configuration will fail to load.

Impact

The BIG-IP GTM configuration will fail to load from the bigip_gtm.conf file.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • BIG-IP iHealth lists Heuristic H522014 on the Diagnostics > Identified > Medium screen.
  • The BIG-IP GTM configuration fails to load with an error message similar to the following example, indicating a dependent virtual server does not exist:

    Loading GTM system configuration...
    /usr/local/gtm/include/gtm_base_region_isp.conf
    /usr/share/monitors/gtm_base_monitors.conf
    Loading configuration...
    /config/bigip_gtm.conf
    0107024e:3: Dependent VS /Common/GTM:/Common/vs_GTM_vs2 does not exist
    Unexpected Error: Loading configuration process failed.

Workaround

There is no workaround for this issue. However, you can save the depends-on configuration, upgrade to a 'fixed' software version, and then merge the depends-on configuration from a previously saved file after the upgrade. To do so, perform the following procedure:

Impact of procedure: The following procedure includes upgrading an alternate slot on the BIG-IP system and rebooting to the upgraded slot. The system will be offline during the reboot process. In addition, the virtual server dependencies will not be available until you complete the entire procedure and merge the depends-on configuration with the running configuration.

  1. Save the running configuration (including the depends-on configuration) to a backup file. To do so, type the following command:

    tmsh save /sys config gtm-only one-line file /shared/tmp/gtm-config

  2. To remove the depends-on configuration from the running configuration, type the following command:

    tmsh modify /gtm server all virtual-servers modify { all { depends-on none } }

  3. Upgrade an alternate slot to a 'fixed' version (for example, version 11.5.3).
  4. Once the upgrade is complete, reboot the system to the upgraded slot.
  5. Create a temporary file that contains the depends-on configuration. To do so, type the following command:

    egrep ‘^gtm server’ /shared/tmp/gtm-config > /shared/tmp/gtm-depends

  6. To merge the depends-on configuration with the running configuration, type the following command:

    tmsh load /sys config merge file /shared/tmp/gtm-depends
