Known Issue

This is the result of a known issue. Using a non-optimized query when viewing the Violation under the Learning link in the Configuration utility may cause a long delay that results in a browser timeout, as well as an error message reported by the users browser.

Note: When a large number of records exist, a wildcard or broad query would be considered a non-optimized query.

This behavior occurs with a large violation database (about 3000 unlearned/undefined objects) during which time a non-optimized query results in delayed response to the browser. If the response delay is longer than the browser allows, the browser will timeout and respond with an error message.

F5 Networks Product Development is tracking this issue as CR93906.

Workaround

You can work around this issue and allow the use of non-optimized queries by preventing your database from growing too large. To do so, use the following recommendations:

  • Clear the request log for the affected Web Application

    Note: The request log is located under Learning >> Request in the Configuration utility.

  • Actively monitor learning suggestions after running the policy builder
  • Consider disabling the tightening option for wildcard entities

Note: For more information about working with the Learning utility and changing options for wildcard entities, refer to the Configuration Guide for BIG-IP Application Security Management.
