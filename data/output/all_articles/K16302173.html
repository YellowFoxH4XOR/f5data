Description

When using using On-Demand Certificate Authentication and having it set to require, a user with an iPhone that does not present a valid certificate upon SSL re-negotiation, they will have their session terminated.

Environment

  • iOS
  • BIG-IP APM
  • Client Certificate Authentication

Cause

There may be scenarios where in the Visual Policy Editor an Administrator may want to integrate a On-Demand to re-negotiate a SSL handshake and expect the user will hit the fallback branch. 
Other operating systems will hit the fallback branch whereas iOS users will have their session rejected.

When using On-Demand Cert Authentication there are two options that this can set this to:

Require: Use this mode if your client provides a client certificate.
For iPhone users, when this mode is set to required, the connection is terminated if a certificate is not received from the client.

Request: Use this mode if your client does not provide a client certificate. With this mode, the connection succeeds even if a certificate is not received from the client by taking the fallback branch in the policy. This is the default option.

Recommended Actions

There are two options to make this scenario not reject iOS sessions upon On-Demand Certificate Authentication.

  1. The user could present a valid certificate while Require is selected
  2. Change the On-Demand Certificate Authentication Action in the VPE to Request
    It is possible to do an Client OS Check prior to the On-Demand action to choose branches and only have iOS devices set to Request, and all other OS branches set to Require.
