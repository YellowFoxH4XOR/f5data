LB::detach

Description

This command detaches the server-side connection from the client-side.

Warning

**There are version specific notes for using this command in the LB_FAILED event below, but generally, note that while legal, using LB::detach under LB_FAILED can result in connection failures and server rejects.

Syntax

LB::detach

LB::detach

  • Detaches the server side connection from the client-side connection.
  • Use in conjunction with TCP::notify as best practice.

Examples

when SERVER_CONNECTED {
   if { $connRetry >= $maxAttempts } {
      TCP::notify response
   }
}

when USER_RESPONSE {
   LB::detach
}

LTM 9.3.1 w/HF4 Still true - TMM restarts. Using LB::down w/o LB::detach in LB_FAILED event can cause a quickly restarted server to be placed in a “SESSIONS DISABLED” status and stay there until the server has been stopped for a while. The server must be down long enough for the monitor timeout value to have done the detach work, then the server can be restarted. A quickly restarted server will never come back in service. (25 Jun 2009)
