Topic

This article discusses some of the best practices that you can adopt when you are planning to maximize the performance of your BIG-IP Virtual Edition (VE) hosted in a supported hypervisor.

Description

Important: F5 recommends that you review BIG-IP Virtual Edition Supported Platforms for information about the hypervisor version support for certain performance enhancement features such as single root I/O virtualization (SR-IOV) and Large Receive Offload (LRO) before you attempt to implement any of the following guidelines. Additionally, you should review K17204: BIG-IP Virtual Edition 10 to 40 gigabit NIC adapters that support SR-IOV to determine the high-performance 10/40Gbps NIC adapters that currently support SR-IOV.

If you are planning to maximize performance on your BIG-IP VE, it is important that you review the following guidelines for the hosting hypervisor environment:

Important: For specific instructions on implementing the following guidelines, you must consult the documentation for your hypervisor system.

  • Resource allocation
  • Power management and BIOS settings
  • Storage
  • Networking
  • CPU pinning and NUMA

Resource allocation

To optimize the performance of your BIG-IP VE system, you should allocate your BIG-IP VE system with the maximum allowable vCPUs and memory as defined by your BIG-IP VE license.

As a general guideline, you should allocate 2 GB of memory per vCPU. For example, if your BIG-IP VE has a 1 Gbps throughput Better license, which allows a maximum of 4 vCPUs, you should allocate your BIG-IP VE with the maximum of 4 vCPUs and 8 GB of memory. For more information about maximum allowed vCPUs for a specific license, refer to K14810: Overview of BIG-IP VE license and throughput limits.

Power management and BIOS settings

For maximum performance, you should disable all power management settings in the BIOS of your hypervisor host. You should also disable hyperthreading because some applications may experience performance degradation with hyperthreading. This is because many processor resources (such as the cache) are shared between logical processors when hyperthreading is enabled. Additionally, you should enable virtualization extensions such as Intel Virtualization Technology (VT) in the BIOS.

Storage

Storage best practice depends on the specific environment in which the BIG-IP VE system is deployed. For example, storage that is physically connected to your hypervisor host may provide better performance in some environments, while a well-connected remote storage device may provide better performance in other environments. In both cases, resource provisioning must guarantee enough read/write IOPS and throughput to match the performance of F5 hardware platforms. F5 recommends that you check your storage options and network environment before configuring a storage option for your hypervisor.

Networking

For maximum performance, lowest latency, and efficient CPU utilization, F5 recommends using SR-IOV. Enabling SR-IOV allows the hypervisor guest to directly interact with the physical network hardware and reduces the additional step of passing through the hypervisor host for processing. If your hypervisor host supports SR-IOV, you should enable it and avoid using the hypervisor host's vSwitch to minimize packet copies.

If you have saturated the capacity of a single network interface controller (NIC), as an alternative to obtaining a higher performance NIC, you can scale application performance on a single guest by combining the throughput of multiple NICs.

If the network cards on the hypervisor host support Large Receive Offload (LRO), you should consider enabling this functionality. LRO improves inbound throughput for high bandwidth networks by reducing CPU overhead. This functionality allows the network card to perform specialized functions, such as merging smaller packets into larger ones for the upper application layers.

CPU pinning and NUMA

CPU pinning allows a hypervisor scheduler to dedicate cores to your guest vCPUs. Virtual machines running on shared compute resources may be randomly competing against unknown processes running simultaneously, adversely affecting consistency.

When you enable CPU pinning on hypervisors that support this functionality—primarily Kernel-based Virtual Machine (KVM) or VMware ESXi—it allows for repeatable application performance because no other guests are allowed to run on the reserved compute resource.

You should avoid assigning vCPUs from the same physical CPU to your BIG-IP VE system. For the best sustained predictable performance, you should pin each guest CPU to a physical core instead of pinning each guest CPU to a hyperthreaded core. Certain technologies, such as Intel Hyper-Threading, allow the hypervisor host to assign two vCPUs from the same physical CPU to a hypervisor guest.

When two vCPUs from the same physical CPU are assigned to your BIG-IP VE system, the available processing capacity is less. In some environment, CPU pinning may not make sense as you may prefer to over-subscribe the CPU resources due to application requirements or insufficient hardware resources.

In a multi-CPU server, when your hypervisor host supports non-uniform memory access (NUMA) spanning, you should avoid assigning vCPUs from different NUMA nodes (across one socket to another socket) to the BIG-IP VE system. NUMA can impact performance due to memory access required between the two sockets.

CPU pinning and NUMA configuration parameters may differ depending on hypervisors, and F5 recommends that you check your CPU configuration options before configuring it for your hypervisor. For example, on Red Hat Enterprise Linux, there is a kernel parameter called isolcpus, which defines a set of CPUs where the kernel processes scheduler will not interact with. It allows to prevent kernel's process scheduling subsystem to move host processes onto CPU cores assigned to virtual machines, which could cause processes on hypervisor and virtual machine to share a single CPU core.

Recommendations

When you plan to maximize performance on your BIG-IP VE system, consider the various guidelines discussed previously to optimize the performance of your BIG-IP VE system.
