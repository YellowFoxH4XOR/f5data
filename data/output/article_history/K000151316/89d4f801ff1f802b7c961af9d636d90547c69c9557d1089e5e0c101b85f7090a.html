Description

When reviewing the ASM event logs or learning suggestions for a security profile with a JSON content profile, administrators may encounter unexpected Maximum Array/Object Elements violations, even when the setting is configured as Any, which appears to allow an unlimited number of elements. This article explains how internal parsing behavior and request parameter limits affect ASM’s interpretation of JSON structures and why violations may occur despite seemingly permissive settings.

Environment

  • BIG-IP ASM
  • JSON content profile

Cause

The confusion stems from the interaction between JSON parsing and ASM’s enforcement of request parameter limits. Even when a JSON profile allows Any number of array or object elements (represented internally as -1 in the event logs), JSON parsing remains subject to the global request limits configured under:

  • Learning and Blocking Settings > Maximum Number of Parameters
  • Internal system variable: max_num_request_params

The JSON parser stops processing keys when one of the limits above is reached. As a result, ASM stops parsing the remainder of the request body, including any array or object structures, and may trigger a Maximum Array/Object Elements Exceeded violation even when Maximum Array/Object Elements is set to Any in the JSON profile.

Moreover, even if the Check maximum number of parameters violation is disabled, the limit still constrains the parser during request processing. 

 

Recommended Actions

To avoid unintended violations related to JSON array or object element limits, do not set Maximum Number of Parameters too low, as this may cause parsing to stop prematurely. Keep the default value of 500, or adjust the limit based on the expected size and structure of your application’s requests.

 

Additional Information

  • The internal variable max_num_request_params can also limit parsing, although it is typically not set unless explicitly configured.
  • Setting limits too low may cause false positives or disrupt application functionality because of incomplete JSON parsing.
  • A mismatch between the Detected Value and the configured limit may occur because ASM parses and counts parameters incrementally during inspection.
