Description

When configuring JSON profiles in BIG-IP ASM, administrators may encounter unexpected violations related to “Maximum Array/Object Elements” even if the setting appears to allow unlimited values (set to Any). This article explains how internal parsing behavior and request parameter limits influence ASM's interpretation of JSON structures and why violations can occur despite seemingly permissive configurations.


Environment

- BIG-IP ASM

- JSON profile with “Maximum Array/Object Elements” set to Any


Cause

The confusion arises from the interaction between JSON parsing and ASM’s request parameter limit enforcement. Even when a JSON profile allows “Any” number of array or object elements (represented internally as -1 in Event Logs), parsing is still subject to global request limits configured under:


- Learning and Blocking Settings > Maximum Number of Parameters

- Internal system variable: max_num_request_params


The JSON parser stops processing keys once the one of above limit is reached. This halts further parsing of the request body, including array/object structures, and can trigger a “Maximum Array/Object Elements Exceeded” violation, even when "Maximum Array/Object Elements" is set to 'Any' in json profile.


Moreover, if “Check maximum number of parameters” violation is disabled, the above limit still constrains the parser during request processing. 


Recommended Actions

To avoid unintended violations related to JSON array or object element limits:


- Do not set the “Maximum Number of Parameters” to low value as such configuration might cause parsing to fail early.

- Use the default value of 500, or adjust the parameter cap according to your application's expected request size.


Additional Information

- Internal variable max_num_request_params can also cap parsing, though it is usually not set unless explicitly configured.

- Setting maximums too low may result in false positives or broken application functionality due to incomplete JSON parsing.

- A mismatch between “Detected Value” and configured limits may occur due to how ASM incrementally parses and counts parameters during inspection.
