Topic

The FastL4 profile is a protocol profile that you can use to manage Layer 4 (L4) traffic on the BIG-IP system. Using the FastL4 profile can increase virtual server performance and throughput for supported platforms by using the embedded Packet Velocity Acceleration (ePVA) chip to accelerate traffic.

Description

The ePVA chip is a hardware acceleration field programmable gate array (FPGA) that delivers high-performance L4 throughput by offloading traffic processing to the hardware acceleration chip. For BIG-IP platforms that contain the ePVA chip, the system makes flow acceleration decisions in software and then offloads eligible flows to the ePVA chip for acceleration. For platforms that do not contain the ePVA chip, the system performs acceleration actions in software.

Note: For information about the way the BIG-IP platforms interact with ePVA acceleration, and which features support hardware acceleration, refer to K12837: Overview of the ePVA feature.

You can find the FastL4 profile in the Configuration utility by going to Local Traffic > Profiles > Protocol > Fast L4.

You can associate the FastL4 profile with the following virtual types:

  • Performance (Layer 4)
  • Forwarding (Layer 2)
  • Forwarding (IP)
  • Internal

The following table shows the FastL4 profile settings.

SettingDefault valueDescription
Reset on TimeoutEnabledWhen enabled, the system sends a reset packet (RST) and deletes the connection when a connection exceeds the idle timeout value. The system sends an RST from the virtual server address to the client and from the client address (or SNAT address when configured) to the server.
Reassemble IP FragmentsDisabledWhen enabled, the system reassembles IP fragments. Enabling this setting demotes hardware acceleration to software on receipt of the first valid fragment.
Idle Timeout300 secSpecifies the length of time that a connection remains idle (has no traffic) before the connection is eligible for the system to delete. The following options are available:
  • Specify: Specifies a number of seconds that the connection can remain idle before the system deletes it.
  • Immediate: Specifies that the system deletes connections immediately when they become idle.
  • Indefinite: Specifies that the system does not delete connections regardless of how long they remain idle.
TCP Handshake Timeout5 secIndicates the allowable duration for a TCP handshake. If the TCP handshake takes longer than the specified timeout, the system automatically closes the connection. The following options are available:
  • Specify: Specifies the number of seconds that the system can try to establish a TCP handshake before timing out. The default value is 5 seconds.
  • Disabled: Specifies that the system does not apply a timeout to a TCP handshake.
  • Indefinite: Specifies that attempting a TCP handshake never times out.
Maximum Segment Size OverrideDisabledIndicates a maximum segment size (MSS) override for connections. This setting functions by lowering the MSS set on SYN and SYN/ACK packets if the MSS set value is higher than the configured value. MSS Override cannot increase MSS because doing so is unsafe. The following options are available:
  • Disabled: Specifies that the system does not use an MSS override.
  • Specify: Specifies, in bytes, the size of the MSS override. You can specify any integer between 256 and 9162.

Note: FastL4 always overrides MSS and sets it to the appropriate value for the next hop, regardless of the MSS Override setting. For example, if an IPv4 SYN is received with an MSS of 1460 and is forwarded on to a VLAN with an MTU of 1280, the MSS is lowered to 1240.

IP ToS to ClientPass ThroughFor IP traffic passing through the system to clients, specifies whether the system modifies the IP's type-of-service (ToS) setting in an IP packet header. The following options are available:
  • Specify: Specifies the IP's ToS setting, which the system inserts in the IP packet header. You can specify a number between 0 and 255.
  • Pass Through: Specifies that the IP ToS setting remains unchanged.
  • Mimic: Specifies that the system sets the ToS level of outgoing packets to the same ToS level of the most recently received incoming packet. For example, if the most recently received packet had a ToS level of 3, the system sets the ToS level of the next outgoing packet to 3.

Note: If the field IP ToS to Client is set to any value other than Pass Through, then the setting demotes hardware acceleration to software and a performance drop may be observed.

IP ToS to ServerPass ThroughFor IP traffic passing through the system to servers, specifies whether the system modifies the IP's ToS setting in an IP packet header. The following options are available:
  • Specify: Specifies the IP ToS setting that the system inserts in the IP packet header. You can specify a number between 0 and 255.
  • Pass Through: Specifies that the IP ToS setting remains unchanged.
  • Mimic: Specifies that the system sets the ToS level of outgoing packets to the same ToS level of the most recently received incoming packet. For example, if the most recently received packet had a ToS level of 3, the system sets the ToS level of the next outgoing packet to 3.

Note: If the field IP ToS to Server is set to any value other than Pass Through, then the setting demotes hardware acceleration to software and a performance drop may be observed.

Link QoS to ClientPass ThroughFor IP traffic passing through the system to clients, specifies whether the system modifies the link's quality-of-service (QoS) setting in an IP packet header. The link's QoS value prioritizes the IP packet relative to other Layer 2 traffic. The following options are available:
  • Specify: Specifies the link's QoS setting that the system inserts in the IP packet header. You can specify a number between 0 (lowest priority) and 7 (highest priority).
  • Pass Through: Specifies that the link's QoS setting remains unchanged.
Link QoS to ServerPass ThroughFor IP traffic passing through the system to servers, specifies whether the system modifies the link's QoS setting in an IP packet header. The link's QoS value prioritizes the IP packet relative to other Layer 2 traffic. The following options are available:
  • Specify: Specifies the link's QoS setting, which the system inserts in the IP packet header. You can specify a number between 0 (lowest priority) and 7 (highest priority).
  • Pass Through: Specifies that the link's QoS setting remains unchanged.
TCP Timestamp ModePreserveIndicates whether the system preserves, strips, or rewrites TCP timestamps.
TCP Window Scale ModePreserveSpecifies the action that the system should take on TCP windows. The following options are available: Preserve, Strip, and Rewrite.
Don't Fragment (DF) flagPreserveSpecifies the Don't Fragment (DF) bit's setting in the IP header of the outgoing TCP packet. The following options are available:
  • Pmtu: Sets the outgoing IP header's DF bit based on IP pmtu setting(tm.pathmtudiscovery).
  • Preserve: Sets the outgoing packet's IP header's DF bit to the same setting as the incoming IP header's DF bit.
  • Set: Sets the outgoing packet's IP header's DF bit.
  • Clear: Clears the outgoing packet's IP header's DF bit.

Note: This setting does not work for PVA-assisted flows.

Time to Live (TTL)DecrementSpecifies the outgoing TCP packet's IP header's TTL mode. The following options are available:
  • Proxy: Sets the outgoing IP header's TTL value to 255 for IPv4 or 64 for IPv6.
  • Preserve: Sets the outgoing IP header's TTL value to be the same as the incoming IP header's TTL value.
  • Decrement: Sets the outgoing IP header's TTL value to be one fewer in number than the incoming IP header's TTL value.
  • Set: Sets the outgoing IP header's TTL value to a specific value (as specified by ip-ttl-v[4|6]).

Note: This setting does not work for PVA-assisted flows.

Time to Live (TTL) v4255Specifies the outgoing packet's IP header TTL value for IPv4 traffic. The maximum TTL value you can specify is 255.

Note: This setting does not work for PVA-assisted flows.

Time to Live (TTL) v664Specifies the outgoing packet's IP header TTL value for IPv6 traffic. maximum TTL value you can be specified is 255.

Note: This setting does not work for PVA-assisted flows.

Generate Initial Sequence NumberDisabledWhen enabled, the system generates initial sequence numbers for SYN packets, according to RFC 1948. RFC 1948 proposes a TCP implementation that helps deter sequence number guessing attacks by using a hash algorithm to generate initial sequence numbers (ISN).
Strip Sack OKDisabledWhen enabled, the system blocks a TCP selective ACK SackOK option from passing to the server on an initiating SYN.
RTT from ClientDisabledWhen this option is enabled, the system uses TCP timestamp options to measure the round-trip time to the client.
RTT from ServerDisabledWhen this option is enabled, the system uses TCP timestamp options to measure the round-trip time to the server.
Loose InitiationDisabledThe FastL4 profile determines how the system handles the connection table entries. Enabling the Loose Initiation option allows the system to start a connection when it receives any TCP packet, rather than requiring a SYN packet to start a connection.

Note: F5 recommends that if you enable the Loose Initiation option, you also enable the Loose Close option.

Loose CloseDisabledThe Loose Close option allows the system to remove a connection when the system receives the first FIN packet from either the client or the server. This helps trim connection table entries because the system can remove the connection entry as soon as the connection officially closes, and the system does not need to maintain the connection table entry.
TCP Time Wait TimeoutDisabledSpecifies the number of milliseconds that a connection is in the TIME-WAIT state before closing. In most cases, 2000 milliseconds (2 seconds) is sufficient, and anything more than 10,000 milliseconds (10 seconds) is typically impractical. The default value Disabled is the same as 0 milliseconds.
TCP Close Timeout5 secIndicates the length of time that a connection can remain idle before the system deletes the connection. The system uses this setting to rapidly close out a loosely initiated connection after the system sees the first FIN packet on either the client side or server side. You can use this setting to control when the system flushes a connection from the connection table. If a connection through the system is idle for a long time, the system flushes it from the connection table. Then, when one end or the other eventually closes the connection, the system drops the packets (FIN/FINACK/ACK) because there is no connection table entry to specify the load balancing destination. The TCP Close Timeout value must be less than the Idle Timeout setting. Additionally, the TCP Close Timeout is valid only if you enable the Loose Initiation or the Loose Close options.
TCP Keep Alive IntervalDisabledIndicates the keep-alive probe interval in seconds.
SYN Challenge HandlingNominal
  • Nominal: Initiates SYN cookie challenges after a relatively low number of embryonic connections.
  • Challenge and Remember: Specifies whether SYN packets subsequent to a successful challenge response, from the same source IP address, should be challenged or allowed to pass unchallenged (up to some timeout period). Enabling this feature prevents hardware acceleration for SYN challenges but may be needed/useful in some deployments (for example, direct server return (DSR) mode or when no hardware acceleration is available). Essentially, Challenge and Remember adds the packet's TCP address to the SYN Cookie White List.
  • Disable Challenge: Does not initiate SYN Cookie challenges, regardless of the number of embryonic connections.
SYN Cookie MSS 0Specifies a value that overrides the SYN cookie maximum segment size (MSS) value in the SYN-ACK packet that is returned to the client. Valid values are 0, and values from 256 through 9162. The default is 0, which means no override. You may use this option if back-end servers use a different MSS value for SYN cookies than the BIG-IP system does (1460, by default).
Server SackDisabledIndicates whether the BIG-IP system processes Selective ACK (Sack) packets in cookie responses from the server.
Server TimestampDisabledSpecifies whether the BIG-IP system processes timestamp request packets in cookie responses from the server.
Receive Window0 bytesSpecifies the amount of data the BIG-IP system can accept without acknowledging the server.
Late BindingDisabledEnables intelligent selection of a server or pool, using an iRule to make the selection. When Late Binding is enabled, an iRule can examine Layer 7 (FIX) data, select a server pool, and push selected connections down to ePVA hardware. The ePVA provides a fast, low-latency connection at L4. The BIG-IP software fully establishes the client-side connection before selecting a server. This feature offers application-layer intelligence for server load balancing, together with a low-latency connection. The only TCP options available to the client and server are MSS, accept Selective ACK, and Time Stamp. The BIG-IP system ignores all other options. For example, the BIG-IP system ignores the window scaling option when it uses Late Binding.

The following table shows the list of ePVA specific settings that are available only on BIG-IP platforms with the ePVA chip.

SettingDefault valueDescription
PVA AccelerationFullSpecifies the preferred acceleration mode for the Packet Velocity ASIC (PVA), if the platform supports PVA acceleration.
  • Full: Specifies that the system applies full PVA acceleration when possible.
  • Assisted: Specifies that the system applies partial PVA acceleration.
  • None: Specifies that the system does not use PVA acceleration.
  • Dedicated: Unconditionally enables ePVA acceleration for all TCP FastL4 connections. Inactive, but established, connections are not removed from the ePVA to guarantee low latency forwarding for future packets.
PVA TCP Offload StateSYNSpecifies the TCP state at which the ePVA performs hardware offload.
  • SYN: Specifies that the ePVA performs hardware offload at the first client SYN. It also performs the EST-time snoop if the previous SYN-time snoop fails.
  • EST: Specifies that the ePVA performs hardware offload at the client ACK when in SYN/ACK state, when the connection is transitioning towards established.

Note: The ePVA cannot change the maximum setting size (MSS) once a flow is accelerated. When the FastL4 profile setting PVA TCP Offload State is set to the default (SYN), the MSS override and interface MTU limits are ignored during the SYN/ACK. To ensure TMM accurately calculates the MSS on the SYN/ACK before accelerating the connection, set PVA TCP Offload State to EST.

PVA Other Offload TimingAfter Packets Per DirectionSpecifies when the ePVA performs hardware offload for stateless protocol traffic.
  • After Packets Per Direction: Specifies that the ePVA offloads client and server traffic independently, each after exceeding their own threshold.
  • After Packets Both Directions: Specifies that both client and server traffic thresholds must be exceeded, after which the ePVA offloads traffic from both sides.
PVA Other Offload DirectionBidirectionalFor stateless protocol traffic only, specifies for which direction ePVA can perform hardware offload.
  • Bidirectional: Specifies that, when traffic exceeds the threshold, the ePVA can offload traffic regardless of direction.
  • Client to Server Only: Specifies that the ePVA can offload traffic only from the client to the server. When selected, even when traffic from the server to the client exceeds the threshold, the ePVA does not offload it.
  • Server to Client Only: Specifies that the ePVA can offload traffic only from the server to the client. When selected, even when traffic from the client to the server exceeds the threshold, the ePVA does not offload it.
PVA Other Offload Client Threshold2Specifies the number of client packets before dynamic ePVA hardware re-offloading occurs. Valid value range is 0-10.
PVA Other Offload Server Threshold1Specifies the number of server packets before dynamic ePVA hardware re-offloading occurs. Valid value range is 0-10.
PVA Flow AgingEnabledSpecifies whether automatic aging from ePVA flow cache occurs upon flows that are inactive and idle for a period of time.
PVA Flow EvictEnabledSpecifies whether this flow can be evicted upon hash collision with a new, flow-learn snoop request.
PVA Offload DynamicEnabledWhen disabled, the system offloads flows to ePVA only during the initial handshake. When enabled, the system dynamically checks flows that are previously evicted or timed out and handled by software in TMM after pva-dynamic-client-packets and pva-dynamic-server-packets is reached to determine if they're eligible to be re-offloaded into ePVA. For the system to offload a flow in a connection to ePVA hardware, you must specify both the client (PVA Dynamic Client Packets) and server (PVA Dynamic Server Packets) flow packets settings. If only one setting is relevant, set the other to 0 (zero). The PVA Offload Dynamic setting allows you to instruct the system to dynamically offload flows in a connection to ePVA hardware, if your BIG-IP system supports such hardware. When you enable the PVA Offload Dynamic setting, you can then configure the following values:
  • The number of client packets before dynamic ePVA hardware re-offloading occurs. The valid range is from 0 (zero) through 10.
  • The number of server packets before dynamic ePVA hardware re-offloading occurs. The valid range is from 0 (zero) through 10.
PVA Dynamic Client Packets1Indicates the number of client packets before dynamic ePVA hardware re-offloading occurs. The valid range is from 0 (zero) through 10.
PVA Dynamic Server Packets0Indicates the number of server packets before dynamic ePVA hardware re-offloading occurs. The valid range is from 0 (zero) through 10.
PVA TCP Offload DirectionBidirectionalSpecifies the direction that the ePVA can offload TCP traffic. Options include Bidirectional, Client to Server Only, and Server to Client Only. For example, when Client to Server Only is selected, the ePVA does not offload traffic from server to client, even if the traffic threshold is exceeded.
PVA Offload Initial PriorityMediumSpecifies the initial priority level for traffic flows that you want to the system to insert into the flow accelerator and the flow priority to use when PVA Offload Dynamic Priority is set to Disabled. Options are Low, Medium, and High.
PVA Offload Dynamic PriorityDisabledSpecifies whether flows have their ePVA priority adjusted dynamically. When set to Enabled, the system automatically adjusts flow priority based on throughput, flow table occupancy and collision rate . This provides a prioritization mechanism that supports application-level control of which flows utilize the limited FPGA resources. If this option is set to Disabled, the system does not dynamically adjust ePVA priority on flows. Instead, the system uses the PVA Offload Initial Priority value.

Recommendations

When configuring the FastL4 profile:

  • Consider using the FastL4 profile when you want to accelerate packet processing and do not require the virtual server to use the full proxy architecture when processing connections. For example, you can use the FastL4 profile when the virtual server only needs to be aware of socket level information for each connection (for example, src_ip:port dst_ip:port). You should not choose the FastL4 profile if you require features, such as HTTP optimizations.
  • F5 recommends that you create a custom profile instead of modifying the default FastL4 profile. Creating a custom FastL4 profile allows you to associate the custom profile, which contains specific settings, with the virtual server.
