K000160600: Portal Access application does not load because the back-end server requires the Accept-Encoding header

Type
Support Solution
Published
2026-05-14
Updated
2026-10-29
Applies to
  • BIG-IP
  • BIG-IP APM
Source
https://my.f5.com/manage/s/article/K000160600

Description

You access a web application through BIG-IP APM Portal Access, and the application displays a blank page or does not work as expected. The application works as expected when you access it directly, without BIG-IP APM.

When you troubleshoot this issue, you may observe the following symptoms:

  • The back-end server returns HTTP 404 responses for some resources, for example JavaScript files or other static files, only when the application is accessed through Portal Access.

  • The requests that the BIG-IP system sends to the back-end server do not include the Accept-Encoding header.

Environment

  • BIG-IP APM 17.1.x, 17.5.x, or 21.1.x

  • Portal Access resource and rewrite profile

  • Back-end application that requires the Accept-Encoding request header to serve content, for example the iDRAC web interface

Cause

Portal Access removes the Accept-Encoding header from requests that it sends to the back-end server, so that the server returns content that is not compressed. This is by design. Some back-end applications do not serve resources when the header is missing, and return HTTP 404 responses instead.

Answer/Recommended Actions

To work around this issue, add an iRule to the Portal Access virtual server that inserts the Accept-Encoding header in requests to the back-end server. The iRule uses the HTTP_REQUEST_RELEASE event, which runs after Portal Access has processed the request, immediately before the request is sent to the back-end server.

Impact of procedure: F5 recommends performing this procedure during a scheduled maintenance window.

  1. Log in to the Configuration utility.

  2. Go to Local Traffic > iRules > iRule List.

  3. Click Create.

  4. Enter a name for the iRule, for example apm_portal_insert_accept_encoding.

  5. In Definition, enter the following iRule:

    when HTTP_REQUEST_RELEASE {
        if { [HTTP::header exists "Accept-Encoding"] } {
            HTTP::header replace "Accept-Encoding" "gzip, deflate"
        } else {
            HTTP::header insert "Accept-Encoding" "gzip, deflate"
        }
    }

  6. Click Finished.

  7. Go to Local Traffic > Virtual Servers > Virtual Server List, and click the name of the Portal Access virtual server.

  8. Click the Resources tab.

  9. In the iRules section, click Manage.

  10. Move the iRule from Available to Enabled, and click Finished.

  11. Start a new access session, and verify that the application loads.

To back out of this procedure, move the iRule from Enabled to Available.

Note: You can also try to add the Accept-Encoding header as a custom header in the Portal Access resource item settings (the Advanced headers section). This has not been reliable in all configurations. If the header does not reach the back-end server, use the iRule.

If the issue persists, open a support case and provide the data listed in the Collect HTTPWatch or HAR files for support section of K14184: Troubleshooting BIG-IP APM Portal Access applications. A browser HAR file shows only the requests from the browser to the BIG-IP system. To see whether the requests from the BIG-IP system to the back-end server include the header, F5 Support may ask for a packet capture on the BIG-IP system.
