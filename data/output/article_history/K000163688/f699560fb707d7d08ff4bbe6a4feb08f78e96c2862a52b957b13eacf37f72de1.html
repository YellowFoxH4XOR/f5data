K000163688: F5OS device LLDP Discovery Fails When a Receiving Device Rejects a Zero-Length Port Description TLV

Type
Support Solution
Published
2026-10-13
Updated
2026-10-13
Applies to
  • F5OS Products
  • F5OS-A: 1.8.X, 1.8.4, 1.8.3, 1.8.0
  • F5OS-C: 1.8.X, 1.8.2, 1.8.1, 1.8.0
Source
https://my.f5.com/manage/s/article/K000163688

Description

LLDP discovery may fail in one direction when F5OS sends an LLDPDU containing an empty Port Description TLV (Type 4) with a length of zero. The receiving device may discard the LLDPDU and log:

Error: rxProcessFrame(lldp/pan_lldp_rx_sm.c:293): TLV type 4 has length of 0

Environment

  • LLDP enabled between F5OS and a receiving firewall
  • System Description and/or Port/Interface Description configured as empty

Cause

The F5OS LLDP agent can transmit an optional Port Description TLV with a length of zero when the corresponding description is empty. IEEE 802.1AB permits the Port Description TLV to contain an octet string from 0 through 255 bytes.

Although the zero-length TLV is valid according to the standard, some receiving devices reject it and discard the entire LLDPDU. This is an LLDP interoperability issue between the F5OS LLDP implementation and the receiving device's parser.

Recommended Actions

Configure non-empty values for both description fields in the F5OS LLDP configuration:

  • Enter a non-empty value for System Description.
  • Enter a non-empty value for Port/Interface Description.

Additional Information

  • Chassis ID, Port ID, and Time to Live are mandatory LLDP fields.
  • The Port Description TLV is optional.
  • A zero-length Port Description TLV is valid according to IEEE 802.1AB.
  • Some receiving devices may reject a valid zero-length Type 4 TLV.
  • Configuring non-empty System Description and Port/Interface Description values prevents the interoperability issue.
