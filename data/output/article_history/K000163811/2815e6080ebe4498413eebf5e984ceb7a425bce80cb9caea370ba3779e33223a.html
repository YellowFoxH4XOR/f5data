K000163811: rSeries k3s outbound TCP connections to port 10250 after upgrade/reboot

Type
Support Solution
Published
2026-10-21
Updated
2026-10-21
Source
https://my.f5.com/manage/s/article/K000163811

Description

The k3s service on an rSeries host initiates outbound TCP connections to an external address on port 10250. The metrics-server reports i/o timeout errors when it connects to the kubelet port on the host.

Symptoms and log messages:

  • Firewall logs show TCP connections to port 10250 from the rSeries management address to an external address.
  • The k3s service logs confirming port 10250 being k3s server port:

    k3s: I0916 07:40:37 server.go:149] "Starting to listen" address="<address>" port=10250

  • The metrics-server logs show connection timeouts to port 10250 on the host:

    unable to fetch metrics from Kubelet ...: dial tcp <address>:10250: i/o timeout

  • The k3s logs show DNS search-line truncation:

    E1008 12:29:47 dns.go:126] "Search Line limits exceeded" err="Search Line limits were exceeded, some search paths have been omitted, the applied search line is: kube-system.svc.cluster.local svc.cluster.local cluster.local amazonaws.com idservice.net shpapi.com"

Environment

  • Product: BIG-IP LTM on F5 rSeries (F5OS-A)
  • F5OS-A versions: 1.8.3-23453 upgraded to 1.8.4-28594
  • DNS configuration:

    system dns config search [ amazonaws.com idservice.net shpapi.com ]

  • DNS servers are configured on port 53.

Cause

The DNS search domain amazonaws.com combined with k3s server making DNS queries towards configured DNS servers and search domains.

Answer/Recommended Actions

  1. Review the DNS search domain configuration on the rSeries system. Consider removing amazonaws.com from the search list:

    system dns config search [ idservice.net shpapi.com ]

    Confirm the change with the running configuration before committing it.

  2. Keep the DNS search list short. Long search lists cause k3s to log "Search Line limits exceeded" and omit some search paths.
  3. Reboot the device during a maintenance window if needed to apply the change, then monitor firewall logs for TCP 10250 connections from the rSeries management address.
  4. If connections continue after the change, open a support case and provide firewall logs, a packet capture from the rSeries host, and the current DNS configuration.

Additional Information

  • Port 10250 is used by k3s for health and metrics information on the rSeries host. The service listens on this port by design, so a listening socket on port 10250 is expected behavior.
  • Outbound connections from the host to external addresses on port 10250 are not expected behavior. Consider this traffic unexpected if it appears in firewall logs.
