Topic

You should consider using these procedures under the following conditions:

  • You want to view evasion technique violations logged by the BIG-IP ASM system.
  • You want to configure the BIG-IP ASM system to handle URL-encoded evasion techniques.

Prerequisites

You must meet the following prerequisite to use these procedures:

  • You have access to the Configuration utility.

Description

The Evasion technique detected violation is triggered when the BIG-IP Advanced WAF / ASM system performs normalization on certain requests.

Normalization is the process by which the BIG-IP Advanced WAF / ASM system decodes and modifies the request prior to performing security checks. The system performs normalization because requests often contain encoded strings that the BIG-IP system needs to interpret before doing any further processing.

The BIG-IP Advanced WAF / ASM system performs some normalizations on the URL that are expected and don't generate violations. For example, the BIG-IP Advanced WAF / ASM system may receive a URL-encoded request in which certain characters are replaced with a percent sign (%) followed by numbers as in the following URL:

http://www.mystore.com/big%20sales.html

In the above example, the %20 string represents a space character. Even though the %20 is a legitimate encoded value, the system must decode the request because attackers may use encoding techniques to send crafted requests that bypass the attack signatures and expose the application to attacks.

The BIG-IP Advanced WAF / ASM system performs other normalizations that generate evasion technique violations. The Evasion technique detected violation is triggered when the system normalizes part of a request that obscured a malicious string.

For example, directory traversals can be used to bypass the web server root and request various files. The following scenario outlines how the BIG-IP Advanced WAF / ASM system processes a Directory traversal evasion technique:

  • The Directory traversal evasion technique is enabled in the security policy.
  • An attacker sends the following GET request to the BIG-IP Advanced WAF / ASM:

    GET /etc/mydir/%2e%2e%2fpasswords

  • The Advanced WAF / ASM system performs normalization on the encoded string so that the GET request appears as follows:

    GET /etc/mydir/../passwords

  • The system further normalizes the GET request to the following:

    GET /etc/passwords

  • Since the normalized string is a directory traversal attempt, the security policy blocks the request and triggers the following violations: Evasion technique detected (directory traversal) and Attack Signature detected (directory traversal attempt)

The following table lists the normalization types that can generate Evasion technique detected violations. The table lists the part of the request in which the specific normalization process applies; URL and parameter.

Note: The BIG-IP ASM system cannot learn the number of decoding passes required when it encounters Evasion technique detected violations. You must use the multiple decoding option to fine-tune the number of passes required when the BIG-IP ASM policy is in learning mode.

Procedures

View evasion technique violations logged by the BIG-IP ASM system

  1. Log in to the Configuration utility.
  2. Go to Security > Event Logs > Application > Requests.
  3. Select the filter icon.
  4. On the Basic tab, ensure Security Policy is selected, then select the security policy.
  5. For Violation, begin entering Evasion in the search box and under RFC Violations select Evasion technique detected.
  6. Select Apply.
  7. To view the detail of the triggered violation in a request, under Requests, select the request.

Configure the BIG-IP ASM system to handle evasion technique violations

  1. Log in to the Configuration utility.
  2. Go to Security > Application Security > Policy Building > Learning and Blocking Settings.
  3. Ensure that the policy you want to use is selected.
  4. For Evasion technique detected, select the policy action check boxes you want to use (Learn, Alarm, and Block).
  5. Expand Evasion technique detected.
  6. For Multiple decoding select a value (2 through 5).
  7. For each violation you want to detect, select the Enable check box.
  8. Select Save.
  9. To apply the policy changes, select Apply Policy.
