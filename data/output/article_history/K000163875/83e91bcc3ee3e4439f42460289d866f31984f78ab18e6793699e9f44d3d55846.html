K000163875: F5 Insight storage degradation or upgrade failure due to high /opt partition disk usage

Description

F5 Insight storage degradation or upgrade failure may occur due to high /opt partition disk usage.

Administrators running F5 Insight may observe one or more of the following symptoms:

  • Software upgrade, patch application, or bundle staging fails with error messages indicating insufficient storage on the /opt partition.
  • ClickHouse or VictoriaMetrics pods repeatedly restart or enter CrashLoopBackOff / Evicted states due to disk pressure.
  • The host operating system alerts that filesystem /dev/mapper/vg0-opt is exceeding threshold capacity (greater than 85 - 90% utilization).

Environment

  • You are running F5 Insight 1.2.x.
  • You experience storage degradation or software upgrade failures.

Cause

High volumes of telemetry ingestion, trace logs, internal query histories, or long metric retention cycles can cause the internal analytics data stores (ClickHouse and VictoriaMetrics) to consume the primary storage partition allocated under /opt/f5insight/data. In many environments, this is compounded when F5 Insight has been provisioned with less than the minimum required storage specifications.

Recommended Actions

  • Review the minimum hardware requirements for your F5 Insight deployment to ensure it complies with the recommended sizing requirements. For more information about sizing requirements for F5 Insight, refer to the F5 Insight Deployment Guide on F5 Cloud Docs.
  • If F5 Insight is provisioned with disk capacity below the minimum requirements, expand the underlying virtual disk and filesystem. For more information about how to increase virtual disk storage for F5 Insight, refer to K000163707: Increase F5 Insight virtual hard disk storage after deployment.
  • If disk space is limited, old upgrade and ISO images can be purged to free up storage space. Note that if an ISO image is currently linked to an active or pending upgrade job, the system will prevent you from deleting it until that job is cleared.

If physical VM expansion is not immediately possible and database truncation is required, you can open a support case with F5 Support for assistance in safely clearing log tables or adjusting retention settings. Running database truncations and Kubernetes StatefulSet modifications requires administrative platform access.
