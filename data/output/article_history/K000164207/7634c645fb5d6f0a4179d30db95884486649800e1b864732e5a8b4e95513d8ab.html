Description

This article describes a behavior change introduced in BIG-IP versions 17.1.3.5, 17.5.1.9, and 21.1.0.2 that enforces the RFC 3411 maximum length of 32 octets for the SNMPv3 engineID value configured using:

sys snmp include

Beginning in the following BIG-IP versions, a configuration constraint is enforced on the sys snmp include field that restricts the engineID value to a maximum of 32 octets, in compliance with RFC 3411:

  • 17.1.x: 17.1.3.5
  • 17.5.x: 17.5.1.9
  • 21.1.x: 21.1.0.2

This constraint is enforced at configuration commit time and applies to all configuration interfaces:

  • TMSH
  • iControl REST
  • iControl SOAP

Symptoms

You may observe the following symptoms following this change:

  • Symptom 1 - Configuration rejected on fixed versions when attempting to set an engineID value exceeding 32 octets, the system rejects the commit immediately. For example: 
    TMSH error: 01070903:3: Constraint 'engineID value in include must not exceed 32 octets (RFC 3411 SnmpEngineID max)' failed for '/Common/snmpd' iControl REST error (HTTP 400): { "code": 400, "message": "01070903:3: Constraint 'engineID value in include must not exceed 32 octets (RFC 3411 SnmpEngineID max)' failed for '/Common/snmpd'", "errorStack": [], "apiError": 3 }
  • Symptom 2 - Post-upgrade configuration load failure If a device had an engineID value longer than 32 octets already present in /config/bigip_base.conf before upgrading to a fixed version. The automatic post-upgrade configuration load fails. This results in the following:
    • mcpd stuck in config-load-in-progress state with an error similar to the one in symptom 1.
    • Loss of management connectivity
    • Manual reboot may temporarily restore access to the prior boot volume or console, but does NOT resolve the base config failure on the upgraded volume until the configuration is corrected.

Impact

Any BIG-IP device that has an engineID value longer than 32 octets set under sys snmp include, and is upgraded to BIG-IP 17.1.3.5, 17.5.1.9, or 21.1.0.2 will experience a post-upgrade configuration load failure until the oversized engineID value is corrected.

Environment

  • BIG-IP versions:
    • 17.1.x: 17.1.3.5
    • 17.5.x: 17.5.1.9
    • 21.1.x: 21.1.0.2

  • SNMPv3 engineID value configured using:

    sys snmp include

Cause

Beginning in the following BIG-IP versions, a configuration constraint is enforced on the sys snmp include field that restricts the engineID value to a maximum of 32 octets, in compliance with RFC 3411.

Recommended Actions

Depending on the state of your BIG-IP system, perform one of the following:

  • Before an upgrade:
    The configuration is loaded and you want to verify the current engineID value and its length. 
    1. To verify, use one of the following:
      • TMSH (shell):
        tmsh list sys snmp include
      • on bash, review the configuration file:
        grep -i "engineID" /config/bigip_base.conf
    2. If an engineID value is present and exceeds 32 octets/characters, correct it by performing Set a valid engineID value (32 octets or less) that is compliant or remove the non-compliant value in the Additional Information section.
    3.  Verify the system is loaded with the RFC compliant value by performing the Verification step in the Additional Information section. 
  • After an upgrade:
    The configuration failed to load (See symptom 2). 

    If the system is already in the state where the configuration failed to load after an upgrade, do the following:

    1. Login to to bash on the BIG-IP.
    2. Manually edit /config/bigip_base.conf:
      1. Enter the following command:
        vi /config/bigip_base.conf
      2. Locate the sys snmp block and either remove the include line or replace it with a valid value of 32 octets or less. For example: 
        sys snmp { ... include "engineID " ... }
    3. Reload the configuration:
      tmsh load sys config
    4. Save the configuration after the configuration loads successfully:
      tmsh save sys config 
    5. Verify the system is loaded with the RFC compliant value by performing the Verification step in the Additional Information section. 


    Note    : You cannot run tmsh modify sys snmp include to clear an invalid value when mcpd is in a failed config-load state. You must edit /config/bigip_base.conf directly in this scenario.

Additional Information

Set a valid engineID value (32 octets or less) that is compliant or remove the non-compliant value

Do one of the following to implement the engineID RFC compliance. Enter the following on the bash:

  • modify the engineID to a value compliant with RFC 3411 (<= 32 octets)
    tmsh modify sys snmp include "engineID 0x80001f8880e64c9b"
    tmsh save sys config
  • Remove the include value if a custom engineID is not required. This applies if include contains only the engineID. Enter the following on bash:
    tmsh modify sys snmp include none
    tmsh save sys config

Verification

After remediation, verify that the configuration loads cleanly and the daemon is active:

  • Check the include value using TMSH:
    tmsh list sys snmp include
  • Check the value is rendered correctly in the runtime daemon config:
    grep -in "engineID" /run/config/snmpd.conf
    You should expect the engineID value to be 32 octets or less and snmpd is running without errors.
