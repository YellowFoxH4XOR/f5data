K000161621: REST API Access Blocked After BIG-IP Upgrade (17.5.1.4 / 17.1.3.1) to httpd Allow List Enforcement

Published

Description

After upgrading BIG-IP LTM to version 17.5.1.4 / 17.1.3.1, iControl REST API calls fails. Potential errors include "Cannot index into a null array." or 403 Forbidden. 

This occurs because the script receives an HTML-formatted 403 error page from Apache instead of the expected JSON response, causing the script to fail when attempting to parse the response.  These failures may extend to tools which utilize REST API which worked previously.

 

Environment

Product: BIG-IP LTM

Affected versions: 17.5.1.4 and later (also applies to 17.1.3.1 and later within the 17.1.x branch)

Feature: iControl REST API, sys httpd allow list

Condition: Source IP addresses making REST API calls are not included in the sys httpd allow list.

Cause

A security-related change was introduced in BIG-IP 17.5.1.4 (and similarly in 17.1.3.1) that extended the enforcement of the sys httpd allow list to cover iControl REST API access in addition to the Configuration Utility (GUI).

Prior to 17.5.1.4: The sys httpdallow list only restricted access to the BIG-IP Configuration Utility (GUI). iControl REST API access was not governed by the allow list.

Starting with 17.5.1.4: The sys httpd allow list now also governs iControl REST API access. REST API requests from source IPs not present in the allow list are blocked at the Apache httpd layer with an HTTP 403 Forbidden response.

Answer/Recommended Actions

  1. Add the IP address(es) of the hosts making iControl REST API calls to the BIG-IP sys httpd allow list.
  2. Log in to the BIG-IP Configuration Utility (GUI).
  3. Navigate to System >> Configuration >> Device >> General
  4. Locate the IP Allow Path section under the httpd settings.
  5. Add the source IP address(es) or subnet(s) that need REST API access.
  6. Save the configuration.

Alternatively, use tmsh to update the allow list:

tmsh modify sys httpd allow add { <source-IP-or-subnet> }

tmsh save sys config

After adding the IP(s) to the allow list, retry the REST API calls.

Additional Information

-The "Cannot index into a null array" error is a client-side symptom of receiving a non-JSON response. When the BIG-IP returns an HTML 403 page, scripts expecting JSON will fail to parse the response and produce misleading errors. The root cause is the 403 block at the Apache layer.

-This behavioral change was introduced as a security improvement to close an exposure where the REST API was accessible from any source IP regardless of the httpd allow list configuration.

-Community-contributed tools, including those those which utilize REST API, are not officially supported by F5. If you suspect a plugin is not functioning due to this issue, you can add the source IP it queries from to the httpd allow list as a troubleshooting step.
