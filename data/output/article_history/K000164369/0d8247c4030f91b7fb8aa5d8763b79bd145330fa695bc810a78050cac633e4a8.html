K000164369: Default VIP - Default tenant VIP is not in the F5 XC IP Address and Domain Reference

Description

"Our tenant was assigned a public IP address, but we can't find that IP or its range in the F5 Distributed Cloud Services IP Address and Domain Reference. Which IP addresses do we need to allow on our firewall?"

  • The customer has a default dedicated public VIP assigned to their tenant and is configuring firewall or proxy allowlists.
  • The VIP, or the /24 it belongs to, doesn't appear in the IP Address and Domain Reference.
  • The customer isn't sure whether to allow the VIP, the published ranges, or both.

Environment

  • F5 Distributed Cloud Services, with apps delivered through Regional Edges (REs)

  • HTTP/HTTPS or TCP Load Balancer with VIP Advertisement set to Internet (uses the default tenant VIP)

Cause

The default tenant VIP and the published RE ranges do different jobs:

  • Default tenant VIP: the public destination address that clients connect to. It is announced by anycast from all Regional Edges, as part of a larger F5 prefixes. F5 documents its address space as ranges, not individual tenant IPs, so the VIP isn't listed on its own.
  • RE ranges in the IP Address and Domain Reference: the source addresses that F5 uses toward the customer's origin. Regional Edges are full proxies. The client's connection ends at the RE, and the RE opens a new connection to the origin from these ranges (this includes health checks).

Recommended Actions

Inbound to the origin servers: allow all RE ranges, for all regions, listed in F5 Distributed Cloud Services IP Address and Domain Reference for Firewall or Proxy Settings (TCP 80/443). Allowing only some ranges can cause health check failures and traffic drops, because any RE can serve the application.
