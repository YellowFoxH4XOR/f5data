K000163382: BIG-IP OCSP Validation May Fail When SHA-256 Is Configured for Request Signing

Type
Support Solution
Published
2026-10-07
Updated
2026-10-07
Applies to
  • BIG-IP
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K000163382

Description

The BIG-IP OCSP certificate validator incorrectly uses the configured Request Signing Hash algorithm to generate certificate identification (Cert ID) hashes. When SHA-256 is used, some OCSP responders return responseStatus: unauthorized (6) instead of a valid certificate status.

Environment

  • Product: BIG-IP LTM
  • Feature: OCSP certificate validation
  • Configuration:
    • OCSP validator
    • Server SSL profile with OCSP validation enabled
    • Virtual server for outbound TLS connections
  • Possible deployment: F5 SSL Orchestrator outbound connections
  • OCSP responder: Certificate authorities that support only SHA-1 Cert ID hashes
  • Relevant setting: Request Signing Hash
    • Default: SHA-256
    • Intended to control the hash algorithm used to sign the OCSP request when request signing is enabled

Cause

The OCSP validator applies the Request Signing Hash setting to the certificate identification hashes. This can cause SHA-256 Cert ID hashes to be sent to responders that support only SHA-1.

The Cert ID hash algorithm and the OCSP request-signature hash serve different purposes and should be configured independently.

Answer/Recommended Actions

  1. Identify the OCSP validator associated with the Server SSL profile.
  2. Test OCSP validation against a certificate authority that supports only SHA-1 Cert ID hashes.
  3. Review the OCSP validator statistics and capture the OCSP request and response.
  4. Confirm whether the request contains:
    • hashAlgorithm (sha256) and the responder returns unauthorized (6), or
    • hashAlgorithm (sha1) and the responder returns certStatus: good (0).
  5. As a workaround, set Request Signing Hash to SHA-1 when request signing is not required.
  6. If OCSP request signing is required, do not treat the SHA-1 setting as a complete solution because it also affects the request-signature hash.
  7. Apply the available fix for this issue. Contact F5 Support if assistance is required to identify the applicable fix.

Additional Information

The OCSP Cert ID hash is used by the responder to locate the certificate status. The request-signature hash is used only when the OCSP request is signed.

The expected behavior is:

  • Use SHA-1 for the Cert ID issuer name and issuer key hashes for compatibility with public OCSP responders.
  • Use the configured hash algorithm for request signing when request signing is enabled.

A successful OCSP HTTP response does not necessarily indicate that the certificate status was successfully processed. Confirm the OCSP protocol response and certificate status, such as certStatus: good (0), rather than relying only on the HTTP transaction.
