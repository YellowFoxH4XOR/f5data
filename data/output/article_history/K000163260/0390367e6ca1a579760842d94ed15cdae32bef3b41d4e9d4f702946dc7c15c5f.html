Description

BIG-IP may experience rapidly increasing swap utilization and control-plane memory exhaustion. Kernel messages may include:

  • Out of memory: Kill process ... (java) score ... or sacrifice child
  • Killed process ... (icrd_child)

This condition can cause swap space to become nearly or completely exhausted and may affect management-plane processes.

Environment

  • Product: BIG-IP LTM
  • Multiple TMM instances consuming shared memory
  • Control-plane memory allocations involving:
    • provision.extramb
    • provision.restjavad.extramb
    • provision.tomcat.extramb

Cause

The condition indicates system-level control-plane memory pressure rather than confirmed Java or JVM heap exhaustion.

Restjavad and Tomcat allocations may consume too much of the management memory allocation, leaving insufficient memory for other control-plane processes and TMM-related shared-memory usage. When the system requires additional memory, the Linux kernel may terminate Java or an icrd_child process to recover memory.

The Java process being terminated does not necessarily indicate that it exceeded its configured JVM heap limit.

Answer/Recommended Actions

Perform the following actions during an approved maintenance window on the Standby device first:

1.) Capture baseline diagnostic information. Review memory and swap utilization:

cat /proc/meminfo

2.) Adjust the memory allocation. Do not allow Restjavad and Tomcat to consume all management memory. 

NOTE: Only adjust the Restjavad and Tomcat if there's a need to do so. Sample scenario is when the device is experiencing Java or JVM heap exhaustion, or when F5 support Engineer suggested it to fix some issue. As a guideline, allocate maximum ~75% of the management memory to Restjavad and maximum ~12.5% to Tomcat.

Example maximum allocation values include below:

  • Management: 2048 MB
    Restjavad: 1536 MB
    Tomcat: 256 MB
  • Management: 4096 MB
    Restjavad: 3072 MB
    Tomcat: 512 MB
  • Management: 6144 MB
    Restjavad: 4608 MB
    Tomcat: 768 MB
  • Management: 8192 MB
    Restjavad: 6144 MB
    Tomcat: 1024 MB

3.) Modify the database settings with approved values:

tmsh modify sys db provision.extramb value <management_value>
tmsh modify sys db provision.restjavad.extramb value <restjavad_value>
tmsh modify sys db provision.tomcat.extramb value <tomcat_value>

4.) Save the configuration:

tmsh save sys config partitions all

5.) Restart the affected management services:

bigstart restart restjavad httpd restnoded tomcat

Additional Information

Restarting the system refreshes process and resource utilization, including Java-related services, but does not correct an unsuitable memory-allocation configuration.

Increasing Restjavad or Tomcat memory without increasing available management memory may worsen control-plane memory pressure.

Swap usage alone does not always indicate a memory leak. Review MemAvailable in /proc/meminfo; values below 300000 kB indicate significantly low available memory.
