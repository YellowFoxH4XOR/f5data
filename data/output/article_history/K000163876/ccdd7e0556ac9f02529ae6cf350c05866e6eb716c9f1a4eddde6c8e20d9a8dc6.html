K000163876: NGINX Instance Manager or NGINX One Console can be used to configure F5 NGINX WAF to Help Mitigate PHP Vulnerabilities (CVE-2026-109618 & CVE-2026-109619)

Description

  • You manage F5 NGINX WAF security policy from either NGINX Instance Manager or NGINX One Console
  • Following recent PHP Vulnerabilities announcement, F5/NGINX released Attack Signature library to mitigate these vulnerabilities
  • You want to enable these signatures for a security policy of your choice
  • Signature changelog entries in the 2026.10.21 library:
    • 200103697: Added Command Execution signature for PHP Remote Code Execution (2)
    • 200204115: Added Server Side Code Injection signature for PHP Remote Code Execution (3)
    • 200204113: Added Server Side Code Injection signature for PHP Remote Code Execution
  • Signatures 200103697 and 200204115 address CVE-2026-109618. Signature 200204113 addresses CVE-2026-109619.

Environment

  • NGINX Plus  
  • F5 NGINX WAF  
  • NGINX Instance Manager
  • NGINX One Console
  • NAP WAF compiler 
  • Up to date Attack signature library  

Cause

  • None

Answer/Recommended Actions

From NGINX Instance Manager / NGINX One Console and publishing it to data plane instances, the policy editor shows the following for newly added PHP Remote Code Execution signatures:

  1. Path: Policy > Edit > Attack Signature Exceptions
  2. Signature IDs 200103697, 200204115, and 200204113 can be added and show a status of Enabled.
  3. Signature Name, Attack Type, Accuracy, and Risk all display as shown below administrators can confirm from the user interface that the signatures are recognized and enabled .

Additional Information

Enabled status and metadata display are separate checks. A signature can show as Enabled while its name, attack type, accuracy, and risk fields are blank. The policy JSON is the recommended verification method.

  1. Confirm that the WAF Compiler matches the NGINX WAF version installed on managed instance/s. 
    1. For example, NGINX WAF 5.15.0 is managed by nms-nap-compiler-v5.715.0, following compatibility matrix 
  2. Confirm that the installed compiler has the current attack signature library. The compiler should have the same attack signature revision that is published to the instances.
  3. Verify that the signatures are enabled in the policy:
    1. Open the security policy in NGINX Instance Manager
    2. Go to Details and view the policy in JSON format.
    3. Check the signatures array. Each signature ID should appear with "enabled": true. Example structure:

      "signatures": [
      { "name": "PHP Remote Code Execution", "enabled": true, "signatureId": 200204113 },
      { "name": "PHP Remote Code Execution (3)", "enabled": true, "signatureId": 200204115 },
      { "name": "PHP Remote Code Execution (2)", "enabled": true, "signatureId": 200103697 }
      ]
