K000163644: MQTT connection RST by BIG-IP when EMQX Data Bridge mode is enabled with Protocol Version 0x84/132

Type
Support Solution
Published
2026-10-10
Updated
2026-10-10
Applies to
  • BIG-IP
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K000163644

Description

BIG-IP LTM resets MQTT client connections when a virtual server with an MQTT profile receives a CONNECT packet containing a non-standard protocol version value such as 0x84 (132). Standard MQTT v3.1.1 connections using protocol version 0x04 are processed normally. Packet capture shows the client sending CONNECT with Version: Unknown (132), followed by BIG-IP returning a Connect Ack and immediately closing the connection.

Environment

  • BIG-IP LTM 17.1.3

  • Virtual server configured with TCP and MQTT profiles

  • EMQX Data Bridge with bridge_mode enabled

  • Non-standard MQTT CONNECT protocol version 0x84 (132)

Cause

The BIG-IP MQTT profile enforces strict validation of the MQTT CONNECT protocol version and rejects non-standard values such as 0x84 (132). There is no supported configuration option to relax or bypass this validation, and iRules cannot modify the protocol version before MQTT profile validation occurs.

Answer/Recommended Actions

  • Remove the MQTT profile from the virtual server if non-standard MQTT protocol version values must be passed.

  • Alternatively, use a Performance (Layer 4) virtual server to bypass Layer 7 MQTT protocol inspection and validation.

  • If MQTT profile functionality is required, ensure the client or upstream application uses a standards-compliant MQTT protocol version such as 0x04 for MQTT v3.1.1.

  • Do not rely on iRules to rewrite the MQTT protocol version, as MQTT profile validation occurs before iRules can take effect.

Additional Information

  • Packet capture confirmed different behavior between standard and non-standard protocol versions:

    • Working: MQTT CONNECT with Version 0x04 proceeds normally.

    • Failing: MQTT CONNECT with Version 0x84 (132) is not accepted and the connection is terminated.

  • EMQX bridge_mode sets the high bit in the protocol version byte, changing 0x04 to 0x84 for bridge loop-detection or routing behavior.

  • No explicit LTM or ASM log message was identified for this validation failure.

  • This behavior is expected when the MQTT profile enforces protocol compliance checks.
