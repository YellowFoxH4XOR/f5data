K56427341: Learning and Blocking settings page not loading or spinning after upgrade

Type
Support Solution
Published
2021-01-05
Updated
2023-02-21
Applies to
  • BIG-IP
  • BIG-IP ASM: 16.X.X, 16.0.X, 16.1.3, 16.1.2, 16.1.1, 16.1.X, 16.0.1, 16.0.0, 16.1.0
Source
https://my.f5.com/manage/s/article/K56427341

Description

After an upgrade, the Learning and Blocking settings page just spins and shows Loading Learning and Blocking Settings.

In the browser console, an error like the following appears when navigating to the page with developer tools open:

Error: e.signatureSet is undefined

This may occur for all security policies, or only some. Newly created security policies are unaffected.

Environment

  • After upgrade
  • Security policy
  • GUI

Cause

Policy has a non-existent custom Attack Signature Set applied.

At time of publication, unknown how exactly this occurred.

A similar issue is bug ID 866665.

Recommended Actions

To confirm that the issue is present, first compare the signature sets assigned to the policy, with the overall signature sets configured and available to be assigned to policies.

If the issue is confirmed present, delete the non-existent set from the policy in question.

  1. Retrieve the id of the policy in question:

    curl -sku admin:<pw> https://localhost/mgmt/tm/asm/policies?\$select=name,id | jq .

  2. Review the attack signature sets assigned:

    curl -sku admin:<pw> 'https://localhost/mgmt/tm/asm/policies/<policy id>/signature-sets?$select=signatureSet,name,id' | jq .

    Note the id value.

  3. Look in the MySQL database and check if the id of each signature set corresponds with the rest_uuid for each available set.

    mysql -u root -p$(perl -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw) -e 'SELECT set_id,set_name,rest_uuid from PLC.NEGSIG_SETS'

    If there is an signature set id in the policy that isn't in the PLC.NEGSIG_SETS table, then the issue is present. This non-existent set will need to be removed from the policy.

  4. Utilize the REST API to delete the reference to the non-existent attack signature set from the policy.

    curl -sku admin:<pw> 'https://localhost/mgmt/tm/asm/policies/<policy id>/signature-sets/<set id>' -X DELETE | jq .

The Learning and Blocking Settings page will now load. This procedure will need to be repeated for other affected policies. It could be scripted if there are many policies.
