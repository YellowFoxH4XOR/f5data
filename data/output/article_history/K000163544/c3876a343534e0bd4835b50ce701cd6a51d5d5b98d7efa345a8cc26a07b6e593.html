K000163544: BIG-IP APM HTTP AAA Authentication Fails with invalid command name

Type
Support Solution
Published
2026-10-05
Updated
2026-10-05
Applies to
  • BIG-IP
  • BIG-IP APM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000163544

Description

BIG-IP APM form-based HTTP AAA authentication can fail during access-policy evaluation with the following error:

Rule evaluation failed with error: invalid command name "FFFFFFFFFFFFFFFF"

When this occurs, the HTTP Auth action does not construct or send a request to the configured AAA HTTP server.

Environment

  • BIG-IP APM
  • Access policy with a form-based HTTP Auth action
  • HTTP AAA server configured for authentication
  • Hidden Form Parameters/Values containing session variables
  • Parameters such as:
    • %{session.logon.last.password}
    • %{session.ad.last.attr.gAuthCode}

Cause

The Hidden Form Parameters/Values field uses a space-separated or multiline format that is rejected during access-policy evaluation after CRLF hardening. When a session variable expands to a value such as FFFFFFFFFFFFFFFF, APM can interpret the value as a command and report:

invalid command name "FFFFFFFFFFFFFFFF"

The failure occurs before the HTTP AAA request is created. Therefore, the AAA server receives no request, even when it is reachable and returns 200 OK during an independent test.

This behavior is associated with Bug ID 2503533. A fix is available.

Recommended Actions

  1. Review the APM access-policy logs and confirm whether the following error is present:

    invalid command name "FFFFFFFFFFFFFFFF"

  2. Confirm that the HTTP Auth action references the intended HTTP AAA server.
  3. Review the Hidden Form Parameters/Values field.
  4. Use ampersand-delimited name=value pairs instead of a space-separated or multiline format. For example:

    pass=%{session.logon.last.password}&userkey=%{session.ad.last.attr.gAuthCode}&offset=1&key_size=60&hmac_mode=hmac-sha1

  5. Test authentication with a new access-policy session.
  6. Confirm that:
    • The access policy completes successfully.
    • The HTTP AAA server receives the request.
    • The expected authentication result is returned.
  7. Apply a software fix that addresses Bug ID 2503533 if the multiline format is required.

Additional Information

An independent 200 OK response from the HTTP AAA server confirms that the server can respond to direct requests. It does not confirm that APM successfully evaluates the access policy or constructs the HTTP AAA request. No request to the AAA server appears in a packet capture when access-policy evaluation fails before the HTTP Auth request is created.
