K000163814: ssl_ecdh_curve in a non-default server block does not disable ffdhe2048

Type
Support Solution
Published
2026-10-21
Updated
2026-10-21
Applies to
  • NGINX Products
  • NGINX Plus: 37.0.2
Source
https://my.f5.com/manage/s/article/K000163814

Description

When multiple TLS server blocks share the same listen IP address and port, NGINX Plus can continue to offer the ffdhe2048 finite-field group even when ssl_ecdh_curve in the SNI-matched, non-default server block excludes it. For example, testssl.sh may report:

Finite field group: ffdhe2048 ffdhe3072 ffdhe4096 ffdhe6144 ffdhe8192

Environment

  • NGINX Plus R37 (nginx/1.29.8, nginx-plus-r37.0.4)

  • OpenSSL 3.5.5

  • Enterprise Linux 9.8

  • NGINX configured as a TLS-terminating load balancer

  • Multiple TLS server blocks sharing the same listen IP address and port

  • SSL directives configured at the server level

Cause

For shared TLS listeners, the key-exchange-group list is taken from the default server. With OpenSSL 1.0.2 and later, this list is copied to the connection when it is created and is not replaced after NGINX selects the SNI-matched server block.

If ssl_ecdh_curve is not configured in the default server, the default value auto applies. OpenSSL then uses its configured group list, which can include ffdhe2048. Consequently, an ssl_ecdh_curve setting in a non-default server block does not affect the connection.

Answer/Recommended Actions

  1. Configure ssl_ecdh_curve in the http context so that all server blocks, including default servers, inherit the same group list:

    http {

        ssl_ecdh_curve X25519MLKEM768:X25519:secp384r1;

    }

    If finite-field groups are required, include only the permitted groups. For example:

    http {

        ssl_ecdh_curve X25519MLKEM768:X25519:secp384r1:ffdhe3072:ffdhe4096;

    }

  2. Alternatively, configure ssl_ecdh_curve in the default server for every TLS listen IP address and port.

  3. Do not combine ssl_ecdh_curve with ssl_conf_command Groups, because both directives configure the OpenSSL key-exchange-group list. A server-level ssl_conf_command also replaces inherited ssl_conf_command directives.

  4. Validate and reload the configuration:

    nginx -t
    nginx -s reload

  5. Verify that ffdhe2048 is disabled by scanning with testssl.sh, or by attempting a TLS 1.3 handshake that offers only ffdhe2048:

    openssl s_client -connect example.com:443 -servername example.com -tls1_3 -groups ffdhe2048

    A handshake failure indicates that ffdhe2048 is disabled.

Additional Information

This behavior is expected NGINX and OpenSSL behavior and is not a product defect requiring a later release. Configuring ssl_ecdh_curve in the default server prevents NGINX Plus from offering ffdhe2048 when that group is excluded from the configured list.
