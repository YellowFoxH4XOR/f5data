K000152951: ASM false positives for legitimate traffic after an upgrade to version 17.1.x

Type
Support Solution
Published
2025-08-11
Updated
2025-08-11
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.1.1, 17.1.2, 17.1.0
Source
https://my.f5.com/manage/s/article/K000152951

Description

On BIG-IP Advanced WAF (AWAF) version 17.1.x, legitimate requests may be incorrectly blocked with "Illegal method" violations, such as HTTP POST or GET, even when these methods are explicitly allowed in the security policy.

Error messages and logs may include the following:

  • ASM subsystem error: Watchdog detected failure for process. Process name: asm_config_server.pl, Failure: Insufficient number of threads (required: 3, found: 0).
  • dcc|ERR| [tsconfd::ASMCONFIG_CALL, update mcp device group device] Failed due to Thrift exception: connect() failed: Connection refused

Environment

  • BIG-IP Advanced WAF (AWAF) / ASM 17.1.x, including 17.1.2.1
  • Large number of ASM policies, for example, 200 or more 
  • /var partition sized below the recommended value, for example, 4.5 GB
  • Upgrades or configuration sync operations involving ASM policies

Cause

A change introduced in BIG-IP version 17.1.x altered how running ASM configurations are loaded into the bd process, requiring significantly more space in the /var partition than previous versions. If /var does not have sufficient free space during policy load, upgrade, or config sync operations, temporary files can fill the partition and cause MySQL DCC database corruption. This leads to unpredictable ASM behavior including blocking of legitimate HTTP methods and policy misalignment. This issue is tracked as Bug ID1694693.

Recommended Actions

There are two methods to fix the issue:

  1. Follow the workaround for ID1694693, and then perform the upgrade again.
  2. Export and re-import the security policies that demonstrate the misbehavior. This action will repopulate the ASM databases and will fix the issue. In case of large configurations and the desire to follow the same action for all policies for proactive reasons, the script below can be used.
1. Create the bash script export_import_apply.sh, you can use vim or nano.

# vim export_import_apply_partition.sh

2. Paste the script below and save the file.

#!/bin/bash

# --- Configuration ---
EXPORT_DIR="/var/tmp" # Directory on BIG-IP where policies will be temporarily saved
EXPORT_FORMAT="bin-file" # Use 'bin-file' for .plc, 'xml-file' for .xml, 'min-xml-file' for compact xml
DATE_SUFFIX=$(date +%Y%m%d%H%M%S) # Unique suffix for exported files

# --- Partition Argument ---
# Usage: $0 [/PARTITIONNAME]
# Defaults to /Common if no argument given.
# Accepts partition with or without leading '/' (e.g. "TESTPARTITION" or "/TESTPARTITION").
RAW_PARTITION="${1:-/Common}"
PARTITION="/${RAW_PARTITION#/}" # Ensure leading '/'
PARTITION="${PARTITION%/}"       # Strip any trailing '/'

echo "--- Starting ASM Policy Export/Import/Apply Script ---"
echo "Partition:        $PARTITION"
echo "Export Directory: $EXPORT_DIR"
echo "Export Format:    $EXPORT_FORMAT"
echo "Timestamp:        $DATE_SUFFIX"
echo ""

# --- Step 1: List all security policies in the specified partition ---
echo "1. Listing security policies in partition '$PARTITION'..."
POLICIES=$(tmsh -q -c "cd ${PARTITION}; list asm policy" | grep 'asm policy' | awk '{print $3}')

if [ -z "$POLICIES" ]; then
    echo "No ASM policies found in partition '$PARTITION'. Exiting."
    exit 1
fi

echo "Found policies:"
echo "$POLICIES"
echo ""

# --- Step 2: Export each security policy ---
echo "2. Exporting security policies..."
for POLICY_NAME in $POLICIES; do
    EXPORT_FILE="${EXPORT_DIR}/${POLICY_NAME}_${DATE_SUFFIX}.${EXPORT_FORMAT/bin-file/plc}"

    echo "  Exporting policy '$POLICY_NAME' to '$EXPORT_FILE'..."
    tmsh -q -c "cd ${PARTITION}; save asm policy ${POLICY_NAME} ${EXPORT_FORMAT} ${EXPORT_FILE}"
    if [ $? -eq 0 ]; then
        echo "    Export successful."
    else
        echo "    ERROR: Failed to export policy '$POLICY_NAME'."
    fi
done
echo "Finished exporting policies."
echo ""

# --- Step 3: Import each security policy ---
echo "3. Importing security policies..."
for POLICY_NAME in $POLICIES; do
    IMPORT_FILE="${EXPORT_DIR}/${POLICY_NAME}_${DATE_SUFFIX}.${EXPORT_FORMAT/bin-file/plc}"

    echo "  Importing policy '$POLICY_NAME' from '$IMPORT_FILE'..."
    # The 'overwrite' keyword is crucial for re-importing existing policies.
    tmsh -q -c "cd ${PARTITION}; load asm policy ${POLICY_NAME} overwrite file ${IMPORT_FILE}"
    if [ $? -eq 0 ]; then
        echo "    Import successful."
    else
        echo "    ERROR: Failed to import policy '$POLICY_NAME'."
    fi
done
echo "Finished importing policies."
echo ""

# --- Step 4: Apply (Publish) each imported security policy ---
echo "4. Applying (publishing) security policies..."
for POLICY_NAME in $POLICIES; do
    echo "  Publishing policy '$POLICY_NAME'..."
    tmsh -q -c "cd ${PARTITION}; publish asm policy ${POLICY_NAME}"
    if [ $? -eq 0 ]; then
        echo "    Publish successful."
    else
        echo "    ERROR: Failed to publish policy '$POLICY_NAME'."
    fi
done
echo "Finished publishing policies."
echo ""

# --- Cleanup (Optional) ---
echo "5. Cleaning up exported policy files from $EXPORT_DIR..."
# Uncomment below to enable cleanup:
# find "$EXPORT_DIR" -maxdepth 1 -name "*_${DATE_SUFFIX}.*" -delete
# echo "  Temporary files deleted."
echo "Cleanup step skipped for this example. Files remain in $EXPORT_DIR."
echo ""

echo "--- ASM Policy Export/Import/Apply Script Completed ---"

3. Run the script to process the policies in the /Common partition, and wait for the process to finish.

# bash export_import_apply_partition.sh

4. If you have additional security policies in partitions other than /Common, run the following command to process the policies in all custom partitions.

# for partition in `tmsh list auth partition one-line | awk '{print "/" $3}' | grep -v Common`; do bash /var/tmp/export_import_apply_partition.sh $partition ;done
