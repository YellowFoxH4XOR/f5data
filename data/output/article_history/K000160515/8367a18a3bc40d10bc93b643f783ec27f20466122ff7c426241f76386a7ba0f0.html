Topic

This article explains how to install and run the F5 System Scanner on BIG-IP and standard x86_64 Linux systems. The F5 System Scanner supports the following BIG-IP versions hotfixes (EHFs):

  • BIG-IP versions released between October 2025 and Sept 02, 2026
  • EHFs released between October 2025 and Sept 02, 2026

Notes:

  • F5 System Scanner does not support EHFs after Sept 02, 2026.
  • The F5 System Scanner requires Advanced Shell (bash) access and therefore cannot be run on systems configured in Appliance mode.

Description

Prerequisites

You need the following to perform the procedure in this article:

Important: F5 has released a new version of the F5 System Scanner and accompanying .ndjson files. The first version of the F5 System Scanner is no longer compatible with the new .ndjson files. To confirm you are using the correct version, run the ./f5-system-scanner command with no flags and confirm the usage requires the --dat-file-sha512 flag. If the usage requires the --sha256 flag, you must download a new copy of the F5 System Scanner.

  • BIG-IP host
  • Shell access as root to the target BIG-IP
  • Sufficient disk space on the target BIG-IP for output report files
  • Download the following files from MyF5 Downloads to the BIG-IP host:
    • F5 System Scanner (scanner utility)
    • <release_version>.ndjson (manifest file)
    • <release_version>.ndjson.sha512 (SHA-512 checksum file for .ndjson)

To download the files:

  1. Log in to the MyF5 Downloads site.
  2. For Group, select BIG-IP.
  3. For Product Line, select your BIG-IP branch. Then select your product version. A list of product containers will display.
  4. Under Select a product container, select the F5_System_Scanner option. A list of files to download will display.
  5. Download the </release_version>.ndjson file and the accompanying SHA-512 and MD5 files.
  6. Download f5-system-scanner and the accompanying SHA-512 files.

Procedure

Perform the following procedure to install and run the scanner on the BIG-IP system:

  1. Login to the BIG-IP host as root using SSH.

  2. Prepare the working directory:

    mkdir -p /var/tmp/scanner

  3. Change directory to the new directory:

    cd /var/tmp/scanner

  4. Copy the files you downloaded for the Linux x86_64 to : /var/tmp/scanner
  5. Enter the following command to make the scanner executable: 

    chmod +x ./f5-system-scanner

  6. Verify the integrity of the JSON file by entering the following command:

    sha512sum -c <release_version>.ndjson.sha512

    You should observe an output similar to the following:

    <release_version>.ndjson: OK

  7. Run the scanner by entering the following command:

    nice -n 19 ./f5-system-scanner \
    --dat-file ./<release_version>.ndjson \
    --dat-file-sha512 "$(cut -d' ' -f1 <release_version>.ndjson.sha512)" \
    --root / \
    --format text \
    --progress \
    --output ./scanner-report.txt

    Note: F5 recommends that you use the nice tool to run the scanner at a lower priority to help reduce CPU usage.

    You should observe an output similar to the following:

    f5-system-scanner: 97 skip patterns active (use --no-skip to disable)
    f5-system-scanner: 0 maybe patterns active (use --no-maybe to disable)
    f5-system-scanner: 1 allowlist patterns active

Additional information

Use the following optional flags on the F5 System Scanner as appropriate

  • --progress: Show live progress display
  • -v, -vv, -vvv: Increase verbosity

Platform resource usage

This is a single threaded utility that uses a single core to run, regardless of how many are available on the system. It uses between 3MB-15MB of memory. The approximate run time is expected to be between 1.5 to 3 minutes, but it may take longer depending on how busy the system is.

Scan running processes

Starting in version 1.2, f5-system-scanner can verify running processes by checking their in-memory binaries against a known-good manifest. This feature is also called a memory scan.

The process scan reads binary content directly from /proc and generates a SHA-512 hash for comparison. It does not execute, interpret, or load binary content into memory. The scan treats binary data as raw bytes for hashing only.

The process scan runs as a separate phase after the file integrity scan.

Scan modes

The process scan supports two modes. Both flags are opt-in and disabled by default.

Process scan flags
FlagDescription
--scan-procsScans only process executables that have been deleted from the disk (unlinked). Use this mode to detect execute-and-delete techniques.
--scan-all-procsScans all running processes and verifies their in-memory binaries against the manifest, even if the executable file still exists on the disk.

Note: When you use the --scan-all-procs flag, the scanner may report several unknown processes. At first, all running processes appear as unknown. As scanning progresses, the scanner moves each process to a matched or mismatched status. Some processes remain unknown because their file paths are not included in the installation image used to generate the manifest.

Process scan statuses

The following table describes the status values that the process scan can return.

Deleted-process statuses (--scan-procs and --scan-all-procs)

These statuses apply to processes with executables that have been deleted from the disk.

Deleted process statuses
StatusMeaning
DELETED_MATCHThe deleted binary's hash matches the manifest. This typically indicates an update.
DELETED_MISMATCHThe deleted binary's hash does not match the manifest. This may indicate a modification. Triggers exit code 1.
DELETED_UNKNOWNThe file path is not in the manifest. The scanner cannot verify the binary.
DELETED_ERRORThe scanner could not read the process. Common causes include insufficient permissions or a race condition.

Running-process statuses (--scan-all-procs only)

These statuses apply only when you use the --scan-all-procs flag.

Running process statuses
StatusMeaning
PROC_MATCHThe running binary's hash matches the manifest.
PROC_MISMATCHThe running binary's hash does not match the manifest. This may indicate a modification. Triggers exit code 1.
PROC_UNKNOWNThe file path is not in the manifest. The scanner cannot verify the binary.
PROC_ERRORThe scanner could not read the process. A PROC_ERROR status also appears when a process (that was running when the tool was run) stops running before the scanner can read its information. For example, PROC_ERROR PIDs 1839,4936 usr/bin/rsync (open /proc/1839/exe: no such file or directory)
