Description

On BIG-IP DNS (GTM), the named and zrd services fail to start and are reported as Down in the service list. The named service fails to load its configuration, reporting the following error:

/config/named.conf:51: the 'dnssec-validation yes' option requires configured 'trust-anchors'; consider using 'dnssec-validation auto'.

crit named[22015]: loading configuration: failure

crit named[22015]: exiting (due to fatal error)

notice systemd[1]: named.service: main process exited, code=exited, status=1/FAILURE

Environment

  • Product: BIG-IP DNS (GTM)
  • Software: BIG-IP 17.1.3.7 (BIND 9.20.26), previously running BIG-IP 17.1.3.2 (BIND 9.18.44)
  • Configuration: /config/named.conf line 51 contains dnssec-validation yes; with no trust-anchors statement. This setting was not changed by the upgrade.
  • GTM synchronization is enabled (synchronization yes, synchronize-zone-files yes) across a multi-device sync group. The same configuration load failure appears on each device in the group.

Cause

BIND 9.20 (shipped in BIG-IP 17.1.3.7) requires an explicitly configured trust-anchors statement when dnssec-validation yes is set. BIND 9.18 (shipped in 17.1.3.2) started without it and did not perform DNSSEC validation for zones lacking a matching trust anchor. The configuration that worked on 17.1.3.2 therefore prevents named from starting on 17.1.3.7, which in turn prevents zrd from starting.

Answer/Recommended Actions

Perform the following steps on each device, validating on one device before applying to the rest of the sync group.

IMPORTANT NOTE:

  • F5 strongly recommends creating a backup of every GTM unit in a syncgroup before implementing any changes and storing the backups in a secure, remote location. Refer to K13132.
  • Verify that a minimum of 3 GB of free disk space is available on each of the /var and /shared partitions before proceeding. Refer to K14403.
  • Retrieve the BIG-IP system's master key using the Bash shell and securely retain it with the UCS backup, following the instructions in K9420.
  • Implement all changes during a maintenance window.

 

  1. Check the named configuration file and the current status of the services:

    cd /var/named/config/

    ls -larth

    bigstart status zrd named

    bigstart stop zrd named

  2. Back up the configuration file before editing:

    cp named.conf named.conf.<date>.bak

  3. Edit named.conf (for example, vi named.conf) and change:

    dnssec-validation yes;

    to:

    dnssec-validation auto;

    Alternatively, if manual trust anchors are operationally required, add a valid trust-anchors configuration instead. Refer to the BIND configuration guide for the correct syntax.

  4. Start the services:

    bigstart start named

    bigstart status zrd named

    bigstart start zrd

    bigstart status zrd named

  5. Confirm that both services show as running. Verify that the named log no longer reports the trust-anchors error.

Additional Information

  • Expected behavior: with dnssec-validation yes, BIND 9.20 requires a trust-anchors statement. This is a behavior change from BIND 9.18 in 17.1.3.2, which started without it.
  • Unexpected behavior: named fails to load its configuration on 17.1.3.7, which prevents zrd from starting.
  • Changing to dnssec-validation auto does not require trust-anchors. Confirm the behavior you need before selecting auto or manual trust anchors.
  • Review DNSSEC validation settings before upgrading to BIND 9.20-based releases.
  • Reference: BIND 9.20 change requiring explicit trust-anchors with dnssec-validation yes.
