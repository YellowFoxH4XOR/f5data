K000163789: BIG-IQ device inventory tasks stuck in STARTED or FAILED status cannot be deleted

Type
Support Solution
Published
2026-10-20
Updated
2026-10-20
Source
https://my.f5.com/manage/s/article/K000163789

Description

BIG-IQ device inventory tasks can sometimes become permanently stuck in the STARTED or FAILED status (often hanging at the GatherResults step). When this occurs, attempts to clear the tasks via the GUI fail.

Environment

  • BIG-IQ Centralized Management 8.4.x

  • Device Inventory Tasks

  • PostgreSQL and Elasticsearch (tokumond) backend storage

Cause

The REST API worker daemon restjavad becomes deadlocked or the Elasticsearch index falls out of sync with the underlying PostgreSQL database for that specific task object. Because the REST framework cannot process updates to the corrupted record, standard API interactions are rejected, requiring manual database intervention.

Answer/Recommended Actions

To resolve this issue, you must manually delete the corrupted task from the PostgreSQL database and flush the Elasticsearch cache.

Impact of procedure: Modifying the PostgreSQL database directly carries inherent risks. F5 strongly recommends taking a full UCS backup and a VM snapshot of the BIG-IQ system before proceeding.

  1. Log in to the command line of the BIG-IQ system as the root user.

  2. Stop the REST and Elasticsearch services to prevent the database from being modified while you work:
    bigstart stop restjavad tokumond

  3. Access the BIG-IQ PostgreSQL Database:
    psql -U postgres -d bigiq_db

  4. List the current device inventory tasks to identify the specific API ID of the stuck tasks. Because BIG-IQ stores the REST payload as JSONB, you must query inside the _value column:
    SELECT _value->>'id' AS task_id, _value->>'status' AS task_status FROM bigiqtasks.device_tasks_device_inventory;

  5. Delete the corrupted task by matching the API ID extracted from the JSON payload (replace <STUCK_API_TASK_ID> with the ID identified in the previous step):
    DELETE FROM bigiqtasks.device_tasks_device_inventory WHERE _value->>'id' = '<STUCK_API_TASK_ID>';
    Note: The command should return DELETE 1.

  6. Exit the PostgreSQL prompt:
    \q

  7. Wipe the Elasticsearch index cache. Because the row was surgically removed from PostgreSQL, the Elasticsearch cache must be cleared so it is forced to rebuild from the cleaned database upon boot:
    rm -rf /var/config/rest/elasticsearch/data/*

  8. Restart the services:
    bigstart start tokumond restjavad

It will take a few minutes for BIG-IQ to come back online and re-index the database. Once the services are fully initialized, the stuck inventory task will be completely removed from the system.
