K000149224: Secure cookie attribute for /private/fm/cache-fm.js

Published

Applies to

Description

The secure attribute for the cookie appears not to be applied to cache-fm-Modern.js (/private/fm/cache-fm.js)


Environment

  • APM
  • Portal Access
  • Webtop


Cause

Some vulnerability scanners may incorrectly flag that the secure attribute is not set for all cookies. Additionally, examining the cookie in Developer Tools does not display the 'path=/; secure' attribute.


Example cookie

LastMRH_Session=be0d990c; TIN=300000; MRHSession=6dfb185d95881b7dd02a336abe0d990c; F5_fullWT=1; F5_ST=1736362712c900c100c1736362712c604800c600c


Recommended Actions

This is a false positive. The secure attribute is indeed enabled. The reason the 'path=/; secure' attribute does not appear in Developer Tools is that it is only added to the initial cookie (my.policy).

To confirm this, use the 'Cookies' option in Developer Tools to inspect the cookies directly.
