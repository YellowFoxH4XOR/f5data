K000163709: BIG-IP Edge Client Windows 7.2.7.x fails with SSL server certificate validation errors

Description

After upgrading to or installing BIG-IP Edge Client Windows 7.2.7.x, users may encounter one or more of the following issues when attempting to connect to the VPN gateway:

  • The connection fails during the TLS handshake with an SSL/TLS server certificate validation error (e.g., untrusted certificate authority, incomplete certificate chain, or validation failure).
  • Connections previously succeeded on versions prior to 7.2.7.x on the same client device and against the same BIG-IP APM virtual server.
  • Web browsers on the client machine connect to the same VPN URL without showing certificate warnings.

Environment

  • BIG-IP Edge Client Windows 7.2.7.x and later

Cause

This issue occurs when the BIG-IP virtual server presents only the leaf (server) certificate and omits intermediate Certificate Authority (CA) certificates during the TLS handshake, and the client machine does not have those intermediate certificates pre-installed in its local Windows Certificate Store. Without the intermediate certificates, the client cannot construct a valid chain of trust back to a trusted root CA, causing the TLS handshake to fail.

Why this worked in versions prior to 7.2.7.x

In BIG-IP Edge Client versions prior to 7.2.7.x, the Windows client used native Windows cryptographic APIs for TLS handshakes. Windows Schannel supports Authority Information Access (AIA) fetching (chasing). When a server omitted intermediate certificates, the client automatically initiated background HTTP requests to the external CA repository URL specified in the certificate's AIA extension to download the missing intermediate certificates.

Architectural modernization in version 7.2.7.x

Beginning in version 7.2.7.x, BIG-IP Edge Client for Windows transitioned to an updated, OpenSSL-based cryptographic architecture. For security and connection reliability reasons, the updated engine adheres strictly to modern TLS standards, which require the server to provide the complete certificate chain during the TLS handshake. As a result, the client does not perform automated, client-side AIA certificate chasing.

Answer/Recommended Actions

To resolve this issue, apply either the recommended server-side configuration on the BIG-IP system or deploy the intermediate certificates to client machines. Use the following options:

  • Option 1 (Recommended):
    Configure the intermediate certificate chain on the BIG-IP system. For more information, refer to the step-by-step instructions on configuring the certificate chain across BIG-IP versions in K13302: Configure the BIG-IP system to use an SSL chain certificate
  • Option 2:
    Deploy intermediate certificates to client endpoints If your organization utilizes an internal or private Public Key Infrastructure (PKI), ensure that all required intermediate and root CA certificates are pre-installed in the endpoint's trusted certificate store using your centralized device management platform.
    For example, using Active Directory Group Policy (GPO) to deploy intermediate CA certificates to the Intermediate Certification Authorities store on your Windows clients.
