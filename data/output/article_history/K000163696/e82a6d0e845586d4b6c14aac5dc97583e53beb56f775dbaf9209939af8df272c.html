Description

A BIG-IP DNS cache of type Validating Resolver validates DNSSEC signatures (RRSIG records) by establishing a chain of trust from a configured trust anchor to the requested DNS data. A trust anchor can be represented by a DS or DNSKEY record.

To validate public DNS data through the DNS root zone (.), configure an appropriate root-zone trust anchor. Without a root-zone trust anchor or another applicable trust anchor, the validating resolver cannot establish the chain of trust needed to authenticate that data.

A root-zone trust anchor enables validation of signed zones beneath the root when a valid chain of trust exists. It does not make unsigned zones DNSSEC-authenticated.

Note: Trust anchors configured for DNS cache of type Validating Resolver must be updated manually.

Environment

  • BIG-IP DNS
  • DNS cache configured as Validating Resolver

Cause

Not applicable. This article describes a configuration procedure.

Answer/Recommended Actions

1. Obtain an authenticated root-zone trust anchor

Obtain the appropriate root-zone DS or DNSKEY record from the authoritative IANA root trust-anchor publication:

https://www.iana.org/dnssec/files

Follow IANA’s instructions for authenticating the trust-anchor information and determining which anchors are appropriate for the rollover stage.

Important: Do not rely solely on an unauthenticated DNS query to establish initial trust. Do not remove an existing valid trust anchor until the published rollover guidance indicates that it can be retired.

2. Configure the trust anchor

Using the Configuration utility

  1. Log in to the Configuration utility.
  2. Go to DNS > Caches > Cache List.
  3. Select the validating resolver cache.
  4. Select the Trust Anchors tab.
  5. Select Add.
  6. Enter the authenticated DS or DNSKEY record in the format accepted by your BIG-IP version.

Using tmsh

  1. Connect to the BIG-IP system using SSH or the console.
  2. Add the authenticated record:

tmsh modify ltm dns cache validating-resolver <cache-name> trust-anchors add { "<authenticated-DS-or-DNSKEY-record>" }

Use add to preserve existing anchors. Do not replace or remove existing anchors unless required by your maintenance procedure.

Save the new config with

tmsh save sys config

3. Verify the configuration

Display the configured trust anchors:

tmsh list ltm dns cache validating-resolver <cache-name> trust-anchors

Test DNS queries through the DNS listener that uses this cache:

  • Confirm that a known valid, signed DNS response validates successfully.
  • Confirm that a deliberately invalid signed response fails validation under the configured validation policy.
  • Confirm that unsigned responses are not incorrectly treated as DNSSEC-authenticated.

Ensure that the test queries exercise this validating resolver rather than another resolution path.
