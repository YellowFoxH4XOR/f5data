K000163601: F5OS VELOS: Investigating High Partition-1 Image Volume Utilization

Type
Support Solution
Published
2026-10-08
Updated
2026-10-15
Applies to
  • F5OS Products
  • F5OS: 2.0.0
Source
https://my.f5.com/manage/s/article/K000163601

Description

A VELOS system may generate an SNMP alert indicating that Partition-1 image-volume utilization is growing rapidly:

  • partition1-image-volume-utilization
  • Partition-1 image volume utilization growth rate is high

The alert identifies the partition resource but does not identify the files consuming storage. The affected storage is the tenant image volume associated with the partition.

Environment

  • F5OS on a VELOS system
  • F5OS partition and tenant image management
  • SNMP monitoring of controller and partition storage
  • A partition and its associated system controllers
  • Tenant image volume:
    • /var/F5/partition1/IMAGES
  • The partition’s running-active controller may differ from the chassis-active controller.

Cause

Tenant image storage requires disk-space management. Storage growth may be caused by:

  • Files remaining after failed or abandoned tenant image uploads
  • Retained tenant images that are no longer required
  • Tenant images that remain configured for tenant deployments

Recommended Actions

  1. Log in to the VELOS system-controller CLI as a chassis administrator.
  2. Review the alarms and partition assignments:
    show system alarms
    show system volumes
    show partitions
  3. In the show partitions output, locate the affected partition ID and record:
    • The partition name
    • The controller that is running-active for the partition
    The partition’s running-active controller may differ from the chassis-active controller.
  4. As the root user, check the tenant image volume from the shell of each system controller:
    df -h /var/F5/partition1/IMAGES
    find /var/F5/partition1/IMAGES -exec ls -ldh {} +
    ls -lah /var/F5/partition1/IMAGES/.tmp/
  5. Compare utilization and file listings from both controllers (ssh controller-1 and ssh controller-2). Check whether files exist in:
    /var/F5/partition1/IMAGES/.tmp
  6. Before removing files from .tmp, confirm that:
    • No tenant image upload is in progress.
    • The files are associated with failed or abandoned uploads.
    • The files are not required for an active operation.
  7. Delete only specifically identified abandoned upload files on the affected controller. Do not:
    • Delete the .tmp directory.
    • Use a wildcard to remove files.
    • Remove files while an upload is in progress.
  8. If utilization remains high, review the retained tenant image inventory for the affected partition. Compare retained images with tenant deployment configurations.
  9. Remove a tenant image through partition image management only after confirming that no tenant references it and that it is no longer required.
  10. Recheck both controllers:
    df -h /var/F5/partition1/IMAGES
    Also review:
    show system alarms
  11. If the cause cannot be identified safely, collect:
    • The output of show system alarms
    • The output of show system volumes
    • The partition name and ID
    • The df -h output from both controllers
    • The find output from both controllers
    • The ls -lah output from both controllers
    • The status of recent tenant image uploads

Additional Information

  • The tenant image volume is different from the F5OS partition software ISO images displayed under Software Management → Partition Images.
  • Files left by failed uploads can cause differences in utilization between the two system controllers.
  • A tenant image may remain configured for a tenant after the BIG-IP software inside that tenant has been upgraded. Do not assume that the original deployment image is unused solely because the tenant is running a newer BIG-IP version.
  • Do not delete chassis-controller images or partition ISO images to resolve tenant image volume utilization.
