Security Advisory Description

In October 2026, Certificate Authority eMudhra Technologies Limited (emSign) disclosed an issue where the private keys of multiple intermediate Certificate Authority (CA) certificates were determined to be cryptographically weak and recoverable from public certificate data due to an internal key-generation flaw. While eMudhra reported no infrastructure breach and no evidence of unauthorized certificate issuance or malicious exploitation, eMudhra revoked the affected intermediate certificates, and major browser vendors, operating systems, and root store programs moved to block and distrust these intermediate and related root certificates.

The default trusted Certificate Authority bundle (ca-bundle.crt / f5-default.crt) distributed with supported versions of F5 BIG-IP and select F5 platforms include these affected eMudhra intermediate and root certificates. Although no active abuse has been observed, maintaining trust in these compromised intermediate CA certificates poses an ongoing security exposure: if an adversary derives the weak private keys, they could theoretically forge digital certificates that systems relying on the default CA bundle would validate as authentic.

F5 is actively assessing the scope across all product lines. An updated CA bundle that removes the affected certificates is available on the F5 Downloads site, and clean bundles will be integrated into upcoming software releases.

A system is exposed to this issue when all of the following conditions are met:

  • The system is running a supported version of F5 BIG-IP, BIG-IQ, or an evaluated platform that includes the default trusted CA bundle (ca-bundle.crt / f5-default.crt).
  • The default CA bundle has not been updated with the revised clean bundle released on the F5 Downloads site on November 18, 2026 (or later).
  • The system is actively configured to perform TLS client-side certificate validation against the default CA bundle. Specific examples include, but are not limited to:
    • A Server SSL profile has Server Authentication configured with Server Certificate set to require, and Trusted Certificate Authorities set to ca-bundle.crt or f5-default.crt.
    • An F5 SSL Orchestrator (SSLO) topology is configured for outbound traffic inspection with Server Authentication enabled and referencing the default CA bundle.
    • A BIG-IP APM authentication resource (such as LDAPS, RADIUS over TLS, SAML IdP metadata retrieval, or OCSP/CRL responders) validates peer certificates using the default CA bundle.
    • Management or control plane utilities (such as automated license activation, call-home/telemetry, or remote logging over TLS) establish outbound secure connections that validate remote servers against the system default trust store.

F5 is still researching the issue for the services indicated and will update this article with the most current information as soon as it has been confirmed. F5 Support has no additional information on this issue. This article supersedes the guidance in K000164159: Weak private keys in eMudhra intermediate Certificate Authority certificates.

Impact

Trusting a compromised intermediate CA certificate allows an attacker in possession of the leaked private keys to potentially issue fraudulent digital certificates. If an F5 device acts as a TLS client validating external peer certificates against the default CA bundle, an attacker performing a Man-in-the-Middle (MITM) attack could present a forged certificate that the F5 system trusts.

Product & Feature Scope

This issue affects any system component or feature that validates outbound or inbound TLS connections against the default system CA bundle (ca-bundle.crt or f5-default.crt):

BIG-IP

BIG-IP Control Plane & Management

System utility communications relying on TLS certificate verification (such as subscription licensing updates, NTP over TLS, and telemetry/support uploads).

BIG-IP Data Plane

Server SSL profiles configured to verify remote server certificates against the default CA bundle.

BIG-IP SSL Orchestrator: outbound forward-proxy traffic inspection where server certificate chain validation is enabled.

BIG-IP APM: External authentication paths (e.g., LDAPS, OCSP, CRLDP queries).

BIG-IQ Centralized Management

BIG-IQ follows the same CA bundle remediation steps as BIG-IP.

NGINX Products

NGINX products relies on underlying operating system trust stores and custom CA paths specified in configuration files.

Security Advisory Recommended Actions

If you are running a version listed in the Versions affected by this issue column, you can eliminate this issue by installing a version listed in the Fixes introduced in column. If the Fixes introduced in column does not list a version for your branch, then no update candidate currently exists for that branch and F5 recommends that you upgrade to a version with the fix (refer to the tables).

If the Fixes introduced in column lists a version prior to the one you are running, in the same branch, then your version should have the fix.

Mitigation

F5 strongly recommends that you mitigate this risk by updating your default CA bundle to an unaffected version.
