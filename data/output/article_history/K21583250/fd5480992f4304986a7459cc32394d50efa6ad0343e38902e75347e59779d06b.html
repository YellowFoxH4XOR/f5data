Description
BIG-IP Platform i2800 (C117) load UCS from other platform (migration) with command 'load /sys ucs <filename> no-license platform-migrate', the output indicates ucs been loaded successfully, however, the TMMs keep restarting and device is inoperative. Reboot the device will find below messages in the /var/log/ltm: 

Dec  4 17:10:16 I2800 info chmand[6609]: 012a0006:6:  HSBe2_v4 PCIs found. Dataplane ok.
Dec  4 17:10:16 I2800 emerg chmand[6609]: 012a0000:0: Dataplane INOPERABLE - Incorrect number of HSBs:1, Exp:2, TMMs: 4  : File sw/AtlantisSwSvc.cpp Line 152
Dec  4 17:10:16 I2800 emerg chmand[6609]: 01550004:0: Dataplane init error: Dataplane INOPERABLE - Incorrect number of HSBs:1, Exp:2, TMMs: 4

The symbolic link /config/firmware/hsb/current_version points to the correct firmware file 

  /config/firmware/hsb/current_version    ---> /usr/firmware/hsbe2v4_atlantis/L7L4_BALANCED_FPGA 

Environment

  • BIG-IP Platform i2800 (C117)
  • UCS migration

Cause
The feature HTSplit is disabled on the source device, where the UCS file has been created

Recommended Actions

perform one of the following actions:
  • Enable the HTSplit on the source device and create a fresh UCS, then load the fresh UCS on the i2800;
    Or
  • Enable the HTSplit on the i2800 with below tmsh commands, then reboot: 
modify sys db scheduler.splitplanes.ltm value true; save sys config 

if the mcpd not running, tmsh command may not working, use set_db command to set it to ture: 
set_db scheduler.splitplanes.ltm true
