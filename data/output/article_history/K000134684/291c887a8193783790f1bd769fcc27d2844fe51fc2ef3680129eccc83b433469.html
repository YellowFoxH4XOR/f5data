Topic

The VELOS partition services perform a variety of functions, such as managing partitions and tenants, and performing high availability (HA) failover actions between partition controllers. For a list of the VELOS chassis controller services, refer to K000134457: Overview of F5 VELOS chassis controller services.

Description

The partition services run on either the system controllers or the installed blades. The following tables list the various partition services that run on the system controllers or the installed blades, and the impact to the partition if each service is not running.

  • Partition Services running on system controllers
  • Partition Services running on installed blades

Partition Services running on system controllers

Service Name*DescriptionImpact if not running
part_<ID>_part_vers_<F5OS-C running version>_versThis service is a null service that serves as a placeholder for the internal platform network namespace. This service has no real function except to exist. If this service is not running, platform-services would be inoperative, and manually restarting them would not fix the system. All these services are auto-restarted by docker when the system deems it necessary.
Important: You must not manually restart these containers using the docker restart command, otherwise the system may become inoperative.

Container image name: partition_network

The platform-services would be completely inoperative. The only way to recover is to reboot the controller.
partition_<ID>_alert_serviceLike the alert-service service running on the chassis system controllers, each partition runs an instance of this service. The installed blades and the standby partition controller forward all their alert messages to the alert service on the active partition controller. The alert service on the active partition controller aggregates all alerts and publishes them to ConfD.

Container image name: alert_service

No alert is captured at the partition level.
partition<ID>_authentication-mgrSimilar to the authentication-mgr service running on the chassis system controllers, each partition runs an instance of this service. This authentication service manages the configuration settings for Authentication, Authorization, and Accounting (AAA) at the partition level. F5OS uses standard Linux PAM modules for local and remote authentication.

Container image name: authentication-mgr

No authentication configuration changes can occur.
partition<ID>_cliThis service runs an SSH server for the partition. It also allows SCP uploads to the IMAGES/ and configs/ directories as well as SCP downloads from shared/qkview/, log/ and configs/ directories.

Container image name: partition_cli

Unable to SSH to the partition; unable to SCP upload/download files to/from the allowed directories.
partition<ID>_diag-agentThis service performs diagnostic activities on the installed blades at the partition level.

Container image name: psf-diagnostic-agent-partition

No diagnostics data available.
partition<ID>_fips-serviceThis service enables FIPS_MODE when FIPS license is activated. It propagates FIPS configuration to applicable services and monitors cryptographic errors.

Container image name: fips-service

FIPS device is unavailable to BIG-IP tenants.
partition<ID>_guiThis service runs an instance of the partition web user interface for each partition configured on the VELOS system.

Container image name: partition-gui

No web user interface is available for the partition.
partition<ID>_haThis service controls the high availability (HA) framework between the system controllers at the partition level. It performs file synchronization between the active and standby system controllers at the partition level and subscribes to the vcc-partition-agent service for management port and slot membership information. Additionally, this service sends gratuitous ARPs when a partition floating IP address changes location.

Container image name: partition_ha

High availability fails to work at the partition level; this results in the partition being unable to function properly.
partition<ID>_http-serverThis service is based on Apache and provides the webUI and REST API to the partition. It is also used for ConfD SSL termination.

Container image name: http-server

No access to partition webUI and REST API.
partition<ID>_ihealth-serviceThis service handles the upload of QKViews to the F5 iHealth portal at the partition level.

Container image name: support-service

Unable to upload partition QKViews to iHealth portal.
partition<ID>_image_agentThis service manages the import, list, and removal of tenant images for each partition. It performs tenant image verification during import and replicates verified tenant images to the standby controller at the partition level.

Container image name: partition-image-agent
  • No tenant image available for deployment.
  • Unable to upload tenant image to partition.
  • Unable to remove tenant image from partition.
  • The list of tenant images on the standby partition controller is not in sync with the active partition controller.
partition<ID>_L2This service is responsible for publishing data path configurations related to system like interfaces, port groups, port mappings. It is primarily used to update Confd with the configuration and status of these objects. It works with the partition_L2 service running on each blade in the partition.

Container image name: l2_agent

The partition is unable to configure and report the status of the L2 objects such as interfaces, port groups, port mappings on the assigned blade(s).
partition<ID>_lacpdThis service manages the data plane Link Aggregation Groups (LAGs) for the interfaces configured to be in a LAG for each partition. This service works with the lacpd service on each blade in the partition and updates Confd the status of each LAG in the partition.

The logs are captured in /var/F5/partition<ID>/log/velos.log file on the system controller.

To enable/disable debug logging, enter config mode and commit the following changes:

  • Enable debug logging: system logging sw-components sw-component lacpd config severity DEBUG
  • Disable debug logging: system logging sw-components sw-component lacpd config severity INFORMATIONAL

Container image name: lacpd

The data plane LAG(s) will not be available for the partition.
partition<ID>_license_serviceThis service retrieves the license installed at the chassis level and passes it on to each partition and the deployed tenant(s).

Container image name: license_service

Deployed BIG-IP tenant does not have an activated license.
partition<ID>_managerThis service runs a ConfD instance for the partition. It manages various configuration data such as the assigned blades to the partition, the partition networking information, etc.

Container image name: partition_manager

No partition configuration is available; the partition does not function properly.
partition<ID>_monitorThis service provides monitoring of various partition components such as the following:
  • Monitors the health of other software services in the partition, such as counting service restarts, directly querying for health info provided by a service.
  • Monitors the sensors such as temperature and power throughout the partition.
  • Monitors firmware updates.
  • Saves historical statistics into RRD files which can be queried by other services and collected by the QKView process for troubleshooting purposes.
Additionally, this service provides the following telemetry functions:
  • Collects and formats metrics for the Confd notification streams.
  • Enables F5OS components to export metrics and logs to an OpenTelemetry receiver.

Container image name: psf-monitor
  • No data on the health of the partition is available; this may affect services such as partition<ID>_diag-agent which relies heavily on these data to function properly.
  • Platform telemetry data is unavailable.
partition<ID>_name-service-ldapThis service runs the nslcd process or the LDAP name service process at the partition level. This service is required when you configure the authentication to use LDAP.

Container image name: ldap-nslcd

No LDAP authentication is available for the partition.
partition<ID>_network_managerThis service manages network resources such as VLAN, services, FDB, etc., for the partition, and allocates a default service for each BIG-IP tenant. It receives the L2 listener request with DAG profile from the BIG-IP tenant through the API service gateway and creates/updates the L2 listener in the partition’s ConfD. The BIG-IP tenant sends out the L2 listener request for each assigned VLAN and the L2 listener for the partition identifies the traffic destined to the BIG-IP tenant in the data plane.

Container image name: network_manager

The BIG-IP tenant is unable to receive/send data plane traffic.
partition<ID>_optics-mgrThis service provides the tuning parameters for the optical interfaces on the installed blades assigned to the partition.

Container image name: optics-mgr

The optical interfaces on the installed blades do not function as expected.
partition<ID>_partition-bladesdThis service provides the list of assigned blades for the qkviewd service when the qkviewd service is triggered to run for the partition.

Container image name: partition-bladesd

The qkviewd service may fail to collect the diagnostic data from the assigned blades for the partition.
partition<ID>_platform-stats-bridgeThis service provides platform stats such as blade CPU utilization, memory, temperature, etc., from the tmstat services running on the assigned blades to the partition ConfD. The only way to interact with it is through the partition ConfD CLI commands:
  • show components component blade-<ID> state memory
  • show components component blade-<ID> state temperature
  • show components component blade-<ID> cpu state cpu-utilization
  • show components component blade-<ID> cpu state cpu-cores

The logs are located in the /var/F5/partition<ID>/log/velos.log file and prepended with PlatformStatsBridge.

Container image name: platform-stats-bridge

Unable to view platform stats for the assigned blades.
partition<ID>_qat-support-podThis service runs on the partition system controller and works with the qat-support-pod service on the assigned blades to manage the QuickAssist Technology (QAT) devices on the assigned blades:
  • it initializes the QAT devices and brings them to the ready state.
  • it reports their usage statistics to the tmstat service.

QAT devices are typically used as cryptographic and compression accelerators to offload these operations from the local CPUs.

Container image name: qat-support-pod

No QAT device is available for use by the deployed tenant(s).
partition<ID>_qkviewdThis service gathers the diagnostic data from other containers at the partition level to generate the QKView file when you initiate a QKView capture.

Container image name: qkviewd

No QKView file for the partition can be generated.
partition<ID>_rsyslogdThis service runs a syslog server that processes and transforms logs for the partition. The partition system controllers write their logs in the /var/F5/partition<ID>/log/velos.log file.

This service redirects all logs to facility LOCAL0; no other log facility is supported as of this writing.

This service also runs logrotate separately at the partition level. The log rotation configuration files are located in the /var/F5/partition<ID>/etc/logrotation.d/ directory.

Changing the log rotation configuration is not recommended. You should only change the log rotation configuration under the advice of F5 Support while troubleshooting issues.

Container image name: rsyslogd

The partition is unable to generate system logs.
partition<ID>_snmp_trapdThis service sends SNMP traps to the SNMP server based on the SNMP trap configuration for the partition.

Container image name: snmp_trapd

No SNMP trap is sent from the partition.
partition<ID>_swdiag-agentThis service provides the CLI and REST interface to the ihealth-service service to upload partition QKViews to F5 iHealth portal.

Container image name: swdiag-agent

Unable to initiate partition QKView uploads to F5 iHealth portal.
partition<ID>_syncThis service runs the rsyncd service to replicate files between the partition system controllers. It replicates file in the following directories:
  • /var/F5/partition<ID>/IMAGES/
  • /var/F5/partition<ID>/ssh-keydir/
  • /var/F5/partition<ID>/events/
  • /var/F5/partition<ID>/configs/

The logs are captured in the /var/F5/partition<ID>/log/partition_sync.log file.

Container image name: partition-sync

Files in the listed directories are not in sync between the partition system controllers.
partition<ID>_tcpdumpd_managerThis service is the main tcpdump service for the partition and coordinates with the tcpdumpd services on the assigned blades to receive the captured packets/frames from them.

Container image name: tcpdump_daemon

Unable to capture any packets for troubleshooting.
partition<ID>_tmstat_zmqThis service provides ZeroMQ access to statistics within the partition controller, such as CPU utilization, disk I/O and usage, memory utilization statistics.

Container image name: tmstat-agent

No statistics is available for the partition controllers.
partition<ID>_TPOBThe Tenant Pod Orchestration Bridge (TPOB) service provides a bridge between the partition management layer and the OpenShift control plane in the VELOS system. It is responsible for configuring, provisioning, stopping, and monitoring the configured tenants.

Container image name: orchestration_agent

  • Unable to modify a running tenant to add/remove blades.
  • Unable to query the status of the tenant(s) in the partition.
partition<ID>_user_managerThis service manages the password, group, and shadow files based on the partition configuration data within ConfD.

Container image name: user_manager

Unexpected behavior when a partition user changes password.
partition<ID>_utils-agentThis service provides the utility commands to import and export files from the partition.

Container image name: utils-agent

Unable to import/export files to/from the partition.
partition<ID>_vconsoleThis service provides virtual console access to deployed tenants via the partition’s management interface.

Container image name: partition_vconsole

Unable to access the virtual console of the deployed tenants in the partition.

Recommendations

  • Restarting a service on the partition controller
  • Restarting a service on the partition blade

Restarting a service on the partition controller

To restart a service on the partition controller, perform the following procedure:

  1. Log in to the VELOS system controller CLI as the root user
  2. Restart the service using the following command syntax:

    docker restart <service name>

    For example, you would enter the following command to restart the alert-service service:

    docker restart alert-service

Restarting a service on the partition blade

To restart a service on the partition blade, perform the following procedure:

  1. Log in to the VELOS system controller CLI as the root user
  2. SSH login to the blade as the root user from the VELOS system controller CLI. For example, you would enter ssh root@blade-1 to SSH login to blade 1 in the VELOS system.
  3. Restart the service using the following command syntax:

    docker restart <service name>

    For example, you would enter the following command to restart the alert-service service:

    docker restart alert-service
