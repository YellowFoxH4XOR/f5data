K000164161: Tcpdump on BIG-IP LTM Captures 0 Packets When Run from a Nested Shell Session

Type
Support Solution
Published
2026-11-10
Updated

Applies to

  • BIG-IP LTM: 17.0.0, 17.1.0, 17.0.X, 17.X.X, 17.5.X, 17.5.1, 17.5.0, 17.1.X, 17.1.3, 17.1.2, 17.1.1
Source

Description

Running tcpdump on a BIG-IP LTM interface to capture traffic to load-balanced pool members returns zero packets, even though the pool members are receiving traffic. The command runs without errors:

tcpdump: listening on 0.0:nnnp, link-type EN10MB (Ethernet), capture size 65535 bytes
0 packets captured
0 packets received by filter
0 packets dropped by kernel

The same command run from a fresh root SSH session captures packets normally. No error message identifies the nested shell as the cause.

Environment

  • BIG-IP LTM
  • Load-balanced pool members receiving traffic on the BIG-IP
  • Admin session moved from tmsh (tmos) to bash with bash, without exiting the tmos shell first, so the tcpdump session was nested

Cause

  • The tcpdump captures recorded 0 packets because they were run from a nested shell session.
  • The nested session may be restricted by partition-related permissions after switching between tmos partitions and bash.

Answer/Recommended Actions

  1. Exit all nested shells before capturing. Use exit to leave bash and quit to leave tmsh (tmos). Do not use bash to exit.
  2. Open a new SSH session and log in as the root user.
  3. Confirm the session is not nested by running pstree. The expected structure is:

    |-sshd-+-sshd---bash---pstree

  4. Run tcpdump from that clean session and confirm that packets are captured.
  5. If traffic is still not captured, run tcpdump without filters for a short period to isolate the issue.
