K000164025: Subresource Integrity (SRI) Cannot Be Applied to Client-Side Defense (CSD) JavaScript in Distributed Cloud

Type
Support Solution
Published
2026-10-27
Updated
2026-10-27
Applies to
  • F5 Distributed Cloud Services
  • F5 Distributed Cloud
Source
https://my.f5.com/manage/s/article/K000164025

Description

Vulnerability scanners may report a Subresource Integrity (SRI) finding for a JavaScript file injected by F5 Distributed Cloud (XC) Client-Side Defense (CSD). The scanner expects the script tag to include an integrity attribute, but the CSD script cannot be pinned to a fixed SRI hash.

Environment

  • F5 Distributed Cloud Services
  • Client-Side Defense (CSD) enabled on an HTTP load balancer
  • Web applications scanned with a browser-based vulnerability assessment tool

Cause

The CSD JavaScript is generated per tenant and is rebuilt each time the customer's CSD configuration is updated. Because the content changes, its SRI hash also changes.

If a fixed SRI hash is pinned to the script, the browser blocks the script after the next rebuild. This silently disables the client-side protection that CSD provides.

Answer / Recommended Actions

Recommended actions, in order of preference:

  • Accept the CSD script as designed. The injected script is an expected component of the CSD service. Its presence does not indicate that the F5-hosted infrastructure is compromised.
  • Restrict script sources with a Content Security Policy (CSP). Limit where scripts can load from, for example:
    - script-src 'nonce-...' 'strict-dynamic'
    - An exact host allowlist for the script origin
  • Do not pin a fixed SRI hash to the CSD script unless you take ownership of serving it. If SRI is required, you must:
    1. Proxy or serve the script through your own application layer, using URL rewriting.
    2. Calculate the SRI hash against the exact bytes served to the browser.
    3. Recalculate and update the hash whenever the CSD configuration changes and the script is rebuilt.
  • Document the finding as an accepted risk if SRI enforcement is not feasible, and evaluate the operational impact of the self-hosted approach before choosing it.

Additional Information

  • Expected behavior: CSD JavaScript content and its hash change after CSD configuration updates. This is by design.
