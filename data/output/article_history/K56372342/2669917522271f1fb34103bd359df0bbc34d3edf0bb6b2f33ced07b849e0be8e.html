Description

When a BIG-IP is provisioned with multiple modules, for example LTM, ASM, APM and AVR simultaneously, the system may show dangerously high memory usage. The high memory utilization can trigger oom-killer events or other performance issues.  The TMSH command  tmsh /show sys memoryusually shows only a fraction of the available TMM memory being in use, but this memory is reserved only for TMM and non-TMM processes (Linux) cannot access this memory, leaving those other processes to fight over the scarce remaining memory and swap.

Environment

  • BIG-IP
  • Multiple modules provisioned
  • RAM 16G or less


Cause
Insufficient Linux RAM provisioned

Recommended Actions

When a unit with 16GB of RAM (or less) has both ASM, APM and AVR provisioned, then LTM should be provisioned as None.  ASM, APM and AVR should be provisioned as Nominal.
Note: Because of kernel changes in version 14, swap reporting was changed from earlier versions.  Units with only 16GB of RAM will frequently show high swap under normal conditions, even after changes in provisioning.  A better indicator than the graphs as to readily freeable memory is the MemAvailable statistic in the /proc/meminfo output.

An alternative workaround is to provision extra RAM for Linux:
Important: Please be aware that this command "will" cause a failover, if done on the Active unit.

  1. Log on to the command line of the standby BIG-IP device.
  2. Type the following command to add 4096k of additional ram to Linux: 
    tmsh modify sys db provision.extramb value 4096 
  3. After provisioning the extra ram the BIG-IP device will restart all services.
    After the BIG-IP device is online you can failover to the peer device and repeat these steps on the now standby device.


If you are seeing this issue on a vCMP Guest, which only has two CPUs, which means that it only has 10.25 GB of Physical Memory.
Important: Please be aware that this command "will" cause a failover, if done on the Active unit.

  1. Log on to the command line of the standby BIG-IP device.
  2. Type the following command to add 2048k of additional ram to Linux: 
    tmsh modify sys db provision.extramb value 2048 
  3. After provisioning the extra ram the BIG-IP device will restart all services.
    After the BIG-IP device is online you can failover to the peer device and repeat these steps on the now standby device.

    Note: Setting the LTM module provisioning to  None does turn off licensed LTM functionality.
    Important: If a unit is configured to use iApps that do enforce an LTM provisioning requirement, then they should be modified to remove this requirement before changing the LTM provisioning.
