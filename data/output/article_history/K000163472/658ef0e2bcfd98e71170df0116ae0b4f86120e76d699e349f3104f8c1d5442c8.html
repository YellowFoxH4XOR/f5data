Description

An AS3 Endpoint_Policy for explicit forward-proxy traffic can fail to reproduce a policy that can be configured through the BIG-IP Configuration utility. A rule that evaluates an HTTP method at proxy-request and modifies an HTTP header at the same event may receive an HTTP 422 schema error containing should be equal to one of the allowed values ["request","response"]. In some affected builds, adding a second action to disable HTTP proxy processing at proxy-request can instead produce HTTP 422 with 010716e2:3 and defines an action which occurs before one of its conditions, or before a condition in an earlier rule with lower ID.

Environment

  • BIG-IP LTM

Cause

AS3 validates each policy action against its own supported events; support for proxy-request in an HTTP-method condition or an http action does not establish support for that event in an httpHeader action. Affected AS3 schemas reject the header action before applying the policy. A separate action-handling issue was observed when a build that accepted that header action combined it with an HTTP proxy-disable action in the same rule. This is an AS3 declaration/support issue in the reported scenario, not evidence that the equivalent GUI policy is generally invalid. The policy-ordering error can also have other causes; its presence alone does not identify this issue.

Recommended Actions

  1. Identify which validation stage fails:
    Check the installed AS3 build, the declaration's schemaVersion, each condition and action's type and event, and the complete AS3 response. Compare the httpHeader action's allowed events with the schema for the build actually in use. A response naming the header action's event and allowing only request and response identifies the schema limitation. Changing the event to request is not an equivalent workaround when processing must occur at proxy-request.
  2. Check the complete rule, not only the header action:
    If the header action validates but deployment returns 010716e2:3, review event timing across all conditions, actions, and earlier rules. In particular, check whether the same rule combines a proxy-request HTTP-method condition, an httpHeader action, and an http action with "enabled": false. Do not classify every policy-ordering error as this AS3 issue; different event ordering or rule order can produce the same message.
  3. Request a verified resolution and validate it safely:
    Contact F5 Support with the AS3 build identifier, BIG-IP version, a sanitized declaration, both action definitions, and the exact response. Reference tracking ID 2504081 for httpHeader support at proxy-request, and describe the combined-action failure separately. Ask Support to confirm an approved build or published release that addresses the entire rule. Test the complete declaration and the intended policy behavior in a suitable non-production environment before deployment. Do not edit AS3-managed policy objects manually as an assumed fix.

Additional Information

  • A schema acceptance result for a single httpHeader action does not establish that a rule also disabling HTTP proxy processing will deploy successfully.
  • Confirm the exact AS3 package and its published release notes or obtain an approved package from F5 Support; a version label alone does not establish that both reported failures are fixed.
