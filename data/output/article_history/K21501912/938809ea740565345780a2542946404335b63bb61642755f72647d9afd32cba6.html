Overview

The software lifecycle support policy for F5OS Platform layer software defines the stages of the software lifecycle, from initial release through retirement. The intent of this policy is to provide consistent documentation that helps customers plan and prepare for their organization's support needs. For policies regarding products and software versions that are past their End of Sale (EoS) date, refer to their respective MyF5 articles.

Version schema definitions

F5OS platform layer software uses a three-digit software version schema. The three-digit release structure delineates the magnitude of each product release, enabling customers to select the point in the release cycle at which they want to deploy a version of software.

F5OS platform layer software uses semantic versioning, which uses the following syntax: F5OS- MAJOR.MINOR.PATCH.BUILDNO.variant.tag, tag is optional.

The following definitions describe the items in the version schema.

Version schema definitions

Definition

Key factor in determining this type of release

Major release

Major releases may include significant:

  • Changes in behavior.
  • New functionality.
  • Performance changes.
  • API changes.
  • Architectural changes.

The new version has incompatible API changes. F5 reserves the right to release on-demand new major releases, if needed, for business reasons.

Minor release

Minor releases include:

  • All patches from previous minor release.
  • New product features and functionality.
  • New fixes for product errors or bugs.

The new version has API changes that do not break backwards compatibility.

Patch release

Patch releases include only:

  • Bug and security fixes.

The release does not introduce any new functionality or changes in behavior.

Variant

Variant is the type of platform this software is for:

  • R2R4 denotes rSeries 2000 and rSeries 4000 appliance platforms
  • R5R10 denotes rSeries 5000, rSeries 10000, and rSeries 12000 appliance platforms
  • APPLIANCE denotes all the appliance platforms include r2000, r4000, r5000, r10000, and r12000
  • CONTROLLER denotes VELOS CX410 and CX1610 chassis controllers
  • PARTITION denotes the partitions consisted from VELOS BX110 or BX520 blades
  • CHASSIS denotes to the tar file consists software for both VELOS controller and VELOS partition

Support phase

The support phase is characterized by the introduction of new backwards-compatible features, software fixes (including security updates), and stability improvements, delivered through minor and patch releases.

The support phase for a version of F5OS Platform layer software begins with the first customer ship date and ends at the End of Technical Support (EoTS) milestone. For F5OS, the End of Software Development (EoSD) and EoTS milestones are always the same. F5OS versions that have reached their EoSD/EoTS milestone are no longer supported with new software development. F5 will not provide software fixes, security updates, or consulting services for a version that has reached the EoSD/EoTS milestone. In order to receive support for new fixes or features, you must upgrade to the latest patch release in your current software branch or to the latest patch release in a later software branch. If your current software version has reached the EoSD/EoTS milestone, you must upgrade to a supported software version.

Release support model

Each F5OS Platform layer software version branch has the following two distinct release support models: Long Term Support (LTS) release and Short Term Support (STS) release. LTS releases are intended for those who are satisfied with the current functionality and desire to stay on that release for a longer time period. Short Term Support (STS) releases provide a faster release cycle for the introduction of new functionality.

LTS releases will typically occur on an annual basis after declaring the initial LTS release. These releases will have a versioning schema of the form F5OS-Major.Minor.Patch.Variant.LTS designator. The LTS releases have an explicit LTS moniker suffixed to the version. F5 increments the minor version number of the LTS release based on the scope and extent of the change. The Standard Support phase of an LTS release begins with the Introduction Date and ends in three years.

More frequent STS releases will typically occur on a faster release cadence and include backwards compatible feature additions, enhancements, and bug fixes. These STS releases enable F5 to respond to new feature requirements more rapidly and allow customers who are willing to upgrade more frequently to get the latest features sooner. The STS releases usually have a standard support phase of twelve months.
