Description

Beginning in APM Client 7.2.7.1, as part of the Linux client modernization, F5 is replacing the existing f5vpn (VPN) and f5epi (Endpoint Inspection) packages with a single unified application - f5vpn-ng.

All VPN and endpoint inspection functionality is now handled by one package, simplifying deployment and reducing the overall installation footprint.

  • What's New: One Package Instead of Two
  • Reduced installation size
  • Auto-Upgrade Workflow Changes
  • Migration notes

What's New: One Package Instead of Two

Previously, the Linux APM client required two separate packages - f5vpn for VPN connectivity and f5epi for Endpoint Inspection. With f5vpn-ng, a single package replaces both:

Legacy packageNew packageFunctionURI Scheme
f5vpnf5vpn-ngFull VPN session (authentication, tunnel, routing, DNS)f5-vpn://
f5epif5vpn-ngStandalone Endpoint Inspection (EPI only, no VPN tunnel)f5-epi://

This is what it means for BIG-IP administrators:

  • You only need to install one package, each named download from the APM now actually contains both libraries.
  • There is only one version number to track for upgrades.
  • When installing the appropriate architecture you can list the package contents and should check for errors and missing dependencies see K000158036  below for details.

This is what it means for VPN end users:

  • There is no change in workflow. Clicking a VPN or EPI link in the browser works like before.
  • The same application icon is used for both VPN and EPI sessions.

Auto-Upgrade Workflow Changes

The upgrade process now uses an interactive authentication prompt, requiring the user to authorize installation with their system password. This replaces the previous background installation behavior.

Migration notes

No configuration changes are required on the BIG-IP system. The new client communicates with the same BIG-IP APM endpoints using the same protocol.

  • Untrusted server configuration has moved from /opt/f5/f5_epi.conf to /etc/f5.conf.
  • Log files are now located at ~/.F5Networks/f5vpn.log. The older log files (~/.F5Networks/vpn.log and ~/.F5Networks/epi.log) are no longer populated.

Environment

  • APM Client 7.2.7.1
  • Minimum client system requirements:
    • Ubuntu 24.04 LTS, Ubuntu 26.04 LTS (x86_64 or ARM64), or RHEL 10.x (x86_64)
    • A graphical desktop environment (GNOME, XFCE, Cinnamon, or similar)
    • GTK 3.20 or later
    • WebKit2GTK 4.0 or 4.1
    • OpenSSL 3.0 or later
    • libcurl 7.77 or later 
    • An internet browser capable of handling custom URI schemes (Firefox, Chrome, Edge)
    • Network connectivity to the BIG-IP APM virtual server
  • Supported Platforms

    The earlier version of client (f5vpn/f5epi) carried a large set of bundled third-party libraries many of which accumulated CVEs over time. Upgrading these libraries to fix the CVEs often introduced compatibility issues and kept increasing package size. The new client eliminates these bundled dependencies entirely and relies on OS-provided libraries that are maintained and patched by the distribution vendor. As a result, f5vpn-ng is validated and supported on the following distributions:

    f5vpn-ng may function on other Linux distributions that meet the minimum library requirements, but these configurations are not tested or supported. If your organization requires support for an additional platform, K2633: Submit a support case so F5 can evaluate demand and prioritize accordingly.

Additional Information

Known issues:

  • Post-Quantum Cryptography (PQC): PQC key exchange is supported for VPN tunnel traffic. PQC support for other connections will be available as operating system cryptographic libraries add support.
  • Intermittent connection failures during recurring compliance checks on Ubuntu 26.04: Recurring Endpoint Policy Checks may intermittently fail on Ubuntu 26.04, which can result in unexpected session disconnection. As a workaround, increase the recurring check interval on the BIG-IP access policy, or disable recurring checks if not required.
  • RHEL 10 Dependency Requirement: webkit2gtk4.1 is not installed by default on RHEL 10. Install it before installing the application.
