Topic

You should consider using this procedure under the following condition:

  • You want to use the representational state transfer (REST) API for one or both of the following reasons:
    • You want to verify the proper operation of your VELOS or rSeries system by uploading a QKView file to F5 iHealth.
    • You want to provide a QKView file to F5 Support to aid in troubleshooting an issue with a VELOS or rSeries system.

Note: In affected F5OS-C versions, when you generate QKViews on your VELOS system, you may encounter connectivity issues. For more information, refer to K000138933: VELOS connectivity issues after generating a partition Qkview in 1.6.x.

Description

You can use the qkview utility on the VELOS and rSeries systems to automatically collect configuration and diagnostic information from the system. For more information, refer to K02521182: Generating diagnostic data for the VELOS system using the qkview utility and K04756153:  Generating diagnostic data for rSeries systems using the qkview utility .

You can use the REST API to run the qkview utility on an rSeries system or VELOS system controller or chassis partition to capture diagnostic information from the host system, and optionally from peers, as well as from all associated containers.

Note: The qkview utility on the VELOS and rSeries systems does not capture diagnostic data from tenant BIG-IP systems. To generate diagnostic data for a tenant BIG-IP or BIG-IQ system, log in to the tenant system and perform the relevant procedure in K12878: Generating diagnostic data using the qkview utility.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You have administrative access to the VELOS or rSeries system.
  • You have command-line access to a client system that has the curl utility installed.
  • You have access to F5 Cloud Docs to review REST API documentation.

Procedures

  • Generate a QKView diagnostic file using the REST API
  • Check the qkview status using the REST API
  • Upload a QKView diagnostic file to F5 iHealth using the REST API

Generate a QKView diagnostic file using the REST API

When generating a QKView diagnostic file using the REST API, the API returns immediately after initiating the qkview capture. To generate a new QKView diagnostic file, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the client system that has the curl utility installed.
  2. Generate a new QKView file using the following command syntax:

    curl -X POST -sku <username>:<password> -H "Content-Type: application/yang-data+json" "https://<mgmt_address>/api/data/openconfig-system:system/f5-system-diagnostics-qkview:diagnostics/f5-system-diagnostics-qkview:qkview/f5-system-diagnostics-qkview:capture" -d '{"f5-system-diagnostics-qkview:filename": "<qkview_filename>"}'

    In the command syntax, note the following:

    • <username> and <password> are a username and password combination that has administrative access on the rSeries system or VELOS system controller or chassis partition.
    • <mgmt_address> is the host name or management IP address of the rSeries system or VELOS system controller or chassis partition.
    • <qkview_filename> is the name of the QKView diagnostic file to generate.

    For example, to generate a QKView file named velos.example.com.qkview on the system controller at velos.example.com with the admin user, enter the following command:

    curl -X POST -sku admin:admin -H "Content-Type: application/yang-data+json" "https://velos.example.com/api/data/openconfig-system:system/f5-system-diagnostics-qkview:diagnostics/f5-system-diagnostics-qkview:qkview/f5-system-diagnostics-qkview:capture" -d '{"f5-system-diagnostics-qkview:filename": "velos.example.com.qkview"}'

    Important: Include the .qkview extension in the filename so that iHealth will be able to load the file.

    The command output appears similar to the following example:

    {
      "f5-system-diagnostics-qkview:output": {
        "result": " Warning: Qkview may contain sensitive data such as secrets, passwords and core files. Handle with care. Please send this file to F5 support. \nQkview file velos.example.com.qkview is being collected.\nreturn code 200\n ",
        "resultint": 0
      }
    }

Check the qkview status using the REST API

To check the status of a running qkview, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the client system with the curl utility installed.
  2. Check the status of the running qkview using the following command syntax:

    rSeries:

    curl -X GET -sku <username>:<password> -H "Content-Type: application/yang-data+json" "https://<mgmt_address>/api/data/openconfig-system:system/f5-system-diagnostics-qkview:diagnostics/f5-system-diagnostics-qkview:qkview/f5-system-diagnostics-qkview:state/f5-system-diagnostics-qkview:status"  

    In the command syntax, note the following:

    • <username> and <password> are a username and password combination that has administrative access on the rSeries system.
    • <mgmt_address> is the host name or management IP address of the rSeries system.

    For example, to check the status of a running qkview on an rSeries system at rseries.example.com with the admin user, enter the following command:

    curl -X GET -sku admin:admin -H "Content-Type: application/yang-data+json" "https://rseries.example.com/api/data/openconfig-system:system/f5-system-diagnostics-qkview:diagnostics/f5-system-diagnostics-qkview:qkview/f5-system-diagnostics-qkview:state/f5-system-diagnostics-qkview:status"

    The example output shows the qkview is 76% complete:

    {
      "f5-system-diagnostics-qkview:status": {
        "capture-in-progress": true,
        "percentage": 76,
        "status-msg": "Collecting Data",
        "filename": "rseries.example.com.qkview"
      }
    }

    VELOS:

    curl -X POST -sku <username>:<password> -H "Content-Type: application/yang-data+json" "https://<mgmt_address>/api/data/openconfig-system:system/f5-system-diagnostics-qkview:diagnostics/f5-system-diagnostics-qkview:qkview/f5-system-diagnostics-qkview:status"

    In the command syntax, note the following:

    • <username> and <password> are a username and password combination that has administrative access on the VELOS system controller or chassis partition.
    • <mgmt_address> is the host name or management IP address of the VELOS system controller or chassis partition.

    For example, to check the status of a running qkview on a VELOS system controller at velos.example.com with the admin user, enter the following command:

    curl -X GET -sku admin:admin -H "Content-Type: application/yang-data+json" "https://velos.example.com/api/data/openconfig-system:system/f5-system-diagnostics-qkview:diagnostics/f5-system-diagnostics-qkview:qkview/f5-system-diagnostics-qkview:state/f5-system-diagnostics-qkview:status"

    The example output shows the qkview is 22% complete:

    {
      "f5-system-diagnostics-qkview:output": {
        "result": " {\"Busy\":true,\"Percent\":22,\"Status\":\"collecting\",\"Message\":\"Collecting Data\",\"Filename\":\"velos.example.com.qkview\"}\n ",
        "resultint": 0
      }
    }

Upload a QKView diagnostic file to iHealth using the REST API

After you generate the QKView diagnostic file, you can upload the file to iHealth using the REST API.  As of June 2023, iHealth uses a new identity and authentication mechanism which requires the generation of a new API bearer token when authenticating to the new iHealth2 API.  To upload the rSeries or VELOS system QKView diagnostic file to iHealth2 using the REST API, refer to K000134530: Upload rSeries and VELOS system QKView diagnostic files to iHealth .
