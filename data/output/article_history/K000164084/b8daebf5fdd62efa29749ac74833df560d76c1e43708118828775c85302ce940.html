K000164084: AFM Default global policy action not enforced after upgrading BIG-IP

Type
Support Solution
Published
2026-11-03
Updated
2026-11-12
Applies to
  • BIG-IP
  • BIG-IP AFM: 17.1.0, 17.1.2, 17.1.1, 17.1.X, 17.5.X, 21.1.X, 21.1.0, 17.5.1, 17.5.0, 17.1.3
Source
https://my.f5.com/manage/s/article/K000164084

Description

After upgrading BIG-IP AFM to 17.1.3.6 and later or 17.5.1.10 and later or 21.1.0.3 and later, the Default Global Policy may allow traffic that should be dropped. The configured default action still shows drop, so virtual servers that rely on the default action can become reachable from sources that should be blocked.

Environment

  • Product: BIG-IP AFM
  • Affected versions: 17.5.1.10 and later (reproduced by upgrading from 17.5.1.8 to 17.5.1.11)
  • Configuration: BIG-IP in Firewall mode with the global default action set to drop (tm.fw.defaultaction)
  • Virtual servers using network firewall policies with allow entries (for example, an IP allowlist). The issue was observed on virtual servers both with and without iRules.
  • Trigger: software upgrade to 17.1.3.6 and later or 17.5.1.10 and later or 21.1.0.3 and later

Cause

This issue is tracked under Bug ID 2735613: AFM does not honor the sys db tm.fw.defaultaction value of drop. After the upgrade to 17.5.1.10 and later, connections are accepted even though the default action remains drop.

Answer/Recommended Actions

Workaround: Toggle the default action so that AFM reapplies it.

Option A: Using tmsh

  1. Confirm the current value:
    tmsh list sys db tm.fw.defaultaction
  2. Set the value to accept, then save the configuration:
    tmsh modify sys db tm.fw.defaultaction value accept
    tmsh save sys config
  3. Set the value back to drop, then save the configuration:
    tmsh modify sys db tm.fw.defaultaction value drop
    tmsh save sys config
  4. Confirm the value again:
    tmsh list sys db tm.fw.defaultaction

Option B: Using the Configuration utility

  1. Change the Default Global Policy action from Drop to Reject.
  2. Change the Default Global Policy action back to Drop.

Validation:

  1. Test from a client source that is not on the allowlist, using the same traffic that was previously accepted. Confirm that the connection is blocked.
  2. After any future upgrade to 17.5.1.10 or later, repeat the blocked-source test before placing the system into production.

Permanent fix: A fix is not yet available. Monitor Bug ID 2735613 and any future release notes for a fixed version, and check the fix status before relying on the workaround long term.

Additional Information

  • Expected behavior: With tm.fw.defaultaction set to drop, traffic that is not matched by an allow entry is dropped.
  • Unexpected behavior (this issue): Traffic is accepted while tm.fw.defaultaction still shows drop.
