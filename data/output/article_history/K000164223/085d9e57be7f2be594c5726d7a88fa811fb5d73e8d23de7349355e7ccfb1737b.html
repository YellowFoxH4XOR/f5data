K000164223: Configuring CDN Cache Rules to Treat Requests with Different Query Strings as Distinct Objects

Description

Customers may need CDN content to be cached separately for requests to the same path that differ only in their query string. For example, /app.js?v=1 and /app.js?v=2 should be stored and served as different objects.

The "Eligible For Cache" setting in a CDN Cache Rule controls which parts of the request form the cache key. Two options are available that can appear similar: "Scheme + Proxy Host + URI" and "Scheme + Proxy Host + Request URI." This article explains how each option builds the cache key and which one to select for query-string-based caching.

Environment

  • F5 Distributed Cloud Services
  • CDN
  • CDN Cache Rules

Cause

None

Answer/Recommended Actions

  1. In the CDN Cache Rule, set Eligible For Cache to Scheme + Proxy Host + Request URI.
  2. Confirm that requests differing only in query string (for example, /app.js?v=1 and /app.js?v=2) are cached as separate objects.

Use the following guidance to choose between the two options:

  • Scheme + Proxy Host + URI: Use when query strings should not create separate cache entries.
  • Scheme + Proxy Host + Request URI: Use when query strings must create separate cache entries.

Additional Information

Scheme + Proxy Host + URI

  • Cache key: scheme (http/https) + proxy host + URL path
  • The query string is not part of the cache key.
  • The path is normalized (percent-decoded, duplicate slashes merged, ./ and ../ resolved).
  • Example: /img/logo.png?size=small and /img/logo.png?size=large use the same cached object.

Scheme + Proxy Host + Request URI

  • Cache key: scheme (http/https) + proxy host + full request URI (path + query string)
  • The query string is part of the cache key.
  • The URI is used exactly as the client sent it (not normalized).
  • Example: /img/logo.png?size=small and /img/logo.png?size=large are cached as separate objects.

Expected behavior: With "Scheme + Proxy Host + Request URI," each distinct query string produces a separate cache entry. This can reduce cache hit ratios for URLs with many unique query parameters, such as tracking parameters.
