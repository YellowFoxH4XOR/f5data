Description

The log files on your F5OS-A system include important diagnostic information about the events that are occurring on the system. Some of the events pertain to the Linux host. For example, the Linux host generates system messages that pertain to the different container operations, including messages that are logged during system startup, and information logged by the background daemons that run on the system. Other events are specific to the F5OS-A operating system. For example, the F5OS-A operating system generates messages that pertain to F5OS-A system daemons and services, and configuration changes (audit logging).

F5OS-A logging does not include BIG-IP tenant logging. For logs and events within each BIG-IP tenant, refer to K16197: Reviewing BIG-IP log files.

Local logging

By default, the F5OS-A system logs events locally and stores messages in the /var directory as follows:

  • /var/log: Common Linux log files.
  • /var/F5/system/log: F5OS-A system and services log files

F5OS-A logging uses the rsyslogd daemon that runs inside each container in the F5OS system to consolidate their logs into a centralized location at /var/F5/system/log/platform.log. The system_rsyslogd service redirects all logs to facility LOCAL0; no other log facility is supported as of this writing. For more information on system_rsyslogd, refer to K000134978: Overview of F5 rSeries system services.

    Common F5OS-A log file types

    F5OS-A is the operating system software for the F5 rSeries system and comprises the Base OS and Service components.

    Base OS log file types

    The following lists the Base OS components:

    • CentOS Linux
    • Docker
    • Ansible
    • KubeVirt-appliance
    • K3s

    Log files for these components are located in the /var/log directory.

    Log fileDescription
    appliance.logThe appliance orchestration-manager logs k3s events in this log. It checks and logs on the health of the k3s cluster and pods.
    boot.logThis contains boot messages with information that is logged when the system boots.
    containersThis contains K3s and KubeVirt container logs.
    cronWhen the cron daemon starts a cron job, the daemon logs the information about the cron job in this file.
    dmesgThe dmesg messages contain kernel ring buffer information that pertains to the hardware devices that the kernel detects during the boot process.
    flannel-install.logThis contains logs related to the installation of Flannel, configurations and so on, during the installation process through Ansible.
    httpdThe httpd directory contains the Apache Web server access, error and request logs.
    k3s logsThe k3s logs contain logs related to the core operations of the K3s server and agents. These include events like startup processes, container orchestration, services, update processes and so on.
    kubevirt-install.logThis log contains events and messages related to the installation of KubeVirt, one of the Base OS component used in F5OS-A.
    lcd-webserverThis contains messages from the lcd-webserver service which serves the LCD application and provides the LCD application an API to access the data the LCD application needs from ConfD.
    messagesThis contains system event messages related to global Linux events.
    multusThis contains logs related to the installation of Multus, configurations and so on, during the installation process through Ansible.
    podThis contains K3s and KubeVirt pod logs.
    platform/selThis contains Baseboard Management Controller, BMC related events related to (power, DIMM, thermal, PSU, HDD storage bay and so on) events, errors, and faults.
    secureThe secure log messages contain information related to authentication and authorization privileges.
    sw-mgmt.debug
    sw-upgrade.log
    sw-util.log    		These logs contain information on software import, removal, installation, upgrade of the F5OS-A software.

    F5OS-A service log file types

    The service component comprises mostly F5-produced software and platform-specific packages of F5OS-A. The logs that contain events related to this component generally logs to the /var/F5/system/log directory.

    Log fileDescription
    auditUser authentication and session information are logged in this file. The audit event messages are messages that the F5OS-A system logs as a result of changes to the system configuration.
    confdConfd is a process that provides the configuration engine for the system. The CLI implements ConfD, allowing administrators to interact with the system.
    k3s_events.log 
    lcd.logThis file contains events related to the LCD. This includes communication with the LCD webserver. Refer to /var/log/lcd-webserver as well for LCD diagnostics.
    logrotate.logThe system_rsyslogd service runs logrotate and logs to this file. The configuration files are located in the /var/F5/system/etc/logrotation.d/ directory. Changing the log rotation configuration is not recommended without direction from F5 Support.
    platform.logF5OS-A uses the rsyslogd daemon to consolidate logs into a centralized location at this file. The system_rsyslogd service redirects all logs to facility LOCAL0; no other log facility is supported as of this writing.

    The system_platform-stats-bridge service which provides platform statistics such as CPU utilization, memory, temperature and so on. Other services such as tmstat to ConfD logs to this file as well.

    This file is a good starting point to troubleshoot issues related to services on F5OS-A.
    rsyslogd_init.logThis includes events related to the status of rsyslogd. For more information on rsyslogd, refer to K000134978: Overview of F5 rSeries system services.
    snmp.logThis file captures events related to SNMP. For more information on SNMP, refer to rSeries F5OS-A SNMP Monitoring and Alerting on Clouddocs.
    vconsole logsThe system_vconsole service which provides virtual console access to deployed tenants through the rSeries system management interface logs to these files.

    Log message format

    Log messages are formatted differently depending on the type of log and the component that generated the event messages. The log formats are discussed in the following sections.

    Platform log message format

    The platform log messages, /var/F5/system/log/platform.log, generated by the system includes the following types of information:

    <Date Timestamp> <F5OS hostname> <service name>[<process ID>]: priority="<level>" version=<version> msgid=<message ID> msg=<message text>

    • <time stamp> is the time/date that the system logged the message.
    • <F5OS host name> is the host name of the system that generated the message.
    • <service name> is the name of the service (and process ID) that generated the message.
    • <level> is the severity of the log message. This can be one of Emerg, Alert, Crit, Err, Warn, Notice, Info, Debug.
    • <version>  is the version of the F5OS logging system. This should be 1.0 for all F5OS releases at the time of writing.
    • <message ID> is the identification number of the message.
    • <message text> is the description of the event that caused the system to log the message.

    Audit log message format

    The audit log messages, /var/F5/system/log/audit.log, generated by the system includes the following types of information:

    <Date Timestamp> <F5OS hostname> <service name>[<process ID>]: priority="<level>" version=<version> msgid=<message ID> msg=<message text> <user>/<session ID> <event>

    • <time stamp> is the time/date that the system logged the message.
    • <F5OS host name> is the host name of the system that generated the message.
    • <service name> is the name of the service (and process ID) that generated the message.
    • <level> is the severity of the log message. This can be one of Emerg, Alert, Crit, Err, Warn, Notice, Info, Debug.
    • <version> is the version of the F5OS logging system. This should be 1.0 for all F5OS releases at the time of writing.
    • <message ID> is the identification number of the message.
    • <message text> is the description of the event that caused the system to log the message.
    • <user> is the name of the user who made the configuration change.
    • <session ID> session ID of the (confd CLI, GUI) interface endpoint.
    • <event> is the description of the configuration change or event that caused the system to log the message.

    Log message reference

    When you encounter a specific F5OS log message on your rSeries system, and require more information on it, refer to the F5OS-A rSeries Error Catalog on Clouddocs.

    New features

    F5OS-A 2.0.0:

    • Platform and audit log format changes. F5OS 2.0.0 introduced enhanced logging for critical services. For example, refer to K000162453: The file deletion log format was changed in F5OS v2.0.0.

    F5OS-A 1.8.4: 

    • Structured logging with logrotate support is added to the platform-deployment script and written to a dedicated log file, /var/log/platform-deployment.log. For more information, refer to ID 1462929.
