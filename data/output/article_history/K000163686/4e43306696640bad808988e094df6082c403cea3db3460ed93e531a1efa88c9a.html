Description

On a BIG-IP LTM high-availability pair, the standby device repeatedly logs httpd(pam_audit) authentication failures originating from the active peer:

01070417:6: AUDIT - RAW: httpd(pam_audit): tty=(unknown) host=<Host_IP> failed to login after 1 attempts

The failures may recur every minute. The active device’s BigipFailoverStateWorker uses REST communication through httpd for HA-related operations.

Environment

  • BIG-IP LTM active/standby pair
  • REST communication from the active device to the standby device through management and config-sync addresses
  • Repeated httpd(pam_audit) authentication failures on the standby device

Cause

restjavad on the active device was using stale cached credentials for internal REST communication with the standby peer. Direct REST authentication using the current administrative password succeeded, but internal REST calls continued to fail authentication. 

Answer/Recommended Actions

  1. From the active device, verify REST authentication to the standby device using the current administrative credentials through both the standby management address and config-sync address.
  2. If authentication succeeds through both addresses, restart restjavad on both devices:

    bigstart restart restjavad

  3. Verify that the recurring httpd(pam_audit) login-failure messages stop after the restart.

Note: Perform the restart during a maintenance window when possible. Restarting restjavad can briefly disrupt iControl REST operations, including GUI and API access.

Additional Information

Test Admin REST Login from Active BIG IP to Standby BIG IP
1. SSH into Active device
Log in to Active BIG IP via SSH a root or admin.
2. Run a curl test against Standby BIG IP

From Active BIG IP's bash shell, run:

curl -sku admin:<admin_password> https://<Remote_BIG IP>/mgmt/tm/sys/version | python -m json.tool

  1. Replace <admin_password> with the current admin password and test

 

Restarting restjavad clears its in-memory credential cache. During the next REST communication cycle, BigipFailoverStateWorker re-establishes communication with the peer using current authentication credentials.
