K54073173: Portal Access may fail when the Portal Access resource is in a different route domain with strict isolation enabled

Type
Support Solution
Published
2020-05-31
Updated
2026-11-02
Applies to
  • BIG-IP
  • BIG-IP APM
Source
https://my.f5.com/manage/s/article/K54073173

Description

A Portal Access deployment may fail to work when the Portal Access resource is in a non-default route domain that is different from the route domain of the virtual server, and strict isolation is enabled on the route domain objects.

Environment

  • BIG-IP APM 17.1.x, 17.5.x, or 21.1.x

  • Portal Access resource

  • Strict isolation enabled on the route domain objects

  • The virtual server is in route domain 0 (RD0), and the Portal Access resource is in a different, non-default route domain, for example route domain 1 (RD1)

Cause

This is expected behavior when Strict Isolation is enabled on the route domain objects.

Answer/Recommended Actions

To make this Portal Access deployment work, use one of the following options:

  • Disable Strict Isolation on the route domain objects.

  • Keep Strict Isolation enabled on the route domains, and do one of the following:

    • Move all the objects, for example the virtual server and the Portal Access resource, to the same route domain.

    • Define a parent-child relationship between the route domains. In the previous example (the virtual server in RD0, and the Portal Access resource in the non-default RD1), make RD0 the parent of RD1.

Impact of procedure: Changing route domain settings affects all traffic that uses those route domains. F5 recommends performing this procedure during a scheduled maintenance window.

Additional Information

You can control the forwarding of traffic across route domain boundaries with the strict isolation feature of a route domain:

  • If strict isolation is enabled, the BIG-IP system allows traffic forwarding from that route domain to the specified parent route domain only. This is the default behavior.

    Note: For successful isolation, you must enable strict isolation on both the child and the parent route domains.

  • If strict isolation is disabled, the BIG-IP system allows traffic forwarding from that route domain to any route domain on the system, without a parent-child relationship between the route domains.

    Note: For successful forwarding, you must disable strict isolation on both the forwarding route domain and the target route domain (the route domain to which the traffic is forwarded).
