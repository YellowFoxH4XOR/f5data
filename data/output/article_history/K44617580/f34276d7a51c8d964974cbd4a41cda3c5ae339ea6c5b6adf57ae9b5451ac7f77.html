Description

A previously working Forwarding Virtual Server, stopped responding. Recent changes to the config have been made but apparently unrelated to this Virtual Server or vlans configured on it.

Packets sent to the destination vlan do not seem to be delivered anymore.

TCP dump captures show IN traffic not being matched to any Virtual Server:

10.0.1.1 → 192.168.1.1  38266   22   TCP IN  s1/tmm0 : 38266 → 22 [SYN]
10.0.1.1 → 192.168.1.1  38266   22   TCP IN  s1/tmm0 : [TCP Retransmission] 38266 → 22 [SYN]
10.0.1.1 → 192.168.1.1  38266   22   TCP IN  s1/tmm0 : [TCP Retransmission] 38266 → 22 [SYN]
10.0.1.1 → 192.168.1.1  38266   22   TCP IN  s1/tmm0 : [TCP Retransmission] 38266 → 22 [SYN]

Environment

  • Recent changes to the configuration took place
  • Forwarding VS stops reponding

Cause

The connection.autolasthop db key has been disabled manually by error. An audit log can be seen on /var/log/audit similar to this:

notice mcpd[<PID>]: 01070417:5: AUDIT - client tmui, user admin1 - transaction #11264270-4 - object 0 - modify { db_variable { db_variable_name "connection.autolasthop" db_variable_value "disable" } } [Status=Command OK]

Recommended Actions

Re-enable auto-lasthop setting again on the unit with command below, or add a return route to the source vlan for return traffic to be able to reach back the Client IP.

tmsh modify /sys db connection.autolasthop value enable
