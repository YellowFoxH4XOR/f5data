Description

After upgrading BIG-IP to a major version daemons may not come up, device might be in inoperative state:

show /sys service all

localdbmgr down, waiting for mysql to release running semaphore

Root cause might be that mysqld daemon is not able to start, and after inspecting /var/log/mysql.out we can observe similar noted issue:

Sep 11 11:40:33 Initializing MySQL210911 11:40:33 [Note] /usr/sbin/mysqld (mysqld 5.5.53-MariaDB) starting as process 11191 ... ERROR: 1 Can't create/write to file '/var/tmp/#sql_2bb7_0.MAI' (Errcode: 13) 210911 11:40:33 [ERROR] Aborting 210911 11:40:33 [Note] /usr/sbin/mysqld: Shutdown complete
 

Environment

  • BIG-IP APM
  • Upgrade

Cause
Issue is due to file system permission change.

Recommended Actions

  1. Boot into the previous volume/version.
  2. Delete the upgrade volume/version.
  3. Re-install the BIG-IP version in a new volum.
  4. Import the configuration into the new version from UCS backup. 
    Note: For more information refer to:  K13132: Backing up and restoring BIG-IP configuration files with a UCS archive
