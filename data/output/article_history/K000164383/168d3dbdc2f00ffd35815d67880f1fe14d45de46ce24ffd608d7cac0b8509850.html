K000164383: BIG-IP tenant on r2000/r4000 rSeries: ICMP traffic to a floating IP address is not received by the tenant after a VLAN is moved to a different interface

Type
Support Solution
Published
2026-11-26
Updated
2026-11-26
Source
https://my.f5.com/manage/s/article/K000164383

Description

On a BIG-IP tenant running on an r2000 or r4000 series rSeries appliance, pings to a floating self IP address fail after a VLAN is moved from one interface to another, or after a VLAN on a different interface is added to the tenant.

  • The ICMP echo requests destined to the floating IP address can be observed on the physical interface of the F5OS host.
  • The same traffic is not observed on the virtual interface assigned to the tenant.
  • Moving the VLAN back to the original interface restores connectivity to the floating IP address.

Environment

  • r2000 and r4000 series appliances, all F5OS-A versions
  • BIG-IP tenant running a software version that does not contain the fix for ID1309637

Cause

The behavior is a symptom of ID1309637: MAC masquerade not working after VLAN movement on host interfaces.

When MAC masquerade is configured on a traffic group, the floating IP address is advertised with the masquerade MAC address. The network adapter driver on the F5OS host delivers ingress frames to a tenant virtual function only if the destination MAC address matches a MAC filter programmed on that virtual function. Frames that do not match any MAC filter are not delivered to the tenant, although they can still be observed in a packet capture on the host physical interface.

Due to ID1309637, the masquerade MAC address is not programmed on the tenant interface that is newly initialized when a VLAN is moved to, or added on, a different interface. As a result, traffic destined to the floating IP address reaches the physical interface of the host but is not delivered to the tenant virtual interface.

This applies to r2000 and r4000 series rSeries appliances, on all F5OS-A versions and for all tenants, unless the tenant runs a BIG-IP version in which ID1309637 is fixed. As long as ID1309637 is present, the behavior is expected. Once ID1309637 is fixed, the packets are expected to reach the tenant virtual interface.

The defect is in the BIG-IP (TMOS) software of the tenant. The fix is implemented in TMOS, not in F5OS, so upgrading F5OS-A does not resolve the issue.

Recommended Actions

To resolve the issue, upgrade the BIG-IP tenant to a version that contains the fix for ID1309637 as per Bugtracker:

If the tenant cannot be upgraded, use the following workaround after the VLAN has been moved:

  1. Delete the MAC masquerade address from the traffic group.
  2. Configure the MAC masquerade address on the traffic group again.

Note: Directly modifying the MAC masquerade address is not sufficient while ID1309637 is present.
