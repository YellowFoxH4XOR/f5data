K000163871: ASM JSON Policy Export Omits User-Defined Signatures; Referenced Signatures Must Exist on the Target Device Before Import

Type
Support Solution
Published
2026-10-23
Updated
2026-10-23
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000163871

Description

When an ASM policy is exported in JSON format, user-defined (custom) signatures are not included in the file. The same policy exported in XML format contains them. Searching the JSON export for a custom signature ID returns no match.

Environment

  • Product: BIG-IP ASM
  • Version: 15.x, 16.x, 17.x
  • Export formats compared: XML and JSON
  • Object affected: User-defined signatures (custom signature rules)

Cause

BugID773249 - Sets are contained within the exported policy and are created on the target device, but user-defined Signatures are not.
Bug 1773249 was closed as FUNCTIONS AS DESIGNED.

Resolution / Recommended Actions

  1. Before importing a JSON policy, create the required user-defined signatures on the target device.
  2. Import the policy. The policy imports correctly once the requisite user-defined signatures exist on the target device.
  3. Do not assume the JSON policy alone recreates user-defined signatures.
  4. If user-defined signatures must be preserved in the export, use XML format.
    Bug 1773249 reports no issue with XML (.xml) and .plc policy types.
