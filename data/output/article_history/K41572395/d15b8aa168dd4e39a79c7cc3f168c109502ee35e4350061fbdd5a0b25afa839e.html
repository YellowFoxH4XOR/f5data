Chapter 4: Network Address Translation (NAT)

Table of contents | << Previous chapter | Next chapter >>

A Network Address Translation (NAT) is a mapping of one IP address to another IP address. This mapping can be a translation of source, destination, or both. A NAT can be outbound or inbound.

Outbound NAT

Outbound NAT translates an internal source address to a public address. A NAT can also be used to translate an internal node’s IP address to an Internet routable IP address.

Figure 4.1 Outbound NAT

Creating the Source NAT Outbound profile

  1. Log in to the BIG-IP AFM Configuration utility.
  2. Go to Security > Network Address Translation.
  3. Select Source Translation.
  4. Select Create.
  5. Enter a name for the translation profile.
  6. In the Type menu, select Static NAT.
  7. In the Addresses box, enter the IP address that will be used as the translated source address.

    Note: In the example Figure 4.1 the address is 104.219.104.148.

  8. Set ICMP Echo, Proxy ARP, and Route Advertisement to Enabled.
  9. Set Egress Interfaces to "Enabled on..."
  10. Select the interface or VLAN check box that is used to access the destination resource that requires translation of the source address.
  11. Select Save.
  12. Select Submit.

Creating the Outbound NAT policy

  1. Log in to the BIG-IP AFM Configuration utility.
  2. Go to Security > Network Address Translation > Policies.
  3. Select Create.
  4. Enter a policy name.
  5. Select Add Rule.
  6. Enter a NAT rule name.
  7. Set State to Enabled.
  8. Select the desired protocol to be allowed from the Protocol menu or leave at Any (default).
  9. In the Source box, enter the originating source IP address.

    Note: In the example Figure 4.1 this address is 172.16.20.3.

  10. Leave Destination at the default settings for the following: Address: Any, Ports: Any, with Proxy ARP and Route Advertisement set to Disabled.
  11. From the Translated Destination menu, select the translation profile name created in the previous procedure.

    Note: In the example Figure 4.1 this address is 104.219.104.148.

  12. Select the desired logging profile from the Log Profile menu.
  13. Select Done Editing.
  14. Select Commit Changes to System. 

    Note: At this point you can apply the NAT policy to the appropriate virtual server or as the Global Network Address Translation.

Assigning the NAT policy

  1. Log in to the BIG-IP AFM Configuration utility.
  2. Go to Local Traffic > Virtual Servers > Virtual Server List.
  3. Select the name of the virtual server to modify.
  4. Select Security > Policies.
  5. In the Network Address Translation section, select the NAT policy created in the previous step from the list. 

    Note: You can alternatively assign the new NAT policy to the Global Firewall NAT > Network Address Translation. With that setting, the policy is applied to all virtual servers.

Inbound NAT

Inbound NAT translates a public destination address to an internal address. When an external client sends traffic to the public IP address defined in a NAT, the BIG-IP system translates that destination address to the internal node IP address.

Figure 4.2 Inbound NAT

Creating an Inbound NAT to allow translation of one IP address to another using the Configuration utility

Creating the Source NAT inbound profile

  1. Log in to the BIG-IP AFM Configuration utility.
  2. Go to Security > Network Address Translation.
  3. Select Destination Translation.
  4. Select Create.
  5. Enter a name for the translation profile.
  6. For Type, select Static NAT.
  7. In the Addresses box, enter the IP address or range of IP addresses that will be used as the translated destination addresses.

    Note: In the example Figure 4.2 the address is 172.16.20.3.

  8. Select Save.

Creating the Inbound NAT policy

  1. Log in to the BIG-IP AFM Configuration utility.
  2. Go to Security > Network Address Translation > Policies.
  3. Select Create.
  4. Enter a policy name.
  5. Select Add Rule.
  6. Enter the NAT rule Name.
  7. Set State to Enabled.
  8. For Protocol, select the protocol to be allowed or leave at Any (default).
  9. For Source, enter the originating source IP addresses that are to be translated or Any (default).
  10. For Destination, enter the destination IP address translated to the IP address of the internal destination.

    Note: In the example Figure 4.2 the address is 104.219.104.148.

  11. For Translated Destination, select the translation profile name created in the previous procedure (172.16.20.3).
  12. For Log Profile, select the logging profile.
  13. Select Done Editing.
  14. Select Commit Changes to System.

Applying the NAT policy

  1. Log in to the BIG-IP AFM Configuration utility.
  2. Go to Local Traffic > Virtual Servers > Virtual Server List.
  3. Select the name of the virtual server to modify.
  4. Select Security.
  5. In the Network Address Translation section, select the NAT policy created in the previous step.
  6. Select Update.

    Note: You can alternatively assign the new NAT policy to the Global Firewall NAT > Network Address Translation. With that setting, the policy is applied to all virtual servers.

Dynamic PAT

NAT, by design, is a one-to-one operation, while Port Address Translation (PAT) can be used to map many IP addresses to one IP address in order to hide the source IP networks.

Dynamic PAT Modes and Mapping

In the most common client-server network configuration, the BIG-IP address translation mechanism ensures that server responses return to the client through the BIG-IP system.

  • Deterministic mode
  • NAPT mode
  • Port Block Allocation mode
  • Mapping

Deterministic mode

Address translation mode provides address translation that eliminates logging of every address mapping, while still allowing internal client address tracking using only an external address and port, and a destination address and port. Deterministic mode allows unique identification of the internal client address based on: external address and port (the address and port visible to the destination server), destination address and port (the service accessed by the client), and time. This mode significantly reduces the logging burden while mapping a subscriber's inside IP address with an outside Internet address and port.

NAPT mode

Provides standard address and port translation allowing multiple clients in a private network to access remote networks using the single IP address assigned to their router. For outbound packets, NAPT translates the source IP address and source transport identifier. For inbound packets, NAPT translates the destination IP address, the destination transport identifier, and the IP and transport header checksums. This mode is beneficial for remote access users.

Port Block Allocation mode

Logs the allocation and release of port blocks for subscriber translation requests, instead of separately logging each translation request. Translation requests are serviced from a block of ports on a single IP address. This reduces the number of log entries while maintaining legal mapping and reverse mapping requirements.

Mapping

  • Address Pooling Paired enables all the sessions associated with an internal IP address to map to the same external IP address for the duration of the session.
  • Endpoint Independent Mapping assigns the same external address and port for all connections from the host if it uses the same internal port.
  • None assigns no mapping mode to dynamic port assignments.

Clients and servers on the same subnet

To load balance requests to server nodes that are on the same subnet as the client nodes, create a SNAT so that server responses are sent back through the BIG-IP system rather than directly from the server node to the client node. Otherwise, problems can occur such as the client (172.16.1.30) rejecting the response because the source of the response (172.16.20.1) does not match the destination of the request (172.16.1.100).

BIG-IP system is not server node default gateway

Sometimes a server’s default route cannot be defined to be a route through the BIG-IP system. This can cause problems such as the client rejecting the response because the source of the response does not match the destination of the request.

The solution is to create a SNAT. The BIG-IP system then translates the client node’s source IP address in the request to the SNAT address, causing the server node to use that SNAT address as its destination address when sending the response. This, in turn, forces the response to return to the client node through the BIG-IP system rather than through the server default gateway.

Outbound Dynamic PAT (NAPT Explicit)

Note: Similar behavior to the BIG-IP LTM source address translation SNAT.

Outbound Static PAT translates an internal source addresses to a single translated (public) addresses, inbound response traffic only.

Creating the Dynamic PAT profile

  1. Log in to the BIG-IP AFM Configuration utility.
  2. Go to Security > Network Address Translation.
  3. Select Source Translation.
  4. Select Create.
  5. Enter a name for the translation profile.
  6. For Type, select Dynamic PAT.
  7. For Addresses:, enter the IP address that will be used to translate all traffic as defined by the policy.
  8. For Ports:, enter the expected port or port range that will be used by the translated IP address when accessing resources.
  9. Set ICMP Echo, Proxy ARP, and Route Advertisement to Enabled.
  10. Set Egress Interfaces to "Enabled on..."
  11. For Egress Interfaces, select the appropriate destination interface or VLAN check boxes).
  12. Select Dynamic PAT.
  13. For Mapping > Mode, select Address Pooling Paired.
  14. Set InBound Mode to Explicit.

    Note: Setting Explicit will only allow bi-directional communication for initially established connections.

  15. Select Save.

Creating the Outbound Dynamic PAT policy

  1. Log in to the BIG-IP AFM Configuration utility.
  2. Go to Security > Network Address Translation > Policies.
  3. Select Create.
  4. Enter a policy name.
  5. Select Add Rule.
  6. Enter the PAT rule name.
  7. Set State to Enabled.
  8. For Protocol, select the protocol to be allowed or leave as Any (default).
  9. For Source, add the IP addresses or network range that will use the Dynamic PAT profile for translation.
  10. Leave Destination at the default settings.
  11. For Translated Source, select the translation profile name created in the previous procedure.
  12. Leave Translated Destination to the default setting of None.
  13. For Log Profile, select the logging profile.
  14. Select Done Editing.
  15. Select Commit Changes to System.

Applying the Dynamic PAT policy

  1. Log in to the BIG-IP AFM Configuration utility.
  2. Go to Local Traffic > Virtual Servers > Virtual Server List.
  3. Select the name of the virtual server to modify.
  4. Select Security.
  5. For Network Address Translation, select the NAT policy created in the previous step.
  6. Select Update. 

    Note: You can alternatively assign the new NAT policy to the Global Firewall NAT > Network Address Translation. With that setting, the policy is applied to all virtual servers.

Port exhaustion

Each NAT address has only 65,535 ports available. This is a limit of the TCP and User Datagram Protocol (UDP) protocols, which use a 16-bit unsigned integer for source ports.

Port exhaustion or collisions may occur under heavy usage or unusually distributed client traffic patterns. For performance reasons, the BIG-IP system does not search exhaustively for an available source port. Port exhaustion may occur well before all 65,535 ports are used. As a result, connections that cannot be translated due to lack of available ports on a given translation address may be dropped.

To determine when NAT port exhaustion is occurring by reviewing the system log files. When port exhaustion occurs, the BIG-IP system logs messages to the /var/log/ltm file.

The following is an example of a port exhaustion log message:

01010201:2: Inet port exhaustion on 10.10.20.21 to 4.4.4.2:53 (proto 17) 01010201:2: Inet port exhaustion on 10.10.20.21 to 23.73.217.114:80 (proto 6)

Port mapping

When a NAT is configured on the BIG-IP system (independently or in conjunction with a virtual server), the source address of each connection is translated to a configured NAT address, and the source port is mapped to a port currently available for that NAT address. By default, the BIG-IP system attempts to preserve the source port, but if the port is already in use on the selected translation address, the system translates the source port.

Mitigating port exhaustion

To mitigate port exhaustion, use a range of NAT translation IP addresses. If already using a range of NAT IP address, adding an additional range of NAT IP addresses to the NAT Source or Destination profile can augment the total available ports for use by the NAT.

NAT& PAT statistics

Monitoring the number of concurrent connections going through the NAT using the Configuration utility

  • Go to Security > Reporting > Network Address Translation > Source > Translation
  • Go to Security > Reporting > Network Address Translation > Destination > Translation

Monitoring the number of concurrent connections going through the NAT using tmsh

  • Enter the following command:

    tmsh show /security nat
