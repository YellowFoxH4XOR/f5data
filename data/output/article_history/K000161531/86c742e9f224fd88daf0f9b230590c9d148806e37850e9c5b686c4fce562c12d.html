K000161531: Error Message: 01070734:3: Configuration error: Can't associate Pool folder does not exist

Applies to

Source

Description

When deploying GSLB objects into a custom folder using F5 Application Services 3 Extension (AS3), BIG-IP DNS configuration synchronization fails if the target folder does not already exist on the sync peer.

The affected objects fail to sync, and mcpd logs messages similar to the following:

01070734:3: Configuration error: Can't associate Pool (/Example/Example/example-pool) folder does not exist
01071488:3: Remote transaction for device group /Common/gtm ... failed with error 01070734:3: Configuration error: Can't associate Pool ... folder does not exist

Environment

  • BIG-IP DNS 17.5.1
  • F5 Application Services 3 Extension (AS3)
  • BIG-IP DNS synchronization group
  • Custom folders or partitions (for example, /Example/Example)

Cause

BIG-IP DNS configuration synchronization does not automatically create parent or custom folders on peer devices before syncing the objects inside them. If the destination folder is missing on the peer, the sync transaction fails.

Recommended Actions

Immediate Remediation

  1. Identify the custom folder path required by the AS3 declaration.
  2. Log in to the command line of the peer device.
  3. Manually create the missing folder (and any missing parent folders):

    tmsh create sys folder /Example/Example

  4. Save the configuration on the peer:

    tmsh save sys config

  5. Re-run configuration sync or re-submit the AS3 declaration.

Best Practice for Future AS3 Deployments

When introducing new custom folders in an AS3 workflow:

  1. Deploy folder structure first: Create the custom folder on all sync peers and allow synchronization to stabilize.
  2. Deploy GSLB objects second: Submit the declaration containing the GSLB objects that reside in that folder.
