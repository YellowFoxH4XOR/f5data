Description

When migrating a BIG-IP configuration to an F5OS-A (rSeries) platform using a UCS file, the import may fail if the UCS contains configurations that are not supported on F5OS-A. Specifically, UCS files exported from BIG-IP devices that use trunk (LAG) interfaces require manual editing before they can be successfully imported on an rSeries tenant. Some of the symptoms you may observe are the following:

 

  • UCS import fails on F5OS-A (rSeries) tenant
  • Import errors referencing trunk or STP configurations
  • VLAN interface references to trunks prevent successful load

You may observe the following error messages while loading the UCS file:

Error: trunk configurations are not supported on this platform

Error: net stp configuration references unsupported objects

Environment

  • Source platform: BIG-IP (any version) configured with trunk/LAG interfaces and STP
  • Target platform: F5OS-A (rSeries) — any model (e.g., r2000, r4000, r5000, r10000)
  • Operating System: Linux workstation (used for UCS manipulation)
  • Utilities required: tar, gzip, text editor (nano, vi, or similar)
  • Relevant configuration objects:
    • net trunk — LAG/trunk interface definitions
    • net stp / net stp-globals — Spanning Tree Protocol configuration
    • net vlan — VLAN definitions containing interfaces blocks referencing trunks
  • UCS file: Exported from source BIG-IP via tmsh save sys ucs

Cause

F5OS-A (rSeries) does not support net trunk, net stp, and net stp-globals configurations within a BIG-IP tenant UCS. These constructs are managed at the F5OS host layer, not within the tenant. When a UCS exported from a classic BIG-IP (which manages these objects at the TMOS layer) is imported into an rSeries tenant, the import fails because the tenant has no authority over physical interface aggregation or STP. 

Additionally, net vlan objects that contain interfaces blocks referencing trunks must have those blocks removed, as interface-to-VLAN mapping is also handled at the F5OS host layer on rSeries platforms.

 

Answer/Recommended Actions

The following procedure describes how to manually edit and repackage a UCS file on a Linux workstation to remove unsupported configurations before importing on an rSeries tenant.

 

Step 1: Create Working Directory

mkdir -p ~/ucs_migration
cd ~/ucs_migration

Verify the file is there:

ls -lh bigip-backup.ucs

Step 2: Copy the Original UCS File to Working Directory

Assuming you have the UCS file in your current directory or downloads:

cp /path/to/bigip-backup.ucs ~/ucs_migration/
cd ~/ucs_migration

Warning: if your UCS is large the filesystem containg /home/users or /root (depending on which user you are logged in as) may be too small to copy this file to.   In such instance consider utilizing /var/tmp instead.

Verify the file is there:

ls -lh bigip-backup.ucs

Step 3: Create Extraction Directory and Extract the UCS

mkdir ucs_temp
cd ucs_temp
tar -xzf ../bigip-backup.ucs

Note: You will see many symlink errors like:

tar: config/bigip/auth/pam.d/system-auth: Cannot create symlink to 'ldap/system-auth': Operation not supported
tar: var/libdata/dpi/conf/classification_update.conf: Cannot create symlink to 'classification_update_empty.conf': Operation not supported
...
tar: Exiting with failure status due to previous errors

These errors are NORMAL and expected. They occur because the UCS contains symlinks to system paths that don't exist on your Linux workstation. The actual file content is extracted successfully, and these symlinks will be recreated correctly when the UCS is loaded on the target F5OS system.

Step 4: Verify Extraction Was Successful

ls -la

You should see:

    config/ directory
    etc/ directory
    var/ directory
    home/ directory
    root/ directory
    SPEC-Manifest file
    SPEC-Files file

Step 5: Identify Problematic Configurations

Check for trunk configurations: grep -n "net trunk" config/bigip_base.conf
Check for STP configurations: grep -n "net stp" config/bigip_base.conf
Check for VLAN configurations: grep -n "net vlan" config/bigip_base.conf
Check for any trunk references: grep -i "trunk" config/bigip_base.conf

Take note of the line numbers where these configurations appear.

Step 6: View the Configurations That Need to Be Removed

To see the actual trunk configuration: grep -A 10 "net trunk" config/bigip_base.conf
To see the STP configuration: grep -A 15 "net stp" config/bigip_base.conf
To see the VLAN configurations: grep -A 12 "net vlan" config/bigip_base.conf | head -80

Step 7: Edit bigip_base.conf

You can use either nano or vi. I used nano.

Step 8: Remove Unsupported Configuration Blocks

A. Remove ALL net trunk configurations

net trunk lag1 {
    interfaces {
        1.1
        1.2
    }
    lacp enabled
}

Delete the entire block from net trunk lag1 { to the closing }

B. Remove ALL net stp configurations

net stp /Common/cist {
    trunks {
        lag1 {
            external-path-cost 2000
            internal-path-cost 2000
        }
    }
    vlans {
        /Common/vlan_10
        /Common/vlan_20
        /Common/vlan_30
        /Common/vlan_40
        /Common/vlan_50
    }
}

Delete the entire block from net stp /Common/cist { to the closing }

Also delete:

net stp-globals {
    config-name 00-00-00-00-00-00
}

C. Remove interfaces sections from ALL VLANs. BEFORE (what you'll see):

net vlan /Common/vlan_10 {
    dag-adjustment none
    description internal_network
    interfaces {
        lag1 {
            tag-mode service
            tagged
        }
    }
    sflow {
        poll-interval-global no
        sampling-rate-global no
    }
    tag 10
}

AFTER (what it should look like):

net vlan /Common/vlan_10 {
    dag-adjustment none
    description internal_network
    sflow {
        poll-interval-global no
        sampling-rate-global no
    }
    tag 10
}

Remove ONLY the interfaces { ... } section, but KEEP the rest of the VLAN definition (description, sflow, tag). Repeat this for ALL VLANs that have interfaces sections referencing trunks. 

Note: after you successfully load this configuration via the rebuilt ucs file, you will need to associate your host provided lag or interface to the vlan so that traffic can flow (easily done in the webui).  If you are aware of the approriate host provided interface or lag name you can simply subsitute that name in interfaces stanza.

Step 9: Save and Exit

For nano:

    Press Ctrl + O to save
    Press Enter to confirm
    Press Ctrl + X to exit

Step 10: Verify Changes

Check that trunk configurations are gone: grep -n "net trunk" config/bigip_base.conf
Check that STP configurations are gone: grep -n "net stp" config/bigip_base.conf
Check that VLANs no longer have interface/trunk references: grep -A 10 "net vlan" config/bigip_base.conf | head -60
Double-check for any remaining trunk references: grep -i "trunk" config/bigip_base.conf

Step 11: Navigate Back to Parent Directory

cd ..
pwd

You should be in ~/ucs_migration

Step 12: Repackage the UCS File

cd ucs_temp
tar -czf ../bigip-fixed.ucs *
cd ..

Note: You may see warnings like:

tar: config/customization: file changed as we read it
tar: config: file changed as we read it
tar: var/tmp/storage_temp: file changed as we read it

These warnings are NORMAL and can be ignored. They occur because tar is reading directories while creating the archive.

Step 13: Verify the New UCS Archive Structure

Check the first 20 files in the archive: tar -tzf bigip-fixed.ucs | head -20

Expected output: You should see files like:

config/
config/.auto_schema_data_security_cli.dat-uuid-excluded
config/.bigip_emergency.conf
config/.diffVersions/
...
SPEC-Files
SPEC-Manifest
etc/
var/

Important: There should be NO ./ prefixes at the beginning of any file paths.

Step 14: Check for Problematic ./ Prefixes

tar -tzf bigip-fixed.ucs | grep "^\\./"

Expected output: Nothing (empty)

If this command returns nothing, your UCS file is properly packaged. If it returns file paths starting with ./, the archive is incorrectly structured and will fail to import.

Step 15: Verify Critical Files Are Present

tar -tzf bigip-fixed.ucs | grep -E "^(SPEC-|config/bigip_base\.conf$)"

Expected output:

config/bigip_base.conf
SPEC-Files
SPEC-Manifest

Step 16: Compare File Sizes

ls -lh bigip-backup.ucs bigip-fixed.ucs

The new file should be slightly smaller (since we removed trunk/STP config), but similar in size to the original.

Example output:

-rw-rw-r-- 1 user user 39M Jan 1  bigip-backup.ucs
-rw-rw-r-- 1 user user 38M Jan 1  bigip-fixed.ucs

Step 17: Clean Up (Optional)

rm -rf ucs_temp
ls -lh

You should now see:

    Original: bigip-backup.ucs
    New fixed: bigip-fixed.ucs

Step 18: Upload and Import the Fixed UCS on the F5OS Tenant

Upload the UCS file to the tenant. SSH to the tenant and import the UCS.

ssh admin@<tenant-management-ip>
tmsh load sys ucs /shared/bigip-fixed.ucs no-license platform-migrate reset-trust

Step 19: Post-Import Configuration at the F5OS-A Host Level

After successful import, you must manually configure the following at the F5OS-A host level (not within the tenant):

A. Create LAG (Link Aggregation Group) at F5OS-A Level
B. Create VLANs at F5OS-A Level
C. Assign VLANs to LAG Interface
D. Associate VLANs with Tenant

This procedure applies specifically to UCS files from BIG-IP devices that used hardware-based trunk/LAG interfaces. UCS files from devices without trunk configurations may not require these edits. The platform-migrate flag in the tmsh load sys ucs command is required when migrating between different hardware platforms (e.g., iSeries to rSeries). The reset-trust flag is required to reset device trust relationships, which is expected when migrating to a new platform. After import, interface and VLAN configuration must be validated at the F5OS-A host layer to ensure traffic flows correctly to the tenant.

For LAG and VLAN configuration at the F5OS-A host layer, refer to: F5OS-A Network Configuration on rSeries.
