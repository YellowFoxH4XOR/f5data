K000163802: BIG-IP APM Edge Client Deletes the Windows WinINET AutoDetect Registry Value During VPN Connection

Type
Support Solution
Published
2026-10-20
Updated
2026-10-20
Applies to
  • BIG-IP
  • APM Clients

Description

The F5 Edge Client deletes the Windows WinINET AutoDetect registry value during VPN tunnel establishment. When the value is configured as 0 to disable WPAD and automatic proxy detection, the value becomes missing after the VPN connection is established.

Affected registry path:

HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings\AutoDetect

Observed behavior:

  • Before VPN connection: AutoDetect=0
  • After VPN connection: AutoDetect is missing
  • After Group Policy refresh: AutoDetect=0 is restored

Environment

  • BIG-IP APM
  • F5 Edge Client for Windows
  • BIG-IP APM Network Access VPN resources
  • Windows workstations using Group Policy to configure AutoDetect=0
  • Client Proxy Settings may be enabled or disabled; disabling them does not resolve the issue

Cause

This behavior is associated with Bug alias 2455645:

[WIN] Edge Client deletes the WinINET AutoDetect registry value during VPN tunnel establishment.

During VPN connection establishment, the F5 Edge Client clears or deletes the user-level WinINET AutoDetect value instead of preserving the configured value.

The following setting is separate and does not control proxy auto-discovery:

HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings\ZoneMap\AutoDetect

Recommended Actions

  1. Verify that the intended registry value is configured:

    HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings\AutoDetect

    Expected value:

    AutoDetect=0

  2. Verify the value before connecting to VPN:
    Get-ItemProperty -Path "HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings" |
    Select-Object AutoDetect, AutoConfigURL, ProxyEnable, ProxyServer
  3. Connect to VPN using the F5 Edge Client.
  4. Run the same command after the VPN connection is established.
  5. If AutoDetect is missing, use the existing Group Policy configuration to restore the value to 0.
  6. Apply the product fix for Bug alias 2455645 when available.
  7. If additional investigation is required, collect a Client Troubleshooting Utility report while the issue is reproduced.

Impact

Deleting the AutoDetect value can override an enterprise policy intended to disable WPAD. This may cause renewed WPAD auto-discovery, additional WPAD DNS queries, and increased exposure to malicious proxy auto-configuration.
