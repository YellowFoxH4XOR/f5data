K000163790: XML imports of BIG-IP ASM security policies fail with schema validation errors.

Published
2026-10-20
Updated
2026-10-20
Applies to

  • BIG-IP ASM
Source

Description

Note: In recent BIG-IP versions, XML imports can showcase many schema related errors, if your environment doesn't have strict requirements of using XML format, use JSON/binary (PLC) alternatively.

Example:

A BIG-IP ASM or BIG-IP AWAF security policy exported in XML format may fail to import when Session Tracking is enabled and a login page is configured.

The security policy file does not conform to the schema and cannot be imported.

Element 'deny_blocking' is not expected. Expected is (statuses).

The error may also reference delay_blocking, depending on the policy XML and validation point.

Environment

  • BIG-IP ASM
  • XML Imports of Security Policies
  • A login page configured under Security > Application Security > Session Tracking
  • The exported policy contains a <login_pages> element within the Session Tracking section.

Cause

ID2621657 causes the XML export process to place the <login_pages> element before the closing </delay_blocking> tag. This element order does not conform to the expected security policy XML schema.

During import, schema validation rejects the file because the importer expects a different element, such as <statuses>, at that location.

Recommended Actions

Workaround for an Existing XML Policy

  1. Create a backup copy of the exported XML policy.
  2. Open the XML file in a text editor.
  3. Locate the <login_pages> section associated with Session Tracking.
  4. Move the <login_pages> section so that it appears after the closing </delay_blocking> tag.
  5. Save the modified XML file.
  6. Validate and import the policy in a test environment before using it in production.

The relevant structure should place the Session Tracking login page after the complete delay_blocking section:

<delay_blocking>

...

</delay_blocking>

<login_pages>

...

</login_pages>

Alternative Policy Formats

  • If XML export and import are not strictly required, use the Binary or JSON policy format. This defect affects XML policy export and import; Binary and JSON policy formats are not affected.

Software Remediation

  • If XML format is strictly required, open a case with F5 Support to check if EHF can be provided.

Additional Information

  • The workaround changes the XML element order in the Session Tracking portion of the policy so that BIG-IP can validate and accept the file.
  • The workaround should not alter the security policy's functional behavior.
  •  In recent BIG-IP versions, XML imports can showcase many schema related errors, if your environment doesn't have strict requirements of using XML format, use JSON/binary (PLC) alternatively.
