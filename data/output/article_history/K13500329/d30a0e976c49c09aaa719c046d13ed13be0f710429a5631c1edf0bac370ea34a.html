K13500329: Correcting a Portal Access rewrite failure for a URL

Type
Knowledge
Published
2019-02-15
Updated
2026-10-29
Applies to
  • BIG-IP
  • BIG-IP APM: 17.X.X, 17.1.X, 17.1.1, 17.1.0, 17.0.X, 17.0.0
Source
https://my.f5.com/manage/s/article/K13500329

Description

Portal Access rewrites the URLs in web content so that the browser requests them through the BIG-IP APM virtual server, in the form /f5-w-<hexadecimal scheme, host, and port>$$/<path>. If Portal Access does not rewrite a URL, the browser requests it without this prefix, and the request may fail.

You should consider using this procedure under the following condition:

  • Requests for a Portal Access application reach the BIG-IP APM virtual server without the /f5-w-...$$ prefix.

Symptoms

  • Parts of the application, or the whole application, do not display correctly through Portal Access.

  • Requests for the application fail.

Environment

  • BIG-IP APM 17.1.x, 17.5.x, or 21.1.x

  • Portal Access resource configured

Cause

Portal Access did not rewrite a URL in the web content of the application. One cause is JavaScript that Portal Access cannot parse. For more information, refer to K15142093: BIG-IP APM Portal Access - JavaScript compatibility.

Answer/Recommended Actions

  1. Find the cause of the missing rewrite by following K14184: Troubleshooting BIG-IP APM Portal Access applications.

  2. If the application uses ES6 or later JavaScript, make sure that it is rewritten in Modern mode (K000130439).

  3. If a URL is still not rewritten, open a support case so that the cause can be reviewed for correction. Provide the data listed in the Collect HTTPWatch or HAR files for support section of K14184.

Workaround

You can use an iRule that adds the Portal Access prefix to requests that do not have it.

Important: When you troubleshoot Portal Access with F5 Support, temporarily remove the workaround iRule from the virtual server.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

Finding the hexadecimal value of the back-end application

The value is the hexadecimal encoding of the back-end scheme and host (and port, if it is not the default), for example https://application.example.com = 68747470733a2f2f6170706c69636174696f6e2e6578616d706c652e636f6d.

To find it, open the application through Portal Access and copy the value from a rewritten URL in the browser address bar: it is the part between /f5-w- and $$.

Note: If the URL that is not rewritten belongs to a different back-end host, use the hexadecimal value of that host. You can copy it from another rewritten request to that host, for example in the Network tab of the browser developer tools (F12).

Creating the iRule

  1. Log in to the Configuration utility.

  2. Go to Local Traffic > iRules > iRule List.

  3. Click Create.

  4. Enter a name for the iRule.

  5. In Definition, enter the following iRule:

    when HTTP_REQUEST {
        if { [HTTP::has_responded] } { return }
        if { [string tolower [HTTP::uri]] starts_with "/<uri>" } {
            HTTP::uri "/f5-w-<hex_value>$$[HTTP::uri]"
        }
    }

    Replace <uri> with the beginning of the path of the request that is not rewritten, in lowercase. Replace <hex_value> with the hexadecimal value from the previous section.

  6. Click Finished.

Adding the iRule to the virtual server

Impact of procedure: F5 recommends performing this procedure during a scheduled maintenance window.

  1. Go to Local Traffic > Virtual Servers > Virtual Server List.

  2. Click the name of the Portal Access virtual server.

  3. Click the Resources tab.

  4. In the iRules section, click Manage.

  5. Move the iRule from Available to Enabled.

  6. Click Finished.

To back out of this procedure, move the iRule from Enabled to Available.
