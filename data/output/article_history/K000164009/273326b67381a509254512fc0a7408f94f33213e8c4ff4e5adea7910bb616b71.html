Description

When ASM is provisioned, repeated ASM statistics loads from monpd can exhaust the 384 MB restjavad Java heap. restjavad may generate a Java core and terminate with SIGABRT.

Environment

  • BIG-IP with ASM provisioned
  • monpd ASM statistics processing large batches of HTTP IP and URL statistics

Cause

Repeated ASM statistics loads can retain heap objects faster than garbage collection can reclaim them. When the 384 MB restjavad heap reaches critical capacity, allocation bursts can trigger cascading minor garbage collections, followed by a failed full garbage collection and termination with SIGABRT.

Answer/Recommended Actions

Increase the memory available to restjavad:

tmsh modify sys db restjavad.useextramb value true

tmsh modify sys db provision.extramb value 2048

bigstart restart restjavad

tmsh save sys config

If another restjavad core is generated after increasing the memory, collect a restjavad heap dump together with the new core for further analysis.

Additional Information

Review monpd.log for repeated STAT_BRIDGE_THREAD|ERROR messages, including:

Some rows of load_stat_asm_http_ip_<ts> not loaded

Some rows of load_stat_asm_http_url_<ts> not loaded

The affected batches may contain approximately 2,000 or more ASM HTTP IP and URL statistic rows. These messages can correspond with recurring statistics-loading cycles and garbage-collection cascades.
