K000164252: A failover failure on Azure HA pair

Description

A failover on an Azure HA pair fails even when the CFE dry-run completes without errors. The CFE log shows:

severe: [f5-cloud-failover] Network Interface <nic-name> specifies multiple IPConfigurations but none of the IPConfigurations is specified as Primary.

This occurs when a floating address in traffic-group-1, including a SNAT translation address, is also the primary IP configuration (ipconfig1) of a NIC, such as a device self IP.

Environment

  • Product: BIG-IP LTM
  • Version: 17.5.1 (applicable to other versions with CFE support). A failure was observed on BIG-IP LTM 17.1.3 with CFE 1.15.0.
  • Platform: BIG-IP Virtual Edition on Azure
  • Configuration Components:
    • Active-Standby HA pair with Cloud Failover Extension
    • Azure Network Interfaces with secondary IP configurations
    • Azure Storage Account for the CFE state file
    • CFE configuration with scoping tags, including the f5_cloud_failover_nic_map tag for NIC pairing when using Discovery via Tag
    • Traffic groups and virtual addresses on BIG-IP
    • SNAT translations with inherited-traffic-group true in traffic-group-1, used by SNAT pools attached to virtual servers
  • Cloud Provider: Microsoft Azure

Cause

  • Insufficient Azure permissions for managed identity or service principal to access the storage account and modify network interface configurations
  • Missing or incorrect scoping tags on Azure network interfaces preventing CFE from identifying managed resources
  • CFE configuration not updated after infrastructure or virtual address changes
  • A floating SNAT translation address in traffic-group-1 that is also the BIG-IP self IP and the primary IP configuration (ipconfig1) of a NIC. CFE includes traffic-group-1 SNAT translations when it discovers floating addresses. It then generates a disassociate operation that removes the primary IP configuration from the source NIC. Azure rejects the NIC update because the NIC still has multiple IP configurations and none is marked primary. CFE stops at the source NIC update, so no virtual server addresses move and failover fails.

Answer/Recommended Actions

  • Confirm the managed identity or service principal has permissions to:
    • Read and write to the Azure Storage Account containing the CFE state file
    • Modify network interface IP configurations
    • List and update network interface tags
  • Check the CFE log on the BIG-IP (/var/log/restnoded/) for permission-related errors.
  • Look for errors such as:

    AuthorizationPermissionMismatch This request is not authorized to perform this operation using this permission

  • Look for the primary IP configuration error:

    Network Interface <nic-name> specifies multiple IPConfigurations but none of the IPConfigurations is specified as Primary.

  • Follow the configuration steps in Set up access to Azure's Instance Metadata Service.
  • Check whether any traffic-group-1 SNAT translation or virtual address is also the primary IP configuration (ipconfig1) of an Azure NIC, such as a device self IP. Remove that address from the CFE floating set, or remove the SNAT translation from traffic-group-1 or move it out of the floating set. Review any SNAT pool that uses the address and confirm whether it is still needed. Changing the translation to local-only is an option, but assess its impact on the virtual servers that use the pool first. After any change, confirm which traffic group the translation actually belongs to.
  • Perform a dry-run test to preview failover operations without making changes. On the standby device, run the following command:

    curl -su admin: -X POST -d '{"action":"dry-run"}' http://localhost:8100/mgmt/shared/cloud-failover/declare | jq .

    Note: A dry-run only discovers addresses and does not call the Azure NIC update API. Normal dry-run output does not confirm that a real failover will succeed.
  • Review the dry-run output for:
    • toActive: Addresses that will be moved to the new active unit
    • toStandby: Addresses that will be removed from the current active unit
    • operations: Route changes (if configured)
  • Verify the failover discovery process in the CFE log:

    [f5-cloud-failover] Performing Failover - discovery

    [f5-cloud-failover] Getting failover addresses using selfAddresses

  • Validate failover with an actual test in a non-production environment before production deployment. Verify successful failover in the CFE log:

    [f5-cloud-failover] Associate NICs successful.

    [f5-cloud-failover] Addresses reassociated successfully

  • Monitor the CFE logs regularly for operation status and errors.
  • Update the CFE configuration only when Azure infrastructure or BIG-IP virtual addresses change.
  • No special procedures are required for BIG-IP node restarts.
  • Configuration updates need only be posted to one unit, then synced via ConfigSync.

Additional Information

CFE Configuration Updates:

  • Configuration updates are only necessary when changes occur to Azure resources (network interfaces, tags, storage accounts) or BIG-IP virtual addresses.
  • The POST command updates the stored state in the Azure Storage Account to maintain consistency across failover events.
  • Configuration changes synchronize between HA peers through standard BIG-IP ConfigSync mechanisms.

Scoping Tags:

  • The "f5_cloud_failover_label" tag enables CFE to identify which Azure resources to manage during failover.
  • Tags must be consistent between the CFE configuration and Azure resource tags.
  • The "requireScopingTags" parameter in the CFE configuration determines whether tags are mandatory for resource discovery.
  • All network interfaces managed by CFE should have matching scoping tags.

Address Group Definitions:

  • The "scopingAddress" parameter in addressGroupDefinitions identifies which network interface contains the failover addresses.
  • CFE uses this to determine which secondary IPs should be moved during failover events.
  • Multiple address groups can be defined for complex configurations.

Failover Address Set:

  • With Discovery via Tag, CFE matches BIG-IP addresses in traffic-group-1 to Azure secondary IPs. Traffic-group-1 SNAT translations can also be included in this set.
  • Do not include a NIC's primary IP configuration (ipconfig1, such as a self IP) in the floating address set. Azure requires a primary IP configuration on a NIC that has multiple IP configurations.

Expected Behavior:

  • During failover, CFE automatically reassociates secondary IP addresses from the previous active unit's network interface to the new active unit's network interface.
  • The failover process includes discovery, address operations, and route operations (if configured).
  • State information is stored in the Azure Storage Account to maintain consistency.

Azure's New Control Plane:

  • Azure's new control plane is an internal enhancement focused on architectural improvements to the Azure Network Control Plane.
  • Microsoft has an early access program for the new control plane, which enables CFE to fail over in seconds.
  • To gain early access, contact your F5 Account Manager or Sales Engineer for more information.
