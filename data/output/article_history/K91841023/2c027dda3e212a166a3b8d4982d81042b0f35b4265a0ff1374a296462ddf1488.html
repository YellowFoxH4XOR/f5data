Topic

The FIPS 140-3 Compliant Mode license for BIG-IP Virtual Edition (VE) enables BIG-IP VE to run in FIPS 140-3 Level 1 Compliant mode in a virtual machine. Similarly, the FIPS 140-2 Compliant Mode license for BIG-IP VE enables BIG-IP VE to run in FIPS 140-2 Level 1 Compliant mode in a virtual machine.

The following table lists the FIPS licenses that are effective on their respective BIG-IP versions.

FIPS licenseBIG-IP versions
FIPS 140-3 Compliant Mode license*
  • 17.5.x
  • 17.1.0.1
  • 16.1.3.1
FIPS 140-2 Compliant Mode license
  • 15.1.2.1
  • 14.1.2
  • 14.1.0.3
  • 13.1.1
  • 12.1.2 HF1

*You must reactivate the FIPS 140-2 Compliant Mode license to activate FIPS 140-3 Compliant Mode on BIG-IP 16.1.3 and later.

The license is an add-on and works as follows:

  1. You apply the license with the FIPS 140 Compliant mode to your BIG-IP VE.
  2. The system prompts you to reboot the BIG-IP system.
  3. After the system restarts, it puts several daemons on the virtual machine into FIPS 140 Compliant mode.

Note: A restart is no longer required to apply the FIPS 140-2 Compliant Mode license in BIG-IP VE 14.1.2 and later versions of the 14.x branch on cloud platforms.

Description

Note: The section also applies to Platform FIPS. For more information about Platform FIPS, refer to the F5 Platforms: FIPS Administration manual.

When booting in FIPS 140 Compliant mode, the system automatically reorganizes the Secure Sockets Layer (SSL) cipher suites so the FIPS-approved cipher suites appear at the top of the list as the most preferred ciphers.

The following system daemons start in FIPS 140 Compliant mode:

  • big3d
  • bigd
  • chmand
  • devmgmtd
  • fipscheck
  • httpd
  • mcpd
  • named
  • ntpd
  • openssl
  • raccoon
  • sshd
  • tamd
  • tmm

Cipher list the daemons use

When you are in FIPS 140 Compliant mode, the daemons use the following cipher list:

ECDHE-RSA-AES128-GCM-SHA256:ECDHE-RSA-AES256-GCM-SHA384:ECDHE-RSA-AES128-SHA:ECDHE-RSA-AES256-SHA:ECDHE-RSA-AES128-SHA256:ECDHE-RSA-AES256-SHA384:ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-ECDSA-AES128-SHA:ECDHE-ECDSA-AES256-SHA:ECDHE-ECDSA-AES128-SHA256:ECDHE-ECDSA-AES256-SHA384:AES128-GCM-SHA256:AES256-GCM-SHA384:AES128-SHA:AES256-SHA:AES128-SHA256:AES256-SHA256:ECDHE-RSA-DES-CBC3-SHA:ECDHE-ECDSA-DES-CBC3-SHA:DES-CBC3-SHA

Note: You can use the FIPS cipher string to enable FIPS-preferred ciphers in an SSL profile, even if the device is not running in FIPS 140 Compliant mode.

Verifying that you activated FIPS 140 Compliant mode

Use any of the following methods to determine whether you activated FIPS 140 Compliant mode.

First method:

  1. Log in to the Configuration utility.
  2. Navigate to System > License and look for either the FIPS 140-3 Compliant Mode or the FIPS 140-2 Compliant Mode string.

    As long as you applied the license and rebooted the system (if needed) the system is running in FIPS 140 mode.

Second method:

  1. Log in to the Traffic Management Shell (tmsh) by typing the following command:

    tmsh

  2. To see if you activated the FIPS 140 Compliant mode, type the following command:

    list sys db security.fips140.compliance  

    If the resulting value is true, then you activated the FIPS 140 Compliant mode.

Other indicators that you activated the FIPS 140 Compliant mode

  1. Log in to the tmsh utility by typing the following command:

    tmsh

  2. Use the following command syntax:

    list sys <daemon>

    For example:

    list sys httpd

    If you activated FIPS 140 Compliant mode, the previous command has fips-cipher-version set to 1.

    After you restart the system, note the following in the /var/log/ltm file:

    • The daemons log a message indicating that they started in FIPS 140 Compliant mode.

Client SSL and Server SSL profiles

In FIPS 140 Compliant mode, Client SSL and Server SSL profiles continue to use the cipher keyword: DEFAULT.

The BIG-IP system adds two new cipher string keywords, FIPS and @FIPS, as follows:

  • FIPS—This cipher string keyword selects only FIPS-compliant cipher suites.
  • @FIPS—This keyword orders cipher suite preference to use FIPS-compliant cipher suites first.

When you want to use only FIPS-compliant cipher suites, do the following:

  • In advanced configuration mode for the profile, change the cipher string from DEFAULT to FIPS.

When you want to use only FIPS-compliant cipher suites, and you also want the cipher suites sorted from the most to the least recommended, do the following:

  • Use the following cipher string in the profile:

    FIPS:@FIPS

The FIPS cipher string loads the FIPS-approved ciphers, and the @FIPS action keyword reorders the cipher suites to prefer the strongest FIPS-compliant ciphers first.

Notes:

  • You can still change the cipher string in an SSL profile to include non-FIPS-compliant cipher suites. 
    • Doing this allows client applications that lack support for any of the FIPS-compliant cipher suites to negotiate down to a non-FIPS-approved cipher suite.
    • Doing this also invalidates the FIPS compliance of any BIG-IP configuration objects that use the modified SSL profiles.
  • If you want to continue using the DEFAULT cipher suites, you can still use the @FIPS action word to re-order the FIPS-recommended ciphers suites to the front of the list by using the following cipher string in the profile:

    DEFAULT:@FIPS

Important: The DEFAULT:@FIPS cipher string invalidates the FIPS compliance of any BIG-IP configuration objects or profiles that use that string.

To see how the system orders ciphers in each of these modes, run the following command syntax from the command line at any time:

  • clientssl-ciphers <cipher string> <action>

The following are some example commands:

  • clientssl-ciphers DEFAULT:@FIPS
  • clientssl-ciphers FIPS:@FIPS
  • clientssl-ciphers DEFAULT 

Behavior changes while in FIPS mode

The system behaves the same as it does when the FIPS mode license is not applied, except for the following:

  • All daemons start up in FIPS mode.
  • There are some internal improvements to entropy generation to bring it up to NIST standards.
  • Changes in SSL connections.
  • The GUI disallows private key exporting

Changes in SSL connections

In FIPS mode, the system alters the preferred cipher list for system daemons to prefer stronger ciphers over weaker ones, and since these SSL connections are not eligible for hardware acceleration, the system can incur a performance penalty. Pay close attention to system performance after you apply the FIPS mode license.

Disabling FIPS mode

You cannot disable FIPS mode using the Configuration utility or tmsh. The only way to disable FIPS mode is to remove the license. To do so, perform the following procedure:

Impact of procedure: Removing the license reverts the cipher list for SSL profiles to the pre-FIPS configuration.

  1. Log in the Configuration utility.
  2. Navigate to System > License. 
  3. Click Re-Activate and apply a registration key for a license that does not have the FIPS 140 Complaint mode enabled.
  4. Restart the machine.

Recommended action

If you own the BIG-IP VE and need to demonstrate FIPS 140 Compliant mode do the following.

Impact of recommended action: When you switch your BIG-IP VE to FIPS mode for the first time and use the FIPS cipher string, you may incur performance impacts on your system daemons, and Client and Server SSL profiles. After you activate the license, closely monitor your system performance.

  1. Purchase this license and apply it to your BIG-IP system.
  2. Reboot your BIG-IP system to initiate FIPS mode.

    Note: You no longer need to restart your system to apply the FIPS 140-2 Compliant Mode license in BIG-IP VE 14.1.2 and later versions of the 14.x branch on cloud platforms.
