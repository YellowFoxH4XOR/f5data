K000163783: Resolving Missing HTTP Security Headers in BIG-IP Management 403 Responses

Type
Support Solution
Published
2026-10-20
Updated
2026-10-20
Applies to
  • BIG-IP
Source
https://my.f5.com/manage/s/article/K000163783

Description

Qualys may report a missing HTTP security header when scanning BIG-IP management IP addresses.

The finding occurs when a BIG-IP management HTTP 403 response does not include:

X-Content-Type-Options: nosniff

Example response:

HTTP/1.1 403 Forbidden

Access forbidden! Access to the Setup utility is restricted to https://.
Error 403

Qualys describes this finding as a missing security header in an edge-generated HTTP response. This QID does not necessarily map to a CVE.

Environment

  • BIG-IP LTM and BIG-IP DNS/GTM systems.
  • Qualys scanning the BIG-IP management IP addresses.
  • Management HTTP responses generated by the built-in httpd service.
  • HTTP 403 responses generated by the management interface.

Cause

The BIG-IP management httpd service can generate HTTP 403 responses without the X-Content-Type-Options: nosniff response header.

Testing showed that the generated HTTPD configuration used Header append for X-Content-Type-Options. This header was present on some successful HTTPS responses but was absent from the edge-generated HTTP 403 response evaluated by Qualys.

Resolution

An HTTPD include can explicitly remove any existing X-Content-Type-Options header and then add the required header using Header always set.

Important: Test this change on a nonproduction device before applying it to all systems. This configuration is specifically intended to address the scanner finding and is not a standard response-header configuration option in the BIG-IP sys httpd properties.

  1. Review the existing HTTPD include configuration. The sys httpd include property can be specified only once. If an include already exists, add the directives to the existing include instead of creating a second include.
  2. Configure the include:

    tmsh modify sys httpd include '
    Header unset X-Content-Type-Options
    Header always set X-Content-Type-Options "nosniff"
    '

  3. Save the configuration:

    tmsh save sys config

  4. Restart the management HTTP service:

    bigstart restart httpd

    Restarting httpd briefly interrupts access to the Configuration utility.

  5. Verify the exact management URL, port, response status, and headers reported by Qualys. Confirm that the HTTP 403 response contains:

    X-Content-Type-Options: nosniff

  6. Test the following functions after applying the change:
    • Configuration utility access.
    • REST API and iControl communication.
    • High availability behavior.
    • Reboot behavior.
    • Upgrade persistence.
  7. Run a Qualys rescan. The rescan is required to confirm that QID 735183 has cleared.

Validation

The configuration was tested on BIG-IP 17.5.1.6. Testing did not identify issues with:

  • High availability communication.
  • Configuration utility access.
  • REST API or iControl communication.
  • Reboot behavior.
  • Upgrade persistence.

The customer subsequently applied the configuration to all affected BIG-IP GTM and LTM devices. The customer confirmed that Qualys rescans showed the vulnerability as fixed.

Additional Information

  • The Qualys report included a scan of port 80 and evaluated an edge-generated HTTP 403 response.
  • A request to / may return an HTTP 301 redirect, while other management paths may return HTTP 403. Verify the exact path used by Qualys before validating the remediation.
  • Using only the following directive may add the header to the HTTP 403 response:

    Header always set X-Content-Type-Options "nosniff"

    However, this may result in duplicate X-Content-Type-Options headers on HTTPS responses.

  • Using Header unset followed by Header always set avoids the duplicate header observed during testing.
  • A malformed HTTPD include can affect access to the Configuration utility. Review the configuration carefully before restarting httpd.
  • Management interfaces should be restricted to trusted sources using network firewalls and access-control policies. Do not expose BIG-IP management interfaces unnecessarily.
