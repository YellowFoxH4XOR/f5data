Topic

This article explains the different types of image sizes for BIG-IP tenants deployed on rSeries and VELOS systems.

Description

When you download BIG-IP tenant images from the F5 Downloads site, to help you select the correct version and hypervisor type, the tenant image name incorporates fields for software version, software build number, type, and hypervisor extension.

For example:

BIG-IP-<version>.<build>-<type>-<hypervisor>

Tenant image types

There are multiple image types available for download depending on the deployment. The following section provides a description of each tenant image type:

T1

This image type provides support for a tenant provisioned with BIG-IP LTM or BIG-IP DNS only to provide maximum tenant density. Only one software volume or boot location is available. In case you need to upgrade, a new tenant with the relevant version should be deployed.

T2

This image type provides support for a tenant provisioned with BIG-IP LTM or BIG-IP DNS only. This image size supports two software volumes or boot locations and enables you to upgrade to a newer release or point release while providing high tenant density. You can use this image if you do not plan to provision additional software modules, such as BIG-IP AFM, BIG-IP APM, or BIG-IP Advanced WAF.

ALL

This image type provides support for a tenant provisioned with any or all of the following software modules: BIG-IP LTM, BIG-IP DNS, BIG-IP AFM, BIG-IP Advanced WAF, BIG-IP APM, IPS, and IP Intelligence and Geolocation.

This image size supports two software volumes or boot locations and enables you to upgrade to a newer version or point release.

T4

This image type provides support for a tenant provisioned with any or all of the following software modules: BIG-IP LTM, BIG-IP DNS, BIG-IP AFM, BIG-IP Advanced WAF, BIG-IP APM, IPS, and IP Intelligence and Geolocation.

The T4 image has the largest capacity and provides the most disk space for the tenant. By default, this image size supports two software volumes or boot locations and enables you to upgrade to a newer release or point release.

Recommendations

You should select the tenant image type based on your software module requirements and the number of tenants you want to deploy. You can expand the disk size of a tenant at a later date if needed, but you cannot shrink the disk size, so initially choosing the right size is important. This solution provides guidance to the best combinations of vCPU’s modules and tenant image sizes. None of these are enforced limits, and you are free to deploy any image type with any vCPU combination. F5 recommends that you avoid running maximum tenant density with the larger size images as this may lead to oversubscription of disk resources in the future. For example, it is possible to use the T2 image for a 1 vCPU tenant, but doing so utilizes more disk space at maximum tenant density. Tenant images are available for download from the F5 Downloads site.

Additional Information

Identifying the virtual disk size from an image file

You can determine the virtual disk size from a BIG-IP tenant image file with the qemu-img utility installed on your client system. To do so, perform the following procedure on your client system:

Important: The qemu-img utility is a third party software that can runs on Windows or Linux operating systems. F5 does not provide support for this and recommends you verify the security of your download source and installation file.

Note: The following procedure assumes you already have the qemu-img utility installed on your client system, and uploaded the BIG-IP tenant image file to the client.

  1. Unzip the BIG-IP tenant image file by using the following command syntax:

    unzip <filename>.qcow2.zip.bundle

    For example, enter the following command:

    unzip BIGIP-17.1.0.2-0.0.2.ALL-F5OS.qcow2.zip.bundle

  2. Determine the virtual disk size of the BIG-IP tenant image using the following command syntax:

    qemu-img info <filename>.qcow2

    For example, enter the following command:

    qemu-img info BIGIP-17.1.0.2-0.0.2.qcow2

    You may observe an output similar to the following example. The virtual size in this example is 82G.

    image: BIGIP-17.1.0.2-0.0.2.qcow2
    file format: qcow2
    virtual size: 82G (88046829568 bytes)
    disk size: 6.2G
    cluster_size: 65536
    Format specific information:
        compat: 0.10
        refcount bits: 16

Identifying a tenant's virtual disk size on disk

You can determine the virtual disk size of a BIG-IP tenant.

rSeries appliances with F5OS-A

  1. Access F5OS Bash Shell (generally by SSH to the system as root user).
  2. Check the size of virtual disks under /var/F5/system/cbip-disks/<tenant_name> by using the following command:

    ls -lsh /var/F5/system/cbip-disks/*

    You may observe an output similar to the following example.

    /var/F5/system/cbip-disks/bigip1:
    total 5.8G
    5.8G -rw-r--r--. 1 root root 77G Mar  8 09:09 bigip1.raw

    /var/F5/system/cbip-disks/bigip2:
    total 7.0G
    7.0G -rw-r--r--. 1 107 107 142G Mar 19 04:30 bigip2.raw

    /var/F5/system/cbip-disks/bigip3:
    total 6.2G
    6.2G -rw-r--r--. 1 107 107 77G Mar 19 04:30 bigip3.raw

  3. In the example output, the disk sizes of bigip1 is 5.8G, bigip2 is 7.0G, and bigip3 is 6.2G.

VELOS chassis system with F5OS-C

  1. Access F5OS Bash Shell (generally by SSH to the system as root user).
  2. Check the size of virtual disks under /var/F5/partition<partition_number>/cbip-disks/<tenant_name> on cluster blades by using the following command syntax:

    for blade in blade-{1..<number_of_blades>}; do echo $blade; echo =======; ssh $blade ls -lsh /var/F5/partition*/cbip-disks/*; done

    For example, enter the following command on VELOS system with two blades inserted:

    for blade in blade-{1..2}; do echo $blade; echo =======; ssh $blade ls -lsh /var/F5/partition*/cbip-disks/*; done

    You may observe an output similar to the following example:

    blade-1
    =======
    FIPS mode initialized
    /var/F5/partition1/cbip-disks/bigip1:
    total 6.6G
    6.6G -rw-r--r--. 1 107 107 77G Mar 19 01:28 bigip1.raw

    /var/F5/partition1/cbip-disks/bigip2:
    total 7.5G
    7.5G -rw-r--r--. 1 107 107 82G Mar 19 01:28 bigip2.raw

    blade-2
    =======
    FIPS mode initialized
    total 6.3G
    6.3G -rw-r--r--. 1 107 107 82G Mar 19 01:28 bigip3.raw

  3. In the example output, the disk size of bigip1 is 6.6G and bigip2 is 7.5G on blade-1, and bigip3 is 6.3G on blade-2.

Guarantee storage resources to tenant

Note: This is only required for customers who desire to guarantee disk resources, which F5 considers unnecessary in most field deployments.

rSeries appliances with F5OS-A

If you want to guarantee storage resources to their tenants, you may want to make sure that the combined storage values for all tenants, whether running or not, is less than the size of the filesystem mounted at /var/F5/system/cbip-disks.

  1. Access F5OS-A system CLI (generally by SSH to the system as admin user).
  2. Check storage values for all tenants by using the following command syntax. Sum the storage size of all tenants.

    show running-config tenants tenant config storage size

    You may observe an output similar to the following example. The summed value in this case is 361G (142+142+77).

    tenants tenant bigip1
     config storage size 142
    !
    tenants tenant bigip2
     config storage size 142
    !
    tenants tenant bigip3
     config storage size 77
    !

  3. Access F5OS Bash Shell (generally by SSH to the system as root user).
  4. Check the size of the filesystem mounted at /var/F5/system/cbip-disks.

    df -h /var/F5/system/cbip-disks

    You may observe an output similar to the following example. The size of the filesystem in this case is 428G.

    Filesystem                         Size  Used Avail Use% Mounted on
    /dev/mapper/partition_tenant-root  428G   15G  392G   4% /var/F5/system/cbip-disks

  5. The summed tenants' storage size 361G is well below the size of the filesystem mounted at /var/F5/system/cbip-disks 428G, and tenants' storage can grow up to their possible maximum.

VELOS chassis system with F5OS-C

If you want to guarantee storage resources to their tenants, you may want to make sure that the combined storage values for all tenants, whether running or not, is less than the size of the filesystem mounted at /var/F5/partition<partition_number>/cbip-disks on cluster blades.

  1. Access F5OS-C system CLI for a partition (generally by SSH to the system as an admin user).
  2. Check storage values for all tenants in the partition by using the following command syntax. Sum the storage size of all tenants.

    show running-config tenants tenant config storage size

    You may observe an output similar to the following example. The summed value in this case is 159G (77+82).

    tenants tenant bigip1
     config storage size 77
    !
    tenants tenant bigip2
     config storage size 82
    !

  3. Access F5OS Bash Shell for the controller (generally by SSH to the system as a root user).
  4. Check the size of the filesystem mount point, under which /var/F5/partition<partition_number>/cbip-disks resides, by entering the following command:

    for blade in blade-{1..<number_of_blades>}; do echo $blade; echo =======; ssh $blade df -h /var/F5/partition*/cbip-disks; done

    For example, enter the following command on VELOS system with two blades inserted:

    for blade in blade-{1..1}; do echo $blade; echo =======; ssh $blade df -h /var/F5/partition*/cbip-disks; done

    You may observe an output similar to the following example with two blades inserted. The size of the filesystem in this case is 668G.

    blade-1
    =======
    FIPS mode initialized
    Filesystem                 Size  Used Avail Use% Mounted on
    /dev/mapper/velocity-root  668G   37G  598G   6% /var

  5. The summed tenants' storage size 159G is well below the size of the filesystem mounted at /var 668G, and tenants' storage can grow up to their possible maximum.

    Note: Tenants' virtual disk directory cbip-disks exists within /var mount point, and /var will have many other files besides tenants' virtual disks.
