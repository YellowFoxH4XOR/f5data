K000163770: Selecting the Correct BIG-IP LTM Software Image for an rSeries Tenant Upgrade

Type
Support Solution
Published
2026-10-19
Updated
2026-10-19
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000163770

Description

When upgrading BIG-IP LTM deployed as a tenant on an F5 rSeries platform, select the standard BIG-IP software image for the target release. Do not use the F5OS-A host image, a tenant deployment image, a .qcow2 image, a VELOS image, or an image intended for another hardware platform.


Applies To

  • BIG-IP LTM tenants hosted on F5 rSeries platforms
  • BIG-IP 17.5.x software
  • BIG-IP tenant upgrades performed through the tenant's software management interface


Environment Example

  • Deployment: BIG-IP LTM tenant
  • Host platform: F5 rSeries r5800
  • Current version: BIG-IP 17.5.1.6, Build 0.63.25 Engineering Hotfix
  • Target version: BIG-IP 17.5.1.9
  • Upgrade method: Install the BIG-IP ISO on an unused boot volume within the tenant


Cause

Answer to the question or underlying source of the issue: BIG-IP tenant software and the underlying host software use separate packages. Selecting an F5OS host bundle, a tenant deployment image, a virtual machine image, or a package for another platform can result in selecting an image that is not intended to upgrade an existing BIG-IP tenant.


Answer/Recommended Actions

Select the software image

  1. Sign in to the F5 software download portal.
  2. Select the BIG-IP product family.
  3. Select the applicable BIG-IP release branch and target release.
  4. Download the standard BIG-IP ISO intended to upgrade an existing BIG-IP tenant.
  5. Retain the checksum, signature, README, and release-note files supplied with the download.
  6. Confirm that the target release is supported for the tenant deployment.

Do not use the following as the BIG-IP tenant upgrade image:

  • F5OS-A host software bundles
  • rSeries host images
  • VELOS or F5OS-C images
  • .qcow2 or .qcow2.zip.bundle tenant deployment images
  • Images intended for initial tenant deployment
  • Packages intended for another hardware platform
  • Engineering Hotfixes built for a different BIG-IP release

Prepare for the upgrade

  1. Review the target release notes and supported upgrade path.
  2. Confirm software and platform compatibility using the related content listed below.
  3. Create and retain a current UCS backup.
  4. Generate and retain a fresh QKView.
  5. Confirm sufficient tenant storage for an additional boot volume.
  6. Retain the existing working boot volume for rollback.
  7. Confirm that the tenant is operational before beginning the upgrade.
  8. For an HA pair, confirm that the standby tenant is healthy and synchronized.

Install the BIG-IP ISO

Upload the BIG-IP ISO directly to the BIG-IP tenant, not to the host software layer.

  1. Log in to the BIG-IP tenant Configuration utility.
  2. Go to System > Software Management > Image List.
  3. Select Import and upload the standard BIG-IP ISO.
  4. Select the uploaded image and choose Install.
  5. Install the image on an unused boot volume.
  6. Monitor the installation until it completes.
  7. Go to System > Software Management > Boot Locations.
  8. Select and activate the newly installed boot location according to the approved change plan.
  9. Reboot the BIG-IP tenant into the new boot location.
  10. Keep the previous working boot volume until validation is complete.

Upgrade an HA pair

  1. Upgrade the standby tenant first.
  2. Reboot and validate the standby tenant.
  3. Confirm the software version, configuration status, HA state, and operational readiness.
  4. Upgrade the active tenant according to the approved change plan.
  5. Validate synchronization and traffic processing on both tenants.

Validate the upgrade

After reboot, verify:

  • BIG-IP version and build
  • Active boot location
  • Licensing
  • Provisioned modules
  • Management access
  • Configuration loading
  • Network connectivity
  • Virtual server and pool status
  • Traffic processing
  • HA synchronization and device status
  • System logs
  • Application functionality

Engineering Hotfix Considerations

Apply an Engineering Hotfix only when it matches the installed BIG-IP release and has been supplied or approved through the applicable F5 Support process.

Before applying a fix:

  • Confirm that it applies to the installed BIG-IP release.
  • Validate the supplied signature and checksum files.
  • Follow the approved change and testing plan.
  • Retain a rollback option.
  • Test the fix after installation.
  • Use a released software update instead when it already includes the required fix.


Additional Information

  • The BIG-IP tenant image and host software image are separate software components.
  • Upgrading the BIG-IP tenant does not upgrade the host software.
  • The standard BIG-IP ISO and a tenant deployment image are not interchangeable.
  • Compatibility must be verified before selecting the target release.
  • The previous working boot volume should remain available until post-upgrade validation is complete.
