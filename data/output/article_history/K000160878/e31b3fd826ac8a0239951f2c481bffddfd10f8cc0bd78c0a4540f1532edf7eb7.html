Overview

This document defines the various lifecycle stages of the BIG-IP eBPF Observability (EOB) product.

Product release versioning schema

The BIG-IP EOB product release schema consists of the product name followed by a simplified three-digit structure, representing the level of change and the support duration. For example, BIG-IP EOB a.b.c.

Definitions for the BIG-IP EOB version schema are in the following table.

Release typeVersion positionVersionDefinitionExample
Majoraa.x.xRepresents major new feature sets and may involve behavior changes or API changes that are not backwards compatible. Major releases should happen approximately once per year or less frequently. Major releases are for introducing significant new functionality with proper solution testing for long term consumption by all customers. After a new Major release is introduced, no new Minor releases are made available for the prior Major release. No new Maintenance releases are made available for the prior Major release after one year.If the latest BIG-IP EOB release advances from version 2.40.x to 3.0.0, then BIG-IP EOB 2.40.x will continue to receive maintenance releases for 6 months after that transition
Minorba.b.xRepresents changes that introduce new functionality. After a new Major release is introduced, no new Minor releases are made available for the prior Major release.If the latest BIG-IP EOB release advances from version 2.40.x to 3.0.0, no BIG-IP EOB 2.41.x releases will be produced.
Maintenanceca.b.cAddresses bug fixes, security updates, and minor enhancements/hardening that do not introduce significant new functionality. As a general rule, new maintenance releases are made available for only the latest minor release.If the latest BIG-IP EOB release advances from version 2.39.37 to 2.40.0, any subsequent bug or security fixes will be delivered in the 2.40.x release stream. The next such release would be 2.40.1, not 2.39.38.

Customers should upgrade to the current release to receive the latest bug fixes.

Product stages

The BIG-IP EOB products have three stages:

  • Active development: the upcoming major/minor version is considered under "active development." This software may be made available as "early access" or "release candidate" software for limited customers (for example, customers partnering on new functionality), for limited scope (for example, lab-only), or both. The details of the limitations are spelled out in the release notes for that release.
  • Current major release: the most recent major release of the product. Current major releases receive new functionality in the form of minor releases, and security updates and bug fixes in the form of maintenance releases.
  • Last major release: the major release that came immediately before the current release. The previous major release is eligible for maintenance releases that contain critical bug and security fixes for a period of one year after the new major release. No new functionality will be added to the last major release. Any maintenance releases would be based on new critical bugs or CVEs discovered, and the maintenance release would be built on the last minor release.
    • Example: if the last major/minor release was BIG-IP EOB 2.40, then for a period of 6 months after BIG-IP EOB 3.0 was released, any customer running BIG-IP EOB 2.40 could get critical bug and CVE fixes in BIG-IP EOB 2.40.x maintenance releases. Only the latest major/minor release and its immediate predecessor are supported. Versions older than the last major/minor release (e.g., BIG-IP EOB 2.39.x and earlier) are not supported and will not receive any fixes. Customers running unsupported versions are required to upgrade to a supported release to receive maintenance or security updates.

Feature stages

The F5 BIG-IP EOB product features have the following two stages:

  • Early Access Features: features that are being supplied for customer trial and feedback but are not supported for use in production. If these features are used in production, customers with paid support may obtain only technical advice on their use, but no security updates or bug fixes. Features that are "early access" may be either locked out when using production licenses or referenced as "early access" in the user documentation accompanying that release.
  • General Availability Features: features that are fully supported in Production (based on the Product Stage for the product version).
