K000164106: ASM out of memory error: event code P310

Type
Support Solution
Published
2026-11-04
Updated
2026-11-04
Applies to
  • BIG-IP
  • BIG-IP ASM
Source
https://my.f5.com/manage/s/article/K000164106

Description

BIG-IP ASM stops processing additional transactions when the module is provisioned at the Minimum level. At this level, ASM memory is capped at 750 MB and cannot expand with traffic.

Log indicators:

  • emerg perl[26592]: 01310003:0: ASM out of memory error: event code P310
  • ASM operates at its memory limit.

Environment

  • BIG-IP ASM 17.1.3
  • ASM module provisioned at Minimum under System > Resource Provisioning
  • Multiple ASM security policies applied to virtual servers, including policies with learn from responses enabled and learning disabled

Cause

The ASM module was provisioned at Minimum, which limits the module to 750 MB of memory. Memory cannot grow with traffic at this setting, so ASM reached its limit.

Answer/Recommended Actions

  1. Check the current ASM provisioning level under System > Resource Provisioning.
  2. If ASM is set to Minimum, change it to Nominal. This change reloads ASM services, so the unit is briefly offline (about 1–2 minutes).
  3. In an HA pair, reduce disruption by using this sequence:
    1. Temporarily disable Auto Sync between the units.
    2. On the standby unit, change ASM provisioning to Nominal.
    3. After the standby is back online, fail over to it.
    4. On the previously active unit, change ASM provisioning to Nominal.
    5. Re-enable Auto Sync.
  4. After the provisioning change, check the CLI for a "Reboot required" banner. Reboot only if this banner appears.

Additional Information

  • Expected behavior: when provisioned at Nominal or higher, ASM memory usage grows and shrinks with traffic and policy requirements.
