Topic

When limiting sessions per user, the Max Session Per User setting utilizes the value set for the session.logon.last.logonname session variable.

Description

The BIG-IP APM system limits the number of active user sessions based on the value configured for the Max Sessions Per User setting in the access profile. Session limits are enforced on a per-user basis by extracting the value of the session.logon.last.logonname session variable. The value for this variable is commonly set with a simple logon page action in the access policy.

If the access policy is not configured with a logon page, such as when verifying credentials using client certificates (Client Certificate Inspection, On-Demand Cert Auth), Kerberos, SAML SP, etc., the session.logon.last.logonname session variable is not populated. This behavior causes the Max Sessions Per User setting to apply globally, rather than per user. For example, when Max Sessions Per User is set to 2 and no logon page or other access policy agent is configured to populate the session.logon.last.logonname session variable, a maximum of two active user sessions are allowed even when they are established by different users. Attempting to establish a third active user session fails with the following message in the /var/log/apm file:

Session deleted due to admin initiated terminiation

Recommendations

If a logon page or other access policy action does not populate the session.logon.last.logonname session variable, you should consider the following when configuring the Max Sessions Per User setting:

  • Configuring the Max Sessions Per User setting to a default value of 0 allows an unlimited number of active user sessions for users with no global limits.
  • If you want the Max Sessions Per User setting to apply per user, ensure the access policy includes an agent that uniquely identifies the user by the session.logon.last.logonname session variable. How this is configured in your access policy depends on the type of deployment and unique information available to identify users. For example, your deployment may populate the following session variables with user identity information:
    • session.logon.last.username
    • session.saml.last.identity

For example, if the session.logon.last.username session variable is populated, you can create a variable assign action to set the session.logon.last.logonname session variable using an expression similar to the following:

expr { [mcget {session.logon.last.username}] }

For more information about session variables and the variable assign action, refer to the BIG-IP Access Policy Manager: Visual Policy Editor guide.
