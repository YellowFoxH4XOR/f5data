Known Issue

The BIG-IP system does not allow IPv4-mapped IPv6 addresses with a prefix length greater than 32.

This issue occurs when all of the following conditions are met:

  • BIG-IP AFM is licensed and provisioned on the BIG-IP system.
  • You attempt to specify an IPv4-mapped IPv6 address in the configuration using the Configuration utility or TMOS Shell (tmsh).
  • The prefix length of the IP address is greater than 32.

For example, the BIG-IP system does not allow you to configure an IP address in a BIG-IP AFM firewall rule using the following notation:

::ffff:0.0.0.0/96

Impact

You cannot configure BIG-IP AFM firewall rules or other BIG-IP AFM configuration objects with the IPv4-mapped IPv6 addresses.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • When attempting to configure IPv4-mapped IPv6 addresses using the Configuration utility, the system logs an error message that appears similar to the following example:

    Error parsing IP address: ::fff:0.0.0.0/96

  • When attempting to configure IPv4-mapped IPv6 addresses using tmsh, the system logs an error message that appears similar to the following example:

    Syntax Error: "::ffff:0.0.0.0/96" Invalid prefix length

  • Administrators are unable to add IPv4-mapped IPv6 addresses to the BIG-IP AFM configuration.

Workaround

If you want the BIG-IP system to drop the entire block of IPv4-mapped IPv6 IP addresses, you can set the value for the dos.dropv4mapped database variable to true. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the Advanced Shell (bash).
  2. Set the value of the dos.dropv4mapped database variable to true by typing the following command:

    tmsh modify /sys db dos.dropv4mapped value true
