K000163859: BIG-IP HA and ConfigSync fail when TMM allocation leaves insufficient host memory after relicensing

Type
Support Solution
Published
2026-10-23
Updated
2026-10-23
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000163859

Description

A BIG-IP LTM HA pair experienced ConfigSync and HA failures, intermittent web UI inaccessibility, and a disconnected device after a license transition from perpetual to subscription keys. The issue was associated with insufficient host OS memory caused by excessive TMM memory allocation.

Environment 

  • BIG-IP LTM HA pair with ConfigSync enabled
  • BIG-IP version 17.5.1 
  • License transition from perpetual to subscription keys 
  • ASM de-provisioned 
  • 16 GB physical RAM, with more than 13.6 GB allocated to TMM and approximately 2.4 GB remaining for the host OS

Cause

Excessive TMM memory allocation left insufficient physical memory for the host OS, resulting in out-of-memory behavior, HA failure, ConfigSync failure, intermittent web UI inaccessibility, and a disconnected device.

Recommended Actions 

  1. Manually reclaim 4 GB of physical memory from TMM for the host OS. 
  2. Reboot the affected device. 
  3. Perform a controlled failover, then reclaim the memory and reboot the other device.

Additional Information

Insufficient host OS memory can cause incorrect BIG-IP behavior, including intermittent web UI access and failure of HA and ConfigSync functions.
