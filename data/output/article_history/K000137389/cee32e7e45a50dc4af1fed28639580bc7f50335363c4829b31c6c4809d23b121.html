Description

Your system has a remote authentication sever configured, like RADIUS, TACACS+. When the remote authentication server is unavailable or it has no remote user counterpart mapped to local user, all the none-admin or none-root local users cannot log in the device.

You cannot log in BIG-IP using none-admin or none-root local user and you might see below log in /var/log/audit.

Oct 19 22:58:04 localhost.localdomain info httpd(pam_audit)[9533]: 01070417:6: AUDIT - user testapi - RAW: httpd(pam_audit): User=testapi tty=(unknown) host=192.168.211.67 failed to login after 1 attempts (start="Thu Oct 19 22:57:59 2023" end="Thu Oct 19 22:58:04 2023").

Environment

  • BIG-IP v13 and above
  • Remote Authentication

Cause

The Fallback to Local feature is disabled by default.

Recommended Actions

You can enable the Fallback to Local feature by the following steps:
  1. Log in to the Configuration utility.
  2. Go to System > Users > Authentication.
  3. Click on the Change botton in the bottom
  4. Find and enable the Fallback to Local.
  5. Click on Update.

Additional Information

Begining 13.x, the root and admin accounts use local authentication at all times even there is a remote authentication server configured. This feature is controlled by a DB key systemauth.nolocalonly:
If this database key is set to true, the root and admin accounts use remote authentication.
If this database key is set to false (default), the root and admin accounts use local authentication at all times.
