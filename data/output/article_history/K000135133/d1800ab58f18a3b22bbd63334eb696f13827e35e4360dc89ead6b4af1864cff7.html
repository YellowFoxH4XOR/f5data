Description

This guidance is to be used when you have obtained a report from a third party security scanner showing any number of vulnerabilities, and need to validate findings and determine next steps, this article will guide you. 

Security teams often run vulnerability scanners against F5 products (e.g., BIG-IP, F5OS etc) and this may result in a list of CVEs to be addressed by F5 support. Vulnerability scans can return a large number of results when run against F5 products as well, however many of these vulnerabilities will already have been evaluated by F5 and documented in Security Advisories. 

Environment

Cause

You have obtained such a report showing vulnerabilities to mitigate, and you require our assistance.

Note:: please be advised due to the BIG-IP operating as a full-proxy in many cases, when scanning a virtual server, you will most likely be getting results against your backend server and not the BIG-IP itself.

Recommended Actions

As a general rule - if you have a report of a vulnerability on F5's products, you may search for the relevant article with the CVE number; we will document if it affects us or if it can be a problem for your applications, as well as on rare occasions where it needs to be said that an issue does not affect us.  If you show a positive and we show it is fixed, the instructions to mitigate will be present in the article - this can be with a full upgrade, an engineering hotfix and/or update to additional packages (iRules LX, APM client, etc.), or even by simply hardening your device per a given vulnerability's mitigation steps.

A second general rule is that if we show we have a critical vulnerability, then a fix is ready at that time, and you simply need to review the article to obtain that fix.  This is almost always a software upgrade.

We recommend the following actions be performed before reporting the issue to F5 support. 

  1. For shorter reports: search on My F5 to see if there is an existing solution for your issue.  As a general rule - per the above, if we know of it, we will post it in an article, with mitigation steps or other direction to where to get the fix.
  2. For longer reports: Use a qkview to search out any vulnerabilities that immediately affect you.  See K27404821 for steps and further related information.

If you find that you must ask us for further assistance in these circumstances for any reason, we ask that you please follow these guidelines when opening a case with F5:

 

  • Verify all information from external sources as best as you are reasonably able, and format the report for readability if needed; CVEs are generally acceptable as a format.  Please remember that F5 cannot validate the veracity of any third party with 100% certainty.
    • You are not expected to fully research this, but we ask you do your best to verify what you have to get the fastest response possible. 
  • Continue to review F5's documentation as per above, either through a search for CVEs or by uploading a qkview as noted above, to find relevant articles as available
  • For multiple CVEs - Group CVEs by product (APM, LTM, etc.), technology offering (Big IP, Big IQ, NGINX, etc.), and/or function (openssl, MySQL, tomcat, etc.) for the most efficient handling possible
    • Please open one case for a maximum of 5 CVEs as consolidated above to help distribute the work
