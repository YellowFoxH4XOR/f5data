K91946885: [F5OS] Traffic load is distributed unevenly across the data plane CPU cores in VELOS and rSeries system tenants

Description
The BIG-IP system may distribute traffic unevenly between the data plane CPU cores in VELOS and rSeries system tenants.

You may encounter one or more of the following symptoms:

  • You observe performance degradation in the system's traffic processing for the affected virtual server.
  • You analyze the traffic distribution in the system and observe uneven distribution across the data plane cores and TMMs. For more information, refer to K91433389: Analyze and troubleshoot traffic distribution across data plane cores in BIG-IP systems.

This may impact the performance of the traffic processing in the system.

Environment

  • BIG-IP tenant in VELOS or rSeries systems

Cause

This issue can occur when ingress traffic destined for a tenant in VELOS or rSeries systems, originates mostly from even numbered ports. A common example where this may occur is when traffic destined for the BIG-IP tenant originates from a device running Linux kernel version 4.2 or later.

Recommended Actions

You can avoid this issue by using the dag-adjusment VLAN setting if your BIG-IP supports it. Refer to K000133574: What does the 'dag-adjustment' VLAN setting offer? Otherwise perform the following workaround:

To work around this issue, on VELOS systems, r5x00 and r10x00 platforms, you can reconfigure your tenants to use an odd number of data plane CPUs. This means the number of vCPUs you should assign a tenant is 2, 6, 10, 14, 18, or 22. This corresponds to 1, 3, 5, 7, 9 and 11 data plane CPUs.

Note: On VELOS systems and r5x00, r10x00 platforms, the system CPU uses Intel Hyper-Threading Technology. Each HT Technology physical core has a single TMM running. The even-numbered hyper-threads (0, 2, 4, etc.) are dedicated to TMM as a high-priority process to service data plane tasks. The odd-numbered hyper-threads (1, 3, 5, etc.) process control plane tasks at a normal priority level. For more information, refer to K15003: Data and control plane tasks use separate logical cores when the BIG-IP system CPU uses Intel Hyper-Threading Technology

Note: On r2x00 and r4x00 platforms, as they don't support Intel Hyper-Threading Technology, the workaround above cannot be implemented.

To reconfigure your VELOS and rSeries tenant to use odd number of data plane CPUs, perform the following procedure:

Note: In High Availability, HA systems, you must perform the same procedure to reconfigure the BIG-IP peer tenant to use the same number of data plane CPUs as well. When you do so, and the system's DB key statemirror.clustermirroring is set to between, you may encounter ID 1063473 where the system continues to distribute traffic load unevenly. We recommend upgrading to 15.1.5.1 or higher prior to this operation to address the issue, ID 1063473. You need to configure both HA systems to use an odd number of vCPUs. This is because HA cluster mirroring requires both HA systems to have the same number of blades and CPUs.

Impact of procedure: When you shutdown a tenant, it will not be able to process traffic. Other tenants are not affected, and a high availability peer (if configured) can continue to process traffic – however mirroring is not possible during this procedure. F5 recommends performing this during a scheduled maintenance for the affected tenant.

  1. Configure your tenant to the Provisioned state.
    To do so, refer to the Shut down a tenant on the VELOS system procedure in K21121803: Shut down and restart a tenant on the VELOS system

  2. Log in to the partition webUI as the partition administrator for a VELOS system, or the webUI as the admin user for an rSeries system.
  3. Go to TENANT MANAGEMENT > Tenant Deployments.
  4. Select the name of the tenant.
  5. For vCPUs Per Slot, select the appropriate number of vCPUs.

    Note: To assign the tenant an odd number of data plane CPUs, select 2, 6, 10, 14, 18, or 22.

  6. Select Save & Close.
  7. Select OK to confirm the change of state for the tenant.
  8. Configure your tenant back to the Deployed state.
    To do so, refer to the Start up a tenant on the VELOS system procedure in K21121803: Shut down and restart a tenant on the VELOS system.
