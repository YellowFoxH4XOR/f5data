Description

BIG-IP Live Update may fail and generate an error message in /var/log/tomcat/liveupdate.log similar to the following:

curl: (60) SSL certificate problem: unable to get local issuer certificate

A packet capture between the BIG-IP device and the F5 Live Update address, callhome.f5.com, may show that the original callhome.f5.com certificate is replaced during the TLS/SSL handshake by a certificate issued by the organization’s internal CA.

In the packet capture, the client, BIG-IP, may send the following alert and terminate the handshake, resulting in Live Update failure:

TLSv1.2 Alert (Level: Fatal, Description: Unknown CA)

Environment

  • BIG-IP Live Update
  • BIG-IP’s route to the Internet is terminated or intercepted by a TLS/SSL proxy, such as SSL Orchestrator, a firewall with SSL decryption, or a web gateway.

Cause

Live Update uses the command line tool curl to access F5 Live Update services on the Internet. The tool uses the CA bundle located at /config/ssl/ssl.crt/ca-bundle.crt to validate the server certificate.
Note: /etc/pki/tls/certs/ca-bundle.crt is a symlink to /config/ssl/ssl.crt/ca-bundle.crt

When the organization’s internal CA certificate, which signs the replacement certificate presented by the TLS interception proxy instead of the actual F5 Live Update service certificate, is not included in this CA bundle, the TLS/SSL handshake fails.

Answer/Recommended Actions

Use the following procedure to append the organization’s internal CA certificate to the BIG-IP CA bundle:

  1. Log into the BIG-IP command line.
  2. Append a line break to the bundle:
    printf '\n' >> /config/ssl/ssl.crt/ca-bundle.crt
  3. Append your organization's CA certificate using the following syntax:
    cat /<path>/<your CA cert> >> /config/ssl/ssl.crt/ca-bundle.crt
    For example:
    cat /var/tmp/company-root-ca.crt >> /config/ssl/ssl.crt/ca-bundle.crt
  4. curl can immediately read changes to the ca-bundle.crt file to solve the issue; however, you must reload the configuration to load the changes to the bundle into the BIG-IP running configuration. Test the reload first using the following command:
    tmsh load sys config verify
  5. If there are no errors, proceed with loading the configuration.:
    tmsh load sys config
  6. You can verify the certificate is now included in the bundle by going to System > Certificate Management > Traffic Certificate Management > SSL Certificate List > ca-bundle.crt in the GUI.
    If the changes didn't load you may need to execute an mcpd force load. For more information refer to K13030: Forcing the mcpd process to reload the BIG-IP configuration.
  7. Please note that the CA bundle file is managed by the BIG-IP system. This means that after a BIG-IP TMOS upgrade, or after updating the CA bundle using the procedure in K60612439, the organization’s CA certificate will be overwritten. If that happens, you will need to append the organization’s CA certificate again after each update.
