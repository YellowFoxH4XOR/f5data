Description

In BIG-IP High Availability environment, you have set the HA order in the traffic-group. And did the following tests

  1. BigIP01 is active, BigIP02 is standby
  2. On BigIP01, you've enabled 'Always failback to first device if it is available', and moves BigIP02 to the top of the preferred order list
  3. Save changes, then syncs the device group

Expected BigIP02 to become active, but it didn't.

Environment

  • BIG-IP HA environment (BigIP01 and BigIP02)

  • Enabled  'Always failback to first device if it is available' within X seconds

Cause

The reason it does not happen, is because BigIP01 (current active) last become active as a result of user action.

Recommended Actions

Auto-failback is intended to fail back in the scenario where a peer becomes active as a result of a genuine failover event (TMM killed , lose connectivity). So if testing it after enabling auto-failback, you should see it works as expected.

Here's an example for auto-failback functionality:

1. Have preferred active unit currently active (BigIP01)
2. Experience a failover event (e.g. kill TMM, lose connectivity) on the active unit (BigIP01)
3. Peer (BigIP02) will become active
4. After original active (preferred) unit recovers, auto-failback will take over and it will become active again (BigIP01)

Additional Information

To verify auto-failback is working, you should make the preferred active unit active to begin with, then force a failover event (like restarting TMM). In that case, there should be a failback.
Note: testing the auto-failback option might cause traffic impact, hence it recommended to have a maintenance window to perform this activity.
