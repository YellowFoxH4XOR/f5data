K000135274: Discovery process shows "CANCEL_REQUESTED" for long time or you need to stop the process

Description

When the discovery process shows \"CANCEL_REQUESTED\", there's nothing that can done from the GUI to stop it, so you'll need to do the following via the command line on the BIG-IP. Also the \"CANCEL_REQUESTED\" might last for several hours, and you might want to stop the process

 

Environment

  • BIG-IP APM
  • CANCEL_RQUESTED status
  • autodiscover task
  • You have clicked on "Start" again but still showing the old one running

Cause

By design the task is intended to proceed till completed, and the GUI doesn't have any option to stop that process.

 

Recommended Actions

1) Remove this "Cancel Requested"

You must have access to CLI as root or administrator

2) Check the autodiscover task and selflink for the provider that is failing with the following command:

restcurl /tm/access/oidc/discover

You should get an output similar to this one:

\"status\": \"STARTED\",
\"startTime\": \"2021-12-03T12:52:19.623+0100\",
\"userReference\": {
\"link\": \"https://localhost/mgmt/shared/authz/users/admin\"
},

3) Forcing \"CANCEL_REQUESTED\" (replace \"admin\" with its admin password) command:

restcurl -u admin: -X PATCH -d '{\"status\":\"CANCEL_REQUESTED\"}' https://localhost/mgmt/tm/access/oidc/discover/9bd276c7-d83c-4af6-8794-0918686cfb60

***(replace the ID \"9bd276c7-d83c-4af6-8794-0918686cfb60\"used in the example above with the actual ID from command #A1)***

4) Forcing \"CANCELED\". This can only be sent if status is \"CANCEL_REQUESTED\" (most of the times it is not needed as task moves automatically from \"CANCEL_REQUESTED\" to \"CANCELED\", but it's safe to run the command anyway)

restcurl -u admin: -X PATCH -d '{\"status\":\"CANCELED\"}' https://localhost/mgmt/tm/access/oidc/discover/9bd276c7-d83c-4af6-8794-0918686cfb60

***(replace the ID \"9bd276c7-d83c-4af6-8794-0918686cfb60\" used in the example above with the actual ID from command #A1)***

5) Go back to the TMUI and check if the discovery task shows the expected status:

restcurl /tm/access/oidc/discover?\$select=providerName,status\&\$filter=status+eq+CANCEL_REQUESTED

You should see something similar to the output below:

{
\"selfLink\": \"https://localhost/mgmt/tm/access/oidc/discover\",
\"totalItems\": 0,
\"items\": [],
\"generation\": 0,
\"kind\": \"tm:access:oidc:discover:oidcdiscovercollectionstate\",
\"lastUpdateMicros\": 0
}

Additional Information

Note: Optionally, if the issue persists you could add more memory to make RESTJAVA more reliable

It is recommended to test these settings in non-production first. The values used may differ depending on how much memory is available in your environment.

tmsh modify sys db provision.tomcat.extramb value 512
tmsh modify sys db provision.extramb value 2000
tmsh modify sys db restjavad.useextramb value true
*tmsh modify sys db provision.restjavad.extramb value <size in MB>
bigstart restart restjavad && sleep 20 && bigstart restart restnoded

*Only available in more recent software versions. See related content below.
