Description

BIG-IP APM Portal Access rewrites the web content of a back-end application, including its JavaScript, so that the application works through the BIG-IP APM virtual server. Portal Access parses JavaScript as part of rewriting. If parsing fails, the script is not rewritten, and the application may not work as expected. Some browsers tolerate JavaScript that contains syntax errors. Portal Access does not correct these errors, and it may fail to parse or rewrite such code.

Portal Access has two JavaScript rewriting modes, selected per application with the Rewrite Control List (RCL) in the rewrite profile:

  • Legacy (the default): supports JavaScript up to ECMAScript 5 (ES5).

  • Modern: supports newer JavaScript. To configure Modern mode, refer to K000130439: Configuring the Rewrite Control List (RCL) to use Modern JavaScript rewriting for Portal Access.

In Modern mode, Portal Access supports the following JavaScript (ECMAScript) versions:

BIG-IP versionSupported JavaScript versions (Modern mode)
17.1.x, 17.5.xUp to ECMAScript 2016 (ES7)
21.1.xUp to ECMAScript 2022 (ES13)

ECMAScript 2023 (ES14) and later are currently not supported.

JavaScript modules: BIG-IP 17.1.x and 17.5.x have limited support for import and export statements. BIG-IP 21.1.0 and later support import and export statements, dynamic import(), and import.meta.

The following known issues affect JavaScript rewriting in BIG-IP 21.1.x:

  • Portal Access does not parse from and as when they are used outside of import and export statements. Fixed in 21.1.0.2. For more information, refer to Bug ID 2388377.

  • Portal Access does not parse a line separator or paragraph separator character (U+2028, U+2029) inside a string. This is not fixed at the time of publication.

When you troubleshoot this issue, you may observe one or more of the following symptoms:

  • The application, or part of it, does not load or work as expected through Portal Access.

  • The browser developer console shows JavaScript errors when the application is accessed through Portal Access.

  • Requests are not rewritten correctly. For example, they reach the BIG-IP APM virtual server without the Portal Access prefix (/f5-w-<hex>$$), and may fail or be reset.

  • The issue started after the back-end application was upgraded.

  • The BIG-IP rewrite log (/var/log/rewrite*) contains JavaScript parse errors. In Modern mode, the messages include MODERN failed to parse. In Legacy mode, they are similar to the following example (the memory address is replaced with a placeholder):

    error rewrite - fm_patchers/jsParser.cpp:91 (<address>): jsParser::Tokenize(): There was an error: [Oops - failed to parse at line 1, context after error: =>{"use strict";var rt={};functi]

Environment

  • BIG-IP APM 17.1.x, 17.5.x, or 21.1.x

  • Portal Access resource configured

  • The back-end application uses JavaScript syntax that is not supported in the configured mode or BIG-IP version, or that is affected by a Portal Access parser issue

Cause

JavaScript rewriting can fail when the application uses syntax that the rewriting mode (Legacy or Modern) or the BIG-IP version does not support, or when it uses syntax affected by a known Portal Access parser issue. If parsing fails, Portal Access does not rewrite the script.

Answer/Recommended Actions

  1. If the application uses ECMAScript 2015 (ES6) or later, make sure that the application is rewritten in Modern mode. For more information, refer to K000130439.

  2. If the application uses ECMAScript 2017 (ES8) through ECMAScript 2022 (ES13), upgrade to BIG-IP 21.1.x, using its latest maintenance release. BIG-IP 17.1.x and 17.5.x support up to ES7. ECMAScript 2023 (ES14) and later are not supported in any version, including 21.1.x. If the application uses JavaScript modules (import and export), upgrade to BIG-IP 21.1.x. For supported versions, refer to K5903: BIG-IP software support policy.

  3. If you cannot upgrade, or the application uses ECMAScript 2023 (ES14) or later, use a method that does not rewrite the application content: publish the application with Web Access Management (LTM+APM), give users access through a Network Access (VPN) resource, or give users a remote desktop resource from which they open the application. For more information, refer to K14079: Converting an access policy to LTM+APM mode.

  4. Compare the application's behavior when you access it directly and when you access it through Portal Access.

  5. If requests are sent without the Portal Access rewrite prefix, you can use the iRule workaround in K13500329: Correcting a Portal Access rewrite failure for a URL. Open a support case so that the cause of the rewrite failure can be reviewed.

  6. If the issue persists, open a support case and provide the data listed in the Collect HTTPWatch or HAR files for support section of K14184: Troubleshooting BIG-IP APM Portal Access applications.
