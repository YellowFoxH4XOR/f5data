Known Issue

F5 Insight Provisioning and System-Manager keep stale Vault client certificate after rotation causing Vault operations failure.

This issue occurs when all of the following conditions are met:

  • You are running F5 Insight 1.2.2.
  • The F5 Insight deployment has been running for 30 days or more and has rotated Vault client certificate.

This is a known issue documented in the Known Issues section of the F5 Insight 1.2.2 release notes. Provisioning and other operations that require securely stored credentials might fail after an internal authentication certificate expires, even when a replacement certificate has been generated. Affected services continue using the previous certificate until you restart them.

Impact

The following may fail: device provisioning; saving or accessing SMB storage credentials; scheduled backups; and online software downloads.

Symptoms

As a result of this issue, you may encounter one or more of the following symptoms:

  • Provisioning and other operations that require securely stored credentials may fail after an internal authentication certificate expires, even when a replacement certificate has been generated. Affected services may continue using the previous certificate until restarted.
  • The F5 Insight UI may display error messages similar to the following examples:

    device credentials unavailable - cannot check BIG-IP disk space

    Vault is unavailable. Cannot securely store password.

Workaround

To work around this issue, you can restart the provisioning and system-manager pods. To do so, perform the following procedure:

Impact of workaround: Performing the following procedure should not have a negative impact on your system.

  1. Log in to the F5 Insight command line.
  2. Enter the following command to restart the provisioning pod:

    sudo kubectl rollout restart deployment/provisioning -n f5-insight

  3. Enter the following command to view the pod status and confirm the pod restarted:

    sudo kubectl rollout status deployment/provisioning -n f5-insight

  4. Enter the following command to restart the system-manager pod:

    sudo kubectl rollout restart deployment/system-manager -n f5-insight

  5. Enter the following command to view the pod status and confirm the pod restarted:

    sudo kubectl rollout status deployment/system-manager -n f5-insight
