K000164105: BIG-IP LTM Pool Shows Inactive After Upgrade to 17.1.3.7 When HTTPS Monitor "Time Until Up" Is Large

Type
Support Solution
Published
2026-11-04
Updated
2026-11-04
Applies to
  • BIG-IP
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K000164105

Description

One pool shows as Inactive and its members remain DOWN. Logs show "No members available for pool /Common/<pool_name>" and member status down from the attached Monitor object (like, '/Common/https') with the error "No successful responses received before deadline". The health monitor's "Time Until Up" value is already configured with large value like 86500 seconds, so a member must pass the monitor continuously for about 24 hours before the BIG-IP marks it UP. The timer starts only after the first successful probe, so a member that never passes a probe stays DOWN.

Environment

  • BIG-IP LTM
  • After either the System Reboot, Upgrade, or Health check's changes (UP/DOWN)
  • Pool uses the Health Monitor object (like, /Common/https)
  • Monitor setting: Time Until Up = 86500

Cause

There are two possible causes to be considered, as below:

  • The health monitor did not receive successful responses from the pool members before its deadline.
  • The Time Until Up setting explains why members did not return to UP after the probes were failing. It does not explain why the probes failed.

Answer/Recommended Actions

1) Confirm that each pool member responds successfully to the attached health monitor probes on destined port. Check the back-end servers and any network path between the BIG-IP and the members.

2) Review the "Time Until Up" value on the monitor settings. Confirm that the large value is intended.

3) As a test, reduce "Time Until Up" to a smaller value (for example, 5 seconds). Allow time for the change to take effect, then check whether the members change status.

4) If members are still DOWN after the change, capture a packet trace between the BIG-IP and the pool members. Run the capture for at least 2–3 monitor intervals:

Note: You need to replace your desired Pool Members' IP and PORT in below sample command, before running the final revised command.

# tcpdump -s0 -nni 0.0:nnnp "(host <MEMBER-IP-1> or host <MEMBER-IP-2>) and tcp port <MEMBER-PORT>"

5) After any change, confirm that the pool members transition to UP and that the pool is available.

6) Set "Time Until Up" to the value your application requires. A large value keeps members DOWN for a long time after they recover.

Additional Information

  • Expected behavior: With "Time Until Up" set to a large value, a member that has just started passing probes stays DOWN until it has passed continuously for the full period. The timer starts after the first successful probe. See K70501161.
  • Unexpected behavior (the symptom in this Article): Members remain DOWN because the monitor never receives a successful response. In this case, the members were DOWN and a large "Time Until Up" value kept them DOWN after the probes were failing.
