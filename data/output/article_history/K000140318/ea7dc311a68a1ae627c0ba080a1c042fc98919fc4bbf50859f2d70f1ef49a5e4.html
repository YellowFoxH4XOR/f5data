Description

NGINX upstream status settings and what they mean.

 

Environment

NGINX Plus

Load balancing

Passive and active health checks

 

Cause

NGINX Upstream Statuses

 

1. "Up" Status:

Indicates that the server is healthy and able to accept requests.

 

2. "Draining" Status:

Indicates that the upstream server is being phased out and marked for removal in the dashboard. Except for existing persistent connections, no new connections are sent to this server. Session persistence is maintained until the session cookie expires or the server is fully removed, so the draining process may take some time.

 

3. "Down" Status:

Manually controlled by the administrator and remains static until changed. The server is marked as down, meaning it is temporarily unavailable, and NGINX will not send requests to it. Session persistence is immediately disrupted for all sessions, including those with session persistence.

 

4. "Unavail" Status:

Passive check only. Status changes dynamically based on real-time server health checks and traffic responses. The status will be marked as "Unavail" if NGINX fails to receive a response or receives a 5xx error a specified number of times () within a certain time period ().

 

5. "Checking" Status:

Applies if an active health check with the mandatory option is used. Initially, the server is in a “checking” state until the first health check is completed. Client requests are not passed to servers in this state. Without the parameter, the server is initially considered healthy.

The persistent parameter sets the initial “up” state for a server after reload if the server was healthy before reload.

The status "checking" is reset after each reload/restart or adding a new upstream server via the API or DNS resolving.

 

6. "Unhealthy" Status:

Active health check only. For example:

health_check interval=5 fails=3 passes=2 match=100_499_ok mandatory persistent keepalive_time=60s;

 

- fails=3 marks the server as unhealthy if the health check fails 3 times in a 15-second period, blocking traffic to the server.

- passes=2 marks the server as healthy if it passes 2 consecutive health checks in a 10-second period, allowing traffic to the server.

- match=100_499_ok indicates a match block in the configuration defining health check success conditions.

- mandatory setting establishes the checking state for the first health checks, rather than assuming the server is healthy by default.
