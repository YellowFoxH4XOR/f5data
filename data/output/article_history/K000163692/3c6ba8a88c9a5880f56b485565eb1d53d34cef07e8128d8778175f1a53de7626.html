K000163692: Reconnect Drive Mappings when connecting with Edge Client

Type
Support Solution
Published
2026-10-15
Updated
2026-10-15
Applies to
  • BIG-IP
  • BIG-IP APM: 17.1.3
Source
https://my.f5.com/manage/s/article/K000163692

Description

Your employees rely on mapped network drives to access intranet resources at the office. 

However, when working remotely, these drives appear disconnected. Even after establishing a secure VPN tunnel, Windows OS often leaves these network drives in a disconnected state until they are manually accessed or refreshed.

For example, for User 'user1', DC 'ws.lab.lan', Domain 'lab.lan' and Shared resource '\LABData':

C:\Users\user1.LAB>net use
New connections will be remembered.

Status       Local     Remote                    Network
-------------------------------------------------------------------------------
Disconnected Y:        \\ws.lab.lan\LABData      Microsoft Windows Network
Disconnected Z:        \\ws\LABData              Microsoft Windows Network

Environment

  • APM deployed with Network Access
  • Edge Client package installed on a Windows device

Cause

When employees connect to a VPN from home, their network drives do not automatically reconnect by themselves. 

The VPN creates the secure tunnel, but Windows OS does not instantly re-verify or refresh the network drive mappings the moment that tunnel is established.

Recommended Actions

This procedure allows computers to synchronize with Active Directory policies immediately upon connection establishment, executing logon scripts.

You need to enable "Synchronize with Active Directory policies on connection establishment" in your NA resource.

Path: Access ＞＞ Connectivity / VPN ＞＞ Network Access (VPN) ＞＞ Network Access Lists ＞＞ [Select your NA resource] ＞＞ Network Settings tab ＞＞ Reconnect To Domain ＞＞ Check "Synchronize with Active Directory policies on connection establishment".

Since F5 APM triggers legacy domain logon scripts using standard Windows command paths, it cannot directly execute raw PowerShell files. F5 has filed RFE ID756893 to support the execution of PowerShell script through GPO on VPN establishment. 

To bypass this, you need to wrap your PowerShell script inside a Windows batch (.bat) file.

Register the batch file inside the GPO settings (User Configuration >> Policies >> Windows Settings >> Scripts (Logon)) and place both files within the NETLOGON share on your Domain Controller.

For example, for DC 'ws.lab.lan' and Domain 'lab.lan',

\\ws.lab.lan\SYSVOL\lab.lan\Policies\{GUID of GPO}\User\Scripts\Logon

Important: These scripts are neither supported nor maintained by F5. It is a tool that may help you refreshing Drive mappings when VPN is established.  Feel free to modify these scripts at your convenience to adapt them to your environment. 

The PowerShell script reads mapped drives from 'HKCU:\Network', so you need to map network drives with persistence enabled in order for Windows to add them to HKCU:\Network

net use Z: \\ws\LABData /persistent:yes
net use Y: \\ws.lab.lan\LABData /persistent:yes

Add these two files in your location on DC

  • File "RefreshDrives.cmd".
    Replace 'File' with your own location.
@echo off
"%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe" ^
  -NoProfile ^
  -ExecutionPolicy Bypass ^
  -WindowStyle Hidden ^
  -File "\\lab.lan\SysVol\lab.lan\Policies\{BE4B8F8D-9116-4613-ABD7-6F835CBA10D0}\User\Scripts\Logon\RefreshDrives.ps1"

exit /b %ERRORLEVEL%
  • File "RefreshDrives.ps1"
    Replace 'InternalServer' with your Domain controller FQDN.
$InternalServer = 'ws.lab.lan'
$MaxAttempts = 60
$LogFile = Join-Path $env:TEMP 'F5RefreshDrives.log'

function Write-Log([string]$Message) {
    Add-Content -LiteralPath $LogFile -Value (
        '{0} {1}' -f (Get-Date -Format 'yyyy-MM-dd HH:mm:ss'), $Message
    )
}

$Ready = $false
for ($Attempt = 1; $Attempt -le $MaxAttempts; $Attempt++) {
    & "$env:SystemRoot\System32\PING.EXE" -n 1 -w 1000 $InternalServer > $null 2>&1
    if ($LASTEXITCODE -eq 0) {
        $Ready = $true
        break
    }
    Start-Sleep -Seconds 10
}

if (-not $Ready) {
    Write-Log "Internal host did not respond; no mappings changed."
    exit 1
}

if (-not (Test-Path 'HKCU:\Network')) {
    Write-Log 'No saved drive mappings found in HKCU:\Network.'
    exit 0
}

$Mappings = @(
    Get-ChildItem 'HKCU:\Network' | ForEach-Object {
        $RemotePath = (Get-ItemProperty -LiteralPath $_.PSPath `
            -Name RemotePath -ErrorAction SilentlyContinue).RemotePath

        if ($_.PSChildName -match '^[A-Z]$' -and $RemotePath) {
            [pscustomobject]@{
                Drive = "$($_.PSChildName):"
                Path  = $RemotePath
            }
        }
    }
)

foreach ($Mapping in $Mappings) {
    $Drive = $Mapping.Drive
    $RemotePath = $Mapping.Path

    if (Test-Path -LiteralPath "$Drive\") {
        Write-Log "$Drive already accessible; unchanged."
        continue
    }

    if (-not (Test-Path -LiteralPath $RemotePath)) {
        Write-Log "$Drive target unavailable or access denied: $RemotePath; unchanged."
        continue
    }

    & net.exe use $Drive /delete /y > $null 2>&1
    $RemoveResult = $LASTEXITCODE
    if ($RemoveResult -ne 0) {
        Write-Log "$Drive could not be released (exit $RemoveResult); unchanged."
        continue
    }

    & net.exe use $Drive $RemotePath /persistent:yes > $null 2>&1
    $MapResult = $LASTEXITCODE
    if ($MapResult -eq 0) {
        Write-Log "$Drive mapped to $RemotePath."
    } else {
        Write-Log "$Drive mapping failed (exit $MapResult): $RemotePath."
    }
}

Log file 'F5RefreshDrives.log' is created in 'C:\Users\<user>\AppData\Local\Temp'

After the logon script runs, the network drives will be successfully mapped and accessible to the user.

C:\Users\user1.LAB>net use
New connections will be remembered.

Status       Local     Remote                    Network
-------------------------------------------------------------------------------
OK           Y:        \\ws.lab.lan\LABData      Microsoft Windows Network
OK           Z:        \\ws\LABData              Microsoft Windows Network
The command completed successfully.
