Description

 The issue involves the disk space of the BIG-IP DNS system becoming full due to large SNMPD logs that are not rotated. This results in the disk partition having 0% free space and log disk usage exceeding 80% even after log rotation and manual log deletions.

Environment

  1. BIG-IP DNS
  2. Version - 16.x.x, 17.x.x
  3. Disk partition monitoring and management

Cause

The accumulation of large SNMPD logs that are not being properly rotated. This causes the disk space to fill up, leading to potential system performance issues. 

Answer/Recommended Actions

Follow these steps to resolve the issue:

1. Clear Large Log Files

Delete large log files in the /var/log directory using the following command:

rm -f /var/log/restjavad*

2. Check Disk Space

Verify the disk space usage with the command:

df -h

Ensure the disk usage is well below 100%.

3. Modify Log-Rotate Settings

Use the TMSH command to update the log-rotate settings to include the SNMPD log:

tmsh modify sys log-rotate syslog-include "/var/log/snmpd.log {
    compress
    missingok
    notifempty
    postrotate
        killall -HUP snmpd 2>/dev/null || true
    endscript
}
"

4. Save Configuration

Save the updated system configuration:

tmsh save sys config

5. Restart SNMPD Service

Restart the SNMPD service to apply the changes:

tmsh restart sys service snmpd

6. Reboot System (if necessary)

If the issue persists, reboot the system:

  1. Change the GTM sync group name on the affected device to avoid syncing issues.
  2. Document the number of WideIPs, Pools, and Nodes, and compare them post-reboot.
  3. Reboot the system using the command:
  4. reboot

7. Re-add GTM to Sync Group

After the reboot, re-add the GTM to the sync group:

  1. Log in as root to the GTM system.
  2. Run the following commands:

tmsh
run gtm gtm_add

Follow the prompts to complete the GTM addition process.
