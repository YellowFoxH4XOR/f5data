Description

You can use the tcpdump utility to view traffic on BIG-IP Next for Kubernetes. The tcpdump utility is provided with other diagnostic tools within the debug sidecar container. The debug sidecar container is deployed by default with BIG-IP Next for Kubernetes. You can also run the tcpdump utility using the Debug API on the BIG-IP Next for Kubernetes Cluster Wide Controller (CWC). For more information about using the Debug API, refer to Debug API on F5 CloudDocs. Running the tcpdump utility allows you to capture ingress and egress traffic to the Traffic Management Microkernel (TMM).

Note: Running the tcpdump utility on a worker node's physical interface shows L2 traffic but does not show TMM ingress and egress traffic.

The tcpdump utility supports capturing additional internal TMM information by specifying the noise amplitude in the command. For more information about capturing internal TMM information, refer to K13637: Capturing internal TMM information with tcpdump.

Note: To save tcpdump capture files to a filesystem on a node, you must have a Kubernetes PersistentVolume available for binding.

Run the tcpdump utility 

To run the tcpdump utility, you can access the debug sidecar container running in the f5-tmm pod. The debug sidecar shares network namespace with TMM, which allows the tcpdump utility to capture traffic ingressing and egressing the TMM. To access the debug sidecar container, access the cluster and use the following command syntax:

kubectl exec -it <f5-tmm_podname> -n <namespace> -c debug -- bash

For example, if the f5-tmm-6cabc6bb23-j2r6c TMM pod resides in the default namespace, enter the following command:

kubectl exec -it f5-tmm-6cabc6bb23-j2r6c -n default -c debug -- bash

From the debug container, you can list the available interfaces by entering the tcpdump -D command. The following example output shows the available interfaces, including tmm and the internal and external VLANs:

/tcpdump -D
1.xeth0
2.tmm
3.eth0
4.internal
5.external
6.xnet1
7.xnet2
8.any (Pseudo-device that captures on all interfaces)
9.lo [Loopback]

When running the tcpdump utility in the debug container, you can specify the interface or VLAN on which to capture traffic. You can also include filters to restrict the output to specified addresses, ports, and protocols.

For example, to capture traffic on all TMM interfaces, enter the following command:

Important: Running tcpdump on interface 0.0 has the potential to generate very large files. When capturing on interface 0.0, you should use filters to reduce the size of the capture.

tcpdump -ni 0.0

Note: The -n option disables name resolution.

To capture only the internal VLAN, enter the following command:

tcpdump -ni internal 

To specify destination port 8080, enter the following command:

tcpdump dst port 8080

You can combine options and use the -w option to save the output to a file. This example captures traffic on the external VLAN with destination port 8080 and saves the output to the /var/tmp/ directory on the debug container:

Note: This example assumes the /var/tmp/ directory is mapped to a node using a Kubernetes PersistentVolume.

tcpdump -ni external and dst port 8080 -w /var/tmp/external.pcap

For more information about using tcpdump filters to capture traffic, refer to K411: Overview of packet tracing with the tcpdump utility.

Download the tcpdump output file

When using a Kubernetes PersistentVolume, you can download the tcpdump output file from the node using a utility such as scp. The file is located in the Path directory of the PersistentVolume. For information about transferring files, refer to K175: Transferring files to or from an F5 system. To download a file directly from the debug container, you can use the kubectl cp command with following syntax:

kubectl cp -n <namespace> <pod_name>:<path_to_file> -c debug ./<filename>

For example, if the f5-tmm-6cabc6bb23-j2r6c pod is running in the default namespace and the path to the file in the debug container is /var/tmp/external.pcap, then enter the following command:

kubectl cp -n default f5-tmm-6cabc6bb23-j2r6c:/var/tmp/external.pcap -c debug ./external.pcap
