K42238409: AWS HA fails to recover from Active/Active

Type
Support Solution
Published
2021-07-09
Updated
2025-02-06
Applies to
  • Public Cloud
  • BIG-IP
  • Amazon Web Services
Source
https://my.f5.com/manage/s/article/K42238409

Description

  • After recovering from a temporary Active/Active condition the AWS EIP does not get assigned back to Active unit
  • BIG-IPs in HA recover from a temporary Active/Active but traffic does not flow
  • Error messages similar to those shown below appear in /var/log/ltm AFTER the Active/Active condition has resolved:
Jun 29 09:21:15 ip-10-10-10-10 notice logger: /config/failover/tgrefresh : Starting tgrefresh script.
Jun 29 09:21:16 ip-10-10-10-10 err tmsh[21853]: 01420006:3: The string 10.20.30.1010.20.30.1110.20.30.1210.20.30.12 is not a valid ip address.
Jun 29 09:21:16 ip-10-10-10-10 notice logger: /config/failover/tgrefresh : Route lookup command failed, unable to retrieve route list. Error code 1
Jun 29 09:21:16 ip-10-10-10-10 err tmsh[21484]: 01420006:3: The string 10.20.30.2010.20.30.2110.20.30.2210.20.30.22 is not a valid ip address.
Jun 29 09:21:16 ip-10-10-10-10 notice logger: /config/failover/tgrefresh : Route lookup command failed, unable to retrieve route list. Error code 1
Jun 29 09:21:16 ip-10-10-10-10 notice logger: No local routes detected
Jun 29 09:21:16 ip-10-10-10-10 notice logger: /config/failover/tgrefresh : Standby unit does not own any EIPs (Local address is ip: EIP:165.160.15.20203.0.113.33198.51.100.132192.0.2.72 associated with ). No Action required

Environment

  • AWS HA
  • BIG-IP versions prior to v14.1.x
  • HA uses template "f5.aws_advanced_ha.vx.y.z.tmpl"
  • BIG-IPs in HA both went active due to loss of failover network connectivity, but re-established connectivity and returned to Active/Standby

Cause

The script /config/failover/tgrefresh executes when the Active unit recovers from an Active/Active condition. It consumes data provided by the AWS HA iApp. The data is formatted incorrectly by the iApp, resulting in IP addresses being concatenated.

Recommended Actions

  1. Click on iApps>Templates>f5.aws_advanced_ha.v1.x.y
     
  2. In the implementation text box find the text that matches this (there are two sections like this, but only one is missing commas):
    if [ $e = 0 ]
      then
       eip=$(echo "$eip${eip_map}")
       e=1
     elif [ $e = 1 ]
      then
       eip_map=$(echo $eip_map | sed -e "s/\(\/\).*\(\/\)//")
       az1=$(echo "$az1${eip_map}")
       e=2
     elif [ $e = 2 ]
      then
       eip_map=$(echo $eip_map | sed -e "s/\(\/\).*\(\/\)//")
       az2=$(echo "$az2${eip_map}")
       e=0
     else
       break
     fi

    And change it to this (adding commas after each "{eip_map}"):

    if [ $e = 0 ]
      then
       eip=$(echo "$eip${eip_map},")
       e=1
     elif [ $e = 1 ]
      then
       eip_map=$(echo $eip_map | sed -e "s/\(\/\).*\(\/\)//")
       az1=$(echo "$az1${eip_map},")
       e=2
     elif [ $e = 2 ]
      then
       eip_map=$(echo $eip_map | sed -e "s/\(\/\).*\(\/\)//")
       az2=$(echo "$az2${eip_map},")
       e=0
     else
       break
     fi
     
  3. Click Save at the bottom of the screen, then click Update Application at the top right. When you get back to the application screen, click "Finish" at the bottom. This should update the deployment from the corrected template.
