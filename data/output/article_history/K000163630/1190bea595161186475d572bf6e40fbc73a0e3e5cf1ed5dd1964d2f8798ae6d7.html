K000163630: APM Session ACL Blocks Application Access

Type
Support Solution
Published
2026-10-12
Updated
2026-10-12
Applies to
  • BIG-IP
  • BIG-IP APM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000163630

Description

BIG-IP APM-authenticated users cannot access application destinations because an ACL assigned to the APM session rejects the requested traffic.

For Portal Access applications published through a webtop, users might receive:

You do not have permission to access this page.

Access was denied by an access control list.

The browser status bar might display:

my.acl.php3? errorcode=17

Environment

  • BIG-IP APM
  • Portal Access

Cause

The application IP address, virtual server IP address, or another requested destination is rejected by an ACL rule.

For Network Access configurations, this can occur when the ACL assigned by an Advanced Resource Assign action lacks an explicit allow entry for the requested destination, causing the traffic to match the ACL default reject rule.

Answer/Recommended Actions

  • Keep the staging destination explicitly permitted in the ACL assigned to users who require access.
  • Verify that group membership and the resulting APM resource assignment match the user’s required application access.
  • After any group or ACL change, validate the assigned ACL in the APM session details and test both production and staging destinations.
