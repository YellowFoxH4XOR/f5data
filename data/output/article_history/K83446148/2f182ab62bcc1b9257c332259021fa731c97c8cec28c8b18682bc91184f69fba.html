Description

On BIG-IP systems, Default Route, 0.0.0.0/0, learnt via BGP is not advertised with the new 'as-local-count' weight update (under imish) unless bgp is restarted gracefully. The graceful restart of bgp leads to high convergence time depending on size of network that can result into service outage for a variable window.

Environment

  • BIG-IP
  • BGP routing

Cause

Bug ID 760982: An NLRI with a default route information is not propagated on 'clear ip bgp <neighbor router-id> soft out' command in some scenarios

Recommended Actions

  1. Please collect relevant details including packet capture, content of relevant bgp commands and qkview then open a service request with support requesting for EngHF for ID760982, if desired.
