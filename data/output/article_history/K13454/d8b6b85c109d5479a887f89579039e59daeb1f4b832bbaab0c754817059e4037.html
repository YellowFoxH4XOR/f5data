Topic

This article applies to BIG-IP 11.x through 21.x. For information about other versions, refer to the following article:

  • K8537: Configuring SSH host-based authentication on BIG-IP systems (9.x - 10.x)

You should consider using this procedure under any of the following conditions:

  • You want to allow one-way secure shell (SSH) public key authentication from a remote system to the BIG-IP system.
  • You want to allow one-way SSH public key authentication from the BIG-IP system to a remote system.
  • You want to allow bi-directional SSH public key authentication between the BIG-IP system and a remote system.

Description

Public key authentication uses the public key of a specified user on the SSH client system to authenticate that user to the remote server's SSH daemon instead of requiring password input. This provides a non-interactive form of authentication best used in scripts and automated processes, such as application health monitors, cron jobs, automated backups, and file transfers, or in other situations where a user is not present to input authentication information.

For an SSH server to accept public key authentication, the SSH server configuration must allow this authentication method globally. The SSH server must also be pre-configured with information about the remote users who are allowed to authenticate using this method by adding the remote user's public key to the local user's authorized_keys file.

You must inform the SSH client that you want public key authentication whenever possible and let the SSH client know the public host key for the remote system to which the SSH client connects.

Note: In BIG-IP 11.x, due to a known issue, a UCS install or an upgrade to BIG-IP 11.x causes public key authentication to malfunction. For more information, refer to K17318: Host-based SSH authentication may fail after installing a UCS. In BIG-IP 12.x and later, to prevent the previously described known issue, the system creates a symlink for /home/<user>/.ssh/authorized_keys to /etc/ssh/<user>/authorized_keys; however, /etc/ssh/ is not included in a UCS backup, so a subsequent UCS install to a location without the file or a BIG-IP upgrade causes the symlink to point to a nonexistent file. For more information about the workaround, refer to K4422: Viewing and modifying the files that are configured for inclusion in a UCS archive. For more information about this known issue, refer to K22327083: UCS backup files do not include the /etc/ssh/ directory.

Prerequisites

You must meet the following prerequisites to use this procedure:

  • You are familiar with the SSH software used on the remote system.
  • The specified user is configured in the local user directory of your BIG-IP system.

    Note: Since root and admin are always authenticated as local accounts, you can always use public-key authentication for these users.

Procedures

Configure public-key authentication from a remote system to the BIG-IP system

This configuration allows one or more users on a remote system to authenticate to a BIG-IP system without entering a password. You may want to follow this procedure to enable automated systems for monitoring purposes, or to install administrators' keys for convenience.

Note: Key types other than RSA may be supported depending on your BIG-IP version, configuration, and remote system. RSA is always available.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Generate an SSH RSA key pair on the remote system.

    For detailed instructions on generating the key pair on your remote system, refer to the documentation from your vendor. If the remote system is another BIG-IP system, refer to the procedure that follows this one instead. You need the public key in OpenSSH format, which looks similar to the following example. (This example has been shortened for consolidation purposes.)

    ssh-rsa AAAAB3NzaC1yc2EA[...]EBaw== user@host

  2. Acting as the user you want to authenticate with this key, use SSH to switch to the BIG-IP system.
  3. Make sure you have an .ssh directory in your home directory by entering the following command:

    mkdir ~/.ssh

  4. Edit the authorized_keys file using a text editor of your choice, for example, nano or vi.

    For example, if using nano, enter the following command:

    nano ~/.ssh/authorized_keys

  5. Add the public key to the end of the authorized_keys file.
  6. Save your changes and exit the text editor.
  7. Configure your remote system to prefer public-key authentication.

Configure public-key authentication from the BIG-IP system to a remote system

This configuration allows a user account on the BIG-IP system to authenticate to a remote system over SSH without requiring a password. You may want to follow this procedure to, for example, enable custom cron jobs to connect to remote systems.

The remote system must be configured to accept public-key authentication.

Note: You can perform this procedure only for users with Administrator access to the BIG-IP system.

Important: All users with Administrator access to the BIG-IP system can access other users' SSH keys. Consider security implications before you implement the following procedure.

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. While logged in as the user whom you want to run SSH, generate an SSH RSA key pair on the BIG-IP system by entering the following command:

    ssh-keygen

    Note: When logged in to the BIG-IP system with Administrator access, running the ssh-keygen command defaults to generating a key pair in .ssh/id_rsa and .ssh/id_rsa.pub in the root user's home directory. Specify the user's home directory as needed.

    Note: The ssh-keygen command defaults to a 2048 bit key.  If you would like to use a larger 4096 bit key, run the command ssh-keygen -b 4096.  A 4096 bit key may display additional CPU usage if large number of SSH connections are initiated on the BIG-IP host.

  2. Use cat to print the new public key by entering the following command:

    cat ~/.ssh/id_rsa.pub

  3. Install this public key on the remote system as an authorized key for the user whom you wish to authenticate. One option for performing this step in most cases is to use the ssh-copy-id command on the BIG-IP. Use the following syntax:

    Note: The command below creates the .ssh directory and authorized_keys file on the remote system for the user if it does not already exist.

    ssh-copy-id <user account on remote system>@<remote system IP address>

    For example:

    ssh-copy-id user1@192.0.2.121

  4. To allow bi-directional SSH public key authentication between the BIG-IP system and a remote system, refer to the previous procedure. If the remote system is another BIG-IP system, repeat this procedure on that BIG-IP.

    The BIG-IP system is configured to attempt public-key authentication by default.
