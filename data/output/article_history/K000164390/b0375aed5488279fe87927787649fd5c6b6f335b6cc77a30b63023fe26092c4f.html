K000164390: Higher CPU usage each hour when ASM Provisioned - OWASP Compliance Score

Type
Knowledge
Published
2026-11-27
Updated
2026-11-27
Applies to
  • BIG-IP
  • BIG-IP ASM
Source
https://my.f5.com/manage/s/article/K000164390

Description

When ASM is provisioned, the OWASP Compliance score task runs once an hour inside the restjavad process. Each run logs the following message:

OWASP Compliance Score generation task next iteration scheduled to run in 60 minutes from now.

This message is a status entry. It schedules the next run. When no policies have changed, the run logs OWASP score generation: No policies found updated from previous schedule of score generation. and recalculates nothing.

When security policies have changed since the previous run, the task recalculates the OWASP score for each changed policy. This can cause a temporary increase in CPU usage during that run. The increase is larger when many policies changed at once.

 

Environment

  • BIG-IP ASM or Advanced WAF provisioned
  • Security policies configured, with more policies or larger configurations increasing the work per run

Cause

The hourly OWASP score generation task runs in restjavad. When policy changes exist, it recalculates scores for the changed policies, which consumes CPU for the duration of the run.

 

Recommended Actions

 None. It's expected behavior.

 

Additional Information

  • Some high CPU is caused by the OWASP Compliance page itself. Each page load triggers score calculation, so avoid leaving the page open or refreshing it repeatedly.
  • For high CPU on the highest-numbered CPU core when ASM is provisioned, which is a separate and expected behavior, see K48061132: High CPU Utilization on the Last (Highest-Numbered) CPU logical core.
