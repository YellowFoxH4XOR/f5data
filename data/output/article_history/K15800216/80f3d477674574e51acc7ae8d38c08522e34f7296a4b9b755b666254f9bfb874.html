Topic

The f5-tcp-progressive profile is based on the parent TCP profile, but contains settings that allow throughput higher than or equal to the TCP profile.

Description

The f5-tcp-progressive profile is for early adopters because it utilizes new TCP profile features each time they're introduced in a BIG-IP release and is for general use across all network types.

You can use the f5-tcp-progressive profile to specify how a BIG-IP virtual server processes TCP traffic. To manage traffic, you can use the f5-tcp-progressive profile alone, or in conjunction with other profiles. For example, you can use the HTTP profile to process Layer 7 (L7) traffic, or use the SSL profile to process SSL traffic.

Modified options in the f5-tcp-progressive profile

The f5-tcp-progressive profile contains the following modifications to the default TCP profile as of BIG-IP 17.1.x:

Note: The default values for some settings in the default TCP profile may change between versions. These changes are inherited by the f5-tcp-progressive profile. For information about the default TCP profile settings, refer to K50411377: Overview of the TCP profile (16.x and later), K74767112: Overview of the TCP profile (15.x), K29377715: Overview of the TCP profile (14.x) or K10711911: Overview of the TCP profile (13.x).

Auto Proxy BufferEnabledSpecifies, when enabled, that the system uses the network measurements to set the optimal proxy buffer size.
Auto Receive WindowEnabledSpecifies, when enabled, that the system uses the network measurements to set the optimal receive window size.

Initial Receive Window Size16 MSS unitsSpecifies the initial receive window size for connections to this destination. Actual window size is this value multiplied by the MSS (Maximum Segment Size) for the same connection. Valid values range from 0 to 64.
Nagle's AlgorithmAutoSpecifies that the system will determine whether to use Nagle's algorithm (Detailed in RFC 896) based on network conditions. The Nagle Algorithm is a TCP optimization that makes the stack wait until all data is acknowledged on a connection before sending more data. This process, called nagling, increases the efficiency of a network application system by decreasing the number of packets that must be sent.
Proxy Buffer High262144 bytesSpecifies the proxy buffer level, in bytes, at which the receive window is closed.

Note: Increasing the buffer size will result in more memory usage per connection. For more information, refer to K3422: Overview of content spooling.

Proxy Buffer Low196608 bytesSpecifies the proxy buffer level (in bytes) at which the receive window is opened.

Note: Increasing the buffer size will result in more memory usage per connection. For more information, refer to K3422: Overview of content spooling.

PUSH FlagAutoSpecifies how the BIG-IP system receives ACKs. By default, the BIG-IP system receives a TCP acknowledgement (ACK) whenever the system sends a segment with the PUSH (PSH) bit set in the Code bits field of the TCP header. This frequent receipt of ACKs can affect BIG-IP system performance. To mitigate this issue, configure PUSH Flag to control the number of ACKs that the system receives as a result of setting the PSH bit in a TCP header. Auto: Sets the PSH flag in these cases:
  • When the receiver’s Receive Window size is close to 0.
  • Once per round-trip time (RTT), that is, the length of time that the BIG-IP system sends a signal and receives an ACK.
  • When the BIG-IP system receives the event HUDCTL_RESPONSE_D

Note: Increasing the Receive Window size allows the BIG-IP system to receive more data each time, but also increase memory usage for each connection.

Send Buffer262144 bytesSpecifies the size (in bytes) of the send window.

Note: Increasing the Send Buffer size allows the BIG-IP system to output more data each time, but also increase memory usage for each connection.

Recommendations

When configuring the f5-tcp-progressive profile, you should consider that using the f5-tcp-progressive profile may result in slightly higher CPU utilization when compared to the parent TCP profile. As a result, you should monitor the system CPU utilization for a time after you associate the f5-tcp-progressive profile with a virtual server.

F5 recommends that, instead of modifying a default profile, you create a custom profile using the default profile as the parent profile. You can then modify some or all of the values defined in the custom profile, while leaving the parent profile settings at their default value. For information, refer to K14488: Working with profiles.

You can create a custom f5-tcp-progressive profile in the BIG-IP Configuration utility by going to Local Traffic > Profiles > Protocol > TCP. Once on that page select Create and then choose f5-tcp-progressive for the Parent Profile. Apply it to your virtual server when complete.
