K000164063: How long does Source IP Stickiness last?

Published

Description

You want to know how long Source IP Stickiness (persistence/affinity) keeps a client connected to the same origin server, and whether it has a timeout.

Environment

  • F5 Distributed Cloud (XC) HTTP Load Balancer or TCP Load Balancer
  • Load balancing algorithm: Source IP Stickiness
  • Origin pool algorithm: Load Balancer Override

Cause

Source IP Stickiness does not have a timeout. It uses a hash of the client's source IP address to select an origin server. It does not store a session record that expires after a set period. As a result, the same client IP is sent to the same origin server for as long as the origin pool stays unchanged.

Answer/Recommended Actions

A client keeps reaching the same origin server as long as all of the following remain true:

  • The origin pool members do not change.
  • The origin pool members stay in the same configured order.
  • The origin pool members remain consistently healthy under the health check.

If any of these change, a client may be sent to a different origin server. Inactivity alone does not end the mapping.

Additional Information

  • Do not confuse Source IP Stickiness with timeout settings. The HTTP idle timeout controls how long an idle connection stays open. It does not control how long a client stays mapped to an origin server. For details on the timeout types, see K000146636: What is the difference between client-side and server-side timeouts?
