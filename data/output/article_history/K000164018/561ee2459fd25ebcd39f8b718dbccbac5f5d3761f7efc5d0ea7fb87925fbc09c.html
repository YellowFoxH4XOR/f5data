K000164018: F5 SSL Orchestrator O365 URL Updater Fails When a Custom CA Certificate Object Is Selected as Trusted Certificate Authority

Type
Support Solution
Published
2026-10-27
Updated
2026-10-27
Applies to
  • BIG-IP
  • BIG-IP SSL Orchestrator: 21.1.0
Source
https://my.f5.com/manage/s/article/K000164018

Description

The Office 365 URL Updater in F5 SSL Orchestrator fails when a custom CA certificate object is selected under Trusted Certificate Authority. The O365 URLs/IP Address update and save configuration operations report failure on one or more devices. The default and ca-bundle.crt options complete successfully.

Error messages from the O365 update log:

Save/update on device <device-name> failed with message: Attempt ("+ str(count) +") to request O365 information failed (1005): "+ str(e.reason))

AttributeError: 'FileNotFoundError' object has no attribute 'reason'

The restnoded log shows the underlying failure in url_fetch:

context = ssl.create_default_context(purpose=ssl.Purpose.SERVER_AUTH, cafile=self.cafile)

FileNotFoundError: [Errno 2] No such file or directory

The error handler then raises AttributeError because FileNotFoundError has no reason attribute, which hides the original error.

Environment

  • F5 SSL Orchestrator, version 21.1.0
  • Multi-device configuration (both devices show the same failure)
  • O365 URL Updater configured with a custom CA certificate object as the Trusted Certificate Authority
  • Working option: the system-provided ca-bundle.crt certificate, or the default option
  • Certificate properties compared with tmsh list sys file ssl-cert <name> all-properties:
    Certificatesystem-pathis-bundle
    ca-bundle.crt (system)/config/ssl/ssl.crt/ca-bundle.crttrue
    Custom CA certificate objectnonefalse

Cause

Bug ID Bug ID 2693685. The O365 URL Updater script (sslo_o365_update.py) determines the location of the trusted CA file from the certificate's system-path attribute. This attribute is populated only for system-generated certificates. For a custom CA certificate object, the attribute is none, so the script attempts to load a file that does not exist.

Answer/Recommended Actions

  • Until the fix is available, select a system-provided certificate (ca-bundle.crt or the default option) as the Trusted Certificate Authority for the O365 URL Updater.
  • Track Bug ID 2693685 for the fix. The fix is planned for a future general release. No EHF is currently documented.

Additional Information

  • Engineering has confirmed that custom CA certificate objects are intended to be supported for this feature. The current behavior is a defect, not expected behavior.
  • The product documentation for the Office 365 URL Updater does not explicitly state whether custom CA certificate objects are supported.
