Security Advisory Description

If BIND encounters a particular invalid data structure in a DNS record, it will accept the invalid data, and may subsequently abort and exit. BIND will first need to store a DNS record for a key (KEY, DNSKEY, etc.). That key must specify a PRIVATEDNS algorithm (253), and in the algorithm identifier, improperly give a length longer than the actual identifier data. The invalid identifier will be stored. If BIND later needs to render that record to text, it will use the invalid length during processing, leading to a consistency check failing. This issue affects BIND 9 versions 9.18.0 through 9.18.50, 9.20.0 through 9.20.24, 9.21.0 through 9.21.23, 9.18.11-S1 through 9.18.50-S1, and 9.20.9-S1 through 9.20.24-S1. (CVE-2026-10822)

Impact

This vulnerability allows a denial-of-service (DoS) when BIND processes a DNS KEY/DNSKEY record specifying a PRIVATEDNS algorithm (253) where the algorithm identifier length field is larger than the actual identifier data. BIND accepts and stores the invalid record without validation. When BIND later attempts to render that record to text, it uses the incorrect length, causing an internal consistency check to fail and the named process to abort. When the BIG-IP DNS is configured as a recursive resolver with BIND enabled and DNS cache enabled, an attacker controlling or spoofing an authoritative zone can serve a malformed PRIVATEDNS algorithm-253 DNSKEY record, causing the named process to crash and resulting in a DoS.

Mitigation

To mitigate this issue, you can disable BIND, disable DNS caching, or disable recursion.

  • Disable the Use BIND Server on BIG-IP option in the DNS profile
  • Disable DNS caching in the DNS profile
  • ⁠Restrict DNS recursion on the BIG-IP DNS system

Disable the Use BIND Server on BIG-IP option in the DNS profile

Important: Disabling the BIND server can affect DNS configurations that use BIND as a fallback method (return to DNS) for resolution.

  1. Log in to the Configuration utility.
  2. Go to one of the following locations:
    • Local Traffic > Profiles > Services > DNS.
    • DNS > Delivery > Profiles > DNS.
  3. Select the applicable DNS profile.
  4. For Use BIND Server on BIG-IP, select Disabled.
  5. Select Update.

Disable DNS caching in the DNS profile

Impact of procedure: Caching allows the BIG-IP system to answer repeated queries from memory. With caching disabled, every query must be sent to external nameservers, local DNS server pools, or processed by the local BIND instance, introducing network and processing latency. Additionally, clearing the DNS cache will require the cache to be rebuilt if the cache is re-enabled, resulting in a temporary rise in resolution latency. F5 recommends that you evaluate changes in your test environment prior to making changes to the production environment.

  1. Log in to the Configuration utility.
  2. Go to one of the following locations:
    • Local Traffic > Profiles > Services > DNS.
    • DNS > Delivery > Profiles > DNS.
  3. Select the applicable DNS profile.
  4. In the DNS Features section, locate DNS Cache and select Disabled from the list.
  5. Select Update.
  6. Go to DNS > Caches > Statistics.
  7. Select the check box next to the cache you want to clear.
  8. Select Clear Cache.
