K000163765: BIG-IP Configuration load fails after upgrade because of a missing EPSEC filestore

Type
Support Solution
Published
2026-10-19
Updated
2026-10-19
Applies to
  • BIG-IP
  • F5 Distributed Cloud Services
  • BIG-IP LTM: 21.1.0
Source
https://my.f5.com/manage/s/article/K000163765

Description

After upgrading BIG-IP LTM to version 17.5.x or 21.1.x, the configuration validation or loading may fail with an error similar to:

01070712:3: Failed: name (/Common/epsec-1.0.0-892.0.iso)
Cache path (/config/filestore/files_d/Common_d/epsec_package_d/
:Common:epsec-1.0.0-892.0.iso_64633_1) does not exist and there is no copy in trash-bin to restore from.
Unexpected Error: Validating configuration process failed.

Note: The issue can happen when APM is licensed, even if APM is NOT provisioned.

Environment

  • BIG-IP LTM
  • Known Versions: 17.5.x, 21.1.1.x
  • APM licenced

Cause

ID2277529

During configuration validation, BIG-IP attempts to access or restore the referenced file in bigip.conf. If the file is not present in the filestore or trash-bin, configuration validation fails.

APM does not need to be currently provisioned for this condition to occur.

Answer/Recommended Actions

  1. Access the command line and back up the configuration:
    cp /config/bigip.conf /config/bigip.conf.bak
  2. Confirm that APM is NOT provisioned and review the EPSEC objects in the bigip.conf file:
    grep -n -A6 -B1 epsec /config/bigip.conf
  3. Comment out the obsolete EPSEC package block for epsec .iso from the configuration.
    Important: Do not remove unrelated APM objects.

    Example:
    #apm epsec epsec-package /Common/epsec-1.0.0-892.0.iso{
    # cache-path /config/filestore/files_d/Common_d/epsec_package_d/:epsec-1.0.0-892.0.iso_64633_1
    # oesis-version 4.3.5302.0
    # revision 1
    # version 1.0.0-892.0
    #}
  4. Validate and reload the configurations:
    tmsh load sys config verify
    tmsh load sys config
    tmsh save sys config
