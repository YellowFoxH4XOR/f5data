Description

It is common that you will need to collect data and/or test configuration changes and would like to do so in the least intrusive way possible.

Environment

  • BIG-IP APM
  • Virtual Server

Cause

When collecting data, you may need to apply an iRule to decrypt traffic or enable debug logging. There can be several reasons why these changes cannot be done on a production Virtual Servers

Recommended Actions
Create second Virtual Server to handle test traffic

A. Created a copy of the current Access Policy

  1. Login to the WebUI
  2. Navigate to:
    Access  ››  Profiles / Policies : Access Profiles (Per-Session Policies)
  3. Locate the Access Policy you would like to copy
    Click Copy... from the Copy column
  4. Name the new Access Policy 
  5. Click Copy

B. Considerations when making changes to the copy of the Access Policy

  • When changing policy objects, consider the effect a change may have on the evaluation of the policy.
    Example: 
    If you are using AD AAA and have session.ad.$name.attr.$attr_name to set session variables, these will need to be changed to session.ldap.$name.attr.$attr_name accordingly.        
  • If collecting debug logging, a new logging profile will need to be created and applied to the Access Policy.

C. Create a second Virtual Server that only listens for the Client IP or Lease Pool IP address/subnet of the source IP

For example, if this is your current production virtual server, all traffic will be sent to this VS

Production Virtual ServerIP Addresses
Source IP Address0.0.0.0/0
Destination IP Address192.168.1.1

You would create a new Virtual Server with all the same settings and profiles

Test Virtual ServerIP Addresses
Source IP Address10.10.10.0/24
Destination IP Address192.168.1.1

** By the order of precedence, the more specific Source IP address will allow you to test from a specific IP address or Source Subnet. (See K14800)
** If you are testing a virtual server that is accessed over a VPN tunnel, ensure you have the VPN tunnel added to the VLAN and Tunnel Traffic in the new test virtual server 

D. Associate a pool to the new test virtual server. (LTM+APM Use case only)

If you are using a LTM+APM virtual server, associate a pool to the new test virtual server.                                                                                                                           

E. Apply the copy of the Access Policy to the new Test Virtual Server

Additional Information

No need to update DNS, no need to update firewall rules.                                                                                                                                                                   

F. Additional Information step:

The above procedure is not suitable to environment running proxies and/or Source Address translation for ingress connections.
