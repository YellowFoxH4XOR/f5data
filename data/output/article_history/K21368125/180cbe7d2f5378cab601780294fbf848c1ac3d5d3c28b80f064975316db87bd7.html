K21368125: Websites that use CNAME DNS records fail through SSLO

Type
Support Solution
Published
2019-12-26
Updated
2025-02-06
Applies to
  • BIG-IP
  • BIG-IP APM: 13.1.X, 13.1.4, 13.1.3, 13.1.1, 13.1.5, 13.1.0
Source
https://my.f5.com/manage/s/article/K21368125

Description

Websites that have CNAME DNS records are failing through SSLO (SSL Orchestrator) configuration with the BIND Server as an internal DNS server.

  • You want to browse the Internet through SSLO
  • The browser will throw the error "ERR_TUNNEL_CONNECTION_FAILED".
     

Environment

  • SSL Orchestrator
  • BIND DNS Server
  • CNAME DNS Records
     

Cause

The SSLO DNS object is sending a query with case sensitive characters to the DNS server but the bind service on the DNS server is not treating it as case sensitive.

Recommended Actions

Disable "Randomize Query Character Case" option in the DNS Resolver of SSLO

  1.  Login to the BIG-IP Configuration Utility
  2.  Navigate to Network > DNS Resolver
  3.  Click on the DNS Resolver name created by the SSLo
    Example: sslo_proxy-net-resolver
  4.  Uncheck "Randomize Query Character Case"
  5.  Click Update
     

Additional Information

None.
