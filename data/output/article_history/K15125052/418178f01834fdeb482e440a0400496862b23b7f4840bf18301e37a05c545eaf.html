Description

UCS backup files are huge, and most of the space is used in two directories:

/var/ts/dms/policy/policy_versions
/var/tmp/filestore_temp/files_d/Common_d/epsec_package_d/

Environment

  • UCS backup
  • ASM and/or APM provisioned

Cause

Accumulation of Security Policy history and OPSWAT EPSEC files.

Recommended Actions

Files in these directories can be cleaned up to reduce the overall size of generated UCS backup files.

/var/ts/dms/policy/policy_versions

The policy_versions directory is used to store historical versions of ASM security policies in binary format. Those would be found under Security > Application Security : Policy : History (exact GUI location varies depending on version). From that page you can restore the historical versions if you wish to do so.

These history files are included in a UCS file, and a new history file is saved each time a policy is applied. So they can get quite large over time.

Fortunately, it is completely safe to delete these files. You just have to bear in mind that the historical versions won't be available any more for restoration. However, you can back up these files off box if needed, and they can be imported later if necessary as a binary policy import.

There is a subdirectory structure which uses the policy ID associated with each policy, which is an internal ASM reference.

To see the id for each policy, a mysql query can be used:

mysql -t -u root -p$(perl -MPassCrypt -nle 'print PassCrypt::decrypt_password($_)' /var/db/mysqlpw) -e 'select id,name from PLC.PL_POLICIES';

In BIG-IP versions 13.1.3 and above, housekeeping of these files can be configured so they don't get too large.

There is a configuration file under /etc/ts/tools/policy_history.cfg that can be used to control the maximum size of all the history files, along with a minimum number kept.

[CleanPolicyHistory]
# maxSizeOfSavedVersions=100000000  <------ Note this is commented out by default, which doesn't impose a size limit
minRetainedFilesInDir=2

Beginning in BIG-IP versions 16.1.0 and 17.0.0, you can maintain the housekeeping configurations by modifying or creating ASM system parameters policy_history_min_retained_versions and policy_history_max_total_size from Configuration utilities (GUI) > Security > Options > Application Security > Advanced Configuration > System Variables.

Restart ASM after the changes:

tmsh restart sys service asm

Note: This is traffic impacting.

/var/tmp/filestore_temp/files_d/Common_d/epsec_package_d/

Unused OPSWAT EPSEC files can be deleted using the procedure described here:

  • K21175584: Removing unnecessary OPSWAT EPSEC packages from the BIG-IP APM system

Note: In some cases, the EPSEC files are not deleted from the filestore even after you delete them from the configuration. In that case it is usually safe to delete them manually from the filestore afterwards, or alternatively move them to a larger partition like /shared. Take care to ensure there are no configuration references to the file before you delete or move it. If you are not sure, leave the file in place.

Additional Information

UCS file size can vary significantly between systems, depending on the size of the configuration and provisioned modules.
