K000163730: Repeated TLS Connection Failures on NGINX Ingress Controller when connecting to

Applies to

Description

NGINX Ingress Controller leader pod logs repeated TLS connection failures:

grpc: addrConn.createTransport failed to connect ServerName: "oss.edge.df.f5 .com:443"
transport: authentication handshake failed:
tls: failed to verify certificate: x509: certificate signed by unknown authority

The failure occurs when connecting to the product telemetry endpoint on port 443.

Environment

  • NGINX Ingress Controller 
  • Kubernetes deployment.
  • Product telemetry enabled.
  • Product telemetry endpoint: Telemetry_1.example.com:443.
  • NGINX error logging available for monitoring licensing and usage-reporting activity.

Cause

  • The telemetry connection cannot validate the server certificate because the certificate authority is not trusted by the NGINX Ingress Controller environment.
  • Telemetry reporting and subscription usage reporting use separate services. A telemetry TLS failure does not by itself confirm that subscription usage reporting has failed or caused missing information in the licensing portal.

Recommended Actions

  1. Verify DNS resolution and network connectivity to the required telemetry and licensing endpoints.
  2. If telemetry is required, verify that the container trust store includes the certificate authority needed to validate the certificate presented by the telemetry endpoint.
  3. Configure NGINX error logging at the info level and monitor the logs for usage-reporting messages and license-expiry countdown information.
  4. Do not use the licensing portal’s Products section to verify telemetry delivery. Telemetry data is not displayed there.
  5. If telemetry is not required, disable it during Helm installation:
    controller.telemetryReporting.enable=false
  6. Alternatively, disable telemetry reporting in the controller deployment:
    -enable-telemetry-reporting=false
  7. Review the NGINX subscription licensing documentation and allow all licensing-related FQDNs required by the deployment. Allowing only the telemetry endpoint may not provide the connectivity required for subscription licensing and usage reporting.
  8. Monitor the NGINX error log for usage-reporting failures so that licensing connectivity issues can be detected before subscription validation is affected.

Additional Information

  • Product telemetry is enabled by default with NGINX Ingress Controller.
  • Product telemetry is optional and does not affect normal Ingress Controller operation.
  • Product telemetry is sent over HTTPS to a dedicated telemetry service.
  • Subscription checks and usage reporting use separate licensing endpoints.
  • Successful telemetry delivery does not confirm that subscription usage reports were sent.
  • Usage-reporting verification requires the NGINX error log to be configured at an appropriate level.
  • Refer to the NGINX Ingress Controller product telemetry documentation and telemetry command-line documentation for configuration details.
  • Refer to the NGINX subscription licensing documentation for the complete list of licensing-related FQDNs.
