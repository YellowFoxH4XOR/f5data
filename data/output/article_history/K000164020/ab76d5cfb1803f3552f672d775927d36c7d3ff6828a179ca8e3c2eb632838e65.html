Description

BIG-IP sends "X-Cnection: close" header to clients

 

Environment

- LTM

- HTTP/S virtual server with oneconnect and http profile with "OneConnect Transformations" enabled

- Pool member sends HTTP/1.1 response with "Connection: close"

 

Cause

Expected behavior of OneConnect transformations. Not a defect.

 

Answer/Recommended Actions

The behavior is by design.

BIG-IP converts "Connection: close" to "X-Cnection: close" in both directions when "OneConnect Transformations" is enabled. This is intended to keep OneConnect load balancing working across requests.
