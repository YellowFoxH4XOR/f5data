K000164325: UCS Load Fails on BIG-IP VE 17.5.1 with "Symmetric Unit Key decrypt failure"

Type
Support Solution
Published
2026-11-20
Updated
2026-11-26
Applies to
  • BIG-IP
  • BIG-IP LTM: 17.5.1
Source
https://my.f5.com/manage/s/article/K000164325

Description

When migrating from a physical BIG-IP to a BIG-IP VE using a UCS file, the load fails with the message "Symmetric Unit Key decrypt failure - decrypt failure." This message is misleading and masks the actual configuration validation errors. See K36822000: Misleading "Symmetric Unit Key decrypt failure" error while loading UCS.

The true cause is found in the mcpd validation errors. Configuration validation stops the load, and the following errors appear in the LTM log:

01071837:3: The pool (...) contains a reference to a gateway failsafe device (...), which does not exist on the system.

01070330:3: Static route gateway (...) is not directly connected via an interface.

01071a95:3: Admin IP gateway for management route /Common/IMC is not in a connected network.

01420006:3: Validating configuration process failed.

Bug ID 1043141 can prevent these real errors from appearing during configuration reload, so only the decrypt message is shown.

Additional messages seen in the logs, which are not blocking, include:

Master key OpenSSL error: ... PEM routines:PEM_read_bio:no start line ... Expecting: CERTIFICATE

Error processing MCP messages: Local connection to MCPD failed: MCP error 0x1020048: 01020048:7: Connect to mcp daemon failed

Environment

  • Product: BIG-IP LTM VE, version 17.5.1
  • Migration from a physical BIG-IP to a BIG-IP VE
  • Load command: tmsh load sys ucs <ucs_file> no-license platform-migrate keep-current-management-ip
  • The UCS was collected from the physical source device and edited to remove gateway failsafe objects.
  • The source configuration references:
    • Gateway failsafe devices that do not exist on the VE
    • A static route gateway not directly connected to any interface on the VE
    • A management route gateway (/Common/IMC) not in a connected network on the VE

Cause

The UCS references gateway failsafe devices, a static route gateway, and a management route gateway that are not valid on the new VE. These validation errors block the load.

Bug ID 1043141 hides the real validation errors during configuration reload, so only the "Symmetric Unit Key decrypt failure" message is shown.

Answer/Recommended Actions

  1. Review the LTM log immediately after the failed load and filter for mcpd errors: grep "err mcpd" /var/log/ltm
  2. Correct every reported validation error in the UCS or on the VE:
    • Remove or update gateway failsafe pool members and references that point to devices not present on the VE.
    • Correct static routes so the gateway is directly connected via an interface on the VE.
    • Correct the management route (/Common/IMC) so its gateway is in a connected network.
  3. Confirm connectivity to each gateway from the VE (for example, with ping) before loading the configuration. Self-IPs must be in the same network as the gateway.
  4. Reload the corrected UCS and check the LTM log again for remaining err mcpd entries.
  5. After the load, verify that gateway failsafe pool members are monitored as expected. If a gateway is unreachable, the device may report "FailsafeFault" and fail over, so check that the production interfaces are enabled and the gateway can be reached.
  6. For HA configurations, ensure the peer management IPs are allowed in the httpd configuration (for example, add them to "allow httpd") on each unit.

Additional Information

  • The "Symmetric Unit Key decrypt failure" message in this scenario is misleading. Review the mcpd errors in the LTM log for the actual cause.
  • Expected behavior: a UCS load with invalid gateway, route, or failsafe references is rejected during validation, and the LTM log reports the specific errors.
  • Unexpected behavior: the decrypt message appears without any mcpd validation errors in the log, which may indicate the issue described in Bug ID 1043141.
