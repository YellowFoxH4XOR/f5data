Security Advisory Description

Session serializer mismatch can lead to remote code execution. Session upload progress, when enabled, can store attacker-controlled data in a session key using the php_binary or php_serialize session serializer. If the same session is later read with the php serializer, because session.serialize_handler is changed at runtime or differs between applications sharing a session store, bytes inside the key can be passed to the unserializer. A remote attacker able to submit a multipart upload can inject objects, which may lead to code execution when the reading application contains a suitable gadget chain, or to session corruption or denial of service. This issue affects PHP versions 8.2.* before 8.2.36, 8.3.* before 8.3.37, 8.4.* before 8.4.28 and 8.5.* before 8.5.13. (CVE-2026-115560)

Impact

There is no impact; F5 products are not affected by this vulnerability.

Security Advisory Status

F5 Product Development has evaluated the currently supported releases for potential vulnerability, and no F5 products were found to be vulnerable.

BIG-IP contains the affected code. However, F5 identifies the vulnerability status as Not vulnerable because the attacker cannot exploit the code in default, standard, or recommended configurations.

Note: F5 evaluates only software versions that have not yet reached the End of Technical Support (EoTS) phase of their lifecycle. For more information, refer to the Security hotfixes section of K4602: Overview of the F5 security vulnerability response policy.

Security Advisory Recommended Actions

None

BIG-IP mitigation

All BIG-IP modules are not vulnerable to this issue. A mitigation was provided when F5 was still researching on the issue. The mitigation is not required on your BIG-IP system.

Protection for your backend pool members

The following will mitigate the exposure of backend applications running on your pool members.

If you are using BIG-IP Advanced WAF, BIG-IP ASM, F5 WAF for NGINX, F5 WAF for Distributed Cloud (https://www.f5cloudstatus.com/incidents/r7t009rtmd3k) or NGINX App Protect WAF to protect your backend pool members, you can mitigate this vulnerability for your backend pool members by using the following attack signatures enabled in blocking mode:

  • CVE-2026-115560: PHP Remote Code Execution, ID 200204113
    • 200204113 - ASM/Adv WAF Attack Signature Sets: WebSphere signatures, Server Side Code Injection Signatures, Low and Medium Accuracy Signatures, All Signatures

The updated attack signature is part of the newly released attack signature update ASM-AttackSignatures_20261029_152921.im; you must perform a signature file update to ASM-AttackSignatures_20261029_152921.im or later for these signatures to be available on your system.

For information about updating attack signatures on the BIG-IP system, refer to K82512024: Managing BIG-IP ASM Live Updates. For information about assigning attack signatures to security policies on the BIG-IP system, refer to the Assigning Attack Signatures to Security Policies chapter of the BIG-IP Application Security Manager: Attack and Bot Signatures guide.

For information about updating attack signatures on the NGINX system, refer to the Update F5 WAF for NGINX signatures chapter of the F5 WAF for NGINX guide.

For information about updating attack signatures on the F5 Distributed Cloud instance, refer to Best Practices for Signature Staging guide for F5 WAF for Distributed Cloud.
