Security Advisory Description

Statement from www.php.net:
We suggest you set session.upload_progress.enabled=0 until the next regular bugfix release, to fully protect from an unlikely RCE vector. This setting was already listed as a mitigation in the GHSA-6wmf-4rv5-p3rp advisory for CVE-2026-109619 published on Oct 21st, 2026. If you applied it then, keep it in place and no further action is needed.
The issue can only occur under an unusual combination of configuration and application code. An application must set session.serialize_handler to php_binary or php_serialize in its configuration and then switch it to php at runtime with ini_set() before calling session_start(). Session upload progress must also still be enabled. Applications that never change the serialize handler at runtime can keep the feature enabled. Since this setup is unlikely in practice, we are handling it in the regular release cycle and will publish a full advisory for CVE-2026-115560 with the next release. (CVE-2026-115560)

Mitigation

BIG-IP mitigation

The following mitigates BIG-IP control plane configuration utility exposure as well as BIG-IP APM data plane exposure. If you applied the mitigation from K000163821: PHP vulnerabilities CVE-2026-109618 and CVE-2026-109619, then session.upload_progress.enabled = 0 is already configured and you don't need to perform the following mitigation.

At a high level, the admin needs to login on BIG-IP with advanced shell, create a new file with the content below, and restart apache.

Important: F5 recommends that you verify the following php.ini configuration in your testing/staging environment before deploying to your production environment.

Note: If you have a multi bladed system these steps must be done on each individual blade.

  1. Create a new file - /etc/php.ini.d/K000163878.ini and include the content below.

    ; The configuration mitigations recommended by PHP for CVE-2026-115560
    ; These will NOT survive an upgrade of BIG-IP TMOS.
    session.upload_progress.enabled = 0

  2. Restart apache using bigstart restart httpd.

    On multi-bladed systems, restart apache using clsh bigstart restart httpd.

  3. Only for BIG-IP APM systems, restart apache using bigstart restart httpd_sam.

    On multi-bladed BIG-IP APM restart apache using clsh bigstart restart httpd_sam.

    Note: Restarting the httpd_sam process may disrupt webtop connections, requiring users to reconnect.

  4. If you have configured a device group, repeat on each high availability (HA) peer in the group.
