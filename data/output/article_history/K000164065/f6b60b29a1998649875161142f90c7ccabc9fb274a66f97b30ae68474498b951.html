K000164065: Customer Edge Site with 1 Control Node and 2 Worker Nodes Is Not a Supported HA Production Topology

Type

Published
2026-10-30
Updated
2026-10-30
Source

Description

A Customer Edge (CE) site has one Control node and two Worker nodes. You want to know whether this layout is supported for High Availability (HA) production use.

Environment

  • F5 Distributed Cloud (XC) Customer Edge Secure Mesh Site v2
  • Multi-node site with 1 Control node and 2 Worker nodes

Cause

The site was created without the node HA choice, so the first node to register became the only Control node. The other two nodes joined as Worker nodes. Worker nodes are only supported to augment an existing three-node control plane. They cannot replace the missing Control nodes, so the site has no control-plane redundancy.

Answer/Recommended Actions

A layout of 1 Control node + 2 Worker nodes is not a supported High Availability (HA) production topology. F5 Distributed Cloud documentation states that Worker nodes are only supported to augment an existing three-node control plane.

Worker nodes do not add control-plane resilience. Because of this layout, you may see the following problems:

  • Configuration stops for the whole site. etcd and vpm run only on the single Control node. Memory or CPU pressure on that node can stop configuration ingestion for the entire site.
  • No failover. With three Control nodes, the peers maintain quorum and the configuration stream fails over. With one Control node, no peer can take over.
  • Worker nodes run headless during a Control node outage. They can keep forwarding traffic for a period, but if a container restarts, experiences memory pressure, or fails a liveness probe, it cannot recover without the control plane. This can cause route withdrawal and service disruption.
  • The site must be rebuilt to fix the layout. The HA option cannot be changed after the site object exists. Moving to three Control nodes requires recreating the site.
