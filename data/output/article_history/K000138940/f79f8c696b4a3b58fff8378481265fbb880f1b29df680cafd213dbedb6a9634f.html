K000138940: TCL "SSL::disable serverside" errors in LTM log

Type
Support Solution
Published
2024-03-18
Updated
2024-03-22
Applies to
  • BIG-IP
  • BIG-IP LTM: 15.1.8
Source
https://my.f5.com/manage/s/article/K000138940

Description

LTM log entry with the following error:

TCL error: /<Virtual Server> <HTTP_REQUEST>Unknown error (line *) (line *) invoked from within "SSL::disable serverside"


Environment

Platforms using iRules


Cause

Invoking SSL::disable within an HTTP_REQUEST block when a server side connection already exists.


Recommended Actions

If no server side encryption is being performed (e.g. ssl offload on the virtual server) remove SSL::disable as it is not needed.


In the case where server side traffic needs to switch between encrypted and non-encrypted traffic then either the client side connection needs to be in a detached state (e.g. oneconnect, LB::detach) as documented in:

https://clouddocs.f5.com/api/irules/SSL__disable.html

or the iRule modified to use SSL::disable within the block of SERVER_CONNECTED and toggled via a flag set within HTTP_REQUEST where SSL::disable was previously located (or the appropriate iRule logic for the specific application).


Additional Information

Using SSL::disable within the block of HTTP_REQUEST triggers the attempt to set an initial server side connection parameter with every http request, even if a server side connection already exists.

In the case where the server side connection already exists (e.g. SERVER_CONNECTED) it is not possible to switch ssl on/off.

The error is generated when a new http request is being sent while a server side connection exists.
