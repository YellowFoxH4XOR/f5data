K000163581: Edge Client 7.2.7+ aborts the TLS handshake when it is asked to perform client certificate authentication but finds no client certificate

Type
Support Solution
Published
2026-10-07
Updated
2026-10-07
Applies to
  • BIG-IP
  • BIG-IP APM: 21.1.0, 17.5.1
Source
https://my.f5.com/manage/s/article/K000163581

Description

Edge Client 7.2.7+ aborts the TLS handshake when it is asked to perform client certificate authentication but finds no client certificate. The correct behavior should be to send an empty Certificate message to the APM virtual server (the APM virtual server should decide what to do with the empty certificate message).

During this problem, on the Edge Client GUI, an error pop-up window might be observed with a message like:

SSL certificate verification failed.
SSL connect error
Error Code: 35

Under client-side logs (%temp%\logterminal.txt), the following kind of errors will be observed:

2026-10-05, 7:52:52:751, 10640,10088,APPCTRL, 48, \AppTunnelEx.cpp, 5551, CAppTunnelEx::InternalLoadConfiguration, Loading configuration. URL: "https://vpn.example.com/pre/config.php?version=2.0"
2026-10-05, 7:52:52:751, 10640,10088,APPCTRL, 48, \URLConnect.cpp, 371, URLConnect::Connect, Request to Connect
2026-10-05, 7:52:52:813, 10640,10088,APPCTRL, 2, \SSLClientCertHelper.cpp, 1002, SSLClientCertHelper::select_client_cert_impl, No suitable client certificate found in store

Environment

• BIG-IP APM installed with APM client 7.2.7 or later.

• BIG-IP APM virtual server configured with a client SSL profile requesting a client certificate (request or require).

• The client did not have an available client certificate for the requested TLS client authentication.

Cause

The root cause is a defect tracked via ID2564701.

Answer/Recommended Actions

• Install a valid client certificate and its private key on affected clients, if client-certificate authentication is required.

Additional Information

The TLS flow will look like:

Client sends Client Hello to the server
The server responds with Server Hello, Certificate, Server Key Exchange, Certificate Request, Server Hello Done
Client aborts the TLS connection by sending an Alert (Level: Fatal, Description: Internal Error)

The correct behavior should be that the client sends an empty Certificate message to the server (instead of aborting the TLS connection).
