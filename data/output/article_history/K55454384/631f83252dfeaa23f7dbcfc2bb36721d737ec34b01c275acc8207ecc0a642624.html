K55454384: Hosted Content accessed through Portal Access fails with error, ''No available SNAT addr''

Source

Description

This solution will explain the cause of this error and where and how to determine if you are affected by this issue.

  • Accessing Hosted Content through Portal Access fails.
  • In a browser you may see a "Page cannot be displayed" message.
  • You seeing the following error in /var/log/apm:

<apm_hostname> debug tmm1[20450]: 019cffff:7: /Common/Test_AP:Common:00000000: New connection 172.18.5.173 58916 10.154.165.79 443 on tmm 0 1
<apm_hostname> debug tmm1[20450]: 019cffff:7: /Common/Test_AP:Common:50f514a6: Request (GET /f5-w-687474703a2f2f72656e64657265722e61706d3a38303830$$/public/share/BIGIPEdgeClient.exe HTTP/1.1 User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/103.0.0.0 Safari/537.36 Content-Length: )
<apm_hostname> debug tmm1[20450]: 019cffff:7: /Common/Test_AP:Common:50f514a6: Client-type (none)
<apm_hostname> debug tmm1[20450]: 019cffff:7: /Common/Test_AP:Common:50f514a6: RD: [C] 172.18.5.173.58916 i 10.154.165.79.443: server-side connection was reset, reason: No available SNAT addr


Note: This log message will only observed if the Virtual Server has a VDI profile configured. If not you can also observe this error in /var/log/ltm or a packet capture by enabling TCP Reset Logging:

K13223: Configuring the BIG-IP system to log TCP RST packets
