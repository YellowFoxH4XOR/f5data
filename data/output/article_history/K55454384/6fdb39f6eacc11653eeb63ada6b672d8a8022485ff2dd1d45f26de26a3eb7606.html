K55454384: Hosted content accessed through Portal Access fails with the error "No available SNAT addr"

Type
Support Solution
Published
2022-08-26
Updated
2026-11-02
Applies to
  • BIG-IP
  • BIG-IP APM
Source
https://my.f5.com/manage/s/article/K55454384

Description

You access hosted content through a BIG-IP APM Portal Access resource, and the content does not load. The browser may show a "Page cannot be displayed" message.

When you troubleshoot this issue, you may observe the following symptoms:

  • The BIG-IP system resets the server-side connection with the reset cause No available SNAT addr.

  • The /var/log/apm file contains a message similar to the following example (the addresses, ports, and IDs vary):

    debug tmm1[<pid>]: 019cffff:7: /Common/<access_profile>:Common:<session_id>: RD: [C] <client_address>.<port> i <virtual_server_address>.443: server-side connection was reset, reason: No available SNAT addr

    Note: This message is logged only if the virtual server has a VDI profile. If it does not, you can see the reset cause in the /var/log/ltm file after you enable TCP reset logging, or in a packet capture. For more information, refer to K13223: Configuring the BIG-IP system to log TCP RST packets.

Environment

  • BIG-IP APM 17.1.x earlier than 17.1.3.1, or 17.5.x earlier than 17.5.1.8

  • Portal Access resource that publishes hosted content

  • IPv6 enabled on the BIG-IP system (the default)

Cause

When IPv6 is enabled, Portal Access gets hosted content from the BIG-IP system over the IPv6 loopback address (::1). Connections from this address are reset with No available SNAT addr, so the hosted content cannot be accessed. This issue is tracked as Bug ID 1136905.

Answer/Recommended Actions

Upgrade to a release that includes the fix: 17.1.3.1, 17.5.1.8, 21.0.0, or later. If you need an engineering hotfix, refer to K4918: Overview of the F5 critical issue hotfix policy.

Workaround

If you cannot upgrade, and the BIG-IP system does not need IPv6, you can disable IPv6.

Impact of workaround: The BIG-IP system no longer sends or responds to IPv6 traffic. Do not use this workaround if any virtual server, self IP address, pool member, or other configuration object on the system uses IPv6. F5 recommends performing this procedure during a scheduled maintenance window.

  1. Log in to the TMOS Shell (tmsh) by entering the following command:

    tmsh

  2. To check the current value, enter the following command:

    list /sys db ipv6.enabled

  3. To disable IPv6, enter the following command:

    modify /sys db ipv6.enabled value false

  4. To save the configuration, enter the following command:

    save /sys config

  5. Start a new access session, and verify that the hosted content loads.

To back out of the workaround, enter the following command, and save the configuration:

modify /sys db ipv6.enabled value true

For more information, refer to K15056: Disabling IPv6 on a BIG-IP system.
