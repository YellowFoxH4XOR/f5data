K000162979: Portal Access returns an unexpected HTTP response (such as HTTP 400) when query parameters contain & or =

Type
Support Solution
Published
2026-08-19
Updated
2026-11-02
Applies to
  • BIG-IP
  • BIG-IP APM: 17.5.0, 21.0.X, 21.0.0, 17.5.1, 21.X.X, 21.1.X, 21.1.0
Source
https://my.f5.com/manage/s/article/K000162979

Description

A web application accessed through BIG-IP APM Portal Access returns an unexpected HTTP response, for example HTTP/1.1 400 Bad Request, when a link contains query parameters with the & or = character. The application works as expected when you access it directly, without BIG-IP APM.

When you compare the requests, you may observe that Portal Access sends the characters to the back-end server as HTML entities:

  • = becomes &#x3D;

  • & becomes &amp;

For example:

Direct accessThrough Portal Access
/f?p=xxx/f?p&#x3D;xxx
&filedownload=X&amp;filedownload=X

Environment

  • BIG-IP APM 17.1.3.x, 17.5.x, or 21.1.x

  • Portal Access resource and rewrite profile

  • Web application with links whose query parameters contain & or =

Cause

This issue is tracked as Bug ID 2137909: Portal Access: unwanted decoding html entities in attribute values of HTML tags. The issue was introduced by the fix for Bug ID 926917, which was first included in BIG-IP 17.1.3 and 17.5.1.

The issue affects both Legacy and Modern rewriting (K000130439: Configuring the Rewrite Control List (RCL) to use Modern JavaScript rewriting for Portal Access).

Answer/Recommended Actions

Upgrade

As of October 2026, the fix is not yet released in a 17.x or 21.1.x maintenance release. Check Bug ID 2137909 for the releases that include the fix, and upgrade to one of them when it is available.

Workaround: iRule

You can apply an iRule to the Portal Access virtual server that replaces &amp; with a literal & only for the affected requests. The iRule uses the string replacement method described in K16533717: iRule to replace a string in the HTTP URI.

Important: A global replacement can modify unrelated requests and cause unexpected application behavior. Restrict the condition to the affected Portal Access download path.

Impact of procedure: F5 recommends performing this procedure during a scheduled maintenance window.

Add the following iRule to the Portal Access virtual server. Replace <The path of the query string> with the path of the affected requests:

when HTTP_REQUEST {
    if {
        ([HTTP::path] starts_with {/<The path of the query string>}) &&
        ([HTTP::uri] contains "&amp;")
    } {
        HTTP::uri [string map {"&amp;" "&"} [HTTP::uri]]
    }
}

Note: This iRule example replaces only &amp;. It does not change &#x3D; back to =.

If the workaround does not resolve the issue for your application, open a support case and reference Bug ID 2137909. Provide the data listed in the Collect HTTPWatch or HAR files for support section of K14184: Troubleshooting BIG-IP APM Portal Access applications.
