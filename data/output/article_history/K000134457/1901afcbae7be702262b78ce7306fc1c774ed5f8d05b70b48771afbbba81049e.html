Topic

The VELOS system chassis controller services perform a variety of functions, such as configuring and controlling switch chips, managing partitions and tenants, and performing high availability (HA) failover actions between system controllers. For a list of the VELOS partition services running at the partition and blade level, refer to K000134684: Overview of F5 VELOS partition services.

Description

The following tables list a description for the various VELOS system services at the system controller level, and the impact to the VELOS system operation if each service is not running.

Service NameDescriptionImpact if not running
alert-serviceThe alert-service runs on both system controllers as well as each blade installed in the VELOS system. The installed blades and the standby system controller forward all their alert messages to the alert service on the active system controller. The alert service on the active system controller aggregates all alerts and publishes them to ConfD.

Container image name: alert_service

No alerts occur.
authentication-mgrThe authentication service manages the configuration settings for Authentication, Authorization and Accounting (AAA) at both the chassis and partition levels. F5OS uses standard Linux PAM modules for local and remote authentication.

Container image name: authentication-mgr

No authentication configuration changes can occur.
cc-lacpdThe LACP daemon used for the backplane (management ports) LACP link aggregations between the system controllers and the installed blades. This service works with the cc-switchd service to prevent network loops between the system controllers and installed blades.

Container image name: cc_lacpd

Communication failure between the installed blades and controllers.
cc-switchdThe switchd service manages the control plane (also known as overlay) and data plane (also known as datapath) switches on the system controllers. Each controller runs an instance of the switchd service and configures the switches for the local controller only.

The switchd service also configures the VLANs for the overlay network, provides redundancy and aggregation for all overlay network links as well as configures overlay and datapath switches to provide isolation between partitions.

The logs are captured in the /var/log_controller/switchd file.

To enable/disable debug logging, enter config mode and commit the following changes:

  • Enable debug logging: system dbvars config debug switchd all true
  • Disable debug logging: system dbvars config debug switchd all false

Important: You must restart the container using the docker restart command after enabling/disabling debug logging. Otherwise, the log level will not be reflected in switchd log file. There should be no failover of the controllers after doing so. Make sure you restart cc-switchd on the active controller.

Container image name: cc_switchd

No traffic between the controllers and blades can occur.
chassis-guiThe chassis-gui service provides the necessary files for the system controller web user interface (webUI) via the http-server service.

Container image name: chassis-gui

No web user interface.
confd-key-migration-mgrThe confd-key-migration-mgr service allows the admin user to set the ConfD primary-key to a known value and aid in the migration of a configuration from one VELOS system to another. Controller ConfD encryption keys are stored in chassis backplane EEPROM, whereas partitions' ConfD encryption keys will be stored in controller ConfD.

Container image name: confd-key-migration-mgr

Sensitive configuration that uses the system encryption keys may fail to load; similarly, such configuration may not be able to migrate to another VELOS system.
confgenThe confgen service produces configuration files for system services such as NTP. It subscribes to ConfD and generates the configuration files based on the configuration in ConfD. The configuration files are then used by the operating system and any other containers.

Container image name: confgen

The date/time may be out of sync on the operating system and containers.
controller-identifierThe controller-identifier service is a null service that serves as a placeholder for the internal platform network namespace. This service has no real function except to exist. If this service is not running, platform-services would be inoperative, and manually restarting them would not fix the system. All these services are auto-restarted by docker when the system deems it necessary.
Important: You must not manually restart these containers using the docker restart command, otherwise the system may become inoperative.

Container image name: vcc-partition-software-manager

The platform-services would be completely inoperative. The only way to recover is to reboot the chassis controller.
controller-services-registry-<registry-port>This service provides the docker container registry for F5OS container images at the chassis level. You can list the container images in the registry by using the following command in the VELOS command line as the root user:

curl http://localhost:<registry-port>/v2/_catalog | jq .

Note: The partition container image registry is provided by the partition-services-registry service.

Container image name: registry

The containers fail to start; as a result, the VELOS system is unable to start up and initialize properly.
controller_rsyslogdThe controller_rsyslogd service runs a syslog server that processes and transforms logs. The chassis system controllers write their logs in the /var/log_controller/velos.log file.

The controller_rsyslogd service redirects all logs to facility LOCAL0; no other log facility is supported as of this writing.

This service also runs logrotate separately at the chassis. The log rotation configuration files are in the /var/F5/controller/etc/logrotation.d/ directory.

Changing the log rotation configuration is not recommended. You should only change the log rotation configuration under the advice of F5 Support while troubleshooting issues.

Note: There is an equivalent service for each partition. Refer to the Partition Services table for details.

Container image name: rsyslogd

The system is unable to generate system logs.
controller_tmstat_zmqThe controller_tmstat_zmq service provides ZeroMQ access to statistics within the chassis controller, such as CPU utilization, disk I/O and usage, memory utilization statistics.

Container image name: tmstat-agent-cc

No statistics is available for the system controllers.
controller-usermanThis service manages the passwd, group and shadow files based on the chassis system controller configuration data within ConfD.

Container image name: user_manager

Unexpected behavior when a chassis user changes password.
controlleraudit_serviceThis service is responsible for monitoring and logging all configuration modifications at the chassis controller level to the audit log file /var/log_controller/audit.log.

Container image name: audit_service

No audit logs with configuration changes is logged to the audit log file.
diag-agentThe diag-agent service performs diagnostic activities such as Power-On Self-Test, On-Line diagnostics, Off-Line diagnostics on the system controllers at the chassis level.

Container image name: psf-diagnostic-agent-cc

No diagnostics data available.
fips-serviceThe fips-service service enables FIPS_MODE when FIPS license is activated. It propagates FIPS configuration to applicable services, monitors cryptographic errors. It runs on each controller, partition and blade.

Container image name: fips-service

FIPS device is unavailable to BIG-IP tenants.
firmwareThis service is responsible for updating firmware on the chassis system controllers.

Container image name: firmware-cc

Unable to update firmware on the chassis system controllers.
http-serverThe http-server service is based on Apache and provides the webUI and REST API to the VELOS system. It is also used for ConfD SSL termination.

Container image name: http-server

No access to webUI and REST API.
ihealth-serviceThe ihealth-service service handles the upload of QKViews to the F5 iHealth portal.

Container image name: support-service

Unable to upload QKViews to iHealth portal.
lcd-webserverThe lcd-webserver service serves the LCD application and provides the LCD application an API to access the data the LCD application needs from ConfD.

Container image name: lcd-webserver

LCD is not operational.
license-serviceThe license-service service is responsible for license installation/activation on the VELOS hardware.

Container image name: license_service

License installation/activation fails.
lopdThe lopd service manages the Lights Out Processor (LOP) on the system controllers. The LOP is responsible for managing low-level platform resources such as the serial console port.

Container image name: lopd

The serial console port is unavailable.
name-service-ldapThe name-service-ldap service runs the nslcd process or the LDAP name service process, which configures the system to load users and groups from an LDAP directory such as the Active Directory. This service is required when you configure the authentication to use LDAP.

Container image name: ldap-nslcd

No LDAP authentication is available.
orchestration_managerThe orchestration_manager service performs the following on the VELOS chassis:
  • installs OpenShift using openshift-ansible playbooks and monitors the OpenShift cluster health
  • adds new masters (system controllers) and nodes (blades) to the OpenShift cluster when they are inserted
  • sets up third etcd instance for high availability (HA) support between the system controllers
  • installs kubevirt and multus in the OpenShift cluster
  • creates OpenShift namespaces for each configured partition, labeling the blades to denote which partition they are assigned to
  • distributes OpenShift tokens to the installed blades and system controllers
  • updates the /etc/hosts file based on the OpenShift cluster membership

The orchestration_manager service runs in active-standby mode on both system controllers and is managed by the systemctl service.

The logs are captured in the /var/log/openshift.log file on the system controllers.

Container image name: orchestration_manager

The OpenShift cluster does not function, and the VELOS system does not work as expected.
partition-services-registry-<registry port>This service provides the docker container registry for F5OS partition container images. The default registry port is 2200. You can list the container images in the registry by using the following command in the VELOS command line as the root user:

curl http://localhost:<registry-port>/v2/_catalog | jq .

Container image name: registry

The partition containers fail to start; as a result, the partition is unable to start up and initialize properly.
platform-diagThe platform-diag service runs on the system controllers. It provides reports and measurements of the low-level hardware at the chassis level via HTTP and ZeroMQ APIs. It works with the diag-agent service which performs the diagnostic activities on the assigned controllers.

Container image name: psf-platform-diag-cc

No diagnostics data available.
platform-fwuThe platform-fwu service provides HTTP and ZeroMQ APIs for the firmware updater. The firmware updater is responsible for firmware updates for various components such as the LOP, BIOS and CPLD. It is also responsible for loading the FPGA bit files.

Container image name: psf-firmware-updater

No firmware update can be performed.
platform-halThe platform-hal service provides low level data for the following components on the system controllers:
  • Drives (capacity, SMART attributes, I/O etc)
  • LOP (sensors, Fan Tray, PSU controllers etc)
  • CPU (sensors, utilization)
  • Memory (utilization, ECC)

Container image name: psf-platform-hal-cc

The VELOS hardware product may not function as expected. System services requiring access to hardware resources/information via the HAL will not function properly.
platform-monitorThis service provides monitoring of various platform components including software, firmware and hardware such as the following:
  • Monitors the health of other software services in the system, such as counting service restarts, directly querying for health info provided by a service.
  • Monitors the sensors such as temperature and power throughout the system.
  • Monitors firmware updates.
  • Saves historical statistics into RRD files which can be queried by other services and collected by the QKView process for troubleshooting purposes.
Additionally, this service provides the following telemetry functions:
  • Collects and formats metrics for the Confd notification streams.
  • Enables F5OS components to export metrics and logs to an OpenTelemetry receiver.

Container image name: psf-monitor
  • No data on the health of the system is available; this may affect services such as diag-agent which relies heavily on these data to function properly.
  • Platform telemetry data is unavailable.
platform-stats-bridge-ccThe platform-stats-bridge-cc service provides platform stats from the tmstat service to ConfD. The only way to interact with it is through the ConfD CLI commands:
  • show components component controller-<ID> state [memory | temperature]
  • show components component controller-<ID> cpu state [cpu-utilization | cpu-threads]

The logs are located in the /var/log_controller/velos.log file and prepended with PlatformStatsBridge.

Container image name: platform-stats-bridge-cc

Unable to view platform stats for the system controllers.
platform-statsThe platform-stats service captures various utilization stats related to the CPU, drives, and memory, and then stores the data in the tmstat tables.

Container image name: platform-stats-collector

No utilization stats are available.
qkviewdThis service gathers the diagnostic data from other containers and the host to generate the QKView file when you initiate a QKView capture.

Container image name: qkviewd

No QKView file can be generated.
snmp-trapdThis service sends SNMP traps to the SNMP server based on the SNMP trap configuration in ConfD.

Container image name: snmp-trapd

No SNMP trap is sent from the VELOS system.
swdiag-agentThis service provides the CLI and REST interface to the ihealth-service service to upload QKViews to F5 iHealth portal.

Container image name: swdiag-agent

Unable to initiate QKViews uploads to F5 iHealth portal.
system-serviceThis service handles host system level configurations such as system reboot, hostname changes, and system date/time operations through ConfD.

Container image name: system_service

Unable to modify host system configuration through CLI or webUI.
upgrade-serviceThe upgrade-service validates dependencies, checks for Confd version compatibility and instructs the vcc-partition-software-manager service the software version the partition and/or controllers should run via the Confd config database.

Container image name: upgrade-service

Unable to upgrade F5OS-C software on the VELOS system.
utils-agentThis service provides the utility commands to import and export files from the Chassis controller.

Container image name: utils-agent

Unable to import/export files to/from the Chassis controller.
vcc-chassis-managerThis service performs the following tasks on the system controllers:
  • provides hardware configuration data to ConfD
  • collects Platform Event Logs (PEL)
  • manages power for the installed blades (power on only)
  • performs automatic firmware update as needed during system startup

The logs are captured in the following files on the system controllers:

  • /var/log_controller/velos.log
  • /var/log_controller/chassis-manager

To enable/disable debug logging, enter config mode and commit the following changes:

  • Enable debug logging: system dbvars config debug chassis-manager all true
  • Disable debug logging: system dbvars config debug chassis-manager all false

Container image name: vcc-chassis-manager
  • Unable to power up the VELOS system completely
  • Firmware update cannot be completed
  • No PEL available
vcc-confdThis service is the system controller instance of ConfD, the configuration manager for F5OS-C.

The logs are captured in the following files on the system controllers:

  • /var/log_controller/cc-confd
  • /var/log_controller/cc-confd-hal
  • /var/log_controller/cc-confd-health
  • /var/log_controller/cc-confd-health-diag-agent
  • /var/log_controller/cc-confd-init
  • /var/log_controller/velos.log

To enable/disable debug logging, enter config mode and commit the following changes:

  • Enable debug logging: system logging sw-components sw-component vcc-confd config severity DEBUG
  • Disable debug logging: system logging sw-components sw-component vcc-confd config severity INFORMATIONAL

Container image name: vcc-confd

Unable to load/modify any configuration on the VELOS chassis.
vcc-config-object-managerThe vcc-config-object-manager polls the software management API, looking for any changes to imported images, and creates/updates the corresponding configuration objects in ConfD when there are changes. These objects can be viewed using the show running-config image <controller|partition> config command via the CLI.

The logs are captured in the following files on the system controller:

  • /var/log_controller/config-object-manager
  • /var/log_controller/config-object-manager-hal

Container image name: vcc-config-object-manager

The F5OS-C software images repository may be out of sync.
vcc-ha This service performs the following tasks:
  • exchanges messages with the peer system controller
  • coordinates Active and Standby role selection
  • coordinates graceful and reactive failovers
  • keeps the selectable internal chassis network and network IDs programmed
  • provides some of the high availability related operational data for various user interfaces

The logs are captured in the following files on the system controller:

  • /var/log_controller/ha
  • /var/log_controller/ha-hal

To enable/disable debug logging, enter config mode and commit the following changes:

  • Enable debug logging: system logging sw-components sw-component vcc-ha config severity DEBUG
  • Disable debug logging: system logging sw-components sw-component vcc-ha config severity INFORMATIONAL

Container image name: vcc-ha

High availability between system controllers does not function as expected.
vcc-host-configThe vcc-host-config service is responsible for maintaining the dynamic network configuration required for the proper operation of the system controller. This includes but is not limited to the following:
  • Bring up the internal interfaces for the system controllers
  • Add routes
  • Add iptables rules

Additionally, the vcc-host-config service reads the base MAC in the EEPROM using the chassis controller hardware abstraction layer (HAL) and writes the chassis base MAC to Confd.

The logs are captured in the following files on the system controller:

  • /var/log_controller/host-config
  • /var/log_controller/host-config-hal
  • /var/log_controller/velos.log

To enable/disable debug logging, enter config mode and commit the following changes:

  • Enable debug logging: system logging sw-components sw-component vcc-host-config config severity DEBUG
  • Disable debug logging: system logging sw-components sw-component vcc-host-config config severity INFORMATIONAL

Container image name: vcc-host-config

No network configuration on the system controllers. As a result, the system controllers are unable to communicate with each other.
vcc-image-serverThe vcc-image-server service provides the functionality to import a software ISO and use the VELOS system internal networks to PXE-boot blades and system controllers in order to install base software.

The logs are captured in the following files on the system controller:

  • /var/log_controller/image-server
  • /var/log_controller/image-server-dhcp
  • /var/log_controller/image-server-hal
  • /var/log_controller/image-server-httpd
  • /var/log_controller/image-server-monitor

Debug logging for the vcc-image-server service is enabled when you enable debug logging for the vcc-chassis-manager service.

Container image name: vcc-image-server

Unable to import software and install software on the blades and system controllers.
vcc-partition-agentThe vcc-partition-agent service runs on the system controller to provide an interface between the system controller and the chassis partition(s). It manages the chassis-wide MAC address pool and provides the MAC addresses on demand to the partition(s).

The logs are captured in the /var/log_controller/velos.log file on the system controller.

To enable/disable debug logging, enter config mode and commit the following changes:

  • Enable debug logging: system logging sw-components sw-component vcc-partition-agent config severity DEBUG
  • Disable debug logging: system logging sw-components sw-component vcc-partition-agent config severity INFORMATIONAL

Container image name: vcc-partition-agent

No MAC addresses available for partition(s).
vcc-partition-software-managerThis service manages the software for the controllers and partitions. It compares the currently running software versions with the configured software versions (from upgrade-service) and takes action to ensure they match.

Container image name: vcc-partition-software-manager

Unable to upgrade software for controllers and/or partitions.
velocity-tsyslogdThis service extracts logging configuration from ConfD and translates the configuration to logging rules for the controller-rsyslogd service. It produces rules for logging to remote servers, replicating logs within the system, and adjusting the log severity levels.

Container image name: velocity_rsyslogd

No logging configuration can be provided to the controller-rsyslogd service. As a result, no logging is available.

Recommendations

To restart a service, perform the following procedure:

  1. Log in to the VELOS system controller CLI as the root user
  2. Restart the service using the following command syntax:

    docker restart <service name>

    For example, you would enter the following command to restart the alert-service service:

    docker restart alert-service
