Description

A BIG-IP software upgrade can fail while creating or adding a planned volume when the root filesystem has insufficient free space.

The Software Management page may display an error similar to:

Status Details failed

(tm_install::VolumeSet::VolumeSet_add_planned - error adding /r83 volume to set sda.1)

Attempts to delete the affected boot location may also display:

failed to delete volumeset

Environment

  • BIG-IP LTM
  • BIG-IP software versions: 16.x, 17.x

Cause

The root filesystem is full or has insufficient free space before the upgrade begins. Large data stored on the root filesystem can prevent the upgrade process from creating or managing the required volume set. The root filesystem is not intended for general file storage on a BIG-IP system.

Recommended Actions

  1. Verify with df -h that the root filesystem has sufficient free space before retrying the upgrade.
  2. Identify unnecessary user data stored on the root filesystem using K14403: Maintaining disk space on the BIG-IP system
  3. Delete the large user files or move them to a filesystem intended for temporary or user data storage, such as /shared/tmp/.
  4. If the affected boot location cannot be deleted through the Configuration utility and the system reports failed to delete volumeset, reboot the BIG-IP system to recover the volume-management state.
  5. Confirm that the affected volume has been removed with tmsh show sys software and that sufficient root filesystem space is available.
  6. Retry the software installation.
  7. Monitor the installation progress and review the installation logs if the failure recurs.

Additional Information

  • A full root filesystem can prevent both software installation and boot-volume management operations.
  • Store files in an appropriate location such as /shared/tmp/
