K000163583: BIG-IP ASM Attack Signature Updates Remain in “New Update File” Status

Type
Support Solution
Published
2026-10-07
Updated
2026-10-07
Applies to
  • BIG-IP
  • BIG-IP ASM: 17.1.3
Source
https://my.f5.com/manage/s/article/K000163583

Description

BIG-IP ASM Attack Signature updates downloaded with Real Time installation may remain in New Update File status instead of changing to Currently Installed. In an HA pair, the Active device may install the update successfully while the Standby device reports the update as new. Synchronization can then overwrite the installation state reported by the GUI and REST interface.

The Attack Signatures may remain installed and loaded even when the reported status is incorrect.

Environment

  • BIG-IP ASM running on v17.1.3.2
  • ASM Attack Signature Live Update configured for Real Time installation
  • High-availability sync-failover device group
  • ASM synchronization Enabled
  • Manual synchronization with Auto-sync disabled
  • One device operating as the ASM Master and the peer operating as the secondary device
  • Automatic ASU installation on the secondary device disabled [liveupdate.allowautoinstallonsecondary = false]

Cause

At the time of writing this KB Article, an Internal Bug ID 2515301 is associated with the incorrect installation status.

The ASU can install successfully on the Active ASM Master device. Because Automatic installation on the secondary device is disabled, the secondary device may not install the same ASU.

The difference in Live Update state between the HA peers can trigger synchronization of ASM Live Update data. The synchronization may overwrite the successful installation state and change the displayed status back to NEW.

The issue primarily affects the installation status reported by the GUI and REST interface. The ASU and its signatures can remain installed and loaded.

Answer/Recommended Actions

1) Enable Automatic ASU installation on the secondary device, and then save the config change:

# tmsh modify sys db liveupdate.allowautoinstallonsecondary value true
# tmsh save sys config

Note: Running the above two commands should not have any Impact on Traffic flow.

2) If the status remains 'New Update File', manually install the latest ASU on both HA devices.

3) Verify that the latest ASU displays as 'Currently Installed' on both devices.

4) Synchronize the HA devices after both have consistent ASU installation states.

5) If the GUI or REST status remains inconsistent, collect the following from both devices, and share on the Support Ticket with F5 Team:

  • Live Update installation status and history
  • ASM QKview
  • Screenshots of the Live Update page before and after installation
  • Results from manually installing the affected ASU

Note: Apply a product Fix that addresses the reported Bug ID 2515301, when available. In this regard, you may check for an update on the F5 Bug Tracker portal - once published.

Additional Information

  • 'Real Time' Live Update installation installs an update after it has been downloaded.
  • A successful installation can be confirmed through Live Update logs and installation records even when the GUI or REST interface reports New Update File.
  • Manually installing the same ASU on both HA devices can clear the inconsistent installation state.
  • A secondary device may not independently install an update when it is not the ASM Master and Automatic installation on the secondary device is disabled.
