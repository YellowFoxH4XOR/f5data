Description

APM's Portal Access feature is incompatible with the backend App server "Dynatrace" feature. When "Dynatrace" is Enabled on the backend App server, it cause communication trouble between the client PC and the backend App server (Pool-member). Often, this issue can cause looping behavior where-in the client PC continues to request "GET /private/fm/volatile.html", which appears to be fulfilled by the BigIP APM subsystem. But the loop prevents the backend App server's landing page from being loaded.

Environment

Relevant environmental factors:

  • BIG-IP APM
  • APM client using Portal Access to access a backend App server with the "Dynatrace" feature Enabled.

Cause

This issue is caused by an incompatibility between the BigIP APM's Portal Access functionality, and the "DynaTrace" feature. 

Recommended Actions

This issue can be resolved by one of two means. Either the "Dynatrace" feature can be Disabled on the backend App server. Or, the below iRule can be applied to the Virtual Server to block "Dynatrace" traffic, thereby preventing the problem behavior from occuring.

  1. Create new iRule containing the below logic:
when HTTP_REQUEST {
  # Short-term mitigation for Dynatrace agent incompatibility with APM Portal Access
    if { [HTTP::has_responded] } { return }
    if { [HTTP::path] matches_glob "*/ruxitagentjs*.js" } {
        HTTP::respond 404
    }
}
  1. Then, attach the new iRule to the Virtual Server.
