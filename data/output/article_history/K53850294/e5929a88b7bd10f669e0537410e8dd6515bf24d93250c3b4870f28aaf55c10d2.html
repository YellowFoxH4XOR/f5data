K53850294: Portal Access application does not load when Dynatrace is enabled on the back-end server

Type
Support Solution
Published
2022-08-17
Updated
2026-10-29
Applies to
  • BIG-IP
  • BIG-IP APM: 17.X.X, 17.0.X, 17.0.0
Source
https://my.f5.com/manage/s/article/K53850294

Description

You access a web application through BIG-IP APM Portal Access, and the landing page of the application does not load. The browser repeatedly sends the same request, and the page does not finish loading. Dynatrace is enabled on the back-end server, and the application loads the Dynatrace JavaScript agent (files whose name starts with ruxitagentjs).

Environment

  • BIG-IP APM 17.1.x, 17.5.x, or 21.1.x

  • Portal Access resource and rewrite profile

  • Back-end application with Dynatrace enabled

Cause

Portal Access does not support applications with Dynatrace enabled. This is a documented limitation in the Portal Access section of the BIG-IP APM Client Compatibility Matrix.

Answer/Recommended Actions

Use one of the following options:

  • Disable Dynatrace for the application on the back-end server.

  • Add an iRule to the Portal Access virtual server that blocks requests for the Dynatrace JavaScript agent.

To add the iRule, perform the following procedure:

Impact of procedure: The Dynatrace JavaScript agent is not loaded in the browser for users who access the application through Portal Access, so browser-side monitoring data is not collected for them. F5 recommends performing this procedure during a scheduled maintenance window.

  1. Log in to the Configuration utility.

  2. Go to Local Traffic > iRules > iRule List.

  3. Click Create.

  4. Enter a name for the iRule.

  5. In Definition, enter the following iRule:

    when HTTP_REQUEST {
        # Short-term mitigation for Dynatrace agent incompatibility with APM Portal Access
        if { [HTTP::has_responded] } { return }
        if { [HTTP::path] matches_glob "*/ruxitagentjs*.js" } {
            HTTP::respond 404
        }
    }

  6. Click Finished.

  7. Go to Local Traffic > Virtual Servers > Virtual Server List, and click the name of the Portal Access virtual server.

  8. Click the Resources tab.

  9. In the iRules section, click Manage.

  10. Move the iRule from Available to Enabled, and click Finished.

To back out of this procedure, move the iRule from Enabled to Available.

If the issue persists, refer to K14184: Troubleshooting BIG-IP APM Portal Access applications.

Additional Information

For other Portal Access limitations, refer to the Portal Access section of the BIG-IP APM Client Compatibility Matrix for your BIG-IP version.
