K10835: Specifying BIG-IP GTM virtual server dependence on the iQuery connection state

Topic

The iQuery protocol allows the gtmd process to collect dynamic information over port 4353 from the big3d process on a remote or local BIG-IP server. The vs_depends_server_state global variable allows a BIG-IP GTM administrator to specify whether the virtual server status depends on the current state of an iQuery connection between the BIG-IP GTM system and the BIG-IP LTM device hosting the virtual servers.

Note: For information about specifying BIG-IP GTM virtual server dependence on iQuery in BIG-IP GTM version 9.x, refer to K8506: Specifying GTM virtual server dependence on the iQuery connection state in BIG-IP GTM version 9.x.

By default, the vs_depends_server_state global variable is enabled (set to yes), and BIG-IP GTM immediately marks down all virtual servers hosted on a BIG-IP LTM when iQuery communication failed or was briefly interrupted due to a network issue. When the iQuery connection fails, the BIG-IP GTM directs traffic away from the BIG-IP LTM even if the network event was brief and lower than the configured timeout settings of the BIG-IP monitor used by the BIG-IP GTM. In most cases this is desirable behavior because the BIG-IP GTM system is able to direct traffic to a BIG-IP LTM system in an alternate datacenter.

However, in some cases this behavior of marking virtual servers down based on the iQuery connection state may inappropriately cause prolonged site outages. This may be the case when there is no alternate resource to which the BIG-IP GTM system can direct traffic. By disabling the vs_depends_server_state global variable, the BIG-IP GTM can keep the virtual servers in an up status if iQuery communication is briefly interrupted due to a network issue.

Disabling the vs_depends_server_state global variable

BIG-IP GTM 11.5.0 and later

To disable the vs_depends_server_state global variable in 11.5.0 and later, and configure the BIG-IP GTM system to keep the virtual servers in an up status if iQuery communication is briefly interrupted due to a network issue, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to DNS > Settings > GSLB > General.
  3. Under the Monitoring section, select Depends on Monitors Only from the Virtual Server Status drop-down menu.
  4. Click Update.

Note: Alternatively, you can enter the following command from the command line:

tmsh modify /gtm global-settings general virtuals-depend-on-server-state no

BIG-IP GTM 10.1.0 through 11.4.1

To disable the vs_depends_server_state global variable in 10.1.0 through 11.4.1, and configure the BIG-IP GTM system to keep the virtual servers in an up status if iQuery communication is briefly interrupted due to a network issue, perform the following procedure:

  1. Log in to the Configuration utility.
  2. Navigate to System > Configuration > Global Traffic > General.
  3. Select Depends on Monitors Only from the Virtual Server Status drop-down menu.
  4. Click Update.

Note: Alternatively, you can enter the following command from the command line:

tmsh modify /gtm global-settings general virtuals-depend-on-server-state no

BIG-IP GTM 10.0.x

Note: The vs_depends_server_state global variable is not configurable using the Configuration utility in GTM version 10.0.x. For more information, refer to: K10857: The vs_depends_server_state global variable is not configurable using the Configuration utility in BIG-IP GTM version 10.0.x.

To disable the vs_depends_server_state global variable in version 10.0.x, and configure the BIG-IP GTM to keep the virtual servers in an up status if iQuery communication is briefly interrupted due to a network issue, perform the following procedure:

  1. Log in to the command line.
  2. To disable the vs_depends_server_state global variable, type the following command:

    tmsh modify /gtm settings general virtuals-depend-on-server-state no:
  3. To verify the command setting, type the following command:

    tmsh list /gtm settings general virtuals-depend-on-server-state:
  4. To save the configuration, type the following command:

    tmsh save /sys config
