Description

This article explains how to resolve an issue where BIG-IP DNS (GTM) devices fail to synchronize configuration objects, such as Data Centers, after initial setup. The problem is characterized by one device not replicating changes to the other, with show /gtm iquery showing one device as "connected" and the other as "connecting" or "not-connected." System logs may display SSL handshake errors like:

SSL Error: error:140760FC:SSL routines:SSL23_GET_CLIENT_HELLO:unknown protocol

SSL error during shutdown: SSL SSL_ERROR_SSL

Environment

  • BIG-IP DNS (GTM) Virtual Editions, version 17.5.1
  • Platform: F5-BIG-LTM-I5820-DF, C125
  • Two DNS VEs configured in a sync group for configuration synchronization
  • FIPS 140-3 compliance enabled on both devices
  • Self IP Port Lockdown initially set to "None"
  • iQuery traffic observed on port 4353
  • Certificate trust and SSL handshake required for iQuery connections

Cause

The root cause is the Self IP Port Lockdown setting configured as "None," which blocks iQuery (port 4353) traffic required for SSL handshake and synchronization between BIG-IP DNS devices. FIPS 140-3 compliance may further restrict available SSL ciphers, contributing to handshake failures.

Recommended Actions

Change the Self IP Port Lockdown setting from "None" to "Default" (or a custom setting that includes port 4353) on both DNS devices to permit iQuery traffic.

Verify that each device has the peer's certificate in both the Trusted Device Certificates and Trusted Server Certificates sections; remove any outdated certificates if present.

Re-run the certificate exchange using:

bigip_add <peer_DNS_IP_address>

Restart services on both devices:

tmsh restart sys service gtmd

tmsh restart sys service big3d

If FIPS 140-3 compliance is enabled and issues persist, consult F5 support for an Engineering Hotfix.

If synchronization still fails, remove and re-add the DNS devices to the sync group.

Additional Information

Port Lockdown must allow port 4353 for iQuery communication.

FIPS compliance can restrict available ciphers; additional steps or hotfixes may be needed if issues persist.

After resolving Port Lockdown settings, synchronization should occur as expected.
