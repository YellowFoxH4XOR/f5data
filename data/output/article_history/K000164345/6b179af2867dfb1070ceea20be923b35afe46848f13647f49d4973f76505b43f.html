Description

Configuration load fails after an upgrade with error 0107161f. A log publisher referenced by an Application DoS security log profile has no ArcSight, Splunk, or Syslog destination, so configuration validation rejects it.

0107161f:3: Log publisher '/Common/<security log profile>' used by Application DoS Security log profile can have only ArcSight, Splunk or Syslog destinations.

Unexpected Error: Loading configuration process failed.

Environment

  • BIG-IP ASM or BIG-IP AFM module provisioned

  • Security log profile of type remote

  • BIG-IP LTM 17.5.1.11 upgraded to a later hotfix, with a configuration that includes a log publisher with no log destination, referenced by Application DoS and Bot Defense security log profiles

Cause

  • The bigip.conf file became corrupted when a security log profile was deleted.

  • A log publisher referenced by an Application DoS security log profile contains no ArcSight, Splunk, or Syslog destination. For example, the publisher contains only a description. Configuration validation rejects the publisher, so the load fails.

  • The publisher was left without a destination after the destination was deleted while profile references to the publisher remained.

Answer/Recommended Actions

  1. Run "tmsh load sys config verify" and check the output for the error above. Identify the log publisher named in the error.

  2. Review the log publisher. If it has no ArcSight, Splunk, or Syslog destination, do one of the following:

    • Add a supported destination to the publisher. For example, in "/config/bigip.conf" under sys log-config publisher <publisher name>, add a destinations { <destination name> { } } block that references an existing supported destination.

    • Remove the references to the publisher from the security log profiles.

  3. Check every security log profile that references the publisher, including Application DoS and Bot Defense logging profiles, and update or remove stale references.

  4. Load the configuration and confirm that the load completes with no further errors. In this regard, Run "tmsh load sys config verify" again on the unit and confirm there are no errors.

  5. If there was no further Error, then load the config normally by running "tmsh load sys config", and wait for a couple of Sec. for complete config load.
