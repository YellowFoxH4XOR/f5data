Topic

You should consider using this procedure under the following conditions:

  • You want to verify the proper operation of your BIG-IP Next SPK, BIG-IP Next CNF, or BIG-IP Next for Kubernetes deployment.
  • You want to provide a QKView file to F5 Support to aid in troubleshooting an issue.

Description

The qkview utility is a program that you can use to automatically collect diagnostic and logging information from BIG-IP Next SPK, BIG-IP Next CNF, or BIG-IP Next for Kubernetes systems. The qkview utility is an executable program that generates machine-readable (XML) diagnostic data and combines the data into a single compressed Tape ARchive (TAR) format file. You can upload this file, called a QKView file, and provide it to F5 Support to help them troubleshoot any issues.

Note: F5 Support requires a QKView file in all cases in which remote access to the product is not available.

In BIG-IP Next SPK, BIG-IP Next CNF, and BIG-IP Next for Kubernetes, you can run the qkview utility using the QKView API on the system's Cluster Wide Controller (CWC) to collect diagnostic information about running containers.

Prerequisites

You must meet the following prerequisites to use these procedures:

  • You have BIG-IP Next SPK, BIG-IP Next CNF, or BIG-IP Next for Kubernetes running in a cluster.
  • You have administrative access to the cluster.

Procedures

In order to run the qkview utility, you need to authenticate to the QKView API on the CWC by providing SSL/TLS certificates in a POST request. The API request is sent to the node where the CWC is running using the nodeport for the CWC service.

You can also enable the CWC admin token for authentication. When you enable the admin token, you must supply the admin token in addition to the SSL/TLS certificates to authenticate to the QKView API. To enable the admin token, include enableAuthToken: true in the cwc-values.yaml file. For example:

cwc:
   enableAuthToken: true

You can use the following procedures to retrieve the information needed to build the requests to the QKView API and run the qkview utility. To do so, perform the following procedure:

Impact of procedure: Performing the following procedure should not have a negative impact on your system.

  1. Access the cluster where BIG-IP Next for Kubernetes is running.
  2. If the CWC admin token is enabled, use the following command syntax, where <namespace> is the namespace where the CWC pod is running, to retrieve the admin token:

    kubectl get secret cwc-auth-token -n <namespace> -o jsonpath="{.data.token}" | base64 --decode; echo ""

    For example, the namespace used in this procedure is f5-utils:

    kubectl get secret cwc-auth-token -n f5-utils -o jsonpath="{.data.token}" | base64 --decode; echo ""

    The output should show the admin token similar to the following example:

    jOghNJzq3oYMWcQUtDsF70q1UE3qOdcp

  3. To access the QKView API on the CWC, you also need the SSL/TLS certificates that were generated when installing the cert manager. They should be in the api-server-secrets/ssl/ directory depending on the installation. First, enter the following command to create a directory named cwc_api for the CWC REST API certificates:

    mkdir cwc_api

  4. Copy the certificate files to the newly created directory using the following syntax:

    cp <path_to_source_file> ./cwc_api

    For example, if the files are located in ~/cwc/api-server-secrets/ssl/ directory, enter the commands as follows:

    cp ~/cwc/api-server-secrets/ssl/ca/certs/ca_certificate.pem ./cwc_api
    cp ~/cwc/api-server-secrets/ssl/client/certs/client_certificate.pem ./cwc_api
    cp ~/cwc/api-server-secrets/ssl/client/secrets/client_key.pem ./cwc_api

  5. Enter the following command to confirm the nodeport assigned to the CWC service in your cluster:

    kubectl get svc -n f5-utils | grep cwc

    The following example output shows the nodeport is 30881:

    f5-spk-cwc                  NodePort    10.96.158.127   <none>        38081:30881/TCP,19891:30921/TCP   218h38m

  6. Enter the following command to determine which node the CWC pod is running on:

    kubectl get pods -n f5-utils -o wide | grep cwc

    The example output shows the node is bnk-node1:

    f5-spk-cwc-57989fd55b-mzplc         3/3     Running   0          218h56m   10.244.227.198   bnk-node1          <none>           <none>

  7. Use the following syntax, where <node_name> is the name of the node where the CWC pod is running, to show the node IP address:

    kubectl get nodes -o wide | grep <node_name>

    For example, if the name of the node is bnk-node1 enter the following command:

    kubectl get nodes -o wide | grep bnk-node1

    The example output shows the node IP address is 10.11.0.3:

    bnk-node1          Ready    <none>          218h42m   v1.32.0   10.11.0.3     <none>        Debian GNU/Linux 12 (bookworm)   6.8.0-51-generic  containerd://1.7.24

  8. Now you can use the gathered information to send a POST request to the QKView API to run the qkview utility. The following syntax includes the admin token in the Authorization header:

    curl -k --request POST https://<node_IP>:<nodeport>/v1/qkview --cacert cwc_api/ca_certificate.pem --cert cwc_api/client_certificate.pem --key cwc_api/client_key.pem -H "Authorization: Bearer <token>" -d '{"namespace": "<namespace>","filename": "<filename>",<options>}'

    Note: If you do not specify a namespace the qkview will include all namespaces. If you do not specify a filename the system will generate a unique identifier.

    In the command syntax, note the following:

    • <node_IP> is the IP address of the node where the CWC pod is running.
    • <nodeport> is the nodeport for the CWC service.
    • <token> is the admin token.
    • <namespace> is the namespace where the pods are running. <optional>
    • <filename> is an custom filename for the qkview. <optional>
    • <options> includes any other options for the qkview.

    For example, to generate a qkview including all namespaces with no other options, you can omit the POST data and the system will generate the needed defaults. To do so using the example node IP address, nodeport, and admin token, enter the following command:

    curl -k --request POST https://10.11.0.3:30881/v1/qkview --cacert cwc_api/ca_certificate.pem --cert cwc_api/client_certificate.pem --key cwc_api/client_key.pem -H "Authorization: Bearer jOghNJzq3oYMWcQUtDsF70q1UE3qOdcp"

    To include only the default namespace specifying qkview-bnk as the filename, enter the following command:

    curl -k --request POST https://10.11.0.3:30881/v1/qkview --cacert cwc_api/ca_certificate.pem --cert cwc_api/client_certificate.pem --key cwc_api/client_key.pem -H "Authorization: Bearer jOghNJzq3oYMWcQUtDsF70q1UE3qOdcp" -d '{"namespace": "default","filename": "qkview-bnk"}'

    If successful, output will include the qkview id similar to this example:

    {"id":"b7decd1f-747e-44a9-ac0c-f0f19b32ac32", "filename":"qkview-bnk"}

  9. To check the status of the running qkview, use the following syntax:

    curl -k https://<node_IP>:<nodeport>/v1/qkview/<id>/status --cacert cwc_api/ca_certificate.pem --cert cwc_api/client_certificate.pem --key cwc_api/client_key.pem -H "Authorization: Bearer <token>"

    In the command syntax, note the following:

    • <node_IP> is the IP address of the node where the CWC pod is running.
    • <nodeport> is the nodeport for the CWC service.
    • <id> is the qkview id returned from the previous command.
    • <token> is the admin token.

    For example, to use the qkview id from above, enter the following command:

    curl -k https://10.11.0.3:30881/v1/qkview/b7decd1f-747e-44a9-ac0c-f0f19b32ac32/status --cacert cwc_api/ca_certificate.pem --cert cwc_api/client_certificate.pem --key cwc_api/client_key.pem -H "Authorization: Bearer jOghNJzq3oYMWcQUtDsF70q1UE3qOdcp"

    The output should be similar to the following example snippet:

    ...

       "status": "Completed"
    },
    "validations": {
       "status": "Completed",
       "nested": {

  10. To list all the qkviews on the system, use the following syntax:

    curl -k https://<node_IP>:<nodeport>/v1/qkview --cacert cwc_api/ca_certificate.pem --cert cwc_api/client_certificate.pem --key cwc_api/client_key.pem -H "Authorization: Bearer <token>"

    In the command syntax, note the following:

    • <node_IP> is the IP address of the node where the CWC pod is running.
    • <nodeport> is the nodeport for the CWC service.
    • <token> is the admin token.

    For example, to use the example node IP address, nodeport, and admin token from above, enter the following command:

    curl -k https://10.11.0.3:30881/v1/qkview --cacert cwc_api/ca_certificate.pem --cert cwc_api/client_certificate.pem --key cwc_api/client_key.pem -H "Authorization: Bearer jOghNJzq3oYMWcQUtDsF70q1UE3qOdcp"

    The following example snippet shows the previously generated qkview:

    ...
    [
      {
        "id": "b7decd1f-747e-44a9-ac0c-f0f19b32ac32",
        "namespace": "default",
        "filename": "qkview-bnk",
        "created_at": "2025-04-02T17:05:44.750878737Z",
        "size": "775870",
        "status": "Completed"
      }
    ]
    ...

  11. Once the qkview is complete, use the following syntax to download the qkview file:

    curl -k https://<node_IP>:<nodeport>/v1/qkview/<id>/download --cacert cwc_api/ca_certificate.pem --cert cwc_api/client_certificate.pem --key cwc_api/client_key.pem -H "Authorization: Bearer <token>" --output  <qkview_filename>

    In the command syntax, note the following:

    • <node_IP> is the IP address of the node where the CWC pod is running.
    • <nodeport> is the nodeport for the CWC service.
    • <id> is the qkview id returned when running the qkview.
    • <token> is the admin token.
    • <qkview_filename> is the name you want to assign to the downloaded qkview output file.

    Using the example node IP address, nodeport, qkview id, and admin token from above, to download and save the qkview file as qkview-bnk.tar.gz, enter the following command:

    curl -k https://10.11.0.3:30881/v1/qkview/b7decd1f-747e-44a9-ac0c-f0f19b32ac32/download --cacert cwc_api/ca_certificate.pem --cert cwc_api/client_certificate.pem --key cwc_api/client_key.pem -H "Authorization: Bearer jOghNJzq3oYMWcQUtDsF70q1UE3qOdcp" --output qkview-bnk.tar.gz

  12. You can upload the QKView file to iHealth by logging in to https://ihealth.f5.com/qkview-analyzer/.

    Note: You can also provide the QKView file to F5 Support. To do so, refer to K000090853: Exchange files with F5 Support using MyF5..
