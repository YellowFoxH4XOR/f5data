K000163782: F5OS management plane queries DNS root servers during DNSSEC trust-anchor maintenance

Type
Support Solution
Published
2026-10-20
Updated
2026-10-20
Applies to
  • F5OS Products
  • F5OS: 2.0.0
Source
https://my.f5.com/manage/s/article/K000163782

Description

F5OS management-plane DNS traffic includes DNSKEY and _ta-4f66 trust-anchor telemetry queries generated by unbound-anchor. This is expected DNSSEC behavior and does not by itself indicate a security compromise.

Environment

  • F5OS version 2.0.0

  • F5OS management plane

  • unbound-anchor.service and unbound-anchor.timer

  • Configured DNS nameservers that may be unable to complete or support the required DNSSEC queries

  • DNSSEC/DNSKEY-related traffic

Cause

The unbound-anchor.timer systemd timer periodically starts unbound-anchor.service to refresh and verify the DNSSEC root trust anchor. If the configured DNS resolver cannot complete or support the required DNSSEC queries, the process may query DNS root servers directly.

Recommended Actions

  • Do not disable unbound-anchor.service or unbound-anchor.timer. These components support DNSSEC validation and future root-key rollovers.

  • Maintain approved DNS nameservers in the F5OS configuration where required for management-plane name resolution.

  • Ensure the configured DNS infrastructure can process the DNSSEC-related queries required by the trust-anchor refresh process if direct root-server access is to be avoided.

  • No supported F5OS configuration or workaround is currently available to suppress unbound-anchor activity.

  • Treat DNSSEC/DNSKEY traffic as expected unless additional traffic cannot be correlated with the trust-anchor refresh process.

Additional Information

Observed traffic may include DNSKEY queries and _ta-4f66 trust-anchor telemetry queries. The unbound-anchor process periodically refreshes the DNSSEC root trust anchor in accordance with RFC 5011.
