K37209021: Configuring SNMP trap when iQuery status is not connected

Description


Users can create custom SNMP traps for iQuery status when disconnected from the iQuery mesh. This will log an alert under /var/log/ltm to view. 

Environment

  • BIG-IP GTM/DNS
  • iQuery
  • SNMP trap
  • CLI

Cause

The GTM will log when iquery connections are starting, but does not log when connections are in a disconnected state.

Recommended Actions

1. Create a new file for the script.

touch /config/gtm_iquery_monitor.sh

2. Use an editor such as nano to paste the below text to the file /config/gtm_iquery_monitor.sh

nano /config/gtm_iquery_monitor.sh

#!/bin/bash

#Check to see if any iquery connections are in state not-connected or connecting
nc1=$(tmsh show gtm iquery | awk '/not-connected/ { count++ } END { print count }')
nc2=$(tmsh show gtm iquery | awk '/connecting/ { count++ } END { print count }')
  
#set null responses to 0
if [ -z "$nc1" ]; then nc1=0; fi
if [ -z "$nc2" ]; then nc2=0; fi
#add responses
nc3=$(($nc1+$nc2))
#log if responses are > 0
if [ $nc3 -ge 1 ]; then
    logger -p local0.notice "$nc3 iquery connections not connected"
fi

3. Make the script executable:

chmod +x /config/gtm_iquery_monitor.sh

4. Run this script as a crontab, maybe every 10 minutes. For example:
  a. run this command:
    crontab -e
  b. and add this entry to the list of cron jobs
    */10 * * * * /config/gtm_iquery_monitor.sh

5. The script will create a log message in /var/log/ltm when the amount of iquery connections that aren't connected is above 0.

6. Finally, create a custom SNMP trap by adding the following lines to the /config/user_alert.conf file to alert you when the message with "iquery connections not connected" appears in /var/log/ltm:
  
alert IQUERY_ALARM "iquery connections not connected" {
   snmptrap OID=".1.3.6.1.4.1.3375.2.4.0.300"
}

Note: The OID for custom traps starts at 300, if you have existing traps then increment the last octet accordingly.
