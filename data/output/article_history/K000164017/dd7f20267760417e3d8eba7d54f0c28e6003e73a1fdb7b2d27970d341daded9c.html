Description

On a BIG-IP LTM Active-Standby device pair, the Active device shows the Standby device as Offline under Device Management. The Standby device shows both devices as healthy and communicating.

  • On the Active device, tmsh show /cm failover-status shows the failover connections to the peer in Error, with the warning "Not receiving any failover updates." The last received packet from the peer is about one month old.
  • On the Standby device, tmsh show /cm failover-status shows it receiving failover updates from the Active device on one connection (status Ok). The other connections show Error, with the warning "Only receiving failover updates from [peer] on 1 connections, out of 4 total."
  • Network reachability is not the cause. Pinging the peer's failover address succeeds and TCP port 1026 is open.

Environment

  • HA Pair
  • Configuration: Active-Standby device pair with device trust and config sync failover configured. Failover addresses use TCP port 1026.
  • Traffic groups: /Common/traffic-group-1 and /Common/traffic-group-2 (both active on the Active device)

Cause

The Active device's failover communication state with the Standby device was stale. The Active device had not received failover updates from the peer for approximately one month, so it kept reporting the Standby as Offline. The Standby device continued to receive valid updates from the Active device.

Answer/Recommended Actions

  1. Schedule a maintenance window, because restarting sod affects traffic.
  2. On the affected device, restart the sod process:
    bigstart restart sod
  3. On the Active device, run tmsh show /cm failover-status and confirm that the connections to the peer show Ok and that the device no longer reports "Not receiving any failover updates."
  4. On the Standby device, run tmsh show /cm failover-status and confirm that it still receives updates from the Active device.
  5. In Device Management on the Active device, confirm that the Standby device is shown as Online.

Impact of workaround: Restarting the sod process will disrupt traffic processing and should only be performed during a maintenance window.
