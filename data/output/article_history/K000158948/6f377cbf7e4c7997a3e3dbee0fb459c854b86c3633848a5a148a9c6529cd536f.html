K000158948: High CPU usage in BIG-IP 17.1.3 due to FFDHE enforcement in TLSv1.3 negotiations with cipher groups ordered by 'strength'

Type
Support Solution
Published
2025-12-30
Updated
2025-12-30
Source
https://my.f5.com/manage/s/article/K000158948

Description

After upgrading BIG-IP systems to version 17.1.3, sustained high CPU usage (up to 100%) may be observed on both active and standby devices under load.

The issue manifests with the following symptoms:

  • CPU usage spikes to 90-100% during normal traffic loads
  • The tmm.0 process is identified as the top CPU consumer
  • High sw_crypto (software crypto) CPU utilization/statistics show elevated percentage
  • Rolling back to version 17.1.2.1 resolves the issue

Environment

  • BIG-IP LTM version 17.1.3
  • Cipher groups configured with FFDHE groups (FFDHE4096, FFDHE3072, FFDHE2048)
  • Cipher group ordering set to 'strength'
  • TLSv1.3 enabled for client-side SSL profiles
  • Applies to both Virtual Edition (VE) and hardware platforms

Cause

Bug ID2141297(There is currently no fix for Bug ID2141297 in version 17.1.3. )

The root cause is the enforcement of FFDHE key exchange in TLSv1.3 handshakes when FFDHE groups are present and prioritized in the cipher group (using 'strength' ordering). This behavior, introduced in 17.1.3, results in high software crypto CPU usage due to expensive FFDHE key generation operations.

Recommended Actions

Modify the cipher group configuration using one of the following approaches:

Option 1: Remove FFDHE groups entirely

  1. Navigate to Local Traffic > Ciphers > Groups
  2. Select the cipher group in use
  3. Remove FFDHE4096, FFDHE3072, and FFDHE2048 from the cipher group configuration
  4. Save the changes
  5. This allows TLSv1.3 to use ECDHE groups (X25519, P256, P384) which have lower CPU overhead and do not cause high sw_crypto utilization

Option 2: Change cipher group ordering

  1. Navigate to Local Traffic > Ciphers > Groups
  2. Select the cipher group in use
  3. Change the Order setting from 'strength' to 'speed'
  4. Save the changes
  5. This prioritizes ECDHE groups (X25519, P256, P384) over FFDHE groups
  6. FFDHE groups remain available but are not preferred, reducing sw_crypto CPU load

Additional Information

  • FFDHE groups (FFDHE4096, FFDHE3072) are used in 17.1.3 but not in 17.1.2.1
  • On version 17.1.3 the fix for ID1352213: Handshake failed with ffdhe group was introduced for TLSv1.3. This is why on 17.1.2.2 those groups weren't used, at least in TLSv1.3.
  • The FFDHE support introduced a side effect: (Bug alias 2141297) FFDHE is enforced through a hello retry if it is the BigIPs prefered cipher, even if the client sent a keyshare of another cipher that is allowed by the BigIP.
