K000141028: Power BI reports fail through Portal Access with cache-fm-Modern.js errors in the browser console

Description

When you access Power BI reports through a BIG-IP APM Portal Access resource, the reports do not load or do not work as expected. The browser developer tools console shows one or both of the following errors from the Portal Access rewriter file cache-fm-Modern.js. The examples are excerpts; line and column numbers vary.

  • Error 1:

    Uncaught TypeError: Cannot read properties of undefined (reading 'document')
    at get_ (cache-fm-Modern.js:1494:187)
    at get_frameElement (cache-fm-Modern.js:1496:8)
    at F5_st (cache-fm-Modern.js:1497:9)

  • Error 2:

    Uncaught DOMException: DOMException: Failed to read the 'localStorage' property from 'Window': The document is sandboxed and lacks the 'allow-same-origin' flag.
    at F5_st (cache-fm-Modern.js:7:124)
    at F5_st_set (cache-fm-Modern.js:2233:1387)

Error 2 can also occur with other applications that load content in a sandboxed iframe.

Environment

  • BIG-IP APM 17.1.x, 17.5.x, or 21.1.x

  • Portal Access resource for Power BI, or for another application that loads content in an iframe with a sandbox attribute

  • Error 1 only: BIG-IP APM 17.1.x before 17.1.3.5, or 17.5.x before 17.5.1.2

Cause

Each error has a different cause:

  • Error 1: Bug ID 1617037. The cache-fm-Modern.js file detects the Chrome browser as Safari, because the Chrome user agent string also contains Safari. The file then runs code that is intended for Safari only, and this code fails.

  • Error 2: Bug ID 840257. Portal Access does not support the HTML iframe sandbox attribute. When the application loads a page in an iframe with a sandbox attribute that does not include allow-same-origin, the browser treats the page in the iframe as a page from a separate origin. The Portal Access rewriter code in that page cannot read localStorage, and the page fails.

Answer/Recommended Actions

Use the procedure for the error that you see. If you see both errors, resolve Error 1 first.

Error 1: Upgrade, or use the latest cache-fm-Modern.js file

Upgrade to a release that includes the fix for Bug ID 1617037:

  • BIG-IP 17.1.3.5 or later

  • BIG-IP 17.5.1.2 or later

  • BIG-IP 21.1.x

If you cannot upgrade, use the latest cache-fm-Modern.js file from K000148786: Latest cache-fm-Modern.js file for Portal Access. The file is derived from BIG-IP 21.1.x, which includes the fix.

Error 2: Add allow-same-origin to the sandbox attribute with an iRule

Portal Access does not support the iframe sandbox attribute, and no software fix is listed for Bug ID 840257. As a workaround, you can use an iRule that adds allow-same-origin to the sandbox attribute in the JavaScript file of the application that creates the iframe.

Impact of procedure: The iRule changes the response for every request path on the virtual server that ends with the file name you enter. It adds allow-same-origin and keeps allow-scripts. If the page in the iframe has the same origin as the page that embeds it, this combination allows the page in the iframe to remove its own sandbox, and the iframe is no longer isolated. Use this iRule only for iframe content that you trust, and test it in a non-production environment before you apply it to production.

  1. Find the JavaScript file that creates the sandboxed iframe. In the browser developer tools, search all files of the application for sandbox="allow-scripts", and note the name of the file that contains it, for example app.bundle.js.

    Note: If you cannot find the file, open a support case and provide the data listed in the Collect HTTPWatch or HAR files for support section of K14184: Troubleshooting BIG-IP APM Portal Access applications.

  2. Log in to the Configuration utility.

  3. Go to Local Traffic > iRules, and click Create.

  4. For Name, enter a name for the iRule, for example pa_iframe_sandbox.

  5. For Definition, enter the following iRule. Replace replacethisfilename.js with the name of the file from step 1.

    # This iRule is from MyF5 article K000141028
    when HTTP_REQUEST {
        if { [HTTP::has_responded] } { return }
        if { [HTTP::path] ends_with "replacethisfilename.js" } {
            HTTP::header remove "Accept-Encoding"
            if { [HTTP::version] eq "1.1" } {
                if { [HTTP::header is_keepalive] } {
                    HTTP::header replace "Connection" "Keep-Alive"
                }
                HTTP::version "1.0"
            }
            set sandbox 1
        }
    }
    when HTTP_RESPONSE {
        if { [info exists sandbox] } {
            if { [HTTP::header exists "Content-Length"] and [HTTP::header "Content-Length"] <= 6291456 and [HTTP::header "Content-Length"] != 0 } {
                HTTP::collect [HTTP::header Content-Length]
            } else {
                HTTP::collect 6291456
            }
        }
    }
    when HTTP_RESPONSE_DATA {
        if { [info exists sandbox] } {
            unset sandbox
            set str_sandbox { sandbox="allow-scripts"}
            set strt_sandbox [string first $str_sandbox [HTTP::payload]]
            if { $strt_sandbox > 0 } {
                HTTP::payload replace $strt_sandbox [string length $str_sandbox] { sandbox="allow-same-origin allow-scripts"}
            }
            HTTP::release
        }
    }

    Note: The iRule collects up to 6291456 bytes (6 MB) of the response and replaces only the first occurrence of the text  sandbox="allow-scripts" (with a leading space) in the collected data. If the file is larger, the text must be in the first 6 MB. If the file uses a different sandbox value, change str_sandbox and the replacement text to match it.

  6. Click Finished.

  7. Go to Local Traffic > Virtual Servers, and click the name of the Portal Access virtual server.

  8. Click the Resources tab, and in the iRules section, click Manage.

  9. Move the iRule to the Enabled list, and click Finished.

  10. Clear the browser cache, close the browser, start a new access session, and open the application. Verify that the browser developer tools console no longer shows Error 2.

To back out of this procedure, remove the iRule from the virtual server, and clear the browser cache.

Note: F5 Support does not design or configure iRules. If you need help to adapt the iRule to your application, contact F5 Professional Services.
