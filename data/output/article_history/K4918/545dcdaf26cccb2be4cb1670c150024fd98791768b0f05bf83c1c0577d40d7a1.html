Policy Information

F5 is committed to responding quickly to software issues in F5 products. F5 may provide temporary code patches or engineering hotfixes to address issues between normal new Major, Minor, and Point software releases. F5 produces engineering hotfixes only for customers who have active contracts with F5 Global Support or F5 Premium Plus Support. While F5 endeavors to release the most stable code possible, engineering hotfixes do not undergo the extensive QA assessment of scheduled software releases, for example, for performance. F5 offers engineering hotfixes with no warranty or guarantee of usability.

The issues addressed by engineering hotfixes are included in the next software release of the affected product if the hotfix has completed a full QA regression analysis. Once F5 has included a fix in released code, any engineering hotfix already coded will be available for 30 days after the release date of the release containing the fix. F5 will not produce new engineering hotfixes for a software defect that has already been addressed in a software release.

F5 recommends that customers update or upgrade software to take advantage of CVE fixes, hardening, and new functionality included in the released version. An update involves installing a more recent maintenance or point release on the same code branch (for example, updating from 17.1.0.3 to 17.1.1.3). An upgrade involves installing a more recent code branch (for example, upgrading from 16.1.4 to 17.1.1.3).

Supported Major, Minor, Maintenance, and Point releases within their Standard Support Phase are eligible for the critical issue hotfix process. For more information about Major, Minor, Maintenance, and Point release numbering, refer to K8986: F5 product support policies.

Note: Engineering hotfixes will be created for only the most recent maintenance release and point release of the eligible versions.

For a list of the latest cumulative hotfixes for each BIG-IP software version, refer to K9502: BIG-IP hotfix and point release matrix.

F5 reserves the right to decline requests for the creation of an engineering hotfix without citing cause. The only issues that F5 considers for the critical issue hotfix process are those that do not possess simple configuration workarounds and demonstrate definite impact on customers' business.

F5 endeavors to create engineering hotfix packages that address as many issues as possible at the time of creation for a specific product. Cumulative hotfixes for BIG-IP software branches are roll-ups of all available hotfixes that are considered stable.

For information about F5 supported hardware and software versions, refer to the following articles:

  • K4309: F5 platform lifecycle support policy
  • K8986: F5 product support policies

For information about software issues that affect the security of an F5 product, such as CERT advisories, refer to K4602: Overview of the F5 security vulnerability response policy.
