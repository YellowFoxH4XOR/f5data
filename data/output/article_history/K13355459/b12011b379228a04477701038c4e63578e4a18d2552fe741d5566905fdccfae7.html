Description

The BIG-IP iSeries platform includes a new, logical volume named appdata for storing dynamic data from provisioned modules such as BIG-IP Analytics, ASM, APM, and Virtual Clustered Multiprocessing (vCMP). You can increase its size with the lvextend utility.
 

Environment


You must meet the following prerequisites to use this procedure:

You have access to the Advanced Shell (bash) of the BIG-IP system
 

Cause

None.
 

Recommended Actions

Impact of workaround: Increasing volume size may prevent the installation of more than three TMOS images. For more information, refer to K41812306: The /appdata volume on BIG-IP iSeries platforms is now larger. While system services are stopped, the system does not pass traffic and the Configuration utility is unavailable; therefore, F5 recommends that you perform this procedure during a scheduled maintenance window.  Additionally, the specific lvextend command string in this procedure increases the file system first, so data is not lost by the logical volume change; however, while unlikely, any change to a file system or logical volume has the potential for data loss.

1. Create a user configuration set (UCS) backup of the BIG-IP system. If vCMP guests are deployed on the system, create UCS backups of all guests. For more information, refer to K13132: Backing up and restoring BIG-IP configuration files (11.x - 12.x).

2. Log in to the BIG-IP command line using the management IP address or the serial console port.

3. Verify the amount of free space (VFree) in the volume group by entering the following command:

vgs

Output appears similar to the following example:

# vgs
  VG        #PV #LV #SN Attr   VSize   VFree
  vg-db-sda   1  17   0 wz--n- 447.12g 21.37g

4. Verify the size of the appdata volume by entering the following command:

df -h

5. To allow the lvextend utility to unmount the /appdata directory, stop all system services by entering the following command:

tmsh stop sys service all


6. To unmount appdata volume, type the following command:

umount /appdata

7. Increase the size of the appdata volume by 20 GB by entering the following command:

lvextend  --size +20G /dev/vg-db-sda/dat.appdata

Output appears similar to the following example:

Extending logical volume dat.appdata to 341.44 GiB
Logical volume dat.appdata successfully resized

8. Run e2fsck to correct any file system issue on appdata

e2fsck -f /dev/vg-db-sda/dat.appdata

Output appears similar to the following example:

e2fsck 1.41.12 (date)
Pass 1: Checking inodes, blocks, and sizes
Pass 2: Checking directory structure
Pass 3: Checking directory connectivity
Pass 4: Checking reference counts
Pass 5: Checking group summary information
dat.appdata: 17/21069824 files (0.0% non-contiguous), 1355196/84262912 blocks

9. Issue this command to enlarge the unmounted appdata volume

resize2fs /dev/vg-db-sda/dat.appdata

10. To mount back appdata volume, type the following command:

mount /dev/vg-db-sda/dat.appdata /appdata/

11. Start all system services by entering the following command:
tmsh start sys service all

12. Confirm the amount of free space in the volume group is increased by 20 GB by entering the following commands:
vgs
df -h
lvs
