K000164100: BIG-IP Integrity Check Report Shows "Critical file modifications result in failure" When '/usr/libexec/sys-eicheck.py' Is Interrupted

Type
Support Solution
Published
2026-11-04
Updated
2026-11-04
Applies to
  • BIG-IP
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K000164100

Description

When "/usr/libexec/sys-eicheck.py" is run manually on a BIG-IP system, the console may display the following heading, followed by a Python traceback:

BIG-IP Integrity Check Report
- Critical file modifications result in failure.
^CTraceback (most recent call last):
  File "/usr/libexec/sys-eicheck.py", line 221, in <module>
    sys.exit(main())
  File "/usr/libexec/sys-eicheck.py", line 191, in main
    crit_modified, crit_missing = check_files()
  File "/usr/libexec/sys-eicheck.py", line 145, in check_files
    if is_bin and not istext(filepath):
  File "/usr/libexec/sys-eicheck.py", line 100, in istext
    ...

The traceback appears when the script is interrupted (for example, with Ctrl-C) during the istext() subprocess call in check_files(). The "Critical file modifications result in failure" line is only the report heading. The script prints its heading first and its results last, so this line does not indicate the result of the check.

Environment

  • BIG-IP LTM
  • Hardware platform with FIPS (like, I5820-DF, C125)
  • Script: "/usr/libexec/sys-eicheck.py"

Cause

Interrupting "/usr/libexec/sys-eicheck.py" before it finishes. The heading is printed before the results, so an interrupted run shows the heading and a traceback without a final result.
No product fault was identified. A completed run of the script reported 0 critical files missing, 0 critical files modified, and Integrity Test Result: [ PASS ].

Answer/Recommended Actions

1. Run "/usr/libexec/sys-eicheck.py" and let it run to completion. Do not interrupt it.

2. Evaluate the result only from the final Integrity Test Result line.

  • [ PASS ] with 0 critical files missing and 0 critical files modified indicates the check succeeded.

3. If the script reports an integrity failure, or lists missing or modified critical files, collect a new QKview and open a support case. Include the complete script output.

Additional Information

Expected behavior: The heading line "Critical file modifications result in failure" always prints first. Use the final result line to determine status.

Expected behavior after an upgrade: The following may be checked before and after an upgrade:

  • "tmsh run util fips-util info" output
  • Master keys and certificate keys
  • File count in the cavfips directory
  • Certificate key values may differ for re-encrypted fields (for example, Challenge-password). This is expected.

Log messages indicating a healthy system:

  • FIPS Integrity Check:: Startup integrity check successful.
  • tpm-status[...]: System Integrity Status: Valid
