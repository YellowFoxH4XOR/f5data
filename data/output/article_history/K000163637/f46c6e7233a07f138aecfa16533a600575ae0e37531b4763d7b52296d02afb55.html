K000163637: F5 BIG-IP Terraform Module: Certificate/Key Updates Add Inherited Options to Child Client SSL Profiles

Type
Support Solution
Published
2026-10-09
Updated
2026-10-09
Applies to
  • BIG-IP
  • BIG-IP LTM
Source
https://my.f5.com/manage/s/article/K000163637

Description

Updating only the certificate or key of a child client SSL profile with the Terraform BIG-IP provider can explicitly add inherited SSL options to the child profile. Although the defaults-from

relationship remains configured, later changes to those options on the parent profile do not propagate to the child.

The child profile may incorrectly contain an explicit configuration such as:

 

options {
    dont-insert-empty-fragments
    no-ssl
    no-tlsv1.1
}

Environment

  • BIG-IP LTM
  • Terraform BIG-IP provider
  • Parent and child client SSL profiles configured with defaults-from
  • The child profile has a certificate and key that are managed by Terraform

Cause

The Terraform provider incorrectly included inherited client SSL options in the update payload when modifying only the child profile’s certificate or key. BIG-IP then stored those options explicitly on the child profile.

This causes configuration drift because explicitly configured child attributes take precedence over inherited parent values.

A certificate/key-only update performed directly with tmsh, without an options parameter, does not add explicit options to the child profile.

Answer/Recommended Actions

  1.  Upgrade the Terraform BIG-IP provider to a release that includes the fix for this issue (See additional information below)
  2. Check whether inherited options values were added explicitly to the child profiles.
  3. Remove unintended child-level options using the approved BIG-IP configuration-management process.
  4. Reapply the Terraform configuration.
  5. Verify that certificate/key-only changes do not add an options block to the child profile.
  6. Confirm that changes to the parent profile’s options propagate to the child profile.
