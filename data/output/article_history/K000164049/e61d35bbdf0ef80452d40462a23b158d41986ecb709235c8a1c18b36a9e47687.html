K000164049: Policy Stuck in Compiling Status and Publish Failure in NIM

Type
Support Solution
Published
2026-10-29
Updated
2026-10-29
Source

Description

An NGINX App Protect security policy remains in the Compiling state indefinitely in NGINX Instance Manager (NIM), and configuration publishing fails. The NIM log shows a pre-check failure in which the compiler version is reported as undefined, even though the App Protect and compiler versions on NIM and the managed instance match.

Example NIM log messages:

compiler-controller/compiler_controller.go:613 controller: pre-check failed for ({AppProtectPolicyName:<policy_name> ... CompilerVersion:undefined ...}): missing the specified compiler (undefined) please install it and try again

http failure with code '13018': missing the specified compiler (undefined) please install it and try again

http failure with code '13012': security policy bundle object with given ID was not found

Environment

  • Products: NGINX Instance Manager (NIM) managing NGINX Plus with NGINX App Protect
  • Reported versions: NGINX Plus nginx/1.29.8 (nginx-plus-r37-p1), App Protect 5.690.0, NGINX Instance Manager compiler package nms-nap-compiler-v5.690.0
  • OS: Ubuntu 24.04
  • NIM compiler directory: /opt/nms-nap-compiler/ contained two compiler installations, app_protect-5.635.3 and app_protect-5.690.0
  • Policy configuration: The NGINX Plus configuration assigned two App Protect policy references at the same time, a JSON policy source and a compiled TGZ bundle (see Additional Information)
  • Recent changes: A URL was added to the allow list and the policy was published. The issue appeared during that publish.

Cause

  • The log reported CompilerVersion:undefined for the policy, but the compiler directory contained the matching app_protect-5.690.0 compiler.
  • Debug-level NIM logs for the affected policy showed the compiler was identified correctly. The debug logs for the test run were not captured as expected.
  • The issue could not be reproduced after the environment was upgraded.
  • Probable cause,  the NGINX Plus configuration contained both a JSON and TGZ fomat policy on the object.

Answer/Recommended Actions

If you see this behavior, collect the following information and open a support case:

  1. Confirm the installed NIM compiler packages and the compiler version used by the affected policy:

    dpkg -l | grep -i nms-nap-compiler

    Also check the compiler version of the policy in the NIM GUI or REST API bundle listing. Refer to the NGINX documentationNote: This link takes you to a resource outside of MyF5, and the third party could remove the document without our knowledge.

  2. If the App Protect version on the managed instance is not installed on NIM, install the matching compiler. Refer to: NGINX documentationNote: This link takes you to a resource outside of MyF5, and the third party could remove the document without our knowledge.

  3. Restart the integration service and check whether the behavior changes:

    sudo systemctl restart nms-integrations

  4. Review the NGINX Plus configuration for the affected server or location. Ensure only one App Protect policy reference is active. See the Additional Information section.

  5. If the problem persists, enable debug logging and reproduce it:

    1. Set the NIM log level to debug in the NIM configuration file. Refer to: NGINX documentation
    2. Restart NIM:

      sudo systemctl restart nms

    3. Trigger a fresh compile of the affected policy by editing its description or re-publishing it.
    4. Immediately search the NIM log for the policy name and the policy UID.
    5. Generate a new NIM support package. Refer to: NGINX documentationNote: This link takes you to a resource outside of MyF5, and the third party could remove the document without our knowledge.
    6. Set the log level back to info. Debug logging is verbose and should not be left enabled.

  6. Collect the following outputs and attach them to the support case:

    • dpkg -s nms-nap-compiler-v5.690.0
    • ls -ld /opt/nms-nap-compiler/app_protect-5.690.0
    • The policy bundle listing from the NIM REST API (/api/platform/v1/security/policies/bundles, with includeBundleContent=true and the policy name as a query parameter)
    • The NGINX Plus diagnostic package and the NIM support package
