Description

A large number of F5OS services are run in Docker containers. This article provides a list of useful kubernetes and docker commands that you can use as quick reference when troubleshooting issues live.

Environment

You encounter issues on F5OS

  • F5OS-C
  • F5OS-A

Cause

On initial troubleshooting, you determine the F5OS service is running in a docker container.

Recommended Actions

  • Before diving in to troubleshoot issues on the docker containers, verify the health of your Openshift cluster, VELOS controller and blades first. 
    Login to confD and enter the following command: show cluster

  • Refer to the relevant log files to isolate the issue. For more information, refer to K000139582: Troubleshoot F5OS using log files.
  • F5 support may request that you run the following commands and provide its output for troubleshooting.

    Important: Kubernetes and Docker are third party software. F5 does not provide further information/explanation on the output and does not support the (Kubernetes, Docker) software itself. For more information on the commands refer to CLI reference on Kuberbetes and Docker. 

DescriptionCommand syntax/examplesAdditional Information
Pod commands (oc, kubectl)
Verify cluster, pod health
  • Display all pods
    • oc get pods --all-namespaces (F5OS-C only)
    • kubectl get pods --all-namespaces -o wide
  • Use grep to display unhealthy pods
    • kubectl get pods --all-namespaces -o wide | grep -v 'Running\|Completed'

Use bash utilities e.g. grep to filter unhealthy pods with the following:

  • Pods with status other than Running or Completed
  • Pods with incomplete Ready values. e.g. 0/1
  • Pods with large number of restarts. e.g. 5
Display detailed information using kubectl describe
  • From the output of the previous row use the following syntax:
    • kubectl -n <namespace> describe pod <pod_name>
    • kubectl -n partition-3 describe pod tmstat-rsync-5abcdefg55a5-11abc

Use this to get detailed information on the status, stats of a specific pod you found unhealthy.

Display the logs of a pod
  • From the output of kubectl get pods, use the following syntax:
    • kubectl -n <namespace> logs <pod_name>
    • kubectl -n default logs docker-registry-2-abc12

Refer to container logs when troubleshooting any issues. Note that the absence of logs does not indicate an issue.

Bash commands
docker version
  • To get the version of the docker engine and other related packages
Enter docker version
journalctl
  • To query the /var/log/journal logs, use the following syntax:
    • journalctl -D /var/log/journal -b -u <service> --no-pager
    • journalctl -D /var/log/journal -b -u platform-services-deployment.service --no-pager
  • The -u or unit switch filters the logs to display only the service you specify.
  • To list all the units in the system and a description of each one, enter the following command:
    systemctl list-units --all
  • To list every unit or service that has ever written a log entry to the journal files, enter the following:
    journalctl -F _SYSTEMD_UNIT
Docker container commands
To list and filter docker containers
  • Lists all containers
    • docker ps -a
  • Lists only running containers
    • docker ps
  • Lists specific containers with filters:
    • docker ps | grep -i <name>
    • docker ps -f Name=http-server
    • docker ps --filter 'name=vcc-confd' --format 'table {{.Names}}\t{{.Image}}\t{{.Status}}'
Display and identify the name and ID of a docker container that is facing an issue and requires troubleshooting. Use the name or ID to run more commands on the container.
Login to a specific container
  • Login to a container
    • docker exec -it <container name> /bin/bash
  • Run command(s) inside a container
    • docker exec -it http-server ls /var/log/httpd
    • docker exec http-server bash -c 'python -V; httpd -v'
Login to the container from F5OS bash and run commands in the container
Display detailed information on docker objects of a container using docker inspect
  • Display all docker objects:
    • docker inspect <container name>
  • Display specific object using filters:
    • docker inspect --format='{{json .State}}' vcc-confd | jq
    • docker inspect --format='{{json .Mounts}}' vcc-confd | jq
This is useful to get the state, network, mount, directory bindings and detailed information in the container
  • Display the state of a container.
    • docker inspect --format='{{json .State}}' vcc-confd | jq
    • docker exec http-server bash -c 'uptime; httpd -v'
Get detailed container information such as uptime, status, status error code, software library versions and so on.
Display the logs of a container
  • Displays container logs. 
    • docker logs --details -t <container name>
  • Follow the container logs
    • docker logs --details --follow -t ihealth-service
Refer to container logs when troubleshooting any issues. Note that the absence of logs does not indicate an issue. In such cases, refer to K000139582: Troubleshoot F5OS using log files, where logs could be logged in other locations.
Display container resource usage
  • Display the top output for a container
    • docker container top <container name>
  • Display the top output by running the command within a container
    •  docker exec -it <container name> top
    •  docker exec -it v cc-confd top -cbn 2 -d 1.0 -w 512
  • Display CPU and memory usage for a ist of services
    • docker stats
    • docker stats --all --format "table {{.Container}}\t{{.CPUPerc}}\t{{.MemUsage}}\t{{.MemPerc}}" snmpd snmp-trapd partition2_snmpd partition2_snmp_trapd
  • Display docker disk usage
    • docker system df
  • Display disk usage inside a container by running the command within a container
    • docker exec -it vcc-confd df -h
    • docker exec -it vcc-confd du -sk /var/log/* | sort -n
Verify system resource (CPU, memory, disk) usage by docker and its containers
Copy a file out from a container
  • Copy a file out from a container
    • docker cp <container>:<source_path> <destination_path>
    • docker cp http-server:/var/log/httpd/access_log /var/tmp/
Ensure that you do not copy secure files out that may violate your company's security policy.
Using bash utilities to loop through F5OS docker containers
  • Use a for loop to execute a command on all containers
    • for i in $(docker ps --format '{{.Names}}'); do docker <command> ;done
  • Get the status of all containers using docker inspect
    • for i in $(docker ps --format '{{.Names}}'); do echo $i\n; docker inspect --format='{{json .State.Status}}' $i ;done
  • Get the uptime of all containers
    • for i in $(docker ps --format '{{.Names}}'); do echo $i\n; docker exec $i uptime ;done
Use bash utilities to loop through containers when you need to run the same command on more than one container.
Important: The following commands make changes to the system. You should run these commands only when specifically asked to do so by F5 Support.
Stop, start docker containers
  • docker restart <container name>
  • docker stop <container name>
  • docker start http-server
Note that not all F5OS services should be restarted in this way. You should run these commands only when specifically asked to do so by F5 Support.
