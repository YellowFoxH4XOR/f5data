Description

On VELOS systems a VELOS blade can restart unexpectedly under heavy traffic load. The restart causes the blade's tenant to fail over, and the chassis AOM (Application Oriented Management) also resets.

Symptoms:

  • A gap of several minutes in the tenant logs under /var/log/ltm.
  • The gap is followed by a boot marker in the logs.
  • Chassis logs show AOM entries similar to the following:

    AOM boot marker (v1.00.231.0.1)

    pin reset

    power-on reset

  • Tenant logs contain a number of "clock advanced" messages.

This behaviour matches Bug ID 2382985. The restart is not a logging interruption or a TMM restart.

Environment

  • Platform: VELOS chassis with BX520 blades
  • Software: F5OS-C 1.8.2, 2.0.0
  • Condition: CPU TurboBoost is enabled on the blade. This is not the expected default configuration.
  • Trigger: Sustained traffic load

Cause

Bug ID 2382985. The blade restarts when CPU TurboBoost is enabled and the system is under traffic load.

Answer/Recommended Actions

  1. Confirm the TurboBoost state. Check the BIOS setup on the affected blade to determine whether Intel Turbo Boost is enabled.
  2. Apply the workaround if TurboBoost is enabled. Disable TurboBoost in the BIOS. This prevents the restart condition.
    Note: Disabling TurboBoost lowers the CPU clock speed under load. This reduces throughput and increases latency.
  3. Upgrade to a release that contains the fix. The fix for Bug ID 2382985 is included in F5OS-C 1.8.3 and later. Upgrading permanently resolves the issue and removes the need for the workaround.
  4. Verify after the upgrade. Confirm that no new AOM resets or tenant logging gaps occur under peak load.

Additional Information

Expected behavior: TurboBoost is not supposed to be enabled on these platforms. Disabling it is the expected configuration.

Security note: When TurboBoost is enabled on Intel processors, the system is exposed to CVE-2022-24436 (Hertzbleed). See K14335949: Intel processors vulnerability CVE-2022-24436 for details.

Expected performance impact: The drop in throughput and increase in latency after disabling TurboBoost is expected.
