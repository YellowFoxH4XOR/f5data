Overview

This document defines the different feature and lifecycle stages of the BIG-IP Next cloud-native family of products. Products covered by this document include:

  • BIG-IP Next for Kubernetes
  • BIG-IP Next Service Proxy for Kubernetes (SPK)
  • BIG-IP Next Cloud-Native Network Functions (CNFs)
    • BIG-IP Next Edge Firewall CNF
    • BIG-IP Next Carrier-Grade NAT (CGNAT) CNF
    • BIG-IP Next DNS CNF
    • BIG-IP Next Policy Enforcer CNF

Product release versioning schema

The F5 BIG-IP Next cloud-native products release schema is: BIG-IP Next for Kubernetes a.b.c, or BIG-IP Next SPK a.b.c, or BIG-IP Next CNFs a.b.c., as explained in the following table.

Release typeVersion positionVersionDefinitionExample
Majoraa.x.xRepresents major new feature sets and may involve behavior changes or API changes that are not backwards compatible. Major releases should happen approximately once per year or less frequently. Major releases are for introducing significant new functionality with proper solution testing for long term consumption by all customers. After a new Major release is introduced, no new Minor releases are made available for the prior Major release. No new Maintenance releases are made available for the prior Major release after one year.If the latest BIG-IP Next SPK release goes from version 2.3.5 to 3.0.0, after this point, there would be maintenance releases of BIG-IP Next SPK 2.3.x for one year.
Minorba.b.xRepresents changes that introduce new functionality. After a new Major release is introduced, no new Minor releases are made available for the prior Major release.If the latest BIG-IP Next SPK release goes from version 2.3.5 to 3.0.0, after this point, there would be no BIG-IP Next SPK 2.4.x releases.
Maintenanceca.b.cAddresses bug fixes, security updates, and minor enhancements/hardening that do not introduce significant new functionality. As a general rule, new maintenance releases are made available for only the latest minor release.If the latest BIG-IP Next SPK release goes from version 2.3.5 to 2.4.0, after this point, any new bug/security fixes would be made available in version 2.4.1 (not in version 2.3.6), unless there was a maintenance release already planned and committed to a customer

The intended path for customers to receive the latest bug fixes is to update to the current release.

Product stages

The F5 BIG-IP Next cloud-native products have four stages:

  • Active development: the upcoming major/minor version is considered under “active development." This software may be made available as “early access” or “release candidate” software for limited customers (for example, customers partnering on new functionality), for limited scope (for example, lab-only), or both. The details of the limitations are spelled out in the release notes for that release.
  • Current major release: the most recent major release of the product. Current major releases receive new functionality in the form of minor releases, and security updates and bug fixes in the form of maintenance releases.
  • Last major release: the major release that came immediately before the current release. The previous major release is eligible for maintenance releases that contain critical bug and security fixes for a period of one year after the new major release. No new functionality will be added to the last major release. Any maintenance releases would be based on new critical bugs or CVEs discovered, and the maintenance release would be built on the last minor release.
    • Example: if the last major/minor release was BIG-IP Next SPK 2.5, then for a period of one year after BIG-IP Next SPK 3.0 was released, any customer running BIG-IP Next SPK 2.x could get critical bug and CVE fixes in BIG-IP Next SPK 2.5.x maintenance releases.
    • Limitation: The F5 BIG-IP Next cloud-native products use a licensing framework that involves telemetry reports from customers using the product in production. If there are no current telemetry reports from paid customers still using the last major release in production, F5 may treat that major release as if it were a “prior major release” (see following bullet).
  • Prior Major Releases: all major releases that are more than one major release back from the Current Major Release. If a customer has paid support, they can obtain technical support on these releases, but no security or bug fixes will be issued.

Feature stages

The F5 BIG-IP Next cloud-native product features have the following two stages:

  • Early Access Features: features that are being supplied for customer trial and feedback but are not supported for use in production. If these features are used in production, customers with paid support may obtain only technical advice on their use, but no security updates or bug fixes. Features that are “early access” may be either locked out when using production licenses or referenced as “early access” in the user documentation accompanying that release.
  • General Availability Features: features that are fully supported in Production (based on the Product Stage for the product version).

Exceptions

In exceptional circumstances, special releases may be issued for individual customers, resolving a bug or CVE that would not ordinarily be fixed in that Product Stage or in that version branch. These exceptional releases would be designated as a “hotfix” and issued to the customer with a timeline specifying when the fix would be merged into the appropriate next maintenance release. Hot fixes are not intended to be long-term fixes; they are intended to resolve an emergency problem until a normal release can be delivered.
