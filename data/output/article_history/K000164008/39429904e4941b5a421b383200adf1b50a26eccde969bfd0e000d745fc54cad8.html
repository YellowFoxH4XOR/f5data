K000164008: Saving an iRule with AUTH::abort causes TMM to crash

Description

BIG-IP LTM may experience a TMM crash and HA failover when an iRule is modified or saved if the iRule contains an AUTH::abort command outside of an after block. This occurs during iRule updates via REST API or the Configuration utility, resulting in a successful 200 OK response followed by all interfaces going down, TMM crash, core file generation, and cluster failover. TMM logs indicate crashes with SIGFPE.

Environment

  • iRule containing AUTH::abort $tmm_auth_ssl_ocsp_sid outside an after block
  • iRules

Cause

Bug ID 1825357

Answer/Recommended Actions

Move the AUTH::abort command inside an after block before saving or modifying the iRule.

Example:

after 1 { AUTH::abort $tmm_auth_ssl_ocsp_sid }

Impact of workaround: The system will not be available during the TMM restart and HA failover triggered by the fix.

If the issue has already occurred, inspect TMM crash logs and core files to confirm the condition. Look for SIGFPE entries in TMM logs during or immediately after an iRule save or modification event. Verify that the affected iRule contains AUTH::abort outside an after block. Avoid modifying or saving the iRule in its original form until the workaround is applied.
